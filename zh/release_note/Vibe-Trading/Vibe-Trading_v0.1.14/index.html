Vibe-Trading v0.1.14

自 0.1.13 以来汇总了 272 个提交/74 个合并的拉取请求。

添加

  • 选项实验室（#1096，关闭#1095，感谢@shadowinlife）——一个 Web UI 页面 有四个表面：到期收益图、现货×IV情景损益矩阵、 投资组合希腊卡，以及实时美国期权链。数学并不新鲜：两个 只读 HTTP 端点包装现有的 options_payoff / get_options_chain 工具，因此页面和 MCP 表面根据 相同的测试引脚 src/quantlib/options.py。仅供研究——它没有放置 订单。
  • “运行详细信息”中的 “因子研究”选项卡（#1099，感谢 @shadowinlife）— IC 统计卡、每日 IC 系列及其平均线、分位数组 权益曲线和 IC 相关热图，全部由 factor_analysis 工件运行已写入。新的只读 GET /runs/{run_id}/factor 端点扫描运行的 artifacts/ 树并 计算成对 IC 时间序列相关矩阵，该矩阵存在 之前无处可去； has_factor_artifacts 标志控制选项卡，因此无需运行 因子输出不显示空面板。 -“运行详细信息”中的“位置”选项卡**（#1097，关闭#1098，感谢@shadowinlife）— 现有 positions.csv 的投资组合账簿结构：每个交易品种 带有日期滑块、部门和资产类别净暴露的权重饼图/树状图 条形图和重量演化堆叠区域。馅饼的成分是粗 （绝对重量，包括短裤和现金）而金条是净 每个行业的风险敞口，因此一个行业的多头/空头对在该行业的净值为零 条形图，而两条腿在饼图上仍然可见。两张图的答案不同 故意提问。
  • 运行详细信息中的撕纸选项卡（#1091，关闭#1090，感谢@shadowinlife）— 月回报热图（年×月，包含全年列），年度 回报条形图、前 5 名回撤表以及用 注释的权益曲线 排名下降区。一切都源自client端 equity.csv 行运行响应已携带：没有后端更改，没有新的 依赖性，月份轴标签来自 Intl.DateTimeFormat 而不是 每个区域设置的月份键。
  • 交互式回测研究仪表板（#1084，感谢@AndyLongest）- 可选的报告样式视图，用于与现有的一起完成回测 烛台和交易细节视图：总体回报/风险/交易 KPI， 标准化股本与基准相比，滚动夏普回撤已实现 交易损益表、交易分类帐和完整的指标表。 CLI 回测得到 安静的本地报告服务器引导程序，以便 Full Report 路由到仪表板 无需手动服务器步骤。
  • 策略发现（#978 第 1 阶段和 #1007 第 2 阶段，参考号 #969，谢谢 @shadowinlife）——一个只读外观，回答“存在什么策略以及什么” 他们处于什么状态？”横跨 Alpha Zoo 和 SDM 策略商店， 每个 (strategy, regime) 证据行而不是场景标签。船舶 list_strategies / query_strategies / get_strategy_evidence 为代理并 证据门背后的 MCP 工具（最低贸易、覆盖范围和 成本收支平衡阈值，每个阈值都有明确的警告），加上启动 当任何广告工具实际上没有使用时，防护会丢弃路由文本 已注册。第 2 阶段添加人口路径 — refresh_strategy_evidence 作为代理工具、MCP 包装器和 vibe-trading strategy-evidence refresh --manifest — 与 backtest-diagnose 硬门检查表作为摄取门（稳定 hard-gate:* 跳过标记）和原子重建。新鲜度是在读取时计算的 从证据窗口年龄开始的时间（fresh/aging/stale）；陈旧行失败 关闭 include_stale 选择退出后的默认建议，并且 sdm:* 行反映了 SDM 生命周期。
  • 预定的研究现已自行完成。 完成的简报离开了 运行发件箱而不是等待被读取：发件箱行是 在发送之前根据租约提出索赔，因此交付途中的崩溃不会加倍 post，发送连接到会话和通道运行时，并且 推送发生在终端事件上。交付已配置并从以下位置观看 市场观察。
  • 每个监视器的最新结论都保留在其工作中（#1152，参考#943， 感谢@he-yufeng）——运行的终端简报被服务器端解析为 结构化的 last_verdict 记录和 /scheduled-runs 列表携带它 内联，因此列表呈现判决而无需重新解析每行的自由文本或 进行 N+1 次会议。五本研究手册形成了严格相加的 ## Verdict 尾部 — 每个跟踪符号一条 - SYMBOL: STATE - reason 行， 每个剧本都声明自己的状态词汇。解析是故意的 strict：临时提示永久落在 no_verdict_section 并呈现 因为除了警告之外什么也没有，没有任何追踪的运行才是真正的“不” 呼叫”答案而不是缺席，并且格式错误的部分降级为 contract_violation 而不是显示错误的判决。之前的记录是 在写入时嵌入一层深，并且不再更深。
  • Futu 连接器 - 七个扩展只读端点（#1135，谢谢 @549236606-oss) 缩小了 SDK 暴露的内容和 连接器消耗：get_rehab（股息/分割/权利调整因素，所以 回测随着价格变动停止读取股息缺口），get_capital_flow （历史超大/大/中/小流入桶），get_capital_distribution （今天的流入与流出快照），get_history_deals（填充记录 真正的基于成本的重建，上限为 SDK 的 360 天窗口）， get_acc_cash_flow、get_financials（收入/余额/现金流量表）， 和 get_earnings_calendar 与 EPS 和收入一致。各航线 通过与 _quote_ctx / _trade_ctx / _assert_gateway 相同的信封 原来的五个，所以缺少数据、缺少权限和缺少 OpenD 全部 降级为干净的故障关闭有效负载，而不是 SDK 堆栈跟踪。的 futu-api SDK 保持延迟加载。
  • 越南股票 (HOSE) 作为回测市场（#1033，感谢 @ngoanpv）。 .VN 与 _MARKET_PATTERNS 中没有条目匹配，因此 _detect_market 回退到 a_share 并根据中国 A 股规则执行越南金条 — 并询问 对于雅虎明确没有帮助，因为两个雅虎加载程序都通过后缀进行控制 并在构建请求之前拒绝了 .VN。 .VN 现在通过 带有 ["yahoo", "yfinance", "local"] 后备链的雅虎装载机并运行 在专用的 VietnamEquityEngine 上。
  • 离线 USD-M 账户对账（#1106，涉及#1030，谢谢 @honginp) — 不可变的 Binance USD-M 账户和头寸快照合约 将交换观察结果与现有的 AccountState 进行比较 RiskSnapshot 不变异，报告数字、结构、 丢失符号和意外符号确定性漂移。清算引擎 验证是明确不评估的，而不是默默假设的。这是 Shadow 1 切片：仅合同和固定装置的离线对账。
  • Novita AI 作为内置 OpenAI 兼容提供商（#1059，谢谢 @jax-novita) — 在提供者注册表中注册为 NOVITA_API_KEY / NOVITA_BASE_URL 和有线直通功能、CLI 载入、 .env.example 和 README 提供程序列表，因此可以从 内置列表而不是手动配置为自定义端点。
  • GitHub Copilot 通过官方 github-copilot-sdk 作为提供商 （#990，取代#899，感谢@sykuang），使用 SDK 管理的身份验证 COPILOT_GITHUB_TOKEN、GH_TOKEN、GITHUB_TOKEN、存储副驾驶 CLI 凭证或 gh 凭证，加上 LangChain 兼容的调用、流式传输、 推理和工具调用处理以及设置/预检集成。这个 实现边界 #899 关闭：没有借用的 OAuth client ID，也没有 编辑器模拟标题。
  • tickerall 托管 MetaTrader 5 数据源（#968，关闭#897，谢谢 @miguelangelo78) — 经纪商通过托管提供的 MetaTrader 5 蜡烛图 TickerAll HTTP API，因此外汇和金属回溯测试可以在任何没有本地操作系统的操作系统上运行， 已登录 MetaTrader 5 终端。纯粹选择加入：is_available() 是错误的 除非设置了TICKERALL_API_KEY和TICKERALL_ACCOUNT_ID，并且加载器 从不加入自动链。
  • 再平衡模式的漂移容差带 - 会移动的再平衡 小于乐队的书被跳过而不是执行四舍五入 差异。
  • 西班牙语和德语语言环境（#1087 感谢@daviddaco1，#1117 感谢 @1ps构造函数）。西班牙发货完整的钥匙对钥匙 es.json plus README_es.md，使西班牙语成为第六个自述文件；德国船舶 de.json 完整的 UI 键集。两者都在 SUPPORTED_LANGUAGES 中注册并且 现有延迟加载路径上的 localeLoaders 以及区域设置奇偶校验和 插值变量测试涵盖了它们。
  • 桌面更新安全边界（#1101，参考文献#1016，感谢@QCYTSN）- 严格 PID 范围内的后端/看门狗关闭结果以供将来更新 切换、休眠 Windows 候选验证、中断尝试恢复 原语，以及一个记录的、经过测试的拒绝矩阵，用于篡改、未签名、 无效签名、错误发布者和降级候选人。所签署的 0.3.0 → 0.3.1 运行本身在签名身份上仍然被阻止；这是 在证书存在之前可以执行的部分，包括 证明桌面清理永远不会杀死不相关的 Python 进程。
  • Docker 镜像带有飞书和 Telegram 频道依赖（#1088， 感谢@birdxs），具有手动触发的工作流程，可以构建并推送到 GHCR 和 Docker Hub 并将项目描述同步到 Docker Hub 页。
  • 严格的 alpha t-stats 在工作台 JSON 和 HTML 报告中（#1085，谢谢 @jay79-boop)，因此严格模式编号可以从工件中读取 仅控制台。
  • MCP 表面上的偏移分页 用于 SEC 备案和财务报表 (#1138)，并且 load_skill 通过注册表进行路由，因此是一个超大的技能 页面而不是在传输限制时被截断（#1137）。

已更改

  • MCP 表面增加到 74 个工具（0.1.13 中为 70 个）。
  • smartmoneyconcepts 现在是可选的 [smc] 附加产品，而不是基础产品 依赖 - 过时的 <3.14 上限已从两个项目中消失 元数据和分发清单。包裹拉了进来 numba → llvmlite，并且 llvmlite 不从 0.46 发货 macOS x86_64 轮子 向前，因此作为基本依赖项，它将每个 Intel-Mac 安装变成 需要 CMake 的源构建（讨论#1035）。它只支持一项技能 例如，其 SKILL.md 已经告诉读者安装它。英特尔-Mac Python 3.11–3.13 上的用户现在无需使用 pip install vibe-trading-ai 工具链。
  • CI 在地板和天花板上运行测试作业 requires-python，因此会捕获任一端的特定于版本的中断 在发布之前而不是由用户发布。
  • Vite 在前端开发工具链中从 6.4.3 移动到 8.2.0 (#1022)。
  • 市场数据来源现在声明每个市场的交易量单位（#1065， #1131，感谢@shadowinlife），而 get_market_data 就是这个出处 通过 MCP 而不是将其丢弃在传输边界处。
