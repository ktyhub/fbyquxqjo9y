Vibe-Trading v0.1.13

v0.1.13 — 接地修复、金融数学层和机构研究

pip install -U vibe-trading-ai 自 v0.1.12 (2026-07-22) 以来，有 408 项提交和 162 项合并拉取请求** — 迄今为止最大的版本，来自 35 名贡献者。完整详细信息请参见 CHANGELOG.md。

🛡 标题是一个修复，而不是一个功能

0.1.12 系列中用户最明显的一个缺陷：格式良好的问题将花费几分钟时间进行真实的工具调用，然后拒绝回答，返回

当前无法安全确认标的身份或价格证据，因此没有生成交易结论。请确认候选证券代码和交易所后再继续。 （无法安全确认仪器身份或价格证据） 身份/接地门正在拒绝它已经有证据的答案。七个独立的根本原因，每个现在都已修复并由两侧防护测试覆盖（健康样本必须通过；不良样本仍必须被阻止）加上突变测试： | ＃|根本原因|效果| |---|-----------|--------| | 1 | .SS 和 .SH 被视为不同的乐器 | 每个上海股票代码永久为ambiguous | | 2 | A+H双重上市和裸香港代码崩溃至ambiguous |死胡同而不是入围名单| | 3 |雅虎为每个 CJK 查询返回 HTTP 400；记录为来源 失败 |升级为阻止 invalidated 而不是“此处未列出”| | 4 |失败的辅助查询可能会降低已锁定的身份 |粘性聚合状态且无法恢复 | | 5 |每个工具的硬编码白名单决定了哪些裸代码可以匹配 | 17 个记录的参数拼写中的 11 个被阻止（修复后 3/14 → 14/14）| | 6 |来源和货币必须以 ASCII 书写 |中文答案因写 雅虎/腾讯 或 元 而不是 人民币 而被拒绝 | | 7 |千位分隔符分隔子句中间数字 | ¥1,309.22 与 1 与观测范围进行比较 → 虚假价格冲突 | 根本不需要仪器的概念性问题和比较报告也不再是死胡同。 记录的 OHLC 证据之外的引用仍然被拒绝。门变得更精确，而不是更弱 - 这就是两侧测试的重点。 针对真实的法学硕士、真实的工具和真实的网络进行端到端验证：之前需要6分钟14秒并以预设拒绝结束的600519.SH查询现在在7-9秒内得到答案，零拒绝； 14秒内茅台； 14秒的一道知识题。 这也结束了 0.1.12 线中范围较窄的情况——从来不是价格的数字（置信度分数、指标读数、移动平均窗口、8/5 等无年份日期、百分比范围和交易计划自己的触发水平，其中 close ≥ 6.45 是一个条件而不是报价）——并使众多候选者的入围名单算作答案而不是停滞的解决方案（#1001、#983、第955章）。

🧮 src/quantlib — 经过测试的金融数学层

跨 19 个模块的 265 个测试函数 — 该工具现在导出允许列表中的每个模块。技能现在“导入”这些，而不是在 Markdown 代码块中携带公式 - 如果您发现 SKILL.md 中存在定价公式，那么这是一个错误，而不是模式。

模块 覆盖范围
options Black-Scholes 价格 + Greeks、隐含波动率反转
fixedincome 债券数学，Nelson-Siegel / Svensson 曲线拟合
credit Altman Z 分数、Merton / KMV 距离默认值
timeseries 平稳性、协整、GARCH、bootstrap
risk · var_backtest VaR / CVaR / EVT 及其回测
attribution Brinson-Fachler 分解
performance · fundmath TWR / MWR / 改良 Dietz； XIRR / MOIC / DPI / TVPI
factormodel · eventstudy 因子回归、事件研究
multipletesting · crossvalidation 意义被削弱，简历被清除
impact 市场影响模型
只读 quantlib_call 工具通过一份合约实现所有这些，因此财务数学适用于 CLI、Web UI、REST API 和 MCP — 包括部署 其中 bash 被关闭。从结构上来说，它不是一个 shell——模块白名单，仅调度 __all__，export_* 拒绝。计量经济学需要额外的stats；这些函数会延迟导入并命名缺失的函数。

💰 估值引擎

拒绝发明自己的输入的估值引擎。 contracts.py 中的一条规则：缺少输入会使模型无法运行，并且永远不会默默默认 - 估值模型中的每一次默认都是穿着常量衣服的意见。

  • run_dcf — FCFF 桥、WACC 构建、年中贴现、净债务桥、WACC×g 灵敏度网格。双终端值：每种方法都根据另一种方法的隐含倍数和隐含 g 进行交叉检查。
  • run_comps — EV 桥、LTM + 历年日历化、多矩阵。分母为非正数的同级将被排除并报告，永远不会平均为负倍数。
  • threestatement — 与硬平衡断言、显式左轮手枪插头以及必须收敛或上升的迭代利息↔债务循环性相关联的投影。 工件经过输入散列和版本控制，并具有 xlsx / pptx 导出功能。

🏛 机构研究

六个斜线命令 - /comps /dcf /attrib /memo /earnings /screen - 每个命令都带有一个步骤框架和一个算术一致的工作示例：布林森分解精确地求和为主动收益，收益桥精确地求和为 EPS 增量。 投资者视角成为一项独立技能：命名投资者推理框架作为可堆叠分析叠加，与数据层分离。每个镜头都是一个操作程序——优先信号、取消资格的条件、典型的误用——而不是传记，也没有命名任何工具。 五个现成的研究手册（上市前简报、收益季节跟踪器、投资组合检查、A 股资金流向、机构持股差异），可通过三种方式访问​​：授权门控 REST 路线、vibe-trading playbook CLI 子命令和 /playbook 斜线命令。模板以自然语言而不是命名工具来陈述其数据需求，因此覆盖范围可以在不编辑模板的情况下扩大，并且每个模板都要求命名缺失的输入，而不是从内存中填充它。

📊 四个新的只读数据工具 - 全部来自免费的公共资源

  • get_institutional_holdings — SEC 13F-HR 以经理/股票持有者/高层经理模式记账，并具有用于因子使用的季度间位置差异。封面总数以 value_units + 为基础，因为 2023 年之前的备案报告数量为数千。
  • etf_holdings — 跨市场透视。美国 SEC N-PORT；对于 A 股，半年度/年度报告包含完整账簿，而不是季度前十名：510300 回报342 行覆盖净资产的 98.66%，而 10 行/22.74%。 coverage 将 full_portfolio 与 top_n_disclosed 区分开来，每个回复都会标记报告期间 - 完整的书始终是较旧的披露内容。
  • prediction_market — 事件合约搜索/事件/市场/历史，价格转换为隐含概率并标记单位，因此下游永远不会将 0.63 读取为美元。通过构造只读：无顺序路径。
  • research_papers — arXiv + OpenAlex 搜索/读取源锚定声明提取。源中不存在的任何内容都会留空并标记为 not stated in source，并且论文声称的性能永远不会作为我们的回测结果呈现。

🧾 治理融入每一次运行

  • 运行清单对提示、技能内容、工具注册表和软件包版本进行哈希处理 - 那么“什么方法产生了这个数字？”一个月后答复。
  • 审计账本将每条记录链接到其前任的哈希和 fsync。编辑或删除记录是可检测的，并且重新计算其自身哈希值的编辑稍后仍会通过 prev_hash_mismatch 捕获一条记录。时间戳始终由调用者提供；这里没有模块调用datetime.now()。
  • 跟踪编辑是接收器感知的：content 仅在工具结果接收器中发布，并在工具调用参数和实时审计分类账使用的失败关闭参数接收器中保持编辑状态。 env 从未发布。结果字符串经过模式清理，因为 shell 输出以 JSON 信封形式到达。
  • 所有 30 个群体预设 都经过重新审核 - 没有授予工具可以计算的交付物现在被声明为这样，而不是发明的。

🧱 平台

  • 桌面 shell — 拥有后端生命周期的源优先 Electron 主机：随机环回端口、每次启动秘密、五种语言环境启动恢复、拥有进程清理 (#923)。 Windows 打包组装了一个校验和固定的嵌入式 Python 3.12 运行时，带有 x64 NSIS 审查/签名路径，加上用于许可名单凭证集的 Electron safeStorage - 渲染器可以设置或清除秘密，但永远不会读取它们，纯文本配置迁移一次，并且未签名的审查和签名的构建都无法在错误的签名状态下关闭（#1015）。 该 PR 中未发布任何安装程序工件。
  • eToro 作为 第 13 个经纪商连接器 加入，具有路径分隔的演示/真实配置文件；演示密钥在结构上仅到达 /demo 路径 (#989)。
  • 韩国 (KRX: KOSPI/KOSDAQ) 成为第 9 个回测引擎 — 统一报价网格上的执行时间 ±30% 范围，结构上仅限多头，配置驱动的 2026 0.20% 证券交易税 (#693)。
  • 加拿大股票端到端 - .TO/.V 分类为加元，雅虎 → yfinance → 本地，加拿大特定的 GlobalEquity 规则，XIC.TO 基准，混合货币聚合被拒绝（#1024、#1019、#1037、关闭#952）。
  • OpenBB Workspace 桥 (#817) 和只读 Taiwan snapshot 工具 (#848)。
  • src/entities — 一个类型实体+用于资产净值、capital 看涨期权和优惠券的不规则日期现金流基底，故意与条形引擎平行，因此 nav 列永远无法达到一个并以收盘价定价。由 cashflow_performance 浮出水面。
  • orderbook_depth — 通过 ccxt 的加密 L2 阶梯：价差基点、深度不平衡以及规定名义的影响成本双向遍历真实书籍。
  • ModelScope 加入内置提供程序 (#1011)； vibe-trading update 自我升级并将车轮安装与可编辑结账区分开来（#1020）； 设置获得实时模型发现并记录实际为每个回复提供服务的不可变提供者/模型/推理身份（#924）。
  • MCP 表面增长到 70 个工具。 alpha_zoo + 有界 alpha_bench (#979) 和 QVeris 发现/检查/执行（#976，从市场读取成本报价，而不是从调用者处读取 trusted）加入，六个已到达代理但从未到达 MCP 的只读分析工具 — quantlib_call、cashflow_performance、 orderbook_depth、sentiment、technical_indicators 和 get_fundamentals。下单工具在结构上仍然不公开：镜像注册路径拒绝任何 is_readonly 不是 True 的类。
  • 内存层 2 — 分层路由、BM25 语义链接、TF-IDF 压缩和具有 CJK 二元标记化的 FTS5 索引，位于单行 VT_MEMORY=off|on|full 预设后面。默认情况下全部关闭（#815、#733）。
  • 新的只读工具：sentiment (#939)、technical_indicators (#921)、分析 options_payoff (#946)。

🔒 沙盒

弥补差距：生成的策略代码可以导入代理层，并且可以通过重命名的绑定**到达socket / subprocess / os.system / ctypes **。之前都被接受了；现在两者均被拒绝。 src.quantlib仍然进口。

✅ 正确性——昂贵的

  • SEC 报告期以 (start, end) 跨度为关键。 10-Q 在相同的结束日期和会计周期下归档真实季度和年初至今的框架，因此 period="annual" 已返回 AAPL 2018-2020 财年的单个季度 — 4.2× 轻描淡写 — 并且季度系列中的每个第四财季时段都包含全年数据。
  • Tushare A 股价格在因子基准测试和回溯测试中均经过公司行动调整。除息日的原始收盘回报率高达 47 个百分点（300750.SZ，2023-04-26）。 CSI300 基准还掩盖了其时间点指数成员身份的每个日期。
  • bar_returns 不再消除超过远期填充窗口的交易暂停的波动 - 恢复波动被默默地记录为 0，低估了波动性并夸大了夏普。
  • 年化现在涵盖每个时间间隔的所有 24 个数据源，当装载机在没有条目的情况下着陆时，覆盖测试会导致 CI​​ 失败。
  • 跨市场综合回测拒绝混合货币代码集，而不是将人民币、美元和韩元汇总到一条股票曲线中。
  • 期权腿以开仓时的波动率标记，消除了高达 +93% 溢价的捏造零日损益。
  • 19-PR 间隔标准化扫描 - 小写 1h/4h/1d/1w 随处接受，不受支持的间隔快速失败，而不是默默地返回每日柱。
  • 两个 quantlib 模块已列入允许名单，但无法访问。 attribution (Brinson-Fachler) 和 impact（市场影响模型）没有携带 __all__，而 quantlib_call 仅在 ZZPH100​​ZZ 上调度 - 因此该工具列出了这两个模块的 零 功能，而包文档字符串则宣传了它们。现在两者都导出，并且当任何列入白名单的模块不公开任何内容时，防护测试都会失败；现有的测试仅断言每个模块导入，这永远无法捕获这一点。
  • 发布的 MCP 清单低估了服务器。 SKILL.md 的工具计数是通过计算 @mcp.tool 装饰器得出的，它忽略了通过镜像路径注册的每个工具 - 因此有四个机构研究工具在 MCP 上运行并且不在清单中，并且合同测试断言缺席是正确的。两项测试现在均测量 mcp.list_tools()。
  • 资源泄漏已关闭：HTTP 节流阀可清除陈旧的存储桶间隔感知，速率限制器不再使用唯一的 client IP 无限制增长，事件总线在清除时通知并删除订阅者，并且 _json_loads 可以防止数据库列中损坏的 JSON。
