Vibe-Trading v0.1.15

自 0.1.14 以来，汇总了 551 次提交/162 次合并拉取请求，从 35 次 贡献者。 本周期的主题是数据说明一切。现在有价格框架 带有其所服务的调整口径。一个因子传播 其投入的缺口而不是填补它们。无法提供服务的装载机 市场不再声称它，并且无法刷新的源是一个错误 而不是较小的投资组合。其中三个穿着相同的虫子 不同的衣服：默认情况下会默默地替换一个合理的值 缺失的一个，与真实的下游无法区分 观察。三个新市场、第十四个经纪商和十五个量化交易商 图书馆的新增内容也随之而来。

添加

  • 英国股市（#1206，感谢@cgycorey）——LSE .L 和 .IL 符号端到端：市场数据、雅虎支持的财务报表和 指标、uk_equity 的贸易期刊推断及其自己的引擎 路径。 SDRT 按照实际情况进行建模 — 0.5% 的关税 仅购买一方，而不是对称的往返费用。为两者充电 双方将每次往返的费用夸大了一半，这正是 均值回归策略所依赖的边缘大小。
  • Zerodha Kite Connect（#1193，感谢@ashutoshsinghpr7）——第十四个 印度股票的经纪商连接器。 Kite 没有暴露运行时论文/实时 鉴别器 — 无账户 ID 格式、主机分离、演示标志或交易 环境 - 因此在红线下方它的上限为纸张加上只读： place_order 和 cancel_order 硬拒绝任何非纸质配置 第一行，不存在可供选择的 *-live-trade 配置文件。那现在 涵盖 Longbridge、Dhan、Shoonya 和 Zerodha； Trading212 更进一步 拒绝所有订单下单，包括纸质订单。
  • 只读多经纪商投资组合（#1072，感谢@goatyyc；入门 #1250 中的合约）——每个启用的聚合快照 连接实例，可通过四种方式访问：Web /portfolio 页面、REST 在 portfolio_routes.py、portfolio_summary 代理工具下，以及 vibe-trading portfolio show | refresh | sources。三大设计要点 这并非偶然：无法刷新的源是一个错误 从总数中排除（状态 error、last_success_at、 complete=false)，绝不是结转缓存，因此是部分快照 无法解读为较小的投资组合；每个 remote_mcp 读取通过 interactive_oauth=False，因此聚合永远不会弹出身份验证提示； 并且 analysis_context() 携带 risk_xray_args 所以 portfolio_risk_xray 是“喂养”而不是重新实现。资格是一项规则—— is_portfolio_connection_profile 需要只读 和 account.read 和 Positions.read — 其下为 IBKR 官方 MCP 配置文件，其中 仅宣传发现，正确地不是投资组合来源。
  • 定量图书馆，十五个补充（感谢@santhreal） - Heston (1993) 随机波动率期权定价（#1195）；分层风险平价 分配（#1196）；阿基米德和高斯关联分析 (#1197)； 市场微观结构分析——VPIN、滚动价差、Amihud 流动性不足、 凯尔的 lambda (#1198)；具有现金回扣的分析单一障碍期权 处理（#1163）加上有限差分灵敏度希腊语 （＃1203）； ISDA 标准模型单名 CDS 估值引擎 危险率转换（#1164）；关键利率持续时间分解 基准期限（#1165）； Vasicek 信用组合损失模型和 传播 DV01 (#1167)；截面因子 信息 系数 时间 系列（#1166）； Ornstein-Uhlenbeck 精确校准半衰期 （＃1161）；溃疡和疼痛指数的回撤分布分析 （＃1162）； Corrado 秩和 Cowan 广义符号非参数 事件研究测试（#1160）；使用欧拉进行多因素风险分解 边际贡献，报告 unmatched_weight 而不是 将其标准化（#1159）；和组清除的 k 倍交叉验证 面板数据（#1168）。该层的规则始终成立：公式有 正是一种实现，并且技能导入它而不是携带 SKILL.md 代码块中的源代码。
  • 巴西葡萄牙语语言环境 (#1327，感谢 @nandofmike) — 第八个 运语言，登陆全键平价。奇偶校验套件 glob locales/*.json 而不是列出语言，因此涵盖了新的语言环境 文件到达之日；德国此前曾以完美平价发货 覆盖率为零，因为该列表是手写的。
  • Nobitex 和 Wallex (#1263，感谢 @Emad211) — 只读伊朗语 在无密钥公共 UDF 端点上交换源，仅限显式源。 两者都位于 _NO_NETWORK_FALLBACK_SOURCES 并被禁止使用加密货币 故意的后备链：它们是唯一引用 Toman 的来源，并且 声明 markets={"crypto"} 纯粹是可达的，因此降低了 对该链的不可用 BTCIRT 请求将返还 USDT报价系列就像Toman一样。
  • 币安 USD-M 证据路径（#1229、#1230，感谢 @honginp；#1248、 感谢 @lorenzozanee) — 只读 USD-M 账户快照、漂移证据 将模拟填充与记录填充进行比较的伪影，以及 从这些记录中得出的确定性公差校准 比假设的。关键是公差有一个来源：它是 根据实际填充进行测量，而不是选择。
  • 离线评估工具（#1271，感谢@AirHua-byte）-验证运行的 持久化工件（提示保存、工具调用和结果、 身份、证据、提供商使用情况、迭代预算、RunManifest 完整性）针对版本化案例/判决模式，没有 LLM、网络、 代理或 MCP 调用：它仅读取文件。缺少仪器会发出 NOT_EVALUABLE 而不是通过，这就是重点 - 缺失 字段不得被解读为良好行为。
  • 人择提示缓存（#1366，感谢@averatec0773）——一个明确的 系统块上的缓存断点，因此静态工具+系统前缀是 从缓存中读取而不是按全价重新发送，并记录缓存使用情况 在使用信封中。仅本机适配器，位于后面 VIBE_TRADING_ANTHROPIC_PROMPT_CACHE;如果有兼容的代理，则将其设置为 0 拒绝 cache_control 请求参数。
  • 每个市场数据源优先级（#1231，感谢 @sambazhu）- 设置 卡和 MARKET_DATA_ORDER_* 环境覆盖重新排序市场 后备链。验证为默认的多集排列，因此 添加、删除或复制源时重新排序通道是 拒绝，默认有效。覆盖作为 setitem 应用于 相同的 dict 对象，因为 runner.py 和 market_data.py 导入 按名称命名为 FALLBACK_CHAINS 并重新绑定将使它们保留旧顺序。
  • 日历触发的部分重新平衡（#1277，感谢@thisisjun786） 和一个与评估窗口分开的数据窗口，所以热身 条形图不再计为评估，且策略不会在条形图上评分 它需要被定义。
  • 特工确认的预定研究（#1187，感谢@AirHua-byte）和 每个监视器在作业列表上呈现的最新判决（#1156，谢谢 @he-yufeng），因此重复性作业的状态无需打开即可清晰读取。
  • Swarm 重播和重试（#1158，感谢 @cgycorey；vibe-trading swarm #1194 中的重试 --resume，感谢 @SiMinus) — 恢复失败或取消的任务 DAG 运行，同时保留已完成任务的工件， 而不是再次为整个图表付费。
  • 订单计划拒绝报告（#1245，感谢@lorenzozanee）——一个 _on_plan_rejected 钩子加上一个运行级别报告 引擎想要但无法进行的交易。被拒绝的计划 之前已经消失了，所以这个策略正在被无声地扼杀 购买力看起来与没有信号的购买力相同。
  • 只读币安连接器加密身份（#1242，谢谢 @pengpengyi92）和公共场所目录对解析，所以是一个加密对 根本不需要代理连接即可解决。
  • 网络聊天中的多文件拖放和粘贴上传（#1179， 感谢@AirHua-byte）。

已修复

缺失的数据不再被合理的值填充

  • Alpha Zoo NaN 合约，在注册表中强制执行（#1377，关闭 #1376，感谢 @cgycorey) — factors/base.py 在自己的合约中声明了合约 header: NaN 通过预热和丢失数据被保留，没有沉默 fillna(0)。在比较中与 np.where 分支的 alpha 违反了它，但看起来并不像它那样，因为 NaN 比较是 False 和三元落入其常数。消隐每个 在整个动物园的一个条上声明输入，返回 462 个 alpha 中的 84 个 无论如何都是一个数字 - 因为 dropna() 是保持间隙的机制 在 IC 中，每个制造的 ±1 都被作为真实信号消耗。 Registry.compute 现在将输出屏蔽为 NaN，只要声明了 该栏缺少依赖项，随后进行相同的扫描发现 无。单独固定在路上：gtja191_004 (#1371)， gtja191_003 和 gtja191_059 (#1372)、gtja191_069 (#1373)、gtja191_019 和 gtja191_086 (#1379)、alpha101_007 和 alpha101_051 (#1380)、alpha101_009 和 alpha101_046 (#1381)、alpha101_021 和 alpha101_024 (#1382)、 alpha101_010/023/027 (#1383) 和 alpha101_049 的热身面罩 (#1374) — 谢谢@Shizoqua。 **声明而不是悄悄进行：**热身部分 仍然开放。以同样的方式测量，52 个 alpha 仍然在内部发出一个值 他们自己声明的 min_warmup_bars （gtja191_154 声明 198 和 在第 0 行发出），因为在这些条上存在输入并且仅 滚动窗口未定义。注册表级预热掩码也会空白 其声明仅过度声明两到三倍的 alpha 行 栏，因此一半需要方向调用而不是 52 个拉取请求。
  • 默认情况下 pct_change() 前向填充（#1397、#1398、#1399、#1400、 谢谢@Shizoqua； #1172) — pandas 仍然默认 pct_change() 向前填充，因此缺失的收盘价将成为 0.0% 的回报，而永远不会 发生，下一个柱将两天的走势报告为一天。四个 PR 每个固定一个呼叫站点；扫技能穷尽发现24个站点 跨 10 个文件，其中两个位于这些 PR 所在的文件中 编辑。该课程现已在整个存储库范围内关闭：SDM 策略模板 (#1397)、跨市场波动权重 (#1398)、多因素 TopN 选择现在排除没有因素观察的资产，而不是 将它们排名为零（#1399），并且情感因素正交化 不再回归到它自己填充的零（#1400）。阿尔法动物园回归 在 #1172 中停止向前填补空白。
  • 幸存者偏差披露到达报告（#1289，谢谢 @bonyohana) — 标志被计算出来，然后不在 HTML 工作台中呈现 报告，与上一级的故障模式相同：存在一个警告 在数据中而不是在读者所看到的内容中。

价格说明了它们的口径

  • 调整口径印在服务框架上（#1317，关闭#1301， 感谢@he-yufeng）——框架现在带有其价格的实际含义。 仅在针对实时有效负载进行测量的情况下记录口径或 由加载程序自己的端点选择固定；任何无法衡量的事情都会解决 unknown 是故意的，因为原点侧调整是不可见的 加载程序代码 - 雅虎提供带有零调整逻辑的分割调整报价 在这个仓库中。
  • 仍然将股息记作损失的装载机（#1287，#1288， 谢谢@he-yufeng； #1320，感谢 @lorenzozanee) — 雅虎、FMP 和 Tiingo 路径服务于调整后的价格，并且未解析的符号现在重试 后备链，而不是停在第一个缺少它的源处。
  • 明确的来源本身回答（#1276、#1342、#1185、#1316、 感谢@lorenzozanee、@he-yufeng、@cgycorey) — FMP 已移至稳定版 端点，并且在明确命名时不再默默地回退；斯托克的 反机器人挑战被标记而不是被解析为数据，这是 “无数据”和“JavaScript 页面解释为价格”之间的区别； 代码、日期范围和来源在获取之前进行验证，而不是 在它之后；并且交易品种搜索与外汇对和索引的获取保持一致， 所以你搜索到的东西就是你得到的东西。
  • 腾讯历史分页（#1154，感谢@BigFishEmily）-长范围 被默默地截断到第一页。

期货到达正确的引擎，现在有了来源

  • 分类（#1369，#1389，感谢@Shizoqua；#1396，感谢 @he-yufeng;以及全局端的 349bf202） — 数字前缀和 月份代码冲突的产品代码，Tushare 自己的交换拼写 (SHF/CZC/CFX/GFE)，外壳在提取时折叠，而不是每次折叠 查找并注明日期的全球合同（CL2412.NYMEX， ESZ4.CME) 每个都通过每个模式达到 a_share 默认值。一个美国 原油合约因此以T+1运行，没有做空，结算于 人民币。
  • 覆盖率 (#1395) — 装载机链是最后一个环节，它是 空的。它命名为 tushare 和 akshare，都没有实现 期货端点：ETF/指数/的tushare._fetch_daily_frame分支 HK 并将其他所有内容发送至 A 股股票端点 daily()， 而akshare._fetch_one则以# Default: try A-share结尾。 AK 立即分享 通过无代币的新浪每日端点提供中国合约，注明日期和日期 主线连续，在上海期货交易所（RB2601、RB0）、中金所（IF2512、 T2512)、GFEX (SI2601) 和 ZCE (MA2605)。全局合约返回空并且 达到 local 而不是作为股权定价。修剪 tushare 的 markets 单独设置是行不通的：resolve_loader 走链条 并且从不咨询 markets，所以 tushare 会排在第一位。 主连续合约 (RB0) 也已被路由 - 一份有日期的合约仍然存在 大约一年，所以任何比合同周期长的回测都必须命名 卷系列。
  • 中国期货保证金来源（306aca2c，收盘#1393）——现在正在运行 说明哪些产品是按照通用默认值而不是表格定价的 条目。 rb的实际保证金率为0.10，与默认数字相同，并且 “查找”不得读作“假设”。

实时交易失败关闭

  • 经纪人读到的不是答案（#1212，#1232，感谢@he-yufeng； #1244、#1254，感谢 @cgycorey) — 位置读取返回 API 错误， 和到达停止扫描中间的误差包络，都被视为 成功的空结果。扫描现在仅锁定它的剧集 实际上在每集闩锁文件下扫描，并且仅在尝试之后 副作用。
  • 必须在重启后继续存在的状态（#1233，感谢@he-yufeng；#1213， ＃1221，＃1222，感谢@Elfsa-Miranda）-扁平闩锁仍然存在 跑步者重新启动，未解决的羊驼提交在经纪人之前拥有 通过精确的 client ID 写入和恢复，包括填充，因此重新启动 中期提交不能产生重复项或孤立项。
  • 订单大小和时间（#1312、#1361、#1253，感谢@he-yufeng 和 @cgycorey； #1209) — 限价买入订单的大小按报价中的最差者确定 对两种传输的限制，市场触发的价格变动会被跳过，而 休市，羊驼持仓数量在开市前双方签字 到达任务门。
  • 任务门在两个方向上变窄（#1285，感谢@Jackzigen）
    • 强制缩小非数字和列表语义的变化 调整还拒绝了 "none" 作为无效类型，这使得大多数 保守派授权不可提交。九个 CI 检查是绿色的： 八个新测试都是 raises 断言，单向套件不能 看到一些应该被允许的事情被拒绝了。
  • #1207 小批量中的四个连接器间隙（#1388，谢谢 @he-yufeng) — 高于交易品种交易量上限的 MT5 订单悄无声息 夹紧并发送，而低于最小值的一侧出错（关闭失败 现在命名帽子）；没有 limit_price 的 eToro 限价订单发出为 没有 TriggerRate 的 MIT，在阅读时未触发 已接受；富途K线继承了未公开的调整口径；和裸露的 BTCUSDT通过A股规则——T+1且不做空， 永久的。
  • 当没有验证任何内容时，报告审核失败关闭（#1362，谢谢 @cgycorey）——检查零索赔的审核返回“通过”。

回测执行语义

  • 选项（#1299，#1305，感谢@cgycorey；#1306，感谢@he-yufeng； #1177) — 信号填充在 下一个 条上，而不是它们所在的日期 计算得出，这让策略以生成的价格进行交易 它自己的信号； HV 预热条使用配置的默认 IV，而不是 未定义的；空头期权腿保持保证金，买入大门打开 权力，因此裸空头无法再卖出它永远无法回补的溢价； 并且根据实际日期验证明确的到期日期 可以向邻居提供，而不是默默地解决。
  • 短裤、重新平衡和会计（#1298、#1344、#1281，谢谢 @cgycorey) — 1x 空头在非严格模式下因不利走势而清算；一个 过度投入的重新平衡篮子规模以适应而不是中止 佣金透支；和请求的目标更改是分开的 执行的重新平衡填充（关闭#1275），因此重新平衡计数显示为 读者是填充的数量而不是意图的数量。
  • 通过复合状态进行市场规则（#1309、#1332、#1370，谢谢 @he-yufeng 和 @Shizoqua）——A 股和印度规则是通过 复合状态而不是每个引擎，最后一个停止位置标记 交易接近，而不是进入成本，子引擎的活动符号是 在每个复合调度之前同步，而不是每个柱同步一次。
  • 永续合约和外汇（#1307，感谢@he-yufeng；#1226，感谢 @P1Piyush) — 资金按 8 小时以上间隔的柱跨度结算，而不是一次 每根柱线，外汇金属被视为点大小、手数大小和 传播。 50 盎司黄金订单已四舍五入为零。
  • 符号路由到引擎（#1351，感谢@cgycorey） - 点状美国 类别股票（BRK.B.US、BF.B.US）获取空图表。
