netdata v2.12.1

修订 发布时间2026年10月8日 来源netdata/netdata 英文原文

netdata v2.12.1

这个项目是干啥的：一个开源实时监控工具，能看服务器和容器的CPU、内存等各项指标，给想盯紧机器状态的运维人员用。

变更架构图

亮点

  • 无破坏性变更，也无需迁移 — 这是维护性补丁，不是重新打标或仅改元数据的版本。跑 Windows Agent、eBPF、Docker Engine 29+ 或高负载 dbengine Parent 的建议升级；如果 v2.12.0 在你的环境里稳定，其余情况可以放心跳过。
  • Windows 可靠性 — 修复了因捆绑的 Cygwin 回填不完整导致的 msys-2.0.dll 启动访问违例；MSYS2 运行时已重建，打包时现在会固定并校验其版本。时区检测不再越界读取，也不会对未映射的 IANA 时区吐出乱码：解析属性时改用有边界的拷贝，优先采用用户所在地区，失败时保留原有时区。
  • eBPF 兼容性与崩溃修复 — 把 ebpf-co-re 同步到 v1.7.0.3、kernel-collector 同步到 v1.7.0.4，提升了磁盘和进程探针的兼容性，包括没有 BTF 的主机。还修复了 possible CPU 数超过 online CPU 数时的堆损坏、旧版 libbpf 在对象或 BTF 加载失败时的崩溃，以及命令行分发错误，使 --unittest 等选项能按文档工作。
  • Docker 采集器的效率与准确性 — 通过最多每五分钟刷新一次镜像列表、并把默认 update_every 从 1 秒改为 10 秒，降低了 dockerd 和 containerd 的负载，Docker Engine 29+ 的 containerd 镜像存储尤其受益。采集和镜像发现的频率因此下降；同时修复了与 API 版本低于 1.51 的守护进程通信时，活动镜像和悬空镜像计数不准的指标问题。
  • 数据库与平台相关修复 — 移除了仅用于调试的 dbengine 数据文件删除扫描，它会遍历并锁住整个清理队列，现在高负载 Parent 的开销降低了。Redfish 现在接受 HPE iLO 返回的同源 URI 别名，不再让任务永远停在 partial；SMBIOS Memory 只在 Linux 上构建，避免在 macOS、FreeBSD 和 Windows 上必然失败的默认任务。

netdata v2.12.1 版本更新了什么

Netdata v2.12.1 是一个补丁版本，用于解决自 v2.12.0 以来发现的问题。

此版本修复了 Windows 代理中的启动崩溃和时区检测错误，在更广泛的内核和 libbpf 版本中稳定 eBPF 收集器，减少了 Docker 收集器对 Docker 守护进程的负载，并消除了繁忙父进程上 dbengine 数据文件删除中不必要的工作。

窗口

  • 修复了 Windows 代理在启动时因 msys-2.0.dll 内的访问冲突而崩溃的问题。捆绑的 MSYS2 运行时携带了上游 Cygwin 更改的不完整向后移植；软件包现在提供了一个使用缺失的上游修复程序重建的运行时，MSYS2 安装程序由标签和校验和固定，如果预期的运行时不是所提供的，则打包失败（#24170、@stelfrag）
  • 修复了当 Windows 时区在 IANA 映射中不匹配时 Windows 时区检测报告垃圾或读取超过其缓冲区的问题。现在，映射由具有有界副本的属性进行解析，用户的区域优先于世界默认区域，并且在失败时保留现有时区（#24101、@stelfrag）

eBPF 收集器

  • 将 eBPF 收集器与 ebpf-co-re v1.7.0.3 和 kernel-collector v1.7.0.4 同步，重新设计磁盘和进程探针以获得更好的内核兼容性，包括没有 BTF 的主机（#24008、@thiagoftsm）
  • 修复了 ebpf.plugin 在可能的 CPU 数量超过在线 CPU 数量的主机上因堆损坏而中止的问题，例如 VMware guest 虚拟机（#24008、@thiagoftsm）
  • 修复了无法在旧版 libbpf 版本上加载 eBPF 对象或 BTF 数据时发生的崩溃（#24008、@thiagoftsm）
  • 修复了 ebpf.plugin 对大多数命令行选项运行错误的操作，因此 --unittest 等选项现在按其所说执行（#24008、@thiagoftsm）

数据库

  • 删除了对每个 dbengine 数据文件删除时运行的打开缓存的扫描，仅用于提供从发布版本编译出来的调试检查。扫描在其锁下遍历整个干净队列，这对于繁忙的父级来说可能很大（[#24162]（https://github.com/netdata/netdata/pull/24162），[@stelfrag]（https://github.com/stelfrag））

收藏家

  • Docker：减少了收集器在 dockerd 和 containerd 中造成的 CPU 负载，这对于带有 Containerd 映像存储的 Docker Engine 29+ 非常重要。图像列表现在最多每 5 分钟刷新一次，并且模块的默认 update_every 从 1 秒提高到 10 秒（#24146、@ilyam8）
  • Docker：修复了协商 1.51 之前的 API 的守护进程上的图像使用指标，其中每个图像都被计为活动图像，而悬空图像始终报告为 0。使用情况现在源自每个集合上的容器列表（#24147、@ilyam8）
  • Redfish：配置表单现在仅显示使用它们的身份验证方法的用户名和密码（#24106、@ilyam8）
  • Redfish：修复了收集器永久跳过 @odata.id 与从中获取资源的 URI 不同的资源的问题，例如尾随斜杠变体以及 HPE iLO 返回的重新映射的网络适配器和存储路径。受影响的作业仍处于 partial 状态，并发出长期 redfish_collection_status 警告。现在接受同源别名，其他 URI 安全检查仍然适用，拒绝报告具体原因（#24186、@ilyam8）
  • Ceph：从配置表单中删除了杂散选项选择器，并阻止 Redfish TLS 设置渲染重复的选项卡条（#24108、@ilyam8）
  • SMBIOS 内存：收集器现在仅在 Linux 上构建，Linux 是导出其读取的 SMBIOS 表的唯一平台。在 macOS、FreeBSD 和 Windows 上，其库存作业通常会以 read SMBIOS entry point: ... no such file or directory 启动和失败（#24169、@ilyam8）
