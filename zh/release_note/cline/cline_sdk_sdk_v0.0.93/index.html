cline v0.0.93

修订 发布时间2026年10月13日 来源cline/cline 英文原文

变更流程图

亮点

  • 插件执行改为进程内（可能需要迁移） — 插件通过一个进程级注册表加载，编译后的 CLI 和 hub 不再需要 PATH 上有 Node/Bun；Bun 构建的 hub 还暴露 Bun 全局。每个会话拿到独立的插件模块副本，保留模块级状态；超时和生命周期追踪把失败通过 session.create 的 plugins 策略、pluginIssues、plugins.list/plugins.status/plugins.reload 和 plugin.status_changed 暴露出来，而不是静默丢工具或停掉 daemon。如果你依赖子进程隔离，请设 CLINE_PLUGIN_MODE=sandbox。

  • 推理控制现在感知 provider — 关闭推理不再局限于原先固定的 provider 列表。没有关闭选项的模型保持默认，没有 reasoning 能力的模型会被跳过，Gemini/Vertex 只在声明了预算时收到 thinkingBudget，仅有级别的 Gemini 模型改为收到思考级别。原生控制（如 effort 或 thinkingConfig）优先，一个请求绝不会同时带原生和可移植控制。

  • 图片密集型会话不再无谓自动压缩 — estimateRequestInputTokens 和 createTokenEstimator 现在每张图按固定的 ESTIMATED_TOKENS_PER_IMAGE 1600 计，而不是把 base64 负载按文本计费。约 90 KB 的截图以前算作约 3 万 token；@cline/shared 还导出了 createImageAwareReplacer。另外，目录条目没有上下文窗口但所选模型覆盖有值时，压缩会采用该覆盖值，修正了错误的预算。

  • 定时任务明显更可靠 — 排队任务在 bun:sqlite 下能正确认领（之前把命名参数绑定成 NULL，导致桌面 hub 从不认领，一直挂起且无报错）；provider 错误结束的任务记为 failed 并带错误信息，同时保留使用量和工具调用；被更新实例取代的 cron 事件会被取消，不再把整段积压连续重播。符号链接的规则文件现在能从配置目录加载并随刷新更新目标编辑，.claude/skills 也让 Claude Code 编写的技能可见。

  • 升级前需审核的 API 与模型默认变更 — 破坏性：resolveComposioToolsStatePath 改名为 resolveComposioConnectionStatePath，请更新 import。Composio 现在通过元搜索发现工具，并支持通过 connectorsRequest（@cline/core 导出的 ConnectorsRequest）做 host 认证。Cline 和 OpenRouter 默认改为 anthropic/claude-sonnet-5.5，CLINE_DEFAULT_MODEL_ID 从 Claude Sonnet 5 升到 5.5，OpenCode Go 的 base URL 改为 https://opencode.ai/inference/go/v1。目录从 6,572 增到 6,862 个模型，新增 AI/ML API、LowRouter 和 Prime Inference，并改变大量 provider 默认值。插件、定时任务、截图密集和模型默认相关的用户应升级；不受这些 API 变更影响的纯文本负载可以安全跳过。

  • 插件通过每个进程一个注册表而不是节点/bun 子进程进行进程内加载，因此编译后的 CLI 及其集线器不再需要 PATH 上的运行时，并且插件可以使用 Bun 构建的集线器下的 Bun 全局。 CLINE_PLUGIN_MODE=sandbox 保留子进程沙箱。注册表通过超时和错误捕获包装导入、设置、挂钩、工具和命令，并跟踪每个插件的状态（加载/就绪/降级/失败/禁用）及其最后一个错误。失败的插件不再默默地删除其工具：session.create 接受 plugins 策略并返回 pluginIssues，以后的故障以状态通知的形式到达受影响的会话，集线器应答 plugins.list/plugins.status/plugins.reload 并广播 plugin.status_changed，守护程序将插件标记为失败，而不是在出现未捕获的错误时关闭。每个会话都有自己的每个插件模块的副本，因此在模块级别保持每个会话状态的插件可以继续工作

  • 关闭推理现在适用于每个提供商，而不仅仅是固定列表。目录条目没有关闭选项的型号不会发送任何内容并保留默认值，并且会跳过没有 reasoning 功能的型号。 Gemini 和 Vertex 仅向宣传预算的模型发送准确的 thinkingBudget 值；仅级别的双子座模型会获得思考级别（他们拒绝了 thinkingBudget）。请求永远不会同时携带可移植推理选项和本机提供程序控制（effort、thinking、thinkingConfig，…）；本地人获胜

  • cline 提供商的默认型号是 Cline 推荐型号列表中的第一个条目，后退到 anthropic/claude-sonnet-5.5。 CLINE_DEFAULT_MODEL_ID 从 Claude Sonnet 5 移至 Claude Sonnet 5.5，openrouter 提供商默认值现在也是 anthropic/claude-sonnet-5.5

  • estimateRequestInputTokens 和 createTokenEstimator 不再按文本速率对 Base64 图像有效负载进行计费。约 90 KB 的屏幕截图相当于约 30k 令牌，因此一些图像早在文字记录接近预算之前就触发了自动压缩。现在，每个图像都会添加一个平面 ESTIMATED_TOKENS_PER_IMAGE (1600)。新款createImageAwareReplacer出口@cline/shared

  • 自动压缩使用已解析模型的上下文窗口。当发现的目录条目没有限制但选定的模型覆盖有限制时，压缩将交给裸目录条目并运行错误的预算

  • 计划运行：在 bun:sqlite 下正确声明排队运行，这将存储的命名参数绑定为 NULL，因此桌面集线器从未声明排队运行，并且它保持挂起状态，没有错误。其代理回合以提供程序错误（例如已退役的模型 ID）结束的运行现在被记录为失败并带有错误消息，而不是默默地成功，并且运行报告会保留使用情况和工具调用。排队的 cron 事件被同一计划的较新事件取代被取消，因此积压的 cron 事件不再连续重播每个错过的时间段

  • 作为符号链接的规则文件现在从配置目录加载而不是跳过。对链接目标的编辑将在下一次刷新或新会话中进行

  • resolveSkillsConfigSearchPaths 扫描 .claude/skills，因此为 Claude Code 编写的技能对 Cline 可见

  • 编辑器工具将 old_text 作为纯字符串进行广告。当架构允许 null 时，某些模型会发送 null 而不是替换文本。 Null 在运行时仍被接受并被视为省略

  • Composio 连接器：登录会话注册 Composio 的元工具（搜索、管理连接、等待连接、多重执行），因此代理可以跨工具包查找连接器工具，向用户提供尚未连接的应用程序的连接链接，并运行它找到的内容。连接器工具是通过元搜索发现的；保存的桌面连接状态不再提供模型工具。主机可以通过新的 connectorsRequest 选项（从 @cline/core 导出的 ConnectorsRequest）提供自己的身份验证，该选项也会转发到计划的会话。 resolveComposioToolsStatePath更名为resolveComposioConnectionStatePath

  • @cline/core 中的 Cline 云登录助手接受 AbortSignal，因此主机可以在轮询时取消待处理的登录

  • 云会话刷新更新打开的会话，并在网络上重命名标题，并在刷新进行时保留本地重命名

  • 更新了模型目录（6,572 → 6,862 模型）。添加 AI/ML API、LowRouter 和 Prime Inference 提供程序。 models.dev 不再列出 v0，因此 v0 提供程序仅附带其默认模型 v0-1.5-md。 OpenCode Go 的基本 URL 从 https://opencode.ai/zen/go/v1 更改为 https://opencode.ai/inference/go/v1。 Cline 空闲列表添加了第 5 步预览。 302.AI、CrossModel、Cortecs、DigitalOcean、NEAR AI Cloud 和 Ofox (Claude Haiku 5.5)、DevPass (LLM Gateway)、LLM Gateway 和 Meta (Muse Wonder 1.0)、Aixy (GPT-6.1 Sol)、CloudFerro Sherlock 和 Moark (GLM 5.3)、Ambient、Ambient、 NanoGPT、Neuralwatt 和 Novita AI 完整 Changelog：https://github.com/cline/cline/compare/sdk/sdk/v0.0.92…sdk/sdk/v0.0.93
