openhuman v0.61.2

修订 发布时间2026年7月15日 来源tinyhumansai/openhuman 英文原文

此版本在协调代理、构建可靠的工作流程以及加强整个应用程序的隐私性、稳定性和可观察性方面向前迈出了一大步。向前！ 🚀

变更流程图

亮点

编排中心和代理车队控制🧠

编排成熟为真正的控制中心：以 TinyPlace 为中心的集线器和专用选项卡、用于批准和阻止运行的关注/“需要您”区域、类型化 v2 线束会话流以及用于管理会话的主聊天控制通道（包括更好的 DM 摄取/回复和更安全地处理无法解密的消息）。 这还扩展了可编排的内容 - 共置本地 CLI 代理、Cursor/Windsurf 线束支持、托管大脑 client 工作以及新的设备工具执行流程（具有 trust 门控和批准），以保持强大的操作可用且安全。 (#4588、#4589、#4592、#4609、#4623、#4627、#4652、 #4660、#4693、#4709、#4710、#4712、#4713、 #4720、#4722、#4725、#4738、#4753、#4773、 #4775、#4777、#4778、#4837) — 谢谢@oxoxDev、@sanil-23、@senamakel、@M3gA-Mind、@CodeGhost21 和@YellowSnnowmann！

从基础到完善的用户体验的工作流程（微小流程）🔁

工作流程演变为 rapidly：核心引擎接缝和域登陆，然后触发/恢复/历史记录、批准和 trust、运行检查、列表 + 导航、画布视图以及包含发现和运行的完整工作流程页面检修。构建者获得了重大的生活质量升级——实时目录基础、更清晰的输入处理、更安全的默认值和门控、更好的诊断以及失败运行的“通过代理修复”路径。 随后进行了一系列正确性修复：条件和路由验证、计划渲染、工具输出路径处理（包括无模式探测）、更好的运行诚实性（包括警告）、重复数据删除输出渲染、持续副驾驶聊天以及防止意外启动计划/副作用流。 (#4433、#4447、#4449、#4450、#4471、#4472、 #4474、#4477、#4552、#4561、#4570、#4573、 #4574、#4578、#4580、#4586、#4587、#4590、 #4591、#4602、#4605、#4606、#4607、#4608、 #4628、#4630、#4636、#4645、#4647、#4651、 #4659、#4662、#4663、#4664、#4665、#4668、 #4670、#4672、#4673、#4674、#4698、#4702、 #4707、#4750、#4822、#4823、#4826、#4834、 #4835、#4836、#4858、#4865、#4869、#4870、 #4874、#4876) — 谢谢@graycyrus、@senamakel、@CodeGhost21 和@YellowSnnowmann！

TinyAgents + 代理利用可靠性（以及更好的答案）🧩

一大波工具和 TinyAgents 迁移工作落地：具有检查点/HITL/可观察性的 agent_graph 状态机工具、迁移完成、结构化策略块消息传递、更好的“最终答案”保证、工具故障分类出现在 UI 上，以及增强的内存读取→重复数据删除→写入→索引契约（加上围绕不可用工具和无进展推动的长尾修复）。 大量的稳健性工作还涉及防止楔形转向和改进编排行为——超时、并行扇出、更安全的委托路径、更清晰的工具故障渲染、及时的状态调整以及更好的调度程序/cron 强化。 (#4261、#4362、#4372、#4386、#4399、#4400、 #4413、#4419、#4425、#4430、#4431、#4434、 #4443、#4444、#4445、#4473、#4476、#4478、 #4479、#4480、#4481、#4482、#4483、#4485、 #4495、#4502、#4504、#4507、#4509、#4512、 #4524、#4539、#4542、#4601、#4603、#4658、 #4682、#4683、#4686、#4741、#4748、#4751、 #4752、#4757、#4764、#4768) — 谢谢@senamakel、@M3gA-Mind、@oxoxDev、@sanil-23、@sanil-23 和@CodeGhost21！

内存引擎升级：TinyCortex 迁移🧠📚

通过分阶段的 TinyCortex 迁移，内存获得了基础升级：适配器接缝、类型统一、连接基础、块存储翻转（读取路径、批处理、列表），以及最后的完整引擎迁移——由奇偶校验工具工作和更新的覆盖范围支持。 在此过程中，出现了一些重要的质量修复：更安全的渲染垫片、更好的内存存储自我修复、更清晰的错误分类以及 Vault 运行状况和同步状态之间改进的可靠性信号。 (#4363、#4526、#4529、#4532、#4534、#4538、 #4546、#4547、#4551、#4555、#4559、#4781、 #4785、#4787、#4788、#4789、#4790、#4794、 #4820、#4699、#4700、#4703、#4340、#4410) — 谢谢@senamakel， @YellowSnnowmann、@CodeGhost21、@M3gA-Mind 和 @oxoxDev！

隐私模式和仅限本地执行🔒

隐私成为一流：隐私模式和仅限本地推理执行，加上出口描述符 + 披露事件、隐私状态表面、每个操作披露 UI 以及 PII/身份风险检测。 这项工作还扩展了跨集成和工具的仅限本地强制执行，使您可以在运行某些操作之前更轻松地了解哪些内容将（或不会）离开您的计算机。 (#4446、#4812、#4813、#4849、#4850) — 谢谢@oxoxDev！

可观察性和 Langfuse 追踪（更深入+更安全）🔭

跟踪和可观察性显着扩展：更丰富的 Langfuse 元数据、每轮一次跟踪、具有实际成本的跨代/工具/子代理的完整内容跟踪，以及图形/流运行的导出（包括代理-图形-视图元数据）。日志遥测现在提供 Langfuse 使用/运行见解，并且生成的子代理的跟踪父子关系已正确链接。 稳定性改进完善了这一点：分块摄取批次、降级噪声拒绝路径以及多个跟踪正确性修复（包括通过依赖项碰撞修复上游观察 ID 冲突）。 (#4498、#4499、#4506、#4562、#4568、#4676、 #4678、#4864) — 谢谢@senamakel、@M3gA-Mind 和@oxoxDev！

桌面稳定性、启动恢复和用户体验优化🖥️

跨平台桌面可靠性得到改善：Windows 启动时主动清理过时进程、macOS/Linux 过时锁 reaping 和安装程序预安装终止、用于错误处理/构建的更好的 Linux 链接，以及通过 SwiftShader 进行 CEF/Windows GPU 路由（以及 Windows CEF 前恢复的更严格范围）。 在用户体验方面，该系列添加了具有实时状态的远程核心连接设置、窗口几何持久性和最小化窗口恢复行为、更好的登录错误消息传递以及一组应用程序范围的标头/登陆标准化。 (#3793、#4405、#4406、#4643、#4644、#4649、 #4817、#4818、#4851、#4857、#4859、#4860、 #4805) — 谢谢@sanil-23、@M3gA-Mind、@senamakel 和@NgoQuocViet2001！

渠道和通讯：电子邮件、Telegram/WhatsApp、会议 ✉️

OpenHuman 获得了原生 IMAP/SMTP 电子邮件集成，并通过tinychannels 迁移和运行时边界继续在渠道上开展工作。 Telegram 配对和工具调用的可靠性得到了改善，历史摄取受到了背压，WhatsApp 损坏处理现在已恢复，而不是淹没 Sentry。 会议通过实时记录、改进的相关 ID、召回日历自动加入和 UI 改进、更丰富的机器人“说话”标记吉祥物姿势，甚至每个吉祥物语音 + 扬声器交替的双吉祥物来提升。 (#4367、#4414、#4569、#4549、#4557、#4349、 #4350、#4354、#4391、#4585、#4715、#4740) — 谢谢@oxoxDev， @senamakel、@graycyrus 和@YellowSnnowmann！

推理 + 核心运行时现代化 ⚙️

Inference 转向更干净、板条箱原生和 TinyAgents 驱动的架构：将调用者迁移到tinyagents ChatModel、解耦每轮状态、采用 ModelRouter 路由以及多个“Motion”步骤以将 BYOK 云 slugs 和 OpenAI/codex 路径切换到板条箱原生实现，同时还解决 SSE 挂起场景并确保保留原始 BYOK 模型 ID。 在平台方面，核心运行时获得了可插拔性和“舰队主机”，再加上DomainSet组合和编译时语音功能门。托管文件存储代理工具和表面存储传输工具也取得了进展。 (#4393、#4614、#4625、#4629、#4769、#4780、 #4782、#4783、#4784、#4298、#4791、#4808、 #4833、#4576、#4577) — 谢谢@senamakel、@oxoxDev、@sanil-23 和@YellowSnnowmann！

质量：CI、测试和发布管道🧪

该系列在构建和测试信心方面投入了大量资金：双通道 CI（精简版/完整版）、仅更改文件的 PR 通道和全套发布通道、测试审核和分阶段清理/回填、更快的 Rust 测试构建以及跨平台和发布“尾部”的许多 E2E 稳定性。 发布机制也受到了关注：工作流解析修复、完整的 dist 工件恢复、发布通道解锁和超时、分支/限制调整（包括上限移除）以及 CodeQL 警报接收器强化。 (#4486、#4488、#4489、#4492、#4494、#4497、 #4500、#4501、#4511、#4519、#4521、#4527、 #4530、#4531、#4533、#4540、#4543、#4548、 #4553、#4554、#4556、#4579、#4646、#4666、 #4671、#4701、#4721、#4759、#4827、#4830、 #4838、#4866、#4867、#4871) — 谢谢@senamakel、@M3gA-Mind、@CodeGhost21 和@graycyrus！

产品体验：聊天、角色、奖励、设置和文档 🎁

聊天和对话得到了重大升级：每轮流程历史记录和多阶段时间线重构、改进的减速器中的事件合并、更可靠的工具结果渲染、时间线锚定/重复数据删除修复以及聊天 v1 的 1M 上下文窗口调整。还有用户体验改进，例如处理时间线中的工具调用失败解释和更安全的取消范围。 其他地方：早间简报个性化、引导角色构建者角色模板、成就令牌奖励可见性、字体大小微调、标准化分析交互跟踪，以及主要文档更新，包括设置/恢复指南和重新组织的安装/工作流程/编排文档。 (#4373、#4416、#4424、#4612、#4604、#4622、 #4626、#4765、#4711、#4696、#4873、#4407、 #4508、#4514、#4515、#4792、#4493、#4510、 #4513、#4516) — 谢谢@M3gA-Mind、@senamakel、@oxoxDev 和@YellowSnnowmann！

整个应用程序中较小但强大的修复🛠️

一系列有针对性的修复提高了日常可靠性：停止 API 使用泛洪、在活动用户交换机上正确重新绑定状态、优雅地处理/公告/最新 404、更好的离线提供程序行为以防止 Sentry 泛洪，以及云模式下更安全的启动行为。 学习和 Agentworld 实用程序、连接清理正确性、MCP 目录添加、Windows 上的 shell 执行路由以及 Composio 批准停放行为也得到了改进。 (#4379、#4417、#4415、#4402、#4484、#4518、 #4697、#4717、#4723、#4758、#4584、#4704、 #4819、#4848、#4298) — 谢谢@oxoxDev、@mysma-9403、@CodeGhost21、@M3gA-Mind、@sanil-23 和@YellowSnnowmann！

基于语言的工作流程 (RLM/Rhai) 和“Codex”供应商工作 🧠🧰

基于语言的工作流程通过一流的 Rhai .ragsh REPL 工具和后续域重命名形成，并得到规划文档和更广泛的供应商战略工作的支持。 一组“codex”和供应商 PR 也落地了：TinyJuice/TokenJuice 工作、TinyChannels 运行时片段和提供商采用、tiny.place SDK 供应商和配对流程，以及保持堆栈一致的各种子模块更新。 (#4528、#4571、#4523、#4400、#4535、#4549、 #4557、#4560、#4575、#4620、#4491、#4563、 #4815) — 谢谢@senamakel！

其他亮点🔗

一些更有针对性的贡献使这个版本更加完善，其中有针对性的修复和改进值得一提。 (#4475、#4525、#4550、#4558、#4564、#4582、 #4599、#4611、#4621、#4624、#4642、#4694、 #4807、#4816、#4824、#4831、#4832、#4839、 #4842、#4875) — 谢谢@sanil-23、@senamakel、@CodeGhost21、@YellowSnnowmann 和@M3gA-Mind！
