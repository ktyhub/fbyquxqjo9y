✨ 新功能

  • 使用情况（配额百分比 + 提供商美元钻取）： @@om-usage 和 HTTP 使用端点现在将个人 API-key 配额报告为 剩余百分比（美元金额不包含在命令输出中），提供商剩余配额按配置的配额截止值缩放，因此受保护的储备读取为剩余 0%，并且配额仪表板重新获得 提供商美元成本钻取（/api/usage/provider-window-costs + ProviderUsdCostModal，管理授权门控）。还尊重观察到的提供商配额重置：检测到相同的 resetAt 重置（使用量回落到重置下限），并且优先于提供商 USD 窗口和 API-key 美元配额的过时记录的每周事件。新src/lib/usage/providerWindowCosts.ts。回归防护：tests/unit/provider-window-costs.test.ts、tests/unit/internal-usage-command.test.ts、tests/unit/api-key-usage-limits.test.ts、tests/unit/lib/quota-reset-events.test.ts。由 @Witroch4 从 #5863 中提取。
  • 仪表板（反向代理后面的实时 WS）： 实时仪表板 WebSocket 现在可以通过 NEXT_PUBLIC_LIVE_WS_PUBLIC_URL（例如 wss://ws.my-ai.com/live-ws）由反向代理或 Cloudflare Tunnel 前置。对于预构建的 Docker/npm 映像，该 URL 在构建时（env 内联到包中）和 运行时 均受到尊重：/api/v1/ws?handshake=1 握手现在回显延迟读取的 live.publicUrl（仅接受 ws:///wss:// 值；其他任何内容都被拒绝给 null），并且 useLiveDashboard 从中解析 URL连接前握手，回退到之前的 ws(s)://hostname:20129 默认值。还记录了 LIVE_WS_ALLOWED_HOSTS 并将 .env.example 中的 GitLab Duo OAuth 范围行与实时配置 (ai_features read_user) 对齐。回归防护：tests/unit/live-ws-public-url.test.ts (5)。 (#5877 作者：@ianriizky)
  • 提供程序（CLI 配置文件自动同步）： 选择加入切换以在提供程序模型同步后自动重新生成 CLI 工具配置文件。启用后，模型目录更改会从实时目录（Codex (~/.codex/*.config.toml) 和现在的 Claude Code（~/.claude/profiles/<name>/settings.json，通过提取的 syncClaudeProfilesFromModels + 镜像 Codex 路径的新 claudeProfileAutoSync.ts）中（重新）写入该工具的配置文件。两者都是默认关闭并且永远不会触及活动/默认的 CLI 配置；它们由 OMNIROUTE_AUTO_SYNC_CODEX_PROFILES / OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES 功能标志（DB/仪表板覆盖 > env > 默认“false”）支持，并另外在现有 CLI_ALLOW_CONFIG_WRITES 写保护后面进行门控。 CLI 代码仪表板上的 “CLI 配置文件自动同步” 卡可切换每个（从 #5778 中的提供商仪表板移动 — 感谢 @rdself）。回归守卫：tests/unit/claude-profile-auto-sync-gate.test.ts、tests/unit/codex-profile-auto-sync-gate.test.ts、tests/unit/cli/setup-claude.test.ts（#5737 的后续内容）。
  • cli（启动横幅）： serve 启动横幅现在在 ASCII 徽标下方打印正在运行的 OmniRoute 版本 (v3.8.x)，因此活动版本一目了然，无需单独的 --version 调用。回归防护：tests/unit/cli-serve-version-banner.test.ts。谢谢 @chirag127 (#5752)。
  • 分析（订阅成本）：固定费率提供商现在在成本分析中显示 $0，而不是夸大的每个代币估算。订阅/编码计划提供商（每个 cookie-web 提供商 — ChatGPT Web、grok-web 等 — 加上专用的 Minimax Coding、Kimi Coding、GLM Coding、Alibaba Coding Plan 和 Xiaomi MiMo 计划）收取固定费用，而不是按代币计费，但仍包含用于估算的按代币定价行 — 因此分析仪表板高估了其成本。分析界面（分析路线、使用统计、使用分析）通过选择加入的 flatRateAsZero 成本选项咨询新的统一费率分类器 (src/lib/usage/flatRateProviders.ts)，因此这些提供商读取 0 美元，而预算/配额/路由保持估计不变。故意不归零：codex/cx（OmniRoute 主动跟踪 Codex 代币成本 — 快速乘数、GPT-5.x 定价 — 并且 Codex 可以是计量账户）、byteplus（计量 ModelArk）、minimax-cn（计量中国 API）。回归防护：tests/unit/flat-rate-cost-5552.test.ts。 (#5552)
  • mcp (RTK)： 将 RTK 工具输出 学习/发现 工作流程公开为两个新的 MCP 工具，以便代理可以在不离开协议的情况下扩展 RTK 过滤器目录。 omniroute_rtk_discover 分析最近捕获的原始工具输出 (discoverRepeatedNoise / suggestFilter) 并返回候选噪声模式以及建议的滤波器； omniroute_rtk_learn 列出捕获的命令样本 (listRtkCommandSamples) 并将命令解析为其 RTK 过滤器 ID (commandToId)。两者都是只读的（范围 read:compression），包装现有的 RTK 发现原语（引擎中没有新逻辑），并记录到 MCP 审计跟踪。回归防护：tests/unit/compression/rtk-mcp-tools.test.ts (4)。间隙 v3.8.42 — T07。
  • 压缩（LLM 层）： 添加一个 选择加入、默认关闭的 LLM 层压缩引擎 (llm)，该引擎通过可插入的聊天完成后端压缩非系统消息的散文。它反映了 llmlingua 引擎的合约，但 构造安全：默认后端是无操作传递（引擎永远不会改变有效负载，直到操作员启用它并通过 setLlmCompressorBackend() 连接真正的后端），它不是默认堆叠管道的一部分，enabled 默认为 false，受保护的代码块和 system 消息永远不会发送到模型，并且每个后端错误无法打开（原始段/正文被保留，从不抛出）。 minTokens 楼层会跳过小提示。真正的生产后端故意是经过 VPS 验证的后续（硬规则#18），就像 llmlingua 工作后端被门控一样。新款open-sse/services/compression/engines/llm/index.ts。回归防护：tests/unit/compression/llm-compressor-engine.test.ts (8)。间隙 v3.8.42 — T05/C3。
  • 记忆（类型化衰减）：添加选择加入类型化记忆衰减（TV6），以便会话内存存储停止累积陈旧的 episodic 噪音。现在，每个注入的内存都会跟踪 access_count + last_accessed_at（始终开启、非破坏性遥测；迁移 111_memory_typed_decay），并且选择加入、默认关闭扫描（MEMORY_TYPED_DECAY_ENABLED、默认 false）会删除超过每类型 TTL 且无法免疫的内存。默认情况下仅 episodic 衰减（30d，环境可调）； factual/procedural/semantic 是免疫的，任何访问 >= 3 次的内存都会获得访问免疫（镜像“护栏/约定/决策永不衰退”）。衰变时钟重新基于上次访问，因此使用过的内存得以幸存。删除重用 deleteMemory（SQLite + sqlite-vec + Qdrant 保持同步）并打开失败；可选的定期扫描是双重选择的（也需要 MEMORY_TYPED_DECAY_SWEEP_INTERVAL>0）。关闭标志后，任何内容都不会被删除（规则#20 的精神）。新款 src/lib/memory/typedDecay.ts。回归防护：tests/unit/memory/typed-decay.test.ts (15)。间隙 v3.8.42 — T10/TV6。
  • 仪表板（组合）：命名组合编辑器现在允许您拖动以重新排序堆叠压缩管道，而不是仅编辑固定位置步骤。新的纯模型（src/shared/components/compression/compressionPipelineModel.ts）拥有引擎→强度不变的添加/删除/移动/更新和永不空的保证，并且@dnd-kit/sortable编辑器（CompressionPipelineEditor.tsx，匹配侧边栏重新排序模式）替换了CompressionCombosPageClient中的内联列表。订单通过现有的组合端点保持不变。回归防护：tests/unit/compression-pipeline-model.test.ts (11) + tests/unit/ui/compression-pipeline-editor.test.tsx (4)。专用的 tests/e2e/compression-studio.spec.ts（Tela A 渲染 + 选项卡开关）弥补了组合直播规范未涵盖的工作室 e2e 差距。间隙 v3.8.42 — T06 + T03。
  • 压缩（管道）：向堆叠压缩管道（T02）添加一个选择加入、默认关闭的每引擎断路器。当引擎在请求中重复抛出时，它的断路器会打开，并且堆叠循环会跳过该引擎（保持该步骤的正文逐字记录 - 失败打开）进行冷却，然后探测一次（惰性半开）；成功将关闭它，失败的探测将重新打开它。这与提供程序断路器（src/shared/utils/circuitBreaker.ts，提供程序范围 + DB 持久）不同 - 新的 pipelineEngineBreaker.ts 是引擎范围的，进程本地的，并在热路径上添加零 DB/IO。它与现有的按请求 TV1 跳出（在单个请求内跳过）组成；断路器添加了交叉请求内存。 默认关闭 (COMPRESSION_PIPELINE_BREAKER_ENABLED=false) → 字节与预断路器管道相同（除非单独启用 TV1，否则抛出引擎仍会传播）。可按调用、按 CompressionConfig 或通过 env (_THRESHOLD/_COOLDOWN_MS) 配置。回归防护：tests/unit/compression/pipeline-circuit-breaker.test.ts（9，包括投掷引擎集成）；现有的策略选择器/救助套件保持绿色。间隙 v3.8.42 — T02 (2.2)。
  • 压缩 (CCR)： CCR 检索反馈 (H8) 现在已毕业，而不是二进制 cliff。以前，检索到 >= 3 次的块被标记为“不压缩”，并且低于该块的所有内容都保持完全可压缩。现在，每次先前的检索都会线性地提高块的有效minChars（effectiveMinChars），因此频繁检索的内容被压缩得越来越少； >= 3 排除项被保留（如 Infinity）。斜坡由 retrievalRampFactor 控制（默认 2、每个组合配置或 COMPRESSION_CCR_RETRIEVAL_RAMP_FACTOR）； 1 准确再现了旧版二进制行为。 Per-(principal, hash) 隔离度不变。回归防护：ZZPH100​​ZZ（12）；现有的 CCR 套房 (51) 保持绿色。间隙 v3.8.42 — T08/H8。
  • 压缩（缓存感知）：添加一个选择加入、默认关闭使用观察前缀冻结 (H5)。缓存感知防护之前仅为被识别为缓存的_static_启发式提供者保留系统提示。现在，它还了解哪个系统提示实际上会重复出现：一旦观察到系统提示 >= 是跨请求的阈值，它就会被视为稳定的可缓存前缀并保留压缩状态即使对于提供者来说，静态检查也会丢失 — 恢复提示缓存命中，否则前缀压缩模式会崩溃。通过系统提示符的散列（OpenAI / Claude / Gemini 形状）进行内容寻址，内存中 + 有界，零 DB/IO； “冻结”仅_保留_前缀，因此它永远不会改变有效负载。默认关闭（COMPRESSION_PREFIX_FREEZE_ENABLED，阈值_THRESHOLD）；遵循 never 保留模式（永不冻结）。全新 open-sse/services/compression/prefixFreeze.ts，已连接至 resolveCacheAwareConfig。回归防护：tests/unit/compression/prefix-freeze.test.ts（10）； 44 个现有的缓存感知/保留模式测试保持绿色。间隙 v3.8.42 — T08/H5。
  • 压缩（读取生命周期）：添加一个新的选择加入、默认关闭的 read-lifecycle 引擎 (H7)，该引擎会崩溃过时/被取代的文件读取工具结果。在代理对话中，同一文件会被重复读取；一旦同一路径被稍后的写入/编辑重新读取（被较新的视图取代）或修改，早期的读取就会变得过时。引擎用短存根替换那些早期的读取结果——仅保持当前（最后的、未被取代的）读取完整——恢复模型不再需要的令牌。与 session-dedup（相同内容）或 ccr（可逆标记）不同，这是语义 + 有损，因此它是可选的（enabled 默认为 false）。构造保守：仅匹配众所周知的读/写工具名称，比较确切的路径，仅在严格稍后的调用触及相同路径时折叠只读，并且在任何意外形状上失败打开。支持 Anthropic (tool_use/tool_result) 和 OpenAI (tool_calls + role:"tool") 形状。新款 open-sse/services/compression/engines/readLifecycle/index.ts。回归防护：tests/unit/compression/read-lifecycle.test.ts (10)。间隙 v3.8.42 — T08/H7。
