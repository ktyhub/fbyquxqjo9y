OmniRoute v3.8.40

[3.8.40] — 待定

开发中 — 每个 PR 添加的项目符号；发布时最终确定.

✨ 新功能

  • 功能（压缩）：相关性提取引擎 - 一种新的选择加入压缩引擎，通过用户最后一个查询的术语重叠（Jaccard）对每个句子进行评分，减去长度/样板惩罚，贪婪地在预算内保留最相关的内容，并重建原始顺序。纯字符串、确定性、ReDoS 安全（字符代码标记化、用户输入无 RegExp）、故障打开、默认关闭。非常适合将长粘贴的 RAG 上下文/工具输出修剪为相关内容。携带真实信号的句子（数字/URL/错误/代码/路径）永远不会被丢弃； overlapThreshold/budgetPercent/boilerplateWeight 是可配置的。压缩特征提取路线图的第 2 层项目 (#7)。 (#5289)
  • feat(压缩)：硬预算模式 — 压缩到 ≤ N 个令牌 — 确定性后通道（targetTokens / targetRatio，默认未设置 → 无操作），将主体修剪为令牌预算。它按平均 scoreToken 升序对句子/行进行排名，并丢弃最低显着性的句子/行，直到正文适合（通过精确的 cl100k countTextTokens 测量），保留原始顺序。携带真实信号的线路（数字、URL、Error: 系列、代码栅栏、堆栈 at 帧、多段路径、key=value）永远不会被丢弃；预算按比例分配给消息，因此总停留数≤目标；无法到达的目标（全部保留）会显示 validationWarnings 注释，而不是默默地失败。不接触 estimateCompressionTokens 预算门估算器。压缩特征提取路线图的第 3 层项目 (#17)。 (#5288，后续#5291)
  • 功能（压缩）：确定性引擎的结果记忆（选择加入） - 缓存(input, config) → result以实现可证明的纯无状态模式（lite/standard/rtk和{lite,caveman,rtk}的堆叠管道）以跳过热路径上的重新计算。通过 memoizeCompressionResults 选择加入（默认关闭 → 零行为变化）。保守的选择加入白名单（有状态的 ccr/session-dedup — 写入跨请求 CCR 存储 — 以及模型支持的 ultra/aggressive/llmlingua 永远不会被缓存）、主体范围（在没有主体的情况下跳过，因此不会出现跨主体主体泄漏）以及存储上克隆 + 读取时克隆。压缩特征提取路线图的第 3 层项目 (#21)。 (#5286)
  • 功能（压缩）：内联透明度注释 - 从现有压缩统计数据派生的表面 tokens=847→312; rules: filler×8, dedup×2。 X-OmniRoute-Compression 响应标头已扩展仅附加（mode; source=X 前缀保持字节相同，因此现有标头解析器不会破坏），并且压缩工作室驾驶舱显示匹配的徽章。零新计算 - 它聚合了统计数据中已有的 rulesApplied/techniquesUsed。压缩特征提取路线图的第 3 层项目 (#18)。 (#5284)
  • 功能（压缩）：压缩工作室中的显着性热图 - 预览工作室现在可以按显着性为每个标记着色：ultra 每个标记 scoreToken（0–1，绿色→红色渐变）或从现有差异中保留/删除的通用。切换后的试运行可视化（正常预览无成本；关闭时向后兼容）。完成路线图项目 #13 的可视化部分（#5080 中提供的 A/B 比较）。 (#5285)
  • feat(compression)：用于 RTK 检测的复合命令分割器 — cd /x && git status 现在检测为 git-status（之前整个字符串被视为一个命令并且不匹配任何过滤器）。报价感知顶级分词器在 &&/||/; 上进行拆分（绝不会在引号或 $(…)/反引号子 shell 内），并将 last 段提供给 RTK 命令检测，因此每个 RTK 过滤器/渲染器都会触发包含在 cd … &&/||/; 链中的命令。 O(n)，命令上没有正则表达式（ReDoS 安全）。压缩特征提取路线图的第 3 层项目 (#16)。 (#5283)
  • feat(mcp)：omniroute_tool_search 工具 + 单行 TS 签名 — 新的 MCP 工具，可以对每个 MCP 工具的名称/描述进行词法关键字搜索，并以紧凑的单行 TypeScript 签名的形式返回最匹配的内容（大约是 JSON 模式令牌成本的一半），因此代理可以按需发现工具，而不是每回合都携带所有大约 88 个模式。搜索是 ReDoS 安全的（子字符串评分，查询中不会出现 new RegExp）并且具有确定性； tools/list 保持完整（没有隐藏工具）。添加 read:tools 示波器。压缩特征提取路线图的第 1 层项目。 (#5269)
  • 功能（压缩）：RTK语义命令输出渲染器（选择加入） - 向 RTK 引擎添加第二个选择加入压缩层，将结构化命令输出重写为更紧凑的语义形式：git diff → 文件头 + @@ 块 + 仅更改行；全绿 pytest/jest/vitest/eslint 运行→其一行摘要； terraform/tofu plan→Plan: +N ~M -K加资源列表； kubectl/aws JSON 数组 → 最小表。每个渲染器都是保守的（当形状不匹配时无操作）并且集成是故障开放的；测试绿色渲染器永远不会折叠携带任何失败信号的输出。由 RtkConfig.enableRenderers 门控（默认关闭 → 零行为变化）。压缩特征提取路线图的第八项。 (#5268)
  • 功能（压缩）：QuantumLock 缓存前缀稳定（选择加入，默认关闭） — 恢复上游提示缓存命中，否则系统提示中的易失性片段会崩溃。当调用者每轮将会话 UUID、unix 时间戳、请求 id、JWT、API 密钥形状或长十六进制摘要注入到 role:system 消息中时，跨轮的最长公共前缀以该变化的字节结束→整个系统在每轮重新计费和重新处理后提示。 QuantumLock 将每个非语义易失性片段替换为 位置、值无关 占位符 ⟦Q{i}⟧，并将实际值附加在分隔的 ⟦QUANTUMLOCK⟧ 尾部中。重写被发送到模型（无损 - 不恢复），因此系统提示正文变得跨轮字节相同，并且提供程序缓存长稳定前缀，而只有小尾部不同。选择加入，默认关闭，仅适用于缓存提供程序 (isCachingProvider && config.quantumLock.enabled)；有界 ReDoS 安全模式；幂等； 没有日期/时间模式（语义上有意义 - 明确的非目标）。 Studio 获得一个切换按钮 + 一个“🔒 N 挥发性片段稳定”的试运行徽章。压缩特征提取路线图的第七项（bench：[#5080]（https://github.com/diegosouzapw/OmniRoute/pull/5080），gate：[#5127]（https://github.com/diegosouzapw/OmniRoute/pull/5127），fuzzy：[#5143]（https://github.com/diegosouzapw/OmniRoute/pull/5143），ionizer：[#5148]（https://github.com/diegosouzapw/OmniRoute/pull/5148），TOON： #5163，CCR 范围：#5187，风险门：#5243)。 (#5260)
  • kilocode： 匿名（无身份验证）访问 Kilo Code 的免费模型，反映 opencode/mimocode 模式。如果没有连接 Kilo 帐户，请求现在会回退到网关的匿名层（api.kilo.ai/api/openrouter 上的 Authorization: Bearer anonymous），因此免费模型无需注册即可使用；连接的 OAuth 帐户仍然不变地用于付费层（#5259，#4019 — 感谢 @Theadd 的参考实现）
  • feat(logging)：呼叫日志相关 ID（端到端） — 每个请求现在都会获得一个唯一的相关 ID，在 X-Correlation-Id 响应标头中返回，保留在 call_logs 中（迁移 109），可通过 /api/usage/call-logs 进行过滤，并显示在仪表板请求记录器中（每个块流时间戳 + 活动请求优先排序）。这是更大的 #5275 的安全、有凝聚力的核心子集 — 独立存在，因此低风险值不会被仍在审查中的 PR 部分所阻碍。 （#5279 — 感谢@hartmark）
  • 壮举（提供商）：Microsoft 365 Copilot 个人提供商 — 添加了 copilot-m365-web 提供商（第 237 个），将 M365 BizChat 框架/连接帮助程序连接到由 m365.cloud.microsoft/chat 支持的可选 Web 会话提供商，用于个人 Microsoft 365 计划。 Builds on the M365 pure-framing groundwork from #4696.回归守卫：tests/unit/copilot-m365-web-executor.test.ts。 （#5302 — 感谢@skyzea1）

🔧 错误修复

  • ci(docker)： 将 Docker Hub / GHCR :latest（和 :latest-web）标签重新指向刚刚发布的版本。在 release: released 事件中，当 docker-publish 运行时，新创建的 git 标签通常对 git fetch --tags 不可见，因此 :latest 升级门纯粹从 git tag -l 构建其候选集，并将最高 semver 解析为上一个版本 - 使 latest 落后一个版本（3.8.39 已发布，latest 仍然3.8.38）。该决定现在位于 scripts/ci/should-promote-latest.sh 中，它在选择最高稳定的 semver 之前将当前的 VERSION 折叠到候选集中，从而使升级独立于标签同步时间（在更高次要版本之后发布的补丁仍然不会抢占 latest）。回归守卫：tests/unit/build/should-promote-latest-5301.test.ts (#5301)
  • 命令代码： 将非正 max_tokens/max_completion_tokens （例如 Zoo Code 的 -1“让服务器选择”）视为“无限制” - 省略该字段而不是强制其为 1。 clampMaxTokens 之前执行了 Math.max(1, …)，因此 client -1 作为 max_tokens: 1 发送到上游，截断了对单个令牌的响应（观察到的 completion_tokens: 1、content: null、reasoning_content: "The" 和 finish_reason: stop）。 Now any value ≤ 0 is dropped so Command Code applies the model’s native default; positive values are still floored and clamped to the 200k ceiling. Regression guard: tests/unit/command-code-maxtokens-negative-5166.test.ts (#5166 — thanks @Stazyu)
  • fix(auth): compare-and-swap guard on the OAuth refresh persist — under multi-agent load, the per-connection refresh mutex makes [network refresh + DB write] atomic for one connection, but it does not protect against a third writer (a sibling request, a concurrent HealthCheck, or a replica) landing a fresher refresh_token rotation on the same connection_id between the staleness read and the persist.覆盖较新的行会恢复同级的轮换； the next caller then loads the now-consumed token, Auth0/Anthropic flag it as refresh_token_reused, and the whole token family gets revoked (the 1352× claude/aa5dd5cf invalidation storm). getAccessToken now re-reads the row’s current refresh_token immediately before persisting (inside the mutex) and skips the write when it has rotated past the token the caller presented — the caller still receives the freshly-issued access token, only the DB overwrite is skipped.通过 runWithCasGuard 选择加入（无主动保护 ⇒ 字节相同行为）；通过 getCasGuardStats() 公开的跳过/保留计数器。回归防护：tests/unit/token-refresh-cas-guard-4038.test.ts。 （#4038 — 感谢@KooshaPari 的根本原因诊断）
  • mcp: break the schemas/tools.ts ↔ schemas/toolSearch.ts import cycle introduced when the tool_search defs (#5269) were extracted into their own module — toolSearch.ts imported McpToolDefinition from tools.ts while tools.ts imported toolSearchTool from toolSearch.ts, failing check:cycles on release/v3.8.40。共享的 AuditLevel + McpToolDefinition 类型现在位于同时导入的叶子 schemas/toolDefinition.ts 中； tools.ts 重新导出它们以实现向后兼容性。
  • **压缩（分析）：**记录尝试但无操作的压缩运行，因此当 Stacked 不保存任何内容时不再不可见。 Previously a compression_analytics row was written only on a net-positive saving, so a Stacked (RTK→Caveman) pipeline that ran on already-compact context produced no row — indistinguishable from “never dispatched” (byMode.stacked.count stayed flat while Ultra climbed). Such runs are now recorded with skip_reason and surfaced as a per-mode skipped count plus totalSkipped/bySkipReason in the analytics summary and the Mode Breakdown;现有的净节省总数/平均值保持不变（跳过行被排除在外）（#4268 - 感谢@abdulkadirozyurt，@androw）
  • cli（托盘）： 修复 omniroute server --tray 在 macOS/Linux 上显示无托盘且未打印错误的问题。 The wired Unix tray path loaded systray2 through an inline loader that called require("module") inside an ESM .mjs file ("type":"module") → ReferenceError: require is not defined, silently swallowed (regressed in v3.8.34);即使它已加载，systray2 也不在 node_modules 中（它被延迟安装到 ~/.omniroute/runtime 中）。 The loader now delegates to the runtime loader, the icon path (icon.png) is corrected, isTemplateIcon is false (the full-color icon rendered as a white square under macOS template mode), and tray start failures are surfaced to stderr instead of being swallowed (#4605 — thanks @ProgMEM-CC)
