OmniRoute v3.8.38

✨ 新功能

  • 功能（侧边栏）：彩色菜单图标 - 侧边栏菜单图标现在使用每个项目的强调色进行渲染：已知项目的精选颜色（SIDEBAR_ICON_ACCENTS）加上确定性的基于散列的回退（getSidebarIconAccent），因此每个项目在会话中都获得稳定、独特的颜色。 （#3812 — 感谢@rafapti23）
  • feat(providers)：添加 Factory (factory.ai) 作为订阅网关提供商 — factory（Factory Droids 的托管网关）现在是 OpenAI 兼容的 https://api.factory.ai/v1 端点上的一流路由提供商，具有 Bearer apikey 身份验证；密钥由仪表板连接（而不是 env）提供。 （#5065 — 感谢@KooshaPari）
  • feat(providers)：添加具有 OAuth 导入令牌流的 Grok Build (xAI) 提供商 — grok-cli（别名 gc）通过 Grok 的 CLI 聊天代理进行路由；用户粘贴他们的 ~/.grok/auth.json（或 JWT），并自动旋转 refresh_token。公共 xAI client_id 通过 resolvePublicCred("grok_id") 嵌入（硬规则 #11），而不是文字。 （#5020 — 感谢@fulorgnas）
  • feat(dashboard)：click-在提供程序页面中编辑模型别名 — click 一个别名，用于内联编辑（Enter/模糊保存，Escape 取消），而不是只能删除并重新添加它。 （#5119 — 感谢@waguriagentic）
  • feat(providers)：添加 ZenMux Free（session-cookie free-tier）提供商 — zenmux-free（别名 zmf），带有专用执行器，将 ZenMux 的 Anthropic 风格的 SSE 转换为 OpenAI 格式；提供 12 个免费层型号（DeepSeek V3.2、GLM 4.7 Flash Free 等）。 （#5105 — 感谢@mrnasil）
  • feat(providers)：默认允许本地/私有提供商 URL（Allow Local Provider URLs 标志） — 在环回/LAN 地址（例如 http://127.0.0.1:3264/api）上添加/验证 OpenAI 兼容提供商被 SSRF 防护以“阻止私有或本地提供商 URL”拒绝，即使 OmniRoute 是本地优先。新的 OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS 功能标志（默认 ON，在“设置”→“功能标志”中切换）现在将提供商验证防护范围限定为允许本地/私有主机，同时仍然阻止云元数据端点（169.254.169.254、metadata.google.internal）。禁用它以恢复严格的仅限公开的阻止。 Webhook/remote-image SSRF 默认值保持不变。 （[#5066]（https://github.com/diegosouzapw/OmniRoute/issues/5066），谢谢@daniij）
  • feat(blackbox)： 使用最新模型刷新提供者模型目录。 （感谢@ptkelanatechsolutions）
  • kiro：内联 <thinking> 流分割器 - 当 <thinking_mode>enabled</thinking_mode> 存在时，assistantResponseEvent 内容现在被分割成单独的 delta.content / delta.reasoning_content SSE 块（新的 open-sse/executors/kiroThinking.ts 模块连接到 KiroExecutor.transformEventStreamToSSE）。
  • feat(cursor): 解析 Cursor Composer DeepSeek 风格的内联工具调用 - Composer cu/composer-2.5* 模型使用 <｜tool▁calls▁begin｜>…<｜tool▁calls▁end｜> 标记而不是结构化的 protobuf 框架将工具调用嵌入到其可见文本中；新的流解析器 (composerToolCalls.ts) 在流和非流路径中拦截这些内容，抑制来自 client 可见内容的标记，并发出正确的 OpenAI tool_calls 增量，以便下游 client 本地处理它们。 （感谢@noestelar）
  • feat(proxy)： 支持无身份验证的 host:port 批量导入和表面代理测试失败。 （感谢@dimaslanjaka）
  • feat(video)：阿里巴巴 DashScope 视频提供程序 (wan2.7-t2v) — 添加通过标准 apikey 凭证路径连接的 alibaba 视频提供程序（DashScope 异步任务 → 轮询 → MP4），因此文本到视频请求可以路由到阿里巴巴的 wan2.7-t2v 模型。 （感谢@josevictorferreira）
  • feat(cc)：Claude-Code 兼容提供程序的每个连接“总结思维显示”切换 — 公开驱动现有 Copilot 总结思维标记的连接级别切换，因此操作员可以从 UI（架构 + 请求默认值 + 提供程序模式，使用 i18n）选择 CC 兼容连接进入总结推理显示。 （感谢@rdself）
  • 壮举（压缩）：工作室中的压缩游乐场（播放 + 比较选项卡） - /dashboard/compression/studio 获得了一个合成游乐场：粘贴文本 → 每个引擎 通道（每个确定性引擎通过 /api/compression/preview 单独运行）加上 stackPriority 订购的 组合瀑布，以及一个免费的 A/B 比较 网格，可按需提供 美元上限 保真度判决 (/api/compression/compare + compare/verify）。预览路由现在使用真正的 cl100k tokenizer，返回 engineBreakdown，并接受有序的 pipeline[]；新增compare / compare/verify / retrieve航线；实时 WS 源移至 /dashboard/compression/live。仅限管理。 (#5080)
  • 功能（仪表板）：在组合编辑器中公开 Fusion judgeModel + fusionTuning - Fusion 策略编辑器现在显示判断模型（合成小组答案；默认为第一个小组模型）以及 open-sse/services/fusion.ts 已读取的仲裁宽限调整字段（minPanel、stragglerGraceMs、panelHardTimeoutMs）。模式验证+有界；空调永远不会持续。 (#5074)
  • 功能（压缩）：选择加入堆叠管道的每步保真度门 - 每个压缩步骤现在都可以由纯保真度检查器（4个不变量，故障开放）来保护，因此会拒绝将提示降级到超过阈值的有损引擎，并跳过其通道，而不是静默运输。可通过 fidelityGate 配置（故意省略 API 高级阈值），并在工作室操场切换中显示每通道拒绝故障。 (#5143)
  • 壮举（压缩）：模糊近重复重复数据删除（会话重复数据删除第二次传递） — 会话重复数据删除引擎获得第二次模糊传递，可折叠近乎重复（不仅仅是字节相同）段，并使用游乐场切换来比较开/关。 (#5143)
  • feat(quota)：选择加入 Codex/Claude 自动 ping keepalive — 选择加入后台 keepalive 可以定期 ping Codex/Claude 连接以保持其会话/配额状态温暖，从而减少第一个实际请求时的冷启动失败。 (#5102)
  • feat(ops)：SRE 剧本 + ops 帮助脚本 — 从封闭的陈旧 PR 中抢救出来；添加操作员运行手册和操作帮助程序脚本。 (#5138 — 感谢@KooshaPari / @diegosouzapw)
  • feat(mcp)：Web 会话稳健性 — Cookie 重复数据删除 + 浏览器池可观察性 — MCP Web 会话路径现在可以在（重新）水化会话时消除重复的 Cookie（避免重复的 Cookie 标头冲突），并为无头 Web 提供商公开浏览器池可观察性（池大小/使用中/获取指标）。 （#5121，基于 #3368）
  • 功能（压缩）：离子发生器引擎 - 通过 CCR 可逆有损 JSON 数组采样 - 一种新的压缩引擎，可将大型 JSON 数组下采样为代表性子集并记录紧凑变化表示 (CCR)，以便可以重建省略的行，以准确性换取表格/数组重负载上的大量令牌减少。 (#5148)

🔧 错误修复

  • 修复（代理）：使 SOCKS5 握手超时操作员可调（SOCKS_HANDSHAKE_TIMEOUT_MS） - 在针对单个住宅网关主机的高并发情况下，即使代理可访问，SOCKS5 连接握手也可能超过硬编码的 10 秒，显示为错误的 [Proxy Fast-Fail] Proxy unreachable（池大小已可通过 OMNIROUTE_PROXY_DISPATCHER_CONNECTIONS 进行调整）。握手超时现在为 SOCKS_HANDSHAKE_TIMEOUT_MS（默认为 10000 不变，上限为 120000），因此并发密集型部署可以在不更改代码的情况下提高它。 #5109 的缓解措施（完全并发 100 崩溃仍需要记者的实时负载测试确认）。 (#5109)
  • 修复（api）：不区分大小写地解析 GET /v1/models/{id} - 规范化模型 ID 的 client（例如，OpenCode 请求 minimax/minimax-m3 获取规范目录条目 minimax/MiniMax-M3）错过了区分大小写的单模型查找，并退回到广告 context_length: 0。 findModelById 现在更喜欢精确大小写匹配，并回退到不区分大小写的匹配，因此无论大小写如何，都会返回真正的条目（及其上下文窗口）。 (#5082)
  • 修复（服务）：嵌入 WS 代理遵循 LIVE_WS_HOST；尽早拒绝空 messages — 两个无头/Docker 部署修复 (#5110)。嵌入的 WebSocket 代理 (:20131) 仅读取 EMBED_WS_PROXY_HOST，因此在反向代理/隧道后面，即使设置了 LIVE_WS_HOST=0.0.0.0，它仍然绑定到 127.0.0.1，并且实时仪表板显示“WebSocket 已断开连接”；现在它回落到 LIVE_WS_HOST （默认仍然环回）。另外，带有显式空 messages: [] 数组的请求被转发到上游，并作为令人困惑的原始 400/502 反弹回来； handleChat 现在通过明确的 messages: at least one message is required 预先拒绝它（响应 API input 请求不受影响）。 (#5110)
  • 修复（代理）：修复一 click Deno 和 Cloudflare 中继部署 — /api/settings/proxy/test 端点仅识别 vercel 中继类型，因此测试部署的 Deno 或 Cloudflare 中继返回 proxy.type must be http, https, or socks5 并且从未到达中继；现在，它通过 isRelayType() 路由所有继电器类型。使用 STORAGE_ENCRYPTION_KEY 安装时，中继身份验证令牌通过 extractRelayAuth（加密的 relayAuthEnc 形式）读取，修复了导致 publicIp 为空的静默 401。 Cloudflare Worker 上传现在以 application/javascript 形式发送脚本部分（API 拒绝 application/javascript+module；ES 模块语义来自 main_module），并且代理注册表架构接受 deno/cloudflare 类型 + deno-relay/cloudflare-relay 源，因此编辑已部署的中继不再需要 400 秒。 (#5128)
  • 修复（kiro）：从 Kiro 目录中退出 claude-sonnet-4.5 + 固定确切的 Kiro 400 错误 - claude-sonnet-4.5 离开了 Kiro 免费系列（当前活跃型号：Opus 4.8/4.7/4.6、Sonnet 4.6、Haiku 4.5），因此它已从 Kiro 注册表项中删除，并且免费模型目录。现在，回归测试将 Kiro 的逐字 [400] Invalid model. Please select a different model to continue. 固定到 isModelUnavailableError 模型不可用分类。每个模型（包括当前模型）上的 400 都指向服务器端 Kiro 层/区域门，而不是 OmniRoute 目录错误。 （#5140，关闭#4484）
  • 修复（仪表板）：在加载/保存弹性设置时保留每个渲染字段 - ResilienceTab 渲染 comboCooldownWait 和 quotaShareConcurrencyLimit，但初始加载和保存路径都重写了没有这些字段的组件状态，因此在成功的 /api/resilience 响应后，卡收到了 undefined 并且页面回退到通用“加载失败”状态。共享的 toResilienceResponse() 映射器现在保留所有渲染字段，并且 PATCH /api/resilience 返回 quotaShareConcurrencyLimit 以匹配 GET 和 UI 契约。 （#5139 — 感谢@rdself）
  • 修复（配额）：从快照+范围自动组合候选中水化内存中配额缓存 - 重新启动后，配额缓存为空，因此已知耗尽的连接在重新查询之前看起来很健康； isAccountQuotaExhausted 现在从持久的 ZZPH100​​ZZ 中缓慢地水合。自动组合候选扩展的范围也限于每个组合目标实际允许的连接，而不是为提供者拉入每个连接。 （#5015 — 感谢@JxnLexn）
  • 修复（弹性）：强化配额截止、Gemini 音频 MIME 和模型锁定冷却 - 存储的配额硬截止值不再从任意字符串强制转换为 enabled=true； Gemini 音频输入部分在转发之前已对其 MIME 类型进行验证/标准化；模型锁定现在遵循配置的 maxCooldownMs 上限。 （#5093 — 感谢@KooshaPari）
  • 修复（流）：强化与 OpenAI 兼容的长 SSE 流 - 后期管道结束错误无法再覆盖已记录的成功流（streamCompletionRecorded 保护），client 断开最终确定为 499 client_disconnected 而不是中毒提供者/帐户失败状态，实际上是 SSE 的 JSON 主体（错误的 application/json 内容类型）是嗅探和重新流式传输，推理字段（reasoning/reasoning_content + OpenRouter/Gemini 加密的 reasoning_details）通过 JSON-as-SSE 后备保留。 （#5124 — 感谢@rdself）
  • 修复（用法）：重复数据删除请求使用日志记录和反跳统计事件 - saveRequestUsage 现在可以防止重复插入（自然键：时间戳 + 提供程序 + 模型 + 连接 + api-key + 令牌计数），回填缺失的 endpoint，并且仅在实际插入行时发出 usageRecorded；统计数据 update/pending 事件突发被折叠成单个去抖通知以减少流失。 （#4940 — 感谢@nguyenxvotanminh3）
  • 修复（sse）：在 Antigravity MITM 处理程序中将本机 Gemini 请求正文转换为 OpenAI 格式 — contents / systemInstruction / generationConfig / thinkingConfig 现在在转发到 /v1/chat/completions 之前转换为 OpenAI 聊天完成格式，因此具有思考能力的模型（例如 ag/claude-opus-4-6-thinking）不再在提供商端失败400“无效参数”错误。 （#4845 — 感谢@anuragg-saxenaa）
  • 修复（db）：将两个 pt-BR SQLite 驱动程序后备日志行翻译为英语 - [DB] Pré-inicializando sql.js WASM… 和 [DB] Drivers síncronos indisponíveis… 是唯一的非英语服务器日志字符串，在日志中混合了语言。现在是 [DB] Pre-initializing sql.js WASM (synchronous drivers unavailable)… / [DB] Synchronous drivers unavailable — falling back to sql.js (WASM)，由扫描驱动程序路径以查找带重音的日志字符串的测试来保护。 (#5103)
  • 修复（诊断）：非流式 Claude 响应不再为 empty_choices 的 false-502 — v3.8.37 malformed-200 检测器 (#4942) 只能理解 OpenAI choices 和 Responses-API output 形状，因此 /v1/messages 响应保持 Claude 形状({type:"message", content:[…]}) 下降到 empty_choices → 502（级联到组合中的“所有型号均失败”）。最明显的是，一个扩展思维回合，其缓冲主体是一个空思维块，带有有效的 signature（Claude Code 的非流式 Bash 分类器），每次调用都会进行 502 处理。 detectMalformedNonStream 现在理解 Claude 形状：带有签名计数的文本/工具_使用块和思维块作为有效输出，而真正空的 content:[] 仍被标记。 （#5108，谢谢@insoln）
  • 修复（组合）：空内容 502 现在在同一请求内进行故障转移，而不是耗尽提供程序 - 响应 HTTP 200 且没有可用完成的分支被重写为 502 "Provider returned empty content"，但组合耗尽分类器将该合成 502 视为连接级故障 (#1731v2) 并将整个提供程序/连接标记为耗尽，跳过该请求中每个剩余的 相同提供程序 分支。连接实际上是健康的（它只是返回了一个空主体），因此空内容 502 现在被分类为模型级瞬态故障：请求前进到下一个分支，并且该提供者的其余分支保持合格。正版网关 502s 仍然出现连接耗尽问题。 （#5085，感谢@andrea-kingautomation）
  • 修复（仪表板）：显示详细的凭据验证错误，而不是裸露的“无效”徽章 - 添加连接模式中的内联“检查”丢弃了 /api/providers/validate 返回的 error 消息，并仅显示 invalid 徽章。对于网络提供商（claude-web / chatgpt-web），真正的原因通常是后端已经报告的环境错误（例如 TLS impersonation client failed to start: EACCES … mkdir tls-client-node/bin），因此用户只能猜测。现在，该模式会在徽章旁边呈现完整的原因。 （[#5088]（https://github.com/diegosouzapw/OmniRoute/issues/5088），谢谢@tkhs101）
  • **修复（执行者）：从 Cerebras 和 Mistral 的转发主体中剥离 client_metadata - 当直通主体携带 client_metadata（OpenAI Codex / Claude CLI 字段，这些上游没有等效项）时，Cerebras 返回 400 (wrong_api_format)，Mistral 返回 422 (extra_forbidden)。现在，默认执行器在向下游发送之前会为这两个提供程序删除它；其他提供商（特别是 openai/codex）保留它。 （感谢@saurabh321gupta）
  • **修复（codebuddy）：**仅在 client 请求推理时发送推理参数。 （感谢@anki1kr）
  • **修复（sse）：**当 JSON client 请求时，保持强制流提供程序的流式传输。标记为 forceStream:true 的提供商拒绝 stream:false 上游 (HTTP 400)； resolveStreamFlag 现在可以防止这种情况，因此即使 client 发送 Accept: application/json 或 stream:false，仅流式传输的提供商也会继续流式传输。 （感谢@anki1kr）
  • **修复（sse）：**防止非 JSON SSE 线路和重复的 [DONE] 破坏 clients。 （感谢@qianze0628）
  • fix(sse): 执行程序 buildHeaders 路径中的重复数据删除大小写变体 Anthropic 标头 — Node/undici 的 fetch 将 anthropic-version 和 Anthropic-Version 合并为 Anthropic API 拒绝的单个 "v, v" 值，因此两种大小写变体现在都折叠为一个规范的小写标头（相同）对于 anthropic-beta）。 （感谢@Delcado19）
  • oauth(kiro)： 支持 Kiro IDC（组织）令牌导入 — 当 ~/.aws/sso/cache 令牌携带 clientIdHash 时，自动导入现在读取链接的 client 注册文件以获取 clientId/clientSecret，探测 Kiro IDE profile.json 中的 profileArn（ARN 区域标准化为us-east-1 用于运行时网关），并通过区域 AWS OIDC 终端节点而不是社交路径进行刷新；导入模式和模式转发这些凭证，因此手动导入也适用于 IDC 令牌。 （感谢@enjoyer-hub）
  • **修复（翻译）：**将 Claude 格式请求（例如 Claude 代码）路由到阿里巴巴 DashScope 的 OpenAI 兼容提供程序（alibaba / alibaba-cn）时保留 client cache_control 断点。 Claude→OpenAI 翻译之前从系统和消息文本块中剥离了标记，因此 DashScope 的显式缓存从未启用，并且每个请求都是缓存未命中。现在，当支持缓存的 OpenAI 格式提供程序请求保存时，缓存提示仍然存在。 （感谢@sacrtap）
  • 修复（tts）： 从目录中解析 Gemini TTS 模型，并将 gemini-3.1-flash-tts-preview 添加为新的默认 Vertex TTS 模型。 （感谢@nguyenha935）
  • 修复(sse)：不要在自己造成的上游超时 (504) 上冷却健康连接 — 当 OmniRoute 自己的截止日期过去时（显示为 TimeoutError/BodyTimeoutError → 504），连接不再禁用/故障转移，因此缓慢但健康的提供程序不会因我们的超时而受到惩罚。正版上游5xx/429仍触发冷却；反重力有它自己的政策。 （感谢@costaeder）
  • **修复（译者）：**将图像 tool_result 块转发为 image_url，而不是字符串化 base64。 （感谢@alican532）
