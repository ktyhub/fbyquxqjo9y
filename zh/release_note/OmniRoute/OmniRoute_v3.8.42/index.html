OmniRoute v3.8.42

✨ 新功能

  • 压缩（管道）：向堆叠压缩管道（T02 / Headroom H1）添加一个诚实的默认开启通货膨胀防护。如果全栈引擎生成的主体实际上并未收缩（其令牌计数是原始的 >=），则压缩的主体将被丢弃，并且逐字原始请求将被发送到上游，并在压缩统计信息中记录 pipeline-inflation-guard 警告。这在构造上是安全的（唯一的后备是未经修改的原始版本，始终是有效的有效负载），并且补充了现有的选择加入每步 TV1 救助，该救助控制逐步推进而不是最终输出。新款open-sse/services/compression/pipelineGuards.ts；连接到同步和异步堆叠路径共享的单个 finalizeStackedResult 阻塞点。 tests/unit/compression-pipeline-inflation-guard.test.ts 中的回归防护（包括充气发动机集成测试）。
  • **压缩（穴居人）：**使用它们缺少的 dedup（重复上下文折叠）和 ultra（缩写/简洁）类别来完成德语、法语和日语规则包 - 这三种语言以前仅提供 context/filler/structural，而en/es/id/pt-BR 全部五个。因此，以更高强度压缩的 de/fr/ja 对话现在会瓦解重复的样板文件（“wie bereits besprochen”→“Siehe oben.”、“comme提及né précédemment”→“Voir ci-dessus.”、“今晚のとおり”→“（上记依托）”）并缩写密集的技术词汇（Datenbank→DB， Authentifizierung→Auth；base de données→BD，authentification→auth；データベース→DB，アプリケーション→app）。模式镜像现有的 es 包并保持 ReDoS 安全（有限的文字替换；CJK 包不使用 \b，因为日语没有单词边界）。回归防护：tests/unit/caveman-packs-de-fr-ja.test.ts（打包加载+验证+缩小代表性样本）。间隙 v3.8.42 — T05/C2。
  • **压缩（穴居人）：**添加一个 中文（zh / wenyan 文言）输入端规则包 — 现有输出端 terse-cjk 样式的对应项。新的rules/zh/{dedup,filler,ultra}.json折叠了重复的上下文（“如前说”→“见上。”），删除了客套话/对冲（“请帮我…/谢谢/我觉得”）​​，去掉句末情态助词（“吗/呢/吧”），并缩写了密集的技术术语（“数据库”→“DB”，“应用程序”→“app”）。现在可以自动检测中文：detectCompressionLanguage 通过不带假名的汉字来区分 zh 和 ja（假名是日语独有的，因此汉字较多的日语句子仍解析为 ja），并且 zh 列在 listSupportedCompressionLanguages 中。模式是 ReDoS 安全的（有界文字替换，没有 \b，因为 CJK 没有字边界）。回归防护：tests/unit/caveman-packs-zh-wenyan.test.ts（打包加载 + 验证 + 收缩；zh/ja/非 CJK 检测）。间隙 v3.8.42 — T05/C6。
  • 压缩 (RTK)： 将 Gradle 和 .NET CLI (dotnet) 添加到 RTK 工具输出过滤器目录。 gradle/gradlew 和 dotnet build|test|restore|publish 的工具输出现在可以识别（通过命令和输出内容）并压缩：Gradle 守护进程/欢迎横幅和无操作 > Task … UP-TO-DATE/SKIPPED/FROM-CACHE 行被删除，而 BUILD SUCCESSFUL/FAILED、“出了什么问题”和堆栈跟踪被保留； .NET 构建横幅、版权和 Determining projects to restore/Restored … 信息将被删除，而 Build succeeded/FAILED、error CS####/warning CS#### 和测试摘要将被保留。新的内置过滤器 engines/rtk/filters/{gradle,dotnet}.json（通过目录门运行内联测试）以及命令检测器中的 gradle/dotnet 条目。回归防护：tests/unit/rtk-gradle-dotnet-filters.test.ts。间隙 v3.8.42 — T07/R9。

🔧 错误修复

  • 提供商 (chatgpt-web)： 修复 Electron 桌面应用程序上的 502 ChatGPT sentinel failed: Digest method not supported，该问题导致每个 chatgpt-web/* 请求失败。哨兵工作量证明使用本机 createHash("sha3-512") 进行哈希处理，但 Electron 的 Node 是针对 BoringSSL 构建的，它不实现 SHA-3 系列（电子/电子#30530），因此摘要导致构建失败 - 该提供程序在桌面版本上无法使用（在普通 Node/OpenSSL 下工作）。 PoW 现在通过一个新的运行时可移植帮助程序 (open-sse/utils/sha3-512.ts) 进行哈希处理，该帮助程序更喜欢本机摘要，并在本机 SHA-3 不存在时透明地回退到无依赖的纯 JS Keccak-f[1600]。针对本机 createHash("sha3-512")（300 个随机输入）和已发布的 FIPS-202 已知答案向量对后备进行了逐位验证。 tests/unit/chatgpt-web-sha3-boringssl-5531.test.ts 中的回归守卫。 (#5531)
