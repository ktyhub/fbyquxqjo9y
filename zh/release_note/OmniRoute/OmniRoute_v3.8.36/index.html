OmniRoute v3.8.36

✨ 新功能

配额共享系统

  • feat(quota): 引入专用的 quota-share 组合策略 (Fase 3 #9) - 赤字循环调度，具有每个模型的运行中门控 (P2C)、促进现有 qtSd/* 组合的自动数据库迁移以及每个策略门控，以便无效的分配不会将 allow 泄漏到意外连接。 （[#4939]（https://github.com/diegosouzapw/OmniRoute/pull/4939），[#4901]（https://github.com/diegosouzapw/OmniRoute/pull/4901））
  • feat(quota)： 多窗口使用存储桶、每个（键、模型）上限和会话粘性 — 连接现在可以跟踪 5 小时、7 天和每个模型窗口的消耗情况； quota_allocation_model_caps 强制执行每个密钥/型号的限制；会话粘性可以保持提示缓存的完整性。 (#4928、#4927、#4929)
  • feat(quota)： 余量策略 + 主动饱和 — 新的 headroom 组合策略按可用配额余量选择连接；通过上游令牌使用响应标头实现通用主动饱和；真实的克劳德配额饱和度源自 /api/oauth/usage。 (#4908、#4907、#4885)
  • feat(quota): 并发控制 + 冷却等待 (Fase 2.1) — max_concurrent 在调度时强制执行；配额共享组合对并发请求进行排队，并具有短暂的冷却等待并根据插槽可用性重新调度（变体 A）； cron 修复会在窗口重置后主动恢复连接。 (#4965、#4970、#4967、#4900) 组合路由
  • feat(combo)： 任务感知路由策略 - 根据任务类型元数据将请求路由到最适合的连接，从而在组合中实现每个任务提供程序的专业化。 (#4945)
  • feat(combo): 融合策略（第 16 个策略）——并行扇出到可配置的模型面板，然后通过判断模型综合结果。 (#4652)
  • feat(combos)： 添加可编辑的每个组合 description 字段。路由组合表单现在有一个描述输入，通过 /api/combos (POST/PUT) 保留在组合 data blob 中，并通过 GET 往返 - 没有新的数据库列。 (#5005)
  • feat(routing): 遵循 X-Route-Model 请求标头来覆盖 body.model，从而无需修改请求正文即可实现每个请求的模型切换。 （#4863 — 感谢@costaeder） 提供商和模型
  • **feat（提供商）：**更新 volcengine-ark 型号列表，添加 DeepSeek-V4-Flash 和 DeepSeek-V4-Pro。 (#4905 — 感谢@kenlin8827)
  • feat(provider): 添加 CodeBuddy CN (copilot.tencent.com) — 完整的 OAuth + 执行器 + 模型目录堆栈。 (#4664)
  • feat(opencode-go): 宣传 glm-5.2 和 kimi-k2.7-code 以与官方 Go 端点保持一致。 (#4711)
  • feat(sse)： 添加 Google Flow 视频生成提供商。 (#4769)
  • feat(api/v1)： 在 /v1/models 列表中包含别名支持的模型。 (#4630) 代理池
  • feat(proxy-pool): Cloudflare Workers 代理部署器 + 池集成 — 直接从仪表板部署 Cloudflare Workers 中继并将其注册到代理池中。 (#4640)
  • feat(proxy-pool): Deno Deploy 中继 + 组操作按钮 — 部署 Deno Deploy 中继工作人员并使用新的批量操作控件管理代理组。 (#4643) 压缩和基础设施
  • 功能（压缩）： Kiro/CodeWhisperer 工具结果压缩引擎 - 用于集成到流管道中的 Kiro/CodeWhisperer 工具输出的专用压缩器。 (#4635)
  • feat(endpoint): 每个端点自定义系统提示注入。端点设置卡中的切换 + 文本字段允许用户将自定义系统提示注入到每个模型请求中，并通过现有的系统提示引擎应用。存储在设置数据库中。 （#5022 — 感谢@whale9820）
  • feat(live-ws): 允许通过 LIVE_WS_ALLOWED_HOSTS 环境变量进行非环回 clients，从而使多主机设置能够访问实时 WebSocket API。 （#4877 — 感谢@KooshaPari）
  • feat(db)： 跟踪 usage_history 上的 API 端点维度，以进行每个端点的成本和使用情况分析。 (#4676)

  • **修复（授粉）：**停止在每个请求上强制使用 jsonMode。 Pollinations 将 jsonMode=true 视为“模型必须返回 JSON”，并拒绝（HTTP 400“消息必须包含单词“json”）任何消息未提及“json”的正常聊天请求，因此所有非 JSON 聊天都被破坏。现在仅当调用者实际请求 JSON 输出（json_object 或 json_schema 的 response_format.type）时才启用 jsonMode。 (#3981)
