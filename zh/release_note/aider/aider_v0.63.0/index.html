aider v0.63.0

小版本 发布时间2024年11月13日 来源Aider-AI/aider 英文原文

变更流程图

亮点

  • 支持 Qwen 2.5 Coder 32B — 新增对一个开放权重代码模型的一等支持，为团队提供闭源 API 模型之外的可靠选择——如果你通过 LiteLLM 兼容端点跑本地或自托管推理，这点尤其相关。如果你一直在等一个许可宽松、代码编辑能力过硬的模型，这次更新让它成为实用选项，而不是实验室项目。

  • /web 现在只提供上下文 — 值得注意的行为变更：/web 现在只把抓到的页面注入聊天就结束，不再立即触发 LLM 回复。好处是你可以先备好多个页面作为上下文，再一次性提问，既省 token 又由你掌控模型何时运行。如果你的脚本或肌肉记忆指望 /web 当场给出答案，要注意这个流程现在需要显式追加提示。

  • 首选聊天语言 — 提示收紧后，Aider 更可靠地遵守你配置的聊天语言。非英语团队应该能看到更一致的输出语言，不必每次会话重复说明，少些提示样板，也少些重构中途突然冒出的英文回复。

  • LiteLLM 异常处理 — 由于 Aider 几乎把所有提供商调用都经 LiteLLM 转发，在这里加固异常处理会惠及所有后端：上游 API 限流、超时或返回畸形响应时更少硬崩溃，也给出更可操作的诊断而不是看不懂的堆栈。当你把它指向不稳定或自托管端点时，这点尤其重要。

  • 缓存 token 统计修复 — 修正了缓存统计中重复计入缓存 token 的 bug，该 bug 虚高了报告的使用量和成本。如果你按会话追踪花费，过去的数字很可能被高估——做预算时应以升级后的报告为准。

  • LLM 误建文件修复 — 修补了模型可能凭空创建新文件的 bug，改善仓库整洁度：编辑后 git status 里要发现（并清理）的游离未跟踪文件更少了。对让 Aider 在宽泛编辑权限下运行的人来说，这是个不大但很提升信任度的修复。（顺带一提，本版本 55% 的代码由 Aider 自己编写。）

  • 支持 Qwen 2.5 编码器 32B。

  • /web 命令仅将页面添加到聊天中，而不触发 LLM 响应。

  • 改进了用户首选聊天语言的提示。

  • 改进了 LiteLLM 异常的处理。

  • 修复了报告缓存统计信息时重复计算令牌的错误。

  • 修复了 LLM 创建新文件的错误。

  • 其他小错误修复。

  • Aider 编写了此版本中 55% 的代码。
