aider v0.10.1

aider v0.10.1

变更流程图

亮点

  • /add 与 /drop 的路径语义 — 这些命令现在按 git 根目录而非当前工作目录解析路径。这是唯一带有迁移影响的改动：凡是从子目录脚本化调用 aider、或依赖 cwd 相对路径的人，都应重新检查调用方式，因为同一个参数现在可能指向不同位置。
  • 对话内 git 与多行输入 — 新增 /git 命令，无需离开 aider 会话即可运行 git；多行聊天消息现在通过 Meta-ENTER（部分环境为 Esc+ENTER）输入。如果你常驻 aider 对话，这些工作流改进值得升级；它们不影响现有自动化。
  • 安全与权限加固 — aider 会自动创建含 .aider* 的 .gitignore，防止自身文件被误提交；GPT 被引导用”将文件加入对话”之类的措辞来请求编辑许可；错误的编辑块现在会返回详细错误并要求重试，而不是静默失败。可以预期编辑行为会更可靠、更少意外，首次运行后仓库也更干净。
  • 终端与中断行为 — 两秒内连按两次 Ctrl-C 现在必定强制退出；检测到 VSCode 终端时会自动强制 --no-pretty。注意 VSCode 下的覆盖：你在那里配置的任何样式都会被忽略。启动时还会检查 PyPI 新版本并给出通知。
  • 值得升级吗？ — gpt-4/diff 基准为 64.7%，无回归，因此没有能力上的代价。为 /git 命令、更安全的文件处理和更健壮的编辑而升级吧；如果你依赖 cwd 相对的 /add//drop 路径且尚未验证，或这些体验改进对你都无所谓，就可以跳过。这是真正的特性/修复版本，不是重新打标签或仅改元数据的更新。

v0.10.1

  • /add 和 /drop 始终使用相对于 git root 的路径
  • 鼓励 GPT 使用“将文件添加到聊天”之类的语言来请求用户允许编辑它们。

加上 v0.10.0 的更改

  • 添加了 /git 命令以从辅助聊天内部运行 git。
  • 使用 Meta-ENTER（在某些环境中为 Esc+ENTER）输入多行聊天消息。
  • 使用.aider*创建.gitignore，以防止用户意外将aider文件添加到git中。
  • 检查 pypi 是否有较新版本并通知用户。
  • 更新了键盘中断逻辑，以便 2 秒内 2 ^C 始终强制助手退出。
  • 如果 GPT 产生了错误的编辑块，请提供详细的错误，要求重试。
  • 如果助手检测到 --no-pretty 正在 VSCode 终端内运行，则强制执行 --no-pretty。
  • 基准测试，gpt-4/diff 的 64.7%（无回归）
