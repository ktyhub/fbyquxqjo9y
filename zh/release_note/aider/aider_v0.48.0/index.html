aider v0.48.0

小版本 发布时间2024年8月6日 来源Aider-AI/aider 英文原文

变更架构图

亮点

  • Monorepo 性能与 --subtree-only — 本版本主打改动：aider 在大型/单体仓库上更快了，新的 --subtree-only 参数可把范围限制在当前目录子树。如果你只在大 monorepo 的某个包里工作，从那个目录启动 aider 就能降低索引/上下文开销，让仓库地图更聚焦——对一直苦于启动慢、上下文嘈杂的人来说，这是最能立刻用上的改进。

  • 用 --map-tokens 1024 让任意模型都能用仓库地图 — 通过把仓库地图限制在 1024 token，即便上下文预算紧张的模型也能开启它。这是一种有意的取舍：用更少的地图细节换取兼容性；如果你以前不得不在便宜/小模型上完全关掉地图，这个很实用。

  • /add-clipboard-image — 图片可以直接从剪贴板加入聊天，截图、报错弹窗、设计稿不用再先存盘再添加。功能不大，但让”快看这个错误”的常见流程顺畅了很多。

  • Sonnet 8k 输出窗口 — 正式支持 Sonnet 的 8k 输出上限。补充说明：aider 此前实际上已能处理近乎无上限的 Sonnet 输出，所以这更像是个上限/形式上的确认，而非行为变化——别指望 Sonnet 会话会突然变得不一样。

  • litellm 可靠性修复 — 针对 litellm 重试 API 服务器错误的 bug 加了规避方案，并升级依赖以带入上游 litellm 的修复。如果你见过服务商瞬时 5xx 响应导致的偶发失败，这应该会减少；但因为它只是规避方案，在认定它一劳永逸之前，还是要留意后续的 litellm 更新。

  • 破坏性变更 — 无。

  • 大型/单一存储库的性能改进。

  • 添加了 --subtree-only 以将辅助程序限制为当前目录子树。

    • 应该有助于提高大型/单一回购性能。

  • 新的 /add-clipboard-image 可将图像从 clipboard 添加到聊天中。

  • 使用 --map-tokens 1024 将存储库映射与任何模型一起使用。

  • 支持 Sonnet 的 8k 输出窗口。

    • Aider 已经支持 Sonnet 的无限输出。

  • 解决重试 API 服务器错误的 litellm 错误。

  • 升级了依赖项，以修复 litellm 错误。

  • Aider 编写了此版本中 44% 的代码。
