aider v0.8.1

修订 发布时间2023年7月8日 来源Aider-AI/aider 英文原文

aider v0.8.1

亮点

  • Git 仓库自动初始化 — 找不到仓库时，aider 现在会主动提出初始化 git，因为它的变更追踪、diff 和撤销流程都建立在 git 之上。在任何全新或未纳入版本的目录里接受它，否则就失去审查和回滚 GPT 编辑的能力。注意在 CI/脚本环境里可能出现交互提示，导致自动化卡住。
  • /add 和 /drop 支持通配符 — 现在接受通配符，可按模式批量添加或移除文件，不必逐一列举路径。这让把 aider 限定到整个包或测试树变得实用，但过宽的通配会迅速撑大聊天上下文——以及 token 成本。
  • 显式 UTF-8 I/O 与 --encoding — 文本文件现在默认以 UTF-8 读写，--encoding 可覆盖，解码错误会优雅处理。同样的标志也会传给 ctags，要求其返回 utf-8。这是行为改变：若代码库依赖旧的区域编码，请显式设置 --encoding，否则有乱码和意外重写风险。
  • Windows 支持加固 — 修复了路径分隔符问题，文件路径处理更稳健以避免 8.3 短名解析，并新增在 Windows 上跑完整测试套件的 CI 步骤。结合 UTF-8 的工作，这针对 Windows 上两大失败来源；状态消息现在也会解释 ctags 为何被禁用。
  • GPT-4 正式可用与基准数据 — GPT-4 被标记为普遍可用，同时发布了一份对比 GPT-3.5 与 GPT-4 代码编辑任务的基准。这让采用者在决定统一哪个模型时有了成本/质量权衡的具体证据，而非靠猜。
  • 编辑循环 bug 修复 — 修复了文件名缺失时 whole coder 的实时 diff、涉及多文件的聊天，以及 editblock coder 提示的问题。这些都命中核心编辑路径，因此多文件会话和默认的 editblock 工作流应该会明显更可靠。

v0.8.1

  • 如果没有找到，则要求创建一个 git 存储库，以更好地跟踪 GPT 的代码更改
  • /add 和 /drop 命令现在支持 Glob 通配符
  • 将 --encoding 传递给 ctags，要求它返回 utf-8
  • 更稳健地处理文件路径，以避免 8.3 窗口文件名
  • 添加了常见问题解答
  • 将 GPT-4 标记为普遍可用
  • 修复了缺少文件名的整个编码器的实时差异
  • 修复了多个文件聊天的错误
  • editblock 编码器提示中的错误修复

加上 v0.8.0 的所有内容

  • GPT-3.5 和 GPT-4 中代码编辑的基准比较
  • 改进的 Windows 支持：
    • 修复了与 Windows 中路径分隔符相关的错误
    • 添加了 CI 步骤以在 Windows 上运行所有测试
  • 改进了 Unicode 编码/解码的处理
    • 默认情况下显式读取/写入使用 utf-8 编码的文本文件（主要有利于 Windows）
    • 添加了 --encoding 开关来指定另一种编码
    • 优雅地处理解码错误
  • 添加了 --code-theme 开关来控制代码块的 pygments 样式（由 @kwmiebach 提供）
  • 更好的状态消息解释 ctags 被禁用的原因
