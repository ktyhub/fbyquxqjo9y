aider v0.29.0

小版本 发布时间2024年4月21日 来源Aider-AI/aider 英文原文

aider v0.29.0

变更流程图

亮点

  • 原生多服务商连接 — v0.29.0 直接与 Anthropic、Cohere、Gemini 等多家 LLM 服务商通信，不再强制所有请求都走 OpenAI 兼容的适配层。现在可以分别提供各家的 API Key、按能力或成本挑模型，还能避免服务商 API 变动导致的代理兼容问题。如果你之前被锁在单一服务商上，这是本版本里影响最深远的采用变化。

  • --weak-model 分层路由模型 — 用一个专门的参数把更便宜、更快的模型分配给提交信息生成和聊天历史总结，把强模型留给代码编辑。这些辅助任务频繁触发且消耗上下文 token，把它们分流出去，在长会话里是能实测到的成本与延迟收益。要真正用上它，记得更新启动脚本或配置。

  • Anthropic 与视觉的一等快捷方式 — --opus、--sonnet、--4-turbo-vision、--anthropic-api-key 让你不必死记精确的模型标识，接入 Anthropic 密钥也只需一个参数。--4-turbo-vision 是新增图片支持的配套项：正是它让 aider 能真正对你加入的图片进行推理，采用多模态工作流时请把两者搭配使用。

  • 通过 whole/diff 后端支持 Cohere Command-R+ — “whole” 和 “diff” 编辑后端针对 Cohere 可免费使用的 Command-R+ 模型做了调优，让真正零成本的编辑循环成为可能。这是评估 aider 最低门槛的入口，但后端质量仍因模型而异，提交前请审查 diff。

  • /add 可添加磁盘任意位置的图片 — 图片文件不再必须放在仓库或工作目录里，可以从任意文件系统路径加入。这样很方便把机器别处的截图、设计稿、报错画面直接丢进来——搭配 --4-turbo-vision 使用。无需迁移，只是输入面更宽了。

  • CI 与脚本的稳定性 — 修复了 detached-HEAD 仓库中的崩溃，这对在 CI 或”按提交检出”工作流里跑 aider 的场景很重要。另外，CLI 与 Python 脚本 API 现在共用同一个默认模型，消除了库调用者悄悄拿到与 CLI 不同模型这一细微不一致。请重新测试所有嵌入了 aider 的自动化。

  • 添加了对直接连接到 Anthropic、Cohere、Gemini 和许多其他 LLM 提供商 的支持。

  • 添加了 --weak-model <model-name>，它允许您指定用于提交消息和聊天历史记录摘要的模型。

  • 用于处理流行模型的新命令行开关： ---4-turbo-vision ---opus

    • --sonnet
    • --anthropic-api-key

  • 改进了“整体”和“差异”后端，以更好地支持 Cohere 的免费使用 Command-R+ 模型。

  • 允许来自文件系统中任何位置的 /add 图像。

  • 修复了在分离 HEAD 状态下在存储库中操作时发生的崩溃问题。

  • 修复：在 CLI 和 python 脚本中使用相同的默认模型。
