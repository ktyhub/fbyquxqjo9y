aider v0.59.0

小版本 发布时间2024年10月4日 来源Aider-AI/aider 英文原文

aider v0.59.0

这个项目是干啥的：一个在命令行里陪你写代码的AI助手，能自动改代码、总结聊天记录、规范提交信息，给爱用终端的程序员用。

变更架构图

亮点

  • 破坏性选项改名 — --yes 改为 --yes-always，配置也迁移到 AIDER_YES_ALWAYS 和 yes-always:。现有 YAML 和 .env 文件必须更新；命令行上的 --yes 仍可作为缩写使用。

  • 破坏性配置语法变更 — 列表型设置现在要求标准 YAML 列表，用 - list entries 每行一项。升级前请把现有的非标准列表配置改写过来。

  • /read-only 更强 — 文件补全现在用 shell 风格覆盖整个文件系统，并支持 src/**/*.py 这样的 glob，同时保留仓库文件的完整路径补全。这实实在在地改善涉及外部文件或批量读取的工作流。

  • 启动校验与速度控制 — --editor-model 现在和主模型、弱模型一样在启动时做健全性检查，更早发现配置错误。新增的 --skip-sanity-check-repo 开关可缩短大仓库的启动时间，代价是跳过该校验。

  • 稳定性与升级建议 — 架构师模式现在能正确处理 Control-C，确定性的仓库地图生成配合改进缓存应让仓库上下文更一致。/settings 也会显示启动公告，提交信息提示得到改进。依赖仓库地图或架构师模式的用户值得升级；其他人若无这些增量工作流改进的需求可以跳过。

  • /read-only 的改进：

    • 现在支持整个文件系统的 shell 式自动完成。
    • 仍然自动完成存储库文件的完整路径，例如 /add。
    • 现在支持像 src/**/*.py 这样的 glob

  • 将 --yes 重命名为 --yes-always。

    • 现在使用 AIDER_YES_ALWAYS 环境变量和 yes-always: yaml 密钥。
    • 现有的 YAML 和 .env 文件需要更新。
    • 仍然可以在命令行上缩写为 --yes。

  • 配置文件现在使用标准 YAML 列表语法和 - list entries，每行一个。

  • /settings 现在包含与发布时打印的相同的公告行。

  • 理智检查现在发布的 --editor-model，与主要和弱型号相同。

  • 添加了 --skip-sanity-check-repo 开关以加速大型存储库中的启动。

  • 修正了架构师模式可以正确处理 Control-C。

  • Repo-map 现在是确定性的，并改进了缓存逻辑。

  • 改进了提交消息提示。

  • Aider 编写了此版本中 77% 的代码。
