aider v0.46.0

小版本 发布时间2024年7月29日 来源Aider-AI/aider 英文原文

变更架构图

亮点

  • 只读代码问答成为一等模式 — 新增 /ask <question> 和 /chat-mode ask，让你在不让 aider 改动任何东西的前提下审视代码库；/chat-mode <mode> 还提供 code 和 help 模式，让每个会话的意图明确。真正的好处是安全：你可以探索陌生代码或问”鉴权在哪里强制执行的？“，而绝无意外写入的风险，这让 aider 能用于审查、上手和研究工作流——而不只是生成。

  • 通过配置持久化项目上下文 — 在 .aider.conf.yml 里写 file: CONVENTIONS.md（或列表 file: [file1, file2, file3]），即可在每个会话自动加载这些文件。这是与团队最相关的一项：你可以把风格指南、架构说明或提示约定纳入版本控制，保证每位开发者——以及每次脚本化调用——都以相同的上下文起步，而不用靠谁记得去 /add。

  • 流式传输时也能报告成本与 token — 增强的用量/成本报告覆盖了流式响应这条常见交互路径。这补上了一个真实的可观测性缺口：此前流式回合的开销统计基本是盲的。如果你按会话做预算或对比模型成本，请采用此版，因为你之前的数字很可能偏低。

  • --no-verify-ssl 修复并扩展到 /web — 修复了 v0.42.0 中破坏该标志的回归，现在 /web 抓取网站时也会禁用证书校验。如果你曾因公司代理后的 TLS 失败或自签证书而锁在旧版本，现在终于可以升级了。注意：保持开启是一项全局安全权衡——它会在所有适用处关掉证书校验，所以请限定在可信环境使用。

  • 提交信息与 /web 加固 — 提交提示改用祈使语态，弱模型生成不了消息时会回退到主模型，减少空提交或失败提交；/web 获得更好的错误处理，并修复了 Elm tree-sitter scm 语法错误（由 @cjoach 提供）以及流式传输到终端时的 UnicodeEncodeError。模型回退对无人值守/自动化提交流程最关键——此前弱模型失败意味着该步骤直接断掉。

  • 无破坏性变更 — 纯增量命令与修复，无需迁移步骤。

  • 新的 /ask <question> 命令可询问您的代码，无需进行任何编辑。

  • 新的 /chat-mode <mode> 命令用于切换聊天模式：

    • 询问：询问有关您的代码的问题，而不进行任何更改。
    • 代码：请求更改您的代码（使用最佳编辑格式）。
    • 帮助：获取有关使用 aider 的帮助（使用、配置、故障排除）。

  • 将 file: CONVENTIONS.md 添加到 .aider.conf.yml 以始终加载特定文件。

    • 或 file: [file1, file2, file3] 始终加载多个文件。

  • 增强的代币使用和成本报告。现在在流式传输时也可以使用。

  • /add 和 /drop 的文件名自动完成现在不区分大小写。

  • 提交消息改进：

    • 更新了提交消息提示以使用祈使时态。
    • 如果弱模型无法生成提交消息，则回退到主模型。

  • 阻止助手多次要求将相同的网址添加到聊天中。

  • --no-verify-ssl 的更新和修复：

    • 修复了在 v0.42.0 中破坏它的回归。
    • 当 /web 抓取网站时禁用 SSL 证书验证。

  • 改进了 /web scraping 功能中的错误处理和报告

  • 修复了 Elm 的 tree-sitter scm 文件中的语法错误（由 @cjoach 提供）。

  • 将文本流式传输到终端时处理 UnicodeEncodeError。

  • 将依赖项更新到最新版本。

  • Aider 编写了此版本中 45% 的代码。
