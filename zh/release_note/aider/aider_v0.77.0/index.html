aider v0.77.0

小版本 发布时间2025年3月13日 来源Aider-AI/aider 英文原文

亮点

  • 语言支持大换血（tree-sitter-language-pack） — Aider 将解析后端换成 tree-sitter-language-pack，新增 130 种带 linter 支持的语言和 20 种支持 repo-map 的语言。由于 repo-map 是 Aider 构建代码上下文图的核心机制，这才是本次的重头戏：它实实在在地扩大了 Aider 能智能导航的仓库范围，而不只是加个语法高亮。最大受益者是混合技术栈或小众语言中原本不受支持的那些代码库。

  • 推理控制升为一等公民 — 新增 /think-tokens 和 /reasoning-effort 命令，可在运行时调节模型思考强度；不带参数调用时会显示当前值。--thinking-tokens 现在接受 8k、10.5k、0.5M 这类易读字符串，而不再是原始整数；两项设置也会出现在模型信息里——想在不重启的情况下随时调整成本/延迟，这很实用。

  • 架构师编辑默认自动接受 — 新标志 --auto-accept-architect 默认为 true，架构师 coder 格式的输出无需确认就会直接应用。注意：这改变了信任边界——如果你希望在架构师生成的改动落到文件前先过一遍目，请显式关闭它。

  • /drop 现在保留只读输入 — 单独执行 /drop 不再清除最初通过 args.read 提供的文件，因此重置对话上下文不会把有意设为只读的文件一并丢掉。这是个细微的行为修复，主要影响脚本化/自动化 Aider 工作流。

  • 新模型 — 支持名单加入 cohere_chat/command-a-03-2025 和 gemini/gemma-3-27b-it，为已在使用 Cohere/Gemini 的用户多了两种选择。

  • 健壮性与易用性修复 — 已弃用的 --shortcut 开关不再覆盖命令行显式指定的模型；自动补全现在需要输入 3 个字符才触发，减少干扰；模型缓存的 JSONDecodeError 和 git 配置的 GitCommandError 得到优雅处理；文件监视器新增 ignore_permission_denied（感谢 Yutaka Matsubara），受限文件不再不断报错。

  • 通过采用树保姆语言包，在支持的编程语言方面进行了重大升级。

    • 130 种带有 linter 支持的新语言。
    • 20 种新语言，支持 repo-map。

  • 添加了 /think-tokens 命令来设置思考代币预算，支持人类可读格式（8k、10.5k、0.5M）。

  • 添加了 /reasoning-effort 命令来控制模型推理级别。

  • /think-tokens 和 /reasoning-effort 命令在不带参数调用时显示当前设置。

  • 在模型信息中显示思维代币预算和推理努力。

  • 更改了 --thinking-tokens 参数以接受具有人类可读格式的字符串值。

  • 添加了 --auto-accept-architect 标志（默认值：true）以自动接受架构编码器格式的更改，无需确认。

  • 添加了对 cohere_chat/command-a-03-2025 和 gemini/gemma-3-27b-it 的支持

  • 裸 /drop 命令现在保留通过 args.read 提供的原始只读文件。

  • 修复了以下错误：即使已在命令行中指定，默认模型也会由已弃用的 --shortcut 开关设置。

  • 改进了自动完成器，要求 3 个字符进行自动完成，以减少噪音。

  • 修复了加载模型缓存文件时 JSONDecodeError 的处理。

  • 修复了检索 git 用户配置时对 GitCommandError 的处理。

  • 在文件观察器中添加了ignore_permission_denied选项，以防止访问受限文件时出现错误，作者：Yutaka Matsubara。

  • Aider 编写了此版本中 72% 的代码。
