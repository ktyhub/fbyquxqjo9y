claude-mem v15.20.0

小版本 发布时间2026年11月17日 来源thedotmack/claude-mem 英文原文

claude-mem v15.20.0

变更流程图

亮点

  • worker 不再因 settings.json 格式错误而死亡（#6259） — 以前，如果 ~/.claude-mem/settings.json 无法解析，worker 会拒绝启动，即使数据库已持有它试图保存的设备身份，结果什么都不捕获、也不注入上下文。现在它会记录警告、保持文件不动并启动；首次启动且没有已保存身份时，错误会指明文件并提示修复或删除。如果一次错误的配置编辑曾静默杀死你的捕获/注入，这条至关重要。

  • macOS 上 Codex Desktop 实时捕获修复（#6285、#6283） — 在 macOS 的 Bun 下，当另一个进程向某文件追加内容时，fs.watch 不会发出事件，而 Codex Desktop 会为一个线程整个生命周期保持 rollout 文件打开，导致会话在 Codex 关闭文件才被一次性读取——有时迟了一天。转录监视器现在每 3 秒重新检查已 tail 过的文件，一次只等一个 stat，使庞大的 ~/.codex/sessions 历史不会阻塞 worker，且它仍不会自行打开新文件。macOS Codex Desktop 用户应立即升级。

  • 导入接受度修复，附带破坏性限制变更（#6206） — Supermemory --documents 重跑不再重复，15.19.0 导入的文档仍计为已导入，Mem0 过期现在包含其自身日期。迁移提示： 无来源的 100 MiB 总量上限和 10,000 条默认记录被移除；现在每个导入限制都要指明来源，--max-records 保留。如果任何导入脚本或预期依赖那些旧默认值，请在升级前审查。

  • 三个 16.0.0 早期特性随该补丁一同发布 — #6229 重新设计经典 viewer 和 TV 页面：跳到长时间线末尾不再因 React error 185 崩溃，并提供单行页头、带计数的线型 chip、“在已加载记忆中查找”、日期标签、以最新摘要命名的会话页、标签式设置，以及三行标题和 Live 圆点的 TV 页面。#6233 新增五步设置栏、各处返回按钮、纯语言错误（原始原因在 Details 下），以及非破坏性的 Stop import（POST /api/setup/import/stop 自身不删除任何内容也不重启）和添加内容回执。

  • 升级结论 — 不是空操作、重新打标签或纯元数据发布：它带两个关键修复和三个前移到本补丁的 16.0.0 特性。如果你在 15.19.0 或更早版本，建议升级——尤其是 macOS Codex Desktop 用户和 ~/.claude-mem/settings.json 损坏的人，他们的捕获/注入此前已静默失效。只有不使用 Codex 捕获或导入、配置健康且宁愿等稳定 16.0.0 的用户可以合理跳过；唯一迁移步骤是检查依赖已移除限制默认值的导入配置。

两个关键修复

  • 当设置时工作器启动。json 无效 JSON (#6259)。当无法解析 ~/.claude-mem/settings.json 时，工作线程拒绝启动，即使数据库已经保存了它试图保存在那里的设备标识。没有捕获任何内容，也没有注入任何上下文。现在它会记录一条警告，保持文件不变，然后启动。在没有保存身份的情况下首次启动时，错误会命名该文件并提示修复或删除它。
  • macOS 上的实时 Codex 桌面捕获（#6285，感谢 @MaxWang007；由 @AlbertValverdeC 在 #6283 中报道）。在 macOS 上的 Bun 下，fs.watch 不会发出任何事件，而另一个进程会追加到它保持打开状态的文件，而 Codex Desktop 在线程的生命周期内保持打开的转出文件。当 Codex 关闭文件时，Codex 会议会被一次性读取，有时是一天后。转录观察器现在每 3 秒检查一次已跟踪的文件并读取新字节。它一次等待一项统计数据，因此大量的 ~/.codex/sessions 历史记录永远不会阻塞工作线程，并且它永远不会自行打开新文件。

自 15.19.0 起也位于 main 上

即将推出的 16.0.0 的三部分已在主网上发布，也在此版本中发布：

  • Mem0 和超级内存导入接受修复 (#6206)：超级内存 --documents 重新运行不再重复，并且 15.19.0 导入的文档仍然算作已导入。 Mem0 到期包含其自己的日期。每个进口限制都会注明其来源；未获取的 100 MiB 总计和 10,000 条默认记录都消失了（--max-records 保留）。
  • 经典查看器和电视页面重新设计（#6229）：跳转到长时间线的末尾不再使查看器崩溃（React 错误 185）。单行标题、时间线类型的芯片，包含计数、“在加载的内存中查找”、日期标签、以最新摘要为标题的会话页面、选项卡式设置和更简单的日志。电视页面最多可容纳三行标题，并显示一个实时点。
  • 设置步骤栏和停止导入 (#6233)：一个五步栏，每个屏幕上都有“返回”，在“详细信息”下以简单的文字显示错误，并显示原始原因，并停止导入（POST /api/setup/import/stop，没有删除任何内容，也没有任何内容自行重新启动），并附有添加内容的收据。
