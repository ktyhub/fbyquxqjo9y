claude-mem v16.0.4

修订 发布时间2026年11月22日 来源thedotmack/claude-mem 英文原文

claude-mem v16.0.4

修复

  • 在嵌入模型下载时色度搜索再次工作（#6399，关闭@FengJie2004报告的#6365的“无效端口”部分，根本原因由@kevincommits发现）。 httpx 0.28 误读了括号中的 IPv6 条目，例如 NO_PROXY 中的 [::1]，并因 Invalid port: ':1]' 失败，因此 chroma-mcp 无法添加文档，并且搜索回退到 FTS5。 chroma-mcp 子级现在获得相同的主机，不带括号 (::1)。具有端口的条目以及所有其他条目均保持不变。
  • 上下文注入保留其概念是旧的普通字符串的观察（#6393，感谢@jianjian248，关闭@soarkit报告的#6389）。关键字搜索与 缓存 等遗留概念相匹配，但上下文注入丢弃了相同的观察结果。现在，两者都通过一个共享的 SQL 表达式来读取概念，因此它们不会再次疏远。
  • OpenCode Go 回答了我的工作刷新和语料库步骤（#6395，感谢 @HemanRamlal）。 API 代理现在发送 OpenCode Go 需要的 x-opencode-session 标头（每次运行一个 id），并使用 Go 所遵循的 reasoning_effort: none 关闭推理。之前，400 MissingSessionID每一步都失败了，或者在思考时用完了其答案预算。
  • 过期的实时观察者输入被计数并报告（#6394，感谢@Zhong-fan，关闭@abhiroopb 报告的#6391）。实时缓冲区仍然会在五分钟内丢弃无人认领的输入，并且仍然不会重播它。 WARN 行现在带有运行总计，/api/processing-status 将其返回为 expiredObserverInputs，因此无需读取日志即可看到损失。
  • /api/tool-uses 拒绝糟糕的约会而不是忽略它（#6387，感谢@kevincommits）。非数字（ISO 日期、拼写错误或给定的参数两次）的 dateStart 或 dateEnd 被删除，并且列表返回每个日期的行。现在它的答案是 400 INVALID_DATE。纪元毫秒值的工作方式与以前一样。
  • /api/dedup/candidates 拒绝小数限制而不是回答 500 （#6388，感谢 @REI-330）。 limit=2.5 与 datatype mismatch 失败。非整数的限制现在回答 400 limit must be a whole number，并且存储会限制它绑定的内容，因此负限制无法读取每一行。
  • /api/advisor-calls 像其他列表一样限制其偏移量（#6396，感谢 @DeryFerd）。巨大的 offset 使 SQLite 扫描并丢弃工作线程共享连接上的行。它现在使用共享列表上限，并且使用 offsetCapReached 保持分页停止的查看器。

托管同步服务

  • 同步 API 在发送其秘密之前检查投影仪 URL（#6397，感谢 @DeryFerd）。 INTERNAL_PROJECTOR_URL 现在遵循与 FORWARD_ORIGIN 相同的规则（绝对 https、仅用于环回的纯 http、无凭据、查询或片段），并且在启动时失败。之前，拼写错误或 http:// 地址以明文形式发送了内部承载秘密。这会更改 services/sync-api，它不是 npm 包的一部分：只有在部署该服务后它才会到达用户。

内部

  • 一名助手现在决定列表抵消是否超过上限（#6398，感谢@DeryFerd）。行为没有改变。
  • 16.0.3 changelog 现在告诉 OMP 用户运行 npx claude-mem install --ide omp 一次以获得服务器运行时修复。 完整 changelog：https://github.com/thedotmack/claude-mem/compare/v16.0.3…v16.0.4
