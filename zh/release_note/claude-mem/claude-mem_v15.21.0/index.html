claude-mem v15.21.0

小版本 发布时间2026年11月17日 来源thedotmack/claude-mem 英文原文

变更流程图

亮点

  • Code Mode 兼容性 — claude-mem 不再 hook tool.call，而是通过 session.append 读取结果，使 Claude Code 实验性的 Code Mode（2.1.323+）可以在启用插件时启动。自动清除在支持 mod 的版本（2.1.287+）上仍有效。Code Mode 用户应升级；无需配置变更。

  • 自动清除的连续性与阈值 — 自动清除仍通过 CLAUDE_MEM_AUTO_CLEAR_ENABLED=true 可选启用。现在从 40% 上下文使用率开始，而非 33%，并在 /clear 后使用保存的列表、已完成任务和总体目标恢复；不完整状态仍回退到 continue。CLAUDE_MEM_AUTO_CLEAR_PERCENT 仍是覆盖项，如需旧阈值请显式设置。

  • 新集成与 provider 控制 — Hermes Desktop 通过 claude-mem hermes install --mcp-only --project-cwd <absolute-directory> 获得仅 MCP 的搜索/保存，不进行自动捕获。VS Code 中的 Copilot 现在通过 ~/.copilot/mcp-config.json 暴露 claude-mem 工具，modelgo 预设支持 https://api.modelgo.ai/v1 而不选默认模型。CLAUDE_MEM_API_AGENT_EXTRA_BODY 还支持 provider 专属选项，如在 vLLM 上禁用 Qwen thinking。使用这些客户端或 provider 请升级；否则这些新增是可选的。

  • My Work 与大数据可靠性 — 慢速 API agent 响应现在获得完整 10 分钟上限，拒绝 max_tokens 的端点会重试一次并改用 max_completion_tokens，过大的 story 工作会被拆分而不是耗尽模型上下文。当托管提示数据超过 2 MiB 时，设置流程不再卡在 99%，大型导出分块导入而非报 HTTP 413。使用慢模型、长对话或大型备份的用户应升级。

  • 安全与针对性平台修复 — shell-quote 1.11.0 脱离关键 CVE-2026-102422 的影响范围，adm-zip 0.6.1 和 zod 4.6.7 修复 High 级公告。Gemini API key 从 URL 移入请求头，原子写入使用独占的随机临时文件，未认证的 /v1/info 泄露更少。还修复了 Windows 上 RULES-AND-TOOLS.md 加载、影响 claude-mem start 的陈旧别名，以及自托管任务重试。未列出破坏性变更或必需迁移；未受影响用户可跳过（除非想要安全加固），而 Windows 和自托管用户应升级。

claude-mem 不再关闭 Claude Code 的代码模式

  • 代码模式从启用 claude-mem 开始（#6278，感谢 @naive000；由 @nasif-naseef 在 #6209 中报告）。当插件的钩子模块钩子 tool.call 时，代码模式（实验性、Claude Code 2.1.323 及更高版本）拒绝启动。 claude-mem 的自动清除模式确实如此，因此对于启用了 claude-mem 的每个人来说，代码模式都处于关闭状态，即使自动清除功能已关闭。该模组现在改为通过 session.append 读取工具结果。自动清除功能仍然适用于运行 mods 的每个 Claude Code 版本（2.1.287 及更高版本）。

自动清除从上次中断的地方开始

除非将 CLAUDE_MEM_AUTO_CLEAR_ENABLED 设置为 true，否则自动清除仍处于关闭状态。当它打开时：

  • 它以继续提示而不是简单的“继续”一词继续（#6294）。在清理之前，克劳德最后一次保存其工作状态，命名其正在工作的列表、刚刚完成的任务以及总体目标。在 /clear 之后，自动清除发送： You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. 如果该保存留下了三个中的任何一个，它会像以前一样发送“继续”并记录原因。
  • 它从上下文窗口的 40% 开始，而不是 33% (#6294)。您在 settings.json 中设置的 CLAUDE_MEM_AUTO_CLEAR_PERCENT 或环境仍然获胜。

新的连接方式

  • Hermes Desktop，通过 MCP 搜索并保存（#6284，感谢 @krishnadobhal；#5940 的一部分）。 claude-mem hermes install --mcp-only --project-cwd <absolute-directory> 添加 claude-mem 作为 Hermes One 和 Hermes Desktop 的 MCP 服务器，但不使其成为内存提供者。当您要求时，您可以搜索并保存；没有任何东西是单独捕获或注入的。 claude-mem hermes uninstall 仅删除其写入的内容并逐字节恢复 config.yaml。
  • VS Code 中的 GitHub Copilot （#6286，感谢 @krishnadobhal；#5895 的一部分）。 npx claude-mem install --ide copilot-vscode 写入 VS Code 的 Copilot 代理读取的 MCP 条目（~/.copilot/mcp-config.json，与 Copilot CLI 使用的文件相同）。该条目现在包括 "tools": ["*"]。如果没有它，VS Code 连接到 claude-mem 但从未向模型提供其工具。还没有自动捕捉。
  • ModelGo 预设（#6277，感谢 ModelGo 团队的 @lichloe1116-gif）。兼容 OpenAI 的提供商为 https://api.modelgo.ai/v1 预设了 modelgo。它没有设置默认模型，因此请选择您的密钥可以使用的一个。

也是新的

  • 工作状态写入检查（#6217，感谢@vieGPT）。您可以让 work_state_write 在写入您在 ~/.claude-mem/work-state-write-guard.json 中选择的列表之前运行本地检查命令。拒绝写入会返回 HTTP 409 并且不会保存任何内容。如果没有文件，则不会发生任何变化。
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY（#6225，感谢@Moep90；#6223）。添加到 api 代理发送的每个请求的 JSON 对象（“我的工作”刷新和具有 api 的语料库代理）。对于 vLLM 上的 Qwen 模型，{"chat_template_kwargs":{"enable_thinking":false}} 会关闭推理。 model、messages 和 max_tokens 等字段会被删除并发出警告，并且永远不会发送到 cmem.ai 网关。

我的工作刷新

  • 您自己的模型的缓慢答案不再在大约 5 分钟内失败（#6224，感谢 @Moep90；#6222）。在应用 api 代理的 10 分钟请求限制之前，Bun 的提取放弃了已安静 5 分钟的连接。现在，这一限制是唯一的。
  • 想要 max_completion_tokens 工作的端点 (#6242)。当端点拒绝 max_tokens 时，api 代理会再次使用 max_completion_tokens 发送请求，而不是使用 HTTP 400 使每个调用失败。
  • 刷新不再因被拒绝两次的答案而停滞（#6212，感谢@Moep90）。在重试一次分组、聚焦或审阅时，未通过检查的部分将被删除，其余部分将被保存。以前，同一批次每次运行都会失败。
  • 构建故事是分段编写的（#6279，感谢@0xABCD01；@Moep90 在#6226 中报道）。故事步骤在一个问题中发送了每一条更改的评论。这个问题超出了模型的上下文窗口，之后的每次刷新都失败了。现在，它会发送符合其他步骤使用的相同问题预算的部分。
  • 长对话按最新请求分组，而不是前十个请求（#6243，感谢@Afloat16）。
  • 使用 git commit --message 或 --message= 所做的提交被识别（#6236，感谢@Afloat16）。
  • 仅当证据命名一个存储库时，提交才会获得 GitHub 链接（#6237，感谢 @Afloat16）。
  • 当“我的规则”等待代理时，它会链接设置 API 刷新的说明（#6214，感谢 @liuyinchu）。

设置、导入和导出

  • 当提示历史记录很大时安装完成（#6280，感谢@0xABCD01；#6266；@deserteaglemj 在#6227 中报告）。当最近的提示超过 2 MiB 托管上传限制时，安装程​​序在“查找您最近的工作”时停止在 99%，并且每次重试都以同样的方式失败。现在它已完成在您计算机上的设置并如此说明。同意步骤还显示“一次上传太多。取消勾选工具或跳过扫描。”并关闭上传按钮，直到选择合适。
  • 大量出口进口（#6261，感谢@Afloat16）。在保存任何内容之前，超过工作人员 5 MiB 请求限制的文件被拒绝 (HTTP 413)。现在，大文件会分部分发送，首先发送会话及其完整内容。
  • 当 CLAUDE_MEM_DEDUP_ENABLED 开启时，通过重复数据删除找到导入的观测值，就像实时观测值一样（#6263，感谢 @Afloat16）。
  • claude-mem import --dry-run 不再因错误的工作设置而停止，因为预览永远不会调用工作人员（#6215，感谢@liuyinchu）。
  • 从另一个代理导入的 Codex Desktop 对话不再算作在 Codex 中输入的提示（#6219，感谢 @rigel905；#6218）。
  • 导出到 /dev/stdout、/dev/stderr、符号链接或 FIFO 在那里写入干净的 JSON，进度线和警告转到另一个流（#6288，来自@Afloat16 的#6258）。

修复

  • Windows：Claude Code 再次加载 RULES-AND-TOOLS.md （#6234，感谢 @QuantScorpus）。 claude-mem 用反斜杠编写了 @ 导入行。 Claude Code 会跳过那些没有任何单词的内容，然后 claude-mem 也省略了指令的其他副本，因此两者都没有到达模型。这些行现在使用正斜杠。受保护的代码示例中显示的 @ 导入不再算作真实的导入（#6293，来自@Afloat16 的#6241）。
  • claude-mem start 运行已安装的工作程序（#6235，感谢 @ZedingZhang；由 @ExactDoug 在 #6228 中报告），而不是旧 shell 别名指向的副本，它可能会缺少其依赖项。
  • 备份在时钟调回后保留新快照（#6273，感谢@Afloat16）。之前，清理可以删除它刚刚报告为已保存的快照。
  • 即使可选共享步骤失败，teambrain join也会打开新的同步连接（#6275，感谢@Afloat16）。
  • 不存储没有进展的摘要（#6202，感谢@ShitK）。过去，只有标题或未来计划的摘要会被保存并宣布为成功。
  • Claude Code 的自动消息不再分割请求（#6251，感谢 @Afloat16）。顾问和可交付扫描将它们视为新请求，并丢失了同一回合的早期建议和文件写入。
  • Corpus 构建了超过 250,000 个观察工作（#6271，感谢 @Afloat16）。他们的 too many SQL variables 失败了。
  • Codex：使用点 TOML 键关闭的插件保持关闭（#6239，感谢 @Afloat16），例如 plugins."claude-mem@claude-mem-local".enabled = false。
  • mem-search 技能的 frontmatter 有效 YAML （#6276，感谢 @Afloat16；由 @orbiutyt 在 #6267 中报告）。
  • Aider： 安装程序编辑 Aider 实际使用的配置文件（首先是工作目录，然后是 git root，然后是 home）（#6289，来自 @Afloat16 的 #6230），并在 read: 列表中保持引用的文件路径完整（#6290，来自 @Afloat16 的 #6231）。
  • 当两次刷新重叠时，光标和 Grok 上下文文件会保留较新的上下文（#6291，来自 @Afloat16 的 #6232）。
  • 自托管服务器： 具有撤销密钥或范围违规的作业运行一次而不是三次 (#6252)，并且 claude-mem server jobs retry 使用队列的重试和退避重新发布 (#6253)，感谢 @HEOJUNFO。 OpenRouter 提供程序在检查令牌字段错误的答案时最多读取 64 KiB（#6238，感谢 @Afloat16）。一个不可读的代理事件不再破坏该表的每次读取（#6199，感谢@DeryFerd）。

安全

  • shell-quote 1.11.0 （#6205，感谢 @manippoudel；由 @lucasbritolubro 在 #6200 中报告）。版本 1.9.0 位于 CVE-2026-102422（严重）范围内。 claude-mem 中没有代码路径到达受影响的代码；这把它从什么船上拿出来了。
  • adm-zip 0.6.1 和 zod 4.6.7 在插件运行时中，出于他们的高级建议（#6220，感谢 @LeviReisJs；@noumanbhatti 在 #6211 中报告）。
  • Gemini API 密钥位于标头中，而不是请求 URL（#6196，感谢 @DeryFerd），因此代理和访问日志不会记录它。
  • 临时文件获得随机名称，并在剩余的原子写入站点上专门创建（#6198，#6193，感谢@DeryFerd），因此植入的符号链接无法重定向设置或状态文件的写入。
  • 自托管服务器未经身份验证的 /v1/info 仅显示状态（#6195，感谢 @DeryFerd）：没有身份验证模式、架构版本、Redis 主机或驱动程序错误文本。
  • CI：安装后白名单检查检查每个直接插件依赖项（#6197），生成环境检查读取生成上方声明的 env 块并扫描插件运行时（#6194），感谢 @DeryFerd。

对于贡献者

  • TypeScript 7.0.2（#6207，感谢@krishnadobhal；#6188）。使用编译器 API 的脚本和测试通过别名保留 TypeScript 6。
  • 导入冒烟测试会在最终扫描之前关闭其 SQLite 读取器（#6216，感谢 @liuyinchu）。
