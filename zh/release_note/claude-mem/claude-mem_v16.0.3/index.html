claude-mem v16.0.3

修订 发布时间2026年11月21日 来源thedotmack/claude-mem 英文原文

claude-mem v16.0.3

这个项目是干啥的：给 Claude Code 装长期记忆的插件，让 AI 记住跨会话的上下文和你的习惯，不用每次重新交代。给天天用它的开发者用。

变更架构图

亮点

  • OMP + 服务端运行时会话不再被静默丢弃——需要迁移步骤 — 在 CLAUDE_MEM_RUNTIME=server 或 server-beta 下，OMP hook 一直把所有内容发往本地 worker，导致 OMP 会话消失。现在它读取 CLAUDE_MEM_SERVER_URL、CLAUDE_MEM_SERVER_API_KEY、CLAUDE_MEM_SERVER_PROJECT_ID（或 CLAUDE_MEM_SERVER_BETA_* 名称；环境变量优先于 settings.json）并直接驱动服务端 /v1 API，应用 worker 自身的规则（剥离 <private>、遵循排除项目和 CLAUDE_MEM_SKIP_TOOLS、记录每条提示、从 git 派生项目名），服务端配置不全时回退到 worker（#6367）。因为 hook 是复制出来的文件，仅更新插件不会替换它：OMP 用户必须运行一次 npx claude-mem install --ide omp。如果你把 OMP 与服务端运行时配合使用，请立即升级；其他人在此无收益。
  • 停滞请求和超大数据不再卡死或撑爆 worker — 知识查询/prime 现在 10 分钟后停止，语料请求 15 分钟后以 504 结束，而不再在 Agent SDK 流停滞后永久挂起；语料在工作真正停止前保持锁定，因此删除或重建后不能再写入（#6368）。claude/codex/gemini/opencode 的 CLI 输出被限制在 128 Mi 字符（#6384），超过 64 MiB 的 JSONL 记录被跳过并警告文件名、偏移和大小（#6383），字段压缩/Telegram Claude 子进程现在也在 worker 的进程列表中，硬退出不会留下孤儿进程（#6385）。对运行长生命周期 worker、回填或大型转录的人，这是升级的有力理由。
  • 安装程序和 CLI 行为更安全 — OpenClaw 安装程序不再对 ~/.openclaw/openclaw.json 指定的任意路径执行 rm -rf；只在目录缺失、为空或包含 claude-mem 自身 manifest 时替换文件夹，否则警告并回退到默认扩展目录（#6381）。server api-key create/migrate-scopes 上裸用 --scope、--name、--team 或 --project 现在打印 --<flag> requires a value 并以 1 退出，而不再创建一个作用域为字面量 true 的 key（#6375）；未认证的 /v1/info 不再把 Redis 主机/端口错误文本泄漏进响应（#6380）。
  • 新的可选控制及各类故障修复 — CLAUDE_MEM_CHROMA_MAX_THREADS=2 是对 chroma-mcp 嵌入线程的可选上限，配合 Linux 上的 taskset 也限制 CPU；默认关闭（0），因为它拖慢首次回填，底层问题 #6365 仍未解决（#6369）。还新增面向 openai-compatible provider 的 AIGROW 预设（#6370），修复无模型的观察导致 agent 成本报告崩溃（#6376）、通过 node:20-trixie 修复 tree-sitter 0.26 较新 glibc 的 Docker 构建（#6386）、OpenCode 2.x 拒绝 --pure/--dir 时的 My Work 刷新（#6361），以及 OMP/Hermes 在 settings.json 中使用数字 CLAUDE_MEM_WORKER_PORT 的问题（#6363）。命中任一项请升级。
  • 托管同步加固实际上不在此 npm 版本内；除此之外是可安全直接替换的升级 — services/sync-api 和 services/sync-hub 现在以常数时间比较内部 projector 凭证以避免时序泄漏（#6382），但它们未随 npm 包提供，因此只有部署了那些服务的用户才能享受到——不要把 v16.0.3 当作包含此项。此补丁没有破坏性变更或移除，除 OMP 重装外都是直接升级：OMP/服务端和可靠性敏感用户应尽快升级，其余可按需升级，只关注测试套件变更（#6360）的人可以跳过。

关键修复

  • OMP 挂钩与服务器运行时一起工作（#6367，感谢 @flipcyde101，关闭 @walynde 报告的#6366）。当 CLAUDE_MEM_RUNTIME 为 server 或 server-beta 时，OMP 挂钩仍将所有内容发送到本地工作线程，因此 OMP 会话被丢弃。该钩子现在读取 CLAUDE_MEM_SERVER_URL、CLAUDE_MEM_SERVER_API_KEY 和 CLAUDE_MEM_SERVER_PROJECT_ID（或 CLAUDE_MEM_SERVER_BETA_* 名称；环境变量胜过 settings.json）并直接与服务器的 /v1 API 对话：会话启动、工具和回复事件、上下文和会话结束。它应用与工作人员在保存任何内容之前应用的相同规则：<private> 块被剥离，排除的项目和 CLAUDE_MEM_SKIP_TOOLS 被遵守，记录每个提示，项目名称来自 git。如果服务器设置不完整，则会像以前一样回退到工作程序。
  • OMP 用户：运行 npx claude-mem install --ide omp 一次即可获得此修复。 OMP 挂钩是复制文件，因此单独的插件更新不会替换它。

修复

  • 知识查询和语料库请求不能再永远挂起（#6368，感谢@flipcyde101，关闭@soarkit报告的#6364）。一个停滞的代理 SDK 流用于使请求及其 Claude CLI 子项保持活动状态。现在，知识查询或素数在 10 分钟后停止，语料库请求在 15 分钟后停止，并出现 504 错误。语料库将保持锁定状态，直到超时工作真正停止为止，因此在删除或重建后无法写入。
  • 一旦 Codex 保存，“暂停保存内存”通知就会消失（#6374，感谢@ryrenz，关闭@raw34 报告的#6372）。在克劳德配额暂停后将 CLAUDE_MEM_PROVIDER 切换到 codex 后，每个新会话仍然表示捕获已暂停，直到旧的克劳德冷却时间耗尽。现在，当 Codex 存储内存时，会重新计算通知。
  • 没有值的 server api-key create --scope 被拒绝（#6375，感谢@ryrenz，关闭@soarkit 报告的#6373）。它用于创建一个范围为文字字符串 true 的键，然后每个请求都会被拒绝。现在，在 create 和 migrate-scopes 上，裸机 --scope、--name、--team 或 --project 都会打印 --<flag> requires a value 并退出 1，而不写入任何内容。
  • 代理成本报告不再因没有模型的观察而崩溃（#6376，感谢@ZedingZhang，关闭@Realauster 报告的#6371）。当一个窗口同时存在缺失型号和已命名且未定价的型号时，acr.py rollup 提出了 TypeError。
  • Docker 服务器映像再次构建（#6386，关闭@InfoALR 报告的#6379）。它现在使用 node:20-trixie，因为树守护者 0.26 需要比 node:20 更新的 glibc。
  • 我的工作刷新在 OpenCode 2.x 上运行（#6361，@Realauster 报告的参考文献#6339）。 OpenCode 2.x 拒绝 --pure 和 --dir 标志，因此每个刷新步骤都会退出 1。该步骤现在检查 opencode --version 并使用每个版本自己的隔离。 2.0.0 到 2.2.2 和 3.x 被拒绝是有原因的，因为它们无法阻止插件。在每个版本上，刷新代理现在都拒绝所有工具。
  • OMP 和 Hermes 读取保存为数字的工作端口（#6363，感谢 @chuenchen309）。 settings.json 中的 {"CLAUDE_MEM_WORKER_PORT": 45678} 过去会被忽略，因此它们的请求会转到默认端口。
  • OpenClaw 安装程序不再删除未安装的文件夹（#6381，感谢 @DeryFerd）。它在名为 ~/.openclaw/openclaw.json 的任何安装路径上运行 rm -rf。现在，仅当文件夹丢失、为空或包含 claude-mem 自己的 OpenClaw 清单时，它才会替换该文件夹。其他任何内容都会留下警告，并使用默认的扩展文件夹；如果它也被其他东西占用，安装程序就会停止。
  • 工人可以阻止它启动的每个克劳德孩子（#6385，感谢@DeryFerd）。字段压缩和 Telegram 总结在工作进程列表之外启动了 Claude 进程，因此硬退出的工作进程让它们继续运行。它们现在位于该列表中，并且不占用并发槽。
  • CLI 卡住的打印无法无限制地增加工作人员的内存（#6384，感谢 @DeryFerd）。从 claude、codex、gemini 和 opencode 收集的输出上限为 128 Mi 个字符，大约是测量的最大实际匝数的 2.5 倍。超过上限后，将保留开始和结束，记录警告，并且拒绝回复而不是读取部分答案。较小的输出保持不变。
  • 无止境的转录记录无法无限制地增长工人的记忆（#6383，感谢@DeryFerd）。超过 64 MiB 的 JSONL 记录（测量的最大实际记录为 44 MiB）将被跳过，并显示一条警告，指出该文件的名称、记录的偏移量及其大小。它后面的行可以正常读取。
  • 未经身份验证的 /v1/info 不再显示 Redis 错误文本（#6380，感谢 @DeryFerd）。无法读取的队列通道用于发布驱动程序的错误，例如主机和端口。原因现在保留在服务器日志中。

新

  • 选择加入 chroma-mcp 的 CPU 上限（#6369，感谢 @flipcyde101，部分解决了 @FengJie2004 报告的#6365）。如果 chroma-mcp 使多个核心保持忙碌，请将 CLAUDE_MEM_CHROMA_MAX_THREADS 设置为 2。它限制了嵌入器的线程，并且在具有 taskset 的 Linux 上，chroma-mcp 可以使用 CPU。默认情况下它处于关闭状态 (0)，因为始终开启的上限会减慢第一次回填的速度。 #6365 保持开放。
  • AIGROW 为 OpenAI 兼容提供商预设（#6370，感谢 @guglielmo-io）。

托管同步服务

  • 同步服务在恒定时间内比较其内部投影仪凭证（#6382，感谢@DeryFerd）。普通字符串比较可能会通过响应时间泄露共享秘密。这改变了 services/sync-api 和 services/sync-hub，它们不是 npm 包的一部分：它仅在部署这些服务后到达用户，而不是通过此版本。

测试

  • 片状的成绩单测试现在计算附加民意调查的戳数，而不是与文件检查竞争（#6360）。 完整 changelog：https://github.com/thedotmack/claude-mem/compare/v16.0.2…v16.0.3
