claude-mem v15.11.0

小版本 发布时间2026年11月6日 来源thedotmack/claude-mem 英文原文

claude-mem v15.11.0

这个项目是干啥的：给 Claude Code 装长期记忆的插件，让 AI 记住跨会话的上下文和你的习惯，不用每次重新交代。给天天用它的开发者用。

变更架构图

亮点

  • 安装程序遥测 — v15.11.0 在九个设置屏幕上新增逐屏追踪，包括回访、分支路径和错误。事件遵循 DO_NOT_TRACK，校验已知字段，并排除提示、文件名、URL 和凭证。逐屏历史从此版本开始；旧安装程序缺失的事件不应被解读为放弃安装。对诊断设置摩擦有用，但不是单纯为了最终用户功能而升级的理由。
  • 更安全的本地捕获恢复 — 实时捕获现在使用有界交接；陈旧的挂起观察者工作 5 分钟后过期，并在配额/认证失败时被丢弃，而不是恢复后重放。行为变更： 中断期间跳过的捕获不会回填，尽管已保存的记忆和原始转录保持完整。如果陈旧重放曾造成问题，请升级；否则要考虑到中断期捕获会故意丢失。
  • 服务端运行时修复 — 服务端 viewer 读取端点恢复，使用 Postgres 数据和既有团队/项目授权，而共享服务器日志文件仍对租户 key 不可访问。dumb_search 不再在服务端运行时宣传，因为只有本地 worker 能执行它。服务端 viewer 用户应升级；仅本地用户一般可跳过，除非受影响。
  • 本地默认值与 UI 修复 — 默认 worker 端口现在按安装派生以避免冲突，同时保留旧的 Windows 服务端端口。生成的上下文把项目外的家目录文件显示为 ~/…，My Work 刷新优先使用配置的 provider 的 agent。这些都是对受影响安装的体验改进，但未记录明确的破坏性 API 变更或必需迁移步骤。

安装程序屏幕遥测和运行时修复

Claude-Mem 现在通过本地设置屏幕记录进度，因此管理员可以显示设置在哪里继续、返回、遇到已知错误或没有记录下一步。

  • 跟踪九个实际设置屏幕：扫描、显示、选择内存、查看节省、结帐、完成设置、导入历史记录、启动和工作区。
  • 单独计算每个渲染屏幕的访问次数。返回屏幕会创建新的访问；失败的切换不会成为成功的前向转换。
  • 保留真实的设置分支。在 Home 和现有 Pro 配置中，跳过结帐，历史导入返回到“完成设置”，而简化运动设置则跳过启动动画。
  • 仅在工作程序接受成功的设置状态写入后才记录本地设置完成。
  • 当安装完成时保留挂起的屏幕事件并重试临时本地工作连接失败，因此快速完成或缓慢的遥测请求不会丢失访问历史记录。
  • 启用遥测功能时，通过现有安装程序配对传递新的设置尝试 ID，从而允许匹配的管理报告将设置进度连接到授权帐户流程。

这些事件遵循现有分析设置，包括 DO_NOT_TRACK。他们的架构仅接受已知的屏幕 ID、操作、错误代码、时间戳和随机尝试/访问 ID。提示、文件名、URL、凭据和自由格式的错误文本均被排除。示例预览不会发出设置事件。工作人员的长期匿名身份没有别名到帐户。

每屏历史记录从此版本开始。较早的安装人员没有记录这些屏幕，因此他们丢失的事件不会被视为零转换或放弃。

自 v15.10.1 起包含运行时修复

  • 配额或身份验证恢复后停止重播陈旧的本地观察者工作。实时捕捉使用有界切换；待处理的输入将在五分钟后过期，并在配额/身份验证失败时被丢弃。保存的记忆和原始记录保持完好。中断期间跳过的捕获不会自动回填。
  • 使用服务器的 Postgres 数据和现有团队/项目授权恢复服务器查看器的读取端点。共享服务器日志文件对租户密钥仍然不可用。
  • 停止在服务器运行时通告 dumb_search，只有本地工作人员可以执行它。
  • 派生每次安装的默认工作端口以避免本地端口冲突，同时保留旧版 Windows 服务器端口。
  • 在生成的上下文中将主目录下的项目外部文件显示为 ~/…，而不是父目录段的长链。
  • 首选已配置提供商的代理进行“我的工作”刷新。
