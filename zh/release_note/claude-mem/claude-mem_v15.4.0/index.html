claude-mem v15.4.0

claude-mem v15.4.0

变更流程图

亮点

  • 聚焦领域取代 My Goals — “My Work” 现在围绕带优先级、needs-you 计数、合并进度和待处理请求的”聚焦领域”组织；在移动端显示为一行 chip。新领域可以保留、重命名、合并或忽略，决策会跨设备同步。迁移： My Goals 已退役，请改用新的领域页面；其内容已迁移过去。
  • 对话在分组 agent 运行前即归档 — 已有代码链接或匹配的 request_id 会立即加入请求。在 CMEM Pro 上或使用你自己的 OpenRouter key 时，Jev 还会提出匹配建议：分数 ≥0.8 自动加入，0.5–0.8 显示 Join / Not this，更低分数则新建请求。聚焦领域建议在自动归类校准前仅供参考。没有 Jev 时行为不变。
  • 请求现在能跨项目根目录保留对话 — 若请求的决策指定了项目根目录，来自其他根目录的对话也能加入并在后续刷新中保持关联。这对 monorepo、仓库迁移以及跨多个 checkout 的工作很重要。
  • 请求密集型工作流值得升级 — 更清晰的优先级和更早的归档应能帮助管理大量活跃请求的用户，尤其是 CMEM Pro 或 OpenRouter key 用户。满意现有工作流的用户可以跳过：/api/inference/v1/decisions 对 Pro 上线只是配套基础设施，另一个修复只是让 sync-api 查询计划测试与测试顺序无关。未列出 API 迁移。

我的工作：重点领域以及自行归档的请求

重点领域是我的工作的顶层 (#5131)

  • 我的焦点轨道。 您的重点领域按优先顺序列出，并附有您所依赖的每个需求。每个请求都位于一个区域或其他。在手机上，这些区域显示为芯片行。
  • 区域标题。 每个区域页面都会显示其目标句子、综合进度、您自己的引言、您尚未开始的问题以及指向过去焦点的链接。 “我的目​​标”页面已停用；它的内容现在就在这里。
  • 建议。 新区域会自行出现在此处。您可以保留、重命名、合并或取消每一项，并可撤消。您的决定在计算机之间同步，并且刷新永远不会覆盖它们。
  • 所有者目标对其挖掘的内容进行排序。 它按顺序应用三个测试，因此每个陈述恰好成为一个焦点领域、要求或规则。优先事项和开放请求不再相互重复。
  • “焦点”步骤取代了自动刷新中的“对齐”。 它放置每个请求，并从“其他”或包含多个单独请求的请求提出新区域。
  • 请求卡。 每张卡都会显示其区域，并且请求详细信息具有 移动到…。 “结果”现在称为可交付成果。

法官根据他们的要求提交新的对话 (#5110)

  • **在任何分组代理运行之前，**每个新对话都会被归档：代码链接（相同的工作状态列表或 request_id）立即加入。在 CMEM Pro 上，或者使用您自己的 OpenRouter 密钥，Jev 还会检查对话是否继续您的开放请求之一。当检查分数为 0.8 或更高时，它会加入。在 0.5 和 0.8 之间，您会在卡上看到 加入/不是这个 建议。否则它会启动自己的请求。
  • 也有焦点区域。 在相同的安装中，Jev 在焦点步骤运行之前为每个请求建议一个焦点区域。目前，选择只是对焦点代理的一个提示：自动放置会等待，直到您自己的动作足够多，以校准截止。
  • 没有 Jev， 一切都像以前一样。

请求在项目根之间保留其对话 (#5106)

  • 其决策命名其项目根的请求会保留来自其他根的对话，并且以后的刷新仍然可以添加到它。

修复

-sync-api 查询计划测试应用其自己的架构，因此它不再根据测试顺序而失败。 CMEM Pro： Jev 决策网关 (/api/inference/v1/decisions) 已针对 Pro 订阅者推出。
