claude-mem v15.15.1

claude-mem v15.15.1

这个项目是干啥的：给 Claude Code 装长期记忆的插件，让 AI 记住跨会话的上下文和你的习惯，不用每次重新交代。给天天用它的开发者用。

变更架构图

亮点

  • 中断后不再重放——值得了解的行为变更 — 捕获路径现在会丢弃 worker 拒绝的工作，而不是暂存后重发：被拒绝的转录行被跳过（重启时不再重放），Cowork 丢弃失败的提示/观察/摘要（只有会话开始、会话结束和子 agent 停止保持暂存，较旧残留会在下次 flush 时清除），OpenCode 对被拒绝的会话开始只发送一次，而不是重试约 10 秒（#5663）。这用”至多一次”取代了”至少一次”投递：无需迁移，但被拒绝的捕获现在会丢失，意外的后台模型调用也停止了。任何依赖捕获在 worker 重启后存活的人请注意。
  • 默认脱敏新密钥——升级以阻止新的泄漏 — Grafana 服务账号令牌（glsa_）、Grafana Cloud 令牌（glc_）和 Postman API key（PMAK-）现在被 worker 和 Cowork shim 双双脱敏（#5662）。可通过 CLAUDE_MEM_REDACT_DISABLED_BUILTINS（grafana_token、postman_key）按内置项选择退出。changelog 未提及清理已捕获数据，因此请把它视为只保护未来的捕获。
  • OpenClaw <private> 截断泄漏修复 — <private> 内容现在在输出被截断到 1,000 字符之前剥离，未闭合 <private> 标签之后的文本也被丢弃（#5663）。此前在私有块内截断会移除其闭合标签并留下被存储的私有文本——这是真实的隐私暴露，对 OpenClaw 用户是升级的有力理由。
  • 无迁移成本的小修小补 — claude-mem status 现在用文字说明依赖项（如 “Observer data directory setup required”），并指向 claude-mem doctor 而非设置页面，doctor 不再丢弃来自更新 worker 的状态；Done/Dropped 现在任何大小写都能关闭工作项；CCS Align 拒绝损坏的排除文件，而不是当成空文件读取并覆盖；Viewer 为 sensitive 观察提供独立的 “Sensitive” 过滤器，不再归入 “Other”（#5661、#5663）。
  • 谁该升级、谁可跳过 — 对捕获密钥或使用 OpenCode/Cowork/OpenClaw 的人值得升级，主要是为了脱敏和私有内容修复；没有破坏性 API 变更或迁移步骤，也不是空操作或重新打标签。不捕获敏感数据且未命中上述 bug 的团队可安全跳过：其余都是内部改动——共享的设置/计费/扫描/刷新状态定义、删掉约 60,000 行测试，以及 CI 变更（Bun 固定到 1.4.4、安装 ripgrep、新增 Cowork runner 和 agent 成本报告 Python 测试、工具密集套件移到集成通道）（#5661、#5663）。

中断后不会重播

当工作线程宕机或拒绝捕获时，某些捕获路径会保留该工作并稍后再次发送，这可能会启动无人要求的模型调用。他们现在放弃工人拒绝的工作并继续新的工作（#5663）：

  • 转录本捕获： 工作人员拒绝或无法获取的转录本行将被跳过。之前，观察者停在该行，一旦工作人员返回，就将其后面的每一行再次发送。重新启动也不再重新发送中断造成的线路。
  • Cowork： 发送失败的提示、观察或摘要将被丢弃，而不是被假脱机并由稍后的钩子再次发送。只有会话开始、会话结束和子代理停止事件仍会被假脱机处理，并且旧假脱机中留下的提示、观察结果和摘要将在下次刷新时被删除。
  • OpenCode： 工作人员拒绝的会话启动会发送一次，例如观察结果和摘要，而不是在后台重试大约 10 秒。

修复

  • 编辑： Grafana 服务帐户令牌 (glsa_)、Grafana 云令牌 (glc_) 和 Postman API 密钥 (PMAK-) 由工作人员和 Cowork shim 进行编辑。使用 CLAUDE_MEM_REDACT_DISABLED_BUILTINS（grafana_token、postman_key）（#5662，感谢 @kevin9327）按名称关闭其中之一。
  • OpenClaw： <private> 内容在输出被削减到 1,000 个字符之前从工具输出中删除。以前，私有块内的剪切会删除其结束标记，因此存储了私有文本。未闭合的 <private> 标签后面的文本现在也被删除 (#5663)。
  • 状态和医生： claude-mem status 用文字命名每个依赖项，例如“需要观察者数据目录设置”而不是 observer_dir: setup_required，其提示指向 claude-mem doctor 而不是不显示这些的“设置”屏幕。 doctor 显示新工作人员的状态，而不是删除它 (#5661)。
  • 工作状态： Done 和 Dropped 在任何地方以任何字母大小写关闭项目。之前，将所有者目标项目保存为 Done 被拒绝，尽管每个读者都已将其视为已关闭 (#5661)。
  • CCS 对齐： 损坏的排除文件被拒绝，而不是被读取为空，因此排除的观察结果保持排除状态，并且文件不会被覆盖 (#5663)。
  • 查看者： sensitive 类型的观察在会话页面上获得自己的“敏感”过滤器，而不是计入“其他”(#5663)。

也在这个版本中

  • **设置和我的工作：**每个设置、计费、扫描和刷新状态都定义一次并由安装程序、工作人员和页面共享，因此新状态无法通过类型检查，直到每个屏幕都处理它为止（#5661）。
  • 测试： 删除了约 60,000 行测试：仅检查自己的固定装置、重复案例（折叠到表格中）和代理成本报告 Python 测试的四个重复副本的测试。保持回归测试运行生产代码（#5663）。
  • CI: Bun 固定到 1.4.4，安装 ripgrep，运行 Cowork 运行程序和代理成本报告 Python 测试，并将工具密集型套件移至集成通道 (#5663)。
