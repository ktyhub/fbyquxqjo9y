claude-mem v15.9.0

小版本 发布时间2026年11月2日 来源thedotmack/claude-mem 英文原文

claude-mem v15.9.0

变更流程图

亮点

  • Devin 支持与 My Work 控制 — npx claude-mem install 现在端到端配置 Devin CLI 和 Devin Desktop：自动写入 hook、识别 Devin 的工具名、注册记忆搜索工具（#5172、#5276）。“My Work / Past Focus” 新增 “Refresh now” 按钮（#5249），并支持通过 CLAUDE_MEM_WORK_VIEW_CLAUDE_MODEL、CLAUDE_MEM_WORK_VIEW_CODEX_MODEL 和 CLAUDE_MEM_WORK_VIEW_GEMINI_MODEL 按 provider 设置刷新模型（#5236）。Devin 用户，或希望手动控制视图刷新的人，单凭这一点就值得升级。

  • 隐私与安全加固——附带一处兼容性破坏 — 禁用错误报告现在也会阻止已保存错误被发送（#5272）；存储前脱敏的密钥范围大幅扩大（Slack/Discord webhook URL、Stripe、PyPI、SendGrid、DigitalOcean、Shopify、Docker Hub 和 GitLab 令牌、Authorization 头之后的凭证、--auth-token/--client-secret）（#5277、#5207、#5204、#5224、#5222、#5197、#5205）；Kimi 配置备份现在仅本人可读（#5290）。迁移提示：其他 localhost 站点不再能通过 work-state、dedup、corpus 和 advisor 路由写入 worker（#5200）——依赖它的本地工具将失效。

  • 远程 worker：新增设置，但实质上破坏性 — CLAUDE_MEM_WORKER_URL 现在遇到无效值会明确报错，而不再静默回退；任何不在本机的 worker 必须使用 https（#5285）。指向明文 http 远程 worker 的人必须改用 TLS，否则连接会被拒绝——这是升级前需要先调整的主要原因。

  • 记忆、导入与 token 计数准确性 — 会话中途切换观察者 provider 不再重复观察（#5227），重复的回合摘要不再堆积（#5228），Codex/Gemini 提示和旧版 Gemini 用量不再重复计数（#5292、#5217、#5295），路径分隔符两种写法都匹配（#5214），纯数字的 dateStart/dateEnd 按 epoch 毫秒读取（#5234），含空白的 Claude 转录不再在导入时被跳过（#5289）。若你依赖搜索结果或 token 计数的准确性，值得升级。

  • CLI/安装修复与升级结论 — npx claude-mem adopt --help / npx claude-mem cleanup --help 现在打印帮助而不是执行命令（#5288），但 PATH 上的 claude-mem 启动器仍会执行它们，所以查帮助请用 npx；另有 macOS keychain 重试/诊断（#5258，未必解决 #5250 的所有情况）、Windows 启动器与锁修复（#5256、#5198），以及 CODEX_HOME 和带引号 TOML 的处理（#5216、#5212）。这是一次实质性的安全与正确性发布——除非你依赖 http 远程 worker 或 localhost 跨站写入且无法切换到 https/本地调用，否则应升级。

新消息

Devin 支持。 npx claude-mem install 现在可以设置 Devin CLI 和 Devin Desktop：为您编写挂钩，了解 Devin 的工具名称，并注册内存搜索工具。 （#5172、#5276，作者：@patrickballard 和 @ssthormess） **我的工作按照您的条件刷新。**我的工作和过去的焦点有一个“立即刷新”按钮（#5249 by @Kirat0201）。新设置选择每个提供商的刷新模型：CLAUDE_MEM_WORK_VIEW_CLAUDE_MODEL、CLAUDE_MEM_WORK_VIEW_CODEX_MODEL 和 CLAUDE_MEM_WORK_VIEW_GEMINI_MODEL（#5236 by @LucianVane）。 远程工作人员。 新的 CLAUDE_MEM_WORKER_URL 设置。错误的值会失败并出现明显的错误，而不是回退，并且任何不在您自己的计算机上的工作人员都必须使用 https。 （#5285 作者：@Kirat0201）

隐私和安全

  • 现在关闭错误报告还会阻止发送已保存在磁盘上的错误。 （#5272 作者：@thedotmack）
  • 更多机密在存储前经过编辑：Slack 和 Discord webhook URL、Stripe webhook 机密、PyPI、SendGrid、DigitalOcean、Shopify、Docker Hub 和 GitLab 令牌、授权标头后的基本凭证以及 --auth-token 和 --client-secret 等 CLI 标志。 （#5277、#5207、#5204、#5224、#5222、#5197，@kevin9327；#5205，@parveen0029）
  • 在本地主机上运行的其他网站无法再通过工作状态、重复数据删除、语料库和顾问路由向工作线程发送写入。 （#5200 作者：@DeryFerd）
  • Kimi 配置备份现在只有您可读。 （#5290 作者：@patrickballard）

您可能注意到的修复

内存和搜索

  • 在对话中切换观察者提供者不再重复观察。 （#5227 作者：@liuyinchu）
  • 重复的回合总结不再堆积。 （#5228 作者：@Dev-0710）
  • 记录观察器不再丢失无法排队的会话结束摘要。 (#5246 by @liuyinchu)
  • 文件搜索匹配路径分隔符的书写方式：src/a.ts 或 src\a.ts。 （#5214 作者：@rudycelekli）
  • 全数字 dateStart 和 dateEnd 搜索值读取为纪元毫秒。 （#5234 作者：@vinirib）
  • 在 Chroma 重建期间重新启动工作器不再再次嵌入已完成的文档。 （#5238 作者：@vinirib）
  • 为合并项目构建的语料库保留采用的记忆，失败的重建不再丢失保存的语料库。 （#5235 作者：@liuyinchu；#5291 作者：@rudycelekli）
  • 类型上带有杂散结束标签的观察结果仍然会被读取，并且批次会在验证保留中幸存下来。 （#5221，@Montinou；#5252，@Kirat0201）
  • 上下文刷新保留您自己编写的标记示例，CLAUDE.md 生成仅从项目文件夹向下检查重复的路径段。 （#5203，@rudycelekli；#5232，@vinirib） 我的作品和查看者
  • 评论超过限制的几个字符不再使整个刷新失败，并且超大评论在一次重试后恢复。 （#5230，@juelpb；#5286，@Kirat0201）
  • 我的工作不再减慢大型数据库上的其他工作人员请求，并且保存规则或焦点会重建视图一次而不是两次。 （#5284，@Kirat0201；#5239，@LucianVane）
  • 查看器过滤器将项目过滤器和选定类别中的大小写变化会话保持为零计数。 （#5213、#5215 作者：@rudycelekli） 导入历史记录和令牌使用情况
  • JSON 中带有空格的克劳德转录本不再被跳过。 （#5289 作者：@rudycelekli）
  • Codex 和 Gemini 提示不再导入两次，并且旧版 Gemini 使用情况不再在迁移的副本中计算两次。 （#5292、#5217、#5295，作者：@rudycelekli）
  • 当无法读取一个转录源时，令牌使用保持部分状态而不是失败。 （#5294 作者：@rudycelekli） 提供商和帐户
  • 工作人员回收不再报告为身份验证失败。 (#5278 by @2023Anita)
  • macOS：工作人员直接重试登录钥匙串，并在凭据查找失败时提供更好的诊断。这可能无法解决 #5250 中的所有情况。 （#5258 作者：@Kirat0201）
  • OpenRouter：需要推理的端点不再丢失批次；不设置则重发一次请求。 （#5267 作者：@markjoin123）
  • 已送达的请求被拒绝的超额存储桶不再被视为拒绝。 （#5223 作者：@beckman55） 安装和CLI
  • npx claude-mem adopt --help 和 npx claude-mem cleanup --help 现在打印帮助。之前，他们运行了命令。尚未修复：您的 PATH 上的 claude-mem 启动器仍然运行它们，因此请使用 npx 阅读它们的帮助。 （#5288 作者：@WhitePepperLambSoup）
  • macOS 27：被操作系统杀死的启动器被重建，而不是被保留为外来的。 （#5253，@REI-330）
  • Windows：启动器安装重试短文件锁，并使用 npm 的 claude.exe 代替 sh shim。 （#5256 作者：@HoneyTyagii；#5198 作者：@balabommablock-cpu）
  • Codex：尊重 CODEX_HOME，并正确更新引用的 TOML 设置。 （#5216、#5212 作者：@rudycelekli）
  • T3 代码：即使 T3 从未保存过，也会找到默认的 Claude 和 Codex 提供程序。 （#5283 作者：@balabommablock-cpu）
  • OpenCode：预期的仅注册表设置调用不再发出警告。 （#5264 作者：@Bl0ck154）
  • Hermes：用于结帐的缓存项目密钥现已过期，因此它不会过时。 （#5287 作者：@DeryFerd）
  • claude-md:regenerate 从 CLAUDE_MEM_DATA_DIR 读取数据库。 （#5210，@Bortlesboat）
