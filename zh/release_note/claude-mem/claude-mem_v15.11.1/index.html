claude-mem v15.11.1

修订 发布时间2026年11月7日 来源thedotmack/claude-mem 英文原文

claude-mem v15.11.1

变更流程图

亮点

  • 全新安装时 Pro 登录恢复 — 由于 better-auth 从未随包提供、其认证表也从未创建，每次全新安装插件后 cmem.ai Pro 登录都会返回 500；现在插件会附带 better-auth 和 @better-auth/api-key，并在首次使用时创建这些表（#5455）。如果你在干净安装后一直无法登录 Pro，请升级——这正是修复。

  • Worker 可靠性，尤其是 OpenCode Go — 因传输/限流式中止而暂停的运行现在会释放其声明，让挂起工作能真正过期（#5457）；超预算的 condense 回复会被限制而非丢弃（#5452）；无推理重试现在能识别 OpenCode Go 的 “cannot be represented” 错误措辞（#5439）。如果你运行 worker 或遇到中止/预算路径，值得升级；OpenCode Go 用户获得针对性重试修复。

  • Claude Code 上下文与 hook — OAuth 提示和网关回退通知现在在上下文裁剪前预留，使 SessionStart 上下文保持在 Claude Code 的 10,000 字符限制内（#5441）；Stop hook 现在直接读取 last_assistant_message，而不再解析转录文本（#5449）。如果你遇到过 SessionStart 上下文溢出或转录读取问题，这条与你相关。

  • 安装程序与 Codex 健壮性 — Goose YAML 配置改为原子写入，中断的安装/卸载不会再留下截断的 config.yaml（#5442）；Codex 应用服务器的陈旧子进程会在认证恢复探测时被回收（#5438）。低风险加固；“My Work” 定时刷新间隔现在也成了可配置项（#5437）。

  • 无破坏性变更或迁移步骤 — 这是一次 bug 修复补丁加文档更新（#5447、#5458），不是重新打标签或纯元数据发布。可放心升级；只有当你完全不涉及受影响的路径（全新安装的 Pro 登录、worker、OpenCode Go、Claude Code 上下文、Goose/Codex）时才可以跳过。

专业版登录再次正常

每次新安装插件时，从插件登录 cmem.ai Pro 都会返回 500 错误。该插件的安装不包括 better-auth，并且其表从未创建。该插件现在将 better-auth 和 @better-auth/api-key 作为依赖项提供，并在第一次需要时创建身份验证表（#5455，感谢 @0xABCD01）。

修复

  • **Worker：**当运行在传输、速率限制或类似中止后暂停时，它现在会释放其声明，因此暂停的会话不再保留永远不会过期的待处理工作（#5457，感谢@akashpandey）。
  • 工人： 超出预算的压缩回复会被限制在预算范围内，而不是被丢弃（#5452，感谢@xunguangzlj-cloud）。
  • **Worker：**无推理重试现在可以识别 OpenCode Go 的“无法表示”错误措辞（#5439，感谢 @akashpandey）。
  • 钩子： Stop 钩子直接读取 Claude Code 的 last_assistant_message 并跳过读取脚本（#5449，感谢 @xunguangzlj-cloud）。
  • 上下文： OAuth 提示和网关回退通知在安装上下文之前保留，因此 SessionStart 上下文保持在 Claude Code 的 10,000 个字符限制之下（#5441，感谢 @liuyinchu）。
  • Codex： 过时的应用程序服务器子进程在身份验证恢复探针上回收（#5438，感谢@akashpandey）。
  • 安装程序： Goose YAML 配置是自动写入的，因此中断的安装或卸载不会再留下截断的 config.yaml （#5442，感谢 @DeryFerd）。
  • 测试： 同步矩阵在读取页面正文之前等待页面正文，修复浏览器就绪竞赛（#5448）。

也在这个版本中

  • 我的工作： 计划的刷新检查间隔现在是一个设置（#5437，感谢@weirui828）。
  • 文档： README 和文档中的一个故事：Claude-Mem 记得，您的编码代理在会话之间忘记了（#5447）。
  • 文档： 自述文件翻译保持围栏代码示例和单引号链接完好无损（#5458，感谢@Afloat16）。
