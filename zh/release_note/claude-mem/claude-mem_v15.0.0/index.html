claude-mem v15.0.0

大版本 发布时间2026年10月20日 来源thedotmack/claude-mem 英文原文

claude-mem v15.0.0

这个项目是干啥的：给 Claude Code 装长期记忆的插件，让 AI 记住跨会话的上下文和你的习惯，不用每次重新交代。给天天用它的开发者用。

变更架构图

亮点

  • 智能记忆召回成为默认——旧 API 被移除（破坏性） — 召回现在遵循”步骤间推理”的 Smart 工作流（搜索紧凑索引 → 用 timeline 查看上下文 → 用 get_observations 取选定详情；Cloud/Pro 从 memory_search 开始，通过 get_summaries 拉取选定摘要）。一次性调用路径改为 dumb_search，明确标注”快但浅”，仅做确定性的标题匹配。迁移是必需的：替换对旧 mem_search guided/auto API 和 flash_search 的调用，去掉 continuation cursor，并刷新已有 MCP 连接让客户端加载新工具目录。任何用自定义脚本或集成调用 mem_search/flash_search 的人都会在升级时中断。

  • 默认值变化为何重要 — 这是有意用少量延迟换取可靠的相关性：agent 现在会推理哪些结果真正相关，而不是盲目抓取一个浅层命中。结合正确性修复（上下文锚定到选定的云端结果、仅观察的原生索引、混合索引保留会话/提示 ID 前缀使后续读取不会抓到同号的其他记录类型，以及对截断的选定详情输出给出诚实边界），召回拉错记忆的概率显著降低——这是升级的主要理由。

  • 广泛的可靠性、性能与隐私加固 — 除搜索外：本地上下文读取期间 worker HTTP 请求保持响应，宽泛全文回退受到限制，去了二次复杂的标签剥离停顿；type="all" 真正搜索所有类别，被删除的观察移除其 Chroma 文档，Chroma 意外退出会拒绝挂起请求，Windows 检查点重命名失败会保留原检查点。隐私也收紧（完全私密的提示不再存为用户请求、密钥脱敏处理尾部连字符、内部 Grok 研究简报不会成为用户工作）。安装/运行时修复覆盖 Windows、macOS、Conda、Qoder、Goose、OpenCode、Antigravity、Codex 和 TeamBrain，外加新的 Hermes Agent 支持，以及带配额恢复的 Anthropic API key/订阅回退。

  • 结论：为可靠性而升级，但有一处注意 — 基本上推荐所有 v14.x 用户升级，因为召回正确性和跨平台安装修复意义重大，且除了有意弃用的搜索 API 外没有明显特性移除。唯一应暂停的人群是依赖 mem_search guided/auto 模式、flash_search 或 continuation cursor 的用户（先迁移），以及需要在刷新 MCP 客户端前冻结工具目录的人。可选启用 CLAUDE_MEM_CONTEXT_PROJECTS=all 可获得跨项目上下文。

  • 发布完整性说明 — changelog 称验证与交付身份在”最终构建、部署和包检查完成后”单独记录在发布回执中，因此镜像文本本身并不确认这些最终检查；请把它当作一次实质性、真正的 v15.0.0 特性发布（不是空操作、重新打标签或纯元数据变更），但如果签名/交付产物对你的部署很重要，请核对上游发布回执。

默认智能内存搜索

内存调用现在默认为智能：搜索紧凑索引，检查相关结果周围的上下文，然后仅获取选定的详细信息。代理会推理这三个步骤之间的相关性。本地、云/专业版和独立服务器指令描述了该运行时中可用的工具。 可选的一调用查找现在为 dumb_search。它的描述很明确：“不对结果进行推理。快速，但肤浅。使用 Smart 进行可靠的回忆。”它执行确定性标题匹配并且不推理相关性。

迁移

  • 使用mem-search技能进行默认智能召回。本地工具为search→timeline→get_observations； Cloud/Pro 以 memory_search 开头，可以使用 get_summaries 获取选定的摘要。
  • 使用智能工作流程替换对旧 mem_search 引导/自动 API 和 flash_search 的调用，或明确选择 dumb_search 进行浅层查找。自动/引导模式和连续光标被删除。
  • 刷新现有的 MCP 连接，以便 clients 加载新的工具目录和描述。

正确性

  • 云时间线支持锚定到选定搜索结果的上下文。
  • 独立服务器召回范围仅限于其配置的服务器项目，而不是读取本地工作人员的内存。
  • 选定的详细信息输出诚实地报告其边界，并在必须缩短长内容时保留选定的记录标识。
  • 本机内存查找使用仅观察索引，混合本地索引保留会话/提示 ID 前缀，因此后续读取无法选择具有相同编号的不同记录类型。
  • 安装程序提示、公共文档、集成说明和生成的内存指南使用相同的智能优先策略。

自 v14.0.1 以来的其他变化

  • 添加了 Hermes Agent 内存支持和安装，包括安全处理现有 YAML 配置。
  • 在 Anthropic API 密钥和 Claude 订阅之间添加了回退，并在消息边界处进行配额分类和恢复到主要提供者。
  • 在本地上下文读取期间保持工作线程 HTTP 请求响应，限制广泛的全文回退搜索，并删除二次标签剥离停顿。
  • 改进的内存正确性：type="all" 搜索每个类别，删除的观察会删除其 Chroma 文档，意外的 Chroma 退出会拒绝待处理的请求，失败的 Windows 检查点重命名会保留以前的检查点。
  • 加强隐私和请求处理：完全私密的提示不再成为存储的用户请求；键密文处理尾随破折号； Grok 内部研究简报不会成为用户的工作；多语言工作请求得到认可；而OpenRouter字段压缩避免了不必要的推理。
  • 改进了 Windows、macOS、Conda、Qoder、Goose、OpenCode、Antigravity、Codex 和 TeamBrain 上的安装和运行时可靠性。修复包括启动器自递归和工作目录处理、过时的临时目录清理、可操作的身份验证和丢失运行时错误以及正确的主机挂钩注册。
  • 添加了带有 CLAUDE_MEM_CONTEXT_PROJECTS=all 的可选跨项目上下文，更正了文件夹上下文排序和全局匹配，过期的孤立摘要假脱机条目，以及改进的有效数据目录日志查找和云身份验证遥测。 最终构建、部署和包检查完成后，验证和交付身份将单独记录在发布收据中。
