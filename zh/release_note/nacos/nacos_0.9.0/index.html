nacos 0.9.0

小版本 发布时间2019年3月1日 来源alibaba/nacos 英文原文

nacos 0.9.0

这个项目是干啥的：阿里开源的服务发现和配置管理中心，帮微服务互相找到彼此并统一管配置，支持gRPC和IPv6，给微服务团队用。

变更架构图

亮点

  • 分角色启动（招牌特性） — [#840] 加入区分 “config” 与 “naming” 的启动模式，[#802] 加入多启动（multi-boot）模式支持。这是主要升级理由：现在可以跑专用的纯配置或纯命名服务器，而不是一个单体实例，对想隔离角色或独立扩缩两者的团队很重要。如果这种灵活性对你有用就值得；否则收益主要在架构层面，不是行为层面。
  • 破坏性配置变更——必须迁移 — application.properties 的默认内容已更新，发布说明明确警告要保留 nacos.security.ignore.urls 的默认值。如果升级时覆盖或 diff-merge 该文件而没有带上新默认值，安全忽略 URL 规则可能悄悄失效。任何从更早版本升级的人，重启前都该把自己的 properties 文件与 0.9.0 默认值做 diff。
  • 服务发现正确性修复 — 一组命名修复：[#762] 修复单机模式下健康检查模式为 server 时实例注册失败；[#824] 让 getServicesOfServer 在服务列表为空时不再抛异常；[#759] 处理实例不自动删除；[#756] 增加实例/服务格式校验；[#768] 让 BeatReactor 心跳间隔遵循服务端返回值。如果你依赖临时实例、单机 server 健康检查或客户端驱动心跳，这些是实在的可靠性提升——只有完全不用命名（纯配置部署）才可跳过。
  • 长驻服务器稳定性 — [#720] 修复 PushService 内存泄漏，[#240] 降低对日志的强依赖，[#473] 处理 Kubernetes 集群模式启动时 nacos.log 报错，[#653] 修复 nacos-common-0.2.1-RC1.jar 中 IoUtils 无法处理空编码字符串。这些对生产集群和常驻进程最重要——泄漏和日志问题会随时间累积。
  • 兼容性与文档（低风险、增量） — [#588] 让客户端兼容 JDK 1.6，对卡在旧运行时的用户有用；[#800] 补充客户端到服务端寻址模式的文档。对旧 JDK 用户和配置寻址的人有用，但本身不构成升级理由。这是正常的特性/修复版本，不是重新打标或纯元数据空操作。

注意：application.properties 的默认内容已更新，请注意保留 nacos.security.ignore.urls 的默认值。

[#840] Nacos 服务端新增启动模式以区分 config 与 naming。 [#762] 单机模式下健康检查模式为 ‘server’ 时注册实例失败。 [#473] Nacos 集群模式 kubernate 启动时 nacos.log 报错。 [#240] 日志强依赖问题。 [#824] 服务列表为空时 getServicesOfServer 抛异常。 [#802] Nacos 服务端支持 multi-boot 模式。 [#800] Nacos 客户端到服务端寻址模式文档介绍。 [#768] BeatReactor 中心跳发送间隔不受服务端返回值控制。 [#759] 实例为何不能自动删除。 [#756] 应校验实例和服务的格式。 [#720] PushService 内存泄漏。 [#653] nacos-common-0.2.1-RC1.jar 下的 IoUtils 缺少对空 encoding 的判断。 [#588] 客户端兼容 jdk1.6。
