nacos 1.2.0-beta.0

预发布 发布时间2020年2月5日 来源alibaba/nacos 英文原文

变更流程图

亮点

  • 访问控制落地，但这是公测 beta — 招牌新增是资源级访问控制（#1105），附带专门的配置指南；启用它会改变客户端的鉴权方式，也是尝试这个版本的主要理由。但维护者明确说这是公测、“不推荐用于生产”。没有正式的破坏性变更或迁移章节——唯一的新步骤是照着链接里的访问控制指南做——所以当评估升级看待，别当稳定版。
  • 配置数据丢失与回滚修复 — #434 是最重要的正确性修复：编辑配置后显示错误的历史版本，回滚还可能把配置整个丢掉。另外还修了 1.1.4 删除配置后 UI 列表为空（#2184）、IOUtils.toString NPE（#2020）、zip 上传类型判断 bug（#1966）。新增配置能力包括同命名空间内克隆（#2171）、自定义 namespace ID（#2145），以及服务端 application.properties 可热加载（#2248）。如果你依赖配置历史/回滚，这个 beta 带着早期版本没有的修复。
  • 命名/发现与客户端稳定性 — 修复了一批生产痛点：1.1.3 引入的潜在死循环（#2000）、集群模式发现失败（failed to req API:/nacos/v1/ns/instance after all servers ... tried）（#1993）、namingService 取消订阅所有监听器后仍继续更新实例（#1858）、修改实例时把没传的参数清空（#1957）、客户端心跳包过大（#2123）、无效 HTTP keepalive 导致 Dubbo 消费者大量 TIME_WAIT 套接字（#2018），以及用更具体的错误消息替代泛化提示（#1184）。还修了推送客户端失败（#1947）和实例选择（#2006）。
  • 数据库兼容性 — 修正 MySQL 8.0 支持错误（#2042）和数据库字段赋值错误（#1627）。如果你跑在 MySQL 8.0 上，或在早期版本碰到 schema/字段映射问题，这条相关。
  • 谁该升级 — 适合评估访问控制的团队、被配置回滚丢数据（#434）、1.1.3 死循环（#2000）或 MySQL 8.0 问题坑到的人尝试。生产用户和需要稳定版的人应跳过——beta 标签本身就是明确警告，而且更新日志除访问控制指南外没有生产可用保证或迁移路径。

当前版本用于公测，不推荐上生产。权限控制使用指南见 https://nacos.io/zh-cn/blog/nacos%201.2.0-beta.0.html。

这个版本是用于公测的beta版本，不推荐上生产。可以参考 https://nacos.io/zh-cn/blog/nacos%201.2.0-beta.0.html 来使用这个版本发布的权限控制功能。
