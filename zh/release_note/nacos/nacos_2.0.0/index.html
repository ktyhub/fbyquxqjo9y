nacos 2.0.0

大版本 发布时间2021年3月19日 来源alibaba/nacos 英文原文

变更架构图

亮点

  • gRPC 取代 HTTP 成为客户端—服务端传输 — 2.0.0 把配置模块、命名模块和 Java 客户端的请求/响应式 HTTP 传输换成长期存活的 gRPC 通道，并基于 gRPC 实现推送、连接事件通知和重连（#3328/#3739/#3749/#3776、#3334/#3343/#3350、#3478/#3521、#3611）。这是大版本的标志性改动：连接语义从无状态 HTTP 变成带服务端推送的持久连接，所以不是能直接替换的补丁。

  • 破坏性变更/迁移——必须分阶段推进 — 由于线上协议变了，要计划迁移：Support upgrading and downgrading（#4810/#4845）和 Refactor and adapt v1 openAPI（#3864/#3881/#4112/#4151/#4154/#4376/#4438/#4441/#4461/#4492/#4578/#4832）被明确纳入，让 v2 在滚动升级期间能与 v1 客户端共存，命名元数据迁到 JRaft（#4204/#4260/#4279/#4354/#4367/#4733）。另注意 Api/Client 模块改为按 JDK 1.8 编译（#4383），还有若干针对升级期 NPE 的修复（#4989/#4883/#4987）——请验证鉴权和健康检查行为，并分阶段而非一次性全量上线。

  • 连接韧性与控制面加固 — 新的 gRPC 重连（#3365/#3367/#3385/#3420）、连接负载均衡（#3630/#3751/#3752/#4217）、gRPC 请求鉴权（#3693/#3821/#3970/#4675）、基础连接数限制（#4651/#4752），以及带阈值保护的健康检查（#4728/#4750/#5054），让新传输达到生产级；bug 修复还处理了 CPU 飙高（#4855）、IPv6 client-id 处理（#4788）以及健康检查器启动前/任务阻塞问题（#5080/#5109）。

  • 异步执行、指标与 SDK 扩展 — 耗时操作被异步移出热路径（#4099/#4533/#4595/#4656），新增指标（#4649），支持完整自定义实例注册（#4828），并开启多语言 SDK 方向（#4464）——如果你在意吞吐、可观测性或非 Java 客户端，这些值得关注。

  • 结论：值得为 v2 架构升级，但要当作一次大迁移 — 如果你要持久连接、服务端推送和 v2 特性集，且能做分阶段上线，就升级；只有被钉在 v1 HTTP 行为上、无法接受传输/API 变化时才能跳过。这远不是空操作或仅改元数据的重新打标，而是一次实打实的架构级发布。
