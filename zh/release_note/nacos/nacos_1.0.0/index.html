nacos 1.0.0

变更流程图

亮点

  • GA 生产里程碑 — 首个正式 GA 的 1.0.0，经过约一个月的稳定化、bug 修复和压力测试后宣布可大规模上生产。多数特性已在之前的 RC 版本发布，因此本次主要是加固和发布定性，而非大量新功能。仍在生产跑 RC 或 0.x 的用户有明确理由迁移到受支持、生产认可的基线。

  • 破坏性 API/配置变更——需要迁移 — 多处标识和默认值发生不兼容变化：#839 重构 API URL，#651 直接移除旧的 APICommands 入口，调用这些端点的客户端必须更新；#998 将 serverMode 设置改名为 instanceDefaultEphemeral，#809 弃用实例字段 valid 改用 healthy，#757 在命名模型中全面用 service 替换 domain。#946 还把默认 server mode 改为 AP。升级前请审查并调整配置、客户端和字段引用——这是升级时最容易踩坑的地方。

  • 全新的实例与一致性模型 — 原生支持临时实例与持久实例（#677、#502），服务端可运行在 CP、AP 或混合模式（#745），并新增精确服务端状态的存储与控制（#744）。默认值和行为也与模型对齐：持久实例不再发送客户端心跳（#910），新增全局推送开关和数据查询开关（#634）。需要精细控制注册语义和一致性取舍的团队获得实实在在的能力；#946 的 AP 默认值是要注意的行为变化。

  • 对旧版本的向后兼容 — 升级有明确的兼容性工作支撑：Nacos 1.0.0 可识别 Nacos 0.8.0 的数据文件（#1041），并兼容 nacos-client 0.5.0（#923）。这意味着滚动升级期间存量数据和旧客户端可以继续工作，不必一步到位整体迁移。

  • 稳定性与正确性修复——为可靠性值得升级 — 大量 bug 修复针对真实生产故障：集群初始化/NPE 崩溃（#1008、#961、#1033）、taskDispatcher.addTask 的 ArrayIndexOutOfBoundsException（#974）、客户端心跳处理任务丢失（#938）、PropertyUtil 流未关闭泄漏（#986）、cluster.conf 文件句柄未释放（#973），以及 checksum 值错误（#865）、BeatInfo 内存可见性问题（#866）等正确性修复。/instance 在无匹配 IP 时返回 404（#948）。遇到这些集群、心跳或资源泄漏问题的用户应升级；已在较新 RC 上稳定运行的用户可主要视其为定性变化加增量加固。

这是Nacos的GA版本，已经准备好投入大规模生产环境了。 我们在此版本中引入了几个重要的新功能和优化，其中大部分已在我们之前的 RC 版本中发布。我们花了大约一个月的时间来稳定和优化这个 GA 版本，修复了几个错误并适应了一些默认行为。我们还进行了压力测试来衡量Nacos的性能和容量。 即将发布文章详细介绍 Nacos 1.0.0 带来的变化，请关注我们的聊天群和邮件列表。
