nacos 3.2.4

修订 发布时间2026年8月27日 来源alibaba/nacos 英文原文

nacos 3.2.4

这个项目是干啥的：阿里开源的服务发现和配置管理中心，帮微服务互相找到彼此并统一管配置，支持gRPC和IPv6，给微服务团队用。

变更架构图

亮点

  • JRaft gRPC 服务端身份鉴权（#15687） — 原生 JRaft gRPC 流量现在通过 nacos.core.auth.server.identity.key/nacos.core.auth.server.identity.value 校验对端身份，并考虑滚动升级的强制时机。破坏性：这些值不会在集群内同步，所以升级前请确认每个成员上完全一致；一旦进入 enforced 模式，转换不可逆，也不再支持混合版本滚动降级。
  • 弃用的 AI API 默认关闭（#14817） — 旧版 Pipeline 列表/详情和旧的 MCP 导入 API 现在返回 HTTP 410 Gone。请迁移到正式的 Pipeline 和 /v3/console/ai/import/* API；如果需要更多时间，可临时设置 nacos.core.api.compatibility.enabled=true（一个共享的、默认关闭的开关）。影响仍在使用那些已弃用 v3 AI 端点的人。
  • MCP 导入私网/本地地址白名单（#15749） — 控制台从私网或本地地址导入 MCP 工具，现在需要通过 nacos.console.ai.mcp.import.allowed-private-addresses 配置管理员维护的白名单；公网目标仍然允许。要在每个 Console 实例上配置并重启——对从非公网端点导入的运维是破坏性改动，但显然是 SSRF 式加固。
  • 鉴权、登录与 RBAC 加固（#15475、#15476、#15560、#15634、#15682） — 修复调用方身份转发，使单机 Console 能执行针对调用方的 RBAC；封堵 Prompt 在列表/详情/版本/下载/客户端读取间的可见性缺口；Console 发布后保留 MCP 工具透传鉴权；校正 Admin、HTTP/gRPC、Prometheus 和 AgentSpec API 间的鉴权元数据/资源解析；并统一登录失败信息以阻止用户名枚举。这是安全敏感部署升级的核心理由。
  • 稳定性与体验修复 — 谁该升级 — 解决单机 Console 因缺少 Config 克隆权限检查器 bean 而启动失败（#15660）、Derby 上 Config 历史下一条查询及灰度名称过滤（#15701）、按 IP 聚合监听器时丢失命名空间过滤（#15724），同时收紧内嵌 DB 结果解析（#15661）、健康检查目标校验和危险的 MySQL JDBC 选项（#15712），以及 Config 详情/编辑/历史页面布局（#15695）。跑集群、用 RBAC/MCP/AI API 或碰到这些 bug 的应升级；已经用正式 AI API、公网 MCP 端点且各节点身份一致的用户，可当作低风险加固补丁。

Nacos 3.2.4 主要是 3.2 系列的 bugfix、安全加固和体验改进版本。

本版本聚焦：

  • 加固 JRaft、HTTP/gRPC 鉴权、内嵌数据库、登录、主动健康检查和 MCP 导入安全。
  • 修复单机 Console、Prompt 可见性、Config 历史、监听器状态和 MCP 工具鉴权问题。
  • 改进 Config 详情、编辑和历史页面的易用性。

对集群和 API 运维，本版本还：

  • 为原生 JRaft gRPC 流量增加服务端身份鉴权，并支持滚动升级感知的强制模式。
  • 默认禁用部分弃用的 v3 AI API，并提供临时兼容开关。
  • 为从私网或本地目标导入 MCP 工具增加白名单策略。

Nacos 3.2.4 主要是针对 3.2 系列的 bug 修复、安全加固和体验提升版本。

此版本重点关注：

  • 加强JRaft、HTTP/gRPC授权、嵌入式数据库、登录、主动健康检查和MCP导入安全性。
  • 修复独立控制台、提示可见性、配置历史记录、侦听器状态和 MCP 工具身份验证问题。
  • 改进配置详细信息、编辑和历史页面的可用性。

对于集群和 API 运营商，此版本还：

  • 通过滚动升级感知强制措施，向本机 JRaft gRPC 流量添加服务器身份验证。
  • 默认情况下禁用选定的已弃用的 v3 AI API，并提供临时兼容性开关。
  • 为从私有或本地目标导入 MCP 工具添加允许列表策略。

此版本的详细变化：

特点

  • #15687 通过滚动升级感知强制措施，向本机 JRaft gRPC 流量添加服务器身份验证。

增强/重构

  • #14817 为已弃用的 Pipeline 和 MCP 导入 API 添加共享的、默认禁用的兼容性门。
  • #15661 将分布式嵌入式数据库结果解析强化为支持的标量类型和注册的行映射器。
  • #15688 重构控制器上下文路径 URI 解析以实现一致的路由匹配。
  • #15695 通过紧凑的元数据和全屏内容视图改进配置详细信息、编辑和历史记录布局。
  • #15712 通过验证目标地址和禁用不安全的 MySQL JDBC 选项来强化主动运行状况检查。
  • #15749 为 MCP 工具导入添加可配置的出站访问控制，允许公共目标和列入白名单的私有或本地目标。

错误修复

  • #15475 修复来自独立控制台的呼叫者身份转发，以便服务器强制执行特定于呼叫者的 RBAC。
  • #15476 修复列表、详细信息、版本、下载和 Client 读取路径的提示可见性强制执行。
  • #15560 修复了从控制台发布后 MCP 工具直通身份验证丢失的问题。
  • #15634 #15563 修复了 Admin、HTTP/gRPC、Prometheus 和 AgentSpec API 之间的授权元数据和资源解析。
  • #15660 修复了由于缺少配置克隆权限检查器 bean 导致的独立控制台启动失败的问题。
  • #15682 通过标准化登录失败响应来防止用户名枚举。
  • #15701 修复 Derby 上的配置历史记录下一条记录查询并正确应用灰色名称过滤。
  • #15724 在跨集群成员聚合侦听器按 IP 状态时保留命名空间过滤器。

重大变更通知

Nacos 3.2.4 更改了已弃用的 AI API 和私有 MCP 工具导入的默认行为，并引入了不可逆的 JRaft 身份验证强制转换。

受影响的用户：

  • 用户调用已弃用的管道列表/详细信息或旧版 MCP 导入 API。这些 API 现在默认返回 HTTP 410 Gone。

  • 控制台操作员从私有或本地地址导入 MCP 工具。这些目标现在需要管理员管理的白名单。

  • 在所有成员启用 JRaft 身份验证强制执行后，集群尝试混合版本滚动降级。 推荐升级路径：

  • 迁移到规范管道和 /v3/console/ai/import/* API。如果需要额外的迁移时间，请暂时设置nacos.core.api.compatibility.enabled=true。

  • 在每个控制台实例上配置 nacos.console.ai.mcp.import.allowed-private-addresses，并在需要私有目标时重新启动控制台。

  • 升级之前，请验证每个集群成员上的 nacos.core.auth.server.identity.key 和 nacos.core.auth.server.identity.value 的配置是否相同。 Nacos 使用这些值来验证 JRaft gRPC 请求，但不会跨集群同步它们。

  • JRaft 身份验证进入强制模式后，不要依赖混合版本滚动降级。

已经使用规范 AI API、公共 MCP 端点和一致服务器标识的用户不会受到这些兼容性更改的影响。
