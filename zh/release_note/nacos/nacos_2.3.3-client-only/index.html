nacos 2.3.3-client-only

修订 发布时间2024年6月25日 来源alibaba/nacos 英文原文

变更架构图

亮点

  • 修复发现/配置回归 — Nacos Client 2.3.0 误把 clusterName 用于 address-server 请求路径（ISSUE #10792）。在 Spring Cloud 中，设置服务实例的集群可能因此改变 endpoint 寻址。2.3.3 将 endpoint 配置与服务实例元数据分离；注册中心服务实例的 clusterName 保持不变。

  • 破坏性变更：endpoint 配置必须迁移 — 把 endpoint 相关的 clusterName 设置改名为 endpointClusterName，例如 spring.cloud.nacos.discovery.endpointClusterName 和 spring.cloud.nacos.config.endpointClusterName。spring.cloud.nacos.discovery.clusterName 只保留给注册服务的集群。此前用 clusterName 自定义 endpoint 的用户，旧设置将不再控制该路径。

  • 新增 Java agent RAM 信息解析开关 — 本版本还引入 Java agent RAM 信息解析开关，可能有助于控制 agent 开销或行为。changelog 未给出开关名和默认值，依赖前请查阅 agent 文档或源码。

  • 升级建议 — 这个仅客户端的版本值得受影响的 2.3.0–2.3.2 客户端升级，尤其是配置了 clusterName 的 Spring Cloud 用户。不使用该设置也不需要 Java agent 开关的用户可合理跳过；这是实质的客户端修复，不是换标签或纯元数据版本。

该版本主要修复了一个client块错误并支持java代理解析ram信息开关。 client 区块错误是在 client 版本 2.3.0 中引入的，详情请参见 ISSUE #10792。预期的更改是统一注册中心和配置中心的地址服务器寻址逻辑，并支持地址服务器路径的自定义修改。 然而，在 Spring Cloud 环境中，用于发现的 clusterName 参数具有特定的业务意义：它表示注册的服务实例的 clusterName 属性。当用户为服务实例配置 clusterName 属性时，它同时更改用于寻址地址服务器的路径。 这个bug主要是由于之前Nacos Client的参数命名定义不明确造成的。 为了解决这个问题，从2.3.3版本开始，用于控制地址服务器的参数将带有“Endpoint”前缀。具体来说： 端点的 clusterName 参数将重命名为 endpointClusterName。 服务实例的注册中心使用的 clusterName 属性将保持不变。 以前的配置：

spring.cloud.nacos.discovery.clusterName=my-service-cluster
spring.cloud.nacos.config.clusterName=my-service-cluster

更新配置：

spring.cloud.nacos.discovery.endpointClusterName=my-endpoint-cluster
spring.cloud.nacos.discovery.clusterName=my-service-cluster
spring.cloud.nacos.config.endpointClusterName=my-endpoint-cluster
