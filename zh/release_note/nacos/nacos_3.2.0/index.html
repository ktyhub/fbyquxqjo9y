nacos 3.2.0

变更流程图

亮点

  • AI 注册表补齐”AI 三件套” — Skill Registry（#14110）和 Prompt Registry（#14109）加入已有的 MCP/Agent Registry：技能可组合已注册的 MCP 工具，以带 SKILL.md 的 zip 包发布，并通过 skill-scanner（#14623）获得安全扫描和 find-skill-from-nacos 发现（#14534）；prompt 成为带版本、可按 tag 订阅的制品，支持控制台内调试，Nacos Copilot 辅助编写两者。MCP 工具还新增 outputSchema（#13699）和 _meta/annotations（#14084/#14085）。对基于 REST/gRPC API 构建 agent 框架的团队值得升级；如果只用 Nacos 做配置/服务发现，则无关。
  • 破坏性——强制数据库 schema 迁移 — 插件管理、AI 注册表和审计的新表要求你先备份并应用 conf/schema.sql（MySQL）或对应数据库的等价脚本，然后重启，之后才能使用本版本。不做会静默破坏插件管理、Skill/Prompt Registry 及相关功能。这是硬性前置条件，不是可选项。
  • 破坏性——旧 API、UDP PUSH 移除；Java 17 底线 — api-legacy-adapter 插件和旧 /v1//v2 HTTP API 被移除；如果依赖它们，必须手动从 nacos-group/nacos-api-legacy-adapter 安装兼容插件到 plugins。命名模块的 UDP PUSH 被移除（#14052/#14074），基于 UDP 的服务发现客户端必须转向 HTTP。Nacos-Server/Console 现在要求 Java 17（Nacos-Client 和 Nacos-Maintainer-Client 仍是 Java 8），管理 API 的输入从 JSON body 改为表单参数（#14585）。仍在旧 API/UDP 或 Java 8 服务端上的部署要计划迁移；新的纯 HTTP、Java 17 部署无需担心。
  • 插件架构现代化与 PostgreSQL 内置 — 基于 SPI 的插件发现/管理（#14077）、集群级插件状态同步（#14078/#14101），以及控制台 UI/API（#14079/#14117）让插件成为一等公民；PostgreSQL 和基础实现从 nacos-plugin 合并进来（#14041/#14056/#14048）。插件作者和 PostgreSQL 用户直接受益；数据源插件重组意味着自定义插件代码要按新结构重新验证。
  • 安全/依赖加固与控制台 — Spring Boot 升到 3.4.10 以修复 CVE-2025-55752（#14006），log4j-core 升到 2.25.3，gRPC 升到 1.78.0（#14714），jraft-core 升到 1.4.0（#11180），并新增 OIDC/OAuth2 鉴权插件（#14527）、JDK 17 --add-opens 启动选项（#14122/#14307）、新旧控制台双切换（#14653），以及大量 FindBugs/正确性修复。需要 CVE 修复或鉴权/Java 17 支持的人值得升级；如果 AI、插件、API 移除和 Java 变更都不影响你，这基本是可以推迟的卫生版本。

Nacos 3.2.0 是一个以插件架构增强、AI 注册表扩展、API 现代化和代码质量改进为重点的大版本。主要亮点包括：

  • AI 注册表补齐”AI 三件套”：Skill Registry 和 Prompt Registry 加入已有的 MCP/Agent Registry，并通过 Nacos Copilot 集成实现 AI 辅助管理
  • 插件架构现代化：基于 SPI 的全面插件管理，带控制台 UI、集群级同步和 PostgreSQL 增强
  • API 清理：移除旧版 UDP PUSH 支持，/v1 和 /v2 HTTP API 抽取到子模块以便将来移除
  • 安全与代码质量：OIDC/OAuth2 鉴权插件、多项 FindBugs 修复、死代码清理和 JDK 17+ 兼容性增强
  • 控制台现代化：支持新旧控制台双 UI 切换，体验更佳

⚠️ 重大变更和迁移说明

数据库架构更改（重要）

需要采取的行动： 此版本引入了重大的数据库架构更改，添加了多个用于插件管理、AI 注册表（技能/提示）和增强的审核功能的新表。 升级之前，您必须应用新架构：

  1. 备份现有数据库
  2. 应用架构升级脚本：conf/schema.sql（对于 MySQL）或适合您的数据库类型的相应脚本
  3. schema迁移后重启Nacos服务器 未能应用架构更改可能会导致插件管理、AI 注册表和其他新功能无法正常运行。

API 旧版适配器插件

api-legacy-adapter 插件以及旧版 /v1 和 /v2 HTTP API 已从此版本中删除，以减少占用空间。 如果您的部署仍然依赖于旧版 /v1 或 /v2 API，您可以从以下位置手动引入兼容性插件： https://github.com/nacos-group/nacos-api-legacy-adapter 请下载该插件并将其放入您的 plugins 目录中，以恢复旧版 API 兼容性。

命名模块：UDP PUSH 支持已删除

命名模块删除了旧版 UDP PUSH 支持，转向更干净的 HTTP API 架构。依赖基于 UDP 的服务发现更新的 Clients 必须迁移到基于 HTTP 的机制。

📚 AI 注册表的新增功能

技能登记处

  • 集中管理：通过 UI 或 API 与 changelog 创建、更新和版本技能
  • 技能组合：将多个 MCP 工具链接成具有业务意义的功能（例如，“user_onboarding”= verify_email + create_profile + send_welcome_email）
  • MCP 集成：技能通过完整性验证显式声明对已注册 MCP 工具的依赖关系
  • 基于文件夹的组织：技能以多级文件夹结构显示，以便更好地组织
  • 代理友好的 APIs：用于代理框架（LangChain、CrewAI 等）的 REST/gRPC APIs，用于发现和订阅技能
  • 上传支持：上传带有身份验证的技能包（zip格式，最大10MB）
  • 安全扫描：用于 AI 技能安全验证的集成技能扫描仪
  • 数据级访问：细粒度可见性和访问控制（第 2 和第 3 阶段）

提示注册表

  • 一流的配置：将带有元数据（agentId、modelId、版本、标签）的提示存储为版本化配置工件
  • 多版本管理：通过模板和提交消息跟踪支持并行多版本管理
  • 基于标签的订阅：通过标签订阅提示以进行动态更新
  • 交互式调试：直接在控制台中测试和比较跨版本的提示输出
  • AI Client Proxy：统一HTTP/gRPC client接口，提示操作

Nacos 副驾驶

  • 人工智能助手：集成人工智能助手可帮助优化和创建提示和技能
  • 智能发现：自动从注册表中查找相关现有技能
  • 控制台集成：可直接从 Nacos 控制台访问以实现无缝工作流程
