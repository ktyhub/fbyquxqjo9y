nacos 1.3.0

这个项目是干啥的：阿里开源的服务发现和配置管理中心，帮微服务互相找到彼此并统一管配置，支持gRPC和IPv6，给微服务团队用。

变更架构图

亮点

  • 一致性协议抽象 — #2530/#2758 引入可插拔的一致性协议层，并由 #2761（清理 ProtocolManager#getCpProtocol()/getApProtocol()）、#2740（获取远端状态的新方式）和 #2765（优化 MemberUtils#kRandom）补齐。这是内部 CP/AP（Raft/Distro）管道改动，没有公开 API 破坏，但触及集群/leader 行为——多节点运维升级后应验证故障转移和状态读取。
  • Fastjson 换成 Jackson（#2842） — 最明确的破坏性变更。依赖 Fastjson 特有注解、字段命名、null 处理或钉死 fastjson 依赖的消费者，需要重新测试序列化，可能要做迁移；payload/配置 JSON 的生成方式会不同。
  • HTTPS 与客户端传输修复 — #2638 加入 HTTPS 支持；#2560 修复 ServerHttpAgent 构造未规范化 URL；#2577 修复命名客户端读/连接超时属性；#2569 改进 NamingProxy#reqAPI 异常日志。在 Nacos 前面终结 TLS 或依赖自定义超时设置（此前是坏的）的人值得升级。
  • 配置层正确性 — #2647 改变配置服务 MD5 生成（影响基于校验和的变化检测，所以缓存/配置 diff 客户端可能一次性不匹配）；#2738/#2785 加入租户合法性校验；#2697 修复带空行的 properties 文件无法编辑；#2661 从配置详情返回时保留查询条件；#2664 在 UI 加 groupName；#2871 修复配置服务端 quickstart 的 SQLException。
  • 升级建议 — HTTPS/TLS 用户、受超时问题影响的客户端、碰到 properties/空行或 quickstart bug 的配置管理员，以及想要新协议抽象的集群运维，值得升级；但要围绕 Jackson 序列化和 MD5 变化安排一轮回归。单机、纯 HTTP、没有自定义超时也不依赖那些配置编辑器 quirks 的用户可以跳过——这是正常的特性/修复版本，不是空操作或重新打标。
