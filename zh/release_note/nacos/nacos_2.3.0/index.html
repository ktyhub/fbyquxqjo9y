nacos 2.3.0

小版本 发布时间2023年11月30日 来源alibaba/nacos 英文原文

变更流程图

亮点

  • gRPC 持久实例正式可用 — 在 2.3.0-BETA 的 ability negotiations 之上，[#11393] 新增通过 gRPC 注册/注销持久实例。如果 gRPC 客户端需要持久（而非临时）实例，这是本版重头戏；2.3.0-BETA 明确是基线，因此这里都是增量加固而非从头重写。

  • 需回归测试的细微行为变化（非正式破坏性变更） — 未列出明确的迁移步骤，但三处重构会改变运行时行为：[#11298] 在注册/注销时从实例的 serviceName 中剥离 groupNamePrefix，[#11342] 把 BatchDeregister 匹配收窄为仅 ip 和 port，[#11352] 重写 topN 以降低内存占用并提升准确性。依赖带前缀的服务名、宽泛注销条件或精确 topN 结果的团队，上线前应验证这些路径。

  • 控制台与配置可靠性修复 — 若干面向用户的 bug 被修复：控制台 UI 部署现在显示更多细节如 mode（[#11275]），并修复鉴权分页（[#11299]）、监听查询分页（[#11382]）和配置对比（[#11384]）；配置侧 [#11390] 修复 EncryptionPluginService 顺序，[#11442] 修复未指定命名空间时监听配置检查失败。重度使用控制台或依赖配置加密/插件的用户值得升级。

  • 依赖与安全更新 — [#11439] 升级 UI 组件专门解决安全问题，[#11396] 让 Jackson 与 Spring Boot 依赖版本对齐，[#11216] 把 httpcore 声明为直接依赖以避免版本冲突。仅安全修复就足以让暴露在公网的控制台应该升级。

  • 结论 — 这是正当的稳定版：2.3.0-BETA 用户应为一个月的修复和 gRPC 持久实例特性升级，任何需要 UI 安全修复的用户也应升级。仍在更早稳定版且不需要 gRPC 持久实例的用户可跳过，但应先检查上述三个行为变化。这不是空操作或纯元数据换标签——有实质代码改动。

该版本主要基于2.3.0-BETA，经过一个多月的测试，进行了部分优化和修复。 主要变化与2.3.0-BETA相同，可回顾2.3.0-BETA的changelog。 另外，2.3.0版本基于2.3.0-BETA中的ability negotiations功能，支持Grpc注册和注销持久化实例。 其他附加更改侧重于增强功能和错误修复。 详细见：

特点

[#11393] 支持通过 grpc 注册或注销持久化实例。

增强&重构

[#11275] 增强控制台 ui 部署，显示更多信息，例如 mode。 [#11298] 在注册或注销时剥离实例 serviceName 的 groupNamePrefix。 [#11310] 简化 serviceinfo 的验证方法。 [#11342] 将 BatchDeregister 实例条件简化为 IP 和端口。 [#11343] 简化参数检查器控制逻辑。 [#11352] 重构 topN 逻辑以提高内存使用率和准确性。

错误修复

[#10353] 一起处理 DataIntegrityViolationException 和 DuplicateKeyException。 [#11299] 修复控制台 ui 身份验证分页失败。 [#11382] 修复控制台 ui 监听查询分页失败的问题。 [#11384] 修复控制台 ui 比较配置失败的问题。 [#11390] 修复 Config EncryptionPluginService 顺序问题。 [#11442] 修复没有命名空间时侦听配置检查失败的问题。

依赖关系

[#11216] 将 httpcore 声明为直接依赖项以修复避免冲突。 [#11396] 升级 jackson 与 spring boot 依赖项相同。 [#11439] 升级部分 UI 组件以解决安全问题。
