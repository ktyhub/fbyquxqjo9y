nacos 3.2.1

修订 发布时间2026年4月23日 来源alibaba/nacos 英文原文

变更流程图

亮点

  • 安全与鉴权 — #14862 和 #14917 修复涉及代理用户同步中硬编码凭据和 LDAP 前缀用户名的 LDAP 鉴权绕过。两个控制台还新增可选的 OIDC/OAuth2 SSO；通过 nacos.auth.oidc.enabled=true 启用，并配置 nacos.auth.oidc.issuer-uri、nacos.auth.oidc.client-id、nacos.auth.oidc.client-secret 和 nacos.auth.oidc.redirect-uri。
  • 必须先做数据库迁移 — 升级前备份数据库、应用更新后的对应数据库 conf/schema.sql，然后重启 Nacos。这些改动解决 PostgreSQL 启动/时间戳和 AI 持久化失败、Oracle 默认时间戳、MySQL 分页准确性，以及 MySQL/Oracle/Derby 上的确定性分页；跳过迁移可能留下启动失败、分页不稳定或 JDBC 资源泄漏。
  • AI 注册表特性与 API 变化 — A2A Registry 1.0/AgentCard v1 支持、Prompt 生命周期 UI、MCP 资源规范、bizTag 技能过滤和管理员强制发布，扩展了注册中心可用性；发布流水线和 ai_resource_version 类型隔离修复提升数据完整性。破坏性 API 变更： downloadSkillZip 从 AiClientProxy 移除；自定义实现必须改用 HTTP 客户端走技能下载。
  • 可靠性、控制台与依赖 — 修复覆盖命名/客户端故障转移竞态、同步执行器线程泄漏、订阅者索引数据丢失、配置导出/导入 null 处理，以及控制台编辑、命名空间、批量导入和过期 token bug。依赖更新到 Spring Boot 3.5.13、MCP SDK 0.17.0 和 log4j-core 2.25.4；请针对这些升级回归测试自定义扩展。
  • 升级建议 — 这是实质性补丁，不是重新打标或纯元数据版本。LDAP 用户应尽快升级；AI 注册表和受影响的控制台用户也有实实在在的改进。满足于 3.2.0 且未受这些问题影响的部署可以推迟，但任何采用 3.2.1 的人都必须先完成数据库迁移。

⚠️ 重大变更和迁移说明

数据库架构更新（关键）

需要采取的行动： 此版本包括针对 PostgreSQL、Oracle、MySQL 和 Derby 架构的关键修复，特别是围绕默认时间戳值和用于确定性分页的 ORDER BY 子句。 升级前：

  1. 备份现有数据库
  2. 应用更新的架构脚本： conf/schema.sql（针对您的数据库类型）
  3. 架构迁移后重启Nacos服务器 受影响的数据库：
  • **PostgreSQL：**默认时间戳修复，AI资源持久兼容性
  • Oracle： 默认时间戳修复
  • MySQL： 分页查询准确性改进
  • Derby： ORDER BY 子句添加、JDBC 资源泄漏修复 未能应用架构更改可能会导致：
  • 数据库启动失败（PostgreSQL）
  • 分页结果不一致
  • JDBC资源泄漏
  • AI资源版本污染

OIDC/OAuth2 SSO 配置

此版本添加了对旧版和下一代控制台的 OIDC/OAuth2 SSO 登录支持。启用：

# OIDC Configuration
nacos.auth.oidc.enabled=true
nacos.auth.oidc.issuer-uri=<your-oidc-issuer-uri>
nacos.auth.oidc.client-id=<your-client-id>
nacos.auth.oidc.client-secret=<your-client-secret>
nacos.auth.oidc.redirect-uri=${domain}/v3/console/login
