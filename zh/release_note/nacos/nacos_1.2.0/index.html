小版本 发布时间2020年3月4日 来源alibaba/nacos 英文原文

nacos 1.2.0

这个项目是干啥的：阿里开源的服务发现和配置管理中心，帮微服务互相找到彼此并统一管配置，支持gRPC和IPv6，给微服务团队用。

变更架构图

亮点

  • 配置安全与管理 — 修复真实的数据丢失 bug（#434）：编辑配置显示错误的历史版本，回滚可能丢配置。还修复删除配置后列表为空（#2184）、配置列表分页（#2168）和 ZIP 上传类型判断（#1966）。application.properties 现在可热加载（#2248），运维不用重启就能调活服务——配置密集型部署应升级。
  • 命名空间隔离与自定义 ID — HealthCheckReactor 现在按命名空间隔离（#2258），消除跨命名空间健康检查干扰；创建时可定义自定义 namespace ID（#2145、#1606），并支持同命名空间内克隆配置（#2171）。多租户用户获得正确隔离；单命名空间用户收益很小。
  • 集群/Distro 稳定性 — Distro 数据加载失败不再中断启动（#2232）；集群发现不再在所有 server 尝试后抛 java.lang.IllegalStateException: failed to req API:/nacos/v1/ns/instance（#1993，#1184 让消息更具体）；潜在死循环（#2000）和推送客户端错误（#1947）也得到处理。生产集群应升级；单机/开发环境收益较小。
  • 命名客户端与注册中心行为 — 修复 HTTP keep-alive，消除 Dubbo 消费者 TIME_WAIT 堆积（#2018）和 NACOS SocketTimeoutException httpPost ... Read timed out 失败（#2056）；修正过大的客户端心跳（#2123）、取消订阅所有监听器后仍更新实例（#1858）以及实例选择（#2006）。注意一个行为变化：修改实例 API 现在会清空你省略的参数（#1957），所以客户端必须重发完整 payload。
  • MySQL 8、访问控制与升级建议 — 新增 MySQL 8.0 支持（#2042）和资源级访问控制（#1105），另有 com.alibaba.nacos.client.config.utils.IOUtils.toString NPE 修复（#2020）及数据库字段赋值修正（#1627）。未声明明确的破坏性变更或迁移步骤；除 #1957 的语义变化外，这是累积的 bugfix 版本，1.1.x 上碰到上述问题的都应升级，未受影响的用户可安全推迟——不是空操作或纯元数据重新打标。
