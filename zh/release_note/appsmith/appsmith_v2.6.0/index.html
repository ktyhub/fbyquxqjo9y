appsmith v2.6.0

这个项目是干啥的：一个低代码内部工具平台，拖拖拽拽就能做出管理后台和仪表盘，还能接数据库和接口，适合想快速做工具的开发者。

变更架构图

亮点

  • 工作流引擎切换（EE） — v2.6.0 带来新的工作流引擎，在 v2.5.x 上由 Temporal 启动的运行不保证能恢复或完成。请把它当作分阶段迁移门槛，而不是原地跳转：先落到 v2.5.1，排空所有在途运行（包括停在审批队列里的），在 Admin Settings → Instance → Admin central 确认 v2.5.0 · Workflow Engine Transition 检查点，然后再升级。启动检查若发现旧引擎待处理审批，可能阻断整个服务，而且它明确并不穷尽——请规划维护窗口，不要指望这道护栏能抓住一切。
  • Brotli RCE 修复（CVE-2026-111497） — 自托管运营方应把它当作安全强制升级。精心构造的 Brotli 压缩输入可以破坏内存、崩溃服务、泄露进程内存或实现远程代码执行；v2.6.0 引入了 Node.js 解码器修复，无需改配置。结合内置依赖更新（#42444、#42449、#42466、#42475、#42492），如果你的实例暴露在公网，这是尽快升级的最强理由。
  • 更严格的 docker.env 与遥测配置 — #42225/#42422 把 docker.env 收窄为已解析的字面值；shell 表达式现在会中止启动并给出脱敏诊断，所以升级前请把 JVM 选项移出到 Docker Compose 或 Helm 环境配置，否则起不来。好处是 OTEL_* 名称（包括文档中的 trace exporter endpoint）现在被接受——不过外部设置的 OTEL_* 在重启时仍会覆盖文件。生成的默认值和 Admin Settings 里的值无需改动，主要工作是审计自定义 env 文件。
  • 数据源插件行为变化 — 两处查询作者会感受到的变化。Redis 现在要求静态命令名；把变量绑定到命令槽会成为硬性的查询配置错误，而绑定值必须待在单个参数内——这堵住了参数注入路径（#42465）。DynamoDB 迁移到 AWS SDK for Java 2.55.9（#42346）：区域字符串被校验为字母/数字/连字符且不超过 63 字符，响应可能包含额外的键，插件现在会遵循服务端设置的 AWS_ENDPOINT_URL、AWS_ENDPOINT_URL_DYNAMODB、AWS_USE_FIPS_ENDPOINT 和 AWS_USE_DUALSTACK_ENDPOINT——对自定义 endpoint 和 FIPS/双栈配置是好消息。
  • 权限与数据归属加固 — #42425 收紧了编辑模式下的页面/布局读取，要求编辑权限并返回草稿，而视图模式仍需读权限并返回已发布页面；用只读凭据访问编辑端点的自动化应预期收到 403。#42462 在更新时保留应用/数据源的原始工作区，#42478 在创建时忽略客户端提供的工作区 id、策略和权限组（由服务端生成）——设置这些字段的客户端会看到它们被静默替换。
  • MCP SQL 过滤与可靠性打磨 — 结构化 SQL 过滤语言获得真正的查询能力：isNull/notNull（#42491）、编译为 OR 且能与其他过滤组合的 anyOf 分组（#42495），以及支持 contains/prefix/suffix/exact 匹配的 like，外加 PostgreSQL ilike（#42496）。运维方面，保存的数据源凭据现在会在每个 pod 上清除缓存连接（#42430），被驱逐连接的清理移出共享请求线程，因此一个挂掉的数据库不再拖垮健康检查（#42450）；公开应用重新拿回配置的 Maps key（#42440）。注意浏览器遥测现在只面向构建者（#42353）——匿名和终端用户的活动从浏览器分析中消失。

⚠️ 对于 EE 用户，在升级到 v2.6.0 之前，请完成在 v2.5.1 上运行的现有临时工作流程

Appsmith 正在转向新的工作流程引擎。升级到 v2.6.0 后，不能依赖在旧 Temporal 引擎上启动的运行来恢复或完成。

运行是工作流程的一次执行。这包括等待某人批准请求的执行，即使他们没有主动处理任何内容。

升级前需要做什么：

  1. 如果您使用的是早期版本，请先升级到v2.5.1。
  2. 让 Temporal 上的所有运行完成，包括任何等待批准的运行。仅当您愿意放弃剩余工作时才停止运行。
  3. 在管理设置 → 实例 → 管理中心中，查看并确认 v2.5.0 · 工作流引擎转换 检查点。请遵循工作流引擎转换指南。
  4. 升级到v2.6.0。

可能的停机时间： 如果升级检查发现来自旧引擎的待批准请求，则可能会阻止整个 Appsmith 服务器启动。升级前完成上述步骤；不要依赖启动检查来查找每个未完成的运行。

如果此检查点阻止启动，请返回 v2.5.1，完成或故意停止受影响的运行，完成检查点，然后重试升级。

🔐 Brotli 安全修复 (CVE-2026-111497)：

Appsmith v2.6.0 修复了 Node.js Brotli 解码器中的漏洞。处理恶意制作的 Brotli 压缩数据可能会损坏内存，并可能导致服务崩溃、暴露进程内存或允许远程代码执行。自托管客户应升级到 v2.6.0 才能接收修复程序。有关详细信息，请参阅 Node.js 安全公告。

⚠️ 重要升级说明

  • 定制的 docker.env 文件必须包含已解析的文字值。 Shell 表达式通过经过编辑的诊断来停止启动。升级之前，将 JVM 选项从 docker.env 移动到 Docker Compose 或 Helm 环境配置。 OTEL_* 名称（包括记录的跟踪导出器端点）现已被接受。生成的默认值和管理设置值无需更改。 （[#42225]（https://github.com/appsmithorg/appsmith/pull/42225），[#42422]（https://github.com/appsmithorg/appsmith/pull/42422））
  • Redis 查询必须使用静态命令名称。命令名称中的绑定会返回查询配置错误。绑定值保留在单个参数内。 (#42465)
  • DynamoDB 插件现在使用适用于 Java 2.55.9 的 AWS SDK。区域只能包含字母、数字和连字符，且最多 63 个字符。响应可以包含附加键；现有的键和值保持不变。如果服务器设置了 AWS_ENDPOINT_URL、AWS_ENDPOINT_URL_DYNAMODB、AWS_USE_FIPS_ENDPOINT 或 AWS_USE_DUALSTACK_ENDPOINT，则插件现在会遵循它们。 (#42346)

🔐 安全

  • 更新了捆绑依赖项以解决报告的漏洞。 (#42444、#42449、#42466、#42475、#42492)
  • 编辑器模式页面和布局读取现在需要编辑权限并返回草稿。查看模式仍然需要读取权限并返回已发布的页面。 (#42425)
  • 更新应用程序或数据源现在保留创建它的工作区。（#42462）
  • 创建工作区现在会忽略 client 提供的 ID、策略和权限组。服务器生成它们。 (#42478)
  • Redis 查询绑定保留在一个命令参数内，因此绑定值无法添加额外的参数。 (#42465)

🛠️ 可靠性

  • 公共应用程序再次接收配置的 Google 地图密钥，因此地图小部件适用于匿名查看者。 (#42440)
  • 保存数据源凭据现在会删除每个服务器 Pod 上该数据源的缓存连接。 (#42430)
  • 关闭已逐出的数据源连接不再在共享请求线程上运行，因此挂起的数据库不再停止运行状况检查。 (#42450)
  • 页面浏览量是在页面打开时记录的，而不是在编辑器加载布局 DSL 时记录的。 (#42429)
  • 嵌套 DynamoDB 请求对象（包括事务项和索引设置）现在每次都以相同的方式构建。 (#42346)

✨ 新功能和增强功能

  • MCP结构化SQL过滤器可以测试isNull和notNull。 (#42491)
  • MCP 结构化 SQL 过滤器可以使用 anyOf 对条件进行分组，该条件编译为 OR 并与其他过滤器组合。 (#42495)
  • MCP 结构化 SQL like 可以匹配包含、前缀、后缀或精确文本。 PostgreSQL查询可以使用ilike。 (#42496)

🎨 UI 和小部件改进

  • 在应用程序设置→导航中，显示徽标和显示应用程序标题在保存过程中不再自行切换。 (#42488)

🔧 Git、部署和配置

  • docker.env 现在接受 OTEL_* 名称，包括记录的 OpenTelemetry 跟踪导出器端点。重新启动时，外部设置的 OTEL_* 值仍会覆盖该文件。 (#42422)
  • 现在仅向构建者发送浏览器遥测数据。浏览器中不再跟踪已发布应用程序的匿名访问者和最终用户。 (#42353)
