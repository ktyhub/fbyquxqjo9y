appsmith v2.0

appsmith v2.0

变更流程图

亮点

  • 升级 2.0 前必须先过渡到 v1.99 — 这是硬性门槛，不是可选准备：所有低于 v1.99 的部署都必须先落到 v1.99 并确认健康，因为 v1.96–v1.99 携带 MongoDB 7 所需的迁移逻辑。跳过会导致 2.0 升级在内置和外置 MongoDB 上都失败，所以要规划带维护窗口的两跳发布，而不是原地跳转。失败的尝试不会破坏数据，因此回到 v1.99 后重试即可恢复。
  • 新的运行时基线：MongoDB 7、Java 25、Node 24 — 2.0 全面抬高了平台下限，而 Mongo 的升级是 v1.99 要求的真正驱动力。如果你发布自定义插件、JS 数据源代码，或依赖特定 JDBC/驱动行为，请先针对这些大版本测试——这里最容易出现静默的兼容性退化。
  • 安全是本版主线 — 修复清单读起来像一次加固：未认证的完整 OpenAPI 文档被关闭（GHSA-v6jh-fx3m-7xhw, #41803）、路径穿越（GHSA-m4hv-9p7g-56vm, #41790）、经 SQL 自动补全的存储型 XSS（GHSA-vjfq-fvfc-3vjw, #41760），以及 App Viewer 导入中的数据源配置泄露（GHSA-93mf-9h52-gfxp, #41764）。依赖更新覆盖 postgresql-jdbc 42.7.11（CVE-2026-42198）、arangodb-java-driver 7.25.0（CVE-2025-52999）、axios 1.15.0 和 protobufjs 7.5.5。如果你公开暴露 OpenAPI 或接受外部邀请/导入，请优先升级。
  • 需要注意配置的行为变更 — 带 token 的邀请邮件在未设置 APPSMITH_BASE_URL 时会失败关闭（GHSA-j9gf-vw2f-9hrw, #41767），并且在被邀请用户落库前会校验请求来源（APP-15239, #41826），所以要显式设置 base URL，否则邀请会失效。Helm chart 从未记录的 _image 键切换到有文档说明的 image values（#41765）：任何通过 _image 覆盖镜像的人都必须迁移 values。Base URL 还新增了尾斜杠规范化和文档提示（#41782）。
  • 可运维性与数据完整性修复 — 泛泛的 “Response not valid” 错误被替换为可操作的提示（#41769），Git 仓库 URL 会做校验（#41819），两者都应能缩短排查时间。数据方面，导入的 JSON 在落库前会剥离身份字段（#41761），Redis 凭据能在 appsmithctl restore 后保留（#41827），HTML 实体解码不再破坏二进制 multipart 上传（#41742）——如果你依赖备份/恢复或文件上传流程，这些很相关。

<旁白> ⚠️

重要/关键 - 请勿在未阅读的情况下升级

如果您要从 v1.96 之前的版本升级，则必须先升级到 v1.99 版本，然后再升级到 2.0+。

对于使用内置 MongoDB 的实例，此要求尤其重要。 Appsmith 2.0 捆绑了 MongoDB 7，版本 v1.96 到 v1.99 包括支持此升级路径所需的迁移更改。

跳过此中间升级将导致升级到 2.0+ 失败，包括使用外部 MongoDB 实例的安装。所有部署都需要完成此步骤。

如果您已尝试升级并遇到失败，则不会发生数据丢失或破坏性更改。只需先升级到 v1.99 版本即可。实例在 v1.99 上成功运行后，您可以继续升级到 2.0+。

详细升级说明请参见：

https://docs.appsmith.com/getting-started/setup/instance-management/update-appsmith

特点

  • 为 Appsmith 基本 URL 设置添加了文档链接工具提示，并实现了尾部斜杠标准化。 (#41782)
  • 在 Helm 部署中添加了对 MongoDB Operator 的支持。 (#41733)
  • 添加了 Ask AI CE 存根 和共享文件连接支持。 (#41692)

修复

  • 在保留受邀请的用户之前验证请求来源。 [APP-15239] (#41826)
  • 在 appsmithctl restore 期间保留 Redis 凭证。 (#41827)
  • 将 postgresql-jdbc 升级到 42.7.11 以修复 CVE-2026-42198。 (#41812)
  • 添加了对 Git 存储库 URL 的验证。 (#41819)
  • 防止未经身份验证的访问完整的 OpenAPI 文档。 （GHSA-v6jh-fx3m-7xhw）（#41803）
  • 修复了路径遍历漏洞。 （GHSA-m4hv-9p7g-56vm）（#41790）
  • 将 arangodb-java-driver 升级到 7.25.0 以修复 CVE-2025-52999。 (#41789)
  • 将通用的“响应无效”消息替换为更具可操作性的错误消息，以提高可观察性。 (#41769)
  • 当 APPSMITH_BASE_URL 未设置时，无法关闭带有令牌的电子邮件。 (GHSA-j9gf-vw2f-9hrw) (#41767)
  • 更新了 Helm 图表以使用记录的图像值而不是未记录的 _image 密钥。 (#41765)
  • 修复了 Appsmith App Viewer 导入中的数据源配置泄漏。 （GHSA-93mf-9h52-gfxp）（#41764）
  • 通过 SQL 自动完成防止 存储型 XSS。 （GHSA-vjfq-fvfc-3vjw）（＃41760）
  • 在持久化之前从导入的 JSON 中删除身份字段。 (#41761)
  • 防止 HTML 实体解码破坏多部分表单数据中的二进制文件上传。 (#41742)
  • 将 protobufjs 固定到 ^7.5.5 以地址 GHSA-xq3m-2v4x-88gg。 (#41745)
  • 将 axios 升级到 1.15.0 以解决 GHSA-3p68-rc4w-qgx5。 (#41739)
  • 将捆绑的 Mongo 升级到 7.x
  • 后端JAVA升级至25.x
  • 将支持的节点升级到 24.x
  • 将捆绑的 MongoDB 升级到 7.x
