cognee v1.6.9

修订 发布时间2026年11月18日 来源topoteretes/cognee 英文原文

发布日期： 2026-11-18 变化： v1.6.8 → v1.6.9 拉取请求： #6639、#6644、#6739、#6742

总结

此版本的重点是扩展集成以及稳定摄取和嵌入行为。我们添加了多个新的连接器（Slack rework、Dropbox、Vercel、Telegram、Evernote、Asana 改进）和 Hermes-agent 集成，以及一些可靠性和嵌入修复，使数据摄取和检索更加可靠。

变更流程图

亮点

  • 主要连接器添加和 Slack 主机重构以改进 Slack 集成。
  • Hermes-代理集成：用于捕获、召回和运行时工作流程的打包代理。
  • 嵌入和存储可靠性修复，包括拒绝短嵌入响应和有界待处理批次。
  • 简化且一致的文档分块（分割内容以进行索引的逻辑）以避免不一致的分割。

重大变更

  • Slack 历史记录导入已删除：旧的 Slack 历史记录导入路径已被删除，并由新的 Slack 连接器和主机模块取代。这意味着：如果您依赖于旧的 Slack 历史导入 API，则必须迁移到新的 Slack 连接器（连接器/slack）并将任何自定义接线更新到新的主机/适配器接口。
  • 连接器封装和端口：添加了多个连接器，并将一些 Slack 内部部件移至新的主机模块中。这意味着：如果您供应商或修补连接器内部结构，请检查连接器/* 布局并将导入更新到新位置。

新功能

  • Slack 主机返工和新的 Slack 源：Slack 连接器已移植到新的主机模块中，并添加了新的直接 Slack 源，取代了旧的 Slack 历史记录导入。它的作用：提供在连接器包内维护的现代化 Slack 集成路径（消息同步、成员链接、Webhooks）。为什么重要：Slack 摄取和交互更易于维护和测试；如果您之前使用了已删除的 Slack 历史记录导入，请迁移到新的 Slack 连接器（请参阅连接器/slack）。
  • Dropbox 连接器：添加了新的 Dropbox 连接器（client、连接器、选择 UI 和源）。它的作用：让您将文件从 Dropbox 提取到 Cognee 中以进行索引和检索。重要性：扩展支持的来源，以便您可以从 Dropbox 提取文档进行内存和搜索。
  • Vercel 连接器：添加了 Vercel 连接器和用于摄取项目数据的接线。它的作用：提供源实现来捕获 Vercel 相关的工件。重要性：您现在可以将 Vercel 项目数据包含在 Cognee 内存和搜索中。
  • Telegram 连接器：添加了 Telegram 连接器。它的作用：捕获 Telegram 消息流并将其集成到 Cognee 中。为什么重要：扩大聊天平台的覆盖范围，以便可以搜索和调用 Telegram 对话。
  • Evernote 连接器：添加了 Evernote 连接器。它的作用：从 Evernote 导入笔记和笔记本。重要性：拥有 Evernote 内容的用户可以将这些笔记包含在 Cognee 内存中以供检索。
  • Hermes-agent 集成：添加了一流的 Hermes-agent 集成（提供程序、运行时、后端、捕获策略和工具）。它的作用：提供一个用于捕获、缓冲、召回通知和运行时编排的固执己见的代理。重要性：简化运行自动捕获和调用工作流程以及与 Cognee 的基于本地代理的集成。

改进

  • 默认分块器统一并解决一次：决定如何拆分文档以进行索引的逻辑（“分块器”）现在在一处解决并一致使用。它的作用：防止代码路径之间的不一致分割。为什么重要：搜索和嵌入行为变得更加可预测，您可以获得更一致的检索结果。
  • 可观察性：LLM 调用捕获：系统现在记录 LLM（大型语言模型）调用以实现可观察性。它的作用：日志和遥测包括操作期间调用的 LLM 调用。重要性：帮助您诊断查询何时触发 LLM 调用并衡量使用情况。
  • 接受图形模型作为 JSON 模式：cognify 路径现在接受作为 JSON 模式提供的图形模型定义。它的作用：使提供图形样式数据提取的模式变得更容易。重要性：简化与生成 JSON 模式图定义的系统的集成。
  • 文档和文档字符串得到加强：许多公共 API 的文档和文档字符串得到了澄清（检索行为、记住/添加文档详细信息、错误案例）。它的作用：澄清检索器何时被绕过以及权限检查行为。为什么重要：更容易理解预期行为并减少集成错误。
  • 测试和 CI：测试套件被拆分和固定，并且添加并稳定了许多连接器单元/集成测试。它的作用：提高存储库的持续集成可靠性。为什么重要：减少错误的 CI 失败并加速安全发布。

性能

  • Asana 的摄取重新启动更加可靠：之前在补偿过期时停滞的列表现在可以正确重新启动，减少摄取期间丢失的项目。
  • 存储中的绑定挂起批次：挂起批次大小现在受到限制，以防止缓冲写入时内存无限增长。
  • 减少冗余分块器解析：仅解析默认分块器一次，从而减少开销并避免在摄取期间重复决策。

安全

  • 此版本中没有新的安全建议。注意：作为 Slack 主机重构的一部分，重新​​组织了 Slack 集成代码，并调整了签名验证实用程序；如果您依赖自定义 Slack 挂钩，请查看新的连接器实现。

错误修复

  • 拒绝 pgvector 存储的短嵌入响应：非常短或格式错误的嵌入响应将被拒绝而不是被存储，以防止向量损坏和索引错误。
  • 重新检查 pgvector 流中跳过的行：将重新评估检查期间先前跳过的行，以避免丢失嵌入索引中的项目。
  • 对 Telegram 故障进行一次计数：Telegram 摄取的故障指标已进行重复数据删除，因此故障计数是准确的。
  • 偏移量过期时重新启动 Asana 列表：Asana 摄取现在会重新启动存储的偏移量过期的列表作业，从而避免摄取卡住。
  • 删除硬编码连接限制：删除了在某些环境中导致连接处理问题的硬编码连接上限。
  • 范围嵌入请求拆分：改进了嵌入请求的拆分方式，以便将正确的请求一起发送，从而减少错误或部分嵌入上传。
  • 区分共享第一行的错误：改进了错误报告，因此可以正确区分具有相同第一行消息的异常。
  • 修复失败的 CI 导入错误和测试稳健性更改：多个测试修复，以确保新测试在 CI 中正确运行并避免特定于平台的故障（例如，pytest-timeout SIGALRM 使用）。

技术变更

  • Slack 主机模块和适配器的大规模重构和移植到连接器包（新模块布局和路由器/同步/适配器实现）。
  • 添加了主要的新连接器代码树：Dropbox、Vercel、Telegram、Evernote、Asana 测试/连接器更新以及这些连接器的许多单元/集成测试。
  • Hermes-agent：广泛的新代码（提供程序、后端、runtime_env、http_backend、捕获策略、工具）以支持基于代理的捕获和调用工作流程。
  • 测试和 CI 重组：测试分为几组，添加/更新了新的 GitHub 工作流程文件，以提高集成和 e2e 测试覆盖率。
  • 代码质量：导入排序、文档字符串强化以及一些重构，以实现更清晰的错误处理和打字改进（例如，Asana 身份验证和重新打字）。
