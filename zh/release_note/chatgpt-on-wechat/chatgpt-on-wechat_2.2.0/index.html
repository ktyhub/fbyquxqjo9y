chatgpt-on-wechat 2.2.0

这个项目是干啥的：一个把大模型接进微信的聊天机器人项目，能让 AI 在微信里自动回复、进群互动，还支持插件和访客页，适合想在微信里玩 AI 的人。

变更架构图

亮点

  • Capabilities 取代 Skills，并支持实时配置 MCP — Skills 菜单变成统一的 Capabilities 中心，收纳内置工具、MCP 工具和技能。你可以通过表单或 JSON 添加 stdio、SSE 和 Streamable HTTP 的 MCP 服务（也可以粘贴 mcpServers 条目）；保存时会做连接检查并列出该服务的工具，改动在下一条消息生效，无需重启（#3155）。工具检索诊断现在暴露排序和回退原因，让你看清某个工具为何没被选中（#3165）。
  • 控制台拆分为按路由组织的功能模块 — 前端页面和后端控制器被拆成功能模块，按模块加载和缓存资源，刷新不再重新下载全部内容，每个页面有自己的 URL（/agents、/settings、/scheduler）；浏览器前进/后退可用，刷新停留在当前页，/chat 会重定向（#3167、#3172）。侧边栏的版本菜单现在一键备份用户数据并应用源码更新，更新失败也不会动到正在运行的服务（#3154）。
  • 新默认模型、100 万上下文的 Claude 以及 Responses API — gpt-6.1-sol 和 claude-opus-5-5 成为新的推荐默认值；Claude 5 系列改为按 100 万上下文窗口 / 128K 最大输出计费，而不再是统一 200K（Claude 4 及更早版本不变），因此请重新核对任何上下文预算假设。对于不再提供 /chat/completions 的端点，设置 open_ai_api_type: responses 即可使用 Responses API；默认值 auto 保持现有行为。
  • 靠稳定提示词和按预算裁剪来降低上下文成本 — 系统提示词现在只带当前日期，精确时间由新的 time 工具提供，使提示词在一天内保持稳定，显著提高模型缓存命中率（#3250）。按轮次和按 token 预算的裁剪合并为单次处理：在预算内不做摘要调用，并始终保留上一轮（#3188、#3199、#3185）。
  • 多代理隔离与 QQ 群会话行为变化 — 技能、文件预览和网站目录现在按代理隔离，委派回复以成员自己的名字/头像流式呈现，并修复了代理替他人回答、成员列表/端点解析的问题（#3234、#3205、#3177）。注意 QQ 的变化：群会话现在默认为每个成员单独一个会话，而不是全群共享一个；设置 "group_shared_session": true 可恢复旧行为（#3209）。
  • 可续跑的回合与加固的外部 I/O — 每一步的回复、工具调用和结果在步骤完成时写入会话数据库，中断的回合在重启或崩溃后可以从已完成的步骤续跑（#3191）。外部下载新增大小/时间上限和重定向复核，所有模型/语音/翻译请求都有超时，配置和 MEMORY.md 写入改为原子操作，频道临时文件被限制目录并限制长度，调试日志中的凭证也被遮蔽。

🧩 能力中心

以前的 技能 菜单现在是 功能，它是 Web 控制台和桌面 client 中的一个位置，用于管理内置工具、MCP 工具和技能：

  • 技能安装：从 Cow Skill Hub、GitHub 或 ClawHub 安装，或上传存档、SKILL.md 或文件夹。每个技能都会先预览，确认后才安装。
  • MCP 配置：在 UI 中添加、编辑和删除 MCP 服务器，涵盖 stdio、SSE 和 Streamable HTTP 传输。表单和 JSON 编辑均可用，您可以直接粘贴一个或多个 mcpServers 条目。保存检查连接并列出服务器的工具；更改将在下一条消息时生效，无需重新启动。谢谢@tsumon (#3155)
  • 工具检索诊断：查看 MCP 工具的排名以及检索在对话期间回落的原因，从而更容易找出工具未被选择的原因。感谢@zhongjunqi7657 (#3165)

相关文档：MCP工具、安装技巧

🤝 多代理协作

  • 任务切换为单独的消息：当代理将任务委托给团队成员时，该成员的回复会以其自己的名字和头像作为自己的消息在 Web 控制台和桌面 client 上传输。
  • 团队会话管理：清除上下文现在可以清除团队会话中的每个参与者；群聊在发送第一条消息之前会在会话列表中显示其成员； @ 选择器可以选择拥有会话的代理。
  • 数据隔离：技能、上传的文件预览和网站目录现在按代理划分范围。
  • 修复：
    • 修复了代理代表团队成员应答以及代理自己的工具调用在刷新后消失的问题。
    • 修复了已删除的特工在成员列表中徘徊，导致直接聊天无法使用工具的问题（感谢@Frank-zhu0404 #3234）。
    • 修复了构建团队成员和清理渠道团队时默认代理未解析的问题（感谢@c020627 #3205）。
    • 修复了仅在请求正文中发送参数时某些端点无法找到代理的问题（感谢@c020627 #3177）。

🖥 控制台升级

  • 前端和后端重建：Web控制台的前端页面和后端API控制器被分成功能模块，替换了难以维护的超大单个文件。前端资源按模块加载并缓存，因此刷新不再再次下载所有内容。每个页面都有自己的 URL（例如 /agents、/settings、/scheduler），浏览器前后移动，刷新停留在当前页面，旧的 /chat 地址自动重定向。谢谢@zkjqd（#3167，#3172）
  • 消息导航器：快速跳转到会话中较早的问题。 Web 控制台通过标题中的按钮打开问题列表，桌面 client 在右侧添加导航栏。
  • One-click 更新：侧边栏中的版本菜单检查并应用一台 click 中的源更新。更新前对用户数据进行备份，更新失败不影响业务运行。谢谢@tsumon (#3154)
  • 回复状态：已停止、已中断和正在进行的回复都会有相应的标签。因服务重启而中断的回复会显示清晰的通知，刷新后您可以继续关注仍在生成的回复。

🧠 记忆和知识库

  • 重新排序：内存检索支持可选的重新排序模型，该模型可以对调用的结果重新评分以获得更高的精度。默认情况下它是关闭的，并通过 rerank_provider 启用。谢谢@SummerCaptain (#3230)
  • 混合检索评分：矢量和关键字检索现在通过排名归一化分数融合，修复当一侧没有命中以及两者之间分数比例不匹配时稀释的分数。谢谢@SummerCaptain (#3164)
  • 知识库索引：当文档被删除或移动时，index.md 会更新（感谢@alanyz106 #3237）；大索引仅注入标题列表，以避免占用太多对话上下文。
  • 共享知识库：修复了读取和同步位于代理工作区之外的共享知识库的问题（感谢 @lorenzozanee #3182、@Jeremy-xuan #3183）；通过工具或控制台进行的编辑现在标记要刷新的索引（感谢@NBSW002 #3184、@c020627 #3206）。
  • 长期记忆：当 MEMORY.md 超过其长度限制时，最新的条目将首先保留（感谢@SEVEN-us #3244）。
  • 文档分块：修复了长 Markdown 文档的第一个标题之前的内容未被索引，以及当跳过标题级别时内容被索引两次； /memory status 提示您重建索引（感谢@Bdysj #3309）。
  • 会话加载：打开会话不再触发内存扫描和索引重建，因此新会话中的第一条消息响应速度更快。

📐 上下文和代币成本

  • 更高的模型缓存命中率：系统提示现在仅携带当前日期，准确时间来自新的 time 工具。系统提示全天保持稳定，大大提高了模型缓存命中率并降低了令牌使用率。谢谢@a1094174619 (#3250)
  • 上下文调整：回合制和代币预算调整被合并到单个预算驱动的通行证中。在预算范围内不会进行汇总调用，避免了不必要的模型请求，并且始终保留上一个回合。感谢@liuns-yang (#3188)、@Frank-zhu0404 (#3199)、@lorenzozanee (#3185)
