Roo-Code v3.38.3

这个项目是干啥的：一个装在VS Code里的AI编程助手，能按你的指令自动写改代码、委派任务给不同AI，给想少敲代码的程序员用。

变更架构图

亮点

  • 递归发现规则 — 一个可选择的 Context 设置现在会遍历子目录查找 .roo/rules 和 AGENTS.md，而不仅是仓库根目录（PR #10446）。对每个包自带约定的 monorepo 和多包代码树，这是真正的收益——但因为它是递归且需主动开启，当大量嵌套目录开始贡献规则时，要注意规则冲突和上下文膨胀。有意识地开启它，并审计哪些子目录确实需要参与。
  • Claude Code 认证稳定性 — 加固了 OAuth refresh-token 处理，止住反复登录的折腾（PR #10410）。如果你把 Claude Code 作为提供程序，这消除了长会话中反复出现的中断；主要在有认证提示打断流程时值得升级，且你侧无需配置变更。
  • 有上限的文件读取并发 — 原生 read_file 工具 schema 现在强制 maxConcurrentFileReads 上限（PR #10449）。这是一道护栏，防止 agent 无限制发散并行读取而耗尽资源或触发提供程序限流。把它当作新的吞吐上限：如果你的任务依赖很高的并行读取数，预期行为会被钳制，应调整该限制而不是当作回归。
  • 文本转语音健壮性 — 在 TTS 的 useEffect 中对 lastMessage.text 增加了类型检查，堵住该字段缺失或非文本时的运行时崩溃（PR #10431）。这是低调的加固，但如果你用 TTS 就很关键：它消除了一类由空消息或非文本消息触发的间歇性错误，不改变任何用户可见行为。

本版本无破坏性变更。

[3.38.3] - 2026-01-03

  • 功能：在上下文设置中添加选项以从子目录递归加载 .roo/rules 和 AGENTS.md（PR #10446 by @mrubens）
  • 修复：通过强化 OAuth 刷新令牌处理来停止频繁的 Claude Code 登录（PR #10410 by @hannesrudolph）
  • 修复：将 maxConcurrentFileReads 限制添加到本机 read_file 工具架构（PR #10449 by @app/roomote）
  • 修复：在 TTS useEffect 中添加 lastMessage.text 类型检查以防止运行时错误（PR #10431 by @app/roomote）
