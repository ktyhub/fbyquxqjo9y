Roo-Code v3.35.0

小版本 发布时间2025年12月1日 来源RooCodeInc/Roo-Code 英文原文

变更架构图

亮点

  • 原生工具调用全面铺开 — 这是 3.35.0 的主标题：结构化工具调用覆盖了一大批提供程序——Bedrock（#9698）、Cerebras（#9692）、带 API 自动检测的 Chutes（#9715）、DeepInfra（#9691）、DeepSeek/Doubao（#9671）、Groq（#9673）、LiteLLM（#9719）、Ollama（#9696）、OpenAI 兼容端点（#9676）、Requesty（#9672）、Unbound（#9699）、Vercel AI Gateway（#9697）、Vertex Gemini（#9678），以及 xAI 与新的 Grok 4 Fast / 4.1 Fast（#9690）。相比 XML 模拟式提示，原生工具意味着格式错误或凭空捏造的调用更少，推理模型上尤其明显。留意一个具体的行为变化：Grok Code Fast 现在默认启用原生工具（#9717），如果你围绕旧格式调过提示词或权限，上线前先重新验证该提供程序。
  • 两种新的编辑原语 — apply_patch（#9663）和 search_and_replace（#9549）让 agent 有更高效、更省 token 的编辑方式，包括跨多文件批量文本替换。对开发者来说，这改变了 agent 驱动编辑的机制：补丁式更新比整文件重写更可靠，但你应预期会看到新的工具权限提示，并考虑现有编辑工具配置或 includedTools/excludedTools 白名单是否需要更新以放行它们。
  • 元数据驱动的子任务与更安全的编排 — 子任务现在由元数据驱动，父任务会自动恢复，并带单开保护（#8081、PR #9090）。这很重要，因为它免去了子任务结束到父任务继续之间的手工干预，而单开保护避免了两个子任务同时打开的竞态。若你围绕嵌套/新任务搭工作流，这是最可能改变任务生命周期行为的改动——测试你对父任务恢复的假设。
  • 按模型控制工具 — 新增 excludedTools 和 includedTools 配置（#9641），让你可以定制某个模型能看到的工具集。这是一个可直接落地的配置面：用它限制会乱调某些工具的模型、缩减上下文/成本，或如上所述显式启用新的 apply_patch 和 search_and_replace 工具。
  • 更少的调用丢失、更好的取证 — 摘要现在会为并行工具调用保留 tool_use 块（#9700、PR #9714），上下文压缩不再悄悄丢掉进行中的工具调用——对长时间、并行密集的运行是实打实的正确性修复。工具格式现在出现在环境细节里（#9661），调试新增了 API/UI 历史按钮（#9684），web-evals 支持查看任务日志、导出失败日志和终止运行（#9637、#9681）。净效果：长运行 agent 更可预测，评测或运行出错时也更容易定位。
  • 破坏性变更 — 无；无需迁移步骤，不过 Grok Code Fast 的原生工具默认值和新工具配置属于值得验证的行为/配置变更。

3.35.0 版本 - 子任务和本机工具

  • 元数据驱动的子任务，具有自动父级恢复和单开安全性，可改进任务编排（@hannesrudolph 的 #8081，@hannesrudolph 的 PR #9090）
  • 原生工具调用支持扩展到许多提供商：Bedrock (PR #9698 by @mrubens)、Cerebras (PR #9692 by @mrubens)、API 自动检测的 Chutes (PR #9715 by @daniel-lxs)、DeepInfra (PR #9691 by @mrubens)、DeepSeek 和 Doubao (PR #9671 by @daniel-lxs)、 Groq（PR #9673 by @daniel-lxs）、LiteLLM（PR #9719 by @daniel-lxs）、Ollama（PR #9696 by @mrubens）、OpenAI 兼容提供程序（PR #9676 by @daniel-lxs）、Requesty（PR #9672 by @daniel-lxs）、Unbound（PR #9699 by @mrubens）、Vercel AI Gateway （PR #9697 by @mrubens）、Vertex Gemini（PR #9678 by @daniel-lxs）和 xAI 以及新的 Grok 4 Fast 和 Grok 4.1 Fast 模型（PR #9690 by @mrubens）
  • 修复：在并行工具调用的摘要中保留 tool_use 块（@SilentFlower 的 #9700，@SilentFlower 的 PR #9714）
  • 默认 Grok 代码快速转为原生工具以获得更好的性能（PR #9717 by @mrubens）
  • 以 Roo Code Cloud 提供商为中心的入职流程的用户体验改进（PR #9709 by @brunobergher）
  • UX 工具栏清理和设置整合，以获得更清晰的界面（PR #9710 by @brunobergher）
  • 通过 excludedTools 和 includedTools 配置添加特定于模型的工具自定义（PR #9641 by @daniel-lxs）
  • 添加新的 apply_patch 本机工具以实现更高效的文件编辑操作（PR #9663 by @hannesrudolph）
  • 添加新的 search_and_replace 工具，用于跨文件批量文本替换（PR #9549 by @hannesrudolph）
  • 添加调试按钮以查看 API 和 UI 历史记录以进行故障排除（PR #9684 by @hannesrudolph）
  • 在环境详细信息中包含工具格式，以实现更好的上下文感知（PR #9661 by @mrubens）
  • 修复：显示安装计数以百万为单位，而不是数千（PR #9677 by @app/roomote）
  • Web 评估改进：添加任务日志查看、导出失败日志和新的运行选项（PR #9637 by @hannesrudolph）
  • Web-evals 更新：添加终止运行功能（PR #9681 by @hannesrudolph）
  • 修复：防止导航按钮在较小的屏幕上换行（PR #9721 by @app/roomote）
