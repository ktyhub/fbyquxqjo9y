claude-code v2.1.307

修订 发布时间2026年10月21日 来源anthropics/claude-code 英文原文

变更流程图

亮点

  • API 版本与安全遥测 — /claude-api api-version 现在指向 API 版本 2026-10-21，因此锁定 API 版本的代码会得到一份新契约。更重要的是，任何被权限规则、auto 模式、安全检查、hook 或沙箱停止、提示或退回的工具调用，现在都会发出 claude_code.safety_event OpenTelemetry 事件——这是真正的审计/可观测性提升。如果你运行 OTel 或需要被拒绝操作的记录，请升级；否则这是附加、低风险的改动。
  • 破坏性：设置作用域与 runner hook 超时 — 两项改动需要迁移。设置 env 块中的 axScreenReader 和 CLAUDE_AX_SCREEN_READER 现在只在用户、托管或 --settings 设置中生效（该行为始于 2.1.305），依赖它们的项目级配置会静默失效——请上移到更高作用域。自托管 runner 的 checkout hook 现在默认 30 分钟后被杀掉并使会话建立失败；如果你的确实需要更久，请调高 --checkout-hook-timeout-min 或设为 0。自托管 runner 运营者应在升级前阅读；纯桌面用户可以忽略。
  • MCP 可靠性是重点 — 大量修复让 MCP 在 headless/CI 中更可靠：macOS 登录钥匙串锁定时服务器不再误报”需要认证”（解锁后无需重新登录即可重连），主机休眠后不再保持失败状态，连接中途关闭时 HTTP MCP 调用不再发送两次——只有只读/幂等工具会被重试。还修复了后台任务中回合缺失 SDK MCP 服务器最新工具，以及子 agent 记录中的占位 token 用量。如果你在 claude -p 或 CI 中依赖 MCP，仅此一点就足以升级。
  • 网关、云与 runner 加固 — 若干此前失效的路径现在可用：CLAUDE_STREAM_FIRST_BYTE_TIMEOUT_MS 在 Claude apps 网关后生效，带 OTEL_EXPORTER_OTLP_HEADERS 的遥测被接受，CLAUDE_CODE_DISABLE_1M_CONTEXT 不再导致 opus[1m] 等别名模型找不到，且 prompt-caching-scope beta 头不再通过自定义 ANTHROPIC_BASE_URL/Foundry 网关发送。云会话不再在重启时丢失 /clear 状态和 /autocompact 窗口，WebFetch 的 4xx/robots.txt 拒绝重新成为正常结果，runner 槽位泄漏和 --use-anthropic-git-proxy 下的 .claude/settings.local.json 残留也已修复。运行网关或自托管 runner 的用户值得升级；本地交互用户收益不大。
  • 较小但值得的补充 — @claude review stop（也有 off/pause）可在不开启新审查的情况下结束 @claude review always 订阅；无法解析的工具调用最多重试两次；并发 fork 子 agent 会被告知哪次启动是自己的；Agent SDK setModel() 现在最多等待 15 秒（原 5 秒）等待 API 确认；VSCode 语音听写、LaTeX 粘贴和证书处理（NODE_EXTRA_CA_CERTS、CLAUDE_CODE_CERT_STORE）也收紧。有用的打磨，但本身不构成升级理由——这是实打实的修复版本，不是空操作或仅元数据重新打标签。

发生了什么变化

  • 添加了 /claude-api api-version 将 Claude API 代码移至 API 版本 2026-10-21
  • 为每个工具调用权限规则、自动模式、安全检查、钩子或沙箱停止、提示或发回添加了 claude_code.safety_event OpenTelemetry 事件
  • 修复了当设置 CLAUDE_CODE_DISABLE_1M_CONTEXT 并且模型是带有 [1m] 后缀的别名（例如 opus[1m]）时，请求失败并出现模型未找到错误的问题
  • 修复了在自定义 ANTHROPIC_BASE_URL 网关后面和 Foundry 上发送的 prompt-caching-scope beta 标头，该标头没有任何效果
  • 修复了登录钥匙串被锁定时 MCP 服务器在 macOS 上的 claude -p 中显示“需要身份验证”的问题；他们现在说出了原因，解锁后的下一次运行无需重新登录即可连接
  • 修复了当 macOS 或 Linux 计算机在连接时进入睡眠状态时，MCP 服务器被报告为超时并在无头运行中保持失败的问题
  • 修复了当连接在调用中关闭时发送两次 HTTP MCP 工具调用的问题；现在仅重试只读或幂等工具
  • 修复了后台任务运行时有时会在没有 SDK MCP 服务器最新工具的情况下启动的问题
  • 修复了一些“Autocompact is thrashing”错误，这些错误依次读取许多 PDF 页面、图像或其他大型工具结果
  • 修复了云会话中的 /autocompact 在会话重新启动后返回默认窗口的问题
  • 修复了当云或自托管运行器会话重新启动时，与 /clear 清除的对话有时会返回的问题
  • 修复了 Claude 应用程序网关会话中忽略 CLAUDE_STREAM_FIRST_BYTE_TIMEOUT_MS 的问题
  • 修复了设置 OTEL_EXPORTER_OTLP_HEADERS 时克劳德应用程序网关后面的克劳德桌面会话被拒绝的遥测问题
  • 修复了 /permissions > 最近拒绝不显示被拒绝的 shell 命令，以及自动模式的本地分类器在检查重试命令时忽略来自那里的批准；现在批准一行会命名命令，而不是其描述
  • 修复了 /help 和 / 命令菜单，显示捆绑技能（例如 /claude-api）的面向模型的长描述，而不是简短描述
  • 修复了记录占位符令牌使用情况的子代理记录以及流式响应的空停止原因
  • 修复了通过代理 SDK 的 setModel() 以及基于其构建的应用程序进行模型切换，当 API 花费超过 5 秒来确认模型时被拒绝的问题； Claude Code 现在最多等待 15 秒
  • 修复了通过连接的应用程序（例如存档空闲会话的桌面应用程序）停止的后台命令，该命令被报告给克劳德为由用户停止；该通知现在为其输出文件命名
  • 修复了 Cowork 云会话中的 WebFetch 在站点以 4xx 状态或 robots.txt 拒绝应答时报告工具错误的问题；现在这是正常结果，就像在本地会话中一样
  • 修复了直接配置的 GitHub MCP 服务器上的写入工具，显示关闭的表单，而无需在桌面应用程序的“代码”选项卡中创建任何内容
  • 修复了当服务器关闭重用连接时 Artifact 工具读取失败并重置连接的问题
  • 自托管运行器：修复了 --use-anthropic-git-proxy 的会话提交早期会话留在克隆中的 .claude/settings.local.json
  • 自托管运行程序：修复了在结帐挂钩期间存档或重新排队会话或停止运行程序的问题，使挂钩的进程保持运行并保留运行程序的槽
  • 改进了无法解析的工具调用的恢复：克劳德代码现在在错误结束回合之前重试调用最多两次
  • 改进了一起启动的分叉子代理：现在每个代理都被告知哪个启动是自己的，因此分叉不太可能尝试启动彼此的工作
  • 改进的浏览器登录：登录完成后立即显示成功页面，无需等待您的帐户配置文件加载
  • 改进了云和自托管运行器会话中的网络搜索错误：搜索被拒绝并给出原因的 403 现在显示该原因，而不是通用的“身份验证错误”
  • 改进了当桌面应用程序的 MCP 服务器之一无法连接时云会话中第一次回复的时间
  • 改进了转录内容包含大粘贴图像或 PDF 读取的会话的远程控制连接时间
  • 更改了当网络搜索预算用完时克劳德收到的通知，也告诉它不要在浏览器中或通过计算机使用来查询搜索引擎
  • 更改了设置 env 块中的 axScreenReader 设置和 CLAUDE_AX_SCREEN_READER，以仅从用户、托管或 --settings 设置应用（自 2.1.305 起）
  • 自托管运行器：将结账挂钩更改为默认在 30 分钟后停止，导致会话设置失败；如果您需要更长的时间，请提高 --checkout-hook-timeout-min 或将其设置为 0
  • 自托管运行器：更改了为 Anthropic 管理的 git 构建的证书文件，以像 CLI 一样过滤其 trusted 证书； [runner:warn] 行给出了遗漏的数字
  • [VSCode] 当语音听写自行停止时（15 秒没有识别语音，或 2 分钟限制），在麦克风按钮上添加了一条通知，说明原因以及迄今为止的文本被保留
  • [VSCode] 修复了一个长提示，显示更多覆盖整个聊天面板：固定提示现在上限为面板的 40% 并滚动
  • [VSCode] 修复了列表项或表格单元格的一部分，其中 LaTeX 数学粘贴为富文本编辑器中的新列表或表格
  • [VSCode] 修复了仅在 ~/.claude/settings.json 中设置 NODE_EXTRA_CA_CERTS 时在 TLS 检查代理后面听写失败的问题；它现在也遵循 CLAUDE_CODE_CERT_STORE
  • [VSCode] 更改了“在其他地方仍然打开”通知，以覆盖扩展重新启动后留下的 Claude 进程，该进程通常会在大约 10 分钟内自行结束
  • [VSCode] 更改了语音听写以像 CLI 一样过滤其 trusted 证书
  • [VSCode] 更改了扩展自身的请求，以像 CLI 一样过滤其 trusted 证书，并将 trust 在环境或用户设置中命名的 NODE_EXTRA_CA_CERTS 文件
  • [云会话] 修复了搜索仍在运行时存储库选择器显示“没有存储库匹配”的问题；现在显示“正在搜索…”，直到结果到达
  • [云会话]修复了自托管环境中“等待运行者”状态被切断的问题；对于按需跑步者，它现在会从您的最后一条消息开始计数并显示失败的尝试
  • [代码审查] 在代码审查中添加了 @claude review stop（也包括 off 和 pause），结束拉取请求上的 @claude review always 订阅，而不开始新的审查
