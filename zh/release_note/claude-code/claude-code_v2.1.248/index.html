claude-code v2.1.248

修订 发布时间2026年8月27日 来源anthropics/claude-code 英文原文

claude-code v2.1.248

发生了什么变化

  • 添加了 --restricted（或 CLAUDE_CODE_RESTRICTED=1）：删除运行命令或代码和 WebFetch 的内置工具（除非在 --tools 中命名），将文件工具保留在工作目录中，拒绝 bypassPermissions，并忽略用户、项目和本地设置文件
  • 将 experimental.cacheTtl（"5m" 或 "1h"）添加到代理 frontmatter：未配置子代理 TTL 设置时使用的每个代理提示缓存 TTL
  • 添加了 claude self-hosted-runner --client-label <label>（或 SELF_HOSTED_RUNNER_CLIENT_LABEL）来覆盖跑步者注册的标签（默认：主机名）
  • 添加了服务器管理的设置诊断：设置加载失败时出现启动警告，以及解释加载失败或未获取它们的原因的 /doctor 和 /status 行（Bedrock/Vertex/第三方提供商、自定义 ANTHROPIC_BASE_URL）
  • 当 GitHub CLI 令牌缺少 workflow 范围时，在 /web-setup 中添加了警告，因为如果没有它，推送到非常大的存储库可能会被拒绝
  • 为通过 AWS Marketplace、自助企业和企业试用计费的企业组织添加了 /usage-credits，以便成员可以向管理员请求更高的使用限制
  • 在 Bedrock、Vertex 和 Foundry 上同一台计算机上的会话之间以及禁用遥测时添加了跨会话消息传递 (SendMessage / ListAgents)
  • 修复了在长会话中大约每小时一次的提示缓存缺失（并丢失扩展思维上下文），该提示缓存缺失是由 OAuth 令牌刷新后重新呈现工具定义引起的
  • 修复了当帐户进入使用超额时，ScheduleWakeup 工具定义在会话与其 --resume 之间发生变化，导致恢复会话第一回合出现完整提示缓存缺失的问题
  • 修复了 Claude 桌面和 Cowork 会话在 30 天后消失的问题：记录清理现在会在应用程序中保留桌面编写的会话（除非组织策略管理保留）；新的 desktopSessionCleanupPeriodDays 设置限制了豁免
  • 修复了当另一个 Claude Code 进程在会话令牌过期时持有令牌刷新锁时发送到登录屏幕的问题；现在请求失败并出现可重试错误
  • Windows：修复了 claude agents 列表在脱离会话后或在 win32 输入模式下的终端选项卡中启动时不响应键盘的问题
  • 修复了 /login 中推荐的控制台登录在无法使用的计算机上显示登录 URL 之前失败并出现 OAuth 错误的问题（例如，当设置了 ANTHROPIC_API_KEY 或 API 密钥帮助程序时）；现在回退到 API 键登录
  • 修复了 /model 中的模型名称和快速模式切换通知以代码形式呈现，因此像 [1m] 这样的后缀按字面显示而不是作为链接显示
  • 修复了设置 CI 环境变量时 claude agents 跳过工作区 trust 提示的问题
  • 修复了当 PR 状态缓存保存格式错误的条目时 claude agents 在启动时崩溃的问题
  • 修复了机器关闭后代理视图恢复几周前的后台会话的问题：此类会话现在显示为在其实际结束处停止，并且在恢复其保存的对话之前打开它会询问
  • 修复了代理视图在开始新会话时有时会打开旧对话并删除键入的提示的问题
  • 修复了 claude agents：打开已在另一个终端中恢复的已停止会话不再启动该对话的第二个进程；该行现在表示它已在终端中打开
  • 修复了当工作树分支已合并到签出的默认分支（例如本地 main）但尚未推送时，claude agents 和 claude rm 拒绝删除会话（“具有未推送到任何地方的提交”）的问题
  • 修复了当 PermissionRequest 或 PreToolUse 挂钩打印无效答案时后台会话静默等待的问题：claude agents 行现在命名挂钩和架构错误
  • 修复了挂钩以静默方式将无效 JSON 的标准输出 {…} 对象视为纯文本的问题；现在，它被报告为解析消息的挂钩错误
  • 修复了 /mcp 列出的项目 .mcp.json 条目，该条目在 trusted“claude.ai”标题下声明 claude.ai 连接器类型；它现在出现在其真实范围内
  • 修复了 headersHelper 提供 Authorization 标头的 MCP 服务器落入 401 上的 OAuth 发现，而不是重新运行帮助程序并重试记录中的调用
  • 修复了 /login 在需要托管设置安全批准对话框时克劳德应用程序网关挂起的问题
  • 修复了当 apiKeyHelper 是唯一凭证时网关模型发现 (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY) 永远不会运行的问题
  • 修复了 claude logs 留下鼠标跟踪、括号内的粘贴以及在运行它的终端中打开的备用屏幕的问题
  • 修复了 trust 对话框的存储库权限规则列表，当长规则在表情符号中间被切断时显示乱码
  • 修复了当您在 ctrl+c 之后按下 Shift+tab 时，权限模式指示器隐藏在“再次按 Ctrl-C 退出”提示后面的问题
  • 修复了 /ultrareview 和本地种子云会话，将未提交的编辑上传到 prod.env 样式和 *.tfvars 文件，或编辑凭证文件的交换、临时和备份副本（例如 key.pem.tmp、id_rsa.swo）；他们现在留在你的机器上
  • 修复了 CLI 静默重新连接后，远程控制会话偶尔不会在连接的设备上显示权限提示或最新消息的问题
  • 修复了当容器的会话凭据尚不可读时云会话偶尔会在启动时失败的问题
  • 修复了当全局标志或包装器注入选项位于子命令之前时 claude remote-control 拒绝其自己的标志（例如 --spawn、--name）
  • 修复了启动警告（例如“N MCP 服务器需要身份验证”），在转录本其余部分的右侧呈现一列
  • 修复了后台工作树会话丢失签出的问题：后台会话现在在运行时保持工作树的锁定，因此清理和 git worktree remove 不会打扰它
  • 修复了其他会话的@提及与使用非拉丁字符输入的名称不匹配的问题（例如通过 IME 输入的韩语）
  • 修复了被默默忽略的无效 crossSessionInbound 值：它现在警告并保留跨会话消息（用户设置）或拒绝它们（托管设置），直到修复为止
  • 修复了速率限制、使用情况和快速模式消息，当您的组织无法使用该命令时，告诉您运行 /usage-credits（例如，使用 DISABLE_EXTRA_USAGE_COMMAND 隐藏）
  • [VSCode] 修复了当会话从未保存时聊天选项卡卡在“未找到对话”的问题；它现在开始一个新的对话
  • 改进了工作流程工具的提示足迹：其描述现在约为 1k 个令牌，而不是 5.7k，脚本编写参考已移至捆绑的 workflow-authoring 技能中
  • 改进了提示页脚 PR 徽章，以在拉取请求不变的情况下减少检查 GitHub 的频率；推送或 gh pr 命令仍然会立即刷新它
  • 改进的托管设置：client 端超时、MCP 启动模式和流看门狗环境变量不再触发设置批准提示
  • 改进了 /ultrareview <PR#>，在启动前检查连接到您的 Claude 帐户的 GitHub 帐户是否可以访问存储库，并解释如何修复它，而不是在云会话启动后失败
  • 改进的跨会话消息传递：当无法使用默认目录时，回退到每个用户的私有 /tmp 目录，并且通知和 /status 命名要修复的目录
  • 更改了代理视图调度输入中的shift+enter以插入换行符（与提示符匹配）； ctrl+enter 现在发送并附加
  • 更改了 /loop：自定进度动态模式和无提示自主默认设置现在始终可用，包括在 Bedrock/Vertex/Foundry 上
  • 将 Anthropic 遥测导出失败更改为在调试级别记录为 [Anthropic telemetry] 而不是 [3P telemetry] OTEL diag error，因此它们不会被误认为 OTel 收集器失败
  • 更改了 Linux 用户命名空间中的跨会话消息传递：未映射所有者的根等效 trust 仅限于规范系统目录
  • 将 SendMessage 从子代理更改为另一个会话：结果现在表明任何回复都会传递到父会话的对话，而不是子代理
