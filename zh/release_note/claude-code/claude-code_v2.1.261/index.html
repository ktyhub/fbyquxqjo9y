claude-code v2.1.261

修订 发布时间2026年9月4日 来源anthropics/claude-code 英文原文

变更流程图

亮点

  • 输出与技能的新开关 — bashOutputMaxChars 和 taskOutputMaxChars 把命令输出和后台任务输出的内联上限提高到 128K 字符，超过后才写入文件，因此因截断而丢失的上下文更少；--append-subagent-system-prompt-file 用于处理命令行装不下的子代理提示词；/skill-doctor 会显示哪些已加载技能未被使用及其上下文开销，方便你精简。全部是可选功能——不使用则默认值不变。

  • 需要留意的变更（本版本最接近迁移的内容） — 文字编辑按键现在遵循 Bash 语义：Ctrl+W 向前删到空白符，Alt+F 和 Alt+D 停在词尾，标点作为分词符；keybindingFlavor 已失效，可从配置中移除。自动模式不再自动批准把内容塞进公共图表渲染 URL 的链接（视为上传）。计数 API 不可用时 /context 会退回到本地令牌估算，而不是额外调用小模型。托管设置固定 forceLoginMethod: "gateway" 时，现在会忽略残留的 API 密钥或 claude.ai 登录并要求 /login（Bedrock、Vertex AI 和 Foundry 会话不受影响）；网关 403 现在会提示 Claude Code 可能未对该组织启用，而不是建议重新登录；无响应头的 API 重试会等待最多 API_TIMEOUT_MS（默认 10 分钟），而不是再等 3 分钟。

  • Remote Control 与断点续聊的正确性改动最多 — 修复了恢复会话丢失钩子输出和并行工具调用周围的上下文（这会改变恢复时的请求）；SDK/云端会话忽略第一条提示词之后立刻发出的 Stop 或中断（现在会真正停止）；从手机或浏览器停止后以及 /clear 之后权限模式过期、转圈/Stop 按钮卡住；/teleport 会话被上传到已连接会话，导致在手机和网页上看起来像是追加进来的。SendMessage 发往离线的 Remote Control 会话时，现在会报告为已排队而非已送达；原生 Windows 上位于 TLS 检查代理之后时，入站事件也能工作。如果你依赖 Remote Control 或会话恢复，这是升级的主要理由。

  • 值得拥有的稳定性与性能修复 — 快速输入或按键重复不再丢失或重排字符，并且可以删除内联 [Image #N] 标记前的字符；无法恢复的后台代理不再陷入紧循环重试烧 CPU；面向更新版本的功能开关不再泄漏到同一台机器上的旧版 Claude Code；/add-dir <subdirectory> 在 /net 自动挂载上不再打印虚假的”无法解析”；启动时超时的 claude.ai 连接器抓取现在会在后台重试；gcpAuthRefresh 在缓慢但有效的 Google 凭证检查时不再打开浏览器。危险 rm 提示现在也能捕获位置参数上的 rm -rf 以及双引号 sh -c 中的情形。

  • 结论 — 不是空操作或仅改标签：这是一个实质的维护版本，主要是修复加可选设置，没有 API 破坏性变更（停用 keybindingFlavor 是唯一真正的行为破坏）。如果你用 Remote Control/teleport、恢复会话、一台机器上跑多个 Claude Code 版本，或处于 Vertex/网关/托管环境，建议升级；输入、CPU 和 rm 安全修复也让大多数其他用户低风险升级。如果你是稳定的单机工作流、不用 Remote Control 且不涉及受影响的集成，可以跳过——这里没有任何会以破坏现有设置的方式改变默认值的内容。

发生了什么变化

  • 在 /status 和 claude doctor 中添加了“组织策略”行，说明无法加载组织策略的原因，例如代理未通过端点
  • 添加了 bashOutputMaxChars 和 taskOutputMaxChars 设置，以提高 Claude 在保存到文件之前内联接收的命令和后台任务输出的数量，最多 128K 个字符
  • 添加了 --append-subagent-system-prompt-file 以从文件中读取子代理系统提示符，提示符太大而无法在命令行上传递
  • 添加了 /skill-doctor 以显示哪些加载的技能未使用以及它们在上下文中的成本，以便您可以修剪它们
  • 修正了键入或粘贴的字符偶尔会乱序或在快速输入或按键重复期间被丢弃的问题
  • 修复了当工作目录位于 /net 自动挂载时 /add-dir <subdirectory> 打印错误的“无法解析”错误
  • 修复了当 AWS 或 AWS 凭证助手从未响应时 Bedrock 设置向导挂起的问题（现在超时并出现明显错误），并且其模型检查在 TLS 检查代理后面失败
  • 修复了当托管设置在 enabledPlugins 中强制启用从 claude.ai 同步的插件时，云会话会丢弃该插件，然后回退到可能失败的市场克隆的问题
  • 修复了提示输入中无法删除内联 [Image #N] 芯片之前的字符的问题
  • 修复了恢复会话丢失挂钩输出和并行工具调用周围的其他上下文，这改变了恢复的请求
  • 修复了当手机、浏览器或 claude.ai 应用程序连接到终端会话时或终端中的模式更改后，远程控制显示陈旧的权限模式的问题
  • 修复了在连接的手机或浏览器停止转动后，或在执行 /clear 等本地斜线命令后，远程控制会话显示为仍在工作的问题（卡住的旋转器和停止按钮）
  • 修复了 SDK 和云会话忽略第一个提示之后、回合开始之前发送的停止或中断的问题；转弯现在停止而不是跑完
  • 修复了远程控制上传使用 /teleport 拉取的会话到连接会话的问题，该会话在电话和网络上显示为附加到原始会话
  • 修复了远程控制的入站事件流在本机 Windows 上的 TLS 检查企业代理后面失败的问题
  • 修复了当工作量来自设置时，远程控制会话在 claude.ai 上显示默认工作量级别的问题
  • 修复了 gcpAuthRefresh 在 Google 凭据检查速度缓慢时在启动时打开浏览器的问题，即使凭据仍然有效
  • 修复了当启动连接器获取超时时，claude.ai 连接器在整个会话中保持缺席的问题 — CLI 现在在后台重试
  • 修复了当后台代理无法恢复并且在紧密循环中重试其唤醒时持续较高的 CPU 使用率
  • 修复了限制到较新版本的功能标志偶尔适用于在同一台计算机上运行的旧克劳德代码版本的问题
  • 修复了当使用端点受到速率限制或启动后立即打开时，/usage 和 VS Code 使用面板会删除特定于模型的每周限制行
  • 修复了 claude -p --resume <file> 采用记录在记录中的格式错误的会话 ID 的问题；现在它会在新的会话 ID 下恢复
  • 修复了终端进度指示器（iTerm2、Ghostty、ConEmu）在后台工作流程或代理仍在运行时显示会话已完成的问题
  • 修复了一个罕见的布局故障，即容器在行和列方向之间切换后，框可能会以错误的高度渲染
  • 修复了当 trusted 代理将端口附加到 X-Forwarded-For 时克劳德应用程序网关 client IP 的问题；设置访问列表后，不可读的条目现在会收到 403
  • 修复了 Claude 应用网关告诉 Claude Desktop 将 OpenTelemetry 导出为 JSON，即使终端 CLI 使用 protobuf，因此仅使用 protobuf 的收集器拒绝 Desktop 的数据
  • 修复了桌面和网络显示会话繁忙而仅监视工件更新的问题
  • 修复了 Chrome file_upload 中的 Claude 在从 Claude 桌面应用程序运行的本地 Cowork 会话中失败并显示“路径：预期数组，收到未定义”的问题
  • 将 SendMessage 修复为另一台机器上的离线远程控制会话，读取交付时的信息；结果现在显示交付已排队，直到该机器重新连接
  • 修复了在后台 Bash 命令中运行的 CLI 的插件安装提示：现在可以检测到它们，并且原始 <claude-code-hint> 标签不再泄漏到对话中
  • 修复了进程中的代理团队队友在第二回合重新发送第一回合工具和技能公告，这会更改请求前缀并错过提示缓存
  • 改进了 /model 选择器和 VS Code 模型药丸，以在 Claude Code 识别模型时显示模型名称，而不是其原始 Bedrock、Vertex AI 或 LLM 网关 ID
  • 改进了设置 GOOGLE_APPLICATION_CREDENTIALS 时 Google Vertex AI 的启动：API client 创建不再重新运行 Google Cloud 项目发现或生成额外的 gcloud 进程
  • 改进的流性能：每次更新时布局不再重新检查已渲染的块
  • 改进了危险的 rm 安全提示，以在位置参数和双引号 sh -c 脚本中捕获 rm -rf
  • 改进了 API 不发送响应标头时的处理：重试现在最多等待 API_TIMEOUT_MS（默认情况下 10 分钟），而不是另外 3 分钟，并且消息会说明要更改的内容
  • 更改了托管设置负载上的克劳德应用程序网关 403（在启动时或 /login 之后），表示可能无法为组织启用克劳德代码，而不是建议重新登录
  • 更改了托管设置固定 forceLoginMethod: "gateway" 的机器，以忽略剩余的 API 密钥或 claude.ai 登录并请求 /login； Bedrock、Vertex AI 和 Foundry 会话不受影响
  • 更改了自动模式，将将内容打包到公共图表渲染器的 URL 中的链接视为上传到该站点：不再自动批准，除非您要求
  • 更改了提示符的单词编辑键以匹配 Bash：Ctrl+W 删除回空格，Alt+F 和 Alt+D 在单词末尾停止，标点符号分隔单词； keybindingFlavor 不再有任何效果
  • 更改了 /context 令牌计数，以在令牌计数 API 不可用时使用本地估计，而不是额外的小模型请求
  • [VSCode] 在输出样式菜单中添加了“构建自定义样式”演练，用于编写自定义输出样式文件并立即列出它
  • [VSCode] 在 MCP 服务器对话框中添加了添加服务器表单和删除操作，因此无需离开 IDE 即可添加和删除 MCP 服务器
  • [VSCode] 在终端、另一个 VS Code 窗口或 Claude Desktop 中打开的会话的会话列表中添加了一个空心环，因此它们看起来不再是关闭的
  • [VSCode] 在权限和问题提示中添加了折叠按钮，以便可以在不关闭它们的情况下阅读它们后面的对话；提示旁边的空间现在可以滚动对话
  • [VSCode] 在会话列表的右侧 click 菜单中添加了“归档会话”，并为“取消归档”提供了自己的图标
  • [VSCode] 修复了从网络上的 Claude Code 传送的会话，将云会话关闭时被切断的问题处理为 declined
  • [VSCode] 修复了会话选项卡的重命名框对于随窗口恢复的选项卡打开为空的问题；现在以当前名称开头
  • [VSCode] 修复了会话列表面板中折叠部分在每次加载面板时短暂显示展开的问题
  • [VSCode] 修复了焦点视图，显示克劳德继续前进后工具调用仍在运行，例如在问题等待您的回答时
  • [VSCode] 修复了当纠正未聚焦的 Claude 选项卡的会话 ID 时，会话列表的活动行突出显示变得过时的问题
  • [VSCode] 修复了当 Claude 选项卡具有焦点时 Cmd/Ctrl+Shift+T 重新打开和深层链接打开将 Claude 选项卡放置在 Claude 编辑器组之外的问题
  • [VSCode] 修复了会话选项卡的“添加到组”，将从 Web 上的 Claude Code 打开的会话分为两组；它现在移动会话列表显示的条目
  • [VSCode] 修复了模型选择器显示组织已禁用的模型，直到窗口重新加载两次
  • [VSCode] 修复了从会话列表打开的选项卡跳回该会话，以及在 VS Code 重新加载选项卡视图后从 Web 会话打开的选项卡重新启动传送或保持为空的问题
  • [VSCode] 修复了在窗口重新加载后立即询问问题或设置文件有错误时，早期会话中的 /btw 附带问题历史记录被覆盖的问题
  • [VSCode] 修复了使用 Claude.ai 或 Console 帐户登录时 Claude 面板重新加载后待处理问题卡不会重新出现的问题
  • [VSCode] 修复了一个面板从设置文件中选择第三方提供商后，仅限 claude.ai 的功能在窗口的其他 Claude 面板中保持可见的问题
  • [VSCode] 修复了当 Claude Code 报告未登录或请求因缺少登录而失败时，尽管禁用登录提示设置，仍会出现登录屏幕的问题
  • [VSCode] 修复了下一个排队的权限提示，保留在上一个提示上键入的文本并立即接受第二个 click
  • [VSCode] 修复了在仅显示会话列表的窗口中打开 Claude 侧边栏而没有安装对话框的安装插件链接
  • [VSCode] 修复了侧边栏使用量表在新窗口中保持为空的问题，直到打开“帐户和使用情况”对话框，并且量表中未显示 0% 使用限制
