claude-code v2.1.281

变更流程图

亮点

  • 企业网关：Bedrock 委托、护栏、遥测 — Claude apps 网关 Bedrock 上游新增 assume_role，让网关以 STS 扮演的 IAM 角色调用 Bedrock（跨账户，可选每位开发者一个会话）；guardrail: {id, version} 对每次请求应用 Amazon Bedrock 护栏（必须在所有 Bedrock 上游上设置或全部不设置——需注意的配置约束），telemetry.resource_attributes 为 Claude Desktop 和 /login 遥测添加固定标签。desktop 策略块新增 blockReadsOutsideWorkingDirectories 和 disableBypassPermissionsMode。网关管理员值得升级；个人 CLI 用户可以忽略。
  • 归属退出选项发布，但附带版本错配注意 — settings.json 中的 "attribution": false 隐藏所有提交和 PR 归属。明确的兼容性说明：旧版 CLI 会跳过包含它的设置文件，因此在跨版本共享的文件中请保留对象形式。如果你依赖归属或在混合版本安装间共享配置，请规划部署，而不是到处粘贴该键。
  • 恢复、提示缓存与 headless/SDK 会话获得本版本最大的可靠性提升 — 修复涵盖：恢复会话以变更后的形式重发早前回合（导致 API 丢弃先前推理）、超大会话只恢复最后几条消息、在待处理的权限提示期间恢复破坏提示缓存、工具调用后或早期顾问结果不可读时恢复、--max-turns 在无限重试循环中被忽略，以及 --input-format stream-json / Agent SDK / VS Code / 定时云会话在纯字符串助手内容或工作目录被删除时失败。如果你使用恢复、Agent SDK 或云/定时会话，强烈建议升级。
  • 代理/网关用户：流与重试失败不再静默 — 干净关闭的流不再被当作完整响应，重复的流事件不再让工具调用执行两次，丢失的事件不再导致 “Content block not found”，仅含用量的尾帧不再丢失停止原因。CLAUDE_CODE_RETRY_WATCHDOG 会话不再在一串 429/529 等待后死于首个 5xx，也不再无上限地按 Retry-After 休眠；HTML 代理错误页显示 HTTP 状态而非原始标记。如果你走代理或网关请升级；否则这些对你不可见。
  • 权限收紧——一项需规划的行为变更——以及 MCP/插件工具 — rm -rf "$(pwd)" 这类仅替换目标现在即使在 auto 和 --dangerously-skip-permissions 模式下有 Bash 允许规则也会提示，可用 CLAUDE_CODE_DISABLE_SUBSTITUTION_RM_PROMPT=1 退出；--setting-sources（SDK settingSources）现在传播到生成的会话；claude --bg 要求先有工作区信任；含 NUL 字节的权限规则不匹配任何内容；macOS /.vol//.nofollow//.resolve 路径在批准前会被检查。另外：claude plugin validate 现在标记会被静默丢弃的 .mcp.json 条目、未声明的 ${user_config.*} 引用和不安全 URL，MCP URL 模式 elicitation 在 2026-07-28 协议连接上可用。依赖基于替换的 rm 的自动化应在升级前设置退出开关。

发生了什么变化

  • 在 desktop 策略块中添加了对较新的 Claude Desktop 密钥的 Claude 应用程序网关支持，包括 blockReadsOutsideWorkingDirectories 和 disableBypassPermissionsMode
  • 在 Claude 应用程序网关 Bedrock 上游添加了 assume_role：网关将 Bedrock 调用为它通过 STS 承担的 IAM 角色，如果需要，可以在另一个 AWS 账户中，每个开发人员可选择一个会话
  • 在 Claude 应用程序网关 Bedrock 上游添加了 guardrail: {id, version}，以将 Amazon Bedrock 护栏应用于通过它们发送的每个请求（将其设置在所有 Bedrock 上游或无）
  • 将 telemetry.resource_attributes 添加到 Claude 应用程序网关配置中，以在 Claude Desktop 和 /login 会话的遥测上放置固定标签
  • 在 settings.json 中添加了 "attribution": false 以隐藏所有提交和 PR 归属；旧的 CLI 版本会跳过保存它的设置文件，因此将对象形式保留在跨版本共享的文件中
  • 在 2026-07-28 协议连接上添加了 MCP URL 模式引出，因此服务器可以要求 Claude Code 打开基于浏览器的流程；当服务器无法确认完成时，屏幕上不会留下等待对话框
  • 添加了对 claude plugin validate 的 MCP 服务器检查：它报告加载时会默默删除的 .mcp.json 条目、未声明的 ${user_config.*} 引用和不安全的 URL
  • 向 /insights 添加了自动模式建议，可估计自动模式在您最近的会话中可以处理多少个权限提示
  • 在全屏模式下向 /skills、/mcp 和 /plugin 安装列表添加了一个滚动条，就像 /workflows 现在的滚动条一样：当鼠标悬停在列表上时它会出现，并且可以被 cli 选中或拖动
  • 修复了重试 API 请求时可能结束会话的崩溃（“不可恢复的接口错误”）
  • 修复了当模型交替不可解析的工具调用和输出限制截断时，可以无限期重试的回合，忽略 --max-turns
  • 修复了以更改的形式重新发送早期轮次的恢复会话（并行工具调用轮次、MCP 工具调用的输入或工具搜索结果，而其服务器仍在重新连接，或者加载轮次被中断的工具搜索结果），这可能会使 API 放弃对话的先前推理
  • 修复了恢复非常大的会话有时仅恢复最后几条消息的问题
  • 修复了在待定权限提示期间重新启动后恢复的会话发送与之前不同的历史记录，这会破坏该点的提示缓存
  • 修复了恢复在工具调用期间结束的会话：克劳德现在看到该调用并被告知其结果未知，并且手动恢复不再添加隐藏的“继续”消息
  • 修复了与早期顾问的会话结果，API 无法再读取每轮失败的一个请求并反复丢失早期推理；历史记录现已修复一次
  • 修复了当 MCP 服务器在对话中断开连接或恢复后仍在连接且工具搜索关闭时（例如在代理或网关后面）时提示缓存丢失的问题
  • 修复了响应被代理或网关缩短的问题，该代理或网关干净地关闭流，显示为完整且没有警告，并且工具调用在重复的流事件上运行两次
  • 修复了当代理在响应中删除流事件时响应失败并显示“未找到内容块”的问题；现在保留部分响应，并且网络搜索保留已经到达的结果
  • 修复了当连接在流的最终事件之前断开时两次请求空的已完成响应的问题
  • 修复了代理发送尾随仅使用帧时丢失的停止原因
  • 修复了 CLAUDE_CODE_RETRY_WATCHDOG 会话在第一个 5xx 上失败或在运行 429/529 等待后断开连接，以及在来自 5xx 的长 Retry-After 上无上限且安静地休眠的问题
  • 修复了当服务器发送 Retry-After: 0 时快速模式连续重试速率限制请求的问题
  • 修复了一个工具，该工具返回超大图像，导致同级工具调用未应答且仍在运行，或者在没有最终消息的情况下结束回合
  • 修复了模型通过过长名称调用工具后对话永久卡在“tool_use.name：字符串最多应有 200 个字符”的问题
  • 修复了当 Claude Code 无法读取其自己的内存使用情况（例如，当文件描述符用完时）时，工具调用失败并显示“无法获取内存使用情况”，或者在运行后报告为失败的问题
  • 修复了当早期的助理消息具有纯字符串内容时，--input-format stream-json 会话（代理 SDK、VS Code 扩展）和计划的云会话每次都会失败并出现错误的问题
  • 修复了非交互式会话（-p、代理 SDK）在会话中启动的目录被删除后下一回合失败的问题
  • 修复了当主机在握手过程中停止响应时，与主机端 (SDK) MCP 服务器的无头会话在第一条消息上停止的问题；远程会话现在最多等待几秒钟
