claude-code v2.1.225

修订 发布时间2026年8月8日 来源anthropics/claude-code 英文原文

claude-code v2.1.225

这个项目是干啥的：Anthropic 官方的命令行 AI 编程助手，在终端里让 Claude 直接帮你读写代码、改项目、跑命令。给习惯用命令行的开发者用。

变更架构图

亮点

  • 网关支出限额 — 用量警告现在会写明支出上限、重置时间和运维者的留言，让触及限额的情况可操作。要求网关版本为 2.1.225；若需要此行为，请同时升级两个组件。未列出其他迁移步骤。
  • 认证可靠性 — 修复了以下 headless 会话问题：一次瞬时 401 把长期有效的 CLAUDE_CODE_OAUTH_TOKEN 替换成短期存储的登录令牌，以及钥匙串超时后 macOS MCP OAuth 401 间歇性爆发。这防止长时间运行工作流中不必要的重启和反复认证失败。
  • Remote Control — SendMessage 现在可以按名称主动与其他机器上的会话发起对话；ListAgents 会把它们显示为 name [ref]。当代理列表不可用时，已确认的远程接收方也不会再与同名本地会话混淆。此外，附加的照片会直接送达 Claude，并修复了恢复超大的已压缩对话的问题。
  • Headless 与自托管可靠性 — 当 --base-dir 无法创建或写入时，claude self-hosted-runner 现在会在启动时以清晰错误失败，而不是注册后每个会话都失败。跨会话消息不再无声地滞留、没有通知或过期；网页重连不再重放不断增长的事件积压；自动模式仍会拒绝不安全操作，但不再把自己权限检查的拒绝计入重试上限。
  • 代理 UI 与升级指引 — claude agents 现在会提示工作区信任，跨项目悬停不再改变下一个代理的起始目录。VSCode Focus 保留当前待办、待回答问题上下文和已确定的答案；思考折叠显示”已思考 N 秒”并在完成后重新折叠。未列出破坏性变更。 如果你使用 headless/自托管会话、Remote Control、macOS MCP OAuth、网关限额或受影响的 VSCode 视图，建议升级；否则这些主要是可靠性和 UI 打磨，可放心跳过。

发生了什么变化

  • 为 Claude Code 的使用警告添加了网关支出限制支持；达到限制的消息现在命名上限、其重置时间和操作员的消息（需要 2.1.225 上的网关）
  • 为 untrusted 目录添加了到 claude agents 的工作区 trust 提示，与 claude 的行为相匹配
  • 修复了瞬态 401 用存储的登录名的短期令牌替换长期 CLAUDE_CODE_OAUTH_TOKEN 的问题，从而中断无头会话直至重新启动
  • 修复了钥匙串读取超时后，macOS 上的 MCP OAuth 服务器间歇性失败并出现大量 401 错误，就好像从未经过身份验证一样
  • 修复了自动模式，将安全过滤器拒绝其自身权限检查的次数计入连续块限制；该操作仍然被拒绝，但模型现在被告知继续前进而不是重试
  • 修复了在无头会话和启动期间跨会话消息在没有通知或过期的情况下保持停放状态的问题
  • 修复了压缩非常大的对话后，远程控制会话恢复时对话历史记录中断的问题
  • 修复了将鼠标悬停在代理列表中另一个项目中的会话上更改下一个代理启动的目录的问题
  • 修复了当 --base-dir 无法创建或写入时 claude self-hosted-runner 注册然后每个会话失败的问题；现在它在启动时退出并出现明显错误
  • 修复了网络会话上的克劳德代码被错误报告为卡住的问题，每次重新连接时都会重新发送不断增长的事件积压
  • 改进的远程控制：从 Claude 应用程序附加的照片现在直接显示给 Claude，而不是通过单独的工具调用从磁盘读取
  • [VSCode] 固定焦点视图折叠最新的待办事项列表、待决问题的上下文和已确定的答案；仅思考折叠显示“Thought for Ns”，并在轮次完成时重新折叠
  • SendMessage 现在可以通过名称与其他计算机上的远程控制会话开始对话（ListAgents 将它们显示为 name [ref]），而不是仅在他们先向您发送消息后才回复
  • SendMessage：当无法检查其自己的列表时，您已确认的远程控制收件人永远不会交换为本机上的同名会话
