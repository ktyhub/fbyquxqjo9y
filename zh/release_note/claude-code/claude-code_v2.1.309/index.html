claude-code v2.1.309

claude-code v2.1.309

变更流程图

亮点

  • 沙箱与权限加固 — 这基本上是一个安全版本。macOS/Linux 上 shell 启动文件不再在每条命令前于沙箱外运行；denyWrite glob 在经符号链接访问时解析为真实路径；沙箱命令和自动接受的编辑不能再修改 --mcp-config 文件；被禁用的 MCP 服务器不会被后续权限提示复活。权限检查也更严：可能打开失败的重定向不再被信任，git 前被包裹/加前缀的 cd 现在像普通 cd 一样提示，Edit(path) 拒绝现在会阻止同样包含子 shell 的 Bash 重定向，Windows Set-Location/cd 带额外参数不再自动批准，worktree 隔离现在拒绝带 locale 前缀和 zsh 算术的命令。配置存储写保护也通过符号链接生效，后台命令比会话活得更久时 Linux 写入拒绝仍然持续。多数用户无需迁移，但依赖上述任一缺口的脚本现在会提示或被拒绝。
  • 可能需要迁移的行为变更 — 几项有意的变更改变了行为：claude ultrareview 现在需要工作区信任（终端上会提示，否则拒绝），脚本必须传 --trust-workspace——一个不带值的标志，PR 号或 base 分支放在它之前——或设置 CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1；sed -i 现在走标准 Bash 提示并按原样执行，不再是模拟的编辑预览，也不再能被 /rewind 还原；worktree 创建/复用不再按需拉取 git 对象，Bash 沙箱下的部分克隆会先拉取；被排除在沙箱外的命令在写入其写列表路径前会先询问，且非沙箱回退被拒绝；桌面/VS Code bypass 模式下，危险的 rm/rmdir 立即被拒绝并给出改写提示，让无人值守会话继续；/claude-api skill 在 multiagent_20261001 上构建 Managed Agents 团队并默认开启动态工作流，而非 coordinator。请更新 ultrareview 自动化及任何依赖 sed -i 可回退的工作流。
  • 会话稳定性、hook 与 skill — 超过大小限制的嵌套 CLAUDE.md 现在只加载开头，结束反复压缩循环；ctrl+enter 和 ctrl+o 的排队/传递得到纠正，其他 agent 和会话的等待消息在记录下方完整显示；/rename、/rewind、/privacy-settings 和反馈流程报告更准确。Hook：PowerShell hook 现在在退出码 2 时阻塞，Windows 下带 "shell": "powershell" 的 PreToolUse/PermissionRequest hook 在没有 Git for Windows 时不再失败即放行，mod 的 turn.step hook 可用 haiku 等别名指定模型。Skill：--add-dir 中冲突的 skill 以 <folder>:<name> 提供，/verify 和 /code-review 能找到从 shell 改动的嵌套包 skill，claude.ai 同步的插件/skill 在磁盘读取错误后仍保留，dataviz skill 新增 APCA 及 apca(text, background)，/claude-api 改进 OpenTelemetry 指引（服务账号密钥和 Workload Identity Federation token 可管理目标；调用不支持的功能前会核对实时文档）。
  • 平台与集成修复 — VS Code 从缓存的不完整面板恢复，不再产生空的”Untitled”历史条目，将长 /goal 风格消息折叠到 Show more 之后（anthropics/claude-code#97469），允许在 ~/.claude/keybindings.json 的 Chat 上下文中将 ctrl+j 设为 null，修复 LaTeX 粘贴和 mod 标签重叠（anthropics/claude-code#102981），并将 Edit/Write 等待缩短到 0.75 秒。云会话修复连接器加载、环境变量损坏、docs 工具行和 Changes 窗格清晰度；Claude Tag 修复 Slack 批准误路由、陈旧会话和线程顺序；Code Review 修复缺失和残留的 PR 检查；claude remote-control 显示真实分支。网络方面：在默认 bedrock-runtime.<region>.amazonaws.com 端点配合 ANTHROPIC_BEDROCK_BASE_URL 时，细粒度工具流式传输可在 Amazon Bedrock 上工作；只发保活的非 Anthropic 网关现在会等 45 秒才提示”Waiting for API response”。Windows git 命令更快并用英文报告错误。
  • 升级建议 — 这是实质性补丁版本，不是重新打标签或仅元数据空操作。如果你使用沙箱/权限系统、worktree、脚本中的 ultrareview、Bedrock 或非 Anthropic 网关、VS Code、Slack/Claude Tag 或自托管 runner（--startup-timeout-min 不再杀死首个提示仍在子 agent 中的会话，跨 runner 移动的会话现在把中断的工具调用视为结果未知），请升级。只有在单账户、默认配置且不触及上述任何界面时才可以合理跳过——这种情况并不常见，且安全修复使这次升级几乎不会后悔。

发生了什么变化

  • 修复了 macOS 和 Linux 上的沙盒 Bash 命令，在每个命令之前在沙盒外运行 shell 的启动文件
  • 修复了当通过符号链接到达模式的文件夹时，macOS 沙箱 denyWrite 全局模式不会应用于路径的真实位置
  • 修复了沙盒命令和自动接受的编辑，能够修改通过 --mcp-config 传递的 MCP 配置文件
  • 修复了打印和 SDK 会话中稍后的权限提示重新连接已禁用的 MCP 服务器的问题
  • 修复了 Bash 权限检查 trusting 由命令设置的变量，其重定向可能无法打开
  • 修复了当 cd 被包装或添加前缀时，Bash 权限检查不会提示某些在运行 git 之前更改目录的复合命令，就像对普通 cd 所做的那样
  • 修复了 Edit(path) 拒绝规则，该规则不会阻止某些也包含子 shell 的命令中的 Bash 重定向到该路径
  • 修复了工作树隔离会话接受隔离防护应拒绝的某些区域设置前缀命令的问题
  • 修复了 zsh 上的工作树隔离会话接受隔离防护应拒绝的一些算术命令的问题
  • 修复了 Claude Code 创建的工作树和分支签出，以便它们忽略 git 替换引用，就像其他 git 操作已经做的那样
  • 修复了通过符号链接到达配置目录时不应用配置文件存储写保护的问题
  • 修复了读取非常大的嵌套 CLAUDE.md 下的文件后重复压缩会话的问题；超过大小限制的嵌套 CLAUDE.md 现在仅加载其开头
  • 修复了 ctrl+enter（立即发送）仅在响应开始之前按下时对消息进行排队，并重新启动提示的挂钩，同时在这些挂钩运行时按下时将消息留在队列中
  • 修复了从 ! 模式在 shell 中运行的键绑定斜杠命令
  • 修复了 ctrl+o 不显示来自其他代理和仍在等待传递的会话的消息；它们现在完整地出现在成绩单下方，标记为等待
  • 修复了长工具输出预览被表情符号剪切，留下 jq 无法解析的会话记录
  • 修复了共享父级 /proc 的 Linux 沙箱中 PDF 页面范围的读取报告“文件不存在”
  • 修复了来自 Claude Desktop 托管会话的消息在连接刷新时有时会丢失的问题
  • 修复了当同一台计算机上的终端登录到不同帐户或组织时，Claude 桌面应用程序中的 Claude Code 会话缺少的功能
  • 修复了 claude remote-control 状态行，显示 HEAD 作为不在 git 存储库中的文件夹的分支
  • 修复了分割窗格代理队友不继承领导者命令行上给出的工具拒绝和 --tools 规则的问题
  • 修复了在 VS Code 窗口重新加载或非交互式 --resume 后以生成的名称向其他会话显示的 /rename 重命名的会话
  • 修复了通过 /code-review --fix、子代理或 shell 命令更改检查点文件的回合显示“无代码更改”的 /rewind 列表
  • 修复了 /privacy-settings 显示过时的“帮助改进我们的 AI 模型”值的问题；现在还显示何时无法获取设置
  • 修复了当您的组织不接受反馈时反馈说“稍后再试”的问题；它现在显示服务器的原因以及在哪里报告错误
  • 修复了超大/反馈报告失败的问题，而不是在没有文字记录的情况下重新发送
  • 修复了 --add-dir 文件夹中的一项技能在其他技能已保留其名称时无法访问的问题；现在提供为 <folder>:<name>
  • 修复了 /verify 和 /code-review 在从 shell 更改文件时找不到嵌套包自己的技能的问题
  • 修复了 /claude-api 技能说 ant beta:worker poll --on-work 将跟踪上下文传递给命令
  • 修复了 /claude-api 技能的 C# 跟踪设置缺少云平台 clients 的跨度
  • 修复了 /claude-api 技能，该技能表示 API 跨越对 AWS 上 Claude 平台的请求无法加入调用者的跟踪
  • 修复了在 PowerShell 中运行的挂钩在挂钩程序以代码 2 退出时不会阻塞，以及在 Windows PreToolUse 和 PermissionRequest 上，在未安装 Git for Windows 时，"shell": "powershell" 挂钩无法打开的问题
  • 修复了 mod 的 turn.step 挂钩，该挂钩通过别名命名模型，例如 haiku，导致每个请求因模型错误而失败：别名现在解析为其模型
  • 修复了从 claude.ai 同步的插件和技能在磁盘读取错误后被删除（有时在会话中）的问题
  • 修复了某些普通页面拒绝的工件发布和更新，例如具有某些缩小脚本的页面或克劳德无法首先阅读的工件
  • 修正了克劳德在对话被压缩后在该回合的剩余回合中请求每个神器更新的许可
  • 修复了当 ANTHROPIC_BEDROCK_BASE_URL 设置为默认 bedrock-runtime.<region>.amazonaws.com 端点时细粒度工具流在 Amazon Bedrock 上停留的问题
  • 修复了仅发送 keepalive ping 的网关后面闪烁的“等待 API 响应”提示：离开 Anthropic 后端的路由现在等待 45 秒
  • 修复了克劳德通过在 PR、问题和评论中提及的方式编写角色名称和占位符来通知不相关的 GitHub 用户的问题
  • Linux：修复了当后台命令超出会话寿命时沙箱写入拒绝提升的问题
  • Windows：修复了 PowerShell 权限检查自动批准某些针对当前目录并携带额外参数的 Set-Location 或 cd 命令的问题；这些现在提示批准
  • macOS：修复了每次 Claude Code 在没有 Xcode 或命令行工具的 Mac 上启动时打开的“安装命令行开发人员工具”对话框
  • 自托管运行程序：修复了 --startup-timeout-min 停止第一个提示（例如 /code-review）仍在子代理中工作的会话的问题；冻结的进程仍然停止
  • 提高了许多 git 命令 Claude Code 在 Windows 上运行的速度；在每个平台上，即使 git 设置为另一种语言，这些命令的错误现在也会以英语显示
  • 改进了当钩子模块嵌套太深而无法加载时的错误：它现在命名文件而不是显示裸露的堆栈溢出消息
  • 改进的磁盘满处理：被满磁盘切断的 Bash 命令现在会这样说并命名要释放的文件夹，并且在满临时卷上启动会打印一条清晰的消息，而不是原始 ENOSPC 错误
  • 改进了 /claude-api 技能，以便在要求添加 OpenTelemetry 时提供 API 跟踪和 SDK 跟踪
  • 改进了 /claude-api 技能，可以在说某个功能不受支持之前检查实时文档
  • 自托管运行器：改进了转移到新运行器的会话：克劳德现在看到被中断的工具调用，标记为结果未知
  • 更新了捆绑的数据可视化技能，以接受 APCA 作为文本对比度度量（在需要符合 AA 的情况下保持 WCAG 2 比率），在其调色板验证器脚本中添加 apca(text, background) 函数，并说明彩色图表填充内的标签是否应为白色或接近黑色
  • 更新了 /claude-api 技能：服务帐户密钥和工作负载身份联合令牌现在可以管理 OpenTelemetry 目的地
  • 更改了 sed -i 以获取标准 Bash 提示符并按编写的方式运行，而不是模拟文件编辑预览；与其他 Bash 编辑一样，/rewind 不再恢复它
  • 将 claude ultrareview 更改为需要工作空间 trust：它在终端上询问，否则拒绝；脚本传递 --trust-workspace，它不带任何值（在其前面放置 PR 编号或基本分支），或设置 CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1
  • 更改了桌面应用程序和 VS Code 中绕过权限模式下危险的 rm 和 rmdir 提示，以通过重写提示立即拒绝该命令，以便无人值守的会话继续进行
  • 更改了从沙箱中排除的设置，以在沙箱已启用但无法运行时写入其写入列表路径之前询问；那里拒绝未沙盒的后备
  • 更改了工作树的创建和重用，因此 git 不再在普通克隆和配置了 Bash 沙箱的部分克隆中按需获取对象；这样的部分克隆首先获取它们
  • 更改了 /claude-api 技能，以在默认情况下启用动态工作流程的 multiagent_20261001 上构建托管代理子代理团队，而不是 coordinator
  • [VSCode] 添加了一条日志警告，说明当听写或扩展程序自身的请求未能通过证书验证（例如在 TLS 检查代理后面）时该怎么做

  • [VSCode] 修复了每次启动新会话而不发送消息时，会话历史记录都会填充空的“无标题”会话的问题
