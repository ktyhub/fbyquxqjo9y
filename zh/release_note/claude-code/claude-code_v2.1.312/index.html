claude-code v2.1.312

修订 发布时间2026年10月27日 来源anthropics/claude-code 英文原文

变更流程图

亮点

  • 自定义模型部署需注意 — Bedrock、Vertex、Foundry 和 Mantle 现在对 Claude Code 不认识的模型名（包括自定义部署名和推理 profile ARN）使用较短的系统提示。被标记消息后的自动回退现在也覆盖这些名称。设置 CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 可保留完整提示，或 CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 禁用回退。
  • Hook 执行现在有上限 — Prompt 和 agent hook 每个会话（含子 agent）最多并发 24 个，最多 12 个等待超出其事件超时；亚秒级 timeout 值按 1 秒处理。重度 hook 用户应检查其超时和并发假设。
  • 数据安全与可靠性修复 — Claude 现在在覆盖大型 CLAUDE.md、规则文件或 @ 包含的文件前会先读取完整内容，或就地编辑。其他修复涵盖 claude -p 中静默缺失的命令、终端恢复后丢失的首条回复，以及 Bash cd 后 skill 消失的问题。
  • 企业与集成改进 — OIDC 身份现在可用 oidc.user_id_claim 代替 sub，适用于 Microsoft Entra ID 的 oid。VS Code 策略加载、云例程、Slack 回复和 Code Review 提交选择也获得针对性修复。
  • 升级建议 — 自定义模型部署、重度 hook 工作流、VS Code 企业用户以及云/Slack/Code Review 用户值得升级。未列出明确的迁移步骤，但自定义部署应测试提示和回退变更；不涉及这些领域的用户可以合理跳过。

发生了什么变化

  • 将 oidc.user_id_claim 添加到 Claude 应用程序网关，以通过 sub 之外的 id_token 声明来识别人员，例如 Microsoft Entra ID 的 oid
  • 添加了 click 发送：在全屏中，clicking 排队消息下的“立即发送”提示会立即发送它，就像它的按键一样
  • 修复了从 VS Code 扩展登录后不会在会话的其余部分获取托管设置和组织策略的问题
  • 修正了克劳德在只看到其开头后覆盖子目录中非常大的 CLAUDE.md、规则文件或 @-included 文件的问题；现在写要求克劳德阅读全部内容或就地编辑
  • 修复了在深入 git 存储库的 Bash cd 后找不到每个目录和 paths: 技能的问题
  • 修复了一种罕见的情况，即下次恢复会话时，终端中恢复会话后的第一个回复可能会丢失
  • 修复了名称无效的命令，阻止所有命令加载，这可能导致 claude -p 没有输出
  • 修复了当同时运行旧会话文件的清理时，读取工具有时会在 PDF 页面上失败并显示“pdftoppm 失败：无法写入图像”的问题
  • 修复了在模型应用任务期间在任务期间命名新选择的努力级别的微调器、OpenTelemetry effort 值和成绩单；他们现在显示有效的水平
  • 修复了 /model 和 /effort 缓存警告，表示重新读取等待您的下一条消息；克劳德工作时所做的改变可以更快地触发它
  • 修复了当最后一条消息仅提到在句子中等待您的项目时，某些会话显示为正在等待您
  • 修复了代理视图在退出前使用 Ctrl+C 清除后在下次启动时恢复输入文本的问题
  • 修复了从空 ! 输入中使用 Ctrl+D 退出后在 shell 模式下重新打开代理视图的问题
  • 修复了 vim 模式 d、c 和 y，其中 gj 或 gk 计数大于删除或复制文本时留下的行数；像 Vim 一样，他们现在只移动光标
  • 修复了 /verify 在 /help 和 / 命令菜单中显示针对克劳德的长描述，而不是短描述
  • 改进了提示的工作量指示器：任务中进行的更改现在表示它可能会等待您的下一条消息，并且当它不再适用时，注释会被清除
  • 改进了云会话中的 WebFetch 错误：无法解析的主机现在被解释为可能位于允许的网络域之外，因此 Claude 指定了允许的主机
  • 更改了 Bedrock、Vertex、Foundry 和 Mantle，以对 Claude Code 无法识别的模型名称使用较短的系统提示，例如自定义部署名称和推理配置文件 ARN，即使它们位于 Sonnet 或 Haiku 前面；设置CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0保持完整提示
  • 更改了标记消息后的自动模型切换，以涵盖 Claude Code 无法识别的模型名称，例如自定义部署名称；设置 CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 将其关闭
  • 更改了使用限制消息，将 5 小时窗口称为“5 小时限制”而不是“会话限制”
  • 更改了从 CLI 启动的云会话，以从服务器获取其名称和分支名称
  • 将提示和代理挂钩更改为每个会话一次最多运行 24 个（包括子代理），加上最多 12 个等待时间超过其事件超时时间的代理；低于 1 秒的 timeout 现在算作 1 秒
  • 更改了子代理的 autoCompactWindow 以降低 CLAUDE_CODE_AUTO_COMPACT_WINDOW 设置的窗口，之前没有效果；它仍然没有升起那个窗口
  • 更改了 OpenTelemetry mcp_server.name 以报告由官方 Anthropic 市场插件声明的固定 URL 远程 MCP 服务器的真实名称，而不是 custom
  • 更改了克劳德代码以停止发送 claude_code.safety_event OpenTelemetry 事件
  • [VSCode] 修复了当组织的设置无法加载或在启动时被拒绝时会话以裸退出代码结束的问题；该选项卡现在会说明原因并提供“重试”或“再次登录”选项
  • [VSCode] 更改了使用限制重置，以显示时钟时间（“下午 3:10 重置”）并表示“5 小时限制”
  • [云会话] 当您创建或编辑在云中运行的例程时，向模型选择器添加了工作级别
  • [云会话] 在云环境设置中的设置脚本框中添加了带有颜色、行号和复制按钮的 Bash 编辑器
  • [云会话] 改进了 Claude 将存储库添加到云会话时显示的步骤：现在打开它会显示发生的情况的简短表格，而不是原始 JSON
  • [云会话]修复了在云会话中发送失败后重新发送未更改的消息（有时会运行两次）的问题
  • [云会话]修复了云环境创建失败的问题，仅在打开的对话框之外显示其错误；它现在出现在对话框内
  • [云会话]修复了在“例程”页面上的例程菜单中进行编辑的问题，无需打开其编辑对话框即可进入例程页面
  • [远程控制] 修复了未存档的远程控制会话在计算机重新连接之前显示为工作状态的问题；现在显示为空闲
  • [Claude Tag] 改进了 Slack 中 Claude Tag 的重试通知，以命名正在使用的模型，或者说达到了速率限制，而不是通用的 API 错误
  • [Claude Tag] 修复了当较旧的私有 Slack 频道公开并获取新 ID 时，Claude Tag 频道的开/关开关和代理设置回落到工作区默认值的问题
  • [Claude Tag] 修复了 Slack 中的 Claude 在环境网络访问设置为“无”的频道中不回复的问题
  • [Claude Tag] 修复了 Slack 中的 Claude 有时在同一频道的另一个线程中回答时在错误的线程中发布文件的问题
  • [代码审查]修复了当 GitHub 延迟交付推送事件时代码审查会审查过时的提交，或根本不审查的问题；现在它会审查拉取请求的当前提交
