claude-code v2.1.305

claude-code v2.1.305

这个项目是干啥的：Anthropic 官方的命令行 AI 编程助手，在终端里让 Claude 直接帮你读写代码、改项目、跑命令。给习惯用命令行的开发者用。

变更架构图

亮点

  • 供应商与 runner 回归修复 — v2.1.304 可能导致在 Vertex、Bedrock 或拒绝/省略 ToolSearch 的网关上每个请求都失败；Claude Code 现在会在不带该参数的情况下重试。自托管 runner 也恢复了 TERM/stdout 共享支持，以及基于 GIT_CONFIG 的 git 凭证助手支持。受影响的用户应尽快升级；否则这些是无感的正确性修复。
  • Linux 沙箱可选开关会削弱隔离 — sandbox.allowNestedUserNamespaces 允许沙箱化进程为 Chromium 和 rootless podman 创建用户命名空间，明确允许它们绕过沙箱的文件保护。除非确有必要，否则保持关闭；启用它是一个安全决策，不是常规的迁移步骤。
  • 权限与 MCP 加载行为变更 — allowedMcpServers 不再只凭 ${VAR} 仅在 env 中出现就过滤 managed-mcp.json 的 stdio 服务器，因此升级后此前被排除的服务器可能会加载；把它们加入 deniedMcpServers 可保持禁用。此外，Claude Desktop 中以路径挂载的插件在 allowManagedPermissionRulesOnly 下会失去 allowed-tools。上线前请同时审查这两处设置。
  • 持久性与会话正确性 — Workflow 恢复现在从日志中提供已完成的 pipeline() 和 parallel() 代理，而不是重新运行它们；裸仓库 worktree 从默认分支开始并正确清理；模型标签、MCP 优先级、压缩通知和 /resume 条目也已修复。如果这些工作流对你重要，建议升级；否则属于可推迟的维护更新。
  • UX 改进，含一项按键绑定迁移 — /usage 警告现在提供单行修复建议，在 CLI、VS Code 和 /doctor 中按 f 即可应用；/artifacts 删除确认现在用 1 或回车保留、2 删除、Esc 取消，y 和 n 不再有效。除此之外，本版本是常规打磨，并非必须升级。

发生了什么变化

  • 添加了 sandbox.allowNestedUserNamespaces，因此 Linux 上的沙盒命令可以创建用户命名空间（Chromium、rootless podman）；这让他们可以绕过沙箱的文件保护
  • 添加了 CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS，因此无人值守重试模式 (CLAUDE_CODE_RETRY_WATCHDOG) 会注意到在重置之前已解除的使用限制
  • 修复了当端点或网关拒绝工具搜索时，Vertex、Bedrock 和其他提供商上的每个请求失败，以及在网关后面使用 ToolSearch 不允许或被排除在 --tools 之外（2.1.304 回归）：Claude 代码现在在没有它的情况下重试
  • 修复了当模型名称因字母大小写或 [1m] 标签与 modelOverrides 值不同时 /effort 和 /autocompact 设置不适用的问题
  • 修复了裸存储库中的新工作树有时从本地 HEAD 而不是默认分支开始，以及未更改的子代理工作树有时不会被清理的问题
  • 修复了完整磁盘上的 Bash 命令因原始 ENOSPC 文件路径而失败的问题：错误现在表明磁盘已满并且没有运行任何内容
  • 修复了云会话或 SDK 的 setMcpServers 传递的 MCP 服务器稍后在会话中被您自己的设置中的同名服务器替换的问题
  • 修复了在子代理切换到后备模型后，克劳德为子代理的工作命名错误的模型
  • 修复了云会话和队友在压缩必须将最旧的消息从其摘要中留下以适应时不告诉克劳德的问题
  • 修复了更多已安排的 Cowork 云会话等待五分钟的情况，每个子代理的 WebFetch 需要 URL 批准，但没有人在那里给予批准
  • 修复了工作流程恢复重新运行已完成的 pipeline() 和 parallel() 代理，而不是从运行日志中提供服务的问题
  • 修复了与 /resume 切换对话后远程控制在 /resume 中留下空“（会话）”条目的问题
  • 修复了 /usage 行在狭窄终端中被切断的问题
  • 修复了在徽标上方打印为原始文本的启动警告：它们现在转到调试日志，并且不限制任何内容的权限规则在横幅下显示为警告行
  • 修复了屏幕阅读器模式：搜索框现在显示“搜索：”，而不是符号 VoiceOver 读取为“电话录音机”，并且突出显示的提示文本，例如 Ctrl+R 搜索匹配项和“ultrathink”，单词内不再有空格
  • 自托管运行器：修复了仅与运行器或协调器共享其标准输出的启动脚本，当设置 TERM 时，该启动脚本会失败并出现 Resource temporarily unavailable（2.1.300 回归）
  • 自托管运行器：修复了自 2.1.296 以来，当 git 凭据帮助程序或 Askpass 程序通过 GIT_CONFIG 读取其设置时存储库访问失败的问题
  • 自托管运行器：修复了当在后台启动的运行器保持其输出打开时，编排器报告生成运行器挂钩超时的问题
  • 改进了 /usage：每个警告现在都是一行修复，指定其来源，并且 f 应用修复； VS Code 和 /doctor 中出现相同的修复
  • 改进了 MCP 同意对话框，因此用于提示的 Enter 不太可能被视为接受
  • 改进了 mod 的 Image 以在 iTerm2 3.5 中绘制其图片，然后使用全屏渲染，仅显示其 alt 文本
  • 远程控制：改进了生成模式消息：按 w 现在表示新模式已保存到文件夹中，稍后使用保存的模式的 claude remote-control 启动会显示它来自哪里
  • 更改了 allowedMcpServers 以停止过滤仅在 env 中使用 ${VAR} 的 managed-mcp.json stdio 服务器：您遗漏的许可列表现在会在升级时加载；使用 deniedMcpServers 将其关闭
  • 更改了 Claude Desktop 通过路径安装的插件，当您组织的托管设置设置为 allowManagedPermissionRulesOnly 时，不再保留其 allowed-tools
  • 修改/artifacts删除确认为1或Enter保留，2删除，Esc取消； y和n不再接听
  • 更改了 mod 的停靠窗格，使其保持在终端宽度的 45% 以内，包括与更宽的终端保持的宽度
  • [VSCode] 添加了“正在运行启动挂钩”微调器状态，并在 SessionStart 或安装挂钩运行时显示屏幕阅读器公告
  • [VSCode] 修复了当您的 spinnerVerbs 设置用短动词替换内置动词时，微调器会切断“正在压缩…”的问题
  • [VSCode] 更改了会话未及时启动且没有钩子运行时显示的消息：它现在以输出日志开头并列出原因，而不是首先指向登录和网络
  • [云会话] 修复了云环境管理页面错误地拒绝保存现有环境并出现“安装包”错误
  • [云会话] 改进了删除自托管环境，因此对话框和错误消息会说明阻止删除的内容以及它将影响的内容
  • [Claude Tag] 添加了公共 Slack 频道 Claude 尚未加入 Claude Tag 管理员 添加地点搜索，因此管理员可以从那里设置一个
  • [Claude Tag] 修复了 Claude Tag 访问捆绑包，以便可以再次添加移动到另一个 GitHub 帐户的存储库
  • [Claude Tag] 修复了 Slack DM 线程中设置的例程在该线程中的另一个例程重新启动对话后不再发布；两人现在都继续在那里发帖
  • [Claude Tag] 修复了在 Slack 线程中设置的例程，报告成功但在对话结束后不发布；这些运行现在被跳过并告诉创建者
  • [Claude Tag] 改进了大型组织中的 Claude Tag 管理页面，因此插件、技能和捆绑包编辑可以在频道列表仍在加载时进行
  • [代码审查]修复了在审查期间多次推送落在拉取请求上时代码审查有时不审查最新提交的问题
  • [代码审查] 更改了代码审查重新审查，因此它们不再与 LGTM 一起开放，而早期的阻止结果仍然开放
