claude-code v2.1.274

这个项目是干啥的：Anthropic 官方的命令行 AI 编程助手，在终端里让 Claude 直接帮你读写代码、改项目、跑命令。给习惯用命令行的开发者用。

变更架构图

亮点

  • MCP 启动与协议默认值 — Bedrock、Vertex、Foundry 和关闭遥测的安装现在默认使用 v2 MCP 客户端，对直连 HTTP 服务器采用 MCP 2026-07-28 协商；可用 MCP_SDK_GENERATION=v1 或 MCP_PROTOCOL_NEGOTIATION=legacy 退出。修复覆盖旧版 HTTP+SSE 的 4xx 失败、工具调用超时过长、漏掉列表变更更新、误导性的 403 登录错误，以及首回合启动卡顿（CLAUDE_CODE_MCP_STARTUP_WAIT_MS）。重 MCP 用户应升级。
  • 对迁移敏感的变化 — .mcp.json、设置、插件和代理文件中的 "type": "sdk" 条目现在会被跳过并给出警告，因为只有 SDK 宿主能注册进程内服务器。插件/市场克隆会把 Git LFS 内容保留为指针，请在受影响的检出中运行 git lfs pull。Bash 加固还增加了对特殊变量循环/赋值的权限提示，并在 worktree 隔离会话中拒绝某些嵌套展开；升级前请测试受影响的自动化。
  • 长会话与代理可靠性 — 无休止的 unexpected tool_use_id 重试循环现在会自愈或以 /rewind 提示终止；/goal 能在压缩/恢复后保留，被中断的后台工作恢复更可靠，headless/SDK 的后台完成会批量处理，避免每个任务一次模型调用。还修复了自托管 runner 401 重试、云端供应商上的子代理模型选择、内存压力终止、语言服务器卡顿和 shell profile 重载延迟。对自动化和长会话非常值得。
  • 网关运维与遥测 — 在 claude_code.llm_request 上新增 effort，新增 claude_code.managed_settings_resolved（OTEL_LOG_MANAGED_SETTINGS=1 时记录脱敏设置与摘要），以及 OTEL_LOG_RAW_API_BODIES=file:<dir> 下的请求/响应关联。网关启动时会重试 Postgres 三次，store.connect_timeout_seconds 控制默认的 5 秒，支出检查从四次数据库往返减少到一次，SIGTERM 时通过 CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS 最多排空在途请求 25 秒。网关运维应升级。
  • VS Code 与云端会话体验 — VS Code 新增重载续跑、Memory/Instructions 自定义、编辑器组锁定控制、键盘/屏幕阅读器修复，并防止并发设置损坏。云端会话新增分支到分支的 diff、更有韧性的例行任务与凭证，包括 GitHub 连接缺失时的 72 小时重试。推荐 VS Code 或云端用户升级；不受这些问题影响的基础 CLI 用户可以放心跳过。

发生了什么变化

  • 添加了当内存使用至关重要时的可见警告，以及释放内存或安全重新启动的步骤
  • 添加了 CLAUDE_CODE_MCP_STARTUP_WAIT_MS 来限制第一个非交互式回合等待连接 MCP 服务器的时间（0 = 不等待）
  • 将 effort 属性添加到 claude_code.llm_request OpenTelemetry 跟踪范围，匹配 api_request 事件
  • 添加了 claude_code.managed_settings_resolved OTel 事件：托管设置源和策略帮助程序状态；使用 OTEL_LOG_MANAGED_SETTINGS=1 编辑设置和摘要
  • 将 store.connect_timeout_seconds 添加到 Claude apps 网关配置中，以延长 Postgres 连接超时（默认 5 秒），并改进了数据库无法访问时的启动错误，以指向 store.postgres_url 和配置的超时
  • 将 IdP 主体 enduser.sub 添加到通过 Claude 应用程序网关发送的遥测 Claude Desktop 和 Cowork
  • 添加了当副本打开的请求多于一次向上游发送的 256 个请求时，克劳德应用程序网关警告，以及显示该限制的启动日志行
  • 为全屏模式下折叠的队友和代理消息添加了 click-to-expand
  • 修复了会话无休止地重试“意外的 tool_use_id”400 错误的问题：损坏的记录现在可以在可能的情况下自我修复，否则明确的错误（带有 /rewind 提示）会结束循环
  • 修复了配置为 http 的 MCP 服务器，仅使用旧版 HTTP+SSE，当它们用 422 或另一个 4xx 错误应答第一个请求时无法连接
  • 修复了 Streamable HTTP MCP 工具调用在大约 5 分钟后超时的问题，即使设置了更长的每服务器 timeout
  • 修复了当服务器在未声明 listChanged 的情况下发送列表更改通知时 MCP 提示和资源不刷新的问题
  • 修复了 MCP 工具调用被拒绝并报告 403 unavailable_scope 为过期登录的问题：该错误现在命名了缺失的权限并指向 /mcp 重新身份验证
  • 修复了钩子驱动的会话（例如活动的 /goal），当上下文在反应性压缩后再次溢出时，以“提示太长”结束而不是压缩
  • 修复了恢复（--continue / --resume）已压缩的会话时活动的 /goal 丢失的问题
  • 修复了自动更新重新启动后 claude agents 丢失 --model、--effort、--permission-mode、--allow-dangerously-skip-permissions 和 --agent 的问题
  • 修复了语言服务器发布数千个文件的项目范围诊断时每轮速度减慢的问题
  • 修复了基岩、顶点或铸造厂上的 model: "opus" 子代理在其 id 没有可识别的模型系列时离开会话模型的问题（除非设置了 ANTHROPIC_DEFAULT_OPUS_MODEL）
  • 修复了自托管运行者会话在几次失败的令牌刷新后每回合都会失败并显示 401 的问题，直到下一次计划的刷新为止；运行程序现在不断重试，并在 401 之后获取新令牌
  • 修复了指向本地文件路径的 clickable 链接，在 VS Code 和需要 file:// URI 的其他终端中不执行任何操作
  • 修复了您自己的消息中的文字记录重新编号排序列表（输入“3.2.1.”显示“3.4.5.”）；数字和“N)”标记现在显示为键入的内容
