claude-code v2.1.265

修订 发布时间2026年9月8日 来源anthropics/claude-code 英文原文

claude-code v2.1.265

变更流程图

亮点

  • 安全修复 — 包含反斜杠的插件路径可能在 macOS/Linux 上绕过符号链接约束；已修复，同时修复了以 .. 开头的插件目录被误拒，以及插件目录不可访问时错误信息更清晰。Artifact 工具现在把其他用户的页面视为不可信，并标记其中嵌入的指令。插件和远程 MCP 用户应升级。
  • 会话与工作流可靠性 — 恢复会话会保留被中断的工具调用而不重写最后一条提示词，在提示词前缀中保留钩子/技能内容以复用缓存，并避免在回合中途淘汰 --bg 会话。长会话恢复更快，cd 现在能跨非交互、Agent SDK 和云端回合保持。带缺失日志的 Workflow 运行现在会明确失败，而不是重跑每个代理——这是值得注意的恢复行为变化。
  • 插件开发改进 — --plugin-dir 现在接受一个父文件夹，其下的子清单会随着文件夹增删而动态加载。市场元数据会补齐显示名/描述的空缺，并在”已安装”/详情中优先。/workflows 也暴露工具调用状态和子代理任务列表。无需迁移；主要利好插件作者和工作流用户。
  • 托管网关变更 / 迁移 — forceLoginGatewayUrl 现在从启动起就强制网关会话，并忽略残留的 claude.ai 登录或 API 密钥；上线前请核验托管凭证。配置后网关遥测会直接导出到 OTEL_EXPORTER_OTLP_ENDPOINT 指定的收集器，否则经中继。Desktop/Cowork 现在还会发送 user.email 和 user.groups，请审查收集器的访问权限与隐私影响。
  • 存储上限与升级判断 — 磁盘保存的工具结果上限为 1 GB，保存的输出被截断时会在会话中提示；处理超大产物的用户应预期磁盘完整性下降。这是一个实质的安全与可靠性版本，不是仅改标签。不受插件、托管网关、云端/SDK 工作流或大输出影响的基础终端用户可以合理推迟。

发生了什么变化

  • 将 user.email 和 user.groups 添加到通过 Claude 应用程序网关发送的遥测 Claude Desktop 和 Cowork，匹配终端会话
  • 添加了对将 --plugin-dir 指向插件文件夹的支持：带有清单的每个子文件夹都会加载，并且会拾取运行时添加或删除的子文件夹
  • 添加了保存到磁盘的工具结果 1 GB 的上限；对话中预览显示保存的文件何时被截断
  • 修复了恢复前台生成的子代理更改其工具列表和系统提示符前缀的问题，这会破坏该代理的提示缓存重用
  • 修复了代理队友和恢复的子代理在稍后的回合中将 SubagentStart 挂钩上下文和预加载技能移出提示前缀的问题，这会破坏提示缓存重用
  • 修复了工具运行时前一个进程死亡后的恢复：最后的提示不再重写，中断的工具调用被保留并标记为已中断
  • 修复了 /model opusplan[1m] 因“找不到模型”而被拒绝的问题
  • 修复了权限提示和消息中的语法突出显示代码有时会在 Ruby ?、Erlang $ 或 Perl $ 印记后省略字符的问题
  • 修复了每当斜杠命令或@文件建议列表打开或关闭时全屏记录会跳一行的问题
  • 修复了包含反斜杠的插件路径，绕过了 macOS 和 Linux 上的符号链接包含检查
  • 修复了名称以两个点开头的插件目录被错误地拒绝为插件根目录之外的问题
  • 修复了 VS Code 和 SDK 会话在会话关闭并刷新其令牌时偶尔需要重新登录的问题
  • 修复了远程控制会话在回复的最后一条消息之前发送回合结束信号的问题，这可能会在最后一部分到达之前在 Claude 应用程序中显示已完成的回复
  • 修复了当消息在空闲超时之前到达时，后台 (--bg) 会话偶尔会在轮流中退出的问题
  • 修复了 Claude Code 自己的 git status 和 diff 探针，运行由工作树内的嵌套存储库配置的干净过滤器
  • 修复了顾问工具及其指令根据请求模型中的每个请求重新决定的问题；现在，该决定只需做出一次，并在更改时在对话中宣布
  • 修复了工件发布接受连接器工具名称但连接器未公开的问题；现在，当声明的工具都不存在时，发布会被拒绝，而只有某些工具不存在时，则会发出警告
  • 修复了当托管设置仅锁定插件技能时 /add-dir <subdirectory> 拒绝加载子目录的代理，以及当仅锁定代理时承诺代理的问题
  • 修复了当第二个键在一秒后到达时，双键键盘快捷键会默默取消的问题，就像 tmux 内发生的情况一样；现在，他们会等待 3 秒，并在超时时显示通知
  • 修复了分叉技能 (context: fork) 不流式传输其开球提示的问题，并且使用 --forward-subagent-text，其文本在流 json 中变成进度事件
  • 修复了操作系统无法检查的插件的默认组件文件夹，例如符号链接循环，被静默跳过；现在在 /plugin 中报告错误代码
  • 修复了 Claude 应用程序网关的 OTLP 遥测中继在拒绝一些格式错误或太大的有效负载后暂停所有转发到收集器 30 秒的问题
  • 修复了 /plugin 发现/浏览和 claude plugin list --json --available 不显示元数据仅存在于 plugin.json 中的市场插件的描述或显示名称的问题
  • 修复了在登录到由托管设置设置的 Claude 应用程序网关的会话中重新运行时，/login 显示“未配置网关 URL”的问题
  • 修复了当设置文件无法写入时 /model 声称模型“保存为默认值”的问题；现在显示保存失败以及原因
  • 修复了远程控制中的 /clear 在完成之前等待 SessionStart 挂钩和打开终端对话框的问题
  • 修复了 /config 对话框在选项卡之间切换时改变高度的问题
  • 修复了容器重新启动后恢复工作流程运行的问题；缺少运行日志的简历现在失败并出现明显错误，而不是重新运行每个代理
  • 修复了 claude-api 技能的错误代码参考：模型访问失败返回 404，不可用的测试标头返回 400，而不是 403
  • 修复了非交互式会话（带有流 json 输入的 -p、代理 SDK、云会话）在每个新用户消息时重置 shell 工作目录； cd 现在在转弯时仍然存在
  • 修复了配置为 http 的 MCP 服务器，仅使用传统 HTTP+SSE 传输，从不连接；正如 MCP 规范所述，Claude Code 现在回退到 SSE
  • 修复了云会话中的一些 claude.ai 连接器显示为需要身份验证，即使它们已在 claude.ai 中连接（使用 HTTP 401 应答不受支持的请求的服务器）
  • 修复了远程会话在连接器批准或登录链接等待您时保持其沙箱容器处于活动状态的问题
  • 修复了恢复会话在“后台任务未完成”通知中显示较长的面向模型的恢复指令，而不是较短的状态行
  • Windows：修复了在 AppContainer 或受限令牌沙箱内运行时读取、写入和编辑拒绝每个文件的问题（“检查权限后符号链接解析发生更改”）
  • 改进了大型存储库上的 --worktree 启动：新的工作树现在并行检出（git 2.32+）
  • 改进了 /workflows 代理详细信息：工具调用被标记为正在运行、失败或已完成，子代理的任务列表会在有任务列表时显示，按 Enter 键会展开列出的调用及其输入和结果
  • 改进了在提示符中输入的斜杠命令：匹配项现在显示在列表中（Tab 在全屏之外打开它）而不是单个建议，并且现在可以通过其裸名称找到插件技能
  • 改进了需要登录的远程 MCP 服务器：在您实际进行身份验证之前，Claude Code 不再向它们注册 OAuth client
  • 改进了恢复读取许多文件的长会话的时间
  • 改进了当无法解码超过大小限制的图像时显示的错误：它现在指出原因以及如何修复它，而不是仅引用限制
  • 改进了 Artifact 工具对其他人编写的工件的读取：摘要现在将页面视为 untrusted 内容并标记嵌入式指令，而不是转发它们
  • 更新了 .claude 文件夹权限选项以说明其实际允许的内容：编辑会话的项目 .claude 文件夹（或 ~/.claude）中的文件
  • 将托管设置中具有 forceLoginGatewayUrl 的计算机从启动时更改为 Claude 应用程序网关会话，例如 forceLoginMethod: "gateway"；未使用剩余的 claude.ai 登录名或 API 密钥
  • 更改了图像处理以使用运行时的内置图像支持； CLI 不再将本机映像模块提取到临时目录
  • 更改了插件显示元数据，以在“已安装”选项卡和 claude plugin details 上更喜欢市场条目而不是 plugin.json，填补了 plugin.json 的空白
  • 更改了 Claude 应用程序网关会话，将 OpenTelemetry 直接导出到 OTEL_EXPORTER_OTLP_ENDPOINT 中网关的托管设置名称的收集器，而不是通过网关的中继；没有指定收集器的会话仍然使用中继
  • [VSCode] 添加了对一段时间内不活动的会话的自动归档（新的“归档不活动会话”设置，默认 14 天）
  • [VSCode] 修复了当对话打开超过 10 分钟时，侧边栏聊天在重新加载窗口或重新启动后返回空白的问题
  • [VSCode] 修复了“远程控制已激活”消息文本下方的时间线点
