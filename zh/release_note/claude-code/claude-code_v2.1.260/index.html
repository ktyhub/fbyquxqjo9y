claude-code v2.1.260

修订 发布时间2026年9月3日 来源anthropics/claude-code 英文原文

claude-code v2.1.260

变更流程图

亮点

  • 权限与沙箱加固——单为这一点就该升级。 关闭了几个真实的绕过：含括号的路径规则不再被丢弃/忽略（此前会让”只读”目录仍可写）；无法编译的拒绝规则（如未闭合的 [）现在会保护其字面路径，而不是让每次编辑都因 Invalid regular expression 失败；在 REPORTTIME/REPORTMEMORY/DIRSTACKSIZE 赋值中隐藏命令替换的 zsh 命令不再自动批准；Glob/Grep 现在在探测路径之前就判定权限。另外，2.1.259 中把 Read() 拒绝规则应用到 Bash 参数的改动已被回滚——它曾在 Read(./**/build/**) 下拒绝 npm run build，并让 cd … && grep 即使在自动模式下也弹提示。任何依赖权限规则或沙箱的用户都应为这些修复升级。

  • 上线前需检查的行为变更。 在 ! bash 模式提示下输入的命令现在在沙箱外运行，即使 sandbox.allowUnsandboxedCommands: false（和你自己的终端一样）；全屏下的 ctrl+l/cmd+k 现在像终端 clear 一样清空转录（向上滚动可看历史）；规则右括号后面的尾部文本（如 Bash(ls) x）现在会被报告为无效设置，而不是静默忽略；托管的 claudeMd 不再触发安全审批对话框（钩子、shell 命令、沙箱和不安全的 env 设置仍会）；Claude in Chrome 现在遵循组织管理员设置，因此管理员禁用它会使 --chrome、/chrome 和浏览器工具不可用；当 desktop 策略在 managedMcpServers 或 orgPluginSettings 中拼错嵌套字段时，网关会拒绝启动并点名字段。请先审查权限规则语法以及管理员/网关设置。

  • 提示缓存与 Fable 5.1 / 1M 上下文修复——用这些模型就值得。 修复了以下问题：model: fable 代理忽略 ANTHROPIC_DEFAULT_FABLE_MODEL 固定值上的 [1m] 标签（静默以 200K 运行）、/model 选择器隐藏 Fable 5.1（此前只接受手动输入 /model claude-fable-5-1）、Fable 5.1 的缓存不覆盖工具结果之后附带的上下文（每个工具回合都重新发送未缓存内容），以及会话中途 /effort 变更使缓存失效。/cost 和状态栏的 prompt_cache 字段现在会显示未命中的可能原因。1M 上下文的 Opus/Fable 的自动压缩现在会在接近上限前触发，恢复压缩不再在 10 分钟时超时。

  • 新命令与 headless/SDK 能力。 /diff 在对话旁打开全屏 diff 面板，显示 Claude 编辑时未提交的更改；/reload-plugins 现在在 headless 会话中可用（出现在 Desktop/SDK 命令列表）；文本形式的 /advisor（/advisor <model>、/advisor off）可用于桌面、Remote Control 和 -p/Agent SDK 会话；网关新增 oidc.scope_on_refresh 和较新的 Desktop 策略键（userPluginMarketplacesEnabled、userPluginUploadsEnabled，以及列表形式的 orgPluginSettings，适用于 Desktop 1.15200.0+）。SDK 提供的 MCP 服务器现在首回合就会出现，非交互 -p/SDK 会话的空闲 CPU 占用也得到改善。Bedrock 用户注意：中止请求的输入令牌现在通过 bedrock:CountTokens 统计（需授予该操作），而不是用一次一令牌的请求。

  • 可靠性与 IDE 打磨——优先级较低，不受影响可跳过。 /rewind/--rewind-files 在备份文件缺失时不再误报成功；-p --resume/--continue（桌面应用使用）现在能在 worktree 丢失 git 元数据时恢复；代理团队转录和 SendMessage 唤醒在长时间重试期间不再丢失、变空或重复；GitLab 嵌套子群组和 owner/repo#123 链接已修正；Workflow agent({schema}) 会预先拒绝无法满足的 JSON Schema；并移除了子代理后台命令的 1 小时上限。VSCode 获得 effort 药丸/状态过滤/历史选择器修复。这是一个实质版本，不是仅改标签——如果上述条目都不适用于你，可以跳过这次升级。

发生了什么变化

  • 添加了一个差异面板，该面板在全屏模式下在对话旁边打开，并在克劳德编辑时显示您未提交的更改；使用 /diff 切换它
  • 向 /cost 和状态行的 prompt_cache 字段添加了提示缓存未命中的可能原因（例如工具定义或系统提示已更改、空闲超过 TTL）
  • 将 /reload-plugins 添加到无头会话中，因此它出现在 Claude Code Desktop 和 SDK 命令列表中
  • 为桌面应用程序、远程控制和其他无头（-p/Agent SDK）会话添加了 /advisor（/advisor、/advisor <model>、/advisor off）文本形式
  • 将 oidc.scope_on_refresh 添加到 IdP 的 Claude 应用程序网关，仅在再次请求 openid 时才在刷新时返回 id_token
  • 在 desktop 策略块中添加了对较新的 Claude Desktop 密钥的 Claude 应用程序网关支持，包括 userPluginMarketplacesEnabled 和 userPluginUploadsEnabled
  • 修复了 Edit/Write/Read 权限规则，其路径包含括号，被 Bash 沙箱视为无效或忽略，从而使“只读”文件夹可写
  • 修复了一个具有不可编译模式（例如未封闭的 [）的文件权限规则，导致每个文件编辑都因 Invalid regular expression 失败；这样的拒绝规则现在保护它所拼写的字面路径
  • 修复了 Bash 权限检查自动批准的 zsh 命令，这些命令隐藏 REPORTTIME、REPORTMEMORY 或 DIRSTACKSIZE 分配中的命令替换；这些现在提示批准
  • 修复了当公司根 CA 仅位于操作系统证书存储中时，Bedrock 模型发现、令牌计数和 AWS SSO/STS 凭证调用因“无法获取本地颁发者证书”而失败的问题
  • 修复了 macOS 上的 permissions.blockReadsOutsideWorkingDirectories 从沙盒 git 隐藏用户的 git 配置并隐藏工作树隔离的子代理自己的结帐
  • 修复了无法为 claude.ai 企业/团队用户加载托管设置的问题，这些用户还拥有早期 /login 剩余的 API 密钥
  • 修复了 /status 列出已登录的 claude.ai 帐户和配置的 API 密钥的问题，就好像两者都有效一样；未使用的凭证现已标记
  • 修复了以捆绑技能别名（例如 checkup 表示 /doctor）为关键的托管 skillOverrides 条目不适用，以及 Skill(name) 拒绝规则不涵盖列为 <dir>:name 的嵌套技能的问题
  • 修复了 model: fable 代理忽略 ANTHROPIC_DEFAULT_FABLE_MODEL 引脚上的 [1m] 标签并使用 200K 上下文窗口静默运行的问题
  • 修复了 /model 选择器未向可以使用它的组织显示 Fable 5.1 的问题，该组织仅在键入 /model claude-fable-5-1 时才接受
  • 修正了 Claude Fable 5.1 上的提示缓存不覆盖工具结果后附加的上下文，因此它在每个工具调用回合中作为未缓存的输入重新发送
  • 修复了插件挂钩加载失败后模型切换在会话的剩余时间内保持阻塞的问题；现在每个交换机都会重新检查并列出拒绝的原因
  • 修复了当无法加载组织管理的插件市场时会话被阻止的模型切换
  • 修复了 SDK 提供的 MCP 服务器（例如桌面连接器）有时会在第一轮中丢失而仅出现在下一轮中的问题
  • 修复了添加或删除连接器时，Chrome 工具中的 Claude 在云托管的 claude.ai 会话中出现“未连接”任务中失败的问题
  • 修复了标志、连接的表情符号和重音字母在换行中分开，以及当标志或连接的表情符号落在终端的最后两列时，过时的文本留在屏幕上（现在显示为 …）
  • 修复了远程控制接受不是有效模型名称的模型选择的问题；现在它被拒绝并出现错误，而不是在下一条消息上失败
  • 修复了当检查点备份文件丢失且实际未恢复任何内容时 /rewind 和 --rewind-files 报告成功的问题
  • 修复了 /rewind 在回滚轮中留下过时的文件读取跟踪，这会导致“自上次读取后文件未更改”存根以及外部编辑后的完整文件重新注入
  • 修复了一旦会话的工作树目录丢失其 git 元数据，-p --resume/--continue（由桌面应用程序使用）每次重试都会失败的问题；现在失败一次，然后在没有工作树的情况下恢复
  • 修复了通过 SendMessage 恢复另一个代理的子代理永远不会被该代理完成唤醒的问题（通知转至主对话）
  • 修复了代理团队：在长时间的 API 重试等待期间（例如在 CLAUDE_CODE_RETRY_WATCHDOG 下），进程内队友的成绩单丢失消息或变为空白，因为重试通知驱逐了真实消息
  • 修复了移至后台的会话在 ListAgents 中出现两次（一次作为同名的虚拟“交互式”双胞胎）并在查看器中接收 SendMessage 传送的问题
  • 修复了许多会话共享项目目录时间歇性的“任务输出交换被拒绝”错误
  • 修复了全屏中的 Ctrl+Z 将 shell 留在备用屏幕上、在暂停的界面上绘制的问题
  • 修复了工作流工具子代理在长上下文压缩仍在进行时因停滞而重新启动的问题
  • 修复了当主机应用程序（例如 Claude Desktop）将其存储为目录时，来自 URL 市场的插件无法安装并显示“市场入口路径不保留在市场目录内”的问题
  • 修复了在您从 claude.ai、桌面应用程序或移动设备（远程控制）驾驶的会话中发布工件时打开的额外浏览器选项卡
  • 修复了 Artifact 工具的首次调用在某些 Cowork 会话中因“工具参数无效”验证错误而失败的问题
  • 修复了运行技能或斜杠命令时删除 IDE 行选择的问题（“选择了 N 行”上下文现在到达了克劳德）
  • 修复了嵌套子组中 GitLab 项目的存储库检测（例如 gitlab.com/group/subgroup/project）
  • 修复了在 GitLab 存储库中工作时链接到 github.com 的渲染输出中的 owner/repo#123 问题引用；他们现在链接到 gitlab.com 问题
  • Glob/Grep：修复了在权限检查之前在磁盘上探测的搜索路径；现在，在决定许可后会报告丢失的路径，就像读取一样
  • 恢复了将 Read() 拒绝规则应用于 Bash 参数的 2.1.259 更改；它在每种模式下都根据 Read(./**/build/**) 规则拒绝 npm run build，并且即使在自动模式下也会提示 cd … && grep
  • 改进的结构化输出：工作流程 agent({schema}) 拒绝永远无法预先满足的 JSON 模式，并且重试上限错误现在包括上次验证失败
  • 改进了删除工作树具有未推送提交的后台会话：消息现在命名分支和提交计数，再次删除会丢弃工作树
  • 改进了克劳德应用程序网关的刷新失败日志以命名失败的步骤
  • 改进了非交互式 (-p / SDK) 会话的空闲 CPU 使用率
  • 改进了 Amazon Bedrock 上的 Claude 应用程序网关：中止请求的输入令牌现在使用 AWS 的免费 CountTokens API（授予 bedrock:CountTokens）而不是单令牌请求进行计数
  • 改进了 Edit(C:\dir\(name)\**) 等规则的设置错误，其中 \( 被读取为转义括号而不是路径分隔符，以建议明确的拼写
  • 改进了 1M 上下文模型的自动压缩：Opus 和 Fable 会话现在在 1M 令牌限制之前不久进行压缩，并且非常大的上下文上的恢复压缩不再在 10 分钟超时
  • 改进了 /ultrareview 和 claude ultrareview，以便长时间运行的云审核等待长达 45 分钟（之前为 30 分钟）
  • 改进了 Claude Fable 5.1 上的 /effort，因此在会话中更改工作量不再使提示缓存失效
  • 更新了捆绑的 claude-api 技能，使其 Go、Java 和 C# 示例使用当前一代模型 ID，并澄清更便宜的工作人员或子代理模型也应该是当前一代
  • 更改了全屏模式下的 ctrl+l / cmd+k，以像终端 clear 一样清除记录视图；向上滚动查看较早的消息
  • 更改了右括号后文本的权限规则（例如 Bash(ls) x），它从未匹配任何内容，将被报告为无效设置，而不是被默默忽略
  • 更改了服务器管理的设置，因此托管的 CLAUDE.md (claudeMd) 不再触发安全审批对话框；挂钩、shell 命令、沙箱和不安全的 env 设置仍需要批准
  • 更改了 Chrome 中的 Claude，以在 Chrome 管理设置中关注您组织的 Claude；当管理员将其关闭时，--chrome、/chrome 和浏览器工具将不可用
  • 更改了 Claude 应用程序网关，以 Claude Desktop 1.15200.0 及更高版本读取的列表形式发送 orgPluginSettings；较旧的桌面会忽略它
  • 当 desktop 策略拼错 managedMcpServers 或 orgPluginSettings 条目的嵌套对象中的字段时，将 Claude 应用程序网关更改为也拒绝启动、命名字段
  • 更改了在 ! bash 模式提示符下键入的命令，以便即使在严格沙箱模式 (sandbox.allowUnsandboxedCommands: false) 开启时也可以在沙箱之外运行，就像在您自己的终端中键入一样
  • 更改了自托管运行器 --kill-session-after-min 以释放仅等待用户的会话（已暂停，可在下一条消息时恢复），而不是终止它并报告失败
  • 取消了子代理启动后台命令的一小时时间限制；它们现在运行直到退出或停止，与主会话匹配
  • [VSCode] 将选定的努力水平添加到页脚模型药丸中，修复了切换模型后过时的努力水平，并将页脚药丸恢复到之前的紧凑尺寸
  • [VSCode] 在会话列表的状态过滤菜单中添加打开和关闭
  • [VSCode] 修复了当远程控制自动打开时欢迎屏幕在新会话中消失的问题
  • [VSCode] 修复了会话历史记录选择器在会话已在另一个选项卡中打开时再次加载会话的问题；现在切换到该选项卡
  • [VSCode] 修复了会话选项卡的重命名命令在选项卡视图重新加载时不执行任何操作的问题；现在它总是适用
  • [VSCode] 修复了 Claude Code 重试丢弃的响应后屏幕上保留的半成品消息、空工具卡或额外的“Thought for”行
  • [VSCode] 修复了“为所有会话启用远程控制”不适用于翻转切换时仍在启动的会话选项卡的问题
