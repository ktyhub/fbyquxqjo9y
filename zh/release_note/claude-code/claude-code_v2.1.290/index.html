claude-code v2.1.290

变更流程图

亮点

  • 权限与安全——托管/沙箱环境应紧急升级 — 修复了基于符号链接绕过读取限制的问题，将 Read 拒绝规则扩展到图片和 @ 提及的文件夹，并阻止用户安装的 mod 禁用组织防护。Bash 自动批准对通配符展开的命令和 shell 变量差异收紧，MCP URL 限制现在覆盖 .mcp.json、插件和 agent 中的条目。依赖旧豁免的自动化现在可能会提示或被拒绝；请据此审查权限和沙箱规则。
  • 长会话与计划任务可靠性——普遍值得升级 — 修复 /loop 和提醒在压缩或后台交接后消失、重复定时运行、子 agent 思考和提示缓存丢失、图片密集请求失败、深层嵌套崩溃和长消息停滞。计划任务持久化修复适用于从 v2.1.290 起执行的压缩；它不承诺恢复升级前已丢失的任务。
  • 插件与 mod hook——新增 API 与更好的诊断 — turn.step 现在返回 serverToolUses，暴露顾问执行的工具调用 ID、名称、输入和耗时。tool.check 新增 agentId 和 ceiling，让 hook 能区分子 agent 检查和组织要求的批准级别；类型定义新增 ThemeKey 和 Color。claude plugin validate 现在报告门控 hook 是否有 .catch，包括 --json 下的 gatingHooks。未列出破坏性 API 变更或必需迁移。
  • CLI、集成与平台修复——受影响就升级 — claude attach <name> 和 claude logs <name> 接受会话名称片段；WebFetch 现在报告超过 100,000 字符的文本并支持 offset。修复了代理/网关 beta 头失败、远程会话流式传输、计划模式恢复、后台 agent 重启、Windows CRLF skill 块和 WSL 启动停滞。Remote Control、云、Windows/WSL、网关和后台 agent 用户获得实实在在的好处。
  • 总体建议 — 这是实质性的错误修复与安全版本，不是重新打标签或仅元数据更新。大多数活跃用户应升级，尤其是使用计划任务、子 agent、长上下文、代理或托管权限的用户。固定版本或轻度使用的安装如果上述工作流都不适用可以跳过，但要考虑到权限提示有意收紧，而非假设旧的自动批准行为不变。

发生了什么变化

  • 将 serverToolUses 添加到 mod 的 turn.step 挂钩的结果中：该工具调用 API 运行本身（顾问），每个都有其 id、名称、输入、开始和结束
  • 将 agentId 添加到插件挂钩的 tool.check 事件中，因此挂钩可以告诉子代理的权限检查与主会话的权限检查
  • 将 ceiling 添加到问题和判决中，mod 的 tool.check 挂钩读取，命名组织所需的工具批准
  • 在插件挂钩类型中添加了 ThemeKey 和 Color 类型，因此编辑器列出了 mod 绘图可以命名的主题颜色
  • 添加到claude plugin validate：mod在门控站点注册的每个钩子都会列出它是否有.catch（--json下的gatingHooks）
  • 在 Claude 应用程序网关的登录批准页面添加了拒绝按钮：它会结束待处理的登录，因此等待的终端会在几秒钟内停止
  • 添加了 claude attach <name> 和 claude logs <name>：会话名称的一部分代替 id
  • 添加了 /claude-api managed-agents-onboard <url> 以设置页面描述为 ant apply 文件的托管代理模式
  • 添加了 /claude-api managed-agents-onboard <quickstart-name> 以构建控制台快速入门模板，例如 deep-researcher 与 ant CLI
  • 当托管设置文件是指向托管设置文件夹外部的文件的链接时添加了警告
  • 当托管设置忽略用户配置的沙箱允许读取路径或允许的域时添加了 /status 和 doctor 警告
  • 修复了请求在代理和网关后面失败的问题，这些请求会拒绝状态不是 400 的 Claude Code 的 Beta 标头之一，或者与第二个 Beta 一起拒绝
  • 修复了数百张图像陷入“请求因模型无法处理而被拒绝”错误的长时间会话
  • 修正了当克劳德还在思考时，API的输出内容过滤器停止回复时，回合立即结束的问题；现在，在显示错误之前会重试请求一次
  • 修复了恢复的子代理和队友在运行中途收到消息后丢失先前的思维和提示缓存的问题
  • 修复了 WebFetch 静默丢弃超过 100,000 个字符的页面文本的问题；现在显示有多少内容未读，需要 offset 才能继续阅读
