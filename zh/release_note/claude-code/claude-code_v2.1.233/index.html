claude-code v2.1.233

修订 发布时间2026年8月14日 来源anthropics/claude-code 英文原文

claude-code v2.1.233

变更流程图

亮点

  • 破坏性——新模型上移除 todo 工具 — TaskCreate/Get/Update/List 和 TodoWrite 在 Opus 4.8、Sonnet 5、Fable 5、Mythos 5 及更新模型上不再可用；如果你的工作流依赖这些模型做任务跟踪，必须设置 CLAUDE_CODE_ENABLE_TODO_TOOLS=1 来恢复。这是唯一可能破坏升级的改动，部署前请阅读。
  • Windows：回滚 2.1.232 的回归 — 针对 Cygwin 风格符号链接和输入重定向（< file）的 Bash 权限改动已回滚（更窄的版本稍后推出），且 auto 模式不再对普通的 cd <dir> && <command> > file 停止等待手动批准。卡在 2.1.232 的 Windows 用户应升级；注意底层权限收紧只是推迟，并未取消。
  • 自托管与 Linux 的新选择启用控制 — Anthropic 上游的 forward_user_identity 将已登录用户身份作为头部发送，使网关代理可以按用户归因支出；CLAUDE_CODE_TOOL_MEMORY_LIMIT 为 Linux 上的 Bash 命令增加 cgroup 内存上限，防止失控构建拖住会话；CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS 调整 WebFetch URL 缓存（默认仍为 15 分钟）。全部选择启用且默认值不变，因此多用户网关运营者和 Linux 用户零迁移成本获得真正控制——其他人可视为无变化。
  • 值得升级的可靠性与安全修复 — 堵住 Windows NTLM 凭据泄露向量（带 \??\ 设备前缀的路径绕过 UNC 校验）；阻止 MCP v2 连接对终止长流的无服务器主机不断重开 subscriptions/listen；修复权限提示期间云会话被误标丢失、Notification hook 在 Claude Desktop/VS Code 下不触发、Linux 空闲会话因沙箱占住一个 CPU 核，以及 /checkup、/review 等内置别名在被遮蔽时于 -p 模式报”Unknown command”。对 Windows、无服务器 MCP 和 IDE/桌面用户升级理由最强。
  • 易用性与诊断（不是空操作版本） — GitLab MR 现在通过 --worktree 解析并在 claude agents 中显示为 !N；claude self-hosted-runner 通过避免重写工作树和两次阻塞往返来更快启动会话；来自 Vertex、Foundry 和 AWS 上 Claude Platform 的网关 400/413 错误现在显示上游消息（也修复自动压缩）；claude plugin validate 检查裸 .claude/skills 目录中无法解析的 SKILL.md frontmatter；屏幕阅读器下 /effort 变为带编号的类型化提示；[claude-code:unrecognized_model] stderr 行标记未知模型 ID（可通过 modelOverrides 静默）。便利改进而非必选项——GitLab/自托管 runner 用户受益最大，其他人在处理好 todo 工具门控后可从容升级。

发生了什么变化

  • 添加了对 --worktree 标志和 claude agents 视图的 GitLab 合并请求 URL 支持（其中 MR 显示为 !N）
  • 在 Anthropic 上游添加了一个选择加入的 forward_user_identity 应用网关设置，该设置将登录用户的身份作为标头发送，因此网关后面的代理可以归因于每个用户的支出
  • 添加了对 Linux (CLAUDE_CODE_TOOL_MEMORY_LIMIT) 上的 Bash 工具命令的选择加入内存 cgroup 支持，因此失控的构建无法停止会话
  • 添加了 CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS 环境变量来配置 WebFetch 会话 URL 缓存 TTL（默认不变：15 分钟）
  • 修复了当克劳德等待权限提示时环境关闭时云会话偶尔会被标记为丢失的问题
  • 修复了 MCP v2 连接不断重新打开订阅/监听流的问题，这些服务器在固定超时时终止长期持有的流（例如无服务器主机）
  • 修复了在 Claude Desktop 或 VS Code 下运行时通知挂钩不会触发权限提示的问题
  • 修复了启用沙箱时 Linux 上的空闲会话有时会将一个 CPU 核心保持在 100% 的问题
  • 修复了捆绑技能别名（如 /checkup 和 /review）在 -p 模式下或在用户或项目技能隐藏捆绑技能时加载插件/MCP 时报告“未知命令”
  • 修复了技能/命令参数替换，以防止参数值被重新扩展为模板标记
  • 修复了使用 NT \??\ 设备前缀拼写的 Windows 路径，绕过 UNC 路径验证，从而关闭 NTLM 凭据泄漏向量
  • 改进了 claude self-hosted-runner 会话启动时间：现在无需重写工作树即可创建会话分支，并且两次服务器往返不再阻止代理的启动
  • 改进的应用程序网关错误转发：来自 AWS 上游 Vertex、Foundry 和 Claude Platform 的 400/413 错误现在携带上游自己的消息；修复了应用程序网关上自动压缩的错误
  • 改进了 claude plugin validate 以检查裸 .claude/skills 目录，报告 frontmatter 无法解析的 SKILL.md 文件
  • 改进的屏幕阅读器模式：/effort 选择器呈现为带有键入数字提示的编号列表，提示和对话框文本不再是 clipped
  • 改进的打印模式诊断：当发出 Claude Code 无法识别的模型 ID 请求时，[claude-code:unrecognized_model] 行将写入 stderr；将其映射为 modelOverrides 以静音
  • 更改了 GitHub 应用程序设置提示，使其不再出现在原始远程位于 gitlab.com 或 bitbucket.org 上的存储库中；企业市场提示现在涵盖非 GitHub 内部 git 主机
  • Opus 4.8、Sonnet 5、Fable 5、Mythos 5 和更新型号不再提供 Todo/任务跟踪工具（TaskCreate/Get/Update/List、TodoWrite）；设置 CLAUDE_CODE_ENABLE_TODO_TOOLS=1 将它们带回来
  • Windows：修复了自动模式反复停止以手动批准普通 cd <dir> && <command> > file Bash 命令的问题（2.1.232 回归）
  • 恢复了 Windows 上 Cygwin 样式符号链接和输入重定向的 2.1.232 Bash 权限更改 (< file)；较窄的版本将在以后的版本中返回
