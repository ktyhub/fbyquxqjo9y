claude-code v2.1.293

修订 发布时间2026年10月7日 来源anthropics/claude-code 英文原文

变更架构图

亮点

  • 新的默认 Haiku 模型（claude-haiku-5-5） — Claude Haiku 5.5 成为 Anthropic API 上的默认 Haiku，提供 1M 上下文和每百万令牌 $0.10/$0.50（超过 100K 的提示为 $0.50/$2.50）。任何固定 Haiku 行为或做令牌预算的人都应重新核对成本与输出质量；仅凭这一点，对量大且成本敏感的用户就值得升级。

  • 需要规划的破坏性变更与回滚 — claude purge 现在会删除它能删的、列出删不掉的，并以退出码 1 结束，而不是静默退出 0，因此依赖退出码 0 的脚本会坏掉。两项早期修复被回滚：2.1.281 的自动模式拒绝措辞（拒绝再次只覆盖确切命令，而非结果）和 2.1.290 的容器重启后云端会话唤醒修复（待处理的 /loop 唤醒和定时任务不再恢复，会话保持休眠）。另外，非 ASCII 名称现在在代理列表和向模型公布的 MCP 服务器中排在 ASCII 之后，OpenTelemetry claude_code.at_mention 每次读取提示最多发出 100 个代理和 100 个 MCP 资源事件。如果你依赖任一被回滚的行为，就别升级；否则这是一次安全的升级。

  • 值得为核心代理可靠性升级 — Claude 不再撤回或重做在上下文压缩前刚完成的工作；在 Claude 工作时发送的消息不会因 ← 把会话转入后台而丢失（← 现在若无法移动会原地不动并给出提示）；后台、--agent 和恢复会话中的权限/绕过同意、SendMessage 可用性以及内置工具禁用报告都已修正；当文件是通过 Bash 工具里的单文件 cat/head/tail/sed -n/grep 查看而非 Read 工具时，路径范围规则和嵌套 CLAUDE.md 现在也会加载。这些都是影响大、用户可见的修复——日常使用的最强升级理由。

  • Mod 与插件创作更新 — subagentStatusLine 的负载新增 agentType 以区分自定义子代理类型；$.tool.register 新增 isDeferred，设为 false 时从一开始就把工具 schema 列在提示词里，而不是藏在工具搜索之后；claude plugin test 现在支持 mod 通过新的 mock.session 调用 $.session.append；claude plugin test/eval 及 classic.* 钩子处理也已修复（插件 worker 重启期间不再跳过钩子，Docker Desktop 的凭证链接拒绝现在会点名违规的存储）。mod 作者应更新以使用新字段和测试支持。

  • Remote Control、Chrome 与运维修复 — 修复了 HTTP MCP 内存泄漏（每个请求会一直保留到关闭）；长的 Remote Control/云端会话恢复流式回复，凭证恢复后不再重新上传起始历史；--chrome/--no-chrome 和慢标签页处理改进了 Claude in Chrome；Team/Enterprise 启动现在更早获取策略和托管设置，并带 3 秒重试；自托管 runner 的轮询加入抖动，改为 4–6 秒，避免副本同步轮询。主要与 Remote Control、Chrome 和企业/自托管用户相关——纯本地、单用户 CLI 且没有上述问题的用户可以推迟。

发生了什么变化

  • 添加了 Claude Haiku 5.5 (claude-haiku-5-5)，现在是 Anthropic API 上的默认 Haiku 模型 — 1M 上下文，每个 Mtok $0.10/$0.50（$0.50/$2.50 对于超过 100K 的提示）
  • 将 agentType 添加到 subagentStatusLine 有效负载，因此脚本可以区分自定义子代理类型
  • 为 mods 添加了 isDeferred 到 $.tool.register：false 从一开始就在提示中列出工具的架构，而不是在工具搜索后面
  • 修正了克劳德有时将上下文压缩之前的最后一个操作视为在上下文压缩之后完成的操作，并撤回或重做已完成的工作
  • 修复了 HTTP MCP 连接保留其发送的每个请求直至关闭的内存泄漏问题
  • 修复了当 ← 将会话移至后台时克劳德工作时发送的消息丢失的问题；如果排队的消息无法移动，← 现在会保持原状并这样说
  • 修正了 /model 努力 ←/→ 环绕超过最高或最低水平，这可能会意外地将低保存为模型的默认努力
  • 修复了 /tui 在以 --chrome 启动的会话中在 Chrome 中断开 Claude 的连接，并忽略 --no-chrome
  • 修复了克劳德被告知在会话中继续使用 SendMessage 或向子代理发送消息，包括恢复的会话，其中主机、权限规则或 --tools 列表删除了该工具
  • 修复了子代理和 --agent 会话被告知内置工具在整个会话中被禁用的问题，而只有他们自己的工具列表将其排除在外
  • 修复了 claude.ai 同步技能的编辑描述有时在新对话或 /clear 之前无法到达模型的问题
  • 修复了 claude logs、stop、kill、rm 和 claude daemon status、stop、uninstall 有时在登录已过期或即将登录时注销的问题
  • 修复了读取会话文件夹短暂失败后页脚代理计数消失的问题（例如，打开的文件太多）
  • 修复了名为 worker 的自定义代理在启动时显示为“代理”，并且代理详细信息对话框的标题在代理完成后丢失代理类型的问题
  • 修复了 Artifact 工具的转录行在发布调用仍在流入时短暂读取 Artifact("(unprintable path)")
  • 修复了 Linux 上的 /ultrareview 上传错误地拒绝某些存储库（例如另一个结帐内的存储库）的问题，因为在运行沙盒命令时“无法解析”设置文件
  • 修复了 /ultrareview 上传拒绝分割索引文件的问题，建议使用 git 命令，该命令可能导致 git 无法读取其索引
  • 修复了很长的远程控制和云会话中的回复，这些回复仍然可能一次出现一个块，而不是流式传输
  • 修复了远程控制在每次凭据恢复后再次上传会话的启动历史记录的问题
  • 修复了使用 claude remote-control 启动的会话中推送通知报告“远程控制无效”的问题
  • 修复了当插件钩子工作重新启动时，Mod 对 classic.* 事件的钩子被跳过，这使得设置钩子在没有它们的情况下回答
  • 修复了 claude plugin test 对于调用 $.session.append 的 mod 失败的问题；测试可以使用新的 mock.session 读回附加的行
  • 修复了 claude plugin eval 拒绝在带有 Docker 桌面的 Mac 上运行的每次 Bash 授予的问题（~/.docker/bin 下的链接）；现在，拒绝指定凭证存储的哪个部分持有链接
  • 修复了当 desktop 策略设置 Claude Desktop 的内置浏览器密钥（例如 builtinBrowserEnabled）时 Claude 应用程序网关拒绝启动的问题
  • 修复了 claude agents 提供绕过权限，当同意仅保存在 .claude/settings.local.json 或 --settings 文件中时，后台会话会忽略这些权限；现在它首先请求同意，并且忽略旁路的会话会显示一条简短的通知
  • 修复了 ← 在提示保留未发送文本（现在取消移动）或有问题等待您回答时 10 秒后将会话置于后台的问题
  • 修复了当 ← 刚刚被按下以将会话移至后台时，在权限提示中 Esc 或“否”而没有反馈的问题不会停止转动
  • 修复了当无法读取会话文件夹时（例如，打开的文件太多），代理视图会短暂地用占位符行替换会话列表
  • 修复了当 Claude 在 Bash 工具而不是 Read 工具中使用单文件 cat、head、tail、sed -n 或 grep 命令查看文件时，路径范围规则和嵌套 CLAUDE.md 文件不会加载
  • 修复了以相同单词开头和结尾的粘贴文本有时会被发送给克劳德，就好像它已被键入一样
  • 修复了在粘贴合并到最后一个字母后立即键入或粘贴重音时，粘贴文本中的技能名称被视为键入的问题
  • 修复了在发送报告时按 Ctrl+O 或 Ctrl+Z 后 /feedback 返回草稿列表，导致发送无法取消的问题
  • 修复了当无法删除文件或文件夹时 claude purge 静默停止（退出 0，或在终端中挂起）的问题；现在它会删除其余内容，列出无法删除的内容，然后退出 1
  • 修复了键绑定。json 检查：单独的“”（空格键）不再报告为错误，并且像“ctrl+ k”这样的键现在会收到警告
  • 修复了 vim 模式 >> 和 << 位于仅包含空格的行上，使光标超出行尾，其中后续的 x 没有删除任何内容
  • 修复了 vim 模式：在可视模式下删除整行（V 然后 d）后，光标落在第一个非空白处，而 . 作用于光标所在行后
  • Windows：修复了停止状态行、挂钩或 shell 命令有时会终止已被赋予相同进程 ID 的不相关进程的问题
  • 恢复了 2.1.281 的自动模式拒绝消息更改，该更改告诉克劳德拒绝涵盖结果，而不仅仅是确切的命令
  • 恢复了 2.1.290 修复，以防止容器重新启动后保持睡眠状态的云会话丢失挂起的 /loop 唤醒或计划任务；克劳德不再被告知，会话保持睡眠状态
  • 改进了团队和企业组织的启动：更早获取策略和托管设置，并在 3 秒后重试停止的请求
  • 改进了 Chrome 中的 Claude：当浏览器报告其选项卡速度缓慢时，拒绝的页面操作更少
  • 改进了无法访问浏览器时云会话中 Chrome 中的 Claude 消息：如果您属于多个组织，它现在会提示扩展程序必须登录到同一个组织，以及如何更改该设置
  • 改进了 Bash 编辑差异注释，以表明命令运行时列出的文件发生了更改，其中可能包括其他进程的写入
  • 改进的工件：克劳德将库固定到两周或更早的确切版本
  • 更改了 claude.ai 技能同步，在没有使用会话时每 40 分钟检查一次更改，而不是每 10 分钟检查一次
  • 更改了向模型宣布的代理列表和 MCP 服务器的顺序：带有非 ASCII 字符的名称现在在 ASCII 名称之后排序
  • 更改了 OpenTelemetry claude_code.at_mention 日志记录，以便每次读取提示时发出最多 100 个代理和 100 个 MCP 资源事件
  • 自托管运行器：将协调器更改为在轮询之间休眠 4 到 6 秒，而不是恒定的 5 秒，因此一个环境的多个副本会同时停止轮询
  • [Claude Tag] 修复了 Slack 中的 Claude，当 Slack 用未连接的工作区标记消息时，跨工作区共享的企业网格通道中未设置工作区
  • [Claude Tag] 修复了当管理员更改频道的连接器、插件、技能或规则时，Slack 中的 Claude 会停止频道中的任务；克劳德完成后，更改立即生效
  • [Claude Tag] 修复了要求 Slack 中的 Claude 现在运行线程例程的问题，并附加注释启动无法回发的单独运行；现在运行在该线程中继续
  • [Claude Tag] 修复了 Claude Tag 管理设置中访问捆绑包的“添加连接器”对话框，显示每次 Google 登录后每个 Google 连接器均已连接
  • [Claude Tag] 改进了 Claude Tag 管理设置，以列出尚未连接的企业网格，并带有“连接”按钮
  • [Claude Tag] 将 Slack 中的 Claude 更改为加入公告频道，只有管理员可以发帖，而无需发布简介
  • [Claude Tag] 将每个工作区和组织范围的 Slack 页面的 Claude Tag 管理设置中的频道规则限制从 20 条更改为 50 条
  • [代码审查]改进了代码审查的添加存储库对话框，以列出无法添加的每个存储库及其原因，例如缺少 GitHub 写入权限
