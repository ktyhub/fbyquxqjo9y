claude-code v2.1.219

修订 发布时间2026年7月24日 来源anthropics/claude-code 英文原文

claude-code v2.1.219

变更流程图

亮点

  • 默认模型与快速模式 — Claude Opus 5（claude-opus-5）成为默认 Opus 模型，提供 1M 上下文，快速模式价格为每百万令牌 $10/$50。破坏性变更： Opus 4.7 不再支持快速模式；/fast 现在只作用于 Opus 5 和 Opus 4.8。claude-api 技能也默认使用 Opus 5，并提供从 Opus 4.8 迁移的路径。
  • 沙箱网络 — 新增 sandbox.network.strictAllowlist，沙箱化命令访问非白名单主机时直接拒绝，不再询问。适合需要确定性网络限制的无值守或 CI 负载；已有配置无需迁移，除非主动启用。
  • 子代理与工作流规模 — 嵌套子代理默认支持深度从 1 提升到 3；设置 CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 可保持原有行为。--forward-subagent-text 现在转发深度 2 及以上的代理，以派生它的 Agent tool_use id 为键。动态工作流也默认采用中等规模指引（目标少于 15 个代理），可通过 /config 或 workflowSizeGuideline 调整。
  • 托管 MCP 配置——行为变更 — 托管 MCP 允许/拒绝列表中的 ${VAR} 条目现在从启动环境和托管设置环境解析，而不是设置文件环境。如果相关变量只存在于设置文件 env 中，请把它们移到启动环境或托管设置环境，以保持解析有效。
  • 无头与自托管可靠性 — claude -p 会保留在流中途 API 报错前已经生成的答案；MCP 失败会暴露 HTTP 诊断、空白字符警告，以及对被跳过的 --mcp-config 条目的 mcp_server_errors；自托管 runner 的审批在重启后依然有效，启动终止时也能干净地注销。无头、重度 MCP 或自托管用户应升级，尤其当这些故障曾影响到你时；使用固定模型、工作流稳定的交互式用户可以跳过。

发生了什么变化

  • 添加了 Claude Opus 5 (claude-opus-5)，现在是默认 Opus 模型 — 1M 上下文，快速模式，每个 Mtok 10/50 美元
  • 添加了 sandbox.network.strictAllowlist 设置，以拒绝非白名单主机执行沙盒命令而不提示
  • 添加了 DirectoryAdded 钩子，该钩子在 /add-dir 或 SDK register_repo_root 控制请求在会话中注册新工作目录后触发
  • 将 mcp_server_errors 添加到无头流 - json 初始化事件中，列出配置验证跳过的 --mcp-config 条目；终端运行打印启动警告
  • 添加了 workflowSizeGuideline 设置键，以便可以从任何设置文件设置咨询动态工作流程大小指南； /config 行被隐藏，而另一行则被隐藏
  • 在流-json 中添加了嵌套子代理转发：在设置 --forward-subagent-text 时，现在会出现在深度 2+ 处生成的子代理，并通过其生成代理 tool_use id 进行键入
  • 修复了当转弯因中流 API 错误而死亡时，claude -p 文本输出会丢弃已生成的答案
  • 当服务器无法连接时，向 claude mcp list 和 /mcp 添加了 HTTP 状态和错误文本，并对带有隐藏前导或尾随空格的 MCP 配置值发出警告
  • 修复了您在自托管运行器重新启动时批准的权限在会话恢复时被删除的问题，因此批准的操作现在运行
  • 修复了当过时的缓存已烘焙标签时，寓言模型行显示包含它的计划的“需要使用积分”
  • 修复了当自托管运行器启动时 SIGTERM 到达，留下陈旧的活动行直到租约到期；它现在干净地注销
  • 为自托管运行器生成和会话故障添加了结构化故障类别，因此可以区分挂钩错误、运行器崩溃和配置错误
  • 修复了 /model 选择器将合并的 Opus 行显示为普通“Opus”而不是“Opus（1M 上下文）”
  • 修复了 GNU 丝网打印 base64 内的选择复制到终端而不是复制选择的问题
  • 修复了远程控制 clients 在模型切换、重新连接或组织检查失败后保持过时的快速模式状态的问题
  • 修复了 Windows 上的 CLAUDE_CODE_GIT_BASH_PATH 当路径不是 bash/sh 二进制文件时退出或用作 bash 的问题；现在它被忽略并带有警告
  • 修复了 Vim 模式：在空提示符下按 ← 现在可从 NORMAL 模式返回到代理视图，而不仅仅是 INSERT
  • 修复了屏幕阅读器模式在每次击键时重写整个输入行，而不是仅回显键入的字符
  • 改进了“只能通过 api.anthropic.com 进行远程控制”错误，以命名导致该错误的具体设置
  • 改进了 claude --teleport，以在与会话的存储库不匹配时显示当前结账点所在的存储库
  • 将动态工作流程更改为默认中等规模准则（目标是少于 15 个代理）；选择其他尺寸或不受 /config 中动态工作流程尺寸的限制
  • 更改了托管 MCP 允许列表/拒绝列表 ${VAR} 条目，以从启动环境和托管设置环境（而不是设置文件环境）解析
  • 更改了 /model 选择器以仅突出显示最新型号的名称，因此突出显示标记新版本而不是列表的任意子集
  • 将当前默认工作流程大小添加到正在运行的工作流程状态行，并带有指向 /config 的指针以进行更改
  • 从快速模式中删除了 Opus 4.7； /fast 现在适用于 Opus 5 和 Opus 4.8
  • 将 claude-api 技能更新为默认为 Claude Opus 5，并具有从 Opus 4.8 的迁移路径
  • 子代理现在默认可以生成深度为 3 的嵌套子代理（原为 1）；设置 CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 以禁用嵌套
