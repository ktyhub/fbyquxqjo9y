claude-code v2.1.257

修订 发布时间2026年9月1日 来源anthropics/claude-code 英文原文

变更架构图

亮点

  • 新默认模型与定价 — claude-fable-5-1（“Claude Fable 5.1”）成为默认模型，拥有 1M token 上下文窗口，价格为 $10/$50 每 Mtok，缓存读取 $0.25/Mtok。默认配置的用户无需任何改动就会换用不同模型和成本结构，因此若在意请显式固定。另有新增：timeFormat/timeZone 设置（12 小时、24 小时、24 小时 UTC 或 strftime 模式）用于回合时钟和记录时间戳，以及 CLAUDE_CODE_SUBAGENT_MODEL_FORCE 用于强制所有子 agent 使用 CLAUDE_CODE_SUBAGENT_MODEL（或主模型），无视按次生成或 agent 定义的覆盖。
  • 破坏性：项目级 bypassPermissions 不再生效 — .claude/settings.json 或 .claude/settings.local.json 中的 defaultMode: "bypassPermissions" 现在会被忽略（与 "auto" 一样）；请将它移到用户/托管设置，或传入 --permission-mode。另两项行为变更需注意：/btw 历史浏览从 ←/→ 改为 Shift+←/Shift+→（或 [/]）；--effort 现在只在本次会话解除新模型的默认努力程度锁定，而非永久。managedSourcesBehavior: "merge" 现在也会从最高优先级的托管源整体取用 sandbox.credentials.awsPairs 和 sandbox.ripgrep，而非合并。
  • Auto 模式与权限明显收紧 — 新增的 Containment Escape 规则不再自动批准云元数据凭据获取、出口规避和跨租户访问，除非你的环境将其标记为预期；首次读取工作目录之外的文件前会弹出一次性提示（可用 permissions.blockReadsOutsideWorkingDirectories 阻止）。此版本还堵住数个权限绕过：permissions.ask 在复合命令/子 shell 中被跳过、Bash Read()/Edit() 拒绝规则不作用于 < file 重定向或 tac/egrep、zsh 解析不同的 [[ ]] 条件被自动批准，以及插件通过符号链接组件路径逃出自身目录。如果你过去依赖这些，预期会看到更多提示或被阻止的操作。
  • 真正的收益是后台/agent 工作流的可靠性 — 子 agent 现在会在响应被 sleep、连接断开或服务器错误中途截断时自动继续；修复了顾问模型、Remote Control、截图密集会话和 /fork 的提示缓存未命中；claude -p 会等待已武装的 Monitor，而不是在给出结果约 5 秒后退出；每回合的渲染/提示输入工作量减少。修复了 macOS npm 自更新和 Windows 陈旧守护进程锁导致后台会话无法启动的问题，以及许多 claude agents/--bg、恢复和通知故障。这是重度 claude agents、--bg 和 Remote Control 用户升级的主要理由。
  • 结论：升级，但先做一次简短的配置检查 — 如果你使用 auto 模式（新的安全门禁）、后台会话/agent（大部分修复）或想要新默认模型，就值得升级；部署前请检查项目级 bypassPermissions、/btw 键位变更和任何 --effort 工作流。如果你固定了特定模型、不使用 auto/后台功能，且希望避免新的权限提示，可以放心跳过——这是一个大型、以修复为主的版本，除这些设置变更外没有强制的新配置。

发生了什么变化

  • 添加了 Claude Fable 5.1 (claude-fable-5-1)，现在是默认的 Fable 模型 — 1M 上下文，每个 Mtok 10/50 美元，带有 $0.25/Mtok 缓存读取
  • 添加了“时间格式”(timeFormat) 和 timeZone 设置：12 小时、24 小时、24 小时 UTC 或回合结束时钟和成绩单视图时间戳的 strftime 模式
  • 在自动模式中添加了遏制逃逸规则，因此云元数据凭据获取、出口规避和跨租户访问不再自动批准，除非您的环境将其标记为预期
  • 添加了 CLAUDE_CODE_SUBAGENT_MODEL_FORCE 以将 CLAUDE_CODE_SUBAGENT_MODEL（或主模型）应用于每个子代理，忽略每个生成和代理定义模型覆盖
  • 在 /effort 中添加了 s 以仅更改当前会话的工作量，匹配 /model
  • 为被终止的会话留下的过时的沙箱掩码文件添加了 /doctor 警告
  • 在工作目录之外读取第一个文件之前，在自动模式下添加了一次性提示，并可以选择阻止此类读取（permissions.blockReadsOutsideWorkingDirectories）
  • 在发现的 /model 选择器条目 (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY) 上添加了对网关提供的 description 的支持；没有的条目仍显示为“来自网关”
  • 修复了启动后创建的 .claude/ 文件夹中的设置在重新启动之前不会被拾取的问题
  • 修复了从使用 ← 打开的代理视图分派的会话始终以原始会话的权限模式启动，覆盖目标目录的 defaultMode 和代理的 permissionMode
  • 修复了 keybindings.json 重新绑定 Ctrl+G 在 claude agents 中被忽略的问题；它的 Ctrl+S / Ctrl+T 现在可以通过新的 Agents 上下文重新绑定
  • 修复了在自我更新期间无法在 macOS npm 安装上启动后台会话的问题，以及在 Windows 上当过时的守护程序锁定文件指向重复使用的进程 ID 时无法启动的问题
  • 修复了斜线命令面板后面的响应流时工作旋转器停止的问题
  • 修复了后台会话的 state.json detail 在计划唤醒后重复其自己的调度提示的问题
  • 修复了 claude agents 在再次完成后将您重新提示的后台会话隐藏在“已完成”中的问题；截至目前已完成订单
  • 修复了刚刚删除的目录中的 claude --bg 报告“后台”并留下崩溃的会话行；现在打印原因并退出 1
  • 修复了远程控制连接在会话中重新发送 Bash 工具定义，导致提示缓存丢失的问题
  • 修复了双重列出的自定义 Authorization 标头覆盖基岩、地幔、顶点和 WIF 上配置的凭据，以及顶点设置向导从 ~/.config/anthropic 中拾取剩余的人类配置文件
  • 修复了 Claude 应用程序网关向 Foundry、Vertex 和 Bedrock 发送杂散主机 Authorization 或配置文件标头的问题，并且在设置 ANTHROPIC_FOUNDRY_API_KEY 时 Foundry Entra ID 上游未启动
  • 修复了在 API 密钥模式下与 Foundry 订阅密钥一起发送的剩余 Anthropic API 密钥或身份验证令牌
  • 修复了 /schedule 例程，其提示在没有消息角色的情况下保存，然后无所事事地运行
  • 修正了 claude agents 没有说后台会话正在等待您批准来自另一个会话的消息，或者是谁发送的消息
  • 修复了在打开的后台会话中使用 Ctrl+S 隐藏的提示在会话闲置或停止然后重新打开时丢失的问题
  • 修复了通过服务器管理的设置推送的遥测 (OTEL) 设置在热启动时被忽略的问题，包括桌面应用程序代码会话
  • 修复了当领导者的邮箱写入被短暂锁定时队友权限请求被应答两次的问题
  • 修复了命令的自动连续响应流式传输时，飞行中转弯下方出现幻影重复斜线命令行渲染的问题
  • 修复了 policyHelper、timeoutMs 和 refreshIntervalMs 值高于计时器最大值 (2147483647) 导致失败或每毫秒重新运行的问题；他们现在被夹住了
  • 修复了切换到另一个子代理的记录后令牌计数器冻结或爬行的问题，并使后台子代理和队友的计数器在响应流时实时更新
  • 修复了用尾随点（example.com.）编写的沙箱网络主机：deniedDomains条目没有阻止沙箱内的主机，并且对于此类主机不断提示“不要再询问”
  • 修复了忽略远程控制同意提示（Esc 或 claude remote-control 处的 n）算作同意的问题，因此下一个请求无需询问即可连接
  • 修复了 /mcp 重新连接并启用仍然连接设置文件 MCP 服务器，托管 MCP 允许/拒绝列表或启动后加载的 strictPluginOnlyCustomization 应阻止的问题
  • 修复了当 strictPluginOnlyCustomization 将 MCP 锁定到仅插件服务器时 claude mcp remove 留下远程服务器存储的 OAuth 凭据的问题
  • 修复了从 Claude 应用程序启动的远程控制 (claude remote-control) 会话忽略所选模型并在计算机的默认模型上运行的问题
  • 修复了启用 allowManagedPermissionRulesOnly 时，在重新加载第一个设置后 --disallowedTools 和会话拒绝规则被删除的问题
  • 修复了 --resume 两次列出后台对话并 --continue 重新打开其停滞的预后台副本的问题； --continue 现在还可以打开已完成的后台会话
  • 修复了全屏模式不允许您 click ! shell 命令输出来展开它
  • 修复了运行较旧的克劳德代码二进制文件的后台会话在自动更新中堆积而不是被淘汰的问题
  • 修复了 claude agents --json 将终端短暂切换到原始模式并在退出时撤消另一个程序的终端设置的问题
  • 修复了主动输出样式会话在后台命令或启动的监视器仍在运行时忙于循环填充消息和重复日志读取而不是空闲的问题
  • 修复了由于计算机睡眠、连接断开或服务器错误导致响应中途中断时子代理停止的问题；他们现在会自动继续，而不是以不完整的响应结束
  • 修复了 ← 在 claude agents 会话内的 /btw 面板中不执行任何操作的问题：它现在返回到代理列表（甚至是中间答案），并且当您重新打开会话时面板会返回
  • 修复了顾问模型集缺少后台请求提示缓存（压缩、/recap、提示建议）的会话，并且每次都重新发送未缓存的完整对话
  • 修正了 claude -p 在最终结果后约 5 秒退出，而模型武装的监视器仍在运行；现在等待手表触发或超时
  • 修复了当匹配命令在复合命令或子 shell 中运行时，在自动模式下跳过 permissions.ask 规则，使其在没有确认提示的情况下运行
  • 修复了插件能够通过声明的命令、代理、技能、挂钩或其他作为符号链接的组件路径读取自己目录之外的文件的问题；现在，此类路径会被拒绝并出现错误
  • 修复了 /add-dir 拒绝当前工作目录内的目录的问题；现在，它会加载该目录的技能、命令和代理，就像 --add-dir 在启动时所做的那样
  • 修复了当您从其脚本视图恢复已停止的子代理时，主代理不会被告知的问题
  • 修复了将 ANSI 颜色文本（例如 CI 日志）粘贴到 /feedback 等对话框中时发生的崩溃
  • 修复了当项目的 .mcp.json 是 FIFO 或设备文件符号链接时 claude mcp add/remove 挂起或耗尽内存的问题；现在它会快速失败并显示可操作的消息
  • 修复了非 JSONL 数据通过管道传输到 claude -p --input-format stream-json 时内存无限增长的问题；现在它很快就会失败并出现明显的错误
  • 修复了当子代理或其他工具运行时偶尔会在后台运行一个回合（← 或 Ctrl+B），从而使后台会话将该工具视为被拒绝而不是重新运行它
  • 修复了 Bash Read()/Edit() 拒绝规则不适用于 < file 重定向和阅读器命令（如 tac 和 egrep）；任何参数或重定向目标的拒绝规则现在拒绝该命令
  • 修复了对转录本已超过 5 MB（例如在读取许多图像后）的子代理进行恢复或发送消息时失败并显示“未找到转录本”的问题
  • 修复了拒绝 Bash 循环、$VAR 读取、"$(…)" 和heredocs 的工作树隔离会话，这些会话从不接触 git，因为“太复杂，无法验证它是否保留在工作树内”
  • 修复了 /model 和 /effort 在将对话倒回到空后显示提示缓存警告的问题
  • 修复了一旦图像超出每个请求大小上限，在长屏幕截图的会话中每回合都会出现提示缓存丢失的问题
  • 修复了编辑权限提示的差异视图渲染表情符号和多代码点字符宽度不正确的问题
  • 修复了 WebSocket MCP 服务器连接失败被记录为“[object ErrorEvent]”而不是底层错误的问题
  • 修复了当另一个 Claude Code 进程正在下载 npm 更新时后台会话无法打开并显示“无法启动后台服务”的问题；现在开始等待它
  • 修复了在任务停止或 Claude Code 退出时脱离 shell 的后台命令（例如在 timeout 或 setsid 下）
  • 修复了当您从任务面板或连接的 client 停止后台命令时克劳德没有被告知的问题
  • 修复了停止后台子代理并使其监视器保持运行的问题
  • 修复了链接工作树中的沙盒 git 命令在 cd 进入子目录后丢失对存储库的公共 .git 目录的写访问权限的问题
  • 修复了 Opus 4.7 及更高版本上的长时间隐藏思考阶段中基岩和基岩地幔请求保持沉默的问题，这会导致空闲超时切断连接；该流现在携带进度事件
  • 修复了在克劳德应用程序网关过期或撤销会话后启动克劳德代码的问题：它现在表示会话已结束并提供 /login，而不是报告网络错误
  • 修复了当会话的网络代理在启动时无法启动时，云会话会丢失其余会话的 git/GitHub 凭据的问题；它现在在后台重试并恢复
  • 修复了后台守护程序启动中断后系统临时目录中剩余的 cc-daemon-* 文件夹； cleanupPeriodDays 固位扫描现在可将其移除
  • 修复了 Bash 权限检查自动批准 zsh 与 bash 解析方式不同的某些 [[ ]] 条件；这些命令现在提示批准
  • 修复了当设置还关闭详细跟踪或原始 API 主体注销或打开跟踪导出时，托管设置批准提示显示一般警告而不是遥测措辞
  • 修复了 tmux/iTerm2 窗格中的代理团队队友在确认关闭请求后有时保持打开状态的问题
  • 修复了无密钥控制台登录（“使用您的控制台帐户登录”）不应用组织的服务器管理设置，以及 /status 不显示该登录的组织的问题
  • 改进的渲染性能：在长时间对话中每次重新渲染工作更少，流媒体不再随着回复的增长而减慢，后台代理更新不再重新渲染整个屏幕
  • 通过减少每次击键的渲染工作来提高提示输入响应能力
  • 改进的策略帮助程序诊断 - 刷新失败现在显示在 /status、decli 中，托管设置对话框会打印 Claude Code 退出的原因，并且帮助程序超时会报告为超时
  • 改进了 /code-review --comment，以通过 glab mr note 发布有关 GitLab 合并请求的结果，而不是将目标报告为不受支持
  • 改进的通知：在另一个对话框下排队的 MCP 启发或权限请求现在以与可见请求相同的延迟发送其空闲桌面通知
  • 改进了详细/转录输出：一起到达的异步钩子完成通知现在显示在一行上，而不是每个钩子一行
  • 改进了 claude self-hosted-runner --configure-git 以启用 git 推送协商，因此从过时克隆第一次推送新分支时仅上传新提交而不是整个树
  • 改进了向 SDK 主机的活动报告，同时响应通过网关保持活动保持打开状态，因此在提高的 CLAUDE_STREAM_IDLE_TIMEOUT_MS 下的长时间等待不会被误认为是挂起的会话
  • 改进了 MCP 连接和 OAuth 调试/错误日志，以便编辑服务器 URL 或请求标头中携带的凭据
  • 改进了 /fork，以将原始对话的提示缓存保留在新的后台会话中：其工作树简报现在以消息形式到达，而不是系统提示更改
  • 改进了表情符号自动完成功能，以接受剩余的 GitHub/Slack 短代码别名（:satisfied:、:telephone:、:collision:，…）
  • 更改了 --effort，以仅解除新模型在该会话中的默认努力保持，而不是永久解除；现在，在 claude.ai 上为远程控制会话选择的一项工作在暂停期间适用
  • 更改了 MDM 中的 policyHelper 或 managed-settings.json 在启动时被缓存的服务器管理设置隐藏，以便在获取报告它们已删除后立即运行（或退出），而不是在下次启动时运行（或退出）
  • 更改了 managedSourcesBehavior: "merge"，以从设置它们的最高托管源中获取整个 sandbox.credentials.awsPairs 和 sandbox.ripgrep，而不是组合源的值
  • 更改了网关模型发现 (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1)，即使设置了 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 也可以运行，因为它只查询您的网关
  • 更改了 claude --resume <session-id> --bg，以便在没有任何内容运行时使用自己的 ID 继续该会话，而不是默默地启动副本；现已公布副本
  • 将 /btw 历史浏览从 ←/→ 更改为 Shift+←/Shift+→（或 [/]），逐步浏览您最近的附带问题并返回实时答案
  • 将.claude/settings.json或.claude/settings.local.json中的defaultMode: "bypassPermissions"更改为忽略，如"auto"；在用户或托管设置中进行设置，或通过 --permission-mode
  • 更改了 Claude 应用程序网关会话中的 fable 和 best，以暂时继续解析《神鬼寓言 5》，因为尚未为《神鬼寓言》5.1 配置的网关会拒绝它；在/model中选择《神鬼寓言》5.1来使用
  • 更改了 --add-dir、/add-dir 和 additionalDirectories，以在接触网络路径（UNC 共享、/net/<host> 自动挂载）之前显示一条消息来拒绝它们；在 Windows 上使用映射的驱动器号
  • 更改了 Claude 应用程序网关登录和令牌刷新请求，以验证网关的固定 TLS 证书，就像托管设置获取已经做的那样
  • 更改了 Cowork 和 claude.ai 云会话：读取不属于您的工件现在总是先询问您，即使在自动模式下也是如此
