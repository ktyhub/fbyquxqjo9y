claude-code v2.1.267

修订 发布时间2026年9月9日 来源anthropics/claude-code 英文原文

claude-code v2.1.267

变更流程图

亮点

  • 新的努力程度与系统提示控制 — maxEffortLevel（顶层或 modelSettings 下按模型设置）可为包括 Bedrock、Vertex 和 Foundry 在内的所有 provider 设置努力程度上限，同时仍允许用户选择更低级别；--system-prompt-snapshot off 让每次请求重新渲染系统提示而非复用已记录的快照（便于迭代提示文本）。无需迁移；如果你希望跨 provider 设置硬性努力上限或正在调校提示，这项功能很有用。
  • 安全：托管设置改为”失败即关闭” + 路径包含性修复 — 当无法读取时，托管的 allowedHttpHookUrls、httpHookAllowedEnvVars 和 allowedChannelPlugins 现在会拒绝一切而非放行一切；此外，marketplace 条目路径中包含反斜杠时，可能在 macOS/Linux 上绕过对已获取 marketplace 的路径包含性检查。请将”失败即关闭”视为行为变更：依赖这些托管设置的组织应在升级前确认其能被正确解析，因为不可读的值现在会静默阻止 hook/渠道，而不是放行。
  • 会话恢复与提示缓存可靠性（升级的主要理由） — 大量修复解决了恢复会话丢失扩展思考、并行工具调用及其 hook 输出（包括超过 5 MB 的记录）、重写 MCP 工具声明/定义、以及在 /model 切换、-p --resume、会话中途的 MCP/插件工具、--system-prompt/--append-system-prompt 会话和会话与恢复之间 claude.ai 连接器变化时破坏缓存的问题；--resume 的首次渲染在 Bash 密集型会话中也更快。对依赖恢复、MCP 连接器或扩展思考的用户非常值得。
  • 网关与自托管 runner 行为变更 — 网关 forward_user_identity 上游现在将 429 原样返回给开发者，而不是故障转移到下一个上游，刻意保留每用户限额；自托管 runner 现在在注册时上报 --use-anthropic-git-proxy，并对仍通过旧代理克隆的会话逐会话警告。如果你运营网关或自托管 runner，请检查此项，因为故障转移和代理行为发生了变化。
  • 广泛的平台打磨——不受影响可跳过 — VS Code 修复（循环记录导致 100% CPU、WSL2/WSLg 截图粘贴、diff 块忽略配色主题、CRLF 编辑失败、带空格的 @ 提及、Remote-SSH 会话、失控的 ripgrep），web 修复（GitHub Enterprise token 刷新、没有 Claude GitHub App 时的 gh/API 调用），以及移动端 /context、tmux/ssh 密钥处理、artifact 发布错误/重试和若干 Claude Tag 管理修复。这是真正的维护版本，不是重新打标签或仅元数据构建——遇到上述问题的用户应升级，否则无紧迫性，除上述托管设置和网关注意事项外无需迁移。

发生了什么变化

  • Added maxEffortLevel setting (top-level or per model under modelSettings): caps the effort level on every provider, including Bedrock, Vertex and Foundry;用户仍然可以选择较低的级别
  • 添加了 --system-prompt-snapshot off 以在每次请求时呈现新鲜的系统提示，而不是重用对话的录制提示（用于迭代提示文本）
  • Fixed Cowork scheduled tasks in the cloud failing at startup for organizations whose managed settings require sandboxing
  • Fixed /context and other local command output rendering blank on mobile clients
  • Fixed shift+enter and option+backspace not working after reconnecting to a tmux or ssh session inside an agent view
  • Fixed the dim last-prompt header not appearing at the top of the conversation when scrolling up in fullscreen mode
  • Fixed Workflow agent() calls with large output schemas being refused in auto mode instead of being checked by the safety classifier
  • 修复了包含反斜杠的市场入口路径可能绕过 macOS 和 Linux 上获取的市场的遏制检查的情况
  • 修复了主机应用程序（例如 Claude Desktop）下过期的 AWS 或 Google Cloud 凭证在出现重新身份验证错误之前重试十次并显示通用“请求失败”的问题
  • 修复了在 /compact 或通过 -p --resume 运行另一个斜杠命令后恢复会话的问题：一个虚假的“从您离开的地方继续”。不再插入转弯
  • 修复了恢复大型会话（超过 5 MB 的脚本）：并行工具调用及其挂钩输出不再从重新加载的对话中删除
  • Fixed managed allowedHttpHookUrls, httpHookAllowedEnvVars and allowedChannelPlugins to admit nothing, not everything, when unreadable
  • Fixed /login on machines whose managed settings require Claude apps gateway sign-in: Esc now closes the dialog instead of doing nothing
  • 修复了工件发布因上传过程中连接断开而被切断的问题：现在，当克劳德代码可以告诉上传从未完成时，它们会重试一次，而不是报告未知的结果
  • 修复了自定义命令、技能和子代理上的 effort: frontmatter 在默认工作仍然固定的模型上被忽略的问题（Opus 4.7、Opus 4.8、Fable 5）
  • Fixed artifact publish failing with an unhelpful error when the page file isn’t valid UTF-8 or contains a replacement character (U+FFFD);错误现在指定了要修复的行和列
  • Fixed claude agents @ directory menu not listing repositories created after the session started
  • Fixed Remote Control clients that join a Claude Desktop or VS Code session showing a stale permission mode until it was changed again
  • Fixed claude remote-control exiting and dropping every attached session when its server credential expires (about 30 days after start);主机现在重新注册并继续
  • 修复了当不同型号或模式的请求报告不同的限制窗口时，使用限制警告在会话期间闪烁的问题
  • Fixed earlier reasoning being dropped when an MCP server re-sends, or a built-in tool re-renders, a tool the model already loaded
  • 修复了一个在对话中消失的工具，从断开连接的 MCP 服务器或升级中消失，重写工具列表并放弃之前的想法
  • 修复了从会话中分叉的后台工作人员将 EnterWorktree 添加到会话中的会话工具块，这破坏了提示缓存重用
  • 修复了会话中 MCP 和插件工具被添加到没有 ToolSearch 的会话中的工具列表中的问题，这会破坏提示缓存的重用；支持的模型现在将它们作为延迟定义接收
  • 修复了使用 /model 重新发送每个工具定义的切换模型（提示缓存未命中）；提交和 PR 归属文本现在作为对话注释到达，更新模型更改
  • 修复了当 MCP 连接器在与之前不同的时刻重新连接时恢复的会话重写内联工具集的问题
  • 修复了恢复会话重新渲染工具描述，而不是在第一回合运行工具时重播记录的描述
  • 修复了当 claude.ai 连接器的工具在会话和恢复之间发生变化时提示缓存未命中并放弃扩展思考的问题
  • 修复了恢复会话在连接器重新连接之前重写早期 MCP 工具公告（并放弃扩展思考）的问题
  • 修复了交互恢复打印模式 (-p) 对话时的提示缓存中断：系统提示前缀不再更改
  • 改进了 /diff 面板：在稳定之前不再闪烁“0 个文件已更改”和旋转器，并且其空状态位于面板中央
  • 改进了 Bash 工具的描述指南，以便 Claude 用简单的语言描述命令的作用，而不是回显命令
  • 改进了沙箱指导，因此当 clipboard 命令（例如 pbcopy）在沙箱内失败时，克劳德建议使用 /copy
  • 改进了具有许多 Bash 工具调用的会话的 --resume 首次渲染时间
  • 改进的提示输入响应能力：击键不再偶尔在旋转器或流重绘后面等待一帧
  • 改进了提示缓存稳定性：使用 --system-prompt 或 --append-system-prompt 启动的子代理和会话现在记录一次系统提示和工具定义，而不是重新呈现它们
  • 改进了 Artifact 工具发布错误：当发布被拒绝时，消息现在会说明原因以及如何处理
  • 自托管运行器：将 --use-anthropic-git-proxy 更改为在注册时向服务器报告，并为仍通过旧版 git 代理克隆的每个会话打印警告
  • 网关：更改了 forward_user_identity 上游，将 429 按原样返回给电子邮件被转发的开发人员，而不是故障转移到下一个上游，因此代理的每用户限制保持不变
  • [VSCode] 修复了在分叉、编辑较早消息或在保存的记录包含 cyclic 父链接的对话中倒带时，扩展主机挂在 100% CPU 的问题
  • [VSCode] 修复了在 WSL2/WSLg 上粘贴屏幕截图将原始图像字节插入聊天输入的问题；当 clipboard 提供图像时，现在会附加图像，否则粘贴将被忽略
  • [VSCode] 修复了聊天差异块始终使用深色编辑器主题渲染的问题；它们现在遵循活动的 VS Code 颜色主题，包括高对比度
  • [VSCode] 修复了在消息输入中键入时以错误顺序混合从右到左和英文文本渲染的问题
  • [VSCode] 修复了在 Windows (CRLF) 行结尾的文件的 diff 视图中接受编辑失败并显示“在文件中找不到字符串”的问题
  • [VSCode] 修复了 @-mentions 删除路径包含空格的文件
  • [VSCode] 修复了当工作区文件夹仅存在于远程主机上时，会话列表视图无法在通过远程 SSH 连接的窗口中加载的问题
  • [VSCode] 修复了在大型或符号链接较多的工作区中查看文件时失控的 ripgrep 进程
  • [网络上的克劳德代码] 修复了 GitHub Enterprise Server 会话，一旦其令牌过期，就会显示您的 GitHub 帐户已断开连接； PR 和问题操作现在会自动刷新
  • [网络上的克劳德代码] 修复了在没有克劳德 GitHub 应用程序的组织中 gh 和 GitHub API 呼叫失败的问题；他们现在使用您连接的 GitHub 帐户，并在没有连接时这么说
  • [Claude Tag] 在 Claude Tag 管理设置中的预设连接表单中添加了“使用自定义连接器”链接，以便您无需重新开始即可切换到自定义连接
  • [Claude Tag] 修复了当组织用完使用积分时克劳德回复“API 拒绝请求无效”的问题；现在的回复是这样说的，并解释了如何添加更多内容
  • [Claude Tag] 修复了编辑或删除 Claude 在频道顶层发布的消息的线程请求，得到了更正的答复，而不是到达发布该消息的会话
  • [Claude Tag] 修复了管理设置 > 审查请求失败并显示“授权失败”或将请求的访问包显示为已删除的工具访问请求的 连接
