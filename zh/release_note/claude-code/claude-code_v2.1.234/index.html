claude-code v2.1.234

修订 发布时间2026年8月17日 来源anthropics/claude-code 英文原文

变更架构图

亮点

  • 安全加固（建议升级） — 拒绝 Windows NT 命名空间（\??\）路径出现在远程读取、会话恢复、CLAUDE.md include、工作流脚本和上传中，堵住了审批前 NTLM 凭证泄露的残余途径。MCP 诊断不再打印已解析的秘密，strictKnownMarketplaces 会校验 host 实际会连接的 git，转发的权限预览会执行信任/能力门控并采用更强的凭证遮蔽。未列出迁移步骤。

  • 权限与重启正确性 — 修复了后台子代理提示词中会话级允许/拒绝规则丢失，以及压缩后反复出现沙箱网络拒绝的问题。/permissions 和 /add-dir <path> 现在可在回合中途使用，规则变更对当前回合生效。行为变更： 全屏渲染器和 /tui 重启不再静默丢弃限制；/tui 会拒绝无法保留限制的切换。在全屏模式下，Esc 不再清除鼠标选择——需要时绑定 selection:clear。

  • Remote Control 与跨会话消息 — 桌面/VS Code 托管的会话现在能正确上传文件，Claude Desktop 的会话间消息不再被静默丢弃，更换已登录的 claude.ai 账号或组织会及时停止会话，而不是几小时后才失败。远程客户端会收到权限模式和 effort 更新，claude.ai/code 还会收到模型更新。当账号的会话列表未被完整检查时，SendMessage/ListAgents 现在会发出警告。Remote Control 和多会话用户应升级。

  • 可观的上下文节省与健壮性 — 内置 claude-api 技能现在按需加载参考文档，其上下文开销从约 200k+ 令牌降到约 25k。本版本还修复了畸形非流式网关响应导致的崩溃、严重的 Unicode markdown 性能下降，以及若干队列、对话框和渲染缺陷。即使不用新 UI 功能，大上下文和第三方网关用户也能受益。

  • 升级前需复核的默认值 — 当 claude.ai 用量限额重置时，会话现在会自动继续；可通过 /config → “在用量限额处自动继续”退出。移除的设置： “默认队友模型”；队友现在继承主代理的模型，除非派生时指定，因此若依赖旧默认值请在派生时显式指定。另外新增可选 CLAUDE_CODE_PROJECT_DIR_NAME、selection:clear、GitLab MR 徽章，以及 30 分钟以上的 /goal 检查点（CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 可退出）。未列出正式的破坏性 API 变更；不受影响的用户可跳过，但重视安全与可靠性的用户应升级。

发生了什么变化

  • 添加了可选的 CLAUDE_CODE_PROJECT_DIR_NAME 环境变量：为每个会话提供自己的配置目录的主机可以为每个项目的脚本目录选择一个短名称
  • 添加了selection:clear按键绑定操作，因此可以绑定一个按键来清除应用内的文本选择；也适用于代理视图
  • 在页脚和状态行中添加了 GitLab 合并请求徽章：带有 GitLab 遥控器的存储库和经过身份验证的 glab CLI 显示 MR !N 以及草稿/待定/绿色状态
  • 当 claude.ai 使用限制重置时，Claude Code 现在会自动继续您的会话；在 /config 中将其关闭（“在使用限制时自动继续”）
  • 克劳德现在被告知仅使用您的帐户电子邮件来识别您的身份，除非您要求，否则不要将其发送到不相关的服务
  • 安全性：远程文件读取、会话恢复、CLAUDE.md 包含、工作流脚本和文件上传现在拒绝 Windows NT 命名空间 (\??\) 路径，针对 NTLM 凭据泄漏向量强化剩余的预批准文件访问
  • 修复了在很长的会话中自动模式在会话被压缩后反复重新检查和拒绝沙盒命令的网络访问
  • 修复了在回答后台子代理工具权限提示时丢弃会话范围的权限答案（包括拒绝）的问题
  • 修复了当非流式后备路径（通常通过第三方网关）上的 API 响应包含缺少其思考字段的思维块或缺少其文本字段的文本块时发生的崩溃
  • 修复了某些包含异常 Unicode 序列的消息的 Markdown 渲染变得极其缓慢的问题
  • 修复了当会话名称达到 200 个字符上限或表情符号较多时，SendMessage 拒绝从 ListAgents 复制的收件人的问题
  • 修复了存储库检测错误读取具有异常用户信息的 git 远程主机的问题，为错误的主机生成链接和特定于存储库的行为
  • 修复了 MCP 诊断打印已解析的机密：范围冲突警告现在显示配置的 ${VAR} 表单，连接失败详细信息仅显示服务器源
  • 修复了 strictKnownMarketplaces 允许名单接受 SCP 风格的 git 市场源，其主机与 git 实际连接的主机不同
  • 修复了模式文本（例如 /login OAuth URL）在全屏复制时丢失字符的问题
  • 修复了渲染 Markdown 中的 --- 水平线跑入其后的行
  • 修复了当待办事项/任务更新在它们之间交错时，连续的 shell 命令分成多个“Ran 1 shell command”行
  • 修复了 ! shell 命令运行时打开的 /permissions 等对话框在命令完成后被关闭的问题
  • 修复了按向上箭头编辑排队输入后，排队的 ! shell 命令以纯文本形式发送到模型的问题
  • 修复了排队消息在仍在排队时重新出现在提示历史记录中的问题，选择排队消息时按 Esc 键不再中断回合，并且 ! 模式在中途提交后不再保留
  • 修复了接受“尝试新的全屏渲染器？”的问题提示重新启动会话，无需其权限模式（例如 --dangerously-skip-permissions）、工具允许/拒绝规则、模型或工作量标志
  • 修复了 /tui 重新启动时丢弃启动 --allowed-tools/--disallowed-tools 规则的问题；它现在 declines 进行切换，原因是，当会话有限制时，重新启动无法继续
  • 修复了在存储库存在之前首次看到目录时 trust 提示忽略存储库范围警告的问题
  • 修复了在权限重新提示期间关闭 IDE diff 选项卡可能会使用之前的输入回答新提示的情况
  • 修正：在 Claude Code Desktop 或 VS Code 托管的远程控制会话期间发送给用户的文件现在上传，因此它们可以在手机和网络上打开，而不是显示空卡
  • 修正：在 /login 设置 CLAUDE_CODE_OAUTH_TOKEN 后，陈旧令牌提醒不再泄漏到克劳德的自动恢复回合中 - 现在它只对你显示
  • 修正：权限预览现在仅中继到入站 trust 门允许的通道服务器，并且尊重服务器的显式权限功能选择退出
  • 修复：中继权限预览上的凭据屏蔽无法再向审批者隐藏命令、路径或目的地；超大私钥块现在在全力编辑下进行编辑
  • 修正：屏蔽权限预览的提供者 API 令牌现在即使直接跟有 shell 分隔符也会屏蔽
  • 修复了当跨会话消息读取为禁用时，Claude Desktop 会话间消息被收件人会话静默丢弃的问题，这使得发件人的查询“思考”了很多分钟
  • 远程控制：将此计算机登录到不同的 claude.ai 帐户或组织现在会在几秒钟内停止正在运行的会话并说明原因，而不是在 404 小时后发出误导性的 HTTP 404
  • 从 Claude Code Desktop 或 VS Code 启动的远程控制会话现在可以在会话的权限模式（以及模型上的 claude.ai/code）发生变化时保持电话和 claude.ai/code 的更新
  • 远程控制：在手机或 claude.ai/code 上进行的工作选择现在适用于终端和桌面/VS Code 托管的会话，并且会话将其工作级别发布到连接的 clients
  • SendMessage 和 ListAgents 现在会在您帐户的会话列表太长而无法完全检查时发出提示，而不是将未见的会话视为不存在
  • 当 claude.ai 登录优先时，过期的 Anthropic 个人资料凭据现在会将您指向 /login
  • 改进了文字记录：您自己的提示现在以与回复相同的方式呈现 Markdown（突出显示的代码块、内联代码、列表）
  • 改进了“API 返回空或格式错误的响应”错误，以说明返回的内容（内容类型、正文类型、大小、请求 ID）以及原始流请求失败的原因
  • 改进了自动生成的会话标题，使其读取为简短的特定名称（例如“登录按钮错误”），而不是重申您的请求的句子（例如“修复移动设备上的登录按钮”）
  • 通过按需加载参考文档，将加载内置 claude-api 技能的上下文成本从约 200k+ 令牌减少到约 25k
  • /permissions 现在可以在克劳德工作时打开 - 规则更改适用于当前回合的其余部分
  • 现在可以在克劳德工作时使用 /add-dir <path>； /add-dir、/autocompact、/theme、/help、/config 和 /advisor 对话框在全屏 TUI 中打开
  • /goal 现在会在回合因不可恢复的错误（例如撤销授权、信用余额耗尽或上下文溢出）而死亡时通过通知清除自身，而不是保持武装状态
  • /goal：当后台任务让目标等待 30 分钟以上时，克劳德现在会检查它们，而不是无限期地等待（将 CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 设置为选择退出）
  • claude setup-token 现在拒绝意外的额外参数，而不是默默地忽略它们
  • 更改了全屏模式下的 Esc，不再清除鼠标文本选择：它会照常中断或取消，并且选择保持突出显示
  • 删除了自动模式在每个代理工具调用下显示的冗余“自动模式分类器允许”行
  • 删除了/config的“默认队友模型”设置；特工团队的队友现在使用领导者的模型，除非生成者指定了一个
  • 调暗运行工具标题上的经过时间计数器，使其不再与粗体计数竞争
  • 轮次之间传递的后台任务通知现在发送到 <system-reminder> 标签内的模型，与轮次中传递相匹配
  • Mantle：当已经选择主循环模型时，在启动时跳过管理引脚可用性探测
  • Windows：当 ~/.claude.json 为只读时，启动不再因重复重命名重试而停止
