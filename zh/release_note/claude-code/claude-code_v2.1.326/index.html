claude-code v2.1.326

修订 发布时间2026年11月16日 来源anthropics/claude-code 英文原文

变更架构图

亮点

  • Code Mode 支持 agent 团队 — Code Mode 现在可与 agent 团队一起启用；如果此前已启用，团队会话现在会自动以它启动。修复还恢复了通过 $.tool.call 和 $.tool.check 的工具访问、内联 ! 命令批准，以及后台子 agent 的 skill 预加载。如果你使用团队或 Code Mode，请升级，因为此版本将该功能与大量正确性修复结合在一起。
  • 设置与管理员策略——迁移检查 — 未列出明确的破坏性 API 变更，但有两项行为变更需注意：嵌套超过 64 层的设置现在会被丢弃并发出警告，托管子 agent 模型设置会覆盖 Claude Desktop Code 选项卡中的本地选择（除非这些设置也选择了 provider 或网关）。新警告会识别无效的工具规则、格式错误的插件字段、不可写的设置文件以及被管理员禁用的功能。管理员和设置嵌套很深的用户应检查配置。
  • 数据完整性与权限保护 — 此版本修复了若干工作或状态可能丢失/被误报的途径：在受影响的 Linux 云/Remote Control 会话中，重发的文件不再静默覆盖 Claude 的编辑，恢复的会话保留更多历史，当恢复不完整时 /rewind 报告”Code changes unknown”，且 stdout 被重定向时 claude purge 提示可见。还纠正了错误的 Edit 拒绝规则失败、误导性的”Dangerous rm operation”警告，以及命令被误分类为读取/搜索。这些广泛的安全修复使升级即便在你不使用新功能时也值得。
  • MCP 可靠性与 schema — 修复涵盖跨调用结果污染、精确名称工具查找加载其他服务器的工具、重复服务器名称冲突、headersHelper 认证失败、重连取消和输入表单行为。根级 anyOf/oneOf schema 现在保留所有参数形式；因此像 42 这样的文本在另一个 schema 分支期望数字时可能以数字形式到达。精确名称工具查找可能需要再次批准。MCP 重度用户应升级并测试依赖参数类型的集成。
  • 后台、远程、认证与可观测性 — 后台会话现在在缺少所需网关凭据时会在模型请求前停止，进程复用不再有误杀无关进程的风险，Remote Control/云会话改进了 Stop 行为、上传重试和 artifact 处理。登录/退出和隐私设置修复减少了陈旧密钥和错误账户的问题。OTEL_RESOURCE_INCLUDE_HOST 将 host.name 和 host.id 添加到 OpenTelemetry 属性，但默认关闭。如果你依赖远程执行、自定义认证或隐私控制，请升级；不受这些流程影响的用户可安全跳过此补丁。

发生了什么变化

  • 添加了在启用代理团队时打开代码模式的支持；如果您已经打开它，与团队的会话现在会在代码模式下开始
  • 添加了当 --allowedTools、--disallowedTools 或 --tools 值具有看起来不像完整规则的条目时的启动警告
  • 添加了一条消息，解释当管理员在会话期间添加 managed-mcp.json 时，为什么 MCP 服务器停止加载
  • 在 /status 中添加了一行，说明您的提供程序或环境变量（例如 DISABLE_TELEMETRY）何时关闭功能
  • 当忽略格式错误的 plugin.json 字段（例如 author 或 homepage）时，在 /plugin 和 claude plugin list 中添加了注释
  • 添加了 Ctrl+O 显示隐藏的启动通知
  • 在空提示中添加了提示，说明请求失败后该怎么做
  • 在子代理视图中添加了 esc to stop 页脚提示，Esc 将停止它
  • 添加了 OTEL_RESOURCE_INCLUDE_HOST 以将 host.name 和 host.id 包含在 OpenTelemetry 资源属性中（默认情况下关闭）
  • 在 mod 的 Box 上添加了 overflowX="scroll"，在其 Text 上添加了 maxLines 和 wrap="clip"
  • 修复了当 Edit 拒绝规则仅覆盖其源时文件的 cp 被拒绝的问题
  • 修复了删除或覆盖文件（find -delete、cat a > b、sort -o）的 Bash 命令在记录中总结为搜索或读取
  • 修正了一些没有 rm 的命令的 Bash 权限提示中的误导性“危险 rm 操作”警告，导致 Claude Code 无法可靠地读取
  • 修复了后台会话在崩溃后、从另一个文件夹重新打开后或后台服务缺少时丢失 shell 导出的 LLM 网关的问题：它们现在在任何模型请求之前停止
  • 修复了当列表中的进程号已被其他用户的进程重用时后台服务会结束您自己的进程（例如 SSH 登录）的问题
  • 修复了在 /permissions 或主对话工具提示以及 /add-dir 文件夹中添加的规则，当设置文件无法写入时看起来已保存；终端现在发出警告并为其命名
  • 修复了失败的 MCP headersHelper，或者未在 untrusted 文件夹中运行的 MCP headersHelper，使得其他会话在没有该服务器的情况下启动，对于大多数没有存储 OAuth 刷新令牌的服务器
  • 修复了某些键名称的托管设置，阻止克劳德代码启动或影响其他托管文件
  • 修复了设置文件，其值嵌套了数千层，导致克劳德代码崩溃或仅在某些时候应用；现在，超过 64 个级别的值将被丢弃并发出警告
  • 修复了保存的设置文件在会话中出现错误而被静默跳过的问题；现在会出现警告命名文件
  • 修复了托管设置中设置的子代理模型不适用于 Claude Desktop 的“代码”选项卡；它现在会覆盖您自己的设置，就像在终端中一样，除非这些设置也选择了提供商或网关
  • 修复了当通过 /net 的符号链接到达主目录或配置目录且沙箱设置拒绝读取它时，沙箱命令无法在 Linux 上启动的问题

  • 修复了在已 trusted 父文件夹下显示的文件夹 trust 提示中回答“是”的问题
  • 修复了安装结束时的额外 Enter 接受提议，使自动模式成为默认模式

  • 修正了在选项卡隐藏后发送给克劳德的权限提示上键入的注释
  • 修复了托管设置中的 PreToolUse 挂钩，当它们拒绝直接工具调用时，不会留下 OpenTelemetry tool_decision 事件或 permission_denials 条目
  • 修复了在 /sandbox 上输入的字母或在 /permissions 中移动选择的删除问题
