claude-code v2.1.277

修订 发布时间2026年9月18日 来源anthropics/claude-code 英文原文

变更流程图

亮点

  • Agent 指令与网关控制 — 没有 CLAUDE.md 的项目现在回退到 AGENTS.md，可在 /config 的 Project instructions 下配置；Bedrock、Vertex 或 Foundry 上尚不可用。网关运营者可发送静态上游 headers:，并设置 CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1，使请求以主机名而非本地解析的目标地址到达前向代理。
  • 破坏性变更：已弃用的 TaskOutput 被移除 — 后台任务输出现在必须用 Read 读取。仍在调用 TaskOutput，或依赖 taskOutputMaxChars、TASK_MAX_OUTPUT_LENGTH 的自动化必须更新，因为这些设置不再生效。
  • 值得升级的可靠性与正确性修复 — 本版本解决 headless/SDK 挂起和错误的用量统计、消息丢失、本地配置格式错误导致崩溃、不安全的复合命令沙箱豁免、插件更新损坏、Unicode 编辑/路径 bug，以及若干影响缓存的恢复会话问题。沙箱变更是行为性的：复合 Bash 命令的每个部分都必须匹配 sandbox.excludedCommands，而不是一个部分匹配就豁免整条命令。
  • 按界面划分的改进 — VS Code 用户新增后台任务控制、/copy、在计划限额不适用处的成本/用量报告，并修复持续快速模式、努力程度设置和斜杠命令对话框；Web 版 Claude Code 用户获得修订的环境共享与管理流程；/ultrareview 现在拒绝没有 base 分支或共享历史记录的非交互运行，并清楚描述空审查的情形。

发生了什么变化

  • 添加了 AGENTS.md 支持：在没有 CLAUDE.md 的项目中，Claude Code 改为读取 AGENTS.md；在 /config 中的“项目说明”下更改它（尚未在 Bedrock、Vertex 或 Foundry 上）
  • 为 Claude 应用程序网关添加了 CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1，其唯一出口是转发代理：每个出站请求都将主机名交给代理，而不是在本地解析它
  • 在 Claude 应用程序网关上游添加了可选的 headers: 映射，以将静态标头发送到您在提供商面前运行的代理
  • 添加了一行，说明当 /tasks 等面板打开时，后台任务的更新正在等待完成
  • 修复了 claude -p 和代理 SDK 会话在内部错误后可能挂起且没有结果的问题；他们现在报告错误并以代码 1 退出
  • 修复了当较早的助理在其他内容旁边持有空文本块时（包括在 --resume 之后），每个请求都会失败的问题，并显示“文本内容块必须非空”
  • 修复了当较旧的 Claude Code 版本（例如 IDE 扩展捆绑的 CLI）与当前计算机在同一台计算机上运行时意外注销的问题
  • 修复了当 ~/.claude.json 持有格式错误的 customApiKeyResponses 值时，交互式启动挂起或为 ANTHROPIC_API_KEY 用户显示错误的问题
  • 修正了更新检查每 30 分钟出错一次，以及在设置最小或最大版本时如果代理返回无效版本则 claude update 挂起的问题；现在会忽略格式错误的 minimumVersion
  • 修复了 winget 或 apk 管理的安装上的 claude update 在版本查找失败时报告“最新”的问题
  • 修复了在重新安装会话或其他程序正在使用的插件版本时，claude plugin install 有时会失败并破坏已安装的副本；未更改的副本现在被保留
  • 修复了当由于系统进程、内存或文件句柄不足而无法启动搜索时 Grep 和 Glob 报告没有匹配项的问题；他们现在返回一个错误，这样说
  • 修复了当目标路径是现有目录时，写入工具以 declined 权限静默结束回合；它现在报告一个明显的错误
  • 修复了编辑工具将转义反斜杠后跟 uXXXX 文本视为 \uXXXX 转义，这可能会使非 ASCII 字符的编辑重写转义反斜杠序列
  • 修复了当包含非 ASCII 文本的非常大的编辑与文件不匹配时，编辑工具报告“无效的正则表达式：正则表达式太大”而不是“在文件中找不到字符串”
  • 修复了当工具调用的文件路径包含写为转义序列的 \u0000 时，回合以“路径包含空字节”提前结束的问题；转义控制字符现在保留为文字文本
  • 修复了当插件的 LSP 服务器退出或关闭其标准输入时后台会话 (claude --bg) 退出的问题
  • 修复了打开 /mcp 或 /plugin manage 时 ~/.claude.json 中的 claudeAiMcpEverConnected 值格式错误时发生的崩溃（“类型错误”）
  • 修复了当 ~/.claude.json 持有格式错误的 theme 值时启动时发生的崩溃
  • 修复了提示包含包含终端颜色代码的文本时的崩溃（“不可恢复的界面错误”），例如从历史记录中调用的提示或从外部编辑器加载的文本
  • 修复了恢复会话时发生的崩溃，该会话的保存历史记录包含存储为纯字符串的助理消息
  • 修复了当第一个微调器出现时，缓慢或负载过重的计算机上的会话有时会退出并显示“无法恢复的界面错误后克劳德代码退出”的问题
  • 修复了一种罕见的情况，即在内部渲染错误后屏幕可能会在会话的其余部分停止更新
  • 修复了 Windows 上的一种罕见情况，即克劳德回复后，回合可能会因“内存不足”等错误而停止，因此回复的工具调用永远不会运行
  • 修复了当 SessionStart 挂钩打印输出时，/clear（重新启动、--continue、--resume）丢失第一条消息的部分后会话继续进行，导致完全提示缓存丢失的问题
  • 修复了来自其他代理（例如子代理的 SendMessage）的中途到达的消息显示在“Ran N shell 命令”行下方，而不是它们到达的位置
  • 修复了在全屏 /resume 选择器和覆盖提示区域的其他面板中拖动选择文本后不出现“已复制”通知的问题
  • 修复了启用沙箱时在沙箱外部运行的 Bash 命令中的 $TMPDIR 扩展为空的问题
  • 修复了 Cowork 云会话中的 WebFetch 和 WebSearch 不告诉 Claude 请求被拒绝的原因，例如用完的获取预算或管理策略
  • 修复了设置代理时克劳德应用程序网关的遥测中继忽略 NO_PROXY 中列出的收集器主机名或域的问题
  • 修复了一个格式错误的 strictKnownMarketplaces 或 blockedMarketplaces 条目会默默地禁用整个企业市场策略
  • 修复了自动更新失败导致 ~/.cache/claude/staging 中大量分阶段下载的问题

  • 修复了当技能或旧命令被命名为内置对象属性（例如 constructor 或 toString）时，/plugin → 已安装和 /skills 崩溃的问题
  • 修复了当多选中的每次安装失败时 /plugin 关闭时没有消息的问题

  • 修复了插件重新加载预览，使插件存档的每个预览副本都解压直到退出，并覆盖缓存的 --plugin-url 存档，重新加载在下载失败时回退到该位置
