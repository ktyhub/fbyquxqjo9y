claude-code v2.1.330

修订 发布时间2026年11月20日 来源anthropics/claude-code 英文原文

变更流程图

亮点

  • 企业登录与认证 — 现在支持在 Anthropic 企业管理控制台中管理的组织：claude auth login 之后，Claude Code 会应用组织设置并通过其云提供商或网关路由。/login/claude auth login/claude setup-token 的链接现在短得多，若短链接出错或脚本解析它，可用 CLAUDE_CODE_FULL_SIGN_IN_LINK=1 打印完整 URL。企业/团队管理员以及编写认证脚本的用户应为这项升级。

  • 自托管 runner：新控制项、指标与强制的运维变更 — 新增 --start-dir / SELF_HOSTED_RUNNER_START_DIR（工作在仓库子目录中开始；设置/钩子仍照常加载）和两个新的 /metrics 序列：claude_code_self_hosted_runner_order_to_registered_seconds 与 claude_code_self_hosted_runner_order_to_first_session_seconds。若干修复需要运维人员行动：403（如 IP 白名单）现在以服务器原因开头，而不是”错误的 secret 或 token”——请更新匹配旧措辞的日志告警；Linux 上的 pkill -f 需要 pkill --ignore-ancestors 以免杀掉 runner；磁盘满的 runner 现在会等待空间，一分钟后退出 1（除非由工作单派生）；warn 模式现在每条会话最多报告 50 项发现，而不是遇到第一项就停止。runner 运维应升级并复核这些。

  • 升级前需知的行为变更 — 磁盘满时 claude -p 现在会打印错误并退出 1，而不是静默退出 0（完整 NFS 导出仍可能未被察觉）；周期性任务和 /loop 现在最多运行 30 天而不是 7 天——但本版本之前创建的任务仍在 7 天结束；/mcp 把服务器重新分组为”插件 MCP”和”其他 MCP”（--mcp-config 和内建）；2.1.329 移除 max_tokens 自动重试的改动已回滚；SessionStart 钩子环境变量现在能在 claude -p --continue 中保留；Google Cloud Agent Platform 上的 fastMode 在模型来自 ANTHROPIC_MODEL 或设置文件时也能正确计费。脚本作者以及依赖 7 天任务上限或日志/监控输出的人应考虑到这些。

  • easel 内置图表 mod — 这是一个内置 mod，在被要求时以及在 MCP 指标结果下方绘制图表，Pro/Max 可用，Team/Enterprise 在 macOS 和 Linux 上可用的地方也可用；可在 /config 中关闭自动图表。它还修复了图表工具在 Code Mode 中失败，以及启动时的”MCP server blocked by enterprise policy: easel”警告——注意如果 MCP 允许/拒绝列表把 easel 排除在外，它仍会被阻止。如果你使用指标/图表或执行 MCP 策略，这项相关。

  • 可靠性与性能——强烈的升级信号 — 这是一个实实在在的修复版本，不是仅改元数据的重标签：它消除了压缩后、WebFetch 中以及 Windows 慢仓库/Git Bash 中的长达数分钟的冻结；修复并发/数据丢失问题（同时保存设置、并行 claude plugin/任务更新、ExitWorktree 删除另一会话的 worktree、/rewind 恢复过期文件、不完整的 ~/.claude.json 备份）；并稳定了 Code Mode、MCP/子代理和后台代理，同时加快文件 diff 和 Windows Grep/Glob。几乎所有人都应升级；唯一能合理跳过的是完全不走这些路径且对上述行为变更敏感的用户。

发生了什么变化

  • 添加了对 Anthropic 企业管理控制台中管理的组织的登录：在 claude auth login 之后，Claude Code 应用组织的设置并使用其云提供商或网关
  • 添加了画架，这是一个内置模块，可在询问时在 MCP 指标结果下绘制图表，适用于 macOS 和 Linux 上的 Pro、Max 以及可用的 Team 和 Enterprise；在 /config 中关闭自动图表
  • 添加了 CLAUDE_CODE_FULL_SIGN_IN_LINK=1 以打印完整的登录链接（如果短链接显示错误或脚本从中读取值）
  • 自托管运行器：添加了 --start-dir / SELF_HOSTED_RUNNER_START_DIR 以使 Claude 在存储库的文件夹中开始其工作，而设置和挂钩加载就像没有它一样
  • 当无法获取插件市场时，在云和自托管运行器会话中添加了一条通知，因为其存储库不是会话的存储库之一
  • 自托管运行器：添加了当 Anthropic 管理的 git 拒绝插件自己的存储库时的通知、命名插件以及执行操作
  • 将 commandPrinted 添加到 claude plugin install --json 结果中，当插件的安装命令写入 stderr 时为 true，当插件因错误退出、被终止或超时时为 commandFailed
  • 将 claude_code_self_hosted_runner_order_to_registered_seconds 添加到自托管运行器的 /metrics：在协调器生成的运行器上，从发出工作订单到接受注册的秒数
  • 将 claude_code_self_hosted_runner_order_to_first_session_seconds 添加到自托管跑步者的 /metrics：从工作订单到移交第一个会话的秒数（在开始会话的跑步者上）
  • 修正了克劳德代码在压缩很长的对话后冻结长达几分钟的问题
  • 修复了 WebFetch 在某些页面上冻结会话几分钟，并为其他一些页面返回空结果的问题
  • 修复了 ExitWorktree 和工作树退出对话框删除另一个正在运行的克劳德代码会话正在其中工作的工作树
  • 修复了当多个 Claude Code 进程同时保存用户设置更改时丢失的问题

  • Linux：修复了 Bash 命令等待几秒钟，并且在具有大型被忽略文件夹（例如 node_modules）的慢速存储库中，会话的其余部分不显示文件差异
