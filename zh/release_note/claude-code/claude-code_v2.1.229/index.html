claude-code v2.1.229

修订 发布时间2026年8月12日 来源anthropics/claude-code 英文原文

变更架构图

亮点

  • Remote Control 与自托管 runner — 这是成熟度提升最明显的部分：自托管 runner 会话现支持服务端提供的 hook（与托管环境行为一致），ListAgents 现在把断开的 Remote Control 会话标记为 offline、把云会话标记为 cloud，并记录 claude remote-control --continue 用于恢复最近的会话。实际的运维痛点也清除了：在笔记本终端输入斜杠命令后卡住的工作指示器、部署 managed-mcp.json 时自托管 runner 启动即退出（这些 MCP 服务器现在会被跳过并警告），以及 Git Credential Manager 挂起现在会快速失败。运营 runner 或云会话的用户强烈建议升级。
  • 破坏性变更与迁移 — 自托管 runner 在 Windows 上启动现在必须显式指定 --base-dir；Windows 上没有默认检出目录，因此必须更新 Windows runner 配置。升级前需检查两项行为变更：/commit-push-pr 不再自动批准危险的 git/gh 标志（--force、--amend、--no-verify 等），网络域名列表中含糊的拼写现在强制”失败即关闭”（IPv6 字面量现在加方括号，如 [::1]:443），由 /doctor 标记。对普通本地用户没有 API 层面的破坏性变更。
  • 流式传输与终端可靠性 — SSE 保活 ping 现在会在长时间思考停顿期间继续发送，防止 Vertex 和 Bedrock 上游的空闲超时断连。几项崩溃/数据丢失修复也很重要：长响应不再部分消失并重复打印，极窄终端中的 RangeError 崩溃（也可能破坏启动时的 claude --continue/--resume）已修复，SDK / --input-format stream-json 会话不再因纯空白消息报 400。仅消息本身就超过 32 MB 请求限制的对话现在会明确报错一次，而不是徒劳地重试压缩。流式输出很长或走网关的用户值得升级。
  • 插件 marketplace 与工作流成本 — 新增插件 marketplace 的 command 来源：本地命令（如 IDE）打印插件目录，该目录每次会话重新解析并立即应用，无需重启；mode: "link" 就地使用。一项修复移除了一次性 claude plugin 命令遗留的存活文件，该文件可能阻碍清理过时的插件版本。工作流扇出现在会错开同前缀的兄弟 agent，使后面的 agent 读取缓存的提示前缀而非重新付费（CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0 可禁用）。与插件作者和重度多 agent 工作流用户相关。
  • 谁应升级 / 谁可跳过 — 不是空操作或仅元数据版本，而是广泛的稳定性与功能更新。使用 Remote Control 或自托管 runner（Windows 迁移是必须的）、Vertex/Bedrock 网关、插件市场或多 agent 工作流的应升级。没有自定义网关、runner 和插件的普通单用户 macOS/Linux 用户可以跳过——其余部分（VSCode 会话组、可调整大小的 /btw 面板、内置反馈对话框、CLAUDE_CODE_ATTRIBUTION_HEADER auto 模式以及 MCP OAuth 127.0.0.1 重定向的边缘情况）都是增量改进。

发生了什么变化

  • 记录 claude remote-control --continue 用于恢复最近的远程控制会话
  • 添加了服务器提供的对自托管运行器会话的 Claude Code 挂钩支持，匹配托管环境行为
  • 在长时间思考暂停期间向网关流响应添加了 SSE keepalive ping，防止 Vertex 和 Bedrock 上游的空闲超时断开连接
  • 添加了插件市场 command 源：本地命令（例如 IDE）打印插件目录，每个会话都会重新解析并应用而无需重新启动； mode: "link"就地使用它
  • ListAgents 现在将断开连接的远程控制会话标记为 offline，并将您的云会话标记为 cloud
  • 修复了长响应在流式传输并在终端中打印两次时部分消失的问题
  • 修复了当工具调用具有非字符串 glob、file_path 或 command 值时错误屏幕崩溃（包括受影响会话的 --resume）
  • 修复了在非常狭窄的终端窗口中呈现进度条或降价表时出现的 RangeError 崩溃问题（也可能在启动时导致 claude --continue/--resume 崩溃）
  • 修复了当工具调用或消息通过扩展长度 (\\?\) 或 UNC 路径引用文件时 Windows 上的崩溃
  • 修复了通过 CLAUDE_CODE_ATTRIBUTION_HEADER（直接 Anthropic API 连接）禁用归因标头的用户每次工具调用时自动模式失败的问题
  • 修复了 /model 使用自定义 ANTHROPIC_BASE_URL 网关拒绝 claude.ai 订阅者的 Sonnet/Opus 1M 的问题
  • 通过在重定向 URI 中使用 127.0.0.1 而不是 localhost 修复了具有严格授权服务器的 MCP OAuth
  • 修复了在笔记本电脑终端中输入斜杠命令后，远程控制 clients 显示卡住的工作旋转器
  • 修复了由 /install-github-app 生成的 Claude 代码审查工作流程，无需在拉取请求上发布其审查即可完成
  • 修复了在连接 IDE 扩展时编辑包含数千个 IDE 诊断的文件后出现的多秒 UI 停顿问题
  • 修复了一次性 claude plugin 命令留下的杂散活动文件，该文件可能会阻止清理过时的插件版本
  • 使用主机的核心计数而不是容器的 CPU 限制修复了 CPU 限制容器内的动态工作流程
  • 修复了原子文件替换后的文件观察器句柄泄漏，以及计划任务观察器在网络或虚拟文件系统上失败时在 Windows 上出现的未捕获错误
  • 修复了提交纯空白消息时 SDK 和 --input-format stream-json 会话收到 400 API 错误的问题
  • 修复了仅消息超过 API 的 32 MB 请求限制的对话，当没有图像或文档可以被剥离时重试压缩；他们现在失败一次并发出明确的信息
  • 修复了当桌面管理网关同时也是遥测端点时，从 Claude Desktop 会话导出的 OpenTelemetry 被桌面管理网关拒绝的问题
  • 修复了部署 managed-mcp.json 且服务器提供 MCP 服务器时启动时退出的自托管运行器和其他远程会话；现在会跳过这些服务器并发出警告
  • 修复了 Git 凭证管理器提示中挂起的自托管运行器存储库准备问题；现在，当凭据丢失时，git 会快速失败
  • 改进了工作流程扇出以错开相同前缀的同级代理，以便后续代理读取缓存的提示前缀而不是重新支付（CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0 禁用）
  • 改进了“提示太长”错误，以解释为什么自动压缩无法恢复，而不是仅提示 /compact
  • 改进的沙箱：网络域列表中的 IPv6 文字现在被括起来 ([::1]:443)，并且通过 /doctor 强制执行失败关闭和标记不明确的拼写
  • 更新了 /login 以在成功登录后重复 CLAUDE_CODE_OAUTH_TOKEN 覆盖警告
  • 更改了 /commit-push-pr，因此带有危险标志的 git/gh 命令（--force、--amend、--no-verify 等）不再自动批准
  • 更改了自托管运行程序 Windows 启动以需要显式 --base-dir； Windows 上没有默认的结账目录
  • [VSCode]“报告问题”和 /bug 现在打开内置反馈对话框，而不是已停用的调查链接
  • [VSCode] 通过拖动其边界使 /btw 侧面问题面板在侧面停靠和堆叠布局中可调整大小
  • [VSCode]侧边栏新增会话组——右键click创建、重命名或删除； Cmd/Ctrl- 或 Shift-click 一次移动多个会话
