claude-code v2.1.273

修订 发布时间2026年9月15日 来源anthropics/claude-code 英文原文

变更流程图

亮点

  • 自动压缩准确性（升级的最强理由） — 上下文计量器和自动压缩此前把顾问工具回合按约 2 倍真实大小计算，导致压缩在约一半真实窗口处触发、过早裁剪上下文；长会话也变快了，因为 hook 进度和子 agent 活动不再每次更新都重新处理整个对话。任何运行长会话或上下文密集会话的用户仅凭这一点就应升级。
  • 权限与托管设置强制生效 — permissions.blockReadsOutsideWorkingDirectories 下的安全相关修复：无法分析的 Bash 命令不再跳过提示，子 shell 不能在 bypass 模式下隐藏危险的 rm，仓库设置的内存目录不再被加载/索引。关键是，通过 MDM 或 managed-settings.json 设置的 allowManagedMcpServersOnly、deniedMcpServers 和 disableClaudeAiConnectors 在同时存在服务器托管设置时被忽略——以为这些控制已生效的管理员应升级，因为它们此前被静默未执行。从 claude.ai 同步的 skill 现在也会在组织禁用 Skills 时移入回收站。
  • 需验证的行为变更（无需迁移） — Bedrock、Vertex 和 Foundry 上的 auto 模式现在默认使用本地分类器；设置 CLAUDE_CODE_AUTO_MODE_SERVER=1 可恢复服务端分类。还回滚了 2.1.268 的一项变更：Read/Edit 拒绝规则不再作用于无法分析的 Bash 行（eval、env -C），因此 time -p make build 会再次提示而非被拒绝——依赖该拒绝行为的团队应重新检查策略。这些都不是硬性破坏，但默认行为变了。
  • 网关、遥测与隐私新增功能 — 可选的 LLM 网关头（x-claude-code-request-class、x-claude-code-agent-type、x-claude-code-prev-tool-durations、x-claude-code-compaction、x-claude-code-context-compacted）通过 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 开启；OTEL_LOG_TOOL_DETAILS=1 现在在成本/token 指标中加入真实的 agent/skill/plugin/MCP 服务器名称；/bug / /feedback 现在只发送模型行为参数，去掉请求元数据和 CLAUDE_CODE_EXTRA_BODY——对此前报告泄露 body 字段的用户是隐私改善。
  • 升级结论 — 这是实质性维护版本，不是空操作、重新打标签或仅元数据变更；主要是错误修复和更清晰的错误信息（如 401/403 → /login，SSL/代理错误提示 NODE_EXTRA_CA_CERTS）。如果你运行长会话、使用企业 MDM/托管设置、网关、Remote Control 或 Claude Tag/Code Review，请升级；否则纯本地单模型、没有压缩或权限问题的用户可以合理跳到下一版本。

发生了什么变化

  • 为 LLM 网关添加了 x-claude-code-request-class、x-claude-code-agent-type、x-claude-code-prev-tool-durations、x-claude-code-compaction 和 x-claude-code-context-compacted 请求标头；选择加入 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1
  • 添加了当 MCP 服务器在会话中断开连接并且自动重新连接放弃时的通知，指向 /mcp
  • 添加了从 Claude 应用程序中分叉以 claude --remote-control 或 /remote-control 开始的会话； fork 在您的计算机上作为后台会话运行
  • 修复了权限检查器无法完全分析的 Bash 命令，跳过 permissions.blockReadsOutsideWorkingDirectories 下的提示，以及在旁路模式下隐藏危险 rm 的子 shell
  • 修复了从 claude.ai 同步的技能在您的组织关闭技能后仍然可用的问题；他们现在转移到可回收垃圾中
  • 修复了当服务器管理的设置也存在时，通过 MDM 或 managed-settings.json 设置的 allowManagedMcpServersOnly、deniedMcpServers 和 disableClaudeAiConnectors 被忽略的问题
  • 修复了 Bedrock、Vertex 和 Foundry 以及 Claude 应用程序网关 403 上的 401/403 错误，告诉您运行 /login；该消息现在指定要刷新的凭据或指向您的网关管理员
  • 修复了 /login、/upgrade 和 /extra-usage 丢弃对话中早期想法的问题，这会强制在下一个请求上进行完整的提示缓存重写
  • 修复了当 Artifact 工具上传附加到云或远程控制会话中聊天的文件时自动模式停止等待批准的问题
  • 修复了在删除或移走存储库的 .git 目录后重新创建存根 .git/info/exclude 的长时间运行会话
  • 修复了主提示符在已处于 shell 模式时丢弃在开始时键入的 ! 的问题，因此可以键入 ! grep … 等否定命令
  • 修复了 macOS 上的 Read 拒绝拖入屏幕截图或系统在第二个路径下报告的任何文件的问题，其中“检查权限后符号链接分辨率已更改”
  • 修复了 permissions.blockReadsOutsideWorkingDirectories：由存储库设置选择的内存目录不再加载到提示中、调用、索引或通过内存提取使用
  • 修复了当最终流式回复省略令牌使用或不携带模型 ID 时，子代理和后台代理被报告为失败，其结果从未交付的问题
  • 修正了上下文计量器和自动压缩计数顾问工具的轮数，大约是其实际上下文大小的两倍，这使得自动压缩在大约一半的实际窗口中触发
  • 修复了 /tui 拒绝重新启动的问题，因为代理团队队友已经完成工作并且不再显示在代理面板中
  • 修复了将 .claude/scheduled_tasks.json 复制到另一个文件夹（例如新工作树）后在错误会话中运行的已保存计划任务
  • 修复了 SDK 和 --output-format stream-json 输出在中途移动到后台后丢弃子代理的剩余消息和最终报告的问题（例如，通过 CLAUDE_AUTO_BACKGROUND_TASKS）
  • 修复了 /install-github-app 将 SAML 单点登录块报告为“需要管理员权限”的问题
  • 修复了附加到 Claude Desktop、VS Code 或 JetBrains 会话的远程控制 clients 在请求会话的上下文窗口使用情况时被拒绝的问题
  • 修复了微调器在压缩状态行上显示双省略号（“……”）的问题，例如“正在运行 PreCompact 挂钩…”
  • 修复了阅读或发布工件后建议使用前端设计插件的误报旋转提示
  • 恢复了 2.1.268 更改，该更改在权限检查器无法分析的 Bash 行上检查了读取和编辑拒绝规则（eval、env -C）；像 time -p make build 这样的命令会再次提示而不是被拒绝
  • 改进了长时间会话中的响应能力：挂钩进度和子代理活动不再在每次更新时重新处理整个对话
  • 改进了当发布包含不提供工件的文件类型时工件工具的错误：克劳德被告知提供哪些类型以及要做什么，并且终端显示一行简单的信息
  • 改进了 Artifact 工具的页面读取，以向任何可以发布到该页面的人说明该 Artifact 服务为该页面保留的功能和数据库规则
  • 改进的工件数据库写入：更新现在可以删除单个字段，而不是重写整个文档
  • 改进的工件发布：在到达 claude.ai 后连接断开的发布现在可以安全地重新发送，而不是失败或创建重复版本
  • 改进了 IP 允许列表、暂停的应用程序安装或 SAML 单点登录的云会话 GitHub 错误，以显示原因而不是通用安装提示
  • 改进了 /autofix-pr：当 gh pr view 失败时，它现在显示 gh 自己的错误（登录、SAML、速率限制），而不是通用退出代码行
  • 改进了 /autofix-pr，以说明为什么无法为 PR 设置 GitHub Webhook 传递（例如，没有链接的 GitHub 帐户），而不是一般警告
  • 改进了 /web-setup 错误：拒绝的 GitHub 令牌现在列出了可能的原因和修复方法，连接失败则指出配置的代理或 TLS 证书问题
  • 改进了会话中 SSL 证书和代理连接错误，以命名错误代码以及要修复的内容，例如 untrusted 公司 CA 的 NODE_EXTRA_CA_CERTS
  • 改进了由于您的克劳德登录已过期或被撤销而无法创建云会话时的错误：它现在告诉您运行 /login
  • 改进了当 MCP 服务器的登录在会话中过期时显示的错误，说明如何重新进行身份验证 (/mcp)
  • 更改了 Bedrock、Vertex 和 Foundry 上的自动模式，目前默认使用本地分类器；设置 CLAUDE_CODE_AUTO_MODE_SERVER=1 使用平台的服务器端分类器
  • 更改了 OTEL_LOG_TOOL_DETAILS=1，使其在成本和代币指标上还包括真实代理、技能、插件和 MCP 服务器名称
  • 更改了使用 Claude 帐户的登录方式，以请求访问您的 claude.ai 插件
  • 将 /bug 和 /feedback 报告更改为仅包含上次 API 请求中的模型行为参数（模型、系统提示、工具），省略请求元数据和 CLAUDE_CODE_EXTRA_BODY 字段
  • [VSCode] 修复了“报告问题”仍然出现以及 /bug / /feedback 打开报告表单的问题（对于禁用产品反馈的组织）
  • [VSCode] 修复了完成打开 Windows 后出现的红色“Claude Code 进程已退出，代码为 4294967295”横幅

  • [网络上的克劳德代码] 修复了从组织设置创建自托管环境偶尔会因服务器错误而失败并留下半创建的环境的问题
