claude-code v2.1.327

变更流程图

亮点

  • 会话状态与恢复可靠性（重点） — 本版本主要是修复状态丢失或”复活”问题：重启后再崩溃时 Stop 之后被遗忘的消息、/clear 后创建的任务丢失或被清空的任务重新出现、回退的提示词重新出现、headless 会话在 kill 后以相同 UUID 重发消息时丢消息，以及输出 token 限额截断后立即压缩导致丢失回复的工具调用和结果。多数问题限于云、Remote Control 和未加载功能标志的自托管 runner 会话，以及拥有数万连接器权限的组织恢复缓慢。这些用户强烈建议升级；仅本地短会话用户收益不大。
  • 权限、shell 执行与命令控制（行为变更） — 首条 Bash 命令更快，因为 shell 启动文件现在可能在批准前运行（即使用户拒绝）；可用 CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1 退出。Stop 现在能可靠终止重启后才收到批准的命令；auto 模式遵守通配符 PowerShell 规则，如 PowerShell(.\scripts\build.ps1 *)；含括号的 --disallowedTools 规则和 Code Mode 的第二脚本权限提示也已修复。两项行为变更需验证：WebFetch 在任何权限提示之前拒绝超过 2000 字符的 URL，且只将前 100 个 @ 提及作为文件查找。
  • MCP、agent 与配置完整性 — 项目作用域的 claude mcp add/remove 不再删除 .mcp.json 中的其他顶层键（如 $schema 或其他工具的 servers）——这是实实在在的数据丢失修复。新增 claude mcp add-json <name> - 从 stdin 读取服务器 JSON，使令牌不出现在命令行上，但在 Claude Code 会话内不可用。通过 --agents 传入的 agent 在插件加载/重载后仍保留，插件的 agent 在 --resume 选择器后仍保留，通过 https 以主机名访问的远程 MCP 服务器在中断后会在后台重试约一天。
  • 网关、计费、认证与 mod（迁移注意事项） — 管理员新增 attributionProject 用于在网关设置 admin.billing_group_tag 时命名会话的计费组；当托管设置 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 时，x-claude-code-managed-settings-checksum 会加入网关提示头（包括原本已启用的场景）。对嵌套令牌配置是破坏性变更：未收到会话令牌的命令不再继承其 CLAUDE_CODE_OAUTH_SCOPES — 需要者必须显式设置；forceLoginOrgUUID 不再错误拒绝这些命令。Mod 作者注意：$.model.complete/$.model.classify 现在在用量限额时立即收到 API 错误而非挂起，请处理该错误。还修复了 claude -p 在模型设置获取停滞时挂起（现在 10 秒后继续）、非 TTY 环境中裸 host:port 形式的 https_proxy/HTTPS_PROXY，以及 .claude/settings.json 的 ANTHROPIC_BASE_URL 网关下 /model 列出错误模型的问题。
  • 安全、诊断与 TUI（值得升级吗？） — /install-github-app 现在在修改仓库前会确认，新模型上的提交和 PowerShell 中会避开可能含机密的文件，/status//config 会暴露损坏的 agent、skill、命令和输出样式文件、键位与 hook 错误、不可用的沙箱、被忽略的权限设置和覆盖设置。/tui classic 是非全屏渲染器的新名称，但 /tui default 仍可用，因此无需重命名迁移。其余是大量 TUI、回滚缓冲区和对话框打磨以及 artifact 批准和 hook 修复。不是空操作或重新打标签——内容实质且无移除；建议云、Remote Control、自托管 runner、SDK、MCP 配置、网关和 mod 用户升级，而仅本地短会话用户可以跳过。
