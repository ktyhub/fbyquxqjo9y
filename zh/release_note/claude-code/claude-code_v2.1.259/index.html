claude-code v2.1.259

修订 发布时间2026年9月2日 来源anthropics/claude-code 英文原文

变更架构图

亮点

  • 托管 MCP 行为（破坏性） — managedMcpServers 让组织以与 .mcp.json 相同的条目结构分发 HTTP/SSE MCP 服务器；基于命令的条目会被跳过。另外，allowedMcpServers 现在只管理用户添加的服务器。此前被允许列表过滤掉的 managed-mcp.json 中的字面量服务器在升级后会加载——如果它们必须保持禁用，请迁移到 deniedMcpServers。
  • 无人值守执行与权限加固 — --permission-prompts none 拒绝任何需要提示的操作，同时保留活动的权限模式判定。Bash Read() 拒绝规则现在覆盖选项值、文件操作数和复合命令，对拒绝路径的递归 grep/cp 会提示。无法解析的托管设置现在会阻止启动，而不是静默让策略未生效。
  • 会话完整性与生命周期修复 — 并发会话不再互相覆盖 ~/.claude.json，保留工作区信任以及 MCP/项目状态。Remote Stop 现在真正终止后台 agent/工作流，工作流恢复不再复制正在退出运行中的 agent。还修复了仅附件恢复失败、提示缓存丢失，以及长回合后全屏对话空白的问题。
  • 模型与开发者工作流改进 — 命令/skill frontmatter 的 model: 现在在交互模式下生效，auto 模式保留会话模型而不再选择不支持的模型。还新增 GitLab MR 摘要、机器可读的 claude plugin validate --json、worktree 命令兼容性，以及 VSCode 会话状态过滤器。
  • 升级建议 — 托管策略用户、无人值守主机、并发/远程会话和工作流重度团队值得升级；托管 MCP 管理员应先审计允许列表。与这些领域无关的单用户本地工作流可以安全推迟，不过权限和托管设置修复在安全上普遍相关。

发生了什么变化

  • 添加了 managedMcpServers 托管设置：组织可以向每个用户提供 HTTP/SSE MCP 服务器（与 .mcp.json 相同的条目形状）；指定要运行的命令的条目将被跳过
  • 为无人值守的无头主机添加了 --permission-prompts none：当活动权限模式（包括自动模式）不断决定时，任何会提示的内容都会被自动拒绝
  • 添加了对 glab mr create/merge/close/reopen/note/update 的识别，因此 GitLab 合并请求在折叠的工具摘要中显示为 MR !N 并刷新页脚 MR 徽章
  • 将 --json 添加到 claude plugin validate 以获取机器可读的验证报告
  • 修复了并发会话默默地恢复彼此的 ~/.claude.json 更改 — 工作区 trust 不再重置，并且一次运行多个会话时 MCP/项目状态不再丢失
  • 修复了一个对话，该对话的想法一旦被拒绝，之后的每个回合都会再次被拒绝
  • 修复了 Bash Read() 拒绝规则，不涵盖作为选项值给出的文件（--ignore-revs-file=.env、-f.env、@file）、git diff/git grep 文件操作数或 cd DIR && cat FILE 化合物；现在对保存被拒绝文件的目录进行 grep -r/cp -r 询问
  • 修复了在禁用遥测的会话中刷新 OAuth 令牌时提示缓存失效的问题
  • 修复了全屏模式在数百次工具调用长时间转动后显示空白对话的问题
  • 修复了当命令或技能的 frontmatter model: 命名为一个时，在不支持的模型上运行的自动模式；现在回合保持会话模型
  • 修复了 Claude Code 无法识别的模型版本的 Vertex 样式模型 ID（@YYYYMMDD 后缀）会忽略 CLAUDE_CODE_MAX_CONTEXT_TOKENS
  • 修复了正在运行的 shell 命令的实时输出预览，当较早的行换行时隐藏其最新行
  • 修复了 claude.ai 用户每次启动时运行的后台 GitHub 连接检查；现在，每次启动都会记住结果
  • 修复了当保存的会话包含没有有效负载的附件条目时 --resume 失败（以及 --continue 打开空对话）的问题
  • 修复了交互式会话中忽略自定义命令和技能的 frontmatter model:
  • 修复了 Artifact 发布失败一次，并在从旧版本继续的对话中出现“意外参数 note”错误
  • 修复了当 MDM 配置的策略帮助程序或托管设置文件已运行时，托管 forceRemoteSettingsRefresh 在启动时被忽略的问题
  • 修复了工作树隔离拒绝在 git rev-parse 失败并显示“不是 git 存储库”以外的消息的计算机上钩子创建的工作树的问题
  • 修复了云会话中缺少 user.email、organization.id 和 user.account_uuid 属性的 OpenTelemetry 指标和事件
  • 修复了在启动时列出其工具时断开连接的 MCP 服务器，显示为没有工具连接，而不是报告错误
  • 修复了文件编辑权限对话框有时显示更改的行被缩短而没有任何指示的问题
  • 修复了存储库检测在短暂的 git 探针失败后删除已知存储库身份的问题
  • 修复了当无法解析托管设置文件、插入项、MDM plist 或 HKLM 值时，托管设置会自动不强制执行的问题：Claude Code 现在拒绝启动并命名源
  • 修复了“停止”实际上并未停止远程控制会话中的后台代理和工作流程：被终止的任务现在保持可见并可重新停止，直到其进程退出
  • 修复了在先前停止的运行仍在退出时恢复工作流程运行的问题，这可能会运行其代理的重复副本
  • 修复了 github.com 上带有尾部斜杠或悬空 ?/# 的市场存储库 URL，产生不可用的 .git 克隆 URL
  • 修复了阻塞停止钩子，导致阻塞后的转弯丢失该转弯的模型推理，并且在某些模型上错过提示缓存
  • 修复了浏览器托管的 MCP 服务器页面消失后，远程 (claude.ai) 会话需要 60 秒才能开始一轮的问题
  • 修复了工作树隔离的会话拒绝常见的 Bash 循环、xargs 管道和启动器包装的命令，这些命令无法到达主结帐
  • 通过重用文本测量，改进了长响应的终端调整大小和首次渲染性能
  • 改进了 /workflows 代理细节：JSON 结果打印得很漂亮，带有语法颜色和实际换行符，长结果折叠在展开切换后面
  • 改进了无头/SDK 会话启动：当 MCP 服务器完成连接时，第一轮开始时间提前了 50 毫秒
  • 改进了 /install-github-app 以解释它仅适用于 GitHub，并在 GitLab 存储库中运行时指向 GitLab CI/CD 文档
  • 改进了嵌套后台子代理结果保存在父子代理的转录本中，因此恢复的子代理会保留它们，并且共享转录本会显示交付情况
  • 更改了 allowedMcpServers 以仅管理用户添加的服务器：用于过滤掉白名单的字面 managed-mcp.json 服务器现在在升级时加载；使用 deniedMcpServers 将其关闭
  • [VSCode] 在会话列表侧边栏添加了活动快速过滤器和状态过滤器菜单（需要输入、正在工作、已完成）
  • 修复了在会话暂停时批准连接器工具权限提示后远程和计划会话不执行任何操作的问题
