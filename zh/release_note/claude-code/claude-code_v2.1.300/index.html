claude-code v2.1.300

修订 发布时间2026年10月14日 来源anthropics/claude-code 英文原文

变更架构图

亮点

  • Mod 与插件创作 API — 对 mod 作者是一次大扩展：新增 prompt.change 钩子，在提示词因非手动编辑（历史召回、清空、撤销或插件填充）而变化时触发；virtualText 可绘制永不进入草稿或已提交提示词的装饰；$.ui.view({ agentId }) 在主视图显示某代理的转录，$.ui.view({}) 返回；Text 新增 dir 属性支持从右到左的行；prompt.edit 现在也会对通过 chat:newline（Ctrl+J / 重绑定的 Enter）输入的换行触发；agent.spawn 现在可以改写工作流代理的 prompt 和 model，此前只能拒绝。如果你编写 mod，这是重头戏；其他用户不受影响。

  • 破坏性变更 / 迁移 — PreToolUse 和 PermissionRequest 钩子返回的 updatedInput 现在像 Claude 自身输入一样被校验：未知键会被丢弃，被工具拒绝的输入会否决调用。在 Cowork 云端会话中，PermissionRequest 钩子允许里的 setMode 更新会被忽略。claude remote-control 不再接受 --sandbox/--no-sandbox（两者都会报错退出）——请在设置中配置 sandbox.enabled。CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST 会话会忽略设置中的 CA bundle、工具代理和 git TLS 变量（如 SSL_CERT_FILE）（在 Claude Desktop 下只忽略项目设置）。如果依赖其中任何一项，升级前请审查钩子和沙箱/TLS 配置。

  • 可观测性 / 遥测 — api_request 现在按生命周期拆分缓存写入，增加 cache_creation_5m_tokens 和 cache_creation_1h_tokens；追踪 span 新增 OTel GenAI 语义约定属性（gen_ai.provider.name、gen_ai.conversation.id、gen_ai.tool.name、error.type）；tool_result 事件在 reftable 仓库中重新带上 git_commit_id；被 mod 的 prompt.submit 钩子改写或丢弃的提示词不再被记录为手动输入到 user_prompt 事件；本地转录现在内嵌每个请求的系统提示词、工具和参数，便于精确复现。发往 api.anthropic.com 的大请求即使关闭遥测也会 gzip 压缩（CLAUDE_CODE_GZIP_REQUEST_BODIES=0 可禁用）。对成本归因和可分享的复现很有价值；请检查依赖旧事件结构的看板。

  • Headless / 恢复 / 压缩可靠性 — 若干静默的正确性修复：恢复 headless 或 Agent SDK 会话时，不再丢失因输出令牌上限回复后被压缩保留的近期消息，也不再在重试/未完成回复后丢失压缩摘要；崩溃截断恢复后的第一条转录条目会保留；云端容器切换后，后台代理不再被误报为丢失/不可恢复；ENABLE_TOOL_SEARCH=auto 不再在对话中途（如 MCP 重连时）自动关闭；压缩后才连接的服务器，其 MCP 工具/指令在下一次工具调用时可用。对 Agent SDK、headless 和长云端会话用户是强升级理由——这些是数据丢失问题，不是外观问题。

  • 新增功能面与结论 — /advisor 登陆 AWS 上的 Claude Platform，但完全可选：在你通过 /advisor、advisorModel 或 --advisor 选择之前不会运行任何东西，CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 可将其关闭。还有大量 --worktree/git reftable 修复（裸仓库、看起来像 commit id 的标签/分支名、.invalid 分支），VS Code 新增 claudeCode.attachSelection 并修复快速模式烧额度的问题，Cowork/Remote Control 的 diff 与审批修复（远程 diff 视图要求本机安装 Claude Code v2.1.296+），以及 Claude Tag 中的 Slack Connect 支持。这是一个有分量的功能与加固版本，不是空操作或仅改标签：如果你使用 mod、遥测、worktree/reftable、VS Code 或 headless/云端会话，建议升级；只有完全不涉及这些功能面且没有钩子受校验变更影响时，才可以合理跳过。

发生了什么变化

  • 在mod的提示装饰中添加了virtualText：在从未进入草稿或提交的提示的提示框中绘制的文本
  • 将 cache_creation_5m_tokens 和 cache_creation_1h_tokens 添加到 OpenTelemetry api_request 事件，按生命周期拆分缓存写入
  • 为 mods 添加了 $.ui.view({ agentId })：当您询问时，在主视图中显示特工的记录，而 $.ui.view({}) 返回
  • 在 mod 的 Text 上添加了 dir 属性，用于从右到左的文本：在 Windows 上和 VS Code 的终端中，其行沿该方向读取并位于右侧齐平
  • 在 AWS 上的 Claude 平台上添加了 /advisor；除非您选择带有 /advisor、advisorModel 或 --advisor 的顾问，否则顾问不会运行，而 CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 将其关闭
  • 向跟踪范围添加了 OpenTelemetry GenAI 语义约定属性，例如 gen_ai.provider.name、gen_ai.conversation.id、gen_ai.tool.name 和 error.type
  • 在agent.spawn mod hook中添加了对重写工作流代理的prompt和model的支持，该功能之前只能拒绝工作流代理
  • 添加了 prompt.change mod 挂钩，当提示框的文本更改而没有键入编辑时引发：调用历史记录条目、清除、撤消或插件填充
  • 修复了云会话，告诉克劳德当会话自己的网络设置阻止主机时，组织策略阻止了主机
  • 修复了当您选择较小的自动压缩窗口时关于高令牌使用的 /autocompact 警告
  • 修复了后台命令仍在运行时退出时 SessionEnd 挂钩有时不运行的问题
  • 修复了 claude --help 在 --restricted 描述中命名已删除工具的问题
  • 修复了当其中一个拉取请求的数据返回不完整时，claude agents 不会刷新任何拉取请求的状态
  • 修复了在更换云会话的容器后，当代理已经恢复一次时，克劳德被告知后台代理丢失且不可恢复的问题
  • 修复了您输入消息后不久从 /tasks 中消失的子代理，无法返回对话
  • 修复了当您查看子级时，已完成的父级代理会掉落面包屑（其子级在顶层显示为重新扎根）
  • 修复了当输入突然到达时，代理视图会在该键上输入“向上”、“向下”或“退出”等单词，这可能会在回复中移动窥视或清除草稿
  • 修复了自动工具搜索 (ENABLE_TOOL_SEARCH=auto) 在对话过程中关闭的问题，例如在恢复后 MCP 服务器重新连接时
  • 修复了 forceLoginOrgUUID 拒绝登录，导致被拒绝组织的令牌被存储或在 /login 之后生效的问题
  • 修复了克劳德桌面和远程控制会话中的差异视图，没有注意到可检索存储库中存在冲突的挑选或恢复
  • 修复了当呼叫输入到达时 Artifact 工具的详细行和 ctrl+o 行读取 Artifact("(unprintable path)") 的问题；它的行现在显示“正在等待…”和“正在运行…”，就像 Bash 一样
  • 修复了当崩溃缩短了记录的最后一行时，恢复会话后写入的第一个记录条目丢失的问题
  • 修复了当 /branch 包含 Unicode 行或段落分隔符（U+2028、U+2029）时，/branch 丢弃消息以及 claude purge 跳过子文件夹项目的问题
  • 修复了当 Claude Code 以 --worktree 开头时插件 WorktreeCreate 和 WorktreeRemove 挂钩未运行（尚未以 --tmux 开头）
  • 修复了使用可引用引用存储的存储库中 git commit -q 之后 OpenTelemetry tool_result 事件丢失 git_commit_id 的问题
