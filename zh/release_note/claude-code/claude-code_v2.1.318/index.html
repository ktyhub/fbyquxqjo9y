claude-code v2.1.318

修订 发布时间2026年11月4日 来源anthropics/claude-code 英文原文

变更流程图

亮点

  • 凭据过期在生效前就可见 — claude auth status 现在报告 loginExpiresAt，claude -p 的 JSON 结果包含 credential_expires_at，并在存储的 claude.ai 登录到期前 10 天发出一行 stderr 警告。当令牌真的到达时限时，错误现在会明确说明并引导 headless 用户使用 claude auth login / claude setup-token，而不是误导性的”Not logged in”；带 forceLoginOrgUUID 的机器上有效的 setup-token 令牌也不再在启动时被拒。解析 claude -p JSON 的自动化获得机器可读的过期字段。
  • ~/.claude.json 与网络 home 目录的数据丢失是本版本最大的修复簇 — 非交互启动不再把无效 JSON 替换为默认值：现在启动会失败、保持文件原样并打印恢复指引（anthropics/claude-code#87551）；没有备份的空文件被视为缺失，恢复命令不再指向空/截断的备份。在共享网络 home 目录上，保存不再那么容易删除文件、短暂清空或用近乎空白/较旧的副本替换配置；home 满不再把存储的登录截断为空文件；/logout、claude auth logout 和 claude mcp remove 在写入失败时不再报告成功；信任/同意/MCP 变更不再被静默丢弃；保留期清理在删除最后一份完好备份前会先做新备份。claude mcp add/remove 现在会获取配置锁（等待或退出 1），claude plugin 命令会等待缓慢的令牌刷新完成保存。这对网络 home 目录、多终端/多主机账号和无人值守的 claude -p 机群最重要。
  • 升级前需检查的破坏性变更 — 在 IDE 终端中启动 Claude Code 不再安装或更新 IDE 扩展；请从外部终端使用 /ide 或在编辑器的扩展视图中操作。自托管 runner orchestrator 日志格式变了：ok session=… 现在在所有日志级别打印到 stdout，并在 jti=… 后带 reason=…，nack session=… 在 retryable=… 后以 reason=… 结尾——更新匹配 retryable=true: / retryable=false: 的脚本。deniedMcpServers 的 URL 条目现在在上游 URL 匹配时也会屏蔽 Anthropic 提供的服务器和云/自托管连接器（否则按名称拒绝连接器）。/claude-api managed-agents-onboard 把新 agent 的内置工具和 quickstart MCP 工具默认设为 auto 策略（“判断风险操作”）；说”run without asking”可退出。当”消息被标记时切换模型”设为”每次询问”时，子 agent 会停止而非切换模型。Mod 方面：turn.step hook 不再让停止的回复在 headless 运行中作为成功完成，prompt.submit 附件留在用户回合中而不是作为系统消息离开。2.1.288 的恢复修复被移除，因此从 2.1.286 或更早开始的对话中的思考现在可能被丢弃。
  • 网关、mod 与 runner 新能力 — mantle 上游上的 assume_role 可启用另一个 AWS 账户中的角色，并按开发者做 AWS 成本归因。Mod 在 $.model.fork 上新增 effort 选项，让快速支线任务无论会话努力程度如何都以 low 运行，结果中报告实际发送的 effort。自托管 runner 的 spawn hook 现在收到 CLAUDE_RUNNER_SPAWN_REASON（如 runner_lost、resumed），无原因时未设置，ok session=… 日志带该原因。云会话新增”No repository”选项、通过 google-chrome/CHROME_PATH 的标准 Chrome 名称，以及更可操作的 Create PR 失败提示。
  • 结论：实质性升级，不是重新打标签 — 应为凭据过期处理、配置文件韧性和 headless/SDK 正确性升级（claude -p 和 Agent SDK 在 turn.step hook 截断回复时不再报告成功，Stop 现在取消模型切换后刚发出的消息，自定义斜杠命令打印输出，空闲压缩不再用非摘要内容替换对话）。Remote Control、后台守护进程和自托管 runner 用户获得对更新删除仍在运行的进程二进制文件后 spawn ENOENT 的真正修复。如果你是单机、不用 mod/网关/自托管 runner 或 IDE 自动安装，且接受上述小行为变更，可以跳过。

发生了什么变化

  • 当 Claude Code 要求打开它在会话中写入的 mod 时，添加了您的回答记录
  • 在 Claude 应用程序网关的 mantle 上游添加了 assume_role，用于另一个 AWS 账户中的角色以及每个开发人员的 AWS 成本归因
  • 在 mod 的 $.model.fork 中添加了 effort 选项，因此无论会话使用什么努力，快速的副业都可以在 low 上运行；结果报告了发送的工作量
  • 将存储的 claude.ai 登录结束日期添加到 claude auth status (loginExpiresAt) 和 claude -p JSON 结果 (credential_expires_at)
  • 在 claude -p 文本输出中添加了一行 stderr 警告，从存储的 claude.ai 登录结束前 10 天开始
  • 修复了 --continue 有时在格式错误的工具调用重试结束后丢失早期对话的问题（2.1.314 中的回归）
  • 修复了 macOS 会话，其中许多正在运行的 Bash 命令在内存增长时停止
  • 修复了在发送消息后或出现缓慢提示之前通过键入按键应答的权限提示
  • 修复了当无法在共享网络主目录上更新配置文件时，/logout、claude auth logout 和 claude mcp remove 报告成功以及对 trust 的更改、同意或 MCP 设置被无言删除的问题
  • 修复了当另一个终端或主机再次登录同一家庭的同一帐户和组织时，作业会以 Not logged in 退出的问题
  • 修复了 claude mcp add 和 remove 在没有锁的情况下写入配置的问题：它们现在等待它或退出 1，尽管另一个作业的保存仍然可以替换已保存的服务器
  • 修复了在保存缓慢令牌刷新之前退出的 claude plugin 命令，这可能会让您在下次运行时退出
  • 修复了 claude plugin validate 传递 claude plugin marketplace add 拒绝的自定义命名的市场文件的问题
  • 修复了在每次启动时重新探测版本探测时退出的 stdio MCP 服务器；因自身原因在 3 秒内死亡的服务器也会被固定到旧版握手中 7 天
  • 修复了启动时会话被同一台计算机上的另一个登录名存储的 allowedProviders 列表拒绝的问题
  • 修复了空闲压缩，用非摘要的回复替换对话的问题
  • 修复了后台子代理运行时大约每 30 秒重新出现一次的“现在使用使用积分”通知
  • 修复了失败的自定义斜杠命令，或者只有 Claude 可以调用、在 claude -p 和 SDK 会话中不打印任何内容的问题
  • 修复了当 Mod 挂接 turn.step 时 API 错误切断回复时 claude -p 和代理 SDK 会话报告成功的问题
  • 修复了在无头会话中停止后模型更改后立即发送的消息仍在运行的问题：立即停止会取消或停止它，就像排队消息一样
  • 修复了当空闲的非交互式会话退出时，使用最后的提示重新创建已删除的会话记录
  • 修复了在更新或版本清理删除仍在运行的进程的二进制文件后，claude remote-control 主机、后台守护程序和自托管运行程序无法启动新会话 (spawn ENOENT) 的问题
  • 修复了另一用户拥有的正在运行的 Claude Code 进程（例如 sudo claude 留下的进程）被版本清理视为死亡，这可能会删除其二进制文件
  • 修复了 /remote-control 在连接失败后显示会话可用的问题
  • 修复了请求失败并出现 404 错误时 /design revoke 报告成功的问题
  • 修复了自托管运行器或云会话重新启动后批准的 shell 命令在会话的开始文件夹中运行，而不是在要求的文件夹中运行；如果无法进入该文件夹，则不会运行
  • 修复了云会话重启后批准的连接器工具不可用时克劳德没有被告知的问题
  • 修复了当服务拒绝上传几分钟时云会话在转弯过程中停止的问题
  • 修复了 Setup 挂钩写入 CLAUDE_ENV_FILE 的变量在某些云会话中未到达 Bash 工具的问题

  • 修复了重新启动的会话在后面等待的新消息之前重新发送因 API 错误而失败的消息的问题
  • 修复了当克劳德读取大图像或重试工具调用后立即重新启动时，重新启动的会话会放弃其中断的回合

  • 修复了工作流程在使用限制后恢复时重新运行已完成的代理的问题
