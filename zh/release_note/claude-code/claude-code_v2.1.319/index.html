claude-code v2.1.319

修订 发布时间2026年11月6日 来源anthropics/claude-code 英文原文

变更流程图

亮点

  • Auto 模式更严格；网关配置可能需要调整 — 当遥测或功能标志关闭时，服务器无法检查的操作现在会提示或拒绝，不再回退到内置分类器。设置 CLAUDE_CODE_AUTO_MODE_SERVER=0 可保留之前的本地行为；Bedrock、Vertex 和 Foundry 不受影响。在 LLM 网关后，使用 CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS 的托管设置还必须设置 CLAUDE_CODE_AUTO_MODE_SERVER=1 才能启用服务端检查。
  • CLI 退出码行为变更 — 当 auto 模式因没有可用安全检查而拒绝操作时，claude -p 现在退出 1。当缺失的 MCP 服务器导致延迟的工具调用无法完成时，claude -p --resume 也会退出 1，同时保留该调用并拒绝后续输入。claude remote-control 现在在首次运行问题未回答后退出 1，而不是静默成功。请将把退出 0 视为成功的自动化更新。
  • 安全修复使升级值得 — 补丁包括通过构造环境变量前缀绕过 Bash 权限、worktree 沙箱逃逸、跳过 sed 权限检查、遗漏带引号的词规则，以及 /rewind 通过目录符号链接穿越。使用 --trust-workspace false 的自托管 runner 现在也会阻止来自仓库设置的 hook 和 skill；Claude Desktop 在包含此版本后将支持连接器终端权限名称。
  • 后台工作与无人值守工作流更稳健 — MCP 任务现在立即转入后台并稍后报告完成；CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND 可恢复同步等待。/tasks 新增”本次会话更早”用于重新打开已完成的子 agent，/clear 不再杀死持久后台工作或将其从任务列表隐藏。新增 permissions.denyInsteadOfPrompting，让回合在自动拒绝后继续，而不必等待用户批准。
  • 网关运维与可靠性改进；总体建议升级 — 网关新增按日/周/月的支出、共享预算排序控制、login_notice，以及通过 CLAUDE_GATEWAY_LOG_FORMAT=json 输出 JSON 日志。CLAUDE_CODE_DISABLE_FEATURE_FLAGS 停止标志获取而不禁用遥测，并使每个标志使用内置默认值。其他修复涵盖 MCP 握手/恢复失败、名为 HEAD 文件周围的 diff 失败、磁盘满导致的配置损坏、过度的 NFS 启动扫描和陈旧认证状态。这是实质性版本，不是重新打标签：网关、MCP、自动化和安全敏感用户应升级；未涉及这些领域的用户可以合理跳过。

发生了什么变化

  • 更改了遥测或功能标记关闭的自动模式，包括在 LLM 网关后面：服务器无法检查的呼叫会被询问或拒绝，不会回退到内置分类器；设置CLAUDE_CODE_AUTO_MODE_SERVER=0继续使用（Bedrock、Vertex和Foundry不变）
  • 更改了 LLM 网关后面的自动模式：即使设置了 CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS，CLAUDE_CODE_AUTO_MODE_SERVER=1 也会打开服务器端检查；如果托管设置设置了后者，则它们也必须设置 1
  • 添加了对终端中 MCP 任务的支持：当 MCP 服务器将工具调用作为任务运行时，Claude Code 会立即将其移动到后台，并在完成时告诉 Claude 结果
  • 添加了 CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND 环境变量，使 Claude Code 在其工具调用中等待 MCP 任务，而不是立即将其移至后台
  • 添加了 permissions.denyInsteadOfPrompting 设置：在终端会话、子代理和队友中，将等待权限提示的工具调用被拒绝，并且轮流继续
  • 添加了 /claude-api latency-optimize 来查找您的 Claude API 代码让人们等待的地方，并针对您的评估尝试更快的设置
  • 添加了 CLAUDE_CODE_DISABLE_FEATURE_FLAGS 环境变量，该变量可在不关闭遥测的情况下停止功能标志获取；然后每个标志都使用其内置默认值
  • 当网关运行此版本或更高版本时，为没有支出限制的 Claude 应用程序网关背后的开发人员将今天、本周和本月的支出添加到 /usage
  • 将 admin.pooled_conflict_rule 和 admin.pooled_priority_order 添加到 Claude 应用程序网关，以设置哪个集合组预算首先为多个组中的开发人员支付
  • 向 Claude 应用程序网关添加了可选的 login_notice 设置，该设置在网关的浏览器验证页面和 Claude Code 的登录屏幕上显示运营商定义的消息
  • 将 CLAUDE_GATEWAY_LOG_FORMAT=json 添加到 Claude 应用程序网关：对于从字段读取级别的日志收集器，操作日志行变为 JSON 和 severity、time 和 message
  • 添加了克劳德应用程序网关启动警告，用于解决另一个策略的 availableModels 也允许一个策略按名称列出的自定义模型 ID 的情况
  • 在 Claude Desktop 于 11 月 10 日进行更改之前，向 Claude 应用程序网关添加了针对没有 desktopHome 且依赖于 coworkTabEnabled: false 或 chatSessionRetentionDays 的策略的启动警告
  • 当您的 claude.ai 登录结束并且 Claude Code 继续从 ant auth login 登录时添加了警告，这会向您的 Claude Console 组织收取使用费用
  • 在启动时添加了一行，命名 Claude Console 组织，该组织在 Claude Code 使用 ant auth login 登录的情况下计费
  • 在 /tasks 中添加了“本次会话中的早些时候”行，其中列出了已完成的子代理，因此即使在它离开列表或重新启动后，您也可以重新打开一个子代理并向其发送消息
  • 在云会话中的 /loop 确认中添加了一条注释，即计时器随其容器停止，并提供了一个存活的循环
  • 修复了旧握手上的 MCP 服务器无法连接或返回空结果的问题，因为 Claude Code 声明了一个仅与较新服务器一起使用的扩展
  • 修复了 claude.ai 连接器上长时间运行的 MCP 工具调用有时在 --resume 后从不报告其结果的问题
  • 修复了当 Claude Code 运行的文件夹包含名为 HEAD 的文件或文件夹时，会话的差异无法在 claude.ai 和移动应用程序上加载的问题
  • 修复了当 git 存储库的顶层有名为 HEAD 的文件或文件夹时 /diff 显示“Diff unavailable”的问题
  • 修复了 64 次或更多轮次编辑文件的会话中 /diff 窗格打开为空白的问题
  • 修复了在前导空格、制表符或换行符之后键入的斜杠命令以纯文本形式发送给 Claude，而不是运行
  • 修复了每次重试时始终失败并出现 401 刷新登录并导致其他会话出现 401 错误的请求
  • 修正了 /context 在以后的每个回合中将其完整的视觉网格发送给克劳德的问题；克劳德现在只读取表格
  • 修复了 claude -p 在自动模式下退出 0 的问题，因为没有可用的安全检查，其操作被拒绝：文本和 JSON 输出现在退出 1
