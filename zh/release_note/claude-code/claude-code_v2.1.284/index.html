claude-code v2.1.284

变更流程图

亮点

  • 新默认模型与模型切换行为 — Claude Sonnet 5.5 (claude-sonnet-5-5) 成为 Anthropic API 上的默认 Sonnet：1M 上下文，$2/$10 每 Mtok，缓存读取 $0.20/Mtok。另外，在通过 ANTHROPIC_DEFAULT_OPUS_MODEL 或 modelOverrides 固定 Opus 的会话中，安全相关的模型切换现在让 API 按标志选择切换目标，而不是使用你固定的模型——依赖固定模型处理这些切换的用户应重新验证行为。
  • Auto 模式成为默认；Ultracode 与 xhigh 解耦 — 未配置权限模式时，交互式终端和 VS Code 会话现在在每个 plan/provider 下都以 auto 模式启动（permissions.defaultMode 仍可覆盖）。Ultracode 移至独立的 /effort 开关（Tab 或 /effort ultracode [on|off]），不再强制 xhigh 努力程度——它在任何级别都保持开启，并新增 effortSlider:decreaseEffort、increaseEffort、toggleUltracode 键位。如果你曾依赖 Ultracode 隐含 xhigh，请显式设置努力程度；如果你想要旧的权限模式，请设置 permissions.defaultMode。
  • 可靠性修复——升级的主要理由 — 损坏的流（把原始 “JSON Parse error”/“undefined” 写入答案）现在会重试或报告为中断，而不是静默损坏；紧跟思考块之后的可重载/5xx 错误会重试；压缩后的 “Prompt is too long” 会触发第二次更严格的压缩；恢复会话中的 MCP 工具调用现在最多等待 10 秒连接服务器，/mcp reconnect all 会重试每个失败的服务器；Agent SDK 不再因图片 source 或文档块格式错误而崩溃；/usage、/extra-usage 和 IDE 用量视图在限流后会退避而非重复请求。遇到流损坏、恢复会话 MCP 失败或用量限额循环的用户应升级。
  • 可能需调整配置的安全/策略加固 — 非纯资源名的 ANTHROPIC_FOUNDRY_RESOURCE 值现在会被拒绝，而不是被插入到端点主机中；通过 allowed-tools 自批准的 marketplace、claude.ai 和 npm 插件，在托管 allowManagedPermissionRulesOnly 下失去预批准（除非来自 Anthropic 官方/背书来源）；从项目外部符号链接的 .claude/rules 和 .claude 现在需要外部导入批准；托管设置将服务器限制为插件时，claude mcp add 会拒绝并给出指引；artifact 发布会拒绝未映射网络共享上的文件。如果你使用自定义 Foundry 资源、第三方插件或符号链接规则，请重新检查。
  • 网关与 VS Code 新增功能；结论 — Claude apps 网关在 /usage 和状态行增加美元金额（rate_limits.spend_limit 新增 used_usd、limit_usd、period），auth: { google: {} } 将遥测转发到 Google Cloud OTLP，支持 private_key_jwt 客户端认证，availableModels 启动警告，以及 256 KiB 头大小限制（修复分组多的 IdP 出现 431）；VS Code 新增可选消息时间戳和 Effort 面板的 Ultracode 开关及多项修复。这是实质性、非元数据版本，不是空操作：大多数用户应升级以获取稳定性修复，网关运营者和 IDE 用户直接受益；固定特定权限模式或依赖 Ultracode⇒xhigh 的用户只有在调整配置后才能跳过。

发生了什么变化

  • 添加了 Claude Sonnet 5.5 (claude-sonnet-5-5)，现在是 Anthropic API 上的默认 Sonnet 模型 — 1M 上下文，每个 Mtok $2/$10，带有 $0.20/Mtok 缓存读取
  • 在读取工作目录之外的内容之前，对自动模式的提示添加了“是，但下次再询问”答案，这样您就可以允许该读取，但仍会被询问稍后的内容
  • 当网关运行此版本或更高版本时，在 /usage 和状态行中为 Claude 应用程序网关支出限额添加了美元金额（例如“本月支出 $271.40 / $500.00”）；状态行的 rate_limits.spend_limit 也获得 used_usd、limit_usd 和 period
  • 添加了 effortSlider:decreaseEffort、increaseEffort 和 toggleUltracode 键绑定操作，因此 /effort 滑块的箭头和 Tab 键可以在 keybindings.json 中反弹
  • 将 /rate-limit-options 添加到 /help 以及 claude.ai 订阅者的命令菜单，因此提及它的使用限制通知指向您可以找到的命令
  • 在交互终端中添加了/mcp reconnect all，以立即重试每个连接失败或需要身份验证的MCP服务器
  • 添加了当托管策略的 availableModels 为空时，或遗漏克劳德代码在未设置 model 或 enforceAvailableModels 的情况下启动的模型时，克劳德应用程序网关启动警告
  • 为 Claude 应用网关 telemetry.forward_to 目的地添加了 auth: { google: {} }，因此可以使用网关的 Google Cloud 凭据将遥测数据直接导出到 Google Cloud 的 OTLP 端点
  • 在 Claude 应用程序网关与其身份提供商之间添加了证书 client 身份验证 (private_key_jwt)，适用于颁发证书凭据而不是 client 机密的身份提供商
  • 修复了显示原始错误（例如“JSON 解析错误”或“未定义不是对象”）的损坏响应流，或将“未定义”一词写入答案，而不是重试或报告为中断响应
  • 修复了思维块以错误结束回合而不是重试后立即出现的过载或服务器错误
  • 修复了压缩后仍然存在的“提示太长”错误：当压缩的请求仍然太长时，克劳德代码现在会再次压缩，保留较少的最近对话
  • 修复了模型不可用的会话，没有留下后备模型，仅显示“当前不可用”消息（或云会话中的“出现问题”），而不是模型不可用通知及其“了解更多”链接
  • 修复了当用户消息包含带有格式错误的 source 的图像时代理 SDK 会话崩溃，以及在格式错误的文档块之后的每个回合中失败的问题；格式错误的图像现已替换为解释性注释
  • 修复了在服务器仍在连接时，恢复会话中的 MCP 工具调用失败并显示“没有此类工具可用”的问题；现在，呼叫等待服务器最多 10 秒
  • 修复了在限制速率或拒绝登录后重复调用计划使用端点的问题：/usage、/extra-usage 和 IDE 使用视图现在会后退而不是重新询问
  • 修复了当托管设置将 MCP 服务器限制为插件时 claude mcp add 报告成功的问题；它现在拒绝并说明要做什么，而不是保存永远不会加载的服务器
  • 修复了 /plugin 配置屏幕：布尔选项现在是真/假选择，而不是自由文本，数字选项拒绝无效输入，以及 ←/→ 更改选项字段而不是切换选项卡
  • 修复了 ANTHROPIC_FOUNDRY_RESOURCE 插入未验证的 Foundry 端点主机的问题；现在拒绝非普通资源名称的值
  • 修复了克劳德应用程序网关后面的克劳德桌面不提供 1M 上下文选项的问题：网关现在自动标记每个支持 1M 的桌面模型
  • 修复了 shell 模式下的 ↓ 选择隐藏后台任务药丸的问题，这会阻止 Backspace 和 Ctrl+U 编辑提示
  • 修复了 Bash 工具在启用了许多插件的 Windows 上失败的问题：不存在的插件 bin/ 目录不再添加到 PATH，并且继承的条目不会添加两次
  • 修复了 sparsePaths 插件市场克隆空并替换旧 git 上的工作本地副本（2.39 之前）的问题，每次刷新都会失败，并显示“marketplace.json 文件不再存在”
  • 修复了当 [ 在转录模式下将对话写入回滚时，全屏渲染会擦除会话上方的终端输出（macOS 和 Linux）
  • 修复了当向上滚动回复完成流式传输时，全屏滚动位置跳转到上一条消息或底部的问题
  • 修复了 /config 和 /plugin 等对话框中的选项卡栏在狭窄终端中破坏标题和选项卡标签中字的问题；不适合的选项卡现在会整个移动到下一行
  • 修复了滚动到最后一个型号后 /model 选择器在列表下方显示“+1 型号”的问题；计数现在仅涵盖可见行下方的模型
  • 修复了 /keybindings 为页脚操作编写退格键和删除绑定的问题，该操作对生成的 keybindings.json 没有任何作用
  • 修复了反弹代理面板关闭键（footer:close）在您正在查看的代理行上键入“x”而不是其自身的问题
  • 修复了 vim 模式 . 不重复快速键入的文本（例如通过 ssh 或在 tmux 中）或在没有括号的情况下粘贴的文本，并且在不键入任何内容的情况下重复更改后将提示保留在 INSERT 模式（例如 cw 然后 Esc）
  • 修复了 vim 模式下将光标留在最后一行的 dd 或提示末尾的 yy 之后的图像占位符的左括号上，其中 r 或 x 会破坏或删除图像
  • 修复了在终端重新获得焦点并在短暂的安全延迟重新启动之前回答远程控制启用提示时按下的按键
  • 修复了在主目录中启动 Claude Code 时切换渲染器或更新后第二次出现的工作区 trust 对话框
  • 修复了从项目外部符号链接到 .claude/rules 的规则被跳过，而不会显示外部导入批准提示；从项目外部符号链接的 .claude 目录现在要求相同的批准
  • 修复了来自市场、claude.ai 和 npm 的插件通过受管理的 allowManagedPermissionRulesOnly 下的 allowed-tools 预先批准自己的工具；仅来自官方 Anthropic 来源或管理设置的来源保证保持预先批准的插件
  • 修复了当无法满足依赖项的版本范围时，第一个 claude plugin install 失败，使插件启用并记录的问题
  • 修复了当挂钩也写入 stdout 时调试日志会删除失败挂钩的 stderr，并且对于没有输出的失败挂钩不记录任何内容；失败的钩子现在也会记录它们的状态代码
  • 修复了 Eliitation 和 EliitationResult 挂钩返回的 {"decision":"block"} 被忽略的问题；它现在 declines MCP 引发，如退出代码 2 所做的那样
  • 修复了在没有 SendMessage 工具（例如 Claude Desktop）的情况下启动的会话仍被告知用它向其他会话发送消息的问题
  • 修复了当排队消息被拉回终端提示进行编辑时，通过远程控制从克劳德应用程序发送的照片丢失，以及光标为没有标题的照片移动一个字符的问题
  • 修复了在自动使用限制等待期间输入消息的问题，当该回合再次达到限制时，等待将脱离“在使用限制下自动继续”设置的控制
  • 修复了向已使用最高 Max 套餐的用户建议 /upgrade 的使用限制警告；当 /usage-credits 可用时，警告和 /upgrade 本身现在指向 /usage-credits
  • 修复了当会话运行 Claude Code 无法识别的模型 ID（例如代理后面的自定义模型）时，Claude API 上的 Explore 子代理切换到 Opus；现在探索继承了该模型
  • 修复了自定进度模式下的 /loop 状态更新经常不会显示的问题，因为克劳德只在推理中写入它们；克劳德现在将每次更新以及循环停止时的结果写入可见文本
  • 修复了从 Claude 桌面应用程序在 macOS 或 Linux 上创建的 git 工作树启动时 /ultrareview 无法上传工作树的问题
  • 修复了当工作目录被拒绝写入并包含拒绝读取目录时，沙盒 Bash 命令无法在 Linux 上启动的问题
  • 修复了工件数据库写入结果，告诉 Claude 每个查看者都会看到对查看者的私有 data/users/ 子树的写入，并为 as_level 添加了“查看”级别
  • 修复了克劳德应用程序网关对来自其身份提供商列出了许多组的登录的每个请求应答 431 Request Header Fields Too Large 的问题；它现在接受最大 256 KiB 的请求标头
  • 改进了使用限制等待：使用积分选项的限制状态和倒计时现在在提示下显示为一个块，并且限制消息不再重复倒计时
  • 改进了 Claude 在没有前缀的 Chrome 工具中调用时出现的“没有此类工具可用”错误：它现在命名要调用的工具
  • 改进了监视器事件行，以显示每个事件打印的内容，而不是重复描述，并在每个事件后停止重复未更改的“等待 N … 完成”行
  • 改进了工作流工具沙箱强化，以防止异步脚本挂钩引发的错误
  • 通过仅构建设置文件实际使用的设置架构部分来改进启动时间和内存使用
  • 改进了 /claude-api：hillclimb 不再花费时间进行提示改写太小而无法进行评估，并且您在 report.html 旁边请求的额外页面将构建为一个本地文件，不会从网络加载任何内容
  • 改进的列表，例如 /tasks、/copy 和 /hooks：每个名称后面的详细信息现在在适合时排列在一列中，否则位于右边缘
  • 改进了 claude plugin marketplace add，以说明何时替换已从不同来源以相同名称添加的市场，以及如何撤消它
  • 改进了当托管设置需要登录（forceLoginMethod 或 forceLoginOrgUUID）并且配置了 API 密钥、令牌或 apiKeyHelper 时的启动拒绝：它现在命名正在使用的凭据、设置位置以及如何删除它
  • 改进的自动内存加载：模仿 Claude Code 自己的标记的隐形字符和标签在 MEMORY.md 中被中和，并在到达 Claude 之前调用内存注释
  • 改进了 claude remote-control：在您还没有 trust 的文件夹中，它现在要求终端上的工作空间 trust 而不是退出
  • 改进的神器页面：克劳德将其设计计划写入页面而不是回复，并使用您已经给出的名称作为页面标题
  • 改进了 Artifact 工具，以便当 Claude 获得 claude.ai 聊天或项目链接、聊天中的工件或其本身的工件 ID 时，它会请求正确的链接或内容，而不是停止
  • 在每个计划和提供商上，将交互式终端和 VS Code 会话更改为在未配置权限模式时以自动模式启动； permissions.defaultMode 仍然覆盖它
  • 将 Ultracode 更改为 /effort（Tab 或 /effort ultracode [on|off]）中自己的切换：它不再强制 xhigh 努力并保持在任何努力水平
  • 更改了响应中途连接断开后的重试，以便与请求的其余重试共享一个预算，因此失败的请求会更快放弃
  • 更改了十四行诗模型的防护措施标记消息以解释其发生原因并提供编辑和重试时显示的通知
  • 更改了使用 ANTHROPIC_DEFAULT_OPUS_MODEL 或 modelOverrides 固定 Opus 模型的会话中的安全相关模型开关：在 Anthropic API 上，API 现在选择要切换到每种标志的模型，而不是固定模型
  • 更改了非交互式第一回合，即使 CLAUDE_CODE_MCP_STARTUP_WAIT_MS 为 0，仍等待最多 2 秒来连接由 --allowedTools 或 mcp_tool 挂钩命名的 MCP 服务器
  • 将 /recap 更改为 decline，当它从聊天线程（包括您自己的）或例程或 Webhook 中继到达时，会立即发出通知；在终端、Claude 应用程序、远程控制、-p 或 SDK 主机中输入，它会像以前一样运行
  • 更改了 /artifacts，使其在标题旁边显示带有单字标签（全部、我的、共享）的过滤器选项卡，使用与 /config 和 /plugin 相同的选项卡栏
  • 更改了工件发布以拒绝网络共享（\\host\share 路径或 /net 自动挂载）上的文件，除非该文件位于使用 --add-dir 添加的映射网络驱动器上
  • [VSCode] 在每个提示和响应上方添加了一个可选时间，并在日期变化处添加了日期线（Claude Code：显示消息时间戳设置，默认情况下关闭）
  • [VSCode] 在管理插件行中添加了插件加载错误和注释，并带有弹出窗口以禁用、卸载或复制错误
  • [VSCode] 在 Effort 滑块下方添加了 Ultracode 开关，取代了滑块的 Ultracode 停止点；模型药丸在任何努力水平下都会显示“·Ultracode”
  • [VSCode] 修复了在保存编辑的文件之前从“内存”对话框重新启动克劳德的问题
  • [VSCode] 修复了一个恢复的选项卡打开另一个 Claude 进程仍然打开的对话；现在它首先询问
  • [VSCode] 修复了当子代理正在工作或从视图中修剪该部分的第一步时展开的焦点视图部分自行关闭的问题
  • [VSCode] 修复了在聊天中输入 /model 和输入打印使用文本而不是打开模型选择器的问题
  • [VSCode] 修复了 Vertex、Bedrock 和 Foundry 上的 /feedback 在按下“发送”后被拒绝的问题；报告现在已保存在这台计算机上，就像终端一样
  • [VSCode] 修复了窗口重新加载后登录等待 Python 扩展长达一分钟的问题
  • [VSCode] 修复了重新启动扩展后停止响应的 Claude Code 选项卡：它们现在重新打开对话
  • [VSCode] 修复了来自另一个代理的消息，没有记录的发件人在聊天中显示为原始 XML
  • [VSCode] 修复了来自其他代理、会话或频道的消息在重新加载后消失的问题
  • [VSCode] 修复了用户自己的 /mcp、/config 或 /settings 命令被扩展对话框隐藏的问题
