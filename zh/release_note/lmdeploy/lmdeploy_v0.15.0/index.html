lmdeploy v0.15.0

这个项目是干啥的：一个把大模型跑成在线服务的推理部署工具，支持MoE、FP8和拆分式服务，给需要高效部署模型的开发者用。

变更架构图

亮点

  • 新模型覆盖 — 重头戏是 DeepSeek V4 支持（#4554），加上围绕 Qwen3.5 的大量工作：fp8 MoE 限定为 qwen3.5（#4740）、MTP recurrent-state 往返（#4744）、零中心 RMSNorm 修复（#4790），以及 Ascend-A3 上的 Qwen3.5 MTP（#4721），此外还有 GLM MTP（#4749）和通用的 tensor copy / 架构感知的 Gated Delta Rule kernels（#4757）。如果你想服务这些架构中的任何一个，这个版本就是它们落地的版本；如果你只跑老的、已支持的模型，就没有为新模型升级的理由。

  • 吞吐与延迟优化 — 长上下文和 MTP 前缀缓存命中（#4688）、面向投机解码的 guided decoding（#4559，并在 #4726 中正确集成了 XGrammar）、新的 turbomind 内存分配器 / 对象缓存 / 调度器集成（#4717）、memdecode（#4767）、TTFT 优化（#4695），以及 AgRs all2all 后端（#4739），都瞄准吞吐和首 token 时间。对延迟敏感或高并发服务值得升级；前缀缓存还得到一处正确性修复（#4700），陈旧缓存行为也改善了。

  • 破坏性变更——需要迁移 — 有几个接口被移除，而不只是新增：--disable-vision-encoder 被移除，纯文本 VLM 推理改用 --language-model-only（#4716）；交互式聊天被移除，推理现在显式无状态（#4730）；弃用的模型支持被砍掉（#4693）。新的 --generation-config CLI 用于设置服务端采样默认值（#4708）。任何脚本化这些 flag、依赖聊天会话状态或服务弃用模型的人，必须在升级前适配；这是最应该暂缓并规划迁移的一组用户。

  • 硬件/平台细节 — Ascend 获得 ascend-A3 上更精细的多节点支持（#4711），线性注意力强制 blksize=128（#4705）以及 head_dim=256 时强制（#4723），还有 Ascend-A3 上的 qwen35 MTP（#4721）。NVIDIA 侧包括 SM90 GDR PDL 和 CP 矩阵布局修复（#4787）、带旧 kernel 覆盖的 GDR CP 控制（#4779）、triton 3.5.1 的 _reduce_split_kernel 修复（#4696）和 triton fp8 all-reduce group 修复（#4702），以及多 DP 单机启动的 HCCL 端口冲突修复（#4722）。dlblas 从 lmdeploy 中移除（#4682）。Ascend-A3 和 SM90 用户在这里获益最多。

  • 稳定性修复与结论 — 一大批 bug 修复涉及块布局中的 INT8 KV 量化参数偏移（#4764）、异步 TP 关闭死锁（#4770）、chat completions 的唯一 chatcmpl id（#4707）、恢复 turbomind 指标（#4768）、turbomind 健康检查的假阴性（#4745），以及批处理 completion 的会话 id 冲突（#4774）。总之：这是一次有实质内容的发布，不是空操作或纯元数据重打标签。需要 DeepSeek V4/Qwen3.5、更好的缓存/延迟或这些修复的用户应升级；只有依赖被移除的 flag、有状态聊天或弃用模型的用户才需要暂缓或分阶段升级。
