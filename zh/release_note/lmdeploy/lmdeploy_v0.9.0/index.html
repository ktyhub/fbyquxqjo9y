lmdeploy v0.9.0

这个项目是干啥的：一个把大模型跑成在线服务的推理部署工具，支持MoE、FP8和拆分式服务，给需要高效部署模型的开发者用。

变更架构图

亮点

  • 拆分式服务（PD / Distserve）是重头戏 — PR #3304 带来了 “LMDeploy Distserve”，如今有迁移流控（#3599）、异步迁移（#3610）以及 DSV3 PD 拆分修复（#3547）作支撑。如果你运行 prefill/decode 分离的集群，这是第一个拥有连贯且持续维护的技术栈、而非实验性实现的版本；从配套修复的数量看，这一特性显然是本次发布的重点。

  • FP8/MoE 量化大幅扩展——请检查你的 checkpoint — 增加 Qwen3 MoE 的运行时 bf16→FP8（#3631）、TurboMind 的 FP8 MoE（#3601）、InternLM3 dense FP8（#3527）、分块 FP8 TMA（#3470），以及溢出（#3650）和零 scale（#3652）修复。迁移/行为注意点：分块 FP8 的 scale 名称被改过（#3532），请验证现有分块 FP8 checkpoint 是否仍能加载，或计划重新量化；另请注意默认量化行为的修复（#3640）。

  • 运行时控制与服务生命周期迎来实质升级 — 客户端现在可以通过请求终止 API 服务（#3533），PyTorch 后端（#3535，含 #3562 中的 dp=1）和 TurboMind 后端（#3566）都支持从 API 服务更新模型参数。另外，tool-call-parser 与 reasoning-parser 不再互斥（#3550），Ascend 现在默认使用 Ray 分布式后端（#3603）——如果你把工具调用与推理模型结合使用，或依赖旧的默认行为，这点很相关。

  • 模型覆盖向 Qwen3 和 VLM 拓展 — 为 Qwen3-MoE 加入 EPLB（#3582，并在 #3591 中合并了 EPLB+microbatch），支持 Qwen3 的 /think / /no_think 与 enable_thinking（#3564）并附带 chat 模板修复（#3641），新增 InternVL3-8B-HF（#3633），以及 Qwen2.5-VL 的 AWQ（#3559）和 AWQ kernel 修复（#3618）。多个 Qwen3 与 VLM 的 bug（gemma3vl 批量推理 #3592、qwen2 #3614、VLM 运行时量化 #3644）也被修复。

  • 升级结论：多数人值得升，但不是空操作 — 这是一次功能性的大版本发布，不是重打标签或纯元数据变更。如果你需要 Qwen3/MoE 服务、FP8、PD 拆分、针对 dp>1 的多 API 服务启动（#3414）或运行时参数更新，应升级。如果你在旧的分块 FP8 scale 命名下服务稳定的 dense 模型，并且依赖此前 tool-call-parser/reasoning-parser 的互斥性或 Ascend 旧的默认后端，可以有理由跳过——但这些行为已经改变，上线前应测试。
