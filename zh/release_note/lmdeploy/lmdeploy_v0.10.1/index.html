lmdeploy v0.10.1

变更流程图

亮点

  • 模型支持 — 新增 GLM-4.5、InternVL3.5-Flash、SDAR 和 gpt-oss，包括通过新引入的 openai_harmony 包在 /v1/chat/completions 中支持函数调用与推理响应。需要这些模型就升级；否则仅此一项并不迫切。
  • GPU 与安装支持 — 新增 ROCm 安装指引和 AMD GPU 的 FlashAttention 兼容性、CUDA 12.8 wheels，以及 RTX 50 系列安装说明。AMD 和 CUDA 12.8/RTX 50 用户有明确的升级理由；已受支持 GPU 的用户可以跳过这部分。
  • 输出与 API 行为 — 新增 stop_str 和 token_id 返回；启用 include_stop_str_in_output 时，还会返回最后一个 token 的 logprobs、logits 和 last_hidden_states。这对需要精确停止边界数据而非仅生成文本的客户端很重要。
  • 性能与可靠性 — 新增 FP8*(B)F16 GEMM 并优化 AsyncEngine；修复覆盖 Triton 3.4.0、LongRoPE、无预热的 CUDA graphs、SequenceManager::Erase、PyTorch chat CLI 设备参数，以及 InternVL 长上下文准确性。撞上这些问题的生产用户应升级。
  • 兼容性变化与建议 — 服务 VLM 模型时前缀缓存现在被禁用，cudnn 和 NCCL_LAUNCH_MODE 被移除，引擎构建不再包含 tokenizer，服务依赖也发生变化。没有记录明确的破坏性变更或迁移步骤，但依赖这些行为的自定义集成应重新测试，并对 VLM 吞吐做基准测试。不受这些修复影响的稳定部署可以合理跳过此补丁。
