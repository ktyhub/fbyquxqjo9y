lmdeploy v0.12.2

这个项目是干啥的：一个把大模型跑成在线服务的推理部署工具，支持MoE、FP8和拆分式服务，给需要高效部署模型的开发者用。

变更架构图

亮点

  • 模型覆盖与 FP8 服务 — 新增对 glm5、Qwen3.5、GLM-4.7-Flash 的支持，TurboMind 可处理 Qwen3.5 dense + MoE 模型；在线 FP8 量化现在覆盖 Qwen/Internlm/Llama 的 dense 与 MoE 变体。使用这些模型的用户应升级，其他人则没有立即可得的模型支持收益。
  • 性能与显存 — 降低 MLA KV-cache 占用、加速 MLA kernel、新增 recurrent_gated_delta_rule kernel，并支持 Qwen 与 InternLM 模型使用 FP32 头。重度使用 MLA 和大规模部署的场景应评估升级带来的吞吐与容量提升。
  • Transformers 与环境兼容性 — 改进与 transformers 5.0 的兼容性，修复 transformers >=5 下的模型问题，并把 Docker 镜像从 CUDA 11 更新到 CUDA 12.4 → 12.6。迁移提示： 锁定旧 CUDA 镜像或 transformers 版本的用户可能需要更新环境；更新日志没有给出最低依赖版本。
  • 稳定性与服务修复 — 修复了鉴权、会话关闭、请求中止异常、InternVL AWQ 量化配置解析、XGrammar bitmask/null 处理，以及 V100 上 Qwen3.5-0.8b 的崩溃。撞上这些问题的部署应升级；无关负载可以放心跳过，除非能从性能或兼容性改动中受益。
  • 生成控制与测试 — 新增重复 n-gram logits processor 和投机解码测试。需要基于 n-gram 的重复控制的用户有了明确的升级理由；仅增加测试覆盖本身不构成升级动力。
