lmdeploy v0.18.0

小版本 发布时间2026年9月28日 来源InternLM/lmdeploy 英文原文

lmdeploy v0.18.0

变更流程图

亮点

  • 服务 API 能力 — 除输出 logprobs 外新增输入 logprobs、工具参数的增量流式传输、checkpoint-engine 权重更新，以及仅请求的缓存使用量指标。这些改进了评估、交互式工具调用 UI、在线模型更新和缓存可观测性。
  • 性能与模型覆盖 — 扩展了 SM90 量化 GEMM，统一 TurboMind linear 执行，新增分段 CUDA graph prefill 以及修订的 MoE FFN 放置/分片。还为 Qwen3.5 加入 dflash，并在 Ascend 上支持 GLM-5.2。AWQ W4A16 后端明确是原型，且更新日志没有给出实测加速，所以性能敏感型部署应做基准测试。
  • 服务可靠性 — 修复包括 tool_choice='required' 和 Intern-S/GPT-OSS 工具处理、在线 FP8 量化后的 MLA KV-B 初始化、GLM-5.2 MTP FP8 排除、多模态预处理，以及视觉 workspace 溢出。同步 ZMQ 断连和降低 health-RPC 调度延迟也改善了长期运行的分布式服务。
  • 破坏性变更/迁移 — 旧版 OpenAI API 客户端被移除；依赖它的调用方必须迁移到 OpenAI SDK。TurboMind 现在要求 C++20 构建支持，且安装必须满足 xgrammar < 0.2.5.post1。自定义 CacheEngine、后端 builder 或 scheduler 集成应重新测试，因为它们的内部和 API 边界经过了重构。
  • 升级建议 — 使用工具调用、多模态服务、在线 FP8/MLA、MoE 多 GPU 部署、SM90/Ascend、logprobs 或在线权重更新的用户应升级。稳定的纯文本负载且没有自定义集成的用户可以跳过这一轮；这是一次有实质内容的发布，不是重打标签或纯元数据更新。
