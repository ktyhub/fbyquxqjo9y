lmdeploy v0.13.0

这个项目是干啥的：一个把大模型跑成在线服务的推理部署工具，支持MoE、FP8和拆分式服务，给需要高效部署模型的开发者用。

变更架构图

亮点

  • 模型与硬件支持 — 新增 Qwen3.5 35BA3B 的 Ascend 支持（#4485）、InternS2 Preview（#4575），并优化 Blackwell GPU 上使用 cublasGemmGroupedBatchedEx 的 Qwen3.5 MoE 推理（#4490）。混合模态处理和更多消息项类型也得到扩展。与部署这些特定模型或硬件栈的用户最相关。
  • 服务 API 与输出解析 — 新增 Anthropic 兼容端点（#4538），并在 OpenAI 路由上暴露 repetition n-gram 参数（#4522），拓宽了集成选项。推理/工具调用解析器经过重构，包括新的 XML parser 抽象（#4548）；非流式响应现在也能正确剥离 <think> 标签（#4576）。现有客户获得了新选项，没有声明迁移要求，不过自定义 parser 集成应做回归测试。
  • 安全与请求生命周期行为变化 — 新增显式的 trust_remote_code 控制（#4511），加载远程代码的部署应检查其配置。过期会话或休眠引擎上的请求现在会被拒绝，休眠会取消活跃请求并阻止新输入（#4496、#4541）。用户提供的 session_id 会被映射到内部 ID（#4523）。这些都是值得验证的行为变化，但更新日志没有记录明确的破坏性 API 移除。
  • 性能、缓存与正确性 — 新增 kernel block-size 支持并修复了缓存大小/布局的边界情况、块偏移 padding、Ascend 前缀缓存，以及高解码负载下的 prefill 饥饿问题。还解决了 Ray 内存泄漏、MoE 排序开销、seed=0，以及若干 MTP 问题（含 FP8、RL 和张量并行）。运行长生命周期 Ray 作业、重度使用 KV-cache 的负载或 MTP 配置的用户有明确的升级理由。
  • 升级建议 — 这是一次有实质内容的发布，不是重打标签或纯元数据更新。使用 Qwen3.5、InternS2、Blackwell/Ascend 后端、Anthropic 兼容服务、高并发推理，或受影响的缓存/MTP/Ray 路径的用户应升级；Transformers ≥5.0 用户也受益于 lite-module 修复（#4488）。无关且稳定的负载大概率可以跳过，因为发布说明没有指出强制迁移步骤。
