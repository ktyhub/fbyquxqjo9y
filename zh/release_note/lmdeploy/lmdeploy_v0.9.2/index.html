lmdeploy v0.9.2

这个项目是干啥的：一个把大模型跑成在线服务的推理部署工具，支持MoE、FP8和拆分式服务，给需要高效部署模型的开发者用。

变更架构图

亮点

  • 放弃 Python 3.8、加入 3.13（破坏性，需迁移） — remove python3.8 support and add python3.13 support（PR #3638）意味着仍锁定 3.8 的人必须在升级前迁移环境。配套改动也落地：UT/CI 升级到 py310（PR #3718），并修复了 lmdeploy-builder 镜像中 py313 环境创建失败的问题（PR #3739）。本版本没有标记其他 API 破坏性变更。

  • 新硬件与 attention kernel — 这是性能方面升级的主要理由：FlashAttention 3 支持（PR #3623）、“初步支持 Blackwell（sm_120a，RTX 50 系列）“（PR #3701）以及 pytorch_engine_qwen2_5vl_sm120（PR #3750），还有放宽 FP8 张量并行要求（PR #3697），扩大了 FP8 TP 的部署范围。另有针对 SM7X kernel-meta 检索的修复（PR #3746），覆盖较旧的 GPU。

  • 视觉语言与模型覆盖扩展并得到修正 — Qwen2/2.5-VL 现在可在 turbomind 引擎上运行（PR #3744），并适配 transformers>=v4.52.0（PR #3771）；InternVL 获得 PyTorch 支持以及 turbomind/norm 修复（PR #3765、PR #3769、PR #3756）；并支持 vlm hf_overrides 与 Qwen3-MoE YaRN（PR #3757）。对于 Qwen3 dense，有一项修复避免量化 qk norm（PR #3733）；DeepSeek-R1-0528 修复了未定义的 seq_aux 属性（PR #3728）。Qwen2/2.5-VL、InternVL、Qwen3 和 DeepSeek-R1 用户应升级；受影响模型之外、在稳定 0.9.1 上的用户可以跳过这些特定改动。

  • 生成/服务行为与配置变化值得验证 — 计算 max_new_tokens 和判定 finish_reason 的逻辑修复（PR #3727）以及新增的 limit max_session_len 上限（PR #3751）可能改变停止条件和会话行为，升级时请回归测试负载。易用性新增：HF config.json 现在可通过 CLI 覆盖（PR #3722），并加入指标支持（PR #3534）；修复覆盖带工具调用的 chat 模板（PR #3773）、VL “nothink” 模式（PR #3776）、PD 拆分重复下架（PR #3762），以及 scheduler_stats 中的可变默认值 bug（PR #3730）。

  • 构建/打包变化与内部重构 — turbomind 后端现在直接在 setup.py 中集成和构建（PR #3726），版本解析接受 post-release 版本（PR #3764），RelWithDebInfo 成为默认 CMake 构建类型（PR #3774）——如果你从源码构建或锁定 release 标签，这些很相关。内部通过 Refactor linear（PR #3653）和 VL 输入拆分（PR #3699）做了重构；这些不是面向用户的 API，但值得做冒烟测试。这是一次有实质内容的发布，不是重打标签或纯元数据变更：为 Blackwell/FA3/FP8、新 VLM 或模型专属修复而升级；只有在你仍用 Python 3.8（必须先迁移）或处于稳定且不涉及这些模型/硬件的环境时，才可以跳过。
