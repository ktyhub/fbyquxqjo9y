lmdeploy v0.12.3

lmdeploy v0.12.3

变更流程图

亮点

  • 视频与多模态输入 — 现在端到端支持视频输入（PR #4360），并有图像/视频 resize 修复（PR #4478）和 Qwen3.5 PyTorch 多模态推理修复（PR #4430）作支撑。如果你此前被视频理解卡住或撞上 resize bug，这个版本就解除了阻碍；generate 端点和多轮聊天也得到正确性修复（PR #4432、PR #4438）。

  • Qwen3.5 是模型工作的重头戏 — 这个版本实际上让 Qwen3.5 趋于稳定：Volta 支持（PR #4405）、整体优化（PR #4434）、内置 MRoPE（PR #4393）、fp8 修复（PR #4470）、MTP 支持（PR #4437），以及针对 Qwen3.5 工具调用的拆分/工具调用 JSON 参数处理（PR #4433）。如果你在生产环境跑 Qwen3.5，强烈建议升级——其中几项是正确性修复，而不只是提速。

  • 破坏性/迁移提示 — tilelang 现在成为仅 Linux 的依赖，与 triton 一致（PR #4469）；依赖它的非 Linux 用户必须调整环境。Docker wheel 准备现在改为分阶段构建并默认使用 Python 3.12（PR #4476），请锁定/核对你的基础镜像和 Python 预期。另请注意 Rope 初始化与设备处理被对齐/统一（PR #4466、PR #4467、PR #4483），这可能改变对 RoPE 敏感模型的数值结果——如果依赖精确输出，请重新验证准确性。

  • 量化与服务可靠性 — TurboMind 新增对 compressed-tensors gs32 的完整支持（PR #4429），并修复了 torch 的 AWQ（PR #4503）和 paged-attention 指针范围（PR #4494），提升量化推理的正确性。分布式方面，Ray API 变得更安全（PR #4455），移除了未使用的远程函数返回值（PR #4422），并修复了使用外部 placement-group bundle 的 worker 排序（PR #4397）；异步引擎取消清理也得到加固（PR #4439）。如果你用 Ray 大规模服务或做模型量化，这些很相关。

  • 值得升级吗？ — Qwen3.5 用户、多模态/视频用户，以及需要安全修复（PR #4447）或 Transformers 5.0+ 兼容性（PR #4435、PR #4418）的人，答案是肯定的。这是一次有实质内容的补丁，不是空操作或重打标签。只有在你是稳定的、非 Qwen3.5、纯文本负载且不暴露于已修复的安全/Transformers 问题时，才可以合理跳过——不过安全修复仍使升级成为更安全的默认选择。
