lmdeploy v0.12.1

这个项目是干啥的：一个把大模型跑成在线服务的推理部署工具，支持MoE、FP8和拆分式服务，给需要高效部署模型的开发者用。

变更架构图

亮点

  • Transformers v5 兼容性 — 这实际上就是 transformers v5 的适配补丁：PR #4303 修复 rotary embedding 处理，PR #4348 修复 transformers v5 下的 qwen3vl。如果你一直因为 lmdeploy 而无法把 transformers 升到 v5，这是升级的主要理由；为此没有声明 API 或迁移变更。
  • 新模型与硬件 — 新增 glm-4.7-flash（PR #4320）以及 interns1_pro 的别名 interns1_1（PR #4334），并为 EP 加入 [ascend] 支持（PR #3696）。只有需要这些特定模型或 Ascend 专家并行时才值得；否则不构成升级理由。
  • 量化与 kernel — Qwen3 量化配置现在可以忽略特定层（PR #4293），新增自定义 noaux kernel（PR #4345）并更新了其检查（PR #4358），smooth_quant 不再依赖过时的 q_linear 引用，改为把量化 norm 移到 CPU（PR #4352）。这些主要对 Qwen3 量化用户有意义，最后一项是真正的健壮性修复，而不只是新增配置面。
  • 正确性与并发修复 — 修复了多处静默输出错误：工具调用解析器的流式游标（PR #4333）、TP 下 guided decoding 的数据竞争（PR #4341）、Attention op 中的负 KV 序列长度错误（PR #4316）、qwen3-vl-moe 长上下文（PR #4342），以及时间序列预处理（PR #4339）。如果你依赖工具调用、TP guided decoding 或长上下文 Qwen3-VL-MoE，应升级——这些会污染结果，而不只是崩溃。
  • 构建/CUDA 与升级建议 — INPUT_CUDA_VERSION 改为 12.6.2（PR #4322），Docker 构建在使用 cu13 时跳过 FA2（PR #4356），FA3 加入了检查（PR #4340）。没有记录破坏性变更或迁移步骤，这是一次有实质内容的补丁，不是重打标签或纯元数据发布。如果你在 v0.12.0 且遇到上述任一痛点，应升级；如果环境稳定、不用 transformers v5 也不需要新模型，可以放心跳过。
