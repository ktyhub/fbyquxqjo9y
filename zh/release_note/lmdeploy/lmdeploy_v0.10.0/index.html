lmdeploy v0.10.0

小版本 发布时间2025年9月9日 来源InternLM/lmdeploy 英文原文

lmdeploy v0.10.0

变更流程图

亮点

  • 新模型覆盖（gpt-oss、GLM-4.x、InternVL） — v0.10.0 为 TurboMind 加入初步的 gpt-oss 支持（#3839），并在 PytorchEngine 中支持 bf16（#3820），背后是新的 MXFP4 GEMM 路径（#3927）以及针对 sm70 与 sm75 的权重转换分发（#3937）。新支持的还有：GLM-4-0414 与 GLM-4.1V（#3846）、internvl3.5（#3886），以及 Ascend A3 上的 InternLM-S1（#3831）。如果其中有你的目标模型，这个版本就是解锁它们的版本。
  • 破坏性变更/迁移——升级前必读 — 若干接口被移除或改变：lmdeploy convert 从 CLI 中移除（#3813），移除了基于 Gradio 的服务（#3829），api_server 交互模式被弃用（#3830），各引擎的 chat.py 被一个通用的取代（#3836），chat 模板改用 tokenizer 的 apply_chat_template（#3845）。两个引擎的响应行为被对齐（#3821，后续修复 #3888）。运行时技术栈升级到 torch 2.8.0 和 triton 3.4.0（#3930），FA 2.8.3（#3936），并调整了默认值（#3921）。请审查所有调用被移除 CLI/API 的脚本，并重新确认依赖预期。
  • 引擎能力与性能收益 — TurboMind 新增权重与 KV-cache 卸载（#3798）、内置指标（#3811）及 Prometheus 客户端（#3792）、改进的前缀缓存（#3835），并支持 cache_max_entry_count >= 1（#3913）。PytorchEngine 新增 sleep/wakeup（#3687）、logprobs（#3852）、OpenAI 兼容的 max_completion_tokens 参数（#3876），以及可用于外部 Ray placement group 的 Ray MP 后端（#3790、#3850）；dlinfer 也加入了 Ray 支持（#3903）。吞吐方面包括 FP8 MoE GEMM 重构（#3795）、简化 GEMM 接口（#3818）、deepgemm 新 API 支持（#3827），以及针对 head_dim=128 的 rmsnorm 优化（#3814）。
  • 值得拥有的稳定性修复 — 值得注意的修复包括：把 level 参数从字符串转换导致的 sleep 端点崩溃（#3897）、/chat/completions 流式模式下重复的 token usage（#3859）、Windows 推理（#3865）、CUDA 12.8 预构建（#3857）、CUDA 12.4 上的 flashmla（#3872）、CUDA 11 Docker 镜像中的 NCCL（#3896），以及 30 多次 wakeup 后的流断言（#3883）。如果你使用 sleep/wakeup 或流式 OpenAI 服务，升级能消除真实的故障点。
  • 应该升级吗？ — 如果你需要 gpt-oss/GLM-4.1V/internvl3.5，想要 TurboMind 的资源卸载或指标，或撞上过任何已修复的流式/构建 bug，就值得升级。如果你依赖 lmdeploy convert、Gradio 服务、api_server 交互模式或旧的 chat 模板行为，请谨慎跳过或分阶段进行——它们都需要迁移。这是一次实质性的功能发布（v0.9.2 → v0.10.0），不是重打标签或纯元数据变更。
