lmdeploy v0.11.0

小版本 发布时间2025年12月4日 来源InternLM/lmdeploy 英文原文

lmdeploy v0.11.0

变更流程图

亮点

  • 推理 API — 新增通过 /abort_request 取消请求（#4092）、/generate 的 image_data 输入（#4086）、文本/图像交错消息（#4141），以及 response_format: json_object 支持（#4080）。这些减少了客户端为取消请求、多模态提示和结构化 JSON 生成所做的绕过方案；流式媒体处理也得到修复（#4130）。

  • 新模型与扩展选项 — 新增 Qwen3 Next 与 Qwen3-VL 支持（#4039、#4093），以及投机解码（#3945）和上下文并行（#3951）。MoE 部署还获得分组路由、路由专家复用、扁平化 bucket 权重同步和 BF16 专家并行（#4120、#4090、#4109、#4144），同时修复了专家并行部署和 RL worker 放置的问题（#4084、#4107）。

  • 破坏性与兼容性变化 — 需要迁移： EngineOutput.num_tokens 被移除（#4088），读取它的客户端、封装代码和指标代码都必须更新；更新日志没有给出替代方案。依赖要求把 pynvml 换成 nvidia-ml-py（#4118），可能影响自定义依赖检查或直接 import。vocab_size 掩码变更被回滚（#4089），依赖该行为的集成应重新审查。

  • 生产可靠性与性能 — 修复针对前缀缓存调度、KV-cache 量化、逐出、LoRA、EP 部署、Qwen 量化和数值正确性，同时优化 RMSNorm、TurboMind sleep level=1 和专家缓存保留。CUDA 13 的包弃用以及 CUDA 11/更旧 SM 的构建检测也得到处理（#4117、#4165、#4175）。指标现在默认启用（#4108），运维人员应考虑到这一监控默认值的变化。

  • 升级建议 — 对于部署新支持模型、大规模 MoE/EP 或并行负载、多模态与结构化输出 API 的用户，或任何受缓存、部署和构建修复影响的人来说，值得升级。稳定的单模型推理用户如果都不需要这些，可以推迟升级——除非依赖 EngineOutput.num_tokens 或旧的 pynvml 依赖，那样升级前需要先做兼容性工作。
