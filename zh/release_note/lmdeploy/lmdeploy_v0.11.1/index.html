lmdeploy v0.11.1

这个项目是干啥的：一个把大模型跑成在线服务的推理部署工具，支持MoE、FP8和拆分式服务，给需要高效部署模型的开发者用。

变更架构图

亮点

  • 新模型支持 — 新增 DeepSeek V3.2（“Deepseek v32”，PR #4026），并大幅加固 Qwen3-VL 支持：vision id（PR #4183）、多模态处理器参数（PR #4196、PR #4200）以及整体改进（PR #4207）。如果你服务这两个模型之一，这是从 v0.11.0 升级过来的主要理由。
  • 安全修复 — PR #4202 封堵了调用 torch.load() 时不安全反序列化的路径。任何加载不可信或社区 checkpoint 的人都应升级；仅此一项就足以支撑这次补丁发布。
  • 调度器/引擎内部重构与吞吐 — PR #4163 重构了调度器和 engine.py，配套改动包括为 dummy 输入预留块（PR #4157）、在 prefill 中构建块 trie 并加入命中率指标（PR #4184）、指标改进（PR #4178）、DP 超时变更（PR #4204）和 FlashAttention 3（FA3，PR #4166）。文档没有说明 API 迁移，但由于触及核心服务内部，上线前应对推理路径做冒烟测试。
  • API 与分布式行为变化 — v1/chat/completions 现在接受 chat_template_kwargs（PR #4201）；请求取消时会返回路由专家（PR #4197）并按 query 长度拆分（PR #4180）；混合 return_logprobs 请求的问题被修复（PR #4222）。Ascend 新增 DP+TP（dptp，PR #4218），Maca 获得 Ray/显存同步修复（PR #4164）——主要与 Ascend/Maca 及数据并行部署相关。
  • 值得升级吗？ — 没有指出破坏性变更或迁移步骤；这是一次常规补丁发布，不是重打标签或纯元数据变更。如果你用 DeepSeek V3.2、Qwen3-VL、量化模型（PR #4212、PR #4229、PR #4230 中有多处 scale-fmt/quant8 修复），或在意 torch.load() 安全修复，就应升级。如果你是稳定的单节点、非量化部署且不需要这些模型，可以放心跳过。
