DeepTutor v1.4.0

小版本 发布时间2026年5月22日 来源HKUDS/DeepTutor 英文原文

发布日期： 2026.05.22 v1.4.0 是 v1.4 系列的 GA 剪裁。它携带完整的 v1.4.0-beta 范围 （自动模式、三层内存工作台、代理深度研究/深度求解/ 问题，LlamaIndex聊天重构，统一能力基础设施+ i18n、Visualize/Animator 合并、新聊天工具、设置拆分、多用户 隔离强化和 deeptutor start / deeptutor init 发射器） 并在顶部添加了一组集中的代理引擎和运行时强化修复。 有关完整的 beta 范围，请参阅 v1.4.0-beta。

自 v1.4.0-beta 以来的新增内容

推理努力 + 提供者思维标志

代理引擎现在将跨提供商的“推理工作”标准化为一个 放置，而不是每个管道重新派生它。

  • build_provider_extra_kwargs 在 deeptutor/core/agentic/client.py 中 解析 reasoning_effort 与 provider_registry，映射 minimal / minimum 到正确的电线形状（DashScope 使用 minimum），并布线 通过提供商思维方式切换的开/关意图 - thinking_type（DeepSeek）、enable_thinking（Qwen 风格）或 reasoning_split。已知推理模型默认为high；的 默认情况下，deepseek-v4-flash 形状的思考被禁用。
  • LLMClientConfig.reasoning_effort 是端到端的管道连接。所有四个 管道 — 代理聊天、问题、研究、解决 — 传递绑定 + 努力成build_completion_kwargs，所以单一的用户级别设置 控制跨能力的推理行为。

严格提供者的工具架构回退

一些与 OpenAI 兼容的提供商拒绝本机函数调用模式 非标准错误。 run_labeled_step 现在检测到该情况，剥离 来自请求的 tools / tool_choice，重试一次，并发出警告 进度事件，以便用户知道调用是在无工具散文模式下运行的。 对于正常接受工具模式的提供者来说，行为没有改变。

重新启动安全转向运行时

服务器或容器重新启动用于将数据库行保留下来 飞行中转弯卡在 running 上，阻止该区域的下一条消息 会话并使 UI 挂在永远不会发生的事件流上 完成。

  • 孤儿检测 - TurnRuntimeManager 现在检查这是否 进程仍然拥有该回合的内存中运行程序。如果没有，则坚持 回合标记为 failed，并带有“”回合因服务器重新启动而中断。 请重试您的消息。”`
  • start_turn 清除之前会话中陈旧的活动回合 创建新回合，以便用户可以在重新启动后立即重试。
  • subscribe_turn 合成终端 error + done 事件 孤立的回合，因此前端干净地关闭其流状态 而不是无限期地等待。

前端 API 基础 — Docker 占位符强化

web/lib/api.ts 从精确匹配切换到子字符串标记检测 NEXT_PUBLIC_API_BASE 占位符，并公开 isApiBasePlaceholder() 以供重复使用。这在 Docker 占位符形状的微小变化中仍然存在 之前漏过并产生了一个空白的设置页面，没有 可见错误。未使用的自动生成的 web/.env.local 随 测试版已被删除。

LLM 配置探针 — 更清晰的状态副本

/settings/llm 探针现在发出明确的“基本 LLM 完成” 成功了。聊天还验证了流媒体和提供商工具 运行时的兼容性。”排烟完成后，让用户知道 探针故意不覆盖流/工具调用路径 聊天练习。

CLI 聊天 REPL — 配置界面与文档对齐

deeptutor chat REPL 表面经过收紧，因此与公众相匹配 文档位于 deeptutor.info。

  • deeptutor chat --config key=value 和 --config-json '<json>' 种子 初始配置，无需先输入 REPL。
  • /config set key value 和 /config set key=value 均可接受； JSON 值（[…]、{…}）通过 shlex 正确解析。
  • 反斜杠连续让您可以一轮发送多行提示。
  • /refs 打印结构化状态快照（会话、功能、工具、 知识库、历史记录、笔记本、语言、配置）而不是一条暗线。
  • deeptutor plugin info <name> 现在也返回 cli_aliases 和 能力 availability 块。

仓库和文档卫生

  • 公共文档站点 (.github/ISSUE_TEMPLATE/docs.yml) 的新问题模板。
  • AGENTS.md 进行了现代化改造，以反映自动模式、工具浇口和 当前的能力阶段。 ——.gitignore覆盖.playwright-cli/；陈旧的 .playwright-cli/ 捕获、.env.example_CN 和 DeepTutor.code-workspace 已删除。

测试

  • 新型 tests/core/test_agentic_client_provider_kwargs.py 覆盖 推理努力+提供者思维方式矩阵。
  • 新tests/core/test_labeled_step_tool_fallback.py锻炼 针对脚本化 client 的工具架构端到端重试路径。
  • tests/services/session/test_turn_runtime_subscribe.py 增加了覆盖范围 用于 subscribe 和 start_turn 上的孤儿运行轮恢复。
  • tests/cli/test_chat_cli.py 添加了 REPL 配置/反斜杠测试和 插件信息合同检查。
  • 新的 tests/cli/test_docs_contract.py 保留公共站点文档 与 CLI 表面同步（链接 + deeptutor … 示例）。
  • tests/scripts/test_docker_compose.py + web/tests/api-resolve-base.test.ts 涵盖新的占位符检测。

升级注意事项

  • 来自 v1.4.0-beta： 直接上车。 PyPI 使用 pip install -U deeptutor 安装 （PyPI 将 1.4.0 标准化为 1.4.0b0）。 Docker用户拉 ghcr.io/hkuds/deeptutor:latest。
  • 推理努力现在从 LLMConfig.reasoning_effort 读取。如果 您之前在 extra_body 中手动设置提供商思考标志， 代理仍然会尊重他们，但建议的路径是设置 reasoning_effort 并让引擎映射它。
  • 重新启动恢复是自动的。升级后，任何现有的 之前崩溃导致的数据库行卡在 running 上 下次会议开幕时最终确定。
  • Beta 工件清理： web/.env.local 由 旧版启动器不再需要。如果你重建了前端 手动使用该文件，在下次构建之前将其删除。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.4.0-beta…v1.4.0
