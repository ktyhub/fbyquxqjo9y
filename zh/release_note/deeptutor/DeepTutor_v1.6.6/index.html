DeepTutor v1.6.6

修订 发布时间2026年9月8日 来源HKUDS/DeepTutor 英文原文

发布日期： 2026.09.08 v1.6.6 是一个修复版本，也是一个异常清晰的版本。通过 v1.6.5 反馈进行研究表明，人们报告的大多数内容都不是回归：v1.6.5 大部分删除了掩盖旧损坏的内容，因此默默地提交失败的答案、报告从未成功过的复制按钮以及自 v1.6.0 以来无法使用的阅读操作都立即变得可见。这些问题及其背后的一批社区拉取请求都已在这里修复。直接插入——无需迁移。

新消息

您提交的答案实际到达

回合已经结束的 ask_user 卡无法再到达后端，因此提交不会执行任何操作。更糟糕的是，当提交被拒绝时，三位作曲家丢弃了你输入的内容，而错误告诉你发送一条新消息——这正是被阻止的事情。两者都是固定的：仍拥有未应答卡的已完成回合保留其地址，而拒绝的应答将作为普通消息重新发送，而不是被丢弃。 自 v1.6.3 起，带有答案图像的笔记本条目根本无法保存 - 插入内容针对 22 个值列出了 23 列，并且每次都会提高 OperationalError。

首次加载明显更轻

生成的品牌图标表（每个商店徽标，大约 95 KB）位于每条路线共享的应用程序外壳块中，以实现一个页脚链接。它已经推出，侧边栏的会话组织 UI 和 Co-Writer 笔记本选择器现在可以按需加载，并且主路由从 305 KB 下降到 203 KB，而预算为 300 KB。没有一条路线不再超出预算。

复制实际上是复制

无论是否有任何内容到达 clipboard，复制按钮都会报告成功，并通过 aria-live 宣布错误成功 - 因此屏幕阅读器用户被告知复制有效，但实际上没有。现在，在第一个 await 之前会探测 Clipboard 访问（过早地花费用户手势津贴是根本原因），并且真正的故障显示为一个。

知识库：名称、上传、空库

可以创建一个以斜杠命名的知识库，然后永远不会删除。验证现在位于管理器上，因此所有八个注册入口点都共享它，并且可以删除已经存在的坏名称。传输过程中失败并显示“无法获取”的大型上传也可以正常工作：代理正在重播 client 的 Expect: 100-continue 标头，undici 会直接拒绝该标头。创建空知识库不再引发进度错误。

合作伙伴可以使用您的互联知识库

将黑曜石保险库、链接索引、WeKnora 或 IMA 分配给合作伙伴过去常常会彻底失败：配置只知道如何复制文件夹，而指针知识库在设计上不知道如何复制文件夹。连接的碱基现在注册为指针，在合作伙伴的库中保持可见，并且可以再次删除。 Obsidian、MarginNote 和子代理基地被故意 declined — 每个都驱动一种专有功能，该功能将接管该合作伙伴的每个回合。 合作伙伴在聊天下载中为提问者提供的文件，并且合作伙伴对话现在显示它来自哪个聊天，因此飞书群组线程不再与直接消息无法区分。

Chat 不再使用它没有的工具

read_source 属于在答案循环之前运行的上下文调查器，而不是循环本身。提示和附加源清单另有说明，因此模型不断尝试通过从未提供的文件工具重新打开 PDF。

推理到达了它缺失的地方

共享代理循环从未捕获一轮的推理 - 该字段在其结果类型上不存在 - 因此在其上构建的表面（包括书籍测验）会显示提供者推理错误而不是内容。现在已经进行了。

Codex登录在Docker内完成

当浏览器无法到达容器的环回回调时，您可以粘贴浏览器登陆的地址并完成登录。粘贴的地址必须与为该尝试注册的重定向 URI 完全匹配，重复的 OAuth 参数将因不明确而被拒绝；它被解析并丢弃，永远不会被提取、存储或回显。目录兼容版本也已提高，因此旧版本省略的符合条件的型号现在出现。

值得命名的较小修复

自 v1.6.0 以来，需要文本选择的四个阅读操作已无法通过鼠标使用 - 在 click 着陆之前，注释弹出窗口解除了工具栏的武装。向导师询问另一种语言是可行的，并且该偏好的浏览器和服务器副本不再相距甚远。 Mastery Path 将 mastery_mode 识别为重新绑定路径的工具。学习者帐户可以再次打开课程。格式错误的 ###heading 文本会在不触及代码围栏内的 #include 的情况下进行标准化。

修复

Moonshot Kimi k3 系列仅命名一次，而不是按发布的 ID 命名，因此 k3-256k 和更高版本保持其温度覆盖；对于不支持的 input[N].status 响应请求被拒绝，在没有它的情况下重试一次并记住型号； LightRAG SDK 从候选版本移至 1.5.7；自述文件概述屏幕截图是最新的。

升级注意事项

运行pip install -U deeptutor； Docker用户拉动ghcr.io/hkuds/deeptutor:latest。没有什么需要迁移。

  • 回滚到 v1.6.4 几乎无法修复这些问题。 大多数这些缺陷早于 v1.6.5；只有知识库命名和掌握路径问题具有真正新的 v1.6.5 表面积。
  • 如果自定义提示或插件告诉应答循环调用 read_source，则将该工作移至上下文调查器 - 循环不会安装它。
  • 英文和中文指南已在deeptutor.info上一起更新。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.6.5…v1.6.6
