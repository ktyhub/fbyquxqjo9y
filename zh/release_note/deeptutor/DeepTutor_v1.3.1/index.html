DeepTutor v1.3.1

修订 发布时间2026年4月28日 来源HKUDS/DeepTutor 英文原文

发布日期： 2026.04.28 v1.3.1 是 v1.3.0 之后的稳定版本。它专注于更安全的 RAG 路由， 更强的嵌入验证、更可靠的 Docker/TutorBot 重启以及 一组小但重要的 Web UX 修复。

亮点

更安全的 RAG 和知识库路由

  • 选定的 KB 现在是 trusted 系统状态 - 聊天 RAG 调用不再让 LLM发明或覆盖kb_name；该模型只看到 query，而 DeepTutor 将其路由到 UI/会话中选择的 KB。
  • 当 RAG 没有 KB 时无静默回退 - 如果启用了 RAG 但没有 KB 选择后，回合会跳过 KB 检索，并显示清晰的进度消息 意外查询过时/默认状态。
  • 默认 KB 别名的处理方式一致 - default、current、 selected 和中文等效项解析为配置的默认 KB 工具调用、文件列表和重新索引 API，而真实的 KB 名为 default 仍然胜过别名。
  • 增量文档添加使用服务层 - 现在添加文件即可 通过 RAGService.add_documents，保持添加/搜索/重新索引行为 相同的提供程序和索引版本路径。
  • RAG 内部结构更容易维护 - LlamaIndex 管道被拆分 分为加载、嵌入、存储、错误和编排的重点模块； 智能多查询检索现在位于 SmartRetriever 中。

嵌入和索引可靠性

  • 嵌入响应在使用前经过验证 - DeepTutor 现在拒绝 删除向量、空值、非数字值、非有限值和 在到达 LlamaIndex 之前尺寸不一致。
  • 连接测试探测批量行为 - 嵌入冒烟测试现在发送 小批量，捕获仅返回一个向量或更改的提供者 输入之间的尺寸。
  • 错误索引失败并显示可操作消息 - 空向量或形状不匹配 检索失败现在返回重新索引提示，而不是暴露低级别 NoneType * float 风格错误。
  • 索引状态在写入期间噪音较小 - 空的正在进行的版本 目录不再将全新的 KB 标记为 needs_reindex，并且清空失败 可能的话会清理版本文件夹。
  • 澄清了嵌入示例 - services/embedding/.env.example 现在记录了完整的端点 URL 语义和具体的提供程序示例 OpenAI、SiliconFlow、Ollama、Cohere、Jina、vLLM、Azure OpenAI、DashScope 和 OpenAI-SDK 型网关。

Docker、内存和 TutorBot 运行时

  • Docker 图像可以公开应用程序版本 - APP_VERSION 被传递 后端和前端运行时环境变量。
  • 共享内存有自己的 Docker 卷 - 现在可以挂载撰写文件 ./data/memory:/app/data/memory；自述文件持久性文档已更新。
  • 内存迁移更安全 - 旧版 SUMMARY.md 和 PROFILE.md 文件 即使目标目录已经存在，也会复制到 data/memory 中，而 现有的目标文件将被保留。
  • 内存刷新是序列化的 - 现在并发配置文件/摘要重写 在锁定下运行以避免写入竞争。
  • TutorBot 重启意图被保留 - 正常的服务器关闭保持每个 机器人的 auto_start 标志在下一次 Docker/主机重新启动时保持不变，而手动 停止仍然禁用自动启动。
  • TutorBot 共享长期记忆 - 启动的机器人代理现在接收 共享内存目录而不是在没有它的情况下运行。

Web 和创作用户体验修复

  • IME 安全消息发送 - 当输入 Enter 时，聊天编辑器不再提交 用于确认中文/日文/韩文输入法候选。
  • 知识列表在聊天中保持新鲜 - 聊天页面重新加载 KB 元数据 焦点、页面显示和可见性更改，因此新创建或重新索引的知识库 无需完全刷新即可出现。
  • Markdown 预览保护伪标签 - 未知的类似 HTML 的标签，例如 <think> 被转义以供显示，同时保留源代码行数 编辑器/预览同步。
  • 共同编写者输出剥离推理标签 - 封闭、别名、归因和 未封闭的 <think> / <thinking> 块将从最终编辑输出中删除。
  • 主题初始化在水合作用之前运行 - 渲染主题脚本 来自服务器，因此在 React 水合之前应用深色/浅色偏好。
  • 知识UI反馈更清晰 - 索引版芯片有更清晰的标签， 解释了失败的空活动索引，以及新 UI 与旧 UI 中的 404 错误 Docker 后端现在建议拉动/重新创建容器。
  • 内存页面反馈更清晰 - 刷新调用区分“勾选、否” 来自真实失败的长期更新”。

启动和 Windows 稳健性

  • CLI/服务器流容忍遗留代码页 - 启动脚本和 API 跑步者使用替换安全文本流来避免 Windows 上的 Unicode 崩溃 语言环境，例如 GBK/CP936。
  • 子进程继承更安全的编码 - web/tour 启动路径设置 PYTHONIOENCODING=utf-8:replace。
  • 生成的前端环境文件是 UTF-8 - start_web.py 现在写入 web/.env.local 具有显式 UTF-8 编码。
  • GHCR compose 提取更新鲜的图像 - docker-compose.ghcr.yml 现在使用 pull_policy: always 为已发布的图像。
  • 文档/语言环境已刷新 - 自述文件持久性注释已更新， 添加了波兰语自述文件链接，并且缺少英文/中文 UI 副本 知识、记忆、TutorBot 灵魂模板和共同作者草稿的标签。

测试

  • 添加/更新了聊天 RAG KB 路由、默认 KB 别名、知识的覆盖范围 文件/重新索引 APIs，嵌入批量验证，LlamaIndex 无效向量 故障、正在进行的索引版本状态、增量添加存储布局、 TutorBot自动启动/共享内存、内存迁移、Windows CLI编码、 IME 键盘处理、Markdown 标签 escaping 和推理标签清理。

升级注意事项

  • Docker 用户应该拉取并重新创建容器，以便 Web UI 和后端 知识 API 保持同步。
  • 如果 KB 通过损坏或更改的嵌入提供程序进行索引，请使用 修复嵌入设置后，从知识页面重新索引。
  • 如果您手动保留数据，请添加新的共享内存挂载： ./data/memory:/app/data/memory。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.3.0…v1.3.1
