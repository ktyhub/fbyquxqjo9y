DeepTutor v1.3.0

小版本 发布时间2026年4月27日 来源HKUDS/DeepTutor 英文原文

发布日期： 2026.04.27

变更流程图

亮点

版本化知识库索引和重新索引工作流程

知识库现在为每个嵌入配置保留向量索引，而不是将一个 llamaindex_storage/ 目录视为整个事实。每个新的索引版本都会记录嵌入签名和元数据，因此切换模型不再需要覆盖以前的索引，并且切换回来可以在签名匹配时重用准备好的版本。

  • 版本化存储布局 - 新索引被编写为带有 meta.json 的平面 version-N/ 目录；旧版根和嵌套 llamaindex_storage 布局对于现有安装仍然可读。
  • 嵌入感知读取和写入 - RAG 搜索、文档添加、管理器统计和删除/清理路径现在通过活动嵌入签名解析存储。如果没有现成的版本与当前嵌入模型匹配，检索将返回一个清晰的 needs_reindex 信号，而不是稍后因不透明存储错误而失败。
  • 后台重新索引 API — POST /api/v1/knowledge/{kb_name}/reindex 根据活动嵌入配置重建 KB，通过现有任务通道流式传输日志，并在匹配的就绪索引已存在时返回 noop: true。
  • 索引状态显示在 UI 上 — 知识库摘要现在包括索引版本元数据、活动匹配状态、嵌入不匹配标志、进度和重新索引准备情况，以便前端可以解释为什么知识库需要重建。

知识管理页面重建

知识页面已从单一屏幕拆分为一个集中的主从工作区，用于日常知识库操作。

  • 专用知识库详细信息选项卡 - 文件、添加文档、索引版本和设置现在作为单独的部分存在，并带有显示提供程序、嵌入模型、默认状态、更新时间和实时任务状态的紧凑标题。
  • 原始文件浏览器和内联预览 - 新的“文件”选项卡列出了 KB raw/ 目录中的文档，并在内联预览窗格中打开它们，重复使用 PDF、图像、Markdown、代码/文本和后备下载的聊天预览管道。文件列表可以折叠以回收预览空间。
  • 重新索引控件和日志 — 索引版本部分显示活动、陈旧、旧版和非活动版本，以及用于重建任务的 one-click 重新索引操作和实时进程日志。
  • 进度和历史挂钩 — useKnowledgeBases、useKnowledgeProgress 和 useKnowledgeHistory 将服务器状态与实时 WebSocket/SSE 进度合并，自动刷新活动工作，并保持最近的创建/上传/重新索引结果可见。

嵌入运行时、提供程序覆盖范围和维度发现

嵌入堆栈围绕特定于提供商的行为进行了收紧，而不是假设每个服务的行为都类似于 OpenAI 的默认端点。

  • 不再有硬编码的 3072 默认值 - 嵌入维度现在以未知/空开始，并在成功测试连接后从提供商响应中自动填充。测试探针故意避免发送 dimensions，因此它会在任何 Matryoshka 截断之前测量模型的本机向量长度。
  • 完整端点 URL 语义 — 基于 httpx 的嵌入适配器现在将 EMBEDDING_HOST / 目录 URL 视为要调用的确切端点，而新的 openai_sdk 适配器保留 SDK 样式的 /v1 基本 URL 行为。 .env.example 记录了 OpenAI、Cohere、Jina、Ollama、SiliconFlow 和 Aliyun DashScope 的具体端点示例。
  • 新的嵌入适配器和绑定 - 添加了官方 OpenAI SDK 嵌入支持、Aliyun DashScope 原生多模式嵌入、SiliconFlow 预设、OpenRouter/自定义 OpenAI-SDK 配置文件、提供商批次限制、多模式提供商标志和每个提供商的 API-key 回退。
  • 多模式嵌入请求 — EmbeddingRequest 现在接受结构化 contents 加上 DashScope enable_fusion； Cohere v2、Jina、OpenAI 兼容网关和 DashScope 通过自己的适配器规则处理多模式有效负载。
  • 更好的提供者错误 - 嵌入失败现在可以保留提供者状态、主体、模型和 URL 上下文，并更清晰地处理 4xx 响应和非 JSON/HTML 网关回复。

LLM 推理流和视觉附件稳健性

推理痕迹和图像附件现在流经更多的提供者路径，减少了特定于提供者的意外。

  • 推理增量 - on_reasoning_delta 通过基本 LLM 提供商合同、OpenAI 兼容流、Azure SDK 流、人择路径和 OpenAI 响应解析进行连接。在正常内容恢复之前，流输出将推理文本包装在 <think>...</think> 中。
  • DeepSeek 推理默认值 — DeepSeek 推理模型模式可以在调用者未指定时自动注入高推理工作，匹配需要显式切换到表面思维输出的提供程序。
  • 视觉 URL 功能标志 — 提供商/模型功能现在区分“支持视觉”和“接受图像 URL”。 Moonshot/Kimi 视觉模型和 Anthropic 风格的适配器会在可能的情况下强制将本地附件 URL 转换为内联 Base64。
  • 本地附件 URL 解析 — /api/attachments/... 图像 URL 可以通过附件存储解析回来，并以 Base64 形式发送给拒绝远程 URL 形式的提供商；未解析的外部 URL 被视为已删除的图像输入，而不是默默地假装已发送它们。

Space Hub、技能标签和个人图书馆用户体验

个人学习工件已收集在侧边栏中新的空间区域下。

  • 空间导航 - /space 重定向到 /space/notebooks 和新的迷你导航组笔记本、问题库、技能和记忆，具有共享的部分标题样式。
  • 笔记本部分 — 可以使用渲染的记录预览来创建、删除、搜索、打开和检查笔记本。保存的 TutorBot、聊天、研究和共同作者输出会收到不同的徽章，并且在元数据可用时可以链接回原始聊天会话。
  • 题库部分 — 测验条目可以按全部/添加书签/仅错误进行过滤、按类别分组、重命名、从类别中删除、添加书签、删除以及在源上下文中打开。
  • 内存部分 — 内存页面移至具有编辑/预览模式的空间，用于摘要和配置文件、手动保存、会话刷新、清除操作、未保存的更改状态和本地化反馈。
  • 技能部分 — 用户编写的技能现在支持 frontmatter 中的标签以及 .tags.json 词汇表。 API 添加了标签列表/创建/重命名/删除端点，UI 可以按标签过滤、管理标签、重命名技能和编辑标签分配，同时保留现有的 SKILL.md 工作流程。

依赖层、TutorBot 调试和 Windows 启动

安装故事已围绕 pyproject extras 进行了重新组织，需求文件保留为 Docker/CI 环境的镜像。这也使得 TutorBot 设置和通道调试不再那么模糊：代理引擎、通道 SDK、Matrix 本机依赖项和核心服务器提供程序导入现在位于清晰分离的层中。

  • 额外层次结构 - .[cli] 现在包括 RAG、文档解析和内置提供程序 SDK； .[server] 基于 CLI 和 FastAPI/uvicorn 构建； .[tutorbot]、.[matrix]、.[math-animator]、.[dev] 和 .[all] 明确分层可选功能。
  • TutorBot 依赖边界 — requirements/tutorbot.txt 现在镜像 .[tutorbot]，依赖于 server.txt，并在 TutorBot 层中保留通道/代理依赖项，例如 cron、MCP、Telegram、飞书/Lark、钉钉、Slack、QQ、Socket.IO、socks 和消息包工具，而不是将它们混合到基础安装中。
  • 矩阵通道拆分 - 矩阵/元素支持有自己的 .[matrix] 额外功能和 requirements/matrix.txt，以及 matrix-nio[e2e]、Markdown 清理助手和用于本机加密依赖项的显式 libolm 设置说明。
  • 运行时依赖项修复 (#391) — loguru 和 json-repair 移至服务器依赖层，因为提供程序核心导入在涉及 TutorBot 之前需要它们。这修复了之前因缺少模块而崩溃的干净服务器安装。
  • Windows 启动器稳健性 (#391、#398) — scripts/start_web.py 现在将后端/前端子进程输出读取为 UTF-8 并进行替换，避免在 Windows 语言环境（例如 GBK）上使用 UnicodeDecodeError。
  • 文档和 CLI 提示 - 自述文件、中文自述文件、CLI 自述文件和 CLI 错误消息现在将用户指向 pip install -e ".[cli]" / pip install -e ".[server]"，而不是旧的需求优先命令。新的 requirements/matrix.txt 镜像了 Matrix extra，并记录了本机 libolm 的先决条件。

错误修复

  • 知识上传/创建诊断（#392、#405） — 知识库初始化、上传和重新索引任务现在通过任务日志传播故障详细信息和堆栈跟踪；当后台摄取失败时，UI 可以显示更丰富的错误，而不是显得什么也不做。
  • KB 名称验证 — HTTP 和 CLI 创建路径现在拒绝类似路径或 URL 保留的字符，同时保留 Unicode 友好的名称，防止无效的 KB 文件夹和不安全的路由。
  • 不区分大小写的文档发现 - KB 目录扫描和 CLI 文档收集现在使用共享文件路由器，因此一致接受 .PDF 和 .MD 等大写扩展名。
  • 更安全的文档文件名 - 上传的文件名被标准化，路径片段被剥离，并且扩展名在验证和存储之前被小写。
  • 原始文件服务安全 — KB 原始文件端点严格解析 raw/ 目录下的路径并拒绝遍历尝试。
  • 模型目录环境覆盖 — .env 值仅在目录看起来仍然原始时同步到目录中，避免用户拥有多个自定义配置文件后发生意外覆盖。
  • 研究报告后备 (#404) — 报告代理的 JSON 后备警告现在使用 f 字符串，因此不应用 % 格式的记录器仍然干净地包含部分标题。

测试套件扩展

  • 知识/RAG — KB 命名、索引版本分配和读取优先级、传统到平面存储兼容性、LlamaIndex 存储布局、原始目录初始化、不区分大小写的文件路由、KB 删除和 API 上传边缘情况的新覆盖范围。
  • 嵌入/配置 - 新测试涵盖测试探针的尺寸自动填充、目录 .env 覆盖行为、DashScope 和 OpenAI SDK 适配器、Qwen3 send_dimensions、URL 透明度、非 JSON 提供商响应和多模式嵌入请求。
  • LLM/多模式 — 新测试验证需要内联 Base64 图像的提供商的推理/视觉能力行为和本地附件 URL 转换。
  • CLI 和验证 — CLI KB 集合和文档验证器测试涵盖大写扩展名、中文文件名和 Windows 样式路径剥离。
