DeepTutor v1.4.2

修订 发布时间2026年5月28日 来源HKUDS/DeepTutor 英文原文

发布日期： 2026.05.28 v1.4.2 是 v1.4.1 之上的稳定和完善版本。 它通过 Visualize 和聊天代理解锁了 Gemini 2.5+，修复了 ContextVar 回归，静默地将经过身份验证的请求路由到 管理工作区，强化推理模型的聊天协议 原生工具调用，在每次聊天中提供流畅的用户体验 表面，并添加了对 Lemonade 本地提供商的支持。

Gemini 2.5+ 推理默认关闭

Gemini 2.5 / 3 默认启用思维并烧毁整个 max_tokens 推理预算，除非 reasoning_effort: "none" 是 根据请求发送。 v1.4.2将该逻辑集中在 reasoning_params.default_reasoning_effort_for，单一来源 所有三个执行路径（OpenAI SDK、aiohttp 后备和推理 kwargs 构建器）。可视化、聊天、解决问题、 配置后代理循环全部停止返回空体 反对 gemini-2.5-pro / gemini-2.5-flash / gemini-3-*。

可视化管道强化

修复了三种独立的故障模式：

  • 每功能 max_tokens 默认值 — Visualize 现在拥有自己的 agents.yaml 中的条目（16k 代币）来自 DEFAULT_AGENTS_SETTINGS，因此现有用户已过时 data/user/settings/agents.yaml 自动拾取较高上限 无需手工编辑。
  • SVG / HTML 根修剪 — 当模型用散文包装其输出时 （“给你：<svg>…”）或在同一条线上发出关闭栅栏 作为结束标签，生成器代理现在修剪到最外面 <svg>…</svg> / <!doctype>…</html> 因此渲染器始终接收 干净的根。
  • 回顾步骤 JSON 模式崩溃 → 优雅的回退 — 大或 复杂的 SVG 偶尔会跳闸 JSON 模式 escaping 在评论中 步骤。 Visualize 现在记录失败，而不是导致转弯崩溃 并发送未经审核的草稿，以便用户仍然看到渲染的 结果。

经过身份验证的请求落在正确的工作空间中 (#485)

在 v1.4.1 中，require_auth 是同步 FastAPI 依赖项。快API 通过 anyio.to_thread.run_sync 调度同步依赖项，这 在请求上下文的副本下的工作线程中运行它们 - 因此安装的依赖项内的 set_current_user(...) 调用 线程上下文中的用户，当 线程返回。然后端点读取未设置的默认值并下降 返回管理工作区，静默路由每个经过身份验证的 用户通过本地管理员的数据读取/写入。 require_auth 和 require_admin 现在是 async def，所以它们 在与端点相同的异步任务中执行 ContextVar 下游随处可见。 HTTP 和 WebSocket 入口点现在共享一个 _install_current_user 帮助器，因此 从令牌有效负载解析的用户对象在各个方面都是相同的 运输。

推理模型+原生工具调用：标签协议已修复

v1.4.1 试图巧妙地利用具有原生特性的推理模型 工具调用支持 - 它告诉他们忽略 TOOL/THINK/ FINISH/PAUSE标签和依靠reasoning_content加 单独使用tool_calls，在run_labeled_step内部进行处理 <think> 前奏和任何传入的工具调用增量都是隐式的 标签分辨率。在实践中，这两种捷径都会造成伤害：当工具 调用以 JSON 形式泄漏到内容流中，而不是真实的 tool_calls delta，没有可修复的标签，并且 循环很高兴地将 JSON-as-answer 视为 FINISH。多圈 推理+工具工作流程要么会在修复时烧毁迭代 重试或提前静默终止。 在 v1.4.2 中：

  • Reasoning + native-tools 系统提示告诉模型 推理显示在单独的跟踪区域中，但形式化 内容流仍必须以以下之一开始 FINISH/TOOL/THINK/PAUSE.
  • run_labeled_step 不再将工具调用增量视为 标签分辨率权威，implicit_think_label 忽略（保留 API 兼容性）。缺失的标签总是会掉落 到 LABEL_UNKNOWN，所以聊天管道的协议修复路径 抓住它，而不是默默地错误转弯。
  • 内联 <think>...</think> 前奏曲实时传输到 推理子跟踪并从返回的正式 text 中剥离 到循环 - 因此答案区域不再泄漏原始提供者 标记。

每个聊天界面的流畅流式传输

rAF 打字机 (useSmoothStreamText) 上周推出 主要聊天现在通过 AssistantResponse 进行连接，因此 预订聊天面板、测验后续选项卡以及任何其他表面 渲染辅助消息都获得相同的帧对齐节奏 在流式传输和已完成消息的无操作传递期间。 同伴修复：

  • 书籍聊天面板和测验后续选项卡将自动滚动移至 useLayoutEffect 并停止使用 scrollIntoView({behavior: "smooth"}) — 平滑的动画与下一帧竞争 快速流期间布局更新并产生可见的抖动。他们 现在在布局阶段做一个 scrollTop = scrollHeight 引脚， 与 useChatAutoScroll 在主聊天中的操作相匹配。
  • 图书聊天面板用 data-chat-scroll-root 标记其滚动条，以便 全局 overflow-anchor: none 规则适用（浏览器的 当代码块时，内置滚动锚定可以对抗手动固定 在光标上方回流）。
  • AssistantResponse 现已被记忆 — 已完成气泡停止 当不相关的流同级更新时重新解析 markdown 父母。

侧边栏重新设计

扩展侧边栏的聊天会话列表移至其自己的列表中 可折叠 Recents 区域具有独立的滚动视口，因此 漫长的历史不再将辅助导航推离屏幕。 “新聊天” 按钮消失了（导航中的 clicking 聊天 已经开始一个新的 会话），以及指向 deeptutor.info 的文档链接 位于页脚中 GitHub 链接旁边。 现在每个会话都会呈现一个确定性的、友好的 Lucide 图标 — 火花、叶子、羽毛、云、水滴、太阳、月亮、火焰、星星等。

  • 所以侧边栏一眼看上去就感觉不同，而无需拖拖拉拉 重新渲染。跑步时会添加轻微的摆动动画；闲置的 保持静止。

柠檬水本地供应商

AMD Ryzen AI / NPU 运行时的新 lemonade 提供程序绑定 （默认基本 URL http://localhost:13305/api/v1）。自动检测者 端口 13305，不需要 API 密钥，在自述文件 Docker 主机中列出 - 网关部分和提供者配置文档中 Ollama / LM Studio / llama.cpp / vLLM。

型号-端点探头荣誉DISABLE_SSL_VERIFY

上下文窗口自动检测现在通过 aiohttp.TCPConnector(ssl=False) 当 DISABLE_SSL_VERIFY 设置时， 与 HTTP 层其余部分的行为相匹配。自签名本地 推理服务器不再回退到默认上下文窗口 只是因为探测器无法验证他们的证书。

测试

  • tests/api/test_auth_contextvar.py — 固定 #485 的回归： 同步 require_auth 会丢失 ContextVar；异步版本 跨依赖边界保留它。
  • tests/services/llm/test_reasoning_params.py — 涵盖 集中式 default_reasoning_effort_for 映射。
  • tests/core/test_labeled_step_think_prelude.py — 更新以反映 新的“标签总是需要的”语义。
  • tests/agents/chat/test_agentic_parallel_tools.py — 验证 推理+本机工具路径仍然可以解决多工具转弯问题。
  • tests/services/config/test_context_window_detection.py — 的 models-endpoint 探针认可 DISABLE_SSL_VERIFY 并通过了 TCPConnector(ssl=False) 到 aiohttp 会话。

升级注意事项

  • 从 v1.4.1 直达：pip install -U deeptutor； Docker用户拉 ghcr.io/hkuds/deeptutor:latest。
  • 如果您之前手动编辑过 data/user/settings/agents.yaml 碰撞 Visualize 的 max_tokens，这个价值仍然获胜。新的16k 默认仅agents.yaml未提及的种子用户 完全可视化。
  • 如果您连接 Gemini 2.5+ 型号并看到空输出或截断输出， 无需更改配置 - 现在默认关闭行为 自动应用。
