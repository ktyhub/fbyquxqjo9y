DeepTutor v1.5.12

修订 发布时间2026年8月13日 来源HKUDS/DeepTutor 英文原文

发布日期： 2026.08.13 v1.5.11 是关于编写答案时发生的情况。这个问题是关于它的材料来自哪里。网络搜索层被重建到一个表上——这就是如何发现悄悄影响结果的三个缺陷的原因——并在其上添加了六个提供商，其中大多数可以从中国大陆访问。第六个文档解析引擎登陆，您轮换凭证的 MCP 服务器现在重新连接，而不是用排除真正原因的一个解释进行回答。直接插入——无需迁移，无需重新索引。

新消息

网络搜索重建，新增六家提供商

提供程序列表已被复制到七个位置 - 后端注册表、运行时配置、设置路由器、CLI 向导、前端目录、i18n 和测试 - 并且它们已经分开了；前端标记 Serper 已弃用，而后端仍然提供它。现在，所有七种技术均源自一张 SEARCH_PROVIDERS 规格表。整合它后，我们发现了三个无声缺陷：Serper 的 num 从未达到 API，因此 max_results 什么也没做； Serper 放弃了其代理配置；而 Jina 根本没有结果数限制。 六家供应商加入了该桌子——豆宝、博茶、智浦、Firecrawl、百度千帆和阿里云IQS。它们出现在“设置”→“目录”→“搜索”中，其凭据字段源自规范，deeptutor init 也提供了它们。豆宝返回的是答案而不仅仅是链接； Firecrawl 添加了整页提取。百度在官方千帆 API 上以 qianfan 的形式回归——旧的 baidu 密钥仍然被弃用而不是恢复。

搜索失败不再导致回合失败

用于结束整个回合的速率限制、超时或无法访问的主机。该请求现在会遍历您的其他凭据搜索配置文件，最后遍历 DuckDuckGo，记录它在顶级 search_fallback 密钥下尝试的内容，以便跟踪显示降级而不是隐藏它。代理随请求一起传输，因此后备仍然可以在请求后面工作。 丢失的 API 密钥被视为相反类型的问题，并且对于六个新提供商来说仍然会立即失败。其中五个是中国托管的，DuckDuckGo 在这些网络上无法访问 - 静默降级会将“您没有配置密钥”变成其他地方的无法解释的超时。

LiteParse 加入解析引擎

第六个文档解析引擎，可在“设置”→“知识库”中选择，以及“仅文本”、“MinerU”、“Docling”、“markitdown”和“PyMuPDF4LLM”。轻量级，无需本地模型下载。使用 pip install deeptutor[parse-liteparse] 安装。

当凭证更改时 MCP 服务器重新连接

轮换存储的凭据不会影响实时连接：存储的配置仍然保留 ${secret:...} 引用，因此其指纹是字节相同的，并且重新加载差异得出的结论是没有任何变化。现在，连接已根据“已解析”配置进行指纹识别，因此帐户将使用刚刚设置的密钥重新连接。另外，工具调用（最常见的是身份验证）期间的传输失败在 SDK 自己的任务组内引发，并使调用者等待完整的工具超时，报告已排除的一个原因。现在，在通话过程中会监视连接，因此真正的错误是模型和用户在通话的那一秒内被告知的错误。 URL 是从这些消息中编辑出来的，因为服务器可以在查询参数中携带其凭据。

CodeBuddy 和 OrcaRouter

另外两个模型提供程序：CodeBuddy/WorkBuddy，它验证 CodeBuddy SDK 身份验证并在需要时启动浏览器登录；OrcaRouter，一个可用于聊天和嵌入的命名 OpenAI 兼容网关。

Codex 保持推理努力，并且可以看到

现在，托管推理工作覆盖会持续存在，而不是在会话之间重置，并且 OpenAI Codex 被标记为具有视觉功能，因此图像可以到达而不是被丢弃。 Gemini 3 和 2.5 Pro 拒绝 reasoning_effort="none"，现在默认为 minimal——这些系列接受的最低级别。

什锦

  • RAG 引文读取结构化有效负载。 引文提取更喜欢 ToolResult.metadata["sources"]，而不是解析文本答案，后者通常根本不会产生任何来源；解析仍然是旧跟踪的后备。
  • 响应工具调用不再交叉调度。 缺少的输出项 id 用文字 fc_0 填充并注册为身份，因此省略其 id 的下一个调用解析为上一个调用的缓冲区并在其名称和参数下运行。占位符不再是别名。
  • 掌握路径独立于聊天会话，因此打开路径不再干扰您所在的会话。
  • 聊天历史记录在加载后沉淀在底部，而不是在滚动中间着陆。
  • 当模型在标记内发出杂散间距时，辅助输出正确渲染 **bold**。
  • 过时的 Typer 额外内容已从两个包装清单中消失。

升级注意事项

pip install -U deeptutor； Docker用户拉动ghcr.io/hkuds/deeptutor:latest。没有架构更改，没有重新索引，没有迁移。

  • GET /api/v1/settings/provider-choices 改变了形状。 search 数组中的每个条目都获得了 requires_api_key、requires_base_url、soft_fallback 和 status，并且该数组现在还返回 exa、baidu 和 openrouter 以及 status: "deprecated" — 故意的，因此 client 可以告诉名称拼写错误导致的过时配置。 DeepTutor在status上自带的UI过滤器；直接呈现数组的任何其他使用者将显示三个已弃用的选项，直到它执行相同的操作为止。
  • get_providers_info() 条目获得了 requires_base_url，达到了 deeptutor config show 和 /api/v1/system 诊断。
  • 无法识别的搜索提供商名称现在回退到 DuckDuckGo 而不是提高。此前，仅 exa、baidu 和 openrouter 被降级，其他未知名称被上调。显式的 none 仍然会引发，因为这意味着搜索已关闭。
  • get_available_providers() 返回的内容比以前多。 它之前实例化了每个提供程序并吞掉了凭证错误，因此它实际上只报告了活动提供程序以及两个不需要密钥的提供程序；现在，它会报告凭据完整的每个配置文件。
  • Brave 在 CLI 诊断中被标记为 Brave，而不是 Brave Search — UI 已经显示了较短的名称。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.5.11…v1.5.12
