DeepTutor v1.2.2

修订 发布时间2026年4月22日 来源HKUDS/DeepTutor 英文原文

发布日期： 2026.04.22

亮点

用户创作的技能系统

引入了完整的 技能 子系统，允许用户从 Web UI 创建、编辑和激活自定义 SKILL.md 文件。每个技能都位于 data/user/workspace/skills/<name>/SKILL.md 下，带有 YAML frontmatter（name、description、可选的 triggers）和 Markdown 正文，该正文在激活时逐字注入聊天系统提示中。

  • 后端 — SkillService (deeptutor/services/skill/service.py) 提供 CRUD + 列表 + 选择，并具有严格的名称验证 (^[a-z0-9][a-z0-9-]{0,63}$)、frontmatter 解析和目录级隔离。 REST API 与 GET /list、GET /{name}、POST /create、PUT /{name}、DELETE /{name} 一起安装在 /api/v1/skills 处。
  • 前端 — 知识管理页面 (web/app/(utility)/knowledge/page.tsx) 中的新 技能 选项卡，带有内联 SKILL.md 编辑器，以及聊天编辑器中的技能选择器菜单。技能可以单独切换或设置为自动模式（将ZZ​​PH15ZZ发送到后端）。 web/lib/skills-api.ts 提供缓存的 client 侧 API 层。 UnifiedChatContext 通过 WebSocket 有效负载携带 skills。

聊天输入性能大修（#351、#360、#362）

通过深层状态共置消除了长时间对话中的输入延迟：

  • ComposerInput — 从 ChatComposer 提取到自己的 memo 组件中，因此频繁的击键重新渲染与编辑器的其余部分（功能面板、参考芯片、工具菜单）隔离。公开命令式 ComposerInputHandle（clear()、getValue()）以避免提升输入状态。
  • SimpleComposerInput — TutorBot 聊天页面的轻量级变体，完全去除 @-mention 和功能开销，修复初始重构后报告的残留滞后。
  • 配置面板上的 React.memo — QuizConfigPanel、MathAnimatorConfigPanel、ResearchConfigPanel 和 VisualizeConfigPanel 现在包含在 React.memo 中； ChatPage 中的父回调与 useCallback 保持稳定。
  • @-mention 帮助程序导出 — shouldOpenAtPopup 和 stripTrailingAtMention 移至 ComposerInput.tsx 作为跨组件重用的命名导出。

response_format 拒绝的自动回退

使用运行时自动恢复路径扩展了 v1.2.1 静态 supports_response_format 防护。当提供程序意外地为 response_format={"type":"json_object"} 返回 HTTP 400（常见于 LM Studio + Gemma/Qwen 样式模型）时，两个 LLM 执行路径现在都会检测到错误，删除该字段，然后重试一次：

  • aiohttp 路径 (cloud_provider.py) — _looks_like_unsupported_response_format 启发式检测 _openai_complete 和 _openai_stream 中的拒绝；匹配时，将在没有 response_format 的情况下重试请求，并缓存（绑定、模型）对。
  • OpenAI SDK 路径 (executors.py) — _create_with_format_fallback 包装 client.chat.completions.create，捕获 BadRequestError 并应用相同的重试 + 缓存逻辑。
  • 运行时缓存 (capabilities.py) — disable_response_format_at_runtime / is_response_format_disabled_at_runtime 记录在模块级 set 中发现的不兼容性，因此后续调用会预先跳过 response_format，而无需支付重试成本。
  • _answer_now.py — stream_synthesis 现在在连接 response_format 之前检查 supports_response_format，从而首先防止快速路径应答流出现 400。

LAN/远程访问修复 (#340)

当本地网络上的另一台计算机打开 Web UI 时，构建时 NEXT_PUBLIC_API_BASE（通常为 http://localhost:8001）将解析为远程浏览器自己的环回而不是服务器。 web/lib/api.ts 中的新 resolveBase() 帮助程序会检测到这种不匹配，并在运行时将主机名交换为 window.location.hostname，因此无论哪台计算机打开页面，apiUrl() 和 wsUrl() 都会到达正确的后端。

侧边栏版本徽章和 GitHub 链接

侧边栏现在显示当前构建版本以及状态指示器：

  • /api/version 路由 — Next.js ISR 端点，用于查询 api.github.com/repos/HKUDS/DeepTutor/releases/latest（每小时重新验证，可选的 GITHUB_TOKEN 用于速率限制空间）并返回最新的标签、名称、URL 和发布日期。
  • VersionBadge — 将 NEXT_PUBLIC_APP_VERSION（在构建时通过 next.config.js / git describe --tags 注入）与获取的最新版本进行比较。最新时显示绿点，过时时显示琥珀色，未知时显示中性。 Clicking 导航至发布页面。
  • Dockerfile — 新的 APP_VERSION 构建参数通过管道传输到 Next.js 环境中，因此基于 Docker 的部署也可以获得准确的版本显示。
  • GitHub 图标 — 添加到折叠和展开侧边栏状态的存储库的直接链接。

Deep Solve 图像附件支持

DeepSolveCapability 现在通过新的 _first_image_url 帮助程序从 context.attachments 中提取第一个图像附件（数据 URI 或 URL），并将其传递给规划器和求解器代理。在内部，PlannerAgent 和 SolverAgent 被重构为通过 BaseAgent 的统一多模式管道使用 Attachment 数据类，而不是手动构建多模式消息数组 - 删除两个相同的 _build_multimodal_messages 辅助函数。当在没有显式 messages 的情况下提供 attachments 时，BaseAgent.stream_llm 还获得了从 system_prompt + user_prompt 构造消息的逻辑，以及在为非视觉模型剥离图像时的日志。

代理聊天管道附件直通

AgenticChatPipeline 中的 _stage_responding 和 _stage_acting 方法现在在构建消息后调用 _prepare_messages_with_attachments，确保用户上传的图像在每个聊天阶段（而不仅仅是初始思考阶段）转发到 LLM。

TutorBot WebSocket 弹性 (#354)

强化 /api/v1/tutorbot/{bot_id}/ws 端点：

  • 自动启动 — 如果机器人已配置但在 WebSocket 连接时未运行，端点现在会自动调用 mgr.start_bot()，而不是立即以 4004 关闭。未知机器人 ID 在关闭前仍会收到 JSON 错误负载。
  • _safe_send 包装器 — 所有 ws.send_json 调用都会通过一个捕获 WebSocketDisconnect / RuntimeError 的帮助程序，防止 client 在中流中掉落时出现未处理的异常。
  • 优雅地断开 — _handle_user_messages 将 WebSocketDisconnect 接在 receive_text 上并干净利落地断开。

设置页面：API 按键屏蔽 (#355)

设置页面上的 API Key 字段现在默认呈现为 type="password"，并带有 Eye / EyeOff 切换按钮。在服务或配置文件之间切换时，可见性状态会重置。

图书库用户界面大修

用完整的 BookLibrary 组件 (web/app/(workspace)/book/components/BookLibrary.tsx) 替换了最小的“选择一本书”占位符，该组件具有搜索、带有章节/页数的状态过滤卡、创建和删除操作以及状态徽章（草稿/大纲/编译/就绪）。 BookSidebar 被简化为带有“← 所有书籍”后退按钮的单书阅读器视图，并且书籍页面现在根据当前视图有条件地显示图书馆或侧边栏。

可视化全屏模式

SVG、Mermaid 和 ChartJS 可视化现在有一个 最大化 按钮（右上角），可以通过 Escape-to-close 在全屏覆盖中打开图形。 HTML iframe 可视化被排除在外，因为它们已经提供了自己的“在新选项卡中打开”功能。

错误修复

  • 嵌入适配器 ConnectError 未重试 (#353) — 将 httpx.ConnectError 添加到 OpenAICompatibleEmbeddingAdapter 中的重试异常元组中，因此嵌入过程中的瞬时连接失败会使用指数退避重试，而不是立即引发。
  • RAG None 嵌入强化 - 当提供程序返回 None 时，CustomEmbedding._aget_query_embedding 和 _aget_text_embedding 现在会引发明确的 ValueError，而不是稍后在相似性计算中崩溃。批处理方法 _aget_text_embeddings 现在从同级向量或配置的 dim 确定后备零向量维度，如果两者都不可用，则引发（防止零长度向量的静默持久性）。
  • KB 删除丢失目录时崩溃 — KnowledgeBaseManager.delete_knowledge_base 现在直接通过 self.base_dir / name 解析路径并处理磁盘上文件夹已被删除的情况，清理孤立的 kb_config.json 条目而不是提升 FileNotFoundError。
  • CLI parse_json_object 空白 — 该函数现在在解析之前去除前导/尾随空白，因此 shell 管道中的尾随换行符不再导致 json.JSONDecodeError。

测试套件扩展

  • TutorBot WebSocket — 2 个新测试，涵盖已停止但已配置的机器人的自动启动以及未知机器人 ID (tests/api/test_tutorbot_router.py) 的 JSON 错误负载。
  • CLI 帮助程序 — 2 个针对 parse_json_object 空白处理和无效 JSON (tests/cli/test_common.py) 的测试。
  • 路由参数 — 针对新 firstParam 实用程序 (web/tests/route-params.test.ts) 的 3 项测试。
  • API 解析基础 — 测试 LAN 主机名交换逻辑 (web/tests/api-resolve-base.test.ts)。
