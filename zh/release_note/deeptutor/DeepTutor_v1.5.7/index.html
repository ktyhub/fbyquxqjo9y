DeepTutor v1.5.7

修订 发布时间2026年7月30日 来源HKUDS/DeepTutor 英文原文

发布日期： 2026.07.31 v1.5.6 的后续版本，为导师提供了 DeepTutor 从未提供的工具：每个人为自己安装的托管 MCP 服务的精选存储，以及聊天代理可以直接调用的 CLI-Anything 目录中的 101 个命令行应用程序。两者都提供了共享部署实际需要的授权和隔离——安装是一项特权操作，运行则不是，并且任何授权人员都不会停留在代码沙箱可以读取的任何地方。直接插入——无需迁移。

新消息

您自己安装的 MCP 商店

学习空间 → MCP 服务 是一个包含 45 个精选托管服务器的存储库，您可以在一个 click 中自行添加，以及您通过 URL 配置的任何远程服务器。每个目录端点都通过向其发送真实的 MCP initialize 进行验证，并且不会联系徽标 CDN - 渲染商店会将您的已安装服务列表发送给每次油漆的第三方。响应 401（Notion、Linear、Sentry、Asana、monday、Canva、Prisma）的服务器使用 PKCE 和动态 client 注册通过 OAuth 2.1 登录；后台重新连接永远不会在同意屏幕上阻塞，它只是报告 needs_auth，以便 UI 可以提供“连接”按钮。静态密钥通过引用存储，并在连接时在内存中解析，因此令牌永远不会出现在显示、由 API 返回或复制到日志中的配置文件中。 stdio 条目被拒绝用于自助服务：命令作为应用程序用户在主机上执行。 MCP 不再在“设置”下配置 - /settings/mcp 重定向到商店 - 并且工具选择器现在将数百个工具折叠到每个服务的一行中。

CLI 导师可以运行的应用程序

学习空间 → CLI 应用程序 目录从两个 CLI-Anything 注册表快照的 101 个工具，聊天代理直接调用已安装的工具，仅在需要时加载该应用程序自己的使用指南。仅管理员可以进行安装，因为 pip install 在应用程序容器中运行程序包自己的 setup.py — 无需多加注意即可实现自助服务。注册表的 install_cmd 永远不会被执行：它被解析为一个计划，其 argv DeepTutor 构建（注册表已包含 curl … | bash），npm 安装脚本被强制关闭，并且无法构建的更新将回滚工作环境。 66 个第一方线束条目固定到一个经过审核的 CLI-Anything 提交；任何指向不同上游的东西都被标记为第三方，因此安装它是一个明智的选择。 应用程序登陆 data/cli-apps，每个环境一个，以只读方式安装到沙箱运行器中。这种分割就是要点：转义的命令不能覆盖应用程序的入口点，并且以后的每个回合，对于每个帐户，都运行替换命令。

沙箱无法访问的凭据

授权一个人的所有内容都移至 data/system — 数据树的一个分支，永远不会绑定安装到运行器中。 Codex OAuth 令牌现在位于 data/system/user-secrets/<owner>/private/openai-codex/ 中，每用户 MCP 配置位于 data/system/user-mcp/<owner>.json 中，旁边还有 MCP 令牌和 API 密钥。现有的 Codex 登录名在首次使用时会重新定位，并且该移动拒绝通过符号链接目录运行，而不是冒险重新定位另一个帐户的存储。 这关闭了真正的暴露，而不是理论上的暴露：运行程序接收到的每用户安装是整个用户根目录，因此 data/users/<uid>/ 下保存的凭证可以从每个其他帐户的沙盒 shell 中读取和写入。

插件工具，按人管理

赠款获得 cli_apps 白名单，其默认拒绝姿势与 MCP 工具已具有的相同：已安装的应用程序是在沙箱中运行的第三方代码，部署安装应用程序与允许每个帐户运行它的决定不同。在这背后，每轮注册表视图将一个用户的提供者工具完全排除在进程全局注册表之外——服务器共享工具名称的两个租户不能再互相干扰——并且拒绝 execute 上未经授权的工具，而不仅仅是在清单中，因为文本协议回退可以合成一个从未提供过的名称。

一个作曲家告诉你窗口有多满

编辑器中的芯片会报告本轮实际在模型上下文窗口中放入的内容以及填充的内容，这些内容是根据已组装的提示块、工具模式和消息列表测量的，而不是重新派生的 - 因此读数不会偏离发送的内容。长时间的对话也会在记录的左侧空白处留下一串勾号，每个问题都会有一个勾号，用于跳回历史记录。

DeepTutor 在手机上

工作区和实用程序布局现在折叠为单列外壳，在小屏幕上带有滑过侧边栏，而不是在视口边缘渲染桌面三窗格布局。

各种修复

  • 作曲家在您发送后保持焦点，并在您切换选项卡并返回时将其取回（#720）。
  • 发布的容器镜像带有出处和 SBOM 证明（#722）。
  • git 安装在应用程序映像中，并安装在运行程序映像中的 Node 运行时中，应用程序安装程序和 npm 打包应用程序的控制台脚本都需要它们。

升级注意事项

从 v1.5.6 插入：pip install -U deeptutor； Docker用户拉动ghcr.io/hkuds/deeptutor:latest。架构或配置不会发生变化，并且现有的 Codex 登录名会继续存在 — 其凭证在第一次解析时会自行重新定位。

  • docker-compose 部署应该重新启动，而不仅仅是重新启动：运行程序服务获得只读的 ./data/cli-apps 挂载，如果没有它，安装的 CLI 应用程序将被编录但无法执行。
  • 在“设置”下配置的 MCP 服务器保持原样 — 部署范围内的 mcp.json 保持不变，仍然由管理员拥有。新商店是一个并行的、按帐户的商店； /settings/mcp 现在重定向到它。
  • 安装 CLI 应用程序仅限管理员使用，分配它是第二步。 非管理员帐户在拨款命名之前看不到已安装的应用程序，这与 MCP 工具和技能已经工作的方式相同。 完整 Changelog：https://github.com/HKUDS/DeepTutor/compare/v1.5.6…v1.5.7
