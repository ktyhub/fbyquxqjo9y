laya v0.4.27

变更流程图

亮点

  • TypeScript 与 Python 行为对齐 — 本版大部分改动是在补齐 laya-ts 与 Python 的行为差距：leafNonEnglish 现在逐行读取叶子节点（#1450）；maxLoaded 用 int() 解析，无法读取的上限不会再静默关闭淘汰（#1457）；Router 自身钩子受 hooksTimeout 约束（#1459）；Router.predictBatch 的回答按 minConfidence 过滤（#1460）；批次按解析后的 checkpoint 分组（#1461）。如果你用 TS binding，这就是升级的首要理由——之前悄悄和 Python 分叉的路径现在行为一致了。
  • 批处理 — TypeScript SDK 新增 HTTP 批量预测（#1471），另有两项加固：分块器无法消费的 batch_size 现在会被拒绝（#1458）；旧版 batch 关键字回退能正确组合（#1468）。把 #1458 当作行为变更：以前蒙混过关的超大或无法消费的 batch 请求现在会被拒绝，调用方升级前应审计自己的 batch_size。
  • ONNX 导出 — opset 现在默认取已安装 torch 实际实现的 opset 的上取整（#1451），避免导出时请求本地 torch 无法支持的 opset。有 ONNX 模型导出需求的值得升级；否则影响很小。
  • 校验与 CPU 性能 — 集成侧现在拒绝过宽的数字答案字段（#1466），补上了校验缺口，可能让以前能接受的输入被拒。另有一项无感的 CPU 加速：把精确注意力窗口和打包的决策头结合（#1467）——不改 API，只是推理更快。
  • 升级结论 — 没有破坏性 API 变更或明确的迁移步骤，也不是重新打标或仅改元数据。依赖 laya-ts、批量预测、ONNX 导出或 CPU 推理性能的建议升级；不涉及这些的纯 Python 用户可以跳过。测试（#1462）和文档（#1463）改动属于内部变更，对运行时无影响。

发生了什么变化

  • 修复（ts）：读取 https://github.com/NandhaKishorM/laya/pull/1450 中 @sathariels 的 leafNonEnglish 中的每个叶行 *修复（onnx）：默认将opset设置为https://github.com/NandhaKishorM/laya/pull/1451中@thread3d所安装的火炬实现的上限
  • 修复（laya-ts）：像 int() 一样读取 maxLoaded，因此不可读的上限无法禁用 https://github.com/NandhaKishorM/laya/pull/1457 中 @aashish254 的驱逐
  • 修复(batch): 拒绝一个batch_size，分块器不能通过@aashish254在https://github.com/NandhaKishorM/laya/pull/1458中花费 *修复（ts）：用hooksTimeout绑定路由器自己的钩子，就像https://github.com/NandhaKishorM/laya/pull/1459中@aashish254的Python所做的那样
  • 修复（ts）：gate Router.predictBatch 在 minConfidence 上给出答案，正如 @aashish254 在 https://github.com/NandhaKishorM/laya/pull/1460 中 Python 所做的那样
  • 修复（ts）：按已解析的检查点对批次进行分组，就像 https://github.com/NandhaKishorM/laya/pull/1461 中 @aashish254 所做的那样 Python
  • test(hooks)：通过行为检查关闭的协程，而不是通过 @ogmanojdev 在 https://github.com/NandhaKishorM/laya/pull/1462 中的 getcoroutinestate
  • 文档（贡献）：@ogmanojdev 在 https://github.com/NandhaKishorM/laya/pull/1463 中说明共享测试列表除了 mcp 之外还需要什么 *修复（集成）：拒绝@mertkayacs在https://github.com/NandhaKishorM/laya/pull/1466中的宽数字答案字段
  • perf(common)：在 https://github.com/NandhaKishorM/laya/pull/1467 中结合精确的 CPU 注意力窗口和 @bahram-po 打包的决策头
  • 修复（路由器）：在 https://github.com/NandhaKishorM/laya/pull/1468 中由 @GoldArowana 编写遗留的批处理关键字后备
  • feat(sdk)：在https://github.com/NandhaKishorM/laya/pull/1471中添加@xinpingzh的TypeScript HTTP批量预测
