chrome-devtools-mcp v0.14.0

小版本 发布时间2026年1月27日 来源ChromeDevTools/chrome-devtools-mcp 英文原文

chrome-devtools-mcp chrome-devtools-mcp-v0.14.0

这个项目是干啥的：把 Chrome 开发者工具通过 MCP 接给 AI，让它能自己调试网页、抓网络请求、分析内存堆栈。给做前端开发和用 AI 写代码的人用。

变更架构图

亮点

  • 移动端与载荷保真度 — new_page 新增 background 参数（#837），支持设备视口和 user-agent 模拟（#798），网络请求/响应体可写入 filePath 而不是内联（#795）。这些共同解锁响应式/移动端 QA，并让大载荷不进入 agent 上下文——相较 v0.13.0 是实打实的能力跃升。
  • 更省、更快的交互循环 — 输入工具可跳过快照生成（#821），节点 id 在快照间复用（#814），长文本输入超时提高（#787）。由于快照主导 MCP 会话的 token 成本和延迟，这直接降低了自动化重度工作流的用量和不稳定性，且无需改代码即可受益。
  • 调试可靠性 — get_console_message 现在包含栈追踪（#740），控制台消息和元素检索错误报告更有用（#844、#845），请求/响应处理加固（#846），导航能处理 beforeunload 对话框（#788）。这些修复了真实的失败模式：如果你遇到过无声的导航挂起或语焉不详的控制台错误，值得升级。
  • Agent 集成与文档（无运行时行为变化） — 新增使用 chrome-devtools-mcp 的 skill（#830），以及 gemini-cli 扩展（#834）、自动连接（#779）、Android 调试（#783）和贡献指南中 evals（#773）的文档。对上手和 agent 采纳有用，但都不改变 server 行为——已接好的团队基本可忽略。
  • 升级结论 / 迁移 — 未列出破坏性变更或迁移步骤；这是增量+修复版本，不是重新打标或纯元数据空版本。如果你需要模拟、filePath 响应体、快照效率或任何上述错误/导航修复，应升级；如果还在 v0.13.0 只做基本 DOM 检查且没遇到这些痛点，可安全跳过。
