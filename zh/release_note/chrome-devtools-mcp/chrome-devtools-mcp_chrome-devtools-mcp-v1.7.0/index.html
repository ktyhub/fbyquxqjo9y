chrome-devtools-mcp v1.7.0

小版本 发布时间2026年8月10日 来源ChromeDevTools/chrome-devtools-mcp 英文原文

chrome-devtools-mcp chrome-devtools-mcp-v1.7.0

这个项目是干啥的：把 Chrome 开发者工具通过 MCP 接给 AI，让它能自己调试网页、抓网络请求、分析内存堆栈。给做前端开发和用 AI 写代码的人用。

变更架构图

亮点

  • 堆/泄漏调试获得一等公民工具 — 新增 get_heapsnapshot_object_details MCP 工具（#2374），快照摘要现在会输出原生上下文（#2375）并可过滤（#2377），加上上下文销毁时（#2428）和加载失败时（#2449）的 worker 清理；内存泄漏技能也更新为使用这些原生工具（#2436）。注意两处对解析响应的人有影响的输出 schema 变化：maxRetainedSize 列被重命名（#2402），get_tab_id 的文本响应现在包含 tab id（#2381）——没有明确的迁移步骤，但需调整下游解析器。
  • 新增遥测（与隐私相关） — 三项新信号会记录 DevTools 数据（#2460）、为每次工具调用附加 is_devtools_open（#2445），并上报调用是否指向 localhost（#2455），背后是新增的 localhost 检查工具（#2454）。在注重隐私或气隙环境中上线前值得审视；它不改变工具行为。
  • CLI/守护进程可靠性 — 现在会校验会话 ID（#2475），当 CLI 版本与守护进程版本不一致时会发出警告（#2461），带连字符的浏览器标志在守护进程惰性启动时能经受参数序列化（#2405），守护进程生命周期得到改进（#2360），陈旧的 CDP 会话不再同步抛错（#2466）。这些针对多会话和惰性启动场景中难以捉摸的失败。
  • 延迟/资源修复 — 消除了操作过程中打开对话框时 180 秒的互斥锁停滞（#2427），按导航限制网络请求保留量（#2435），start_trace 在设置失败时重置其运行标志（#2420），take_screenshot 会释放其元素句柄（#2422）；未模拟视口时会对视口截图降采样（#2380），source-map 惰性加载现在可切换（#2486），已处理过的对话框不再抛错（#2437）。Lighthouse 升级到 13.4.1（#2398）。
  • 结论 — 这是一个实质性的功能与修复版本，不是空操作或重新打标签，且没有明确的破坏性变更或必需的迁移步骤。如果你依赖内存泄漏调试、Lighthouse 审计、带连字符的浏览器标志，或遇到对话框/停滞问题，就升级；稳定在 1.6.0 且避开这些路径的用户可以安全跳过。
