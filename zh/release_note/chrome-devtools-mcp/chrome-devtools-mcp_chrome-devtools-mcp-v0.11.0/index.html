chrome-devtools-mcp v0.11.0

小版本 发布时间2025年12月3日 来源ChromeDevTools/chrome-devtools-mcp 英文原文

chrome-devtools-mcp chrome-devtools-mcp-v0.11.0

变更流程图

亮点

  • 新工具：地理位置、DevTools 问题、--user-data-dir — 三项实质新增：地理位置模拟工具（#634）、将 DevTools 问题纳入控制台工具（#636），以及用于控制浏览器配置文件的 --user-data-dir 标志（#622）。如果你的工作流需要位置模拟、感知问题的控制台检查，或稳定/持久的 Chrome 配置文件，就值得升级。
  • 一处需要迁移的命名变更 — “page content” 被重命名为 “latest page snapshot”（#579），并且当快照中缺少选中元素时，快照现在会附带说明（#593）。任何基于旧 “page content” 标签的提示词、脚本或客户端都必须更新；这是唯一的迁移项，且属于重命名而非能力移除。
  • 改变运行时行为的正确性修复 — wait_for 现在遵守传入的超时（#630，关闭 #624），DevTools 发现会忽略 URL 哈希片段（#608），当所有页面都被过滤掉时服务器不再抛错（#616），错误处理能容忍非 instanceof Error 的值（#618），resolveCdpElementId 也不再抛错（#606）。这些修复消除了挂起和无谓的崩溃，采用风险很低。
  • 谁该升级、谁可跳过 — 如果你使用地理位置、--user-data-dir，或依赖 wait_for 的计时行为，就升级。如果你只是读 README，可以放心跳过：有六次提交仅涉及文档/配置（Antigravity 配置及修复 #580/#605、Qoder CLI #552、VS Code 徽章 #532、browser-url 说明 #613、agy 浏览器集成 #612），对运行时没有影响。
  • 并非重新打标签 — 这是从 v0.10.2 而来的一次真正的次要版本，包含功能和修复，不是纯元数据。唯一的打包变更（#604）防止发布时某些文件中的许可证声明被丢弃——只有当你检查或再分发 npm 包时才相关，对普通用户无关。
