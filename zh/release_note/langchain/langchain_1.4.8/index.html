langchain 1.4.8

修订 发布时间2026年11月2日 来源langchain-ai/langchain 英文原文

langchain langchain==1.4.8

这个项目是干啥的：一个搭建 AI 应用的万能积木框架，把大模型、工具、数据串成能自动干活的工作流，给想把大模型做成真正产品的开发者用。

变更架构图

亮点

  • 无新功能，纯维护/安全版本 — 这实质上是一个依赖刷新版本，而非空操作的重新打标签：langchain 本身没有 API 变更、新功能或行为变更。唯一与 langchain 相关的变更是 release(langchain): 1.4.8 (#41636) 加上 chore(langchain): bump langchain-core (#41640)（跟进最新 core）。可视为安全的直接替换升级，无需迁移步骤。
  • 真正的内容是安全相关的依赖升级 — 更新了认证/加密相关的包：authlib 1.7.2→1.9.1（#41539）、joserfc 1.7.4→1.7.6（#41587）、pyasn1 0.6.4→0.6.5（#41591）、fastmcp 4.0.11→4.1.2（#41437）、opentelemetry-api 1.44.0→1.45.1（#41423），以及跨 3 个目录共 32 项更新的分组“minor-and-patch”升级（#41465）。如果你通过这些传递包暴露在风险中，这就是升级的理由。
  • 漏洞补丁曾尝试后被回滚 — build(deps): patch vulnerable integration dependencies (#41473) 随即被 revert: patch vulnerable integration dependencies (#41481) 撤销。因此更广泛的集成层补丁没有发布；实际的安全修复仅限于上面的直接升级。不要以为这个版本加固了集成依赖。
  • 放宽依赖约束 — chore(infra): relax third-party dependency upper bounds (#41407) 移除了版本上限，这对固定了较新第三方库版本的应用很重要：与 langchain 1.4.8 一起安装时，应该会更少遇到 ResolutionImpossible/冲突错误。
  • Python 3.10 终止支持——提前规划 — 更新日志警告 Python 3.10 支持将在 langchain-core 1.8.0 和 langchain 1.5.0 中移除；当前的 1.4.x / core 1.x 小版本是最后支持 3.10 的。仍在使用 3.10 的用户可以安全升级到 1.4.8，但在跳到 1.5.0 之前应迁移到 Python 3.11+。如果你想要安全修复或更宽松的约束（低风险、无迁移），建议升级；如果你的部署是固定版本的隔离环境、不暴露于这些升级过的包，可以跳过。

[!警告] langchain-core 1.8.0 和 langchain 1.5.0 中将不再支持 Python 3.10。 当前的次要版本是最后支持 Python 3.10 的。请升级到Python 3.11或更高版本。
