rust 1.99.0

小版本 发布时间2026年10月1日 来源rust-lang/rust 英文原文

rust 1.99.0

语言

  • 添加默认允许的 raw_borrows_via_references lint，用于检查立即衰减为原始借用的引用
  • 将 unconditional_panic lint 扩展到当块/窗口大小为零时发生恐慌的函数调用
  • 稳定 C 变量函数定义
  • 稳定使用 #[unsafe(naked)] 函数定义 C 变量函数 (#![feature(c_variadic_naked_functions)]) 的能力。
  • 特征方法现在已在调整后的 never 类型上解决（生成 FCW）
  • 如果推理变量通过子类型与已知为 Sized 的类型相关，则从推理变量强制到特征对象
  • 稳定#[my_macro] mod foo;。这允许概述模块 (mod foo;) 位于自定义属性或派生宏主体中的任何位置。
  • 通过重复否定修复 overflowing_literals lint。例如，它现在不再在 --128_i8 上 lint，而 arithmetic_overflow lint 已经检测到了这一点。
  • 将 POSIX 符号添加到 invalid_runtime_symbol_definitions 和 suspicious_runtime_symbol_definitions lint
  • 检查内联模块上未使用的 #[path] 属性
  • 启用 unreachable_cfg_select_predicates lint 作为 unused lint 组的一部分
  • 在 x86 上使用 asm! 通过向量寄存器稳定传递 128 位整数
  • 明确记录某些分配允许就地增长（但不允许收缩）
  • 我们现在保证无需通过get即可访问UnsafeCell的内容
    • invalid_reference_casting lint 已相应调整
  • global_asm! 中全局启用的目标功能的帐户
  • 如果在宏调用中使用无效的 doc 属性，则发出警告

编译器

  • 将 -Ctarget-cpu 转换为 AVR、AMDGCN 和 NVPTX 的目标修饰符
  • 在所有 gnu 目标上启用 static_position_independent_executables
  • 当提供有关缺失方法的建议时，rustc 现在更喜欢来自 doc 别名属性 的完全匹配的名称，而不是来自其他方法名称的相似性搜索。如果您的新用户有时期望使用不同名称的方法，那么除了帮助他们通过 rustdoc 搜索找到它之外，添加文档别名现在还可以帮助他们通过 rustc 建议找到它：当建议方法名称时，更喜欢精确文档别名而不是类似的名称

平台支持

  • 使用主机工具将 riscv64-unknown-linux-musl 升级到 Tier 2 有关 Rust 分层平台支持的更多信息，请参阅 Rust 的平台支持页面。

图书馆

  • RangeInclusive（a..=b范围）的迭代现在[在某些情况下更好地优化]（https://github.com/rust-lang/rust/pull/155114）。作为其副作用，已经用尽（作为迭代器）的 RangeInclusive 值的行为已经改变。例如，此类范围上的 start() 和 end() 的返回值可能返回不同的值，并且使用此类范围作为切片索引可能具有不同的行为。这些行为不能保证稳定，因此这些更改被认为不是破坏性更改。
  • 放宽transmute_copy接受?Sized类型
  • 更新 transmute_copy 以使用非展开恐慌
  • escape_debug_ext 中不要转义 U+FF9E 和 U+FF9F
  • [在alloc（和std）中重新导出core::fmt::NumBuffer]（https://github.com/rust-lang/rust/pull/161430）

稳定的 API

  • IntoIterator 适用于 Box<[T; N]>
  • IntoIterator 适用于 &Box<[T; N]>
  • IntoIterator 适用于 &mut Box<[T; N]>
  • VecDeque::retain_back
  • core::ffi::VaList
  • Box::into_non_null
  • Box::from_non_null
  • Vec::into_parts
  • Vec::from_parts
  • core::mem::size_of_val_raw
  • core::mem::align_of_val_raw
  • core::alloc::Layout::for_value_raw
  • String::from_utf8_lossy_owned
  • string::FromUtf8Error::into_utf8_lossy
  • FusedIterator for StepBy<I>
  • std::fs::set_times
  • std::fs::set_times_nofollow
  • <LocalKey<Cell<T>>>::update

货物

  • 添加新的内置配置文件 debug。这是将 dev 配置文件从调试中过渡出来的准备工作，以便为更快的开发迭代提供更合理的默认值。目前dev和debug型材没有区别。 文档 #17214
  • 2024 版或更高版本的工作区成员现在可以覆盖继承的工作区依赖项的 default-features 字段。例如，serde = { workspace = true, default-features = false } 现在会关闭默认功能，即使工作区定义启用了这些功能。在早期版本中，default-features = false 会被忽略并出现警告。 (RFC 3945) #17126 另请参阅 全货 changelog

Rustdoc

  • 添加新的 unused_footnote_definition rustdoc lint
  • 更智能地过滤特征实现可使性能平均提高 20%，在某些现实世界的 crate 上可提高高达 40%。 (1、2、3、4、5)

兼容性说明

  • 完全弃用旧的集成模块。例如，std::i32::MAX 应通过 i32::MAX 进行访问。
  • 将no_mangle_generic_items升级为硬错误
  • Pin::new_unchecked 的安全不变量略有改变
  • 不提倡引用外部静态
  • 确保 let 模式的推断类型进行类型检查
  • 隐士/fs: 返回 unsupported() 而不是 from_raw_os_error(22)
  • 修复了在稳定的 Rust 上意外允许 #[repr(simd)] 进行宏调用的错误
  • 当生成的值的类型中有泛型时，中止 const-eval
  • 不适用于任何内容的属性现在是文档注释中代码块中的错误
  • Box::leak：告诉人们避免泄密
  • PowerPC 内联 ASM：修复小端上错误矢量通道中的标量浮点数
  • 过滤文档测试时不要考虑 doc(cfg())
  • 推断关联常量类型中的匿名生命周期为 'static
  • 扩展为分号的宏现在会产生警告 lint (semicolon_in_expressions_from_non_local_macros)，即使该宏来自另一个板条箱。以前，此类警告仅针对同一包中的宏出现，以避免显示无法在本地修复的警告；然而，这掩盖了问题，因为提供宏的包中的集成测试被编译为单独的包，因此测试通常不会揭示这个问题。如果您遇到这样的 lint，请务必将其报告给提供宏的 crate，以便他们可以修复它；不要只是把它关在你自己的板条箱里。
    • semicolon_in_expressions_from_macros：非本地宏上也有 Lint
    • 将非本地 semicolon_in_expressions_from_macros 拆分为单独的 lint
  • 在 Cargo 中，在 CI 中运行时，现在默认禁用增量编译。 CI 通过 CI 环境变量检测。 #17220
  • Rust 参考不再建议使用单个模式将联合与另一个值匹配，例如在手动编写的标记联合中。这是因为我们发现，在某些情况下，此类代码会导致编译器在检查检查者的其余部分是否与模式的其余部分匹配之前读取联合的内容。这可能会导致代码中出现未定义的行为，类似于之前参考文献所建议的行为。

内部变化

这些更改不会影响 Rust 的任何公共接口，但它们代表了 rustc 及相关工具的性能或内部结构的重大改进。

  • 更新至 LLVM 23
