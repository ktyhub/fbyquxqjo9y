小版本 发布时间2026年4月16日 来源rust-lang/rust 英文原文

rust 1.95.0

语言

  • 稳定比赛手臂上的 if let 防护装置
  • irrefutable_let_patterns lint 不再在 let 链上出现 lint
  • 支持导入路径段关键字并重命名
  • 稳定 PowerPC 和 PowerPC64 的内联汇编
  • const-eval：在键入副本期间填充行为更加一致
  • 不再评估常量块以确定涉及错误操作的表达式是否可以隐式提升常量。。隐式提升能力取决于 const 块结果的表达式不再隐式提升。
  • 使模式匹配的操作语义独立于 crate 和 module

编译器

  • 稳定 --remap-path-scope 以控制路径如何在生成的二进制文件中重新映射的范围
  • 将 CVE-2026-6042 和 CVE-2026-40200 的补丁应用于供应商的 musl

平台支持

  • 使用主机工具将 powerpc64-unknown-linux-musl 升级到 Tier 2
  • 将aarch64-apple-tvos提升至2级
  • 将aarch64-apple-tvos-sim提升至2级
  • 将aarch64-apple-watchos提升至2级
  • 将aarch64-apple-watchos-sim提升至2级
  • 将aarch64-apple-visionos提升至2级
  • 将aarch64-apple-visionos-sim提升至2级 有关 Rust 分层平台支持的更多信息，请参阅 Rust 的平台支持页面。

图书馆

  • thread::scope：记录 join 如何与 TLS 析构函数交互
  • 在 aarch64 目标上加速 str::contains，默认启用 neon 目标功能

Rustdoc

  • 在搜索结果中，不稳定的项目排名较低
  • 在rustdoc中添加新的“隐藏不推荐使用的项目”设置

兼容性说明

  • 数组强制现在可能会导致比以前更少的推理约束
  • 由于对 self 导入进行更严格的错误检查，现在不再允许导入 $crate 而不重命名，即 use $crate::{self};。
  • const-eval：在类型复制期间填充行为更加一致。 在极少数情况下，这可能会导致编译错误，因为指针部分的字节最终出现在 const 或 static 的填充字节中。
  • 当使用不明确的 glob 导入特征时，现在会报告未来不兼容警告 lint ambiguous_glob_imported_traits
  • 检查仅提及类型参数的类型的生命周期界限
  • 报告更多与可见性相关的不明确导入错误
  • 弃用 Eq::assert_receiver_is_total_eq 并在手动实现上发出未来兼容性警告
  • powerpc64：使用目标规范中设置的 ELF ABI 版本而不是猜测（修复了 OpenBSD 目标使用的 ELF ABI）
  • 在 #[non_exhaustive] 枚举上匹配 现在读取判别式，即使枚举只有一种变体。这可能会导致闭包捕获它们以前不会捕获的值。
  • mut ref 和 mut ref mut 模式是不稳定的 Match Ergonomics 2024 RFC 的一部分，意外地允许在结构模式字段速记内稳定。这些模式现在已正确进行特征门控，因为在此位置不稳定。
  • 为与内置属性冲突的派生帮助器属性添加未来兼容性警告
  • JSON 目标规格 已不稳定，现在需要 -Z unstable-options 才能使用。以前，如果没有标准库就无法使用它们，因为标准库没有稳定的构建机制。为了准备添加该支持的 build-std 项目，正在主动控制 JSON 目标规格，以确保即使 build-std 稳定，它们也仍然不稳定。 Cargo 现在包含 -Z json-target-spec CLI 标志，可在需要时自动将 -Z unstable-options 传递给编译器。请参阅 #150151、#151534 和 rust-lang/cargo#16557。
  • 现在检查无效目标上的 #[feature] 属性的参数

内部变化

这些更改不会影响 Rust 的任何公共接口，但它们代表了 rustc 及相关工具的性能或内部结构的重大改进。

  • 更新至 LLVM 22
