rust 1.91.0

小版本 发布时间2025年10月30日 来源rust-lang/rust 英文原文

rust 1.91.0

语言

  • 按照写入顺序降低模式绑定，并根据主绑定的顺序放置基本顺序
  • 稳定 sysv64、win64、efiapi 和 aapcs ABI 的 C 风格可变参数函数的声明。这使这些 ABI 与 C ABI 保持一致：可变参数函数可以在 extern 块中声明，但不能定义。
  • 添加 dangling_pointers_from_locals lint 以警告局部变量中的悬空指针
  • semicolon_in_expressions_from_macros从警告升级为拒绝
  • 稳定LoongArch32内嵌组装
  • 针对整数到指针转换添加默认警告 integer_to_ptr_transmutes lint
  • 稳定sse4a和tbm目标特征
  • 添加 target_env = "macabi" 和 target_env = "sim" cfgs 作为具有相同值的 target_abi cfgs 的替代品。

编译器

  • 不要警告从不将任何 as 强制转换为无法访问

平台支持

  • 使用主机工具将 aarch64-pc-windows-gnullvm 和 x86_64-pc-windows-gnullvm 升级到第 2 层。 注意：llvm-tools 和 MSI 安装程序缺失，但将在未来版本中添加。
  • 将aarch64-pc-windows-msvc提升至一级 有关 Rust 分层平台支持的更多信息，请参阅 Rust 的平台支持页面。

图书馆

  • 在紧急消息中打印线程 ID
  • 修复 core::panic::Location::file 返回类型中过度限制的生命周期
  • std::cmp 中 min / max/ minmax 的 _by() 变体的保证参数顺序
  • 关于 Clone 和 Eq 性状的文件假设
  • std::thread：如果设置线程堆栈大小失败，则返回错误 这用于在标准库中发生恐慌。

货物

  • 🎉 稳定 build.build-dir。此配置设置存储中间构建工件的目录。这些工件是由 Cargo 和 rustc 在构建过程中生成的。最终用户通常不需要与它们交互，并且 build-dir 内部的布局是一个实现细节，可能会更改，恕不另行通知。 (配置文档) (构建缓存文档) #15833 #15840
  • --target 标志和 build.target 配置现在可以采用文字 "host-tuple" 字符串，该字符串将在内部由主机的目标三元组替换。 #15838 #16003 #16032

Rustdoc

  • 在搜索结果中，文档别名的排名低于同名的非别名项目
  • 原始指针现在可用于基于类型的搜索，如引用。这意味着您现在可以搜索 *const u8 -> 之类的内容，此外，接受或返回原始指针的函数现在将在搜索结果中正确显示其签名。

兼容性说明

  • 始终要求协程捕获实时生效
  • Apple：与 cc 链接时始终传递 SDK 根，并通过 SDKROOT env var 传递它。这应该可以修复 Xcode 中运行的 ZZPH100​​ZZ 的链接问题。 /usr/local/lib 中的库可能不再自动链接，如果您开发或使用依赖于此的包，则应在 build.rs 脚本中显式设置 cargo::rustc-link-search=/usr/local/lib。
  • 现在正确禁止像 TraitRef<AssocTy: ?Sized> 中这样的关联类型绑定位置中的放宽边界
  • 添加不稳定的 #[sanitize(xyz = "on|off")] 内置属性，该属性会遮蔽同名的程序宏
  • 修复了 drop 检查器对于使用 let-else 声明的绑定更加宽松的问题
  • 解析属性时更加严格，许多无效属性会出错
    • 无效 #[should_panic] 属性错误
    • 无效 #[link] 属性错误
  • 将名称解析中的所有弃用 lint 标记为默认拒绝，并在依赖项中报告
  • 对于表达式位置中扩展为以分号 (;) 结尾的 macro_rules! 宏，lint semicolon_in_expressions_from_macros 现在默认被拒绝。它已经是默认警告，并且未来兼容性警告（FCW）甚至在依赖项中也会发出警告。这个 lint 将来会成为一个硬错误。
  • 固有 impl 中的 Trait impl 修饰符（例如，unsafe、!、default）在语法上不再有效
  • 开始报告依赖项中 ill_formed_attribute_input 的未来损坏
  • 限制 Rust Edition 2024 中 if let 审查中的宏 pin!、format_args!、write! 和 writeln! 创建的临时文件的范围。 这适用于 Rust Edition 2024’s if let 临时作用域规则 到这些临时变量，这些临时变量以前可以在 if 表达式之后生存，无论版本如何。
  • 元组索引、元组结构索引和结构字段名称位置中的无效数字文字后缀现在被正确拒绝
  • 标有关键字 static 的闭包现在在语法上无效
  • 不再允许在 --cfg 和 --check-cfg 参数中使用 Shebang
  • 添加未来不兼容 lint 以暂时缩短 Rust 1.92 的使用寿命 货物兼容性注意事项：
  • 设置 build.build-dir 时，cargo publish 不再将 .crate tarball 保留为最终构建工件。这些 tarball 以前由于疏忽而被包含在内，现在被视为中间工件。要获取 .crate tarball 作为最终工件，请使用 cargo package。在未来版本中，无论 build.build-dir 为何，此更改都将适用。 #15910
  • 调整货物消息以匹配 rustc 诊断风格。这会更改 Cargo 消息使用的一些终端颜色。 #15928
  • 依赖于Cargo build-dir 的内部细节 的工具和项目可能不适用于更改 build-dir 布局的用户。对于这样做的人，我们建议主动测试这些情况，特别是因为我们正在考虑将来更改 build-dir 的默认位置 (cargo#16147)。如果您无法迁移 Cargo 的内部详细信息，我们希望在准备更改 build-dir (cargo#15010) 的布局时了解有关您的用例的更多信息。

内部变化

这些更改不会影响 Rust 的任何公共接口，但它们代表了 rustc 及相关工具的性能或内部结构的重大改进。

  • 更新至 LLVM 21
