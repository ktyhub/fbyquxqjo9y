rust 1.93.0

小版本 发布时间2026年1月22日 来源rust-lang/rust 英文原文

rust 1.93.0

语言

  • 稳定多个与 s390x vector 相关的目标功能和 is_s390x_feature_detected! 宏
  • 稳定 system ABI 的 C 风格可变参数函数的声明
  • 使用某些关键字作为 cfg 谓词时发出错误
  • 稳定asm_cfg
  • const求值时，支持逐字节复制指针
  • LUB 强制现在可以正确处理函数项类型以及具有不同安全性的函数
  • 允许 const 项目包含对 static 的可变引用（这是非常不安全，但并非总是 UB）
  • 添加默认警告 const_item_interior_mutations lint 以警告对内部可变 const 项目发生变异的调用
  • 添加默认警告 function_casts_as_integer lint

编译器

  • 稳定-Cjump-tables=bool。该旗帜以前称为 -Zno-jump-tables。

平台支持

  • 将 riscv64a23-unknown-linux-gnu 升级到 Tier 2（无需主机工具） 有关 Rust 分层平台支持的更多信息，请参阅 Rust 的平台支持页面。

图书馆

  • 停止在 Copy 特征上内部使用 specialization，因为它在依赖生命周期的 Copy 实现中是不健全的。这可能会导致一些性能下降，因为某些标准库 API 现在可能调用 Clone::clone 而不是执行按位复制
  • 允许全局分配器使用线程本地存储和std::thread::current()
  • 使 BTree::append 在附加已存在的条目时不更新现有密钥
  • vec::IntoIter<T>: UnwindSafe 不需要 T: RefUnwindSafe

稳定的 API

  • <[MaybeUninit<T>]>::assume_init_drop
  • <[MaybeUninit<T>]>::assume_init_ref
  • <[MaybeUninit<T>]>::assume_init_mut
  • <[MaybeUninit<T>]>::write_copy_of_slice
  • <[MaybeUninit<T>]>::write_clone_of_slice
  • String::into_raw_parts
  • Vec::into_raw_parts
  • <iN>::unchecked_neg
  • <iN>::unchecked_shl
  • <iN>::unchecked_shr
  • <uN>::unchecked_shl
  • <uN>::unchecked_shr
  • <[T]>::as_array
  • <[T]>::as_mut_array
  • <*const [T]>::as_array
  • <*mut [T]>::as_mut_array
  • VecDeque::pop_front_if
  • VecDeque::pop_back_if
  • Duration::from_nanos_u128
  • char::MAX_LEN_UTF8
  • char::MAX_LEN_UTF16
  • std::fmt::from_fn
  • std::fmt::FromFn

货物

  • 在基于配置文件的构建脚本中启用 CARGO_CFG_DEBUG_ASSERTIONS
  • 在cargo tree中，支持--format变量的长格式
  • 将 --workspace 添加到 cargo clean

Rustdoc

  • 删除#![doc(document_private_items)]
  • 在“宏”的搜索过滤器中包含属性和派生宏
  • 在 import 的搜索过滤器中包含外部板条箱
  • 验证板条箱级文档属性的使用。这意味着如果 html_favicon_url、html_logo_url、html_playground_url、issue_tracker_base_url 或 html_no_source 中的任何一个具有缺失值、意外值或错误类型的值，rustdoc 将发出默认拒绝的 lint rustdoc::invalid_doc_attributes。

兼容性说明

  • 将pin_v2引入内置属性命名空间
  • 将捆绑的 musl 更新为 1.2.5
  • 在 Emscripten 上，使用 panic=unwind 进行编译时使用的展开 ABI 已从 JS 异常处理 ABI 更改为 wasm 异常处理 ABI。 如果将 C/C++ 对象文件与 Rust 对象链接，则现在必须将 -fwasm-exceptions 传递给链接器。在每晚 Rust 上，可以使用 -Zwasm-emscripten-eh=false -Zbuild-std 获得旧行为，但它将在未来版本中删除。
  • 用于定义测试的 #[test] 属性以前在没有意义的各个地方被忽略（例如，在特征方法或类型上）。将 #[test] 属性放在这些位置不再被忽略，并且现在会导致错误；这也可能导致生成 rustdoc 时出现错误。 将 test 属性应用于结构时出错
  • Cargo 现在在更多情况下设置 CARGO_CFG_DEBUG_ASSERTIONS 环境变量。这将导致依赖于 static-init 版本 1.0.1 到 1.0.3 的包编译失败，并显示“无法解析：使用未解析的模块或未链接的包 parking_lot”。有关详细信息，请参阅链接的问题。
  • 现在检查 offset_of! 宏中的用户编写类型是否格式良好。
  • 当 build.build-dir 配置未设置时，cargo publish 不再发出 .crate 文件作为用户访问的最终工件
  • 将 deref_nullptr lint 从默认警告升级为默认拒绝
  • 为 extern 块之外没有模式的 ... 函数参数添加未来不兼容警告
  • 针对判别值不适合 c_int 或 c_uint 的 repr(C) 枚举引入未来兼容性警告
  • 引入未来兼容性警告，防止忽略 repr(C) 类型作为 repr(transparent) 的一部分
