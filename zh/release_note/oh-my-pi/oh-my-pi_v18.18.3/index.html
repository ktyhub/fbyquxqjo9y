oh-my-pi v18.18.3

修订 发布时间2026年11月9日 来源can1357/oh-my-pi 英文原文

oh-my-pi v18.18.3

@oh-my-pi/pi-目录

已更改

  • 在 eager 和 restrained 之间添加了 balanced 委托偏差；没有 delegation-bias 规则的模型现在解析为它而不是 eager

@oh-my-pi/pi-coding-agent

重大变化

  • ask 工具采用一种 HTML 表单 ({ html }) 而不是 questions[]：该模型编写一个由单选、复选框、选择、文本输入和文本区域组成的 <form>，并预选其推荐，并接收提交的表单数据作为 JSON。 AskToolDetails 现在是 { answers: { name, question, answer }[]; timedOut? }； QuestionResult，工具的“其他”、“聊一下这个”、答案注释和答案图像路径被删除，/tree重新答案重新打开原始形式（NavigateTreeResult.reopenAsk携带html）。

添加

  • 在 Tern 中，右键 clicking ask 答案会提供注释，该注释会注释该答案而不选择它（#18551 by @H4vC）
  • task.eager (preferred/always) 现在仅塑造主代理人的系统提示；子代理退回到其模型自己的委托策略，而不是被迫产生更多子代理
  • ask 表单可以显示图片：来自 http(s) URL、data: URI 或本地文件（相对于会话的工作目录）的 <img src>，以及内联 <svg> 图表，以终端形式绘制并在 Tern 中本地绘制
  • ask 表单为每个单选按钮和复选框组提供自由文本“其他”答案：其文本是单选按钮的值或附加到复选框组的数组（包括逐个字段后备、协作访客和 ACP 启发）
  • 扩展 UI 获得可选的 ui.formDialog(html, options)，它呈现 HTML <form> 并解析为 { data, timedOut? }（取消时未定义）。交互式 TUI 将其呈现为表单对话框，具有表单诱导的 ACP client 获得每个字段一个属性的一次诱导，而没有表单诱导的主机 (RPC) 通过 select/input/editor 逐字段回答 ask 工具。
  • Eval 单元可以使用 sh 运行 shell 命令：Python 中的 sh("git status")、await sh`ls ${dir}` or await sh("make", { cwd }) in JavaScript. Commands run on the embedded bash engine to completion (never auto-backgrounded), return their output, and raise ShellError，失败时返回退出代码。
  • Windows 上的 omp zsh 对于 PATH 没有的命令运行 omp 的内置实用程序（ls、cat、head、jq 等），除非 command_not_found_handler 处理它们（@H4vC 的 #18532）。

已更改

  • 澄清了 history:// 简明笔录、proc:// 作业保留和驻留代理查找以及 read JSON 查询文本输出的工具和内部 URL 描述（#18553 by @xiangnan0811）
  • 没有委派规则的模型（Claude、Gemini 等）不再被推送到委派：搜索工具描述中的“通过任务映射未知代码”规则和“任务 + 侦察”提示被替换为使用侦察员探索不熟悉的子系统的简单建议
  • 在 Tern 中，clicking ask 答案，然后 Note 现在注释了所显示问题上突出显示的答案，而不是仅 clicked (#18551 by @H4vC)

已修复

  • 修复了在选择答案登陆上一问题（而不是显示的问题）后立即添加 n 的 ask 注释； Tern click 然后 Note 仍会记录答案为 clicked，Note 按钮将其命名为 (#18317 by @DonMikone)
  • 修复了 /export 在 Windows 上保存到当前目录（包括 sub/../session.html 等相对路径）时失败的问题；导出消息现在显示写入文件的完整路径（@minhngoc25a 的 #18369、#18525）。
  • Todo 初始化现在将空阶段命名为 Tasks，因此后续更新可以解决它们（#18552 by @xiangnan0811）
  • Windows 上的 omp zsh 和 bash 工具：没有作业控制的后台命令会像 zsh 和 bash 一样忽略 Ctrl-C（INT 和 zsh 中的 QUIT），因此控制台的 Ctrl-C 让它们继续运行（#18532 by @H4vC）。
  • omp zsh 在 Debian、Ubuntu 和 Arch 上以及 Windows 上从适用于 Windows zsh 的 MSYS2、Cygwin 或 Git 查找系统 zsh 的函数库（compinit 加载）（#18532 by @H4vC）。
  • Windows 上的 omp zsh：键入的命令不再以 ^M 结尾，通过 Path 找到程序，每行运行管道脚本，cd 采用 C:\…/C:/…、.. 和 ~（将 $PWD 保留为 C:/…），>/dev/null 有效，提示符为% 而不是 root 的 #，$OSTYPE 是 msys，并且不会打印 USERNAME 警告（@H4vC 的 #18532）。
  • Windows 上的 omp zsh 使用 ZLE 编辑行（历史记录、Tab 补全、按键绑定、$COLUMNS）； Ctrl-C 放弃该行，运行 INT 陷阱，或中断随后继续的 read，而不是通过 @H4vC 结束 shell (#18532)。
  • Windows 上的 omp zsh：Ctrl-C 中断前台程序，jobs、fg 和 bg 工作（用 fg 带回的作业也得到 Ctrl-C），进程替换到达 Windows 程序（diff <(…) <(…)、prog >(…)）（#18532 @H4vC)。
  • 在 Windows 上，/dev/null 在 bash 工具（>/dev/null、cat /dev/null、[ -c /dev/null ]）（#18532 by @H4vC）中工作。
  • 在 Windows 上，/dev/tty 在 omp zsh 和 bash 工具 (prog >/dev/tty) 中打开控制台，并且通过 Ctrl-C 杀死的 MSYS 或 Cygwin 程序报告状态 130 而不是 512 (@H4vC 的 #18532）。
  • omp zsh 在作业控制下为后台管道打印 [n] pid 行，就像它为单个命令所做的那样（#18532 by @H4vC）。
  • omp zsh 启动 compinit 的速度要快很多倍：分配和读取单个数组和关联元素而无需复制整个参数，并且 autoload -r 不再为其解析的每个函数重新读取 $fpath 中的 .zwc 摘要（@H4vC 的 #18533）。
  • omp zsh 的 ZZPH100​​ZZ 和 read -q 无需像 zsh 那样等待 Enter 从终端读取密钥，而不是通过 @H4vC 读取标准输入（#18533）。
  • omp zsh 完成列表再次标记文件类型（dir/、exe*），print -c 在没有终端的情况下将单词排列在列中，而 ${x?msg} 则像 zsh 一样以状态 1 结束非交互式 shell（@H4vC 的 #18533）。
  • omp zsh 浮点数在算术中保持完全精度（s=$EPOCHREALTIME; print $(( EPOCHREALTIME - s )) 不再漂移最多一秒），并且仍然以 -F/-E 样式打印（#18533 by @H4vC）。
  • omp zsh 的 typeset -U path / typeset -U fpath（和 local -U path）会像 zsh 一样删除重复的条目（#18533 by @H4vC）。
  • omp zsh 和 bash 工具：后台管道的 $! 是其最后一个程序的 pid，如 bash 和 zsh 中一样，因此 kill $! 向该程序发出信号； omp zsh 的后台管道的 [n] 行列出了每个进程的 pid，就像 zsh 所做的那样（#18547 by @H4vC）。
  • omp zsh 更快：函数调用、循环和算术运行速度快 2-3 倍，compinit 几乎快 4 倍，并且一次构建大型数组或关联一个元素（a+=(x)、h[k]=v）或从大型数组读取 $a[i] 不再因其大小而减慢（#18565 @H4vC)。

@oh-my-pi/collab-web

已更改

  • ask 工具卡显示 HTML 表单的字段集图例和待处理时的字段计数，以及每个问题及其提交的答案（或“（无答案）”）一旦回答，标记超时提交的内容

@oh-my-pi/pi-tui

重大变化

  • ask 工具渲染器现在绘制 { html } 表单调用和 AskToolDetails { answers, timedOut } 结果； QuestionResult 和问题列表详细信息字段已删除。

添加

  • 在 Tern 中每个询问对话框答案行的右侧 click 菜单中添加了一个注释条目，注释该答案而不选择它（#18551 by @H4vC）
  • 添加了 HtmlFormDialog，它将 HTML 表单呈现为交互式终端表单，将长表单拆分为页面，并将答案返回为 JSON。单个 <select> 是单行下拉菜单，单选和复选框组获得自由文本“其他”答案，<img>（URL、data: URI 或本地文件）和内联 <svg> 图片在后台加载，可选的不活动超时提交当前值，Tern 终端本地获取表单。
  • 在 Editor.setText 中添加了 cursor: "start" 选项，以便预填充的多行文本在第一行打开。

已更改

  • 询问对话框的“注释”位于指针 click 之后，现在会注释所显示问题的突出显示答案，而不仅仅是 clicked 的答案，并且“注释”按钮不再命名重定向目标（#18551 by @H4vC）

已修复

  • 修正了键盘选择后询问对话框的 n 注释上一个问题的答案而不是显示的突出显示的行；只有指针 click 仍然将 Note 重定向到刚刚选择的答案，然后“Note”按钮将其命名为（#18317 by @DonMikone）
