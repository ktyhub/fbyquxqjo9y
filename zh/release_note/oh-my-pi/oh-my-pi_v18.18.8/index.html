oh-my-pi v18.18.8

修订 发布时间2026年11月11日 来源can1357/oh-my-pi 英文原文

oh-my-pi v18.18.8

@oh-my-pi/pi-ai

已修复

  • 修复了因 claude_code_version_too_old 失败而被拒绝的并发 OAuth 请求，而不是使用所需版本重试 (#18651)
  • 聊天完成网关请求保留显式工具严格模式选择，因此当调用者设置 strict: false（#18672 by @0xeb）时，Codex 工具可以省略可选参数。

@oh-my-pi/pi-目录

添加

  • 在元模型 API 和 Muse 代码上添加了 Muse Ember (muse-ember-1.0)，具有 minimal–max 推理工作量阶梯及其 >200K 长上下文定价
  • 在 Gemini API、Vertex AI、Google Antigravity 和 Cursor 上添加了 Gemini 4 Carbon 定价（2026 年 11 月 30 日之前每 100 万代币 2 美元输入/$0.10 缓存/10 美元输出，然后是 4 美元/$0.20/20 美元），而不是显示 0 美元（#18734） @eggpeat)

已修复

  • 修复了当 NanoGPT 的 <id>:thinking 兄弟行具有较大限制时重新生成将 18 个推理模型标记为非推理的目录（#18673、#18728）

@oh-my-pi/pi-coding-agent

已更改

  • curl -fsSL https://omp.sh/install | sh 和 install.ps1 现在默认安装独立二进制文件，即使存在 Bun，因此安装时会获得增量更新；通过 --source/-Source 进行包子包安装
  • 询问表格可以为选定的选项附加注释；这些注释与答案分开，与提交的表单值分开（#18779 by @Shadorain）

已修复

  • 当重置也清除神鬼寓言上限时，克劳德自动兑换现在会在被每周限制封锁的帐户上花费完全保存的重置；此类重置被视为仅限寓言并在寓言使用有空间时跳过（#18801）
  • 修复了代理在代理中心显示为空闲状态，同时在流式编辑预览失败 (edit.streamingAbort) 自动恢复回合后仍在运行的问题 (#18790 by @H4vC)
  • 现在，未打开的选项卡上的浏览器调用表示使用 await browser.open({ name }) (Python: await browser.open(name=…)) 以及打开它的 url 和应用程序打开它，而不是指向已删除的 action:"open" (#18739 by @will-bogusz)
  • 修复了当确切的应用程序名称有一个打开的窗口时，computer.window({ app }) 和 computer.windows({ app }) 匹配类似名称的应用程序，例如 Google Chrome 和用于测试的 Google Chrome (#18744 by @will-bogusz)
  • 在 Tern 中，浏览器 role/ 选择器保留土耳其语和阿塞拜疆语言环境下的输入角色和名称（#18658 by @will-bogusz）
  • Chrome role/RootWebArea 等待 visible 返回文档而不是失败，而 hidden 等待继续等待（#18658 by @will-bogusz）
  • 会话的 bash 工具或 eval 单元在 Tern 或 cmux 内启动的 omp -p 或其他 omp 不再从它继承的窗格中选择 Tern 或 cmux，因此其浏览器选项卡停止浮动在您的窗格上 (#18773 by @will-bogusz)
  • 当另一个连接在其页面上禁用自动附加时，共享选项卡的浏览器中继连接不再丢失跨站点框架；当最后一个武装页面离开时，自动子级在本地分离，而显式附加的框架子树在选择退出后仍然可用（#18657 by @will-bogusz)
  • 浏览器代理现在会在无法通过页面完成某个步骤时发出提示，而不是使用脚本修补页面并报告该步骤已完成（#18761 by @will-bogusz）
  • 扩展的 assistant_message 重写现在到达下一个 Codex 响应请求：用于重新发送捕获的原始文本的相同模型本机重播，而转录本显示重写的文本 (#18312)
  • MCP 重新连接和工具列表刷新现在使扩展停用的工具保持不活动状态，同时启用新发现的工具 (#18678)。
  • 中止 bash 命令后退出现在会等待其耐 TERM 的前台进程被终止 (#18669)。
  • edit 接触多个文件，锚定未显示的行，现在会在一次拒绝中显示每个文件的这些行，因此适用相同的重新发送，而不是在下一个文件中再次被拒绝（#18742 by @MaisonnatM）
  • omp auth-gateway stdio 现在提供判断、图像、语音、嵌入、重新排名和视频模型：/v1/models 列出它们，/v1/systemone 回答 typesafe/jev-* 或 @judge，而不是聊天模型中的 404 或 422（#18740 by @andyhite）
  • 当 omp auth-gateway stdio 的输入在慢速阅读器读取之前结束时，omp auth-gateway stdio 不再在 128 KiB 处切断其最后响应（#18740 by @andyhite）
  • omp --session <id> --restore 恢复该会话，就像 omp --restore --session <id> 一样，而不是打开会话选择器：裸露的 --restore 保留已命名的会话 --session 或 --resume (#18685 by @AdamDureyAtWillship)
  • 旧版 Pi 虚拟模块现在构建在 npm 安装中，使捆绑的 Pi 软件包保持嵌套：它锚定到已安装的软件包，因此其导入通过该软件包自己的依赖关系图进行解析（#15208、#18733 by @yuzu-octopus）
  • 用户级代理、命令和其他 ~/.omp/agent 配置（包括从代理中心保存的代理）现在遵循 PI_CODING_AGENT_DIR，匹配 omp agents unpack 写入的位置 (#18684)
  • 修复了 grep 和 glob 将以内部 URL 开头并包含本地路径（例如 artifact://1;notes.txt）的 ; 列表视为一个地址；现在可以搜索每个列出的目标（@eggpeat 搜索#18714）
  • 编辑名称包含空格的文件的独立任务现在提交该文件，包括在嵌套的 git 存储库中，而不是将其保留为未暂存状态或提交共享部分名称的其他文件（#18715 by @eggpeat）
  • 已处置或切换的会话现在释放它拥有的每个持久外壳，包括表面以其自己的名称保留的外壳（/loop 条件），而不是在进程的生命周期中为每个表面保留一个本机外壳（#18717 by @eggpeat）

@oh-my-pi/collab-web

已更改

  • 询问结果卡在匹配的所选答案下方呈现保存的注释（#18779 by @Shadorain）

@oh-my-pi/pi-natives

已更改

  • macOS 键、在窗口中键入和按住的键现在会转到附加到其上且保持键盘焦点的工作表，例如 macOS 发送的打开工作表或 Finder 的“转到文件夹”，而不是抛出 InvalidTarget 并命名工作表；该工作表的控件键也是如此，该工作表将其下方的窗口报告为自己的窗口（#18675 by @will-bogusz)
  • 当另一个 omp 会话的调用占据桌面时（例如 apps.open 等待其窗口），计算机输入不再因 InputBusy 失败：在 macOS、Linux 和 Windows 上，它最多等待 5 秒才能完成该调用（#18746 by @will-bogusz）

已修复

  • 修复了解析具有深度嵌套列表或块引用的 Markdown 时发生的崩溃，例如一行数百个 - 标记，这使得编辑此类文件会终止进程（#18707）
  • 修复了 Windows 上使用 bash.gitGuard（或智能 git）内置的 shell 的 git 在退出 127 (…\Git\cmd\git: No such file or directory) 时每个允许的命令失败时的问题；它现在运行 git.exe (#18722)
  • 计算机元素搜索接受本机角色名称、空格角色名称，例如 macOS radio 控件的 text field 和 radiobutton，而不更改打印的辅助功能角色（#18745 by @will-bogusz）
  • 修复了 macOS 后台输入和接管拒绝每次调用且不发送任何内容，而 Finder 位于前面且焦点位于桌面且 Finder 窗口打开的问题； Finder 恢复其正面状态，焦点留在桌面上（#18680 by @will-bogusz）

@oh-my-pi/pi-tui

已更改

  • 询问表单支持选项注释：单选/复选框行上的 n 和选择菜单上的 Alt+n (app.ask.note)，选定的注释显示在提交的答案旁边，未选择的选项的注释标记为草稿 (#18779 by @Shadorain)

已修复

  • 询问从 Tern 编辑的表单文本区域现在重新启动不活动超时，而不是在编辑中提交
  • 修复了 ask 表单中的图片在表单关闭后仍保留在屏幕上的情况（#18693 by @jaredlyon）
  • 修复了终端设备属性回复（例如 ^[[?64;1;2;4;6;17;18;21;22c）在退出时泄漏到 shell 提示符中的问题（#18662 by @asuffield）

@oh-my-pi/pi-utils

已删除

  • 删除了getConfigAgentDirName()；使用 getAgentDir()，它也尊重 PI_CODING_AGENT_DIR (#18684)
