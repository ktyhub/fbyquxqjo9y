oh-my-pi v18.18.9

oh-my-pi v18.18.9

@oh-my-pi/pi-agent-core

添加

  • 工具调用得到 ctx.toolCall.earlierEffectsSettled，一旦在它们旁边运行并可能写入文件的其消息的早期调用完成（它们的批准，询问其参数，不是 read），它就会解决；推测结果在验证之前等待这些效果，等待时取消会阻止它们的提交（#16274 by @will-bogusz)

@oh-my-pi/pi-ai

添加

  • 添加了 SOFYA_API_KEY 作为 sofya 提供程序的环境密钥（@yusufgurdogan 的#18185）

已修复

  • Devin 请求不再发送 temperature: 0：目录的 temperature-floor 将其提升到 0.0001，因此会话标题和 Mnemopi 内存提取可以在 Devin 上工作，而不是因 Cascade 的不透明 invalid_argument 失败并默默地退回到另一个模型（#18423）
  • Auth-gateway /v1/messages 现在为 output_config.format（以及 GA 前的 output_format）回答 400 invalid_request_error，而不是返回 200 且输出模式不受约束，因此结构化输出 clients 回退到提示端模式（#18842）
  • Auth-gateway 请求仅被拒绝所请求的模型（Codex ChatGPT 帐户、Cursor 计划）现在切换到另一个帐户，并使被拒绝的帐户可用于其他模型，而不是将工作凭证标记为可疑；网关轮换现在遵循与本地会话相同的规则，包括等待同级的短使用块

@oh-my-pi/pi-目录

添加

  • 添加了 web/sofya 搜索模型（@yusufgurdogan 的#18185）
  • 添加了 temperature-floor 兼容轴，在 Devin 上分配了 0.0001，以便引脚 temperature: 0 的请求到达 Cascade 作为它接受的值 (#18423)
  • 为黑客新闻故事和评论添加了无密钥 web/hackernews 搜索引擎模型

已修复

  • Devin 请求现在标识为 Devin CLI 3000.12.43（当前稳定版本），而不是 3000.11.205（#18766 by @will-bogusz）
  • 修复了命令代码上的 Gemini 4 氩和碳不显示推理级别的问题；两者现在都提供低、中、高
  • 修复了 OpenCode Zen Gemini 4 Carbon 请求转到聊天完成端点而不是本机 Gemini 端点 Zen 为其提供服务的问题

已删除

  • 在 Devin 的实时模型列表加载之前（首次启动，或当 Devin 无法访问时），从模型 omp 列表中删除了 Devin 退役的 SWE-1.6 Fast（#18795 by @will-bogusz）

@oh-my-pi/pi-coding-agent

添加

  • 使用 SOFYA_API_KEY 或存储的 sofya 凭证添加 Sofya 作为网络搜索引擎 (web/sofya) (#18185 by @yusufgurdogan)
  • docs/autoresearch.md 中记录的自动研究模式：激活及其 git 门、三个停止条件、默认为无的每段迭代上限、工具 METRIC/ASI 合约以及 OMP_AUTORESEARCH_DB_DIR 重新定位的磁盘存储（#18655 @sjawhar)
  • 扩展可以导入表单主题、本机跨度帮助器（styledSpans、compactText、rowsText 和其余 ANSI/span 转换）、xd:// URL 帮助器（parseXdUrl 和朋友）以及来自 @oh-my-pi/pi-coding-agent 的 cfgExtensionTranscriptPresenters 设置句柄，而不是内部模块路径，这会在文件移动时阻止扩展加载(#18849 作者：@materemias)
  • /context 在自己的类别中显示加载的指令文件和技能；系统提示标记每个位置而不需要计算两次，并在扩展或 SDK 回调在构建后更改提示时进行注释（#17971 by @c-w-z）
  • 添加了黑客新闻搜索（web/hackernews）：范围为 site:news.ycombinator.com 的 web_search 查询现在通过无钥匙 HN 搜索 API 在配置引擎之前搜索 HN 故事和评论

已更改

  • 另一个 omp 实例中的角色编辑不再重写每个正在运行的会话的 task 和 eval 工具描述，这会使从工具定义开始的 Anthropic 提示缓存失效，并在前缀绑定模型上删除签名的思维块；每次调用模型广告现在被冻结到基本提示表面中，并且仅在该表面重建时才会改变（#18716、#18732 by @yuzu-octopus)
  • 代理到代理的消息现在总是在用户轮流时到达收件人：结束 wait 的消息会紧随其后到达，而不是在 wait 工具结果内，并且不会通过开发人员或系统权限发送任何消息
  • 启动服务现在持续适用于非交互式会话
  • shell 的内置 jq 现在的行为类似于 jq 1.8.2 而不是 jaq：相同的输出（数字格式、颜色、-S、--indent、--seq、--stream）、错误消息和退出状态、jq 的完整选项集（--version 报告 jq-1.8.2）及其语法和内置函数（?//、$__loc__、模块、getpath/setpath 创建缺失路径、|= 删除、Oniguruma 正则表达式、日期）；它通过了jq 1.8.2自己的测试套件

已修复

  • Nix 使用 withAppleFm = false 构建不再使用主机的 Xcode 编译 Apple Foundation Models 桥接 (#18911)
  • Apple Silicon Nix 构建包含 Apple Foundation Models 支持，而不是在没有它的情况下默默构建（#16584 by @honsunrise）
  • 在 Windows 上，当 omp 本身在 AppContainer 沙箱中运行时，bash 工具会运行外部命令，而不是使用 Permission denied 使每个命令失败（退出 126）（#18800 by @devjay4561）
  • 当命令也匹配关键模式时，显式 Bash 提示规则在 yolo 模式下保持强制执行（@jasonharrison 的 #18788）。
  • 修复了当 widget 模型错误时作业小部件和标题彻底失败的问题：他们现在尝试角色的下一个模型（retry.fallbackChains.widget，否则内置 smol 默认值），并且仅在每个候选人都有一次时失败（#18793）
  • 失败的作业小部件、作业标题、缓存预热、作曲家预测和子代理完成探测调用现在将提供程序的错误消息保留在其会话使用记录中（#18792）
  • /changelog、/changelog full 和 /changelog last N 现在列出最新版本，匹配 CHANGELOG.md 和启动 release notes (#18809)
  • 修复了在同一消息中的 bash 调用之后放置的 read，在主要和顾问轮流中返回该命令更改、创建或删除文件之前的文件（#16274 by @will-bogusz）
  • RPC/ACP /session delete 现在在删除其文件之前切换实时会话，因此稍后将保存到新的可恢复会话（#18665）。
  • Chromium 选项卡上的浏览器 tab.click、tab.dblclick、tab.check、tab.uncheck、tab.uploadFile 和 frame.click 现在，当页面在 click 消失之前替换元素时，包括在交付观察程序设置期间和之后，会再次查找其选择器，而不是等待被替换元素的操作超时；通过元素句柄的 click 或元素被替换的 aria-ref 立即失败（#18676 by @will-bogusz）
  • 代码使用 document、window、location 或其他仅页面全局的浏览器 tab.run 现在表示代码在 omp 的运行时而不是页面中运行，并使用 tab.evaluate，而不是仅“文档未定义”（#18840 @will-bogusz)
  • 以赋值、块、循环或声明结尾的 JavaScript eval 单元和 tab.run/computer.run 字符串现在不返回任何内容；尾随表达式和显式返回仍然会产生值 (#18865 by @will-bogusz)
  • 调用 window.print() 的页面不再挂起浏览器 omp 启动：print() 立即返回，tab.pdf() 仍然生成 PDF（#18838 by @will-bogusz）
  • tab.select() 和元素句柄 select() 返回页面的 input 和 change 处理程序运行后选择的选项，而不是页面然后重置的选择（Chromium 选项卡）或页面处理程序刚刚替换的选项（cmux 和 Tern 选项卡）（#18829 @will-bogusz)
  • 当omp的机器上没有文件时，tab.waitForDownload()失败，命名它所寻找的路径，就像通过另一台机器上的app.cdp_url访问浏览器一样，而不是返回不存在的路径；这样的下载被排除在 tab.downloads() 之外（@will-bogusz 的#18830）
  • 当 Chrome 从打开的中继选项卡 omp 中分离 omp 且 omp 无法重新连接时，错误现在表示 omp 试图关闭该选项卡并打开一个新选项卡，而不是告诉代理在 Chrome 中导航该选项卡；失败的关闭可能会推迟到继电器重新连接为止（@will-bogusz 的#18832）
  • 不匹配选项卡的继电器 app.target 现在建议省略 app.target 以打开 omp 自己的选项卡（#18833 by @will-bogusz）
  • 在候选法官为其模型回答 404 后，判断会跳过五分钟，就像在 401/402/403 之后所做的那样，而不是在 find 调用的每次判断时重新发送失败的请求（#18854）
  • 修复了 Tern 和其他 OSC 7501 终端显示会话为 working 的问题，无需提醒，同时有一个对话框等待您，例如 ctx.ui.confirm 扩展的 tool_call 处理程序打开以控制命令：TUI 显示的每个对话框（扩展和挂钩对话框、工具批准、ask、cfg:// 更改、编码计划保留确认、计划审查）现在报告blocked 会显示它所询问的内容，直到您回答为止，一旦您回答，工具批准就会再次报告 working（#15107、#18868，作者：@wolfiesch）
  • 外壳的内置 jq 不再因重复更新（例如 reduce range(n) as $i ([]; . + [$i])）而减慢速度
  • /tan完成通知现在引用用户的请求并将结果标记为用户的切线，因此主代理不再将其误认为是自己的工作
  • 使用 zsh-autosuggestions 的 completion 策略的 omp zsh 不再将每个键入的键回显到新行：zpty 命令内的 vared 现在在 pty 而不是 shell 的终端上进行编辑
  • 使代码栅栏保持打开状态的指令文件在其末尾关闭，因此系统提示符的其余部分将照常格式化（#17971 by @c-w-z）
  • 只读活动在快照压缩或另一个中转转录重建后保持可见，而不是让 UI 卡在“正在工作…”（#18876 by @JustasMasiulis）。
  • 开启 Spotlight 实验后，当 Spotlight 找不到 Stencil 凭据时（每次凭据丢失一次），会话都会发出警告，并说明如何再次登录； spotlight:shape 日志条目记录因原因 (failureCauses) 而失败的 Spotlight 调用（#18850，作者：@wolfiesch）

已删除

  • 删除了 /mcp smithery-search、/mcp smithery-login 和 /mcp smithery-logout； Smithery 于 2026 年 10 月 31 日关闭了 API（#18822 by @samettemizer）

@oh-my-pi/pi-natives

添加

已更改

  • macOS 插件的安装名称是 @rpath/libpi_natives.dylib，而不是它内置的目录 (#18911)
  • 一组 OMP_APPLEFM_SWIFTC 必须命名一个可用的 Swift 6.4+ 编译器和 macOS 27+ SDK：构建现在会失败，而不是回退到 Xcode、命令行工具或没有 Apple Foundation 模型的构建（#16584 by @honsunrise）

已修复

  • 修复了 macOS 窗口屏幕截图将窗口绘制得比实际显示的要小的问题，因此 clicks 的瞄准会以数十点的误差来瞄准；跨越显示器或部分离开屏幕的窗口将以其屏幕上的尺寸完整捕获，除非打开了大于窗口的工作表（#17757 by @will-bogusz）
  • 修复了 Linux 计算机读取导致正在读取的应用程序崩溃的问题（6.9.2 应用程序之前的 Qt 5 和 Qt 6；2.45 之前具有 at-spi2-core 的发行版上的 GTK 3 和 Firefox 应用程序，例如 Ubuntu 22.04），并且不会从较新的 Qt 应用程序的文本字段中读取任何文本（#18823） @will-bogusz)
  • 修复了 macOS 背景左 clicks 在 Electron 应用程序中以及在 Chrome 中当 click 更改 URL 时导致页面崩溃的问题（history.pushState，与单页应用程序一样）（#18824 by @will-bogusz）

@oh-my-pi/omp-stats
