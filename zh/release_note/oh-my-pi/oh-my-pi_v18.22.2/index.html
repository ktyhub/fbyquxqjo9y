oh-my-pi v18.22.2

修订 发布时间2026年11月18日 来源can1357/oh-my-pi 英文原文

oh-my-pi v18.22.2

@oh-my-pi/pi-ai

添加

  • Added the native Kiro provider: sign in with AWS IAM Identity Center, AWS Builder ID, Google, GitHub, or a Kiro API key (KIRO_API_KEY), stream responses with reasoning, tool calls, and images, and report Kiro credits in /usage (#18955 by @Xytronix，基于 @ajdiyassin 的 #14215）
  • 在OAuthError基础上添加了definitive选项； isDefinitiveOAuthFailure now takes the error object and disables a credential marked definitive without matching its message (#18955 by @Xytronix)
  • buildAnthropicSearchHeaders 采用 extraBetas，在网络搜索测试版旁边发送特定于请求的测试版（#18125，作者：@will-bogusz）
  • Added omitDemotedReasoning to StreamOptions: an Anthropic request leaves out other models’ reasoning that it would otherwise replay as text, and a refused request reports how many such blocks it carried in demotedReasoningBlocks (#10407) (#17610 by @will-bogusz)

已修复

  • Fixed shutting down or cancelling an omp session making every other session sharing the agent directory see its OAuth accounts as depleted for 5 minutes;关闭期间也会提供仍然有效的令牌（#19607）
  • OAuth accounts refreshed through an auth broker keep their stored routing metadata (such as an API endpoint) in the key built for the request, instead of losing it after the first refresh (#18955 by @Xytronix, based on #14215 by @ajdiyassin)
  • 带有很长的连续线的围栏（```思考）推理在流式传输时不再减慢（#19493 by @H4vC）
  • Fixed Anthropic requests that replay a signed server-compaction block still asking for a message thread, which the API refuses (thread_unsupported_request), so every such request first paid a rejected round trip before resending without the thread (#19473 by @alphastorm)
  • Anthropic requests whose connection drops before any response now say how long after the request started it dropped and whether the request body was still uploading or had all been written to the socket, with its size, instead of a bare “Connection error.” (#18624 作者：@will-bogusz)
  • 修复了人类请求放弃早期非克劳德回合在另一个凭证下签名或通过压缩保留的推理；现在像其他模型的推理一样重播 (#7241) (#17610 by @will-bogusz)

@oh-my-pi/pi-目录

添加

  • Added Kiro to the model catalog with automatic discovery of every model available to the signed-in Kiro account (#18955 by @Xytronix, based on #14215 by @ajdiyassin)
  • Added Factory Droid’s Claude Fable 5.2, Gemini 4 Carbon (with its launch credit promotion, half the input rate until 2026-12-01) and Kimi K3.1 Pro, each listed once the account’s feature flag enables it, and GPT Image 2.6 and GPT Image 2.6 Flare ahead of GPT Image 2.5 in the image 角色的出厂默认值（#19191 by @will-bogusz）
  • 添加了 writeModelCacheAsync() 和 forEachInSlices()：模型刷新现在在产生事件循环的切片中构建和缓存发现的模型； writeModelCache() 返回其结果，并且不再重写行未更改的提供程序

已更改

  • readModelCache() 每个进程解析一次有效负载：保存相同行的缓存文件返回相同的共享行对象

@oh-my-pi/pi-coding-agent

添加

  • 计算机 el.setValue(75) 现在将数字写入 "75"，而不是拒绝非字符串； NaN、Infinity、布尔值和对象仍然被拒绝，超过 2^53 的整数和带有指数的数字也被拒绝，它们以数字文本形式传递（#19405 by @will-bogusz）
  • 在 macOS 上的浏览器结果中添加了本机窗口报告，用于可见的托管浏览器、生成的 Chromium 浏览器和环回中继：<select> 菜单、颜色或日期选择器，或打印、保存、登录、密钥或权限表或气泡，在其选项卡上引发的调用以其 computer.window() id 命名，而浏览器的选项卡列表在其窗口前面显示该选项卡，在调用返回后显示的下一个调用以及调用失败时也；连接的 CDP 端点、远程中继和页面支持的弹出窗口被排除（#18925 by @will-bogusz）
  • 添加了 Kiro 作为内置提供程序：运行 /login kiro，选择身份中心、构建器 ID 或 API 密钥，然后选择发现的 kiro/<model-id> 模型。每个 /login kiro 添加一个帐户（@Xytronix 的 #18955，基于 @ajdiyassin 的 #14215）
  • 将 Google 和 GitHub 添加到 /login kiro：在 app.kiro.dev 批准一次性代码，然后使用该帐户（@Xytronix 的 #18955 登录，基于 #14215 @ajdiyassin)
  • /usage 和 omp usage 现在显示 Kiro 积分：每月计划积分及其重置日期、有效奖金积分及其到期时间，以及启用超额时的超额积分和费用 (@Xytronix 的 #18955，基于 #14215 @ajdiyassin)

已更改

  • 一个进程中的模型注册表（SDK 嵌入器、测试）现在共享已发现的模型构建，因此刷新另一个注册表会跳过重建先前已构建的模型

已修复

  • 修复了提交提示时 UI 短暂冻结的问题：提示历史记录现在在后台（100 毫秒内和退出时）写入磁盘，而不是在按 Enter 键时写入磁盘
  • 修复了合并大型提供商目录中发现的模型时 UI 冻结的问题：合并现在以切片形式运行，从而产生事件循环
  • 修复了当 Chromium 从未完成正常关闭时关闭 omp 的无头浏览器大约需要 7 秒的问题（在 macOS 27 上使用 Chrome for Test 150 看到）：omp 创建的配置文件上的浏览器现在立即被终止
  • 失败的计算机运行保留 JavaScript 和 Python Eval 中已生成的文本和屏幕截图，因此代理可以检查部分操作而不会丢失错误；直接计算机调用还会显示故障的名称和消息以及部分输出（#19100 by @will-bogusz）
  • 修复了当配置的凭据无法解析时（例如失败的 !command），Exa 和 Firecrawl 网络搜索会默默地回退到其无密钥公共端点；他们现在报告凭证错误
  • 修复了评估单元能够在未完成委托任务的情况下调用 yield（直接或通过 xd://yield）的问题； eval 现在拒绝 yield 并指向直接工具（@alphastorm 的 #19470）
  • 修复了早期输出后的服务 ready.log 和等待模式在行边界处与 ^ 和 $ 不匹配的问题 (#19471 by @alphastorm)
  • 修复了 shell 的 stat、diff 和 find 内置函数在打印文件时间时忽略 TZ 的问题； find -ls 现在打印 shell 时区的时间而不是 UTC，find -newermt 读取 shell 时区中类似 Nov 15, 2023 的日期 (#19482 by @alphastorm)
  • 当 TTSR 规则处于活动状态时，大型 write 和 edit 调用不再因其参数流而变慢（#19494 by @H4vC）
  • 修复了 /commit 和 eval commit 在合并期间创建单父提交的问题；当合并、cherry-pick、恢复、变基或 git am 正在进行中或索引有未解决的冲突时，提交现在会被拒绝（#19474 by @alphastorm）
  • 修复了 apply_patch 工具描述，将其称为 shell 命令并禁止绝对路径（#19325、#19468 by @alphastorm）
  • 修复了 shell 的 rg 内置忽略包含斜杠的 --glob 模式（#19476 by @alphastorm）
  • 修复了当 eval commit only(...) 的路径或 glob 之一与未更改的文件匹配时失败的问题；现在报告了不匹配的（@alphastorm 的#19472）
  • 修复了一个 Tern 浏览器块，在页面评估从未返回的调用（例如被重定向中断的调用）之后，用“选项卡正忙：此选项卡上的另一个调用仍在运行”来应答每个后续浏览器调用；现在，此类呼叫在其时间限制或取消时结束，并且该选项卡将接听下一个呼叫
  • 修复了浏览器工具报告 JavaScript confirm 或 prompt 仍处于打开状态，并且在用户 cli 将其关闭或另一个 CDP client 应答后对其进行页面调用失败的问题（#19481 by @will-bogusz）
  • 修复了 Chrome 中 <select> 上的 computer setValue 或 macOS 上 Electron 应用程序失败并显示空选项列表的问题；现在它选择值名称的选项 (#19224 by @will-bogusz)
  • 当另一个扩展程序的框架（例如撤销清除中继的密码管理器的自动填充菜单）使 Chrome 拒绝 omp 时，中继选项卡不再关闭：调用无法说明持有该选项卡的内容，该选项卡在用户离开时保持打开状态，并且下一个调用重新附加到它（#19178 by @will-bogusz）
  • 修复了计算机工具告诉模型只有 X11 接管才能在不发送任何内容的情况下结束的问题，因为用户一直在打字； macOS 接管现在也等待用户暂停并以相同的方式报告 UserIntervened (#19296 by @will-bogusz)
  • 当浏览器中继在选项卡 omp 驱动器（密码管理器的内联菜单或保存卡）中隐藏另一个扩展程序的框架时，遇到它的调用或该选项卡上的后续调用现在会命名框架的页面、扩展程序的 ID 和页面自己的标题，并表示该框架也对用户隐藏（#19001 @will-bogusz)
  • 人类网络搜索现在将 site: 范围的查询传递给 Claude，域和路径仍在文本中，并告诉 Claude 始终进行搜索，因此它认为可以从内存中回答的那些查找和查询不再因“未返回任何来源”而失败（#18125 by @will-bogusz)
  • 对带有拒绝后备模型（Opus 5 和 5.5、Sonnet 5.5、Fable 5）的 Anthropic Web 搜索，Anthropic 在另一个 Claude 模型上重试安全分类器 declines 的查询，并按名称报告拒绝或失败的搜索（too_many_requests，…），而不是“未返回来源” (#18125 作者：@will-bogusz)
  • 没有输出模式的子代理（包括没有 schema 的 eval agent() 调用）不再获得 yield 工具；他们的最终信息就是结果。
  • 没有 data 的 yield 不再使用子代理的最后一条消息作为结果；它仅完成已提交的增量部分。
  • 在后台打开 macOS 弹出按钮或菜单按钮菜单的 computer 按键现在无法列出项目并命名按键或选择一项的 click，而不是用键盘保持菜单打开（#19179 by @will-bogusz）
  • 修正了克劳德在模型切换后看不到早期 Codex、Kimi、Grok 和其他非克劳德转弯的推理，包括通过压缩保持的转弯；现在它以文本形式获取推理。当 Claude 由于携带推理而拒绝使用 Refusal (reasoning_extraction) 进行轮次时，轮次会在没有它的情况下重试一次，并且会话停止将其发送给 Claude (#7241) (#17610 by @will-bogusz)
  • 在人为拒绝之后，以后的回合不再重新发送拒绝文本，工具调用已停止：这些调用现在仅重播为“未执行”，因此一个 reasoning_extraction 拒绝停止使得会话的每个后续回合也可能被拒绝（[@flosrn]（https://github.com/flosrn）的[#19419]（https://github.com/can1357/oh-my-pi/pull/19419））
  • 修复了选择性提交跳过更新的子模块指针的问题；现在可以审查并显式选择现有的初始化 gitlink，而无需在子模块内提交更改（@kim-dali 的 #19556）
  • 修复了 git 读取，例如当后台 git 进程保持输出管道打开时 /commit 的状态扫描挂起（#19478 by @alphastorm）
  • 修复了在 macOS 上首次启动新的 WebKit 引擎构建时浏览器回退到 Chromium 的问题：当 macOS 扫描引擎的二进制文件和库时，WebKit 主机现在有 60 秒而不是 10 秒的时间来应答其问候语（#19423 by @shgew）
  • 修复了当终端的最后一个会话在另一个目录中启动并在其第一条消息之前关闭时，--continue 打开一个新的空会话；它现在恢复当前目录的最新会话（#19495）。
  • 修复了 eval commit 命名空间和 omp commit 引发的错误中缺少拒绝 pre-commit 钩子的标准输出（例如 pre-commit 框架的每个钩子报告）（#19449）
  • /commit 现在显示提交消息钩子写入提交的主题，而不是钩子运行之前的主题（#19448 by @eggpeat）
  • ^model 引用后跟句子标点符号现在注册其模型代理，而不是保留文字（#19445 by @yuzu-octopus）
  • 稀疏签出中的选择性提交不再将锥体外部的路径报告为提交挂钩的未暂存删除（#19453 by @yuzu-octopus）
  • Custom providers pointing at the Zhipu Coding Plan endpoint now retry at the Beijing-time quota reset instead of waiting eight hours too long (#19446 by @yuzu-octopus)
  • /copy 现在复制中间回合 out:// 回复显示的内容，而不是回复工具自己的“显示给用户”。结果，并在回合块中列出回复的代码块（#19551 by @bannert1337）
  • 修复了目标模式期间启用的工具在离开后变得不可用的问题（#19514 by @yuzu-octopus）
  • 修复了状态行使用部分显示多凭证 API 密钥提供商（例如 opencode-go）的另一个帐户的配额；现在，它遵循会话路由器实际从 (#19456) (#19492 by @thekitaev) 提供服务的凭证行。
  • 修复了 Mach-O 二进制文件的 Ghidra 分析中的 Objective-C 消息结果和arm64 保留寄存器数据流，包括之前分析的缓存提取框架（@shgew 的#19558）。
  • With a modal dialog open, browser fill, type and press aimed at a field behind it now fail naming what covers it, as click does, instead of typing into the dialog’s button and reporting success (on Chromium tabs and Tern tabs without native DOM reads); press also refuses a disabled element (on Chromium tabs and Tern tabs without native DOM reads), and Chromium drag refuses a covered start or end (#19524 by @will-bogusz)
  • Fixed RPC login refusing providers with an at-your-own-risk warning (antigravity-cli, google-antigravity): the warning now reaches the host as an extension_ui_request input, and login continues on “yes” and cancels on anything else (#19523)
  • On Linux, file watching for language servers no longer puts an inotify watch on every directory under node_modules and .git/objects, which could use up the system’s inotify watch limit and keep other programs such as systemd from adding watches (#19459)
  • /restart 现在通过启动器 omp 重新执行，因此打开的会话会转移到升级的二进制文件上，而不是重新运行保留的旧安装（#19529 by @yuzu-octopus）
  • RPC hosts now always receive a terminal agent_end after an over-quota 429: usage-limit bookkeeping is bounded so a stalled usage report can no longer hold the event (#19411, #19417 by @yuzu-octopus)
  • Rex and other OSC 7501 terminals no longer play a success sound mid-run when a stale agent end arrives after another run has opened (#17307, #19418 by @yuzu-octopus)

@oh-my-pi/pi-natives

添加

  • TtyWriter now works on Windows consoles: it writes off the JS thread in 16 KiB WriteFile chunks, restores the UTF-8 console code pages that child processes change, and stop() cancels a blocked write
  • 添加了 isolateThreadStartsFromConsole()，它可以防止终端停止读取的 Windows 控制台阻塞进程中的新线程

@oh-my-pi/pi-tui

添加

  • ui.loop-blocked 日志记录现在命名事件循环的内容（cause、causeShare、top），由始终在线的分析器采样； PI_LOOP_SAMPLER=0 将其关闭

已更改

  • 在 Windows 上，终端输出从 JS 线程中注销，因此输入和渲染在控制台消耗大量重绘时保持响应

已修复

  • 在 Windows 上，当终端停止读取其输出时，omp 不再冻结（挂起的 Windows 终端、暂停的 ssh client）；它会继续运行并在终端再次读取时赶上

@oh-my-pi/pi-utils

添加

  • 添加了 readBoundedBody 和 readBoundedJson，用于读取具有大小限制的 HTTP 响应主体，并带有可选信号，以便停滞的对等点不能超过调用者的截止日期（@Xytronix 的#18955）

发生了什么变化

  • 壮举：https://github.com/can1357/oh-my-pi/pull/18955 中的 @Xytronix 原生 Kiro 提供程序（IdC、Builder ID、Google/GitHub 登录、/使用）
  • 修复（计算机）：@will-bogusz 在 https://github.com/can1357/oh-my-pi/pull/19100 中运行失败时保留输出和屏幕截图 完整 Changelog：https://github.com/can1357/oh-my-pi/compare/v18.22.1…v18.22.2
