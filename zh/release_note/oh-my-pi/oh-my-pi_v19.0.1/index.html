oh-my-pi v19.0.1

oh-my-pi v19.0.1

@oh-my-pi/pi-ai

已修复

  • 修复了 GIF 图像无法通过 HTTP 422 进行 Liquid AI 判断的问题；它们现在以 PNG 形式发送（@alphastorm 的 #19757）
  • 人类严格工具回退现在将 structured_outputs（allowedPartnerModelFeatures /“不允许的功能结构化_输出”）的 Vertex 组织策略拒绝视为严格工具拒绝，在没有 strict 的情况下重试一次，并通过引脚 strictToolsDisabled (#19576) (#19655 @koeria)
  • 使用 Input is too long. 或 CONTENT_LENGTH_EXCEEDS_THRESHOLD 拒绝的 Kiro 请求现在可以通过会话压缩来恢复（@emotionbug 的 #19723）
  • Kiro 思考现在会关闭推理，而不是运行模型的默认工作；无法禁用推理的模型会使用最低的努力（@emotionbug 的#19722）
  • Kiro /usage 显示购买的附加积分，并且计划积分已用完的帐户在附加积分剩余的情况下继续提供服务（#19724 by @emotionbug）
  • AWS GovCloud（美国）中的 Kiro Identity Center 登录现在列出 us-gov-west-1 和 us-gov-east-1 中的配置文件，而不是商业区域，后者拒绝 GovCloud 令牌（@TechDufus 的 #19726）
  • 无状态网关错误读取 stream interrupted 现在像 stream was interrupted 一样重试，而不是结束回合（[#19709]（https://github.com/can1357/oh-my-pi/issues/19709））。

@oh-my-pi/浏览器中继

已修复

  • 浏览器中继扩展在加载权限集早于 downloads 权限的浏览器中继续存在：服务工作线程无需下载配对即可继续工作，而不是在连接之前崩溃（#19659 by @pavel-kalmykov）

@oh-my-pi/pi-目录

添加

  • 新增Liquid AI的d1.2和d1.2-ultra裁判模型； liquid 现在默认为 d1.2 (#19753 by @alphastorm)
  • 将 gemini-4-neon 添加到捆绑的反重力 CLI 名册中，并提供 agy 为其提供的 low/medium/high/xhigh 思想水平（#19787 by @ataberkus）。
  • Model.snapcompactShape ({ variant, frameSize? }) 为模型提供了自己的 snapcompact 框架形状 (#19591 by @ryanskidmore)

已修复

  • 发现当思考被设置为关闭时，无法关闭推理的 Kiro 模型现在会使用最低支持的努力（#19722 by @emotionbug）
  • Kiro 接受 AWS GovCloud（美国）配置文件 ARN (arn:aws-us-gov:codewhisperer:…)，该 ARN 之前在配置文件列表期间被跳过 (@TechDufus 的 #19726）
  • Google Antigravity 不再将 Gemini 4 Hydrogen 的声纳监视器插槽或其分层 High/XHigh SKU 作为单独的型号列出；分层 SKU 折叠成一个 Gemini 4 Hydrogen 型号（@eggpeat 的#19795）
  • Google Antigravity 上的 Gemini 4 Neon 现在显示为一个模型，其思维水平（低、中、高、xhigh）选择匹配的 SKU，而不是四个单独的模型，并且定价为每百万代币 3/15 美元（$0.15 缓存）而不是 0 美元（#19789 by @eggpeat）
  • Gemini 4 Neon 现在也可以在 Gemini CLI 上折叠成一个模型，在 Gemini API 和 Vertex AI 上提供 xhigh 思维水平和高达 262,144 个代币的长输出，其价格为 3 美元/15 美元 Gemini API

@oh-my-pi/pi-coding-agent

添加

  • /session 显示会话的 local:// 目录的路径，/copy local 复制它，首先创建目录，以便可以在写入任何内容之前输入该目录（@farnoy 的 #19778）
  • models.yml 型号、modelOverrides 和扩展 registerProvider 型号上的 snapcompactShape 设置该型号的 snapcompact 框架形状（#19591 by @ryanskidmore）

已修复

  • 修复了 PTY 命令记录有时会出现一个空行，其中 \r\n 行结尾被分成两个终端读取。
  • 修复了 Windows 上 shell 的 dirname 内置忽略 \ 分隔符和驱动器前缀（dirname 'C:\a\b' 打印 .），这会破坏 VS Code 的 code 启动器 (./Code.exe: No such file or directory) 等脚本
  • 修复了当命令由 \ 路径或 .exe（"C:\Program Files\Git\cmd\git.exe" status、git.exe log）命名时在 Windows 上跳过 bash 输出最小化的问题
  • 修复了捆绑的 omp://tools 文档仍然描述已删除的 ida 工具； tools/dsm.md 现在记录 eval 的 dsm 命名空间和 disassembler.* 设置，而 tools/read.md 记录仅元数据可执行读取（#19608）
  • 修复了本机终端主机（例如 Tern）将扩展放置在编辑器小部件上方以及状态行和托盘之间的空白行；小部件现在位于状态行上方 (#19767)
  • 修复了排队消息中提到的 ^model（代理忙时的 ->/=>、编号列表的后续项目、RPC steer/follow_up、ACP 转向）以文字 ^provider/model 文本到达模型，而不是通过注册其 m<N> 代理（#19683 @a-glapinski)
  • 修复了当代理正忙于以文字形式访问模型时使用 sendUserMessage({ deliverAs: "steer" | "followUp" | "aside" }) 发送的扩展消息中提到的 ^model (#19799 by @H4vC)
  • 修复了未送达的 ^model 提及后排队的每条消息，向模型重复“m<N> 现已可用”通知（#19799 by @H4vC）
  • 具有非字符串 extensions 条目（例如对象）的插件清单不再使使用 ERR_INVALID_ARG_TYPE 加载扩展崩溃；该条目被报告为未找到，但有效条目仍在加载（#19674 by @koeria)
  • 修复了嵌入的 bash script.sh 将 BASH_SOURCE[0] 解析为 bash 而不是脚本路径，这会破坏脚本加载自身旁边的文件（#19792）
  • 修复了代理模型发现忽略网关广告的输入模式和输出令牌上限的问题（#19754 by @zhyc9de）。
  • 修复了通过身份验证网关（models.yml 中的 transport: pi-native）路由的提供商仍然列出来自提供商自己的端点的模型，并在那里发送网关密钥；此类提供程序现在跳过提供程序的模型发现并保留其捆绑和缓存的模型（#19646 by @ray8828）
  • 修复了压缩后第一轮的虚假“缓存未命中”标记：压缩会重写提示前缀，因此未命中是预期的并且不再被标记（[@Petyok]（https://github.com/Petyok）的[#19679]（https://github.com/can1357/oh-my-pi/pull/19679））
  • 修复了当会话目录不再存在时 --mode rpc、--mode rpc-ui 和 --mode acp 下的 omp --resume <id> 在启动时失败的问题；会话现在在其存储位置打开，以启动目录作为其工作目录，而不询问是否移动它（#19651 by @sjawhar）
  • 修复了浏览器中继扩展在加载权限集早于 downloads 权限的浏览器中默默死亡的问题：它现在无需下载配对即可继续工作，并且中继报告下载跟踪间隙而不是通用的未找到（#19659 by @pavel-kalmykov）
  • 当访客加入时，共享其子代理报告进度快于上行链路消耗的会话不再以“协作发送积压超出其限制”结束
  • 修复了 /loop 迭代和 /goal 延续在回合后触发约 800 毫秒以等待后台子代理或作业；他们现在等待运行完成 (#19781)
  • 修复了Codex和OpenAI API网络搜索忽略web角色思维水平的问题（openai-codex/gpt-6-luna:xhigh）；现在级别达到了 reasoning.effort 的请求（#19793）
  • 修复了计划审查根据预先计划模型而不是“继续”滑块中选择的层来测量“批准并保留上下文”的问题，因此切换到更大的上下文层现在可以启用它（[#19660]（https://github.com/can1357/oh-my-pi/issues/19660））

@oh-my-pi/pi-natives

已修复

  • 修复了保存会话时 WSL2 上的 omp 冻结几秒到几分钟的问题：Linux FileLock 现在锁定 sidecar 文件而不是绑定套接字，每次调用大约需要 10 毫秒。仍在运行的较旧的 omp 版本看不到这些锁，因此更新后重新启动它们（#19704 by @turgaybulut）

@oh-my-pi/snapcompact

添加

  • resolveShape() 使用模型配置的 snapcompactShape 代替其模型系列默认值；显式变体仍然获胜，并且计费仍然遵循模型（#19591 by @ryanskidmore）

@oh-my-pi/omp-stats

添加

  • 在统计仪表板时间选择器中添加了带有每小时存储桶的 2d 和 3d 范围预设（#19766、#19774 by @thekitaev）。

@oh-my-pi/pi-tui

添加

  • 本机会话表将 Local 报告行（会话的 local:// 目录）显示为 ID 和文件旁边的可复制字段（#19778 by @farnoy）

已修复

  • 修正了之前会话中的图像在 herdr-app 中的 /new 之后重新出现在屏幕左上角的问题 (#19749 by @jaredlyon)
  • 循环停顿诊断 (ui.loop-blocked) 在没有 TUI 运行时不再对 JS 线程进行采样，例如在外部编辑器中或会话结束后 (#19703 by @will-bogusz)
  • 修复了使用情况仪表板，将没有配额栏（预付余额、已用配额）的耗尽或压力使用行呈现为暗淡的信息文本；他们现在采用报告状态所需的错误或警告颜色，并且没有可测量金额的已用配额显示为“耗尽”而不是“无数据”（#19764）
