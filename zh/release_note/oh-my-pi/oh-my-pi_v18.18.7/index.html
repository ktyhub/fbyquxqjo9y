oh-my-pi v18.18.7

修订 发布时间2026年11月10日 来源can1357/oh-my-pi 英文原文

oh-my-pi v18.18.7

@oh-my-pi/pi-ai

添加

  • LiteLLM 使用适配器 (@oh-my-pi/pi-ai/usage/litellm) 报告网关的密钥和用户美元预算（#17873 by @maykonmichel)
  • UsageApi.replaceConfiguredProviders 在运行时覆盖和内置解析器之间注册配置来源的使用提供程序，并且 UsageProvider.usesRequestKey 仅使聚合使用探测将发送的关键推理 (#17873 by @maykonmichel)

已更改

  • 具有 login-warning 身份验证规则的提供商会在新登录之前显示其帐户风险，并仅在用户回答 yes 后才启动；任何其他答案或取消都不存储任何内容，并且他们的登录列表条目被标记为“（风险自负）”（#18499）

已修复

  • 克劳德寓言发射重置现在报告他们清除的寓言每周限制，而不是未知窗口（#18661 by @TheAifam5)

@oh-my-pi/pi-目录

添加

  • 在元模型 API 和 Muse 代码上添加了 Muse Ember (muse-ember-1.0)，具有 minimal–max 推理工作量阶梯及其 >200K 长上下文定价
  • 添加了 login-warning "<text>" 身份验证规则，这使得新登录首先接受规定的帐户风险（#18499）

已更改

  • 在登录警告后恢复 Google 反重力而不是暂停它 (#18499)

已修复

  • Morph (api.morphllm.com) 请求现在发送 x-session-id，与保存其提示缓存的工作进程保持对话 (#18704 by @wolfiesch)

@oh-my-pi/pi-coding-agent

添加

  • /usage 和 omp usage 显示内置 litellm 提供程序和每个具有 discovery.type: litellm 的 models.yml 提供程序的 LiteLLM 密钥和用户预算，除非在 disabledProviders 中列出（@maykonmichel 的 #17873）
  • 分机可以在交互退出前询问操作员，或使用 session_before_shutdown 取消交互；进一步的 /exit 或 Ctrl+D 会跳过挂起的提示并关闭 (#18424 by @aw1cks)

已更改

  • 每个窗口设置已保存重置自动兑换：codexResets.autoRedeem5h/autoRedeemWeekly 和 claudeResets.autoRedeem5h/autoRedeemWeekly/autoRedeemFable 替换每个提供商的 autoRedeem，其值迁移到 5 小时和每周密钥中；克劳德寓言发射重置仅由 autoRedeemFable 控制，并且仅用于包含《寓言》每周上限的区块，或在《寓言》使用量高于零时到期之前（#18661 by @TheAifam5)
  • 没有提示 UI 的会话（例如 omp -p）不再花费已保存的重置，而自动兑换为 unset，即使是即将过期的会话（#18661）
  • Google Antigravity 回到 /login 和 omp login 中，标记为“（风险自负）”：新的登录首先说明 Google 可能会暂停从第三方工具登录的帐户，只有在您输入 yes 后才能继续；保存的反重力登录再次起作用（[#18499]（https://github.com/can1357/oh-my-pi/issues/18499））
  • 在 Windows 上，bash 工具的描述告诉模型它在模拟的 bash 环境中运行，而不是 cmd 或 PowerShell，因此它编写 bash 而不是 dir、%VAR% 和其他 cmd 语法

已修复

  • 当操作员仍在接听时，session_before_* 处理程序显示的分机提示不再在 30 秒后超时（#18424 by @aw1cks）
  • 第二个退出请求现在会跳过待处理的 worktree.onExit 提示并保留这些工作树，而不是等待答案（#18424 by @aw1cks）
  • 使代理在完成后继续工作的建议不再第二次返回，通常作为阻止者，而代理正在修复它：顾问对早期答案的审查被取消，顾问对修复进行审查（#18735 by @H4vC）
  • 在 Windows 上，bash 工具的 shell 会解析各处的 MSYS 驱动器路径（/c/Users/...、/mnt/c/...），因此运行 /c/.../tool.exe、cd /c/...、[ -f /c/... ] 和 < /c/... 会到达驱动器 C：就像它们已经对 ls 和其他内置实用程序所做的那样
  • 在 Windows 上，bash 工具中的 cmd 样式命令行（例如 dir | find /c /v ""、sort /r、timeout /t 5 和 whoami /all）运行为其编写的 Windows 程序，而不是 pi 的 GNU 样式 find/sort/timeout/whoami（将 /c 读取为驱动器 C: 并且可以遍历整个驾驶）
  • 在 bash 工具的 shell 中更改或取消设置 PATH 现在会像 bash 一样忘记记住的命令位置，因此命令不再从离开 PATH 的目录运行
  • 一位缓慢或泛滥的协作客人不再结束房间共享：主持人删除该客人的积压并要求其重新加入，可以加入大于发送预算的会话，并且无人收到的客人问题被解决为不可用（#18629 by @iliaal)

@oh-my-pi/pi-tui

已更改

  • 没有匹配项的 grep 和 ast_grep 结果呈现为一行，并带有警告颜色的 0 matches，删除单独的 No matches found 行（#18700 by @JustasMasiulis）

已修复

  • 已保存重置消息将克劳德寓言每周限制命名为“克劳德寓言每周”，而不是其原始 ID（#18661 by @TheAifam5）

发生了什么变化

  • 修复（tui）：在 https://github.com/can1357/oh-my-pi/pull/18700 中 @JustasMasiulis 在一行上以黄色显示 grep 的 0 个匹配项
  • 修复（shell）：通过 https://github.com/can1357/oh-my-pi/pull/18703 中的 @H4vC 解析 Windows 引擎中的 MSYS 驱动器路径（/c/…）
  • 修复（目录）：将 Morph 对话固定到 https://github.com/can1357/oh-my-pi/pull/18704 中 @wolfiesch 的 x-session-id 的一名工作人员
  • 修复（shell）：通过 https://github.com/can1357/oh-my-pi/pull/18711 中的 @H4vC 的 Windows 程序 pi 的实用程序 Shadow 运行 cmd-syntax 命令行
  • 壮举（编码代理）：将已保存重置自动兑换分为 5 小时、每周和 Claude Fable 设置，由 @TheAifam5 在 https://github.com/can1357/oh-my-pi/pull/18661 中设置 *修复（顾问）：停止被取代的评论重新提出建议，主要问题已经由https://github.com/can1357/oh-my-pi/pull/18735中的@H4vC修复
