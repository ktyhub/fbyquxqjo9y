oh-my-pi v18.18.4

oh-my-pi v18.18.4

@oh-my-pi/pi-ai

添加

  • 添加了 base64SkipThoughtSignature 兼容标志，以便将 thoughtSignature 解码为 base64 的 Gemini 网关（例如 Hyperspace AI LLM 代理）可以接收未签名工具调用旁路哨兵，而无需使用 400 拒绝请求（@tandinh0801 的#18586）。

已更改

  • 由 disabled 身份验证规则（当前为 Google Antigravity）暂停的提供商将被排除在内置登录列表之外，拒绝登录、令牌刷新和使用探测，不解析任何来源的密钥，并拒绝带有暂停原因的请求和图像生成；删除规则后，存储的登录信息将被保留并再次工作，并且在暂停的 ID 下注册自己的登录信息的扩展会将其收回（#18622 by @H4vC）

已修复

  • 称为 Cursor MCP 工具的专用工具（edit、write、eval 等）现在保留其在工具批次中的位置，因此通过编辑发送的 shell 或读取不再针对旧文件运行或在较早的调用完成之前启动（#18502 by @eggpeat）

@oh-my-pi/pi-目录

添加

  • 添加了 Otari 网关提供商：/login otari 和 OTARI_API_KEY，每个工作区实时发现的模型（#17841 by @tbille）
  • 添加了 base64SkipThoughtSignature Google compat 标志，该标志为将 thoughtSignature 解码为字节的网关发送 Gemini 未签名工具调用旁路哨兵 base64 编码（#18586 by @tuandinh0801）。
  • 添加了暂停提供程序的 disabled "<reason>" 身份验证规则：没有登录提供它，也没有任何东西调用它，而其代码和用户存储的登录保持不变（#18622 by @H4vC）

已更改

  • 暂停了 Google 反重力，因为 Google 可能会限制在自己的应用程序之外使用它的帐户（#18622 by @H4vC）

@oh-my-pi/pi-coding-agent

添加

  • SDK：PromptOptions.followUps将提示排队，在提示后按顺序运行；如果提示从未到达代理，他们会在 DroppedPrompt.followUps 中返回提示

已更改

  • task 工具不再公布每次调用的 model 字段，除非 task.perCallModel 是 on 或者捆绑的降神会是可生成的；无论如何发送的 model 在发送前仍然被拒绝 (#18554 by @xiangnan0811)

已修复

  • /usage、会话统计和 omp stats 现在包括来自默认分叉标题和微型标题模型的会话标题支出，并且微型模型标题计入 --max-cost（#18177、#18491 by @yuzu-octopus）
  • --model pi/<role>（或 @<role>、<role>）之后的重试现在会走该角色的 retry.fallbackChains 条目而不是 default 链，包括在 --continue 上（#18389、#18534 @harshaygadekar)
  • 修复了发送到空闲会话的 -> / => 列表，该会话在第一个项目之前运行第二个项目；如果第一个项目无法启动（Esc，设置被拒绝或失败），整个列表将返回到编辑器（#10802）
  • 修复了当系统提示和工具模式单独超出压缩预算时，自动压缩每次都会重复的问题；它现在改为警告一次（#18589）。
  • 修复了每次调用的空白 model（"" 或空格）导致任务调用、eval agent() 和 eval workpool() 失败的问题，而不是使用代理的配置模型（#18576 by @iwangjie）
  • 使用空模型字符串或空模型数组的 task 工具调用现在使用代理的正常模型路由（#18554 by @xiangnan0811）
  • 修复了没有阶段失败的 todo append，而不是将任务添加到活动阶段、最后一个阶段或新的 Tasks 阶段（#17265、#18575 by @taotao7）。
  • 仅学习记忆指导不再告诉模型读取丢失的 memory_summary.md （@nick-maderight 的 #18523）。
  • 现在超时的 wait 会显示它等待了多长时间以及连续等待允许多长时间，而不是返回代理读取为空结果的裸露仍在运行的快照，并且连续提醒告诉代理不要启动 sleep 作业以等待更长时间（@alphastorm 的#18612）。
  • 即使 modelRoles 未设置角色，auth-gateway stdio 现在也会遵循角色配置的后备链（没有自己链的聊天角色继承 default 链）（#18509 by @enieuwy）
  • 在伪 shell 可视化中，; 分隔的链不再将其语句分隔符绘制为自己的行，因此 echo a; echo b 读取为两个语句（#18258、#18497 by @yuzu-octopus）
  • Autoresearch update_notes 和 append_idea 现在会创建一个 ## Ideas 部分，而不是在笔记仅包含类似名称的标题（例如 ## Ideas backlog 或 ### Ideas）时在第一个标题之前插入项目符号（#18505 by @eggpeat）
  • 称为光标 MCP 工具的专用工具（edit、write、eval 等）现在保留其在工具批次中的位置，因此在编辑后立即发送的检查会看到新文件，并且在较早的读取完成之前不再开始编辑（#18502 by @eggpeat）
  • 现在，一旦 30 天的审核期结束，即使没有隔离新内存，隔离的事后记忆也会被删除（#18504 by @eggpeat）
  • 压缩显示摘要不再要求推理，因此思维模型返回摘要，而不是花费 512 个令牌上限进行推理并且不返回任何内容（#18541 by @phillipxkang）
  • 对同一模型的重试现在在连续三次通用中止后停止，而不是花费整个重试预算（#18535 by @nick-maderight)
  • 当 lsp.formatOnWrite 包含 JSDoc/块注释或一次性奇数缩进时，lsp.formatOnWrite 不再以每级 1 个空格重新缩进 2/4 空格文件，并且不再将使用 JSDoc 块打开的制表符缩进文件转换为空格（#18544）
  • 隔离任务沙箱现在可以在 SIGHUP 或其他信号后完成清理，即使释放它们所需的时间比代理关闭宽限期长（#18519）。

@oh-my-pi/pi-mnemopi

已修复

  • 修复了后期后台嵌入写入覆盖更新记忆的新向量或为删除记忆重新创建向量的问题（#18503 by @eggpeat）
  • 修复了为不同本地嵌入模型配置的第二个 Mnemopi 实例，静默重用第一个实例的编码器，同时使用配置的模型标记其向量：本地编码器现在按模型缓存，失败的加载仅逐出该模型的条目（#18562 by @eggpeat）

@oh-my-pi/omp-stats

已修复

  • 修复了文件系统设备号更改后 omp stats 重新解析每个未更改会话的问题，例如跨 ZFS 重新安装 (#14736) (#18536 by @Alex-Wengg)。

@oh-my-pi/pi-tui

添加

  • 包含两个或多个 <fieldset> 的 ask HTML 表单在每个问题上显示一个选项卡，并在 Tern 中显示一个“评论”选项卡；接下来继续，←/→ 和 PgUp/PgDn 切换选项卡，并提交审核中的生活 (#18608 by @Gabriel-Hiss)
  • ask HTML 表单使用 app.ask.hide (Alt+H) 或隐藏按钮隐藏到一行，就像询问对话框一样 (#18608 by @Gabriel-Hiss)

已修复

  • 预填充的单行 ask 字段现在在其值的开头打开，而不是在聚焦时滚动到末尾（#18585）。
  • 修复了包裹盒图树线 (├── **label**: …) 的 │ 导轨，在彩色 Markdown 下采用节点前导粗体、斜体或代码跨度的颜色和粗细；延续轨道现在与第一行的轨道匹配，并且节点文本保持自己的样式（#18584 by @chan1103）
  • 修复了事件循环停止后中继的 Windows 终端事件，这样它们既不会中止正在运行的回合，也不会在编写器中输入 TSP 数据（#18512）。
  • 修复了作曲家上方几圈的转录行从屏幕和回滚中消失的问题，在每次调整大小时都会移动的位置，而待办事项列表或子代理面板在一轮后保持不变（#18510 by @mccraigmccraig)
  • 修复了 xd://<device>:raw 和 xd://<device>:conflicts 解析为该设备的问题。这些后缀保留在名称中，因此读取或写入不再运行设备（#18561 by @wisehead）
  • 修复了比作曲家区域高的 ask HTML 表单在 Tern 中被切断且不可滚动的问题：表单现在在作曲家位置滚动，并且“取消/提交”保持可见
  • 修复了 Tern 中的特工中心在列出数百个特工后冻结自身及其后面的会话的问题：移动选择不再重新发送每个名册行，并且大型中心上的实时名册更新会批量更新（最多每秒一次），以便终端保持同步
