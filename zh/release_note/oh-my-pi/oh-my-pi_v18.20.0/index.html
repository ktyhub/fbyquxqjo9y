oh-my-pi v18.20.0

@oh-my-pi/pi-agent-core

已更改

  • prepareCompaction() 作为 compaction.prepare 循环阶段运行，因此 ui.loop-blocked 从冷令牌遍历长分支名称压缩而不是“未知”（[@wolfiesch]（https://github.com/wolfiesch）的[#15027]（https://github.com/can1357/oh-my-pi/issues/15027），[#18867]（https://github.com/can1357/oh-my-pi/pull/18867））停顿

@oh-my-pi/pi-ai

添加

  • 为 Google 的 Gemini Decisions API (gemini-decision-1) 添加了 google-decisions 判断 API，带有文本和图像输入（#19060 by @kevcube）
  • 将 apiKey 添加到 oauth.accessById() 和 oauth.accessAll() 的成功 OAuthAccessResolution 结果中：为该帐户发送的关键正常请求，这与具有结构化凭证的提供商的 accessToken 不同（@Xytronix 的 #19030）
  • 在 ToolCallLoopGuard 中添加了可选的 exemptionAlias，以便传输调用可以与 exemptTools 中调度的工具名称相匹配（#18860）
  • 为 Liquid AI 的决策模型添加了 liquid-systemone 判断 API，该判断在发送之前拒绝超过 Liquid 10,000 个 32×32 补丁请求上限的图像集（#18076、#18100 by @SuperUserA）
  • 为 Nace 的 Drex 决策模型添加了 nace-systemone 判断 API，它将图像作为 Drex 的顶级 images 数据 URL 发送，并用描述替换 Drex 在判断文本中拒绝的 Base64 图像、音频、视频和 PDF 数据 URL (#18950 by @alphastorm)

已修复

  • 修复了已使用的 Codex 帐户在其兄弟姐妹仅被拒绝所请求模型的情况下每分钟重试的问题：它们的短模型策略块不再算作可用的兄弟姐妹，因此使用限制等待会跟随已用帐户的重置并且模型回退可以接管（[#17637]（https://github.com/can1357/oh-my-pi/issues/17637），[#19019]（https://github.com/can1357/oh-my-pi/pull/19019） @wolfiesch)
  • Auth-gateway client 令牌 (serve --clients) 无法再设置请求来自谁、谁付款或网关如何到达提供商：聊天路由删除其请求标头、userProfileId、initiatorOverride、metadata、serviceTier、cacheRetention 和其他仅网关选项，而网关令牌保留它们(#19067 作者：@alphastorm)
  • 修复了身份验证网关的 /v1/pi/stream 丢弃其他聊天路由接受的 taskBudget、include 和 anthropicPrefixMismatchBehavior (#19067 by @alphastorm)
  • 修复了对 Vertex AI Mistral 合作伙伴模型（mistral-medium-3、mistral-small-2503、codestral-2）的请求失败的问题，因为它们是以 Anthropic 的请求格式发送的（#19010、#19022 by @yuzu-octopus）
  • 添加了 Gemini 的 xhigh 思维水平，发送到 Gemini API 和 Vertex 上，用于梯子暴露它的模型（Gemini 4 Hydrogen）。
  • 修复了当 ~/.aws 是文件而不是目录时 omp 无法以 ENOTDIR: not a directory, stat '~/.aws/credentials' 启动的问题 (#19083 by @iamshatter)

@oh-my-pi/pi-coding-agent

重大变化

  • secrets.yml 正则表达式规则现在是 Rust regex 模式，以线性时间本地运行：不再支持环视和反向引用，并且 (?P<secret>…) 组标记要编辑的部分（其周围的文本是保留的上下文）； \d、\w 和 \s 可以识别 Unicode。未编译的正则表达式规则会停止启动，并出现命名文件和条目的错误，而不是被跳过。将(?<=password=)\S+迁移至password=(?P<secret>\S+)；请参阅 docs/secrets.md（#18965 作者：@H4vC）
  • 秘密占位符现在是友好名称后的四个驼峰式单词，例如GitHubToken_correctHorseStapleBattery，没有 $$ 分隔符，无论模型在何处写入分隔符，记录都会显示真实值。旧 $$NAME_HASH:CASE$$ 表单中的占位符在此更改之前保存的会话中保留文字文本，包括在模型将其复制到的工具调用中；启动一个新会话以获取工作占位符（#19014 by @H4vC）
  • 模型从占位符写入的内容（回复、思考、工具调用、摘要）存储为写入和重放的字节相同，保持思考签名和提示缓存有效；仍然保留值的模型输出（在密文关闭时或配置机密之前写入）将在重播时进行密文编辑。正则表达式规则稍后找到的值不再重写早期历史记录。 friendlyName 按写入方式向模型显示，并且仅当它阐明自己的秘密时才会被删除（@H4vC 的#19014）
  • Nix 使用 withAppleFm = false 构建不再使用主机的 Xcode 编译 Apple Foundation Models 桥接 (#18911)
  • Apple Silicon Nix 构建包含 Apple Foundation Models 支持，而不是在没有它的情况下默默构建（#16584 by @honsunrise）
  • 没有表单对话框的 RPC 主机上的 ask 现在显示每个提示以及表单周围的段落、列表、预格式化块和表格，而不仅仅是问题（#18927）

添加

  • 为 judge 角色添加了 Gemini Decision 1 法官 (google/gemini-decision-1)，models.yml 接受 google-decisions API (#19060 by @kevcube)
  • ssh:// 主机列表、ssh:// 自动完成和 /ssh list 现在包括 ~/.ssh/config 和 /etc/ssh/ssh_config 的 Host 别名（以下为 Include）； ssh.json 参赛作品因名称冲突而获胜
  • 添加了 find.verifyModel，一个模型选择器，其法官仅回答 find 的通道验证，而文件名和草图排名保留在 judge 角色上（#19006 by @alphastorm）
  • 添加了 omp bench --account 以对特定存储的 OAuth 帐户进行基准测试，并报告拒绝的优先级请求，而不是默默地对标准速度进行基准测试。
  • 将浏览器或计算机调用类型文本输入到页面或应用程序中，例如密码，不再以纯文本形式出现在 eval 单元格的状态行或会话文件中（#18981 by @will-bogusz）
  • Tern 和 WebKit 中的浏览器页面脚本观察现在会屏蔽密码值，包括用作可访问名称或描述的值 (#18983 by @will-bogusz)
  • Chromium 主世界 waitForFunction 调用不再将 Puppeteer 的内部 ARIA 查询绑定公开到页面脚本（#18883 by @will-bogusz）
  • 在 macOS 上，在启用安全输入时结束的 computer 运行现在以一条注释开始，该注释命名了持有它的应用程序，并表示用户的 Escape 和输入在运行结束之前不会被看到，而不是在 capabilities() 仍然报告 globalEscape: true 时什么都没有（#18982 by @will-bogusz）
  • Windows 计算机现在运行时会解释锁定或断开连接的会话或安全桌面何时阻止捕获和输入确认应用程序的状态（#18947 by @will-bogusz）
  • 计算机助手现在拒绝未知的选项和过滤键，而不是默默地忽略它们，包括所选 wait 或元素 press 重载未使用的键，并命名有效键和可能的拼写更正（#18753 by @will-bogusz）
  • 选择器等待 Chromium 支持的浏览器选项卡，其框架现在接受 state: "attached" | "detached" | "visible" | "hidden" 以及 Puppeteer 的 visible/hidden 表单，包括实时快照引用和跨导航的等待，并拒绝未知选项、无效值或冲突的可见性标志，而不是默默地忽略它们。帧等待超时在同一运行中稍后仍可捕获； Tern 和 cmux 选项卡未更改（#18924 by @will-bogusz）
  • Chromium 主世界 waitForFunction 在提前等待后通过导航调用重新武装，而不是通过“等待失败”来拒绝（#18884 by @will-bogusz）
  • 在 Chromium 浏览器选项卡中，隐藏匹配上的 tab.hover 和元素句柄 hover() 现在等待它出现，如果它从未出现，则会因原因（以及选择器的匹配计数）而失败，就像 clicks 所做的那样，而不是立即因 Puppeteer 的“节点不是 clickable 或不是元素”而失败(#18750 作者：@will-bogusz)
  • 将浏览器 tab.console() 或 tab.errors() 的结果视为数组现在失败，并显示一条消息，提示读取其 .entries，而不是 slice is not a function，并且浏览器文档声明了 { entries, nextSeq, dropped } 形状（#18738 by @will-bogusz）
  • 打印的浏览器 tab.observe() 结果，包括通过 tab.run() 返回的完整观察结果（不是具有 elements 数组的任意对象），或作为 JavaScript Eval 单元格的最后一个值留下的一个，显示每个元素，每个元素一行，而不是前 100 个，后跟 ... N more items；返回后观察发生变化，包括就地原型编辑、作为普通检查输出打印、包含每个元素（#18772 by @will-bogusz）

已更改

  • 秘密修订不再针对每个请求重新扫描整个对话：重复使用先前请求中已修订的文本，直到新的秘密更改结果为止，并且 secrets.yml 正则表达式规则会跳过缺少前导文字的文本，将大型会话的修订时间从 17–55 毫秒减少到每个请求的约 1 毫秒，并将加载后的第一个请求缩短 2–4 倍
  • 修改了默认系统提示：工具选择规则现在仅指向read、edit和find；推理格式、AST 和子代理限制指南消失了（ast_edit/ast_grep 在自己的摘要中陈述了他们的偏好）；工作流程、交付和关键规则更短，不再相互重复； Spotlight 关于工具结果如何形成的注释是工具 I/O 下的一个简短列表，而不是末尾的一个段落；和 xd:// 设备按裸名称列出
  • edit.modelVariants 现在选择最长的匹配模型模式而不是第一个，因此无论配置顺序如何，像 openai/gpt-5 这样的特定键都会胜过 gpt (#17835 by @DeprecatedLuke)
  • 安装 ABKit 引擎后，浏览器选项卡在 omp 自己的无头 WebKit 引擎中打开，而不是在托管 Chromium 中打开（Windows 上的 ~/.o2/lib/abkit/ABHost、ABHost.exe，Tern 也使用该位置；或 browser.webkitPath 设置/PI_BROWSER_WEBKIT_PATH）：页面会看到一个可见的、聚焦的窗口，没有自动化标志，并且默认选项卡在页面中不运行 omp 脚本（控制台、错误和请求日志来自引擎；route、地理定位/区域设置/离线仿真、vitals 和 reactEnable 仅在调用时添加页面代码； Chromium 仍然打开 headed 选项卡，其中引擎没有查看器并接管，并在引擎无法启动时说明原因； app: "chromium" 选择 Chromium 进行一次打开，app: "webkit" 需要 WebKit（headed: true 的选项卡在窗口中打开），而 browser.webkit 设置或 PI_BROWSER_WEBKIT=0 将其关闭。在 macOS 上，该引擎具有 WebGL、WebGPU、静默视频和音频播放、Web Audio、WebRTC、WebAuthn、游戏手柄和 Web Share，其 TLS 握手、HTTP/2 设置和请求标头是 Safari 发送的
  • 当 app: "webkit" 丢失时，omp 将其 WebKit 引擎 ABKit 从 build.stencil.so 下载到 ~/.o2/lib/abkit（根据构建的 SHA-256 检查）；当打开发现未安装浏览器时，在 Chrome 之前进行测试；下载失败会在 Chromium 上打开并说明原因
  • task工具描述现在仅列出交付规则（结果自动交付、wait、未经验证的completed）； read proc://、write proc://<id>/kill、作业到期和 write agent:// 参考随会话的第一个生成结果一起到达
  • ask.timeout 设置、README 和 RPC 架构文档现在将 ask 工具描述为在超时时提交其当前值的 HTML 表单，而不是自动选择选项的问题选择器
  • bash 工具描述再次直接从 shell 列出嵌入式 shell 的进程内内置函数，因此它遵循每个 PI_DISABLE_* 交换机和平台
  • read 的 SQLite、存档、JSON 查询、可执行文件、视频和 SVG 的选择器，以及 proc://、ssh:// 和 issue:///pr:// 的子路径语法，不再随每个请求一起提供：模型在 xd://read/sources 和 xd://read/urls 处按需读取它们，并且它们保留read 关闭时内联
  • /browser visible 和 /browser headless 现在立即显示和隐藏 omp 的 WebKit 选项卡的窗口，而不是等待下一次打开：引擎提供其查看器 (macOS) 时，每个选项卡都有一个自己的窗口，用户也可以 click、滚动和输入，并且 headed: true 或 browser.headless off 在 WebKit 上保留带有窗口的选项卡，而不是将其发送到铬。 Chromium 选项卡仍会在下次打开时更改模式
  • 在其引擎原生读取 DOM 的 Tern 中，浏览器 observe、选择器、clicks、打字、元素读取和等待不再在页面中运行脚本：引擎查找元素（跨框架和封闭阴影根），并且每个操作都是在其解析时输入的 trusted；然后，type 在插入符处键入 click 位置，并且 text/ 选择器忽略大小写
  • 浏览器屏幕截图的文本是一行（模型看到的大小、保留时的全尺寸文件以及 tab.clickAt 的坐标因子），而不是具有字节大小和格式的四行，browser.open 报告选项卡、它在不是请求的 URL 时登陆的页面（使用导航的规范化 URL 比较）以及一行标题（#18776 @will-bogusz)
  • RPC select 请求携带 initialIndex、selectionMarker、checkedIndices 和 markableCount，因此主机可以显示哪些 ask 复选框选项已被选中，而不是让用户盲目切换它们（#18929 by @andrebrait）
  • 现在每个语言服务器都将文件监视交给omp（只有TypeScript 7）；在服务器上设置 watchFiles: false 以保留自己的观察者
  • 失败的 JavaScript Eval 单元打印错误消息和单元自己的帧，用一行计算来自 omp 运行时、其依赖项和引擎的隐藏帧，而不是完整的主机堆栈；项目本地依赖帧保持可见，标头不再与错误匹配的缓存堆栈保持不变，即使使用缓存堆栈，浮动拒绝也保留其当前消息和丢失等待提示，并且 catch 中的 print(e.stack) 仍然显示每个帧（#18775 by @will-bogusz)
  • Snapcompact 压缩在预检时解析框架形状并将其传递给 compact()，compact() 使用 auto 形状设置重新导出它；预检扫描脚本一次而不是两次，作为 compaction.snapcompact 循环阶段运行，并在渲染之前进入事件循环（#15689、#18867 by @wolfiesch）
  • 完整会话文件重写（修剪、图像丢失、救援标记）作为 session.rewrite 循环阶段运行，因此它们的停顿归因于 ui.loop-blocked 日志（#15027、#18867 by @wolfiesch）

  • 修复了经过身份验证的 openai-codex、google-antigravity 和 google-gemini-cli 提供程序的冷或过时缓存上的错误未知模型回退警告，停止禁用的冷缓存提供程序推迟回退警告，并停止延迟目录加载覆盖已完成或失败的发现状态（#19017 @PGupta-Git)

  • 当服务器还发送 SDK 包装的结构化内容（#18894、#18920 by @yuzu-octopus）时，返回列表或字符串的 MCP 工具不再在模型上下文中重复其有效负载
  • 在 Chromium 浏览器选项卡中，tab.run 内的 page.evaluate、evaluateHandle、$eval、$$eval 和 waitForFunction 现在可以像 tab.evaluate 一样看到页面自己的全局变量和自定义元素，而不是 null 或 undefined；等待支持简洁的方法，在页面端间隔轮询，拒绝无效的轮询选项，保留中止原因并在取消时停止轮询，处理延迟的结果（#18751 by @will-bogusz)

  • omp --help 列出了 --tools 接受的工具名称，分为默认启用和可选；浏览器和计算机使用记录为 eval 功能（@nibblebot 的#19064）
