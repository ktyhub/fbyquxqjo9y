hypit v0.2.2

这个项目是干啥的：一个用 AI 助手批量「克隆」爆款短视频的工具，换脸、换台词、换素材后一条命令产出上百个变体，给做短视频矩阵和批量投放的内容团队用。

变更架构图

亮点

  • Windows 媒体执行终于能用了 — ffmpeg 和 ffprobe 此前用一个为 POSIX 编写的环境白名单启动，导致 Windows 子进程既拿不到 %TEMP% 也拿不到 %TMP%，无法创建临时文件；现在 HyperFrames 渲染路径和共享媒体执行路径都在 POSIX 列表旁带上 Windows 列表，且仍然不向子进程泄露 Host 密钥。这是头条修复：遇到渲染/probe 失败的 Windows 用户应升级（#259、#260）。

  • 破坏性——凭据 Store 路径必须位于 Host 状态根目录内 — file 和 platform 类型 Store 的 config.path 现在相对 Host 状态根目录解析并检查是否包含其中；0.2.1 曾接受的根目录外绝对路径，现在在 Store 打开时会被拒绝。带有位于 Host 状态根目录之外的 file 或 platform Store 路径的既有 Profile 会被 0.2.2 拒绝，因此这些用户必须在升级前把 Store 路径移回根目录内——这明确是相对 0.2.1 的行为变更（#265）。

  • Linux Profile 现在开箱可用 — runtime init 生成的起步 Profile 会选用 @hypit/credential-store-platform，因此在 Linux 上也能像 macOS 和 Windows 一样打开和写入；macOS 和 Windows 仍在相同的服务和键下使用平台锁，所以既有凭据依然能找到，os、file 和 env 仍可按名称选择。此前拿到无法打开的 Profile 的 Linux 用户应升级（#247）。

  • 凭据争用只是部分修复——别指望完整的跨进程安全 — 单个凭据文档的读取和替换现在在进程内有序进行（resolve 在读取期间保持文档打开，put 通过 rename 替换），减少了进程内的重叠；但它不协调独立的 CLI 与 Worker 进程，因此跨进程的替换失败（Node 在 Windows 上的 MoveFileExW 在目标文件被打开时拒绝替换）在 0.2.2 中依然存在，且各键彼此独立。另外，Windows Credential Manager 辅助程序现在被限制到与 macOS security(1) 相同的 10 秒超时，卡住的锁会失败而非挂死 CLI（#276、#261）。

  • 其余都是低风险的 CLI/文档卫生改进——若上述都不涉及你可跳过 — programs down 现在对仅 probe 的 Program 报告 No external programs to stop，而非退出码 1（就绪的 probe 表示已安装而非正在运行；可启动但未就绪且没有 Hypit PID 的 Program 仍报告 not-ours）（#272）；总览帮助列出了 programs prepare|up|status|down，缺失 Profile 的恢复文案也更一致（#266）；三个包声明了源码导入的 workspace 依赖（#253）；英文快速上手的 Build 一节补上了中文版早已有的内容（#275），auth status 示例也包含必需的 endpoint 参数（#254）。没有格式或脚本语法变化——内部格式和逻辑模块标识符仍是 @1，脚本语法与 0.2.0 一致——因此不受 Windows 媒体、Linux 凭据或根目录外 Store 路径影响的用户可安全跳过。

Windows 媒体环境和凭证存储的正确性

此版本包括 Windows 执行修复和凭证目录选择的更改。具有主机状态根之外的文件或平台存储路径的现有配置文件将被 0.2.2 拒绝；这是 0.2.1 的行为更改。新的起始商店选择仅适用于新初始化的配置文件。

Windows 媒体执行

ffmpeg 和 ffprobe 以环境变量白名单启动，因此主机环境不会出现在媒体子项中。该白名单是为 POSIX 编写的，因此 Windows 子级既没有收到 %TEMP% 也没有收到 %TMP%，并且无法创建临时文件。 HyperFrames 渲染路径和共享媒体执行路径现在都带有 Windows 列表以及 POSIX 列表。主机秘密仍然保密。 （＃259，＃260）

凭证存储

  • runtime init 编写一个选择 @hypit/credential-store-platform 的入门配置文件，因此它生成的配置文件可以在 Linux 以及 macOS 和 Windows 上打开和写入。 macOS 和 Windows 将平台锁保留在相同的服务和密钥下，因此仍然可以找到现有的凭据。 os、file 和 env 仍然可以通过名称进行选择。 (#247)
  • 文件和平台存储的配置文件的 config.path 根据主机状态根解析并检查包含情况。当 Store 打开时，转义该根的路径将被拒绝。根之外的绝对路径以前被接受，但现在不被接受。 （＃265）
  • 一个凭证文件的读取和替换在一个过程中轮流进行。 resolve 使文档在整个读取过程中保持打开状态，而 put 将其替换为重命名，并且 Node 的 Windows 重命名实现使用 MoveFileExW，它可以在目标打开时拒绝替换。进程本地排序减少了一个进程内的这种重叠；它不协调单独的 CLI 和 Worker 进程。 0.2.2 中仍然存在跨进程替换故障。按键保持独立。 （＃276）
  • Windows 凭据管理器帮助程序与 macOS security(1) 调用一样具有 10 秒超时限制，因此卡住的储物柜会失败，而不是挂起 CLI。 （＃261）

运行时和 CLI

  • programs down 将没有有效 Hypit PID 且没有 start 命令的程序视为无需停止，并报告 No external programs to stop 而不是退出 1。启动器配置文件的 media.local 和 hyperframes.local 仅声明 probe()，因此就绪探针意味着该工具已安装，而不是进程正在运行。无需 Hypit PID 即可启动的程序仍会报告 not-ours。 （＃272）
  • 概述帮助列出了没有选定配置文件的 programs prepare|up|status|down、programs 和 runtime 报告 build、pricing、auth 和执行命令已使用的相同恢复语句。 （＃266）
  • 三个包声明其源导入的工作区包。 （＃253）

文档

  • 英文版快速入门的构建工作流程部分包含中文版本已有的依赖项准备、.gitignore、共享资源库和存档命令材料。 （＃275）
  • auth status 示例携带所需的端点参数。 (#254)
