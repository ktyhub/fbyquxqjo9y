hypit v0.2.3

修订 发布时间2026年9月17日 来源hypit-ai/hypit 英文原文

hypit v0.2.3

变更流程图

亮点

  • Windows 上的凭据可靠性 — 文件型凭据现在使用 Result store 原生的 Windows 替换路径，消除了进程内的队列，同时在失败时保留原值。OS 凭据替换不再在写入前删除旧值，卡住的子进程辅助程序也会被终止。如果你依赖 Windows 上的凭据替换，就升级。

  • 恢复自定义凭据目录 — 位于 Host 状态根目录之外的显式 file/platform 凭据位置再次被接受，而 Profile 仍掌控存储选择。这修复了自定义部署的回归；没有描述配置迁移。

  • 更早校验无效的媒体映射 — 生成映射现在会在上传或提交请求之前，拒绝无法传输的所提供媒体字段，且可选布尔值同时保留 true 和 false。这避免了无谓的上传和错误的请求载荷。

  • 更准确的媒体与字体处理 — FFmpeg/FFprobe 探针现在在可执行文件的实际运行环境中运行，仅用于 probe 的 Program 不再被报告为正在运行的服务，解析物理 Distribution 目录修复了 Windows 短路径别名把已安装字体误分类的问题。扩展的 Windows/Linux CI 现在覆盖准备、渲染、导出和完整媒体解码。

  • 低风险升级，无文档记录的破坏性变更 — 逻辑模块和格式标识符仍是 @1，脚本语法未变，保存的视频项目不迁移也不重写。受 Windows 凭据、自定义存储、媒体准备或字体解析影响的用户应升级；其他人可跳过。已安装的 Hypit Skill 会单独更新以反映修订后的 Runtime profile 指导，而可选的 AI 分析工作流仅在仓库内，不影响 npm CLI。

本地执行和请求正确性

  • 文件支持的凭据现在共享结果存储的本机 Windows 替换实现。 CLI 和工作进程可以读取和替换完整的凭据值，而无需进程本地队列。替换失败保留之前的值；不受支持的文件系统操作会报告错误。
  • Windows 操作系统凭据替换不再删除写入前的先前值。子进程超时和输出失败会终止帮助程序。
  • 再次接受主机状态根之外的显式文件/平台凭证目录。配置文件保留对其所选存储位置的控制。
  • 在上传或提交请求之前，生成映射拒绝明确提供的无法传输的媒体字段。可选布尔值保留 true 和 false。
  • 媒体准备探测执行环境中选定的 FFmpeg/FFprobe 可执行文件。仅探测程序准确地报告安装/准备情况，而不声称是正在运行的服务。
  • 启动器在加载包之前解析其物理分发目录。这修复了 Windows 短路径别名错误地导致安装的字体出现在其自己的发行版之外的问题。
  • 安装包 CI 现在可以验证 Windows 和 Linux，包括组件构建、字体、显式浏览器准备、渲染、导出和完整媒体解码。
  • 项目视频提供商示例通过其说明性上传传输携带第一/最后一帧人物参考分类。

这些更改不会添加静默下载、重试、回退浏览器、锁定文件协议、中央队列或持久协调元数据。逻辑模块和格式标识符仍然是@1；脚本语法未更改。

更新中

对于全局 CLI 安装：

npm install -g @hypit/hypit@0.2.3
hypit --version

对于项目本地安装：

npm install --save-exact @hypit/hypit@0.2.3
npm exec --no -- hypit --version

已安装的 Hypit Skill 通过用于安装它的工具单独更新。从此存储库更新该安装以接收修订后的运行时配置文件指南，它将准备、进程启动和凭据连接分开。更新安装不会迁移或重写已保存的视频项目。

仅存储库更改：手动触发可选的 AI 分析工作流程，读取一个问题或 PR 并在操作摘要中返回建议。它没有问题/PR 写入权限，并且独立于 npm CLI。
