hypit v0.2.5

这个项目是干啥的：一个用 AI 助手批量「克隆」爆款短视频的工具，换脸、换台词、换素材后一条命令产出上百个变体，给做短视频矩阵和批量投放的内容团队用。

变更架构图

亮点

  • MiniMax H3 登陆 Monid — #286 通过 Monid 的 minimax /v1/video/minimax-h3 端点，把 @hypit/minimax-h3@1#minimax-h3 加入 @hypit/provider-monid，使 H3 成为继 HypiHub、HiAPI、Pollo 和 TokenDance 之外的第三个内置网关 Provider。如果你用 Monid 且想要 H3，这就是升级的全部理由；如果你用别的网关或不需要 H3，这里没有任何东西会改变你的工作流。

  • 必须留意的三个路由级 H3 特性 — H3 使用与 Seedance 相同、带角色标签的 ModelArk content 数组，但在影响请求/响应处理的方式上有差异：resolution 是端点必填项，因此省略的值会按 2K 发送（与 HypiHub 一致）；无 aspect-ratio 的文生视频会在解析任何参考之前被报告为不支持，而帧模式和图生视频按 adaptive 发送；返回的视频从 content.url 读取，不是 Seedance 用户可能在解析的 ModelArk video_url。任何消费 H3 输出或移植 Seedance 脚本的人都需要更新响应处理。

  • Provider 感知的端点映射（内部但值得注意） — Monid 按 provider 和路径定位端点，因此每条映射现在携带转发的 provider，而非每次运行都假定为 bytedance。这正是让 minimax 这类非 ByteDance 端点正确工作的原因；这是内部结构性变更，无需面向用户的迁移。

  • 目录范围刻意收窄 — 没有新增描述其他模型。Monid 的 ElevenLabs 端点基于 voice-id，无法服务 @hypit/elevenlabs-speech@1#eleven_ttv_v3（语音设计需要它们没有的语音描述字段），而 H3 Fast / Max / Max Turbo 声明的是各自值域的不同模型，因此不在该映射覆盖范围内。不要指望这个版本解锁它们。

  • 升级安全性与谁该费心 — 脚本语法与 0.2.0 一致，内部格式和逻辑模块标识符仍是 @1，更新不会迁移或重写保存的视频项目；已安装的 Hypit Skill 通过其自身的安装器单独更新。这是真正的特性版本，不是重新打标签或仅元数据空转——Monid + H3 用户值得升级，其他人可安全跳过。

Monid 上的 MiniMax H3

@hypit/provider-monid 现在通过 Monid 的 minimax /v1/video/minimax-h3 以及它已经映射的四个 ByteDance Seedance 端点为 @hypit/minimax-h3@1#minimax-h3 提供服务。该模型除了 HypiHub、HiAPI、Pollo 和 TokenDance 之外还有第三个捆绑网关提供商。 （＃286）

H3 采用与 Seedance 端点相同的角色标记 ModelArk content 数组，在正文中命名其模型，并且既不携带它们所采用的 generate_audio 也不携带 web_search 字段。该路线处理了三个差异：

  • resolution 是端点所必需的，而模型的端口是可选的，因此在 2K（HypiHub 提供商也选择的分辨率）上发送声明没有的请求。
  • 端点不采用文本到视频的 adaptive 比率，而帧模式解析上传图像的框架，视频参考默认为自适应。在解析任何引用之前，不携带 aspect-ratio 的文本转视频请求将报告不受支持；其他两种模式以 adaptive 形式发送。
  • H3 在 content.url 而不是 ModelArk video_url 返回其视频。

Monid 通过提供程序和路径对端点进行寻址，因此每个映射现在都带有中继它的提供程序，而不是每次运行都假设 bytedance。

Monid 目录的其余部分不包含此发行版描述的其他模型。它的 ElevenLabs 端点是基于语音 ID 的，而 @hypit/elevenlabs-speech@1#eleven_ttv_v3 是语音设计的，需要一个没有字段的语音描述，而 H3 Fast、Max 和 Max Turbo 变体则声明了具有自己的值域的不同模型。

更新

对于全局 CLI 安装：

npm install -g @hypit/hypit@0.2.5
hypit --version

对于项目本地安装：

npm install --save-exact @hypit/hypit@0.2.5
npm exec --no -- hypit --version

已安装的 Hypit Skill 通过用于安装它的工具单独更新。内部格式和逻辑模块标识符仍为 @1。 0.2.0 中的脚本语法没有变化。更新不会迁移或重写已保存的视频项目。
