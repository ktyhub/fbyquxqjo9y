显着变化

性能分数变化

在 8.0 版本中，我们描述了 TTI 逐渐减弱的角色，今天我们有后续内容。交互时间 (TTI) 不再影响性能分数，并且不会显示在报告中。然而，在灯塔结果 JSON 中仍然可以访问它。 如果没有 TTI，累积布局偏移 (CLS) 的权重将从 15% 增加到 25%。请参阅文档，了解 如何在 10.0 中计算性能分数 或 使用评分计算器 的完整详细信息。

Node 包的类型

Lighthouse 现在包含类型声明！我们的示例 TypeScript 配方 演示了如何使用 Lighthouse 实现适当的类型安全。

第三方实体分类

自 Lighthouse 5.3 以来，社区驱动的 third-party-web 数据集已用于通过 third-party-summary 审核来总结页面上找到的每个第三方对总 JavaScript 阻塞时间的贡献。通过 Lighthouse 10.0，我们向 JSON 结果 (entities) 添加一个新属性，以进一步利用该数据集。页面上遇到的每个来源现在都在 entities 中分类为第一方或第三方。在 10.0 中，此分类用于为现有的第三方过滤器复选框提供支持。 在 Lighthouse 的未来版本中，这将用于根据每个审计源自的实体对表项目进行分组，并聚合来自该特定实体的项目的影响。

🆕 新审核

后退/前进缓存

后退/前进缓存（简称 bfcache）是一种浏览器优化，当在会话历史记录中后退或前进时，它会从完全序列化的快照中提供页面。页面可能不符合此优化条件的原因有 100 多种，因此为了帮助开发人员，Lighthouse 现在尝试触发 bfcache 响应，并将列出阻止浏览器使用 bfcache 的所有内容。 #14465 有关 bfcache 的更多信息，请参阅 web.dev 文章。 注意：此审核最初不适用于 PageSpeed Insights。

防止粘贴到输入

审核 password-inputs-can-be-pasted-into 现在为 paste-preventing-inputs。此审核的逻辑与以前一样工作，但不只是考虑 [type=password] 输入，如果 any 非只读输入元素阻止用户粘贴，它现在会失败。 #14313

Lighthouse 文档现已位于developer.chrome.com

我们的文档不再托管在 web.dev 上。如需最新的审核文档，请访问 developer.chrome.com/docs/lighthouse/

💥 重大变更

在幕后，Lighthouse 现在默认使用新的用户流支持基础设施，甚至对于传统的导航运行也是如此。您可以通过以下方式选择退出：在 CLI 中，使用 --legacy-navigation；在 DevTools 中：检查设置菜单中的“旧版导航”。如果您有需要此逃生舱口的用例，请提出问题。我们计划删除 11.0 中的此旧路径。

对于 Lighthouse 结果 JSON (LHR) 用户

Lighthouse 结果上的页面 URL

到目前为止，有两个 URL 字段来描述 Lighthouse 运行：

  • requestedUrl：用户给出的 URL，Lighthouse 指示 Chrome 导航到该 URL
  • finalUrl：任何服务器发起的 HTTP 和 JS 发起的重定向后的 url 此分类法无法解释更复杂的场景，例如 JS 发起的重定向、历史记录 API 的使用或软导航。它们对于时间跨度和快照模式也没有明确的定义。为了解决这个问题，Lighthouse 10.0 现在具有以下 URL 字段： -（已更改）requestedUrl：Lighthouse 在重定向之前最初导航到的 URL。这与之前的导航模式相同，但现在时间跨度/快照中将是 undefined。 -（新）mainDocumentUrl：导航期间请求的最后一个文档的 URL。它不考虑页面加载后进行的软导航或历史 API 事件。仅在导航模式下可用，在时间跨度和快照模式下未定义。 -（新）finalDisplayedUrl：Lighthouse 运行结束时在浏览器组合框中显示的 URL。它负责软导航和历史 API 事件。提供导航、时间跨度和快照模式。 -（已弃用）finalUrl：与 mainDocumentUrl 相同的值。

审计变更

  • password-inputs-can-be-pasted-into -> paste-preventing-inputs
  • preload-lcp-image -> prioritize-lcp-image
  • third-party-summary 不再对 item.entity 使用 link 值，而是使用原始 text 值
  • full-page-screenshot 不再是审计，而是存储在 lhr.fullPageScreenshot 中。要禁止在 CLI 中收集全页屏幕截图，您必须从 --skip-audits full-page-screenshot 迁移到 --disable-full-page-screenshot。

对于节点用户

  • 不再支持节点 14，现在最低为节点 16
  • 如果您导入灯塔节点包中的路径：lighthouse-core/ 和 lighthouse-cli/ 文件夹现在只是 core/ 和 cli/
  • 从 CommonJS 转换为 ES 模块。您仍然可以通过动态导入在 CommonJS 中使用 lighthouse：await import('lighthouse')。要仅访问 CommonJS 中的 lighthouse 函数，您还可以使用 require('lighthouse/core/index.cjs')
  • Lighthouse 的 CSV 输出现在更加有用。请参阅 PR 以获取新格式的示例
  • LHError 现在为 LighthouseError。如果您尝试捕获 Lighthouse 引发的错误，请务必考虑到这一点！

节点 API 变化

lighthouse 功能现在与 Puppeteer 更好地集成。使用 lighthouse(url, flags, config, page) 运行 Lighthouse，将现有的 Puppeteer.Page 句柄作为 page 传递。 用户流 api 已移至顶级节点入口点，可以使用 import {startFlow} from 'lighthouse' 导入。 新的 flow.startNavigation() 和 flow.endNavigation() 函数允许您定义用户触发的导航，而无需任何回调函数。请参阅用户流程文档以获取示例。 要更改单个用户流程步骤的设置，请在顶级标志选项 flow.snapshot({skipAduits: ['uses-http2']}) 而不是 settingsOverride 属性上定义设置覆盖。 要为流程步骤指定自定义名称，请使用 flow.snapshot({name: 'Custom name'})。以前这是通过 stepName 完成的。

用于 Lighthouse 自定义（自定义配置、收集器、审核）

  • 要在 Lighthouse 10.0 中工作，自定义收集器将需要实现新的 Gatherer 接口（示例）。否则，它们只能在旧版导航模式 和旧版本的 Lighthouse 中工作
  • Lighthouse 无法再使用 passes 在导航模式下多次加载页面。如果您需要多次加载页面，我们建议使用用户流。请参阅我们的配置文档，了解有关如何转换为新配置格式 的说明
  • ScriptElements神器现在是Scripts，形状略有不同
  • Audit.makeOpportunityDetails 和 Audit.makeTableDetails 现在接受选项对象作为第三个参数。对于 Audit.makeOpportunityDetails 来说，这最终是一个重大改变。 #详细changelog
