lighthouse v6.0.0

大版本 发布时间2020年5月19日 来源GoogleChrome/lighthouse 英文原文

原始提交 changelog 我们预计此版本将在 Chrome 84 的 DevTools 中发布。

显着变化

这么多！请参阅Lighthouse 6.0：新增功能博客文章 进行深入了解。

🆕 新审核

  • 最大内容绘制 (LCP) 是一个新指标，用于测量从导航到渲染视口中最大内容元素的时间（#9905、#10213、#10452、 [#10529]（https://github.com/GoogleChrome/lighthouse/pull/10529））。
    • largest-contentful-paint-element 是一项配套审核，提供有关哪个元素触发了 LCP 的信息（#10517、#10713）。
  • 累积布局偏移 (CLS) 是一个新指标，用于测量页面加载时内容意外移动的量（#9037、#10427、#10495、 #10570、#10728)。
    • layout-shift-elements 是另一个伴随诊断，它提供有关页面加载时移动的元素的信息 (#10702)。
  • unused-javascript 是一项审核，已经存在了一段时间，但现在才默认启用。它解释了 JavaScript 已加载但在页面加载期间从未执行的内容，并估计可以通过代码分割、死代码消除或明智地使用删除键来节省的加载时间（#9854）。
  • PWA maskable-icon 在主屏幕上看起来更好，因此这项新审核鼓励您在清单中至少有一个可用 (#10370)。
  • timing-budget 扩展了预算断言，现在可以在所有性能指标上进行设置（#9901、#9925）。
  • 新的 charset 审核可确保页面内容的字符编码正确（#10284、#10389、#10689）。
  • image-size-responsive 检查图像的长宽比和分辨率是否与其在页面上的显示方式相匹配 (#10460)。
  • 更新到最新版本的axe-core已解锁许多新的可访问性审核：aria-hidden-body、aria-hidden-focus、aria-input-field-name、aria-toggle-field-name、 duplicate-id-active、duplicate-id-aria、form-field-multiple-labels、heading-order (#9798)。

⚗️ 实验审核

这些审核尚未成为默认 Lighthouse 体验的一部分，但它们将根据页面 JavaScript 捆绑包的分析提供性能建议。今天可以使用 --preset=experimental 标志在命令行上测试它们。

  • legacy-javascript 翻遍你的包，寻找不必要或过时的 polyfill 和打包器转换（#10303、#10568、#10564）。
  • duplicated-javascript 还会深入浏览页面的 JavaScript，查找最终在捆绑包内或跨多个捆绑包重复的代码 (#10314)。
  • unused-javascript 现在默认运行（如上所述），但是当在 experimental 下运行时，审核可以使用源映射来显示哪些_原始_源代码从未运行并且可以推迟或消除（[#10090]（https://github.com/GoogleChrome/lighthouse/pull/10090））。

💥 重大变更

  • 性能指标分数已重新加权，以更好地反映用户的加载体验(#9949)。
  • 运行桌面 Lighthouse 测试时，指标分数曲线已更新，以考虑更快的连接和 CPU（#9911、#10756）。
  • frameNavigated 事件现在用于跟踪重定向，这意味着现在在确定运行的 finalUrl 时会考虑 JS 重定向（#10339）。
  • 模拟移动设备已从 Nexus 5x 移至 Moto G4（但现有 DPR 保持不变）（#10191、#10749）。
  • mixed-content 预设已被删除，因为它没有被广泛使用，并且需要很长时间才能添加到默认的 Lighthouse 体验中（#10159、#10750）。
  • full 预设已重命名为 experimental，表示默认情况下该代码可能尚未准备好运行（#9930、#10311、#10333、#10585）。
  • 模拟的 Chrome UA 字符串已更新为 Chrome 80 (#9967)。
  • installable-manifest：Web 应用清单中的图标必须可获取才能被视为可安装（#10168、#10320）

🤖💥 针对程序化用户的重大变化

这些更改不太可能影响最终用户，但如果您正在编写自定义配置、插件或处理 Lighthouse JSON 输出，这些更改可能很重要。

  • 通过审核的 LH.Audit.Context 现在被视为不可变。如果代码之前推送到 context.LighthouseRunWarnings 以获得顶级警告，那么它现在应该将其传递回审计产品的 runWarnings (#10555)。
  • Audit.computeLogNormalScore 已被重新定义，以指定具有中位数和 p10 点的对数正态曲线（删除“收益递减点”）。现有审核已移至此新定义，因此不应发生分数更改 (#10715)。
  • loadFailureMode 设置已添加到 Config 传递中，以控制页面加载失败时的行为。以前这是隐式控制的（例如，没有可用的脱机页面不会导致错误）（#9987）
  • time-to-first-byte 已更名为 server-response-time，以更好地反映审核所测量的内容 (#10735)。
  • resource-summary：为了清晰起见，details.items.size 已重命名为 transferSize（#10700、#10743）。

🧱 核心

改进、错误修复、澄清
