minio RELEASE.2025-10-15T17-29-55Z

这个项目是干啥的：一个开源对象存储服务，兼容S3协议能存海量文件还支持后量子加密，给需要自建文件存储的团队用。

变更架构图

亮点

  • 关键安全修复（立即升级） — 本版本修复 CVE GHSA-jjjj-jwhf-8rgr，即“通过服务账号和 STS 中的会话策略绕过实现权限提升”。服务账号和 STS 凭据的会话策略强制执行存在绕过，可能让调用方将权限提升到预期范围之外。任何使用该版本并启用服务账号或 STS 的用户都应视为强制升级；上游公告明确建议立即升级。这是升级的首要理由。
  • 会话/子策略强制更严格 — PR #21642（“存在子策略时正确检查”）强化了子策略检查，很可能属于上述权限提升修复的一部分。若你签发限定范围的会话策略，升级后此前被接受但过于宽泛的请求会被正确拒绝——建议对服务账号/STS 策略边界做一次快速回归测试。
  • 认证与 S3 兼容性修复 — PR #21582 修复 StartTLS 配合 tls_skip_verify=off 时 LDAP TLS 握手失败的问题（若你依赖严格证书校验的 LDAP，此修复相关），PR #21612 允许 AWS S3 POST 策略末尾带斜杠（修复与生成此类形式客户端的兼容性）。若这两点影响到你，值得升级；否则影响很小。
  • 多池/rebalance/复制正确性 — PR #21590 修复下线后添加池时 poolID 错误，PR #21597 修复 saveRebalanceStats 留下 cancel 为空的问题，PR #21615 修复 timeN 闭包从未被调用，PR #21569 移除不必要的复制检查。运行下线/rebalance 或多池复制的运维人员应升级以求稳定；单节点用户收益很小。
  • 构建/工具链与升级说明 — Go 工具链指令提升到 1.24.8（PR #21629，另见 PR #21613 新增 gofumpt）；未记录显式破坏性变更或迁移步骤。注意发布说明中未发布预构建容器镜像——容器用户必须克隆仓库，checkout RELEASE.2025-10-15T17-29-55Z，并通过 TAG=... make docker 构建。所有人都应为安全修复而升级；除非实例完全隔离且不用于服务账号/STS（这仍有风险），否则没有可安全跳过的群体。

安全

报告了一个 CVE 通过服务帐户和 STS 中的会话策略绕过进行权限升级，并在此版本中修复，

建议所有用户立即下载并升级其 MinIO 设置。

安装最新版本

go install -v github.com/minio/minio@latest

或

go install -v github.com/minio/minio@RELEASE.2025-10-15T17-29-55Z

对于容器环境，请克隆源并构建最新的容器。

git clone https://github.com/minio/minio
git checkout RELEASE.2025-10-15T17-29-55Z
TAG=myregistry.com/minio/minio:RELEASE.2025-10-15T17-29-55Z make docker
