hyperframes v0.9.82

这个项目是干啥的：HeyGen 开源的 AI 视频剪辑框架，把 HTML 当视频来写并渲染成 MP4，还能让 Claude Code 等助手直接改片，给会写网页的开发者和做批量视频的人用。

变更架构图

亮点

  • 离线 GSAP / 运动路径渲染 — 本次头号改动：渲染现在会提供 CLI 自带的每一个 GSAP 版本，CDN 被阻断时回退到自带副本（#8349）；运动路径插件也从页面自己的 GSAP 旁边加载，不再从一个页面从未指定的 CDN 拉取（#8523）。预览和渲染现在完全断网可用，也不再静默地从未经许可的 CDN 拉插件——这是受限网络或离线环境用户升级的首要理由。
  • 密封预览的正确性 — 一组修复让密封（锁定）预览真正可用：不再捕获或响应键盘输入（#8521），即使某一帧自身无法发声也会播放音频（#8495），能提示嵌套合成中被丢弃的移动操作（#8517），裁切/旋转图层的边界与轮廓计算也修正了（#8502、#8496）。如果你交付的密封预览用到音频、变换或嵌套合成，建议升级。
  • 大项目性能 — 多项卡顿/冻结修复针对大规模场景：同一段 4K 视频被剪成很多片段时不再冻结渲染探测（#8284），含数千个 script 标签（#8518）或数千个媒体文件（#8505）的页面不再卡住预览，视口判断改为基于已挂载的时间线行而非原始片段数（#8511）。大项目值得升级，合成较小的用户可以跳过。
  • CLI 安全与数据完整性 — 固定文件下载器现在会在读写前校验缓存目录是否为私有（#8486），publish 只有在本机曾关联该项目时才会更新已提交的项目（#8487），cloudrun/lambda 在加载云 SDK 之前先报告用法错误（#8510）。粘贴或写入的标记不能再携带别处的合成来源，粘贴/复制在每次编辑后都会重新校验文件（#8520、#8519）。基本属于加固，风险低；但依赖跨机器 publish 的用户升级前请先验证。
  • 升级建议 / 破坏性变更 — 这是一个补丁版本（v0.9.81 → v0.9.82），几乎全是修复加内部测试改动；没有列出破坏性变更或迁移步骤，也不是仅改元数据的重新打标。遇到上面离线 GSAP、密封预览或大项目问题的用户应升级；未受影响的用户可以跳过，不会有损失。

超帧 v0.9.82

发布于 2026 年 11 月 22 日。 预览会从页面自己的 GSAP 文件夹或主机的副本加载 GSAP 的运动路径插件，因此它无需网络即可工作。密封预览得到了更多修复，从声音和键盘到嵌套组合内的移动。

修复

  • 生产者： 渲染服务于 CLI 附带的每个 GSAP，以及当 CDN 被阻止时它自己的服务（8c9c94572、#8349）。
  • 核心： 运动路径插件从页面自己的 GSAP 旁边加载，绝不会加载未命名的 CDN（80f45de33、#8523）。
  • 制作人： 一部 4K 视频包含许多 clips 的影片不再冻结渲染探针（4daeb78c3、#8284）。
  • Studio: A sealed preview never keeps the keyboard, so no key it reports is acted on (196eff39e, #8521).
  • Studio: A turned layer’s cropped box is the bounds of its cut corners (e5e360154, #8502).
  • Player: A sealed film is heard when its frame may not start sound (87fddbc1a, #8495).
  • 核心： 粘贴或书写的标记永远不会携带来自其他地方的组合源（2425df5f4、#8520）。
  • CLI： 固定文件下载程序在读取或写入缓存文件夹之前检查其是否为私有（[675e3a876]（https://github.com/heygen-com/hyperframes/commit/675e3a876e550a5e5850b0b0123ffffec8be7cce），[#8486]（https://github.com/heygen-com/hyperframes/pull/8486））。
  • Studio： 每次编辑后粘贴并复制检查他们写入的文件（[bd7a8402d]（https://github.com/heygen-com/hyperframes/commit/bd7a8402db87662cf256c4e2e29212c03b48b7de），[#8519]（https://github.com/heygen-com/hyperframes/pull/8519））。
  • CLI： 仅当本机链接文件夹（886f609c4、#8487）时，发布更新已提交的项目。
  • CLI: Print project file names in check’s stderr notes as visible escapes (4202462ca, #8485).
  • Player: A late timeline from the old film no longer keeps a switched player ready (c19d98d9a, #8500).
  • 核心： 嵌套组合内的密封移动显示其掉落位置（ec9a3a8ef、#8517）。
  • Studio Server： 包含数千个脚本标签的页面不再停止预览（0bc7963ff、#8518）。
  • 生产者： 探测步骤的内存不足错误保留其字样，因此它仍然读取为内存（[258a3cf4e]（https://github.com/heygen-com/hyperframes/commit/258a3cf4ea1a2b9c9d9305809be52a960b7e880e），[#8513]（https://github.com/heygen-com/hyperframes/pull/8513））。
  • CLI: Cloudrun 和 lambda 在加载其云 SDK 之前显示使用错误（fbd1cd4bc、#8510）。
  • 核心： 标签抛出的时间线不再清空 clip 列表（5d4420fee、#8512）。
  • Studio： 当在开发数据文件夹（b3d37f948、#8514）中打开项目时，Vitest 退出。
  • Studio： 视口门通过其安装的行而不是 clips（dd7799037、#8511）来告诉虚拟时间线。
  • Studio: A cropped layer’s outline is cut at the layer’s own scale, sealed or not (2b1495f7a, #8496).
  • 核心： 源被交换的远 clip 学习其新长度（4a47c33ea，#8509）。
  • Studio Server： 预览包含数千个媒体文件的页面不再使应用程序停止运行（f03233ab4、#8505）。
  • Producer: A render that stops while preparing names the step it stopped in (852611378, #8506). ＃＃ 内部的
  • CLI： 诊断测试的 ffmpeg 替代回答解复用器列表，不写入文件（[f38a4e367]（https://github.com/heygen-com/hyperframes/commit/f38a4e3675a76d8742acf8843fd6f909e2a0e96b），[#8515]（https://github.com/heygen-com/hyperframes/pull/8515））。
  • Studio： 视口门作业失败的行走在支票上自行命名（086948766、#8516）。
  • CLI： 登录返回测试等待每个窗口的导航而不是一秒（[20a91dd5f]（https://github.com/heygen-com/hyperframes/commit/20a91dd5f1092e3b1709f20886cc16bcf2c53c39），[#8507]（https://github.com/heygen-com/hyperframes/pull/8507））。
