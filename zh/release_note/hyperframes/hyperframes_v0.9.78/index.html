hyperframes v0.9.78

超帧 v0.9.78

发布于 2026 年 11 月 21 日。 现在，在代理步骤后撤消会恢复其更改的文件。 Windows 上的目录间隙报告永远不会将您的 shell 将运行的查询放入命令中，并呈现共享一个捕获代理以保持其连接。

特点

  • 引擎： 延迟图像的加载时间在到达时被记录（e65b11e5c、#8372）。

修复

  • CLI： 在重复失败原因的通知中将控制字符显示为文本（c75860ddf、#8387）。
  • 核心： Windows 重命名到存在的文件夹会立即失败，而不是等待 1.3 （[7cb548e45]（https://github.com/heygen-com/hyperframes/commit/7cb548e45b846683d74dac3c2108fedceb5d146a），[#8389]（https://github.com/heygen-com/hyperframes/pull/8389））。
  • 核心： 将文本方向标记和键入的文本显示为打印行中的可见文本（f01d1f32b、#8384）。
  • Studio Server： 当文件时间与其时钟不一致时，历史记录会按顺序保留撤消步骤（63e700de1、#8383）。
  • 核心： 长文本的名称被切入一个单词，而不是一个单词内部（19587337f、#8388）。
  • CLI： Check 将其自己的截止日期报告为 check_deadline (d78e9a5f3，#8378)。
  • CLI： Windows 仅终止 CLI 启动的进程，而不会终止重用的 pid（[93f2fcca4]（https://github.com/heygen-com/hyperframes/commit/93f2fcca49071184da4d0cc3c8fa095b7d817644），[#8382]（https://github.com/heygen-com/hyperframes/pull/8382））。
  • 播放器： 在快速搜索后停止预览重新加载，并在较慢的连接上停止（[120689e3c]（https://github.com/heygen-com/hyperframes/commit/120689e3c7d13ab8efa9cad5416d162b4723d931），[#8339]（https://github.com/heygen-com/hyperframes/pull/8339））。
  • CLI： 在自己的行上打印检查和验证设置命令（[88f7d4052]（https://github.com/heygen-com/hyperframes/commit/88f7d4052dd30ae3e29e1889d68f2231da3d4983），[#8381]（https://github.com/heygen-com/hyperframes/pull/8381））。
  • Studio Server： 预览文件检查可解析拒绝本机真实路径的卷上的链接（40cc86252、#8377）。
  • CLI: 在自己的行上打印捕获设置命令（281f1a2a4、#8374）。
  • Studio Server： 代理步骤等待历史记录的第一个副本，因此撤消会恢复旧文件（fbbf5ee67、#8375）。
  • **Studio Server：**历史拒绝带有封闭的原因，因此调用者会告诉他们失败（[d5881e8aa]（https://github.com/heygen-com/hyperframes/commit/d5881e8aa67f796f851ae15a75702294ef53cc9f），[#8376]（https://github.com/heygen-com/hyperframes/pull/8376））。
  • Studio Server： 超时的历史记录表明它仍然可能落地，因此调用者不要盲目重试（[6b74cfa9f]（https://github.com/heygen-com/hyperframes/commit/6b74cfa9f5bbf01ebb0fe30420c0dab6c71f4f84），[#8300]（https://github.com/heygen-com/hyperframes/pull/8300））。
  • CLI: 在命令名称之前读取 —json 与其之后相同（9a618b798、#8365）。
  • CLI： 在捕获、figma、用法和通知行中将控制字符显示为文本（7fcc4909b、#8366）。
  • Studio： 添加或删除文本字段会保留单词之间的空格（e8f52dc86、#8369）。
  • CLI： 接收到的文件写入会等待锁定，而不是在 Windows 上失败（f74e1545c、#8367）。
  • CLI： stop 从 Linux 上的 /proc 读取进程树，因此 load 无法隐藏子进程（a2df08e49、#8363）。
  • 引擎： 许多浏览器共享的捕获代理不再在 128 处丢弃隧道（5e16c18b1、#8362）。
  • CLI: 在 init、技能和渲染打印行中将控制字符显示为文本（8bc73a0bd、#8352）。
  • CLI: 在更多命令的打印行中将控制字符显示为文本（7a1163fc9、#8353）。
  • Studio Server： 预览文件请求不再在事件循环的静默驱动器上等待（7cb605c78、#8254）。

目录

  • CLI： 仅当每个 shell 将查询作为文本读取时（414557262、#8373），目录差距报告才会交回一行。

内部

  • CLI： 探针缓存快照测试要求 8 秒 clip 的 16 次，而不是 20 秒中的 40 次（c7a6c9315、#8390）。
  • Lint： 线性扫描保留到读取的字符和一个粗略的时间限制（[e0d844030]（https://github.com/heygen-com/hyperframes/commit/e0d84403096c7b4d77c55448087251e9ffd3f44a），[#8386]（https://github.com/heygen-com/hyperframes/pull/8386））。
  • Studio： 只要框架需要应答，字幕越过上限检查就会等待（[b0d9f3615]（https://github.com/heygen-com/hyperframes/commit/b0d9f3615984e6e88c2d6b4dae862fbde2004da1），[#7757]（https://github.com/heygen-com/hyperframes/pull/7757））。
  • Studio Server： 检查保留文件编辑是否存在阻塞等待，而不是挂钟间隙（29a5003ee、#8236）。
  • Studio Server： 保留的保存证明它永远不会使线程休眠，而不是 100 毫秒的停顿限制（[ba81f6793]（https://github.com/heygen-com/hyperframes/commit/ba81f67930cce689b1444c03dc3a4c0dbf13e97b），[#8359]（https://github.com/heygen-com/hyperframes/pull/8359））。

其他变化

  • CLI： 代理修复及其 Node.js 22.19 楼层在此版本之前再次出现；他们以 v0.10.0 发货（296031974、#8311、66156bf35、#8391)。
