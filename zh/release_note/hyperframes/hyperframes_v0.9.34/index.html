hyperframes v0.9.34

这个项目是干啥的：HeyGen 开源的 AI 视频剪辑框架，把 HTML 当视频来写并渲染成 MP4，还能让 Claude Code 等助手直接改片，给会写网页的开发者和做批量视频的人用。

变更架构图

亮点

  • 帮助程序执行更安全 — FFmpeg、FFprobe 等辅助程序现在只从已安装位置或显式配置的路径解析，不再从项目目录里找；插件启动器和媒体辅助程序也统一使用固定版本的 CLI。这能防止仓库里的同名程序”顶替”受信任的可执行文件。迁移建议： 把项目自带的辅助程序装到系统全局，或显式配置它们的路径。
  • 可选开启的严格变量检查 — 开启后，Producer 会拒绝页面未声明的变量。默认关闭，所以不打开的话现有渲染行为完全不变。建议团队考虑启用，在渲染前就揪出拼错或过期的输入。
  • 预览更隔离 — CLI 预览现在默认使用内置的 Studio，除非显式开启 local Studio 模式。Studio 的字体和模块只在自己的预览帧里加载，缩略图使用密封页面，着色器转场也能兼容禁用本地存储的浏览器。迁移建议： 如果工作流依赖本地 Studio 检出，就显式开启 local Studio 模式。
  • 文件系统可靠性 — 现在即使磁盘因权限问题拒绝创建硬链接，保存文件也能正常进行。如果渲染或项目落在网络盘、受限文件系统等当前保存会失败的环境中，建议升级。
  • 注册表与写入范围收窄 — 注册表安装和 Studio 写入被限制在项目内容目录内，安装时也会拒绝额外的 coding-agent 指令文件。迁移建议： 检查那些往内容目录外写文件或依赖这些指令文件的包和自动化脚本。涉及安全或上述工作流的用户值得升级；完全可信、纯本地使用的用户可以跳过。

超帧 v0.9.34

发布于 2026 年 11 月 11 日。 HyperFrames 现在仅从安装位置运行 FFmpeg 等帮助程序，而从不从项目文件夹运行。当该检查打开时，渲染器还可以拒绝页面未声明的变量。

特点

  • 生产者： 在打开严格变量的情况下，当给定页面未声明的变量时，渲染会失败。默认情况下它处于关闭状态，因此渲染保持不变（f312fca7e、#7548）。

修复

  • Studio Server： 仅在 Studio 自己的预览框架中加载字体和模块（ffb13c3b6、#7553）。
  • 技能： 插件启动器和媒体助手运行固定的 CLI，而不是项目副本（a8fe3a5b6、#7552）。
  • CLI： 预览版使用捆绑的 Studio，除非选择本地 Studio 模式（668983e1a、#7551）。
  • 安全性： FFmpeg、FFprobe 和其他帮助程序仅从它们的安装位置或您设置的路径中获取，而不是从项目文件夹（84799bdc5、#7524）中获取。
  • 核心： 保存文件适用于因权限错误而拒绝硬链接的驱动器（f36463e29、#7474）。
  • Studio： 缩略图在密封页面中捕获，并且在浏览器阻止本地存储的情况下着色器过渡仍然有效（80cda85d7、#7528）。

目录

  • CLI： 拒绝注册表安装中的更多编码代理指令文件（[9bab57ab4]（https://github.com/heygen-com/hyperframes/commit/9bab57ab48db70f3aee3376f6bb86af5f7c50583），[#7549]（https://github.com/heygen-com/hyperframes/pull/7549））。
  • CLI 和 Studio： 注册表安装和 Studio 文件写入保留在项目内容文件夹内（b96c82b78、#7523）。

内部

  • 引擎： URL 读取并发测试在具有 32 个或更多核心的计算机上通过（3ad7611f9、#7544）。
