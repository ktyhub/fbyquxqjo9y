hyperframes v0.9.58

这个项目是干啥的：HeyGen 开源的 AI 视频剪辑框架，把 HTML 当视频来写并渲染成 MP4，还能让 Claude Code 等助手直接改片，给会写网页的开发者和做批量视频的人用。

变更架构图

亮点

  • npm 可用性（并非空操作） — v0.9.57 已准备好但从未发布到 npm；v0.9.58 是首个包含其全部内容的正式构建，所以一直在等 v0.9.57 修复的用户必须专门升到 v0.9.58。这是真正的特性/修复版本，不是重新打标签或仅元数据变更，尽管尾部大部分（Publish #7929/#7922/#7920/#7880、Player Safari 偶发问题 #7685、CI 超时 #7933）属于发布工程/测试卫生，对用户影响很小。
  • 密封预览交换 — Studio 现在可以导出密封预览中已勾选的元素读取值和替代占位内容（#7918），密封预览帧也会转发 Studio 的播放按键（#7844）。如果你在多个 Studio 实例之间传递密封预览，或依赖密封帧内的播放按键，这项改动很重要。
  • 项目文件隔离——值得关注的行为变化 — 一系列广泛的修复把渲染、carve 和音频都限制在项目自己的文件内：媒体输入拒绝可能打开其他文件的格式（#7931），渲染读取器跳过私有项目文件和文本艺术输入（#7928），渲染编译不再内联 @font-face 指定的私有文件（#7925），carve 使用自带的 core 分析副本（#7926），音频引擎只在项目文件夹内读写（#7897），嵌套的 .hyperframes 保持私有（#7927）。没有正式的迁移步骤，但此前越出自身项目文件夹的合成现在可能会失败——上线前请先测试。
  • CLI 行为与网络限制 — check 和 info 不再探测合成的远程媒体 URL（#7942）；打开合成的命令现在遵守 PRODUCER_RESTRICT_PAGE_NETWORK（#7935），并修复受限页面网络下的缩略图/Ctrl-C 清理问题（#7941）；open 现在在主文件夹而不是运行它的文件夹里启动桌面应用（#7937）；新增了管理或取消付费方案的页面（#7784）。
  • 谁该升级 — 如果你使用 Studio 密封预览、carve 或音频引擎（尤其是涉及私有/项目本地文件），或者需要现在就拿到已并入本版的某个 v0.9.57 修复，建议升级；调色溶解/擦除播放（#7756）和通过导出的 analyseCarveDynamics 重跑 carve（#7893）也相关。如果你锁定在可用构建上，只关心渲染/发布内部机制或偶发测试修复，可以跳过。

超帧 v0.9.58

发布于 2026 年 11 月 16 日。

Studio 导出密封预览的检查元素读取和替身，并将渲染、雕刻和音频引擎保留到项目自己的文件中。此版本还包含为 v0.9.57 准备的所有内容，但从未到达 npm。

特点

  • Studio： 密封预览帧转发 Studio 的播放键（b741ecf13、#7844）。
  • CLI： 显示并打开页面以管理或取消付费计划（[b2e6076b7]（https://github.com/heygen-com/hyperframes/commit/b2e6076b7e7f73debadd1ac91a5b64ea2c4d3ae0），[#7784]（https://github.com/heygen-com/hyperframes/pull/7784））。
  • Studio： 导出密封预览的检查元素读取和替身（a0848ad35、#7918）。

修复

  • CLI： 检查和信息永远不会探测合成的远程媒体 URL（[78648113d]（https://github.com/heygen-com/hyperframes/commit/78648113dbdac0f5daae75fed820509860267b41），[#7942]（https://github.com/heygen-com/hyperframes/pull/7942））。
  • CLI： Open 在主文件夹中启动桌面应用程序，而不是在其运行的文件夹中启动（a2e7306b2、#7937）。
  • CLI： 受限页面网络下的 Studio 缩略图和 Ctrl-C 清理（707e20f18、#7941）。
  • Studio Server： 在构建工作线程上构建页面的主机可以退出（e8f1fff5f、#7939）。
  • CLI： 打开合成的命令遵循 PRODUCER_RESTRICT_PAGE_NETWORK (49e9424ba、#7935)。
  • 引擎、制作人、cli： 媒体输入拒绝打开其他文件的格式（ead110aab、#7931）。
  • 引擎： 也检查 Bun 下受限下载的解析地址（04b690361、#7860）。
  • 解析器： GSAP 时间线内联器中的绑定总扩展（aed28486f、#7930）。
  • 嵌套.hyperframes保持私有，捕获页面服务器检查主机，项目清单引脚没有CLI（[d5f0b1a5b]（https://github.com/heygen-com/hyperframes/commit/d5f0b1a5bfd498256c1642f32451e670616e831b），[#7927]（https://github.com/heygen-com/hyperframes/pull/7927））。
  • Studio Server： 子合成预览在截止日期内根据请求线程构建（d159ec51c、#7857）。
  • 发布： 首次发布尝试不再无法查找重试将重用的工件（9f85cf0a2、#7929）。
  • 播放器： Safari 音频检查在干净的十次播放中不再出现问题（916bcc83a、#7685）。
  • 核心： 颜色分级视频在预览和导出中溶解和擦除播放（889143eac、#7756）。
  • 媒体使用： carve 包导出 analysisCarveDynamics，因此 carve 再次运行（94e499d8c、#7893）。
  • **解析器：**过去 10,000 个相同元素，每个 id 仍然是唯一的（472909914、#7919）。
  • 制作人： 计划副本会检查每个项目条目，无论其名称如何（7aaeb9371、#7906）。
  • **生产者：**渲染编译永远不会内联由@font-face命名的私有项目文件（[209477b65]（https://github.com/heygen-com/hyperframes/commit/209477b65810bb441f2e6a5ac12a79efdb5e7ed5），[#7925]（https://github.com/heygen-com/hyperframes/pull/7925））。
  • Studio： 预览图片在同一帧中采用其框的大小，无论是否缩放（1e040f6fe、#7907）。
  • 引擎、制作人： 渲染媒体阅读器跳过私有项目文件和文本艺术输入（6411df4e3、#7928）。
  • 媒体使用： Carve 运行自己的核心分析副本，而不是项目的（25c603521、#7926）。
  • Studio： 显示静态内容的主机一次会重新加载一页预览（dab8dc807、#7905）。
  • 命名项目文件的警告将控制字符打印为可见转义符（d42bbd67f、#7863）。
  • Studio： 恢复草稿由每个项目自己的服务器保存，而不是浏览器（2be03408d、#7904）。
  • 媒体使用： 音频引擎仅在项目文件夹内读取和写入（c2c6d8c59、#7897）。
  • CLI： 以占位符开头的模板的批量输出保留在工作文件夹中（cf44c60cd、#7868）。

文档和示例

  • 技能： 风格采样每次都会拉取模板，因此首先检查收到的副本（[d796fd59e]（https://github.com/heygen-com/hyperframes/commit/d796fd59ec0b4517b351433fa2f2eb0600cdf322），[#7924]（https://github.com/heygen-com/hyperframes/pull/7924））。

内部

  • 技能： 从仅主要的clawhub环境中读取ClawHub令牌（[5d5e2c062]（https://github.com/heygen-com/hyperframes/commit/5d5e2c062a4876e590f8d5a9fe59833d7b1e3684），[#7923]（https://github.com/heygen-com/hyperframes/pull/7923））。
  • Studio Server： 测试 CLI 的 20 秒上限，以便繁忙的 CI 运行程序停止超时（8ec98be29、#7933）。
  • 引擎： 浏览器池测试永远不会启动主机的缓存 Chrome（cadcdb955、#7759）。
  • 发布： 仅发布 tarballs npm 按照检查的方式读取（dac0468f7、#7922）。
  • 发布： 将 Lambda 发布重试绑定到不可变的运行工件（8e8eeb205、#7920）。
  • 发布： 该版本仅保留 Lambda 资产 npm 引脚或此运行构建的（11a7d2749、#7880）。
