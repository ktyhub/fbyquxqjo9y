ComfyUI v0.29.0

这个项目是干啥的：是一个用拖拽节点来搭AI绘画流程的工具，让用户像拼积木一样组合模型和控制步骤，把出图过程看得见、改得动。

变更架构图

亮点

  • 视频内存与训练 — 视频转码现在以流式输出，而不是把每一帧都缓冲到 RAM 里（CORE-353/CORE-351，PR #14813），降低了大视频的峰值内存压力。Trainer、数据集和图像处理节点也获得了视频支持（CORE-81，PR #13588）。如果你跑大型视频任务或视频训练，值得升级；纯图像用户可以跳过这些变化。
  • 新模型与控制覆盖 — 新增对 JoyImageEdit、Gemma4 12B 和 MageFlow 的原生支持，外加 anima lllite 控制、Wan 的原生 Uni3C Controlnet，以及 krea 2 的参考图支持。还修复了 Wan Dancer 的批处理、LTXV IC-LoRA 检测，以及 LTXVEmptyLatentAudio 中的浮点 FPS。这些都是增量式的，没有记录必须迁移的步骤；使用受影响的模型或控制就升级。
  • 性能与硬件行为 — comfy-kitchen 的 int8 和 RMS-RoPE 优化覆盖 Anima、JoyAI 图像、z image/lumina 2、Ernie、LTXV 和 Ideogram；latent_upsampler 迁移到 ModelPatcherDynamic。MageFlow 现在无需 bf16 也能工作，gfx1035 被当作 RDNA2 处理，默认后台占用上限提高到 128GB。受影响的硬件/模型用户应升级，而内存吃紧的安装应复核这个更高的上限；没有基准数字能证明普遍提速。
  • partner 节点扩展与 API 变化 — 新增 GPT5.6、Gemini 3.5 Flash、Claude Opus 5、Recraft V4.1 模型和 V4 图像编辑节点、ByteDance audio-1.0-multilingual，以及新的 HeyGen 节点。请求现在携带 ComfyUI Job Id 并遵循 X-Comfy-Credits-Used；Google Omni 切换到 Interactions API，使用内联视频数据。如果你用这些 provider 或节点就升级；Omni 切换没有记录用户侧迁移步骤。
  • 兼容性与升级结论 — 没有列出明确的核心破坏性变更或强制迁移步骤。Runway Gen3a 已弃用，因此要计划把工作流迁移走。便携版回退到较旧的 ROCm 栈，这对便携版 AMD 用户有影响。对视频、新模型、partner 和受影响性能的用户来说，这是一个有实质内容的版本；这些领域之外的成熟工作流可以跳过。
