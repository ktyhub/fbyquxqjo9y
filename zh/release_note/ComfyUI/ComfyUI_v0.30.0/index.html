ComfyUI v0.30.0

小版本 发布时间2026年8月3日 来源comfyanonymous/ComfyUI 英文原文

ComfyUI v0.30.0

变更流程图

亮点

  • 新模型与解码器支持 — 原生加入 MiniMax-H3（CORE-375，PR #15224），同时带来支持 768P 分辨率的 partner 节点（PR #15167、PR #15227）、用于加速 LTX2.3 解码的 PrunaVAED（PR #15129）、int8 convrot embedding 查找（CORE-371，PR #15035），以及 grok-imagine-video-1.5（PR #15197）和 Ideogram P-Image（PR #15154）的 partner 更新。如果你用这些模型系列，这条就很关键；PrunaVAED 是最值得关注的解码提速。
  • 低显存 / 内存管理 — 权重现在按 MRU 策略加载到进程内存中，复用 pinning 基础设施（PR #15027）；动态 pin 的清理延迟到模型销毁时（PR #15183），修正了 pin 注册优先级（PR #15226），comfy-aimdo 升到 0.4.11（PR #15215），并为 Windows 上 swap-memory 查询失败加了保护（PR #15219）。在有限显存/内存上跑大模型的用户值得升级。
  • 注意力后端与 AMD/Linux 可靠性 — 在 Linux 上 flash attention 失败时回退到 cuDNN attention（PR #15146），并在后端会为 GQA 回退到 math 时扩展 k、v（PR #15190）；comfy-kitchen 从 0.2.23 升到 0.2.26，带来 flux kv 修复（PR #15144）和 AMD 支持（PR #15160）。遇到注意力失败或 flux 问题的 Linux/AMD 用户应升级。
  • 破坏性变更 / 迁移与安全 — comfy/logging.py 重命名为 comfy/internal_logging.py（PR #15231），因此 import comfy.logging 的自定义节点必须更新；新的 DETAIL 日志旁路（CORE-369，PR #15064）是可选启用，且明确默认不开启（PR #15159）。安全加固包括：为数据集操作增加专用数据集文件夹，避免任意文件夹访问（PR #14807）、用实际的函数校验路径是否在目录内（PR #15216），以及修复因存储型 XSS 强制下载改动而失效的 SVG 预览（PR #15149）。
  • 值得升级吗？ — 这是一个有实质内容的特性版本，不是空操作或仅改元数据的重新打标签。低显存用户、Linux/AMD 用户、使用 MiniMax-H3/LTX/flux 视频或相关 partner 节点的人，以及希望获得安全修复的多用户/不可信工作流运营者，都应升级。如果你依赖 comfy.logging 导入、在自定义节点打好补丁前先别升，或者新模型/注意力修复都与自己无关、又想避开 partner 节点的定价变化（Bria 视频端点，PR #15155 / PR #15171 / PR #15186），则可以跳过。
