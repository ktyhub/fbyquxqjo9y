ComfyUI v0.31.0

ComfyUI v0.31.0

这个项目是干啥的：是一个用拖拽节点来搭AI绘画流程的工具，让用户像拼积木一样组合模型和控制步骤，把出图过程看得见、改得动。

变更架构图

亮点

  • MiniMax-H3 可靠性 — 修复了 H3 VAE 的设备放置、噪声 mask 采样、音频采样、audio-VAE 完整卸载，以及 EasyCache 导致的音频损坏；新增 int8_convrot VAE 支持。运行 MiniMax-H3 的用户 —— 尤其是涉及音频、卸载或 EasyCache 工作流的 —— 应优先升级，以获得正确性和运行时修复。
  • 性能与内存行为 — 加速 LTX 和 Wan，避免 res_multistep 中不必要的噪声创建，恢复 SDPA 非 cuDNN 小注意力旁路，并降低无 swap 的 Linux 系统上内存过度分配的风险。对 LTX/Wan 用户以及内存受限或非 cuDNN 环境来说，这些是最直接的收益，不过官方没有给出基准数字。
  • 新模型与节点 — 新增 Wan-Animate2、BFL Flux 3 视频、TopazAI Bloom 2 和 Wonder 3.5、ByteDance SeeDance 2.5，以及 asym w4a8_int 支持，另有 ImageCompositor 和 Seedream Layer Separation 节点。需要这些能力就升级；否则这一部分对你没什么实际价值。
  • partner 节点迁移 — 破坏性变更： Kling 已退役的旧模型和 Virtual Try-On API 被移除，使用它们的工作流必须迁移；changelog 中没有给出替代模型/API。Reve 节点是被弃用而非报告为已移除，因此规划替代方案时不要以为现有工作流已经失败。
  • 总体升级建议 — 这是一个有实质内容的错误修复、性能和特性版本 —— 不是重新打标签或仅改元数据的更新。受影响的模型、内存/注意力修复或新节点相关用户应升级；在这些领域之外工作流稳定的用户可以合理跳过。前端和模板更新（comfyui-frontend-package 1.48.7、工作流模板 v0.11.34）属于次要理由。
