PaddleOCR v2.1.1

#PaddleOCR v2.1.1

变更流程图

亮点

  • 以部署为核心的发布 — v2.1.1 没有新模型或训练特性；所有新增内容都是 deploy/ 下的推理侧工具。如果你一直在等 PaddleOCR 从 notebook 走向生产，这个版本正是补上这一环的。注意分支：所有路径都在 release/2.1 下，所以请固定检出版本，不要跟踪 master。
  • 通过 PaddleSlim 压缩模型 — deploy/slim 引入剪枝和量化流程。这是本版本其余内容的基石：压缩后的模型才让 Lite 和 Android 目标真正可用。要预期精度上的取舍——上线前请在自己的数据上做基准测试，因为更小更快的模型未必是更好的模型。
  • 用 Paddle-Lite 做端侧推理 — deploy/lite 新增了基于 Paddle-Lite 的移动端部署路径。请按 C++ 推理流程来规划，而不是 Python，并针对 Lite 运行时做模型转换/优化；Paddle-Lite 是独立依赖，有自己的版本兼容约束。
  • Android 示例应用 — deploy/android_demo 提供了一个可运行的 ppocr Android demo，是在真实硬件上端到端验证 OCR 的最快方式。把它当作集成模板而不是即插即用的库：你仍需把原生库接入自己的应用，并针对具体场景调优相机/预处理。
  • 用 Paddle Serving 做服务端推理 — deploy/pdserving 新增了基于 Paddle Serving 的部署方式，为生产负载提供网络 OCR 接口。这引入了一整套服务栈（模型产物、服务配置、RPC/HTTP）需要运维，因此除了模型精度，还要把扩缩容和生命周期管理考虑进去。
  • 破坏性变更 — 无；所有新增都是 deploy/ 下可选的新目录树。
