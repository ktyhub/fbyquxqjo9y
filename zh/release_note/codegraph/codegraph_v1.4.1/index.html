codegraph v1.4.1

[1.4.1] - 2026-07-10

新功能

  • MCP 服务器现在会注意到何时存在较新的 CodeGraph 版本并告诉您 - 一个长期运行的服务器过去常常默默地落后于版本，直到出现问题。启动时，它会在后台检查最新版本（从不阻塞，最多一天一次，缓存在计算机上的所有服务器上），并在服务器日志、代理在连接时看到的说明以及 codegraph_status 中显示一行“可用更新 - 运行 codegraph upgrade”通知。没有任何东西会自行更新，离线就意味着没有通知。使用 CODEGRAPH_NO_UPDATE_CHECK=1 选择退出； DO_NOT_TRACK=1 也禁用它。 (#1243)

修复

  • Windows npm 安装上的 codegraph upgrade 实际上再次运行 npm — 现代 Node 拒绝直接启动 npm.cmd，因此在执行任何操作之前升级会失败并出现生成错误。 npm 现在以终端运行它的方式调用。 (#1238)
  • codegraph uninstall 现在实际上卸载了 CodeGraph。它过去只删除代理配置并留下每个已安装的二进制文件，因此 codegraph 之后仍然运行 - 当 npm 全局安装和独立安装都存在并且删除一个仍然让另一个在 PATH 上应答时尤其令人困惑。现在，Uninstall 会找到计算机上的每个安装（独立捆绑包、npm 全局包、启动器链接），并在向您准确显示它找到的内容并首先询问之后将其全部删除（--yes 会跳过提示）。机器级设置（例如您的遥测选择）将被保留，源签出永远不会被触及，并且新的 --keep-cli 标志将恢复旧的仅配置行为。 (#1071)
  • codegraph_explore 不再让自然语言问题中的普通英语单词在碰巧与代码符号名称匹配时劫持排名。像“升级流程如何检查最新版本”这样的问题，用于将“检查”视为代理按名称要求的符号，将不相关的定义文件排在第一位，并将问题实际上完全排除在答案之外。精确书写的符号名称（camelCase、PascalCase、snake_case、限定名称）仍然像以前一样名列前茅，就像单词属于同一文件中的纯单词符号包一样。
  • 通过类属性进行的 PHP 方法调用 - $this->dep->method()，构造函数注入代码库（Symfony、Laravel）中的主要调用形式 - 现在解析为属性声明类型上的方法，因此调用者和影响分析会看到生产调用站点，而不是将 DI 重的方法报告为未调用或仅测试。提升的构造函数参数、类型化属性、经典构造函数赋值（包括多行签名）和类型化 setter 注入都重要；接口类型的属性解析为接口方法，继承的方法通过类型层次结构解析。仅参考属性形状的声明 - 其他地方的同名局部变量或参数永远不会错误输入属性 - 并且无法静态恢复类型的属性保持未链接而不是猜测。谢谢@w0lan。 (#1220)
  • codegraph upgrade 现在还会刷新安装到代理中的先前版本 - CLAUDE.md / AGENTS.md / GEMINI.md 中的 CodeGraph 部分和 MCP 条目 - 因此升级不再让代理遵循为已重命名或删除的工具编写的说明。仅刷新：您从未配置的代理不会被触及，并且您的权限和挂钩选择将被保留。也可手动使用 codegraph install --refresh，并可跳过 CODEGRAPH_NO_INSTALL_REFRESH=1。 (#1238)
  • npm 安装上的 codegraph upgrade 现在再次通过 npm 升级，而不是悄悄创建永远不会赢得 PATH 竞赛的第二个副本 - 以前，无论您升级多少次，codegraph --version 都会永远报告旧版本。 (#1238)
  • 每次升级后，CodeGraph 现在都会检查您的终端解析的 codegraph 命令是否确实提供新安装的版本 - 确认您不需要新终端，或者准确地告诉您哪个过时的安装正在影响新终端。 (#1071)
  • 安全监管机构不再杀死严重退化存储上的健康索引。它过去纯粹通过事件循环来判断活动性，因此在陷入困境的磁盘上进行的一次长数据库写入看起来与挂起的进程相同，并且可以终止有效的、正在进行的索引。在 codegraph index/codegraph init 期间，看门狗现在还会在执行操作之前检查磁盘上的索引文件是否正在推进：缓慢但正在进行的工作将被单独保留（受硬上限限制），而真正挂起的进程仍然会像以前一样快地被终止。 (#1231)
  • 增量同步现在会拾取仅在编辑后才可解析的跨文件关系 - 例如，当一个文件获得另一个未更改的文件已导入或调用的导出时。以前，从未重新访问未更改的文件中的引用，因此调用者、影响和流结果会默默地忽略新边缘（同时状态报告干净的索引），直到完全重新索引。尚无法解析的引用现在会被记住，并在更改引入可以满足它们的符号时自动重试 - 这也涵盖了获得其他文件已调用的新方法的类。感谢@loadcosmos 提供的报告，复制量极少。 (#1240)
  • 相反的情况也得到修复：当编辑删除或移动符号（或删除其文件）时，未更改文件中的调用者现在会在同一同步期间重新解析 - 移动时重新绑定到符号的新位置，或等待它返回时自动重新连接 - 而不是默默地失去它们的关系，直到完全重新索引。 (#1240)
