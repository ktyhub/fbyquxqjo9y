codegraph v1.1.3

[1.1.3] - 2026-06-29

修复

  • CodeGraph 现在对 git 记录为 gitlink 的嵌套存储库进行索引，因此通过将多个存储库堆叠在另一个存储库中构建的工作区完全从顶部的单个 codegraph init 进行索引。当一个存储库包含另一个 git add 的 git 存储库时（因此 git 将其作为 160000“提交”指针而不是文件文件夹进行跟踪）或一个在结账中不是活动的、初始化的子模块的子模块，该嵌套存储库的源代码通常会被完全跳过：对顶层的索引停止在嵌套存储库的边界处，并仅拉入外部存储库自己的文件，因此是一个堆叠存储库项目几乎是空的（一份报告看到在根目录索引了约 10 个文件）。 CodeGraph 现在深入到每个这样的嵌套存储库，该存储库在磁盘上有一个真正的工作树，并递归地将其索引为自己的嵌入式存储库，因此堆叠工作区的每一层都被覆盖。活动子模块（已处理）和普通未跟踪嵌套克隆未更改；依赖项目录下的嵌套存储库（例如 vendor/ 或 node_modules/）保持排除；并且磁盘上未检出任何内容的子模块正确地保留在原处，而不是报告为空。感谢@ofergr 和@kun-yx 的报告。 （＃1031，＃1033）
  • 当您在根目录索引的工作空间的子模块（或其他嵌套存储库）中工作时，CodeGraph 不再显示误导性的“不同 git 工作树”警告。因为索引工作区现在会拉入其子模块和嵌入式克隆，所以从内部运行的查询可以正确解析到工作区的单个索引 - 但它仍然警告结果来自“不同的工作树”，并建议您运行 codegraph init -i，这会将子模块拆分回其自己的单独索引并撤消统一视图。 CodeGraph 现在认识到嵌套存储库的代码已经是工作区索引的一部分并保持安静。对于真正的 git 工作树，该警告仍然会出现 - 第二次签出另一个分支上的相同存储库，它确实有自己的未提交符号 - 因为它就是这样存在的。 （＃1031，＃1033）
  • 在 Windows 上，CodeGraph 的后台服务器现在可以干净地关闭，而不是偶尔因崩溃错误而中止。当索引项目包含嵌套存储库（子模块或嵌入式克隆）时，停止服务器可能会与文件观察器的拆卸发生冲突，并以 Windows 崩溃代码退出，而不是干净退出。现在关闭可以让拆卸首先完成，因此服务器可以干净、迅速地停止。 （仅限 Windows；其他平台不受影响。）(#1033)
  • 从模板化基类继承的 C++ 类（class Widget : public Base<int>、class App : public CRTPBase<App> 等 CRTP 基类或继承模板的结构）现在链接到图中的该基类。以前，模板参数 (<int>) 使继承无法被识别，因此这些类看起来像是从无到有继承，并且影响/调用者分析在边界处停止；现在像任何其他基类一样遵循连接。感谢@ryancu7 的报告。 (#1043)
  • 在堆栈上构造的 C++ 对象（Calculator calc(0) 或 Widget w{1, 2}）现在记录封闭函数实例化该类，与堆构造 (new Calculator(0)) 已经做的一样。以前只跟踪 new 形式，因此使用普通堆栈语法构建对象的函数看起来好像没有构建它们，并且影响/调用者缺少依赖项。感谢@Dshuishui 的报告。 (#1035)
  • 图表不再存储相同关系的重复副本。同一位置的相同两个符号之间的相同依赖性可能会被记录多次，这会增加边缘计数，并使调用者/影响结果将关系列出两次。现在，每个关系都只存储一次，并且下次 CodeGraph 打开现有项目时，它们会自动进行重复数据删除。感谢@inth3shadows 的详细报告。 (#1034)
  • codegraph node 现在可以从命令行读取文件。文件读取模式 — 通过 -f/--file 获取文件源，其中包含行号以及依赖于它的文件，与 codegraph_node MCP 工具的输出相同 — 被拒绝，并显示“缺少必需的参数‘名称’”，因为即使文件模式没有符号名称，该命令也始终需要符号名称，从而无法从 CLI 访问该功能。符号名称现在是可选的：codegraph node -f src/auth.ts（或 codegraph node src/auth.ts）读取文件，codegraph node parseToken 查找符号，并且在不打印简短使用提示而不是神秘错误的情况下运行它。感谢@jcrabapple 的报告。 (#1044)
  • codegraph query 不再在每个结果旁边打印无意义的相关性百分比，例如“12042%”。该数字是原始全文搜索分数——仅用于对结果进行排序，而不是真正的 0-100% 数字——因此将其乘以 100 会产生狂野的值，使输出看起来很糟糕。结果已经首先列出了最佳匹配，因此 CLI 现在只是按顺序显示它们，没有分数，与搜索工具向 AI 代理报告的内容相匹配。如果您针对 codegraph query --json 编写脚本，则仍会包含原始 score 以进行排序或阈值处理。感谢@jcrabapple 的报告。 (#1045)
  • codegraph explore 不再报告广泛的自然语言查询中令人震惊的、夸大的结果计数。 “在 M 个文件中找到 N 个符号”摘要用于对排名时搜索到的每个符号进行计数，因此大型项目上的广泛查询（例如“将状态发布到 API”）可能会在代码库的很大一部分中公布数百个符号 - 读起来就好像您必须费力地浏览所有符号一样 - 即使实际上只有最相关的少数符号及其来源。现在，摘要仅计算浏览返回源的文件，因此该数字与您所看到的相符。排名和结果保持不变：正确的符号仍然排在第一位，任何其他相关文件仍然按名称列在“上面未显示”下，因此没有隐藏任何内容。感谢@jcrabapple 的报告。 (#1046)
  • Android 资源文件不再使索引膨胀。一棵 res/ 树——布局、绘图、值包（字符串、颜色、样式）、菜单、导航图——不包含代码符号，但在 Android 应用程序上，它可能是绝大多数文件（一个项目：26,000 多个 XML 文件，约 97% 的所有内容，贡献零符号），这会导致数据库膨胀，减慢索引速度，并填充文件计数和 codegraph explore/搜索结果，其中包含无法找到的条目。 CodeGraph 现在默认跳过 Android 资源目录 - res/layout/、res/values/、res/drawable/、res/menu/ 等，包括它们的区域设置/密度/版本变体，例如 res/values-es/ 或 res/drawable-hdpi/。您的实际代码没有受到影响，一种带有符号的 XML — MyBatis 映射器文件也没有受到影响，它位于 src/main/resources/ 下，而不是 res/ 下。 res/raw/ 是故意保留的（它可以保存实际资产），您可以使用 .gitignore 否定重新包含任何排除的目录，例如 !res/values/。感谢@jcrabapple 的报告。 (#1047)
