codegraph v1.6.3

[1.6.3] - 2026-11-17

变更流程图

亮点

  • 另外九名代理和编辑。 codegraph install 现在设置了 IBM Bob、Factory Droid、Windsurf、Qwen Code、DeepSeek Harness、Grok Build、Kimi Code、Qoder CLI 和 Pi。
  • 安全修复。 敏感文件夹（例如 ~/.ssh）无法再通过链接、连接或其路径的其他拼写作为项目打开，并且捆绑的 Node.js 移动到 24.22.1，这修复了 CVE-2026-111497。
  • 每种语言的链接都更加准确。 数百个修复程序可帮助调用、导入和类型到达其含义的代码，尤其是在 JavaScript 和 TypeScript、Go、C 和 C++、Rust、Python、C#、Java 和 Dart 中。 Tauri、CodeIgniter 3、Drupal 服务和插件、Next.js 中间件和 MediatR 处理程序现在也涵盖在内。
  • 为您的代理提供更好的答案。 codegraph_explore 不再在大型项目上停滞不前，在几秒钟内回复粘贴的日志或文件，查找以中文、日文或韩文命名的代码，并且其 Flow 到达您查询命名的每个符号。
  • 新命令。 codegraph cycles 查找在循环中相互导入的文件，codegraph implementations 列出实现类型的文件，codegraph files --format package 按包拆分 monorepo，codegraph init --local-only 将 .codegraph/ 保留在 git 之外。
  • 更稳定的后台服务器。 当后台服务器卡住时，新会话不再等待几分钟，在会话期间升级会将其切换到新版本，并且 codegraph sync 和文件观察器在添加、删除和恢复文件时保持正确的链接。
  • 更快、更轻。 仅读取索引的命令启动速度更快，索引占用的 CPU 和内存更少，尤其是在小型项目以及 C 和 C++ 上。
  • 升级： 在此版本后使用 codegraph index 重新索引您的项目。大多数这些修复是在索引时编写的，codegraph status 和您的代理都会告诉您旧版本何时构建索引。

安全

  • 像 ~/.ssh、/etc 或 C:\Windows 这样的敏感文件夹不能再通过链接或连接、不同的 capitalized 名称、\\?\ 路径或其中缺少文件夹的路径用作项目。以前，任何这些都可以让代理的查询读取其中的文件。谢谢@mixxer。 (#2929)
  • MCP 服务器不再使用 ~/.ssh 或 /etc 等敏感文件夹作为会话的默认项目，无论它来自代理的工作区、启动的文件夹还是 --path。之前，会话开始于一个会话，其中包含从内部文件中回答的索引。 (#3012)
  • 捆绑的 Node.js 运行时移至 Node 的 10 月安全版本 24.22.1，该版本修复了 CVE-2026-111497（Brotli 解码器中的高严重性越界写入），现在每个版本都会根据 nodejs.org 发布的校验和检查其捆绑的 Node。它还修复了当 codegraph sync 之类的命令在工作完成后退出时 Windows 崩溃的问题。感谢@Ancienttwo 和@IdealBoy709。 （＃2617，＃2780）

  • codegraph install 现在设置 DeepSeek Harness (dsh)：~/.dsh/cordis.patch.yml 中的一个条目涵盖了所有配置文件，再加上 ~/.dsh/AGENTS.md 中的一小部分。谢谢@hfldqwe。
  • codegraph install 现在设置 Grok Build，将 CodeGraph MCP 服务器添加到 ~/.grok/config.toml 或项目的 .grok/config.toml，以及 rules/codegraph.md 中的简短规则。谢谢@ximing。
  • codegraph install 现在设置 Kimi Code，将 CodeGraph MCP 服务器添加到 ~/.kimi-code/mcp.json 或项目的 .kimi-code/mcp.json，以及 AGENTS.md 中的一小部分。谢谢@zhouxbalabala。
  • codegraph install 现在设置 Qoder CLI，将 CodeGraph MCP 服务器添加到 ~/.qoder/settings.json 或项目的 .qoder/settings.local.json。谢谢@greatjackzhou。
  • codegraph install 现在设置 Pi，将 CodeGraph MCP 服务器添加到 ~/.pi/agent/mcp.json 或项目的 .pi/mcp.json，以及 AGENTS.md 中的一小部分。谢谢@roymina。
  • CodeGraph 的 MCP 服务器现在为代理和编辑者提供其显示名称和图标，因此显示它们的服务器（如 Codex 应用程序）会按名称和徽标列出 CodeGraph。谢谢@fedosov。
  • 仅读取索引的命令（例如 codegraph callers、query、node、impact 和 explore）现在启动速度更快并使用更少的内存，MCP 服务器的第一次握手和代理的提示挂钩也是如此。
  • codegraph status 现在显示何时只有某些语言的文件产生符号，并在没有产生符号时发出警告； codegraph status --strict 在该警告或索引缺失、未完成或过时时以非零值退出。谢谢@ferrine。 (#1658)
  • 升级后，您的代理对其索引早于引擎的项目的第一个答案现在会发出警告一次，命名构建它的版本和 codegraph index，而 codegraph_status 显示这两个版本。谢谢@cbeaulieu-gt。 （#1852）
  • codegraph serve --mcp --no-telemetry 关闭一个 MCP 服务器条目的遥测，因此共享 MCP 配置可以在没有环境变量的情况下选择退出。谢谢@danusha2345。 （#1908）
  • codegraph implementations <name> 列出了实现或扩展特征、接口或类的类型，以及每个类型的文件、行以及是否是测试代码； --depth 遵循子类的子类。谢谢@danusha2345。 (#2833)
  • 索引速度更快，尤其是在 C 和 C++ 上，在 Rust、Java 和 TypeScript 上索引速度更快，因为解析调用对于它所查看的每个名称重复的工作更少。
  • 索引一个小项目需要更少的 CPU 和内存：CodeGraph 仅启动项目需要的线程，解析速度慢的文件不再阻碍其他文件。
  • 设置 CODEGRAPH_SYNTH_MIN_INTERVAL_MS 以限制实时同步重建项目范围回调和事件链接的频率，在大型 TypeScript 或 Vue 存储库上几乎每次编辑都会发生这种情况。谢谢@danusha2345。 (#2911)
  • 索引大型项目在高峰期占用的内存更少。
  • 索引大型项目运行更少的线程并尽快完成，占用更少的 CPU 和内存。
  • 对于贡献者来说，测试套件现在在 Vitest 4 上运行，并且在此存储库中工作需要 Node 22.12 或更新版本；安装和使用 CodeGraph 不会改变。谢谢@danusha2345。
  • 新的 codegraph cycles 命令以文本或 --json 的形式列出以圆圈形式相互导入的文件组，并在找到任何文件时退出 1，因此它可以用作预提交或 CI 检查。感谢@jianyq9 和@goutham80808。 （#888）
  • codegraph init --local-only 使 .codegraph/ 完全脱离 git，因此 CodeGraph 的任何内容都不会显示在 git status 中，并且可以在已经设置的项目上运行。感谢@jadchene、@jianyq9、@Wood-Q 和@walterf3。 (#910)
  • 现在可以理解 CodeIgniter 3 项目：控制器方法和 routes.php 条目成为路由，包括 HMVC 模块，并通过 $this->load 加载链接到它们到达的方法进行调用。谢谢@darkspock。
  • 在 Drupal 中，来自 *.services.yml 的服务、插件定义和 #[Hook] 方法现在都在图中，并且通过 \Drupal::service('x') 的调用到达该服务类上的方法。谢谢@mikedamoiseau 和@marcelovani。
  • 在 Next.js 中，路由现在链接到在 config.matcher 之后运行的 proxy.ts 或 middleware.ts，因此影响、调用者和 codegraph_explore 显示对其进行的更改到达了哪些路由。谢谢@RIGOandre。

修复

窗口

  • 在 Windows 上，删除项目中链接指向的文件夹（例如与外部库的连接）不再使 CodeGraph 的服务器使用完整的 CPU 核心或停止获取您的编辑。谢谢@L0garithmic。
  • 在 Windows 上，位于驱动器根目录的项目（例如 Z:\ 等映射网络驱动器、subst 驱动器或网络共享的根目录）现在会编制索引，而不是因为“路径遍历被阻止”而拒绝每个文件。谢谢@Kaamilslaoui93。
  • 在 Windows 上，不存在的驱动器上的临时文件夹（例如拔出的磁盘或卸载的 RAM 驱动器）不再在启动时挂起每个 codegraph 命令。
  • 在 Windows 上，主结帐内的 git 工作树（例如 ZZPH100​​ZZ 下的工作树）现在可以识别，无论其路径如何编写，例如使用小写驱动器号 VS Code 和光标传递。谢谢@nk33-dev。
  • 一旦 GitHub 的匿名请求限制用完，Windows 安装程序 irm …/install.ps1 | iex 不再以“(403) Forbidden”停止，并且现在可以安装没有 v 的版本（如 CODEGRAPH_VERSION=1.6.2）。谢谢@hiyochi。
  • 在具有 Windows (CRLF) 行结尾的 JavaScript 和 TypeScript 文件中，在后面的行上导出的存储（如 export default useStore;）现在已对其操作进行索引，就像 Unix 行结尾一样。
  • 在 Windows 上，在 try! 之后编写的 Swift 调用（例如 try! Settings.Defaults.load()）现在链接到它所调用的内容，就像在 macOS 和 Linux 上一样。

设置、后台服务器和CLI

  • Claude Code 提示挂钩现在根据您键入的内容进行操作，跳过 Claude Code 的桌面应用程序在提示之前放置的状态注释，并且不提供来自另一个会话的消息的上下文。谢谢@WonderMr 和@yang0228。 (#2635)
  • 在代理会话打开时升级 CodeGraph 不再让旧版本的后台服务器负责：新安装的第一个会话会将其替换为当前会话。谢谢@lipchey。 (#2335)
  • 当过时的锁命名的进程不是 CodeGraph 时，codegraph index 不再停止并建议运行 codegraph daemon stop，而 codegraph daemon stop 并不存在；它清除锁定并重建。感谢@inth3shadows 和@danusha2345。 (#2770)
  • 共享后台服务器在更新另一个项目的索引时不再因“主线程无响应”而被终止，例如会话名称为 projectPath 的索引。谢谢@mradwankhalil。 (#2404)
  • 现在，会话通过 projectPath 查询的项目在没有查询的空闲时间结束后就会被释放，而不是保持锁定状态直到另一个项目的空闲时间用完。谢谢@bompus。 (#2087)
  • 其 projectPath 命名项目内文件的 MCP 工具调用现在从该项目进行应答，而不是因“路径不是目录”而失败。感谢@inth3shadows 和@maxmilian。 (#2982)
  • 由于索引运行中途停止而导致索引不完整，因此每次启动时不再导致后台服务器因“主线程无响应”而被终止；现在已在后台修复。谢谢@cbeaulieu-gt。 (#1887)
  • 当后台服务器卡住时，新的代理会话不再等待几分钟才能获得第一个应答：它会在几秒钟内放弃，自行应答并在服务器重新启动后切换回来。
  • 后台服务器现在会在空闲时将大量查询留下的突发归还给内存，并且暂停后的下一个调用仍然与其他调用一样快。感谢@danusha2345 和@doomsday1906。
  • 其代理停止读取答案的 MCP 会话现在会在下次应答时完全关闭，而不是因“未捕获的异常：错误：EPIPE”而崩溃。谢谢@iiijiashu。 (#2991)
  • 参数不是对象的工具调用（例如 "arguments": "alpha"）现在会收到标准的无效参数错误并且不会运行任何工具，而不是内部 CodeGraph 错误。感谢@inth3shadows 和@kjgggggg。 (#2981)
  • 使用bun从源代码构建CodeGraph，如在bun run build中，不再不断地重新开始直到它停止；使用 npm 构建没有改变。谢谢@bompus。
  • 当 CodeGraph 无法打开项目的数据库时，它现在会显示 SQLite 的错误、文件的路径以及要检查的内容，而不是总是说“CodeGraph 需要节点：sqlite (Node.js 22.5+)”。
  • 当从另一个结帐索引回答 git 工作树时，codegraph status 和您的代理的警告现在建议工作树中使用普通的 codegraph init，而没有不再执行任何操作的 -i 标志。谢谢@GaoSSR。
  • 当杂散的 <!-- CODEGRAPH_START --> 行位于 CodeGraph 部分上方时，codegraph upgrade 不再擦除您的代理指令文件，如全局 AGENTS.md 或 CLAUDE.md。谢谢@pzaj2。 (#2506)
  • codegraph install、upgrade 和 uninstall 现在通过符号链接指令或配置文件（例如点文件中的指令或配置文件）进行写入，而不是用副本替换链接。感谢@jguerra6、@meganemura 和@danusha2345。 (#2721)
  • 当您的 codegraph install 和 upgrade 的写入方式不同时，不再向 Codex 的 config.toml 添加第二个 [mcp_servers.codegraph] 条目，并修复已损坏的文件。感谢@dencoseca、@danusha2345 和@rudycelekli。 (#2562)
  • 对于 Hermes Agent，codegraph install 和 upgrade 不再将 mcp-codegraph 添加到 platform_toolsets.cli，这可能会隐藏您的其他 MCP 服务器，或重置您的 mcp_servers.codegraph 设置。谢谢@Huy3ko、@conifercone 和@rudycelekli。 (#2485)
  • 从主文件夹运行的 codegraph upgrade 现在升级全局 npm 安装，而不是在那里放置第二个副本，并且 pnpm、yarn 或 bun 安装获取升级它的命令。感谢@timlincool 和@maxmilian。 (#2477)
  • 升级后，codegraph status 和升级提醒现在会告诉您运行 codegraph index，而不是 codegraph sync 或 codegraph index -f。谢谢@Adam0120。
  • 当索引文件丢失符号时，codegraph status 不再说索引是最新的：它现在命名它们，status --json 计算它们，codegraph files --json 列出它们的错误。谢谢@lipchey。 (#2336)
  • codegraph sync 不再在较旧的 CodeGraph 构建的索引上显示“已经是最新的”：它会同步您的更改，然后警告它未触及的文件仍然需要完整的 codegraph index。谢谢@bompus。
  • codegraph affected --filter 现在将其 glob 与全名进行匹配，因此 tests/**/*.py 还会直接在 tests/ 中找到测试，而 tests/*.py 不再计算 tests/x.py.bak。谢谢@Jseca666。
  • codegraph init 和 codegraph index 打印的时间现在涵盖整个运行，包括解析引用和链接，并且 codegraph sync 也报告其整个运行。感谢@bompus 的报告。 (#2334)
  • codegraph context 现在打印的调用路径以 codegraph_explore 使用的单词命名桥接每个动态调度跃点的内容，因此通过接口的调用不再看起来像发出的事件。

索引和同步

  • 在延迟加载工作区包的项目（如 () => import('@vben/layouts').then((m) => m.IFrameView)）中，codegraph sync 不再因“FOREIGN KEY 约束失败”而失败。感谢@bompus 和@inth3shadows。 (#2565)
  • codegraph status 和 codegraph_status 现在报告其 git 存储库文件夹内项目中未提交的编辑、新文件和删除，如 monorepo 包。谢谢@innoxxicide。 (#1636)
  • 当无法加载语言解析器时，文件不再保存为没有符号的文件，就像升级删除正在运行的服务器的安装后发生的情况一样；以这种方式清空的文件将在下次同步时重新索引。谢谢@lipchey。 (#2335)
  • codegraph sync 和文件观察器现在链接导入因文件大小或解析失败而被跳过的文件的文件，一旦编辑允许它被索引，就像完整索引一样。谢谢@inth3shadows。 (#3016)
  • 使用 CodeGraph 作为库来索引所选文件的程序现在会将其他 CodeGraph 进程（例如 git hook 的 codegraph sync）保留在索引之外，直到这些文件被存储为止。
  • 当多个 CodeGraph 进程在一个进程崩溃后同时启动时，现在只有一个进程接管其留下的写锁，因此两个进程不再同时写入索引。感谢@inth3shadows 和@vedantb7。 (#2979)
  • 使用 CodeGraph 作为重新运行完整索引的库的程序现在可以通过其名称中的单词来查找每个符号，codegraph_explore 和提示钩子可以匹配问题。谢谢@rudycelekli。
  • 使用 CodeGraph 作为库的程序在传递 watch() 回调、onSyncError 或 onDegraded 抛出异常时不再崩溃；错误已被记录，并且失败的同步仍会重试。谢谢@johnhldiver-beep。 (#2643)
  • 长时间运行的会话现在会注意到在运行时添加或删除的框架，例如新 package.json 中的 Express，而 codegraph status 建议使用完整索引。感谢@nk33-dev 和@inth3shadows。 （＃2516，＃2519，＃3007）
  • 在 codegraph index 重建项目时运行 codegraph status 不再导致重建失败并显示“数据库已锁定”，并且状态现在会显示重建何时运行。感谢@sealad886、@danusha2345 和@KissFeng。 (#2913)
  • 运行 codegraph query、explore、node、callers 和其他读取命令，或 Claude Code 的上下文挂钩，而 codegraph index 重建不再导致重建失败并显示“数据库已锁定”。谢谢@sealad886。 (#2913)
  • 当多个 CodeGraph 进程同时打开一个项目时，打开其索引需要架构更新的项目不再会因“UNIQUE 约束失败”或“数据库被锁定”而失败。感谢@inth3shadows 和@johnhldiver-beep。 (#2980)
  • codegraph init 和 codegraph index 不再将 git 仍列出的已删除文件或损坏的符号链接报告为“无法读取”，并且不再查找稀疏签出的遗留文件。谢谢@xianzhi-xzw。 (#2904)

  • 由主题编辑器保存的 Shopify JSON 模板或部分组（在顶部写入评论）现在链接其列出的部分，因此它们看起来不再未使用。谢谢@Puma7。 (#2494)

  • 在 Liquid 中，名称带有连字符的变量（如 {% capture icon-cart %}）现在在其全名下建立索引，因此搜索并 codegraph_explore 可以找到它。谢谢@Puma7。 (#2498)

  • 在 CFML 中，解析器无法读取的 <cfquery> 或 <cfscript> 块不再将其整个文件标记为无贡献，因此 codegraph init 和 codegraph status 不再标记该文件。谢谢@HarryMuc。 (#2654)
  • 在 CFML 中，像 extends="contenscms.core.basecore" 这样的点状 extends 现在链接到它命名的组件，即使测试套件镜像其文件夹和文件名也是如此。感谢@HarryMuc 的报告。 (#2650)
  • 在 CFML 中，<cfinclude template="formlistshared.cfm"> 及其脚本形式现在将它们所在的组件、函数或模板链接到它们包含的文件中。感谢@HarryMuc 的报告。 (#2651)
  • 在 PHP 中，通过命名空间别名编写的类（其大小写不同于 use 语句）现在链接到该类，因为 PHP 读取命名空间名称时不考虑大小写。谢谢@danusha2345。 (#2369)
