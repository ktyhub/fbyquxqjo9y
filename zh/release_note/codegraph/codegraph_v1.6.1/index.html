codegraph v1.6.1

这个项目是干啥的：把代码库画成一张能查询的关系图谱，让 AI 和人都快速搞清代码结构、谁调用了谁。给想理清大型项目的开发者用。

[1.6.1] - 2026-09-29

变更架构图

亮点

  • 来自 codegraph_explore 的更清晰的答案。 它返回您命名的函数和方法 - 即使来自一个非常大的文件，或者一个充满同名覆盖的文件 - 尊重查询中的行号，并在它缩短答案而不是称其为完整时表示。
  • 你的应用程序的导航和请求都在图表中。 Expo Router、Next.js、React Router、TanStack Router、Vue Router / Nuxt 和 SvelteKit 页面及其之间的链接是路由和 navigates 边缘，页面的 fetch 到达为其提供服务的路由，因此“这个去哪里”和“什么调用这个端点”是 codegraph_explore 的一个问题。
  • Explore 表示呼叫发生时。 codegraph_explore 的 Flow 部分中的每个跃点都包含其运行条件，适用于 JavaScript、TypeScript、Swift、Python、Java、Kotlin、C#、Go 和 C。
  • 更少错误链接。 对 TypeScript、JavaScript、Python、Java、Kotlin、Go、Rust、Scala、PHP 和 C/C++ 中的调用、导入和继承解析方式进行了许多修复，因此调用将停止登陆恰好共享其名称的不相关符号。
  • 您可以信赖的实时同步。 MCP 服务器在 codegraph index 之后遵循重建索引，中途中断的同步可恢复干净索引的内容，符号链接文件夹保持同步，Windows 驱动器上的 WSL 项目获得自己的索引。
  • 在大型存储库上更轻。 MCP 服务器的重复探索不再重新扫描整个图表，并且在索引时不再读取或解析超大文件和 .ts 视频装置。
  • 升级： 在此版本之后重新索引您的项目 - 在索引时编写了一些修复和新的导航链接。

新功能

  • Codex 和 Astra 阅读了 AGENTS.md 的项目指南。 规范代理指南现在位于 AGENTS.md 中（带有嵌套的 docs/AGENTS.md 用于长验证注释）； CLAUDE.md 是 Claude Code 的薄 @AGENTS.md 包装器。 Codex/Ast​​ra 不再错过旧的仅 CLAUDE 指令。
  • Next.js 页面及其导航位于图表中。 App Router 页面 (app/(group)/blog/[slug]/page.tsx → /blog/:slug) 和 Pages Router 页面是绑定到它们导出的组件的路由，以及 <Link href>、内部 <a href>、router.push / router.replace（next/navigation 和 next/router）、redirect() / permanentRedirect() 和中间件的 NextResponse.redirect(…) 是它们之间的 navigates 边。 app/api/**/route.ts 导出（GET、POST 等）是绑定到其函数的端点，pages/api/* 处理程序是 ANY /api/…。升级后重新索引。
  • **TanStack 路由器路由和导航位于图表中。 ** TanStack 应用程序声明路由的方式有两种：基于文件的，其中 createFileRoute('/posts/$postId') 携带整个路径；以及基于代码的，其中每个 createRoute({ path, getParentRoute }) 都是通过其父级组成的 - 而 navigate({ to })，抛出的 redirect({ to }) 和 <Link to> / <Navigate to> 是它们命名的路由的 navigates 边缘。无路径的 _auth 布局、(group) 文件夹和 __root 不是页面，并且计算出的目的地被遗漏而不是猜测。升级后重新索引。
  • Vue Router、Nuxt 和 SvelteKit 导航在图中。 Vue: 路由是从 createRouter({ routes: [...] }) 读取的，包括惰性 component: () => import('@/views/Login') 和 router.push / router.replace / $router.push，Nuxt 的 navigateTo 和 <router-link> / <RouterLink> / <NuxtLink> 是navigates 边，通过路线名称和路径解析。 SvelteKit： 来自加载或表单操作的 goto('/login')、redirect(303, …) 和普通 <a href> 是 navigates 边缘，并且页面将连接到为其提供服务的页面文件及其旁边的 +page.server.js。计算出的目的地或没有声明的路径被遗漏而不是猜测。升级后重新索引。
  • React Router 导航位于图表中。 history.push / history.replace、useNavigate 中的 navigate(…)、加载器或操作中的 redirect() 以及 <Link to> / <NavLink to> / <Navigate to> / React-router-bootstrap 的 <LinkContainer to> 现在是它们打开的路由的 navigates 边缘， /cart 和 /cart/5 都可以到达带有可选参数（/cart/:id?）的路由。计算出的目的地或没有路由服务的路径被遗漏而不是猜测，并且阵列上的普通 paths.push('/x') 永远不会被误认为导航。升级后重新索引。
  • codegraph_explore 跨层跟踪 Web 应用程序。 页面的 fetch('/api/users', { method: 'POST' }) — 或 axios / ky / got / $fetch 调用，包括通过 axios.create({ baseURL }) 实例的调用 — 现在到达在同一索引中为其提供服务的路由。放在 BullMQ / Bull 队列上的作业到达 @Process 方法、使用它的 Worker 或 queue.process 处理程序、NestJS EventEmitter2 事件及其 @OnEvent 侦听器、网关的 @SubscribeMessage 处理程序并返回的套接字消息，以及从 client 文件调用的 Next.js 服务器操作是到服务器的交叉。每个都是 Flow 部分命名的合成跳跃，以及它的连接位置。仅文字路径或事件名称对。重新索引以拾取新的边缘。
  • codegraph_explore 表示每次调用发生时。 Flow 部分中的每个跃点都包含其调用站点所在的条件 - ↓ calls (when isCollected) - 从调用周围的 if / else、switch / when / match、三元、try 和 && / and 分支读取，以及在它之前提前返回（if (busy) return 读作 !busy，Go 的 if err != nil { return } 读作 err == nil）。它适用于 JavaScript、TypeScript、Swift、Python、Java、Kotlin、C#、Go 和 C，是从源代码中读取的，没有规则的语言除了猜测之外什么也不说。
  • React Native 应用程序：Swift 本机模块及其事件端到端连接。 像 captureView.finalizeCaptureSession() 这样的 JS 调用（其中 captureView 绑定到 NativeModules.CaptureView 并且该模块是通过 RCT_EXTERN_MODULE 填充程序公开的 Swift 类）现在解析为 Swift 方法本身，而不是在常量处停止，因此 codegraph_explore 遵循本机代码。 Native → JS 事件现在也登陆内联编写的侦听器 (ZZPH100​​ZZ)，这归因于注册它们的组件。升级后重新索引以拾取新的边缘。
  • Expo Router 应用程序：屏幕和导航位于图表中。 app/（或 src/app/）下的每个屏幕文件现在都是一个以其路径命名的路由节点 - /object-detail、/item/[id]，其中 (group) 文件夹被剥离 - 链接到它渲染的组件。像 router.push('/object-detail?…')、router.navigate({ pathname: '/item/[id]', params })、模板文字 href、本地 const 中保存的 href 和 router.push(await pickRoute()) 之类的调用，其中助手返回屏幕路径（每个屏幕可以返回一个边缘）解析为它们打开的屏幕，作为记住 href 的新 navigates 边缘，因此“点击此去哪里”和“谁打开此屏幕”是其中的一跳codegraph_explore 和 callers 代替了琴弦的死角。升级后重新索引以拾取新的边缘。

修复

  • 当后台代理完成时，克劳德代码提示钩子不再在克劳德代码注入的任务通知消息上运行，从而消除了每次这样的多秒停顿。 (#1832)
  • Rust 对 self 的调用现在保留在封闭类型中，而不是链接到不相关类型的同名方法。谢谢@L4XB。 （#1861）
  • 现在关闭遥测会重置其身份并停止运行进程以记录、发送或恢复未发送的数据。 （#1869）
  • JavaScript、JSX 和 TypeScript 文件之间的调用保留其调用者和回调流。
  • Zustand 操作在读取类型存储、从存储状态解构或通过挂钩选择时保留其调用者。
  • 直接 React Native 桥接调用保留其本机实现和跨平台关系。
  • 使用 WebAssembly 解析器时，Dart 扩展类型 getter 仍然可搜索。
  • 对等待的值调用内置方法不再记录对恰好声明同名方法的不相关类的调用，并且绑定到等待的调用的变量现在解析调用返回的类型上的方法。谢谢@maxmilian。 (#1840)
  • Spring 映射现在包括每个声明的路径组合并解析在同一文件中声明的常量，而未解析的路径不再显示为错误的根路由。 (#1461)
  • codegraph node 现在接受带有行号的文件引用 - src/app.ts:42、src/app.ts:42-80、src/app.ts#L42、src/app.ts#L42-L80 - 而不是将文件报告为未索引；行范围成为读取的窗口，您自己传递的 --offset/--limit 仍然获胜。真正以这种方式命名的路径仍按书面形式进行查找。 (#1831)
  • codegraph callers、codegraph callees 和 codegraph impact 现在根据定义解析限定名称、分组结果和 JSON 边，并接受 --file 来缩小不明确的名称；谢谢@ferrine。 （＃1512，＃1656）
  • codegraph callers、codegraph callees 和 codegraph impact（CLI 和 MCP）现在会报告缺失的名称，并带有您的意思建议，而不是另一个符号的结果，并且没有呼叫者的精确匹配保持为空；谢谢@uvmplus。 （＃1473，＃1481）
  • 当 codegraph_explore 修剪大文件时，其源代码中的间隙现在仅使用文件预算剩余的空间来命名被遗漏的符号，因此名称永远不会推出代码本身。 (#1711)
  • codegraph_explore 不再通过未声明该方法的基类报告“运行时调度”，因此许多不相关子类共享的通用名称不再打开包含数千个实现列表的答案。
  • 当您在一个文件中命名多个函数并且不相关的代码位于它们之间时，codegraph_explore 现在会返回您在它们周围的代码之前命名的函数，而不是在该代码上占用文件空间并让您要求的函数之一根本没有源。
  • codegraph_explore 现在返回您与其类一起命名的方法的主体，例如 SQLCompiler.as_sql，即使在充满同名覆盖的文件中也是如此。它曾经将您请求的方法缩小到其签名行，而其周围较小的方法则完整返回。现在，对于答案来说太长的方法会以其开头行加上调用您命名的其他符号的位置返回，并带有返回其余部分的精确后续查询。
  • codegraph_explore 现在支持查询中的行号：compiler.py:776 返回包含该行的方法，而 compiler.py lines 900-1003（或 :900-1003、#L900-L1003、L900-L1003）准确返回这些行。它用于固定文件并忽略数字。
  • 当 codegraph_explore 查询中的文件名与多个文件夹中的文件匹配时，只会固定定义该查询也命名的函数或类的文件，并且摘要行会列出未列出的文件。每场比赛过去都是固定的，所以你所说的文件只有你省略其名称时所获得的一半空间；许多文件共享的名称（例如 models.py）现在可以以相同的方式解析，而不是被报告为不明确。

MCP / 索引

  • 在 Windows 上，共享 MCP 守护程序现在等待另一个程序（防病毒扫描、索引器或读取其锁定文件的另一个会话）的时间更长，以释放该文件，因此它会启动，而不是让会话回退到速度较慢的进程内服务器。 （#1773）
  • 超过大小限制的文件在被跳过之前不再被读取。大型提交的视频和 blob 固定装置过去会被完全加载到内存中，每次索引传递一次，只会被丢弃；索引和更改检测现在改为根据文件的大小进行。谢谢@danusha2345。 （＃1910）
  • 碰巧命名为 .ts（testdata/、e2e clips 下的黄金装置）的 MPEG 传输流视频现在从其第一个字节开始识别并跳过，而不是馈送到 TypeScript 解析器，该解析器在每个 clip 上花费了很长时间，没有符号。真正的 TypeScript 文件仍然被索引。谢谢@danusha2345。 （＃1910）
  • 从正在运行的 MCP 服务器重复调用 codegraph_explore 不再每次都重新排列整个图以查找项目的核心文件；答案将被重复使用，直到索引发生变化。谢谢@danusha2345。 (#1864)
  • 文件监视不再放弃同步失败时所要求的完全重新扫描已删除的目录，因此已删除的文件会保留索引而不是徘徊。 (#1964)
  • 在 MCP 服务器运行时运行 codegraph index 不再将实时自动同步写入旧的、替换的索引中：服务器现在在下次更新之前切换到重建索引，并赶上否则会错过的所有内容。谢谢@danusha2345。 （＃1902）
  • 守护进程启动和清理现在保留实时遗留的仅 PID 锁，同时仍然回收死的或身份被证明的记录，从而防止两个编写器为同一个项目提供服务。
  • 父目录中留下的空或无表的 codegraph.db（由中断的 codegraph init 或从未填充的 ~/.codegraph/）不再算作已初始化的项目，因此它无法再隐藏其下每个项目的真实索引。只有实际携带代码图模式的数据库才会被视为已初始化，并且包含损坏文件的目录中的 codegraph init 现在会修复它，而不是用“已初始化”来拒绝。谢谢@danusha2345。 (#1895)
  • 增量同步现在可以保持边缘重新绑定崩溃安全：用原子提交的恢复引用替换已解析的边缘，因此中断无法永久删除关系。
  • 状态现在可以检测已提交但未索引的更改并恢复编辑，而无需扫描每个源文件；谢谢@inth3shadows。 （#1829）
  • 从主目录或更广泛的包含杂散工作区清单的目录运行时，提示挂钩不再注入不相关的项目。 (#1454)
  • codegraph_explore 现在这样说，当查询命名无扩展名文件时，索引不包含该文件。像 scripts/deploy 这样的路径在其最后一段上没有扩展名，因此它未能通过形状测试，该形状测试确定跨度是一条毫无疑问的路径 - 名称留在查询中，被分解为 scripts 和 deploy，并且答案作为一堆不相关的源返回，没有任何迹象表明您命名的文件从未被查阅过。现在根据项目目录检查这样的跨度：如果它是真实文件，则答案带有相同的 No indexed file uniquely matches ... 注释，而拼写错误的 src/foo.ts 已经得到。被删减的散文 - and/or、input/output、gen_server:call/2 - 后面没有文件，并且仍然保留在查询中不变。 （＃1830）
  • 当 Node.js 的 SQLite 缺少 FTS5 时，索引现在会成功，搜索会退回到名称和模糊匹配；谢谢@aniruddhaadak80。 (#1532)
  • codegraph_explore 现在明确表示建议的呼叫计数是建议性的，因此当答案不完整时，客服人员会继续探索；谢谢@rongbc。 （＃1504，＃1570）
  • 现在，包含原始字符串模板的匿名名称空间后面的 C++ 函数可以正确索引，即使模板文本类似于未完成的宏调用也是如此。 (#1505)
  • 当解析器错误导致文件没有任何符号（包括带有 16 个字符分隔符的 C++ 原始字符串）时，索引现在会发出警告，因此丢失的代码不再是无声的。 (#1522)
  • codegraph index <path> 现在拒绝未初始化的路径并命名最近的初始化父路径，而不是默默地重建它；谢谢@danusha2345。 （＃1524，＃1689）
  • 同步现在在引用解析中断后恢复与干净索引相同的连接，包括以前丢失的继承调用和回调。 (#1577)
  • codegraph_explore 现在将源重新提供给新的子代理并在上下文压缩后，只有通过显式的 CODEGRAPH_EXPLORE_DEDUP=1 选择加入才能实现交叉调用重复数据删除；谢谢@danusha2345。 （＃1620，＃1624）
  • 观察者范围现在匹配 git ls-files --exclude-standard (#1728)。 buildDefaultIgnore / buildScopeIgnore 读取 .git/info/exclude 和 core.excludesFile （不仅是根 .gitignore），并且种子目录 git 报告为忽略未跟踪，因此嵌套的 .gitignore 效果会像索引器跳过它们一样修剪实时观察者。单文件自动同步已经是增量的（pendingFiles → 范围 sync({ paths })）；剩下的间隙是观察 git 已排除的树木。
  • 当读取器保持打开状态时，实时同步不再让预写日志无限制地增长 (#1539)。 增量同步现在使用与已使用的完整索引相同的写入器暂停，并且如果一旦日志超过其记录的大小限制，检查点仍然无法完成（通常是因为查询池同时读取），同步会停止并出现明显错误，而不是继续写入直到磁盘填满。先前的行为可能会在大型项目上的几 GB 索引旁边留下数十 GB 的日志。关闭并发读取器并重试，或者如果项目的限制太紧，则提高 CODEGRAPH_WAL_VALVE_MB。
  • 同一项目上的第二个 codegraph serve --mcp 不再默默地终止自动同步 (#1740)。 直接模式（CODEGRAPH_NO_DAEMON=1 或代理→进程内后备）现在采用独占 .codegraph/writer.pid 锁；第二个编写器立即退出，并指导停止其他服务器或取消设置 CODEGRAPH_NO_DAEMON，以便 clients 共享守护程序。共享守护进程已经将 N client 多路复用到一个观察者上 - 这弥补了文档警告 Windows/WSL 但没有保护的相同操作系统双直接差距。
  • 索引不再检查项目外部的文件是否存在。指向项目目录 (../../something) 上方的相对导入使 CodeGraph 在解析时探测磁盘上的该位置。项目之外的任何内容都没有被读取，也没有这样的文件被添加到索引或链接到，但检查本身不应该发生——这样的导入现在只是解析为空。项目内指向保存在其他地方的代码的符号链接不受影响，并且仍然像以前一样索引。谢谢@ErQrYfkrju。 (#1631)
  • codegraph install 现在支持 CLAUDE_CONFIG_DIR 和 CODEX_HOME 进行全局 Claude Code 和 Codex 设置，以便 CodeGraph 加载到您选择的配置文件中（感谢 @seanchann；#1627）。
  • codegraph install --refresh 不再在未设置的代理配置旁边留下 .backup 文件。检查代理是否已经具有 CodeGraph 意味着读取其配置，而无效的 JSON 配置（例如，反重力安装旁边的空 mcp_config.json）会被复制到一边，并发出 CodeGraph 即将覆盖它的警告，即使代理随后被原封不动地跳过。检查现在沉默了；无法读取的配置仍然会备份，但前提是 CodeGraph 确实要替换它。谢谢@Gotman08。 (#1870)
  • 使用 includeIgnored 选择加入的文件现在保留在早于 2.36 的 Git 索引上，并且嵌入式存储库对观察者仍然可见（感谢 @maxmilian 和 @newshowardz777；#1549）。
  • codegraph init 和 codegraph index 现在列出了不支持的文件扩展名，并解释了当未找到支持的源文件时 CodeGraph 处于非活动状态 (#1502)。
  • codegraph_explore 现在标记从带有替换的模板文字或字符串连接构建的动态 import()/require()，而转义的 \${…} 保持纯字符串。谢谢@inth3shadows。 (#1967)
  • 过时文件警告不再仅仅因为其路径是答案显示的路径的前缀或后缀而命名待处理文件（src/app.ts 与 src/app.tsx）。谢谢@inth3shadows。 (#1968)

链接和导航

  • <Card/> 是文件导入的卡，而不是存储库中的第一个。 当两个组件共享一个名称（Section、Picker、FrameCard，每个功能文件夹一个）时，组件的渲染链接会选择第一个被索引的组件，忽略文件实际声明或导入的内容，因此组件获得了一个指向它从未渲染和调用者的链接，并影响死胡同在它所做的那一个。现在，它遵循文件自己的声明或导入，并且 JavaScript 标记更喜欢 JavaScript 组件，而不是移动应用程序本机一半中的同名类。升级后重新索引。
  • 前往多个地点之一的导航现在链接到所有地点。 作为选择写入的目的地 — 分页器的!isAdmin ? keyword ? \/搜索/${keyword}/页/${x}` : `/页/${x}` : `/admin/productlist/${x}`, redirect(307，用户？`/profile/@${user.username}`： ‘/login’)in a loader,router.push(cond ? ‘/a’ : ‘/b’)— used to produce no edge at all, because one edge carried one destination and picking an arm would have been a guess. Every arm is now its ownnavigates` 边缘到它命名的路线；命名相同路线的武器仍然可以构成一条。
  • 条件中的条件不再读取错误的分支。 编写为 !isAdmin ? keyword ? '/search/…' : '/page/…' : '/admin/…' 的分页器在第一个 : 处分割，而不是在匹配的分页处分割，因此管理员的页面链接指向店面的分页。现在，手臂已经正确配对，并且三向选择——这比一个链接可以命名的目的地还要多——就不用管了。
  • 在包含多个应用程序的存储库中，链接不再指向不同的应用程序。 每个应用程序都有一个 /，大多数应用程序都有一个 /login，并且路由表是立即为整个存储库构建的，因此无论哪个应用程序首先索引，都会声明每个地址 - 一个应用程序中的 <Link to="/posts"> 解析为另一个应用程序的 /posts。在 477 个应用程序的 monorepo 上进行测量：82% 的导航指向属于不同应用程序的路线，现在所有导航都指向自己的路线。
  • 带有类型参数的 client 调用 - useSWR<Team>('/api/team', fetcher)、ky.get<User>('/api/users/1') - 现在像非类型化形式一样到达其路由。

路由和框架检测

  • SvelteKit 布局不再是页面地址处的第二条路线。 +layout.svelte 和 +error.svelte 与它们旁边的 +page.svelte 位于同一路径，并且每个都被索引为路线，因此一个地址在索引中出现了两三次。现在只有一个页面是一条路线。
  • 再次检测到其包位于子文件夹中的框架。 在将其依赖项保持为低一级的项目中（frontend/ 和 backend/ 或 apps/web/），框架检查在任何文件被索引之前运行一次，没有找到可查找的文件夹，并在其余运行中记住空答案。每个 React、React Router 和 Next.js 行为都依赖于知道框架是否存在，但对这些项目没有任何作用。
  • app.use('/api', router) 后面的快速路由由请求所采用的路径命名。 安装在前缀上的路由器（通过导入或 require 通过与应用程序嵌套的 router.use('/users', usersRouter) 级别一样多）现在将其路由命名为 POST /api/users 而不是 POST /，并且链接形式 router.route('/:id').get(getProduct).put(protect, updateProduct)（是否跨行分割）为每个方法注册一个路由。 client 的请求也通过该真实路径与其路由配对。
  • 通过包装器编写的 Express 处理程序是端点的处理程序。 const authUser = asyncHandler(async (req, res) => { … }) — express-async-handler 习惯用法 — 现在是其路由绑定到的处理程序。
  • 检测到在工作区的 package.json 中声明的框架。 当 React、Next.js、Expo Router、Express 和 NestJS 的依赖项存在于 frontend/、backend/、apps/web/ 或 packages/api/ 中而不是存储库根目录中时，会发现它们，因此单一存储库的页面和端点存在于索引中。

  • 检测到位于单一存储库的一个目录中的 FastAPI 服务。 backend/pyproject.toml 和 backend/app/main.py 不仅计数存储库根目录中的文件，而且还对官方全栈模板的路由进行索引。
  • React Router 路由现在从每个 <Route> 标签自己的属性和每个路由对象自己的字段中读取，因此 element 不再渗透到同级或父路由中。谢谢@inth3shadows。 (#1348)
