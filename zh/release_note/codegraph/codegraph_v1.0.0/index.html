codegraph v1.0.0

[1.0.0] - 2026-06-12

安全

  • 关闭了一个路径遍历漏洞，其中索引项目内指向项目根目录“外部”的符号链接可以使 CodeGraph 将该根外文件的内容（例如主目录下的文件）提供给 AI 代理。 CodeGraph 现在在验证文件访问时解析符号链接，并拒绝读取实际位置在项目外部的任何内容，同时仍然允许符号链接保留在项目内。谢谢@sulthonzh。 (#527)
  • CodeGraph 现在仅按键对 Spring 配置文件 (application.properties / application.yml) 进行索引，并且从不将其值包含在 codegraph_explore 或 codegraph_node 输出中。以前，提交给这些文件之一的秘密（数据库密码、API 密钥或具有嵌入式凭据的连接字符串）可以向询问附近代码的 AI 代理显示，即使代理从未打开过该文件。配置键仍然被索引，因此参考和影响分析不受影响；真正需要值的代理会读取文件本身。 Shopify Liquid {% schema %} 块同样仅按名称索引。 （＃383）

新功能

  • CodeGraph 现在索引 R (.R / .r) — 每种赋值形式的函数（name <- function(...)、name = function(...)、嵌套定义）、S4 / Reference / R6 类及其方法、setGeneric/setMethod 泛型、顶级变量和常量、library() / require() 导入、source() 文件引用和调用边 —包括 tidyverse 管道链内的调用。统计和研究代码库获得完整的探索/影响/调用者界面。 (#828) (R)
  • 保存多个 git 存储库的工作空间现在作为一个整体进行索引。 在包含多个独立 git 存储库的目录的根目录运行 codegraph init — 包括常见的“超级存储库”布局，其中父存储库的 .gitignore 隐藏子存储库以保持 git status 安静 — 现在将每个嵌套项目索引到一个图表中，并尊重每个子存储库自己的 .gitignore。 codegraph sync 和实时文件监视也会获取嵌套存储库内的更改（以前的更改检测仅参考父存储库，因此子存储库中的编辑在完全重新索引之前是不可见的）。 node_modules（npm git-dependencies）内的 Git 存储库仍被排除。 (#514)
  • codegraph_explore 现在解释流程在哪里结束而不是保持沉默。 当您询问的符号不是静态连接时（因为代码通过计算调用 (handlers[action.type](...))、Python 的 getattr、命令/中介总线 (sender.Send(new DeleteCommand(...)))、反射或 new Proxy 等运行时机制进行调度），探索现在会宣布确切的调度站点（文件和行），其中静态路径停止，当调度键在源中可见时，它会列出可能的运行时目标（例如将 MediatR 命令直接指向其 Handler.Handle 方法）。检测是确定性的，仅在流无法连接时运行；完全连接的流没有变化，索引或图本身没有任何变化。相关地，其发射和处理程序通过单个合成跃点连接的自定义事件总线现在显式地显示该跃点（通过注册站点）——它之前没有呈现任何内容，因为连接对于流程部分来说“太短”。 （#687）
  • 匿名使用情况遥测，逐个字段进行记录，并且易于关闭。 CodeGraph 现在收集一小组匿名使用情况统计信息 - 使用了哪些命令和 MCP 工具、对哪些语言进行了索引、连接了哪些代理 - 因此语言和代理支持工作会在实际使用情况下进行。绝不是任何代码、文件路径、文件或符号名称、搜索查询或 IP 地址；在发送任何内容之前，使用情况会在本地聚合到每日总数中，并且摄取端点是存储库中公共的、可审核的代码，该代码强制执行记录的字段列表。安装程序会通过可见的默认打开开关预先询问（并且不会再次询问）；在其他地方，在第一次发送之前会打印一行通知。使用 codegraph telemetry off、CODEGRAPH_TELEMETRY=0 或交叉工具 DO_NOT_TRACK=1 标准随时禁用 — off 表示关闭：不记录任何内容，不发送任何内容，并删除缓冲数据。 TELEMETRY.md 记录每个领域。
  • 子代理和非 MCP 代理现在可以访问 CodeGraph。 两个新的 CLI 命令 — codegraph explore "<symbols or question>" 和 codegraph node <symbol-or-file> — 准确打印匹配的 MCP 工具返回的内容（相关符号的源 + 调用路径；一个符号的源 + 调用者；使用行号读取文件），因此任何具有 shell 的代理都可以使用该图。 codegraph install 现在将一个小的标记围栏 CodeGraph 部分写入每个代理的指令文件 (CLAUDE.md / AGENTS.md / GEMINI.md) 中，指向两个表面 - 该文件是任务工具子代理实际看到的内容，其中 MCP 服务器自己的指导仅到达主代理。在委托代码探索任务上进行测量：子代理从几乎从不使用 CodeGraph（9 次运行中大约有 1 次）到每次运行都使用它，包括零 grep/文件读取回退的运行。该部分很小，可以保留您自己的内容，从旧的长块中干净地升级，并且 codegraph uninstall 将其删除。谢谢@liuyao37511。 （#704）
  • MCP 工具列表现在集中默认为四个 — codegraph_explore、codegraph_node、codegraph_search 和 codegraph_callers。其他四个（codegraph_callees、codegraph_impact、codegraph_files、codegraph_status）保持完整功能 - CLI 和库 API 保持不变，CODEGRAPH_MCP_TOOLS 重新启用其中任何一个 - 但默认情况下它们不再列出给代理：测量的代理行为显示它们从未或很少被选中，并且它们携带的信息已经内联到达工具代理上请使用（探索的爆炸半径部分、节点的从属注释、符号自己的主体作为其被调用者列表）。更精简的列表会保存每个会话的上下文标记，并仅通过存在即可引导代理使用正确的工具。
  • CodeGraph 现在在未索引的项目中变得安静，而不是大声失败。 当 AI 代理的会话在没有 CodeGraph 索引的工作区中启动时，MCP 服务器现在会通过一条简短说明宣布自己处于非活动状态，并且根本不列出任何工具 - 而不是在每次调用时显示完整的工具集和错误，这教会代理即使在工作的地方也要 distrust CodeGraph。查询另一个未索引的项目同样会返回明确的指导（使用该代码库的常规工具；用户可以在那里运行 codegraph init 来启用 CodeGraph）而不是错误，并且真正的内部错误现在会告诉代理重试一次而不是完全放弃 CodeGraph。索引保留由您决定——代理被告知不要自行运行。 (#769)
  • Astro 项目现已编入索引。 .astro 文件以前根本没有被解析 - 在典型的 Astro 站点上，大部分代码库对于搜索、影响和 codegraph_explore 都是不可见的。 CodeGraph 现在提取 TypeScript frontmatter（函数、导入、getStaticPaths 等）和 client 端 <script> 块，捕获模板标记中的函数调用和 <Component> 用法，以便跨组件依赖性跟踪端到端，解析 Astro 全局和 astro:* 模块导入为框架提供的，并映射src/pages/ 基于文件的路由到路由节点（.astro 页面和 .ts 端点，包括 [param] 和 [...rest] 动态段，正确排除以下划线前缀的文件）。在两个真实的 Astro 站点上进行了验证，测量的跨文件覆盖率为 93%，并且每个页面都映射到其路线。谢谢@xingwangzhe。 （#768）（天文）
  • monorepo 应用程序中的同名符号不再合并。在每个应用程序一个 UserService 的 NestJS 风格工作区中，codegraph_callers、codegraph_callees 和 codegraph_impact 现在报告 每个不同定义一个部分 - 每个应用程序的调用者和爆炸半径在其自己的文件标签标题下 - 而不是单个合并列表，并接受 file 参数以准确地集中您的意思的定义（就像 codegraph_node 已经做的那样）。特别是，影响不再通过合并不相关的同名类来夸大变更的爆炸半径。谢谢@Igorgro。 （#764）
  • 修复了跨包错误边缘的相关来源：PascalCase 来自普通 .ts 文件的类型引用被解析为 React 组件，这可以将文件自己的类型别名链接到另一个包中的任意同名类（在一个大型 monorepo 上，这产生了一千多个错误的跨包引用边缘；96% 现在已经消失了，其余的是真正的共享模型导入）。组件解析现在仅适用于来自支持 JSX 的文件的引用，并且在没有位置信号的情况下不会在多个候选之间进行猜测。 Svelte 和 Vue 组件解析器具有相同的任意选择缺陷（Vue 解析了树中任何位置找到的第一个同名 .vue 文件），现在遵循相同的规则：相同目录优先，否则仅解析明确的名称。重新索引项目以受益。 (#764)（TypeScript、React、Svelte、Vue）
  • TypeScript 和 JavaScript 类字段现在报告为属性而不是方法。像 public fonts: Fonts; 这样的普通字段之前被提取为方法，错误地表示了类形状，并让对同名函数的调用解析为数据字段（名为 isArray 的布尔字段吸收了 Array.isArray(...) 调用边缘）。包含箭头函数或函数表达式（onClick = () => {…}，包括像 onScroll = throttle(() => {…}) 这样的包装字段）的字段正确地保留了方法，并且仍然分析它们的主体。字段初始值设定项也被分析，因此 history = createHistory() 记录了它的调用，而之前根本不生成任何符号的 JavaScript 类字段现在出现在图中。重新索引项目以受益。 (#808) (TypeScript, JavaScript)
  • 通过 this 的回调注册现在可以在 TypeScript 和 JavaScript 中精确解析：window.addEventListener("online", this.onOfflineStatusToggle) 或 API 对象（如 { mutateElement: this.mutateElement }）生成 封闭类自己的方法 的引用边缘 - 绝不是不相关类上的同名方法，也绝不是数据字段。基于下面的回调注册支持。 (#808) (TypeScript, JavaScript)
  • 回调注册覆盖范围在另外四种形状中加深：this.<member> 注册，其方法位于基类上，现在通过继承链进行解析（子类中的 bus.on("submit", this.handleSubmit) 链接到父类的 handleSubmit）； Java 和 Kotlin 对其他类的方法引用（Handlers::onMessage、OtherClass::handle）跨文件解析，其中 this:: 和 super:: 的作用域为定义类，并通过故意省略的变量进行引用； Swift 裸回调名称现在仅匹配封闭类型的方法（隐式 self），从而消除了一类错误边缘，其中 request 等参数链接到不相关类型上的同名方法。 （Java、Kotlin、斯威夫特、TypeScript、JavaScript）
  • PHP 字符串和数组可调用现在注册：传递给可调用核心函数（usort($items, 'cmp_items')、array_map('absint', …)、call_user_func、spl_autoload_register等）的字符串链接到该函数（包括跨文件），并且数组形式 [$this, 'method'] 和 [Foo::class, 'method'] 链接到命名方法（$this 形式通过类及其父级解析）。传递给任意函数的字符串会被故意忽略：只有已知的可调用位置才是 trusted。在 WordPress 核心上进行验证（+556 个边缘，每个采样边缘都是真实注册）。 （PHP）
  • Ruby 生命周期挂钩符号现在注册：before_action :authenticate、after_save :reindex、around_create、validate :check、rescue_from(…, with: :handler) 和朋友将符号链接到它命名的方法 - 在类本身上或从父级继承（控制器中的 before_action :authenticate 解析为 ApplicationController 的方法）。 validates（复数）被排除在外，因为它的符号名称为属性，而不是方法。在导轨/导轨上进行验证（+385 个边缘，每个采样边缘都是真实的）。 （红宝石）
  • 对需要无需导入的类型的方法引用现在可以解析：Java/Kotlin 同包引用 (.concatMapMaybe(Maybe::just, …))、Kotlin 伴生对象成员 (KtHandlers::handle) 和跨文件 C++ 成员指针 (&TestSuite::RunSetUpTestSuite)。解析保持锚定到命名类型，因此不同类上的同名成员永远不会匹配。 （Java、Kotlin、C++）
  • CodeGraph 现在可以看到函数注册为回调的位置，而不仅仅是调用它的位置。作为参数传递的函数名称（signal(SIGINT, handler)、qsort(…, compare)、addEventListener(…, onBlur)）、分配给函数指针或字段（ops->recv_cb = my_cb、OnClick := Handler）、或放置在结构初始值设定项或处理程序表（{ .recv_cb = my_cb }、{ "get", getCommand }）中的函数名称现在会生成从注册站点到函数的引用边缘 - 因此 codegraph_callers 和codegraph_impact 表面回调接线以前看起来像死代码。适用于所有受支持的语言，包括特定于语言的形式：C/C++ &fn、Java Class::method、Kotlin ::fn、Swift #selector、Objective-C @selector、Ruby method(:fn)、Scala eta-expansion 以及 Delphi/Pascal @Handler 和 OnClick := Handler 事件接线。调用者输出将这些标记为“通过回调注册”。决议是故意保守的：一个模棱两可的名字不会产生任何优势，而不是一个错误的名字。重新索引项目以受益。谢谢@zmcrazy。 (#756)
  • codegraph_node MCP 工具现在可以像内置读取工具一样读取整个源文件 - 只是速度更快，从索引提供服务。传递一个不带符号的文件路径，它会返回带有行号的文件的当前源（与 Read 生成的相同 <n>⇥<line> 形状，因此助手可以直接从中进行编辑），可以像 Read 一样使用 offset/limit 缩小范围，再加上一行注释，说明哪些文件依赖于它（文件的爆炸半径）。在任何需要读取索引源文件的地方都可以使用它。传递 symbolsOnly: true 仅用于文件结构。配置/数据文件（.yml / .properties）仅通过密钥进行汇总，从不转储，因此其中的秘密永远不会浮出水面。面向代理的指导也进行了重新调整，因此助理可以在“实施”更改时获取代码图（不仅是在回答问题时），因为一个代码图调用返回相同的字节加上爆炸半径，比重新读取文件更快。
  • 新的 codegraph upgrade 命令将 CodeGraph 更新到最新版本 - 它会检测您的安装方式（独立的 install.sh / install.ps1 捆绑包、npm 或 npx），并在 macOS、Linux 和 Windows 上为每个命令执行正确的操作。使用 codegraph upgrade --check 查看更新是否可用而无需安装，或使用 codegraph upgrade <version> 移动到特定版本。升级后，它会提醒您重新索引项目，以便它们获得新引擎的改进。 （#679）
  • 当项目的索引是由比您正在运行的引擎更旧的引擎构建时，codegraph status 现在会进行标记，并建议重新索引（也在 codegraph status --json 中出现），以便您知道 codegraph index -f 或 codegraph sync 何时会添加引入的新版本的覆盖范围。
  • 跨文件影响和爆炸半径覆盖范围现在涵盖所有 22 种受支持的语言和 14 个 Web 框架，每个框架都在真实世界的存储库上进行了验证 - 请参阅自述文件中的新覆盖范围表。此版本提供了其背后的跨文件解析，包括 Lua 和 Luau require、Shopify OS 2.0 Liquid 部分模板、Delphi 表单代码隐藏、Rust 跨模块调用和 Rocket 路由宏、Swift Fluent 关系以及 SvelteKit / Nuxt / Vapor / Axum 路由约定。无处不在的残余物是真正的静态分析前沿（运行时调度、反射/DI、框架约定入口点），从不隐藏。
  • C# record struct 和 readonly record struct 声明现在使用正确的 struct 类型进行索引，并且位置单行记录 (public record struct Money(decimal Amount);) 在每种形式中都可靠地进行索引 - 以前可以完全跳过无实体值类型记录，并且可以停止提取同一文件中其后面的声明。 (#831) (C#)
  • C# 类型现在通过其命名空间限定名称进行跟踪。不同命名空间中的同名类型（例如，域实体和 DTO 都称为 CatalogBrand）会被分开，而不是分解为任意匹配，因此引用会解析为正确的引用，并且影响不再将它们混为一谈。 (C#)
  • ASP.NET Razor (.cshtml) 和 Blazor (.razor) 标记现在可以解析代码关系。 @model / @inherits / @inject 指令将视图链接到 C# 视图模型、基本类型或它命名的服务； Blazor <MyComponent/> 标记（加上 @typeof(...) 和通用 TItem="..." 参数）链接到组件类；并且还分析了@code { } / @functions { } / @{ }块内的C#，因此链接了组件逻辑中使用的服务和类型。仅从标记引用的视图模型、组件或服务不再被报告为没有依赖项，并且编辑它会显示使用它的视图。 （ASP.NET、Blazor）
  • Razor/Blazor 类型引用现在通过组件的 @using 命名空间（包括文件夹的级联 _Imports.razor）进行解析，因此存在于多个命名空间中的简单名称会出现在正确的命名空间中。对 CatalogBrand 的 @model / <MyComponent> / @code 引用解析为 @using’d DTO (BlazorShared.Models.CatalogBrand)，而不是同名的域实体。 （ASP.NET、Blazor）
  • codegraph status --json 现在还报告正在运行的 CLI version、索引目录 (indexPath) 和 lastIndexed 时间戳（ISO-8601，或尚未索引任何内容时为 null），因此 CI 和脚本可以固定 CLI 版本并通过单个命令检查索引新鲜度。匹配的 CodeGraph.getLastIndexedAt() 库方法公开了相同的新鲜度检查，而无需剔除。感谢@12122J 和@eddieran。 （＃329）
  • TypeScript 服务/RPC 合约定义为通用类型的元组 - type MyServiceList = [Service<'query_apply_record', …>, Service<'apply_confirm', …>] - 现在将每个条目的字符串文字名称索引为可搜索符号。以前，这些名称仅作为类型参数存在，因此即使这些名称是应用程序的主要 API 表面，codegraph query query_apply_record 也找不到任何内容。该模式在类型化 RPC/BFF clients 和模拟服务器中很常见，其中类型是运行时代理对象的真实来源。公用事业类型（Pick、Omit、Record）和路线路径被故意省略以避免噪音。谢谢@jiezhiyong。 (#634) (TypeScript)
  • 新的 CODEGRAPH_DIR 环境变量设置每个项目的索引目录名称（默认 .codegraph）。这可以让一个工作树保存两个独立的索引 - 当您从 Windows 和 WSL 打开相同的结帐时最有用，它们无法安全地共享单个 .codegraph/：后台服务器锁和 SQLite 数据库与编写它们的操作系统绑定，并且跨 WSL2/Windows 文件系统边界的 SQLite 锁定是不可靠的。在 Windows 端设置 CODEGRAPH_DIR=.codegraph-win，将 WSL 保留为默认值，每个文件夹都将自己的索引保留在同一文件夹中，而不会破坏另一个文件夹。 CodeGraph 在索引和监视时也会跳过任何同级 .codegraph-* 目录，因此两个环境都不会覆盖另一个环境的数据。谢谢@rrtt2323。 （#636）

修复

  • Windows 上的 opencode 现在可以找到 CodeGraph。 安装程序将 opencode 的全局 MCP 条目写入 %APPDATA%\opencode\，但 opencode 在每个平台上从 ~/.config/opencode/ 读取其配置（尊重 XDG_CONFIG_HOME），因此该条目对其不可见。现在安装在 opencode 实际看起来的位置写入，并且 codegraph install / codegraph uninstall 都从旧的 %APPDATA% 位置中清除陈旧的 CodeGraph 条目 - 该文件中的其他服务器和注释保持不变。感谢@fucknoobhanzo 的报告和@WodenJay 的第一个补丁。 (#535)

  • 重命名的默认导入（import articlesController from './article.controller'，其中模块执行 export default router）现在记录对导入模块的依赖关系。以前仅链接命名导入，因此仅通过默认导入（标准 Express/NestJS 路由控制器模式）使用的模块看起来没有任何依赖于它。外部封装（import React from 'react'）仍然没有优势。 (TypeScript/JavaScript)
  • 后台文件观察器不再耗尽机器的文件描述符预算。在 macOS 上，它之前保留每个监视文件一个打开的文件句柄，因此在一个大型项目中，运行的 MCP 服务器可能会堆积数以万计的句柄并超出系统范围的限制 - 此时不相关的应用程序（您的 shell、编辑器、Docker、浏览器）开始失败，并出现“打开文件过多”，直到代码图进程被终止。监视程序现在在 macOS 和 Windows 上使用单个递归监视，并在 Linux 上使用有界的每个目录监视，因此无论项目有多大，其成本都保持不变。 （#644、#496、#555、#628、#579）
  • 对具有符号密集文件（单个文件中数以万计的函数或方法）的项目进行索引不再会耗尽内存。链接动态调用关系的步骤，用于一次将每个函数和方法加载到内存中，这可能会耗尽堆并在大型或生成的代码库上中止索引，并显示“JavaScript 堆内存不足”；它现在对它们进行流式传输，因此无论项目有多少个符号，内存都保持不变。 （#610）
  • 对非常大的存储库进行索引在第一次同步期间不再因“SQL 变量太多”错误而中止。 (#540)
  • 索引期间不再静默跳过目录下具有非 ASCII 名称（例如 CJK 字符）的文件。 (#541)
  • .codegraph/ 索引文件夹不再混乱 git status：它生成的忽略文件现在排除文件夹中除自身之外的所有内容，因此数据库、daemon.pid、套接字和日志不再显示为未跟踪的更改。 （＃492，＃484）
  • 由旧版本初始化的项目现在会自动修复：在此更改之前编写的 .codegraph/.gitignore（仅列出数据库、缓存和日志，因此让守护程序的 daemon.pid 得到提交）会在您下次运行任何 CodeGraph 命令时就地升级。您自己定制的 .gitignore 保持不变。 （#788）
  • SAP HANA .xsjs / .xsjslib 文件现在索引为 JavaScript。 (#556)
  • TypeScript .mts 和 .cts 模块文件现在已编制索引而不是被跳过。 (#366)
  • 将代码包装在匿名函数中的 JavaScript 模块（AMD/RequireJS、NetSuite SuiteScript、IIFE 捆绑包）现在对其内部函数和调用进行了索引，而不是几乎空的文件。 (#528)
  • 在泛型类型（例如 func (s *Stack[T]) Push(...)）上声明的 Go 方法现在已正确附加到其类型，因此调用者、被调用者和影响包括它们。 (#583)
  • Go 方法现在附加到它们的接收器类型，即使在与 type 本身不同的文件中声明时也是如此 - 这是惯用的分割，其中 type User struct{…} 位于一个文件中，而 func (u *User) Save() 位于另一个文件中。以前，跨文件方法从其结构中被孤立，因此类型的成员列表、调用者/被调用者和影响错过了它；作为连锁反应，其接口满足方法分布在文件中的结构现在也链接到它实现的接口。 (#583)
  • 询问符号影响什么，不再拖累其类的每个不相关的同级方法 - 影响现在遵循真正的依赖关系，而不是结构“包含”关系，使结果集中于实际依赖于符号的内容。 (#536)
  • CodeGraph 的 MCP 服务器现在使用空列表而不是错误来应答代理的 resources/list 和 prompts/list 探测，并清除登录连接的某些 clients（opencode、Codex）的 -32601 消息。 （#621）
  • 通过桶文件使用的 Svelte 和 Vue 组件（从 index.ts 重新导出 export { default as Button } from './Button.svelte' 并在其他地方导入）不再被错误地报告为具有 0 个调用者。 CodeGraph 现在遵循默认的重新导出一直到组件，并解析 .svelte / .vue 文件本身使用的导入，因此 codegraph_callers 和 codegraph_impact 可以看到使用组件的每个位置。这还涵盖从工作区/monorepo (@scope/ui/widgets) 中的另一个包导入的组件和裸目录导入 (import { x } from './')。以前，仅通过桶消耗的活动组件看起来就像死代码。谢谢@nakisen。 （#629）
  • Vue 单文件组件的 <template>（<MyButton /> 或 kebab-case <my-button />）中使用的组件现在被索引为用法，因此 codegraph_callers 和 codegraph_impact 包含仅出现在另一个组件的标记中的组件（包括通过桶重新导出）。以前仅分析了 Vue 组件的 <script> 块，因此仅模板用法是不可见的。 （#629）
  • PHP：静态路径的 include / require / include_once / require_once 现在创建文件→文件依赖边缘，因此 codegraph_callers 和 codegraph_impact 遵循包含在程序/脚本样式 PHP 代码库中 - 以前只有命名空间 use 语句成为依赖边缘。动态包含（include $var、require __DIR__ . '/x'）将被跳过。感谢@atahan150 (#660)。
