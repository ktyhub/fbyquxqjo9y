变更流程图

亮点

  • 新 API：JsonObject.isEmpty() — PR #2233 给 JsonObject 加了 isEmpty() 方法，这是本版严格来说属于 minor 而非 patch 的唯一原因。纯增量，无需迁移；以前写 jsonObject.size() == 0 的调用方可以简化，只支持 2.10.0 的人则用不了。想要这个便捷方法，这就是主要的功能性升级理由。
  • 循环类型适配器创建的线程安全修复 — PR #1832 修复了为存在循环依赖的类型创建适配器时不具备线程安全的问题。如果你的模型有递归/自引用类型，且适配器首次在并发下创建（例如多线程里懒初始化 Gson），这消除了一处真实的竞态；对其他人无感。
  • 行为变更：JsonStreamParser.next() 与 EOFException — PR #2281 移除了 JsonStreamParser.next() 里对 EOFException 的特殊处理。这是唯一可能暗藏迁移风险的一项：显式捕获过、或依赖流结束时旧 EOFException 行为的代码，要按新契约重新核对，尽管签名没变。
  • 重复字段的诊断更友好 — PR #2251 改进了遇到重复字段名时的异常信息；PR #2243 修正了 JsonDeserializer.deserialize() 的 javadoc。两者都不改行为，但让排查畸形输入/反序列化问题更容易——是个小的体验提升。
  • 其余都是构建/测试/文档——低风险升级 — 剩下的改动是依赖升级（jackson-databind 2.14.1、os-maven-plugin 1.7.1、maven-release-plugin 3.0.0-M7、japicmp-maven-plugin 0.17.1、bnd-maven-plugin 6.4.0）、文档（新的排障指南）、GitHub workflow 加固，以及内部清理/测试迁移（JUnit 3→4）。都属于构建或测试范围，不涉及运行时行为。结论：想要 isEmpty() 或并发/EOF 修复的人可以放心升；没有循环类型、也不依赖 EOFException 语义的团队跳过也没影响。没有明确的破坏性变更或必须执行的迁移步骤。

从技术上讲，这是一个次要版本而不是补丁版本，因为有一个小的 API 更改：一种新的 JsonObject.isEmpty() 方法。
