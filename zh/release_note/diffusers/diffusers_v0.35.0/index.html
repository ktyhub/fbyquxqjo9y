diffusers v0.35.0

小版本 发布时间2025年8月19日 来源huggingface/diffusers 英文原文

变更架构图

亮点

  • 新管道 — 新增 Wan 2.2、Flux-Kontext、Qwen-Image 和 Qwen-Image-Edit，以及 DreamBooth 风格的 Kontext 和 Qwen-Image 训练脚本。想要基于指令的图像编辑、更强的视频保真度或 Apache-2.0 图像生成就值得升级；已有管道用户如果不需要这些能力可以跳过。

  • 性能与加载 — 区域 torch.compile 报告编译时间降低 8–10 倍，运行时加速相当。DiffusionPipeline.from_pretrained(..., device_map="cuda") 可直接加载到加速器上，HF_ENABLE_PARALLEL_LOADING=yes 可加速分片 checkpoint——对 Wan 和 Qwen-Image 尤其有用。这是大模型工作负载最明确的升级理由。

  • GGUF 支持 — 新增原生 GGUF CUDA kernel，推理约快 10%；支持 Diffusers 格式的 GGUF checkpoint 加载，并提供 checkpoint 转换工具。使用 GGUF 量化的用户应升级；其他用户可以跳过此特性。

  • 注意力重构 — 引入后端调度器，支持 PyTorch scaled_dot_product_attention、Flash Attention 3 和 SAGE attention。官方称对用户无影响，因此无需迁移；不支持的后端配置现在会抛出运行时错误，而不再只是记录告警。

  • 实验性与维护性改动 — Modular Diffusers 允许用可自由组合的块拼装自定义管道，但其 API 仍在快速演进，不适合作为稳定的集成目标。单文件模型实现属于内部可维护性改动。提交列表还显示 BLIP ControlNet 已弃用，但截断的说明没有指出替代方案或迁移路径；受影响的用户应在升级前核实。

本版本包含全新的图像生成与编辑管道、新的视频管道、新的训练脚本、使用体验改进等等。请完整阅读发布说明的其余部分，别错过有趣的内容。

此版本包含新的图像生成和编辑管道、新的视频管道、新的培训脚本、生活质量改进等等。完整阅读 release note 的其余部分，以免错过有趣的内容。

单文件建模实现

遵循 🤗 Transformers 的单文件建模实现哲学，我们已经开始在单个独立文件中实现建模代码。磁通变压器代码 就是其中之一。

注意力重构

我们大规模重构了模型中的注意力处理方式。这使得我们能够在库中无缝地提供对不同注意力后端（例如 PyTorch 原生 scaled_dot_product_attention、Flash Attention 3、SAGE Attention 等）的支持。 以这种方式支持注意力还允许我们集成不同的并行化机制，我们正在积极致力于这一点。如果您有兴趣，请关注此 PR。 用户根本不应该受到这些变化的影响。如果您遇到任何问题，请打开问题。

区域编译

区域编译通过仅编译模型的小且频繁重复的块（通常是转换器层）来缩短冷启动延迟，并允许在每次后续发生时重用已编译的工件。对于许多扩散架构来说，这提供了与全图编译相同的运行时加速，并将编译时间缩短了 8-10 倍。请参阅本文档 了解更多信息。 感谢 @anijain2305 在 此 PR 中贡献了此功能。 我们还撰写了许多围绕 torch.compile 的使用的帖子。您可以通过以下链接查看它们：

  • 快速呈现 Flux：让 Flux 在 H100 上表现出色
  • torch.compile 和 Diffusers：达到最佳性能的实践指南
  • 使用扩散器和 PEFT 进行通量的快速 LoRA 推理

更快的管道加载⚡️

用户现在可以直接在加速器设备上加载管道，从而显着缩短加载时间。当加载像 Wan 和 Qwen-Image 这样的大型管道时，这一点尤其明显。

from diffusers import DiffusionPipeline
import torch 

ckpt_id = "Qwen/Qwen-Image"
pipe = DiffusionPipeline.from_pretrained(
-    ckpt_id, torch_dtype=torch.bfloat16
- ).to("cuda")
+    ckpt_id, torch_dtype=torch.bfloat16, device_map="cuda"
+ )

您可以通过启用状态字典分片的并行加载来进一步加快加载速度。当您使用像 Wan 和 Qwen-Image 这样的大型模型时，这特别有用，其中模型状态字典通常分布在多个文件中。

import os
os.environ["HF_ENABLE_PARALLEL_LOADING"] = "yes"

# rest of the loading code

更好的 GGUF 集成

@Isotr0py 在 此 PR 中贡献了对本机 GGUF CUDA 内核的支持。这应该可以使推理速度提高大约 10%。 我们还开发了一个将常规检查点转换为 GGUF 的工具，让社区轻松共享他们的 GGUF 检查点。了解更多信息此处。 我们现在支持加载 Diffusers 格式 GGUF 检查点。 您可以在我们的GGUF 官方文档 中了解有关所有这些的更多信息。

模块化扩散器（实验）

模块化扩散器是一个用于使用单独**管道块构建扩散管道的系统。它是高度可定制的，具有可以混合和匹配的块，以适应特定工作流程或多个工作流程或为特定工作流程创建管道。
API 目前正在积极开发中，并将作为实验性功能发布。请参阅我们的文档 了解更多信息。
