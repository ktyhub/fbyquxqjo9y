diffusers v0.42.0

diffusers v0.42.0

这个项目是干啥的：Hugging Face 出品的扩散模型工具库，用它调用 Flux 等模型生成图片和音频，上手也快。给做 AI 绘画和多媒体生成的开发者用。

变更架构图

亮点

  • 破坏性变更与迁移 — 不再支持 Python 3.10：安装前请升级到 Python 3.11 或更新版本。huggingface_hub 必须满足 >=1.32.0,<3.0。自定义模块化 FLUX、Krea 2 和 LTX-Video 工作流现在应把核心去噪组的未打包 latent 传给解码块；打包 latent 的回退方式已弃用，并将在 0.47.0 中移除（#14737）。
  • 新图像模型 — FLUX.3 Image Klein 新增仅模块化的文生图和多参考图编辑，提供基础版/步数蒸馏版 checkpoint、集成的 prompt 上采样、单文件 transformer 加载以及 BFL FP8r/NVFP4 checkpoint；通过 ModularPipeline.from_pretrained(...) 加载后再 load_components(...)。Bria Fibo 2.0 新增 BriaFibo2Pipeline，支持结构化 JSON 的生成与编辑，最多 5 张参考图，并提供四步无 CFG 的 edit-turbo checkpoint 以及 LoRA 加载/训练。如果你在意这些模型或编辑工作流，请升级。
  • 视频、音频与生物分子扩展 — Kandinsky 6 通过 Kandinsky6TI2VAPipeline 和 Kandinsky6SRPipeline 新增音画同步生成与超分；SANA-WM 新增相机控制的图生视频，并可选 LTX-2 精修；AutoencoderKLKVAEAudio 新增 48 kHz 音频编解码；RFD4-Proteína 以靶点、基序或配体为条件联合生成蛋白质序列和全原子结构，由 rfd4-proteina-prep 负责输入与 CIF 准备。
  • 硬件、扩展与性能 — TorchTPU 支持 eager 执行、torch.compile 和张量并行；Intel XPU 新增张量并行；Qwen-Image 2.1 新增模块化管道和张量并行；MagCache 现支持 FLUX.2；LoKr 适配器可在 Z-Image 和 FLUX.2/Klein 上加载；LTX-2 新增 motion_speed，把运动节奏与播放帧率解耦，速度偏离默认值较大时建议搭配 LTX-2.5 慢动作 LoRA 等适配器。对相应硬件、适配器和性能路径来说，这些都是有意义的升级。
  • 正确性修复与升级结论 — 修复包括：从 joint_attention_kwargs 恢复 Z-Image 的 LoRA 缩放、把 Qwen-Image 的 .alpha 缩放应用到 lora_A/lora_B、改进文本编码器适配器检测、在 FlowMatchEulerDiscreteScheduler 中保留显式 timesteps、修复 Anima 的导出/独立去噪，以及在没有 mask 时恢复 InpaintProcessor.preprocess 的三值返回。低于 0.15 的 TorchAO 不再导致导入失败，但量化仍要求 0.15+。受影响路径的用户应升级；Python 3.11+ 且工作流未受影响的用户可以跳过。

[!TIP] 本版本把 FLUX.3 Image Klein、Bria Fibo 2.0、Kandinsky 6、SANA-WM 和 RFD4-Proteína 带入 Diffusers，同时带来新的适配器支持、硬件集成和模块化管道。 🚨 现在要求 Python 3.11 或更新版本。

[!提示] 此版本为 Diffusers 带来了 FLUX.3 Image Klein、Bria Fibo 2.0、Kandinsky 6、SANA-WM 和 RFD4-Proteína，以及新的适配器支持、硬件集成和模块化管道。 🚨 现在需要 Python 3.11 或更新版本。

FLUX.3 图像克莱因

Black Forest Labs 的 FLUX.3 Image Klein 支持使用一张或多张参考图像进行文本到图像的生成和编辑。基本检查点和逐步蒸馏检查点都可以通过 ModularPipeline 获得，并带有集成的提示上采样器，可将简短的请求转换为详细的标题，并支持带有边界框的布局指令。该集成还包括单列变压器加载以及 BFL FP8r 和 NVFP4 检查点。

使用 ModularPipeline.from_pretrained(...) 加载管道，然后使用 load_components(...) 加载其重量。有关提示上采样、编辑和内存使用的示例和指南，请参阅 FLUX.3 文档。

布里亚·斐波 2.0

Bria Fibo 2.0 支持从结构化 JSON 字幕生成图像，并通过 BriaFibo2Pipeline 编辑最多五个参考图像。该集成包括开发检查点和编辑涡轮检查点，该检查点分四个步骤运行，无需无分类器指导。有关支持的提示格式，请参阅 Fibo 2.0 文档。

包含 LoRA 加载和 DreamBooth LoRA 培训示例，用于文本到图像和图像编辑。感谢 @muhammadali-afridi 的模型集成 (#14991)。

康定斯基 6

Kandinsky 6 通过 Kandinsky6TI2VAPipeline 从文本或参考图像生成带有同步音频的视频。单独的 Kandinsky6SRPipeline 提供视频超分辨率。该集成支持 Pro 和 Lite 生成检查点，包括蒸馏变体，并为蒸馏模型引入了 PiflowScheduler。有关检查点特定的设置和超分辨率要求，请参阅 Kandinsky 6 文档。感谢 @lefff 的模型集成 (#14949)。

SANA-WM

SANA-WM 根据起始图像、文本提示和摄像机轨迹生成视频。使用明确的姿势或 WASD/IJKL 动作字符串控制相机，然后可以选择使用单独的 LTX-2 优化器优化输出。有关两阶段工作流程，请参阅 SANA-WM 文档。

感谢 @lawrence-cj 的集成 (#13881)。

RFD4-Proteína

Baker 实验室和 NVIDIA 的 RFD4-Proteína 为扩散器带来了生物分子设计。它共同生成蛋白质序列和全原子结构，同时调节分子背景，例如结合靶标、基序或配体。集成包括管道、变压器、自动编码器、调度器和 LoRA 加载。准备模型输入和编写 CIF 文件使用单独的 rfd4-proteina-prep 包；请参阅 RFD4-Proteína 文档。

感谢 @kierandidi 的集成 (#15088)。

其他亮点

  • Qwen-Image 2.1： 新的模块化管道和张量并行支持。 （[#14976]（https://github.com/huggingface/diffusers/pull/14976），[#14865]（https://github.com/huggingface/diffusers/pull/14865））
  • 更多硬件支持： TorchTPU 集成涵盖急切执行、torch.compile 和张量并行性。张量并行性也获得了 Intel XPU 的支持。 （[#14039]（https://github.com/huggingface/diffusers/pull/14039），[#15013]（https://github.com/huggingface/diffusers/pull/15013））
  • LoKr 适配器： 加载适用于 Z-Image 和 FLUX.2 的 LyCORIS Kronecker 产品适配器，包括 Klein。 (#14163)
  • LTX-2 运动控制： motion_speed 独立于播放帧速率控制位置时基。使用兼容适配器来获得远离默认速度的速度，例如 LTX-2.5 慢动作控制 LoRA。 (#14967)
  • KVAE-Audio： AutoencoderKLKVAEAudio 添加了 48 kHz 音频的编码和解码。 (#14384)
  • 缓存： MagCache 现在支持 FLUX.2。 (#14756)
  • 适配器修复： Z-Image 遵循 joint_attention_kwargs 中的 LoRA 比例，Qwen-Image 将 .alpha 比例应用于 lora_A/lora_B 检查点，并且文本编码器正确报告活动适配器。 (#15015、#15016、#14961)
  • 管道修复： 在 FlowMatchEulerDiscreteScheduler 中保留显式时间步，修复 Anima 文本编码器导出和独立核心去噪，并在未提供掩码时保留从 InpaintProcessor.preprocess 的三值返回。 (#14956、#14943、#14481)

弃用和兼容性

  • Python 3.10 支持已删除。 在安装此版本之前升级到 Python 3.11 或更高版本。 (#15030)
  • 模块化潜在输出： FLUX、Krea 2 和 LTX-Video 现在在其核心降噪组中解包潜在内容。自定义工作流程应将解包的潜在变量传递到其解码块。在 0.47.0 中，不推荐删除打包潜在变量的后备。 (#14737)
  • 集线器兼容性： 支持的 huggingface_hub 系列现在是 >=1.32.0,<3.0。 (#14863)
  • TorchAO 导入： 安装早于 0.15 的 TorchAO 版本不再破坏模型导入。 TorchAO 量化仍然需要 0.15 或更高版本。 (#15095)
