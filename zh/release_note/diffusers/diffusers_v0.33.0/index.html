diffusers v0.33.0

小版本 发布时间2025年4月9日 来源huggingface/diffusers 英文原文

变更架构图

亮点

  • 新增视频与图像管道 — 新增 Wan 2.1 文生视频、图生视频和视频到视频支持；LTX Video 0.9.5 关键帧动画，以及通过 LTXConditionPipeline 和 LTXVideoCondition 实现续写；MLLM 条件驱动的 Hunyuan 图生视频；Sana-Sprint 的 1–4 步文生图；Apache 2.0 的 Lumina2 并支持 LoRA；OmniGen；以及 CogView4。这大幅扩展了可用模型和工作流。

  • 低显存推理选项 — 逐层 casting 把权重存为 torch.float8_e4m3fn 或 torch.float8_e5m2，并在前向传播时升精度，理论上可把权重显存降低约 50%。分组卸载在模型级和顺序卸载之间取得平衡，并可选 CUDA 流预取以提速；除非启用 low_cpu_mem_usage=True，use_stream=True 可能需要约 2 倍模型大小的 CPU 内存。新的 QuantoConfig 后端还支持 float8、int8、int4 和 int2 量化。

  • 更快的 DiT 推理，但要牺牲一点质量 — PyramidAttentionBroadcastConfig 和 FasterCacheConfig 可通过 transformer.enable_cache(config) 启用缓存，减少跨时间步的冗余去噪计算。为吞吐提升而升级，但要预期输出质量略有下降，并对照自己的质量要求做评估。

  • 实验性的远程 VAE 解码 — 首批端点支持 Stable Diffusion v1、Stable Diffusion XL、black-forest-labs/FLUX.1-schnell 和 HunyuanVideo。推理时本地生成 latent（output_type="latent" 且不设置 vae），再由 remote_decode 远程解码——以网络依赖和把推理数据发送到外部服务为代价，降低本地内存占用。

  • 升级建议与破坏性变更 — 这是一个内容可观的增量版本，不是重新打标或仅改元数据。所提供的更新日志未声明显式破坏性变更或强制迁移步骤；新支持模型、内存优化或缓存的用户应升级，对现有管道满意的用户可以安全跳过。

LTX 视频 0.9.5

LTX Video 0.9.5 是超高速 LTX Video 型号系列的更新版本。最新模型引入了额外的调节选项，例如基于关键帧的动画和视频扩展（向前和向后）。 为了支持这些额外的调节输入，我们引入了 LTXConditionPipeline 和 LTXVideoCondition 对象。 要了解有关用法的更多信息，请查看此处 的文档。

浑源图像转视频

Hunyuan 利用预训练的多模态大语言模型 (MLLM) 和仅解码器架构作为文本编码器。 输入图像由 MLLM 处理以生成语义图像标记。然后将这些标记与视频潜在标记连接起来，从而能够对组合数据进行全面的全注意力计算，并无缝集成来自图像及其相关标题的信息。 要了解更多信息，请查看此处 的文档。

新的内存优化

分层铸造

PyTorch 支持 torch.float8_e4m3fn 和 torch.float8_e5m2 作为权重存储 dtypes，但由于未实现的内核支持，它们无法用于许多设备上的计算。 但是，您仍然可以使用这些 dtypes 以 FP8 精度存储模型权重，并在前向传递中使用层时将其即时向上转换为广泛支持的数据类型，例如 torch.float16 或 torch.bfloat16。这称为分层权重铸造。这可能会将模型的 VRAM 需求降低 50%。   <详情> <摘要>代码</摘要>

import torch
from diffusers import CogVideoXPipeline, CogVideoXTransformer3DModel
from diffusers.utils import export_to_video

model_id = "THUDM/CogVideoX-5b"

# Load the model in bfloat16 and enable layerwise casting

> **这个项目是干啥的**：Hugging Face 出品的扩散模型工具库，用它调用 Flux 等模型生成图片和音频，上手也快。给做 AI 绘画和多媒体生成的开发者用。

transformer = CogVideoXTransformer3DModel.from_pretrained(model_id, subfolder="transformer", torch_dtype=torch.bfloat16)
transformer.enable_layerwise_casting(storage_dtype=torch.float8_e4m3fn, compute_dtype=torch.bfloat16)

# Load the pipeline
pipe = CogVideoXPipeline.from_pretrained(model_id, transformer=transformer, torch_dtype=torch.bfloat16)
pipe.to("cuda")

prompt = (
    "A panda, dressed in a small, red jacket and a tiny hat, sits on a wooden stool in a serene bamboo forest. "
    "The panda's fluffy paws strum a miniature acoustic guitar, producing soft, melodic tunes. Nearby, a few other "

    "casting a gentle glow on the scene. The panda's face is expressive, showing concentration and joy as it plays. "
    "The background includes a small, flowing stream and vibrant green foliage, enhancing the peaceful and magical "
    "atmosphere of this unique musical performance."
)
video = pipe(prompt=prompt, guidance_scale=6, num_inference_steps=50).frames[0]
export_to_video(video, "output.mp4", fps=8)

群组卸载

组卸载是顺序卸载和模型卸载之间的中间立场。它通过卸载内部层组（torch.nn.ModuleList 或 torch.nn.Sequential）来工作，这比模型级卸载使用更少的内存。它也比顺序级卸载更快，因为设备同步的数量减少了。 在 CUDA 设备上，我们还可以选择通过 CUDA Streams 启用层预取。当当前层正在执行时，要执行的下一层会加载到加速器设备上，这使得推理速度大大加快，同时仍然保持 VRAM 要求非常低。由此，我们引入了计算与数据传输重叠的想法。 需要注意的一件事是，使用 CUDA 流可能会导致 CPU RAM 使用量大幅增加。如果您选择设置use_stream=True，请确保可用CPU RAM是型号大小的2倍。您可以通过设置 low_cpu_mem_usage=True 来减少 CPU RAM 使用量。这应该限制所使用的 CPU RAM 与模型的大小大致相同，但会在推理过程中引入轻微的延迟。
您还可以在使用 use_stream=True 时使用 record_stream=True 来获得更多加速，但代价是稍微增加内存使用量。 <详情> <摘要>代码</摘要>

import torch
from diffusers import CogVideoXPipeline
from diffusers.utils import export_to_video

# Load the pipeline
onload_device = torch.device("cuda")
offload_device = torch.device("cpu")
pipe = CogVideoXPipeline.from_pretrained("THUDM/CogVideoX-5b", torch_dtype=torch.bfloat16)

# We can utilize the enable_group_offload method for Diffusers model implementations
pipe.transformer.enable_group_offload(
	onload_device=onload_device, 
	offload_device=offload_device, 
	offload_type="leaf_level", 
	use_stream=True
)

prompt = (
    "A panda, dressed in a small, red jacket and a tiny hat, sits on a wooden stool in a serene bamboo forest. "
    "The panda's fluffy paws strum a miniature acoustic guitar, producing soft, melodic tunes. Nearby, a few other "
    "pandas gather, watching curiously and some clapping in rhythm. Sunlight filters through the tall bamboo, "
    "casting a gentle glow on the scene. The panda's face is expressive, showing concentration and joy as it plays. "
    "The background includes a small, flowing stream and vibrant green foliage, enhancing the peaceful and magical "
    "atmosphere of this unique musical performance."
)
video = pipe(prompt=prompt, guidance_scale=6, num_inference_steps=50).frames[0]
# This utilized about 14.79 GB. It can be further reduced by using tiling and using leaf_level offloading throughout the pipeline.
print(f"Max memory reserved: {torch.cuda.max_memory_allocated() / 1024**3:.2f} GB")
export_to_video(video, "output.mp4", fps=8)

引入 DiT 的缓存推理

Diffusion Transformer 模型的缓存推理是一种性能优化，可通过缓存中间值显着加速去噪过程。该技术减少了跨时间步长的冗余计算，从而加快了生成速度，但输出质量略有下降。 查看文档 以了解有关可用缓存方法的更多信息。 金字塔关注广播 <详情> <摘要>代码</摘要>

import torch
from diffusers import CogVideoXPipeline, PyramidAttentionBroadcastConfig

pipe = CogVideoXPipeline.from_pretrained("THUDM/CogVideoX-5b", torch_dtype=torch.bfloat16)
pipe.to("cuda")

config = PyramidAttentionBroadcastConfig(
    spatial_attention_block_skip_range=2,
    spatial_attention_timestep_skip_range=(100, 800),
    current_timestep_callback=lambda: pipe.current_timestep,
)
pipe.transformer.enable_cache(config)

改进了 uintx TorchAO 检查点与 torch>=2.6 的加载

TorchAO 检查点当前必须使用 pickle 进行序列化。对于某些使用 uintx 格式的量化数据类型（例如 uint4wo），这涉及在模型文件中保存子类 TorchAO Tensor 对象。这使得直接使用 Diffusers 加载模型有点棘手，因为我们不允许从 pickle 文件反序列化 artbitary Python 对象。
Torch 2.6 允许将预期的张量添加到 torch 安全全局变量中，这使我们可以直接使用这些对象加载 TorchAO 检查点。

- state_dict = torch.load("/path/to/flux_uint4wo/diffusion_pytorch_model.bin", weights_only=False, map_location="cpu")
- with init_empty_weights():
-     transformer = FluxTransformer2DModel.from_config("/path/to/flux_uint4wo/config.json")
- transformer.load_state_dict(state_dict, strict=True, assign=True)
+ transformer = FluxTransformer2DModel.from_pretrained("/path/to/flux_uint4wo/")
