qwen-code v0.27.2

修订 发布时间2026年11月10日 来源QwenLM/qwen-code 英文原文

qwen-code v0.27.2

亮点

  • Web Shell可以配置微信、QQ、Email通道，包括二维码登录、扫描进度、身份显示、退出（如果支持）。 (#16736、#16724、#16746)
  • Mod 可以运行一次性 $.model.complete 调用，通过 ui.render 重写显示的 AssistantMessage 文本，并使用 $.store 保留插件值。 (#16737、#16794、#16791)
  • /btw 附带问题会根据上下文重播，托管代理会通过手动或可选的自动会话回顾添加私人后续行动。 （[#16408]（https://github.com/QwenLM/qwen-code/pull/16408），[#16758]（https://github.com/QwenLM/qwen-code/pull/16758））
  • 待批准现在显示在实时面板中，并且当终端未聚焦时可以触发终端铃声或桌面通知。 （[#16800]（https://github.com/QwenLM/qwen-code/pull/16800），[#16809]（https://github.com/QwenLM/qwen-code/pull/16809））
  • Web Shell 显示合成器下的回合数、输出速度、总令牌和缓存命中率，以及悬停详细信息和令牌使用访问权限。 (#16815)
  • 用户可以从选定会话的原始运行时工作区导入技能并显式安装，而无需重新上传。 (#16638)

重大变更

  • 修复（deps）！：升级 SDK 和 Web Shell 附带的依赖项（#16452），作者：@yiliang114

  • Mod 现在可以使用 AssistantMessage 渲染站点和 ui.render 挂钩重写 Ink 终端中显示的模型回复文本，而无需更改存储或复制的文本。 （#16794）@qqqys

  • 托管代理渠道交付分类帐现在单独记录每个交付段，为多段交付保留段收据。 （#16797）@wenshao
  • 将 requireBoundWatch 添加到 GitHub 通道，以便仅在保持活动 /autofix-pr 或 /verify-pr 监视时检查或验证绑定接收 PR 事件。 (#16772) 作者：@wenshao
  • 添加微信作为可配置的 Web Shell 通道，具有浏览器内二维码登录、扫描进度、身份显示、注销和过期代码刷新功能。 (#16736) 作者：@wenshao
  • 添加QQ频道配置和可选的二维码登录管理流程，允许Web Shell通过扫描二维码绑定帐户。 (#16724) 作者：@wenshao
  • 将分段数组添加到公共频道传输资源，同时保持现有的单一分段字段兼容。 (#16807) 作者：@wenshao
  • 在 Web Shell 编辑器下显示回合数、输出速度、总令牌和缓存命中率，以及悬停详细信息和令牌使用面板访问。 （#16815）@qqqys

  • 让代理主机安全地重试丢失的注册或替换命令，以便它以现有主机完成，而不是失败或创建副本。 （#16722）@wenshao
  • 在入站任务记录到达评论传递之前拒绝格式错误的authorExclude 值，从而防止崩溃和无效的传递行为。 (#16740) 作者：@wenshao

  • 通过将 Ctrl+C 排除在聚焦 shell 之外、为托管代理测试分叉 40% 的计算机内存以及稳定租约续订检查来阻止分叉 PR CI 故障。 (#16150) 作者：@TianYuan1024
  • 修复了 shell 命令解析，以便自杀防护和文件权限检查正确处理 ANSI-C 转义和 -c 选项终止符。 （#16540）@yiliang114
  • 防止自动修复过时的基础更新重新启动超时的自动 PR 审查，从而避免重复审查和基础更新周期。 (#16749) 作者：@wenshao
  • 当图表渲染器失败但内联数据可读时，回退到数据表视图，而不是将图表显示为不可用。 (#16021) 作者：@zhangxy-zju
  • 文档导出渲染器大小预算提高到合并的包大小，修复了由于合并后 Web Shell 增加而导致的 npm run 构建失败。 （#16774）@yiliang114
  • 仅空闲斜杠命令（例如 /branch、/cd、/fork、/recap 和 /advisor）现在在从空闲 Ink TUI 会话分派时运行，而不是被应用程序范围的状态阻止。 （#16731）@qqqys
  • Web Shell 斜线菜单现在优先考虑命令和技能名称，首先截断描述，而完整的详细信息仍保留在悬停位置上。 （#16790）@callmeYe
  • 后台和工作流审批请求现在在未聚焦时触发终端响铃或桌面通知，尊重general.terminalBell和general.notificationMode。 （#16800）@qqqys
  • 当保存的订阅模型不可用时，CLI 现在会以静默方式打开 Composer，并推迟发送错误，显示网关响应。 (#16798) 作者：@liuxuely0626

  • HTTP 托管会话编写器重新获取现在会等待正在进行的密封，并避免在密封可能仍稳定时获取租约。 (#16726) 作者：@wenshao
  • 通过验证 Linux 上的进程启动令牌，防止陈旧会话在 PID 被回收时被报告为活动会话。 （#16128）@yiliang114
  • 允许通道配置字段声明包含下限，以便在验证和范围消息中正确接受零值。 （#16783）@wenshao

  • perf(memory)：删除捆绑的自动内存引用并保留驻留策略（#16739），作者：@qqqys
  • GitHub 通道的 PR 状态监视和通知列表现在使用条件请求并缓存未更改的响应，以避免在未更改的数据上花费配额。 (#16741) 作者：@wenshao
  • 通过减少 CSI 证明复制、优化 CSI 查找以及使用有上限的启动轮询退避来提高托管代理性能。 （#16828）@doudouOUC
  • 通过在不改变行为的情况下删除冗余的读取路径查询来提高托管代理的响应能力。 （#16827）@doudouOUC

文档

  • 文档：澄清从 tools.core 迁移时的工具桥要求（#16750），作者：@521Peter
  • 添加了双语设计建议，将 /loop 引入托管会话，涵盖时间表和唤醒，而无需更改生产行为。 (#16792) 作者：@wenshao
  • 文档（托管代理）：托管调度设计 - 循环审查修复和外部调度程序（[#16796]（https://github.com/QwenLM/qwen-code/pull/16796）），作者：@wenshao

内部变化

  • 重命名托管代理 JDBC 持久性实现，以将其与存储库接口区分开并简化导入。 （#16759）@doudouOUC
  • 跨连接器共享托管线束功能令牌，因此功能检查保持一致，而无需更改连接器行为。 （#16763）@doudouOUC
  • 将所有分片 CI 通道减少到两个分片，并将烟雾作业上限提高到 75 分钟，同时保留运行空间。 (#16764) 作者：@wenshao
  • 从托管会话日志测试中排除后台激活更新，以防止不相关的日志写入影响其字节偏移检查。 (#16756) 作者：@wenshao
  • 托管运行时工作线程 HTTP 路由现在源自单个路由计划，从而提高了路由门控和安装之间的一致性。 （#16788）@doudouOUC
  • 删除未使用的托管代理服务器构造函数和帮助程序，而不更改运行时行为。 （#16822）@doudouOUC
  • 将会话恢复重构为共享核心，以便进程内调用者无需 HTTP 即可恢复工作区会话。 (#16810) 作者：@wenshao
