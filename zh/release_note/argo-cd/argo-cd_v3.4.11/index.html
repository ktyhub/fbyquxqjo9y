argo-cd v3.4.11

这个项目是干啥的：一个给 Kubernetes 用的持续交付工具，把应用配置放在 Git 里，一改动就自动同步到集群，适合做 GitOps 的运维团队。

变更架构图

亮点

  • 插件失败后 repo-server 可恢复 — 失败的配置管理插件（CMP）运行不再遗留过期 manifest 或泄漏 goroutine，降低应用状态错误和资源压力累积的风险（#29870；3.4 回移 #30141）。
  • OCI 源更可靠 — OCI tag 列表现在会缓存以减少重复仓库请求，同时缓存清理与解压同步，避免干扰正在使用的内容。提升负载下 OCI 后端应用刷新的稳定性（#30118/#30121、#30023/#30104）。
  • hydrator 写回更有韧性 — notes 推送遇到 Git 瞬时 “cannot lock ref” 错误现在会重试而非立即失败，使 hydration 工作流更能容忍并发 Git 活动，且无需改配置（#28469；3.4 回移 #29904）。
  • 归档解压校验更安全 — untar 入站检查现在能正确处理符号链接目标路径，为处理第三方 Helm 或插件归档的运维保留解压包含性校验（#28881；回移 #30054）。
  • 工作流与 UI 正确性 — CronWorkflow 的 create-workflow action 现在输出预期的调度时间格式，减少格式相关调度错误。UI 也只对 Helm 源显示 enableOCI，去掉对其他仓库类型不适用的控件（#29916/#29954、#29974/#30080）。
  • 破坏性变更 — 无。

快速入门

非 HA：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.11/manifests/install.yaml

哈：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.11/manifests/ha/install.yaml
