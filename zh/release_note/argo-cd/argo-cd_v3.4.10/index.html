argo-cd v3.4.10

argo-cd v3.4.10

变更流程图

亮点

  • 安全优先补丁，立即升级 — v3.4.10 实质是紧急安全版本：PR #30039 落地一组协同修复，包括四个严重（CRITICAL）问题——Kustomize remote refs 和 Helm configHome 可在 repo-server 执行命令、Jsonnet imports 可读取 repo-server 任意文件、AppProject 限制可通过 PreDelete/PostDelete 钩子绕过（CVE-2026-77459）。另有高危（HIGH）的并发请求绕过登录频率限制（CVE-2025-61560）和 SSH repo-proxy 命令注入（CVE-2026-55797）。凡是可由多租户提交仓库或应用的 Argo CD，都应立即停下手头事升级；这里的威胁模型是不可信 manifest 抵达 repo-server，而不只是 API 表面。

  • 破坏性：helmGlobals.configHome 对 Kustomize 渲染的 Helm chart 不再生效 — Kustomize 构建渲染 Helm chart 时（GHSA-fw5c-w8rc-j7fx）不再遵循 helmGlobals.configHome。普通 http、https 和 oci chart 仓库仍可用，但依赖从该目录注册 Helm 插件的构建会失效。上线前审计所有依赖自定义 config home 或插件的 kustomize + Helm 配置。

  • 破坏性：OCI manifest 上限 4 MiB — 大于 4 MiB 的 manifest 现在直接拒绝（GHSA-w996-f2wq-x9c6），堵住 repo-server 内存耗尽向量。发布大型 OCI chart 或镜像包的团队应检查并瘦身 manifest，这是硬性功能截断而非警告。

  • 登录尝试现在记录用户名 — 新的服务端日志（#29860，cherry-pick 自 #29841）把失败或成功的鉴权与具体账号关联起来，与并发请求频率限制修复直接配套。有助于发现此前绕过频率限制而漏掉的撞库行为。

  • 较小的修复与依赖加固 — CMP .tgz 流的临时目录现在会清理（#29148 / #29775），避免繁忙 repo-server 的磁盘泄漏；manifest 查看器不再跳动（#29691 / #29726）。依赖升级包括 go-git/go-billy 5.9.0、golang.org/x/crypto 0.57.0 和 js-yaml 4.3.2——主要是承接上游安全补丁而非新特性。

快速入门

非 HA：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.10/manifests/install.yaml

哈：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.10/manifests/ha/install.yaml

Changelog

安全修复

  • 关键：Kustomize 远程引用可以在存储库服务器中运行命令 (GHSA-9v9p-x54c-58gc)
  • 关键：Kustomize Helm 配置主目录可以在存储库服务器中运行命令 (GHSA-fw5c-w8rc-j7fx)
  • 严重：Jsonnet 导入可以从存储库服务器读取文件 (GHSA-m3vr-7329-44ww)
  • 严重：PreDelete/PostDelete 资源挂钩绕过了 AppProject 限制（GHSA-fmxq-cgp8-87wp、CVE-2026-77459）
  • 高：可以通过并发请求绕过登录失败率限制（GHSA-4439-h7jw-5cjj、CVE-2025-61560）
  • 高：通过 SSH Git 存储库上的存储库代理 URL 进行命令注入（GHSA-j6cw-g6p4-7hch、CVE-2026-55797）
  • 中等：启用任何命名空间中的应用程序时，扩展代理 RBAC 会忽略应用程序命名空间 (GHSA-g3ff-q88g-chrj)
  • 中等：过大的 OCI 清单可能会耗尽存储库服务器内存 (GHSA-w996-f2wq-x9c6)

潜在的重大变化

  • 呈现 Helm 图表的 Kustomize 构建不再遵循 helmGlobals.configHome。普通的 http、https 和 oci 图表存储库仍然有效。依赖于从该目录注册的 Helm 插件的构建不会 (GHSA-fw5c-w8rc-j7fx)。
  • 大于 4 MiB 的 OCI 清单现已被拒绝 (GHSA-w996-f2wq-x9c6)。
