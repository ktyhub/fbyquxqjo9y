argo-cd v3.4.14

修订 发布时间2026年11月18日 来源argoproj/argo-cd 英文原文

变更流程图

亮点

  • AppProject 拒绝规则终于生效 — PR #30895（cherry-pick 自 #30884）修复取反的 !name / server 条目的目标否决逻辑：正向匹配拒绝模式的目标现在会被正确拒绝。对多租户控制面这是真正有爆炸半径的一条——此前被放行到你本想屏蔽的集群/命名空间的应用会开始同步失败，因此上线前审计每个项目的 spec.destinations。

  • 大规模部署下控制面内存更低 — PR #30810（cherry-pick #30833）让 gitops-engine 不再为每个集群保留解码后的 OpenAPI 文档。在集群众多的大型安装上，这去掉了一份随集群数增长的长驻内存开销，因此 apiserver/controller 的 RSS 应更平稳，集群频繁变动后残留更少。无需改配置。

  • 安全：regexp2 CVE 已修复 — dlclark/regexp2 升到 v2.13.0 修复 CVE-2026-77299（PR #31005 / #31026）。该正则引擎用于调谐侧匹配，此前精心构造的模式或输入可能演变成 controller 拒绝服务；即使你认为没走到受影响路径，也应按值得打补丁处理。

  • JWT/JOSE 栈加固 — go-jose/v4 4.1.4 → 4.1.6（PR #30918）。这是 token/签名校验背后的库，如果做联邦鉴权或在鉴权链中校验 JWT，保持更新很重要。低风险升级，但值得和 regexp2 修复一起发。

  • 工具链与依赖版本跟进 — Go 工具链升到 1.26.11（PR #30923），git-lfs 升到 3.8.1（PR #31051 / #31053）。主要与从源码构建 Argo CD 或调谐使用 Git LFS 的仓库相关；Go 升级可能让下游构建暴露标准库和构建镜像敏感的行为变化。

本版本无破坏性变更。

快速入门

非 HA：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.14/manifests/install.yaml

哈：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.14/manifests/ha/install.yaml
