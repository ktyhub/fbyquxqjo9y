argo-cd v3.5.6

argo-cd v3.5.6

变更流程图

亮点

  • 通过 SRV 记录实现 gRPC 负载均衡 — 恢复 gRPC 名称解析中 _grpclb._tcp SRV 查询的变通方案（#29989，回移为 #30084 / #30170）。若 API server 或 repo-server 通过基于 DNS 的 grpclb 而非静态服务地址寻址，SRV 查询失效会导致发现静默失败、CLI 和 repo-server 连接不稳——在自定义或拆分视野 DNS 环境中尤其如此。这些连接一直不稳的话，正是要验证的修复。
  • 经 SOCKS5 拉取 SSH 仓库 — 配置 SOCKS5 代理时拉取 SSH 后端 git 仓库被弄坏的回归已修复（#30238，回移 #30246）。通过 SOCKS5 出网的隔离网和防火墙受限环境，升级后应显式重测 SSH 仓库连接；HTTPS 仓库用户不受影响。注意这是回归修复，只有真正走到坏路径的环境才会看到行为变化。
  • 多 manager 场景下服务端 diff 更准确 — 被其他 field manager 删除的字段现在会报为 diff（#30206，回移 #30229）。对使用 server-side apply 且有多个 manager（Argo CD 与 operator 或 Helm 并存）的集群很重要：其他 manager 删字段造成的漂移现在会显现而非隐藏，漂移检测更好。升级后一些此前”干净”的应用会冒出新 diff——可能需要调 ignoreDifferences 来抑制有意的删除。
  • DOMPurify 安全升级 — UI 中渲染不可信内容用的 HTML 清理库已升级（#30176）。低可见度但事关安全：Argo CD 会在 web UI 展示仓库提供的元数据（应用描述、徽章、外链），保持清理库最新可堵住潜在 XSS 路径。若向用户暴露不可信 manifest 内容，值得做一次 UI 冒烟测试。
  • 低风险的 3.5.x 维护版本 — 所有改动都是从 main 回移的 cherry-pick（#30170、#30246、#30229）加 Go 工具链刷新到 v1.26.10（#30305）；没有 schema 或 API 变更。当作从 3.5.5 的直接替换升级——常规滚动升级和镜像/CLI 重新部署即可，镜像带 cosign 签名和 SLSA L3 溯源。重建所有绑定旧 Go 工具链的自定义镜像或插件。
  • 破坏性变更 — 本版本未报告。

快速入门

非 HA：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.6/manifests/install.yaml

哈：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.6/manifests/ha/install.yaml
