argo-cd v3.4.13

argo-cd v3.4.13

变更流程图

亮点

  • 同步生命周期可靠性 — 被同步窗口阻塞的操作现在可以终止（#30502），Job 也能干净退出，而不必等待被取消的 Git 子进程（#30408）。#30659 还在存活对象从调谐缓存消失时移除钩子 finalizer，避免钩子清理卡住。
  • 自定义资源健康检查更准确 — Crossplane、Config Connector 和 SealedSecret 处理现在识别 provider conditions、把非活跃托管资源定义视为健康、适用时使用 status.healthy，并等待当前 SealedSecret generation 再报告健康（#30625、#30424、#30654、#30353），减少误导性健康状态和过早的同步决策。
  • ApplicationSet 安全性与 GitLab MR 发现 — 保留的集群注解不再作为 generator 参数暴露（#30479），防止内部元数据被意外覆盖。GitLab pull-request generator 配置项目路径时现在能正确刷新（#30621）。
  • 受限环境下的 CLI 连通性修复 — gRPC-web 连接现在遵循 HTTP_PROXY、HTTPS_PROXY 和 NO_PROXY（#30499），刷新过期鉴权 token 时保留 --header 值（#30547）。避免代理和自定义鉴权中间件后的 CLI 会话失败。
  • 未鉴权健康端点与调谐竞态修复 — 服务端允许未鉴权的 gRPC 健康检查（#30569），恢复标准探针兼容性。GitOps engine 还修复空 UID 回填竞态（#30526），减少调谐时存活对象关联错误。
  • 仓库、可观测性与 UI 边缘情况 — OCI Helm 仓库现在接受 host:port URL（#30516），转义后的写凭据路由得到正确处理（#29955），响应省略 expires 时遵循 user-info 缓存上限（#30624），同步完成事件包含所有多源 revision（#30470），改善自动化、事件可审计性和缓存行为。

无破坏性变更。

快速入门

非 HA：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.13/manifests/install.yaml

哈：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.13/manifests/ha/install.yaml
