argo-cd v3.6.2

修订 发布时间2026年11月18日 来源argoproj/argo-cd 英文原文

变更流程图

亮点

  • 更快、更安全的调谐 — ApplicationSet 刷新现在只打刷新注解，而不是重写整个对象（#24378、#24647；回移 #31029）。减少不必要的写入和覆盖控制器并发更新的风险。
  • 未知同步状态后的 diff 缓存正确性 — 控制器在同步状态为 Unknown 后绕过缓存 diff，并在 manifest-generate-paths 未变时保留服务端 diff 缓存（#30893、#30812）。漂移检测更准确，同时未受影响的 manifest 仍享有缓存命中性能。
  • 降低控制器内存压力 — gitops-engine 不再为每个集群保留解码后的 OpenAPI 文档，并裁剪缓存压缩 manifest 的多余容量（#30810、#30779）。大型多集群安装无需改配置即可看到稳态内存下降。
  • 拒绝规则优先级修复 — AppProject 的负向目标规则（!name / !server）现在即使有正向规则匹配也会否决（#30896）。检查同时包含 allow 和 deny 模式的策略；此前被放行的目标现在可能被拒。
  • 依赖加固 — regexp2 升到 v2.13.0 以修复 CVE-2026-77299（#31039），Helm 升到 v4.3.2、Go 升到 v1.27.4（#30986、#30915）。升级时请验证任何自定义 Helm 后端集成。
  • 运维与 UI 修复 — 带 ignoreMissingComponents 的 Kustomize 现在会包含所有存在的组件（#30909），UI 修复改进多源导航、Pod 终端连续性、分组 Pod 可见性和面包屑布局。

无破坏性变更。

快速入门

非 HA：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.6.2/manifests/install.yaml

哈：

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.6.2/manifests/ha/install.yaml

发布签名和出处

所有 Argo CD 容器映像均由 cosign 签名。 为符合 SLSA 3 级规范的容器映像和 CLI 二进制文件生成来源。有关如何验证的信息，请参阅文档。
