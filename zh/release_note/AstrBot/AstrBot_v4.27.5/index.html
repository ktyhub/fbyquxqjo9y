AstrBot v4.27.5

AstrBot v4.27.5

变更流程图

亮点

  • 首次运行的密码重新可见（#9879） — 现在用 astrbot run 初始化全新实例时会打印随机生成的密码。这是引导级别的回归：新安装时这个一次性凭据是初次登录的门槛，静默生成会让运维被锁在自己部署之外，且没有明显的恢复路径。升级会恢复预期的首次运行输出；注意它不会补回 4.27.4 上已生成又被丢弃的密码。
  • 密码重置是已受影响安装的恢复路径 — 文档给出的应急手段是 astrbot password，可以设置新凭据而不必清空数据目录或重新初始化。对在 4.27.4 上初始化并撞上登录墙的人来说，这是实际可行的修复，而不是推倒重来。它也是主动轮换凭据的正确工具，不必依赖那次性生成的密码。
  • 范围只是一个修复，不是功能投放 — 差异只有 v4.27.4...v4.27.5，Fixed 下只有一条；没有新增配置项、API 或命令。对现有 4.27.x 用户来说这是低风险的无感升级——行为变化只限于全新引导的输出，升级不会改动你已设置的凭据。一个按日期对照时需注意的元数据小问题：changelog 头部写的是 2026-09-01，而源 tag 日期是 2026-08-31。
  • 破坏性变更 — 本版本无。

已修复
