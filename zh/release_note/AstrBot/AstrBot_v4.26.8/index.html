AstrBot v4.26.8

这个项目是干啥的：是一个能接入QQ、微信、LINE等平台的聊天机器人框架，让想做AI助手的人把大模型、知识库和工具调用串起来，直接放进群里用。

变更架构图

亮点

  • 插件市场迁移到 AstrBot Cloud — 这里影响最大的变化：WebUI 插件市场不再自己持有目录，数据改为从新的 AstrBot Cloud 平台同步。插件作者必须在该平台发布/管理条目，并遵循扩充后的发布指南（#9415）；用户在依赖应用内浏览前，应确认自己已安装的插件仍出现在跳转后的目录中——任何本地维护的市场状态都当作临时的。

  • 按插件设置日志级别与字典配置默认值 — 现在可以从 Dashboard 和插件 API 两个入口按插件调节日志详细程度（#9342），单个话痨插件不再逼你提高整个日志的噪音。字典类型配置字段也支持默认值映射（#9414），即声明为 dict 的插件 schema 能正确填充默认值——如果你的插件此前依赖这些字段为空到达，值得检查。

  • 新供应商，以及会变化的 TTS 默认值 — 支持多模态的 DashScope embedding 供应商（#9137）和 FishAudio TTS 模型配置（#9381）拓宽了供应商选择。注意行为变化：MiMo TTS 的默认模型现在是 mimo-v2.5-tts（#9428），如果你此前依赖旧的隐式默认值、不希望升级后音色变化，请显式设置模型。

  • Windows 下的 FAISS 与启动可靠性 — Windows 自托管用户有实质修复：FAISS 支持非 ASCII 路径（#8323）；恢复懒加载以消除启动卡死（#9350）；无效的索引维度现在会被直接拒绝，而不是事后才失败（#9385）。如果你的数据放在含 unicode 的用户名或路径下，这是很值得升级的版本。

  • 调度器与 LLM/RAG 稳健性 — 持久化定时任务现在能可靠加载：时间戳在相应锁内刷新，调度器状态与数据库同步解耦（#9349、#9419）。请求链路上，LLM 调用失败后检查点仍能保留（#9358）；embedding 批处理顺序得以保持（#9359）；融合阶段保留各知识库自己的稀疏排名（#9426），使独立的 FTS5 索引不再扭曲检索排序——对多知识库部署是实打实的质量提升。

  • 代理处理与崩溃防护 — 未配置代理时，现在会忽略系统代理环境变量（#8897），避免在设置了全局 HTTP(S)_PROXY 的主机上本地 API 流量被静默拦截——如果你发现 “localhost” 调用行为诡异，检查这里。另外，C 扩展重载也加了防护，避免进程崩溃（#9148）。

本次发布无破坏性变更。
