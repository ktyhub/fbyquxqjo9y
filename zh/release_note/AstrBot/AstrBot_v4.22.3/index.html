AstrBot v4.22.3

修订 发布时间2026年4月4日 来源AstrBotDevs/AstrBot 英文原文

变更架构图

亮点

  • 自托管技术栈的 token 统计 — llama.cpp 现在会输出 token 用量（#7358），_extract_usage 不再弄乱 cached_tokens（#6719），于是计费/成本分析终于能反映真实的提示缓存行为。如果你对本地推理做计量，用量数字会变化——请重新校准基于旧的有噪声数字的仪表盘或预算告警。

  • Gemini 行为变化 — 思考部分会从面向用户的消息链中剥离（#7196）：这对隐私和体验是好事，但下游依赖推理片段的逻辑将看不到它们。类似地，function_response 的载荷被重塑以符合 Gemini 的 schema，消除了工具结果轮次的 400 Invalid argument（#7216）。

  • 严格 API 的载荷洁净度 — 空的 OpenAI content 列表被规范化为 None（#6551），空 assistant 消息在发送前被过滤（#7202），消除了严格端点抛出的零内容 400。假设会传入空列表的自定义 provider 应确认现在能处理 None。

  • Rerank 部署灵活性 — vllm_rerank 新增可配置的 rerank_api_suffix（#7278），非默认 API 路径不再需要 fork；百炼 rerank 同时解析旧版和当前响应格式（#7217）——仍固定使用旧结构的用户可以安全升级。

  • 依赖与部署修复 — Docker 镜像打包了 AMR 编码器（#7247），pip 安装会拉取 pysocks，SOCKS5 代理终于可用（#7221），缺失的 qrcode 依赖恢复，二维码生成回来了（commit 5886c437）。Windows 上的 MCP 运行器继承完整系统环境变量（#7054），修复了工具在 PATH 中时启动失败的问题。

  • WebUI 与插件开发者修复 — Monaco worker 在本地打包（#7249），代码编辑不再受 CDN 故障影响；新增模型/平台统计面板（#7152）和 provider 页面改版（#7248），同时在压缩下加入 SSE 心跳以减少 WebChat 误断连（#7003）。插件开发者请注意：Pydantic v2 下 Record.path 不再被错误地要求必填（#7048），Discord/Misskey 热重载通过修正 client_self_id 的误用得到修复（#7331）。

发生了什么变化

新增

  • 新增 vllm_rerank 提供商支持可配置的 rerank_api_suffix，可灵活适配不同 API 路径。（#7278）
  • 适配 llama.cpp 的 token 用量提取支持，增强 token 统计与计费分析能力。（#7358）
  • WebUI 捆绑 Monaco Editor 的 worker 文件，防止从 CDN 下载失败。（#7249）
  • 全新的模型/平台总览统计面板。（#7152）

优化

  • 优化 OpenAI 消息处理，若 content 列表为空时将其置为 None，并降低空内容下的异常率。（#6551）
  • 优化 provider page 布局与样式，提升整体设置页面排版一致性。（#7248）
  • 用户已登录时将直接跳转欢迎页，减少再次进入登录页的步骤。（commit）

修复

  • 修复 Gemini 思考片段泄露到用户可见消息链路的问题。（#7196）
  • 修复 Gemini(OpenAI 兼容 API) 下，function_response 格式要求导致的 400 Invalid argument 错误。（#7216

  • 修复 Bailian Rerank 对新旧响应格式兼容性，避免解析失败。（#7217）
  • Docker 镜像补充 AMR 编码器依赖，修复部分部署场景下的音频转码缺失问题。（#7247）
  • 修复 pip 安装缺少 pysocks 依赖导致的 SOCKS5 代理不可用问题。（#7221）
  • 修复 cached_tokens 在 _extract_usage 中的处理逻辑，避免 token 统计错乱。（#6719）
  • 增强 SSE 断开保护，压缩传输下主动发送心跳，减少 WebChat 误断连。（#7003）
  • 修复严格 API 下空 assistant 消息导致的 400 错误。（#7202）
  • 新增二维码功能缺失的 qrcode 依赖修复，恢复二维码生成功能。（commit）

  • 修复 Record.path 在 Pydantic v2 下被错误视为必填字段的问题。（#7048）
