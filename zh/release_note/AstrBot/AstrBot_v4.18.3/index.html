AstrBot v4.18.3

这个项目是干啥的：是一个能接入QQ、微信、LINE等平台的聊天机器人框架，让想做AI助手的人把大模型、知识库和工具调用串起来，直接放进群里用。

变更架构图

亮点

  • 工具调用的上下文完整性 — （#5417）此前上下文截断可能把工具调用和它的响应拆开，留下畸形的消息历史，导致使用工具的模型失败或产生幻觉。这是对长 Agent 运行的正确性修复，不是表面改动：如果使用了上下文截断策略，请重新测试工具使用密集的会话，因为过往对话可能已被静默破坏。无需改配置。
  • Embedding provider 配置 — （#5442）创建 embedding provider 时现在会自动检测向量维度，省去一个手动步骤——此前配置的维度与模型不匹配是向量检索静默失效的常见原因。已有硬编码维度的 provider 不受影响，但新建时配错的风险降低了。
  • 知识库性能 — （#5463）检索现在批量查询元数据，而不是每篇文档发一次查询，消除了 N+1 模式。大型知识库或远程元数据后端的延迟应会显著降低；这是无感改进，没有 API 或数据迁移，升级即可获得。
  • 人格解析与会话身份 — （#5440）会话更新不再覆盖 persona_id，会话/对话的人格查找逻辑被统一。如果你此前加了每次更新后重新应用人格的绕过代码，现在可以删掉——但要检查依赖旧解析优先级的逻辑，因为人格选择现在可能解析出不同结果。
  • Telegram 媒体兼容性 — 语音消息现在以 OGG 而非 WAV 发送（#5389），修复了通过 OpenAI 兼容 STT 端点的转写问题；视频发送也恢复了（#5430）。如果此前有自定义的 WAV 处理，或一直避开 Telegram 视频，这两条路径都值得重新验证。
  • 平台与工具链加固 — 通用桌面更新器桥接（#5424）为客户端集成方提供了受支持的应用内更新钩子；定时任务在并发下有了更好的会话隔离；QQ 官方频道媒体发送不再泄漏陈旧的 markdown 字段（#5445）；Pyright 问题被清理（#5437、#5474）——如果你的构建用静态类型检查把关，这些很有用。
  • 破坏性变更 — 本版本无破坏性变更。

发生了什么变化

新增

  • 新增桌面端通用更新桥接能力，便于接入客户端内更新流程 (#5424)。

修复

  • 修复新增平台对话框中 Line 适配器未显示的问题。
  • 修复 Telegram 无法发送 Video 的问题 (#5430)。
  • 修复创建 embedding provider 时无法自动识别向量维度的问题 (#5442)。
  • 修复 QQ 官方平台发送媒体消息时 markdown 字段未清理的问题 (#5445)。
  • 修复上下文管理策略 -> 上下文截断时 tool call / response 配对丢失的问题 (#5417)。
  • 修复会话更新时 persona_id 被覆盖的问题，并增强 persona 解析逻辑。
  • 修复 WebUI 中 GitHub 代理地址显示异常的问题 (#5438)。
  • 修复设置页新建开发者 API Key 后复制失败的问题 (#5439)。
  • 修复 Telegram 语音消息格式与 OpenAI STT 兼容性问题（使用 OGG） (#5389)。

优化

  • 优化知识库检索流程，改为批量查询元数据，修复 N+1 查询性能问题 (#5463)。
  • 优化 Cron 未来任务执行的会话隔离能力，提升并发稳定性。
  • 优化 WebUI 插件页的交互。

错误修复

  • 修复了线路适配器未出现在“添加平台”对话框中的问题。
  • 修复了 Telegram 视频发送问题 (#5430)。
  • 修复了 Pyright 静态类型检查错误 (#5437)。
  • 修复了创建嵌入提供程序时嵌入尺寸的自动检测（#5442）。
  • 修复了通过 QQ 官方平台发送媒体消息时过时的 markdown 字段（#5445）。
  • 修复了上下文截断期间工具调用/响应配对丢失的问题（#5417）。
  • 修复了 persona_id 在对话更新期间被覆盖的问题，并改进了角色解析逻辑。
  • 修复了 WebUI 中不正确的 GitHub 代理显示（#5438）。
  • 修复了在设置中创建新密钥后 API 密钥复制失败的问题 (#5439)。
  • 使用 OGG 修复了 Telegram 语音格式与 OpenAI STT 的兼容性（#5389）。

改进

  • 通过批处理元数据查询来改进知识库检索，以消除 N+1 查询模式 (#5463)。
  • 改进了未来 cron 任务的会话隔离，以提高并发下的稳定性。
