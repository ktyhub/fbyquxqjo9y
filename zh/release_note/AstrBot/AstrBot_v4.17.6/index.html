AstrBot v4.17.6

AstrBot v4.17.6

变更流程图

亮点

  • 代码执行需管理员授权（#5214） — Python/Shell 执行工具（即「computer use」功能）现在位于可配置的管理员权限检查之后。高风险操作不再默认对所有 Agent 可用，因此升级前请核对管理员角色/配置，否则合法的自动化会静默失去执行能力——对非管理员上下文，这道门默认关闭，除非显式授权。
  • 插件兼容性元数据（#5235） — 插件现在可以声明 astrbot-version 及平台要求，宿主会在加载时校验。插件作者应把这些字段加进 manifest，以获得清晰的兼容性错误，而不是莫名其妙的运行时崩溃；运维方也能在插件面向不匹配的核心时尽早收到信号。对已有插件是可选启用，但只有采用它，生态才管得过来。
  • MCP 工具全面开放给主 Agent（#5252） — 人格级别的工具选择不再把 MCP 工具从主 Agent 中过滤掉，完整的 MCP 工具集现在全部暴露。这是实打实的行为变化：依赖工具选择来约束能力的人格会突然看到更多工具，所以要重新审查人格配置，防止提示词膨胀和意外的工具访问。本版本还从 tool-schema 属性中移除 additionalProperties（#5253），修复严格供应商下的校验问题——手工编写工具 schema 的用户需要注意。
  • 微信公众号被动回复重构（#5224） — 被动回复现在使用缓冲加分块响应，并调整了超时行为。对微信公众号机器人来说，这直接减少生成缓慢时的丢回复/重复回复；如果机器人会输出大段内容，请注意分块边界的行为——响应现在是分块到达，而不是一次性返回。
  • 会话生命周期与消息可靠性（#5225、#5208、#5250） — reset/new/delete 现在会终止活动事件，杀掉仍在处理中的陈旧响应，避免它们漏进新会话——对以编程方式驱动会话的人来说状态更确定，但要注意以前可取消的工作现在会被主动杀掉。配套修复还包括只发送 JSON 片段时的空消息错误（#5208），以及字典格式 content 中残留 JSON 泄漏（#5250），从端到端收紧了消息处理。
  • 桌面端从 Electron 转向 Tauri（#5226） — Electron 桌面构建流水线已移除，桌面开发迁到 Tauri 仓库。这是本版本最主要的迁移项：基于 Electron 的构建或锁定在此仓库的 fork 不再从这里获得更新，因此如果你发布或依赖桌面应用，请转向跟踪新的 Tauri 仓库。

发生了什么变化

新增

  • 新增 Python / Shell 执行工具的管理员权限校验，提升高风险操作安全性 (#5214)。
  • 新增插件 astrbot-version 与平台版本要求校验支持，增强插件兼容性管理能力 (#5235)。
  • 账号密码修改流程新增“确认新密码”校验，减少误输导致的配置问题 (#5247)。

修复

  • 修复 MCP 工具完整暴露给主 Agent，无视人格 tool 选择的问题 (#5252)。
  • 改进微信公众号被动回复处理机制，引入缓冲与分片回复并优化超时行为，提升回复稳定性 (#5224)。
  • 修复仅发送 JSON 消息段时可能触发空消息回复报错的问题 (#5208)。
  • 修复会话重置/新建/删除时未终止活动事件导致的陈旧响应问题 (#5225)。
  • 修复 provider 在 dict 格式 content 场景下可能残留 JSON 内容的问题 (#5250)。
  • 修复工具 schema 属性中的 additionalProperties 配置问题 (#5253)。
  • 优化账号编辑校验错误提示，简化并统一用户名/密码为空场景返回信息。

优化

  • 优化 PersonaForm 布局与工具选择展示，并完善工具停用状态的本地化显示。

其他

  • 移除 Electron Desktop 流水线并迁移到 Tauri 仓库 (#5226)。
  • 更新相关仓库链接与功能请求模板文案，统一中英文表达。
  • 移除过时文档文件 heihe.md。

修复

  • 修复了仅发送 JSON 消息段时的空消息回复错误 (#5208)。

  • 修复了当 content 采用 dict 格式时提供程序处理中残留的 JSON 内容问题 (#5250)。

改进

  • 增强了 PersonaForm 布局和工具选择显示，并改进了非活动工具的本地化标签。

其他
