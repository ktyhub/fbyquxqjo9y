AstrBot v4.16.0

小版本 发布时间2026年2月12日 来源AstrBotDevs/AstrBot 英文原文

变更流程图

亮点

  • QQ 官方适配器变为双向 — #5066 新增主动消息推送和私聊文件接收，QQ 机器人现在可以发起对话、接收媒体，而不只是被动响应消息。对开发者来说这解锁了推送式工作流（定时报告、告警、主动跟进），但要注意：主动发送依赖机器人被授予的权限，且受 QQ 平台侧频率/权限限制，请内置限流和优雅的失败处理。
  • Telegram 与飞书的消息上下文更丰富 — #5037 引入 send_chat_action，让 Telegram 机器人在 AI 思考时显示“typing…”“uploading image…”状态——改动很小，但显著提升感知响应速度。#5018 让飞书适配器能接收文件、读取引用消息内容（图片、视频、文件、文本），意味着引用的媒体现在可以作为多模态提示的输入。请预料到更大的载荷和新的飞书权限范围；在依赖引用附件前，先确认应用的 file/read 权限。
  • 自定义平台适配器获得 i18n — #5045 为自定义适配器加了国际化支持，适配器作者的字符串可以本地化，而不是硬编码中文。如果你维护或发布第三方适配器，这是让它们适用于非中文部署的关键钩子；请预留一轮工作把消息模板接入新的 i18n 层。
  • 临时文件生命周期有上限 — #5026 新增 TempDirCleaner 和 data/temp 的可配置最大容量。这对长期运行、媒体密集的实例很重要——此前它们面临磁盘无界增长的风险。在启用重度文件工作流前请审慎设定上限——过于激进的默认值可能清掉仍被进行中媒体处理使用的临时文件。
  • 运行时可靠性与正确性加固 — #5033 修复了提前返回时未 await 的 reset 协程（在错误路径上真正防止资源泄漏）；#5015 和 #5031 加固了 frozen/打包桌面运行时下的插件依赖加载；#5029 为 Electron 和后端日志加入按大小轮转。正确性方面，#5069 修复 OpenRouter/DeepSeek 分块错误，#5054 改进转发引用解析并提供可配置的图片回退，#5042 恢复备份中缺失的人设目录映射。如果你运行打包桌面版或使用 OpenRouter DeepSeek，单凭这些就值得升级。
  • 破坏性变更 — 无；v4.16.0 是向后兼容的功能与修复发布，无需迁移步骤。
