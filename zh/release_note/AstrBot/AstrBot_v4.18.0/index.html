AstrBot v4.18.0

小版本 发布时间2026年2月21日 来源AstrBotDevs/AstrBot 英文原文

变更架构图

亮点

  • HTTP API 让 AstrBot 变成可编程服务（Beta） — #5280 新增基于 API-Key 鉴权的 HTTP 接口，覆盖聊天、会话/配置列举、文件上传和出站 IM 消息。这是本版本的架构亮点：你现在可以用脚本、CI 或外部系统驱动机器人，而不只通过聊天平台。它明确标注为 Beta，所以接口契约可能变动——但这是大多数采用者会基于它做集成的钩子。

  • 更细粒度的 Anthropic 推理控制，外加一个低调的新供应商 — #5209 暴露了自适应思考参数（type/effort），你可以调节推理深度，而不必接受供应商默认值。建议直接读该 PR：标题里还提到了发布摘要未列出的「Anthropic Claude Code OAuth provider」——如果你一直在等 Claude Code 凭据支持，这条很相关。

  • Dashboard 桥接字段改名，扩展作者需迁移 — #5269 用 isDesktop 取代 isElectron 运行时桥接字段。听起来像外观改动，但任何基于 isElectron 做分支的自定义 Dashboard 代码或插件，升级后都会静默走错分支。上线前请审查这些判断。

  • ChatUI 配置选择现在真的生效了 — #5292 修复两个相关缺陷：用非默认配置打开的对话其实仍在静默使用默认配置；新对话可能因缺少会话 ID 而绑定配置失败（同时加固了 localStorage 处理）。如果你有多个配置档案，你以为互相隔离的对话可能一直被错误路由——升级后请重新验证。

  • 渠道与市场细节打磨 — #5234 让 Telegram 命令别名注册进原生命令菜单，无需客户端配置即可提升可发现性；#5287 稳定 QQ 官方频道消息投递；#5271 改进插件市场的平台徽标和移动端布局。Telegram 的改动会改变终端用户在客户端看到的内容，所以这一项要做目视检查。

发生了什么变化

新增

  • 新增 AstrBot HTTP API，支持基于 API Key 的对话、会话查询、配置查询、文件上传与 IM 消息发送能力。详见AstrBot HTTP API (Beta) (#5280)。
  • 新增 Telegram 指令别名注册能力，别名可同步展示在 Telegram 指令菜单中 (#5234)。
  • 新增 Anthropic 自适应思考参数配置（type/effort），增强思考策略可控性 (#5209)。

修复

  • 修复 QQ 官方频道消息发送异常问题，提升消息下发稳定性 (#5287)。
  • 修复 ChatUI 使用非 default 配置文件对话时仍然使用 default 配置的问题 (#5292)。

优化

  • 优化插件市场卡片的平台支持展示，改进移动端可用性与交互体验 (#5271)。
  • 重构 Dashboard 桌面运行时桥接字段，从 isElectron 统一迁移至 isDesktop，提升跨端语义一致性 (#5269)。

更改内容 (EN)

新功能

  • 添加了 AstrBot HTTP API 和 API Key 对聊天、会话列表、配置列表、文件上传和 IM 消息发送的支持。请参阅 AstrBot HTTP API（测试版） (#5280)。
  • 添加了 Telegram 命令别名注册，因此别名也可以出现在 Telegram 命令菜单中 (#5234)。
  • 添加了人择自适应思维参数（type/effort），以实现更灵活的推理策略控制（#5209）。

修复

  • 修复QQ官方公会消息发送错误，提高发送稳定性(#5287)。
  • 修复了创建新聊天时由于缺少会话 ID 导致的聊天配置绑定失败，并改进了 localStorage 容错能力（#5292）。

改进

  • 改进了插件市场卡显示以实现平台兼容性，并具有更好的移动可访问性和交互性（#5271）。
  • 将仪表板中的桌面运行时桥接字段从 isElectron 重构为 isDesktop，以实现更清晰的跨平台语义 (#5269)。
