AstrBot v4.26.6

修订 发布时间2026年7月14日 来源AstrBotDevs/AstrBot 英文原文

变更流程图

亮点

  • 人格可移植性进入 WebUI — 现在可以导入和导出人格（#4532），在不同 AstrBot 实例间迁移机器人或共享配置不再靠复制粘贴 YAML。重要提醒：导出内容刻意不包含工具和 Skills 配置，这些绑定不会随人格一起迁移——把导入当作起点，在目标实例上重新挂上工具/技能权限，别以为是原样克隆。

  • Anthropic 缓存切换为 ephemeral cache control — #9197 改变了供应商行为：基于 Anthropic 的供应商现在使用 ephemeral cache control 来提高缓存命中率。对开发者来说，这主要是重复提示或长上下文提示下的成本/延迟收益，但它改变了缓存断点的应用方式——升级后应关注缓存命中指标和 token 花费，别假定计费与旧版完全一致。

  • 消息投递链路加固，容忍错误配置与适配器怪癖 — 多项修复让入站流程对不完美的运维配置更宽容：格式错误的响应清理正则现在会被捕获，不再中断投递（#9183）；LINE 解析会丢弃不受支持的 force 参数，避免破坏 get_json（#9187）；群聊上下文改用 .get()，缺少 image_caption_prompt 的配置档案不再抛 KeyError（#9216）。如果你维护着旧正则过滤器或手工编辑过配置档案，正是这些改动让它们不再静默丢消息或让处理器崩溃。

  • 模型/供应商计量更准确 — NVIDIA MiniMax M3 的 max_tokens 现在处理正确（#9209）；WebChat 的 token 环不再高报上下文用量（#9255）。两者叠加意味着基于 UI 做的配额/成本规划和上下文窗口决策更可信——尤其是你按模型真实上限调提示词时。

  • 流式与 UI 状态经得起真实使用 — 刷新页面后 ChatUI 的活动流式会话可以续上（#9259）；移动端聊天输入框卡死和多行附件对齐问题已修复（#9202）；模型选择会跟随主题（#9200）；技能下载失败现在返回正确的 HTTP 错误，不再静默失败（#9213）。最后一条对自动化很关键：调用技能下载接口的脚本现在可以按状态码分支，而不用从空的成功响应里瞎猜。

  • WebChat 不再需要好友唤醒前缀 — #9215 让 WebChat 免于好友唤醒前缀的要求。对基于 WebChat 的机器人来说这是实打实的行为变化：现在不带前缀的消息也会触发，因此任何依赖前缀来门控或区分 WebChat 输入的逻辑都要重新审视。

本次发布无破坏性变更。
