AstrBot v4.27.4

这个项目是干啥的：是一个能接入QQ、微信、LINE等平台的聊天机器人框架，让想做AI助手的人把大模型、知识库和工具调用串起来，直接放进群里用。

变更架构图

亮点

  • 偏好存储的性能 — 单次偏好读取不再预加载整张 preferences 表（#9747）。对偏好数据量大的自托管实例来说，每次查询都能降低峰值内存和数据库压力——这类修复在并发负载下最重要，而不是在全新的单用户环境里。
  • 推理元数据与 provider 配置解耦 — 推理参数现在与 provider 配置分开存放（#9699）。如果你用脚本或模板管理此前携带推理字段的 provider 设置，请重新检查这些配置：尽管版本只是 patch，契约已经变了，铺开前最好做一次快速配置审计。
  • 更丰富、更稳健的聊天上下文 — JSON 卡片现在会进入群聊上下文，并新增了 LLM 元数据回退端点（#9655、#9725）；音频格式改为从文件内容探测，Telegram 音频会转换成 Record 组件（#9612、#9702）。这些一起让多模态上下文更完整，也不再那么依赖正确的文件扩展名或单一元数据源——留意对卡片和 Telegram 语音消息推理效果的改善。
  • 知识库摄取不再卡住 — 每次上传 10 个文件的上限取消了（#9701）。批量摄取工作流不再需要把大型文档集拆开，对构建大规模知识库的人来说是实实在在的便利。
  • Webhook 与 Dashboard 韧性 — 同步过来的 Weixin Kefu 消息即使缺少 open_kfid 也会被接受，不再让 webhook 处理失败；Dashboard 密码会保留，同时设置 password_change_required（#9665）。两者都是静默失败修复：少丢消息，重启也不会意外轮换凭据。
  • 废弃项清理与诊断 — 统计和 Misskey 可见性处理从废弃接口上移开（#9658、#9674），并会记录 Windows 上实际生效的运行时 shell（#9648）。这些是向前兼容和排障方面的改进——如果你在 Windows 上，或依赖这些集成随着上游 API 演进而工作，会很有用。
