AstrBot v4.21.0

小版本 发布时间2026年3月21日 来源AstrBotDevs/AstrBot 英文原文

变更流程图

亮点

  • Skill 打包格式迁移 — 旧的 skill.md 文件会统一改为 SKILL.md（#6757），现有 skill 应能自动迁移；插件作者仍应检查区分大小写的引用。多行 frontmatter、Windows 编码和缓存沙箱路径修复（#6460、#6058、#6331）让 skill 在不同环境下加载更可靠。
  • Provider 与插件扩展 — Kimi Coding Plan 新增 Anthropic 兼容访问（#6559），小米 MiMo 新增 TTS/STT（#6643），Ollama 现在可以关闭思考（#5941）。插件市场新增分类筛选和按元数据名称安装（带导入标识校验，#6762、#6530），让发现和安装更不易出错。
  • OpenAI 兼容配置 — provider 标签改为“OpenAI Compatible”（#6707）。embedding 请求仅在显式配置时才发送 dimensions（#6432），OpenAI embedding 的 base URL 不再自动追加 /v1 后缀（#6669）；依赖隐式补后缀的自定义端点必须自己显式带上。
  • 取消操作与子 Agent 生命周期 — /stop 现在会拒绝后续消息、清除持久化的 follow-up 状态，并中断子 Agent 的工具等待（#6704、#6656、#5850）。tool_call_timeout 现在覆盖交接、cron 和后台任务，默认值从 60s 提高到 120s（#6713）——长任务有了更多余量，但自动化流程必须把 /stop 当作对待处理 follow-up 的终止信号。
  • 上下文与集成可靠性 — token 统计现在覆盖图片、音频和思维链（#6596）；截断会保留唯一的用户消息，避免 provider 返回 400（#6198、#6581），Gemini 的数组 schema 始终带上 items（#6051）。SQLite busy 超时、Telegram 轮询恢复、Windows MCP/原生构建修复，以及 KOOK 的 Pydantic 和旧 Python 兼容改动，减少了平台相关的失败（#6474、#6648、#5822、#6575、#5719、#6512）。
  • 兼容性 — 未声明破坏性变更。
