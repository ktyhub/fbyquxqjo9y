AstrBot v4.26.4

修订 发布时间2026年7月2日 来源AstrBotDevs/AstrBot 英文原文

AstrBot v4.26.4

这个项目是干啥的：是一个能接入QQ、微信、LINE等平台的聊天机器人框架，让想做AI助手的人把大模型、知识库和工具调用串起来，直接放进群里用。

变更架构图

亮点

  • 更清晰的文件工具报错 — astrbot_file_read_tool 现在遇到目录路径会给出明确错误，而不是误导性的权限失败（#9088），工具失败更容易诊断。
  • 更低延迟、更广的语音兼容性 — Markdown 流式延迟降低了（#9097）；WAV 输入在腾讯 Silk 编码前会先重采样和降声道（#9100），提升响应速度以及各腾讯 IM 适配器间的语音消息兼容性。
  • 更可靠的 webhook 与下载 — webhook 修复恢复了企业微信、企业微信客服和 QQ 官方机器人的校验，在需要处返回纯文本（#9107），并在统一路由上保留原始回调载荷。非 200 的下载现在会被拒绝（#9085），避免错误响应被当成有效文件。
  • 适配器与回退韧性 — Discord 命令注册不再被过严的正则阻断（#9102），后台 Agent 唤醒现在也会遵守后备 chat 模型（#9094），减少命令发现失败和模型降级时的中断。
  • 更安全的重启与插件重载行为 — 桌面端托管的核心重启受到保护（#9098、#9073），针对性的插件重载会对未激活插件跳过 _unbind_plugin（#9096），避免维护期间触发不必要的生命周期钩子。

发生了什么变化

修复

  • 当 astrbot_file_read_tool 收到目录路径时返回明确的错误，而不是报告误导性的权限错误 (#9088)
  • 减少 Markdown 流延迟 (#9097)
  • 为腾讯 Silk 编码重新采样和缩混 WAV 文件 (#9100)
  • Guard 桌面管理核心重启 (#9098)
  • 更新重启逻辑 (#9073)
  • 修复 Discord 适配器命令注册正则表达式过于严格 (#9102)
  • 拒绝非 200 个下载响应 (#9085)
  • 修复 WeCom webhook 适配器返回 JSON 而不是纯文本 (#9107)
  • 保留统一 Webhook 路由的原始 Webhook 回调响应
  • 在指定的插件重新加载期间跳过 _unbind_plugin 对于不活动的插件 (#9096)
  • 将后备聊天模型应用于后台唤醒（#9094）
