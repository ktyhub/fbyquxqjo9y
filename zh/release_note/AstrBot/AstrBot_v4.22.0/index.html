AstrBot v4.22.0

AstrBot v4.22.0

这个项目是干啥的：是一个能接入QQ、微信、LINE等平台的聊天机器人框架，让想做AI助手的人把大模型、知识库和工具调用串起来，直接放进群里用。

变更架构图

亮点

  • 个人微信接入 — #6777 新增官方个人微信账号支持，包含扫码驱动的配置流程、重构的消息管线和改进的媒体处理。这是一个需要接入的新平台适配器，因此会有新的配置/登录步骤（扫码而非机器人 token），而不是即插即用的替换。由于它触及核心消息分发，建议先用小号试点，再切生产流量，并验证图片/语音等媒体在重构后的流程中能正确往返。

  • 图片压缩流水线 — #6794 引入可配置压缩，支持最大尺寸和 JPEG 质量上限，并管理临时文件生命周期。对图片密集型部署来说，这直接降低带宽、存储和上游 API 成本。注意错误路径下的临时文件清理——确认压缩失败时文件会被删除，避免长期运行的实例磁盘泄漏。

  • 更轻量的知识库检索 — #6750 在知识库为空时完全跳过检索，省掉无谓的 embedding/向量查询及其延迟。#6783 作为补充，修复了 YAML frontmatter 中转义换行符的保留问题（并更新了测试和 CI）。如果你解析 frontmatter 元数据，升级后请重建语料索引，让文档按预期解析。

  • 工具调用上下文保真 — #6149 现在保留 全部 CallToolResult.content 项，不再丢弃部分内容。对工具会返回多个内容块（文本 + 图片 + 内嵌资源）的 Agent/MCP 工作流来说，这避免了可能拖累后续推理的静默上下文丢失。无需改配置，但要审查那些假设只有一个内容项的消费方代码——结果载荷会更丰富。

  • 适配器与供应商加固 — #6769 用 Forbidden 取代已弃用的 Telegram Unauthorized 导入，这是跟随上游库弃用而做的兼容性修复。请检查你锁定的 python-telegram-bot 版本，因为新导入意味着有最低支持版本要求。#6788 处理了 OpenAI 供应商中 token 用量为 None 的情况，模型/供应商不返回用量数据时，用量上报不再崩溃。

  • WebUI 插件管理 — #6776 为已安装插件新增置顶和拖拽排序，加快常用插件的访问。纯 UI/UX 改进，不涉及 API 或数据模型。

无破坏性变更。
