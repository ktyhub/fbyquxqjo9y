AstrBot v4.20.0

小版本 发布时间2026年3月12日 来源AstrBotDevs/AstrBot 英文原文

变更架构图

亮点

  • 安全（必须升级） — PR #6093 修复了一个严重漏洞（V-004）。值得注意的是，它只出现在原始 commit 列表里，被结构化的 “What’s Changed (EN)” 摘要遗漏了，只看亮点的人会漏掉它。单凭这一点，任何暴露在公网的实例都值得部署 4.20.0——请把它当安全发布，而不是普通小版本升级。
  • QQ 官方机器人获得真正的媒体支持 — PR #6063 新增文件、语音和视频消息（含 WebSocket 模式），PR #6131 改善了流式投递的可靠性并支持主动发送媒体。如果你在用 QQ 官方适配器，这是头条特性：此前纯文本的工作流现在可以收发附件，流式回复也更稳。QQ 官方用户应升级；其他适配器的用户收益很小。
  • 破坏性变更/迁移：Telegram 适配器 — PR #6044 从 telegramify_markdown.markdownify 调用中移除了已废弃的 normalize_whitespace 参数。这是本版本唯一明确的破坏点：仍在向该调用传 normalize_whitespace 的自定义代码或插件会报错，必须去掉该参数。标准用户不受影响，但升级前请检查任何定制的 Telegram 格式化钩子。
  • 插件、WebUI 与持久化修复 — 依赖自动安装现在只装缺失的包（PR #6088、PR #5954），插件市场在安装后刷新安装状态（PR #6124），减少“已安装却仍显示未安装”的困惑和重复安装。还修复了：Windows 本地 skill 文件读取（PR #6028）、Discord 预确认 emoji 配置重启后不持久（PR #6031）、WebUI 搜索清除行为（PR #6017），以及 Dashboard README 锚点导航（PR #6083）。如果你在 Windows 上、用 Discord 预确认，或频繁装插件，这些值得升级；否则只是体验改善。
  • 谁可以跳过 / 其他小改动 — PR #6081 带来俄语翻译，PR #6064 调整了边界场景下的 booter 选择和消息发送工具（低风险、难观察）。这里没有重新打 tag，也不是纯元数据改动——这是实打实的 4.19.5 → 4.20.0 功能发布。如果你不用 QQ 官方、不受 V-004 影响、也没有 Telegram 定制，可以暂缓；但考虑到这个严重修复，升级是更稳妥的默认选择。
