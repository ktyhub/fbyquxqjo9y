AstrBot v4.25.0

小版本 发布时间2026年5月15日 来源AstrBotDevs/AstrBot 英文原文

变更流程图

亮点

  • 扫码驱动的平台接入 — 飞书/Lark（#8191）、钉钉（#8198）和个人微信（#8196）现在都可以通过扫码配置，app_id/app_secret/域名以及 ClientID/ClientSecret 会自动填充，微信配置只在登录成功后保存。这省去了手动复制凭据，但要注意配套的会话超时清理：陈旧的微信登录会被清除，因此任何复用过期会话的自动化都需要重新认证。
  • 新的 embedding 后端 — Ollama 和 NVIDIA NIM 适配器（#8104）让你可以在本地/私有环境跑 embedding，而不必走托管 API，这对隐私敏感或隔离网环境很重要。切换前请确认所选后端/模型确实提供了兼容的 embedding 端点。
  • 插件 API：废弃项加 kwargs 修复 — context.register_llm_tool() 现已正式废弃，并补上了 LLM Tool docstring 必需的参数格式说明（#8178）；插件作者应迁移并审查工具 docstring，因为格式错误的参数文档会在调用时破坏参数解析。另外，register_platform_adapter_type 和 register_permission_type 现在能正确转发 **kwargs（#8141）——你此前当作“被忽略”的选项会开始生效，请重新检查这些调用点。
  • WebUI 资源选择行为改变 — 当 data/dist 中的 Dashboard 比核心旧时，AstrBot 现在会优先使用自带的 Dashboard（#8172）。这会静默覆盖自定义/过时的前端构建，因此自托管的 data/dist 会被忽略，直到它比核心更新。Noto Sans 增加了西里尔字母/多语言渲染（#8015），控制台自动滚动偏好现在刷新后也能保留（#8186）。
  • 音频与工具调用的健壮性 — 带前导 \x02 字节的 SILK 帧现在能被识别（#8009），AMR 转换质量提升，Opus 复用共享转换路径（#8153），MiniMax TTS 遇到空/无效的 timber-weight JSON 不再崩溃，Claude 在无参数工具返回 None 参数时也不再调用失败（#8136）。你大概率可以去掉 \x02 剥离的预处理了；另外，个人微信媒体发送错误现在会暴露出来（#8175），此前静默的失败可能会出现在日志里。

本版本无破坏性变更。

发生了什么变化

修复

  • 修复 Tencent SILK 音频带 \x02 前缀时未被识别，导致后续 ffmpeg 转换失败的问题。（#8009）
  • 修复个人微信媒体消息发送失败时错误未向上暴露的问题。（#8175）
  • 修复 Claude API 对无参数工具返回 None 参数时工具调用失败的问题。（#8136）
  • 修复 register_platform_adapter_type 与 register_permission_type 未正确透传 **kwargs 的问题。（#8141）
  • 修复 MiniMax TTS timber weight 配置为空或非法 JSON 时可能导致初始化崩溃的问题。

新功能

  • 新增 Ollama Embedding 与 NVIDIA NIM Embedding 提供商适配器。（#8104）
  • 新增飞书扫码一键创建能力。（#8191）
  • 新增钉钉扫码一键创建能力。（#8198）
  • 新增个人微信创建时扫码登录流程，选择个人微信后直接在创建弹窗中显示二维码，登录成功后再保存机器人配置。（#8196）

优化

  • 优化个人微信登录态处理：当接口返回 session timeout 时清理旧登录态，避免继续高频请求失效会话。（#8196）
  • 优化 AMR 音频转换质量，并复用通用音频转换逻辑简化 Opus 转换实现。（#8153）
  • 优化 WebUI 资源选择逻辑：当 data/dist 中的 Dashboard 版本旧于当前核心版本时，优先使用随包内置的 Dashboard，避免旧前端资源造成兼容问题。（#8172）
  • Dashboard 新增 Noto Sans 字体支持，改善西里尔文字等多语言文本显示效果。（#8015）
  • 优化控制台自动滚动状态同步，刷新后能正确恢复并同步到日志显示组件。（#8186）
  • 更新飞书、钉钉、个人微信平台文档，补充扫码创建 / 登录说明、飞书权限开通提醒，以及个人微信新版创建流程。
  • 更新 AI 插件开发文档，明确 context.register_llm_tool() 已弃用，并补充 LLM Tool docstring 参数解析要求。（#8178）

更改内容 (EN)

新功能

  • 新增飞书/飞书一维click二维码设置。创建机器人时，用户可以选择飞书中国或飞书全球，扫描二维码，自动填写app_id、app_secret和域名设置。 AstrBot 还获取生成的配置 ID 显示的机器人名称。 （[#8191]（https://github.com/AstrBotDevs/AstrBot/pull/8191））
  • 钉钉新增一click二维码设置。用户可以通过扫描二维码创建或绑定钉钉应用程序，自动填写ClientID和ClientSecret，同时仍然可以手动设置。 (#8198)
  • 创建个人微信机器人时添加二维码登录。创建对话框现在直接显示登录二维码，并允许登录成功后保存。 (#8196)
  • 添加了 Ollama Embedding 和 NVIDIA NIM Embedding 提供程序适配器。 (#8104)

改进

  • 当 API 报告会话超时时，通过清除陈旧的登录状态，改进个人微信登录状态处理，避免针对无效会话的重复请求。 (#8196)
  • 通过重用共享音频转换路径，提高了 AMR 音频转换质量并简化了 Opus 转换。 (#8153)
  • 改进了 WebUI 资源选择：当 data/dist 包含早于当前核心版本的仪表板时，AstrBot 现在更喜欢捆绑的仪表板，以避免过时的前端兼容性问题。 (#8172)
  • 向仪表板添加了 Noto Sans 支持，以实现更好的西里尔文和多语言文本渲染。 (#8015)
  • 改进了控制台自动滚动状态同步，以便在刷新后将恢复的首选项应用于日志显示组件。 (#8186)
  • 更新了飞书/飞书、钉钉和个人微信平台文档，包含二维码设置/登录说明、飞书权限提醒以及新的个人微信创建流程。
  • 更新了 AI 插件开发指南，以澄清 context.register_llm_tool() 已弃用，并记录所需的 LLM 工具文档字符串参数格式。 (#8178)

错误修复

  • 修复了腾讯SILK音频未检测到前导\x02字节，可能导致ffmpeg转换失败的问题。 (#8009)
  • 修复了个人微信媒体发送失败未正确显示的问题。 (#8175)
  • 修复了当 Claude API 返回无参数工具的 None 参数时工具调用失败的问题。 (#8136)
  • 修复了 register_platform_adapter_type 和 register_permission_type 未正确转发 **kwargs 的问题。 （[#8141]（https://github.com/AstrBotDevs/AstrBot/pull/8141））
  • 修复了当木材重量配置为空或无效 JSON 时 MiniMax TTS 初始化崩溃的问题。
