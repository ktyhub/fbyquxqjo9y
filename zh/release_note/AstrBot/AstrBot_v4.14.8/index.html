AstrBot v4.14.8

修订 发布时间2026年2月8日 来源AstrBotDevs/AstrBot 英文原文

AstrBot v4.14.8

变更流程图

亮点

  • Python 3.12 运行时要求（迁移关键） — 唯一一个部署前必须行动的变化：最低 Python 版本提升到 3.12（#4963）。固定在 3.10/3.11 的部署必须升级解释器并重新验证第三方依赖；容器基础镜像、CI runner 和基于 venv 的安装都要更新，否则应用会拒绝启动。
  • provider 级代理支持 — 代理配置现在按 provider 生效，不再强制走单一全局出口（#4949）。这对需要不同网络路径的多 provider 场景（例如国内与海外模型端点）很重要。升级时请注意与已有全局代理设置的相互作用，优先级可能改变。
  • 由 LLM 决定是否发送工具返回的图片 — 模型现在可以预览工具返回的图片，并自主决定是否转发给用户（#4895）。对工具增强的流水线来说这是行为变化：可能会出现此前不会有的带图回复；如果你的工具会产出图片，请检查提示词设计和 token/成本预算。
  • Electron 桌面部署 — 项目现在支持 Electron 桌面应用部署（#4952），随后还有一个 hotfix 为 Electron 客户端加入特殊的更新处理。这引入了一条非服务器的分发路径；桌面构建的维护者要注意，它的更新流程与标准更新机制不同。
  • WebUI 中的插件命令权限 — 插件命令的权限管理现在可以在 WebUI 管理面板中完成（#4887）。运行多用户或共享机器人的运维可以细粒度控制插件命令访问，无需手改配置文件。新的欢迎功能（本地化内容加上手步骤）也同属面向运维的主题，帮新实例完成首次配置。
  • Telegram 相册与人设上下文修复 — Telegram 现在支持媒体组/相册（#4893），多图消息会作为一个连贯单元到达，而不是拆成碎片事件。再加上人设预设对话在上下文中重复的问题被修复（#4961），消除了一部分 token 用量虚高和系统提示重复——如果你此前依赖那个（有 bug 的）上下文形态，值得验证一下。
