Understand-Anything v2.3.1

Understand-Anything v2.3.1

这个项目是干啥的：一个帮你看懂海量资料的工具，能分析知识库、画出业务领域关系图，给想快速理清陌生领域的人用。

变更架构图

亮点

  • 知识库分析 — 新增 /understand-knowledge，通过 DETECT → SCAN → ANALYZE → MERGE → SAVE 把关联的 wiki 内容变成交互式关系图。article-analyzer 抽取隐式实体、论断和语义边，assemble-reviewer 在合并后修复丢失或不一致的图元素；KnowledgeGraphView 增加搜索、导览和按关系类型着色的边。

  • 用忽略规则限定分析范围 — /understand 现在应用内置排除项，以及来自项目根目录和 .understand-anything/ 的分层 .understandignore 文件。可以从 .gitignore 生成起始文件，随后新增 Phase 0.5 确认关卡——在继续前请检查它，尤其因为扫描器现在有意纳入文档、配置、基础设施和数据文件。

  • 统一且增量的图 — 子域图和批量合并现在会去重成一张图；Python 合并器规范化 ID、映射复杂度并生成详细修复报告。结构指纹支持增量更新，由 --auto-update 和 --no-auto-update 控制；自动化工作流应显式选择策略，并在把结果当作权威之前检查合并报告。

  • 扩展的图 schema — 节点类型从 13 种增加到 21 种，包括 domain、flow、step、article、entity、topic、claim 和 source，边类型扩展到 35 种。有硬编码类型白名单的下游消费者需要更新；func → function 和 doc → document 等别名便于摄入多样化输入。

  • 更广的架构上下文 — 非代码文件现在有明确的 fileCategory 赋值，确定性的基于脚本的发现改进了语言和框架检测。这些上下文现在会输入架构分析，--review 把轻量级内联校验与完整 LLM 审阅分开——请用忽略规则防止无关资源进入图中。

  • 破坏性变更 — 未列出。

新消息

/understand-knowledge — 知识库分析

分析 Karpathy 模式 LLM wiki 知识库的新技能。使用 wiki 链接检测原始来源和 wiki 降价，然后跨五个阶段（检测 → 扫描 → 分析 → 合并 → 保存）生成具有实体提取、隐式关系和主题聚类的交互式知识图。 配备了两个新代理：

  • 文章分析器 — 从 wiki 文章中提取隐式知识：实体（人、工具、论文）、声明（决策、断言）和语义边缘（builds_on、contradicts、exemplifies、authored_by、cites）
  • assemble-reviewer — 合并后质量审核器，可恢复丢失的节点/边、重新映射未知类型并验证跨批次一致性 专用的 KnowledgeGraphView 仪表板组件提供带有搜索、游览突出显示和关系类型边缘样式的强制导向可视化。

.understandignore 支持

用于 /understand 分析的用户可配置文件排除：

  • IgnoreFilter — 使用硬编码默认值（node_modules、构建输出、锁定文件、二进制文件）以及来自 .understand-anything/ 和项目根的分层 .understandignore 文件进行运行时过滤
  • IgnoreGenerator — 通过解析现有的 .gitignore 并检测项目目录，自动生成启动器 .understandignore
  • /understand 工作流程中的新阶段 0.5 在生成忽略文件后暂停以供用户确认

/understand 管道改进

  • 子域图合并（第 0 阶段）——通过重复数据删除将多个特定于域的图合并为一个统一图
  • 批量图形合并 — 新的 Python 脚本，具有 ID 标准化、复杂性映射和详细的修复报告
  • 增量更新 — 带有 --auto-update / --no-auto-update 标志的结构指纹
  • 用于架构分析的语言/框架上下文注入
  • 扩展审核路径 - 内联验证与通过 --review 的完整 LLM 审核

架构和类型扩展

  • 节点类型从 13 → 21 扩展（新增 domain、flow、step、article、entity、topic、claim、source）
  • 边缘类型扩展到 35 种，涵盖结构、行为、数据流、依赖、语义、基础设施、领域和知识关系
  • 灵活输入的类型别名（func → function、doc → document 等）

项目扫描仪改进

  • 现在使用显式 fileCategory 分配处理非代码文件（配置、文档、基础设施、数据）
  • 基于脚本的确定性文件发现，具有改进的语言和框架检测

文档和国际化

  • 韩语 (README.ko-KR.md) 和西班牙语 (README.es-ES.md) 自述文件翻译
  • 结构视图和域视图的动画展示 GIF
  • 多平台徽章（Codex、Copilot、Gemini CLI、OpenCode）

修复

  • 仪表板 URL 现在包含访问令牌
  • 连接的边在节点选择时正确突出显示
  • 图形视图中的稳定布局和范围基础设施过滤器
  • 市场 JSON 架构验证修复
  • 图形合并脚本的边权重强制
