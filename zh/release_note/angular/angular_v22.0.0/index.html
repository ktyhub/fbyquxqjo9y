angular v22.0.0

变更流程图

亮点

  • OnPush 成为默认变更检测策略 — @Component 现在默认采用 ChangeDetectionStrategy.OnPush（eae8f7e30b），除非显式标记为 dirty，视图不再每次异步事件都被重新检查。这是很大的性能收益，但对任何依赖默认 CD”自动”更新的代码都是真实的行为变更。配套迁移（cb4cb77053）会在需要旧语义处注入 ChangeDetectionStrategy.Eager——升级前请运行它并审查依赖隐式检查的组件。

  • 工具链下限提高，以及一次低调的 HTTP backend 切换 — 放弃 TypeScript 5.9 支持（8fe025f514），新增 Node.js 26 支持（b8d3f36ed9）。更隐蔽的是，新增的 provideHttpClient → HttpXhrBackend 迁移（3bc095d508）存在，是因为默认 backend 变了（改为 fetch）；如果你依赖 XHR 特有行为，请运行该 schematic 固定旧实现，否则请求语义会不同。

  • 完整的 AI / WebMcp 工具面上线 — provideWebMcpTools 和实验性的 declareWebMcpTool（3b0ae5fef0、ef1810197b），加上已注册的运行时调试工具和页内 DI 图浏览器（8ce9cc4f6b、75f2cb8f56）。这是 Angular 把应用内部机制定位为可被 AI agent 机器读取——强大，但基本属于实验性：请固定版本，预期 API 会有变动。

  • Signals 与 @defer 成熟，并带来新的构建期守卫 — 防抖 signal（b918beda32）、stream resource 的同步值（4e331062e8）、SSR resource 缓存（5a7c1e62dc），以及 rxResource 订阅泄漏修复（b20f0fe078）完善了响应式状态；@defer 新增可配置的 idle 行为和可选超时（a5981b83a6、98eb24cea0）。留意可能在 CI 中新出现 diagnostics：重复选择器的 NG8023（ca67828ee2），以及 prefetch 没有主触发器的警告（7f9450219f）。

  • Shadow DOM 破坏性变更伴随安全加固集群 — 移除了专用的旧版 shadow DOM 选择器（194f723f66）和弃用的 shadow-CSS 封装 polyfill（4c25a42e98）（如果你依赖它们就是破坏性的），并以 shadow root 下新的 bootstrap 作为补偿（cdda51a3b2）。请把 #68868 的修复当作安全相关：SVG <a> 上的动态 href/xlink:href 现在会被净化，标签名在编译器、运行时和 i18n 之间归一化，因此请审查自定义命名空间的模板。

  • 测试与 DI API 调整 — @Service 现已稳定（8f3d0b9d97、7aad302c3e），injectAsync 登场（444b024d49），ApplicationRef 可带 config bootstrap（a0aa8304cd）。请为两项测试变更做规划：TestBed.getFixture 重命名为 getLastFixture（dc3131c639），Testability 的稳定性现在以 PendingTasks 为准（9f479ae964），这可能改变异步测试的时序和不稳定性。

重大变更

编译器

  • 此更改将触发现有项目的 nullishCoalescingNotNullable 和 optionalChainNotNullable 诊断。 您可能想暂时禁用 tsconfig 中的这 2 个诊断。
  • 数据前缀属性不再绑定输入或输出。
  • 当输入、输出或模型绑定到相同的输入/输出时，编译器将抛出异常。
  • in 变量将抛出模板表达式。

编译器-cli

  • 具有多个匹配选择器的元素现在将在编译时抛出。 ###核心
  • appRef.bootstrap 的第二个参数不再接受 any。确保您传递的元素不可为空。
    • 不再支持早于 6.0 的 TypeScript 版本。
  • 离开动画不再局限于被删除的元素。
  • 未定义 changeDetection 属性的组件现在默认为 OnPush。指定 changeDetection: ChangeDetectionStrategy.Eager 以保留以前的行为。
  • 更改AnimationCallbackEvent.animationComplete签名
  • ChangeDetectorRef.checkNoChanges 已被删除。在测试中使用 fixture.detectChanges() 代替。
  • createNgModuleRef 被删除，使用 createNgModule 代替
  • ComponentFactoryResolver 和 ComponentFactory 不再可用。将组件类直接传递给以前需要工厂的 API，例如 ViewContainerRef.createComponent 或使用独立的 createComponentFunction。
  • ComponentFactoryResolver 和 ComponentFactory 不再可用。将组件类直接传递给以前需要工厂的 API，例如 ViewContainerRef.createComponent 或使用独立的 createComponent 函数。
  • 如果流/可观察同步返回值，stream Resource（包括 rxResource）现在正在同步解析该值。这可能会破坏一些假设值异步解析的测试。

表格

  • 不再支持min和max验证规则 字符串值。绑定值必须是数字或 null。

http

  • 如果您想继续支持上传进度报告，请使用 HttpXhrBackend 和 provideHttpClient(withXhr)。

平台浏览器

  • 当关联的 host 似乎不再使用样式时，这会删除样式。然而，如果不利用 ViewEncapsulation.Emulated 或者这些样式被 Angular 之外的元素使用，页面上的其他 DOM 仍可能会受到这些样式的影响，从而可能导致其他 DOM 显示为无样式。
  • Hammer.js 集成已被删除。使用您自己的实现。 ###路由器
  • TitleStrategy.getResolvedTitleForRoute 的返回类型 以前是“any”，而实际返回类型只能是 string 或undefined。返回类型现在可以正确反映可能的值。 读取该值的代码可能需要调整。 （从提交 ad37f52c1212164c51ffcc533067af05c2c33c89 中挑选的樱桃）
  • 现在需要 CanMatchFn 中的 currentSnapshot 参数和 CanMatch 接口的 canMatch 方法。虽然这已经是路由器在运行时的行为，但 CanMatch 的现有类实现现在必须包含第三个参数才能满足该接口。
  • paramsInheritanceStrategy 现在默认为“始终” paramsInheritanceStrategy 的默认值已从“emptyOnly”更改为“always”。这意味着默认情况下，路由参数继承自所有父路由。要恢复以前的行为，请在路由器配置中将 paramsInheritanceStrategy 设置为“emptyOnly”。
  • provideRoutes() 已被删除。如有必要，请使用 provideRouter() 或 ROUTES 作为多令牌。 ###升级
  • 已弃用的 getAngularLib/setAngularLib 已被删除，使用 getAngularJSGlobal/setAngularJSGlobal 代替。

弃用

http

  • withFetch 现已弃用，可以安全删除。
  • reportProgress 选项已弃用，请使用 reportUploadProgress 和 reportDownloadProgress 代替。
