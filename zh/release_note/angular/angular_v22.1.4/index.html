angular v22.1.4

修订 发布时间2026年8月27日 来源angular/angular 英文原文

angular v22.1.4

变更流程图

亮点

  • 原型污染加固 — common 与 core 中一组协同修复（60a874c3fb、3da35cbab9、7c752d4815）封堵了可能与 Object.prototype 成员（constructor、__proto__、toString）冲突的查找表和 TransferState 合并。这是对 SSR 应用影响最大的变更：序列化状态在水合时再也无法遮蔽原型成员，兼顾正确性与安全性。无 API 变更，但值得审查你写入 TransferState、恰好用了这些名字的自定义键——它们此前只是”碰巧能用”。

  • 可操作的 hydration 错误 — 7546b7a805 把水合/渲染找不到预期 DOM 节点时的硬崩溃，替换为带错误码的 RuntimeError。不匹配调试体验大幅改善：不再是不透明的堆栈跟踪，而是一个可查的稳定错误码。升级后请留意日志里出现这些错误——此前静默的 DOM 漂移现在可能被上报，请把新的 hydration 错误当作检查服务端/客户端标记是否一致的信号。

  • 模板类型检查与诊断 — 三处 compiler-cli 修复：修正可选链的 type-check-block 表达式（079a846263），诊断的 “related message” 源文件现在指向 .html 模板而非生成的 .ts（afe8499a14），并为 strict standalone 错误保留元数据（55eeb46418）。净效果是更少的误报，以及你真正能跳转过去的错误位置——对运行 strictTemplates 或 strict standalone 模式的项目最重要。

  • i18n 应用更安全的升级路径 — standalone bootstrap 迁移不再丢弃 registerLocaleData 调用（85c8829ac1），因此非英文应用可以迁移而不静默丢失 locale 注册——这种失败此前只在运行时的日期/数字管道才暴露。搭配 platform-server 在 URL 解析时不再剥离 unicode 空白（71e52d1396），此补丁让国际化和 SSR 应用的升级路径显著更安全。

  • 区域感知的 NaN 格式化 — e8378dfeab 让数字格式化输出 locale 的 NaN 符号，而非硬编码的那个。这是一个小但可观察的行为变更：在非 en locale 下期望字面字符串 NaN 的快照测试或断言可能需要更新。

  • JIT、动态组件与工具打磨 — b199bdfa2a 在 JIT 模式下显式拒绝外来组件，9a8e4826b9 为动态组件宿主保留命名空间，收紧组件身份相关的正确性；05c7c725a5 为压缩后的嵌套规则中声明的动画限定作用域，使动画作用域在压缩后依然有效。最后，语言服务现在遵循生成 import 的引号风格偏好（93d7f718d2），表单对 readonly 规则配置改用点访问（c8eb7f0056）——这些是人机工效修复，而非行为变更。

无破坏性变更。
