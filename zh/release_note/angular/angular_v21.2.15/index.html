angular v21.2.15

这个项目是干啥的：谷歌出的前端框架，帮程序员用组件化方式搭网页和应用，这次主要修了编译器与模板里的毛病，适合做大型网站的团队。

变更架构图

亮点

  • SVG 命名空间净化（#68925） — 编译器与 core 协同修复，堵上了带命名空间 SVG 的净化器白名单逃逸：SVG <a> 上的动态 href/xlink:href 现在会被净化，带命名空间的 <script> 在模板编译期被剥离，而带命名空间的 <style> 则有意保留。标签名在 DomElementSchemaRegistry 中做了归一化，DOM schema 查找不再区分前缀，core 的运行时净化 schema 也与编译器同步。为什么重要：带前缀的 SVG 模板再也无法绕过净化器；依赖带命名空间 script/style 标签的历史模板现在会被清理。

  • i18n 安全上下文（#68925） — 运行时 i18n 属性安全上下文查找现在会归一化标签名，并新增编译期 i18n 属性校验与之对齐。为什么重要：自定义或带命名空间标签上的翻译绑定，在 AOT 与 JIT 下会按同一上下文校验，堵上了可能让不安全属性值蒙混过关的编译期/运行时差异。

  • TransferCache 跳过带凭证的请求 — withCredentials 调用和带 cookie 的请求现在默认被排除在 SSR 传输缓存之外（582a417bd2、5c6d6df34b）。为什么重要：带认证的响应不会再被序列化进发给客户端的 HTML 载荷；这些请求在水合时会走客户端重新拉取，而非复用传输状态，请为此预留额外的往返开销。

  • SSR SSRF 加固 — platform-server 封堵了通过反斜杠 URL 绕过 HttpClient 的 SSRF（37e8aadf87），并加固了 location/document 的初始化以抵御 SSRF 与路径劫持（72696e244e）。为什么重要：服务端渲染代码里由用户控制的 URL 或路径此前可能触达内网端点；过去能通过的输入现在可能被拒，请审查代理与白名单逻辑。

  • Service worker fetch 语义 — 资源组请求现在会遵守显式的 credentials: 'omit'（b8bd49341d）并保留配置的 HTTP 缓存模式（ca32fc1000），而不再覆盖它们。为什么重要：SW 的缓存与凭证行为变得可预测；如果你依赖隐式的凭证升级或默认缓存模式，请复查 assetGroups 配置。

  • 破坏性变更 — 无；这是补丁级别的加固版本（另含对 digitsInfo 边界与占位符净化的 minor common 修复），无需任何迁移步骤。
