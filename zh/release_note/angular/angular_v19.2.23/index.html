angular v19.2.23

变更流程图

亮点

  • 更严格的 SVG 与 script 宿主校验 — 带命名空间的 SVG <script> 元素在编译期被剥离，SVG 链接上的动态 href/xlink:href 绑定被净化，<script> 作为动态组件宿主被拒绝。请把基于 script 的宿主换成普通元素；绑定不受信任 SVG URL 的应用应校验允许的 scheme。
  • 一致的 DOM schema 与更早的 i18n 校验 — 编译器和运行时的净化 schema 已同步，DOM 查找不再区分前缀，meta 选择器被净化，i18n 属性获得编译期校验。自定义元素和命名空间模板的行为应一致，而无效的 i18n 属性现在可能在构建更早阶段失败。
  • 带凭据的 HTTP 响应绕过 TransferCache — 含 Cookie 的请求默认被跳过，使用 withCredentials 的请求被完全排除。这降低了已认证的 SSR 响应被不当重放的风险，但依赖认证的应用可能看到更少的缓存命中和 hydration 后更多请求。
  • SSR location 初始化加固 — ServerPlatformLocation 规范化路径解析，并保护 location/document 设置免受 SSRF 和路径劫持。请对请求派生的导航、重定向、自定义 base-href 处理和非根部署做回归测试，尤其是在代理之后。
  • Service worker 请求保留显式 fetch 策略 — 重建的资产请求现在保留重定向处理、credentials: 'omit' 和 HTTP 缓存模式。PWA 应用应重测已认证资产、自定义缓存策略和跨域重定向，确保 service worker 重建不再覆盖预期行为。
  • 输入与 i18n 边界情况收紧 — digitsInfo 现在强制上限，占位符被净化，动态 i18n 元素属性更新限定在活动的索引状态。请检查具有极端数字格式设置和本地化动态属性的应用是否有校验或渲染行为变化。
