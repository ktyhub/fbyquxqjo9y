angular v22.1.3

这个项目是干啥的：谷歌出的前端框架，帮程序员用组件化方式搭网页和应用，这次主要修了编译器与模板里的毛病，适合做大型网站的团队。

变更架构图

亮点

  • 生产环境中 DOM 与水合失败更易诊断 — 水合现在对意外节点类型抛 NG0500、对缺失节点抛 NG0502，而不再抛原始 TypeError（#69981、#70199）；过期的 insertBefore 引用现在产生 NG05106，而不是晦涩的 NotFoundError（#70186）。请更新错误监控的映射，但要修的是底层 DOM 或模板的不匹配，而不是把这些错误压掉。

  • 视图销毁后停止 effect 刷新 — 如果某个 effect 销毁了自己的视图，Angular 现在会跳过该次刷新中剩余的 effect，避免针对已销毁的状态继续执行，以及因 effects 列表为 null 而崩溃（#65698）。请在销毁视图之前注册 onCleanup()；之后再注册的清理回调不再保证会执行。

  • 超大 fetch 响应会释放连接 — 当声明的 Content-Length 超过 maxResponseSize 时，FetchBackend 会在抛出 NG02825 前先取消未读取的响应体（#70210）。这避免了拒绝之后 SSR 连接 lingering 残留，同时不改变错误契约。

  • 命名 outlet 的停用守卫收到真实组件 — 对位于无组件父路由下的命名 outlet，canDeactivate 此前收到的是 null；现在 outlet 上下文会按子路由解析，并在组件边界间正确切换（#69591，修复 #34614）。请重新测试依赖组件身份的”未保存更改”守卫。

  • 表单与元数据校验更严格 — [formField] 现在在编译期报告不支持的双向绑定（#70220）；当 ngModel 跨组件边界找不到父 NgForm 时，开发模式会发出 NG01354，提示使用 viewProviders 或 standalone: true（#69585）；Meta.addTag()/updateTag() 会拒绝 on* 属性并报 NG05203（#70127）。请审查动态 meta 定义，把事件行为移出内联属性。

  • 类型与模板保真修复，免去权宜之计 — KeyValuePipe.transform() 保留字面量键的联合类型，而不再拓宽成 string（#70200），生成的装饰器反射元数据接受只读数组和元组，编译器在无关的兄弟控制流块之间保留 &ngsp;（#69583）。用到类型的管道消费者可以去掉类型断言，受影响的模板也避免了空格回归。
