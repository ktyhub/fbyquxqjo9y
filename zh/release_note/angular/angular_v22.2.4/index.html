angular v22.2.4

这个项目是干啥的：谷歌出的前端框架，帮程序员用组件化方式搭网页和应用，这次主要修了编译器与模板里的毛病，适合做大型网站的团队。

变更架构图

亮点

  • 新增 ngClass 迁移 — 本补丁唯一的新功能（6c631a5359）增加了一条 ng update 迁移，把静态字符串和数组的 ngClass 绑定改写为原生 class 绑定。请把它理解为一个方向性信号：Angular 现在希望静态或静态组合的值用 class，把 ngClass 留给动态对象映射。运行该迁移并检查输出，但注意它有意跳过动态对象绑定——如果想彻底去掉该指令，这些仍需手动改写。

  • pre-v22 库的 JIT 变更检测翻转 — 在 JIT 模式（开发构建、测试、playground）下，v22 之前编译的库现在默认采用 Eager 变更检测（1a7ebad7a5），而非先前的行为。这是开发/JIT 与 AOT 的一致性变更：从较旧包引入的组件可能检查得频繁得多，并暴露此前被掩盖的时序敏感问题。如果升级后遇到只在测试或开发环境出现的渲染差异，请从这里查起——本补丁未提及任何退出 flag。

  • i18n 与水合获得生产级加固 — 一组密集的核心修复针对 SSR/i18n 正确性：共享 ICU case 队列不再在水合期间被修改（570679134b），每个属性翻译都会扫描 ICU（b8102ebeb4），增加整数溢出防护（57ae1d1bb6），ICU 表达式内的绑定获得更清晰的警告（84a398bec2）。另有两处修复阻止与 constructor/toString 这类原型命名键的冲突——一处在编译器（bc600a2fc2），一处在 getTransferState（be85e4eb74）。本地化 SSR 应用将受益于更少的水合不匹配和更少的传输状态损坏；两项性能改动还让 i18n 断言和调试名读取不进入生产环境（e79a9199a5、c1b8b0a914）。

  • 路由的 Navigation API 集成趋于稳定 — 对启用浏览器 Navigation API 的应用，本补丁消除了若干痛点：下载不再被拦截（6ccbb0f6aa），traversal 导航期间重定向可用（b8383a1987），守卫抛出 RedirectCommand 时遵守守卫顺序（2f0e2ac5e7）——与鉴权重定向链直接相关。另修复：routerLinkActive 清除过期类（702ba3a2eb），outlet 停用时取消订阅路由数据（6c995a5a6d），以及若干 URL 序列化边界情况（d1da1a7c4c、12b553bc28、ea8cdc4c6b）。

  • 表单与资源收紧校验 — Signal 表单现在拒绝 SignalFormControl 中不支持的 updateOn 值（122663145b），不再静默接受，所以此前宽松的配置会抛错——升级时请审查 signal 表单定义。formControlName 找不到匹配控件时不再崩溃（41b189752e）。响应式方面，参数未变时 resource() 避免重复加载（fe02c34c3c），减少数据驱动视图中不必要的重新获取。

  • 构建工具链与混合应用修复 — compiler-cli 现在要求 @jridgewell/sourcemap-codec ≥ 1.6.0（4b82200c4e）；固定较旧的传递版本会破坏构建，直到更新为止。HTTP 缓存会考虑多个 Cache-Control 头（2251098d52），语言服务能解析受限访问的 input（646e9723db），upgrade 只编译降级组件的模板内容（ecaec13db4）——对 AngularJS/Angular 混合应用值得注意。

本版本无破坏性变更。
