ktransformers v0.6.3

KTransformers：MiniMax-M3 和 GLM-5.2 Day0 支持

我们很高兴地宣布 Day0 支持两个新的大型 MoE 模型：KTransformers + SGLang (sglang-kt) 中的 MiniMax-M3 和 GLM-5.2。这两种模型现在都可通过 kt-kernel 进行 CPU-GPU 异构推理。此更新还提供了为 Qwen3.5 MoE 提供服务的端到端 KT LoRA。

🚀 核心亮点

  • MiniMax-M3 Day0 支持：对 MiniMax 的 128 路由专家稀疏 MoE 架构 (MiniMaxAI/MiniMax-M3-MXFP8) 的全面推理支持。在单个 96 GB GPU 上运行，或通过 kt-kernel CPU 专家卸载扩展至 8 个 GPU。
  • GLM-5.2 Day0 支持：对智普 AI 的 GLM-5.2（zai-org/GLM-5.2、zai-org/GLM-5.2-FP8）的全面推理支持，具有 FP8 和 BF16 精度、NSA 注意力后端以及通过 kt-kernel 的动态专家更新。
  • KT LoRA 服务：端到端 Qwen3.5 MoE KT LoRA 服务工作流程 — 使用 KT SFT 进行训练，转换一次，通过 SGLang 使用单个合并适配器路径提供服务。

📌 KT LoRA 服务于 Qwen3.5 MoE

与 KT 专家 LoRA 一起为 Qwen3.5 MoE 提供新的端到端微调服务工作流程：

  • 统一适配器管道：KT SFT 原始输出 → convert_kt_to_sglang_adapter.py → 合并适配器目录 → SGLang --lora-paths 服务。
  • 专家+非专家LoRA：服务器内部自动分割专家和非专家LoRA权重；用户提供单个合并适配器路径。
  • SFT 内核改进：重构 AMX SFT MoE 内核、AVX2 MoE 基础更新和张量并行 MoE SFT 助手。
  • 文档：KT-FT 微调和推理循环（EN） | 中文

📌 GLM-5.2

GLM-5.2是智普AI最新推出的带有NSA（Native Sparse Attention）的MoE模型。 KTransformers 支持它：

  • FP8 和 BF16 精度：支持 zai-org/GLM-5.2-FP8 和 zai-org/GLM-5.2。
  • NSA 注意力后端：用于 DSA 层的带有 Skip_topk 门控索引器的原生稀疏注意力。
  • 动态专家更新：--kt-enable-dynamic-expert-update 具有统一的放置策略。
  • 工具调用和推理：glm47 工具调用解析器和 glm45 推理解析器。 👉 完整教程

📌MiniMax-M3

MiniMax-M3 是一款 128 专家稀疏 MoE 模型，以 MXFP8（fp8 e4m3 + uint8 ue8m0 1×32 规模）原生交付。 KTransformers 支持 M3 端到端：

  • KT-Kernel 混合：CPU 专家卸载，具有 MXFP8 字节复制和 GPU 影子 FP8 视图；在 8×H20 和单 H20 上进行验证。
  • MXFP8：通过 Triton MoE 后端在 Hopper GPU 上直接进行 MXFP8 推理路径。
  • 工具调用：minimax-m3 函数调用解析器（原生 <minimax:tool_call> XML → OpenAI tool_calls 数组）。
  • 思考模式：通过 chat_template_kwargs.thinking_mode — enabled / disabled / adaptive 进行请求级控制。 👉 完整教程

📥 安装

# Option A: One-click install (from ktransformers root)
git clone https://github.com/kvcache-ai/ktransformers.git
cd ktransformers
git submodule update --init --recursive
cd kt-kernel && ./install.sh
cd .. && ./install.sh

# Option B: pip install
pip install sglang-kt
pip install kt-kernel

需要 CUDA 12.0+；建议将 CUDA 12.8+ 用于 FP8/MXFP8 部署。
