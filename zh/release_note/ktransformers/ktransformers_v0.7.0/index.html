ktransformers v0.7.0

小版本 发布时间2026年8月17日 来源kvcache-ai/ktransformers 英文原文

ktransformers v0.7.0

这个项目是干啥的：一个让普通电脑也能跑 DeepSeek 这类超大模型的推理加速框架，巧用 CPU 加显卡分工来提速省显存，给只有一台机器却想跑大模型的开发者用。

KTransformers v0.7.0：支持全面微调和AMD CPU（AVX512）微调！

KTransformers v0.7.0 为大型 MoE 模型带来了更广泛的硬件兼容性和新的微调功能。此版本主要有五项改进。

变更架构图

亮点

1. AVX512 全面支持 LoRA 微调

KTransformers LoRA 微调现在完全支持兼容的 AVX512 x86 CPU，无需 AMX。 运行时自动选择合适的CPU实现，允许MoE专家训练在更广泛的大内存服务器上运行。

kt_config:
  kt_backend: auto

auto 是 AMX 和 AVX512 平台的推荐设置。 相关更改：#2141

2. 原生 FP8 LoRA 支持

KTransformers 现在支持 DeepSeek-V3.1 的本机 FP8 LoRA 微调。 原始的逐块 E4M3 路由专家权重和比例直接从检查点加载，无需在训练前具体化完整的 BF16 副本。 在测试的 DeepSeek-V3.1 配置中，主机内存要求从使用 BF16 扩展的大约 1.4 TB 减少到大约 800 GB。 相关更改：#2141

3. Qwen VLM MoE 微调支持

KTransformers 现在支持通过 LLaMA-Factory 对 Qwen3-VL MoE 模型进行 LoRA 微调。 该集成处理 Qwen3-VL 的嵌套语言模型层、融合专家权重布局和视觉补丁嵌入，使多模态数据能够完成分布式前向和后向传递、优化器更新和检查点保存。 兼容性路径的范围仅限于支持的 Qwen VLM 模型类型，并且不会更改现有的纯文本训练路径。 相关更改：#2156

4. DeepSeek V4 Docker 快速部署

此版本添加并扩展了 DeepSeek V4 Flash Docker 部署指南。 用户可以通过标准化的 Docker 工作流程启动 DeepSeek V4 环境，而无需手动配置完整的构建和运行时堆栈。

5.CPU激活重用

高级用户现在可以在激活检查点重新计算期间保留 CPU 专家激活，从而减少重复的 CPU 计算并提高训练吞吐量。 当有足够的主机内存可用时，在训练 YAML 中启用它：

kt_cpu_activation: retain

不设置此选项将保留默认的重新计算行为。激活重用会牺牲额外的 CPU 内存来减少重新计算。 相关更改：#2141

发布验证

发布回归涵盖：

  • 两个 GPU 上的 Qwen3.5-397B-A17B BF16 LoRA
  • 四颗 GPU 上的 DeepSeek-V3.1 原生 FP8 LoRA
  • Qwen3-VL-30B-A3B-使用 FSDP2 指导 BF16 LoRA，包括多模式预处理和检查点保存
  • 有限的训练损失
  • 非零LoRA参数更新
  • 分布式 FSDP2 执行
  • FP8 加载、TP 分段、检查点和适配器生命周期测试

安装

pip install "ktransformers[sft]==0.7.0"

匹配的SFT集成包：

  • transformers-kt==5.6.0.post2
  • accelerate-kt==1.14.0.post2
