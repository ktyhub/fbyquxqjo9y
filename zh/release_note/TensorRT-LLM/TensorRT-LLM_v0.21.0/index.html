TensorRT-LLM v0.21.0

TensorRT-LLM 发布 0.21.0

主要功能和增强功能

  • 模型支持
    • 添加了 Gemma3 VLM 支持
  • 特点
    • 增加了大规模EP支持
    • 将 NIXL 集成到分类服务的通信层中
    • 添加了对 KV 缓存传输的结构内存支持
    • 在 ScaffoldingLLM 中添加了 MCP
    • 添加了对 w4a8_mxfp4_fp8 量化的支持
    • 添加了对 fp8 行量化的支持
    • 在 TRTLLM Sampler 中添加了生成 logits 支持
    • 在 TRTLLM 采样器中添加了日志概率支持
    • 优化的 TRTLLM 采样器性能单光束单步
    • 为 Qwen-3 启用分类服务
    • 添加了对 Qwen-3 的 EAGLE3 支持
    • Qwen-MoE 模型的融合最终确定和全部归约
    • 重构Fused MoE模块
    • 添加了对 Blackwell 和 Hopper 的分块注意力的支持
    • 在 Blackwell 的生成阶段引入了滑动窗口注意内核
    • 更新了 DeepSeek FP8 TRT-LLM Gen cubins，以提高大批量场景中的性能
    • 在 SM89 上添加了 FP8 块级 GEMM 支持
    • 启用前锋之间的重叠调度程序
    • 添加了对 MLA 的分段 cuda 图支持
    • 添加了与模型无关的单引擎 eagle3
    • 启用 Finalize + Allreduce + add + rmsnorm fusion
    • 集成 TRT-LLM Gen FP8 块级 MoE 与 Pytorch 工作流程内核自动调节器
    • 添加了对 Eagle3 + 在两个模型推测解码流程中的分解服务的支持
    • 在 H200 NVL 上验证 Llama 3.1 型号
  • 基准：
    • 添加了 all_reduce.py 基准脚本用于测试
    • 向 trtllm-bench 延迟命令添加了波束宽度
    • 修复了 trtllm-bench iter_stats 和 cuda_graph_batch_sizes 错误
    • 启用 trtllm-bench 来运行 LoRA 并为 LoRA 添加基本的 e2e 性能测试功能
    • 支持工作台的 post_proc
    • 添加了 no_kv_cache_reuse 选项和对 trtllm 服务台的流支持

基础设施变化

  • TensorRT-LLM 的基础 Docker 映像已更新为 nvcr.io/nvidia/pytorch:25.05-py3。
  • TensorRT-LLM 后端的基本 Docker 映像已更新为 nvcr.io/nvidia/tritonserver:25.05-py3。
  • 依赖的公共 PyTorch 版本更新为 2.7.1。
  • 依赖的 TensorRT 版本更新为 10.11。
  • 依赖的NVIDIA ModelOpt版本更新为0.31。
  • 依赖的NCCL版本更新为2.27.5。

API 变化

  • 将 _AutoDeployLlmArgs 设置为主要配置对象
  • 从解码器接口中删除了解码器请求
  • 增强了 llm args 中的 torch_compile_config
  • 从 PytorchConfig 中删除了冗余的 use_kv_cache 字段
  • 将 allreduce_strategy 从提交的 api 移至参考

已修复的问题

  • 修复了启用 MNNVL 两次 AllReduce 时分类服务挂起的问题 (#4678)
  • 修复了具有 MTP 层和按 EP 等级进行路由偏移的 EP 负载均衡器 (#4767)
  • 修复了规范解码的 cuda 图填充 (#4853)
  • 修复了 llama 4 长上下文问题 (#4809)
  • 修复了重叠调度的 max_num_sequences 计算 (#4532)
  • 修复了分块预填充+重叠调度（#5761）
  • 修复了由于 LLM API IPC 导致的 trtllm-bench 挂起问题 (#4798)
  • 修复了规范解码中的索引越界错误 (#5954)
  • 修复了 cuda 图预热中的 MTP 非法内存访问 (#5947)
  • 修复了规范解码 + disagg 没有可用插槽的错误 (#5975)
  • 修复了 Gemma3 1B 的一次性注意窗口大小（#5564）

已知问题

  • 准确性/test_cli_flow::TestGpt2::test_beam_search_large 已损坏。
  • 同时启用分类服务、MTP 和重叠调度程序可能会导致准确性问题。
  • 在 0.21 中，添加了完整的分块注意力支持，以确保 LLaMA4 模型可以在 > 8K seq 长度的情况下正常运行，而由于此功能增强，Hopper 上存在已知的性能回归（仅影响 LLaMA4 模型）。回归的根本原因已经确定，修复将成为未来版本的一部分。
