TensorRT-LLM v0.17.0

小版本 发布时间2025年2月7日 来源NVIDIA/TensorRT-LLM 英文原文

TensorRT-LLM v0.17.0

嗨， 我们非常高兴地发布 TensorRT-LLM 的 0.17.0 版本。本次更新包括：

主要功能和增强功能

  • 布莱克威尔支持
    • 注意：仅 Blackwell 平台上的 TRT-LLM 0.17 不支持 pip 安装。相反，建议用户使用 NVIDIA NGC 25.01 PyTorch 容器从源代码构建。
    • 添加了对 B200 的支持。
    • 添加了对使用 Windows Subsystem for Linux (WSL) 的有限型号的 GeForce RTX 50 系列的支持。
    • 添加了对 Llama 和 Mixtral 模型的 NVFP4 Gemm 支持。
    • 添加了对 LLM API 和 trtllm-bench 命令的 NVFP4 支持。
    • 不完全支持 GB200 NVL。
    • 添加了基准脚本来衡量 KV 缓存主机卸载的性能优势以及 GH200 的预期运行时改进。
  • PyTorch 工作流程
    • PyTorch 工作流程是 tensorrt_llm._torch 中的实验性功能。以下是可与 PyTorch 工作流程一起使用的受支持基础架构、模型和功能的列表。
    • 添加了对 H100/H200/B200 的支持。
    • 添加了对 Llama 模型、Mixtral、QWen、Vila 的支持。
    • 添加了对 FP16/BF16/FP8/NVFP4 Gemm 和融合 Mixture-Of-Experts (MOE)、FP16/BF16/FP8 KVCache 的支持。
    • 通过 PyTorch 自定义操作添加了自定义上下文和解码注意内核支持。
    • 添加了对分块上下文的支持（默认关闭）。
    • 添加了仅对解码的 CudaGraph 支持。
    • 添加了重叠调度程序支持，以通过解码 1 个额外令牌来重叠准备输入和模型转发。
  • 添加了对 W4A8 量化工作流程的 FP8 上下文 FMHA 支持。
  • 添加了对 LLM API 的 ModelOpt 量化检查点支持。
  • 添加了对 Llama-3.2 VLM 模型的 FP8 支持。请参阅 examples/multimodal/README.md 中的“MLLaMA”部分。
  • 添加了对基于 userbuffer 的 AllReduce-Norm 融合内核的 PDL 支持。
  • 添加了对无缝前瞻解码的运行时支持。
  • 添加了对 C++ executor API 的标记对齐任意输出张量支持。

API 变化

  • [重大变更] 启用 paged_context_fmha 时，会自动启用 KV 缓存重用。
  • 添加了对 trtllm-bench 的 throughput 子命令的 --concurrency 支持。

已修复的问题

  • 修复了不正确的 LoRA 输出尺寸。感谢 @akhoroshev 在 #2484 中的贡献。
  • 将 NVIDIA H200 GPU 添加到 cluster_key 中以实现自动并行功能。 (#2552)
  • 修复了 LLmArgs 类的 __post_init__ 函数中的拼写错误。感谢 @topenkoff 在 #2691 中的贡献。
  • 修复了 GPT 注意插件中的工作区大小问题。感谢@AIDC-AI 的贡献。
  • 修复了 Deepseek-V2 模型的准确性。

基础设施变化

  • TensorRT-LLM 的基础 Docker 映像已更新为 nvcr.io/nvidia/pytorch:25.01-py3。
  • TensorRT-LLM 后端的基本 Docker 映像已更新为 nvcr.io/nvidia/tritonserver:25.01-py3。
  • 依赖的 TensorRT 版本更新为 10.8.0。
  • 依赖的CUDA版本更新为12.8.0。
  • Linux 平台依赖的 ModelOpt 版本更新为 0.23，Windows 平台仍使用 0.17。

已知问题

  • 由于新的第三方依赖项，运行 pip install tensorrt-llm 时需要 --extra-index-url https://pypi.nvidia.com。
  • 由于 PyTorch ABI/API 中断，PYPI SBSA 轮子与 PyTorch 2.5.1 不兼容，如相关 GitHub 问题 中详述。
