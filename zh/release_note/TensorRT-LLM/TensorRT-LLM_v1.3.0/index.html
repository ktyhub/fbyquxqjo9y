TensorRT-LLM v1.3.0

小版本 发布时间2026年11月20日 来源NVIDIA/TensorRT-LLM 英文原文

TensorRT-LLM v1.3.0

主要功能和增强功能

  • Rubin 支持（预览版）
    • 添加了对 NVIDIA Rubin (SM107) 的预览支持，并在 Vera Rubin 上进行了验证。
    • 添加了对 Vera Rubin 的 DeepSeek-V4 和 Kimi K3 支持。
  • 模型支持
    • 添加了对 Blackwell 和 Rubin 的 DeepSeek-V4 支持（预览版）。
    • 添加了对 Blackwell 和 Rubin（预览版）的 Kimi K3 支持，包括多模式和多节点服务。注意力数据并行性（DEP16）需要 GB300 级 GPU 内存。
    • 添加了对 Hopper、Blackwell 和 Rubin（预览版）的 Qwen3.5 支持，包括 Blackwell 上的 MTP 和 NVFP4，以及 Blackwell 上的 Qwen3.6 和 Qwen3.8-Flash-Next 支持。
    • 添加了对 Blackwell 和 Rubin 的 MiniMax-M3 支持（预览版）。
    • 添加了 Blackwell 上的 GLM-5、GLM-5.2、Kimi-K2.5 和 Step-3.7-Flash 支持。
    • 添加了对 Hopper 和 Blackwell 的 Nemotron Nano Omni 支持。
    • 添加了对 Blackwell 的 Gemma 4 支持，包括多模式。
    • 添加了对 Hopper 和 Blackwell 的 Laguna 支持。
    • 添加了 Mamba 混合模型的前缀缓存，例如 Qwen3.5 和 Nemotron Super V3。
  • 特点
    • 性能：
      • 使用特定于模型的内核融合优化了 DeepSeek-V4、DeepSeek-V3.2、Qwen3.5、Gemma 4、MiniMax-M3 和 Kimi K3。
      • 在 Rubin 上添加了 NVFP4 MoE 的位置域 (uGPU) 本地化，从而使内存流量保持在每个 GPU 芯片的本地。默认启用；设置 DISABLE_LOCALITY_DOMAINS=1 以禁用它。
      • 通过异步预处理和无同步波束搜索减少主机开销，并通过检查点预读减少启动时间。
      • 为 SM10x 添加了级联注意力和低 M BF16 GEMM 调度。
    • 分类服务：
      • 添加了gen-first调度、对话关联路由、波束搜索和混合模型支持。
      • 添加了 Qwen3.8-Flash-Next 的分类服务。
    • 推测性解码：
      • 添加了 DSpark、DFlash、Suffix Automaton 和 PARD 起草器。
      • 添加了 EAGLE3 动态树、Eagle 3.1 草案模型和 LoRA 推测解码。
      • 为单模型路径添加了拒绝采样，并为动态推测添加了基于接受率的自动禁用功能。
      • 添加了从独立检查点加载 MTP 权重。
    • 并行性和 MoE：
      • 添加了 DWDP（分布式权重数据并行）、扩展的 Helix 上下文并行和 KV 缓存感知注意力 DP 路由器。
      • 添加了 DENSEGEMM、MEGAMOE_DEEPGEMM、MEGAMOE_CUTEDSL、CUTEDSL_FC12（仅限 Rubin）和 MARLIN MoE 后端。
      • 添加了 NCCL-EP 后端并支持多达 2048 名专家。
      • 添加了路由器重播 (return_routed_experts) 以返回每个令牌 MoE 路由以进行 RL 训练。
    • KV 缓存：
      • KV 缓存管理器 V2 根据型号进行选择，并且默认情况下对大多数型号系列启用。
      • 添加了 KV 缓存压缩（TriAttention 和 NVFP4 冷页压缩）、NVFP4 KV 缓存和磁盘缓存。
      • 添加了每个对话块的重用和精确的多模式 KV 块哈希。
      • 添加了 FlexKV 和 LMCache 连接器。
    • 量化：
      • 添加了 MXFP8 (W8A8) 线性和 MoE 支持，包括 MXFP8 检查点，例如 MiniMax-M3。
      • 通过 Marlin 添加了 W4A16 NVFP4 仅重量量化，因此 NVFP4 检查点在 Hopper 和 Ada Lovelace 上运行。
      • 添加了可调谐 NVFP4 量化。
      • 添加了对旧版和 ModelOpt 1.x 量化配置格式的支持。
  • **稀疏注意力：**添加了 DSA FP4/FP8 解码内核、GVR Top-K、Skip Softmax Attention（在 Rubin 上具有可选的 2:4 激活稀疏性）和 MiniMax-M3 MSA。
    • 服务和 API：
      • 添加了人择消息 API (/v1/messages) 并扩展了响应 API。
      • 添加了 gRPC 服务器和多进程 HTTP 前端。
      • 将每个请求的 priority 和命名函数 tool_choice 添加到 OpenAI 兼容的 API 中。
      • 添加了 auto 工具和推理解析器选择，以及 GLM-4.7、GLM-5 和 Laguna 工具解析器。
      • 添加了 Prometheus 指标以及 /start_profile 和 /stop_profile 分析端点。
      • 添加了 trtllm-serve 选项 --served_model_name、--kv_cache_dtype 和 --middleware。
      • 添加了完成 API logprobs 和接受 parallel_tool_calls。
    • 采样和 LoRA：
      • 向 TorchSampler 添加了 min_p、bad_words、重复/频率/存在惩罚、全波束搜索选项和处理后的对数概率。
      • 添加了用于推理模型的实验性 thinking_token_budget。
      • 添加了带有 CUDA 图、每专家 MoE LoRA 和密集 FP8 LoRA 的多 LoRA 服务。
    • 其他：
      • 添加了默认启用的前缀感知调度，以避免共享前缀的重复预填充。
      • 添加了预填充和易碎的 CUDA Graph 支持，以及 TRTLLM 注意力后端中的自定义注意力蒙版。
      • 添加了多模态编码器缓存和多模态编码器的 CUDA 图。
      • 为 RL 工作流程添加了飞行重量更新。
      • 为仅编码器型号添加了 /v1/embeddings 和 llm.encode() 快速路径。
      • 添加了原型 ModelExpress 检查点加载。
  • 文档
    • **迁移指南：**添加了TensorRT后端删除迁移指南。
    • 部署指南： 添加了 GLM-5、Kimi K3、MiniMax-M3、Nemotron 3、Qwen3.8-Flash-Next 和 Qwen3.8/Qwen3.5 的部署指南。
    • 功能文档： 添加了 KV 缓存压缩、嵌入、ModelExpress、子代理路由和编码器-解码器模型的指南，并重构了安装指南。
    • 开发人员指南： 添加了稀疏注意力、KV 缓存压缩、遥测和自定义内核的指南。

视觉生成

VisualGen 是 TensorRT-LLM 中针对图像和视频生成模型的全新垂直解决方案。它通过 trtllm-serve 与 LLM 推理一起提供。有关详细信息，请参阅 [VisualGen 文档](models/visual- Generation.md)。

  • 型号
    • 添加了图像生成模型：FLUX.1、FLUX.2、GLM-Image 和 Qwen-Image，包括 Qwen-Image-Edit 和 Qwen-Image-Layered。
    • 新增视频生成型号：Wan 2.2（包括5B TI2V和FastWan）、LTX-2、HunyuanVideo ZZPH100​​ZZ、Cosmos3和MiniMax-H3。
  • 特点
    • 在trtllm-serve中添加了图像生成、图像编辑和视频生成端点。
    • 添加了张量、上下文和 CFG 并行性、NVFP4 和 FP8 量化、CUDA 图和运行时 LoRA。
    • 添加了 TeaCache 和 Cache-DiT 缓存、稀疏注意力以及 FlashAttention 4、FlashInfer 和 cuDNN 注意力后端。
    • 为 VisualGen 模型添加了 trtllm-eval 管道。
  • 文档
    • VisualGen 示例
    • 发表技术博客：
      • “使用 TensorRT-LLM 跨 NVL72 机架缩放视频生成”
      • “TensorRT-LLM 中使用 GEMM 量化、注意力量化和跳过 Softmax 注意力加速视频生成”
  • 已知问题
    • 由 NVIDIA 模型优化器静态量化和导出的 FLUX.1 检查点可能无法初始化，因为导出的转换器配置将 out_channels 设置为 null。

  • 依赖的 CUDA Toolkit 版本更新为 13.4.1。
  • 依赖的公共 PyTorch 版本更新为 2.14.0。
  • 支持 Python、3.10 和 3.12。

    • 上游公共 PyTorch：轮子托管在 PyPI 上。
    • NGC PyTorch 容器：轮子通过 https://pypi.nvidia.com/trtllm_ngcpytorch/. 释放
  • TensorRT、NVIDIA ModelOpt 和 ONNX 不再是 TensorRT-LLM 的依赖项。
  • 相关变压器版本更新为5.5.4。
  • 依赖的flashinfer-python版本更新为0.6.18。
  • 依赖的triton版本更新为3.8.0。
  • 依赖的NCCL版本更新为2.31.2。
  • 依赖的 NIXL 版本更新为 1.4.0。
  • 依赖的UCX版本更新为1.22。
  • 依赖的CUTLASS版本更新为4.4.2。
  • 依赖的xgrammar版本更新为0.1.32。
  • C++ 标准更新为 C++20。

API 变化

  • [重大变更] TensorRT 后端已删除。 PyTorch 是唯一的后端。 trtllm-build、TrtLlmArgs、BuildConfig、MedusaDecodingConfig、LookaheadDecodingConfig、trtllm-bench build 和 trtllm-bench --engine_dir 已删除。请参阅迁移指南。
  • [重大更改] 删除了旧版 C++ 执行器和运行时 API。 删除了 C++ Executor API、旧版运行时和批处理管理器 API 以及 cpp_only 构建选项。
  • [重大变更] TensorRT 引擎 Triton 后端模型已删除。 仅保留 llmapi Triton 模型。
  • [重大变更] TRTLLMSampler 已删除。 TorchSampler 需要 FlashInfer，是唯一的采样器。 sampler_type 参数将被忽略并出现警告，并且 disable_flashinfer_sampling 将被删除。
  • [重大变更] 删除了两种模型推测解码。 eagle3_one_model 和 mtp_eagle_one_model 字段被删除；使用单模型实现。
  • [重大变更] 删除了 AutoDeploy、Star Attention 和 WIDEEP。 AutoDeploy 和 Star Attention 已删除，并且无法再选择 WIDEEP MoE 后端。
  • [重大更改] CLI 标志覆盖 YAML 配置。 显式 trtllm-serve、trtllm-eval 和 trtllm-bench 标志现在优先于 YAML 配置值。
  • [重大更改] KV 缓存传输超时默认为 60 秒。 以前没有超时；用 cache_transceiver_config.kv_transfer_timeout_ms 设置它。
  • [重大变更] 按请求聊天模板是可选的。 使用 trtllm-serve --allow_request_chat_template 启用它们。
  • [重大变更] Logprobs 上限为 100。 较大的 logprobs 或 prompt_logprobs 值会提高 ValueError。
  • [重大更改] /perf_metrics 端点已删除。 请改用 X-TRTLLM-return-metrics: 1 请求标头。
  • [重大变更]重命名动态推测字段。 使用 acceptance_rate_window_size 和 acceptance_rate_threshold；现在的阈值是 [0, 1] 中的接受率。
  • [重大变更] 删除了过时的选项。 这包括 Eagle choices 和 trtllm-serve --fail_fast_on_attention_window_too_large。
  • NVFP4 冷页压缩默认情况下保持选择加入和禁用状态。当启用 DeepSeek-V4 时，NoPE 使用 NVFP4，而 RoPE 现在默认为 2FP4 (nvfp4_residual_dim=64)。设置 skip_rope_quantization=True 以使 RoPE 保持其原始精度，如以前一样，或设置 nvfp4_residual_dim=0 使用单个 NVFP4。活动 GPU KV 缓存数据类型未更改。请参阅NVFP4冷页压缩示例。
  • [弃用] TRITON MoE 后端（TritonFusedMoE、moe_config.backend="TRITON"）自 TensorRT-LLM 1.3 (2026-09) 起已弃用，并将在 3 个月的迁移期后删除。它唯一剩下的作用是为具有 W4A16_MXFP4 的 Hopper 上的 GPT-OSS 提供适度的性能优势 - 单一配置 AUTO 解析为 TRITON，并且 MXFP4 GPT-OSS 检查点采用 SM90 的格式。随着模型集和支持的平台不断增长，单一场景的 MoE 路径不再值得维护成本。 moe_config.backend="CUTLASS" 在 Hopper 上取代了它的功能：它为 SM90 上的 W4A16_MXFP4 以及未量化的 BF16 和 FP8 每张量路径提供服务，并且当 TRITON declines 层时，MoE 后端分辨率已经自动降级到它。在迁移期间，TRITON 继续工作并记录一次性警告。请参阅弃用政策。
  • [弃用] trtllm-serve 选项 --backend、--moe_cluster_parallel_size 和 --metrics-log-interval 以及 trtllm-eval 选项 --backend 已弃用。
  • [弃用] TorchCompileConfig.enable_piecewise_cuda_graph 和 capture_num_tokens、MTPDecodingConfig.num_nextn_predict_layers 和 perf_metrics_max_requests 已弃用。
  • [弃用] 不推荐使用没有 internal_request_auth_key 的分类服务。在分解的服务器配置和每个工作配置中设置相同的密钥。
  • 默认情况下，使用情况遥测处于启用状态。要选择退出，请设置 TRTLLM_NO_USAGE_STATS=1 或 DO_NOT_TRACK=1，将 --no-telemetry 传递给 CLI，或在 LLM API 中设置 telemetry_config=TelemetryConfig(disabled=True)。请参阅遥测指南。
  • GPT-OSS 默认为 Blackwell 上的 TRTLLM MoE 后端。
  • TorchCompileConfig.max_num_streams 现在默认为 3 而不是 1。

已修复的问题

  • 分类服务：
    • 修复了上下文管道并行性和生成张量并行性的挂起，这是 1.2 中的一个已知问题。
    • 修复了驱逐后块重用和仅生成异步 KV 传输的挂起问题。
    • 修正了一个等级导致所有世代等级崩溃的错误。
  • 注意：
    • 修复了 max_seq_len 超过 max_position_embeddings 时的非法内存访问。
    • 修复了 XQA 竞争条件、注意力接收器准确性和滑动窗口非法内存访问。
    • 修复了跳过 Softmax Attention 的 FP8 精度。
    • 修复了 DeepSeek-V3.2 使用 CUDA 图和主机 KV 缓存卸载进行非法内存访问的问题。
  • 推测解码： 修复了 Qwen3-235B-A22B NVFP4 上的 EAGLE3 崩溃问题以及 Hopper 上的 Nemotron Super 上的 MTP 崩溃问题。
  • KV 缓存： 修复了 VSWA 和块重用造成的精度损失，以及主机卸载造成的空闲块计数器损坏。
  • **管道并行性：**修复了 MTP、引导解码和执行程序关闭的挂起问题。
  • MoE： 修复了由非确定性垃圾收集导致的 DeepEP 挂起。
  • 内核： 修复了 Qwen2.5 混合精度精度、两次 AllReduce 精度和 FP8 块级 GEMM NaN 输出。
  • 采样： 修复了 ignore_eos 抑制 TorchSampler 中错误标记的问题，并且 NaN 采样参数现在被拒绝。
  • 常规： 修复了许多 LoRA 适配器或检查点预取期间的编码器-解码器波束搜索损坏和内存不足错误。

已知问题

  • Kimi-K3 NVFP4 可能无法使用捆绑的 Transformer 版本加载其标记生成器。
  • 在使用 DSpark 推测性解码的分类服务中，草稿 KV 缓存不会传输到生成工作线程，这会降低接受率。聚合服务不受影响。
  • 当 max_num_tokens 大于 4096 时，GB200 上的 GLM-5.2 NVFP4（TP=8，注意 DP 禁用）可能会在预热期间出现段错误。将 max_num_tokens 保持在 4096 或更低。
  • 当并发超过最大批量大小时，B300 上 Nemotron-3-Super-120B-A12B FP8 的分类服务可能会失败。
  • B300 上 Qwen3-32B-FP8 的分类服务可能会产生不正确的输出。
  • /v1/responses 端点与某些输入格式、流事件、对话继续和工具调用（Qwen3、GPT-OSS）存在兼容性差距。
  • 具有 FP8 KV 缓存的编码器-解码器模型可能会溢出交叉注意力 KV 缓存池，导致非法内存访问或不正确的输出。
  • 当启用 aws-ofi-nccl 插件时，AWS p4d (A100) 上 TP=4 的 Qwen3-32B 在自动调谐器预热期间可能会出现段错误。
