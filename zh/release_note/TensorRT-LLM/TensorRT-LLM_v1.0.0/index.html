TensorRT-LLM v1.0.0

TensorRT LLM 发布 1.0

TensorRT LLM 1.0 带来了 2 个重大变化：基于 PyTorch 的架构现在稳定且默认体验，LLM API 现在稳定。有关 1.0 新开发的更多详细信息，请参阅下文。

主要功能和增强功能

  • 模型支持
    • 添加Mistral3.1 VLM模型支持
    • 添加 TensorRT-Engine Qwen3（密集）模型支持
    • 添加 phi-4-多模式模型支持
    • 添加 EXAONE 4.0 型号支持
    • 向 TensorRT 后端添加 Qwen3 MoE 支持
  • 特点

    • 添加对 Gemma3 的 LoRA 支持

基础设施变化

  • TensorRT-LLM 的基础 Docker 映像已更新为 nvcr.io/nvidia/pytorch:25.06-py3。
  • TensorRT-LLM 后端的基本 Docker 映像已更新为 nvcr.io/nvidia/tritonserver:25.06-py3。
  • 依赖的 NVIDIA ModelOpt 版本更新为 0.33。
  • 依赖的xgrammar版本更新为0.1.21。
  • 相关变压器版本更新为4.53.1。

API 变化

  • 重大变更 将 PyTorch 提升为默认的 LLM 后端
  • 重大更改 将 trtllm-serve 中的默认后端更改为 PyTorch
  • 重大变更 在 pytorch 后端的 LLM 类中统一 KvCacheConfig
  • 重大更改 重命名 cuda_graph_config padding_enabled 字段
  • 重大更改 将mixed_sampler重命名为enable_mixed_sampler
  • 重大更改 将LLM.autotuner_enabled 重命名为enable_autotuner
  • 将 allreduce_strategy 参数添加回 TorchLlmArgs
  • 添加 LLmArgs 选项以强制使用动态量化
  • 更改默认 LoRA 缓存大小并更改 peft_cache_config 缓存大小字段，以便在 lora_config 中未明确设置时生效
  • 删除已在 lora_config 中指定的已弃用的 LoRA LLM 参数
  • 将 request_perf_metrics 添加到 LLMAPI
  • 删除batch_manager::KvCacheConfig并使用executor::KvCacheConfig代替
  • 删除TrtGptModelOptionalParams
  • 从 TorchLlmArgs 上移除调节旋钮

已知问题

  • 当使用具有管道并行性和 KV 缓存重用的分解服务时，可能会发生挂起。这将在未来版本中修复。同时，禁用 KV 缓存重用将解决此问题。
  • 已知运行每个节点只有一个 GPU 的多节点情况会失败。这将在未来的版本中得到解决。
  • 对于 Llama 3.x 和 Llama 4 模型，使用 FP8 和 NVFP4 权重时存在管道并行性问题。作为解决方法，您可以设置环境变量 export TRTLLM_LLAMA_EAGER_FUSION_DISABLED=1。
