TensorRT-LLM v0.12.0

小版本 发布时间2024年8月29日 来源NVIDIA/TensorRT-LLM 英文原文

TensorRT-LLM v0.12.0

嗨， 我们非常高兴地发布 TensorRT-LLM 的 0.12.0 版本。本次更新包括：

主要功能和增强功能

  • 支持 MoE 型号的 LoRA。
  • ModelWeightsLoader 适用于 LLaMA 系列型号（实验性），请参阅 docs/source/architecture/model-weights-loader.md。
  • 支持 NVIDIA Ada Lovelace 架构的 FP8 FMHA。
  • 支持 LLM 级别的 GPT-J、Phi、Phi-3、Qwen、GPT、GLM、Baichuan、Falcon 和 Gemma 型号。
  • 支持 FP8 OOTB 教育部。
  • 支持 Starcoder2 SmoothQuant。 (#1886)
  • 支持 ReDrafter 推测解码，请参阅 docs/source/speculative_decoding.md 中的“ReDrafter”部分。
  • 支持 BERT 的填充删除，感谢 @Altair-Alpha 在 #1834 中的贡献。
  • 添加了对 GLM 10B 模型的飞行批处理支持。
  • 支持gelu_pytorch_tanh激活函数，感谢@ttim在#1897中的贡献。
  • 向 Whisper 添加了 chunk_length 参数，感谢 @MahmoudAshraf97 在 #1909 中的贡献。
  • 为 gptManagerBenchmark 添加了 concurrency 参数。
  • 执行器API支持不同波束宽度的请求，参见docs/source/executor.md#sending-requests-with-different-beam-widths。
  • 将标志 --fast_build 添加到 trtllm-build 命令（实验性）。

API 变化

  • [重大更改] max_output_len 已从 trtllm-build 命令中删除，如果您想在引擎构建阶段限制序列长度，请指定 max_seq_len。
  • [重大更改] use_custom_all_reduce 参数已从 trtllm-build 中删除。
  • [重大更改] multi_block_mode 参数已从构建阶段（trtllm-build 和构建器 API）移至运行时。
  • [重大变更] 构建时参数 context_fmha_fp32_acc 已移至解码器模型的运行时。
  • [重大更改] 从 trtllm-build 命令中删除了参数 tp_size、pp_size 和 cp_size。
  • C++ 批处理管理器 API 已弃用，取而代之的是 C++ executor API，并且它将在 TensorRT-LLM 的未来版本中删除。
  • 在C++库中添加了API版本，将生成cpp/include/tensorrt_llm/executor/version.h文件。

模型更新

  • 支持 LLaMA 3.1 型号。
  • 支持 Mamba-2 模型。
  • 支持的 EXAONE 型号，请参见 examples/exaone/README.md。
  • 支持 Qwen 2 型号。
  • 支持的 GLM4 型号，请参阅 examples/chatglm/README.md。
  • 添加了 LLaVa-1.6 (LLaVa-NeXT) 多模式支持，请参阅 examples/multimodal/README.md 中的“LLaVA、LLaVa-NeXT 和 VILA”部分。

已修复的问题

  • 修复了 CodeQwen 模型的错误垫标记。 (#1953)
  • 修复了 tensorrt_llm/auto_parallel/cluster_info.py 中定义的 cluster_infos 中的拼写错误，感谢 @saeyoonoh 在 #1987 中的贡献。
  • 删除了 docs/source/reference/troubleshooting.md 命令中的重复标志，感谢 @hattizai 在 #1937 中的贡献。
  • 修复了 TopP 采样层中的分段错误，感谢 @akhoroshev 在 #2039 中的贡献。 (#2040)
  • 修复了转换米斯特拉尔尼莫模型检查点时失败的问题。 (#1985)
  • 将 exclude_modules 传播到仅权重量化，感谢 @fjosw 在 #2056 中的贡献。
  • 修复了自述文件中的错误链接，感谢 @Tayef-Shah 在 #2028 中的贡献。
  • 修复了文档中的一些拼写错误，感谢 @lfz941 在 #1939 中的贡献。
  • 修复了推断 max_seq_len 不是整数时引擎构建失败的问题。 (#2018)

基础设施变化

  • TensorRT-LLM 的基础 Docker 映像已更新为 nvcr.io/nvidia/pytorch:24.07-py3。
  • TensorRT-LLM 后端的基础 Docker 映像更新为 nvcr.io/nvidia/tritonserver:24.07-py3。
  • 依赖的 TensorRT 版本更新为 10.3.0。
  • 依赖的CUDA版本更新为12.5.1。
  • 依赖的 PyTorch 版本更新为 2.4.0。
    • 依赖的ModelOpt版本更新为v0.15.0。

已知问题

  • 在 Windows 上，TensorRT-LLM 的安装可能会成功，但在 Python 中导入库时可能会遇到 OSError: exception: access violation reading 0x0000000000000000。请参阅在 Windows 上安装 了解解决方法。 目前，该项目有两个关键分支：
  • rel 分支是 TensorRT-LLM 发布的稳定分支。它已经过质量检查和仔细测试。
  • main 分支是 dev 分支。它更具实验性。 我们定期更新 main 分支，提供新功能、错误修复和性能优化。 rel 分支的更新频率将会降低，具体频率取决于您的反馈。 谢谢， TensorRT-LLM 工程团队
