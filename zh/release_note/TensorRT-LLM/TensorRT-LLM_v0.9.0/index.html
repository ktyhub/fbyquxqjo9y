TensorRT-LLM v0.9.0

小版本 发布时间2024年4月16日 来源NVIDIA/TensorRT-LLM 英文原文

TensorRT-LLM v0.9.0

嗨， 我们非常高兴地发布 TensorRT-LLM 的 0.9.0 版本。这是一项艰巨的努力，我们希望它能让您轻松部署基于 GPU 的推理，以实现最先进的法学硕士。我们希望 TensorRT-LLM 能够帮助您快速运行这些 LLM。 本次更新包括：

  • 型号支持
    • 支持 distil-whisper，感谢 @Bhuvanesh09 在 PR #1061 中的贡献
    • 支持 HuggingFace StarCoder2
    • 支持维拉
    • 支持 Smaug-72B-v0.1
    • 将 BLIP-2 示例迁移到 examples/multimodal
  • 特点
    • [重大变更] 默认情况下启用具有确定性 AIR TopP 算法的 TopP 采样优化
    • [重大变更] 支持 Gemma 嵌入共享
    • 添加对上下文分块的支持以处理 KV 缓存重用
    • 为美杜莎的每个序列启用不同的倒带标记
    • BART LoRA 支持（仅限于 Python 运行时）
    • 为 BART LoRA 启用多 LoRA
    • 在 C++ 运行时的波束搜索中支持 early_stopping=False
    • 将 logits 后处理器添加到批处理管理器（请参阅 docs/source/batch_manager.md#logits-post-processor-optional）
    • 支持导入和转换HuggingFace Gemma检查点，感谢@mfuntowicz在#1147中的贡献
    • 支持从 HuggingFace 加载 Gemma
    • 支持高级 API 的自动并行规划器和统一的构建器工作流程
    • 支持在没有 OpenMPI 的情况下运行 GptSession #1220
    • 美杜莎 IFB 支持
    • [实验] 支持 FP8 FMHA，注意性能不是最优的，我们会不断优化
    • 更多头部尺寸支持 LLaMA 类模型
      • Ampere (sm80, sm86), Ada (sm89), Hopper(sm90) 现在都支持磁头尺寸 [32, 40, 64, 80, 96, 104, 128, 160, 256]。
    • OOTB 功能支持
      • T5
      • 混合 8x7B
  • API
    • C++ executor API
      • 添加 Python 绑定，请参阅 examples/bindings 中的文档和示例
      • 添加 executor C++ API 的 Python 绑定的高级和多 GPU 示例，请参阅 examples/bindings/README.md
      • 添加 C++ executor API 的文档，参见 docs/source/executor.md
    • 高级别API（参考examples/high-level-api/README.md获取指导）
      • [重大变更] 重用 trtllm-build 工具中使用的 QuantConfig，支持更广泛的量化功能
      • 支持LLM() API接受由trtllm-build命令构建的引擎
      • 添加对 TensorRT-LLM 检查点作为模型输入的支持
      • 优化LLM.generate或LLM.generate_async API中使用的SamplingConfig，支持波束搜索、多种惩罚和更多功能
      • 添加对 StreamingLLM 功能的支持，通过设置 LLM(streaming_llm=...) 启用它
      • 将 Mixtral 迁移到高级 API 和统一的构建器工作流程
    • [重大变更] 将 Qwen 模型重构为统一的构建工作流程，请参阅 examples/qwen/README.md 了解最新命令
    • [重大更改] 将 LLaMA 转换检查点脚本从示例目录移动到核心库
    • [重大变更] 使用统一的构建工作流程重构 GPT，请参阅 examples/gpt/README.md 了解最新命令
    • [重大变更] 从convert_checkpoint.py 脚本中删除了所有 lora 相关标志，并将检查点内容删除到 trtllm-build 命令，以便将该功能更好地推广到更多模型
    • [重大更改] 从convert_checkpoint.py 脚本和检查点内容中删除了 use_prompt_tuning 标志和选项，以便将该功能更好地推广到更多模型。请改用 trtllm-build --max_prompt_embedding_table_size。
  • [重大更改] 将 trtllm-build --world_size 标志更改为 --auto_parallel 标志，该选项仅用于自动并行规划器。
    • [重大变更] AsyncLLMEngine 被删除，tensorrt_llm.GenerationExecutor 类被重构，以便在应用程序级别显式启动 mpirun 并接受由 mpi4py 创建的 MPI 通信器
    • [重大变更] examples/server 已删除，请参阅 examples/app。
    • [重大变更] 从转换检查点脚本中删除 LoRA 相关参数
    • [重大变更] 简化 Qwen 转换检查点脚本
    • [重大变更] 从 gptManagerBenchmark 和 gptSessionBenchmark 中删除 model 参数
  • 错误修复
    • 修复 Whisper 的仅权重量化错误，以确保 encoder_input_len_range 不为 0，感谢 @Eddie-Wang1120 在 #992 中的贡献
    • 修复 Python 运行时日志概率不返回的问题 #983
    • 多模式示例的多 GPU 修复#1003
    • 修复 Qwen #987 的错误 end_id 问题
    • 修复不间断生成问题#1118#1123
    • 修复 example/mixtral/README.md 中的错误链接 #1181
    • 修复仅启用 int8 kv 缓存和每通道 int8 权重时 LLaMA2-7B 的不良结果 #967
    • 修复从 HuggingFace Hub 导入 Gemma 模型时错误的 head_size，感谢 @mfuntowicz 在 #1148 中的贡献
    • 修复 ChatGLM2-6B 在 INT8 上构建失败的问题 #1239
    • 修复百川文档中错误的相对路径#1242
    • 修复 ModelRunnerCpp 中错误的 SamplingConfig 张量 #1183
    • 修复转换 SmoothQuant LLaMA 时的错误 #1267
    • 修复examples/run.py仅从--input_file加载一行的问题
    • 修复 ModelRunnerCpp 未正确传输 SamplingConfig 张量字段的问题 #1183
  • 基准
    • 在 gptManagerBenchmark 中添加模拟静态批处理
    • 支持来自 HuggingFace 的任意数据集进行 C++ 基准测试，请参阅 benchmarks/cpp/README.md 中的“准备数据集”部分
    • 将百分位延迟报告添加到 gptManagerBenchmark
  • 性能
    • 优化gptDecoderBatch支持批量采样
    • 为 BART、Whisper 和 NMT 系列中的型号启用 FMHA
    • 删除路由器张量并行性以提高 MoE 模型的性能，感谢 @megha95 在 #1091 中的贡献
    • 改进自定义 all-reduce 内核
  • 基础设施
    • TensorRT-LLM 的基础 Docker 映像更新为 nvcr.io/nvidia/pytorch:24.02-py3
    • TensorRT-LLM 后端的基础 Docker 映像更新为 nvcr.io/nvidia/tritonserver:24.02-py3
    • 依赖的TensorRT版本更新为9.3
    • 依赖的PyTorch版本更新为2.2
    • 依赖的 CUDA 版本更新为 12.3.2（又名 12.3 更新 2） 目前，该项目有两个关键分支：
  • rel 分支是 TensorRT-LLM 发布的稳定分支。它已经过质量检查和仔细测试。
  • main 分支是 dev 分支。它更具实验性。 我们定期更新主分支，提供新功能、错误修复和性能优化。稳定分支的更新频率会降低，具体频率取决于您的反馈。 谢谢， TensorRT-LLM 工程团队
