TencentDB-Agent-Memory v2.0.3-beta.1

预发布 发布时间2026年10月13日 来源TencentCloud/TencentDB-Agent-Memory 英文原文

TencentDB-Agent-Memory v2.0.3-beta.1

变更流程图

亮点

  • 可插拔决策服务（可选启用） — 技能选择和 Memory L3 更新决策现在可以使用统一的决策服务，provider 默认为 jev。未启用时不会调用 JEV，决策服务失败会做降级，不会中断对话或记忆写入。
  • 按需加载技能（可选启用） — Proxy 可以通过一次客户端工具调用在每轮选择并加载合适的技能，而不必把完整技能目录注入系统提示词。这对上下文敏感的部署能减少提示词开销；现有配置保持不变。
  • 会话轨迹记录（通过 tdai.enabled 可选启用） — 每轮结束后，Proxy 通过 /v3/session/add 把上游消息和模型响应记录到本地 MemoryCore。便于调试和回放，但启用后会在本地保存完整对话内容，因此要先审视留存和数据合规要求。
  • 代码知识库与诊断 — 私有仓库现在支持 SSH 克隆，包括非 22 端口的端点，使用从面板获取的公钥。/health 暴露 ftsAvailable 用于诊断 BM25 检索不可用；失败的 LLM 调用现在会记录状态码、URL 和响应体。
  • 升级评估 — 没有记录破坏性变更或迁移步骤，新能力默认关闭，因此行为在启用前与 v2.0.2 保持一致。需要决策服务灵活性、更小技能提示词、会话轨迹、SSH 仓库索引或更好诊断的用户可以考虑这个 beta；否则升级的即时收益很小。

[2.0.3-beta.1] - 2026-10-13

v2.0.3-beta.1发布，相比v2.0.2增加了可插拔的决策服务、技能循环选择与会话日记 记录能力，并补齐代码知识库的SSH克隆与可启动性信息。以上新能力均默认关闭， 旧配置消耗修改、行为与之前保持一致。

产品定位：让Agent的经验、文档、代码沉淀成可复用的资产，让下一位Agent 直接读档。参见README_CN.md。

🧩可插拔决策服务（默认关闭）

技能选择与记忆L3更新决策统一收敛到决策服务，可灵活替换决策来源：

  • 通过统一的决策服务接口调用，内置JEV，也可接入其他决策API
  • 配置用 provider 指定（默认 jev），旧配置修改消耗
  • 默认不调用JEV，行为与之前一致；开启后即使决策服务调用失败， 也不影响正常的对话和记忆

🧰 技能（Skill）交互选择（默认关闭）

  • 开启后由Proxy每轮自动选出合适的技能，通过一次客户端工具调用加载
  • 不再向系统提示词注入完整技能目录，减少提示词开销

📼 会话轨迹记录

  • Proxy在每轮对话结束后，把往上游的消息与模型回复记录发送到MemoryCore （新增/v3/session/add，写入本地存储）
  • 随 tdai.enabled 开启

🧠代码知识库

  • 北极代码仓支持SSH克隆（含非22端口），在面板获取SSH公钥后即可建图

📈 可落地性

  • /health 新增 ftsAvailable，其次排查 BM25 关键词响应不可用的问题
  • LLM 调用失败日志补充状态码、URL 与响应内容
