graphql-java 25.0.beta-6

预发布 发布时间2025年9月22日 来源graphql-java/graphql-java 英文原文

graphql-java 25.0.beta-6

这个项目是干啥的：一个 Java 版 GraphQL 实现，让前端按需查询接口数据、少拿冗余字段，给用 Java 搭 API 服务的后端开发用。

变更架构图

亮点

  • 测试版，不是稳定的升级目标 — 25.0.beta-6 明确是测试/反馈版本；维护者警告在 25.0 之前还会有更多破坏性变更。只有在针对即将到来的大版本做验证时才采用它；生产环境使用稳定 2x 的用户应跳过并等待 25.0 GA。
  • 链式 DataLoader 性能是重头戏 — 选用这个 beta 的主要理由是 PR #4122 和 PR #4123，它们重新设计了新的链式 dataloader 以提升吞吐，包括一条无锁路径。特别是如果你已经在用链式 dataloader 功能并能提供反馈，值得试；否则这不构成升级理由。
  • 空值注解开始影响公开 API — PR #3892 要求新的 Public/Experimental API 类使用 JSpecify 注解，PR #3899 为 graphql.language 包中的节点指定了空值语义，PR #4087 为 builder 添加 @NullUnmarked。Kotlin 和 NullAway 用户在针对此版本编译时，应预期更多可空性信号（以及可能出现的新警告）。
  • 增量/延迟执行修复 — PR #4073 修复 IncrementalExecutionResult.transform() 以保留增量字段，PR #4083 为延迟支持提供正确的 Instrumentation。如果你依赖 @defer / 增量交付，建议升级；这些是正确性修复，不只是调优。
  • 依赖与打包变更，带有迁移影响 — 一次广泛的依赖更新（jackson-databind 2.20.0、reactor-core 3.7.11、jetty-server 11.0.26、shadow 9.0.2、kotlin 2.2.20、gson 2.13.2、byte-buddy 1.17.7、nullaway 0.12.9），但注意 PR #4113 不再把 Kotlin stdlib 作为依赖包含（Kotlin 消费者必须自己声明），PR #4112 从自省消息中移除了 ' 字符（可能破坏精确字符串断言）。如果你使用 Kotlin 或对自省输出做断言，请检查这两项。

这是即将推出的版本 25 的另一个测试版。

它包含各种更改，特别是新的链式数据加载器功能的性能改进。

警告

虽然所有功能都经过测试并且我们认为它们可以使用，但我们不保证这是一个稳定的版本：这意味着在我们达到 25.0 之前将会有更多的重大更改。

此版本旨在用于测试并向 GraphQL Java 团队提供反馈。
