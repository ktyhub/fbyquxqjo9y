tempo v3.0.0

Tempo 3.0 是一个主要版本，完成了向新的摄取/写入架构的过渡，删除了已弃用的 2.x 组件，将 TraceQL 指标升级为通用版本，并为 Tempo 2.x 用户添加了迁移工具。 此版本包含重大配置和部署更改。升级前请查看迁移指南，特别是如果您使用旧版提取器、旧版覆盖、v2 块、OpenCensus、localblocks 或自定义实时存储/查询前端设置。

变更流程图

亮点

  • 新的摄取/写入架构取代了传统的摄取器。
  • TraceQL指标普遍可用； TraceQL 指标的警报和更快的读取路径仍处于实验阶段。
  • vParquet5 改进和更快的指标查询路径。
  • 扩展了基数管理的指标生成器控制。
  • 跟踪编辑支持。
  • 通过 otelyrscope 提供跨度分析支持。
  • 实时存储和块构建器的正确性和可观察性修复。 有用的链接：
  • Release note：https://grafana.com/docs/tempo/latest/release-notes/v3-0/
  • 迁移指南：https://grafana.com/docs/tempo/latest/set-up-for-tracing/setup-tempo/migrate-to-3/
  • 升级指南：https://grafana.com/docs/tempo/latest/set-up-for-tracing/setup-tempo/upgrade/
  • Changelog: https://github.com/grafana/tempo/blob/v3.0.0/CHANGELOG.md#v300

重大变更

Tempo 3.0 包括一些影响操作员的删除和默认更改。升级前请查看迁移指南。

  • 传统的基于摄取器的写入路径已被删除。部署必须迁移到 3.0 摄取/写入架构。
    • 在 #6504 / #6959 中删除了 @javiermolinar 的摄取器和摄取模块
    • 删除了剩余的应用程序摄取配置和 ingest.enabled by @javiermolinar 在 #6667 / #6873
    • 在 #6981 中删除了 @javiermolinar 的分区环 livestore 配置
    • 在 #6369 中删除了 @javiermolinar 的摄取器和压实机警报
  • 在 #6273 中删除了 @joe-elliott 的 v2 块编码和旧版 v2 压缩器组件
    • 删除了 v2 特定的 CLI 命令：list block、list index、view index、gen index 和 gen bloom。
  • 集中块和 WAL 配置：block_builder 和 live_store 现在始终使用 storage.trace.block 设置；每个模块块配置字段被 @stoewer 在 #6647 中删除
  • 最近的数据查询现在通过在实例滞后时失败来保证完整的结果。默认 query_frontend.query_end_cutoff 为 30s 和 live_store.fail_on_high_lag 为 true by @mapno in #7210 / #7232
  • 默认情况下禁用旧版（平面、无范围）覆盖。如果检测到旧版覆盖，Tempo 将拒绝启动。设置 enable_legacy_overrides: true 或 -config.enable-legacy-overrides=true 以暂时选择重新加入。旧版覆盖将在未来版本中由@ Electron0zero 在 #6741 中删除
  • 用户可配置的覆盖配置 metrics_generator.processors 不再与运行时覆盖合并。 metrics_generator.processors 现在优先于运行时覆盖，与用户可配置覆盖中的所有其他配置相匹配。设置 processors: [] 会通过 #7176 / #7185 中的@ Electron0zero 禁用租户的所有处理器
  • 默认启用RetryInfo。 distributor.retry_after_on_resource_exhausted 现在默认为 5s（原为 0），因此 OTLP clients 会在 #7088 中收到 @ Electron0zero 发出的有关 ResourceExhausted 错误的重试提示
    • 设置为 0 以在集群范围内禁用，或设置每租户覆盖 ingestion.retry_info_enabled: false 以对单个租户禁用。
  • 从 #6909 中的 @ Electron0zero 的 CompactorConfig CLI 标志中删除了重复的 compaction 前缀
    • compaction.compaction.block-retention → compaction.block-retention
    • compaction.compaction.max-objects-per-block → compaction.max-objects-per-block
    • compaction.compaction.max-block-bytes → compaction.max-block-bytes
    • compaction.compaction.compaction-window → compaction.compaction-window
  • 在 #6523 中由 @javiemolinar 删除了 OpenCensus 接收器
  • 在 #6403 中删除了@orkhan-huseyn 遗留的 mem-ballast-size-mbs CLI 标志
  • tempo-cli：支持开始/结束参数的相对时间（now、now-1h），并在 #6458 中的@ Electron0zero 在所有命令中对 RFC3339 进行标准化
    • query search 命令不再接受没有时区的时间戳，例如 2024-01-01T00:00:00；使用 RFC3339，例如 2024-01-01T00:00:00Z，或相对时间。
  • 合并最近数据截止的读取配置。 @mapno 在 #6507 中删除了 query_frontend.search.query_ingesters_until，只支持 query_frontend.search.query_backend_after
  • 删除了已弃用的 querier.query_live_store 配置。该字段必须从@javiermolinar 在#7048 中的升级配置中删除
  • 通过将同一属性上的条件重写为 @stoewer 在 #6353 中的等效数组来优化 TraceQL AST
    • 稍微更改了 != 和 !~ 运算符的数组匹配语义，并为正则表达式文字引入了更严格的规则。
  • 删除了 @javiermolinar 在 #6618 中的跨度度量剩余部分和惰性初始化生成器 clients
  • @javiermolinar 在 #6615 中停用的 livestore MetricsGenerator 查询服务
  • 在 #6555 中删除了 @javiermolinar 的指标生成器 localblocks 处理器和相关的本地块存储管道
  • SpanMetricsSummary 被删除，查询器代码由 @javiermolinar 在 #6496 和 #6510 中简化
  • 将 all 目标设置为 3.0-compatible 并由 @joe-elliott 在 #6283 中删除 scalable-single-binary 目标
  • 在#6505中由@javiermolinar清理了企业jsonnet
