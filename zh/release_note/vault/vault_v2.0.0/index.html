vault v2.0.0

大版本 发布时间2026年4月14日 来源hashicorp/vault 英文原文

vault v2.0.0

重大变更：

  • sdk/helpers/docker：将 docker 助手从 github.com/docker/docker 迁移到 github.com/moby/moby。这是必要的，因为 github.com/docker/docker 不再维护。解决 GHSA-x744-4wpc-v9h2 和 GHSA-pxq6-2prw-chj9。 安全：
  • 将 cloudflare/circl 升级到 v1.6.3 以解决 CVE-2026-1229
  • 将filippo.io/edwards25519升级到v1.1.1以解决GO-2026-4503
  • api/auth/gcp：更新 go.opentelemetry.io/otel/sdk 以修复 CVE-2026-39883。
  • api/auth：更新github.com/go-jose/go-jose以修复安全漏洞CVE-2026-34986和GHSA-78h2-9frx-2jm8。
  • auth/aws：修复了由于 AWS client 缓存不正确而导致用户可能能够绕过 Vault 身份验证的问题
  • auth/cert：确保正在更新的证书与会话附加的证书匹配。
  • 核心：当此标头转发到插件后端时，正确地从授权标头中删除任何 Vault 令牌。仅当“Authorization”明确包含在直通请求标头列表中时，才会转发该标头。
  • 核心：通过升级到 github.com/jackc/pgx/v5 解决 GO-2026-4518 和 GHSA-jqcq-xjh3-6g23
  • 核心：更新 github.com/aws/aws-sdk-go-v2/ 以修复安全漏洞 GHSA-xmrv-pmrh-hhx2。
  • 核心：更新github.com/go-jose/go-jose修复安全漏洞CVE-2026-34986和GHSA-78h2-9frx-2jm8。
  • 核心：更新github.com/hashicorp/go-getter修复安全漏洞GHSA-92mm-2pjq-r785。
  • 核心：更新 go.opentelemetry.io/otel/sdk 以修复 CVE-2026-39883。
  • 核心：拒绝未指定规范路径的 URL 编码路径
  • http：添加了可配置的 max_token_header_size 侦听器选项（默认 8 KB）来限制身份验证令牌标头（X-Vault-Token 和 Authorization: Bearer）的大小，防止通过过大的标头内容进行潜在的拒绝服务攻击。现在还在 HTTP 服务器上设置了 stdlib 级别的 MaxHeaderBytes backstop。设置 max_token_header_size = -1 以禁用限制。
  • sdk：通过升级到 github.com/jackc/pgx/v5 解决 GO-2026-4518 和 GHSA-jqcq-xjh3-6g23
  • sdk：更新github.com/go-jose/go-jose以修复安全漏洞CVE-2026-34986和GHSA-78h2-9frx-2jm8。
  • ui：禁用 ui 构建的围巾分析 *Vault/sdk：将cloudflare/circl升级到v1.6.3以解决CVE-2026-1229 *Vault/sdk：将go.opentelemetry.io/otel/sdk升级到v1.40.0以解决GO-2026-4394
  • 更新 github.com/dvsekhvalnov/jose2go 以修复安全漏洞 CVE-2025-63811。
  • go：将 golang/x/crypto 更新为 v0.45.0 以解析 GHSA-f6x5-jh6r-wrfv、GHSA-j5w8-q4qc-rx2x、GO-2025-4134 和 GO-2025-4135。 变化：
  • Secrets/ldap（企业）：静态角色将从插件管理的队列迁移到 Vault Enterprise Rotation Manager 系统。可以通过新的静态迁移端点检查和管理静态角色迁移进度。有关此过程的更多详细信息，请参阅 LDAP 文档。
  • 审计：名为 supplemental_audit_data 的新顶级密钥现在可以出现在请求和响应数据结构内的“响应”类型的审计条目中。这些新字段可以包含进一步描述请求/响应数据的数据，主要用于基于非 JSON 的请求和响应，以帮助审核。 audit-non-hmac-request-keys 和 audit-non-hmac-response-keys 适用于 supplemental_audit_data 中的键，以删除字段值的 HMAC（如果需要）。
  • auth/alicloud: 更新插件为v0.23.1
  • auth/azure: 将插件更新为 v0.24.0
  • auth/cf: 将插件更新为 v0.23.0
  • auth/gcp: 将插件更新为 v0.23.1
  • auth/jwt: 将插件更新为 v0.26.1
  • auth/kerberos: 将插件更新为 v0.17.1

  • core/managed-keys（企业）：对 API 端点 GET sys/management-keys/:type/:name 的响应现在返回密钥用法的字符串值数组，而不是整数值数组。使用的字符串是“加密”(1)、“解密”(2)、“签名”(3)、“验证”(4)、“包装”(5)、“解包”(6)、“生成随机”(7) 和“mac”(8)。
  • 核心：Bump Go版本为1.26.2
  • 核心：Vault 现在拒绝不规范的路径，例如包含双斜杠的路径 (path//to/resource)
  • 核心：将 github.com/hashicorp/cap 升级为 v0.12.0
  • 核心：现在可以使用主设备上生成的根令牌对辅助 DR 请求进行身份验证。
  • 核心：sys/generate-root 和 sys/replication/dr/ secondary/generate-operation-token 端点现在默认进行身份验证，通过设置新的 HCL 配置键 enable_unauthenticated_access 分别包含值“generate-root”或“generate-operation-token”来启用旧的未经身份验证的行为。
  • 核心：sys/rekey 端点现在默认经过身份验证，通过设置新的 HCL 配置密钥 enable_unauthenticated_access 以包含值“rekey”来启用旧的未经身份验证的行为。
  • 数据库/couchbase：将插件更新为v0.16.1
  • 数据库/elasticsearch：将插件更新为v0.20.1
  • 数据库/mongodbatlas：将插件更新为v0.17.1
  • 数据库/redis-elasticache：将插件更新为 v0.9.1
  • 数据库/redis：将插件更新为v0.8.1
  • 数据库/雪花：将插件更新为v0.16.0
  • 许可证利用率报告（企业）：vault operator utilization 生成的手动报告包的格式已更改。值得注意的是，它们包含 snapshot_records 数组而不是 snapshots。每条记录中的 decoded_snapshot 字段包含先前位于 snapshots 数组中的人类可读数据。
  • mfa/duo：将 duo_api_golang client 升级到 0.2.0 以包含新的 Duo 证书颁发机构
  • 打包：容器映像现在使用压缩的 OCI 映像布局导出。
  • 打包：UBI 容器镜像现在构建在 UBI 10 最小镜像上。
  • 秘密/广告：将插件更新为 v0.22.1
  • Secrets/alicloud: 更新插件至 v0.22.1
  • Secrets/azure：更新 Azure Enterprise Secrets 插件以包含静态角色。
  • Secrets/azure：将插件更新为 v0.25.1+ent。改进了 Azure 应用程序和服务主体创建期间的重试处理，以减少暂时性故障。
  • Secrets/azure：更新插件至 v0.26.1+ent
  • Secrets/GCP：将插件更新为v0.24.0
  • Secrets/gcpkms：将插件更新为 v0.23.0
  • Secrets/keymgmt：将插件更新为 v0.19.0+ent
  • Secrets/kmip：更新插件至 v0.20.0

  • Secrets/kv：将插件更新为v0.26.2
  • Secrets/mongodbatlas: 将插件更新为 v0.17.1
  • Secrets/openldap：将插件更新为 v0.18.0
  • Secrets/pki：逐字签名端点不再忽略 CSR 中的基本约束扩展，如果 isCA=false，则在生成的证书中使用它们；如果 isCA=true，则返回错误
  • Secrets/terraform：将插件更新为 v0.14.1
  • secure-plugin-api：更新至v0.2.0
  • 存储：将 aerospike client 库升级到 v8。
  • ui/secrets：秘密引擎 URL 路径从“/secrets”重命名为“/secrets-engines”
  • ui：删除从列表视图中批量删除秘密引擎的功能。 特点：
  • PKI 外部 CA（企业）：一个新插件，提供通过 ACME 协议从公共 CA 提供商获取 PKI 证书的能力
  • IBM PAO 许可证集成：添加了 IBM PAO 许可证支持，允许通过 IBM PAO 许可证密钥使用 Vault Enterprise。 Vault 配置中需要新的配置节 license_entitlement 才能使用 IBM 许可证。有关更多详细信息，请参阅许可证文档。
  • KMIP 自带 CA：添加新的 API 来管理多个 CA 以进行 client 验证，并可以导入外部 CA。
  • LDAP Secrets Engine 企业插件：添加新的 LDAP Secrets Engine 企业插件。此企业版本添加了对自我管理静态角色的支持以及对自动静态角色轮换的轮换管理器支持。新的插件配置可以设置为“自我管理”，跳过对 Bindpass 字段的要求，并允许静态角色使用自己的密码来轮换其凭据。自动静态角色凭证轮换支持通过 Vault Enterprise 进行细粒度计划轮换和重试策略。
  • 登录 MFA TOTP 自行注册（企业）：简化用户创建登录 MFA TOTP 凭据的过程，允许他们使用登录期间生成的 QR 码（TOTP 机密）自行注册 MFA TOTP。新功能可在 TOTP 登录 MFA 方法配置屏幕上以及通过 API 中的 enable_self_enrollment 参数进行配置。
  • 插件（企业）：创建和更新数据库引擎时允许覆盖固定版本
  • 插件（企业）：启用和调整身份验证和机密后端时允许覆盖固定版本
  • SCIM 2.0 身份配置测试版（测试版/企业版）：添加对 Vault 的测试版支持以充当 SCIM 2.0 服务器，从而允许对 Vault 实体、别名和组进行外部管理。
  • PublicPKICA 的模板集成：现在，当颁发或续订 PKI 外部 CA 证书时，Vault 代理模板会自动重新呈现。
  • UI ACL 策略介绍：入门介绍，为用户提供功能上下文。
  • UI 身份验证方法介绍：入门介绍，为用户提供功能上下文。
  • UI 命名空间向导（企业）：入门向导，根据用户的预期用途向用户提供建议，并指导他们完成命名空间创建。
  • UI 策略生成器（企业）：将策略生成器弹出窗口添加到 KV V2 和 PKI 秘密引擎，并预先填充了每个页面的相关 API 请求。
  • UI Secret 引擎介绍：入门介绍，为用户提供功能上下文。
  • UI TLS 证书登录：添加对 TLS 证书（cert）身份验证的 UI 登录支持。
  • UI：Hashi 构建的外部插件支持：作为外部二进制文件运行时识别并支持 Hashi 构建的插件
  • UI：Hashi-Built 外部插件支持：通过 GUI 支持外部插件版本更新。
  • UI：安装版本控制的外部插件：添加了安装先前注册的外部插件并在启用秘密引擎时指定版本的功能。
  • Vault Agent：ACME 协议支持：添加支持以原生支持公共 CA ACME 工作流程
  • 秘密同步：实现了对秘密同步流的工作负载身份联合支持。 改进：
  • 秘密引擎 UI 改进：更新了配置视图并添加了对所有兼容秘密引擎配置的调整支持。
  • 侧边栏 UI 改进：添加顶部导航栏，更新侧边栏导航结构，并更新页面标题。
  • api：将 SHA256 和字段添加到外部插件的 json 列表响应中。
  • api：添加了 sudo 权限的 sys/reporting/scan 端点，它将输出一组包含有关 Vault 状态信息的文件到 reporting_scan_directory 配置项指定的位置。
  • auth/ldap：登录命令要求非空密码，以防止未经身份验证访问 Vault。
  • 配置/侦听器：记录有关无效 x-forwarded-for 配置的警告。
  • 消费计费：添加一个新的 sys/billing/overview 端点，该端点返回当前和上个月的消费计费指标。可通过 API client 方法 client.Sys().BillingOverview() 访问。
  • 核心（企业）：添加 common_criteria_mode feature_flags 设置，限制侦听器 TLS 密码套件。
  • 核心（企业）：添加了新的遥测指标 vault.core.license.termination_time_epoch。
  • 核心（企业）：使轮换管理器能够在注册和轮换操作期间发送插件后端所需的轮换信息。这允许插件后端拥有有效管理其旋转状态所需的上下文。
  • 核心（企业）：使轮换管理器能够使用可配置的重试策略来限制轮换条目的重试行为，并包括孤立机制来处理超过最大重试尝试次数的条目。
  • 核心（企业）：通过在重新排队失败的轮换时实施退避来改进轮换管理器错误处理
  • core/identity：为别名API添加两个新字段，external_id和issuer。这些字段本身并没有做任何有意义的事情，而是未来功能的一部分。
  • 核心/托管密钥（企业）：允许 GCP 托管密钥利用工作负载身份联合凭据
  • 核心/指标：现在通过 vault.route.read-snapshot.{mount_point} 和 vault.route.list-snapshot.{mount_point} 指标跟踪快照的读取和列出。
  • core/seal：增强 sys/seal-backend-status 以提供有关 seal 后端的更多信息。
  • 核心：每 5 秒而不是 10 秒检查轮换管理器队列以提高响应能力
  • dockerfile：容器现在默认以保管库用户身份运行
  • 事件（企业）：添加对租赁事件的事件通知支持。
  • events（企业）：将事件通知从主集群转发到辅助集群
  • kmip（企业）：添加实验性 API 来执行 KMIP 请求。
  • 许可证利用率报告（企业）：添加已颁发 PKI 证书数量的指标。
  • 许可证利用率报告（企业）：利用率报告现在包括新的许可证元数据字段 issuer、edition、add_ons、license_start_time、license_expiration_time 和 license_termination_time。
  • 许可证利用率报告：添加了消耗计费指标。
  • pki：在 ACME HTTP-01 和 TLS-ALPN-01 质询验证期间拒绝明显不安全的验证目标
  • 策略：添加使用 allowed_parameters 或 Denied_parameters 时有关列表比较的警告
  • 轮换：确保共享路径的轮换仅在主集群的活动节点上执行。确保本地路径的轮换在集群本地活动节点上执行。
  • sdk/rotation：防止在只读存储上进行旋转尝试
  • sdk：添加 NewTestDockerCluster 支持，以便在与服务器相同的容器中运行外部插件。  还添加对这些插件的支持以公开它们自己的侦听器，就像 KMIP 所做的那样。
  • sdk：将 alias_metadata 添加到身份验证方法角色使用的 tokenutil 字段。
  • 秘密同步（企业）：添加了用于协调循环操作的遥测计数器，包括检测到的更正次数、重试尝试和操作结果（带有内部/外部原因标签的成功或失败）。
  • 秘密同步（企业）：添加了用于同步/不同步操作的遥测计数器，其中按目标类型划分状态细分，并在目标列表 API 响应中公开操作计数器。
  • 秘密同步：为秘密密钥粒度关联的同步和不同步操作添加并行化支持
  • Secrets-pki（企业）：将解析格式的响应数据添加到注册协议的审核日志中。
  • Secrets-sync（企业）：添加了对布尔force_delete标志的支持（默认值：false）。 当设置为 true 时，此标志允许删除目标，即使其关联无法取消同步。 此选项仅应用作最后手段的删除机制，因为任何已同步到外部提供程序的机密都将保持孤立状态并需要手动清理。
  • 机密同步（企业）：通过在删除或禁用机密引擎安装时触发外部机密的立即取消同步，改进了安装生命周期更改期间的用户体验。通过将此逻辑从后台协调循环移动到直接回调，系统可以防止感知到的“泄漏”，并确保外部秘密资源与 Vault 卸载同步清理。
  • 秘密/数据库：使用密钥对凭证为 Snowflake 数据库秘密引擎添加根轮换支持。
  • Secrets/keymgmt（企业）：添加对多区域 AWS KMS 密钥的支持。
  • Secrets/kmip（企业）：转发 kmip 请求时遵守配置的 best_effort_wal_wait_duration。
  • Secrets/ldap：用户现在可以完全管理和调整 LDAP 机密引擎。这包括查看、编辑和配置 LDAP 引擎的能力。
  • Secrets/pki（企业）：返回 SCEP GetCACaps 端点内的 POSTPKIOperation 功能，以获得更好的旧版 client 支持。
  • Secrets/pki（企业）：以通用标准模式验证整个链；添加字段以启用验证时间检查
  • Secrets/pki（企业）：当启用 common_criteria_mode 功能标志时，NotBefore 将始终被视为零。
  • Secrets/pki（企业）：启用 common_criteria_mode 功能标志后，在 PKI 角色更新期间，根据 RFC 5280 第 4.2.1.12 部分，为每个 ext 密钥使用集强制执行最小密钥使用集。
  • Secrets/pki：添加 ACME 配置字段challenge_permissed_ip_ranges 和challenge_excluded_ip_ranges 配置来控制允许或禁止哪些IP 地​​址进行质询验证。
  • Secrets/pki：将最新的 CRL 扩展（Delta CRL 分发点）添加到基本 CRL 中
  • Secrets/pki：避免每次叶证书签名多次加载颁发者信息
  • Secrets/pki：在颁发、签名或获取证书的 API 端点的响应字段中包含证书的 AuthorityKeyID。
  • Secrets/pki：OCSP 在审核日志响应条目的新 supplemental_audit_data 部分中填充响应的详细信息。默认情况下，诸如 Issuer_id、next_update、ocsp_status、serial_number、revoked_at 之类的详细信息将显示为 hmac 值，除非添加到安装的 audit-non-hmac-response-keys 键集。
  • Secrets/pki：在通用标准模式下，不允许上传没有 trust 链的证书。
  • 秘密/传输，核心：提高通过随机字节 API 可检索的随机字节的限制。  并添加选项以获取由随机源播种的 PRNG 随机字节。 请注意，大量字节的请求将相应增加 Vault 内存使用量。
  • 秘密/传输：改进非 PKCS#8 密钥的导入错误，以明确要求 PKCS#8。
  • sys（企业）：添加 sys/billing/certificates API 端点以检索已颁发的 PKI 证书的数量。
  • 中转（企业）：将上下文参数添加到数据密钥和派生密钥端点，以允许 DEK 的派生密钥加密。
  • ui/activity（企业）：添加澄清文本以解释“初始使用”列将仅包含升级到版本 1.21 后最初使用的 clients 的时间戳
