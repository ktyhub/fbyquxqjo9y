vault v2.2.0

2026 年 10 月 15 日

重大变更：

  • 容器：在构建时删除 vault 上的 cap_ipc_lock 功能，以允许在公共容器运行时运行 Vault。容器中的 Vault 将不再能够调用 mlock() 来锁定内存。操作员应在 Vault 的配置中设置 disable_mlock = true。建议运行时操作员禁用交换以保证数据安全。
  • 容器：以下软件包已从基于 UBI 的容器镜像中删除：gnupg、openssl、procps。
  • 容器：在构建时在Vault上设置cap_ipc_lock功能。运行 Vault 容器时，容器运行时需要添加 IPC_LOCK 功能。
  • 物理/postgresql：重大更改 - PostgreSQL 存储后端身份验证现在更喜欢 Azure 工作负载身份而不是托管身份。将 go-pgmultiauth 更新为 v1.1.0。如果配置了工作负载身份，现有的基于托管身份的 PostgreSQL 配置可能会停止工作。 受影响的用户必须将 PostgreSQL 身份验证迁移到 Workload Identity。
  • pki：使用默认 sign-verbatim 目录策略的 ACME 现在会拒绝包含 URI SAN、电子邮件 SAN 或其他 SAN 的 CSR。 ACME 挑战仅验证 DNS 名称和 IP 地址；这些 SAN 类型从未经过验证，并且不得出现在颁发的证书中。需要先前行为的运营商可以在 config/acme 中设置 default_directory_policy = "sign-verbatim-unsafe"，接受生成的证书可能包含未经验证的身份声明。
  • sdk/helpers/docker：将 docker 助手从 github.com/docker/docker 迁移到 github.com/moby/moby。这是必要的，因为 github.com/docker/docker 不再维护。解决 GHSA-x744-4wpc-v9h2 和 GHSA-pxq6-2prw-chj9。 安全：
  • 将 cloudflare/circl 升级到 v1.6.3 以解决 CVE-2026-1229
  • 将filippo.io/edwards25519升级到v1.1.1以解决GO-2026-4503
  • acl：修复权限升级漏洞，其中 policies 请求字段上的 denied_parameters 约束可以通过提交大小写混合的策略名称（例如“超级管理员”而不是“超级管理员”）来绕过。 Vault 现在在评估 allowed_parameters/denied_parameters 约束之前将 policies 参数标准化为小写。

  • auth/cert：确保正在更新的证书与附加到会话的证书匹配。
  • auth/radius：添加了 case_insensitive_names 切换以防止用户名冲突并启用不区分大小写的用户处理。
