vault v2.0.4

2.0.4

2026 年 8 月 4 日

重大变更：

  • 容器：以下软件包已从基于 UBI 的容器中删除 图像：gnupg、openssl、procps。 安全：
  • acl：修复权限升级漏洞，其中 policies 请求字段上的 denied_parameters 约束可以通过提交大小写混合的策略名称（例如“超级管理员”而不是“超级管理员”）来绕过。 Vault 现在在评估 allowed_parameters/denied_parameters 约束之前将 policies 参数标准化为小写。
  • 身份/scim（企业）：identity/entity/merge 端点现在拒绝涉及任何 SCIM 管理实体的请求，防止特权操作员绕过 SCIM 所有权护栏跨 SCIM 边界传输别名、组成员身份或策略。
  • Identity：防止实体批量删除端点（identity/entity/batch-delete）删除属于另一个命名空间的实体的底层存储。
  • 身份：实体/名称更新现在拒绝不匹配的 id 或 external_id 选择器，以防止将更新重定向到不同的实体 变化：
  • auth/oci: 将插件更新为 v0.21.3
  • 核心：将 Go 版本升级为 1.26.5。
  • 核心：删除对 HCL 配置文件和策略定义中重复属性的支持。解析 HCL 重复的属性现在总是失败，并且 VAULT_ALLOW_PENDING_REMOVAL_DUPLICATE_HCL_ATTRIBUTES 环境 先前恢复遗留行为的变量已被删除。 特点：
  • 秘密：增加了查看 YAML 格式秘密的能力 改进：
  • auth/cert：即使在 Vault 侦听器上禁用 tls，也支持通过 x 转发的证书标头登录。
  • 核心（企业）：在 sys/config/oauth-resource-server/id/:config_id 添加端点以通过 config_id 读取 oauth 资源服务器配置文件
  • 核心（企业）：通过允许缺少 typ 标头，同时将当前的 typ 值限制为 at+jwt、application/at+jwt 和 JWT，使 OAuth 资源服务器 JWT typ 验证对来自 IdP（例如 Okta）的令牌更加宽松。
  • 核心（企业）：Ameriolate sealwrap 核心路径的锁争用。
  • core/acl：添加全局 deny_slash_in_templated_path 配置选项，以拒绝策略中呈现的身份模板中存在斜杠，默认为 false。
  • core/identity：添加全局 deny_slash_in_templated_path 配置选项，以拒绝策略中呈现的身份模板中存在斜杠，默认为 false。
  • core/managed-keys/PKCS#11（企业）：为一个字段提供非空值而另一字段已保存将被拒绝。要切换寻址模式，您必须通过在同一请求中将旧字段作为空字符串 ("") 与新值一起发送来显式清除旧字段。
  • core/managed-keys/PKCS#11（企业）：slot 和 token_label 现在严格强制作为 HSM 令牌的互斥标识符
  • events：添加VAULT_EVENT_NOTIFICATIONS_BOUNDED_QUEUE_SIZE环境变量来为事件通知订阅者配置有界事件队列。设置为正整数（例如 16）以启用该大小（最大 1000）的缓冲通道。这可以防止订阅者数量较多的部署中的资源耗尽，但代价是订阅者可能会错过事件。默认为 0（无缓冲）以实现向后兼容性。
  • Identity/scim（企业）：根据 RFC 7644 添加了对 GET /scim/v2/Users 和 GET /scim/v2/Groups 端点的过滤支持。支持的过滤器：用户的 userName eq、externalId eq、active eq 和 meta.lastModified gt/ge/lt/le； displayName eq 和 meta.lastModified gt/ge/lt/le 适用于团体。不受支持的过滤器表达式返回 HTTP 400。ServiceProviderConfig 现在通告 filter.supported: true。
  • Identity/scim（企业）：通过使用前缀排序而不是单独的排序过程来提高 SCIM 用户和组列表端点性能。
  • 身份：在实体列表 key_info 响应中包含实体状态和实体/别名时间戳详细信息。
  • oauth-resource-server：添加对丰富授权请求（RAR）中细粒度策略控制选项（参数约束）的支持，包括 authorization_details 中的 allowed_parameters、denied_parameters 和 required_parameters。
  • oauth-resource-server：添加对丰富授权请求 (RAR) 中身份模板表达式（例如 {{identity.entity.id}}）的支持。
  • scim：用户资源现在包含一个只读 groups 字段，根据 RFC 7643，列出由请求 SCIM client 管理的直接组成员身份。
  • Secrets/kv（企业）：支持从加载的快照中读取和恢复 KVv2 机密，包括同一安装和命名空间内的就地恢复和从路径复制。
  • ui：将只读 YAML 视图选项添加到 KV v2 秘密详细信息页面，以及现有的 UI 和 JSON 视图。
  • ui：将 tmp 的条目从 0.2.6 更改为 0.2.7。
  • ui：将 ws 的条目从 8.20.1 更改为 8.21.0。 错误修复：
  • 代理/代理：修复了身份验证方法标头在重新身份验证周期中累积在共享 API client 上的错误。
  • 代理：修复了 Vault 令牌标头在静态秘密缓存更新程序中通过 WebSocket 重新连接累积重复值的错误。
  • Secrets Recovery（企业）：对于对 sys/storage/raft/snapshot-load 的列表请求或对 sys/storage/raft/snapshot-load/{id} 的读取/删除请求，不要重定向到主动节点。如果可能，请在性能备用节点上处理这些请求，否则将请求转发到活动节点。
  • 审核：修复了 CVE-2025-6000 的回归，该回归在配置插件目录时破坏了在 Windows 上启用审核设备。
  • 审计：使文件和套接字审计接收器序列化上下文感知，因此取消或过期的请求将停止在阻塞的审计写入后面等待，从而减少审计接收器争用期间的 goroutine、内存、连接和文件描述符的累积
  • auth/cert：添加对来自 AWS ALB 的 x 转发的证书标头的支持。
  • auth/spiffe（企业）：验证证书时使用完整的对等证书链。
  • aws/auth：从 AWS auth 错误消息中编辑 EC2 实例元数据值。
  • 消费计费：修复来自性能备用节点的 PKI、SSH 和 SSH OTP 证书计费单元未转发到活动节点进行存储，导致备用节点上的计费事件丢失的错误。
  • 消费计费：修复来自性能备用节点的 SPIFFE JWT 令牌计费单元未转发到活动节点进行存储，导致备用节点上的计费事件丢失的错误。
  • 消费计费：修复了无法从存储中读回 SSH 持续时间调整证书计数和以“4”开头的十进制表示形式的 OTP 计数的错误，导致 sys/billing/overview 返回 500 错误，并显示“lz4：错误的幻数”。存储编码现在使用与其他计费指标一致的纯十进制字符串，避免误识别为 lz4 压缩数据。
  • 消费计费：修复了来自性能备用节点的 OIDC 令牌持续时间计数未转发到活动节点进行存储，导致备用节点上的计费事件丢失的错误。
  • 消费计费：通过避免在挂载和插件枚举期间获取嵌套锁，修复了 KMIP 和挂载扫描计费路径中的死锁。
  • 消费计费：修复了用例计费中的 LDAP 和 OpenLDAP 动态和静态角色计数 使用专用计数端点（角色计数、静态角色计数）而不是基于列表的计数，后者低估了角色。
  • 核心（企业）：修复导致不必要的密封重新包装的错误。
  • 核心（企业）：当控制组解开重播返回包装响应的批准请求时，保留包装元数据。
  • 核心（企业）：更新在性能辅助集群上使用时服务器端一致令牌（SSCT）的状态检查。对于向辅助活动节点发出无效的跨集群令牌请求，403 响应代码将优先于 412。
  • 核心/托管密钥（企业）：允许 PKCS#11 托管密钥中的槽编号超过 32 位。
  • core/seal：修复了加密和解密函数超时时发生的 goroutine 泄漏。
  • 核心：将包含重复斜杠的 API 请求重定向到其规范路径时保留 URL 查询参数。 以前，重定向会删除 ?list=true 等参数，这可能会更改请求的结果。
  • 事件（企业）：修复了活动节点重新启动或发生更改事件（密封/解封等）后事件停止转发到性能辅助节点的错误。 *导出API：将活动导出API中的end_time参数规范化为月底，以匹配文档中所述的行为。
  • oauth-resource-server（企业）：当授权详细信息可选时，OAuth 资源服务器授权现在将空 authorization_details 数组视为缺失声明。以前，包含空数组的令牌会被 RAR_NO_MATCH 拒绝，而不是继续通过正常的身份和策略授权。
  • Secrets-sync（企业）：修复了 GCP Secrets Sync 客户控制加密验证的不正确错误响应代码映射，该代码返回为 500 内部服务器错误，而不是 400 错误请求。
  • 机密同步：修复 GCP Secret Manager 目标在 Vault 重新启动时丢失其按区域 KMS 密钥的问题。
  • Secrets-sync：修复详细信息视图中的自定义标签字段以显示具有空值的密钥
  • Secrets/pki-external-ca（企业）：当certificate_format设置为pem_bundle时，将私钥包含在证书API响应字段的PEM中
  • Secrets/transit（企业）：向 CSR 签名添加托管密钥支持并设置证书链端点。
  • ui：在集群配置小部件中显示 TLS 状态时，正确处理 tls_disable 的字符串值（“true”/“false”）。
  • ui：修复了 PKI 生成根，因此在正确控制证书过期输入后无效。
