nanobot v0.1.4.post4

修订 发布时间2026年3月8日 来源HKUDS/nanobot 英文原文

🐈 纳米机器人 v0.1.4.post4 就在这里 — 合并了 58 个 PR，29 个新贡献者，以及来自社区的“大量”现实世界的完善。 这一版本是一项重大更新：更安全的默认设置、更好的多实例支持、更强的 MCP/工具可靠性，以及 Telegram、飞书、QQ、钉钉、Discord、WhatsApp、Matrix 等方面的重大改进。在这个周期中，大量锋利的边缘情况得到了清理——这种修复让纳米机器人每天都感觉更加坚固。

亮点

  • 默认更安全 — 访问控制现在更加严格。此版本包括真正的授权绕过修复和围绕 allowFrom 的更强大的默认处理，使部署开箱即用更加安全。 （＃1403，＃1677）
  • 多实例支持终于成为现实 - --config 支持落地，运行时路径处理得到清理，CLI 代理现在也支持 --workspace / --config。现在运行单独的机器人、租户或环境要容易得多。 （＃1581，＃1635）
  • MCP 变得更加严格 — SSE 传输支持已加入，自动检测更加智能，并且当发生取消或奇怪的故障时，MCP 工具调用不太可能导致进程中断。 （＃1488，＃1728）
  • 工具变得更加宽容 - 自动铸造工具参数、更安全的验证、优雅的日期时间处理和 read_file 大小限制都有助于纳米机器人在工具或输入变得奇怪时减少失败。 （#1610、#1507、#1508、#1511）
  • 提供商支持不断增长 - Azure OpenAI 支持已上线，阿里云编码计划 API 支持已落地，添加了提示缓存关联标头，并且 GitHub Copilot / Codex 兼容性不断改进。 （#1618、#1563、#1428、#1555、#1637、#1525）
  • Cron 变得更加强大 — 外部 jobs.json 更改受到尊重，作业上下文处理更好，并且不再允许 cron 作业永远递归地安排更多 cron 作业。 （＃1371，＃1375，＃1399，＃1458）
  • 上下文变得更清晰 - 连续的用户消息被合并以避免提供方错误，内部推理隐藏在面向用户的进度更新中，图像 MIME 检测更可靠，提示/平台指导更完善。 （＃1456，＃1655，＃1573，＃1579）
  • Telegram 受到很多喜爱 — 代理处理已修复，支持群组主题，/stop 效果更好，流式消息登陆，通用文档现在保留正确的文件扩展名。 （＃1535，＃1476，＃1482，＃1660，＃1522，＃436）
  • 飞书不断变得更好 - 富文本解析、表/卡分割、更智能的格式选择、Groq Whisper 转录、音频/视频兼容性修复和更清晰的事件处理都在此版本中实现。 （＃1361，＃1384，＃1648，＃1605，＃1531，＃1594，＃332，＃1568）
  • 更多渠道，更多完善 - 钉钉群聊支持、QQ群处理和markdown发送、Discord组策略+附件、WhatsApp媒体支持、Slack回退修复和Matrix媒体标准化都已加入。(#1467, #532, #1727, #553, #1613, #1638, #673, #1406)
  • 跨平台稳定性得到改善 - 更好的 Windows 信号处理、更少的缺失导入/依赖项、更干净的测试以及总体上对纳米机器人在不同环境中表现良好的信心。 （#1598、#1485、#1533、#1546、#1339、#1521）

社区

热烈欢迎本版本中的 29 位新贡献者 - 感谢大家跨渠道、提供商、工具、文档和基础设施参与并改进纳米机器人。由于这些贡献，这个项目不断变得更好。
