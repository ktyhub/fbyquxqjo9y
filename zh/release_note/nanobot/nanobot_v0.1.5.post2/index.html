nanobot v0.1.5.post2

修订 发布时间2026年4月21日 来源HKUDS/nanobot 英文原文

🐈 nanobot v0.1.5.post2 在这里 🎉 — 合并了 67 个 PR，12 个新贡献者。特工的世界变得更大、更稳定。 如果说《v0.1.5.post1》是关于代理学习自我管理，那么《v0.1.5.post2》则是关于影响和完善。 Windows 和 Python 3.14 加入了支持的矩阵。 read_file 工具学会了理解 DOCX、XLSX 和 PPTX。 Microsoft Teams 作为渠道出现。兼容 OpenAI 的 API 开始通过 SSE 进行流式传输。除此之外，大约 50 个涉及 cron、内存、重试、会话文件和提供商怪癖的较小修复不断将“它有效”变成“它很可靠”。专用的浏览器 UI 也开始在存储库中成形——目前的源预览。

亮点

  • Windows + Python 3.14 — 一流的支持 — 涵盖 Windows 运行程序和 Python 3.14 的完整 CI 矩阵，以及针对这些平台暴露的怪癖的安装标记和运行时修复。如果您因为“Windows 不太工作”而在 WSL 上运行 Nanobot，那么您可以停止。 (#3194)
  • Office 文档，本机可读 — read_file 工具现在从 DOCX、XLSX 和 PPTX 中提取文本 — 包括表格和分组形状，工作簿句柄安全关闭。与早期的 PDF 支持相结合，代理可以打开您的同事刚刚通过电子邮件发送给您的任何格式，而无需通过转换器。 （＃3336，＃3269，＃3353）
  • OpenAI 兼容的 API — SSE 流 — /v1/chat/completions 现在在 stream=true 时发出 SSE 块，连接现有的 on_stream / on_stream_end 回调。任何为 OpenAI API 构建的 client（LangChain、LlamaIndex、您自己的前端）都会从纳米机器人获取实时增量，而不是等待整个响应。在后端失败后，端点还会停止终止带有成功标记的流，因此错误会诚实地出现。 （＃3222，＃3262）
  • Microsoft Teams、MiniMax Thinking、LM Studio、MyTool — Microsoft Teams 加入了渠道名册。 MiniMax 拥有专用的人择风格思维端点以及 reasoning_effort → reasoning_split 映射修复。 LM Studio 现在通过可空的 API 密钥为不需要的本地服务器提供支持。新的 MyTool 允许代理自省其自身的运行时配置，并在 check 输出中隐藏敏感的嵌套配置字段，以便自检不会泄露秘密。 （#3197、#3160、#3363、#3186、#3177、#3261）
  • 可靠性 - 版本中乏味的一半 - 会话文件现在使用带有损坏文件修复的原子写入，因此错误的关闭不再会影响您的历史记录。内存游标恢复处理非整数损坏。自动压缩会跳过具有活动任务的会话，并跨整合路径统一摘要注入。提供商获得了响应 API 回退的断路器，并认识到zhiPu 1302速率限制。 Cron 停止泄漏中间进度，其工具架构可与 OpenAI Codex/Responses 配合使用，并且重试心跳不再溢出到用户通道中。子代理后续操作会保留在会话历史记录中。其中有一半你永远不会注意到——这正是重点。 （#3312、#3340、#3081、#3304、#3302、#3356、#3320、#3295、#3229、#3242）
  • 频道 - 更安静、更清晰 - Telegram 获得了长回复的中流分割，以及现代 LLM 输出的更好的降价渲染。 Discord 停止将机器人之间的消息视为自循环，并添加了基于通道的允许列表。电子邮件对 SPF/DKIM 拒绝的邮件进行重复数据删除，以阻止记录垃圾邮件并忽略自行发送的邮箱邮件。 WeCom 正确解析混合入站消息。每个个体都很小；它们加在一起意味着更少的“为什么我的机器人要这么做”的时刻。 （#3329、#3355、#3280、#3171、#3325、#3228、#3161）
  • WebUI - 早期预览，仅源代码 - 专用的 webui/ 已登陆存储库，具有 WebSocket 聊天流程、i18n 语言环境切换器、支持 CJK 的 Apple 风格排版以及实时暗模式代码块主题。底层 WebSocket 通道还学会了通过单个连接复用多个 chat_id。 **注意：这只是源代码预览 - WebUI 故意未捆绑到已发布的轮子中。**如果您想尝试一下，请克隆存储库并从 webui/ 运行它。用户体验确定后，将发布打包版本。 （#3310、#3272、#3314、#3306）

社区

v0.1.5.post2 是当基础完成并且人们开始完成工作时发布的样子。来自 @JiajunBernoulli 的 Windows CI 矩阵。来自 @aiguozhi123456 的 Native Office 文档提取。会话原子写入来自同一作者，捕获真实的数据丢失边缘情况。 Telegram 中流拆分，使长回复真正可读。十二位新贡献者和许多回归的贡献者悄悄地完成了每个人愿望清单上的事情。该代理在 Windows 上运行。它会读取您的文档。即使电源闪烁，它也会保留其历史记录。 webui/ 中的 UI 正在成型，任何人都可以一睹为快。这是一个发布后进行发布后工作的过程——还有一些。
