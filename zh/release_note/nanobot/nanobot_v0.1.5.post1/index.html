nanobot v0.1.5.post1

修订 发布时间2026年4月14日 来源HKUDS/nanobot 英文原文

🐈 nanobot v0.1.5.post1 在这里 🎉 — 80 个 PR 合并，25 个新贡献者。代理人学会了自我管理。 如果说 v0.1.5 是为了让建筑变得宜居，那么 v0.1.5.post1 就是为了让建筑学会自我照顾。现在，代理会在其上下文变得太长之前对其进行压缩，在中途注入后续消息而不是让您等待，从其自己的工作流程中发现可重用的技能，并打开一个 WebSocket，以便任何东西都可以与其通信。与此同时，跨 cron、内存、重试和通道的 40 多个错误修复将“大部分时间都有效”变成了“有效”。

变更流程图

亮点

  • 中途注入 - 后续操作不排队 - 如果您在代理仍在工作时发送另一条消息，它不再在锁后面排队。后续内容被注入到活动回合中，并且在流媒体通道上，回复以相同的实时响应继续。这使得长工具调用链感觉是交互式的，而不是单向的。错误路径上的边缘情况排空在后续过程中得到了强化。 （＃3042，＃3110）
  • Dream 学习技能，而不仅仅是事实 — Dream 的整合流程现在可以识别重复的工作流程，并将其提升为 skills/ 下的独立工作空间技能。与排除不需要的技能的 disabledSkills 配置相结合，代理的技能表面现在可以有机增长并保持可管理性。 （＃3048，＃2959）
  • 自动压缩 - 代理管理自己的上下文 - 会话不再增长，直到遇到问题。自动紧凑监视空闲时间，然后主动总结较旧的上下文，同时保留最近的实时消息 - 因此，当您回来时，代理会记住重要的事情，而不会拖累所有不重要的事情。这不是旧的“破坏会话”的方法；而是一种新的方法。正是外科手术式的压缩让谈话感觉连续不断。在配置中将其与 idleCompactAfterMinutes 配对以进行细粒度控制。 （＃3007，＃3081，＃3093）
  • WebSocket 通道 — 连接任何东西 — 新的 websocket 通道运行具有流式传输（delta + stream_end 事件）、基于令牌的身份验证（静态或已发布）、每个连接会话和 TLS 支持的 WebSocket 服务器。 Web 应用程序、CLI、Chrome 扩展、脚本 - 任何可以打开套接字的东西现在都可以与代理实时通信。 (#2964)
  • 渠道变得更深 - Telegram 获得了位置共享。 Discord 获得了流式回复和代理支持。飞书新增done-emoji生命周期、内嵌工具提示、Lark全局域配置。 QQ、微信得到媒体全力支持。 Slack 的 message 工具现在可将 #channel_name 和 @user 解析为真实 ID。 API 端点接受通过 JSON base64 和多部分上传的文件，并在所有通道上自动提取文档（PDF、DOCX、XLSX、PPTX）。重试放大（发送失败将触发级联重试）在每个通道上都是固定的。 （#2910、#2939、#2960、#2993、#3046、#3044、#3138、#2938、#3053）
  • 提供者 — 适应性思维和 Kimi — Anthropic 的 adaptive 推理模式落地，让 Claude 决定思考的时间和程度。 Kimi 思考能力模型（kimi-k2.5、k2.6-code-preview）现在可以通过 reasoningEffort 自动进行 extra_body.thinking 注射。 StepFun Plan API 推理字段正确回退。非克劳德提供者得到适当的角色交替执行。对于拒绝格式错误的 JSON 的严格提供程序，工具调用参数已标准化。 （#2882、#3124、#2903、#2637、#3154）
  • MCP、工具和搜索 — MCP 资源和提示现在作为只读工具公开 — 代理可以直接查询它们。多个 MCP 服务器以独立的任务进行连接，而不是相互竞争。笔记本编辑工具来了。 Kagi 加入了网络搜索提供商阵容。并且执行工具变得更加严格：Windows 支持登陆，allowed_env_keys 允许您有选择地转发环境变量，内部状态文件被写保护，并且工作区之外的 working_dir 被拒绝。 （#2907、#3019、#3017、#2945、#2893、#2962、#3061）
  • Cron 停止丢弃作业 — 四个单独的 cron 修复解决了作业执行期间的可重入存储重新加载、由于并发存储替换而导致的固定间隔任务重复、作业配置未重新加载以及未保留手动运行状态。如果您依赖计划任务，则此版本会让它们变得无聊。 （＃3038，＃3034，＃2895，＃2930）

社区

欢迎来到我们的 25 位新贡献者，他们在此版本中做出了第一个贡献：@Bahtya、@LeoFYH、@xwind、@Xerxes-cn、@BalorLC3、@invictus-z、@zijiefang、@kronk307、@stutiredboy、@SHLE1、@RohitDayanand、@justforyoudear、@XJPeng12、@linziyanleo、 @chenyahui、@JonasGao、@weitongtong、@danielphang、@mterhar、@ramonpaolo、@nikube、@yeyitech、@ravs-cyberrock、@samyzhh 和 @razzh7。 v0.1.5.post1 反映了我们在提交日志中不断看到的一些内容：最好的贡献并不总是最华丽的。 @weitongtong 捕获的 cron 竞争条件。 @Bahtya 发现的重试放大循环。悄悄吞没消息的通道错误路径，已由@yanghan-cyber 修复。这些改变使得代理变得有价值——不是因为它可以做更多的事情，而是因为它不再做错事。 80 个 PR 后，纳米机器人变得更安静、更稳定，也更成熟了一些。这是值得庆祝的。 完整 Changelog：https://github.com/HKUDS/nanobot/compare/v0.1.5…v0.1.5.post1
