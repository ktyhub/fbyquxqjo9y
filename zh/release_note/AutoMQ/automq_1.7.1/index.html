AutoMQ 1.7.1

修订 发布时间2026年6月23日 来源AutoMQ/automq 英文原文

AutoMQ 1.7.1

变更流程图

亮点

  • 安全：AutoMQ API key 现在需要鉴权 — PR #3410 堵住了 AutoMQ 专用 API key 绕过 ACL 校验的缺口。这最可能让运维措手不及：自定义客户端、管理工具或内部作业调用这些 API 时，原本成功的请求可能突然报鉴权错误，上线前请审计 ACL。
  • 故障转移与重试风暴韧性 — PR #3398 加速故障转移，缩短 broker 丢失后客户端停顿或重连的窗口；PR #3380 加入退避以抑制重试风暴。两者针对的是单次事故演变成客户端集体猛敲的级联故障模式；收益在生产环境的抖动中最明显，稳态基准里看不出来。
  • S3/WAL 上传路径加固 — 一组修复让存储路径更快也更稳：#3419 遇到 NoSuchUploadException 时中止分段上传而不是让 broker 崩溃，#3416 预计算写入校验和，#3407 在上传准备阶段批量处理 objectId 以降低每对象开销，#3414 在获取写权限前校验 WAL 预留。单凭崩溃修复就足以构成升级理由。
  • 压缩、内存与上传节奏 — PR #3423 收窄 v1 压缩清理范围（降低过度删除风险），#3427 在 offset 元数据查询后及时释放记录以缓解内存压力，#3434 平滑间隔性上传，避免延迟尖峰或对 S3 的限流。这些都是安静的正确性与稳定性改进，而非新功能。
  • 可观测性与构建/消费者注意事项 — PR #3424 统一指标导出器命名：看板和告警若基于旧指标名，需要更新。PR #3409 声明了 proto source JAR 依赖，对通过 Maven/Gradle 消费 AutoMQ 制品的团队很重要——此前 proto 源码可能未进入解析后的依赖图。
  • 破坏性变更 — 1.7.1 正式没有；上述 API key 鉴权是唯一值得关注的行为变化。

发生了什么变化

  • 壮举：在 https://github.com/AutoMQ/automq/pull/3380 中添加 @superhx 的重试风暴退避
  • perf(failover): 通过https://github.com/AutoMQ/automq/pull/3398中的@superhx加速故障转移
  • 修复(s3wal): 通过 https://github.com/AutoMQ/automq/pull/3407 中的 @superhx 批处理 objectId (#3374) 优化 wal 上传准备
  • 修复（package）：在https://github.com/AutoMQ/automq/pull/3409中通过@Gezi-lzq声明proto源jar依赖
  • 修复（auth）：在https://github.com/AutoMQ/automq/pull/3410中添加@superhx对AutoMQ API密钥的授权
  • 修复：通过 @superhx 在 https://github.com/AutoMQ/automq/pull/3416 中预先计算 s3 写入校验和
  • 修复（s3stream）：在https://github.com/AutoMQ/automq/pull/3414中@Gezi-lzq获取写入之前验证对象WAL保留
  • 修复（s3stream）：在 NoSuchUploadException 上中止上传部分，以防止 @superhx 在 https://github.com/AutoMQ/automq/pull/3419 中导致代理崩溃 *修复（s3stream）：通过https://github.com/AutoMQ/automq/pull/3423中的@superhx限制清理v1压缩范围
  • 修复：在 https://github.com/AutoMQ/automq/pull/3424 中通过 @superhx 对齐指标导出器命名 *修复（日志）：在https://github.com/AutoMQ/automq/pull/3427中通过@superhx查找偏移元数据后释放记录
  • Chore(s3stream): 平滑@superhx在https://github.com/AutoMQ/automq/pull/3434中的间隔上传 *壮举（发布）：通过@superhx在https://github.com/AutoMQ/automq/pull/3435中发布1.7.1
