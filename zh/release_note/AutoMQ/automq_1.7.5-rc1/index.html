AutoMQ 1.7.5-rc1

这个项目是干啥的：是一个兼容Kafka的消息队列，把数据存在便宜的云存储里，让处理海量实时数据的团队既能省钱，又不怕机器宕机丢消息。

变更架构图

亮点

  • 元数据生命周期清理 — 回放处理 RemoveTopicRecord 时现在会清除待处理的 topic 配置，避免旧设置泄漏到同名重建的 topic（#3575）。空的 partition-to-stream 映射也被前瞻性剪枝以限制 metadata-image 增长；已存在的陈旧条目不会回溯清除（#3593）。
  • S3Stream 可用性与提交进度 — 可恢复的对象列举失败现在带退避重试，不再永久污染 Router-WAL 启动（#3603）；但持续故障会让启动一直挂起，因为重试没有上限。全局惰性提交在 WAL 缓存为空时也能完成，避免空闲 broker 拖住 ZeroZone 已提交 epoch（#3600）。
  • 保留策略安全的时间戳查询 — 基于时间戳的 ListOffsets 查找现在遵循日志起始 offset、跳过过期段，并继续进入后续符合条件的段，避免返回低于 LSO 的 offset 或在保留边界处误判未命中（#3610）。
  • ZeroZone router WAL 设置现在生效 — URI 参数如 batchInterval、maxBytesInBatch、maxInflightUploadCount 此前被忽略，现在会传到 ObjectWALConfig（#3619）。升级前请检查现有 router URI：配置的批处理和上传并发值终于会影响运行时行为。
  • 感知复制的负载测试 — automq perf 新增 --replication-factor（默认 1，范围 1–32767），作用于新建 topic 和 Ducktape 性能服务（#3613）。复用的 topic 不会被重新分配，因此要复现生产复制拓扑时请在创建前指定该因子。
  • 兼容性 — 未提及破坏性变更或存储格式迁移。

  • 修复(docker): 在https://github.com/AutoMQ/automq/pull/3597中通过@Gezi-lzq更新S3容器镜像

  • 修复(s3stream): 当 https://github.com/AutoMQ/automq/pull/3600 中的 @superhx WAL 缓存为空时完成延迟提交 *壮举：https://github.com/AutoMQ/automq/pull/3606中@superhx从1.8-#3605中挑选
  • 修复（日志）：在https://github.com/AutoMQ/automq/pull/3610中通过@superhx在时间戳查找中尊重日志开始偏移
