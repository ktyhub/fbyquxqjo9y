AutoMQ 1.7.2

修订 发布时间2026年7月21日 来源AutoMQ/automq 英文原文

AutoMQ 1.7.2

变更流程图

亮点

  • 故障转移与元数据路径延迟 — 故障转移做了延迟优化（#3412、#3443），list-offset 处理并行化（#3445、#3446），繁忙集群的恢复时间和元数据响应应会改善。fix(s3stream): track stalled pending requests（#3441）也有助于暴露卡住的 S3 操作。关心故障恢复时间或 list-offset 高负载的团队应升级；否则这也是扎实的增量可靠性提升。
  • S3 存储行为与内存效率 — feat(s3stream): support cross-bucket multipart copy（#3450）打通跨 bucket S3 工作流，fix(s3stream): distinguish unset write bucket（#3451）纠正写 bucket 未设置时的处理，feat(s3stream): recycle sequential byte buffer slabs（#3461）减少缓冲区分配抖动。这些对 S3 后端或多 bucket 部署、以及内存压力大的 broker 最重要。
  • 客户端兼容与运维控制 — 如果你用 kafka-go 客户端且遇到过元数据兼容问题，fix: add kafka-go metadata compatibility mode（#3459）是升级的关键理由。运维还获得 feat: add runtime monitor（#3420）、feat(connect): Add Connect startup failure log（#3354）和 feat: support shared network bandwidth limiter（#3457），便于诊断和带宽管理。
  • TableTopic/Debezium 变更与升级建议 — TableTopic 用户应检查 fix(tabletopic): use stable fps metric name（#3440），引用旧指标名的看板或告警可能要更新；feat(tabletopic): derive identifiers from Debezium key（#3462）改变了 Debezium key 流的标识符派生方式。除可能的指标名更新外，changelog 未指出 API 破坏性变更或明确迁移步骤；1.7.1 上受上述领域影响的用户应升级，其余环境若运行稳定可跳过此补丁。

  • 修复（tabletopic）：在 https://github.com/AutoMQ/automq/pull/3440 中使用@Gezi-lzq 稳定的 fps 指标名称 *修复（s3stream）：跟踪https://github.com/AutoMQ/automq/pull/3441中@superhx的停滞待处理请求
  • perf(failover)：优化故障转移以减少延迟。 （＃3412）由 @superhx 在 https://github.com/AutoMQ/automq/pull/3443
  • feat(connect): 在https://github.com/AutoMQ/automq/pull/3354中添加@woshigaopp的Connect启动失败日志
  • 壮举：在 https://github.com/AutoMQ/automq/pull/3445 中通过 @superhx 并行化列表偏移处理
  • 重构：通过https://github.com/AutoMQ/automq/pull/3446中的@superhx减少列表偏移并行化差异
  • feat(s3stream): 支持https://github.com/AutoMQ/automq/pull/3450中@superhx的跨桶多部分复制
  • 修复(s3stream): 区分https://github.com/AutoMQ/automq/pull/3451中@superhx未设置的写入桶
  • 重构(s3stream)：通过 https://github.com/AutoMQ/automq/pull/3453 中的 @superhx 将指标声明移至所有者 *壮举：在https://github.com/AutoMQ/automq/pull/3457中支持@superhx的共享网络带宽限制器
  • 修复：在https://github.com/AutoMQ/automq/pull/3459中通过@superhx添加kafka-go元数据兼容模式
