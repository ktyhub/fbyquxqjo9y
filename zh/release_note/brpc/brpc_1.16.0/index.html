brpc 1.16.0

小版本 发布时间2026年1月25日 来源apache/brpc 英文原文

brpc 1.16.0

这个项目是干啥的：百度开源的 RPC 网络框架，让不同服务之间高效互相调用，支持多种协议和高并发，适合写高性能后端服务的工程师。

变更架构图

亮点

  • Protobuf 与工具链兼容性 — 通过把 absl::string_view 适配为 std::string 支持 Protobuf v30+（#3187），并带来 C++23、OpenSSL 链接与 butil 未定义行为修复（#3180、#3159、#3135）。升级 protobuf 的团队应做干净重建，并对序列化热点路径做转换开销基准测试。
  • RDMA 吞吐与并发 — RDMA 块池现可动态扩容（#3155），消息在新 bthread 中执行（#3117），减少固定容量与轮询瓶颈。SQ 溢出修复（#3145）提升负载下稳定性；请针对你的负载验证池大小与背压。
  • 可观测性与调试 — 命名 bthread（#3158）、可配置栈追踪信号（#3124），以及检查所有存活 bthread（#3096），让生产并发问题更易诊断。SetName 死锁与 TaskTracer ABA 修复（#3127、#3115）也减少追踪时的挂起。
  • TLS 诊断 — 设置 SSLKEYLOGFILE 可捕获 TLS 会话密钥用于报文检查（#3173），并提供额外的证书校验模式（#3141）。请把密钥日志当作敏感材料，仅在受控调试环境启用。
  • 部署灵活性 — RISC-V 支持（#3125）与 pthread CPU 亲和性（#3122）拓宽架构与调度选项。亲和性作用于 pthread worker，调优延迟敏感服务时应单独评估 bthread 放置。
  • 服务与协议健壮性 — 新 channel tag 支持选择性 channel 处理（#3189），Couchbase CRUD 支持（#3138）新增一个后端。端点端口校验现拒绝畸形输入（#3193），移除 Redis 解析器递归（#3136）避免深层嵌套命令导致栈耗尽。
  • 破坏性变更 — 未列出破坏性变更。

Apache bRPC 1.16.0 是一个功能版本，其中包括兼容性、性能和功能方面的重大改进。此版本增加了对新架构的支持，增强了调试功能，改进了 RDMA 支持，并修复了多个关键错误。

特点

  • 通过@wasphin 支持 protobuf v30+ 兼容性（将absl::string_view 包装为std::string） (#3187)
  • 添加@Dayuxiaoshui 的 RISC-V 架构支持 (#3125)
  • 支持 @altman08 的选择性频道标签 (#3189)
  • @koarz 通过 SSLKEYLOGFILE 环境变量启用 TLS 密钥日志记录 (#3173)
  • 支持更多 SSL 验证模式 @koarz (#3141)
  • 添加 Couchbase 对 CRUD 操作的支持 @giriraj-singh-couchbase (#3138)
  • 支持命名 bthread 以帮助调试 @ZhengweiZhu (#3158)
  • 支持@chenBright动态扩展RDMA块池（#3155）
  • 通过@ZhengweiZhu 配置 bthread 堆栈跟踪信号数量 (#3124)
  • 支持 @chenBright 共享的 mbvar (#3129)
  • 添加 pthread CPU 亲和性支持 @wenjiecn (#3122)
  • RDMA 轮询模式增强（所有消息在新的 bthread 中运行），作者：@yanglimingcn (#3117)
  • 通过 @chenBright 提供的 Babylon 计数器支持更高性能的 bvar (#3116)
  • 添加对检查所有活动 bthreads 的支持，作者：@ZhengweiZhu (#3096)

错误修复

  • 通过 @AnantShukla-Git-Hub 修复 str2endpoint 中的端口解析验证 (#3193)
  • @liyinsg 修复 C++23 编译问题 (#3180)
  • 通过 @jesson1 在静态初始化期间修复 read_proc_io 中的 SIGSEGV (#3184)
  • 修复@chenBright 的 SQ 溢出错误 (#3145)
  • 修复 @Searion 的 gdb_bthread_stack bthread_begin 错误 (#3176)
  • 修复 @chenBright 的冗余 BeforeAdditionalRefReleased 调用 (#3174)
  • 添加 @kisuke95 为 uint32_t 遗漏的 RegisterFlagValidatorOrDie 定义 (#3171)
  • 通过 @chenBright 修复 NsheadService::_status 空指针 (#3162)
  • 通过 @apocelipes 修复 OpenSSL 动态库链接顺序 (#3159)
  • 通过 @songqing 修复 bvar 的错误返回值 (#3151)
  • 通过 @wwbmmm 修复命名服务单元测试失败 (#3153)
  • 删除 redis 命令解析器中的递归 @howzi (#3136)
  • 修复 @chenBright 的 RDMA 单元测试 (#3146)
  • 修复 SetName 中的死锁（使用 SetNameSimple 代替），作者：@chenBright (#3127)
  • 修复 SignalSyncs 存储（仅存储失败的）由 @chenBright (#3128)
  • 修复由于 ABA 问题导致的 TaskTracer 死锁，作者：@chenBright (#3115)

增强功能

  • 修复 @BusyJay 的 butil 库中未定义的行为 (#3135)
