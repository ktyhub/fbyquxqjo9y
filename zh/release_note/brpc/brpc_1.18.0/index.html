brpc 1.18.0

小版本 发布时间2026年9月17日 来源apache/brpc 英文原文

brpc 1.18.0

这个项目是干啥的：百度开源的 RPC 网络框架，让不同服务之间高效互相调用，支持多种协议和高并发，适合写高性能后端服务的工程师。

变更架构图

亮点

  • 解析器加固是重头戏——把 1.18.0 当作安全升级 — 本版本大量限制线路声明的大小与解压输出（#3382, #3476），并关闭可远程触发的内存安全缺陷：HTTP/2 接收路径资源增长（#3474）、通过 HTTP/1 desync 分帧与丢弃 chunked trailer 实现的请求走私（#3521）、header/URL 查找表中字符符号性导致的越界读（#3376）、AVC SPS 解析中的 exp-golomb 越界读（#3371, #3483, #3334），以及 SingleIOBuf::assign 的释放后使用（#3397）。Redis、AMF、mcpack2pb 与 Thrift 也加入深度/分配上限（#3344, #3353, #3499, #3500）。若把 brpc 的 HTTP 或 Redis 端点暴露给不可信流量，升级能关闭真实可远程触发的缺陷——但要有心理准备：此前被容忍的超大或深层嵌套负载现在会被拒绝。
  • 内置服务迁到 internal_port——上线前规划迁移 — #3308、#3511、#3512 与 #3525 把内置服务（/vars、/status、pprof 等）置于 ServerOptions.internal_port 之后，并对到达公网端口的内置请求施加鉴权检查。这是对运维最具干扰性的变化：在你设置 internal_port 并重新指向之前，健康检查、指标抓取与调试端点将不再在公网端口响应，因此在把 1.18.0 放到负载均衡后面之前，先更新探针与监控配置。
  • 新协议与现代 TLS 显著拓宽采用面 — 干净室实现的 MySQL 客户端覆盖认证、文本协议、事务与预处理语句（#3310, #3330），简单集成可去掉独立的 MySQL 客户端；TLSv1.3（#3319）加上客户端对端名称校验（#3408）让传输安全现代化（对端校验是新行为——外部调用应开启）；支持 Protobuf v35（#3429）解除较新 protobuf 项目的阻塞，body+attachment 校验和（#3407）端到端保护大负载。
  • RDMA 迎来正确性整治——另有共享内存替代方案 — 带 ECE 协商的握手 V3（#3350, #3326, #3352）与基于 LD/ST 的 UBShmTransport（#3290）一同到来，同时修复此前回退路径失败 socket 而非降到 TCP 的问题（#3424, #3406）、重新布防后漏掉接收 CQE（#3425）、服务端数据竞争（#3505）与陈旧 CQ 回调（#3412）。RDMA 用户应重新测试故障转移：Socket::_state 现为原子（#3347），回退时机与状态转换已改变。
  • 流式 RPC 重构，带来新限制与两个新负载均衡器 — #3422 重构流式 RPC 并加入流 ID 校验、每请求流上限与重组消息大小限制（#3485, #3489, #3493, #3494）；请对照这些新上限核验流数量与消息大小。路由方面，Peak-EWMA p2c（#3367）与有界负载一致性哈希 c_murmurhash_bl（#3502）变为可选，WeightedRandomizedLoadBalancer 不再跳过最后一台服务器（#3426）——这是微小但真实的流量分布变化，升级后值得观察。
  • 工具链基线与 API 面变化——构建前请检查 — 所有构建现以 C++14 为目标（#3419），bthread 移除此前未实现的 barrier 与 rwlockattr API（#3504）；ADD/SUB_TLS_PTHREAD_LOCK_COUNT 宏变为内联函数（#3394），ARM 上 TLS 指针访问加入宏保护（#3380）。Bazel 用户获得修复的外部依赖 proto 规则（#3427）与 bzlmod 指南（#3468），RISC-V 新增 Zvbc CRC32C（#3332）及一系列 RVV memcpy/base64/string 优化。升级前请确认编译器满足 C++14，并移除对已移除 bthread 符号的引用。

Apache bRPC 1.18.0 扩大了协议覆盖范围和平台支持，并显着强化了解析器和传输内部结构。
