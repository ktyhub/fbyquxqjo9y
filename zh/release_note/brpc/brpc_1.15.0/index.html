brpc 1.15.0

这个项目是干啥的：百度开源的 RPC 网络框架，让不同服务之间高效互相调用，支持多种协议和高并发，适合写高性能后端服务的工程师。

变更架构图

亮点

  • ARM64 及负载下的 bthread 调度正确性 — 修复若干底层并发缺陷，否则它们可能在生产中表现为挂起或崩溃：aarch64 上 bthread_id_unlock 失败（#3084）、SIMD 未对齐问题（#3092），以及 Signal Trace 模式把 SIGURG 送到错误线程（#3039）。若在 ARM64 上运行 brpc 或启用信号追踪，这些是本版本最高优先级的修复——尤其信号缺陷可能表现为无关线程中的莫名中断。
  • 新增选择启用的 bthread 调参开关 — 新增可配置的 ParkingLot 数量（#3033）、bthread 优先级队列 flag（#3078）、「无等待者时不发信号」的 parking lot flag（#3079），以及 timer bucket 数量 flag（#3112）。所有新 flag 默认 false/既有行为，采用默认零风险；其价值在于此前无法调节调度唤醒或锁分片的高争用服务。在重并发下分析尾延迟时应关注这些开关。
  • RDMA 更易构建且更具扩展性 — brpc::rdma::GlobalRdmaInitializeOrDie 现在即使未定义 BRPC_WITH_RDMA 也会声明（#3047），调用方无需强制完整 RDMA 构建即可针对该 API 编译。RDMA 运行时还放宽块限制，并把轮询模式的消息处理移入新 bthread（#3076），应提升 RDMA 用户的吞吐/隔离——若依赖旧的轮询内处理假设，请仔细测试。
  • 更好的延迟可见性与更安全的诊断 — RPC 现向用户暴露 received_us（#3073），实现此前仅内部可用的准确服务端排队/延迟归因；MultiDimension::set_max_stats_count 公开（#3074）便于统计控制，pb2json 新增深度限制（#3099），jemalloc profiler 限制额外选项（#3101）——前者防止深层嵌套 protobuf 转 JSON 导致的栈耗尽，若你接收不可信 protobuf，这是真实关切。
  • 构建与依赖可移植性 — 通过把 InstallSymbolizeOpenObjectFileCallback 标记为 BAIDU_WEAK 修复与 glog 的符号冲突（#3064），使 brpc 与基于 glog 的技术栈更干净共存。还新增 with_bthread_tracer（#3111）与 NO_PTHREAD_MUTEX_HOOK（#3090）的 Bazel 配置开关，修复含 CMake < 3.5 兼容的 macOS CI（#3080、#3093），并把 google::protobuf::int64 换成普通 int64_t（#3081）——共同降低嵌入、旧工具链与非默认构建配置的阻力。
  • 核心数据路径的稳定性修复 — 处理 socket _versioned_ref 恢复并移除 _hc_started flag（#3060），在 IntRecorder 构造函数中初始化 _combiner（#3066），修复 bucket 数为 2 的幂时 flatmap 扩容的死循环（#3071），防止 WeightedRandomizedLoadBalancer 在无服务器时返回 0（#3108），并移除 SSL 的 BIO 使用（#3105）。这些改动安静但重要：flatmap 循环与负载均衡边界情况在特定条件下会导致 CPU 空转或错误路由，即使不需要新功能也应升级。

错误修复：

  • 修复套接字 _versioned_ref 无法恢复 && 删除 _hc_started 标志 (#3060) by @howzi
  • 通过将 InstallSymbolizeOpenObjectFileCallback 标记为 BAIDU_WEAK 来修复与 glog 的符号冲突 (#3064) by @wangrufeng 和 @ruru
  • 错误修复：@chenBright 在 IntRecorder 构造函数中未初始化 _combiner (#3066)
  • 修复当存储桶计数为 2 的幂时平面地图调整大小时的无限循环 (#3071) by @gitccl
  • 错误修复：MultiDimension::set_max_stats_count 应公开 (#3074)，作者：@chenBright
  • 错误修复：信号跟踪模式可能会通过 @CodeZHXS 将 SIGURG 发送到错误的线程 (#3039)
  • 修复 macos ci (#3080) by @chenBright
  • 修复：修复 aarch64 cpu 中 bthread_id_unlock 失败的问题（#3084），作者：@zhoukangsheng
  • 修复了 macos ci 与 CMake < 3.5 (#3093) by @chenBright 的兼容性
  • bthread：修复 simd 内存对齐问题 (#3092) by @icexin
  • 错误修复：WeightedRandomizedLoadBalancer 在没有服务器的情况下返回 0 (#3108) by @chenBright
  • bazel：修复 with_bthread_tracer 配置设置（#3111），作者：@icexin

增强功能：

  • 添加 brpc::rdma::GlobalRdmaInitializeOrDie 的声明，但不定义 BRPC_WITH_RDMA(#3047) by @yanglimingcn
  • 支持自定义停车场号码 (#3033) by @chenBright
  • 将 RPC 的 receive_us 暴露给用户 (#3073) by @liupengs
  • 重构：在 brpc::Span 中使用 static_cast 进行更安全的向下转型 (#3075)，作者：@zhangqiongyu 和 @xulei25
  • 为 bthread 优先级队列添加标志，默认为 false (#3078) by @chenBright
  • 添加停车场无服务员时无信号的标志，默认为 false (#3079) by @chenBright
  • 使用 int64_t 而不是 google::protobuf::int64 (#3081) by @chenBright
  • rdma rumtime 扩展块限制和 rdma 轮询模式在新 bthread 中处理消息 (#3076) by @yanglimingcn
  • bazel：添加 NO_PTHREAD_MUTEX_HOOK 的配置设置（#3090），作者：@icexin
  • 删除 SSL 的 BIO (#3105) by @jianrujie
  • 添加 pb2json 深度限制 (#3099) by @wwbmmm
  • 限制 jemalloc 分析器的额外选项 (#3101) by @chenBright
  • 添加 brpc 计时器桶计数标志 (#3112) by @yanglimingcn
