airflow 1.14.0

小版本 发布时间2024年6月19日 来源apache/airflow 英文原文

airflow helm-chart/1.14.0

变更流程图

亮点

  • 多命名空间 RBAC 资源被重命名 — 在 multiNamespaceMode 下，pod-launcher、pod-log-reader 和 SCC 的 role/binding 现在会加上 {{ .Release.Namespace }}- 前缀，以防命名冲突（#37197）。请更新引用旧名称的外部策略、监控和自动化，并在升级后检查是否有残留的旧 RBAC 对象。
  • worker 默认改为抵抗自动扩缩驱逐 — workers.safeToEvict 现在默认为 false，阻止 Cluster Autoscaler 缩掉承载 Airflow worker 的节点（#40229）。这保护了运行中的工作负载，但会拖慢容量回收；想要旧行为请设为 true。生成的 pod 模板也新增了 safe-to-evict 支持（#37352）。
  • 默认 Airflow 运行时从 2.8.3 移到 2.9.2 — 上线前请查阅 Airflow 2.9 升级指引，并测试 DAG、插件和 provider 的兼容性（#40160）。镜像覆盖会绕过此默认值，所以固定版本的部署需要显式做出升级决定。配套镜像也变了：StatsD Exporter 移到 0.26.1（#38416），Redis 限制在 7.2 线（#38928）。
  • 移除对 Kubernetes 1.25 的支持 — 仍在运行 1.25 的集群必须先升级才能采用此 chart（#38367）。values schema 现在用 Kubernetes 1.29 资源定义生成（#38460）；请按支持的版本矩阵验证自定义 manifest 和 API 用法，不要假设 schema 支持就等于运行时兼容。
  • executor 与自动扩缩覆盖面扩大 — chart 新增 AWS executor 支持（#38524），并为 triggerer 启用 MySQL 支持的 KEDA 扩缩（#37365），减少这些部署模式的自定义配置。KubernetesExecutor 部署还可以设置 workers.command（#39132）来控制 worker 启动参数，而不必替换 chart 的 pod 模板。
  • 容器与 pod 配置更原生 — 组件环境变量现在接受 valueFrom 以引用 Secret/ConfigMap 中的变量（#40135），extraContainers 和 extraInitContainers 支持模板化（#38507、#38510）。作业新增 priorityClassName（#39133），pod 模板可包含 Kerberos sidecar（#38815）；上线前请用 helm template 验证模板化 sidecar。

重大变化

ClusterRole and ClusterRoleBinding 名称已更新为唯一 (#37197)

已启用“ClusterRole``s and ``ClusterRoleBinding``s created when ``multiNamespaceMode”已重命名以确保名称唯一：

  • {{ include "airflow.fullname" . }}-pod-launcher-role has been renamed to {{ .Release.Namespace }}-{{ include "airflow.fullname" . }}-pod-launcher-role
  • {{ include "airflow.fullname" . }}-pod-launcher-rolebinding has been renamed to {{ .Release.Namespace }}-{{ include "airflow.fullname" . }}-pod-launcher-rolebinding
  • {{ include "airflow.fullname" . }}-pod-log-reader-role has been renamed to {{ .Release.Namespace }}-{{ include "airflow.fullname" . }}-pod-log-reader-role
  • {{ include "airflow.fullname" . }}-pod-log-reader-rolebinding has been renamed to {{ .Release.Namespace }}-{{ include "airflow.fullname" . }}-pod-log-reader-rolebinding
  • {{ include "airflow.fullname" . }}-scc-rolebinding has been renamed to {{ .Release.Namespace }}-{{ include "airflow.fullname" . }}-scc-rolebinding

workers.safeToEvict 默认值更改为 False (#40229)

workers.safeToEvict 的默认值现在默认为 False。这是更安全的默认设置 因为它可以防止正在运行的节点被缩减 K8s Cluster Autoscaler <https://kubernetes.io/docs/concepts/cluster-administration/cluster-autoscaling/#cluster-autoscaler>_。 如果您想保留以前的行为，可以将此配置设置为 True。

默认 Airflow 图像更新为 2.9.2 (#40160)

与图表一起使用的默认气流图像现在是“2.9.2``, previously it was ``2.8.3”。

默认 StatsD 图像更新为 v0.26.1 (#38416)

与图表一起使用的默认 StatsD 图像现在为“v0.26.1``, previously it was ``v0.26.0”。

新功能

  • 启用 MySQL KEDA 对触发器的支持 (#37365)
  • 允许 AWS 执行程序 (#38524)

改进

  • 允许在组件的环境配置中使用 valueFrom (#40135)
  • 在 extraContainers and extraInitContainers 中启用模板 (#38507)
  • 将安全驱逐注释添加到 pod-template-file (#37352)
  • 支持 KubernetesEecutor 的 workers.command (#39132)
  • 将 priorityClassName 添加到作业 (#39133)
  • 将 Kerberos sidecar 添加到 pod-template-file (#38815)
  • 添加对额外容器的模板化字段支持 (#38510)

错误修复

  • 将 workers.safeToEvict 默认设置为 False (#40229)

文档仅更改

  • 模板化文档 extraContainers and extraInitContainers (#40033)
  • 修复 HorizontalPodAutoscaling 文档中的拼写错误 (#39307)
  • 修复文档中支持的 k8s 版本 (#39172)
  • 修复 YAML 路径中“brokerUrlSecretName”的拼写错误 (#39115)

其他

  • 默认 Airflow 版本为 2.9.2 (#40160)
  • 将 Redis 图像限制为 7.2 (#38928)
  • 使用 Kubernetes 1.29 资源构建 Helm 值模式 (#38460)
  • 将缺失的容器添加到资源文档中 (#38534)
  • 将 StatsD 导出器映像升级到 0.26.1 (#38416)
  • 删除 K8S 1.25 支持 (#38367)
