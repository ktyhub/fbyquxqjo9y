airflow 3.0.4

修订 发布时间2025年8月8日 来源apache/airflow 英文原文

airflow 3.0.4

变更流程图

亮点

  • 强制终止任务 — 当 TaskSDK 任务被外部杀死时，BaseOperator.on_kill 现在会运行，DAG Processor 失败回调也在同一路径触发（#53832、#53143）。因此清理和告警能覆盖手动终止和 worker 级 kill；请用强制 kill 而非仅正常失败来测试这些钩子。
  • 调度器与 API server 韧性 — 修复消除了调度器心跳偶发的 DetachedInstanceError（#53858），并防止大日志读取耗尽 API server 内存（#53167）。日志检索现在改为流式，查看高volume任务日志时更不容易拖垮控制面。
  • 远程日志与私有 TLS — 当 secrets backend 不提供连接时，日志 provider 现在可通过 API Server 加载元数据数据库连接（#53761），同时 API server 客户端支持自签名证书（#53793）。这恢复了基于连接的远程日志，并让私有 PKI 部署不再只能依赖实例凭据。
  • 连接编辑与异常 — 连接更新现在会保留密码和 extra，而不是静默丢弃敏感字段（#53973），Airflow 2.x 与 3.x 的连接异常行为也保持一致（#53093）。请审计那些精确匹配异常类的自动化，尤其是凭据轮换工作流。
  • 兼容性敏感行为 — start_from_trigger 被无条件禁用，因为它在 Airflow 3 中不工作（#53750）；NaN 和无穷大现在序列化为字符串以生成合法 JSON（#53844）。请移除对 trigger 启动执行的依赖，并更新那些假设数值为特殊浮点值的自定义客户端。
  • SDK 迁移与 Python 打包 — 从 Airflow models 导入 Connection 现在会发出弃用提示，引导改用 SDK（#53621）。另外 requires-python 去掉了上界和 ~= 语法（#52984、#52987），因此请继续使用 3.0.4 的 constraints 文件，不要让更新的 Python 版本超出 provider 支持范围。

未声明破坏性变更。
