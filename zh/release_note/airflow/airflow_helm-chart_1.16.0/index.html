airflow 1.16.0

小版本 发布时间2025年4月2日 来源apache/airflow 英文原文

airflow helm-chart/1.16.0

变更流程图

亮点

  • Airflow 3 成为默认架构 — chart 默认使用 Airflow 2.10.5（高于 2.9.3）和 FabAuthManager（#46624、#47976）。Airflow 3 部署会运行独立的 DAG processor 和 API server，而 Airflow 2 保留 webserver（#45659、#47085）；升级前请核验你的 airflowVersion、auth manager 和组件拓扑。
  • 公共 API 迁至 /api/v2 与 8080 端口 — AIP-84 将公共 API 移到 /api/v2 下，API server 改用 8080 端口（#47760、#47310）。请更新 ingress 规则、服务探针、健康检查以及客户端；CLI 命令也从 fastapi-api 改为 api-server（#47076）。
  • 多 executor 支持进入可用阶段 — chart 支持多个 executor，并修复了 executor 专属的 scheduler 与 role-binding 问题（#43606、#44424、#46039、#46486）。executor 指标名称和 role binding 已变更以避免冲突（#40778），因此请审查自定义 RBAC、scheduler 配置和 Prometheus 查询。
  • 基础设施默认值大幅升版 — git-sync 升到 4.3.0，PgBouncer 升到 1.23.1，PgBouncer Exporter 升到 0.18.0，StatsD Exporter 升到 0.28.0（#41411、#47416、#43393）。即使你固定了 Airflow 镜像，这些默认值仍会影响仓库同步、连接池和指标行为。
  • 新增更多部署级控制项 — 新选项涵盖 webserver HPA（#41955）、Redis NodePort（#41811）、复用已有 Redis PVC（#41619）、worker 的 extraPorts 与 podManagementPolicy（#46679、#42673）、迁移作业环境变量（#42345），以及 log-groomer sidecar 与执行频率（#46003、#46237）。
  • 配置与可观测性修复需显式审查 — triggerer 选项 default_capacity 更名为 capacity（#48032），execution_api_server_url 移入 core 段（#46969），新增的 ti.running 与 DAG-processor 心跳指标提升了任务可见性（#47773、#42398）。请针对重命名或迁移的设置审查 values 覆盖和告警仪表盘。

上游 changelog 未明确指出破坏性变更。
