airflow 2.7.3

修订 发布时间2023年11月6日 来源apache/airflow 英文原文

airflow 2.7.3

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • Python 3.12 与依赖上限 — 此补丁明确把 Airflow 限制在 < 3.12（#35123），并为 pendulum<3.0（#35336）、connexion<3.0（#35218）、sentry_sdk==1.33.0（#35298）和 WTForms<3.1.0（#34943）加上硬性上界。如果你计划上线 Python 3.12，在这里会被挡住；这些固定也意味着未来升级很可能需要协调地一起移动依赖，而不是简单替换版本。
  • 调度器与 triggerer 可靠性 — 两条崩溃路径被封堵：DAG run 创建失败时 scheduler 不再陷入崩溃循环（#35135），守护模式下 triggerer 线程不再崩溃（#34931）。两者都是值得优先处理的生产稳定性修复——前者尤其影响处于数据库争用或并发创建 DAG run 下的部署。
  • 动态任务映射正确性 — 修复映射任务组内任务被过早求值的问题（#34337）。如果你依赖 expand()/expand_kwargs()，且组中映射值来自上游 XCom，这消除了一类「在输入就绪前就运行」的缺陷——现在这些变通措施不再需要，请核验并移除你加过的 workaround。
  • REST API 语义 — 多项端点细化同时落地：trigger_rule 值现在出现在 REST API 中（#35194），dag_run 和 task_instance 端点获得一致性修复（#34942），只读字段现在拒绝写入（#33413），而用 ~ 作为 dag_id 只返回可读 DAG 的任务实例（#34939）。API 消费方应重新检查任何写入只读字段或依赖旧 ~ 通配行为的代码。
  • 触发规则与时区行为变化 — 使用 all_skipped 触发规则的任务，现在只要任一上游任务为 upstream_failed 就被标记为 skipped（#34392），TimeSensorAsync 现在遵循 DAG 的时区而非 UTC（#33406）。后者可能改变非 UTC DAG 中延迟 sensor 的触发时间——升级前请审计对时区敏感的调度。
  • 前端依赖安全升级 — airflow/www 下 @babel/traverse 升到 7.23.2（#34988），undici 升到 5.26.3（#34971）。这些是传递依赖/安全驱动的更新，预期无功能变化，但依赖审计会更干净。

此版本无破坏性变更。
