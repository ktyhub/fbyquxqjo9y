airflow 3.0.2

修订 发布时间2025年6月10日 来源apache/airflow 英文原文

airflow 3.0.2

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • 通过兼容垫片让 Airflow 2 → 3 迁移更平滑 — 3.0.2 为 EmailOperator（#51004）和 BaseNotifier（#50340）恢复了带弃用警告的兼容垫片，旧的自定义 operator 和 notifier 升级后仍能导入，不会直接报错。结合覆盖自定义 operator 的迁移指南（#50871、#50948）和修订后的升级路径（#50318），这是有意补齐 2→3 鸿沟的举措。如果你曾因自定义 operator 失效而搁置 3.0 升级，这个补丁值得重新评估。
  • 本地测试改走 Task SDK 执行路径 — dag.test（#50300、#50419）、task.test（#50827）和 ti.run（#50141）均已移植到 Task SDK，airflow dags test 现在也能从本地文件运行（#50420）。本地运行现在会使用与生产环境相同的序列化/上下文机制——保真度更高，但如果测试依赖旧的内存内执行路径，需注意行为变化（例如 dag.test() 中延迟任务的恢复本身就在 #51182 中修复了）。
  • 配置项位置调整——检查你的 airflow.cfg — secret_key 移到了 [api] 段（#50839），各种 webserver 设置迁入了 fab provider（#50774、#50269、#50208、#50896）。如果你通过配置文件或环境变量覆盖这些项，需要更新段名/键路径，否则值会被静默忽略。config 命令也去掉了一个多余的「破坏性」标志（#50781），便于查看新的配置布局。
  • bundle 路径加入 sys.path — 任务运行器（#51318）和 DAG processor（#50385）现在都会把 bundle 路径前置到 sys.path。这是一项务实的修复：DAG 和任务可以直接导入随 bundle 一起分发的自定义包，无需手工配置 PYTHONPATH——对 airflow:3 Docker 镜像或远程 bundle provider 尤其重要。
  • 映射任务与 XCom 的正确性 — LazyXComSequence 新增切片以支持过滤映射任务项（#50117），映射任务使用自定义后端时 XCom 反序列化恢复正常（#50687），upstream_mapped_index 也得到正确处理（#50641）。再加上上下文变量中 logical_date 的正确填充（#50898），以及 Airflow 3 中插件定义的宏重新可用（#50642，宏在 #50940 中迁至 Task SDK 的 execution_time 模块），这补齐了若干可能破坏动态任务输出的数据面缺口。
  • API 兼容性与 processor 稳定性加固 — /run 端点恢复了对旧版 Task SDK 客户端的向后兼容，批量 API schema 得到修正以支持 OpenAPI/客户端生成（#50852），变量端点接受含斜杠的键（#50841），patch_task_instance 现在能处理摘要和任务组（#50550）。可靠性方面，修复了 dag-processor 内存泄漏（#50558）、心跳超时时任务管理器 CPU 飙升（#51023），以及 DAG 导入期间的 SIGSEGV 处理（#51171）——如果你在大规模环境运行长驻 processor，这些尤为重要。

此补丁版本没有有意引入破坏性变更。
