airflow 2.10.0

变更流程图

亮点

  • Dataset 调度仅在 DAG 活跃时推进（#38891） — DAG 暂停或被移除期间收到的事件，在其恢复时不再满足调度条件。事件驱动集成必须考虑这项破坏性变更；基于时间的调度（包括 DatasetOrTimeSchedule）不受影响。
  • try_number 在任务被调度时固定（#39336） — 它不再在 worker 启动时递增，并在重新调度/延迟周期内保持不变；只有新的尝试才递增。使用 ti.run() 或 airflow tasks run 的自定义 runner 必须停止依赖自动递增。
  • FAB 登出现在需要 POST 和 CSRF 保护（#40145） — 所有 FAB 认证视图把 /logout 从 GET 改为 POST。请更新自定义模板、自动化、书签和代理规则，改为提交带有效 CSRF 保护的 POST。
  • 可为每个 DAG 或任务分配多个 executor（#40701、#38474） — 单个 DAG 可通过新的 executor 字段和 operator 参数混合 executor 类型。该能力仍是实验性的，生产采用前请验证 executor/任务的兼容性。
  • OpenTelemetry 追踪加入指标支持（#37948） — Airflow 会向兼容 OTLP 的端点发出 scheduler、triggerer、executor、processor 和 DAG-run 的 trace。在广泛启用前请规划 exporter 配置、采样和基数控制。
  • 默认收集用量遥测（#39510） — Scarf 会收集基本运维使用数据。合规敏感的部署应显式设置 [usage_data_collection]enabled = False 或 SCARF_ANALYTICS=false，并在所有环境中核验该设置。

重大变化

数据集不再触发不活动的 DAG (#38891)

以前，当 DAG 暂停或删除时，传入的数据集事件仍会 触发它，当 DAG 取消暂停或添加回 DAG 时，DAG 就会运行 文件。这已被更改；现在只能满足 DAG 的数据集时间表 通过 DAG 处于活动状态时发生的事件。虽然这是一个重大改变， 之前的行为被认为是一个错误。 基于时间的调度的行为不变，包括时间表部分 “DatasetOrTimeSchedule”。

try_number 在任务执行期间不再递增 (#39336)

以前，尝试编号 (try_number) 在工作线程上开始执行任务时递增。由于多种原因，这是有问题的。 其一，这意味着尝试次数在不应该增加的情况下增加，即从重新安排或推迟恢复时。而这也导致了 当任务尚未开始时，尝试编号“错误”。这两个问题的解决方法引起了很多混乱。 现在，任务运行的尝试次数是在计划任务时确定的，并且不会在运行中更改，也不会递减。 因此任务运行后，观察到的尝试次数与任务运行时的尝试次数保持不变；只有当有“新的尝试”时，尝试次数才会再次递增。 这一变化的一个后果是，如果用户“手动”运行任务（例如通过调用“ti.run()`` directly, or command line ``airflow tasks run”）， 尝试次数将不再增加。 Airflow 假设任务始终在调度程序调度后运行，因此我们不认为这是一个重大更改。

FAB Auth Manager 中的“/logout”端点现在受 CSRF 保护 (#40145)

所有现有的“/logout`` endpoint's method in FAB Auth Manager has been changed from ``GET`` to ``POST” AuthViews（AuthDBView, AuthLDAPView, AuthOAuthView, AuthOIDView, AuthRemoteUserView），和 现在包括 CSRF 保护，以增强安全性并防止未经授权的注销。

OpenTelemetry Apache Airflow 跟踪 (#37948)。

这项新功能增加了 Apache Airflow 发出 1) 调度程序的气流系统跟踪的功能， 触发器、执行器、处理器 2) 以 OpenTelemetry 格式部署的 DAG 运行的 DAG 运行跟踪。以前，仅支持在 OpenTelemetry 中发出指标的指标。 此新功能将为用户添加更丰富的数据，以便使用 OpenTelemetry 标准发出跟踪数据并将其发送到 OTLP 兼容端点。

任务流“(@skip_if, @run_if)”的装饰器，使应用是否跳过任务变得简单。 (#41116)

此功能添加了一个装饰器，可以轻松跳过任务。

同时使用多个执行器 (#40701)

这项新功能以前称为混合执行器，允许 Airflow 同时使用多个执行器。可以配置 DAG，甚至单个任务 使用最适合其需求的特定执行器。单个 DAG 可以包含全部使用不同执行器的任务。请参阅气流文档 更多细节。注意：此功能仍处于实验阶段。更详细的说明请参见 documentation on Executor <https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/executor/index.html#using-multiple-executors-concurrently>_。

基于围巾的遥测：Airflow 是否收集任何遥测数据？ (#39510)

Airflow 集成了 Scarf 以收集运行期间的基本使用数据。部署可以通过将“[usage_data_collection]enabled”选项设置为 False 或 SCARF_ANALYTICS=false 环境变量来选择退出数据收集。 请参阅 FAQ on this <https://airflow.apache.org/docs/apache-airflow/stable/faq.html#does-airflow-collect-any-telemetry-data>_ 了解更多信息。
