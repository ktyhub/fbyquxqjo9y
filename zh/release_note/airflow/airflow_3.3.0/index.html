airflow 3.3.0

小版本 发布时间2026年7月6日 来源apache/airflow 英文原文

airflow 3.3.0

变更流程图

亮点

  • 资产分区新增汇总、扇出与部分窗口等待 — RollupMapper、FanOutMapper 以及配合 SegmentWindow 的 FixedKeyMapper，让单个上游事件可以聚合进或展开为多个分区化的下游运行。时间窗口可与 WaitForAll 或 MinimumCount(n) 组合，而 PartitionedAtRuntime 支持直到运行启动时才确定键。可用 [scheduler] partition_mapper_max_downstream_keys 或每个 mapper 的 max_fan_out 限制调度器展开规模（#64571、#66030、#66848、#67184、#67475）。
  • 任务运行时获得持久状态与可编程重试 — task_state_store 和 asset_state_store 提供能在重试与多次运行间存活的 Task SDK 键值状态，支持元数据数据库或自定义 worker 侧存储、保留策略、垃圾回收以及可选的 clear_on_success。另有一套可插拔重试策略，让任务根据异常或自定义退避逻辑决定是否以及何时重试，而不再只依赖固定重试次数（#65759、#66463、#66586、#65474）。
  • Python DAG 可实验性把执行委派给 Java 和 Go — 用 @task.stub(queue=...) 声明工作，再通过 JavaCoordinator 或 ExecutableCoordinator 路由；Variable、Connection 和 XCom 均通过 Execution API 代理。这让编排留在 Python，同时拓宽了任务实现的语言选择，但 Coordinator 与 SDK API 未来可能变化（#65958、#67161）。
  • 重跑时的 bundle 选择变为显式可控 — rerun_with_latest_version 的解析顺序为：请求或 CLI flag → DAG 设置 → [core]，clear/rerun 默认 False，回填默认 True。在需要可复现性的地方请显式设置，尤其 TriggerDagRunOperator 的重跑也遵循此设置（#63884、#67273）。
  • 指标消费方需要更新查询与仪表盘 — OpenTelemetry 计时器现在发出 Histogram 而非 Gauge，改变了速率、平均值和告警的计算方式（#64207）。按 DAG 细分的 dag_processing.last_run.seconds_ago.{dag_file} 指标改为遗留指标；请迁移到带 file_path、bundle_name、file_name 标签的 dag_processing.last_run.seconds_ago。旧名称默认仍启用，可用 [metrics] legacy_names_on 关闭（#62487）。
  • 需升级适配的集成：bundle 重命名、资产 ACL 与日志钩子 — provider 示例 DAG 从 dags-folder bundle 迁到按 provider 划分的 bundle（如 apache-airflow-providers-<distribution>-example-dags），因此按 bundle_name 过滤的 REST 客户端需要修改，而 DAG ID 保持稳定（#66161）。Asset.allow_producer_teams 被 access_control 取代（#66954），远程日志 provider 应实现无参数的 from_config()；直接调用 airflow.logging_config.load_logging_config() 的代码必须迁移，而旧的 airflow_local_settings.py 回退机制计划于 Airflow 4.0 移除（#67056）。

重大变化

资产分区（#64571、#65447、#66030、#66848、#67184、#67475、#67716、#68978）

Airflow 3.3.0 以 3.2.0 中引入的资产划分为基础，大幅扩展了资产划分的方式 单个上游资产事件扇出到分区的下游 Dag 运行。新的分区映射器 — RollupMapper (many-to-one), FanOutMapper (one-to-many), and FixedKeyMapper + SegmentWindow（分类汇总）- 由时间窗口（日/周/月/季度/年）和 wait_policy (WaitForAll or MinimumCount(n)) 来控制分区何时运行。窗户 可以及时向前或向后扇出，并且每个上游事件的总扇出受新的限制 [scheduler] partition_mapper_max_downstream_keys 配置（每个映射器可配置）。气流 3.3.0 还添加了“PartitionedAtRuntime”时间表，它让 Dag 声明其分区键 在运行开始时分配，而不是从上游事件映射。 详细使用说明请参见：doc:/authoring-and-scheduling/assets。

任务和资产状态存储（#65759、#66073、#66160、#66463、#66586、#66859、#67041、#67292、#67319）

Airflow 3.3.0 引入了一流的任务和资产状态存储 (AIP-103)。任务可以持续存在 任意键值状态在重试后仍然存在并通过新的“task_state_store”访问器运行，以及 资产可以通过“asset_state_store”携带自己的状态——两者都可以从任务 SDK 获得。状态被保留 默认情况下在元数据数据库中，或在自定义工作端后端中（[workers] state_store_backend），通过定期垃圾收集和可选的支持每个键保留 clear_on_success，可通过核心 API 和执行 API 完全管理。 详细使用说明请参见：doc:/core-concepts/task-and-asset-state-store。

可插入重试策略 (#65474)

任务重试行为现在是可插入的 (AIP-105)。除了固定的“retries”计数之外，您还可以 附加自定义重试策略来决定是否以及何时重试任务，从而启用诸如 仅在特定异常时重试或根据自定义逻辑进行后退。 详细使用说明请参见：ref:concepts:retry-policies。

语言任务 SDK（Java 和 Go）（#65958、#67161、#67635、#67699）

Airflow 3.3.0 添加了一个协调器层 (AIP-108)，可以编写单独的任务实现 使用非 Python 语言，而 Dag 及其调度保留在 Python 中。在 Dag 中声明了一个任务 与“@task.stub(queue=...)”；工作人员将其路由到配置的协调员 （JavaCoordinator for JVM languages, ExecutableCoordinator 用于独立的本机二进制文件 例如 Go），在语言运行时运行任务并代理变量、连接和 XCom 通过执行 API。 ..警告:: 协调器层和 Java/Go SDK 在 3.3.0 中处于实验阶段，将来可能会发生变化 基于用户反馈的版本。 详细使用说明请参见：doc:/authoring-and-scheduling/language-sdks/index。

清除、重新运行和回填的 Dag 捆绑版本 (#63884)

新的“rerun_with_latest_version”设置控制是否清除、重新运行或回填 Dag 运行 使用最新的捆绑版本或初始运行的原始版本。默认已解决 按优先级：显式请求参数/CLI 标志，然后是 Dag 级别 rerun_with_latest_version， 然后[core] rerun_with_latest_version, and finally False for clear/rerun and True 回填（保留历史行为）。 Airflow 2.x 始终使用最新代码重新运行； 3.x 引入了默认为原始版本的捆绑版本控制，此设置为用户提供了控制权。 有关完整详细信息，请参阅：doc:/administration-and-deployment/dag-bundles。

提供程序示例 Dags 作为专用捆绑包 (#66161)

现在可以通过“ProvidersManager”发现提供商发行版提供的示例 Dags，并且 注册为他们自己的 Dag 捆绑包——每个提供商一个，名为 apache-airflow-providers-<distribution>-example-dags (or <distribution>-example-dags 为 第三方提供商）。 [core] load_examples 选项仍然控制它们是否注册。 REST API clients 为提供商提供的示例 Dags 过滤了“bundle_name`` by ``"dags-folder"” 必须更新为新的每个提供商捆绑包名称； Dag 标识符未更改。

远程日志记录解析与 airflow.logging_config 解耦 (#67056)

远程任务日志处理程序解析现在由共享“airflow_shared.logging.factory”拥有 模块并应用单一的、明确定义的优先级：

  1. 用户自定义 [logging] logging_config_class exporting REMOTE_TASK_LOG / DEFAULT_REMOTE_CONN_ID（现有的自定义配置继续工作）；
  2. ProvidersManager scheme dispatch — the scheme of [logging] remote_base_log_folder 选择一个 提供者RemoteLogIO class, instantiated via a no-argument from_config()类方法；
  3. 过渡遗留后备读取“airflow_local_settings.py”（将在 Airflow 4.0 中删除）。 airflow.logging_config.load_logging_config is deprecated (it now emits DeprecationWarning 和 委托给新的私人助手），并且“configure_logging”不再急切地解析远程 处理程序 - 第一次使用时解析是惰性的。注册了“remote-logging:”区块的提供商却这样做了 不实现“from_config”会跳过并出现警告并进入旧路径。 迁移：用新的替换对“airflow.logging_config.load_logging_config()”的直接调用 帮助程序，并让提供者远程日志处理程序类实现无参数“from_config” 读取“airflow.providers.common.compat.sdk.conf”的类方法。

OpenTelemetry 计时器指标现在使用直方图 (#64207)

OpenTelemetry 计时器和计时指标现在记录为直方图而不是仪表，保留 记录之间的计数、总和和存储桶分布。

Dag 处理“秒前”指标现在已标记 (#62487)

“dag_processing.last_run.seconds_ago.{dag_file}”现在是一个旧指标。新的 dag_processing.last_run.seconds_ago is emitted with file_path, bundle_name 和 file_name tags (file_path + bundle_name 唯一标识 Dag 文件）。遗留指标 默认情况下仍会发出，可以通过“[metrics] legacy_names_on”禁用。

浏览下的新截止日期页面 (#67586)

浏览菜单下提供了一个新的 截止日期 页面，任何已拥有该页面的角色都可以访问 Dag Runs 上的“can_read`` and ``menu_access”。
