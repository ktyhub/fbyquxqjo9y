airflow 3.1.3

修订 发布时间2025年11月14日 来源apache/airflow 英文原文

airflow 3.1.3

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • 上下文感知的秘密后端 — API server 和 scheduler 现在直接从 metastore 读取秘密，而 worker 使用 Execution API 或环境/外部后端，并与数据库隔离。GCSHook、S3Hook 等 hook 现在无需改代码即可在插件、中间件和日志处理器中工作（#56583）。
  • 破坏性：移除 DAG 报告 API — /api/v2/dagReports 被删除，因为它在 API server 内执行用户 DAG 代码，违反 Airflow 的安全模型。任何外部消费者必须迁移到 airflow dags report CLI 命令（#56609）。
  • 凭据安全的模板错误 — Jinja 渲染失败不再暴露秘密，减少通过错误信息和日志的凭据泄露（#57962）。HITL 任务现在也能正确校验参数，防止无效输入蒙混过关（#58144）。
  • 含 NaN XCom 值的更安全升级 — 当 XCom 含 NaN（包括以字符串值表示的 NaN）时，数据库迁移不再失败（#57893、#57614）。如果你的环境依赖自定义序列化器或较旧记录，请用有代表性的 XCom 数据测试升级。
  • 调度器与触发规则修正 — 调度器现在使用正确的缓存 max_active_runs 值，触发规则执行的任务上下文和错误处理已修复（#57959、#57892、#57786）。因此实际任务并发数可能改变以匹配你的 DAG 配置。
  • 更快的 UI 与任务实例 API — 多项修复降低了慢页面加载和任务实例列表响应时间，包括资产页面以及 DAG/任务视图（#58064、#57856、#57794）。连接测试和退出登录也已修复（#57852、#58043）。

重大变化

修复 API 服务器上下文中的连接和变量访问（插件、日志处理程序）(#56583)

以前，API 服务器上下文（插件、中间件、日志处理程序）中使用的挂钩会失败，并显示“ImportError” 对于“SUPERVISOR_COMMS``, because ``SUPERVISOR_COMMS”仅存在于任务运行程序子进程中。 通过使用三个独立的秘密后端链实现自动上下文检测来解决此问题： 上下文检测：

  1. Client 上下文（工作线程中的任务运行程序）：通过“SUPERVISOR_COMMS”存在检测到
  2. 服务器上下文（API 服务器、调度程序）：显式标记为 _AIRFLOW_PROCESS_CONTEXT=server 环境变量
  3. 后备上下文（主管，未知上下文）：都不存在标记，使用最小安全链 后端链：
  • Client：EnvironmentVariablesBackend → ExecutionAPISecretsBackend（通过 SUPERVISOR_COMMS 路由到执行 API）
  • 服务器：EnvironmentVariablesBackend → MetastoreBackend（直接数据库访问）
  • 后备：仅“EnvironmentVariablesBackend”（+来自配置的外部后端，如 AWS Secrets Manager、Vault） 后备链对于需要访问的主管进程（工作端，任务运行程序启动之前）至关重要 用于远程日志记录设置的外部机密，但不应使用“MetastoreBackend”（以保持工作人员隔离）。 架构优势：
  • Workers（主管+任务运行者）从不使用“MetastoreBackend”，保持严格隔离
  • 外部机密后端（AWS Secrets Manager、Vault 等）在所有三种环境中工作
  • 对于外部后端中未找到的连接，主管会回退到执行 API client
  • API 服务器和调度程序可以直接访问数据库以获得最佳性能 影响：
  • 像“GCSHook``, ``S3Hook”这样的挂钩现在可以在日志处理程序和插件中正常工作
  • 现有插件或挂钩无需更改代码
  • 工作人员与直接数据库访问保持隔离（完全支持网络级数据库阻塞）
  • 外部秘密无处不在（工人、主管、API 服务器）
  • 使用安全最小链稳健处理未知上下文 参见：#56120 <https://github.com/apache/airflow/issues/56120>、#56583 <https://github.com/apache/airflow/issues/56583>、#51816 <https://github.com/apache/airflow/issues/51816>__

删除在 API 服务器中执行用户代码的不安全 dag 报告 API 端点 (#56609)

/api/v2/dagReports 端点已被删除，因为它直接在 API 服务器进程中加载用户 DAG 文件， 违反 Airflow 的安全架构。该端点未在 UI 中使用，并且没有已知的消费者。 使用“airflow dags report”CLI 命令代替 DAG 加载报告。
