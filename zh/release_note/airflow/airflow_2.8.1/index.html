airflow 2.8.1

修订 发布时间2024年1月19日 来源apache/airflow 英文原文

airflow 2.8.1

重大变化

核心依赖项 pendulum 包的目标版本设置为 3 (#36281)。

对摆锤 2.1.2 的支持将保留一段时间，大概要等到 Airflow 的下一个功能版本。 建议尽快升级用户代码以使用pendulum 3。

气流包装规范遵循现代 Python 包装标准 (#36537)。

我们标准化了 Airflow 依赖配置，以遵循 Python 封装的最新发展 使用“pyproject.toml”。 Airflow 现在符合那些已接受的 PEP：

  • PEP-440 Version Identification and Dependency Specification <https://www.python.org/dev/peps/pep-0440/>__
  • PEP-517 A build-system independent format for source trees <https://www.python.org/dev/peps/pep-0517/>__
  • PEP-518 Specifying Minimum Build System Requirements for Python Projects <https://www.python.org/dev/peps/pep-0518/>__
  • PEP-561 Distributing and Packaging Type Information <https://www.python.org/dev/peps/pep-0561/>__
  • PEP-621 Storing project metadata in pyproject.toml <https://www.python.org/dev/peps/pep-0621/>__
  • PEP-660 Editable installs for pyproject.toml based builds (wheel based) <https://www.python.org/dev/peps/pep-0660/>__
  • PEP-685 Comparison of extra names for optional distribution dependencies <https://www.python.org/dev/peps/pep-0685/>__ 此外，我们还实现了来自草案的多个许可证文件支持，尚未接受（但受孵化体支持）PEP：
  • PEP 639 Improving License Clarity with Better Package Metadata <https://peps.python.org/pep-0639/>__ 如果用户使用现代 Python 封装和开发工具，这对用户几乎没有明显的影响，通常 说起来，Airflow 的行为应该像以前从 PyPI 安装它时一样，并且安装起来应该容易得多 使用“pip install -e ".[devel]"”用于开发目的。 与用户端的区别是：
  • 气流附加功能现已标准化为“-`` (following PEP-685) instead of ``_`` and ``.” （就像之前的一些额外内容一样）。当您安装带有此类附加功能的气流时（例如“dbt.core”或 all_dbs) you should use - instead of _ and .。 在大多数现代工具中，这将以向后兼容的方式工作，但在这些工具的某些旧版本中，您可能需要 替换“_`` and ``.`` with ``-”。您还可能会收到警告，提示您正在安装的额外内容不存在 - 但通常情况下 这个警告是无害的，无论如何都会安装额外的。但是，建议在您的依赖项中的 extras 中更改为使用“-” 所有 Airflow 附加设备的规格。
  • 发布的气流套件不包含“devel``, ``devel-*``, ``doc`` and ``doc-gen”附加组件。 仅当您在“--editable”模式下从源安装 Airflow 时，这些附加功能才可用。这是 因为这些额外内容仅用于开发和文档构建目的，并且不需要 当您安装 Airflow 用于生产用途时。这些依赖项具有未指定且不同的行为 无论如何，已发布的软件包并且您不应该在已发布的软件包中使用它们。
  • 使用约束安装 Airflow 时，“all`` and ``all-*”附加功能并不总是正常工作 因为它们也被视为仅开发依赖项。通过此更改，这些依赖项是 现在正确处理约束，它们将在约束下正确安装，拉动正确的集合 使用约束时的提供者和依赖项。

Graphviz 依赖项现在是可选依赖项，而不是必需依赖项 (#36647)。

“graphviz”依赖性一直存在问题，因为 Airflow 需要依赖性 - 特别是对于 基于 ARM 的安装。 Graphviz 包需要二进制 graphviz 库 - 这已经是 限制，但它们还需要安装 graphviz Python 绑定才能构建和安装。 这不适用于较旧的 Linux 安装，但更重要的是，当您尝试安装时 适用于 ARM M1 MacBook 的 Python 3.8、3.9 的 Graphviz 库，软件包无法安装，因为 M1 的 Python 绑定编译仅适用于 Python 3.10+。 这在技术上并不是一个重大变化 - 用于渲染 DAG 的 CLI 仍然存在，如果您 已经安装了 graphviz，它将像以前一样继续工作。唯一的问题是当它 不起作用是指您没有安装 graphviz，它将引发错误并通知您需要它。 大多数用户仍需安装 Graphviz：

  • Airflow Image 仍将包含 graphviz 库，因为 它作为额外添加在那里
  • 如果已经安装了旧版本的 Airflow，那么 graphviz 库已经安装在那里，Airflow 将 像以前一样继续工作 唯一的变化是从头开始安装新版本的 Airflow，其中 graphviz 将 需要指定为额外的或单独安装才能启用 DAG 渲染选项。
