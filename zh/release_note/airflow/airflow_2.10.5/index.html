修订 发布时间2025年2月10日 来源apache/airflow 英文原文

airflow 2.10.5

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • 手动修改 DAG 状态时执行 teardown 任务（#45530、#45581） — 过去把 DAG run 手动标记为”失败”/“成功”会给每个任务设上终态，跳过 teardown，导致已清理的基础设施仍处于分配状态。现在只要 setup 之前执行过，teardown 就会运行（只有 setup 被跳过时才跳过）。迁移注意：对带 teardown 的 DAG，手动标记失败/成功时必须让 DAG 停留在 running 状态，teardown 才会被调度；直接设为失败/成功则不会调度 teardown。用 teardown 做清理的团队需要调整人工干预的流程。
  • 自定义算子受影响：移除调度依赖、conf 弃用（破坏性/弃用） — 算子不再能自定义”调度依赖”（#45713、#45742）——这项移除会破坏任何依赖该钩子的自定义算子；同时 conf 从 Task Context 中弃用（#44993）。自定义算子作者升级前应审计并测试；内置 DAG 不受影响。
  • 动态任务映射与触发规则的正确性 — 多项实打实的调度修复：在裸任务的任务生成映射中禁用 trigger_rule=TriggerRule.ALWAYS（#44751）；修复映射后的 ShortCircuitOperator 任务（#44912）；修复映射任务组中 ONE_DONE 等规则的过早求值（#44937）；BaseOperator 中增加 task_id 校验（#44938）；动态任务可按 rendered_map_index 过滤（#45109、#45122）。如果你用映射任务搭配非默认触发规则，这些值得升级。
  • Webserver、API 与 XCom 修复 — 新增 webserver 参数 max_form_parts 和 max_form_memory_size（#46243、#45749）；带正斜杠的 XCom 键现在可通过 API 获取并在 UI 中转义（#45134）；extra-links API 增加 map_index（#46337）；登录表单关闭自动补全（#44929、#44940）。此外还有可靠性修复：空任务实例日志（#45702、#45703）、传感器无休止重调度（#45224、#45250）、事件日志 JSON 请求体（#45546、#45560），以及 BaseOperator.execute 保护中的线程局部访问（#44646、#46280）。
  • 升级结论 — 这是一个实打实的错误修复/补丁版本，不是空操作或仅改元数据的重新打标：一处有意义的行为变更（teardown）、一处破坏性移除（算子调度依赖），其余都是正确性修复。大多数 2.10.x 用户——尤其是使用映射任务或基于 teardown 清理的用户——都应升级；不涉及大版本迁移。如果你维护使用调度依赖的自定义算子，先测试再升级；既没有映射任务、也没有 teardown、更没有自定义调度依赖的用户可以放心跳过。

重大变化

重大变化

确保当 DAG 运行设置为失败时执行拆卸任务 (#45530)

以前，当 DAG 运行手动设置为“失败”或“成功”状态时，最终状态会设置为所有任务。 但这对于定义设置和拆卸任务的情况来说是一个差距：如果使用拆卸来清理基础设施 或其他资源，它们也被跳过，因此资源可以保持分配。 截至目前，当之前执行过设置任务并且将 DAG 手动设置为“失败”或“成功”然后拆卸时 任务被执行。如果还跳过了安装，则将跳过拆卸任务。 作为副作用，这意味着如果 DAG 包含拆卸任务，则将 DAG 手动标记为“失败”或“成功” 需要保持 DAG 处于运行状态，以确保安排拆卸任务。他们不会被安排 如果DAG直接设置为“失败”或“成功”。
