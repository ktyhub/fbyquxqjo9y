airflow 1.19.0

小版本 发布时间2026年2月17日 来源apache/airflow 英文原文

airflow helm-chart/1.19.0

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • 基础镜像跳到 Airflow 3.1.7 和 git-sync 4.4.2 — chart 默认值从 Airflow 3.0.2 升到 3.1.7（#61447），git-sync 从 4.3.0 升到 4.4.2（#54085），因此一次普通的 helm upgrade 就会在无需显式选择的情况下采用 3.1.x 行为。再加上 Airflow 3.x 探针路径修复（#58734）和切换到 bitnamilegacy/postgresql（#61156）：如果你固定或镜像化镜像，或依赖 2.x 的 liveness/readiness 路径，升级前请审计你的覆盖配置。
  • 多组 Celery worker 解锁按组自动扩缩 — workers.celery.sets 加 workers.celery.enableDefault（#58547）让你可完全弃用通用 worker 池，只运行专用组。KEDA ScaledObject 生成现在通过 SQL IN (...) 接受逗号分隔的队列列表（#58547），任何 worker 键都可按组覆盖（例如全局启用 KEDA、对静态组禁用）。请留意 worker 分离的交互修复（#60420），以及多 executor 场景下 KEDA 查询从 queue 字段切换到 executor 字段（#52840、#55559、#55560）——这些改变的是 KEDA 实际按哪个 lag 来扩缩。
  • 两处配置键迁移：createUserJob 与 workers.celery — 默认用户设置从 webserver.defaultUser 移到 createUserJob（#59767），整个 Celery worker 键家族新增 workers.celery.* 对应项：replicas（#59730）、revisionHistoryLimit（#60056）、args（#60163）、livenessProbe（#60186）、updateStrategy/strategy/podManagementPolicy（#60351/#60354/#60359）以及 persistence（#60238）。旧键仍可用但已弃用，所以这是「按自己节奏迁移」项，不是硬破坏。两个坑：apiServer.defaultUser 从未实现，现在设置它会报错（#59767、#59762）；一项针对 workers.celery 的计划中破坏性变更被明确撤回（#61049）。
  • 仓库凭据迁移到 imagePullSecrets — .Values.imagePullSecrets 成为受支持的机制，弃用 .Values.registry.secretName 和由 registry.connection 自动生成的 <RELEASE_NAME>-registry secret（#58094）。如果你使用私有仓库，请把 secret 加入 values 并移除对 chart 托管创建的依赖；注意 DB-cleanup CronJob 有一处独立的 ImagePullSecrets 缺口在此修复（#58626）。
  • StatsD 现在可用 TTL/LRU 缓存限制内存 — 新增 statsd.cache.type（默认 lru，或 random）、statsd.cache.size（1000）和 statsd.cache.ttl（#60933），为聚合加入 LRU 淘汰和 TTL 过期。默认 ttl: 0s 保持现有行为，因此是可选启用：如果你的长期 StatsD 守护进程指标基数无界，请设置 statsd.cache.ttl > 0 并按标签量调整 size。
  • 任务 pod 的安全与韧性加固 — 为可启动 pod 的 executor（Celery、CeleryKubernetes、Kubernetes、LocalKubernetes）新增手动配置 Service Account token 卷（#59156），支持兼容 Kyverno 的最小权限令牌挂载。triggerer 从 pod-log-reader-role 移到 pod-launcher-role（#56872），可能影响 RBAC 策略。新的中断/自动扩缩原语——dag processor 的 PDB（#60294）、triggerer/worker 的 PDB（#59068）、API server 的 HPA（#52392）、KubernetesJobOperator 作业启动（#52024）以及 DB-cleanup CronJob（#58155）——为生产集群提供更多旋钮，但也带来 GitOps diff 中需要协调的新对象。

无破坏性变更：弃用键仍可用，且计划中的那项破坏已撤回（#61049）。

重大变化

StatsD 指标聚合现在支持可配置的启用 TTL 的 LRU 缓存，以防止长时间运行的守护进程中的内存增长 (#60933)

Helm Chart 现在包含 StatsD 聚合管理的新配置选项：

  • statsd.cache.type - Enable TTL-enabled lru cache or random cache for metrics aggregation (default: lru)
  • statsd.cache.size - 缓存的最大指标数（默认值：1000）
  • statsd.cache.ttl - Time-to-live for cached metrics in seconds (0s is TTL disabled) (default: 0s) 此功能通过自动清理陈旧或未使用的指标条目来解决 StatsD 守护程序中不受控制的内存增长问题。启用后，缓存将使用 LRU（最近最少使用）逐出和 TTL（生存时间）过期来有效管理内存使用情况。 为了保持向后兼容性，默认行为保持不变。遇到 StatsD 内存增长问题的用户可以通过在 Helm 值中设置“statsd.cache.ttl`` to value higher than ``0”来启用此功能。

支持 Helm Chart 中的多个 Celery Worker 集 (#58547)

此更改为 Apache Airflow Helm Chart 引入了对高级 Celery Workers 拓扑的支持，从而实现更灵活的资源分配和精确的自动缩放配置。 灵活的工作线程拓扑：新的“workers.celery.enableDefault`` flag allows users to configure a deployment consisting only of specialized worker sets defined in ``workers.celery.sets”部分。 多队列自动缩放支持：更新 KEDA ScaledObject 生成以支持逗号分隔的队列列表。通过使用“SQL IN (...)”子句，我们确保 KEDA 根据所有分配的队列的精确聚合工作负载来扩展工作集。 精细配置覆盖：此更改允许覆盖每个工作集的任何当前可用的工作配置。例如，用户可以全局启用 KEDA，但对于需要静态副本数的特定工作集显式禁用它。

创建默认用户的选项已移至“createUserJob”部分下

请相应地更新您的配置：

  • webserver.defaultUser section is now deprecated in favor of createUserJob (#59767) 以前的配置选项仍然有效，但已弃用，并将在未来版本中删除。 请注意，前面的文档还描述了选项“apiServer.defaultUser``, which was never implemented in the chart. The only supported option is now ``createUserJob``. Using ``apiServer.defaultUser”将引发错误。

Celery 特定配置选项已移至“celery`` section in ``workers”下

请相应地更新您的配置：

  • workers.replicas command is now deprecated in favor of workers.celery.replicas (#59730)
  • workers.revisionHistoryLimit command is now deprecated in favor of workers.celery.revisionHistoryLimit (#60056)
  • workers.args command is now deprecated in favor of workers.celery.args (#60163)
  • workers.livenessProbe section is now deprecated in favor of workers.celery.livenessProbe (#60186)
  • workers.updateStrategy section is now deprecated in favor of workers.celery.updateStrategy (#60351)
  • workers.strategy section is now deprecated in favor of workers.celery.strategy (#60354)
  • workers.podManagementPolicy section is now deprecated in favor of workers.celery.podManagementPolicy (#60359)
  • workers.persistence section is now deprecated in favor of workers.celery.persistence (#60238) 以前的配置选项仍然有效，但已弃用，并将在未来版本中删除。

pod 启动执行器的手动服务帐户令牌卷配置 (#59156)

添加了使用 pod 启动执行器时手动配置服务帐户令牌卷的支持 （CeleryExecutor, CeleryKubernetesExecutor, KubernetesExecutor, LocalKubernetesExecutor）。 这通过 ServiceAccount 和 Pod 级别的控制实现了深度防御安全，提供 与 Kyverno 等安全策略兼容并启用容器特定的权限分配 遵循最小特权原则。

添加 imagePullSecrets 选项 (#58094)

添加“.Values.imagePullSecrets”作为配置注册表凭据的新机制， 弃用“.Values.registry.secretName`` and the automatic creation of the ``<RELEASE_NAME>-registry`` secret from ``.Values.registry.connection”。

默认 Airflow 图像更新为 3.1.7 (#61447)

与图表一起使用的默认气流图像现在是“3.1.7``, previously it was ``3.0.2”。

默认 git-sync 镜像更新为 4.4.2 (#54085)

与图表一起使用的默认 git-sync 图像现在是“4.4.2``, previously it was ``4.3.0”。
