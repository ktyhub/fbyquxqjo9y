airflow 3.0.5

修订 发布时间2025年8月20日 来源apache/airflow 英文原文

airflow 3.0.5

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • 回调与任务上下文恢复 3.0 前应有一致性 — Task SDK 迁移悄悄丢掉了回调和 operator 依赖的数据；此补丁恢复了 DAG 回调执行上下文（#53684）、任务上下文中的 get_previous_dagrun（#53655），以及任务失败回调中的 end_date/duration（通过在调用前填充 TaskInstance，#54458）。它还对卡在 queued 状态、重新排队后失败的实例触发失败回调（#54401）。如果你在迁移到 3.0 后为缺失字段加过 workaround，请移除它们——但要重新检查那些已经开始基于字段缺失做分支的回调。
  • executor 事件导致的调度器崩溃循环被修复 — 两处 DetachedInstanceError 修复（#54334 针对 executor 事件处理，#54362 针对 DagRun.created_dag_version）消除了一类真实的停摆：调度器在循环中崩溃会导致其后所有任务停止调度。仅从严重程度看，这就是从 3.0.4 升级的最强理由。
  • XCom 与映射组语义获得全面正确性梳理 — 自定义 XCom 后端现在会被 BaseXCom.get_all() 尊重（#53814），省略 map_indexes 时 xcom_pull 会遵循 include_prior_dates（#53809），嵌套映射组中上游任务的 map_index 也能正确解析（#54249）。两处改动有结构性意义：TaskGroup 内 MappedOperator 的 unmap 不再在任务 ID 中重复组前缀（#53532），且 trigger 现在可以设置/删除 Variable 和 XCom（#53514）。尤其关注 unmap 修复——任务 ID 会变，因此基于旧 ID 的 sensor、外部触发器和仪表盘需要重新校验。
  • 官方支持回滚到 2.11 — Airflow 现在正式允许数据库从 3.x 降级到 2.11（#54399、#54508）。这是一项降低采用风险的举措而非功能：早期 3.0 采用者面对的是单向迁移，而一等逃生舱改变了仍在评估的团队的考量。请把它当作真实流程——在预发环境演练降级，因为 schema 回滚在实践中很少完美可逆。
  • 来自 secrets 后端的密钥终于被遮蔽 — 从 secrets 后端加载的连接会泄漏进日志；现在遮蔽覆盖了它们（#54574、#54612）。如果你曾压制日志输出或围绕该暴露打补丁，可以开始放宽这些控制——但在假定全面覆盖前，请确认你特定后端的连接 URI 已被覆盖。
  • 配置驱动的任务默认值现在真正生效 — Task SDK 会遵循设置中的自定义默认队列（#52786），任务配置默认值现在从配置读取而非被忽略（#52871）。这是行为变化而非表面改动：设置了这些值却此前发现被丢弃的部署，现在会看到它们被应用，因此上线前请验证队列路由和默认任务参数，避免任务落到意外的地方。

无破坏性变更。
