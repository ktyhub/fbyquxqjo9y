airflow 2.8.2

修订 发布时间2024年2月26日 来源apache/airflow 英文原文

airflow 2.8.2

重大变化

allowed_deserialization_classes 标志现在遵循 glob 模式 (#36147)。

例如，如果想将类“airflow.tests.custom_class”添加到 allowed_deserialization_classes列表，可以通过编写完整的类来完成 名称 (airflow.tests.custom_class) 或模式，例如 glob 中使用的模式 搜索（例如“airflow.*``, ``airflow.tests.*”）。 如果您当前使用自定义正则表达式路径，请确保将其重写为全局模式。 或者，如果您仍然希望将其作为正则表达式模式进行匹配，请将其添加到新的 改为列出“allowed_deserialization_classes_regexp”。 ##audit_logs 权限已更新以提高安全性 (#37501)。 这是在我们不希望像 Viewer、Ops、 以及除管理员之外的其他用户有权访问audit_logs。背后的意图 此更改是为了限制权限较低的用户查看用户详细信息 例如，在不允许的情况下，审计日志中的名字、电子邮件等。 此更改的影响是具有非管理员权限的现有用户将无法 从“浏览”选项卡或从 DAG 运行查看或访问audit_logs。

AirflowTimeoutError is no longer except by default through Exception (#35653)。

AirflowTimeoutError is now inheriting BaseException 而不是 AirflowException->Exception。 参见https://docs.python.org/3/library/exceptions.html#exception-hierarchy 这可以防止代码意外捕获“Exception” 抓住“AirflowTimeoutError”并继续运行。 AirflowTimeoutError 是取消任务的明确意图，不应该 试图处理错误并返回一些默认值时被捕获。 捕捉“AirflowTimeoutError`` is still possible by explicitly ``except” AirflowTimeoutError or BaseException。 不鼓励这样做，因为它可能允许代码在之后继续运行 此类取消请求。 以前依赖于在每种情况下执行严格清理的代码 捕获“Exception`` is advised to use ``finally”块后或 上下文管理器。仅执行清理，然后自动执行 重新引发异常。 请参阅有关捕获“KeyboardInterrupt”的类似注意事项 https://docs.python.org/3/library/exceptions.html#KeyboardInterrupt
