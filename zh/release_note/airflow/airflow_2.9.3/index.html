airflow 2.9.3

修订 发布时间2024年7月16日 来源apache/airflow 英文原文

airflow 2.9.3

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • 时长指标改用毫秒 — scheduled_duration 和 queued_duration 现在以毫秒而非秒上报（#37936）。这与 Prometheus statsd-exporter 期望的 statsd 惯例一致，但属于静默放大 1000 倍的变化：升级前请重新调整基于这些指标的仪表盘、告警或 PromQL 查询，否则会误判调度延迟。
  • OpenTelemetry 指标转为稳定 — OTel 指标支持在 2.7.0 以实验特性落地并累积修复后，现正式宣布生产可用（#40286）。此前因「实验」标签而观望的团队现在可以无保留地采用；已有用户除了去掉实验性开关的假设外，无需迁移步骤。
  • doc_md 禁用 Jinja 渲染 — DAG 文档字符串不再经过 Jinja 模板引擎处理（#40522）。这封堵了一个模板注入面，但属于可见的行为变化：doc_md 依赖模板化值的 DAG 现在会原样渲染这些表达式，因此请审查所有生成的文档。
  • 调度器与 ORM 可靠性修复 — #40563 修正了 SchedulerJobRunner._process_executor_events 中的缺陷，#40345 在 DAG 文件缺失的部署上恢复了 DAG 的暂停/取消暂停，#40314 修复了与旧版 MySQL 8.0 的兼容性，#40391 则阻止 Extra 值泄漏进 SQLAlchemy。整体而言，这些修复减少了调度器异常并避免边缘后端上的状态损坏——如果你运行混合或遗留 MySQL 环境，尤其值得关注。
  • 需要提前规划的弃用信号 — 文档现在警告 PostgresOperator 已弃用（#40662），[webserver]update_fab_perms 加入弃用配置列表（#40317），弃用 API 文档明确指出不应用访问控制（#40129）。不要基于这些 API/operator 构建新集成；对仍在调用旧 API 的场景，应把访问控制说明当作安全警示。
  • 值得阅读的运维指引 — 新文档介绍了通过环境变量传递密钥（#40519），并澄清序列化器不支持 bytes（#40597）。如果你序列化 DAG 状态或在运行时注入凭据，这两条说明能节省调试时间——尤其是 bytes 限制，在自定义序列化器中很容易踩坑。

重大变化

scheduled_duration and queued_duration 的时间单位已更改 (#37936)

“scheduled_duration`` and ``queued_duration”指标现在以毫秒而不是秒为单位发出。 按照惯例，所有 statsd 指标都应以毫秒为单位发出，这在稍后的示例中是预期的。 prometheus 统计导出器。

对 OpenTelemetry 指标的支持不再是“实验性的”(#40286)

2.7.0 中添加了对 OpenTelemetry 的实验性支持，此后添加了修复和改进，现在我们宣布该功能稳定。
