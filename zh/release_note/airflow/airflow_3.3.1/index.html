airflow 3.3.1

修订 发布时间2026年8月12日 来源apache/airflow 英文原文

airflow 3.3.1

变更流程图

亮点

  • Pandas 3 的 XCom 兼容性与升级顺序（#71169） — pandas 3 把 DataFrame 的限定名从 pandas.core.frame.DataFrame 改为 pandas.DataFrame；Airflow 现在同时注册这两个名称，因此无论用哪个版本写入的 XCom，任一版本都能读取，无需改配置，已有数据也保持可读。但升级顺序是个坑：务必在 pandas 3 触及任何组件（尤其是 worker）之前，把所有组件升级到 3.3.1——旧版读取方会抛出一个误导性的 ImportError，让你以为是 allowed_deserialization_classes 的问题，而其实与白名单无关，改它毫无作用；读取方升级后，这些数据自然恢复可读。一旦 XCom 是在 pandas 3 下写入的，回滚就是单向门——在重新升级前它们始终不可读。请审查那些按 dtype == "object" 分支、用 is None 检查单元格或调用 DataFrame.equals() 的 DAG：现在拉取到的 DataFrame 形态由读取方的 pandas 版本决定（字符串列返回为 str，缺失值为 nan 而非 None），下游逻辑可能因此悄然改变行为。
  • 自定义 DAG bundle 的 2.x→3.x 升级障碍被清除（#70994） — 迁移脚本 0082 曾把所有旧数据行的 bundle_name 硬编码为 'dags-folder'，导致使用非默认 bundle 的部署在触发 DAG 运行时报 Requested bundle 'dags-folder' is not configured。DagFileProcessorManager 现在会在启动时执行一次尽力而为的回填，按文件路径把每个受影响的 DAG 路由到正确的 bundle；未匹配的 DAG 会在下一次成功解析时自愈，也可用 airflow dags reserialize 立即强制修复。如果自定义 bundle 正是你卡在 3.0 的原因，3.3.1 就是目标版本。
  • 团队作用域的敏感配置值现已被遮蔽（#71099） — 敏感性判定会在把 [<team>=<section>] 覆盖项（或 AIRFLOW__<TEAM>___<SECTION>__<KEY> 环境变量）映射回基础选项之后进行，因此 AirflowConfigParser.as_dict(display_sensitive=False)、GET /config、单选项配置端点和 airflow config list 现在都会对团队作用域的密钥返回 < hidden >，此前这些值会明文泄露。任何通过这些路径读取团队真实值的调用方都将拿到掩码——确实需要真实值的地方请改用 display_sensitive=True。团队作用域的 _cmd/_secret 条目会就地遮蔽，而不像基础段那样解析后移除。非团队配置保持不变。
  • 插件作者需注意的破坏性变更：ResumableJobMixin 现为抽象类（#70810） — 子类必须实现此前可选的方法，因此升级前请审查所有继承它的自定义 job，否则实例化会失败。请同时参考关于该 mixin 中状态存储清理的新文档（#70792）。
  • 密钥与重定向方面的安全加固 — 多条泄露路径被封堵：构造特定 key 可使团队作用域的密钥查询返回另一个团队的密钥（#71041）；批量更新 Variable/Connection 时密钥在审计日志中未遮蔽（#71043）；JSON 列表形式的 Variable 值以及嵌套在列表/元组/集合中的值绕过了遮蔽（#71069、#70189）；Rendered Templates 视图在 KubernetesPodOperator 下暴露了密钥（#70756）。此外，畸形 URL 导致的开放重定向也被拒绝（#70515）。如果 UI/API 是跨团队共享的，请优先升级。
  • 需测试的行为变化：可延迟重试、邮件后端与可观测性 — 通过触发器发出的 TaskFailedEvent 而失败的可延迟任务现在会遵循重试策略，而非直接终态失败（#71163）；email_on_failure/email_on_retry 终于尊重自定义的 [email] email_backend，而不再一律走 SmtpNotifier；后端无法导入时会明确报错，而不是静默回退到 SMTP（#70129）。新增遥测包括 task.execute OpenTelemetry span（#69359）和 dagrun.duration.failed 上的 run_type 标签（#70731）。依赖下限也提高到 structlog>=26.1.0 和 croniter>=6.2.2 以修复内存泄漏（#70749）——请检查固定的约束文件。

重大变化

Pandas 3 改变了 DataFrame XCom 的存储和读回方式 (#71169)

pandas 3 从“pandas”命名空间公开其公共类，因此 DataFrame 被限定为 pandas.DataFrame instead of pandas.core.frame.DataFrame。 XComs 将该名称与 序列化值，因此写入元数据数据库的名称取决于 pandas 的版本 推动价值的组件。 Airflow 注册两个名称以及由其中之一写入的 DataFrame pandas 版本可以由任何一个读取 - 无需更改配置，现有的 XCom 保留 可读。 你应该做什么：

  • 在 pandas 3 到达任何组件之前将此 Airflow 版本推广到每个组件 — 工作人员 特别是。在此更改之前的组件无法读取写入的 DataFrame XCom pandas 3，拉动失败： .. 代码块:: 文本 ImportError：在反序列化导入的允许列表中找不到 pandas.DataFrame。 要允许它，请将其添加到配置中的 allowed_deserialization_classes 中 该消息指向配置，但允许列表不是原因，更改它也不会 帮助。这些行没有损坏：一旦阅读器升级，它们就会再次可读。
  • 将降级视为那些 XCom 的单向门。 回滚到 Airflow 版本，无需 此更改会搁置在 pandas 3 上编写的任何 DataFrame XCom，并出现相同的错误，直到您 再次向前滚动。
  • 查看检查拉取的 DataFrame 的“dtypes”的 Dags。 reader 的 pandas 版本 确定拉取的 DataFrame 的外观，而不是编写它的版本。在 pandas 3 下， 字符串列返回为“str`` rather than ``object”及其缺失值 返回为“nan`` rather than ``None”。值未更改，但下游代码发生分支 在“dtype == "object"``, checks cells with ``is None”上，或与参考系进行比较 升级后，“DataFrame.equals()”的行为可能会有所不同。

修复配置自定义 Dag 捆绑包时 2.x 到 3.0+ 升级失败的问题 (#70994)

“0082_3_1_0_make_bundle_name_not_nullable”迁移分配了每个旧行 bundle_name='dags-folder', so triggering a DagRun raised 请求的捆绑包“dags-folder”是 未配置。 on any deployment that uses a bundle other than the default dags-folder。 “DagFileProcessorManager”现在在启动时运行一次性的尽力回填，路由每个 根据其文件路径将 Dag 影响到正确的包；无与伦比的 Dags 在接下来的自我修复 成功解析（或运行“airflow dags reserialize”立即强制解析）。

注册为敏感的选项的团队范围值现在被隐藏 (#71099)

配置选项在其基本部分下注册为敏感选项，因此到目前为止只有 选项的基本拼写被屏蔽。团队范围的覆盖——在“[<team>=<section>]”中设置 配置文件部分，或通过 AIRFLOW__<TEAM>___<SECTION>__<KEY> 环境变量 — 未被识别为相同选项并被全额退回。 现在，灵敏度是在解决团队范围拼写回基本选项后决定的，因此 团队范围的价值与基本价值完全一样。 行为改变：

  • AirflowConfigParser.as_dict(display_sensitive=False), GET /config, GET /config/section/{section}/option/{option} and airflow config list 现在返回 “< hidden >”表示注册为敏感的选项的团队范围值。部署 通过其中任何一个来读取团队的真正价值现在将获得面具；使用 display_sensitive=True 需要真实值且合适。
  • 团队范围为“_cmd`` and ``_secret`` entries are replaced with ``< hidden >”，而不是 而不是像在基本部分中那样被解析为它们的值并被删除。解决它们 团队不支持，因此命令字符串或秘密路径也不再显示。
  • 非团队配置不受影响，display_sensitive=True继续返回真实 价值观。
