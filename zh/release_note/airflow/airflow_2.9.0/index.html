airflow 2.9.0

小版本 发布时间2024年4月8日 来源apache/airflow 英文原文

airflow 2.9.0

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • 破坏性：移除 Microsoft SQL Server 作为元数据数据库后端 — 经 PMC 讨论和投票，自 2.9.0 起 MsSQL 不再是受支持的 Airflow 元数据数据库（#36514）。如果你在使用它，请在升级之前通过 apache/airflow-mssql-migration 仓库中的迁移脚本完成迁移（该脚本不提供支持或担保）。这不影响 provider 的 operator/hook——DAG 仍能读写 MsSQL 数据。
  • 破坏性：Dataset URI 校验与 API 重命名 — Dataset 标识符现在必须符合 AIP-60 的 URI 规则，并在 DAG 解析时归一化；你可能需要修改那些只是「看起来像」URI 的标识符（例如依赖 URI auth 段或大小写敏感的协议名）（#37005）。另外，BaseAuthManager.get_permitted_menu_items 更名为 filter_permitted_menu_items（#37627），REST API 审计日志的 event 名现在以 api. 或 ui. 为前缀（#37734）——请更新自定义 auth manager 和所有审计日志消费方。
  • 支持 Python 3.12，但有实际前提 — 官方 3.12 支持落地（#38025），但你必须迁移到 Pendulum 3（Pendulum 2 不支持 3.12），所有 Python 版本的最低 SQLAlchemy 版本提高到 1.4.36，且 apache.beam 和 papermill provider 在首发时不支持 3.12。只有在核对过你的 provider 组合后才采用 3.12。
  • 需规划的运维限制与 MySQL XCom 迁移 — Rendered Template Fields 上限为 4096 字符，超出会截断，可通过 [core]max_template_field_length 调整（#38094）。在 MySQL 上 XCom 的 value 列从 blob 改为 longblob（#38401）：从修订版 b4078ac230a1 降级时要求没有任何超过 65,535 字节的 XCom 值，否则必须清理这些行或运行 airflow db clean xcom。
  • 结论：多数用户值得升级，但不是空版本 — 这是一个内容充实的功能版本：Dataset 驱动调度走向成熟（条件逻辑、逻辑运算符、DatasetOrTimeSchedule）、@task.bash、AIP-58 对象存储 XCom 后端、多 executor 配置，以及 Listener API 钩子（on_starting、before_stopping、on_dag_run_*、on_task_instance_*）现已生产可用（#36376）。想要这些特性或需要 Python 3.12 就升级；如果依赖 MsSQL 作为元数据数据库、旧的认证方式/审计日志事件名，或需要 apache.beam/papermill 的 3.12 支持，则暂缓。另请注意旧的 DAG 详情页已被移除，改用 grid 视图（#37988、#37232）。

重大变化

以下 Listener API 方法被认为是稳定的，可用于生产系统（旧版 Airflow 版本中的实验功能）(#36376)：

  • on_starting
  • before_stopping DagRun 状态更改事件：
  • on_dag_run_running
  • on_dag_run_success
  • on_dag_run_failed 任务实例状态更改事件：
  • on_task_instance_running

Airflow 元数据库对 Microsoft SQL-Server 的支持已被删除 (#36514)

discussion <https://lists.apache.org/thread/r06j306hldg03g2my1pd4nyjxg78b3h4>之后 和 voting process <https://lists.apache.org/thread/pgcgmhf6560k8jbsmz8nlyoxosvltph2>， Airflow 的 PMC 和提交者已达成决议，不再将 MsSQL 维持为受支持的数据库后端。 从 Airflow 2.9.0 开始，Airflow 数据库后端已删除对 MsSQL 的支持。 可以在升级到 Airflow 2.9.0 之前帮助迁移数据库的迁移脚本位于 airflow-mssql-migration repo on Github <https://github.com/apache/airflow-mssql-migration>_。 请注意，提供的迁移脚本不提供支持和保证。 这不会影响现有的提供程序包（运算符和挂钩），DAG 仍然可以访问和处理来自 MsSQL 的数据。

数据集 URI 现在根据输入进行验证 (#37005)

数据集必须使用符合 AIP-60 中规定的规则的 URI，并且值 解析 DAG 文件时将自动标准化。参见 documentation on Datasets <https://airflow.apache.org/docs/apache-airflow/stable/authoring-and-scheduling/datasets.html>_为 有关规则的更详细说明。 如果数据集标识符看起来像 URI，但实际上是，您可能需要更改它们 以不太主流的方式使用，例如依赖 URI 的 auth 部分，或者 有区分大小写的协议名称。

方法 get_permitted_menu_items in BaseAuthManager has been renamed filter_permitted_menu_items (#37627)

将 REST API 操作添加到审核日志事件 (#37734)

审核日志“event`` name for REST API events will be prepended with ``api.`` or ``ui.”，具体取决于它是来自 Airflow UI 还是外部。

官方支持 Python 3.12 (#38025)

但有一些注意事项：

  • Pendulum2 不支持 Python 3.12。对于 Python 3.12 您需要使用 Pendulum 3 <https://pendulum.eustace.io/blog/announcing-pendulum-3-0-0.html>_
  • 当为 Python 3.12 安装 Pandas 时支持的最低 SQLAlchemy 版本为“1.4.36”，发布于 2022 年 4 月。Airflow 2.9.0 将所有 SQLAlchemy 支持的最低版本增加到“1.4.36” Python 版本。 并非所有提供商都支持 Python 3.12。在 Airflow 2.9.0 的初始版本中，以下提供商 发布时不支持 Python 3.12：
    • apache.beam - pending on Apache Beam 支持 3.12 <https://github.com/apache/beam/issues/29149>_
    • papermill - 待发布 Python 3.12 兼容造纸厂 client 版本 including this merged issue <https://github.com/nteract/papermill/pull/771>_

防止大字符串对象存储在渲染模板字段中 (#38094)

现在，可存储在渲染模板字段中的数据长度存在限制。 限制设置为 4096 个字符。如果数据超过此限制，则会被截断。您可以更改此限制 通过在气流配置中设置“[core]max_template_field_length”配置选项。

将 MySQL 后端的 xcom 表列值类型更改为 longblob (#38401)

Xcom 表列“value`` type has changed from ``blob`` to ``longblob”。这将允许您在 Xcom 中存储相对较大的数据，但如果您在 Xcom 中存储大量大数据，则处理过程可能会花费大量时间。 从修订版降级：“b4078ac230a1``, ensure that you don't have Xcom values larger than 65,535 bytes. Otherwise, you'll need to clean those rows or run ``airflow db clean xcom”以清理 Xcom 表。
