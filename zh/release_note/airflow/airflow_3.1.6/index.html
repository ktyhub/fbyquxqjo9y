airflow 3.1.6

修订 发布时间2026年1月13日 来源apache/airflow 英文原文

airflow 3.1.6

变更流程图

亮点

  • HITL 审批授权 — Auth manager 新增 is_authorized_hitl_task()（#59399），让自定义后端可以决定谁有权审批 Human-in-the-Loop 任务，而不再依赖粗粒度的管理员检查。请结合 SimpleAuthManager 在 all_admins=True 下的 ApprovalOperator 修复（#60116）一起审查审批配置：新的授权路径现在会被真正调用。
  • 代理配置按敏感信息处理 — proxy 和 proxies 加入 DEFAULT_SENSITIVE_FIELDS（#59688/#59792），因此代理 URL（包括其中嵌入的凭据）默认会在日志和 UI 中被遮蔽；渲染模板被截断时，其中的密钥也能正确隐去（#59566/#59704）。如果你刻意在报表或自定义遮蔽规则中展示代理设置，请预期原本显示值的地方会出现掩码。
  • DAG 序列化稳定化 — 通过 callable 提供的模板字段不再产生不稳定的序列化 DAG（#60065/#60221），含斜杠/特殊字符的 XCom 键也得到正确处理（#59311）。这减少了调度器中无谓的 DAG 版本变动，并让你可以使用结构化 XCom 键而不破坏 xcom_pull 查找。
  • Execution API 与 Task SDK 通路 — 删除 DagRun 现在会校验运行状态（#60195/#60207），Execution API 的 refresh-token 流程得到修复（#58782/#59713），Task SDK 调用在缺少 Content-Type 时会自动补上（#59676/#59687）。在任意状态下删除运行的客户端可能会遇到新的拒绝。Task-SDK 客户端还去掉了对 FastAPI 的依赖（#59250/#59257）：worker 依赖面更轻，但不要依赖从 SDK 传递泄漏出来的 FastAPI 类型。
  • 回填与监控正确性 — run_on_latest_version 现在按预期默认设为 True（#59304/#59328），回填会使用当前的 DAG 代码而非历史版本——如果你依赖旧默认值，这是可见的行为变化。缺失的 ti_failure 指标现在会被记录（#59731/#59964），调度器重置 TI 时会恢复 TaskInstanceHistory 行（#59639/#59752），使仪表盘和审计轨迹更完整。
  • 调度器与 DAG processor 健壮性 — aiosqlite 0.22+ 的挂起线程保护（#60217/#60245），DAG processor 不再因 DAG 目录中的 Excel 文件（#59069/#59170）或日志错误（#59317/#59581）而崩溃，.airflowignore 的否定规则在子目录中生效（#58740/#59305），清除运行时 DagRun.queued_at 也会正确更新（#59066/#59177）。对 SQLite/本地部署以及混合文件类型的仓库最为相关。

无破坏性变更。

重大变化

is_authorized_hitl_task() 方法现在可在身份验证管理器中使用(#59399)。

现在，身份验证管理器中可以使用此方法来检查用户是否有权批准 HITL 任务

proxy and proxies added to DEFAULT_SENSITIVE_FIELDS (#59688)

Secrets_masker 中的“proxy`` and ``proxies`` have been added to ``DEFAULT_SENSITIVE_FIELDS”默认将代理配置视为敏感
