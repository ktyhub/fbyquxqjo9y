airflow 3.2.2

📦PyPI：https://pypi.org/project/apache-airflow/3.2.2/ 📚 文档：https://airflow.apache.org/docs/apache-airflow/3.2.2/ 🛠 Release Note：https://airflow.apache.org/docs/apache-airflow/3.2.2/release_notes.html 🐳 Docker 图片：“docker 拉 apache/airflow:3.2.2” 🚏 约束：https://github.com/apache/airflow/tree/constraints-3.2.2

重大变化

  • 由“airflow.utils.email.send_email`` now validates the SMTP server's certificate against the system's trusted CA bundle by default. Previously the ``starttls()”调用执行的 SMTP STARTTLS 升级是在没有 SSL 上下文的情况下进行的，因此任何证书都被接受。 有意将 Airflow 指向具有自签名或非验证证书且需要保留之前行为的 SMTP 服务器的部署必须设置 email.ssl_context = "none" in airflow.cfg. The "default" value (now also the default when the option is unset) uses :func:ssl.create_default_context. Previously this option applied only to the SMTP_SSL 路径；它现在也适用于 STARTTLS 路径。 (#65346)
  • 在#64963中，Airflow UI从完全匹配的“*_pattern`` REST API query parameters to the new index-friendly ``*_prefix_pattern`` parameters on list endpoints. This is a behavioral change for search-as-you-type filters in the UI: matches are prefix-based (``LIKE 'term%'`` via a range scan) instead of substring-based (``ILIKE '%term%'``), which means the database can use B-tree indexes and search stays fast on large deployments. The REST API itself keeps both forms: existing ``*_pattern”参数切换而来，其行为仍然与以前完全相同。 在#66015 中，添加了每个搜索栏的“匹配任意位置”切换开关，以便依赖先前子字符串行为的用户可以从 UI 中选择重新使用它。每个搜索输入和每个文本过滤器现在在值旁边都有一个小的正则表达式图标切换；将其翻转到从“*_prefix_pattern`` to ``*_pattern”输入的开关上。 (#66015)
  • 修复导致延迟任务无限期停滞的触发器竞争条件和死锁 调用同步 SDK 方法的触发器（例如，使用的“get_task_states”） 多个 Google 提供商运营商中的“safe_to_cancel”）可能会导致触发器崩溃 内部子流程。 然后触发者会继续正常心跳—— 对调度程序来说显得健康 - 同时默默地处理零触发器，导致 每个延迟任务都会超时。 这是在问题 #64620 中首次报道的；一个 Airflow 3.2.1 (#64882) 中提供了部分修复，但引入了新的死锁 在负载下具有相同的明显症状。 这两个问题都通过用响应替换基于锁的序列化来解决 多路复用：现在每个请求都带有唯一的 ID，响应将路由回 正确的调用者，因此来自触发器线程的并发请求不再竞争或 无论有多少触发器正在运行或它们调用什么 SDK 方法，都会发生死锁。 新：触发子进程看门狗 即使比赛固定，触发器也会阻止事件循环（例如通过调用 time.sleep() or performing blocking I/O directly in async def run()) 会 之前让触发者无限期地保持健康。 新的“[triggerer] runner_health_check_threshold”配置选项（默认值：30 秒） 添加一个看门狗：如果触发子进程静默的时间超过阈值， 父进程停止更新心跳，以便调度程序可以检测到挂起并 重新分配触发器而不是等待它们单独超时。 设置选项 至“0”以禁用看门狗。 (#66412)
  • 收紧“[core] allowed_deserialization_classes_regexp”以要求全字符串匹配 “[core] allowed_deserialization_classes_regexp”中的模式现在已匹配 使用“re.fullmatch()`` instead of ``re.match()”针对整个类名。 此前，“airflow\.models\.Variable”等模式不仅承认 预期的类以及以其开头的名称 （例如“airflow.models.Variable_Malicious``), because ``re.match”仅限锚点 在字符串的开头。 该选项的默认值为空，因此开箱即用的部署是 不受影响。使用依赖于的模式配置此选项的部署 前缀匹配语义 - 例如“airflow\.models\.”表示“任何类 在“airflow.models``" — must add ``.*”下的图案 (airflow\.models\..*) 保留以前的行为。 (#66499)
  • 自定义截止日期参考类现在必须在反序列化时通过新的“deadline_references`` attribute on ``AirflowPlugin``, matching the existing pattern for custom timetables and custom partition mappers. To use a custom ``DeadlineReference`` subclass, register it in a plugin's ``deadline_references`` list. Custom references that are not registered will raise ``DeadlineReferenceNotRegistered”进行注册。 (#66737)
