airflow 3.1.7

修订 发布时间2026年2月4日 来源apache/airflow 英文原文

airflow 3.1.7

变更流程图

亮点

  • 认证与授权 — JWT 生成现在能处理未设置的 issuer/audience 配置（#61331），权限修复覆盖事件日志、DAG 查询过滤、导入错误 API 和 UI 端点（#60958、#60959、#60884、#60988）。登出现在会使刷新令牌失效（#60881），因此认证测试应验证登出后的令牌无法被复用。
  • 调度器与 DAG 生命周期正确性 — 反序列化失败现在会触发调度器护栏，而不再扰乱处理流程（#61210）。陈旧 DAG 的资产调度与版本化 bundle 回调得到修复（#60022、#61106、#61230），仅路径变化的 DAG 修改不再产生无谓的版本变动（#60799）。对已设调度的 DAG 手动运行也会获得唯一的 run ID（#60468）。
  • operator 与 worker 行为 — TriggerDagRunOperator 在 wait_for_completion=False 时不再意外延迟（#60052），避免可延迟执行卡住。worker 在 DAG 加载失败后现在会重新调度任务而非退出（#59604、#60926），triggerer 遇到不可序列化事件时也能继续存活而不崩溃（#60981）。
  • 大规模部署效率 — DAG processor 在写入 DAG 版本时不再加载全部 TaskInstance（#60962），并应用了 gc.freeze()（#60845），降低内存压力。队列调整减少了冗余处理（#60124、#60003），而 XComModel.clear() 现在采用批量删除而非逐条加载记录（#60955），在大型元数据数据库上清理成本大幅下降。
  • API 与 UI 兼容性 — API 现在强制限制最大分页大小（#61073）；分页客户端应预期返回有上限的响应，而非任意大的页面。React Router 升级（#60456）需要对自定义 UI 插件做回归测试。网格虚拟化（#60285）和更快的大日志滚动（#60875）也改善了重型 DAG 视图的响应速度。
  • 兼容性 — 未列出破坏性变更。
