airflow 3.2.1

修订 发布时间2026年4月22日 来源apache/airflow 英文原文

airflow 3.2.1

变更流程图

亮点

  • 破坏性的 /dags 授权变更 — 只读 DAG 访问权限不再授予 GET /dags；该端点现在要求具备 DAG Runs、Task Instances 和 HITL Details 的读权限（DagAccessEntity.RUN、DagAccessEntity.TASK_INSTANCE 和 DagAccessEntity.HITL_DETAIL）。升级前请审计自定义角色和服务账号，在仍需聚合 DAG 数据的地方补授这些权限（#64822）。另一个资产图权限泄漏也得到修复（#65280）。
  • 降低数据库争用与查询开销 — 心跳现在使用快速路径的 UPDATE，在常见情况下避免行锁（#65137）；批量预取消除了序列化环节的 N+1 查询（#65208），并修复了任务实例状态/计数端点中的同类问题（#64695）。繁忙的调度器和 API server 应能看到更少的锁争用和更低的数据库负载。
  • 更干净的关闭与 HTTP 会话生命周期 — dispose_orm() 现在会释放异步引擎（#65284），流式响应和基于生成器的依赖中的会话泄漏得到修复（#65193、#65195）。长时间运行的 API 部署将保留更少的数据库连接、关闭更干净；从心跳表中清除的任务实例的心跳现在正确返回 HTTP 410（#64693）。
  • 更可靠的自动化与 CLI 行为 — SDK 现在遵循 $AIRFLOW_CONFIG（#65200），失败的 CLI 命令返回正确的非零退出码——包括 connections import（#65097、#64449）——@task 在装饰时就会校验 operator 参数类型（#65050）。脚本和 CI 流水线可以信任退出状态，无效的任务定义会更早失败。
  • 日志与遥测连续性 — OpenTelemetry 指标不再在 fork 出的任务进程中丢失（#64720），任务日志可通过 write_to_os 写入 OpenSearch，并恢复了本地设置集成（#65201、#65003）。使用基于进程的执行或集中式 OpenSearch 日志的 operator，应对照这些修正后的路径核验现有 handler。
  • 更灵活的 UI 主题 — 主题的 tokens 现在可选，允许仅用 CSS 或仅用图标进行覆盖；空 {} 会恢复 OSS 默认值（#64552）。现有自定义主题在只改样式时，不再需要重复定义 token。

重大变化

  • 仅对 DAG 具有读取访问权限的用户将无法再从“/dags`` endpoint, as it now requires additional permissions (``DagAccessEntity.RUN``, ``DagAccessEntity.HITL_DETAIL``, and ``DagAccessEntity.TASK_INSTANCE``). This change was made because the endpoint returns aggregated data from these multiple entities. Please update your custom user roles to include read access for DAG Runs, Task Instances, and HITL Details if those users should still have access to the ``/dags”端点获取数据。 (#64822)

改进

  • 允许 UI 主题配置仅包含 CSS 覆盖、仅图标或空“{}`` to restore OSS defaults. The ``tokens”字段现在在主题配置中是可选的。 (#64552)
