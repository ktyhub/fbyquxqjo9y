airflow 3.1.2

修订 发布时间2025年11月5日 来源apache/airflow 英文原文

airflow 3.1.2

变更流程图

亮点

  • 依赖兼容性障碍解除 — #57335 修复了由 structlog 25.5.0+ 触发的导入失败，#56762 将重试逻辑从 retryhttp 迁移到本就是核心依赖的 tenacity，因此可以少一个包。如果你曾把 structlog 固定在 25.5 以下以维持 Airflow 可导入，现在可以解除该固定——但在切换到 tenacity 后请重新测试自定义重试行为，因为异常与退避语义不同。
  • Airflow 2→3 迁移加固 — 迁移路径上的崩溃得到处理：#55884 修复 2→3 升级后 triggerer 的报错，#57459 修正 bundle 初始化期间 DagProcessorManager 中的连接检索，#57330 阻止 DAG processor 摄入来自其他 bundle 的回调。这对多 bundle 或分布式部署最为关键——此前一个游离回调或缺失连接就可能拖垮 processor——统一到 3.1.2 消除了若干升级期的坑。
  • 面向大规模部署的扩展性修复 — 一波集中的查询与内存优化针对大量 DAG 及 DAG 版本的痛点：XCom（#57554）、Event Logs（#57558）和 DAG 列表标签抓取（#57570）中的 N+1 消除，受限访问的 DAG 列表优化（#57460），「Out of sort memory」修复（#57042），动态 DAG 更新不再加载大型序列化 DAG（#57592），通过更智能的 default_args 回调序列化生成更小的序列化 DAG（#57397），以及 API 客户端 SSL 上下文内存泄漏修复（#57374）。大型实例应能看到更低的数据库负载和更快的 UI/API 响应——如果你运行数千个 DAG，值得跑个基准。
  • 任务执行与 API 正确性 — 若干行为修复改变了开发者可以依赖的东西：被外部信号杀死的任务现在能正确重试（#55767），triggering_user_name 在上下文中得到恢复（#56193），outlet event 的 extra 数据会填充到任务实例成功监听器回调中（#57031），Human-in-the-Loop operator 可与 notifier 配合工作（#57551），Task SDK 请求现在携带 Content-Type 头（#57386）。留意 #57616，它收紧了序列化期间的 Pydantic 校验严格度——更严格的检查可能暴露此前漏过的自定义 operator 中的潜在类型错误。
  • 可观测性与 UI 工作流 — 调试更轻松：可一次下载全部任务日志（#56771），XCom 查看器新增时间戳列（#57447），任务启动时会记录 execution API server URL（#57409），事件日志响应暴露 task_display_name 别名（#57609）。注意 #57548 将「Connection not found」从 error 降级为 debug——如果你针对该 error 级日志行设置了告警，请更新规则，否则会漏报。
  • 破坏性变更 — 无；这是一个维护版本，没有重大或破坏性变更。
