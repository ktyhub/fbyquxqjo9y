airflow 3.1.0

小版本 发布时间2025年9月25日 来源apache/airflow 英文原文

airflow 3.1.0

这个项目是干啥的：一个用代码编排定时任务的调度平台，把数据处理流程串成流水线，按时运行、失败可重试，适合要管理大量周期性作业的工程师。

变更架构图

亮点

  • Human-in-the-loop 审批成为一等公民 — AIP 引入 HITLOperator、ApprovalOperator 和 HITLEntryOperator（#52868），配有专用 UI 和受 RBAC 管控的表单（#53035）、可过滤的 API 端点（#53376、#53923），以及新的 No Response Received 动作状态（#55149）。这用原生的暂停/恢复闸门取代了临时拼凑的外部审批 hack；升级后应预期出现新的待处理动作表/权限，并思考 DAG 现在会在哪些地方等待人工输入。
  • Deadline 告警（AIP-86）实现主动 SLA 监控 — Deadline 被建模为与 DAG run 绑定的一等对象（#50925、#50093），可配置参考点和通知回调（#50677、#50093）、支持异步 Notifier（#53831），并提供 UI/API 接口（#53951、#53903、#53201、#55086）。现在你可以在截止之前告警，而不必轮询错过的运行——注意新的异步 notifier 路径可能需要更新自定义 notifier。
  • React UI 现在可通过插件扩展（AIP-68） — 新的 React 插件系统（#52255）、iframe 外部视图（#51003、#51889）以及自定义 React 应用仪表盘集成（#54131、#54144），让你能把自己的页面和操作嵌入现代 UI。如果你维护插件，请留意 /plugins 中新出现的校验告警（#55673），不要假设旧的 FAB 风格视图会自动移植。
  • 运行时与依赖现代化 — 现在支持 Python 3.13（#46891），同时推进 SQLAlchemy 2.0 兼容工作（#52233、#52518、#54940）并新增 psycopg3 Postgres 驱动选项（#52976）。如果你固定在较旧的 Python 或 ORM/驱动版本，请仔细测试 DAG 序列化和数据库连接——SQLAlchemy 2.0 的改动触及底层查询行为。
  • 所有 Airflow 日志切换到 structlog — 全面迁移到结构化日志（#52651、#55434、#55431、#55638）改变了日志形态，同时新增 JWT 令牌脱敏（#55499）、保证 filename/lineno 字段（#55581），并修正 default_timezone 非 UTC 时的时间戳（#54431）。基于旧文本格式构建的下游日志解析器、仪表盘和告警规则需要审查；任务 stdout/stderr 现在也能在日志查看器中过滤（#55508）。
  • 从 2.x 升级的路径大幅加固 — 一批迁移修复涵盖：已有 FAB 表时的数据库降级（#55738）、序列化 DAG v3→v2 降级转换（#55975）、2.x 遗留的孤儿任务（#55848）、使用同步连接调用的自定义 trigger（#55799）、升级期间日志格式保留（#55824），以及 Variable 键中的斜杠字符（#55324）。这些清除了常见的 2.x 升级阻碍——但切换前仍请在预发环境验证迁移和自定义 trigger。

此版本未指出破坏性变更。
