pi v1.5.0

新功能

  • 扩展更新 changelogs：在更新后的下一次全新启动时查看已安装的扩展包中发生的变化。包作者可以选择 changelog 路径，collapseChangelog 压缩通知。请参阅显示 changelog。
  • 更快的流：大型工具调用会逐步解析，代码密集的答案和工具行会重用突出显示和呈现的 Markdown，而不是在每次更新时重复工作。请参阅保持渲染响应。
  • 自定义自更新命令：使用 PI_SELF_UPDATE_COMMAND 或 selfUpdateCommand 通过包装器或其他包管理器更新 pi。请参阅自定义更新命令。
  • GPT-6.1 Terra：通过 OpenAI、Azure OpenAI Responses 和 OpenAI Codex 提供，具有工具搜索、对话中思维水平变化和思维 off。 Codex 提供了 500K 上下文窗口。参见型号。

重大变化

  • 工具参数验证在 @earendil-works/pi-schema 上运行。 JSON 架构之外的 TypeBox 功能（Type.Refine()、Type.BigInt()、Type.Undefined()、编解码器、Format.Set() 格式）不再适用于工具参数；请参阅工具参数模式和类型框。普通 JSON 架构工具（包括 MCP 工具）现在获得与 TypeBox 工具相同的强制转换，例如转换数字字符串并将单个值包装到数组中。验证失败模型看到列表 pi-schema 的消息（- path: missing、- limit: expected number, got string）而不是 TypeBox 的消息（must have required properties path、must be number）。

添加

  • 扩展包现在可以在更新后显示其 changelog。 Pi 从包的 package.json 或包根中的 CHANGELOG.md 读取 pi.changelogPath，并在下一次全新启动时在“扩展更新”下显示比上次看到的版本更新的条目。 collapseChangelog 设置将其压缩为每个包一行（#5958、#8790）
  • pi.exec() 接受限制 stdout 和 stderr 组合的 maxBuffer 选项，其结果有一个 truncated 字段，当输出超出限制时该字段为 true (#11360)
  • 设备代码登录（例如 GitHub Copilot）现在会打开验证页面，并在按 Enter 时复制代码。提供商可以使用 openBrowserOnConfirm: false 或 copyCodeOnConfirm: false 关闭任一操作（#9282、#9301）
  • pi update 可以通过包装器或其他包管理器更新 Pi。设置PI_SELF_UPDATE_COMMAND（例如mise use -g npm:{packageName}@{version}）或全局selfUpdateCommand设置；当 pi.dev 报告较新版本时，pi update 会运行它，并填充该版本中的 {packageName}、{version} 和 {installSpec}。请参阅自定义更新命令（#7756、#5607）
  • 扩展可以使用工具渲染上下文以及消息和条目渲染器选项中的 keyText() 和 keyHint() 格式化用户配置的键绑定。从 @earendil-works/pi-coding-agent 导入这些函数可以解析扩展自己的包副本，该副本看不到 pi 的键绑定，因此在没有密钥的情况下呈现诸如 keyHint("app.tools.expand", "to expand") 之类的提示。文档现在推荐注入的函数（#4748）
  • 将持久会话条目 messageId 和 ISO timestamp 添加到 MarkdownTransformContext。它们在渲染保存的条目时可用，但对于实时渲染未定义（#7952 by @vipentti）
  • 在内联 ctx.ui.custom() 组件中添加了 blocked 选项，以便批准提示和其他自定义对话框可以报告 pi 正在等待用户输入。覆盖忽略该选项。请参阅自定义屏幕和叠加层 (#11428)
  • 添加了 Usage.cost.totalFromProvider，以区分计费总额与 SDK 中的目录估计和扩展使用数据；仅当每个部分都是 (#11178) 时，组合使用才会被标记为提供商报告
  • 将具体的 responseModel 元数据添加到来自 pi 消息提供商（例如 Radius）的消息中，包括请求虚拟模型时。请参阅助手消息 (#11265)
  • 添加了适用于 OpenAI、Azure OpenAI Responses 和 OpenAI Codex 的 GPT-6.1 Terra，以及工具搜索和对话中期思维级别更改。支持思维off； Codex 提供 500K 上下文窗口

已更改

  • 扩展不断从 @earendil-works/pi-ai 导入 Type、Static 和 TSchema：导入到 pi-ai 的兼容条目的 Pi 映射加上它捆绑的 TypeBox，现在 pi-ai 本身不再重新导出 TypeBox，并且它的 StringEnum 保留了 TypeBox TUnsafe<T>。内置工具工厂（createReadTool() 和其他）返回 TypeBoxAgentTool<typeof schema>，这使 params 保持为 TypeBox 的类型。
  • 加强系统提示
  • 从 pi.dev 安装程序安装的 pi update 不再将 --min-release-age=0 传递到 npm ci。发布锁定文件会固定每个包，因此该标志无效，并且阻止它的安全扫描器会停止更新（#11262）
  • 当名称添加 ID 缺少的单词时，/model 和 /scoped-models 现在会在其 ID 旁边显示模型的名称，例如重命名的 models.json 覆盖（#5916、#11347）
  • 当授权服务器支持公共 client 时，MCP OAuth 登录现在默认使用 pi 的 Client ID 元数据文档，否则会动态注册 client，如 Codex、Claude Code 和 opencode。 Clients 在继续使用之前注册，且其重定向 URI 匹配。当设置 clientName 或非默认 callbackUrl 时，新的默认 oauth.clientRegistration: "auto" 会注册； "dcr" 始终注册。 pi mcp add --oauth-client-registration 设置模式 (#11426)
  • 将默认 OpenAI 模型从 gpt-5.5 更改为 gpt-6.1-sol，包括在 ChatGPT 登录后未选择模型时 (#11442)
  • 将内置模型目录更新为 models.dev v2。实时和纯图像模型不再作为聊天模型提供；包括较新的 OpenAI 和 Google 聊天模型

已修复

  • 更新了 glob 匹配，以防止放大的 glob 模式导致拒绝服务。
  • 修复了对于没有 trust 需要资源的项目（例如仅包含 AGENTS.md 的文件夹），已保存的“不要 trust”决策被忽略的问题。 pi auto-trusted 这样的项目，因此 ctx.isProjectTrusted() 返回 true 并且包命令将它们视为 trusted。 trust.json 中保存的决策现在优先； auto-trust 仅在未保存任何决策时适用 (#10947)
  • 修复了 Shift+Enter 排队后续操作，而不是在发送 ESC + Return 的 Apple 终端设置中插入换行符的问题。 pi 现在检查该序列的本地 Shift 键状态，就像它已经对普通 Return 所做的那样；没有 Shift 的 Alt+Enter 仍将后续队列排队（#11559）
  • 修复了在常规 TUI 模式下运行期间 Rex 和 iTerm2 中工作状态 (OSC 7501) 消失的问题。渲染消息将 OSC 133 提示符标记写入终端，终端将其视为新的 shell 提示符；常规模式不再写入它们（#11519）
  • 修复了 SDK 会话中的压缩、分支摘要和错误报告摘要，将存储的 OAuth 令牌作为显式 API 密钥传递回模型运行时。对待显式密钥与存储的 OAuth 不同的提供商身份验证现在可以看到 OAuth 登录，就像正常提示一样 (#11520)
  • 修复了当扩展以不同的顺序设置相同的活动工具时的冗余系统提示更新（工具、规则），例如反向的 pi.setActiveTools() 列表。保持活动状态的工具现在保持其顺序，并附加新激活的工具（#11495）
  • 修复了当命令打印的输出多于字符串所能容纳的输出时，pi.exec() 使 pi 与 RangeError: Invalid string length 崩溃的问题。默认输出上限是 256 MiB 和运行时字符串限制中的较小者；超过上限后，命令将终止，结果为 truncated: true 和非零退出代码 (#11360)
  • 修复了当命令在超时或中止后忽略 SIGTERM 时 pi.exec() 永远不会返回的问题。 pi 现在按预期在 5 秒后发送 SIGKILL
  • 修复了当通过符号链接（例如链接到 dotfiles 存储库的 ~/.pi）到达代理目录时，pi install 和 pi remove 向 npm package-lock.json 添加更深的嵌套条目。 pi 现在将解析后的真实路径传递给 npm (#11358)
  • MCP 登录现在拒绝授权端点和非 http: 或 https: 的其他 OAuth 元数据 URL。之前，恶意 MCP 服务器可以提供 file: 或自定义协议 URL，pi 将其传递给平台 URL 处理程序。
  • 自动 fd 和 rg 下载不再在没有预构建版本的情况下获取 ARM32 和其他架构上的 x86-64 二进制文件。 pi 现在发出警告并建议使用系统包管理器安装该工具（#11209）
  • 修复了 /model 搜索排名字母分散在真实匹配项上方条目较早部分的问题，例如 opus 在 claude-opus-4.1 之前列出 gpt-oss-120b 和 claude-sonnet-4.5（#11220、#11296）
  • 修复了 /resume 搜索匹配会话消息和 ID 中任意位置的分散字母的问题，例如会话 UUID 内的 1024 匹配。会话名称和工作目录仍然模糊匹配； ID 和消息文本现在仅作为精确子字符串匹配（#11220、#11024、#11296）
  • 修复了 HTML 导出在包含数千个条目的会话中显示空白页面的问题（#11225、#11293）
  • 修复了 HTML 导出不显示系统消息：系统提示和工具以及后续部分更新（例如 /reload 之后）的问题。 pi --export 现在也包含系统提示符和工具（#11261、#3464、#11290）
  • 修复了在 macOS 上有时会运行列表中的下一个命令（例如 long_step; next_step）时中止 bash 命令的问题。 pi 现在在杀死进程组之前停止它（#11252、#11289）
  • 修复了大型流式工具调用占用过多 CPU 时间和内存的问题，因为每个增量都会重新解析累积的参数。提供程序和代理代理流现在解析每个增量一次，语法工具不再复制每个增量的整个输入，并且交互式工具渲染器每帧最多运行一次（#9265）
  • 修复了登录对话框打开非 Web URL 的登录 URL，并打印来自登录、设备代码和信息 URL 的控制字符，这可能会结束终端超链接并向终端发送转义序列
  • 修复了 tui.select.pageUp 和 tui.select.pageDown 在斜杠命令和文件自动完成、/settings 以及模型、作用域模型、登录、fork、/mcp 和 llama.cpp 选择器中被忽略的问题。在全屏模式下，PageUp/PageDown 现在移动打开的列表或自动完成菜单，而不是滚动文字记录，并且将分页键绑定到 Ctrl+V 页面自动完成，而不是粘贴图像（#7629，基于 @muyiyr 的 #7680）
  • 修复了工具输出和 ! 命令输出，显示带有 <、= 或 > 前缀的控制序列参数作为文本，例如来自鼠标报告的 35;59;1M 或来自终端回复 ESC[>0;276;0c 的 0;276;0c。键盘模式序列 ESC= 和 ESC> 之后的文本仍保留（#11377）
  • 修复了 pi -e npm:<pkg> 停留在第一次下载时的版本。现在，在每次启动和 /reload 时，当注册表具有较新的匹配版本时，pi 都会重新安装 -e npm 软件包，但没有确切的版本。 pi -e git:<repo>@<branch> 同样停留在第一次结帐状态，现在已被提取并重置到分支；不会获取已签出的提交哈希引用。离线模式和失败的检查会保留缓存的副本（#11375、#11590）
  • 修复了区分大小写比较的 Windows 路径。当工作目录和主目录仅驱动器盘符大小写不同时（c:\Users\me 与 C:\Users\me），~/.agents/skills 中的技能作为项目和用户技能加载两次，并报告为名称冲突。同样的不匹配还重新请求保存的项目 trust，将会话隐藏在 --continue 和 /resume 的自定义会话目录中，并阻止 pi remove 匹配配置的本地包（#10488）
  • 修复了主目录旁边的路径显示为损坏的 ~ 前缀，例如，当主目录为 /home/me 时，/home/me2/project 显示为 ~2/project
  • 修复了 pi mcp login -l 和 pi mcp logout -l 与 Unknown option --local. 一起失败的问题，尽管 pi mcp add 和 pi mcp remove 接受 -l。对于 -l，他们现在要求服务器是项目服务器。现在会报告输入的未知选项，并且输入错误的服务器名称会收到建议，例如 Did you mean "gurker"?
  • 修复了仅在 PNPM_HOME 下安装的 pi update 命名 pnpm，例如 $PNPM_HOME/global-nub/ 下的包装器。 pi 说“不由全局 pnpm 安装管理”；现在，仅当该管理器拥有安装时才命名该包管理器（#7756）
  • 修复了当工作目录很深时，在 WSL 上粘贴、复制和打开浏览器进行登录失败的问题。 powershell.exe 和 explorer.exe 等 Windows 程序无法从 \\wsl.localhost\... 路径超过 260 个字符的目录启动； pi 现在从 / 启动这些助手（#11592）
  • 修复了外部编辑器无提示失败的问题，例如当编辑器命令错误或 Windows 编辑器无法从深层 WSL 目录启动时。 pi 现在显示状态消息，例如 External editor exited with code 1; prompt unchanged (#11592)
  • 修复了 tool_search 和代码模式 searchTools() 将工具排名低于仅在描述中提及其名称的工具，例如 peekaboo app 将 mcp__peekaboo__app 排名第 14。匹配更多查询单词的工具现在排名高于匹配更少的单词，工具名称中的查询单词得分高于其描述中的任何提及次数，整个名称在查询中的工具获得很大的奖励，并且长服务器指令不再降低该服务器工具的分数（[#11331]（https://github.com/earendil-works/pi/issues/11331））
  • 修复了 tool_search 和代码模式 searchTools() 对于中文、日文、泰文和其他非 ASCII 查询找不到任何内容，因为分词器仅保留 ASCII 字母和数字。现在，任何脚本中的单词都会匹配，单词之间没有空格的文本（例如 搜索记录）会被拆分为单词，并且规范等效的文本（例如 café 和 cafe\u0301）会匹配（#10816、#11037 by @haoqixu）
  • 修复了当另一个 pi 会话打开 git 扩展的本机模块或可执行文件时，pi update 在 Windows 上与 git clean -fdx failed with code 1 一起停止的问题。 Windows 无法删除此类文件，因此更新将新代码与旧依赖项一起保留。 pi 现在发出警告，无论如何都会安装依赖项，并在下次更新时重试清理 (#11597)
  • 修复了工具行和流答案，在每次重画时再次突出显示相同的代码。正在运行的代码模式行在每次进度更新和计时器滴答时突出显示其整个脚本，完整的 write 行在每次更新和扩展切换时突出显示其整个文件，流式 write 其在每个增量上的前 50 行，以及流式回答每个增量上的每个早期代码块。现在，行重复使用最后一次突出显示，直到代码、主题或加载的语法发生更改，并且助理消息在流式传输时保留其渲染的 Markdown 块（#10971）
  • 修复了调整大小后的照片即使在 JPEG 小得多的情况下也会以多兆字节的 PNG 形式发送，从而导致大型请求失败或超时的问题。图像大小调整现在首先尝试较小的编码（#11551）
  • 修复了当 npm 的过时注册表元数据将包保留在旧版本时，pi update --extensions 报告成功而不发出警告的问题。 pi 现在报告已安装的版本和预期的版本 (#11536)
  • 修复了即使没有名称冲突也会标记为 [Skill conflicts] 的技能验证警告。它们现在显示在 [Skill warnings] 下 (#11521)
  • 修复了代码模式工具描述，包括每个请求中的整个联合和多行输出类型。对象联合现在总结了它们的领域和鉴别器；其他多行类型指向 describeTool() 的完整声明（#11501）
  • 修复了退出全屏模式后模型范围启动通知留在 shell 中的问题。它现在出现在 pi 的全屏标题中 (#11508)
  • 修复了从已删除的工作目录启动时因未捕获的 uv_cwd 堆栈跟踪而崩溃的问题。 pi 现在要求用户更改到现有目录（#11509）
  • 修复了失败的会话写入，在内存中留下磁盘中不存在的条目，因此后来的条目指向丢失的父项，并且恢复的会话丢失了早期的历史记录和工具（[#11460]（https://github.com/earendil-works/pi/issues/11460））
  • 修复了 /tree 分支摘要忽略会话思维级别的问题，这可能会使推理模型拒绝具有不受支持的 none 工作的摘要请求（#11444）
  • 修复了隐藏思维，带有空的隐藏思维标签，仍然在答案和工具调用之前添加空白行（#11402）
  • 修复了软件包安装和删除打印 npm 审核和资金建议的问题，包括可以将 pi 的第二个副本安装到软件包目录中的 npm audit fix 说明（#11409）
  • 修复了在对话框打开时替换扩展编辑器隐藏对话框并使其无法应答的问题。新的编辑器现在会在对话框关闭后出现（#11431）
  • 修复了当文件包含单独的回车符时 grep 上下文行从 ripgrep 的匹配行号偏移的问题 (#11398)
  • 修复了 --model <provider>/<id> 包含斜线的提供程序 ID 失败的问题，例如 URL 派生的 llama.cpp 提供程序 ID (#11394)
  • 修复了文件系统上缓慢的会话分叉问题，其中通过一个文件句柄写入分叉来打开文件的成本很高（#11253）
  • 修复了 pi.exec() 损坏跨 stdout 或 stderr 块分割的 UTF-8 字符的问题 (#11312)
  • 修复了当无法生成命令（例如缺少可执行文件）时 pi.exec() 返回空 stderr 的问题。现在它保留了生成错误消息（#11257 by @muyiyr）
  • 修复了配置包安装失败导致启动崩溃的问题。 pi 现在会跳过该包，报告扩展警告，并在下次启动或 /reload 时重试；显式安装和更新命令仍然失败并出现非零退出（@Lincoln504 的#11304）
  • 修复了工具调用参数验证失败时导致 TUI 崩溃的待办事项扩展示例 (#8057 by @cyzlmh)
  • 将 undici 更新为 8.12.3，并将 Gondolin 扩展示例更新为 0.14.0 以获取安全建议
  • 使用目录估算而不是报告聊天完成和人为消息的计费来修复 OpenRouter 成本总计。 BYOK 总计包括 OpenRouter 费用和报告的上游成本；组件成本仍然是目录估计值（#9980）
  • 修复了使用共享端点而不是特定于协议的 OpenAI、Anthropic、Google 和 System One 端点的 OpenCode Zen 和 OpenCode Go 请求（#11434 by @vimtor）
