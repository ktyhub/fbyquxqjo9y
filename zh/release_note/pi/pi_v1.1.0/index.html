pi v1.1.0

新功能

  • 程序状态报告：支持 OSC 7501 的终端和代理仪表板可查看 Pi 是否正在工作、在对话框或登录时被阻止、完成或失败。请参阅程序状态。
  • Claude Haiku 5.5：anthropic/claude-haiku-5-5，自适应思维达到 xhigh/max 的努力。
  • 使用 +name/-name 调整默认工具：--tools 条目（如 pi -t +codemode,-write）更改默认选择而不是替换它。请参见工具。
  • GPT-6 Luna 和图像分类：OpenAI 的 GPT-6 Luna 可通过 Decisions API 作为分类器模型，而 codemode 的 models.classify() 接受支持它们的分类器的图像。请参阅使用分类器模型。
  • 本机 llama.cpp 决策模型：由 llama.cpp 0.6.0 提供的 Julia-1、Laya、Kev、lev 和 OpenJev 或更高版本通过 /v1/systemone 作为分类器本机运行。参见【分类】(https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/docs/llama-cpp.md#classification)。

添加

  • 在 --tools 中添加了 +name 和 -name 条目，这会更改默认工具选择而不是替换它，例如 pi -t +codemode
  • 将 durationMs 添加到工具渲染上下文和 tool_execution_end 扩展事件：最终工具结果的记录执行时间 (#10549)
  • 将 outputPad 添加到工具渲染上下文（@rwachtler 的#10557）
  • 通过决策 API 添加了 OpenAI 的 GPT-6 Luna 作为分类器模型，可用于 OPENAI_API_KEY（请参阅使用分类器模型）
  • 将 images 添加到 codemode 的 models.classify() 上下文中，因此接受图像的分类器（例如 GPT-6 Luna）可以判断它们
  • 添加了 OSC 7501 的程序状态报告：支持它的终端和代理仪表板可查看 Pi 是否正在工作、在对话框或登录时被阻止、完成或失败。 PI_PROGRAM_STATUS=1|0 覆盖检测（请参见终端设置）（#10607）
  • 将 aborted 添加到 agent_settled 会话、扩展和 JSON 事件，因此集成可以区分已取消的运行和已完成的运行（#10607）
  • 添加了克劳德俳句 5.5 (anthropic/claude-haiku-5-5)，自适应思维高达 xhigh/max 工作量并在基岩上进行提示缓存
  • 添加了原生 llama.cpp 决策模型：由 llama.cpp 0.6.0 或更高版本提供的 Julia-1、Laya、Kev、lev 和 OpenJev 仅通过 /v1/systemone 列为分类器，而不是聊天模型（请参阅分类）（#10382）

已更改

  • 将 outputPad 更改为也适用于 ! 命令输出、工具输出和摘要块（@rwachtler 的 #9946、#10557）
  • 更改了 pi mcp login --timeout 以限制整个登录，包括对授权服务器的请求，而不仅仅是等待浏览器（#10565）

已修复

  • 修复了 bash 和 PowerShell 结果在重新加载会话后丢失 Took 以及实时 Took（包括挂钟步骤）的问题；现在两者都显示记录的执行时间（#10549）
  • 修复了托管安装，保留每个旧版本； pi update 现在仅保留新版本及其更新版本（#10392、#10511 by @davidbrai）
  • 修复了将 .env、.env.local 和 .env.development 从启动目录加载到 Pi 环境中的独立二进制文件 (#10473)
  • 修复了 !! 命令标头一旦输出到达就会失去暗淡颜色的问题 (#10557 by @rwachtler)
  • 修复了代码模式描述未将 searchTools()、describeTool() 和 describeNamespace() 标记为异步的问题，这导致模型将未等待的承诺序列化为 {} (#10555)
  • 修复了一起运行的代码模式输出项，因此模型无法区分 text() 或 console.log() 输出在哪里结束以及下一个输出在哪里开始。对于多个文本项，每个文本项现在都以 ==> text N/M <== 行开头，并且 console 调用遵循一个 <console_output> 块中的其他输出，每个调用一行
  • 修复了/mcp在打开之前等待所有服务器连接的问题；管理器现在实时更新并在启用、重新连接或禁用服务器时保持可用（#10562）
  • 修复了在节点 24.19+ 和 26.x 上的 node --watch 下运行时图像被删除为“无法调整大小”的问题，其中节点在图像调整大小工作通道上发布自己的消息（#10527）
  • 修复了 clipboard 粘贴在 Termux 中不执行任何操作，并且复制失败而忽略 Termux:API 安装提示 (#10391)
  • 修复了 ! 和 RPC bash 输出，当代码被分割到输出块时，保留颜色代码的片段，例如杂散的 m (#10504)
  • 修复了 MCP OAuth 登录在等待授权服务器时无法取消并在会话结束后继续运行的问题。现在，登录屏幕会在每一步中按 Esc 取消，会话关闭会中止正在运行的登录，并且对授权服务器的每个请求都会在 15 秒后超时 (#10565)
  • 修复了关闭等待长达 15 秒来刷新即将过期的 MCP OAuth 令牌，仅关闭服务器会话的问题 (#10565)
  • 修复了会话切换和其他转录重建中幸存的全屏文本选择，突出显示了新转录中不相关的文本（#9311、#10567 by @christianklotz)
  • 修复了 Bedrock 上的 OpenAI 模型忽略思维级别并始终以 Bedrock 的默认推理工作运行的问题（#9331、#10142 by @jsanter27）
  • 修复了 models.json 中的 headers 模型不覆盖 Codex 请求的 originator 和 User-Agent 标头的问题（#10429 by @lucasmeijer）
  • 修复了 server_busy 和 servers are currently busy 提供商错误结束回合而不是重试的问题 (#10543)
  • 修复了以 finish_reason: "error" 未重试结束的米斯特拉尔响应 (#10487)
  • 在计算输出限制时，通过估计每个令牌的 3.5 个字符而不是 4 个输入来减少上下文限制请求失败（#10497）
  • 修复了组织所有者禁用的半径模型仍被列出的问题
  • 修复了当端口 53692 被保留或使用时，Anthropic 浏览器登录失败并显示“本地主机拒绝连接”的问题，例如 Windows 上的 Hyper-V/WSL 端口排除：登录现在回退到空闲环回端口 (#10571)
  • 修复了通过 OpenCode、OpenCode Go、OpenRouter、Vercel AI Gateway、Google、MiniMax 和其他提供商在具有提示长度定价层的模型（例如 Claude Haiku 5.5、Gemini 3.1 Pro 和 GPT-5.4）上低估长提示的会话成本
  • 修复了 Herdr 中的 Markdown 链接无法 clickable (#10573)
