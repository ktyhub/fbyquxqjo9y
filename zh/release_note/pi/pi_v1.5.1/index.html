pi v1.5.1

新功能

  • Shell 登录和注销：使用 pi auth login <provider> 和 pi auth logout <provider> 而不启动会话，并使用 API 密钥和无浏览器登录选项。请参阅凭据命令。
  • 空闲提示缓存预热：符合条件的缓存现在在运行之间保持预热长达 30 分钟，此时刷新预计会收回成本。请参阅cacheWarming。
  • 人为消息线程：当服务器继续对话时，请求仅发送新消息，当早期上下文发生更改时，会进行完整请求回退。请参阅人类兼容性。
  • 更丰富的美人鱼图：饼图、作者定义的样式、支持终端上的 clickable 标签以及扩展分支和压缩摘要中的图表。请参阅显示设置 和Markdown 转换器。
  • GitHub Copilot 分类器：通过代码模式 models.classify() 调用 Microsoft-Decision-1 以获取类型化决策和概率。请参阅使用分类器模型。
  • 包更新摘要：pi update --extensions 报告每个包的 npm 版本或 git 提交更改，并区分未更改、跳过和警告的更新。请参阅更新 Pi 或软件包。

重大变化

  • 上下文行不再调用自定义 GrepOperations.readFile 回调。该字段仍被接受为可选字段并已弃用，因此现有集成仍可编译。 grep 工具现在从 ripgrep 获取上下文行，并且不再读取匹配的文件本身。要搜索远程系统，请覆盖 grep 的 execute()；请参阅远程执行 (#9276)
  • 当在已使用工具的会话中禁用所有工具时，OpenAI 兼容模型不再发送 "tools": []；该字段被省略。这修复了来自 vLLM 0.20+ 的 400 个错误 (tools must not be an empty array)，同样落后于 LiteLLM。如果您的代理在历史记录有工具调用后需要 tools，例如 Anthropic 前面的旧 LiteLLM 版本，请在 models.json 中为该模型设置 compat.requiresToolsWithToolHistory: true (#11843)

添加

  • pi update 现在列出每个更新的包及其 npm 版本或 git 提交更改，例如 npm:foo 1.2.0 -> 1.3.0，并在没有任何更改时打印 Packages are already up to date。当没有任何改变但更新打印了警告时，例如因为 npm 在解决过时的注册表元数据后留下了安装的旧版本，它会打印 No packages were updated, see the warnings above ；在离线模式下，它打印 Skipped package updates (offline mode)。 PackageManager.update() 将每个更改的包报告为新的 result 进度事件，其 message 保留该行（#11707、#11711）
  • 人类会话现在使用消息线程：每个请求仅发送新消息，服务器从之前的回复继续，当对话发生变化时（例如在压缩或工具列表更改之后），回退到完整请求。 api.anthropic.com 上的 anthropic 提供商默认开启；在 models.json 中设置 compat.supportsMessageThreads 以启用或关闭转发 thread 字段的网关。缓存预热不会影响会话的线程 (#11545)
  • pi.registerMarkdownTransformer() 采用可选的 { messageTypes }，它选择变压器运行的 Markdown 表面。除了用户、助手和思考 Markdown 之外，变压器现在还可以选择 custom（自定义消息和技能块）、summary（分支和压缩摘要）和 changelog（新增功能、/changelog、扩展更新通知和可用更新注释）。如果没有选项，变压器将像以前一样在用户、助手和思维 Markdown 上运行。内置的 Mermaid 渲染器现在还可以在扩展分支和压缩摘要中绘制图表
  • pi auth login <provider> 从 shell 登录到提供程序而不启动会话，例如 pi auth login radius。它在浏览器中使用帐户登录并退出； --api-key 改为保存 API 密钥，--no-browser 改为使用设备代码或复制代码登录。登录 Radius 还会配置 Radius MCP 服务器。 pi auth logout <provider> 删除存储的凭据，如 /logout
  • ctx.ui.custom() 覆盖现在支持 blocked 选项：pi 报告从显示覆盖到调用 done() 期间的阻止程序状态 (OSC 7501)，以及使用 setHidden() 隐藏时的情况。关闭一个覆盖层会阻止其他未解决的问题 (#11816)
  • 使用 QWEN_TOKEN_PLAN_CN_API_KEY 在中国端点上为 Qwen 代币计划个人版添加了 qwen-token-plan-individual-cn 提供商（#7989 by @bigoldcat123）
  • 通过 GitHub Copilot 添加了 Microsoft-Decision-1 分类器支持，包括代码模式 models.classify()（@Marvae 的 #11679）
  • 添加了 compat.promptCacheKeyMode（"auto"、"enabled" 或 "disabled"），以便为兼容代理启用提示缓存密钥，或为拒绝它们的端点忽略它们。使用 pi 时将其设置为 models.json (#9442 by @dannote)
  • 为 OpenAI 兼容端点添加了 compat.requiresNonNullAssistantContent，这些端点在仅包含工具调用的助理消息中需要空字符串而不是 null。使用 pi 时将其设置为 models.json (#8118 by @gaoyk19)
  • 在读写视图中添加了 Dart、Nix、Groovy 和 Gradle 文件的语法突出显示 (#11643)
  • 将 GLM 5.3 添加到 Qwen 代币计划个人模型白名单中（#11658）
  • 将 Claude Fable 5.2 (claude-fable-5-2) 添加到 anthropic 提供商（每百万输入/输出代币 8 美元/40 美元，1M 上下文，128K 输出）。与《神鬼寓言》5.1 一样，它使用每条消息的工作量和对话中系统消息；在 Claude Opus 5 通过服务器端回退回答任何输出之前，请求其安全分类器拒绝并按 Opus 5 的价格计费。其他提供商（例如 OpenRouter 的 anthropic/claude-fable-5.2）上的 Claude Fable 5.2 和 Mythos 5.2 获得相同的每条消息工作量支持

已更改

  • anthropic 提供商的默认型号现在是 Claude Opus 5.5 (claude-opus-5-5)，而不是 Claude Opus 4.8
  • 默认型号以相同或更低的价格转移到新型号：amazon-bedrock Claude Opus 5.5、azure GPT-6.1 Sol、google 和 google-vertex Gemini 4 Argon、vercel-ai-gateway GLM 5.3、baseten GLM 5.3、 minimax 和 minimax-cn MiniMax-M3、qwen-token-plan 和 qwen-token-plan-cn Qwen3.8 Max、opencode-go Kimi K3.1 Pro 和 Kimi K2.7 代码代替 Kimi K2.6 用于 moonshotai、moonshotai-cn、huggingface、opencode、openrouter、 cloudflare-workers-ai 和 cloudflare-ai-gateway
  • cacheWarming 现在默认为 "idle" 而不是 "streaming"：pi 还会在代理运行之间将符合条件的提示缓存保持热状态长达 30 分钟，但前提是刷新预计会收回成本。在全局设置中设置 "cacheWarming": "streaming" 以实现先前的行为
  • 连续缓存预热现在显示为具有累积成本的一条 Cache warmed: $<total> 行，而不是每次预热显示一行
  • OpenAI Codex 提供程序在 /login 和模型选择器中再次显示为“OpenAI Codex”，而不是“OpenAI Codex（旧版）”
  • /login 和 /logout 提供商列表和 /login <provider> 完成现在首先显示首选合作伙伴 Radius 和 OpenRouter，然后按字母顺序显示所有其他提供商。在提供商列表中，合作伙伴标有 ✦，选定的 Radius 行以 Radius 徽标颜色闪烁，选定的 OpenRouter 行以 OpenRouter 的品牌颜色发光（深色主题上呈石灰色，浅色主题上呈紫色）
  • 升级了终端 Mermaid 渲染以支持更多图表类型，包括饼图、作者定义的样式以及具有超链接支持的终端上的 clickable 标签（#8158 by @xl0）

已修复

  • 修复了 grep 工具的 glob 从文件夹 pi 开始匹配，而不是从 path 开始：对于 path: "repo"，glob: "migrations/main/*.js" 返回 No matches found，即使 repo/migrations/main/a.js 存在。 Glob 现在与 path 相关，与 grep 打印其结果的形式相同，当 path 是符号链接时也是如此。前导 ./ (./src/*.ts) 会被忽略，而不是不匹配任何内容（#11807、#10998）
  • 修复了提示模板参数删除撇号和合并单词的问题：单词内的撇号（如 doesn't 中）不再打开引号；没有结束匹配的引用将保留为文本；和 "..." 内的 \" （或 '...' 内的 \'）给出了文字引用（#11861）
  • 修复了当命令已经退出但它启动的后台进程继续写入其输出直到超时时，bash 工具仅报告 Command timed out。该错误现在还报告 shell 的退出代码以及退出时间 (#11613)
  • 转向和后续消息中的图像（包括流式传输时的 prompt()）现在会像空闲提示中的图像一样调整大小，而不是以全尺寸发送和保存（#11738）
  • MCP 连接的失败令牌刷新不再注册 OAuth client 或替换正在进行的登录的 PKCE 验证程序，这导致登录失败。即使环回回调端口发生更改，MCP 登录现在也会使用存储的 client 刷新存储的令牌，而不是注册新的 client 并打开浏览器。 /mcp 中的 Ctrl+C 和 pi mcp login 中的 --timeout 现在也会停止登录，同时等待另一个 pi 进程的令牌刷新长达 25 秒，并且由于除现在等待之外的其他原因而失败的刷新锁定会导致登录失败，而不是打开浏览器。
  • 修复了 pi mcp list 报告具有 "auth": { "provider": "<provider>" } 的 MCP 服务器（例如 Radius）需要登录，尽管提供程序已登录：shell 命令未发送令牌。它现在发送提供商的 /login 令牌并在过期时刷新它。对于这些服务器，登录提示名称 /login <provider> 而不是 pi mcp login，并且 pi mcp login 和 pi mcp logout 指向 /login 和 /logout，而不是因“不使用 OAuth”而失败
  • 修复了 RPC 模式在空闲时忽略扩展的 ctx.shutdown()（例如来自计时器）的问题：进程一直运行，直到 client 发送另一个命令。 pi 现在在空闲时立即关闭，并且扩展命令请求的关闭会等待，直到写入命令的 prompt 响应 (#11599)
  • 修复了当安装的软件包版本具有预发布后缀（例如 0.1.5-20261020.7）时，每次新启动时 changelog 注释会重复的问题：保存的版本被读取为 0.1.0，因此 0.1.1 到 0.1.5 注释每次都会被视为新注释。没有 major.minor.patch 的保存版本现在不显示任何注释，并被安装的版本替换，而不是显示整个 changelog (#11703)
  • 修复了 RPC 模式在 stdin 关闭和 SIGTERM 一起到达时切断关闭清理的问题，例如挂起的 MCP 令牌刷新，Paseo 和 systemd 等进程管理器会这样做。 Pi 丢失了刷新的令牌，MCP 服务器撤销了登录。一旦开始关闭，stdin EOF 或单个信号就不再中断它；第二个信号仍然立即存在。同样，打印模式不再因最终清理期间到达的信号而终止（#11599）
  • 修复了设置 context 时 grep 工具将每个匹配文件读取到内存中的问题，该工具在处理大文件时会耗尽内存；上下文现在来自 ripgrep，它还修复了匹配行中的 UTF-16 文件和单独的 CR，并且当存在精确的 limit 匹配时，不再出现匹配限制通知（#9276、#11423）
  • 修复了当 limit 文件完全匹配时查找工具报告结果限制，以及 find 和 ls 中的 limit: 0 返回每个结果或空列表的问题；低于 1 的限制现在意味着 1 (#7121)
  • 修复了 grep 匹配行、代码模式输出、工具结果的压缩摘要以及 MCP 错误和服务器摘要，在截断时将表情符号或其他非 BMP 字符切成两半，从而在文本中留下无效的单独代理（#7121）
  • 修复了 Windows 上的查找工具对于带有 Windows 分隔符（例如 src\**\*.ts）的模式以及每个路径模式（例如带有 fd 10.5.1 的 src/**/*.ts（pi 现在下载的））不返回结果的问题。 Windows 路径模式现在与每个 fd 版本的匹配方式相同：src/**/*.ts 还直接在 src/ 中查找文件，并且 src/*.ts 不再在子目录中查找文件（#9262）
  • 修复了读取工具将整个文件加载到内存中的问题，即使使用 offset/limit，该工具也会在处理大文件时出现内存不足的问题；它现在流式传输文件并仅保留显示的行。定制 ReadOperations 也可以通过提供新的可选 createReadStream 进行流式传输 (#9654)
  • 修复了 OAuth 登录（例如 openai 和 anthropic）在 pi 在刷新过期令牌时停止后失败并显示 invalid_grant，例如 RPC client 在后台目录刷新运行时启动后立即停止 pi。令牌端点已替换刷新令牌，但 pi 在保存新令牌之前退出。退出时，pi 现在等待保存正在进行的令牌刷新（#11692）
  • 修复了当活动模型不同时 Ctrl+P 不会切换到范围内唯一模型（或唯一可用模型）的问题；它显示“范围内只有一个模型”。 Cycling 从范围外的模型向前转发现在还会选择第一个范围模型，而不是跳过它（#11806）
  • 修复了当扩展打开多个 ctx.ui.custom({ overlay: true }) 时，/reload 和会话开关在屏幕上留下扩展叠加层的问题：仅删除最上面的叠加层，而其他叠加层则保持焦点和输入，尽管打开它们的扩展程序已消失。所有扩展覆盖（包括隐藏的覆盖）现已删除并处理； pi 自己的覆盖层保持打开状态
  • 修复了在成功浏览器登录后，/mcp 登录停留在“正在连接…”几分钟，而 Ctrl+C 不执行任何操作：pi 等待浏览器删除与 OAuth 回调端口的未使用的连接。回调服务器现在在关闭时关闭剩余连接（#11311）
  • 修复了重复图像读取后 pi 中止 (zsh: abort) 的问题，在具有节点 24.16 的 macOS arm64 上报告。每次图像大小调整都会启动一个工作线程，并且 pi 没有等待它停止，因此下一次调整大小会启动一个新的工作线程，而前一个工作线程仍在关闭。崩溃很可能是这种重叠触发的 Node bug，并且无法在 Linux 上重现；图像调整大小现在等待前一个工作程序停止，这会为每个图像增加大约 15 毫秒 (#10695)
  • 修复了 tool_search 和 searchTools() 无法通过本地 $ref 后面的属性名称和描述找到工具的问题，如将其模型放入 $defs 的 MCP 输入模式中。引用的定义被读取一次，因此递归模式不会循环，并且定义中没有引用会保留在搜索文本之外 (#11803)
  • 修复了工具的代码模式 resolves to 摘要，在本地 $ref 后面遗漏了字段名称，例如，对于将模型放入 $defs 的 MCP 输出模式，使用 structuredContent? 而不是 structuredContent?: { results } (#11803)
  • 修复了当任何可调用工具（例如 MCP 工具）的模式中具有格式错误的百分比转义 (#/$defs/%E0) 的 $ref 时，每个代码模式脚本都会因 URI malformed 失败，甚至不调用该工具的脚本也是如此。该参数现在在工具声明中呈现为 unknown (#11803)
  • 修复了代理工作时运行的 ctrl+o 不展开或折叠 ! 和 !! 命令的输出的问题。新的 !/!! 输出现在在当前展开状态下启动，当转向或后续消息排队时，输出不再消失，并且当代理完成时（而不是在下一条提交的消息时）移动到聊天中（#11875）
  • 修复了 /tree 导航到 /thinking 更改之前恢复旧思维水平的会话。与模型一样，实时思维级别现在记录在新分支上并出现下一个提示（#11451）
  • 修复了全屏模式下的内联图像仅在 Orca 中显示第一行，而常规模式则完整显示它们。全屏现在在每个终端上覆盖的行之后绘制 Kitty 图像，就像 WezTerm 所做的那样 (#11835)
  • 修复了编辑工具重写具有混合 CRLF/LF 或单独 CR 行结尾的文件中未触及行的行结尾，以及在文件已写入后在大文件上耗尽内存的问题； diff 现在仅覆盖更改的行及其周围环境，并在写入之前计算（#8544）
  • 修复了当 npm 或 Node.js 打印任何警告（例如来自未知 .npmrc 密钥的 npm warn Unknown user config）时，Windows 安装程序 (irm https://pi.dev/install.ps1 | iex) 在 Windows PowerShell 5.1 中中止并显示 NativeCommandError。迁移 npm 安装以及托管安装期间，它在操作菜单之前失败。无效的 managed-install.json 也会中止安装程序而不是被报告（#11944）
  • 修复了当提供商的登录信息过时时 pi update --models 因 Could not refresh model catalogs: openai: OAuth refresh failed for openai: ... invalid_grant 而失败的问题。目录来自 pi.dev 的内置提供程序（例如 openai）根本不再刷新其 OAuth 令牌以进行目录刷新。对于列出具有登录名的模型的提供商（例如 Radius 和 OpenRouter），失败的令牌刷新现在会打印一条警告，命名提供商和 pi auth login <provider>，而其他目录仍会刷新；该命令仅因其他错误而失败，例如网络故障
  • 修复了当本机命令成功但其 stderr 被重定向时，Windows PowerShell 5.1 下的 powershell 工具报告 Command exited with code 1，如 git push 2>&1 | Select-Object -Last 3 中。 Windows PowerShell 5.1 将 stderr 转换为错误记录；此类命令现在报告退出代码 PowerShell 7 报告 (#8842)
  • 修复了使用 Backspace 删除粘贴标记会损坏后来的短标记（例如 [paste #2]），导致提交标记文本而不是其粘贴的内容（#11923）
  • 修复了被丢弃的提供商流报告为“回复开始后缩短”不触发自动重试的问题（#11879）
  • 修复了子代理扩展示例，在生成编译的 pi 二进制文件时将 Bun 的 Windows 虚拟入口路径作为提示的一部分传递（#11865）
  • 修复了模型选择器和 llama.cpp Hugging Face 搜索在后台目录刷新或搜索结果到达时移动选择的问题 (#9109)
  • 修复了泄漏到终端输出中的内部光标标记，包括多个标记或水平 cli 内容（#9441 by @muyiyr）
  • 修复了显示正在运行的任务已完成、丢失子进程故障诊断以及无法在中止时停止子进程的子代理扩展示例。代理发现和 trust 检查现在使用每个任务的工作目录，并且单个和链结果会被截断，而不会丢失完整的工具详细信息（#8250 by @terrorobe）
  • 修复了切换编辑器、打开自定义 UI 或恢复排队消息时，大的粘贴文本被文字粘贴标记替换的问题 (#10146 by @w-winter)
  • 修复了异步输入挂钩、身份验证或分支摘要期间提示和会话树导航重叠的问题，这可能会安装错误的对话上下文（#9155 by @acmerfight）
