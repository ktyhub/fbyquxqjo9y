pi v0.99.0

新功能

  • Codemode 和 MCP — 连接 MCP 服务器并让模型运行并行调用工具的 JavaScript。请参阅 MCP 服务器 和 启用代码模式。
  • 系统主题 — Pi 的颜色现在默认来自您终端自己的调色板。请参阅使用终端的颜色。
  • 使用 ChatGPT 登录 — 通过 /login openai 使用 OpenAI 提供商的 ChatGPT 订阅。请参阅交互验证。
  • 虚拟模型 - 扩展可以将每个请求路由到不同的物理模型。请参阅虚拟模型。
  • 分类器模型 — 从 codemode 脚本运行 Jev 分类器，或使用任何 llama.cpp 模型作为分类器。请参阅codemode 的工作原理 和分类。

添加

  • 添加了代码模式、工具搜索和 MCP 支持作为内置扩展。 codemode 工具在调用 pi 工具的 QuickJS 沙箱中运行模型编写的 JavaScript；使用 defaultTools 或 --tools 启用它，并使用 codemode.mode 和 codemode.inlineBudget 配置它。 tool_search 查找未向模型声明的工具并声明它们。通过 stdio 或可流式 HTTP 并使用 OAuth 的 MCP 服务器来自 mcp.json（全局，或每个项目一次 trusted）或 pi.registerMcpServer()，并使用 /mcp 和 pi mcp add|remove|list|login|logout 进行管理。请参阅 MCP 服务器 和 启用代码模式 (#10040)。
  • 添加了用于编排工具的扩展工具 API：exposure（direct、model-only、codemode、deferred 或 hidden）、namespace、annotations、outputSchema 与 structuredContent、isError 结果、prepareLoadout()、 ctx.executeTool() 用于嵌套工具调用，它发出带有 parentToolCallId 的事件，并在调用工具的结果上记录为有界 nestedCalls。请参见工具曝光。
  • 添加了当注册相同工具、命令或标志的扩展替换内置扩展时的警告（#10174 by @cristinaponcela）。
  • 添加了实验性虚拟模型：扩展将它们注册到 pi.registerVirtualModel() 并为每个请求选择物理模型和思维水平。页脚显示路由模型，/session 列出每个物理模型的成本，examples/extensions/jev-router.ts 使用 Jev 分类器进行路由。请参阅虚拟模型。
  • 在 /login 中向 OpenAI 提供商添加了使用 ChatGPT 登录，该提供商使用 OpenAI API 的 ChatGPT 订阅。 Pi 在此次登录的全局设置中存储了一个稳定的 deviceId ，并在错误报告中忽略了它。
  • 添加了 system 主题，现在是默认主题，它从终端报告的前景、背景和 ANSI 调色板中派生 pi 的颜色，并在终端在明暗之间切换时重建它们。请参阅使用终端的颜色。
  • 在主题文件中添加了 #rgb、oklch() 和 okhsl() 颜色和可选的 appearance 字段，以及用于扩展的 theme.style()、theme.colors 和 theme.appearance。请参阅主题 和 TUI。
  • 为每个 llama.cpp 聊天模型添加了一个分类器模型，从下一个标记标签概率中回答。参见分类。
  • 在 OpenRouter、Cloudflare Workers AI、Vercel AI Gateway 和 OpenCode Zen 上添加了继承的 Jev 分类器模型。
  • 添加了用于全屏鼠标滚轮滚动的 fullscreenWheelScrollLines 设置和 /settings 条目。默认的 "auto" 可以加速本地 macOS 终端之外的快速轮子旋转 (#9758)。
  • 为成功的 RPC prompt、steer 和 follow_up 响应、AgentSession.steer()/followUp() 和 RpcClient.prompt()/steer()/followUp() 添加了按输入配置； RpcClient.prompt() 还接受 streamingBehavior（#9098、#9803）。
  • 向 ModelRuntime 添加了图像生成：具有运行时解析的身份验证（存储凭据、OAuth、运行时 API 密钥、models.json 标头）的 generateImages()，以及 getModelsOfType()、getModelOfType()、getAvailableOfType()、getAllModels() 和 getAllAvailable()。 OpenRouter 镜像模型列在 openrouter 提供商下并共享其凭证；上游 ID 可以有单独的聊天和图像条目。没有模型列表的 models.json 提供程序和扩展注册保留内置图像生成。扩展模型列表可以包括带有操作实现的可区分聊天、图像和分类器条目；当提供时，它们会替换每个操作中的提供者目录。面向聊天的读取（getModels()、getAvailableSnapshot()、模型选择器）未更改。
  • 为 ModelRuntime 添加了分类器支持，包括 classify()、分类器模型访问器、运行时解析的身份验证和内置 TypeSafe jev-latest 模型。
  • 将 types=chat,image,classifier 添加到 pi.dev 模型目录请求中，以便远程刷新覆盖每个支持的模型类型；未知模型类型的条目将被忽略。
  • 添加了 provider_stream_event 扩展事件，用于在规范化之前观察解析的提供程序事件，并使用选择加入的 /debug-provider 示例查看器（#9784、#9901 by @davidbrai）。
  • 在 HTML 导出中为标记为 display: false 的自定义消息添加了显示/隐藏切换 (H)。默认情况下，消息保持隐藏状态，也可以从侧边栏显示（@rwachtler 的 #8896、#10020）。
  • 添加了继承的 Claude Sonnet 5.5 对 Anthropic 的支持，具有自适应思维和 1M 上下文窗口。
  • 在 pi config 中添加了内置部分，以全局或按项目禁用内置 mcp、llama.cpp、codemode 和 tool-search 扩展，在 extensions 设置中存储为 -builtin:<name>。 SDK 内联扩展选择使用 builtin: true。
  • 在 defaultTools 设置中添加了 +name 和 -name 条目，以添加或删除工具，而无需重复默认设置，例如 "defaultTools": ["+codemode"]。此表单的项目条目适用于用户设置之上。记录了如何在没有 MCP 的情况下启用 codemode 以及如何使用代码模式脚本中的分类器模型（例如 Jev）。
  • 在 codemode 工具结果中添加了 codemode models.classify() 调用的令牌使用和成本，因此它们计入会话成本； codemode 结果显示每次调用的成本。

已更改

  • 将构建从 TypeScript 本机预览切换为具有 ES2024 目标的 TypeScript 7.0，并使用 Node 的内置类型剥离替换 tsx，以从源运行（#9965）。
  • 从启动横幅中删除了 [Themes] 部分。自定义主题在 /settings 中仍然可用，并且仍然报告主题冲突。
  • 更改了启动标题以显示 pi 徽标和版本而不是应用程序名称。
  • 将内置 dark 和 light 主题更改为修订后的 pi 颜色，以 OKHSL 编写。
  • 将亮/暗终端检测更改为首先使用报告的背景颜色，然后是终端的亮/暗报告，然后是 COLORFGBG。首次设置不再显示检测到的外观。
  • 将继承的 OpenAI Codex 提供程序重命名为“OpenAI Codex (legacy)”；在 OpenAI 提供商上使用 ChatGPT 登录取代它。
  • 更改了继承的终端检测，将 TERM=*-direct 视为真彩色。
  • 内置扩展和工具在错误、诊断、RPC 源信息和错误报告中命名为 builtin:<name>（例如 builtin:mcp 和 builtin:read），而不是 <inline:name> 和 <builtin:name>。他们的斜杠命令不再带有 [t] 自动完成标签。
  • --no-extensions 还禁用内置扩展，包括 llama.cpp 提供程序。使用 ZZPH100​​ZZ 显式加载一个，例如 pi -ne -e builtin:mcp。
  • 没有自定义调用渲染器的工具调用（包括直接 MCP 工具调用）现在显示其参数：折叠时在标题行上显示为 key=value 对，展开时每个参数显示一个 key: value 行。 MCP 调用的标题为 server/tool，其结果缩减为 5 行。
  • Codemode 脚本接收的 bash 和 powershell 结构化结果现在最多可容纳 1 MiB 输出，而不是面向模型的 2000 行或 50KB，并添加 truncated 和 full_output_path。较长的输出保持其第一个和最后一个 512 KiB。空输出是 "" 而不是 (no output)。

已修复

  • 修复了当 clipboard 所有者接受未广告的图像目标时，X11 clipboard 文本被错误识别为图像的问题 (#9786)。
  • 阻止托管 git 包自动安装 Pi 对等依赖项，并为列出 dependencies 中主机提供的模块的扩展包添加警告 (#9863)。
  • 修复了加载 -e 的固定 git 扩展在引用更改后继续使用第一个下载的提交（#9982）。
  • 修复了当侦听器在处理事件时取消订阅时，RpcClient 会跳过下一个事件侦听器，这可能会使 waitForIdle() 在 collectEvents() 之后超时 (#9990)。
  • 修复了当模型发送 null 来省略 offset 和 limit 时，完整文件 read 调用渲染为 :1 (#9996)。
  • 修复了当 pi 在第一个助手响应之前退出时新会话丢失的问题。现在，会话文件是在发送第一条用户消息时创建的 (#10000)。
  • 修复了卸载的 llama.cpp 自动加载预设会使用 GGUF 训练上下文覆盖缓存的运行时上下文窗口（#10077、#10158 by @cristinaponcela）。
  • 修复了忽略 terminal.trueColor 和其他终端功能覆盖并以 256 种颜色渲染的自定义主题（#9973、#10039 by @christianklotz）。
  • 修复了粘贴在 Finder 中复制的文件时插入文件图标图像而不是文件路径的问题；路径在 bash 模式下引用（#9999、#10136 by @christianklotz）。
  • 修复了启动标题、加载的资源和聊天通知，在主题更改后保持旧颜色。
  • 修复了 Fireworks 默认模型指向已删除的 Kimi K2.6 模型的问题；现在默认为 Kimi K3。
  • 修复了 OpenCode Go 默认模型指向已删除的 Kimi K2.6 模型的问题；现在默认为 Kimi K3。
  • 修复了Together默认模型指向已删除的Kimi K2.6模型的问题；现在默认为 Kimi K3。
  • 在长时间会话中进行流式传输以及预览主题时减少了 CPU 使用量：页脚缓存会话使用总量，折叠的 bash 结果缓存其预览，并且 sanitizeBinaryOutput() 不再将输出拆分为每个字符数组。
  • 修复了通过 ctx.executeTool() 调用的工具的使用，例如从代码模式脚本中调用的工具，从会话成本中删除；现在它已添加到调用工具的结果使用中。
  • 修复了当加载的技能名称不包含 skill 中的字母时继承的 /skill 自动完成显示为空的问题（#9944）。
  • 修复了打开 (、[、{、< 或反引号等包装器后继承路径和 @ 自动完成功能不起作用的问题。
  • 修复了使用 Kitty 图形协议的终端中继承的图像拉伸问题（#8938、#9957 by @rwachtler）。
  • 修复了当扩展在关闭期间关闭覆盖层时继承的 shell 光标在退出后保持隐藏的问题 (#10026)。
  • 修复了 /settings 子菜单中的鼠标 click 关闭它后继承的键盘输入丢失的问题。
  • 修复了通过 Vercel AI Gateway 继承的 1 小时 Anthropic 缓存写入按 5 分钟费率定价的问题 (#9210)。
  • 修复了 OpenAI 兼容的 API 上的直接 stream()/complete() 调用会丢弃继承的模型级 samplingParams (#9506)。
  • 修复了继承的 Mistral GLM 请求在空内容增量后失败并显示“预计最多一个领先的 ThinkChunk”的问题 (#9674)。
  • 修复了继承的 OpenAI Fast 模式请求按标准费率定价的问题 (#10034)。
  • 修复了继承的米斯特拉尔推理模型忽略所要求的思维水平（[#9678]（https://github.com/earendil-works/pi/issues/9678））。
  • 修复了继承的 OpenCode Zen 和 OpenCode Go qwen3.8-flash 认为在以后的回合中以纯文本形式重播的问题 (#10047)。
  • 修复了从省略 output_index 的服务器继承的 OpenAI 响应流（例如 llama.cpp），运行混合工具调用；此类流现在以错误结束（#9974）。
  • 修复了继承的 Anthropic 和 OpenAI Codex 浏览器登录在提供程序因授权错误而重定向后无限期等待，以及当其回调端口正在使用时 Anthropic 登录失败的问题。
  • 修复了继承的 GitHub 副驾驶 Claude Opus 5.5 在上游模型元数据不完整时提供不受支持的思维水平。
