pi v1.3.0

pi v1.3.0

新功能

  • 选择 /share 上传位置：sessionShareDestination 选择 auto、gist 或 radius。请参阅会话和上下文 和导出或共享会话。
  • 在 OpenAI GPT-6 上缓存保留思维级别更改：使用 API 密钥在会话中更改思维级别会保留提示缓存。
  • Kimi Code over Chat Completions：在对话中添加的工具不再使提示缓存无效。 models.json 基本 URL 覆盖现在必须包含 /v1。请参阅提供商。
  • 干净的模型切换：先前模型的思考被丢弃，而不是以文本形式显示给新模型。
  • 恢复的会话保留其活动工具：--tools +name/-name 适用于它们。请参见工具。

添加

  • 在 OpenAI GPT-6 模型（API 密钥）上更改中间会话的思维水平现在会保留提示缓存（#10853）
  • 添加了 sessionShareDestination 设置，可以为 /share 选择自动、GitHub gist 或 Radius 上传（#10870 by @vegarsti）

已更改

  • 将 kimi-coding 提供商更改为在 https://api.kimi.com/coding/v1 上使用 OpenAI 聊天完成，这是官方 Kimi 代码 client 使用的协议。 K3、K3-256K 和 Kimi For Coding 现在接受在对话中添加的工具，而不会使提示缓存失效。 kimi-coding 基本 URL 的 models.json 覆盖现在必须包含 /v1 (#10720)
  • 更改了模型切换，以从不同模型生成的早期助理消息中删除思维块，而不是以纯文本形式发送它们。新模型之前将旧模型的推理视为其回复的一部分，并且可以开始将自己的推理写入可见答案中（#10995）

已修复

  • 将内部 Pi 依赖项固定到确切的发行版本，以防止全新安装混合不兼容的软件包（#10865）
  • 修复了恢复会话会丢弃会话期间激活的工具的问题。现在，恢复会恢复会话的活动工具，并应用 --tools +name/-name 条目，除非具有工具名称、--no-tools 或 --no-builtin-tools 的 --tools 显式选择工具（#10785）
  • 修复了停止代码模式脚本或达到截止日期等待不可中断的内置函数返回 Bun 的问题 (#10748)
  • 修复了重复的代码模式超时或中止累积幸存工人的问题；入场现在将跨会话的现场工作人员限制为两个，计算取消的工作人员直到实际退出（#10748）
  • 修复了当多个提供商提供匹配项时 --model 按目录顺序选择提供商的问题； Pi 现在更喜欢拥有凭据的提供商，否则会报告歧义。 --models 和 enabledModels 为每个提供该模型的提供商添加一个模型，并警告模糊性（#10160）
  • 修复了 TUI、会话树、HTML 导出和示例中数字字符串或空参数的 read 行范围标签 (#9887)
  • 修复了当提供商切换 APIs 时 Nix flake 构建失败的问题：当模型 API 组不同时，模型目录 pin 现在会从最新发布的目录中刷新，并在标记之前发布 pin 最新目录并使用它进行构建 (#10985)
  • 修复了 Nix 软件包将其 Node.js 放在 PATH 上的问题，这使得 bash 工具 shell 使用 Pi 的 Node 而不是用户的 node/npm。 Pi 的节点现在只是一个后备（#10519）
  • 修复了提示模板删除空引用参数（"" 或 ''），这会移动后面的位置参数并阻止应用位置默认值（#10867）
  • 修复了 Nix 软件包构建在安装检查中失败的问题，因为它仍然需要和弦和 esbuild，而 Pi 不再依赖它们
  • 修复了当字符串包含无效的 \u 转义（例如 \usepackage）时工具调用参数解析删除字段的问题（#10868）
  • 修复了当错误工具结果包含图像时，Anthropic 和 Bedrock Claude 请求失败并显示 400；现在，图像在工具旋转结果之后发送，因此模型仍然可以看到它们（#10794）
  • 通过将 OpenCode Zen 和 OpenCode Go 移动到 opencode.ai/inference 端点，修复了 OpenCode Go Gemini 模型因 404 错误而失败的问题，并向 OpenCode Go 提供商添加了 Google Generative AI 支持
  • 使用 Anthropic Messages API 修复了 OpenCode Go MiniMax M2.7 因“模型不支持此协议”而失败的问题
  • 修复了网关 Unable to forward upstream stream 错误不触发自动重试的问题 (#10920)
  • 修复了 The service is temporarily unavailable 错误不会触发自动重试的问题，这也会导致第一次尝试时压缩失败 (#10965)
  • 修复了 OpenAI 兼容响应，当 LiteLLM 等代理在同一流块中发送推理和内容时，显示答案后的思考 (#10926)
  • 修复了 Google Vertex 上的 Gemini 4 Argon 请求失败并显示“不支持思考预算”的问题，并且其思考级别在 Gemini API 上被忽略（#10890）
  • 修复了小米 MiMo 型号在 minimal 思维水平上无法达到 400 的问题；他们现在仅公开 off 和 high 级别（#10818）
  • 使用 272K 上下文窗口而不是 Codex 现在提供的 500K 窗口修复了 openai-codex/gpt-6.1-sol (#10840)
  • 修复了最终参数格式错误的工具调用 JSON 仅静默运行且仅在错误发生之前解析的字段；他们现在验证失败并向模型显示它发送的原始参数（[#10897]（https://github.com/earendil-works/pi/issues/10897））
  • 修正了 Claude Haiku 5.5 和 Claude Opus 5 不支持 off 思维水平的问题 (#10753)
  • 修复了扩展程序的 ctx.ui.custom({ overlay: true }) 的 done() 关闭最上面的覆盖层而不是其自己的覆盖层，这导致屏幕上完成的覆盖层和另一个扩展的对话框未解决（#10648、#10999 by @masonc15）
