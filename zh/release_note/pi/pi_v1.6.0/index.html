pi v1.6.0

pi v1.6.0

新功能

  • GPT-6.2 Astra 和 GPT-6.2 Sol：这两种型号均可在 openai、azure 和 openai-codex 提供商上使用，并且 GPT-6.2 Sol 现在是这三种型号的默认型号。请参阅提供商。

重大变化

  • 扩展组件：render() 现在返回 readonly string[]，Container 返回相同的缓存数组，而其子项不变。就地修改渲染输出的扩展（包括 Container 子类中的 super.render() 或嵌入式组件的输出）必须首先复制它 (#9549)

添加

  • 将 GPT-6.2 Astra 和 GPT-6.2 Sol 添加到 openai、azure 和 openai-codex 提供程序。两者都拒绝推理努力none和minimal，因此思维水平off不可用。 Azure 为他们提供了 105 万上下文窗口； Codex 为 GPT-6.2 Sol 提供 500K 服务，为 GPT-6.2 Astra 提供 272K 服务
  • 将 qwen4-max-preview 添加到 Qwen 代币计划个人提供商中（#12259）
  • 将 deepseek-v4.1-flash 和 deepseek-v4.1-flash-1017 添加到 Qwen 代币计划个人提供商，以及每个计划关键变量 QWEN_TOKEN_PLAN_TEAM_API_KEY、QWEN_TOKEN_PLAN_TEAM_CN_API_KEY、QWEN_TOKEN_PLAN_INDIVIDUAL_API_KEY 和 QWEN_TOKEN_PLAN_INDIVIDUAL_CN_API_KEY；共享的 QWEN_TOKEN_PLAN_API_KEY 和 QWEN_TOKEN_PLAN_CN_API_KEY 仍然有效（#11773）
  • 当 OpenAI 从请求中删除推理项时添加了转录通知，例如在 GPT-6.2 上压缩后的 OpenAI dropped 2 reasoning items: prefix_mismatch (details in session)。与人择思维通知一样，它在 showCacheMissNotices 打开时显示，并且仅当掉落的物品数量多于之前的响应时才会显示。两份通知均说明了原因

已更改

  • Qwen 代币计划提供商现在使用当前网关（token-plan.maas.qwencloudapi.com 国际、token-plan.maas.qianwenaiapi.com 中国），qwen-token-plan 和 qwen-token-plan-cn 分别命名为“Qwen 代币计划团队”和“Qwen 代币计划团队 CN”。提供商 ID 不变，旧的 aliyuncs.com 主机仍然可以工作 (#11773)
  • 将 undici 更新为 8.12.4，以获取安全建议 GHSA-mqg3-3v4r-cm32、GHSA-7xg3-fphp-28hg、GHSA-5rm8-gv32-r954、GHSA-9v6h-8rgp-m69f、GHSA-3g9m-rv3r-w5w2 和GHSA-r4pc-4jcp-7pqc (#12200)
  • openai、azure 和 openai-codex 提供商的默认型号现在是 GPT-6.2 Sol (gpt-6.2-sol)，而不是 GPT-6.1 Sol，价格相同
  • 查找工具的路径模式现在相对于搜索目录，如 grep 的 glob：src/*.ts 找到 src/a.ts，但不再找到 pkg/src/a.ts；使用**/src/*.ts可以在任意深度进行匹配。没有 / 的模式仍然匹配任何深度的文件名 (#12066)
  • llama.cpp 扩展现在默认连接到 http://127.0.0.1:9931，即当前 llama-server 默认端口，而不是端口 8080 (#12001 by @julien-c)
  • 现在，对于其 baseUrl 位于 api.anthropic.com 上的任何提供程序，人择消息线程默认处于启用状态，而不仅仅是 anthropic 提供程序（#11987）
  • 退出时打印的恢复命令现在位于 To resume this session: 之后的单独一行，因此可以使用三重 click 来选择它（#12237）

已修复

  • 修复了 read 存储当前模型不支持图像的注释，该注释在切换到视觉模型后作为陈旧文本重播到模型。对于没有图像输入的模型，图像仍会根据请求替换为占位符，并且读取结果现在仅在 TUI 中显示警告，折叠时也是如此 (#12131)
  • 修复了当扩展在 session_start 上仅停用其自己的工具时，由 tool_search 加载的 MCP 工具在恢复和 /reload 上被删除的问题，正如 pi-web-access 和 pi-subagents 在 toolActivation: "auto" 模式下所做的那样 (#11996)
  • 修复了独立二进制文件无法解析入口点在 package.json main 或 exports 中声明的扩展 npm 依赖项（例如 shiki、yaml、graceful-fs），包括从其他依赖项内部进行的导入（#12012）
  • 修复了查找工具对于以 ./ 开头的模式不返回结果的问题，例如 ./src/*.ts (#12020)
  • 修复了在打开文件时取消 read 工具调用时 pi 因未捕获的 AbortError 退出的问题 (#11956)
  • 修复了当会话选择器在跳过不是会话的 .jsonl 文件后取消加载时，pi 以未捕获的 AbortError 退出，并修复了此类文件保持打开状态的问题 (#11956)
  • 修复了 GitHub CLI 无法启动时 /share 导致 pi 崩溃的问题
  • 修复了当旧系统 Node.js 在 PATH 上安装程序的独立 Node.js 之前出现时，Windows 托管安装上的 pi update 失败并显示“无法验证托管 Pi”的问题 (#12048)
  • 修复了 /export HTML，显示自定义工具输出中链接周围的原始终端超链接转义代码；链接现在是 clickable (#12003)
  • 修复了当输出以长度超过 100KB 的一行结束时（例如缩小文件中的 grep 匹配），bash 工具不返回任何输出，并带有 [Showing lines 3-2 of 2] 之类的页脚；它现在显示该行的末尾（#12062）
  • 修复了读取“连接已关闭”的提供商错误。不触发自动重试（#12064）
  • 修复了 /resume 有时会在删除或重命名会话后重新加载列表时选择不相关的会话的问题 (#12106)
  • 修复了 Groq Qwen 型号在 400 Unexpected message role 上失败的问题； OpenAI 之外的 OpenAI 兼容提供程序现在使用 system 角色接收系统消息（系统提示和对话中系统消息）（#10741）
  • 修复了 enabledModels/--models 警告，例如在每个 /new、/resume 和 /fork 上的交互式 TUI 上写入 No models match pattern "github-copilot/nope" 警告，这会在全屏模式下留下陈旧的行。现在，警告在启动时、交互模式下的聊天中以及其他模式下的 stderr 上显示一次； RPC 模式不再在每个 new_session、switch_session 或 fork 的 stderr 上重复它们（#11264）
  • 修复了查找工具通过搜索路径上方的文件夹匹配路径模式的问题：对于 ~/src/app 中的项目，src/**/*.ts 返回项目中的每个 .ts 文件 (#12066)
  • 修复了在渲染非常大的编辑差异时，例如在编辑具有多兆字节行的文件之后，以及在该会话的每次恢复时再次出现的 pi 崩溃与 RangeError: Maximum call stack size exceeded (#8036)
  • 修复了在一批工具调用期间按 Esc 键，使尚未开始的调用在会话中没有结果的问题；他们现在得到“操作中止”结果（[#9986]（https://github.com/earendil-works/pi/issues/9986））
  • 修复了在交互式 TUI 上打印 Warning: Could not parse changelog 时不可读的 CHANGELOG.md（pi 自己的或扩展包的）；现在它不显示 changelog 注释 (#11264)
  • 修复了用 /new、/resume、/fork 或 RPC new_session、switch_session 和 fork 替换会话时从未显示的问题，例如，项目扩展在 /resume 后无法加载到另一个项目中，或者 enabledModels 模式在设置更改后不匹配任何内容。交互模式现在在聊天和打印中显示它们，JSON 和 RPC 模式将它们写入 stderr；已报告的问题不再重复。 SDK 主机可以在启动时和每次更换后调用新的 AgentSessionRuntime.takeUnreportedDiagnostics()，以获取每个诊断信息一次
  • 修复了 RPC new_session、switch_session、fork 和 clone 在新会话中运行扩展 session_start 和 resources_discover 处理程序两次。 RPC clients 现在还接收 session_start 处理程序发出的事件，例如它们附加的条目的 entry_appended (#10470)
  • 修复了扩展程序的 pi.events 处理程序在交互式 TUI 上使用 console.error 打印时引发的异常。现在，它像其他扩展错误一样报告：在交互模式下的聊天中，在 RPC 模式下报告为 extension_error，在打印模式下报告为 Extension error (...)。替换会话后失败的处理程序中的错误将被丢弃 (#11264)
  • 修复了当 SDK 主机在已经发出 session_shutdown 后将它们与 bindExtensions({}) 绑定时，AgentSession.reload() 不会向扩展发出 session_start。在 session_start 中开始工作的扩展（例如连接其服务器的 MCP 扩展）在重新加载后保持停止状态
  • 修复了 --mode json 丢弃由扩展 session_start 处理程序发出的事件，例如在启动时和扩展替换会话后附加的条目的 entry_appended
  • 修复了 Could not restore model <provider>/<model>. Using <fallback> 仅在交互式启动时显示的问题。恢复或分叉到模型不再存在或未登录的会话而切换到另一个模型而不另行通知，并且打印、JSON 和 RPC 模式从未显示过。现在在每种模式下、启动时以及 /resume、/fork 和 RPC switch_session 或 fork 之后都会报告
  • 修复了 git 和 npm 输出（例如 Cloning into ... 或 added 12 packages），当 pi 在 /reload、/new、/resume 和 /fork 期间安装或刷新包时，在交互式 TUI 上绘制，包括临时 -e git: 和 -e npm: 包。在交互模式下，它们的输出现在被捕获，并且失败的安装会报告它的结束。在 TUI 启动之前，每个安装都会在 stderr 上宣布为 Installing <source>...，而不是显示 git 和 npm 输出。 git 和 ssh 无法再以交互模式提示：需要输入密码或密码短语的包失败，并提示设置凭据帮助程序或 ssh 代理，或者从 shell 运行一次 pi install <source>。 pi install 和 pi update 保持实时输出 (#11264)
  • 通过在每个轮子事件上重新渲染整个记录，修复了长时间会话中的全屏滚动导致 CPU 核心饱和的问题 (#9549)
  • 修复了 /login、/logout、/scoped-models 和 /resume 中的搜索，在键入之前保持滚动到的行上的突出显示，因此 Enter 选择到达那里的条目而不是最佳匹配；现在，查询会突出显示顶部匹配项，如 /model 所做的那样 (#12245、#12246 by @acmerfight)
  • 修复了现有的 pi、pi config 和 --resume 以及其他启动选择器丢弃仍在标准输出中排队的终端输出，例如关闭鼠标跟踪和 Kitty 键盘报告的重置；然后 shell 可以将鼠标和按键报告打印为文本。 pi 现在在退出或继续之前最多等待一秒等待排队输出 (#12133)
  • 修复了在搜索字段中移动光标的问题，使用 Left、Right、Home 或 End 将突出显示移回 /login、/logout、/model、/scoped-models、/resume、/settings、每个模型设置模型选择器和 pi config 中的第一个条目 (#12245)
  • 修复了 llama.cpp 决策分类器忽略 llama.cpp 报告的图像输入的问题，例如 Clef 及其 mmproj； models.classify() 现在将其图像发送到 /v1/systemone (#12282)
  • 修复了来自外部 pi 的 kill -TSTP 停止它而不恢复终端的问题，这使得鼠标跟踪和 Kitty 键盘协议在 shell 提示符下保持打开状态，并将鼠标移动变成垃圾输入。 pi 现在像使用 Ctrl+Z 一样暂停并在 fg 上重绘（#12283 by @haoqixu）
  • 修复了更改 openai-codex 提供程序的思维水平，使 GPT-6 模型上的提示缓存无效的问题 (#12269)
  • 修复了继承终端前景并在对比工具卡上变得不可读的无范围语法突出显示文本（#11092）
  • 修正了 /copy 说“尚无要复制的代理消息”的问题。在工具调用期间或提供程序错误后按 Esc 键后；它现在复制以前的答案。 RPC get_last_assistant_text 会跳过相同的消息（@acmerfight 的 #12119、#12121）
  • 修复了 pi.exec 报告由信号结束的命令的退出代码 0，例如超时、中止或崩溃；它现在报告 128 + 信号编号，就像 shell 一样（SIGTERM 为 143，SIGKILL 为 137）（#12088、#12089 by @acmerfight）
  • 修复了 GitHub Copilot Gemini 和 Kimi 模型（gemini-4-argon、gemini-4-carbon、gemini-3.8-flash、kimi-k3）忽略思维水平，并且 Copilot 使用始终报告 0 推理标记（@DenielC1 的 #12110）
  • 修复了仅报告节点套接字错误代码的提供程序错误，例如 read ECONNRESET、write EPIPE 或 connect ETIMEDOUT，而不触发自动重试（#12128）
  • 修复了当工具的模式包含没有 type 的节点（例如 items: {} 或 Type.Unknown()）时 OpenAI 拒绝请求并出现 400 错误的问题；此类工具现在以非严格模式发送（#12049）
  • 修复了 Mistral Large 4 工具调用停滞几分钟的问题；除非设置了 compat.supportsStrictMode，否则米斯特拉尔模型不再接收严格的工具（#12148）
  • 修复了非严格的人择工具模式，不告诉模型禁止使用额外的参数（#12067）
  • 修复了响应 API（GPT、Grok、MAI-Code）上的 GitHub Copilot 模型，用空字符串或发明值填充省略的可选工具参数（#12286）
  • 修复了 OpenAI Codex WebSocket 60 分钟连接限制在中途时（例如在长时间思考时）失败的问题；现在在新连接上重试该请求（#12124）
  • 修复了 openai-codex 提供程序在 GPT-6.2 型号上的系统提示几乎没有提示缓存命中的问题 (#12273)
  • 修复了 openai-codex 提供商忽略模型的 maxTokens 的问题
  • 修复了完全重绘（例如调整窗口大小）后全屏 Kitty 图像消失的问题（#12010）
  • 修复了 Markdown 中在图像上绘制的多行内联图像后的文本 (#12017)
  • 修复了覆盖在其上绘制的覆盖层的 Kitty 和 iTerm2 图像 (#11584)
  • 修复了绝对路径 (look at /tmp/fi) 或斜杠命令参数菜单 (/open /tm) 的选项卡路径菜单上的 Enter 提交提示而不是接受完成的问题（#12309、#12312 by @acmerfight）

已删除

  • 从 Qwen 代币计划团队提供商中删除了已退役的 deepseek-v3.2 和 deepseek-v4-flash；使用 deepseek-v4-flash-0731 或 deepseek-v4.1-flash (#11773)
