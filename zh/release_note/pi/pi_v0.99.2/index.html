pi v0.99.2

新功能

  • MCP 服务器不受影响：具有默认 codemode 暴露的服务器不再在 codemode 描述中列出，并且不再阻止第一个提示。它们出现在简短的系统提示部分中，脚本通过 searchTools() 和 describeNamespace() 找到它们的工具。请参见控制工具曝光。
  • 更多 MCP 身份验证选项：oauth.clientName 用于仅接受已知 OAuth ZZPH100​​ZZents 的服务器，"auth": { "provider": "<provider>" } 用于使用提供商的 /login 令牌对 HTTP 服务器进行身份验证。请参阅使用 OAuth 进行身份验证。
  • 来自 Anthropic SDK 环境变量的 Anthropic 工作负载身份联合。请参阅使用环境中的 API 密钥。
  • /reload 启用新添加到 defaultTools 设置的工具。请参见工具。

添加

  • 添加了 MCP 服务器 (pi mcp add --description) 的 description 字段，与系统提示符中的服务器一起显示，用于在工具搜索中对其工具进行排名，以及返回命名空间的指令和工具名称的 describeNamespace(name) 代码模式帮助程序。 describeNamespace() 和 searchTools() 接受 mcp__dev-radius、mcp__dev_radius、dev-radius 或 dev_radius 等命名空间。
  • 为 MCP 服务器 (pi mcp add --oauth-client-name) 添加了 oauth.clientName 设置，以更改 OAuth client 注册期间发送的 client 名称，适用于仅接受已知 clients 的服务器 (#10226)。
  • 为 HTTP MCP 服务器添加了 "auth": { "provider": "<provider>" }，以发送提供商当前的 /login 令牌作为承载令牌，而不是使用 MCP OAuth。每个请求都会读取令牌，因此提供程序刷新适用。仅允许在全局 mcp.json 和扩展中使用，并且需要 https（环回主机除外）。
  • 添加了来自 ANTHROPIC_FEDERATION_RULE_ID、ANTHROPIC_ORGANIZATION_ID 和 ANTHROPIC_IDENTITY_TOKEN_FILE 环境变量的人工工作负载身份联合（请参阅 提供程序）（#10177、#10242，作者：@philfreo）。
  • /reload 现在启用新添加到 defaultTools 设置的工具。从其中删除的工具保持启用状态，会话期间关闭的工具保持关闭状态，除非新添加，并且 --tools、--no-tools 和 --no-builtin-tools 仍会覆盖该设置 (#10245)。

已更改

  • 默认暴露 codemode 的 MCP 服务器不再出现在 codemode 描述中；脚本通过 searchTools() 找到它们。 codemode-deferred 现在是 codemode 的别名。使用 direct 曝光来获取模型无需搜索即可看到的工具 (#10212)。
  • codemode 描述不再包括延迟工具、工具计数或 MCP 服务器指令，因此当 MCP 服务器连接或更改其工具时，它不再更改。出于同样的原因，tool_search 描述不再列出可以加载其工具的服务器。服务器在 mcp_servers 系统提示部分中列出，并带有一行摘要，并在每个提示开始时更新；更改的部分将附加到对话中。脚本使用 describeNamespace() (#10212) 读取服务器指令。
  • 第一个提示不再等待没有 direct 工具的 MCP 服务器。它们在后台连接，并等待代码模式脚本命名它们、脚本搜索工具或 tool_search 运行 (#10212)。

已修复

  • 修复了当新会话属于具有存储凭据的扩展注册本机提供程序时，新会话会间歇性忽略已保存的默认模型，或警告没有可用模型的问题（#9962、#10190 by @davidbrai）。
  • 修复了 /mcp 登录 URL 在换行时无法 clickable 的问题，方法是将其作为带有 Cmd/Ctrl+click to open 行（如 /login）的终端超链接发送（#10186）。
  • 修复了代码模式 image() 接受格式错误的 base64 数据或不受支持的图像类型，这会保留无效的图像块，导致以后的每个提供程序请求都失败并返回 HTTP 400 (#10215)。
  • 修复了 codemode 无法从独立 Windows 可执行文件启动其脚本工作程序的问题 (#10204)。
  • 修复了提示提交会随着会话长度而变慢的问题，因为解析会话的模型选择时，每条助手消息都会查找模型目录一次（#10198）。
  • 修复了具有刷新的 pi.dev 目录的提供者的模型查找速度变慢的问题，因为合并远程目录模型需要花费二次时间。
  • 修复了 built-in-tool-renderer.ts 和 minimal-mode.ts 扩展示例，从系统提示符中删除内置工具的摘要和指南（#10072、#10193 by @christianklotz）。
  • 修复了 Z.AI CN 端点 Prompt exceeds max length 错误的上下文溢出检测 (#10208)。
  • 修复了工具模式使用关键字 Anthropic 严格工具使用拒绝时失败的问题，例如 minimum/maximum；此类工具现在以非严格方式发送（#9953）。
  • 修复了当 Retry-After 标头包含无法解析的日期时提供程序立即重试触发的问题；他们现在使用指数退避（#9571）。
  • 修复了在输入 / 时注册的扩展命令没有字符串名称或处理程序导致 pi 崩溃的问题；扩展现在无法加载并出现错误（#10054）。
  • 修复了当输出为一长行（例如缩小的 JSON）时折叠的 codemode 和 MCP 工具结果填满屏幕的问题。与 bash 输出一样，预览现在仅限于换行而不是逻辑行。
  • 修复了 codemode.mode: "only" 在系统提示的工具列表中列出 read、bash、edit 和 write，尽管请求仅声明 codemode (#10192)。
  • 修复了当两个工具名称仅在 - 和 _ 中不同（例如 read-file 和 read_file）时，代码模式脚本调用错误的 MCP 工具。与 Codex 中一样，MCP 工具和命名空间名称现在用 _ 替换 -（mcp__my-server__x 现在是 mcp__my_server__x），服务器的冲突工具都会获得哈希后缀，仅 - 和 _ 不同的服务器名称将被拒绝（#10239）。
