open-design v0.22.1

修订 发布时间2026年9月9日 来源nexu-io/open-design 英文原文

open-design open-design-v0.22.1

开放式设计 0.22.1 基于 0.22.0 构建，为支持的设计任务提供更简单的启动方式，并在运行出错时提供更清晰的恢复方法。

🔁 已更改

  • 🧭 使用 OD Next 启动支持的设计任务。 原型、幻灯片、营销设计和 Hyperframes 视频默认在支持的代理上使用 OD Next。设置 → 实验室 → 设计线束仍然允许您将其关闭，并且禁用它的现有选择仍然受到尊重。 (#7876)
  • 🧰 保持设计工作的重点。 OD Next 在加载媒体技能时使用更简洁的工具指导、更清晰的完成说明以及主动运行的工作区。 (#7804)

🐛 已修复

💬 对话与恢复

  • 🛟 失败的运行保留了有用的下一步。 失败卡在返回对话时仍然存在，保留超时和重试信息，并在当前聊天无法将运行切换到云时保持重试可用。 （＃7871，＃7884，＃7897）谢谢@lefarcen。
  • 🔑 无效的 API 密钥将为您指明正确的修复方法。 自带密钥身份验证错误有自己的解释和模型设置的快捷方式。 (#7893) 谢谢@lefarcen。
  • 🗺️ 获得有关运行和预览问题的更清晰解释。 有关不可用模型、不支持的功能、超时、缺少预览文件和区域限制的消息提供了更具体的指导。 (#7887) 谢谢@lefarcen。
  • 📝 发送失败时保留您的答案。 如果澄清答案无法启动运行，它会保留在对话中，并通过重试操作重新发送相同的答案。内部路由文本保持隐藏。 (#7900) 谢谢@lefarcen。
  • 📜 随着回复的增长不断关注它。 浏览器滚动调整不再默默地关闭自动关注。向上滚动仍然可以让您阅读较早的消息。 (#7898) 谢谢@lefarcen。

🎨 设计与交付

  • 🎬 失败的媒体工作看起来不再完整。 当图像、视频或音频生成在回合结束之前失败时，回合将显示未完成的工作而不是已完成的复选标记。 (#7933) 谢谢@lefarcen。
  • 💬 问候得到回复。 OD Next 不再为不需要设计的问候或请求发明网站，并且解释的阻止结果避免了重复的失败卡。 (#7725)
  • ✅ 在语法检查尽最大努力的同时保持您的 Web 可交付成果。 合格的 HTML 可交付成果将接受最终语法检查和安全自动修复，无需再次轮流代理。如果检查不完整或安全修复不可用，原始工件仍然可用并继续交付。 （＃7801，＃7925）谢谢@lbjzz-hash。
  • 🧩 继续您刚刚收集的摘要。 官方 Codex 插件在确认摘要时接受摘要收集返回的工作流标识符，同时仍然拒绝不匹配的标识符。 (#7779) 谢谢@taljeon。

🗂️ 工作区和设置

  • 🎯 立即找到您当前的模型。 重新打开模型选择器会将您当前的模型带入视图，包括其在两级 OpenDesign 模型列表中的公司。 (#7917) 谢谢@lefarcen。
  • 📣 公告按钮描述了它们的导向。 新增内容支持与公告目的地相匹配的本地化按钮标签。 (#7943)
  • 🔗 引用您正在使用的工作区中的项目。 项目引用列出了活动工作区的项目，并在您切换工作区时刷新。 (#7701)
  • 🤖 查看本地 CLI 实际使用的模型。 连接测试显示滚动别名背后的已解析模型，使结果更易于检查。 (#6386) 谢谢@MumuTW。
  • 🇫🇷 更一致的法语指导。 设置和恢复消息以及核心文档使用更新的法语措辞。 （＃7753，＃7754）谢谢@davezfr。
  • 🌍 社交链接提示遵循您的语言。 导航工具提示已本地化并支持从右到左的布局。 (#7665)

🖥️ 安装 & Docker

  • 🖼️ 浏览捆绑插件并在 Docker 中预览。 插件海报和悬停 clips 在 Docker 安装中再次可用。 (#7028) 谢谢@jiulongche。
  • 📁 选择下载位置时尊重现有内容。 在决定是否可以采用下载文件夹时，名称类似于系统混乱的目录和符号链接不再被误认为是可忽略的系统文件。 (#7718) 谢谢@mikemikimike。
