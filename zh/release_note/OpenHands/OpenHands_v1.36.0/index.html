OpenHands v1.36.0

这个项目是干啥的：一个让AI替你写和改代码的开发助手，能看懂整个代码仓库、也能在命令行里跑，给想提高效率的程序员用。

变更架构图

亮点

  • 自动化与模板体验 — 本次发布的核心：创建/查看/编辑工作流被统一起来（#19311），系统推荐默认模板、并优先展示使用了已配置集成的模板（#19300），模板打开时不再弹出“缺少集成”提示（#19297）。设置助手现在能感知实例的事件来源（#19335），自动化还可以在 Canvas 中以服务账号身份运行（#19033）。如果你在搭建或管理自动化，这些改动能大幅降低配置摩擦——是实实在在的升级理由。
  • Git 提供商与 Data Center 支持 — 模板设置现在会列出 Bitbucket Data Center 和 Azure DevOps 仓库（#19340）；Data Center 模板随附扩展 0.39.0（#19344），并在 0.40.0 中改用仓库选择器（#19355），@openhands/extensions 升级到 0.41.0（#19393）。模板选中的仓库只会发送给会克隆该提供商代码的服务（#19347），未安装 App 的 GitHub token 可直接列出仓库（#19349），自托管的 GitHub 模板会被引导完成 MCP/token 配置（#19352）。自托管用户和非 GitHub 用户终于获得了原本缺失的可用模板流程。
  • Windows 与 ACP 修复 — Windows 本地后端现在能正确列出工作区文件（#17784），Planner 的工作区路径在 Windows 上也得到正确处理（#18070）。Chat/ACP 方面的修复包括：新连接后 ACP 回合运行时 Stop 按钮保持可见（#19316），本地后端上选择 ACP 时不再写入 agent 设置（#19284），以及历史记录以 hook 事件结尾时不再弹出错误提示（OHE-3909、#19351）。如果你在本地跑 Windows 或使用 ACP agent，值得升级；否则这些属于小众改动。
  • 运行时与依赖升级 — CI、桌面安装包和 Docker 统一迁移到 Node 24.22.1（#19321）；agent-server 升级到 1.60.1（#19388），同时更新了 axios 1.18.0→1.21.0（#19308）、zustand 5.0.14→5.0.16（#19342）、monaco-editor 0.56.0→0.57.0（#17977），以及 react-router/tanstack/eslint/testing 等依赖组。没有明确列出破坏性 API 变更，但 Node 24 基线对自托管用户以及锁定桌面/运行时环境的团队来说是需要规划的迁移点。
  • 升级结论与 macOS 提示 — 如果你使用自动化/模板（尤其是 Data Center、Bitbucket、Azure DevOps 或自托管 GitHub）、Windows 本地后端或 ACP 会话，建议升级；其余用户基本可以跳过，剩余内容多为文档和维护。macOS 用户注意：应用仍未签名，Gatekeeper 可能报“已损坏”——把应用移入“应用程序”后，执行一次 xattr -dr com.apple.quarantine "/Applications/OpenHands Agent Canvas.app" 清除隔离属性即可（签名/公证进度见 #16774）；这只是安装上的坑，不是下载损坏。

macOS 安装说明

该应用程序尚未使用 Apple Developer ID 进行签名，因此 macOS 可能会调用 下载的版本 “已损坏” — 这是 Gatekeeper 隔离区，而不是坏文件。 将应用程序移动到应用程序后，清除一次标志，然后正常打开：

xattr -dr com.apple.quarantine "/Applications/OpenHands Agent Canvas.app"

签名+公证在 OpenHands/OpenHands#16774 中进行跟踪。
