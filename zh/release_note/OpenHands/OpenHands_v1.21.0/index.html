OpenHands v1.21.0

这个项目是干啥的：一个让AI替你写和改代码的开发助手，能看懂整个代码仓库、也能在命令行里跑，给想提高效率的程序员用。

变更架构图

亮点

  • Docker workspace 选择 — Canvas 从 /server_info 读取 execution_runtime，并在服务端声明时请求 DockerExecutionWorkspace，而非默认用 LocalWorkspace；本地和旧版服务端保留回退。临时 Docker workspace 会跳过宿主机 worktree 设置，因此不要以为它们会执行宿主机侧的 checkout 准备（#17177）。
  • Docker 宿主机访问与迁移 — 宿主机服务通过 host.docker.internal 暴露，Automation 改为经 Canvas ingress 路由，而非其仅限 loopback 的后端（#17518）。既有没有 Docker 配置元数据的本地对话仍可通过 REST 读取，但显示为已归档且不再尝试 WebSocket 连接；切换运行时时应将其视为只读历史（#17500）。
  • 对话历史隔离 — 迟到的旧事件（events/search）响应不再会在导航后混入另一个对话。按加载次数做归属检查也保护了加载状态、分页、模型切换和滚动恢复，堵住了慢速网络下可能混合历史的竞态（#16913）。
  • Git provider 集成 — “添加 App”现在将来自 GitHub、GitLab、Bitbucket 和 Gitea/Forgejo 的浏览器文件夹 URL 拆分为仓库来源、ref 和路径（#17504）。显式填写的 Ref/Path 字段仍优先，但含斜杠的 ref 仍有歧义，需要手动输入。Forgejo 的 PR/issue 列表现在使用所配置宿主机的 /api/v1 API 和 token 认证，避免错误地请求 GitHub 或拿到同名 GitHub 仓库的结果（#17486）。
  • 重建与埋点行为 — 静态服务器现在在 Canvas 重建后解析当前文件，因此已移除的带哈希资源返回 404 而非终止服务器，新替换的资源得以提供（#17402）。PostHog autocapture 已禁用：原始 $autocapture 点击/变更/提交事件流停止，而显式类型的 trackEvent/useTracking 事件与同意控制保持不变（#17502）。
  • 破坏性变更 — v1.21.0 未列出。
