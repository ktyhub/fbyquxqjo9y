OpenHands v1.17.0

OpenHands v1.17.0

变更流程图

亮点

  • Node 24 成为 Agent Canvas 的最低要求 — PR #17009 要求 canvas 运行时使用 Node 24。这是真正会让人踩坑的升级：自托管者和任何构建 canvas 的人都必须把工具链迁到 Node 24，否则构建直接失败。应把它当作第一步迁移，而非可选升级。

  • “Canvas Extensions”改名为“Apps” — PR #17064 在代码库中全面重命名该概念。若你用脚本操作或在配置、文档、自动化清单中引用“extensions”，这次改名不只是表面功夫——升级后请审查这些引用。两项配套修复对安装自定义 App 的人很重要：PR #17072 正确拼接本地扩展来源和路径，PR #17120 终于把安装失败原因显示出来，而不是静默报错。

  • Automation 权限拆分为查看与管理 — PR #17105 将原来单一的 automation 权限拆分为独立的查看和管理范围，并为创建者保留例外。这是访问控制行为变更：请审查现有角色分配，因为此前能管理 automation 的用户现在可能只能查看，除非他们是创建者。

  • 安全：DOMPurify 净化绕过已修补 — PR #17060 修复了 DOMPurify 中的净化绕过。若 canvas 渲染任何不可信 HTML，这是应尽快采用该版本的最强理由——这是纵深防御修复，不应拖后。同时 PR #16908 为自托管 canvas 新增 --disable-telemetry 运行时 flag，对注重隐私或气隙部署、此前没有干净退出方式的用户很重要。

  • 全栈组件默认值提升 — agent-server 到 1.45.0、automation 到 1.11.1、SDK 到 1.46.0（PR #17238、#17203、#17086、#16970），automation SDK 版本查找重构为 React Query（#16982）。全新部署会自动采用这些版本，但若你显式固定组件版本，就需要手动推进以避免版本错位 bug。

  • 新增能力与需留意的行为变化 — 本地 Agent Canvas Planner 支持（#16178）、通用自定义 automation 清单（#17129）、云端 LLM provider 连接（#16757），以及现在能感知任务结果的 automation 运行（#16937），扩展了你能构建的东西。行为上，workspace hook 现在在对话开始时自动加载（#16971），插件查询限定到当前后端（#16891），订阅制 LLM 配置保留其 base_url（#16089）——后两项是静默修复，可能改变你的请求实际打到哪个后端或端点。
