OpenHands v1.29.0

这个项目是干啥的：一个让AI替你写和改代码的开发助手，能看懂整个代码仓库、也能在命令行里跑，给想提高效率的程序员用。

变更架构图

亮点

  • Profile 现在拥有自己的配置 — PR #18679、#18685、#18686 和 #18720 把 condenser/验证设置、Model Router 选择和技能选择移入 profile 本身，default 现在按 id 启动。如果你的工作流假定有一套全局配置到处生效，升级后请重新审计每个 profile：你从未显式设置过的配置项现在来自 profile，而不是继承全局默认值，因此长期存在的 profile 会出现行为漂移。另请注意，prompt 和 plugin 预设不再提供 agent-profile 选择器（#18708）。
  • 技能成为服务端目录能力 — 启动器从捆绑的 @openhands/extensions 包读取公共技能（#18683，在 #18730 中升级到 0.32.0），profile 从服务端目录选择技能（#18686）。这让技能变得可版本化、可发现，而不再纯粹是本地配置——很利于可复现性，但意味着你实际生效的技能集现在取决于扩展包，所以在克隆环境或复现 bug 时要固定/核对该版本。
  • npm 嵌入者获得作用域样式表 — #18663 随库发布了一份带作用域的样式表。如果你此前为了渲染 UI 而导入全局 CSS，请改用捆绑样式：这是让 OpenHands 的规则不泄漏到宿主应用（也防止宿主样式破坏组件）的受支持方式。
  • Python 3.15 目前明确不支持 — #18731 把 uvx 固定到 Python 3.12–3.14，直到依赖方发布 3.15 的 wheel。默认使用 3.15 的 CI 镜像或本地 shell 会遇到依赖解析失败；请显式固定解释器，而不是把它当作需要上报的回归。
  • Cloud 会话丢失更少状态，聊天更跟手 — 已连接的仓库现在会持久化到云端会话（#18158），当历史页面滞后于运行时时，第一条 Cloud 消息得以保留（#18719），模型追赶从十秒缩短到一秒（#18651）。对云端托管用户，这直接减少“我的上下文没了 / UI 落后于 agent”的困惑时刻，并提升感知响应速度。
  • macOS 安装仍会遇到 Gatekeeper — 构建尚未做 Apple 签名或公证（在 #16774 跟进），所以新下载可能被标记为“已损坏”；CI 现在在发布页展示解除隔离的变通办法（#18723）。请把清除 com.apple.quarantine 写成脚本（在把应用移入“应用程序”后执行），否则每台新机器都会遭遇误报的恶意软件警报。

本次发布无破坏性变更。

macOS 安装说明

该应用程序尚未使用 Apple Developer ID 进行签名，因此 macOS 可能会调用 下载的版本 “已损坏” — 这是 Gatekeeper 隔离区，而不是坏文件。 将应用程序移动到应用程序后，清除一次标志，然后正常打开：

xattr -dr com.apple.quarantine "/Applications/OpenHands Agent Canvas.app"

签名+公证在 OpenHands/OpenHands#16774 中进行跟踪。
