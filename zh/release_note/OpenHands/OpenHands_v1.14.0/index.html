OpenHands v1.14.0

小版本 发布时间2026年8月17日 来源OpenHands/OpenHands 英文原文

变更流程图

亮点

  • LLM profile 的预检校验 — v1.14.0 在保存时拒绝配置错误的模型 profile（#16417），因此”保存了却悄悄失效”的 Agent 配置应该会大幅减少。注意：过去依赖不完整或隐式凭据的现有配置，现在可能需要先明确修正才能真正保存下来。
  • 结构化的 Canvas 错误结果 — Canvas 失败现在以结构化结果呈现（#16231），而不是含糊的错误。下游自动化和自定义 UI 可以按失败类型分支，而不必解析消息字符串——值得回头检查 v1.13 时代那些解析自由文本的错误处理。
  • 自动化 Git Sync — 专门的 Git Sync 页面（#16521）为自动化提供了一等公民的版本管理与仓库同步路径，取代了此前 config-as-code 工作流所需的手工粘合代码。
  • Canvas 默认模型切换为 Kimi K3 — 默认值现为 Kimi K3，并标记为 free（#16657）。任何依赖此前隐式默认值的用户都会悄悄得到不同的输出和延迟；如果这很重要，请显式固定模型，并注意 “free” 标签会改变该模型在配额/计费中的呈现方式。
  • 对自托管用户很重要的后端 URL 与链接修复 — 开发构建不再把绝对的 VITE_BACKEND_BASE_URL 烘焙进 npm run dev（#16605），会话链接在多后端配置中保留后端作用域（#16091），本地 responder URL 现在从浏览器 origin 推导（#16332）。这些改动消除了常见的 localhost/代理故障——在自定义 origin 后面部署时，这是有实际意义的升级。
  • Cloud 文件浏览与贡献者引导 — Files 标签页现在在云端后端显示完整的工作区树（#16344），新增的仓库地图（#16612）说明代码应该放在哪里，便于浏览和向 agents 包贡献代码。

本版本无破坏性变更。
