OpenHands v1.10.0

OpenHands v1.10.0

这个项目是干啥的：一个让AI替你写和改代码的开发助手，能看懂整个代码仓库、也能在命令行里跑，给想提高效率的程序员用。

变更架构图

亮点

  • 自动化成为一等的数据驱动界面 — PR #16303 为自动化界面增加了清单驱动的子页面，PR #16266 上线了精选自动化落地仪表盘，把自动化 UI 从硬编码页面转向清单定义的页面。PR #16233 让自动化超时上限从部署配置推导，而非固定值；捆绑组件跃升到 agent-server 1.40.1 / automation 1.6.0（#16334）和 @openhands/extensions 0.16.0（#16321）。搭建或配置自动化的团队在这里收益最大。

  • Canvas 默认模型切换为 GLM 5.2 — PR #16146 把 Canvas 默认模型改为 GLM 5.2；除非你显式覆盖模型，新会话都会使用它。这不算硬性破坏性变更，但如果你依赖旧的默认值，这是值得验证的行为变化。PR #16144 还修复了 Canvas 变更期间 MCP 凭据被丢弃的问题——如果你把带认证的 MCP server 接到 Canvas，这点很相关。

  • 安全与多后端可靠性修复 — PR #16264 解决了 npm audit 漏洞；PR #16290 把本地代理目标切到 IPv4 回环地址（修复 IPv6 优先/本地环境中的代理失败）；PR #16243 在侧边栏会话链接上固定后端身份（修复多后端部署中链接解析到错误后端的问题）。PR #16234 增加了活动日志导出，便于审计和事故复盘。

  • 无破坏性变更或迁移步骤 — 这里没有任何东西需要数据迁移或配置重写；改动都是增量特性和修复，加上常规依赖升级（react、tanstack、tailwind、monaco-editor 0.56.0、i18next、testing/typing 组）。CI 现在要求前端截图/视频和一个勾选的人工测试框（#16325），这只是贡献者流程的变化，与运行时无关。

  • 升级建议 — 如果你使用自动化界面、Canvas（尤其是带 MCP server）、本地代理目标、多后端部署，或想要 npm audit 修复，就值得升级。如果你在 v1.9.0 且以上都不适用，暂时可以跳过——这是一次功能与加固发布，不是紧急补丁。
