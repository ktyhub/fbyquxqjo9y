AionUi v2.1.47-final

修订 发布时间2026年8月5日 来源iOfficeAI/AionUi 英文原文

这是通过 GitHub 发行版分发的最终 AionUi 版本。 从现在开始，安装程序和更新来自官方网站。请参阅底部的关于分发的说明，了解这对您、您的数据和开源存储库意味着什么。

变更流程图

亮点

应用内浏览器，由代理控制

  • 网页现在在预览面板中作为选项卡打开，您可以与代理共享一个持久会话 - 手动登录一次，代理就会将该会话带入下一步执行的任何操作。
  • 代理通过新的内置 MCP 服务器 (aionui-browser) 到达浏览器，因此它可以自行导航、click 并提取数据。
  • 关于安全性：让代理驱动 Chromium 的明显方法是 --remote-debugging-port，但该开关是应用程序范围内的，没有针对每个目标的 ACL - 它会将每个 WebContents（包括主窗口及其预加载桥）暴露给任何本地进程，而无需进行身份验证。相反，它提供了一个仅公开浏览器视图的单目标 CDP 桥。没有向配置或数据库写入任何内容；桥的端口和访问令牌沿着进程继承链向下移动，因此多个应用程序实例永远不会交叉连线。

对话分叉

  • 消息悬停行上的分支箭头将该消息中的对话分叉为新对话，并将您带入其中 - 对于在不干扰原始路径的情况下探索不同的路径很有用。
  • 条目出现的位置遵循后端实际可以执行的操作：Codex 可以随时分叉，Claude 和 ACP 代理仅在最新消息上分叉（因此复制的历史记录与分叉会话真正记住的内容相匹配），而没有分叉表面的代理根本不显示条目。

代理驱动的对话命名

  • 支持它的代理现在会自动提出对话标题。您自己设置的名称永远不会被覆盖 - 只有默认名称和派生名称仍然可以替换。

修复和改进

  • v2.1.46 中引入的消息锚轨现在可以清除消息文本并覆盖完整的对话历史记录。
  • 数据库重建在第二次确认后进行，因此错误click 无法擦除您的本地数据。
  • GPU 进程崩溃噪音被抑制，应用程序现在会告诉您何时自动禁用硬件加速。潜在的崩溃来自于使用非常旧的驱动程序的报废 GPU，而不是代码回归，而误导性的崩溃报告使得这一点很难被察觉。
  • 工作区切换保留在其所属的标题栏中。
  • 团队运行状态处理省略的插槽工作，而不是被它迷惑。
  • 预览文件 I/O 迁移到 ChatFileRef /content 端点； PDF 现在通过流 URL 加载，Office 文件通过 ChatFileRef 解析。

引擎更新（AionCore v0.1.57 → v0.1.58）

  • 对话分叉和代理驱动的会话命名在这里端到端支持——上述两个功能的后端部分。
  • 克劳德会话成本现在在进程重生时保持累积而不是重置。
  • 进度卡通过会话拆卸和恢复正确解决。以前，如果空闲收割机在运行中删除任务，而底层工作仍在运行，则存储的行将保持 running — 使“查看步骤”旋转器在已成功的任务上转动几个小时。
  • 恢复对话保留思想水平选择器。
  • 托管节点版本探测现在会重试暂时性故障，而不是在第一次失败时放弃。

关于分发的说明

AionUi 及其商业版本共享一个包名称，但使用不同的签名，并且操作系统拒绝跨签名覆盖安装。应用内更新根本无法帮助您完成任务，因此此版本以“停止模式”发布：启动自动检查被静音，手动更新检查会打开一封指向官方网站的迁移信。 当你搬过来时：

  • 您的对话和文件保留在本地。 代理在您自己的计算机上运行；内容永远不会上传到我们的服务器。
  • 您的本地数据按原样保留。 首次登录后，新版本会继承您现有的对话、设置和 API 密钥 - 无需重新配置。这是一次性迁移：完成后，新版本将拥有该数据，并且此构建不再是其入口点。
  • 没有附加付费专区。 但是，您现在使用它，您将继续使用它；今天免费的东西仍然免费。
  • **开源存储库不断更新。**核心功能保持同步，开源精神不会改变。 新版本需要登录（今天谷歌，更多方法正在开发中）。这一变化背后的原因是相同的：一旦安装人员退出，我们就无法再次联系到它，因此修复永远不会到来，新技能和助手也无法同步——而你们中的许多人所要求的东西，比如多个帐户、数据同步和更安全的移动协作，都需要一个适当的底层服务。 **下一步，仍然是开源的：**团队板（多代理协作的全局视图）、对话存档、跨设备数据同步以及更广泛的组织协作。 这仍然是您的选择。 如果 AionUi 是您日常工作流程的一部分，我们建议迁移到新版本 - 新功能首先出现。如果您更喜欢本地 DIY，请继续拉取此存储库并自行构建。如果您还不想升级，这个版本仍然可以工作；它只是不会收到更新。 感谢您使用 AionUi 走到这一步。
