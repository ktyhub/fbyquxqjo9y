druid 0.14.0-incubating

小版本 发布时间2019年4月9日 来源apache/druid 英文原文

druid druid-0.14.0-incubating

Apache Druid（孵化中）0.14.0-incubating 包含 200 多个新功能、性能/稳定性/文档改进以及来自 54 个贡献者的错误修复。主要新功能和改进包括：

  • 新的网络控制台
  • Amazon Kinesis 索引服务
  • 历史的退役模式
  • 在 Broker 中发布段缓存
  • 布隆过滤器聚合器和表达式
  • 更新了 Apache Parquet 扩展
  • 嵌套 GroupBy 查询的强制下推选项
  • 更好的分段切换和丢弃规则处理
  • 当 Apache Hadoop 摄取任务被终止时自动终止 MapReduce 作业
  • DogStatsD 标签支持 statsd 发射器
  • 新的 API 用于检索所有查找规范
  • 新的压缩选项
  • 更高效的缓存成本段平衡策略 完整的更改列表在这里：https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Amerged+milestone%3A0.14.0 此版本的文档位于：http://druid.io/docs/0.14.0-incubating/

亮点

新的网络控制台

Druid 有一个新的 Web 控制台，提供了之前在协调器和霸主控制台之间划分的功能。 新的控制台允许用户管理数据源、段、任务、数据进程（Historicals 和 MiddleManagers）和协调器动态配置。用户还可以在控制台中运行 SQL 和本机 Druid 查询。 更多详情请参见http://druid.io/docs/0.14.0-incubating/operations/management-uis.html 由 @vogievetsky 在 #6923 中添加。

Kinesis 索引服务

Druid 现在支持从 Kinesis 流摄取，由新的 druid-kinesis-indexing-service 核心扩展提供。 详情请参见http://druid.io/docs/0.14.0-incubating/development/extensions-core/kinesis-ingestion.html。 由 @jsun98 在 #6431 中添加。

历史的退役模式

历史进程现在可以进入“退役”模式，协调器将不再将历史进程视为段复制的目标。协调员还将把部分内容从退役历史中移走。 这是通过协调器动态配置来控制的。更多详情请参见http://druid.io/docs/0.14.0-incubating/configuration/index.html#dynamic-configuration. 由 @egor-ryashin 在 #6349 中添加。

在 Broker 上发布的段缓存

Druid Broker 现在能够通过轮询协调器来维护已发布段的缓存，这可以显着提高 sys.segments 系统表上元数据查询的响应时间。 详情请参见http://druid.io/docs/0.14.0-incubating/querying/sql.html#retrieving-metadata。 由 @surekhasaharan 添加于 #6901

布隆过滤器聚合器和表达式

druid-bloom-filter 扩展中添加了一个新的聚合器，用于在查询时构建 Bloom 过滤器，并支持在 Druid 表达式中执行 Bloom 过滤器检查。 请参阅http://druid.io/docs/0.14.0-incubating/development/extensions-core/bloom-filter.html 由 @clintropolis 添加于 #6904 和 #6397

更新了 Parquet 扩展

druid-extensions-parquet 已从 contrib 扩展移至核心扩展集，现在支持扁平化和 int96 值。 详情请参见http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html。 由 @clintropolis 添加于 #6360

嵌套 GroupBy 查询的强制下推选项

嵌套 GroupBy 查询的外部查询执行现在可以下推到历史进程；以前，外部查询总是在 Broker 上执行。 详情请参见https://github.com/apache/incubator-druid/pull/5471。 由 @samarthjain 在 #5471 中添加。

更好的段切换和保留规则处理

分段切换现在将忽略数据源保留规则删除的分段，从而避免问题 #5868 导致的摄取失败。 期间负载规则现在默认包括未来。 添加了新的“期间删除之前”规则。详情请参见http://druid.io/docs/0.14.0-incubating/operations/rule-configuration.html#period-drop-before-rule。 由@QiuMM 在#6676、#6414 和#6415 中添加。

当 Hadoop 摄取任务被终止时自动终止 MapReduce 作业

当摄取任务被终止时，Druid 现在将自动终止由 Hadoop 批量摄取任务创建的 MapReduce 作业。 由 @ankit0811 在 #6828 中添加。

DogStatsD 标签支持 statsd-emitter

statsd-emitter 扩展现在支持 DogStatsD 样式标签。请参见http://druid.io/docs/0.14.0-incubating/development/extensions-contrib/statsd.html 由 @deiwin 在 #6605 中添加，并支持 @glasser 在 #6791 中添加的常量标签。

新的 API 用于检索所有查找规范

添加了一个新的 API，用于检索所有层的所有查找规范。详情请参见http://druid.io/docs/0.14.0-incubating/querying/lookups.html#get-all-lookups。 由 @jihoonson 在 #7025 中添加。

新的压缩选项

自动压缩现在支持 maxRowsPerSegment 选项。详情请参见http://druid.io/docs/0.14.0-incubating/design/coordinator.html#compacting-segments。 压缩任务现在支持新的 segmentGranularity 选项，弃用了用于控制压缩段的段粒度的旧 keepSegmentGranularity 选项。有关这些属性的更多信息，请参阅 http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html 中的 segmentGranularity 表。 由@jihoonson 在#6758 和#6780 中添加。

更高效的缓存成本段平衡策略

cachingCost 协调器段平衡策略现在将仅考虑平衡决策的历史流程。以前，该策略也不必要地考虑活动工作任务，这些任务不是段复制的目标。 由 @QiuMM 在 #6879 中添加。

新指标：

  • 新的分配率指标 jvm/heapAlloc/bytes，由 @egor-ryashin 在 #6710 中添加。
  • 新的查询计数指标 query/count，由 @QiuMM 在 #6473 中添加。
  • SQL 查询指标 sqlQuery/bytes 和 sqlQuery/time，由 @gaodayue 在 #6302 中添加。
  • Apache Kafka 摄取滞后指标 ingest/kafka/maxLag 和 ingest/kafka/avgLag，由 @QiuMM 在 #6587 中添加
  • 任务计数指标 task/success/count、task/failed/count、task/running/count、task/pending/count、task/waiting/count，由 @QiuMM 在 #6657 中添加

自定义 TLS 证书检查

Kafka 索引服务不再是实验性的

Kafka 索引服务扩展已退出实验状态。

SQL 增强

dsql 增强

dsql 命令行 client 现在支持 CLI 历史记录、基本自动完成以及在查询上下文中指定查询超时。 由 @gianm 在 #6929 中添加。

添加 SQL id、请求日志和指标

SQL 查询现在具有 ID，并且作为 SQL 查询的一部分执行的本机查询将在本机查询的请求日志中具有关联的 SQL 查询 ID。 SQL 查询现在将记录在请求日志中。 现在为 SQL 查询发出两个新指标 sqlQuery/time 和 sqlQuery/bytes。 详情请参见http://druid.io/docs/0.14.0-incubating/configuration/index.html#request-logging和http://druid.io/docs/0.14.0-incubating/querying/sql.html#sql-metrics。 由 @gaodayue 添加于 #6302

  • DataSketches Theta 草图
  • DataSketches 分位数草图
  • 修复了 bin 直方图
  • 布隆过滤器聚合器 由@jon-wei 在#6951 和@clintropolis 在#6502 添加

其他 SQL 增强功能

  • SQL：支持选择多值维度。第6462章

  • SQL：添加“POSITION”功能。第6596章

  • SQL：修复 DruidSemiJoin 中的排序、sortProject 排序。第6769章 由@gianm 添加。

从 0.13.0-incubating 及更早版本更新

升级时 Kafka 摄取停机时间

由于 #6958 中描述的问题，现有的 Kafka 索引任务可能会在 Overlord 滚动升级期间不必要地终止。终止的任务将由 Overlord 重新启动，并在初次重新启动后正常运行。

Parquet 扩展更改

druid-parquet-extensions 扩展已从 contrib 移至 core。部署 0.14.0-incubating 时，请确保您的 extensions-contrib 目录没有任何旧版本的 Parquet 扩展。 此外，扩展中现在有两种样式的 Parquet 解析器：

  • parquet-avro：将 Parquet 转换为 Avro，然后解析 Avro 表示形式。这是 0.14.0-incubating 之前的现有解析器。
  • parquet：一个新的解析器，直接解析Parquet格式。只有这个新的解析器支持 int96 值。 在 0.14.0-incubating 之前，指定 parquet 类型解析器将有一个使用 Avro 转换解析器的任务。在 ZZPH100​​ZZ 中，要继续使用 Avro 转换解析器，您需要更新摄取规范以使用 parquet-avro。 对于使用 Parquet 输入的任务，inputSpec 中的 inputFormat 字段还必须与解析器的选择相匹配：
  • parquet: org.apache.druid.data.input.parquet.DruidParquetInputFormat
  • parquet-avro: org.apache.druid.data.input.parquet.DruidParquetInputFormat 详情请参见http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html。

使用非 2.8.3 Hadoop 运行 Druid

如果您计划将 Druid 0.14.0-incubating 与 2.8.3 以外的 Hadoop 版本一起使用，您可能需要执行以下操作：

  • 将 Hadoop 依赖项坐标设置为您的目标版本，如 Tip #3: Use specific versions of Hadoop libraries 下的 http://druid.io/docs/0.14.0-incubating/operations/other-hadoop.html 中所述。
  • 通过更改主 Druid pom.xml 中的 hadoop.compile.version，然后按照标准构建说明，使用 Hadoop 的目标版本重建 Druid。

其他行为改变

旧任务清理

元数据存储中的旧任务条目现在将与其任务日志一起自动清除。有关详细信息，请参阅 http://druid.io/docs/0.14.0-incubating/development/extensions-core/configuration/index.html#task-logging 和 #6592。

自动处理缓冲区大小

如果未设置，druid.processing.buffer.sizeBytes 属性将具有新的默认行为。 Druid 现在将使用以下公式自动选择处理缓冲区大小的值：

processingBufferSize = totalDirectMemory / (numMergeBuffers + numProcessingThreads + 1)
processingBufferSize = min(processingBufferSize, 1GB)

其中：

  • TotalDirectMemory：-XX:MaxDirectMemorySize 指定的 JVM 的直接内存限制
  • numMergeBuffers：druid.processing.numMergeBuffers 的值。
  • numProcessingThreads：druid.processing.numThreads 的值。 Druid 最多将使用 1GB 作为自动选择的处理缓冲区大小。处理缓冲区大小仍然可以手动指定。 详情请参阅#6588。

保留规则现在默认包括未来

请注意，新的保留规则现在将默认包含未来。详情请参阅#6414。

属性变化

片段公布

用于在 Zookeeper 或基于 HTTP 的段管理/发现之间进行选择的 druid.announcer.type 属性已移至 druid.serverview.type。如果您在 0.14.0-incubating 之前使用过 http，则需要更新配置才能使用新的 druid.serverview.type。 详情请参阅以下内容：

  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-management
  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-discovery

修复 SegmentWriteOutMediumFactory 的 JsonTypeInfo 中缺少的属性

druid.peon.defaultSegmentWriteOutMediumFactory.@type 属性已修复。该属性现在为 druid.peon.defaultSegmentWriteOutMediumFactory.type，没有“@”。 详情请参阅#6656。

弃用

近似直方图聚合器

ApproximateHistogram 聚合器已被弃用；它是一种依赖于分布的算法，没有正式的误差界限，并且存在严重的准确性问题。 DataSketches 分位数 聚合器应该用于分位数和直方图用例。 请参阅直方图和分位数聚合器

基数/HyperUnique 聚合器

Cardinality 和 HyperUnique 聚合器已被弃用，取而代之的是 DataSketches HLL 聚合器和 Theta Sketch 聚合器。这些聚合器具有更好的准确性和性能特征。 有关详细信息，请参阅计数不同聚合器。

查询块周期

chunkPeriod 查询上下文配置以及关联的 query/intervalChunk/time 指标现已弃用。详情请参阅#6591。

keepSegmentGranularity 用于压实

用于压缩任务的 keepSegmentGranularity 选项已被弃用。有关这些属性的更多信息，请参阅 #6758 和 http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html 中的 segmentGranularity 表。

扩展开发人员的界面更改

SegmentId 级

Druid 现在使用 SegmentId 类而不是普通字符串来表示段 ID。详情请参阅#6370。 由@leventov 添加。

druid-api、druid-common、java-util 移至 druid-core

druid-api、druid-common、java-util 模块已移至 druid-core。如果您的项目依赖于这些库，请相应地更新您的依赖项。 详情请参阅#6443。
