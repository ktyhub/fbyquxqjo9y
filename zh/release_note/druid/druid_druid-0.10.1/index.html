druid 0.10.1

修订 发布时间2017年8月23日 来源apache/druid 英文原文

Druid 0.10.1 包含来自 40 多个贡献者的数百项性能改进、稳定性改进和错误修复。主要新功能包括：

  • TopN 查询的大幅性能改进和附加查询指标
  • 能够下推 GroupBy 查询的限制子句
  • 更准确的查询超时处理
  • 对 Amazon S3A 文件系统的 Hadoop 索引支持
  • 支持摄取 Protobuf 数据
  • 可以通过 HTTP 读取输入的新 Firehose
  • 改进了从云存储建立索引时的磁盘空间管理
  • 对协调器查找管理的各种改进
  • 一个新的 Kafka 指标发射器
  • 新的维度比较过滤器
  • Druid SQL 的各种改进 如果您要从 Druid 的早期版本升级，请参阅下面的“从 0.10.0 及更早版本更新”以获取升级说明，包括一些向后不兼容的更改。 完整的更改列表在这里：https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.10.1 此版本的文档位于：http://druid.io/docs/0.10.1/

亮点

TopN 性能改进

现在，历史节点上使用 1-2 个聚合器处理 TopN 查询的速度提高了 2-4 倍。这是通过新的运行时检查逻辑来完成的，该逻辑生成查询处理类的单态实现，从而减少 TopN 查询执行路径中的多态性。 添加了 @leventov 此处描述的一系列 PR：https://github.com/druid-io/druid/issues/3798.

GroupBy 的限制子句下推

Druid 现在可以通过将限制应用程序分发到历史/实时节点来优化 GroupBy 查询中的限制子句，在将部分结果集发送到代理进行合并之前将限制应用到部分结果集。这减少了集群内的网络流量并减少了代理节点上的合并工作负载。更多信息请参阅http://druid.io/docs/0.10.1/querying/groupbyquery.html#query-context。 由 @jon-wei 添加到 https://github.com/druid-io/druid/pull/3873 中。

Amazon S3A 的 Hadoop 索引支持

Amazon 的 S3A 文件系统现在支持深度存储并作为批量摄取任务的输入源。请参阅<>文档。 由 @b-slim 添加到 https://github.com/druid-io/druid/pull/4116 中。

Protobuf 3.0 支持和其他增强功能

添加了对摄取 Protobuf 3.0 数据的支持，以及其他增强功能，例如从 URL 读取 Protobuf 描述符。支持 Protobuf 的代码也已移至其自己的核心扩展中。有关文档，请参阅 http://druid.io/docs/0.10.1/development/extensions-core/protobuf.html。 由 @knoguchi 添加到 https://github.com/druid-io/druid/pull/4039 中。

HTTP 消防水带

添加了用于实时摄取的新 Firehose，可通过 HTTP 从 URL 列表读取数据。请参阅 http://druid.io/docs/latest/ingestion/firehose.html#httpfirehose 文档。 由 @jihoonson 添加到 https://github.com/druid-io/druid/pull/4297 中。

改进了云存储实时索引的磁盘空间管理

Microsoft Azure、Rackspace Cloud Files、Google Cloud Storage 和 Amazon S3 的 Firehose 实现现在支持数据缓存和预取。这些 Firehose 现在可以对部分输入数据进行操作并根据需要提取新数据，而不必将 Firehose 的输入完全读取到磁盘。 请参阅以下链接获取文档： http://druid.io/docs/0.10.1/development/extensions-contrib/azure.html http://druid.io/docs/0.10.1/development/extensions-contrib/cloudfiles.html http://druid.io/docs/0.10.1/development/extensions-contrib/google.html http://druid.io/docs/0.10.1/development/extensions-core/s3.html 由 @jihoonson 添加到 https://github.com/druid-io/druid/pull/4193 中。

协调器查找管理的改进

对查询时查找的状态管理/同步逻辑进行了多项增强，包括查找规范的版本控制。请参阅 http://druid.io/docs/0.10.1/querying/lookups.html 文档。 由 @himanshug 添加到 https://github.com/druid-io/druid/pull/3855 中。

Kafka 指标发射器

添加了一个新的指标发射器，以 JSON 格式将指标数据发送到 Kafka。参见http://druid.io/docs/0.10.1/development/extensions-contrib/kafka-emitter.html 由 @dkhwangbo 添加到 https://github.com/druid-io/druid/pull/3860 中。

列比较过滤器

添加了新的列比较过滤器。此过滤器允许用户比较行内跨列的值，就像 SQL 中的“WHERE columnA = columnB”子句一样。有关文档，请参阅 http://druid.io/docs/0.10.1/querying/filters.html#column-comparison-filter。 由 @erikdubbelboer 添加到 https://github.com/druid-io/druid/pull/3928 中。

Druid SQL 改进

Druid 0.10.1 对 Druid SQL 进行了许多增强，例如对查找的支持（@gianm 的 PR）： https://github.com/druid-io/druid/pull/4368 - 更宽容的 Avatica 服务器 https://github.com/druid-io/druid/pull/4109 - 支持另一种形式的过滤聚合器 https://github.com/druid-io/druid/pull/4085 - 折叠排序链的规则 https://github.com/druid-io/druid/pull/4055 - 添加 SQL REGEXP_EXTRACT 函数 https://github.com/druid-io/druid/pull/3991 - 使行提取可扩展并添加一个用于查找 https://github.com/druid-io/druid/pull/4028 - 支持强制转换为 DECIMAL https://github.com/druid-io/druid/pull/3999 - 能够生成精确的不同计数查询

其他性能改进

Druid 0.10.1 还有许多其他性能改进，包括： https://github.com/druid-io/druid/pull/4364 - 解压缩流，无需先下载到 tmp，作者：@niketh https://github.com/druid-io/druid/pull/4315 - 服务器选择器改进，作者：@dgolitsyn https://github.com/druid-io/druid/pull/4110 - 从 IngestSegmentFirehose 中删除“粒度”，作者：@gianm https://github.com/druid-io/druid/pull/4038 - 序列化 DateTime As Long 以提高 json serde 性能，作者：@kaijianding

从 0.10.0 及更早版本更新

请参阅下文，了解升级前您应注意的 0.10.0 和 0.10.1 之间的变化。如果您从 0.10.0 之前的版本进行更新，请参阅相关中间版本的 release note 以获取更多说明。

不再支持 Hadoop 版本 < 2.6.0

为了添加对 Amazon S3A 文件系统的支持，Druid 现在是针对 Hadoop 2.7.3 库构建的，并且我们将不再支持早于 2.6.0 的 Hadoop 版本。 对于运行早于 2.6.0 的 Hadoop 版本的用户，可以使用解决方法继续使用旧版 Hadoop 运行 Druid 0.10.1。 用户需要在主 Druid pom.xml 中降级 hadoop.compile.version，从 druid-hdfs-storage 核心扩展的 pom.xml 中删除 hadoop-aws 依赖项，然后重建 Druid。 强烈建议用户自此版本起将其 Hadoop 集群升级到 2.6.0+ 版本，因为在未来版本中可能会完全删除对 Hadoop <2.6.0 的支持。 如果用户希望使用 Hadoop 2.7.3 作为摄取任务的默认值，则用户应仔细检查任何现有的 druid.indexer.task.defaultHadoopCoordinates 配置。

Kafka 代理变更

由于 https://github.com/druid-io/druid/pull/4115, 的更改，Kafka 索引服务不再与版本 0.9.x Kafka 代理兼容。用户需要将 Kafka 代理升级到 0.10.x 版本。

协调员查找管理变更

https://github.com/druid-io/druid/pull/3855 引入了对协调器查找传播行为的各种改进。详情请参见http://druid.io/docs/0.10.1/querying/lookups.html。请注意协调器 HTTP API 有关查找管理的更改。 如果在之前的部署中使用了查找，那么作为升级到 0.10.1 的一部分，所有协调器都应该停止、升级，然后一次使用版本 0.10.1 启动，而不是一次升级一个。绝对不应该出现一个协调器运行 0.10.0 而另一协调器同时运行 0.10.1 的情况。 在集群升级过程中，查找查询节点会报告以got notice to load lookup [LookupExtractorFactoryContainer{version='null'开头的错误。这实际上并不是错误，而是更新的副作用。详细信息请参见 https://github.com/druid-io/druid/issues/4603。

堆外查询时查找缓存

请注意，由于内存使用过多的问题，堆外查询时查找缓存此时已损坏，不得使用： https://github.com/druid-io/druid/issues/3663

默认worker选择策略

请注意，默认的工作人员选择策略已从 fillCapacity 更改为 equalDistribution。

滚动更新

滚动更新应遵循 http://druid.io/docs/0.10.1/operations/rolling-updates.html 描述的标准 Druid 更新流程。
