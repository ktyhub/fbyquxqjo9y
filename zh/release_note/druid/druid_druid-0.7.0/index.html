druid 0.7.0

小版本 发布时间2015年2月24日 来源apache/druid 英文原文

更新到 Druid 0.7.0 – 需要注意的事项

  • 新的摄取规范 Druid 0.7.0 需要新的摄取规范格式。 Druid 0.6.172 支持新旧格式的摄取，并具有从旧格式转换为新格式的脚本。该脚本可以通过“tools ConvertSpec”运行，使用与运行 Druid 节点相同的 Main。您可以将 Druid 集群更新为 0.6.172，将摄取规范更新为新格式，然后更新为 Druid 0.7.0。如果您直接将集群更新到 Druid 0.7.0，请确保您的实时摄取管道了解新规范。
  • MySQL 不再是默认元数据存储 Druid 现在默认嵌入 Apache Derby，选择它主要是出于可测试性的目的。但是，我们不建议在生产中使用 Derby。对于测试以外的任何内容，请使用 MySQL 或 PostgreSQL 元数据存储。 元数据存储的配置参数 从 druid.db 重命名为 druid.metadata.storage，并且需要额外的 druid.metadata.storage.type=<mysql|postgresql> 才能使用 Derby 以外的任何内容。 convertProps 工具可以帮助您将所有 0.6.x 属性转换为 0.7 属性。
  • Druid 现在区分大小写 Druid 列名称现在区分大小写。我们之前尝试在查询中不区分大小写，并在数据中保留大小写，但我们决定进行此更改，因为存在许多与各种大小写问题相关的错误。 如果您从 0.6.x 版本升级：
    1. 请确保查询中的列大小写与数据中的列名称的大小写匹配，并相应地更新您的查询。
    2. 需要注意的一件非常重要的事情是，0.6 在摄取时和查询时内部将所有列名称小写。在 0.7 中，情况不再如此，但是，为了简单起见，我们仍然强烈建议您在 0.7 中使用小写列名称。
    3. 如果您当前正在摄取混合大小写列名称的数据作为数据或摄取架构的一部分：
      • 对于 TSV 或 CSV 数据，当您更新到 0.7.0 时，只需将架构中的列名称小写即可。
      • 对于具有混合大小写字段的 JSON 数据，如果您未指定列名称，则可以使用 jsonLowerCase parseSpec 在摄取时将数据小写并保持向后兼容性。 对于所有其他解析规范，您需要将其小写 如果您之前使用混合大小写，则度量/聚合器名称。
  • 现在默认批量分段公告 Druid 现在默认对所有节点使用批量分段公告。如果您已经使用批量分段公告，那么您应该已经准备就绪。 如果您尚未更新为使用批量公告，请先阅读论坛中的指南，了解如何更新当前的 0.6.x 集群以使用批量公告。
  • Kafka 0.7.x 被删除，取而代之的是 Kafka 0.8.x 如果您使用 Kafka 0.7，则必须手动构建 kafka-seven 扩展。它在构建中被注释掉，因为 Kafka 0.7 在 Maven Central 中不可用。 Kafka 0.8 (kafka-eight) 扩展不受影响。
  • 协调器端点更改 许多协调器端点已更改。请参阅协调器文档 了解它们是什么。 尤其：
  1. 协调器上的/info已被删除。 2、历史节点上的/health已被移除
  • com.metamx.metrics.SysMonitor 需要单独的罐子 如果您当前将 com.metamx.metrics.SysMonitor 作为 druid.monitoring.monitors 配置的一部分并且想要保留它，则必须将 SIGAR 库 jar 添加到您的类路径中。 或者，如果您不依赖 sys/.* 指标，则可以简单地删除 com.metamx.metrics.SysMonitor。 我们必须删除对 SIGAR 的直接依赖，才能将 Druid 工件移至 Maven Central，因为 SIGAR 目前在那里不可用。
  • 更新程序 如果您运行的 Druid 版本早于 0.6.172，请先升级到 0.6.172。请参阅 0.6.172 release notes 了解说明。 为了保证平滑滚动升级而不停机，节点必须按以下顺序更新： 1.历史节点 2.索引服务/实时节点 3.路由器节点（如果有的话）， 4. 代理节点 5. 协调节点

新功能

  • 长公制柱支撑 到目前为止，Druid 将所有指标存储为单精度浮点值，这可能会在使用 longSum 聚合器的查询中引入舍入误差和意外结果，尤其是对于 groupBy 查询。
  • 可插入元数据存储 现在立即支持 MySQL、PostgreSQL 和 Derby（用于测试）。 Derby 仅支持单主机或不应用于高可用性生产，请使用 MySQL 或 PostgreSQL 故障转移。
  • 简化数据摄取 API 完全重做Druid的数据摄取API。
  • 将公制列的压缩从 LZF 切换到 LZ4 初始性能测试表明，它的速度可能会提高 15% 到 25%，并且在典型数据集上导致分段缩小约 3-5%。
  • 可配置的倒排位图索引 除了默认的简洁位图之外，Druid 现在还支持咆哮位图。初始性能测试显示，Roaring 对于某些类型的查询可能会快 20%，但代价是段平均增大 20%。
  • 集成测试 我们添加了一组集成测试，使用 Docker 启动 Druid 集群来运行一系列索引和查询测试。
  • 新的德鲁伊协调器控制台 我们引入了一个新的 Druid 控制台，希望它能够更好地概述集群的状态，并且如果您有数十万个段，则具有更高的可扩展性。我们计划扩展此控制台以提供有关 Druid 集群当前状态的更多信息。
  • 查询结果上下文 结果上下文可以在查询标头中的查询期间报告错误。我们目前正在使用此功能进行内部重试，但希望扩展它以向 clients 报告更多信息。

改进

  • 更快的查询速度 由于更快的压缩格式、列结构的小优化、多重聚合查询的优化以及大量的 groupBy 查询性能改进，速度得到了很大的提高。 总体而言，使用新的索引格式，某些查询的速度可以提高两倍。
  • Maven Central 中的 Druid 工件 Druid 工件现在在 Maven Central 中可用 可以让您自己的构建和部署变得更容易。
  • 通用配置文件 Druid 现在有一个 common.runtime.properties，您可以在其中声明所有全局属性以及所有外部依赖项。这避免了跨多个节点的重复配置，并有望让设置 Druid 集群变得不那么痛苦。
  • 默认主机名、端口和服务名称 所有节点的默认主机名、端口和服务名称意味着如果您对默认值感到满意，则预先需要的配置会少得多。这还意味着您可以在一台计算机上运行所有节点类型，而无需处理端口冲突。
  • Druid 列名称现在区分大小写 套管虫死亡。如果您有混合大小写列并且正在使用 0.6.x，请注意更新到 0.7.0 的危险。请参阅上文了解更多详情。
  • 查询重试 Druid 现在将自动重试某些类型的失败的查询。
  • 后台缓存 对于某些类型的查询，尤其是那些涉及不同 (hyperloglog) 计数的查询，这可以将性能提高 20% 以上。 默认情况下禁用后台缓存。
  • 减少协调器内存使用 减少协调器内存使用量（最多减少 50%）。这解决了协调员有时会因频繁的GC而失去领导权的问题。
  • 现在可以将指标发送到 SSL 端点
  • 额外的 AWS 凭证支持，感谢 @gnethercutt
  • 用于实时摄取的额外持久性和节流指标 这应该有助于诊断实时摄取何时受到限制以及持续时间有多长。这些指标可以很好地表明何时需要扩大实时摄取。
  • 代理初始化端点 Brokers 现在在 /druid/broker/v1/loadstatus 提供了一个状态端点，以指示它们是否准备好被查询，从而使滚动升级/重新启动变得更加容易。

错误修复

  • 支持同一实时节点上同一数据源的多个分片。谢谢@zhaown
  • HDFS 任务日志现在应该按预期工作。谢谢@flowbehappy。
  • 修复了代理中可能存在的死锁情况。
  • 返回结果中 GZIP 压缩的各种修复。
  • druid.host 现在也应该支持 IPv6 地址。

已知问题

  • 当前无法合并具有不同类型位图索引的段，因此，如果集群中具有两种类型的索引，则必须将 druid.coordinator.merge.on 设置为 false。 “false”是配置的默认值。
  • https://github.com/druid-io/druid/issues/1045 具有复杂聚合和使用相同名称的后聚合的 GoupBy 查询问题
  • https://github.com/druid-io/druid-api/pull/38 如果您在摄取规范中使用 longSum，则浮点数据可能会引发异常。
