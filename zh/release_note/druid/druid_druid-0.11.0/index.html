druid 0.11.0

小版本 发布时间2017年12月5日 来源apache/druid 英文原文

druid druid-0.11.0

这个项目是干啥的：一个能对海量数据做实时分析的数据库，查询快、几秒就能出结果，给需要做数据看板和实时报表的分析师用。

Druid 0.11.0 包含来自近 40 个贡献者的一百多项性能改进、稳定性改进和错误修复。此版本添加了两项主要安全功能：TLS 支持以及用于身份验证和授权的扩展点。 主要新功能包括：

  • TLS（又名 SSL）支持
  • 身份验证和授权的扩展点
  • 双列支持
  • 缓存成本平衡器策略
  • JSON 解析器中的 jq 表达式支持
  • Redis 缓存扩展
  • GroupBy 性能改进
  • Druid SQL 的各种改进 完整的更改列表在这里：https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0 此版本的文档位于：http://druid.io/docs/0.11.0/

亮点

TLS 支持

Druid 现在支持 TLS，从而实现加密的 client 和节点间通信。有关配置和相关扩展的详细信息，请参阅 http://druid.io/docs/0.11.0/operations/tls-support.html。 由 @pjain1 在 https://github.com/druid-io/druid/pull/4270. 中添加

身份验证/授权扩展点

Druid 中添加了用于验证和授权请求的扩展点。有关配置和扩展实现的信息，请参阅 http://druid.io/docs/0.11.0/configuration/auth.html。 现有的 Kerberos 身份验证扩展已更新以实现新的 Authenticator 接口，如果您使用 Kerberos 扩展，请参阅“从 0.10.1 及更早版本更新”下的“Kerberos 配置更改”部分，了解更多信息。 由 @jon-wei 添加于 https://github.com/druid-io/druid/pull/4271

双列支持

Druid 现在支持 Double 类型聚合器列。有关新 Double 聚合器的文档，请参阅 http://druid.io/docs/0.11.0/querying/aggregations.html。 由 @b-slim 在 https://github.com/druid-io/druid/pull/4491. 中添加

缓存成本平衡器策略

我们鼓励升级到 0.11.0 的用户在其协调器上尝试新的 cachingCost 段平衡策略。与现有成本平衡器策略相比，该策略提供了巨大的性能改进，并且计划在 0.11.0 之后的版本中成为默认策略。 可以通过在协调器上设置以下属性来选择此策略：

druid.coordinator.balancer.strategy=cachingCost

由 @dgolitsyn 在 https://github.com/druid-io/druid/pull/4731 中添加

JSON 解析器中的 jq 表达式支持

Druid 的 JSON 输入解析器现在支持使用 jackson-jq 的 jq 表达式，从而在摄取之前启用更多输入转换。更多详情请参见http://druid.io/docs/0.11.0/ingestion/flatten-json.html。 由 @knoguchi 在 https://github.com/druid-io/druid/pull/4171. 中添加

Redis 缓存扩展

使用 Redis 的新缓存实现已添加到扩展中，由 @QiuMM 添加到 https://github.com/druid-io/druid/pull/4615. 中，请参阅前面的拉取请求以了解更多详细信息。

GroupBy 性能改进

@jihoonson 在以下 PR 中向 GroupBy 查询添加了一些新的性能优化： https://github.com/druid-io/druid/pull/4660 ConcurrentGrouper 的并行排序 https://github.com/druid-io/druid/pull/4576 基于数组的 groupBy 查询聚合 https://github.com/druid-io/druid/pull/4668 添加 IntGrouper 以避免基于数组的聚合中不必要的装箱/拆箱 PR #4660 通过并行化部分结果排序提供了总体改进，而 PR #4576 和 #4668 在对单个字符串列进行分组时提供了显着改进。

SQL 改进

@gianm 在以下 PR 中向 Druid SQL 添加了各种改进和功能： https://github.com/druid-io/druid/pull/4750 - 修剪支持 https://github.com/druid-io/druid/pull/4720 - 不同计数的舍入 https://github.com/druid-io/druid/pull/4561 - SQL 查询的指标 https://github.com/druid-io/druid/pull/4360 - SQL 表达式支持

从 0.10.1 及更早版本更新

请参阅下文，了解升级前您应注意的 0.10.1 和 0.11.0 之间的变化。如果您从 0.10.1 之前的版本进行更新，请参阅相关中间版本的 release note 以获取更多说明。

升级协调员和霸主

以下补丁更改了协调器->霸主重定向的处理方式： https://github.com/druid-io/druid/pull/5037 0.11.0中的霸主领导者选举算法发生了变化：https://github.com/druid-io/druid/pull/4699. 由于上述两个补丁，在将 Coordinator 或 Overlord 升级到 0.11.0 时需要特别小心。所有协调器和霸主必须一起关闭并升级。 例如，要升级协调器，您需要关闭所有协调器，将它们升级到 0.11.0，然后启动它们。霸主应该以类似的方式升级。 在升级过程中，不得存在非 0.11.0 协调器或霸主与 0.11.0 协调器或霸主同时运行的时间段。 请注意，在关闭所有霸主后，应尽快启动至少一个霸主，以便苦工、宁静等在重试后继续发挥作用。 另请注意，现在不再使用 druid.zk.paths.indexer.leaderLatchPath 属性。

服务名称更改

在 Druid 的早期版本中，由 druid.service 定义的服务名称中的 / 字符将被 : 字符替换，因为这些服务名称在 Zookeeper 路径中使用。德鲁伊 0.11.0 不再执行这些角色替换。 示例：1 - 如果旧配置有一个服务名称为 test/broker 的代理： druid.service=test/broker 并且配置了路由器，假设代理服务名称中的 / 将替换为 :， druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"} 应更新路由器配置以消除该假设： druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"} 示例：2 - 如果旧配置的霸主服务名称为 test/overlord，则 druid.coordinator.asOverlord.overlordService 或 druid.selectors.indexing.serviceName 的值应为 test/overlord 而不是 test:overlord 示例：3 - 如果旧配置的霸主服务名称为 test:overlord，则 druid.coordinator.asOverlord.overlordService 或 druid.selectors.indexing.serviceName 的值应为 test:overlord 而不是 test/overlord 以下与服务名称相关的配置也会受到影响，应更新为与发现的其他节点上的 druid.service 属性值完全匹配。 druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap 更多详情请参见https://github.com/druid-io/druid/issues/4992。

Kerberos 配置更改

由于 #4271 引入的新接口，Kerberos 身份验证配置格式已发生更改。请参阅 http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html 了解新的配置属性。 用户可以将 Kerberos 身份验证器的authorizerName 指向“allowAll”授权器的实例，以在无授权的情况下使用 Kerberos 身份验证来复制 0.11.0 之前的集群行为。

查找 API 路径更改

由于 #5058，查找配置 API 的路径已更改。 格式为 /druid/coordinator/v1/lookups 的配置路径现在格式为 /druid/coordinator/v1/lookups/config。 当前的API请参见http://druid.io/docs/0.11.0/querying/lookups.html。

迁移到双列

在 0.11.0 之前，Double* 聚合器会将列值以 Float 形式存储在磁盘上，同时使用 Double 表示形式执行聚合。 PR #4491 允许 Double 聚合器将列值作为 Double 存储在磁盘上。由于与滚动更新和版本降级相关的问题，默认情况下禁用此行为，并且 Druid 将继续将 Double 聚合器作为浮点数存储在磁盘上。 要启用双列存储，请在公共运行时属性中设置以下属性：

druid.indexing.doubleStorage=double

用户不应在初始滚动升级到 0.11.0 期间设置此属性，因为任何运行 0.11.0 之前的 Druid 的节点将无法处理升级期间创建的 Double 列。如果从 0.11.0 降级到旧版本，用户还需要重新索引具有双列的任何段。请参阅#4944 和#4605 了解更多信息。

扫描查询更改

Scan 查询已从 extensions-contrib 移至核心 Druid。作为此迁移的一部分：https://github.com/druid-io/druid/pull/4751, 扫描查询对时间列的处理已更改。 时间列现在作为“__time”而不是“timestamp”返回，如果您没有在“列”中明确要求它，则不再包含它，并且它作为长整型而不是字符串返回。 用户可以通过在查询中设置 "legacy" : true 或设置属性 druid.query.scan.legacy = true 将扫描查询的时间处理恢复为旧扩展行为。这旨在为以前使用 contrib 扩展的用户提供迁移路径。

扩展接口变更

聚合器双列支持

Aggregator接口获得了一个getDouble()方法，默认转换getFloat()的结果。对于任何可以支持双打的自定义聚合器，应该重新实现 getDouble() 方法。 有关详细信息，请参阅 https://github.com/druid-io/druid/pull/4595。

QueryRunner 界面更改

QueryRunner 接口已更改，旧的 run() 方法已被删除，取而代之的是接受 QueryPlus 对象的新方法。 自定义查询扩展将需要实现新接口。 请参阅 https://github.com/druid-io/druid/pull/4184 和 https://github.com/druid-io/druid/pull/4482 了解更多详情。

过滤器界面变化

Filter.getBitmapResult() 方法不再具有默认实现：https://github.com/druid-io/druid/pull/4481 自定义过滤器扩展现在需要提供 getBitmapResult() 的实现。

其他注意事项

jvm/gc/时间度量

不再发出 jvm/gc/time 指标，取而代之的是名为 jvm/gc/cpu 的新指标，原因如下：https://github.com/druid-io/druid/pull/4480

默认工人选择策略

请注意，默认的工作人员选择策略已从 fillCapacity 更改为 equalDistribution。此更改在之前版本的 0.10.1 中已引入，但在 0.10.1 release note 中未提及，因此在此再次调用。

V8 段创建已删除

Druid 现在将始终构建 V9 段，不再支持创建 V8 段，并且用于摄取任务的 buildV9Directly 属性已被删除。 请参阅 https://github.com/druid-io/druid/pull/4420 了解更多详情。

LogLevelAdjuster 已删除

请注意，LogLevelAdjuster 已被删除：https://github.com/druid-io/druid/pull/4236 任何使用 mbeans 配置日志级别的用户都应该使用 jmx 配置 log4j2。
