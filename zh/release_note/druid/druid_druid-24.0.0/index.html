druid 24.0.0

大版本 发布时间2022年9月16日 来源apache/druid 英文原文

Apache Druid 24.0.0 包含 300 多个新功能、错误修复、性能增强、文档改进以及来自 67 个贡献者的额外测试覆盖范围。 有关其他详细信息，请参阅完整的更改集。

# 主要版本更新

从本版本开始，我们从发布版本中删除了前导 0，并将所有其他数字向左提升一位。 Druid 现在的主要版本为 24，比之前的 0.23.0 版本有所提升。在向后兼容性或重大更改方面，此版本与之前的其他主要版本（例如 0.23.0 或 0.22.0）没有显着不同。我们将继续采用与之前版本相同的策略：最大限度地减少升级时需要特别注意的更改数量，并指出 release note 中确实存在的任何更改。对于此版本，请参阅升级到 24.0.0 部分，了解此版本中向后不兼容的更改列表。

# 新功能

# 多阶段查询任务引擎

Apache Druid 的基于 SQL 的摄取 采用分布式多阶段查询架构，其中包括一个称为多阶段查询任务引擎（MSQ 任务引擎）的查询引擎。 MSQ 任务引擎扩展了 Druid 的查询功能，因此您可以编写引用外部数据的查询，并使用 SQL INSERT 和 REPLACE 执行摄取。本质上，您可以执行基于 SQL 的摄取，而不是使用 Druid 原生摄取使用的 JSON 摄取规范。除了易于使用的语法之外，SQL 接口还允许您执行涉及多次数据洗牌的转换。 对于从 Druid 24.0.0 开始的批量摄取，建议使用多阶段查询任务引擎进行基于 SQL 的摄取。还继续支持本机批处理和基于 Hadoop 的摄取。我们建议您在投入生产之前查看已知问题 并在暂存环境中测试该功能。使用带有普通 SELECT 语句（不是 INSERT ... SELECT 或 REPLACE ... SELECT）的多阶段查询任务引擎是实验性的。 如果您要从早期版本的 Druid 升级或者使用 Docker，则需要将 druid-multi-stage-query 扩展添加到 common.runtime.properties 文件中的 druid.extensions.loadlist 中。 有关详细信息，请参阅基于 SQL 的摄取的概述 文档。 第12524章 第12386章 第12523章 第12589章

# 嵌套列

Druid 现在支持在新添加的 COMPLEX<json> 列类型中直接存储嵌套数据结构。 COMPLEX<json> 列存储 JSON 格式的结构化数据的副本以及嵌套文字值（STRING、LONG 和 DOUBLE 类型）的专用内部列和索引。优化的虚拟列允许 Druid 以与标准 Druid LONG、DOUBLE 和 STRING 列一致的速度读取和过滤这些值。 新添加的 Druid SQL、原生 JSON 函数和虚拟列允许您在查询时提取、转换和创建 COMPLEX<json> 值。您还可以在基于 SQL 的摄取中的 INSERT 和 REPLACE 语句中使用 JSON 函数，或者在本机摄取的 transformSpec 中使用 JSON 函数，作为使用 flattenSpec 对象“展平”嵌套数据以进行摄取的替代方法。 请参阅 SQL JSON 函数、原生 JSON 函数、嵌套列、虚拟columns，以及功能摘要 了解更多详细信息。 第12753章 第12714章 第12753章 第12920章

# 更新了 Java 支持

Java 11 得到完全支持，不再是实验性的。 Java 17 支持得到改进。 第12839章

# 查询引擎更新

# 更新了列索引和过滤器的查询处理

重新设计的列索引变得非常灵活，这最终将使我们能够对各种索引类型进行建模。添加了机制来构建使用更新索引的过滤器，同时还允许其他列实现来实现内置索引类型，以提供适配器以在 Druid 提供的当前设置过滤器中使用索引。 第12388章

# 时间过滤运算符

您现在可以使用 Druid SQL 运算符 TIME_IN_INTERVAL 根据时间过滤查询结果。优先使用 TIME_IN_INTERVAL 而不是 SQL BETWEEN 运算符来按时间进行过滤。有关详细信息，请参阅日期和时间函数。 第12662章

# 空值和“in”过滤器

如果 values 数组包含 null，则“in”过滤器匹配空值。这与 SQL IN 过滤器不同，后者不匹配空值。 有关更多信息，请参阅查询过滤器和SQL数据类型。 第12863章

# 搜索查询中的虚拟列

以前，搜索查询 只能搜索数据源中存在的维度。搜索查询现在支持虚拟列 作为查询中的参数。 第12720章

# 优化 __time 上的简单 MIN / MAX SQL 查询

像 select max(__time) from ds 这样的简单查询现在作为 timeBoundary 查询运行，以利用段中的时间维度排序。您可以设置功能标志来启用此功能。 第12472章 第12491章

# 字符串聚合结果

第一个/最后一个字符串聚合器现在仅根据值进行比较。以前，第一个/最后一个字符串聚合器的值首先根据 _time 列进行比较，然后根据值进行比较。 如果您有现有查询并希望继续使用 _time 列和值，请更新您的查询以使用 ORDER BY MAX(timeCol)。 第12773章

# 由于 Jackson 序列化而减少了分配

在 JacksonUtils 中引入并实现了新的辅助函数，以实现重用 SerializerProvider 对象。 此外，默认情况下禁用 GroupByQueryToolChest 中基于映射的行的向后兼容性，从而无需复制重量级 ObjectMapper。引入了一个配置选项，允许管理员显式启用向后兼容性。 第12468章

# 更新了 IPAddress Java 库

添加了新的 IPAddress Java 库依赖项来处理 IP 地址。该库包括 IPv6 支持。此外，还迁移了 IPv4 功能以使用新库。 第11634章

# 查询性能改进

优化的SQL操作和功能如下：

  • 矢量化数字最新聚合器（#12439）
  • 优化了 RangeSet 上的 isEmpty() 和 equals() (#12477)
  • 优化 Yielder 对象的重用 (#12475)
  • 对带有索引的数字列的操作现在更快 (#12830)
  • 通过减少分配来优化 GroupBy。通过重复使用入口和钥匙持有者减少分配 (#12474)
  • 添加了字符串最后聚合器的矢量化版本（#12493）
  • 为 IN 过滤器添加了直接 UTF-8 访问 (#12517)
  • 启用虚拟列来缓存其输出，以防 Druid 在同一底层行上多次调用它们 (#12577)
  • Druid 现在在 IN 连接中尽可能将连接重写为过滤器 (#12225)
  • 添加了 GroupBy 字典的自动调整大小 (#12763)
  • Druid 现在在代理之间更均匀地分配 JDBC 连接 (#12817)

现在，即使存在空分片，您也可以执行 Kinesis 摄取。以前，所有分片都必须至少有一条记录。 第12792章

您现在可以从不同于默认 S3 端点和签名区域的端点提取数据。 有关更多信息，请参阅 S3 配置。 第11798章

# 总体摄取方面的改进

此版本包括以下一般摄取方面的改进。

# 提高任务管理的稳健性

添加了 setNumProcessorsPerTask 以防止各种自动调整大小的线程池变得不合理的大。对于每个任务来说，将其池的大小视为整个计算机上唯一的进程并不理想。在大型机器上，这解决了由于“无法创建本机线程”而导致 OutOfMemoryError 的常见原因。 第12592章

# Avatica JDBC 驱动程序

JDBC驱动程序现在遵循JDBC标准并使用两种语句：Statement和PreparedStatement。 第12709章

# 八小时粒度

Druid 现在接受 EIGHT_HOUR 粒度。您可以将传入数据分段到 EIGHT_HOUR 存储桶，并按八小时粒度对查询结果进行分组。 第12717章

# 摄取常规

# 更新了 Avro 扩展

之前的 Avro 扩展从解析器中泄漏了对象。如果这些对象泄漏到您的摄取中，您的对象将被存储为字符串列，其值为 .toString()。升级后此字符串列将保留，但将返回 Map.toString() 而不是 GenericRecord.toString。如果您依赖以前的行为，则可以使用早期版本中的 Avro 扩展。 第12828章

# 采样器 API

采样器 API 有附加限制：maxBytesInMemory 和 maxClientResponseBytes。这些选件增强了现有选件 numRows 和 timeoutMs。 maxBytesInMemory 可用于控制采样时 Overlord 上的内存使用情况。 client 可以使用 maxClientResponseBytes 来指定它们希望处理的最大响应大小。 第12947章

# SQL

# 列顺序

DruidSchema 和 SegmentMetadataQuery 属性现在保留列顺序，而不是按字母顺序对列进行排序。这意味着查询顺序与摄取顺序更好地匹配。 第12754章

# 将 JOIN 转换为过滤器

您可以通过将查询的 enableRewriteJoinToFilter 上下文参数设置为 true，在运行时将 JOIN 部分或全部推送到基表作为过滤器，从而提高性能。 Druid 现在会下推连接过滤器，以防查询计算连接引用右侧的任何列。 第12749章 第12868章

# 将 is_active 添加到 sys.segments

添加了 is_active 作为 (is_published = 1 AND is_overshadowed = 0) OR is_realtime = 1) 的简写。这表示“所有应该可查询的段，无论它们现在是否确实存在”。 第11550章

# useNativeQueryExplain 现在默认为 true

useNativeQueryExplain 属性现在默认为 true。这意味着 EXPLAIN PLAN FOR 默认将解释计划返回为等效本机查询的 JSON 表示形式。有关更多信息，请参阅Broker 生成的查询配置补充。 第12936章

# 使用 Druid 查询引擎运行内联数据查询

一些不引用任何表的查询（例如 select 1）现在在执行之前始终会转换为带有 InlineDataSource 的本机 Druid 查询。如果无法翻译，对于 SELECT (1, 2) 等查询，则会出现错误。在早期版本中，此查询仍会运行。 第12897章

# 协调员/霸主

# 您可以将协调器配置为将来删除段

您现在可以将 druid.coordinator.kill.durationToRetain 设置为负数周期，以将 Druid 集群配置为杀死 interval_end 为未来日期的段。例如，如果段的interval_end日期是系统生成终止任务时距未来24小时或更短的时间，则PT-24H将允许终止段。 集群操作员还可以通过设置新配置 druid.coordinator.kill.ignoreDurationToRetain=true 来完全忽略 druid.coordinator.kill.durationToRetain。在查找要终止的段时，这会忽略 interval_end 日期，并且可以终止任何标记为未使用的段。这个新配置默认是关闭的，集群操作者在启用它之前应该充分理解并接受风险。

# 改进了霸主稳定性

减少管理线程与从集群接收状态更新之间的争用。当任务数量较多（1000+）时，这提高了 Overlord 和集群中所有任务的稳定性。 第12099章

# 改进了协调器分段日志记录

更新了协调器加载规则日志记录以包括当前的复制级别。添加了一些日志消息中缺少的段 ID 和层信息。 第12511章

# 优化霸主 GET 任务内存使用情况

解决了 Web 控制台间接调用 Overlord 的 GET 任务 API 导致的显着内存开销。当多次打开摄取选项卡时，这可能会导致无响应或 Overlord 失败。 第12404章

# 减少创建间隔的时间

为了通过减少创建间隔所需的时间来优化段成本计算时间，请存储段间隔而不是每次从基元创建它，并通过驻留间隔来减少存储间隔的内存开销。段的间隔集基数较低。 第12670章

# 经纪人/霸主

代理现在每个查询的默认最大排队容量为 25MB。此前，没有默认限制。根据您的使用案例，您可能需要增加该值，特别是当您有大型结果集或大量中间数据时。要调整最大可用内存，请使用 druid.broker.http.maxQueuedBytes 属性。 更多信息请参见【配置参考】(docs/configuration/index.md)。

# Web 控制台

准备好提升您的 Web 控制台体验！ - @vogievetsky

# 带有选项卡和长时间运行查询支持的新查询视图 (WorkbenchView)

您可以使用新的查询视图通过 /druid/v2/sql/task 和 /druid/indexer/v1/task/* API 执行多阶段、基于任务的查询，以及本机和 sql-native 查询，就像旧的查询视图一样。基于 sql-msq-task 的查询的一个关键点是它们可能会运行很长时间。这启发/需要许多用户体验更改，包括但不限于以下内容：

# 选项卡

您现在可以同时存储和运行多个查询，从而显着改善查询视图的用户体验。 您可以打开多个选项卡，复制它们，然后将它们复制为文本以粘贴到任何控制台中并在其中重新打开。

# 进度报告（计数器报告）

使用多阶段查询任务引擎运行的查询具有在摘要进度栏中显示的详细进度报告，以及提供每个步骤的计数器摘要的详细执行表。

# 错误和警告报告

如果出现任何问题，使用多阶段查询任务引擎运行的查询会显示用户友好的警告和错误。 新的查询视图具有可视化这些组件及其完整详细信息（包括堆栈跟踪）的组件。

# 最近查询任务面板

使用多阶段查询任务引擎运行的查询是任务。这使得可以显示当前正在执行的查询和最近执行的查询。 对于“最近查询任务”面板中的任何查询，您可以查看其执行详细信息，还可以将其附加为新选项卡并继续迭代查询。还可以下载“查询详细信息存档”，这是一个 JSON 文件，其中包含给定查询的所有重要详细信息，用于故障排除。

# 连接外部数据流

通过连接外部数据流，您可以使用采样器对源数据进行采样、确定其架构并生成完整的 SQL 查询，您可以在启动提取作业之前对其进行编辑以适合您的用例。这个点对点 click 流程将节省您大量的打字时间。

# 预览按钮

当您键入 INSERT 或 REPLACE SQL 查询时，会出现“预览”按钮。 Click 该按钮可删除 INSERT 或 REPLACE 子句，并将查询作为带限制的“内联”查询执行。这可以让您了解 Druid 应用 SQL 查询中的所有转换后数据的形状。

# 结果表

查询结果表在样式和功能上都得到了改进。现在，它会向您显示列类型的键入图标，并支持轻松操作嵌套列的功能。

# 辅助查询

Web 控制台现在为笔记本电脑和 CTE 用户提供了一些 UI 功能。您可以从主查询中引用辅助查询（保存查询的可折叠元素），就像使用WITH 语句定义它们一样。当您编写复杂的查询时，将其分解为多个查询以单独预览各个部分会很有帮助。

# 其他 Web 控制台工具

… 菜单中提供了更多工具：

  • 解释查询 - 显示 sql 原生和多阶段查询任务引擎查询的查询计划。
  • 将摄取规范转换为 SQL - 帮助您将本机批处理和基于 Hadoop 的规范迁移到基于 SQL 的格式。
  • 打开查询详细信息存档 - 允许您打开之前下载的查询详细信息存档。
  • 加载演示查询 - 让您加载一组预制查询以使用多阶段查询任务引擎功能。

# 新的基于 SQL 的数据加载器

数据加载器作为 GUI 向导存在，可帮助用户使用点和 click 以及快速预览来制作 JSON 摄取规范。 SQL 数据加载器是基于 SQL 的摄取模拟。 与基于本机的数据加载器一样，基于 SQL 的数据加载器将所有状态存储在 SQL 查询本身中。您可以选择在任何阶段直接操作查询。有关数据加载器与 连接外部数据 工作流程有何不同的更多信息，请参阅 (#12919)。

# 其他更改和改进

# 未使用段的行为

Druid 自动保留任何标记为未使用的段。以前，Druid 在保留期限过后从元数据存储和深度存储中永久删除未使用的段。此行为已从 0.23.0 恢复。 第12693章

# druid.processing.fifo 的默认值

druid.processing.fifo 的默认值现在为 true。这意味着同等优先级的任务将以 FIFO 方式处理。对于大多数用例，此更改可以提高负载较重的集群的性能。 第12571章

# 更新 JDBC 语句闭包

在以前的版本中，Druid 在 ResultSet 关闭时自动关闭 JDBC Statement。 Druid 在 EOF 时关闭了 ResultSet。 Druid 关闭了任何异常的声明。然而，这种行为是非标准的。 在此版本中，Druid 的 JDBC 驱动程序更严格地遵循 JDBC 标准： ResultSet 在 EOF 时自动关闭，但不会关闭Statement或PreparedStatement。您的代码必须关闭这些语句，也许可以使用 try-with-resources 块。 现在可以使用不同的参数多次使用PreparedStatement。 （以前这不是真的，因为关闭 ResultSet 会关闭PreparedStatement。） 如果对 Statement 或PreparedStatement 的任何调用引发错误，client 代码仍必须显式关闭该语句。根据 JDBC 标准，语句不会在出现错误时自动关闭。这使您可以在关闭失败语句之前获取有关该语句的信息。 如果您的代码依赖于旧行为，则可能需要更改代码以添加所需的关闭语句。 第12709章
