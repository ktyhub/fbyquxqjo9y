druid 0.6.146

修订 发布时间2014年8月21日 来源apache/druid 英文原文

新功能

  • 添加了重新架构功能。您现在可以提取现有的 Druid 分段并更改分段的名称、维度、指标、汇总等。 （更多信息：http://druid.io/docs/0.6.146/Ingestion-FAQ.html）
  • 近似直方图和分位数。我们开源了一个新模块，druid-histogram，其中包括一个新的聚合器来构建近似分布并可用于分位数。根据所需结果的准确性，此聚合器可能比其他 Druid 聚合器慢。此功能仍处于实验阶段，但我们非常乐意与社区合作，使其生产更加稳定。 （更多信息：http://druid.io/docs/0.6.146/ApproxHisto.html）
  • 查询超时和取消。现在，您可以在 Druid 查询上下文中指定可选的“超时”键和长值，以取消运行时间过长的查询。您还可以发出显式查询取消。 （更多信息：http://druid.io/docs/0.6.146/Querying.html）
  • groupBy 和 select 查询缓存（默认禁用）。 Select 和 groupBy 查询默认不缓存。这是为了防止这些查询的大型结果集溢出缓存。但是，如果您的工作负载生成合理大小的 groupBy 结果，并且您希望为这些查询启用缓存，则可以覆盖 druid.*.cache.unCacheable (http://druid.io/docs/0.6.146/Broker-Config.html) 的默认值。
  • 中层管理人员现在可以被列入黑名单。这允许中间管理器的滚动更新。请参阅有关滚动 Druid 更新的新文档。 (http://druid.io/docs/0.6.146/Rolling-Updates.html)
  • 现在可以从文件中读取 S3 凭据。谢谢@metacret！
  • 现在支持索引服务的 HDFS 任务日志。谢谢@realfun！
  • 索引任务现在支持手动指定 shardSpecs 并能够跳过确定分区步骤。
  • TimeBoundary 查询现在可以仅返回最大或最短时间。 http://druid.io/docs/0.6.146/TimeBoundaryQuery.html

改进

  • 嵌套 groupBy 查询现在支持帖子聚合器和普通 groupBy 查询的所有功能。
  • groupBy 查询现在支持基数聚合器。
  • 苦工的端口查找策略更加智能，现在可以重复使用端口。
  • 现有的完整接收器现在将在实时更新或重新启动后尝试更快地移交。
  • 更灵活的 userData 用于 EC2 上的索引服务自动缩放，不再与我们的部署环境绑定。
  • Druid 路由器中的异步逻辑得到显着改进。
  • 路由器现在支持可选的路由策略覆盖。
  • Druid 0.6.x 部署现在可与 Apache Whirr 配合使用。我们也将很快创建一种使用 docker 部署 Druid 的方法。
  • 清理了索引服务中的一些冗余配置。
  • 添加了大量查询和缓存单元测试。
  • 现在可以为 Hadoop 摄取任务添加显式作业属性。

文档

  • 现在有关于如何滚动 Druid 更新和重新启动的文档。 http://druid.io/docs/0.6.146/Rolling-Updates.html
  • 用于在 Druid 中配置日志记录的新文档。 http://druid.io/docs/0.6.146/Logging.html
  • 现已添加 Kafka 8 文档。谢谢@r4j4h http://druid.io/docs/0.6.146/Kafka-Eight.html
  • 添加了倒置 topN 的文档 http://druid.io/docs/0.6.146/TopNMetricSpec.html#inverted-topnmetricspec
  • 更新了 Cassandra 文档。谢谢@lexicalunit https://github.com/metamx/druid/pull/680

其他

  • Curator 版本升至 2.6.0
  • Jetty 版本升至 9.2.2
  • Guava 版本升至 16.0.1
  • 协调器和历史节点的日志记录现在不再那么冗长
