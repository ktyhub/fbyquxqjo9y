druid 0.20.0

小版本 发布时间2020年10月17日 来源apache/druid 英文原文

druid druid-0.20.0

Apache Druid 0.20.0 包含约 160 个新功能、错误修复、性能增强、文档改进以及来自 36 个贡献者的额外测试覆盖范围。请参阅完整的更改列表 和标记到里程碑的所有内容 了解更多详细信息。

# 新功能

# 摄取

# 组合输入源

添加了新的组合输入源，允许用户在摄取期间组合多个输入源。更多详情请参见https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#combining-input-source。 https://github.com/apache/druid/pull/10387

# 自动确定并行摄取哈希分区的 numShards

当哈希分区用于并行批量摄取时，不再需要在分区规范中指定 numShards。 Druid 现在可以通过在新的摄取阶段扫描数据来自动确定分片的数量，从而确定分区键的基数。 https://github.com/apache/druid/pull/10419

# 并行批量摄取的子任务文件计数限制

基于大小的 splitHintSpec 现在支持新的 maxNumFiles 参数，该参数限制可以在并行批量摄取中分配给各个子任务的文件数量。 用于从现有 Druid 段重新摄取数据的基于段的 splitHintSpec 也有一个新的 maxNumSegments 参数，其功能类似。 更多详情请参见https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#split-hint-spec。 https://github.com/apache/druid/pull/10243

# 任务槽使用指标

添加了新的任务槽使用指标。请参阅 https://druid.apache.org/docs/0.20.0/operations/metrics.html#indexing-service 上的 taskSlot 指标条目了解更多详细信息。 https://github.com/apache/druid/pull/10379

# 压缩

# 支持所有自动压缩分区方案

现在可以为自动压缩定义分区规范，允许用户在压缩时重新分区数据。有关更多详细信息，请参阅压缩 tuningConfig 中新 partitionsSpec 属性的文档： https://druid.apache.org/docs/0.20.0/configuration/index.html#compaction-tuningconfig https://github.com/apache/druid/pull/10307

# 自动压缩状态 API

添加了一个新的协调器 API，它显示数据源自动压缩的状态。新的 API 显示是否为数据源启用了自动压缩，以及压缩进度的摘要。 Web 控制台也已更新以显示以下信息： https://user-images.githubusercontent.com/177816/94326243-9d07e780-ff57-11ea-9f80-256fa08580f0.png 有关新 API 的详细信息，请参阅 https://druid.apache.org/docs/latest/operations/api-reference.html#compaction-status，有关新的相关压缩指标的信息，请参阅 https://druid.apache.org/docs/latest/operations/metrics.html#coordination。 https://github.com/apache/druid/pull/10371 https://github.com/apache/druid/pull/10438

# 查询

# 使用哈希分区进行查询段修剪

Druid 现在支持哈希分区段的查询时段修剪（排除某些段作为查询的读取候选者）。当摄取期间哈希分区规范中指定的所有 partitionDimensions 都存在于查询的过滤器集中，并且查询中的过滤器对 partitionDimensions 的离散值进行过滤（例如选择器过滤器）时，适用此优化。非离散过滤器（例如绑定过滤器）不支持使用哈希分区进行段修剪。 对于拥有现有分段的现有用户，您需要重新摄取这些分段才能利用此新功能，因为分段修剪需要将 partitionFunction 与分段存储在一起，而旧版本 Druid 创建的分段中不存在 partitionFunction。无需显式指定 partitionFunction，因为默认值与 Druid 早期版本中使用的分区函数相同。 请注意，使用默认 partitionDimensions 值（按所有维度 + 时间列分区）创建的段不能以这种方式修剪，需要使用显式 partitionDimensions 创建段。 https://github.com/apache/druid/pull/9810 https://github.com/apache/druid/pull/10288

# 矢量化

要启用矢量化功能，请将 druid.query.default.context.vectorizeVirtualColumns 属性设置为 true 或在查询上下文中设置 vectorize 属性。请参阅 https://druid.apache.org/docs/0.20.0/querying/query-context.html#vectorization-parameters 了解更多信息。

# 对表达式虚拟列的矢量化支持

表达式虚拟列现在具有矢量化支持（取决于所使用的表达式），这在某些情况下会导致性能提高 3-5 倍。 支持矢量化的具体表达式请参见https://druid.apache.org/docs/0.20.0/misc/math-expr.html#vectorization-support。 https://github.com/apache/druid/pull/10388 https://github.com/apache/druid/pull/10401 https://github.com/apache/druid/pull/10432

# 对聚合器的更多矢量化支持

添加了对多种聚合类型的矢量化支持：数字最小/最大聚合器、方差聚合器、ANY 聚合器以及来自 druid-histogram 扩展的聚合器。 https://github.com/apache/druid/pull/10260 - 数字最小值/最大值 https://github.com/apache/druid/pull/10304 - 直方图 https://github.com/apache/druid/pull/10338 - 任何 https://github.com/apache/druid/pull/10390 - 方差 我们观察到，在某些情况下，为最小值、最大值和任意聚合器启用矢量化后，性能提升约 1.3 倍到 1.8 倍，而使用直方图聚合器时，性能提升约 1.04 倍到 1.07 倍。

# 用于 GroupBy 和 Scan 查询的 offset 参数

现在可以为 GroupBy 和 Scan 查询设置 offset 参数，它告诉 Druid 在返回结果时跳过一些行。详情请参见https://druid.apache.org/docs/0.20.0/querying/limitspec.html和https://druid.apache.org/docs/0.20.0/querying/scan-query.html。 https://github.com/apache/druid/pull/10235 https://github.com/apache/druid/pull/10233

# 用于 SQL 查询的 OFFSET 子句

Druid SQL 查询现在支持 OFFSET 子句。详情请参见https://druid.apache.org/docs/0.20.0/querying/sql.html#offset。 https://github.com/apache/druid/pull/10279

# 子字符串搜索运算符

Druid 在其表达式语言和 SQL 查询中添加了新的子字符串搜索运算符。 请参阅 Druid SQL (https://druid.apache.org/docs/0.20.0/querying/sql.html#string-functions) 的 CONTAINS_STRING 和 ICONTAINS_STRING 字符串函数文档以及 Druid 表达式语言 (https://druid.apache.org/docs/0.20.0/misc/math-expr.html#string-functions) 的 contains_string 和 icontains_string 文档。 我们发现，在某些情况下，通过使用这些函数而不是 STRPOS，性能可提高 2.5 倍。 https://github.com/apache/druid/pull/10350

# SQL 查询的 UNION ALL 运算符

Druid SQL 查询现在支持 UNION ALL 运算符，它将多个查询的结果融合在一起。有关此运算符支持哪些查询形状的详细信息，请参阅 https://druid.apache.org/docs/0.20.0/querying/sql.html#union-all。 https://github.com/apache/druid/pull/10324

# 集群范围内的默认查询上下文设置

现在可以通过添加 druid.query.override.default.context.* 形式的配置来设置集群范围的默认查询上下文属性，其中 * 替换为属性名称。 https://github.com/apache/druid/pull/10208

# 其他功能

# 改进的保留规则 UI

Web 控制台中的保留规则 UI 已得到改进。现在，它在周期下拉列表中提供建议和基本验证，显示集群默认规则，并使编辑默认规则变得更容易。 https://github.com/apache/druid/pull/10226

# Redis 缓存扩展增强功能

Redis 缓存扩展现在支持 Redis 集群、选择使用哪个数据库、连接到受密码保护的服务器以及 expiration 和 timeout 属性的周期样式配置。 https://github.com/apache/druid/pull/10240

# 禁用在响应标头中发送服务器版本

现在可以在 Druid 的响应标头中禁用服务器版本信息的发送。 这是由新属性 druid.server.http.sendServerVersion 控制的，默认为 true。 https://github.com/apache/druid/pull/9832

# 使用单位指定基于字节的配置属性

Druid 现在支持指定基于字节的配置属性的单元，例如：

druid.server.maxSize=300g

相当于

druid.server.maxSize=300000000000

更多详情请参见https://druid.apache.org/docs/0.20.0/configuration/human-readable-byte.html。 https://github.com/apache/druid/pull/10203

# 错误修复

# 修复历史记录没有分段时间线时的查询正确性问题

Druid 0.20.0 修复了查询正确性问题，当代理发出查询时期望历史记录具有数据源的某些段，但查询时的历史记录实际上没有该数据源的任何段（例如，在历史记录处理查询之前它们全部被卸载）。在 0.20.0 之前，查询将成功返回，但不会返回之前描述的方式丢失的段的结果。在 0.20.0 中，查询现在在这种情况下会失败。 https://github.com/apache/druid/pull/10199

# 修复阻止填充结果级缓存的问题

Druid 0.20.0 修复了 0.19.0 (https://github.com/apache/druid/issues/10337) 中引入的问题，该问题可能会在启用结果级缓存时阻止填充查询缓存。 https://github.com/apache/druid/pull/10341

# 修复方差聚合器排序

方差聚合器之前使用了不正确的比较器，该比较器使用聚合器的内部 count 变量而不是方差进行比较。 https://github.com/apache/druid/pull/10340

# 修复具有限制规范的 groupBy 查询的错误缓存

Druid 0.20.0 修复了 groupBy 查询和缓存的问题，其中缓存键中未考虑查询的 limitSpec，如果发出除 limitSpec 之外相同的查询，则可能导致错误的结果。 https://github.com/apache/druid/pull/10093

# 修复启用汇总的 stringFirst 和 stringLast

https://github.com/apache/druid/issues/7243 已得到解决，stringFirst 和 stringLast 聚合器在启用汇总的摄取期间使用时不再导致异常。 https://github.com/apache/druid/pull/10332

# 升级到 Druid 0.20.0

从 0.19.0 升级到 0.20.0 时，请注意以下注意事项。如果您从 0.19.0 之前的版本进行更新，请参阅相关中间版本的 release note。

# 默认 maxSize

druid.server.maxSize 现在将默认为 druid.segmentCache.locations 中定义的 maxSize 值的总和。用户仍然可以为 druid.server.maxSize 提供自定义值，该值将优先于默认值。 https://github.com/apache/druid/pull/10255

# 压缩并终止任务 ID 更改

协调器发出的压缩和终止任务现在的任务 ID 将以 coordinator-issued 为前缀，而用户发出的终止任务将以 api-issued 为前缀。 https://github.com/apache/druid/pull/10278

# 并行摄取拆分提示规范的新大小限制

用于并行批量摄取的基于大小和基于段的 splitHintSpec 现在对每个子任务应用 1000 个默认文件/段限制，分别由 maxNumFiles 和 maxNumSegments 控制。 https://github.com/apache/druid/pull/10243

# 新的 PostAggregator 和 AggregatorFactory 方法

使用自定义 PostAggregator 或 AggregatorFactory 实现开发扩展的用户将需要更新其扩展，因为这两个接口具有 0.20.0 中定义的新方法。 PostAggregator现在有一个新方法：

  ValueType getType();

为了支持PostAggregator上的类型信息，AggregatorFactory还增加了2个新方法：

  public abstract ValueType getType();

  public abstract ValueType getFinalizedType();

有关界面更改的更多详细信息，请参阅 https://github.com/apache/druid/pull/9638。

# 新的 Expr 相关方法

使用自定义 Expr 实现开发扩展的用户将需要更新其扩展，因为 Expr 和相关接口在 0.20.0 中已发生更改。详情请参阅下面的 PR： https://github.com/apache/druid/pull/10401

# 更准确的 query/cpu/time 指标

在 0.20.0 中，query/cpu/time 指标的精度得到了提高。以前，它没有考虑查询处理期间的某些工作部分，以下 PR 中有更详细的描述： https://github.com/apache/druid/pull/10377

# 新审核日志服务指标列

如果您使用审核日志记录，请注意审核日志服务指标中已添加新列（comment、remote_address 和 created_date）。还添加了可选的 payload 列，可以通过将 druid.audit.manager.includePayloadAsDimensionInMetric 设置为 true 来启用。 https://github.com/apache/druid/pull/10373

请求日志中的 # sqlQueryContext

如果您使用查询请求日志记录，请求日志事件现在将包括 SQL 查询的 sqlQueryContext。 https://github.com/apache/druid/pull/10368

# 元数据存储中的其他每段状态

由 Druid 0.20.0 创建的哈希分区段现在将在元数据存储中拥有额外的 partitionFunction 数据。 此外，压缩任务现在将在元数据存储中存储额外的每段信息，用于跟踪压缩历史记录。 https://github.com/apache/druid/pull/10288 https://github.com/apache/druid/pull/10413

# 已知问题

# druid.segmentCache.locationSelectorStrategy 注入失败

指定 druid.segmentCache.locationSelectorStrategy 的值可防止服务因注入错误而启动。请参阅 https://github.com/apache/druid/issues/10348 了解更多详情。

# Web 控制台数据采样器中的资源泄漏

当在 Web 控制台中采样数据时发生超时时，为从输入源读取而创建的内部资源不会正确关闭。请参阅 https://github.com/apache/druid/pull/10467 了解更多信息。
