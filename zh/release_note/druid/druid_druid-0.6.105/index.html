druid 0.6.105

修订 发布时间2014年6月7日 来源apache/druid 英文原文

更新中

在不停机更新Druid时，我们强烈建议在更新broker层之前先更新历史节点和实时节点。查询的更改通常与旧的代理版本和新的历史节点版本兼容，但反之则不然。我们推荐的滚动更新流程是： 1.索引服务/实时节点 2.历史节点（每个节点之间有一个等待，等待时间对应于历史节点重新启动并加载所有本地缓存的段所需的时间） 3. 代理节点 4. 协调节点

Release Note

  • 历史节点现在可以使用和维护本地缓存（默认情况下禁用）。该缓存可以是基于堆的，也可以是内存缓存的。这允许历史节点在本地合并结果，并减少代理上的大部分内存压力，同时从缓存中提取大量结果。现在填充缓存也是以异步方式完成的。
  • 实验路由器节点。我们一直在尝试完全异步的路由器节点，它可以根据实际查询将查询路由到不同的代理。目前，路由器节点根据协调器节点的规则决定与哪个代理进行通信。我们的目标是在某个时候合并路由器和代理逻辑并转向分层代理。
  • 聚合后优化。我们优化了后期聚合的计算（之前后期聚合的计算量超出了必要的范围）。在一些初始基准测试中，这可以使涉及后聚合的查询提高 20%-30%。
  • 支持 groupBy 中的 hyperUnique。我们修复了一个报告的问题，即在使用复杂指标（尤其是 hyperUnique）时，groupBys 会报告不正确的结果。
  • 支持groupBy中的维度提取功能
  • 持久和持久合并线程现在在实时摄取期间不再相互阻塞。几个月前，我们添加了一个用于限制实时摄取的参数，我们所看到的是，在等待移交操作完成时，可能会阻止导致大量中间持久化的非常高的摄取率。此行为现​​已得到改进。您现在还可以在管道工中设置 maxPendingPersists。
  • hyperUnique 性能优化：聚合速度加快约 30-50%

其他杂项

  • 修复基于哈希的分区中的整数溢出
  • 支持查询上下文中的任意 JSON 对象
  • 请求日志现在包括查询计时统计信息
  • 默认支持 Hadoop 2.3
  • 更新至 Jetty 9
  • 测试不需要有效的数据库连接
  • 优雅地处理计算节点返回的 NaN / Infinity
  • 针对 ChainedExecutionQueryRunner 抛出 NPE 的情况提供更好的错误报告

扩展：

  • HDFS 存储现在应该可以更好地与 Cloudera CDH4 配合使用
  • S3 存储：对象 ACL 现在始终默认为“存储桶所有者完全控制”
