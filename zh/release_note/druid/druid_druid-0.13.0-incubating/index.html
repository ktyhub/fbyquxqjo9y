druid 0.13.0-incubating

小版本 发布时间2018年12月12日 来源apache/druid 英文原文

Druid 0.13.0-incubating 包含超过 400 个新功能、性能/稳定性/文档改进以及来自 81 个贡献者的错误修复。它是 Apache 孵化器计划中 Druid 的第一个版本。主要新功能和改进包括：

  • 本机并行批量索引
  • 自动分段压缩
  • 系统架构表
  • 改进了索引任务状态、统计数据和错误报告
  • SQL兼容的空处理
  • 结果级代理缓存
  • 从 RDBMS 摄取
  • 布隆过滤器支持
  • 附加 SQL 结果格式
  • 附加聚合器（stringFirst/stringLast、ArrayOfDoublesSketch、HllSketch）
  • groupBy 查询中支持多个分组规范
  • 相互 TLS 支持
  • 基于HTTP的worker管理
  • 经纪商背压
  • maxBytesInMemory 摄取调整配置
  • 物化视图（社区扩展）
  • Influx Line 协议的解析器（社区扩展）
  • OpenTSDB 发射器（社区扩展） 完整的更改列表在这里：https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.13.0 此版本的文档位于：http://druid.io/docs/0.13.0-incubating/

变更架构图

亮点

本机并行批量索引

引入了 index_parallel 管理程序，它可以管理可拆分源的并行批量摄取，而无需依赖 Hadoop。请参阅 http://druid.io/docs/latest/ingestion/native_tasks.html 了解更多信息。 注意： 这是最初的单阶段实现，对于输入数据的分区方式有限制。值得注意的是，它没有 shuffle 实现，该实现将在该功能的下一次迭代中添加。有关更多详细信息，请参阅#5543 中的提案。 由 @jihoonson 在 #5492 中添加。

自动段压缩

以前，将小段压缩为最佳大小的段以提高查询性能需要提交并运行压缩或重新索引任务。这通常是一个手动过程或需要外部调度程序来处理任务的定期提交。该补丁实现了由协调器服务管理的自动段压缩。 注意： 这是初始实现，在与实时摄取任务的互操作性方面存在限制。索引任务当前需要获取它们将要修改的时间线部分的锁，以防止并发操作出现不一致。此实现使用低优先级锁来确保它永远不会中断实时摄取，但这也意味着如果实时任务在压缩的时间间隔上不断获取锁，压缩可能无法取得任何进展。这将在该功能的下一次迭代中通过更细粒度的锁定得到改进。有关更多详细信息，请参阅#4479 中的提案。 此功能的文档：http://druid.io/docs/0.13.0-incubating/design/coordinator.html#compacting-segments 由 @jihoonson 在 #5102 中添加。

系统模式表

将系统架构添加到 SQL 接口，其中包含公开有关已服务和已发布的段、集群节点的信息以及有关正在运行和已完成的索引任务的信息的表。 注意： 此实现包含一些已知的开销低效率问题，这些问题将在未来的补丁中解决。 此功能的文档：http://druid.io/docs/0.13.0-incubating/querying/sql.html#system-schema 由 @surekhasaharan 在 #6094 中添加。

改进了索引任务状态、统计数据和错误报告

改进了与摄取相关的 API 的性能和细节，这些 API 以前相当不透明，因此很难确定解析异常、任务失败的原因以及已完成任务的实际输出。还添加了改进的摄取指标报告，包括移动平均吞吐量统计数据。 由@surekhasaharan 和@jon-wei 在#5801、#5418 和#5748 中添加。

SQL 兼容的 null 处理

通过将空值视为缺失值而不是等同于空字符串或零值，改进了 Druid 对空值的处理。这使得 Druid 更加兼容 SQL，并改进了与支持 ODBC/JDBC 的外部 BI 工具的集成。提案请参见#4349。 要启用此功能，您需要设置系统范围属性 druid.generic.useDefaultValueForNull=false。 由@nishantmonu51 在#5278 和#5958 中添加。

结果级代理缓存

在代理上实现结果级缓存，可以与传统的段级缓存同时运行。提案请参阅#4843。 此功能的文档：http://druid.io/docs/0.13.0-incubating/configuration/index.html#broker-caching 由 @a2l007 在 #5028 中添加。

从 RDBMS 摄取

引入了 sql firehose，它支持直接从 RDBMS 提取数据。 由 @a2l007 在 #5441 中添加。

布隆过滤器支持

添加了对通过应用由外部系统（例如 Apache Hive）生成的 Bloom 过滤器来优化 Druid 查询的支持。将来，#6397 将支持生成 Bloom 过滤器作为 Druid 查询的结果，然后可用于优化未来的查询。 由 @nishantmonu51 在 #6222 中添加。

其他 SQL 结果格式

添加基于行的 JSON 和 CSV 的结果格式，以及包含结果中包含的列列表的 X-Druid-Column-Names 和 X-Druid-Column-Types 响应标头。 由 @gianm 在 #6191 中添加。

‘stringLast’ 和 ‘stringFirst’ 聚合器

引入两个互补聚合器 stringLast 和 stringFirst，它们对字符串列进行操作并分别返回具有最大和最小时间戳的值。 由 @andresgomezfrr 在 #5789 中添加。

ArrayOfDoublesSketch

添加对数字元组草图的支持，通过添加与唯一键关联的双值数组来扩展计数不同 Theta 草图的功能。 由 @AlexanderSaydakov 在 #5148 中添加。

HllSketch

添加基于 https://github.com/DataSketches. 的 HllSketch 的计数不同聚合器的可配置实现 与 Druid 的本机 HyperLogLogCollector 的比较显示出更高的准确性、效率和速度：https://datasketches.github.io/docs/HLL/HllSketchVsDruidHyperLogLogCollector.html 由 @AlexanderSaydakov 在 #5712 中添加。

在 groupBy 查询中支持多个分组规范

添加了对 subtotalsSpec groupBy 参数的支持，该参数允许 Druid 在运行按同一列集的子集分组的多个查询时，通过在代理级别重用中间结果来提高效率。有关更多信息，请参阅 #5179 中的提案。 由 @himanshug 在 #5280 中添加。

相互 TLS 支持

添加对相互 TLS 的支持（服务器证书验证 + client 证书验证）。参见：https://en.wikipedia.org/wiki/Mutual_authentication 由 @jon-wei 在 #6076 中添加。

基于HTTP的worker管理

新增基于HTTP的索引任务管理实现，替换之前基于ZooKeeper的索引任务管理实现。这是一系列改进的一部分，旨在减少并最终消除 Druid 对 ZooKeeper 的依赖。提案请参阅#4996。 由 @himanshug 在 #5104 中添加。

经纪商背压

允许代理对数据服务节点施加背压，以防止代理在结果传入速度快于 clients 读取速度时因内存压力而崩溃。 由 @gianm 在 #6313 中添加。

‘maxBytesInMemory’ 摄取调整配置

以前，索引任务内存管理的一个主要调整参数是 maxRowsInMemory 配置，它确定将内存内容溢出到磁盘的阈值。由于行的“大小”根据多种因素而变化，因此很难正确配置。 maxBytesInMemory 使此配置基于字节而不是基于行。 由 @surekhasaharan 在 #5583 中添加。

物化视图

支持创建物化视图，在某些情况下可以提高查询性能，但需要额外的存储空间。请参阅 http://druid.io/docs/latest/development/extensions-contrib/materialized-view.html 了解更多信息。 注意： 这是社区贡献的扩展，不会自动包含在 Druid 发行版中。我们欢迎反馈意见，以决定何时将其提升为核心扩展。有关更多信息，请参阅社区扩展。 由@zhangxinyu1 在#5556 中添加。

Influx Line 协议解析器

添加了对摄取 Influx Line Protocol 数据格式的支持。欲了解更多信息，请参阅：https://docs.influxdata.com/influxdb/v1.6/write_protocols/line_protocol_tutorial/ 注意： 这是社区贡献的扩展，不会自动包含在 Druid 发行版中。我们欢迎反馈意见，以决定何时将其提升为核心扩展。有关更多信息，请参阅社区扩展。 由 @njhartwell 在 #5440 中添加。

OpenTSDB 发射器

添加了对向 OpenTSDB 发出 Druid 指标的支持。 注意： 这是社区贡献的扩展，不会自动包含在 Druid 发行版中。我们欢迎反馈意见，以决定何时将其提升为核心扩展。有关更多信息，请参阅社区扩展。 由 @QiuMM 在 #5380 中添加。

从 0.12.3 及更早版本更新

这个项目是干啥的：一个能对海量数据做实时分析的数据库，查询快、几秒就能出结果，给需要做数据看板和实时报表的分析师用。

请参阅下文，了解升级前您应注意的 0.12.3 和 0.13.0 之间的变化。如果您从 0.12.3 之前的版本进行更新，请参阅相关中间版本的 release note 以获取更多说明。

MySQL 元数据存储扩展不再包含 JDBC 驱动程序

MySQL 元数据存储扩展现在与 Druid 发行版打包在一起，但没有所需的 MySQL JDBC 驱动程序（由于许可限制）。要使用此扩展，需要单独下载驱动程序并将其添加到扩展目录中。 有关详细信息，请参阅 http://druid.io/docs/latest/development/extensions-core/mysql.html。

S3 扩展所需的 AWS 区域配置

由于从 jets3t 切换到 AWS SDK (#5382)，S3 扩展的用户现在需要显式设置目标区域。这可以通过设置 JVM 系统属性 aws.region 或环境变量 AWS_REGION 来完成。 例如，通过系统属性将区域设置为“us-east-1”：

  • 将 -Daws.region=us-east-1 添加到所有 Druid 服务的 jvm.config 文件
  • 在 middleManager/runtime.properties 中将 -Daws.region=us-east-1 添加到 druid.indexer.runner.javaOpts ，以便该属性将传递给 peon (worker) 进程

摄取规范更改

由于将打包从 io.druid 重命名为 org.apache.druid，通过完全限定类名引用类的摄取规范将需要进行相应修改。 例如，如果您将 Parquet 扩展与 Hadoop 索引结合使用，则 inputSpec 的 inputFormat 字段需要从 io.druid.data.input.parquet.DruidParquetInputFormat 更改为 org.apache.druid.data.input.parquet.DruidParquetInputFormat。

指标变化

新指标

  • task/action/log/time - 将任务操作记录到审核日志所需的毫秒数 (#5714)
  • task/action/run/time - 执行任务操作所需的毫秒数 (#5714)
  • query/node/backpressure - 由于应用了反压，通道无法读取纳秒 (#6335)（请注意，默认情况下未启用此功能，需要自定义实现 QueryMetrics 才能发出）

新维度

  • taskId 和 taskType 添加到任务相关指标中 (#5664)

其他

  • 如果没有记录时间，HttpPostEmitterMonitor 不再发出 maxTime 和 minTime (#6418)

回滚限制

64 位双打聚合器

现在默认使用 64 位双打聚合器（参见#5478）。 Druid 0.11.0 中发布了对 64 位浮点列的支持，因此如果启用此功能，早于 0.11.0 的版本将无法读取数据段。 要禁用并保留旧格式，您需要设置系统范围属性 druid.indexing.doubleStorage=float。

禁用位图索引

0.13.0 添加了对按列禁用位图索引的支持，这可以在位图索引不添加任何值的情况下节省空间。这是通过在维度架构中设置“createBitmapIndex”字段来完成的。使用此选项编写的段将不会向后兼容旧版本的 Druid (#5402)。

行为改变

Java 包名称更改

Druid 的包名称已全部从 io.druid 更改为 org.apache.druid。这会影响启动服务时应运行的 Java 主类的名称，现在是 org.apache.druid.cli.Main。它还可能影响扩展和监视器的安装和配置。

ParseSpec 现在是摄取规范中的必填字段

不再有默认的 ParseSpec（以前是 DelimitedParseSpec）。现在需要指定 parseSpec 摄取规格。如果您之前未提供 parseSpec，则应将其与 "format": "tsv" 一起使用以维持现有行为 (#6310)。

更改为在一个 JDBC 帧中返回的默认最大行数

druid.sql.avatica.maxRowsPerFrame 的默认值从 100k 减少到 5k，以最大限度地减少内存不足错误 (#5409)。

路由到专用于不同时间范围的代理时，路由器行为会发生变化

由于#5595，路由器现在可能会在配置中选择不需要的代理，其中有不同层的代理专门用于不同时间范围的查询。请参阅#1362 进行讨论。

Ruby TimestampSpec 不再忽略毫秒

使用格式为“ruby”的 TimestampSpec 解析的时间戳不再截断毫秒部分。如果您使用此解析器并希望查询粒度为 SECOND，请确保在索引规范中对其进行了适当配置 (#6217)。

ZooKeeper 任务公告的大小小幅增加

数据源名称已添加到 TaskAnnouncement，这将导致 ZooKeeper 中存储的每个任务的数据量略有增加 (#5511)。

将“名称”字段添加到过滤聚合器

“过滤”类型的聚合器现在支持“名称”字段。以前，过滤聚合器继承了它包装的聚合器的名称。如果您为已过滤聚合器和已包装聚合器提供了“名称”字段，则它将更喜欢已过滤聚合器的名称。如果过滤聚合器的名称丢失或为空，它将使用包装聚合器的名称（#6219）。

utf8mb4 现在是推荐的元数据存储字符集

有关升级说明，请使用 ALTER DATABASE 和 ALTER TABLE 指令，如下所述：https://dev.mysql.com/doc/refman/5.7/en/charset-unicode-conversion.html. 有关动机和参考，请参阅#5377 和#5411。

删除了配置属性

  • druid.indexer.runner.tlsStartPort 已被删除（#6194）。
  • druid.indexer.runner.separateIngestionEndpoint 已被删除（#6263）。

扩展开发人员的界面更改

  • 包装已从 io.druid 重命名为 org.apache.druid。所有第三方扩展都需要将其 META-INF/io.druid.initialization.DruidModule 重命名为 org.apache.druid.initialization.DruidModule 并相应更新其扩展的打包 (#6266)。
  • DataSegmentPuller 接口已被删除 (#5461)。
  • java-util 下的许多功能已被删除 (#5461)。
  • Metadata 类的构造函数已更改 (#5613)。
  • ‘spark2’ Maven 配置文件已被删除 (#5581)。

API 弃用

霸主

  • /druid/indexer/v1/supervisor/{id}/shutdown 端点已被弃用，取而代之的是 /druid/indexer/v1/supervisor/{id}/terminate（#6272 和 #6234）。
  • /druid/indexer/v1/task/{taskId}/segments 端点已被弃用 (#6368)。
  • /druid/indexer/v1/task/ID/status 返回的 status 字段已被弃用，取而代之的是 statusCode (#6334)。
  • 摄取调整配置的 reportParseExceptions 和 ignoreInvalidRows 参数已被弃用，取而代之的是 logParseExceptions 和 maxParseExceptions (#5418)。

经纪人

  • /druid/v2/datasources/{dataSourceName}/dimensions 端点已被弃用。应改用段元数据查询或 INFORMATION_SCHEMA SQL 表 (#6361)。
  • /druid/v2/datasources/{dataSourceName}/metrics 端点已被弃用。应改用段元数据查询或 INFORMATION_SCHEMA SQL 表 (#6361)。
