druid 0.6.171

修订 发布时间2015年1月21日 来源apache/druid 英文原文

Druid 0.6.171 是一个错误修复稳定版，主要是为了减少对 Druid 0.7.0 的痛苦更新。展望未来，我们将根据社区的要求向后移植 0.6.x 的修复，并继续开发 0.7.x 的主要功能。

下载

http://static.druid.io/artifacts/releases/druid-services-0.6.171-bin.tar.gz

更新，需要注意的事项

此版本和 0.7.0-RC1 都为 PostgreSQL 作为元数据存储提供了更好的开箱即用支持。为了提供此功能，我们必须对 MySQL 设置的元数据存储中的数据存储方式进行一些小的更改。 在更新到 0.6.171 之前，请确保： 所有 Druid MySQL 元数据表都对所有字符串/文本列使用 UTF-8 编码， Druid MySQL 数据库的默认字符集已更改为 UTF-8。 如果数据库默认字符集不是UTF-8，Druid Coordinator和Overlord将拒绝启动。 要检查列字符编码，请使用 SHOW CREATE TABLE <table>;。 如果默认表编码不是 UTF-8 或者如果任何列使用 UTF-8 以外的任何内容进行编码，则您将需要转换这些表。 要检查数据库默认编码，请使用 SHOW VARIABLES LIKE 'character_set_database'; 如果您尚未对列使用 UTF-8 编码，则可以使用以下命令转换表并更改数据库默认值。请记住，表转换可能需要一段时间（几分钟），并且段加载/切换将在升级期间中断。 在执行升级之前先备份数据库！

ALTER TABLE druid_config    CONVERT TO CHARSET utf8;
ALTER TABLE druid_rules     CONVERT TO CHARSET utf8;
ALTER TABLE druid_segments  CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasks     CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasklogs  CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasklocks CONVERT TO CHARSET utf8;

-- replace druid with your Druid database name here 
ALTER DATABASE druid DEFAULT CHARACTER SET utf8;

改进

我们引入了几种查询优化，主要针对topNs和HLLs 霸主现在可以选择向哪个工人发送任务#904 当最终合并步骤中切换失败时，改进了实时管道工的重试逻辑

错误修复

  • 修复了在多列中搜索相同值的问题
  • 修复了码头默认值以增加线程数量并防止锁定
  • 修复了两次发出查询/等待指标的问题
  • 修复了摄取模式中时间戳和聚合器的默认维度排除
  • 修复了周期粒度的缓存键中丢失的起源
  • 修复了默认 FilteredServerView 实际被过滤的问题
  • 修复了段缓存目录中未正确清理的文件
  • 修复了有时结果无序的问题
  • 修复了 bySegment TopN 查询未在经纪商级别返回的问题
  • 修复了与过滤聚合器相关的一些错误
  • 修复了协调员失去领导权时疯狂的日志记录量
  • 更新了jetty和spymemcached库以进行各种修复
  • 修复了基数聚合器缓存模式问题
  • 修复了协调员和霸主“/status”页面不应重定向到领导者实例的问题
  • 让 postgres 在 0.6.x 中真正开箱即用
