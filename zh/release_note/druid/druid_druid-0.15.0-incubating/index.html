druid 0.15.0-incubating

小版本 发布时间2019年6月27日 来源apache/druid 英文原文

Apache Druid 0.15.0-incubating 包含超过 250 个新功能、性能/稳定性/文档改进以及来自 39 个贡献者的错误修复。主要新功能和改进包括：

  • 新的数据加载器用户界面
  • 支持事务性Kafka主题
  • 新的移动平均线查询
  • 扫描查询的时间顺序
  • 新时刻素描聚合器
  • SQL 增强
  • 路由器的光查找模块
  • 核心ORC扩展
  • 核心GCP扩展
  • 文档改进 完整的更改列表在这里：https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.15.0 此版本的文档位于：http://druid.apache.org/docs/0.15.0-incubating/

亮点

新的数据加载器 UI（批量索引部分）

Druid 有一个新的数据加载器 UI，它与 [Druid Console](http://druid.apache.org/docs/latest/operations/management-uis.html#druid-console) 集成。新的数据加载器 UI 显示一些采样数据，以轻松验证摄取规范并自动生成最终摄取规范。用户应该轻松地发出批量索引任务，而不是自己编写 JSON 规范。 由 @vogievetsky 和 ​​@dclim 分别添加到 https://github.com/apache/incubator-druid/pull/7572 和 https://github.com/apache/incubator-druid/pull/7531, 中。 ## 支持 Kafka 事务主题 Kafka 索引服务现在支持 Kafka 事务主题。 请注意，此更改后仅支持 Kafka 0.11.0 或更高版本。 由 @surekhasaharan 添加于 https://github.com/apache/incubator-druid/pull/6496. ## 新的移动平均线查询 引入了一种新的查询类型来计算[移动平均值](https://en.wikipedia.org/wiki/Moving_average)。 更多详情请参见http://druid.apache.org/docs/0.15.0-incubating/development/extensions-contrib/moving-average-query.html。 由 @yurmix 添加于 https://github.com/apache/incubator-druid/pull/6430. ## 扫描查询的时间排序 扫描查询类型现在支持时间排序。更多详情请参见http://druid.apache.org/docs/0.15.0-incubating/querying/scan-query.html#time-ordering。 由 @justinborromeo 在 https://github.com/apache/incubator-druid/pull/7133. 中添加 ## 新时刻素描聚合器 [矩量草图](https://github.com/stanford-futuredata/momentsketch) 是一种用于近似分位数计算的新草图类型。更多详情请参见http://druid.apache.org/docs/0.15.0-incubating/development/extensions-contrib/momentsketch-quantiles.html。 由 @edgan8 在 https://github.com/apache/incubator-druid/pull/6581. 中添加 ## SQL 增强 Druid 社区一直在努力增强 SQL 支持，现在它不再是实验性的。 ### 新的 SQL 函数 - 已弃用/删除 ### 放弃对自动段合并的支持 不再支持协调器的自动段合并。请改用[自动压缩](http://druid.apache.org/docs/0.15.0-incubating/design/coordinator.html#compacting-segments)。 由 @jihoonson 在 #6883 中添加。 ### 放弃对 `insert-segment-to-db` 工具的支持 在Druid 0.14.x或更早版本中，Druid除了元数据存储之外，还将段元数据（`descriptor.json`文件）存储在深层存储中。这种行为在 0.15.0 中发生了变化，它不再将段元数据文件存储在深度存储中。因此，`insert-segment-to-db` 工具也不再受支持，因为它基于深度存储中的 `descriptor.json` 文件工作。详情请参见ZZPH100​​ZZ。 请注意，如果您使用 HDFS 作为深度存储，并且 0.14.x 或更早版本中缺少 `descriptor.json` 文件，则终止任务将会失败。 由 @jihoonson 添加于 https://github.com/apache/incubator-druid/pull/6911. ### 删除了 SQL 的“useFallback”配置 此选项已被删除，因为它生成不可扩展的查询计划并且不适用于某些 SQL 函数。 由 @gianm 在 https://github.com/apache/incubator-druid/pull/7567. 中添加 ### 为扩展开发人员删除了 `CompressionUtils` 中的公共 API `public static void gunzip(File pulledFile, File outDir)` 已在 https://github.com/apache/incubator-druid/pull/6908 中被 @clintropolis 删除。 ## 其他行为改变 ### 协调器在完成启动之前等待初始化 添加了一个新配置（`druid.coordinator.segment.awaitInitializationOnStart`）以使协调器等待段视图初始化。默认情况下启用此选项。 由 @QiuMM 在 https://github.com/apache/incubator-druid/pull/6847. 中添加 ### 协调器 API 行为更改 协调器定期从元数据存储中轮询段元数据信息并将它们缓存在内存中。在 Druid 0.14.x 或更早版本中，通过协调器 API（`/druid/coordinator/v1/datasources/{dataSourceName}` 和 `/druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}`）删除段会立即更新内存中的段缓存以及元数据存储。但这种行为在 0.15.0 中发生了变化，缓存会根据轮询进行更新，而不是在删除时立即更新。下面的 API 可以通过上面的 API 调用返回删除的段，直到缓存在下一次​​轮询中更新。 - `/druid/coordinator/v1/metadata/datasources/{dataSourceName}` - `/druid/coordinator/v1/metadata/datasources/{dataSourceName}/segments` - `/druid/coordinator/v1/metadata/datasources/{dataSourceName}/segments/{segmentId}` - `/druid/coordinator/v1/metadata/datasources` - `/druid/coordinator/v1/loadstatus` 以下指标还可以包含通过上述 API 调用删除的段，直到在下一次轮询中更新缓存为止。 - `segment/unavailable/count` - `segment/underReplicated/count` @surekhasaharan 在 https://github.com/apache/incubator-druid/pull/7595 中更改了此行为。 ### 列表查找 API 更改 除了动态配置中已知的层之外，`/druid/coordinator/v1/lookups/config` API 现在还会返回集群中当前活动的层列表。 由 @clintropolis 添加于 https://github.com/apache/incubator-druid/pull/7647. ### Zookeeper 损失 使用新配置（`druid.zk.service.terminateDruidProcessOnConnectFail`），Druid 进程可以在与 ZooKeeper 断开连接时自行终止。 由 @michael-trelinski 添加于 https://github.com/apache/incubator-druid/pull/6740. # 从 0.14.0-incubating 及更早版本更新 ##
