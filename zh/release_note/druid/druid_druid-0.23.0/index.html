druid 0.23.0

小版本 发布时间2022年6月23日 来源apache/druid 英文原文

Apache Druid 0.23.0 包含超过 450 个新功能、错误修复、性能增强、文档改进以及来自 81 个贡献者的额外测试覆盖范围。 有关其他详细信息，请参阅完整的更改集。

# 对数组进行分组而不分解数组

# 为第一个/最后一个聚合器中的行比较指定除 __time 列之外的列

您可以使用 LATEST_BY / EARLIEST_BY SQL 函数在 *first/*last 聚合器中传递时间列。这为时间存储为与“__time”不同的列的一部分的情况提供了支持。您还可以指定另一个逻辑时间列。 (#11949) (#12145)

# 查询用户体验的改进

此版本包括多项查询改进：

  • 在失败的 SQL 查询的响应标头中添加了 SQL 查询 ID，以帮助定位错误消息 (#11756)
  • 添加了 DataSketches HLL 的输入类型验证 (#12131)
  • 改进了 JDBC 日志记录 (#11676)
  • 添加了 SQL 函数 MV_FILTER_ONLY 和 MV_FILTER_NONE 来过滤多值字符串维度的行，以分别仅包含提供的值列表或不包含任何值 (#11650)
  • 添加了 ARRAY_CONCAT_AGG 将数组输入聚合到单个数组中 (#12226)
  • 添加了授权使用查询上下文参数的功能 (#12396)
  • 改进了查询 ID，可以更轻松地链接查询和子查询以实现端到端查询可见性 (#11809)
  • 添加了安全除法功能以防止除以 0 (#11904)
  • 您现在可以将查询上下文添加到内部生成的 SegmentMetadata 查询中 (#11429)
  • 在本机表达式处理系统中添加了对 Druid 复杂类型的支持，以使所有 Druid 数据在表达式中可用（#11853、#12016）
  • 当对没有预先存在的字典的字符串或数组值表达式进行分组时，您可以通过 druid.query.groupBy.maxSelectorDictionarySize 控制堆上段级字典的大小。
  • 在 CNF 转换过程中，您可以更好地防止过滤器爆炸 (#12314) (#12324)
  • 您可以通过在查询上下文中将 useNativeQueryExplain 设置为 true 来获得解释 SQL 查询的完整本机查询 (#11908)
  • 您可以让代理忽略实时节点或特定的历史层。 (#11766) (#11732)

# 流媒体摄取

# 用于解析标头和密钥的 Kafka 输入格式

我们引入了 Kafka 输入格式，以便您除了消息内容之外还可以提取标头数据。例如：

  • 事件键字段
  • 事件标题
  • Kafka事件时间戳
  • 存储有效负载的 Kafka 事件值。 (#11630)

# Kinesis 摄取 - 改进

我们在运动摄取方面做出了以下改进

  • 重新分片可能会影响并减慢摄取速度，因为会创建许多中间空分片。这些分片被分配给导致负载分配不平衡的任务。您可以在 kinesis 摄取调整配置中将 skipIgnorableShards 设置为 true 以忽略此类分片。 (#12235)
  • 目前，kinesis 摄取使用 DescribeStream 来获取分片列表。此调用已被弃用并且速度较慢。在此版本中，您可以通过在 kinesis 摄取调整配置中将 useListShards 设置为 true 来切换到较新的 API listShards。 (#12161)

# 本机批量摄取

# 多维度范围分区

多维度范围分区允许用户在任意数量的维度范围上对数据进行分区。它进一步发展了“single-dim”分区背后的概念，现在可以说是最优选的辅助分区，无论是对于查询性能还是存储效率。 (#11848) (#11973)

# 改进的替换数据行为

在之前版本的 Druid 中，如果摄取带有 dropExisting 标志的数据来替换数据，如果没有新数据来替换，Druid 会保留现有数据一段时间。现在，如果您在 ioSpec 中将 dropExisting 设置为 true 并在包含没有数据的时间块的时间范围内摄取数据，则 Druid 使用逻辑删除来掩盖空时间块中的现有数据。 (#12137) 此版本包括对本机批量摄取的多项改进：

  • 当批处理任务完成等待段可用性时，Druid 现在会发出新的指标。 (#11090)
  • 添加了 segmentAvailabilityWaitTimeMs，即任务等待其段被移交给历史节点的持续时间（以毫秒为单位）到 IngestionStatsAndErrorsTaskReportData (#11090)
  • 添加了在摄取过程中保留现有指标的功能 (#12185)
  • 并行本机批处理任务现在可以提供顺序和单相模式的任务报告（例如，与动态分区一起使用）以及单相模式子任务（#11688）
  • 在 druid/indexer/v1/task/{task_id}/reports API 中添加了对 RowStats 的支持，以实现多阶段并行索引任务 (#12280)
  • 修复了并行索引维度分配阶段 OOM 失败的问题 (#12331)
  • 添加了对创建分区边界时处理空维度值的支持 (#11973)

# 总体摄取方面的改进

此版本总体上包括多项摄取改进：

  • 从 IncrementalIndex<AggregatorType> 中删除了模板修饰符，因为不再需要它
  • 您现在可以在摄取期间在 JsonPath 表达式中使用 JsonPath 函数 (#11722)
  • Druid 不再创建段文件的具体化列表并消除文件循环以减少 OOM 问题 (#11903)
  • 在 IndexMerger 的主要“合并”方法中添加了中间持久 IndexSpec (#11940)
  • 如果您传入 ALL，Granularity.granularitiesFinerThan 现在会返回 ALL (#12003)
  • 添加了用于附加任务的配置参数，以允许它们使用共享锁 (#12041)
  • 当无法检索模式时，SchemaRegistryBasedAvroBytesDecoder 现在会抛出 ParseException 而不是 RE (#12080)
  • 将 includeAllDimensions 添加到 dimensionsSpec，以将所有显式维度首先放入 InputRow 中，然后将输入数据中找到的任何其他维度放在首位 (#12276)
  • 添加了在段中存储空列的功能（#12279）

# 压缩

# SQL

# 人类可读且可操作的 SQL 错误消息

在 0.22.1 版本之前，如果您发出不受支持的 SQL 查询，Druid 会抛出非常神秘且无用的错误消息。通过此更改，错误消息恰好包含 Druid 不支持的 SQL 查询部分。例如，如果您运行按时间列以外的维度排序的扫描查询。 (#11911)

# 取消 SQL 查询的 API

我们添加了一个新的 API 来取消 SQL 查询，因此您现在可以像取消本机查询一样取消 SQL 查询。您可以从 Web 控制台使用 API。在以前的版本中，从控制台取消只会关闭 client 连接，而 SQL 查询继续在 Druid 上运行。 (#11643) (#11738) (#11710)

# 改进了 SQL 兼容性

我们对表达式进行了更改，使表达式计算更加符合 SQL 标准。默认情况下禁用此新行为。可以通过将 druid.expressions.useStrictBooleans 设置为 true 来启用它。我们建议启用此行为，因为在某些情况下它的性能也更高。 (#11184)

  • 作为管理员，您现在可以在近似模式下配置 APPROX_COUNT_DISTINCT 和 COUNT(DISTINCT expr) 的实现 (#11181)

# 安全修复

# 支持设置查询上下文的访问控制

如今，用户可以使用任何上下文参数。这可能会导致 1) 如果上下文参数尚未成熟，则会导致糟糕的用户体验；或者 2) 如果敏感参数被滥用，在最坏的情况下甚至会导致查询失败或系统故障，例如 maxSubqueryRows。 Druid 现在能够限制每个用户角色的上下文参数。这意味着，如果您在查询中设置了不允许的上下文参数，则查询将会失败。 可以使用 Druid.auth.authorizeQueryContextParams 启用上下文参数授权。默认情况下禁用此功能，以实现更流畅的升级体验。 (#12396)

# 性能改进

# 摄取

  • 构建堆增量索引时更准确的内存估计。 Druid 现在可以使用（基于任务上下文标志）对聚合行的实际堆占用空间进行更接近的估计，而不是使用最大可能的聚合行大小。这使得索引器能够在执行中间持久之前在内存中容纳更多行。 (#12073)

# SQL

  • 默认情况下启用矢量化虚拟列处理。它将提高大多数查询的性能。 (#12520)
  • 改进了具有大型 IN 过滤器的 SQL 查询的性能。您可以通过减少 SQL 查询上下文中的 inSubQueryThreshold 来获得更好的性能。 (#12357)
  • time_shift 现在已矢量化（#12254）

# 升级到 0.23.0

从 Druid 0.22.x 升级到 0.23.0 时请考虑以下更改和更新。如果您要从 0.22.1 之前的版本进行更新，请参阅相关中间版本的 release note。

# 自动删除段

在 0.23.0 中，现在默认启用段自动终止 (#12187)。新的默认设置应杀死所有超过 90 天的未使用段。如果用户不希望升级时出现此行为，则应明确禁用此行为。这是一个危险的更改，因为根据时间间隔，段在被标记为未使用后将立即被终止。此行为将在下一个德鲁伊版本中恢复或更改。请参阅 (#12693) 了解更多详细信息。

# 其他更改

  • Kinesis 摄取需要对流进行 listShards API 访问。
  • Kafka clients 库已升级到 3.0.0 (#11735)
  • 动态协调器配置，percentOfSegmentsToConsiderPerMove 已被弃用，并将在 Druid 的未来版本中删除。它正在被 (#11257) 中引入的新分段拣选策略所取代。目前，此新策略默认处于关闭状态，但如果将动态协调器配置 useBatchedSegmentSampler 设置为 true，则可以打开该策略。如此设置将禁用已弃用的percentOfSegmentsToConsiderPerMove。在未来的版本中，useBatchedSegmentSampler 将永久变为 true。 (#11960)

# 开发者通知

# 将航空公司依赖项更新为 2.x

https://github.com/airlift/airline 不再维护，因此 druid 已升级到 https://github.com/rvesse/airline（航空公司 2）以主动使用 维护版本，同时最大限度地减少重大更改。 这是向后不兼容的更改，依赖于 CliCommandCreator 扩展点的自定义扩展也需要更新。 12270

# 对于未知的主管或任务返回 404 而不是 400

当未找到主管或任务时，较早的主管/任务端点返回 400。这个状态码对于第三个系统来说并不友好且令人困惑。根据HTTP状态码的定义，404就是这种情况的正确代码。因此，我们将状态代码从 400 更改为 404 以消除歧义。这些端点的任何 clients 应相应地更改响应代码处理。 11724

# 当SQL查询无法规划时返回400而不是500

任何无法被 Druid 规划的 SQL 查询都不会被视为错误请求。对于此类查询，我们现在返回 400。使用 SQL API 的开发人员应根据需要更改响应代码处理。 12033

# ResponseContext 重构

0.23.0 以突破性的方式改变了 ResponseContext 及其按键。响应上下文的先前版本建议在枚举中定义键，然后注册。此版本建议将键定义为对象，然后注册。有关详细信息，请参阅 ResponseContext 类本身。 (#11828)
