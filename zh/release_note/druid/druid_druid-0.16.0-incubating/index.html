druid 0.16.0-incubating

小版本 发布时间2019年9月25日 来源apache/druid 英文原文

Apache Druid 0.16.0-incubating 包含来自 50 个贡献者的 350 多个新功能、性能增强、错误修复和主要文档改进。查看完整的更改列表 和标记到里程碑的所有内容。

亮点

# 性能

#“矢量化”查询处理

0.16.0 中新增了一个实验性“矢量化”查询执行引擎，它可以在 1.3-3x 范围内为时间序列和 group by v2 查询提供速度提升。它的运行原理是对行进行批处理操作，而不是一次处理一行，例如批量迭代位图而不是每行，批量读取列值，批量过滤，批量聚合值等等。这会显着减少方法调用、更好的内存局部性并提高缓存效率。 这是一个实验性功能，但我们将其视为 Druid 查询处理的前进之路，并且随着我们继续改进和填补即将发布的版本中缺失的功能，我们很高兴收到反馈。

  • 只有 timeseries 和 groupBy 有矢量化引擎。
  • GroupBy 尚不处理除“全部”之外的多值维度或粒度。
  • 矢量游标无法处理虚拟列或降序。
  • 任何地方都不支持表达式：不作为聚合器、虚拟函数或过滤器的输入。
  • 只有一些聚合器具有矢量化实现：“count”、“doubleSum”、“floatSum”、“longSum”、“hyperUnique”和“filtered”。
  • 只有某些过滤器具有矢量化匹配器：“selector”、“bound”、“in”、“like”、“regex”、“search”、“and”、“or”和“not”。
  • “默认”以外的尺寸规格尚不工作（无提取功能或过滤尺寸规格）。 可以通过将查询上下文设置为 "vectorize": true 来启用该功能（默认为 false）。这适用于 Druid SQL 和本机查询。当设置为true时，如果可能的话将使用矢量化；否则，Druid 将回退到其非矢量化查询引擎。您还可以将其设置为 "force"，如果查询无法完全矢量化，则会返回错误。这有助于确认确实正在使用矢量化。 您可以通过设置 vectorSize 查询上下文参数（默认为 1000）来控制执行期间的块大小。 https://github.com/apache/incubator-druid/issues/7093 https://github.com/apache/incubator-druid/pull/6794

# GroupBy 基于数组的结果行

groupBy v2 查询现在使用结果行的基于数组的表示，而不是 Druid 之前版本使用的基于映射的表示。这可以更快地生成和处理结果集。开箱即用后，此更改是不可见的并且向后兼容；您无需更改任何配置即可获得这种更高效格式的好处，并且不会对缓存结果产生影响。在内部，代理将_始终_在向历史记录发出的查询中自动使用此格式。默认情况下，结果将被转换回代理处现有的基于“地图”的格式，然后再将其发送回 client。 但是，如果您想避免这种转换的开销，并获得更快的结果，可以在查询上下文上设置 resultAsArray 以直接传递基于新数组的结果行格式。架构如下，按顺序排列：

  • 时间戳（可选；仅当粒度！= ALL 时）
  • 尺寸（按顺序排列）
  • 聚合器（按顺序）
  • 后聚合器（可选；按顺序，如果存在） https://github.com/apache/incubator-druid/issues/8118 https://github.com/apache/incubator-druid/pull/8196

# “次要”压缩

Kafka 索引服务和压缩的用户以及获得少量最新数据的用户可以通过称为“次要”压缩的新概念形式找到_巨大_改进。通过对数据段的版本控制方式进行内部更改，次要压缩基于索引时基于“段”的锁定的思想，而不是当前的 Druid 锁定行为（现在称为“时间块”锁定）。正如您所期望的，段锁定仅允许锁定正在压缩的段，同时仍然允许新的“附加”索引任务（如 Kafka 索引任务）继续运行并同时创建新段。如果您获得大量延迟数据，这将是一件大事，因为当前的行为会导致压缩任务匮乏，因为更高优先级的实时任务会占用锁。这种阻止压缩任务优化数据源段大小的行为会导致整体性能下降。 要启用段锁定，您需要在任务上下文中将 forceTimeChunkLock 设置为 false，或在 Overlord 配置中设置 druid.indexer.tasklock.forceTimeChunkLock=false。不过，注意，启用此功能后，由于段版本控制的变化，内置没有回滚路径，因此一旦升级到0.16，就无法降级到旧版本的Druid。因此，我们“强烈建议”在启用此功能之前确认 Druid 0.16 在您的集群中稳定。 它有一个不起眼的名字，但次要压缩的变化是深入的，并且不可能充分描述在这些 release note 中驱动此变化的机制，因此请查看提案和 PR 以获取更多详细信息。 https://github.com/apache/incubator-druid/issues/7491 https://github.com/apache/incubator-druid/pull/7547

# Druid“索引器”流程

新的Indexer进程是MiddleManager + Peon任务执行系统的替代方案。索引器不是为每个任务分叉一个单独的 JVM 进程，而是在单个 JVM 进程中将任务作为单独的线程运行。 Indexer 的设计比 MiddleManager + Peon 系统更容易配置和部署，并且能够更好地实现跨任务的资源共享。 索引器的优点在于，它允许在所有正在运行的索引任务线程之间共享查询处理资源、查找、缓存的身份验证/授权信息等，从而使每个单独的任务可以访问更大的资源池，并且比 Peon 执行模型（每个任务在其自己的进程中隔离）执行的冗余操作要少得多。 使用 Indexer 确实有一个缺点：Peon 进程提供的进程隔离的丢失意味着单个任务可能会影响该 Indexer 上所有正在运行的索引任务。 druid.worker.globalIngestionHeapLimitBytes 和 druid.worker.numConcurrentMerges 配置旨在帮助最大限度地减少这种情况。此外，索引器进程的任务日志将与索引器进程日志内联，并且不会持久保存到深度存储中。 您可以在启动服务时通过将 server indexer 作为命令行参数提供给 org.apache.druid.cli.Main 来开始使用索引。要使用 Indexer 代替 MiddleManager 和 Peon，您应该能够将配置中的值调整到 Indexer 配置中，将 druid.indexer.fork.property. 配置直接提升到 Indexer，并根据 Peon 大小乘以任务槽数来调整堆和直接内存的大小（与 MiddleManager 不同，它不接受配置 druid.indexer.runner.javaOpts 或 druid.indexer.runner.javaOptsArray）。有关详细信息，请参阅索引器文档。 https://github.com/apache/incubator-druid/pull/8107

# 使用 shuffle 的本机并行批量索引

在 0.16.0 中，Druid 的 index_parallel 本机并行批量索引任务现在支持“完美”汇总，并实现了 2 阶段洗牌过程。 第 1 阶段的任务在基于标准时间的段粒度分区之上执行行的辅助分区，为每个分区创建一个中间数据段。第 2 阶段任务分别分配一组在第 1 阶段创建的分区，并将收集并组合属于该分区的中间数据段集，使其在构建最终段时实现完整的汇总。目前，仅支持基于哈希的分区。 这可以通过在 tuningConfig 中将 forceGuaranteedRollup 设置为 true 来启用；还必须设置 partitionsSpec 中的 numShards 和 granularitySpec 中的 intervals。 Druid MiddleManager（或新的 Indexer）进程对这些索引任务承担了新的责任，将阶段 1 的中间分区段输出提供给阶段 2 任务，因此根据配置和集群大小，可能需要调整 MiddleManager jvm 配置以增加堆分配和 http 线程。这些数字预计会随着集群大小而扩展，因为参与洗牌的所有 MiddleManager 或 Indexer 进程都需要能够相互通信，但我们预计占用空间不会比当前大得多。乐观的是，我们建议尝试使用现有配置，并仅在遇到问题时增加堆和 http 线程计数。 https://github.com/apache/incubator-druid/issues/8061

# 对多值字符串列的 SQL 和本机表达式支持

Druid SQL 和本机查询表达式“虚拟列”现在可以正确利用多值字符串列，可以将它们作为单独的 VARCHAR 值进行操作，以与本机 Druid 查询行为进行奇偶校验，或者作为数组类型，使用一组新的多值字符串函数。请注意，到目前为止，仅在查询时表达式中支持此功能；未来版本将提供通过 transformSpec 在摄取时使用多值表达式的功能。添加的函数和行为更改的完整列表太大，无法在此列出，因此请查看 SQL 和 表达式 文档以了解更多详细信息。 https://github.com/apache/incubator-druid/issues/7525 https://github.com/apache/incubator-druid/pull/7588 https://github.com/apache/incubator-druid/pull/7950 https://github.com/apache/incubator-druid/pull/7973 https://github.com/apache/incubator-druid/pull/7974 https://github.com/apache/incubator-druid/pull/8011

# TIMESTAMPDIFF

为了补充可以按时间单位修改时间戳的 TIMESTAMPADD，可以计算两个时间戳之间的有符号时间单位数的 TIMESTAMPDIFF。有关语法信息，请查看 SQL 文档 https://github.com/apache/incubator-druid/pull/7695

# TIME_CEIL

TIME_CEIL 是 CEIL 功能的特定时间、更灵活的版本，也已添加到 Druid 0.16.0 中。此函数可以将时间戳按 ISO8601 周期向上舍入，例如 P3M（季度）或 PT12H（半天），可选地针对特定时区。 请参阅 SQL 文档 了解更多信息。 https://github.com/apache/incubator-druid/pull/8027

# IPv4

Druid 0.16.0 还添加了专门的 SQL 运算符和本机表达式，用于处理点分十进制字符串或整数格式的 IPv4 互联网地址。新的运算符是 IPV4_MATCH(address, subnet)、IPV4_PARSE(address) 和 IPV4_STRINGIFY(address)，它们分别可以将 IP 地址与 CIDR 表示法的子网进行匹配、将点分十进制字符串格式转换为整数格式、将整数格式转换为点分十进制字符串格式。 请参阅 SQL 文档 了解详细信息。 https://github.com/apache/incubator-druid/pull/8223

# NVL

为了提高对具有其他数据库经验的 Druid 用户的宽容度和 SQL 兼容性，以 NVL 的形式添加了 COALESCE 函数的别名，某些 SQL 方言会使用该别名。 详细信息请参阅 SQL 文档 https://github.com/apache/incubator-druid/pull/7965

# 更新了网站文档

Druid 网站的文档部分进行了重大升级，过渡到使用 Docusaurus，这创建了比我们当前更美观、更实用的页面。现在，每个文档页面都有一个左侧可折叠目录，显示整个文档的概要，右侧目录则显示该特定文档页面的概要，从而极大地提高了导航性。 除此之外，摄取文档也已完全更新，从新的 ingestion/index.md 文档开始，该文档介绍了所有关键的摄取规范概念，并描述了最流行的摄取方法。这是对许多现有文档页面进行的急需的返工，这些文档页面随着时间的推移而有机增长，并且变得难以遵循，变成一组更简单、更少、更大、更多交叉引用的页面。他们也更加“固执己见”，推动新人转向 Kafka、Kinesis、Hadoop 和本机批量摄取。他们讨论了宁静，但没有将其作为强烈推荐的东西来呈现，因为它在最小维护模式下有效。 查看这些改进（以及更多）此处。 https://github.com/apache/incubator-druid/pull/8311

# statsd-emitter

statsd-emitter 扩展有一个新选项 druid.emitter.statsd.dogstatsdServiceAsTag，它允许将 Druid 服务名称作为“标签”发出，例如 druid_service:druid/broker，而不是 druid.broker.query.time 中的度量名称的一部分。使用 druid 作为前缀。因此，druid.broker.query.time 的示例将改为 druid.query.time，从而允许跨 Druid 服务类型整合指标并通过标签进行区分。 druid.emitter.statsd.dogstatsd 必须设置为 true 才能使该设置生效。有关更多详细信息，请参阅文档。 https://github.com/apache/incubator-druid/pull/8238 https://github.com/apache/incubator-druid/pull/8472

# 新扩展：druid-tdigestsketch

Druid 0.16 中添加了一组新的基于 t-digest 的近似草图聚合器，用于计算分位数等。 T-digest 专为并行编程用例（例如分布式聚合或映射缩减作业）而设计，通过使两个中间 t-digest 的组合变得简单而高效。它可以补充 Apache Datasketches 扩展和 moment sketch 扩展提供的现有算法。有关更多详细信息，请参阅扩展文档。 https://github.com/apache/incubator-druid/issues/7303 https://github.com/apache/incubator-druid/pull/7331

# 新扩展：druid-influxdb-emitter

0.16 中还添加了一个新的 Druid 发射器扩展，允许通过 HTTP 将 Druid 指标发送到 influxdb。目前，此发射器仅向 InfluxDB 发送服务指标事件（有关指标列表，请参阅 Druid 指标）。当触发指标事件时，它会被添加到事件队列中。经过可配置的时间后，队列上的事件将转换为 InfluxDB 的线路协议并 POST 到 InfluxDB HTTP API。此时整个队列都被刷新。当发射器关闭时，队列也会被刷新。有关详细信息，请参阅扩展文档。 https://github.com/apache/incubator-druid/pull/7717

# 微调您的工作负载

除了实验性矢量化查询引擎和新的索引器进程类型之外，0.16 还具有一些附加功能，可通过实验对索引和查询性能进行潜在的微调。

# 控制索引中间段压缩

首先，在索引过程中保留中间段时能够独立控制使用（或禁用）压缩方式。此配置可用于 indexSpec 属性，并且可以添加到 tuningConfig 中，如下所示：

"indexSpecForIntermediatePersists": {
  "dimensionCompression": "uncompressed",
  "metricCompression": "none"
}

例如，完全禁用中间段的压缩。考虑“未压缩”中间段的一个潜在原因是，在发布中间段并将其推送到深度存储之前，减少执行中间段最终合并所需的 Java“直接”内存量，因为从未压缩列读取数据不需要用于解码 lz4 和其他编码列的 64kb 直接缓冲区。当然，这是存储空间和页面缓存占用空间的权衡，因此我们建议在确定用于生产工作负载的配置之前进行试验。 https://github.com/apache/incubator-druid/pull/7919

# 控制过滤器位图索引利用率

位图索引通常可以极大地提升 Druid 的性能，但在某些情况下可能会导致查询速度变慢，特别是在基数维度非常高的过滤器的计算成本很高的情况下。在 Druid 0.16 中，一种新机制可以对何时使用位图索引以及何时执行过滤器作为行扫描进行手动控制，并且现在可以在每个过滤器、每个查询的基础上使用。大多数过滤器都会接受新属性 filterTuning，它可能看起来像这样：

"filterTuning": {
  "useBitmapIndex": true
}

useBitmapIndex 如果设置为 false 将不允许过滤器使用位图索引。此属性是可选的，如果未提供 filterTuning，则默认行为保持不变。请注意，此功能_未_记录在面向用户的文档中，被视为实验性的，并且可能在任何未来版本中发生更改。 https://github.com/apache/incubator-druid/pull/8209

# 请求日志记录

如果您想启用 Druid 请求日志记录，但使用 Druid SQL 并发现它们由于所有元数据查询而有点过于繁琐，那么 0.16 很幸运，因为新的配置选项允许有选择地从请求日志记录中屏蔽特定类型的查询。该选项 druid.request.logging.mutedQueryTypes 接受由 Druid 的 本机 JSON 查询 API 定义的“queryType”字符串列表，并且默认为空列表（因此不会忽略任何内容）。例如，

druid.request.logging.mutedQueryTypes=["segmentMetadata", "timeBoundary"]

将静音 segmentMetadata 和 timeBoundary 查询的所有请求日志。 https://github.com/apache/incubator-druid/pull/7562

# 升级到 Druid 0.16.0

# S3任务日志存储

升级到 0.16.0 后，任务日志将需要与将段推送到深度存储相同的 S3 权限，其中有一些额外的逻辑可能会获取存储桶所有者（通过获取存储桶 ACL）并设置段对象的 ACL 以授予存储桶所有者完全访问权限。如果您希望避免提供这些附加权限，可以通过设置 druid.indexer.logs.disableAcl=true 保留现有行为。 https://github.com/apache/incubator-druid/pull/7907

# Druid SQL

Druid SQL 现在默认在路由器上启用。请注意，这可能会给代理进程带来一些额外的压力，因为需要额外的元数据查询来维护查询计划的数据源模式，并且可以通过设置 druid.sql.enable=false 来禁用它以保留以前的行为。 https://github.com/apache/incubator-druid/pull/7808

# Druid SQL查找函数

使用 LOOKUP 函数的 Druid SQL 查询现在将利用作为一对一转换的 injective 查找，这允许执行优化，避免将查找评估下推到历史进程，而是允许稍后完成转换。此更改的缺点是，被错误定义为一对一但实际上在评估时并非一对一转换的查找将产生不正确的查询结果。 https://github.com/apache/incubator-druid/pull/7655

# 协调器元数据 API 更改

协调器提供的元数据 API 已被修改，以提供更一致的 HTTP 响应。这些更改很小，但如果您依赖于特定的 API，则向后不兼容。

  • 发布 /druid/coordinator/v1/datasources/{dataSourceName}
  • 删除 /druid/coordinator/v1/datasources/{dataSourceName}
  • 发布 /druid/coordinator/v1/datasources/{dataSourceName}/markUnused
  • 发布 /druid/coordinator/v1/datasources/{dataSourceName}/markUsed 现在，当没有更改任何段时，返回 {"numChangedSegments": N} 形式的 JSON 对象，而不是 204（空响应）。另一方面 另一方面，不会返回 500（服务器错误），而是返回 204（空响应）。
  • 发布 /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • 删除 /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId} 现在返回 {"segmentStateChanged": true/false} 形式的 JSON 对象。 /druid/coordinator/v1/metadata/datasources?includeDisabled 现在是 /druid/coordinator/v1/metadata/datasources?includeUnused。 includeDisabled 仍然被接受，但在日志中发出警告。 https://github.com/apache/incubator-druid/pull/7653

# 压缩任务

keepSegmentGranularity 选项将创建压缩任务，在压缩之前忽略段的间隔边界，但已被弃用，因为它在大多数情况下不是很有用。如果您确实发现此行为有用，仍然可以通过将 segmentGranularity 设置为 ALL 来实现。 https://github.com/apache/incubator-druid/pull/7747 通过协调器支持“自动”压缩的所有 Druid 版本都存在一个已知问题，其中自动压缩可能会因重复尝试相同的时间间隔而陷入困境。现在可以通过设置 targetCompactionSizeBytes 在 0.16 中缓解此问题，但在使用 maxRowsPerSegment 或 maxTotalRows 时仍然存在。 Druid 的未来版本将彻底解决这个问题。 https://github.com/apache/incubator-druid/issues/8481 https://github.com/apache/incubator-druid/pull/8495

# 索引规范

所有本机索引任务类型现在都使用 PartitonsSpec 来定义辅助分区，以与其他索引任务类型保持一致。这些更改并非向后不兼容，但用户应考虑将 ZZPH100​​ZZ、maxTotalRows、numShards 和 partitionDimensions 迁移到本机、kafka 和 kinesis 索引任务的分区规范。 https://github.com/apache/incubator-druid/pull/8141

# Kafka 索引

Druid 0.12 中引入了 Apache Kafka 索引服务的分段增量发布，此时现有的 Kafka 索引服务被保留为“遗留”格式，以允许从旧版本的 Druid 进行滚动更新。这个“遗留”代码库现已在 Druid 0.16.0 中删除，这意味着不支持从早于 0.12.0 的 Druid 版本进行滚动更新。 https://github.com/apache/incubator-druid/pull/7735

# Avro 扩展

为了清理依赖关系，fromPigAvroStorage 选项已从 Druid 0.16 的 Apache Avro 扩展中删除。此选项提供了 GenericData.Array 的特殊转换，但此列类型现在将由默认的 List 实现处理。 https://github.com/apache/incubator-druid/pull/7810

# Kerberos 扩展

druid.auth.authenticator.kerberos.excludedPaths 被 druid.auth.unsecuredPaths 取代，适用于所有身份验证器/授权器，因此请改用此配置属性。 https://github.com/apache/incubator-druid/pull/7745

# Zookeeper

设置 druid.zk.service.terminateDruidProcessOnConnectFail 已被删除，这是现在的默认行为 - 当发生未处理的 Curator client 异常时，Druid 进程将退出，而不是继续在“僵尸”状态下运行。 此外，新的可选设置 druid.zk.service.connectionTimeoutMs 已连接到 Curator client connectionTimeoutMs，现在可以进行自定义设置。默认情况下，它将继续使用 Curator 默认值 15000 毫秒。 https://github.com/apache/incubator-druid/pull/8458

# 实时进程

已弃用的独立“实时”进程已从 Druid 中删除。一段时间以来，人们一直不鼓励使用此功能，但现在 middleManager 和新的 index 进程应该可以处理所有实时索引任务。 https://github.com/apache/incubator-druid/pull/7915 https://github.com/apache/incubator-druid/pull/8020
