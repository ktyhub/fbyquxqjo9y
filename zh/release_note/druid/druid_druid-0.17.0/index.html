druid 0.17.0

小版本 发布时间2020年1月27日 来源apache/druid 英文原文

Apache Druid 0.17.0 包含来自 52 个贡献者的 250 多个新功能、性能增强、错误修复和主要文档改进。查看完整的更改列表 和标记到里程碑的所有内容。

亮点

批量摄取改进

Druid 0.17.0 对原生批量摄取系统进行了重大更新。此更新添加了内部框架以支持非文本二进制格式，并初步支持 ORC 和 Parquet。此外，本机批处理任务现在可以从 HDFS 读取数据。 此返工更改了在摄取任务中指定摄取源和数据格式的方式。要使用新功能，请参阅有关InputSources和InputFormats的文档。 详细信息请参阅以下文档： https://druid.apache.org/docs/0.17.0/ingestion/data-formats.html#input-format https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#input-sources https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#partitionsspec https://github.com/apache/druid/issues/8812

用于并行本机批量摄取的单维度范围分区

并行索引任务现在支持 single_dim 类型分区规范，该规范允许在单个维度上进行基于范围的分区。 详情请参见https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html。

压缩变化

并行索引任务拆分提示

并行索引任务现在在 tuningConfig 中有一个新配置 splitHintSpec，允许操作员提供提示来控制每个第一阶段子任务读取的数据量。当前有一种分割提示规范类型 SegmentsSplitHintSpec，用于重新摄取 Druid 片段。

并行自动压缩

自动压缩现在可以使用并行索引任务，从而实现更大的压缩吞吐量。 为了控制并行度，自动压缩 tuningConfig 具有新参数 maxNumConcurrentSubTasks 和 splitHintSpec。 详情请参见https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration。 https://github.com/apache/incubator-druid/pull/8570

有状态自动压缩

自动压缩现在使用partitionSpec来跟踪先前压缩任务所做的更改，从而允许协调器减少冗余压缩操作。 详情请参见https://github.com/apache/druid/issues/8489。 如果您启用了自动压缩，请在升级前参阅“升级到 Druid 0.17.0”部分中“状态自动压缩更改”下的信息。

代理上的并行查询合并

Druid 代理现在可以使用多个线程并行合并查询结果。 有关如何配置此新功能的详细信息，请参阅配置参考 的 Broker 部分中的 druid.processing.merge.useParallelMergePool。 默认情况下启用并行合并（由 druid.processing.merge.useParallelMergePool 属性控制），并且大多数用户不必更改配置参考中描述的任何高级配置属性。 此外，可以使用查询上下文在每个查询的基础上控制合并并行性。有关新查询上下文参数的信息可以在 https://druid.apache.org/docs/0.17.0/querying/query-context.html. 中找到 https://github.com/apache/incubator-druid/pull/8578

SQL 兼容的 null 处理

在0.17.0中，我们添加了Druid的SQL兼容空处理模式的官方文档。 详情请参见https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling和https://druid.apache.org/docs/0.17.0/design/segments.html#sql-compatible-null-handling。 此先前未记录的模式中存在的几个错误已得到修复，特别是在数字列中的空处理方面。我们建议用户在升级到 0.17.0 后开始考虑将其集群过渡到这种新模式。 0.17.0 中修复的空处理错误的完整列表可以在 https://github.com/apache/druid/issues?utf8=%E2%9C%93&q=label%3A%22Area+-+Null+Handling%22+milestone%3A0.17.0+ 中找到

LDAP 扩展

Druid 现在支持 LDAP 身份验证。通过将 LDAP 组映射到 Druid 角色，还支持使用 LDAP 组进行授权。

  • LDAP 身份验证通过指定 LDAP 类型凭证验证器来处理。
  • 通过指定LDAP类型的角色提供者并在Druid中定义LDAP组->Druid角色映射来处理使用LDAP的授权。 LDAP 集成需要 druid-basic-security 核心扩展。详情请参见https://druid.apache.org/docs/0.17.0/development/extensions-core/druid-basic-security.html。 由于这是第一个支持 LDAP 的版本，并且 LDAP 生态系统多种多样，因此可能尚不支持某些 LDAP 用例和功能。如果您需要增强此新功能，请提出问题。 https://github.com/apache/incubator-druid/pull/6972

Dropwizard 发射器

新的 Dropwizard 指标发射器已作为 contrib 扩展添加。 目前支持的 Dropwizard 指标类型有计数器、仪表、仪表、计时器和直方图。可以使用控制台或 JMX 报告器发出这些指标。 详情请参见https://druid.apache.org/docs/0.17.0/design/extensions-contrib/dropwizard.html。 https://github.com/apache/incubator-druid/pull/7363

自我发现资源

所有 Druid 服务中都添加了一对新端点，这些端点返回有关 Druid 服务是否已从中央服务发现机制（当前为 ZooKeeper）收到服务已添加到集群的确认信息的信息。这些端点可用作运行状况/就绪检查。 新的端点是：

  • /status/selfDiscovered/status
  • /status/selfDiscovered 详情请参见德鲁伊【API参考】(https://druid.apache.org/docs/0.17.0/operations/api-reference.html)。 https://github.com/apache/incubator-druid/pull/6702 https://github.com/apache/incubator-druid/pull/9005

主管系统表

任务主管（例如 Kafka 或 Kinesis 主管）现在记录在新 sys.supervisors 表的系统表中。 详情请参见https://druid.apache.org/docs/0.17.0/querying/sql.html#supervisors-table。 https://github.com/apache/incubator-druid/pull/8547

延迟加载的快速历史启动

添加了新的历史布尔配置属性 druid.segmentCache.lazyLoadOnStart。 这个新属性允许历史记录将段的加载推迟到第一次查询该段为止，这可以显着减少具有大量段的集群的历史启动时间。 详细请参见【配置参考】(https://druid.apache.org/docs/0.17.0/configuration/index.html)。 https://github.com/apache/incubator-druid/pull/6988

历史段缓存分布变化

添加了新的历史属性 druid.segmentCache.locationSelectorStrategy。 如果 druid.segmentCache.locations 中指定了多个段存储位置，则新的 locationSelectorStrategy 属性允许用户指定使用什么策略来填充这些位置。当前支持的选项是 roundRobin 和 leastBytesUsed。 详细请参见【配置参考】(https://druid.apache.org/docs/0.17.0/configuration/index.html)。 https://github.com/apache/incubator-druid/pull/8038

新的准备端点

添加了新的代理端点：/druid/broker/v1/readiness。 添加了新的历史端点：/druid/historical/v1/readiness。 这些端点与现有的 /druid/broker/v1/loadstatus 和 /druid/historical/v1/loadstatus 端点类似。 它们的不同之处在于，它们不需要身份验证/授权检查，并且它们只返回 200 成功或 503 HTTP 响应代码，而不是 JSON 正文。 https://github.com/apache/incubator-druid/pull/8841

支持基于MiddleManager类别的任务分配

现在可以为每个 MiddleManager 定义一个“类别”名称属性。添加了类别感知的新工作人员选择策略，允许用户根据配置的类别控制如何将任务分配给 MiddleManager。 请参阅配置参考中druid.worker.category的文档，以及以下链接，了解更多详细信息： https://druid.apache.org/docs/0.17.0/configuration/index.htmlEqual-Distribution-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#Fill-Capacity-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#WorkerCategorySpec https://github.com/apache/druid/pull/7066

安全漏洞更新

大量依赖项已更新到新版本以解决安全漏洞。 详情请参阅下面的 PR：

  • https://github.com/apache/incubator-druid/pull/8878
  • https://github.com/apache/incubator-druid/pull/8980

升级为德鲁伊0.17.0

Select 原生查询已被替换

已弃用的 Select 本机查询类型已在 0.17.0 中删除。 如果您有使用 Select 的本机查询，则需要将其修改为使用 Scan。有关语法和输出格式的详细信息，请参阅扫描查询文档 (https://druid.apache.org/docs/0.17.0/querying/scan-query.html)。 对于使用 Select 的 Druid SQL 查询，无需进行任何更改； SQL 规划器已经在选择查询的幕后使用扫描查询类型。 https://github.com/apache/incubator-druid/pull/8739

旧控制台已被删除

旧版协调器和霸主控制台已被删除，并已替换为协调器和霸主上的新 Web 控制台。 https://github.com/apache/incubator-druid/pull/8838

Calcite 1.21 升级，Druid SQL null 处理

德鲁伊 0.17.0 将方解石更新至版本 1.21。这个较新版本的 Calcite 可以进行额外的优化，在规划查询时假定符合 SQL 的空处理行为。 如果您使用 Druid SQL 并依赖 null 处理行为，请阅读 https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling 中的信息，并在升级之前确保您的 Druid 集群在兼容 SQL 的 null 处理模式下运行。 https://github.com/apache/incubator-druid/pull/8566

日志记录调整

Druid 0.17.0 已经整理了它的生命周期、查询和摄取日志记录。 请参阅 https://github.com/apache/incubator-druid/pull/8889 了解详细的更改列表。如果您依赖特定日志消息进行外部集成，请在升级之前查看新的日志记录更改。 当日志记录设置为 DEBUG 级别时，仍然可以看到完整的日志消息集。示例集群中 conf/druid 下的 _common 配置文件夹中提供了模板 log4j2 配置文件，显示如何启用每个包的 DEBUG 日志记录。

有状态自动压缩更改

0.17.0 中的自动压缩调度逻辑跟踪 Druid 元数据存储中的附加段分区信息，这些信息在旧版本中不存在。此信息用于确定一组段是否已在集群当前的自动压缩配置下进行压缩。 当这个新的元数据不存在时，将始终安排一组段进行初始压缩，并且将在压缩后创建新的元数据，如果自动压缩配置未更改，则允许调度程序稍后跳过它们。 由于在 0.17.0 之前不存在此附加段分区元数据，因此自动压缩调度逻辑将在升级到 0.17.0 后重新压缩数据源中的所有段。 对启用了自动压缩的每个数据源的整个段集进行重新压缩意味着：

  • 升级后会有一个过渡期，此时排队的总压缩任务将比正常情况下多
  • 随着整个段集重新压缩，深度存储的使用量将会增加（旧的段集仍然保留在深度存储中，除非明确删除）。 建议用户注意计划压缩任务的临时增加以及对深度存储使用的影响。有关删除旧段的文档位于 https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#deleting-data

targetCompactionSizeBytes 属性已删除

targetCompactionSizeBytes 属性已从压缩任务和自动压缩配置中删除。对于自动压缩，maxRowsPerSegment 现在是强制配置。对于非自动压实任务，可以使用任何 partitionsSpec。 https://github.com/apache/incubator-druid/pull/8573

压缩任务调整配置

由于 #8570 引入的并行自动压缩更改，任何手动提交的压缩任务规范都需要更新为在tuningConfig部分使用index_parallel类型而不是索引。这些规格更改应在集群升级到 0.17.0 后应用。 更新后现有的自动压缩配置可以保持不变；自动压缩将创建非并行压缩任务，直到自动压缩配置更新为使用升级后的并行性。 为了控制并行度级别，自动压缩 tuningConfig 具有新参数 maxNumConcurrentSubTasks 和 splitHintSpec。 详情请参见https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration。

压缩任务 ioConfig

压缩任务现在需要任务规范中的 ioConfig。 详情请参见ZZPH100​​ZZ。 ioConfig 不必添加到现有的自动压缩配置中，升级后的协调器将自动创建带有 ioConfig 部分的任务规范。 https://github.com/apache/incubator-druid/pull/8571

重命名分区规范字段

分区规范中的 targetPartitionSize 和 maxSegmentSize 字段已被弃用。它们已分别更名为targetNumRowsPerSegment和maxRowsPerSegment。 https://github.com/apache/incubator-druid/pull/8507

缓存指标默认关闭

缓存指标现在默认处于禁用状态。要启用缓存指标，请将 "org.apache.druid.client.cache.CacheMonitor" 添加到 druid.monitoring.monitors 属性。 https://github.com/apache/incubator-druid/pull/8561

主管 API 已更改为与任务 API 一致

主管任务规范现在应将 dataSchema、tuningConfig 和 ioConfig 部分作为 spec 字段的子字段。请参阅 https://github.com/apache/incubator-druid/pull/8810 示例。 0.17.0 仍接受旧格式。

段 API 语义更改

协调器上的 /datasources/{dataSourceName}/segments 端点现在返回指定间隔内的所有使用的段（包括遮蔽的段），而不仅仅是可见的段。 https://github.com/apache/incubator-druid/pull/8564

HttpEmitterConfig 基本身份验证的密码提供程序

druid.emitter.http.basicAuthentication 属性现在接受密码提供程序。如果使用 HTTP 发射器，我们建议更新您的配置以使用密码提供程序。 https://github.com/apache/incubator-druid/pull/8618

多值表达式变换变化

在表达式中重用多值列将不再导致不必要的笛卡尔爆炸。详情请参阅以下链接。 https://github.com/apache/druid/issues/8947 https://github.com/apache/incubator-druid/pull/8957

滚动升级期间的 Kafka/Kinesis 摄取

在滚动升级期间，如果有运行 0.17.0 的任务和运行旧版本的霸主，并且任务从其流中读取数据取得了进展，但拒绝了它看到的所有记录（例如，所有记录都无法解析），则当该任务使用其当前流偏移量更新霸主时，您将在运行旧版本的霸主上看到 NullPointerExceptions。 此前，该区域存在一个错误 (https://github.com/apache/incubator-druid/issues/8765)，此类任务无法将其当前偏移量传达给霸主。任务/霸主发布协议已更新以解决此问题，但较旧的霸主无法识别此协议更改。 这种情况应该相当罕见。

默认 Hadoop 版本更改

Druid 0.17.0 现在捆绑 Hadoop 2.8.5 库而不是 2.8.3。 如果您通过 druid.indexer.task.defaultHadoopCoordinates 属性或 Hadoop 摄取规范中的 hadoopDependencyCoordinates 属性在配置中引用捆绑的 2.8.3 库，则需要更新这些引用以指向捆绑的 2.8.5 库。

删除 ParseSpec.verify 方法

如果您正在维护为 ParseSpec 接口提供实现的自定义扩展，则 verify 方法已被删除，并且需要在任何自定义实现中删除该方法上的 @Override 注释。 https://github.com/apache/druid/pull/8744

已知问题

在 SQL 兼容的空处理模式下过滤长列

目前，我们发现在启用 SQL 兼容空值处理时，对长列中的空值应用某些过滤器类型会出现错误 (https://github.com/apache/druid/issues/9255)。 如果您遇到任何其他空处理问题，请提出问题。

Web 控制台中的摄取规范预览

在 Web 控制台的 Data Loader 中创建的本机批量摄取任务显示的预览规范格式不正确，如果您手动复制并提交它们，将会失败。但是，通过数据加载器提交这些规范会提交格式正确的规范。 https://github.com/apache/druid/issues/9144

其他已知问题

有关未解决问题的完整列表，请参阅 https://github.com/apache/druid/labels/Bug
