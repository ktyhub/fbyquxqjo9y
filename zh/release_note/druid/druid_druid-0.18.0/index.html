druid 0.18.0

小版本 发布时间2020年4月20日 来源apache/druid 英文原文

Apache Druid 0.18.0 包含来自 42 位贡献者的 200 多个新功能、性能增强、错误修复和主要文档改进。查看完整的更改列表 和标记到里程碑的所有内容。

# 新功能

# 加入支持

连接是数据分析中的关键操作。在0.18.0之前，Druid支持一些与连接相关的功能，例如SQL中的查找或半连接。然而，这些功能的用例非常有限，对于其他连接用例，用户在摄取数据时必须对数据源进行非规范化，而不是在查询时加入数据源，这可能会导致数据量爆炸和较长的摄取时间。 Druid 0.18.0 历史上首次支持真正的连接。 Druid 目前支持 INNER、LEFT 和 CROSS 连接。对于本机查询，新引入了 join 数据源来表示两个数据源的联接。目前，仅允许 left-deep 连接。这意味着，左侧数据源仅允许使用 table 或另一个 join 数据源。对于正确的数据源，允许使用 lookup、inline 或 query 数据源。请注意，尚不支持 Druid 数据源的连接。同一连接查询中只能有一个 table 数据源。 Druid SQL 还支持连接。在幕后，SQL 连接查询被转换为一个或多个包含连接数据源的本机查询。有关 SQL 翻译的更多详细信息以及编写高效查询的最佳实践，请参阅查询翻译。 发出联接查询时，代理首先_评估_所有数据源，但基础数据源除外，基础数据源是查询中唯一的 table 数据源。评估可以包括执行 query 数据源的子查询。一旦 Broker 评估了所有非基础数据源，它就会用 inline 数据源替换它们，并将重写的查询发送到数据节点（有关更多详细信息，请参阅下面的“Brokers 中的查询内联”部分）。数据节点使用散列连接来处理连接查询。他们为每个非主叶数据源构建一个哈希表，除非它已经存在。请注意，当前只有 lookup 数据源具有预构建的哈希表。有关连接查询执行的更多详细信息，请参阅查询执行。 连接会影响查询的性能。一般来说，任何包含联接的查询都可能比针对非规范化数据源的等效查询慢。 LOOKUP 函数比与查找数据源的联接执行得更好。有关连接查询性能和未来性能改进计划的更多详细信息，请参阅连接性能。 https://github.com/apache/druid/pull/8728 https://github.com/apache/druid/pull/9545 https://github.com/apache/druid/pull/9111

# 代理中的查询内联

Druid 现在能够通过内联子查询来执行嵌套查询。任何类型的子查询都可以位于任何类型的另一种子查询之上，例如以下示例：

             topN
               |
       (join datasource)
         /          \
(table datasource)  groupBy

为了执行此查询，Broker 首先评估叶 groupBy 子查询；它将子查询发送到数据节点并收集结果。收集的结果具体化在 Broker 内存中。一旦 Broker 收集了 groupBy 查询的所有结果，它就会通过将叶 groupBy 替换为具有 groupBy 查询结果的内联数据源来重写 topN 查询。最后，将重写后的查询发送到数据节点来执行topN查询。

# 查询通道和优先级

当您一次运行异构工作负载的多个查询时，您有时可能希望根据查询的优先级来控制查询的资源投入。例如，您可能希望限制分配给不太重要的查询的资源，以便重要的查询可以及时执行，而不会被不太重要的查询中断。 查询通道允许您控制异构查询工作负载的容量利用率。通过laning，代理对查询进行检查和分类，以便将其分配给“lane”。通道具有由代理强制执行的容量限制，可用于确保有足够的资源可用于其他通道或交互式查询（无通道），或限制通道内查询的总体吞吐量。 自动查询优先级根据配置的策略确定查询优先级。增加了基于阈值的优先级策略；它会自动降低跨越任何可配置阈值的查询的优先级，例如数据过去多久、查询涵盖的间隔有多大或参与查询的段数。 有关更多详细信息，请参阅查询优先级和规划。 https://github.com/apache/druid/issues/6993 https://github.com/apache/druid/pull/9407 https://github.com/apache/druid/pull/9493

查询指标中的新维度

由于包含子查询的本机查询可以部分执行，因此引入了新的 subQueryId。每个子查询都有不同的 subQueryId，但有相同的 queryId。 subQueryId 可用作查询指标中的新维度。

新配置

新的 druid.server.http.maxSubqueryRows 配置控制 Broker 内存中具体化的最大行数。 更多详情请参见查询执行。 https://github.com/apache/druid/pull/9533

# SQL 分组集

现在支持 GROUPING SETS，允许您将多个 GROUP BY 子句组合成一个 GROUP BY 子句。此 GROUPING SETS 子句在内部转换为带有 subtotalsSpec 的 groupBy 查询。 LIMIT 子句现在应用于 subtotalsSpec 之后，而不是应用于每个分组集。 https://github.com/apache/druid/pull/9122

# SQL 动态参数

Druid 现在支持 SQL 的动态参数。要使用动态参数，请将查询中的任何文字替换为问号 (?) 字符。这些问号代表执行时参数绑定的位置。有关详细信息，请参阅SQL 动态参数。 https://github.com/apache/druid/pull/6974

# 重要更改

# applyLimitPushDownToSegments 默认禁用

0.17.0 中添加了 applyLimitPushDownToSegments，以将限制评估下推到可查询节点，限制 groupBy v2 的段扫描期间的结果。如果查询处理涉及许多段，这可能会导致性能下降，如 https://github.com/apache/druid/issues/9689, 中报告的那样。这是因为“限制下推到段扫描”会初始化每个段的聚合缓冲区，其开销不可忽略。仅当您的查询涉及每个历史或实时任务相对较少的段时，才启用此配置。 https://github.com/apache/druid/pull/9711

# 默认为咆哮位图

Druid 支持两种位图类型，即 Roaring 和 CONCISE。由于 Roaring 位图提供了更好的开箱即用体验（通常查询速度更快），默认位图类型现在已切换为 Roaring 位图。有关位图的更多详细信息，请参阅段压缩。 https://github.com/apache/druid/pull/9548

# 当禁用 SQL 兼容的空处理（默认模式）时，复杂指标行为会在摄取时发生变化

当禁用与 SQL 兼容的 null 处理时，摄取时复杂指标聚合的行为现已更改为与查询时的行为一致。复杂指标将聚合为 null 的默认 0 值，而不是在摄取期间跳过它们。 https://github.com/apache/druid/pull/9484

# 数组表达式语法更改

Druid 表达式现在支持用于创建数组的类型化构造函数。数组可以用显式类型定义。例如，<LONG>[1, 2, null] 创建包含 1、2 和 null 的 LONG 类型的数组。请注意，您仍然可以创建没有显式类型的数组。例如，[1, 2, null] 仍然是创建等效数组的有效语法。在这种情况下，Druid 将从数组元素推断出数组的类型。这种新语法也适用于空数组。 <STRING>[]、<DOUBLE>[] 和 <LONG>[] 将分别创建 STRING、DOUBLE 和 LONG 类型的空数组。 https://github.com/apache/druid/pull/9367

# 默认启用挂起段清理

元数据存储中的 pendingSegments 表用于为附加任务（例如 Kafka/Kinesis 索引任务或附加模式的批处理任务）创建唯一的新段 ID。 0.12.0 中引入了自动挂起段清理功能，但在 0.18.0 之前已默认禁用。现在默认启用此配置。 https://github.com/apache/druid/pull/9385

# 为本机并行索引创建更好的输入拆分

并行任务现在可以创建更好的拆分。每个分割可以根据大小包含多个输入文件。空文件将被忽略。分割大小可以通过新的分割提示规范进行控制。有关详细信息，请参阅分割提示规范。 https://github.com/apache/druid/pull/9360 https://github.com/apache/druid/pull/9450

# 转换现在是一个扩展点

Transform 是一个 Interface，表示在摄取时应用于每行的转换。该接口现在是一个扩展点。请参阅编写您自己的扩展 了解如何添加自定义 Transform。 https://github.com/apache/druid/pull/9319

# chunkPeriod 查询上下文已删除

自 0.14.0 以来，chunkPeriod 已被弃用，因为它的使用有限（有时仅对 groupBy v1 有用）。此查询上下文现已在 0.18.0 中删除。 https://github.com/apache/druid/pull/9216

# 对 Java 11 的实验性支持

Druid 现在实验性地支持 Java 11。您可以使用 Java 11 运行相同的 Druid 二进制发行版，该发行版是用 Java 8 编译的。我们对 Travis 的测试包括：

  • 使用 Java 11 编译和运行单元测试
  • 使用 Java 8 进行编译并使用 Java 11 运行集成测试 性能测试结果尚未公布。

使用 Java 11 运行 Druid 时非法反射访问的警告

# 新扩展

# 新的 Pac4j 扩展

0.18.0 中添加了一个新扩展，可为 Druid 进程启用基于 OpenID Connect 的身份验证。这可以与支持相同的任何身份验证服务器一起使用，例如Okta。此扩展只能在路由器节点上使用，以使现有身份验证服务器中的一组用户能够使用 Web 控制台 与 Druid 集群进行交互。 https://github.com/apache/druid/pull/8992

# 安全问题

# [CVE-2020-1958] Apache Druid LDAP 注入漏洞

CVE-2020-1958 最近已报告并在 0.18.0 和 0.17.1 中修复。当启用LDAP身份验证时，Druid APIs的调用者可以绕过credentialsValidator.userSearch过滤器障​​碍或检索LDAP服务器上存在的用户的任何LDAP属性值，只要该信息对Druid服务器可见。请参阅链接中的描述以了解更多详细信息。如果您在 Druid 中使用 LDAP 身份验证，强烈建议升级到 0.18.0 或 0.17.1。 https://github.com/apache/druid/pull/9600

# 将 Kafka client 更新为 2.2.2

Kafka client 库已更新为 2.2.2，其中 CVE-2019-12399 已修复。 https://github.com/apache/druid/pull/9259

# 已知问题

# 在具有多值列的 scan 上使用 topN 或 groupBy 查询失败

Brokers 中的查询内联是在 0.18.0 中新引入的，但存在一个错误：如果扫描查询选择多值维度，则在 scan 之上使用 topN 或 groupBy 进行查询会失败。有关详细信息，请参阅 https://github.com/apache/druid/issues/9697。

# 将 Avro 解析器与 Kafka 索引服务结合使用时出现 NullPointerException。

由于错误的 null 检查，Avro 解析器无法与 Kafka 索引服务一起使用。有关详细信息，请参阅 https://github.com/apache/druid/issues/9728。

# 切换期间误导性的 segment/unavailable/count 指标

该指标还应该考虑实时任务所服务的段数量，但现在不是。因此，在历史记录加载新段之前，可用性似乎会急剧上升，即使所有段实际上在实时任务和历史记录的某种组合上连续可用。 https://github.com/apache/druid/issues/9677

# explain plan for查询结果与实际执行计划略有差异

当查询包含连接或子查询时，explain plan for 的结果可能与 Druid 实际执行的结果略有不同。不同之处在于，查询计划的每个部分在 explain plan for 的结果中都将表示为它自己的本机查询。例如，对于数据源 d1 和数据源 d2 上的 groupBy 子查询的联接，explain plan for 可能返回如下计划

     join
    /    \
scan    groupBy
 |        |
d1       d2

而 Druid 实际执行的查询计划是

     join
    /    \
  d1    groupBy
          |
         d2
