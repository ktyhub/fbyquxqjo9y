druid 0.12.0

小版本 发布时间2018年3月9日 来源apache/druid 英文原文

Druid 0.12.0 包含来自近 40 个贡献者的一百多项性能改进、稳定性改进和错误修复。此版本对 Kafka 索引服务进行了重大改进。 其他主要新功能包括：

  • 优先任务锁定
  • 改进的自动分段管理
  • 测试统计后聚合器
  • 数字分位数草图聚合器
  • 基本身份验证扩展
  • 查询请求排队改进
  • 解析批量支持
  • 各种性能改进
  • Druid SQL 的各种改进 完整的更改列表在这里：https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.12.0 此版本的文档位于：http://druid.io/docs/0.12.0/

变更架构图

亮点

Kafka 索引增量切换和解耦分区

Kafka 索引服务现在支持增量切换，以及将 Kafka 索引任务创建的段数量与 Kafka 分区数量解耦。请参阅 https://github.com/druid-io/druid/pull/4815#issuecomment-346155552 了解更多信息。 由 @pjain1 在 #4815 中添加。

优先任务锁定

Druid 现在支持索引任务锁的优先级。当索引任务需要获取数据源+间隔上的锁时，高优先级任务现在可以抢占低优先级任务。请参阅 http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#task-priority 了解更多信息。 由 @jihoonson 添加于 https://github.com/druid-io/druid/pull/4550.

改进的自动段管理

自动挂起段清理

索引任务在元数据存储的“pendingSegments”表中创建条目；在 0.12.0 之前，这些临时条目不会自动清理，导致集群性能随着时间的推移可能会下降。 Druid 0.12.0 允许协调器自动清理待处理段表中未使用的条目。通过在协调器属性中设置 druid.coordinator.kill.pendingSegments.on=true 可以启用此功能。 由 @jihoonson 在 #5149 中添加。

压实任务

压缩段（合并给定间隔内的一组段以创建一组更大但更少的段）是常见的 Druid 批量摄取用例。 Druid 0.12.0 现在支持压缩任务，将给定间隔内的所有段合并为单个段。请参阅 http://druid.io/docs/0.12.0-rc1/ingestion/tasks.html#compaction-task 了解更多详情。 由 @jihoonson 在 #4985 中添加。

测试聚合后的统计数据

新的 z 分数和 p 值测试统计后聚合器已添加到 druid-stats 扩展中。请参阅 http://druid.io/docs/0.12.0-rc1/development/extensions-core/test-stats.html 了解更多详情。 由 @chunghochen 在 #4532 中添加。

数字分位数草图聚合器

druid-datasketches 扩展中添加了数字分位数草图聚合器。 由 @AlexanderSaydakov 在 #5002 中添加。

基本身份验证扩展

Druid 0.12.0 包含一个新的身份验证/授权扩展，可提供基本 HTTP 身份验证和简单的基于角色的访问控制。请参阅 http://druid.io/docs/0.12.0-rc1/development/extensions-core/druid-basic-security.html 了解更多信息。 由 @jon-wei 在 #5099 中添加。

查询请求队列改进

目前，clients 可能会因发送过多的请求而无意中压垮代理，这些请求会在无界的 Jetty 工作池队列中排队。 Clients 通常会在一定的 client 端超时后关闭连接，但代理将继续处理这些请求，从而表现出无响应的样子。与此同时，clients 将继续重试，继续向已经超载的代理添加请求。 经纪人配置和历史配置中新引入的属性druid.server.http.queueSize和druid.server.http.enableRequestLimit允许用户配置请求拒绝，以防止clients通过查询淹没经纪人和历史记录。 由 @himanshug 在 #4540 中添加。

解析批量支持

对于自定义摄取解析扩展的开发人员来说，InputRowParsers 现在可以从单个输入行返回多个 InputRow。这可以通过减少 Druid 外部输入转换的需求来简化摄取管道。 由 @pjain1 在 #5081 中添加。

性能改进

SegmentWriteOutMedium

当创建新的段时，Druid 将一些预处理的数据存储在临时缓冲区中。在 0.12.0 之前，这些缓冲区始终保存在磁盘上的临时文件中。 在 0.12.0 中，@leventov 的 PR #4762 允许将这些临时缓冲区存储在堆外内存中，从而减少摄取期间的磁盘 I/O 操作数量。要为这些缓冲区启用堆外内存，需要相应配置 druid.peon.defaultSegmentWriteOutMediumFactory 属性。如果使用堆外内存作为临时缓冲区，请确保增加 -XX:MaxDirectMemorySize 以适应更高的直接内存使用量。 配置详情请参见http://druid.io/docs/0.12.0-rc1/configuration/indexing-service.html#SegmentWriteOutMediumFactory。

中间 GroupBy 结果的并行合并

@jihoonson 的 PR #4704 允许用户配置多个处理线程，用于并行合并已溢出到磁盘的中间 GroupBy 结果。在 0.12.0 之前，此合并步骤始终在单个线程内进行。 配置详情请参见http://druid.io/docs/0.12.0-rc1/configuration/querying/groupbyquery.html#parallel-combine。

其他性能改进

  • DataSegment 内存优化：#5094 by @leventov
  • 删除 IndexedInts.iterator(): #4811 by @leventov
  • ExpressionSelectors：添加优化选择器：#5048 by @gianm

从 0.11.0 及更早版本更新

请参阅下文，了解升级前您应注意的 0.11.0 和 0.12.0 之间的变化。如果您从 0.11.0 之前的版本进行更新，请参阅相关中间版本的 release note 以获取附加说明。

回滚限制

请注意，升级到 0.12.0 后，由于 https://github.com/druid-io/druid/pull/4762. 中所做的更改，无法再降级到早于 0.11.0 的版本，但仍然可以回滚到 0.11.0 版本。

com.metamx.java-util 库迁移

Metamarkets java-util 库已被引入 Druid 中。因此，以下包引用已更改： com.metamx.common -> io.druid.java.util.common com.metamx.emitter -> io.druid.java.util.emitter com.metamx.http -> io.druid.java.util.http com.metamx.metrics -> io.druid.java.util.metrics 这将影响 druid.monitoring.monitors 配置。对旧 com.metamx.metrics.* 包下的监视器类的引用需要更新为引用 io.druid.java.metrics.*，例如io.druid.java.util.metrics.JvmMonitor。 如果上面显示的 com.metamx 包下的类在其他配置（例如 log4j2.xml）中引用，那么这些引用也需要更新。 扩展开发人员还需要更新他们的代码才能使用新的 Druid 包。

咖啡因缓存扩展

Caffeine 缓存扩展已从扩展中移至核心 Druid 中。此外，Caffeine 缓存现在是默认的缓存实现。升级到 0.12.0 时，如果扩展列表中存在 druid-caffeine-cache，请删除该 druid-caffeine-cache。更多信息请参见https://github.com/druid-io/druid/pull/4810.

Kafka 索引服务变更

EarlyMessageRejectPeriod

earlyMessageRejectPeriod 配置的语义已更改。在确定消息窗口的边界时，earlyMessageRejectPeriod 现在将添加到 (task start time + task duration)，而不仅仅是 (task start time)。请参阅 https://github.com/druid-io/druid/pull/4990 了解更多信息。

滚动升级

在 0.12.0 中，Kafka Supervisor 和 Kafka Indexing 任务之间的协议发生了变化，并且磁盘上保存的元数据格式也发生了一些变化。因此，为了支持滚动升级，所有中层管理人员都需要在霸主之前先升级。请注意，此顺序与标准升级顺序不同，另请注意，此顺序仅在使用 Kafka 索引服务时才需要。如果不使用 Kafka 索引服务或可以处理 Kafka Supervisor 的停机时间，则可以按任何顺序进行升级。 在 Overlord 升级之前，所有 Kafka Indexing Task 都将以与之前相同的方式运行（即使它们已升级），这意味着没有解耦和增量切换。 Overlord升级后，升级后的Overlord启动的新任务将支持新功能。 请参阅 https://github.com/druid-io/druid/pull/4815 了解更多信息。

回滚

一旦霸主和中层管理者都回滚了，就应该开始一套新的任务，这样就可以正常工作了。但是，当前的任务集可能会在回滚期间失败。请参阅#4815 了解更多信息。

扩展开发人员的界面更改

ColumnSelectorFactory API 已更改。聚合器扩展作者和任何其他使用 ColumnSelectorFactory 的人都需要相应地更新他们的代码。更多详情请参见https://github.com/druid-io/druid/pull/4886。 Aggregator.reset() 方法已被删除，因为它已被弃用且未使用。请参阅 https://github.com/druid-io/druid/pull/5177 了解更多信息。 DataSegmentPusher 接口已更改，push() 方法现在多了一个 replaceExisting 参数。详情请参见https://github.com/druid-io/druid/pull/5187。 Escalator 接口已更改：createEscalatedJettyClient 方法已被删除。更多详情请参见https://github.com/druid-io/druid/pull/5322。
