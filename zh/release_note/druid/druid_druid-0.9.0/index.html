druid 0.9.0

小版本 发布时间2016年4月13日 来源apache/druid 英文原文

druid druid-0.9.0

Druid 0.9.0 引入了需要更改配置的扩展系统更新。另外还有 400 多个从 0.8.3 到 0.9.0 的拉取请求。下面我们重点介绍此补丁中更重要的变化。 完整的更改列表在这里：https://github.com/druid-io/druid/issues?q=milestone%3A0.9.0+is%3Aclosed

从 0.8.x 更新

扩展

在Druid 0.9中，我们重构了扩展加载机制。此更改背后的主要原因是使 Druid 从本地文件系统加载扩展，而无需在运行时从互联网下载内容。 要了解有关新扩展加载机制的所有信息，请参阅包括扩展 和包括 Hadoop 依赖项。如果你不耐烦的话，这里是总结。 以下属性已被弃用： druid.extensions.coordinates druid.extensions.remoteRepositories druid.extensions.localRepository druid.extensions.defaultVersion 相反，指定 druid.extensions.loadList、druid.extensions.directory 和 druid.extensions.hadoopDependencyDir。 druid.extensions.loadList 指定 Druid 在运行时加载的扩展列表。一个例子是 druid.extensions.loadList=["druid-datasketches", "mysql-metadata-storage"]。 druid.extensions.directory 指定所有扩展所在的目录。一个例子是 druid.extensions.directory=/xxx/extensions。 注意，由于许可证问题，mysql-metadata-storage 扩展未打包在 druid 发行版中。您必须从druid.io手动下载它，解压然后放入指定的扩展目录中。 druid.extensions.hadoopDependencyDir 指定所有 Hadoop 依赖项所在的目录。一个例子是 druid.extensions.hadoopDependenciesDir=/xxx/hadoop-dependencies。注意：我们没有更改指定使用哪个 Hadoop 版本的方式。因此，您只需确保您要使用的 Hadoop 存在于 /xxx/hadoop-dependencies 下即可。 您现在可能想知道是否必须手动将扩展放入 /xxx/extensions 和 /xxx/hadoop-dependencies 中。答案是否定的，我们已经为您创建了它们。在 http://druid.io/downloads.html. 下载最新的 Druid tarball 解压它，您将在那里看到 extensions 和 hadoop-dependencies 文件夹。只需将它们分别复制到 /xxx/extensions 和 /xxx/hadoop-dependencies 即可，现在一切就绪！ 如果您要加载的扩展或 Hadoop 依赖项不包含在核心扩展中，您可以使用 pull-deps 将其下载到您的扩展目录。 如果您想加载自己的扩展，可以先执行 mvn install 将其安装到本地存储库，然后使用 pull-deps 将其下载到您的扩展目录。 请随时留下有关迁移的任何问题。 扩展现在也已在核心和贡献扩展中进行了重构。核心扩展将由 Druid 提交者维护，并打包为下载 tarball 的一部分。 Contrib 扩展由社区维护，可以根据需要安装。欲了解更多信息，请参阅此处。

维度排序

在 Druid 0.8.x 之前，索引时给出的维度顺序不会影响数据的索引方式。行将首先按时间戳排序，然后按维度值排序，按照维度名称的字典顺序。 从 Druid 0.9.0 开始，Druid 遵循给定的维度顺序，并且将首先按时间戳对行进行排序，然后按给定维度顺序的维度值对行进行排序。 这意味着片段的大小现在可能会根据给出尺寸的顺序而变化。首先指定具有许多唯一值的维度可能会导致比首先指定具有重复值的维度更糟糕的压缩。

不再支持最小/最大聚合器，请使用 doubleMin/doubleMax 代替

如 0.8.3 release note 中所示，最小/最大聚合器已被删除，取而代之的是 doubleMin、doubleMax、longMin 和 longMax 聚合器。 如果您因此而遇到任何启动问题，请参阅 https://github.com/druid-io/druid/issues/2749

配置更改

druid.indexer.task.baseDir 和 druid.indexer.task.baseTaskDir 现在默认使用 java.io.tmpdir 系统属性指定的标准 Java 临时目录，而不是 /tmp， 其他需要注意的问题：https://github.com/druid-io/druid/issues?q=milestone%3A0.9.0+is%3Aclosed+label%3A%22Release+Notes%22 和 https://github.com/druid-io/druid/issues?q=milestone%3A0.9.0+is%3Aclosed+label%3AIncompatible
