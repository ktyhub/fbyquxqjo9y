druid 0.21.0

小版本 发布时间2021年4月28日 来源apache/druid 英文原文

Apache Druid 0.21.0 包含约 120 个新功能、错误修复、性能增强、文档改进以及来自 36 个贡献者的额外测试覆盖范围。有关更多详细信息，请参阅完整的更改列表以及标记为里程碑的所有内容。

# 新功能

# 操作

# 基于Kubernetes的服务发现和领导者选举

新的Kubernetes扩展支持基于Kubernetes的服务发现和领导者选举。此扩展与基于 HTTP 的服务器视图 (druid.serverview.type=http) 和任务管理 (druid.indexer.runner.type=httpRemote) 结合使用，允许您以零 ZooKeeper 依赖项运行 Druid 集群。此扩展仍然是实验性的。详情请参阅Kubernetes 扩展。 https://github.com/apache/druid/pull/10544 https://github.com/apache/druid/pull/9507 https://github.com/apache/druid/pull/10537

# 新的动态协调器配置，用于在查找用于分段平衡的候选分段时限制分段数量

您可以设置 percentOfSegmentsToConsiderPerMove 以限制选择要移动的候选段时考虑的段数。候选人最多被搜索 maxSegmentsToMove * 2 次。这个新配置可以防止 Druid 迭代所有可用段以加快段平衡过程，特别是当集群中有大量可用段时。更多详情请参见协调器动态配置。 https://github.com/apache/druid/pull/10284

# 索引器的 status 和 selfDiscovered 端点

索引器现在支持 status 和 selfDiscovered 端点。有关详细信息，请参阅处理器信息 APIs。 https://github.com/apache/druid/pull/10679

# 查询

# 新的 grouping 聚合器函数

您可以将新的 grouping 聚合器 SQL 函数与 GROUPING SETS 或 CUBE 结合使用来指示当前分组集中包含哪些分组维度。有关详细信息，请参阅聚合函数。 https://github.com/apache/druid/pull/10518

# 改进了表达式和函数中缺少参数的处理

当输入丢失时，表达式处理现在可以进行矢量化。例如不存在的列。当表达式中缺少参数时，Druid 现在可以根据非空参数推断正确的结果类型。例如，对于 longColumn + nonExistentColumn，nonExistentColumn 被视为 (long) 0，而不是 (double) 0.0。最后，在默认的空处理模式下，数学函数可以通过将丢失的参数视为零来正确生成输出。 https://github.com/apache/druid/pull/10499

# 允许 TIMESTAMPADD 为零周期

TIMESTAMPADD 功能现在允许零周期。某些 BI 工具（例如 Tableau）需要此功能。 https://github.com/apache/druid/pull/10550

# 摄取

# 本机并行摄取不再需要明确的间隔

并行任务不再需要您在 granularitySpec 中设置明确的间隔。如果间隔丢失，并行任务会执行额外的输入采样步骤，收集要索引的间隔。 https://github.com/apache/druid/pull/10592 https://github.com/apache/druid/pull/10647

# 旧 Kafka 版本支持

Druid 现在支持比 0.11 更旧的 Apache Kafka。要读取旧版本的 Kafka，请将 consumerProperties 中的 isolation.level 设置为 read_uncommitted。在此版本发布之前，仅 0.10.2.1 经过测试。详细信息请参见Kafka Supervisor配置。 https://github.com/apache/druid/pull/10551

用于本机批量摄取的多阶段段合并

新的tuningConfig maxColumnsToMerge 控制任务中可以同时合并多少个段。此配置可用于避免合并期间的高内存压力。有关更多详细信息，请参阅用于本机批量摄取的tuningConfig。 https://github.com/apache/druid/pull/10689

# 本机重新摄取占用的内存较少

并行任务现在在将段分配给子任务之前按 ID 对段进行排序。这种排序最大限度地减少了每个子任务要处理的时间块的数量。因此，每个子任务预计会使用更少的内存，特别是当发出单个并行任务来重新摄取覆盖很长一段时间的段时。 https://github.com/apache/druid/pull/10646

# Web 控制台

# 更新和改进了 Web 控制台样式

新的 Web 控制台样式更好地利用了 Druid 品牌颜色，并标准化了整个内边距和边距。图标和背景颜色现在源自德鲁伊徽标。 https://github.com/apache/druid/pull/10515

# Web 控制台中提供分区信息

Web 控制台现在显示新 Segment granularity 和 Partitioning 列上的数据源分区信息。

Datasources 选项卡中的 Segment granularity 列

Segments 选项卡中的 Partitioning 列

https://github.com/apache/druid/pull/10533

# Schema 表中的列顺序与 dimensionsSpec 匹配

Schema 表现在反映了 dimensionsSpec 中的尺寸顺序。 https://github.com/apache/druid/pull/10588

# 指标

# 协调员值班运行时指标

协调员执行多项“职责”任务。例如段平衡、加载新段等。现在有两个新指标可以帮助您分析协调器执行这些职责的速度。

  • coordinator/time：执行个人职责的时间
  • coordinator/global/time：可运行的整个任务执行的时间 https://github.com/apache/druid/pull/10603

# 查询超时指标

新指标提供超时查询的数量。以前超时的查询被视为已中断并包含在 query/interrupted/count 中（有关更多详细信息，请参阅更改查询错误的 HTTP 状态代码）。 query/timeout/count：发射期间超时查询的数量 https://github.com/apache/druid/pull/10567

# 批量摄取的随机播放指标

两个新指标为 MiddleManager 和 Indexers 提供随机统计数据。这些指标的维度为 supervisorTaskId。

  • ingest/shuffle/bytes：每个发射周期混洗的字节数
  • ingest/shuffle/requests：每个发射周期的洗牌请求数 要启用随机播放指标，请在 druid.monitoring.monitors 中添加 org.apache.druid.indexing.worker.shuffle.ShuffleMonitor。有关更多详细信息，请参阅随机播放指标。 https://github.com/apache/druid/pull/10359

# 新的时钟漂移安全指标监控调度程序

默认的指标监控调度程序是基于 ScheduledThreadPoolExecutor 实现的，它容易出现无限制的时钟漂移。新的监视器调度程序 ClockDriftSafeMonitorScheduler 克服了这一限制。要使用新的调度程序，请在runtime.properties 文件中将druid.monitoring.schedulerClassName 设置为org.apache.druid.java.util.metrics.ClockDriftSafeMonitorScheduler。 https://github.com/apache/druid/pull/10448 https://github.com/apache/druid/pull/10732

# 其他

# 基于 AWS RDS 令牌的密码提供商的新扩展

新的 PasswordProvider 类型允许使用临时 AWS 令牌访问 AWS RDS 数据库实例。当 RDS 用作 Druid 的元数据存储时，此扩展非常有用。有关更多详细信息，请参阅AWS RDS 扩展。 https://github.com/apache/druid/pull/9518

# sys.servers 表显示领导者

sys.servers 表中新的长类型列 is_leader 指示服务器是否是领导者。 https://github.com/apache/druid/pull/10680

# druid-influxdb-emitter 扩展支持 HTTPS 协议

有关新配置，请参阅 Influxdb 发射器扩展。 https://github.com/apache/druid/pull/9938

# Docker

# 小 docker 图像

通过消除不必要的重复，docker 图像尺寸减小了一半。 https://github.com/apache/druid/pull/10506

# 开发

# 通过新的 DynamicConfigProvider 可扩展 Kafka 消费者属性

新类 DynamicConfigProvider 允许在运行时获取消费者属性。例如，您可以使用 DynamicConfigProvider 从本地环境变量等位置获取 bootstrap.servers（如果它不是静态的）。目前，默认情况下仅支持基于地图的配置提供程序。请参阅 DynamicConfigProvider 了解如何实现自定义配置提供程序。 https://github.com/apache/druid/pull/10309

# 错误修复

Druid 0.21.0 包含 30 个错误修复，您可以在此处查看完整列表。

# 带小计的聚合后计算

在 0.21.0 之前，当您使用带有小计的帖子聚合器时，查询会失败并出现错误。现在这个错误已修复，您可以使用带有小计的帖子聚合器。 https://github.com/apache/druid/pull/10653

# 索引器将自己声明为段服务器

在 0.19.0 和 0.20.0 中，索引器无法处理针对流数据的查询，因为它们没有将自己声明为段服务器。他们被固定在 0.21.0 中正确地宣布自己。 https://github.com/apache/druid/pull/10631

# 历史记录中段文件的有效性检查

历史记录现在在下载段文件后执行有效性检查，并在这些文件崩溃时自动重新下载。 https://github.com/apache/druid/pull/10650

# StorageLocationSelectorStrategy 注入失败已修复

修复了读取 StorageLocationSelectorStrategy 配置时注入失败的问题。 https://github.com/apache/druid/pull/10363

# 升级到 0.21.0

从 Druid 0.20.0 升级到 0.21.0 时请考虑以下更改和更新。如果您要从 0.20.0 之前的版本进行更新，请参阅相关中间版本的 release note。

# 改进了查询错误的 HTTP 状态代码

在此版本之前，Druid 对于大多数查询错误都返回“内部错误（500）”。现在，Druid 根据原因返回不同的错误代码。下表列出了已更改的错误及其对应的代码：

例外 描述 旧代码 新代码
Calcite 中的 SqlParseException 和 ValidationException 查询计划失败 500 500 400
查询超时异常 查询执行超时未完成 500 500 504
资源限制超出异常 查询请求的资源超过配置的阈值 500 500 400
资源不足异常 由于提交时缺少可用的合并缓冲区，查询无法调度 500 500 429，合并到 QueryCapacityExceededException
查询不支持异常 不支持的功能 400 501
还有一个针对查询超时错误的新查询指标。有关更多详细信息，请参阅新查询超时指标。
https://github.com/apache/druid/pull/10464
https://github.com/apache/druid/pull/10746

# 查询中断指标

query/interrupted/count 不再计算超时的查询。这些查询按 query/timeout/count 进行计数。

# 查询指标中的 context 维度

context 现在是为所有查询指标发出的默认维度。 context 是 JSON 格式的字符串，其中包含发出的指标所引用的查询的查询上下文。添加以前没有的维度会改变 Druid 发出的一些指标。您应该计划在指标管道中处理这个新的 context 维度。由于维度是 JSON 格式的字符串，因此常见的解决方案是解析维度并将其展平或提取所需的位并丢弃完整的 JSON 格式的字符串 blob。 https://github.com/apache/druid/pull/10578

# 已弃用对 Apache ZooKeeper 3.4 的支持

由于 ZooKeeper 3.4 已经停产一段时间了，0.21.0 中已弃用对 ZooKeeper 3.4 的支持，并将在不久的将来删除。 https://github.com/apache/druid/issues/10780

# sys.segments 表的一致序列化格式和列命名约定

sys.segments 表中的所有列现在都以 JSON 格式序列化，以使它们与其他系统表一致。列名称现在使用相同的“蛇形命名法”约定。 https://github.com/apache/druid/pull/10481

# 已知问题

# Thrift 库中的已知安全漏洞

Thrift 扩展 可用于将 Thrift 格式的文件引入 Druid。然而，Druid使用的Thrift库版本中存在一个已知安全漏洞。当您使用索引器时，可以通过摄取恶意制作的 Thrift 文件来利用该漏洞。我们建议仅向 trusted 用户授予 DATASOURCE WRITE 权限。

# 基于docker的Druid集群运行权限问题

如果您是第一次在机器上运行 Druid docker 集群，使用 0.21.0 镜像可以使用 root 帐户创建内部目录。因此，Druid 服务可能会因缺乏权限而失败。此问题提交至 https://github.com/apache/druid/issues/11166. 如果您使用的是 docker compose，则可以使用以下命令来解决此问题。这些命令将首先使用旧映像创建内部目录，然后使用 0.21.0 映像启动服务。

$ cd ${PREV_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml create
$ cd ${0.21.0_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml up

如果您没有使用docker compose，则在使用0.21.0镜像启动服务时，可以直接传递/opt/druid/var的卷参数。例如，您可以运行以下命令来启动协调器服务。

$ docker run -v /path/to/host/dir:/opt/druid/var apache/druid:0.21.0 coordinator

有关未解决问题的完整列表，请参阅 https://github.com/apache/druid/labels/Bug.
