druid 0.12.1

修订 发布时间2018年6月8日 来源apache/druid 英文原文

druid druid-0.12.1

Druid 0.12.1 包含来自 10 个贡献者的稳定性改进和错误修复。主要改进包括：

  • 协调器负载状态 API 的性能大幅提升
  • HttpPostEmitter 更多内存限制
  • 修复 Kerberos 身份验证的几个问题
  • 修复 SQLMetadataSegmentManager 以允许连续启动和停止
  • 修复 SegmentMetadataQuery 中的默认间隔处理
  • 支持HTTP OPTIONS请求
  • 修复 Kafka 索引中同一段 id 不同段的 bug 完整的更改列表在这里：https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr+is%3Aclosed+milestone%3A0.12.1 此版本的文档位于：http://druid.io/docs/0.12.1

亮点

协调器负载状态 API 的性能大幅提升

协调器的 loadstatus API 返回集群中实际加载的段与应该加载到集群中的段的百分比。这款API的性能得到了很大的提升。 由 @jon-wei 在 #5632 中添加。

HttpPostEmitter 的更多内存限制

Druid 现在可以将 HttpPostEmitter 使用的内存量限制为可用 JVM 堆的 10%，从而避免缓冲事件导致 OutOfMemory 错误。 由 @jon-wei 在 #5300 中添加。

修复 Kerberos 身份验证的几个问题

Kerberos 身份验证存在一些错误，例如没有 cookie 的身份验证失败或使用路由器时的身份验证损坏。有关详细信息，请参阅 https://github.com/druid-io/druid/pull/5596,、https://github.com/druid-io/druid/pull/5706, 和 https://github.com/druid-io/druid/pull/5766。 由 @nishantmonu51 在 #5596 中添加。 由 @b-slim 在 #5706 中添加。 由 @jon-wei 在 #5766 中添加。

修复 SQLMetadataSegmentManager 以允许连续启动和停止

如果在启动时失去领导权，协调员可能会陷入困境。此错误现已修复。 由 @jihoonson 在 #5554 中添加。

修复 SegmentMetadataQuery 中的默认间隔处理

如果未指定间隔，SegmentMetadataQuery 应该使用 druid.query.segmentMetadata.defaultHistory 的间隔，但它会查询所有段，从而导致意外的性能损失。 SegmentMetadataQuery 现在再次考虑 defaultHistory 选项。 由 @gianm 在 #5489 中添加。

支持HTTP OPTIONS请求

Druid 现在通过修复其身份验证处理来支持 HTTP OPTIONS 请求。 由 @jon-wei 在 #5615 中添加。 ###修复Kafka索引中同一segment id不同segment的bug Kafka 索引服务允许重试任务来覆盖先前失败任务写入的深度存储中的段。然而，这导致了另一个错误，即相同的段 ID 可能在历史记录和深层存储中具有不同的数据。现在，通过为每个 Kafka 索引任务使用唯一的段路径，此错误已得到修复。 由 @dclim 在 #5692 中添加。

还有更多！

完整的更改列表在这里：https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr+is%3Aclosed+milestone%3A0.12.1

0.12.1 是次要版本，与 0.12.0 兼容。如果您从 0.12.0 之前的版本进行更新，请参阅相关中间版本的 release note 以获取附加说明。
