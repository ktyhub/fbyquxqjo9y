druid 39.0.0

大版本 发布时间2026年11月19日 来源apache/druid 英文原文

Apache Druid 39.0.0 包含超过 680 个新功能、错误修复、性能增强、文档改进以及来自 42 个贡献者的额外测试覆盖范围。

请参阅完整的更改集 了解更多详细信息，包括错误修复。 在升级到 Druid 39.0.0 之前，请查看升级说明 和不兼容更改。 如果您要跨多个版本进行升级，请参阅升级说明页面，其中列出了最新 Druid 版本的升级说明。

重要功能、更改和弃用

本节包含有关新功能和现有功能的重要信息。

Java

对 Java 21 的支持已被放弃。您必须升级到 Java 25。

目录的 DDL 语句（实验）

Druid 现在支持 CREATE 和 ALTER 语句来管理目录中的元数据。使用它们来声明表的列、时间分区、集群、聚合投影和物理布局，而不是在每个摄取规范中设置这些内容。 该功能默认关闭。要启用它，请将 druid.sql.planner.enableCatalogDdl 设置为 true。 欲了解更多信息，请参阅产品目录。 #19830 #20377 #20452 #19770 #19711

Kafka 基于标头的过滤

Kafka 主管现在可以按标头过滤记录。当您只需要主题的某些记录时，这可以减少摄取 CPU 和内存的使用。 要使用过滤器，请将 headerBasedFilterConfig 添加到主管的 ioConfig。使用 in 过滤器，其中 dimension 是标头名称，values 列出要摄取的标头值。标头值不在列表中的记录将被删除，并且偏移量仍会提前。 过滤是宽松的：如果记录没有标头、标头值为 null、空或无法解码，或者评估失败，则记录会被摄取。 新的 ingest/events/filtered 指标报告有多少记录头过滤被丢弃。 #18525

类型化查询上下文参数

查询上下文参考 和扫描查询 中列出的常见查询上下文参数现在类型为 QueryContextParameter 描述符。以下更改适用于查询上下文处理：

  • 整数和长参数拒绝非精确整数的值，而不是截断或包装它们。例如 1.5，并且值超出范围。仍然接受 5.0 或“5.0”等整数值。无效值现在会失败并显示错误消息：“查询上下文参数 [x] 应该是 …”
  • 查询上下文中的 null 或 SET x = NULL，不再清除使用 druid.query.default.context 或 Broker 动态配置配置的默认值。默认值适用，就像未设置该密钥一样。以前，null 到达了使用内置默认值的读者。要覆盖配置的默认值，请设置显式值。
  • maxSubqueryBytes 是一个类型化字符串参数，它接受 auto、disabled 或非负字节数，就像子查询 Guardrail 一样。现在，诸如 SET maxSubqueryBytes = TRUE 之类的无效值在验证过程中会失败，并且现在接受诸如 1e9 之类的数字。 #20555

Druid JDBC 驱动程序

Druid 现在提供了自己的 JDBC 驱动程序，该驱动程序使用 /druid/v2/sql/ 端点。我们建议您从 Avatica 驱动程序切换到此驱动程序。新驱动程序具有以下优点：不需要粘性负载平衡的驱动程序端连接管理、流结果、对 SET 语句的支持以及对非本机 SQL 引擎的支持。 #19951

Netty 4.2

Druid 现在使用 Netty 4.2 作为其 HTTP client。此前，Druid 使用的是 Netty 3。这是内存特性的实质性变化：

  • 直接内存：HTTP client 现在消耗一些直接内存。接近 -XX:MaxDirectMemorySize 预算的运营商可能需要增加预算。
  • 池化缓冲区：缓冲区现在是池化的，因此即使在空闲时，常驻内存也可能会高于 Netty 3 下的内存。这对于池化分配器来说是正常的。 有控制 HTTP client 行为的新配置：druid.global.http.connectTimeout、druid.global.http.allocator、druid.broker.http.connectTimeout 和 druid.broker.http.allocator。您还可以直接设置一些 Netty 配置。 #19567

协调器的服务质量过滤

您现在可以为协调器启用 QoS 过滤，以防止突发缓慢的 API 请求耗尽线程池并阻止运行状况检查。 使用 druid.coordinator.server.maxConcurrentRequests 配置此功能 (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8)))。将此属性设置为 0 将其关闭。 领导者状态端点不包括在上限中，因此负载均衡器/监视器不受影响。 #19271

功能区域及相关变更

本节包含按区域分隔的详细 release note。

摄入

  • 添加了对 regex 输入格式的 RE2/J 正则表达式的支持 #19514
  • 更改了 S3 client 以使用 AWS 推荐的标准重试策略。您可以使用 druid.s3.retryMode 和 druid.s3.maxAttempts 自定义重试策略 #19892
  • Protobuf 摄取现在保留未标记为可选的 proto3 字段的默认值。以前，持有 0 的 int32 字段（或持有“”的字符串、持有 false 的 bool、持有其第一个值的 enum）被摄取为 null。这些领域现在被吸收为它们的实际价值。 #20485

基于 SQL 的摄取

  • 工作人员现在仅将必要的工作人员上下文而不是整个工作人员上下文传递给任务上下文。 #20650

流媒体摄取

从选定的分区摄取

Kafka Supervisor 现在接受 ioConfig.partitionIds，它允许您仅摄取主题的选定分区。例如，您可以使用它进行独立的诊断摄取。 #20474

基于成本的自动缩放器改进
  • 您现在可以模拟 Kafka 基于成本的自动缩放器，以帮助确定不同延迟量的最佳任务计数。 #19687
  • 您现在可以为基于成本的自动缩放器设置临界滞后阈值。当滞后达到阈值的 75% 时，自动缩放器会绕过放大边界。当滞后达到 100% 时，自动缩放器会扩展到最大任务计数。 #19655
  • 您现在可以选择通过以下两种方式之一为主管配置基于成本的自动缩放器的冷却时间：
    • 高灵敏度：设置minScaleUpDelay / minScaleDownDelay < taskDuration。例如，如果 minScaleUpDelay = taskDuration / 2，则 2 次任务滚动之间最多会出现 1 个扩展事件
    • 低灵敏度：设置 minScaleUpDelay / minScaleDownDelay > taskDuration。在这种情况下，冷却时间实际上被忽略，并且缩放仅在任务滚动时发生。 #20706
  • 基于成本的自动缩放器现在使用运行平均值而不是任务指标的瞬时值来为基于成本的自动缩放器做出决策。这会导致更平滑的扩展，但有时可能会以稍微延迟响应任务生命周期结束时发生的指标趋势变化为代价。为了对变化趋势具有更高的敏感性，请将 minScaleUpDelay 和 minScaleDownDelay 设置为小于 taskDuration。
其他流媒体摄取改进
  • 修复了一个错误，其中 Kafka 索引任务会在任何样本实际可用之前报告 1.0 的轮询空闲率（即完全空闲），这可能会扭曲主管自动缩放器跨任务的平均空闲率。 #20783

查询

####查询计划时间 现在，您可以使用新的 druid.sql.planner.maxPlanningTimeMs 运行时属性来限制代理花费在规划 SQL 查询上的时间。您还可以使用 maxPlanningTimeMs 查询上下文参数为每个查询设置它。当计划超出配置的预算时，查询会失败并出现 HTTP 504 查询超时错误，而不是占用 Broker 线程。默认值为 0，它禁用超时。 #20314

修复了由查询响应预告片导致的 JDK HTTP client 故障

Brokers 和 Historicals 现在仅当请求包含 TE: trailers 标头时才发送 X-Druid-Response-Complete 和 X-Error-Message HTTP 预告片。读取这些预告片的 Clients 必须发送该标头。这修复了 JDK 17.0.21、21.0.13 和 25.0.5 上的 java.net.http.HttpClient-based clients（包括 Druid JDBC 驱动程序）中的查询失败 (java.net.ProtocolException: CR expected)。 #20717

其他查询改进

  • 您现在可以使用 Dart 查询元数据表，例如 sys 模式中的元数据表 #19952
  • CAST(x AS LONG) 现在被接受为 Druid SQL 中 CAST(x AS BIGINT) 的别名 #20402
  • 将 datasource 过滤器下推添加到 sys.segments 表 #19718
  • 为 FIRST_VALUE 和 LAST_VALUE 窗口函数添加了框架支持 #19301
  • 改进了按降序运行的时间序列、时间边界和扫描查询的性能 #19947
  • 改进了 COALESCE 的性能 #18400
  • 使用持久存储和 MSQ 导出改进了 MSQ 任务的 S3 API 使用效率 #19893
  • 改进了对目录类型的验证和对本机类型字符串的解析#19769
  • 升级至方解石 1.42.0 #19976 #19370

集群管理

Kubernetes 节点标签

druid-kubernetes-extensions 扩展现在支持 k8sNodeLabel 动态配置提供程序，该提供程序从运行 Druid 进程的 Kubernetes 节点的标签解析配置值。 #20404

Peon pod 模板

现在，您可以使用新的 GET /druid/indexer/v1/k8s/taskrunner/podTemplates 端点检索当前在 Overlord 上配置的 Peon Pod 模板名称。它返回每个配置模板的名称。当 Overlord 未使用自定义模板 Pod 适配器时，端点需要 CONFIG 读取权限并返回 404。 #19712

环境变量

environment 动态配置提供程序现在会忽略环境中未设置的变量，而不是生成使消费者（例如具有 NullPointerException 的 Kafka 主管）失败的空值。跳过的变量记录在信息级别。 #20381

连接池

您现在可以使用 druid.global.http.poolImplementation 配置 Druid 连接池如何跟踪连接需求。 默认为 retaining。使用 retaining，池会保留其打开的每个连接，并用新连接替换每个陈旧或损坏的连接，因此池会保持在高水位线。 #20542 #20273

HTTP 响应头

Druid 现在可以选择在 HTTP 响应上返回 X-Druid-Server、X-Druid-Service 和 X-Druid-Version，从而允许操作员识别服务于直接请求或路由器代理请求的进程和版本。这些标头公开集群拓扑和版本信息，因此仅当所有 client 都被允许接收它们时才启用它们。要启用它们，请将 druid.server.http.enableResponseIdentityHeaders 设置为 true。 #20268

改进的 LDAP 支持

在不返回 memberOf 属性的服务器（例如 OpenLDAP）上添加了对基于 LDAP 组的授权的支持。在 LDAP 凭据验证器上配置 groupBaseDn 和 groupSearch 以启用自动解析组成员资格的反向组查找。 #19432

表可见性

现在，查询没有 READ 权限的表的用户会看到“未找到”错误，而不是“禁止”错误。 要恢复以前的行为，请将 druid.sql.planner.authorizeTableVisibility 设置为 false。 此外，当设置为 true 时，INSERT 和 REPLACE 需要对目标表进行读和写访问。如果此属性设置为 false，则它们仅需要 WRITE 权限。无论此属性的值如何，只有当用户对表具有 READ 访问权限时，表才会出现在 INFORMATION_SCHEMA 中。 这是一个重大更改，会影响您所需的权限。有关详细信息，请参阅基于 SQL 的摄取的权限更改。 #20075

Java 主变量

现在，中层管理人员在使用 bin/java 脚本时会尊重 JAVA_HOME，该脚本应该存在于工作目录中。 Druid 使用以下逻辑

  • 如果您指定了命令（例如 config.getJavaCommand 不为空），请使用该命令。
  • 如果 bin/run-java 存在，请使用它
  • 使用java #19709

为协调器端点添加 QoS 过滤

向协调器添加了可配置的 QoS 过滤，以防止突发缓慢的 API 请求耗尽线程池并阻塞运行状况检查。 添加了新配置：druid.coordinator.server.maxConcurrentRequests（默认：max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))，将<= 0设置为禁用）。 领导者状态端点不包括在上限中，因此负载均衡器和监视器不受影响。 #19271

其他集群管理改进

  • 添加了可由嵌入式终止任务使用的 KILL 任务锁定类型，以便 UnusedSegmentsKiller 不会跳过活动摄取的时间间隔 #19921
  • 在 export-metadata 工具中添加了对 PostgreSQL 的支持 #19698
  • 运行不提供查询服务的任务（例如批处理、压缩和 MSQ 任务）的 Peons 现在会忽略 druid.server.http.unannouncePropagationDelay 并无需等待即可关闭。实时流任务仍然尊重延迟 #20444
  • 改进了端口绑定。 Druid 节点现在可以通告不同的明文端口以进行对等发现，同时将 Jetty 绑定到实际服务端口 #19598
  • 减少了加载段的堆占用空间 #20467
  • 修复了shutdownAllTasks霸主API（POST /druid/indexer/v1/datasources/{datasource}/shutdownAllTasks），自德鲁伊32.0.0以来返回404错误。 #20824

数据管理

压缩期间跳过间隔

自动压缩现在支持数据源压缩配置中的 skipIntervals 设置，除了现有的 skipOffsetFromLatest 行为之外，还允许从压缩中排除特定间隔。例如，这对于排除回填作业正在主动写入的时间间隔或始终压缩失败的时间间隔很有用。 #19792

大段文件的更好可见性

Druid 现在会报告您的范围或散列分区设置何时在某个时间块中生成过大的段文件（热分区）。使用哈希或范围分区的本机批量摄取现在会记录警告并发出 ingest/segments/oversized 指标。该指标对具有超过两倍 maxRowsPerSegment 行或超过三倍 targetRowsPerSegment 行的已发布段进行计数（用于范围分区）。任务完成报告还将此计数包含为 oversizedSegments。 #20173

更快的分段搜索

现在，您可以通过启用快速间隔搜索来加速内存中时间线中的分段搜索。此功能使用间隔树 索引来组织内存中的时间线，以便更快地加载和搜索片段。 要使用此功能，请将 druid.segment.timeline.fastIntervalSearch 设置为 true。 #19138 #19861

部分段加载

Druid 现在支持虚拟存储的部分段加载（默认开启）。要关闭它，请将以下任一设置为 false：

  • 运行时属性 druid.indexer.task.virtualStoragePartialDownloadsEnabled
  • 查询上下文参数virtualStoragePartialDownloadsEnabled #19739

其他数据管理改进

  • 添加了对 S3 兼容存储的 MD5 请求校验和的支持。要启用此功能，请将 druid.s3.enableLegacyMd5 设置为 true #20055
  • 添加了对 Azure 和 Google Cloud 深度存储中推、拉和删除段的支持，无需 zip 压缩 #20454 #20327 #20382 #20380
  • 改进了加载算法，以便在使用虚拟存储时更好地跨历史层分散请求 #20155
  • 提高了嵌入式终止任务的效率 #19772

指标和监控

分层存储指标

现在，无论有或没有虚拟存储，层存储指标都可以为历史记录提供更好的可观察性。 tier/required/capacity 和 tier/total/capacity 这两个指标已弃用，并将在未来版本中删除。请改用 ZZPH100​​ZZ 和 tier/storage/capacity。 #20199

task/run/time 公制

statsd 和 prometheus 发射器现在在 task/run/time 上发射 taskStatus 尺寸。这是一个突破性的改变。有关详细信息，请参阅task/run/time 上的警报。 #20122

其他指标和监控改进

  • 使用 Kubernetes Overlord 扩展的集群的 Peon 任务指标现在包括 podTemplate 维度。这使得监控将不同任务映射到不同 pod 模板的集群变得更加容易 #20001
  • 添加了 mergeBuffer/maxSpillProximity，它测量在发射期间任何单个 groupBy 查询与溢出的接近程度，作为 [0.0, 1.0] 中的分数 #19627
  • 将 taskType 添加到各种任务计数指标中，以便您可以按任务类型过滤它们 #20123

贡献者扩展

冰山

Apache Iceberg 摄取现在支持由 iceberg-arrow 支持的选择加入矢量化读取器。使用"useArrowReader": true启用它；使用 arrowBatchSize 调整批处理（默认 1024）。 Arrow 路径支持 Parquet 数据文件、字典编码值、模式演化、时间旅行快照、列投影和谓词下推。不支持包含位置或相等删除文件的快照，Druid 会拒绝它们并显示错误；对这些快照使用标准的删除感知读取器。箭头路径不可拆分，因此在需要并行批处理吞吐量时请将其禁用。默认阅读器保持不变，并且两条路径在同一 Iceberg 输入源类型下共存。 #19510

开放策略代理

添加了 druid-opa-authorizer 贡献者扩展，可通过开放策略代理 (OPA) 进行授权。您可以编写 Rego 策略来根据用户身份、操作和资源类型来控制对 Druid 资源的访问。该扩展支持基本身份验证和 LDAP 身份验证工作流程。 #19670

  • maxSubqueryBytes 是一个类型化字符串参数，它接受 auto、disabled 或非负字节数，就像子查询 Guardrail 所做的那样。现在，诸如 SET maxSubqueryBytes = TRUE 之类的无效值在验证过程中会失败，并且现在接受诸如 1e9 之类的数字。 [#20555][https://github.com/apache/druid/pull/20555/]

Java 主变量

现在，中层管理人员在使用 bin/java 脚本时会尊重 JAVA_HOME，该脚本应该存在于工作目录中。 Druid 使用以下逻辑

  • 如果您指定了命令（例如 config.getJavaCommand 不为空），请使用该命令。
  • 如果 bin/run-java 存在，请使用它
  • 使用java #19709

协调器的服务质量过滤

您现在可以为协调器启用 QoS 过滤，以防止突发缓慢的 API 请求耗尽线程池并阻止运行状况检查。 使用 druid.coordinator.server.maxConcurrentRequests 配置此功能 (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8)))。将此属性设置为 0 将其关闭。 领导者状态端点不包括在上限中，因此负载均衡器/监视器不受影响。 #19271

基于 SQL 的摄取的权限更改

表可见性 更改会影响基于 SQL 的提取所需的权限。 INSERT 和 REPLACE 现在需要对目标表进行 READ 访问（除了 WRITE 之外）。 要恢复以前的行为，请将 druid.sql.planner.authorizeTableVisibility 设置为 false。 #20075

task/run/time 警报

statsd 和 prometheus 发射器现在在 task/run/time 上发射 taskStatus 尺寸。这是 task/run/time 上仪表板和警报的重大更改：

  • statsd（非 DogStatsD 模式）：维度值连接到点分指标名称中，因此 druid.overlord.task.run.time.DATASOURCE.TASKTYPE 变为 druid.overlord.task.run.time.DATASOURCE.TASKSTATUS.TASKTYPE。针对旧名称的查询停止接收数据。
  • statsd（DogStatsD 模式）：添加了 taskStatus 标签。现有查询继续工作并对其进行聚合。
  • prometheus：添加了 taskStatus 标签。更新选择精确标签集的任何查询以及采用旧标签集的任何记录规则。 要保持以前的行为，请使用 druid.emitter.statsd.dimensionMapPath 或 druid.emitter.prometheus.dimensionMapPath 固定旧尺寸列表。 #20122

MariaDB Connector/J 3.x 更改连接 URI 行为

MariaDB JDBC 连接器已从 2.7.3 升级到 3.5.10，影响如下：

  • 对于 druid.metadata.storage.connector.connectURI 和 org.mariadb.jdbc.Driver，请使用 jdbc:mariadb:。旧版 jdbc:mysql: URI 仅在包含 permitMysqlScheme 时才保持可用。例如，jdbc:mysql://<host>/druid?permitMysqlScheme，因为元数据存储将 URI 直接传递给驱动程序。
  • 对于 MariaDB 支持的 SQL 输入源和使用默认 druid.access.jdbc.enforceAllowedProperties=true 的 JDBC 查找，请使用 jdbc:mariadb:。 Druid 的 JDBC 属性验证不会将 jdbc:mysql: 路由到 Connector/J 3.x 解析器，并且 permitMysqlScheme 不在默认的 druid.access.jdbc.allowedProperties 中，仅添加该选项是不够的。
  • 继续提供 Connector/J 2.x 的用户无需更改现有的 jdbc:mysql: 或 jdbc:mariadb: URI。 MySQL 连接器/J 用户不受影响。
  • 从 distribution/docker/Dockerfile.mariadb 重建的映像现在安装 Connector/J 3.5.10 并且必须遵循上面的 3.x 指南。 #20036
