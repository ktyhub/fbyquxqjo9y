nocodb 2026.05.2

变更流程图

亮点

  • 新的排期与分享功能仅付费版可用 — Gantt View 把带日期的表变成可拖拽的排期视图，支持依赖箭头和里程碑；Shared Pages 可以把 NocoDocs 页面发布为只读 URL 或 iframe 嵌入，并能即时撤销。按可用性表，两者都限付费/企业版，CE 用户啥也拿不到；如果不需要项目排期或公开文档，单凭这两项不值得升级。
  • 展开式记录侧栏下放到社区版 — 2026.05.1 时还是付费功能，现在成了所有版本的默认桌面布局：记录停靠在表格右侧，而不是全屏弹窗，编辑字段、看评论、查修订历史时数据始终可见。公开视图和共享视图仍是居中弹窗。这是免费用户最主要的功能收益。
  • 破坏性变更 / 迁移——SSRF 防护默认开启 — 自托管实例如果通过私网/本地网络连数据库或发 webhook，必须通过 NC_ALLOW_LOCAL_EXTERNAL_DBS、NC_WEBHOOK_ALLOW_PRIVATE_NETWORK / NC_ALLOW_LOCAL_HOOKS 选择放行，或者用 NC_DISABLE_SSRF_PROTECTION 全局关闭；否则升级后这部分流量会中断。NocoDB Cloud 始终强制启用 SSRF 防护。上线前请审计这些环境变量。
  • 破坏性变更 / 迁移——2FA 与会话行为变化 — 使用 NC_CONNECTION_ENCRYPT_KEY 的实例上，TOTP 报错（“Invalid verification code”）已修复，但所有用 2FA 的人都必须先关闭再重新绑定。另外，每个账号只允许一个活跃会话现在在所有版本默认开启，SSO 登录路径也算（API token 不受影响），在别处登录会把之前的会话挤下线；企业版管理员也不再能绕过工作区级别的 2FA 强制。如果用户习惯在多设备保持登录，准备好接工单吧。
  • 结论——为修复和安全升级，不是为了头条功能 — 如果你自托管且依赖 NC_CONNECTION_ENCRYPT_KEY+2FA 或私网数据库/webhook（需处理上面的迁移）、是想用 Gantt/Shared Pages 的付费用户，或者被这些 bug 影响（时区导致存错日期、隐藏的 NOT NULL 字段静默丢行、中间表占用表数量上限、空表上的 AutoNumber），就值得升级。满足于弹窗式记录面板、又没用 2FA/私网配置的 CE 用户可以跳过——公开 API 没有变化，依赖安全更新（axios、next、mermaid）无论升不升都是幕后收益。

共享页面

**您现在可以公开共享 NocoDocs 页面**作为任何人都可以在浏览器中打开的只读链接，无需 NocoDB 帐户。无论您是共享产品文档、项目简介还是内部 wiki，您都可以将文档直接从编辑器获取到可共享 URL，或使用 iframe 片段将其嵌入到其他位置。关闭开关即可在几秒钟内撤销链接。 [了解更多关于共享文档→](https://nocodb.com/docs/noco-docs/share-document) ## 社区版中扩展的记录侧面板 2026.05.1 中引入的**扩展记录侧面板**现在在社区版中提供。打开记录会将其停靠在网格右侧，而不是全屏模式，因此当您编辑字段、阅读注释或扫描修订历史记录时，您的数据仍保留在视图中。这是所有版本的默认桌面布局；公众和共享观点仍然作为中心模式开放。 [了解更多关于扩展记录→](https://nocodb.com/docs/product-docs/records/expand-record) ## 账户安全 - **每个帐户一个活动会话。** 在新设备或浏览器上登录会注销之前的会话，跨每个登录路径（包括 SSO）。所有版本均默认开启； API 代币不受影响。 - **工作区 2FA 现在涵盖所有者。** 所有者不再免除工作区范围内的 2FA 强制执行，因此在需要 2FA 的企业工作区中，系统会提示所有者在继续之前进行注册。 ## 改进和修复 - **在扩展记录中搜索并隐藏空白字段。** 在扩展记录中，您现在可以搜索任何字段或值，这在您有大量字段时非常有用。另外还可以隐藏空白字段。 - **日期字段的固定过滤器。** 日期、日期时间、创建时间和上次修改时间字段现在可以作为紧凑的药丸固定到工具栏（确切日期、天前、过去 N 天）。 - **仪表板图表调色板。** 在云仪表板上，条形图、折线图、饼图、圆环图和散点小部件获得调色板选择器，仪表板获得范围颜色的完整颜色选择器。 - **箭头键步进数字表单字段。** 向上和向下箭头现在可递增和递减表单中的整数、小数和百分比字段，与货币已有的行为方式相匹配。 - **空表上的自动编号。** 将自动编号字段添加到空表中不再引发错误；序列初始化正确。 - **行着色在视图切换中保持不变。** 现在，当您切换视图而不是重置时，会保留行颜色条件的值。 - **连接表被排除在表限制之外。** 隐藏的多对多链接表不再计入基本的表限制，从而恢复了用户可见表的预期数量。 - **隐藏必填字段不再静默失败。** 隐藏必填（非空）字段现在会发出警告，在“字段”菜单中对其进行标记，在添加记录时自动展开隐藏字段，并显示明确的保存错误而不是删除该行。 - **日历和日期字段尊重列时区。** 在日历视图上拖动、调整大小和显示不再显示 MySQL DateTime 和时区配置列的错误偏移量。 ## 自托管注意事项 - **如果您使用的是 `NC_CONNECTION_ENCRYPT_KEY` 和 2FA，请务必阅读。** 在设置 `NC_CONNECTION_ENCRYPT_KEY` 运行的实例上，由于加密/解密往返，TOTP 在验证代码时出现问题，导致每个 2FA 验证失败并显示“验证码无效”。这是固定的。如果您使用 2FA，则需要禁用并重新注册。请注意，2FA 仅适用于基于电子邮件和密码的登录，不适用于 SSO。 - **数据库和 Webhook 的专用网络访问。** 默认情况下强制执行 SSRF 保护。如果您的实例连接到数据库或在专用或本地网络上发送 Webhooks，您可能需要选择使用相关环境变量（`NC_ALLOW_LOCAL_EXTERNAL_DBS`、`NC_WEBHOOK_ALLOW_PRIVATE_NETWORK` / `NC_ALLOW_LOCAL_HOOKS`），或使用 `NC_DISABLE_SSRF_PROTECTION` 全局禁用 SSRF 过滤。 NocoDB Cloud 始终强制执行 SSRF 保护。 - **安全依赖性审计。** 此版本清除了整个堆栈中的大量依赖性安全建议（包括 `axios`、`next` 和 `mermaid`），对公共 API 没有任何更改。 ------ ### 已关闭的问题 - [**已关闭**] 🐛 Bug：iFrame 嵌入不适用于共享 noco-docs [#13901](https://github.com/nocodb/nocodb/issues/13901) -
