nocodb 2026.06.2

nocodb 2026.06.2

变更流程图

亮点

  • 安全与鉴权加固 — OAuth refresh token 在并发下严格只能使用一次，access token 不能再当会话 token 用，公开的 OAuth client 端点也不再泄露敏感信息。所有版本还会拦截通过外部数据库主机发起的 SSRF，限制 webhook/图片/公式的资源占用，并修复 AI 提示 tooltip 里的存储型 XSS。广泛建议升级，尤其是对公网暴露的部署；OAuth 集成方要确认能正确处理并发的 token 轮换。
  • 自托管的破坏性变更：Helm chart 重写 — Kubernetes 部署现在把 app 和 worker 拆成各自独立的自动扩缩部署，使用外部 PostgreSQL/Redis 并支持 secret，加了中断预算和反亲和，默认每个 pod 1 vCPU/2Gi。需要迁移： 附件存储从 chart 的环境变量移到应用配置里，因此已有安装必须更新 values/secrets、迁移附件设置，并重新评估资源容量。
  • 更快的表格与更完整的导出 — Base/表格读取做了批量化以减少往返请求，对 Link 和 Lookup 字段很多的大 base 尤其明显；CSV、Excel、JSON 导出现在会把 Links 和 Lookup 单元格里的每条关联记录都包含进来。自托管还可以调节新的限额：NC_WEBHOOK_MAX_BODY_SIZE（默认 10 MB）、NC_THUMBNAIL_MAX_INPUT_PIXELS（默认 24 MP）、NC_THUMBNAIL_MAX_INPUT_PIXELS_SHRINKABLE（默认 100 MP）和 NC_FORMULA_MAX_OUTPUT_LENGTH。
  • 工作流方面也有实在改进 — 日历卡片支持 Compact/Expanded 高度、周视图可显示更多字段、周末可折叠；排序条件可以禁用或调整顺序而不必删除；Lookup 值能有独立的数字/日期格式。Gantt 新增里程碑引导线和持久化的分组开关，Page Designer 支持自定义页面尺寸和命名设计，表单会把未完成的填写内容保存在本地直到提交，同时可以通知 base 的任何协作者。用到这些视图的团队为了体验提升值得升级。
  • Oracle 支持仅企业版可用；不受影响的多数用户可以跳过 — Oracle 加入了受支持的外部数据源，表格、公式、关联、Lookup、聚合和图表都能用，但需要企业版附加组件，并通过 support@nocodb.com 激活。Oracle 客户应升级并联系支持；CE/Free 用户以及没用上改进的工作流、导出或自托管特性的团队，留在当前版本也没问题。

改进和修复

  • 更具可读性的日历。在紧凑和扩展记录高度之间切换卡片，在周视图中查看每张卡片的多个字段，并直接从日历的视图模式下拉列表中折叠或隐藏周末。 了解更多→
  • **百分比字段的圆形进度。**百分比字段现在可以将其进度呈现为 圆形 以及现有的 条形，通过字段的“进度条形状”选项进行设置。 了解更多→
  • 查找字段的格式选项。 当查找解析为数字或日期时，新的 格式 选项卡可让您独立于源字段设置其显示格式（小数、货币、百分比或日期、日期时间、时间），并且它适用于查找出现的所有位置。 了解更多→
  • 更智能的排序。 打开或关闭各个排序条件而不删除它们，然后拖动以重新排序排序字段。 了解更多→
  • 甘特图里程碑指南线和组切换。 里程碑现在会在日期标题处添加一条虚线指南线，以便一目了然地放置它们，可以关闭和重新打开分组而不会丢失其配置，并且生成 URL 的公式字段在侧边栏中呈现为 clickable 链接。 了解更多→
  • 页面设计器中的更多布局控制。 页面设计器扩展现在支持具有您自己的宽度和高度的自定义页面尺寸，并且您可以将多个命名设计保留在一个位置并切换、复制或重命名它们。 了解更多→
  • 以工作日为前缀的日期格式。 新的日期显示格式在单元格和网格组标题中添加星期几的前缀（例如“星期三 2026-06-10”或“星期三 10/06/2026”），适用于 ISO、欧洲和美国基本格式。 了解更多→
  • 表单会记住正在进行的答案。 公共共享表单现在会保存受访者在自己的浏览器中输入的内容，因此刷新或意外导航不会再擦除半完成的表单。草稿在提交时清除。 了解更多→
  • 通过电子邮件将表单回复发送给任何基础协作者。 表单的通知设置现在允许您选择哪些基础协作者在每次提交时收到电子邮件，而不仅仅是表单所有者。 了解更多→
  • 链接记录导出已完成。 CSV、Excel 和 JSON 导出现在包括链接或查找单元格中的所有链接记录。 ＃＃ 安全
  • OAuth 和身份验证强化。 OAuth 刷新令牌轮换现在在并发请求下严格为一次性使用，访问令牌不能再作为会话令牌呈现，并且公共 OAuth client 端点不再返回敏感材料。
  • 防止服务器端请求伪造。 外部数据库连接现在会在连接所有版本之前验证连接主机，从而阻止访问内部网络地址的尝试。
  • 资源耗尽保护措施。 传出的 Webhook 请求和响应正文、图像缩略图输入大小和公式字符串输出现已受到限制，因此过大的有效负载和图像不会再耗尽内存并导致工作线程崩溃。
  • 存储的跨站点脚本修复。 AI 提示工具提示中显示的字段名称现在呈现为纯文本，因此精心设计的字段名称无法再执行脚本。

自托管

  • 生产级 Helm 图表。 Kubernetes 图表从头开始重写，以实现高可用性：单独的应用程序和工作人员部署，每个部署都有自己的自动缩放、具有秘密支持的外部 PostgreSQL 和 Redis、Pod 中断预算和反关联性，以及每个 Pod 1 个 vCPU 和 2Gi 的合理默认资源请求。附件存储现在在应用程序中配置，而不是通过图表环境变量。 了解有关在 Kubernetes 上部署的更多信息 →
  • 更快的基础和网格加载。 打开基础或加载网格时发出的许多内部读取请求现在合并为单个批量请求，从而减少了具有大量链接和查找字段的基础上的往返。
  • 电子邮件和密码与 SSO 一起登录。 自托管部署现在可以在登录页面上的 SSO 旁边显示电子邮件和密码表单，而不是用 SSO 完全替换它，而是使用新的“允许电子邮件和密码与 SSO 一起登录”管理设置。 了解更多→
  • 密码重置在子路径后面工作。 重置密码页面现在从您的站点 URL 派生其基本 URL，因此密码重置链接在子路径和反向代理部署下工作。
  • 新配置选项。 NC_WEBHOOK_MAX_BODY_SIZE（默认 10 MB）限制 Webhook 负载大小，NC_THUMBNAIL_MAX_INPUT_PIXELS（默认 24 MP）和 NC_THUMBNAIL_MAX_INPUT_PIXELS_SHRINKABLE（默认 100 MP）绑定缩略图生成，NC_FORMULA_MAX_OUTPUT_LENGTH 限制公式字符串输出。 了解更多→
