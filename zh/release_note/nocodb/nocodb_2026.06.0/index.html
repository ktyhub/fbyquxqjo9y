nocodb 2026.06.0

这个项目是干啥的：一个开源版Airtable，把数据库变成在线表格看板还能嵌入关联记录，给不想写代码就想管数据的团队用。

变更架构图

亮点

  • 破坏性变更——SQLite 外部数据源受限 — SQLite 作为外部数据源现在仅限免费/未授权的自托管（Community Edition），已授权自托管和 Cloud 上被禁用。不需要改配置，但如果你在授权版或 Cloud 上依赖 SQLite 作为数据源，这条路已经移除——升级前先把数据源迁到受支持的数据库。这是本版唯一真正需要迁移的项目，下面其余内容均向后兼容。
  • NocoDB Sync（付费）与 “App Sync” 改名 — 新的 NocoDB Sync 可以把一个 base 的共享视图镜像到另一个 base，作为与源保持同步的同步表，适合把多个 base 汇总成报表中心，或在不交出原始数据的前提下分享整理后的切片。老用户注意命名变化：基于集成的同步现在统一归到 App Sync 下。仅付费/企业版可用——CE/Free 没有。
  • 文档版本历史与分组开关（付费） — Version History 会自动保存 NocoDocs 页面的每次编辑，查看者能浏览历史、编辑者一键恢复，保留期从 Free 的 3 天到企业版的整整一年。Group Toggle 给每个分组加了一个复选框，不用删配置就能关掉分组。两项都仅限付费档；CE 用户可以跳过。
  • 免费/CE 的实惠——日历多周视图、表格体验与 V3 API — 日历新增 2 Weeks 和 6 Weeks 布局（所有版本可用，按视图记忆）。表格改进包括：按住 Shift/Cmd/Ctrl 点击表头可跨字段批量操作（一次隐藏/删除/分组/筛选）、右键复制行、Select 选项按 A–Z 排序、AutoNumber 作为主显示值。V3 REST API 现在能创建/更新 Timeline 和 Gantt 视图，在 Number/Decimal/Rollup 字段上暴露 separator，并修复了通过 base64 或 URL 上传附件时未走正确文件引用流程的问题。以上任意一项都值得升级。
  • 升级机制与可靠性 — 新迁移（分组开关状态、版本历史表、加宽的 revision-id 列）会自动执行，单查询缓存会在版本变化时失效。当无法确定变更列时，webhook 不再静默跳过字段级触发器；空 body 的 POST/PUT/PATCH hook 现在会记为错误。Schema 同步更安全（关联表缺主键时不会丢掉链接/关系，且保留用户自设的主键）。一批依赖安全更新锁定了 express-rate-limit 和 path-to-regexp，不涉及公开 API 变化。总体看，为了安全和正确性修复值得升级；只有授权版/Cloud 上使用 SQLite 数据源的用户会遇到真正阻塞。

NocoDB 同步

**NocoDB Sync** 将共享视图从一个 NocoDB 库镜像到另一个 NocoDB 库，作为同步表，始终与其源保持最新。无论您是将多个团队基地整合到一个报告中心、从单一事实来源提供下游工作流程，还是在不移交原始数据的情况下共享精选的数据片段，NocoDB Sync 都能使双方保持同步，无需任何手动复制。现有的基于集成的同步现在分组在 **App Sync** 下。 [了解有关 NocoDB 同步的更多信息 →](https://nocodb.com/docs/product-docs/sync/nocodb-sync) ## 文档版本历史 **版本历史记录**会自动将每次编辑保存到 NocoDocs 页面，因此您编写的任何内容都不会真正丢失。无论您是要恢复昨天删除的部分、跟踪共享文档的演变，还是回滚不需要的更改，您都可以重新访问任何早期版本，准确查看更改的内容，并在单个 click 中将其恢复。观众可以浏览完整的历史记录，而编辑者可以恢复，其恢复时间取决于您的计划，从免费版的 3 天到企业版的一整年。 [了解更多版本历史记录→](https://nocodb.com/docs/noco-docs/version-history) ## 日历多周视图 **日历视图**在其周和月选项之间获得了两种新布局：**2 周**和 **6 周**，因此您可以准确地构建您计划的窗口。无论您是规划两周的冲刺，排列六周的内容日历，还是只是想要比一周有更多的背景信息，而不需要一整月的蔓延，这些布局都可以让您一目了然地看到正确的时间片段。每个视图都会记住您选择的布局，因此每个日历都会按照您离开时的方式打开。 ## 组切换 每个分组现在都有一个复选框，因此您可以关闭分组而不删除它，并在稍后以相同的配置完好无损地重新打开它。它可以方便地临时展平视图或比较分组和未分组的布局，而无需重建设置。 ## 改进和修复 - **对多个字段进行批量操作。** Shift-click 或 Cmd/Ctrl-click 网格列标题可一次选择多个字段，然后一步隐藏、删除、分组或按所有字段进行筛选，而无需逐个字段重复更改。 - **从网格中复制记录。** 右键 click 任意行以就地创建其副本。 - **按字母顺序对选择字段选项进行排序。** 持续的 A 到 Z 切换对单选或多选字段中的选项进行排序，并在您工作时保持该顺序。 - **自动编号可以是表的显示值。**自动编号字段现在可以充当主显示列。 - **窄屏幕上的工具栏更整洁。** 当空间紧张时，视图搜索会折叠为单个图标，而不是挤满工具栏。 - **链接和用户字段在电子邮件中正确呈现。** 表单提交和记录电子邮件现在正确显示链接记录和用户字段，而不是占位符文本。 - **更可靠的 webhook。** 当无法确定更改的列时，范围到特定触发器字段的 Webhook 不再被静默跳过，并且带有空正文的 POST、PUT 或 PATCH Webhook 现在会在挂钩日志中标记为错误，而不是显示为成功。 - **更安全的架构同步。** 当相关表没有主键时，同步架构不再删除链接或关系，并且在架构更改期间保留用户设置的主键。 ## API 更新 - **通过 V3 API 的时间轴和甘特图视图。** 您现在可以通过 [V3 REST API](https://nocodb.com/apis/v3/meta#tag/Views/operation/view-create) 创建和更新时间轴和甘特图视图，包括其日期相关选项。 - **V3 API 中的数字分隔符选项。** 数字、小数和汇总字段现在通过 [V3 API](https://nocodb.com/apis/v3/meta#tag/Fields/operation/field-create) 和脚本公开其 `separator` 设置（逗号、句点和空格样式）。 - **通过 V3 API 进行可靠的附件上传。** 通过 V3 API 附加文件，无论是通过 Base64 内容还是通过 URL，现在都遵循正确的文件引用流程，以便正确存储和链接上传。 ## 自托管注意事项 - **SQLite 作为外部数据源现在仅限于免费的自托管版本。** 它在社区版和未经许可的自托管实例上仍然可选，但在许可的自托管实例和云上被阻止。无需更改配置。 - **此版本中提供了新的数据库迁移**（分组切换状态、文档版本历史表和更广泛的修订 ID 列）。它们在升级时自动应用，并且当版本更改时单查询缓存自动失效。 - **依赖项安全批次。** 此版本清除了整个堆栈中剩余的依赖项安全建议批次，固定了包括 `express-rate-limit` 和 `path-to-regexp` 在内的包，对公共 API 没有任何更改。 ------------ ## 已关闭的问题 -
