nocodb 2026.08.2

变更流程图

亮点

  • 界面仪表盘与嵌入式关联记录 — 界面仪表盘的图表现在可以一次绘制多个字段，并支持第二 Y 轴（柱状、折线或散点），不同单位的字段能放在同一张图里；记录详情页的 Link 字段变成真正可用的嵌入式视图——搜索、排序、筛选、分组、就地编辑、关联/取消关联都不用离开记录。新增记录页按钮（Update record、Copy link、Delete、Go to URL、Run automation，配套新的 “When a button is clicked” 触发器）、更丰富的画廊主题、AI 生成筛选提示，以及就地实时更新。做界面应用的话，这就是升级的首要理由。
  • 界面与工作流下放到免费档 — NocoDB Cloud Free 现在也能用 Interfaces，且界面和页面数量不限；Community Edition 每个 base 带 2 个界面（各 2 页）和 2 个工作流，包含核心的触发、记录、流程节点。之前在免费版/自托管上被挡住的，现在门槛没了——但按钮可见性规则和 Every 15 minutes 同步仍仅限 Cloud Business+/已授权自托管。
  • 工作流文件夹、评论订阅与导入相关触发行为 — 工作流和脚本可以归类到文件夹；通过顶部铃铛可以订阅某条记录的全部评论（“Notify me about all comments”），发表评论会自动订阅。Record created/updated/matches conditions 触发器现在也会在 CSV 和文件导入时触发——大批量导入前请检查触发器，每条导入记录都算一次运行。测试运行、List records 的 Limit（现在超过服务端分页大小也生效）以及画布/缩放行为也做了修正；重度依赖自动化的用户升级后要重新核对触发配置。
  • 预告：API 日期时间格式的破坏性变更——已宣布，2026.08.2 尚未生效 — 下个版本会把 PostgreSQL 和 SQLite 上的日期时间从秒精度改为毫秒精度（2026-07-25 12:34:56+00:00 → 2026-07-25 12:34:56.000+00:00），读取时格式化，因此已有记录的返回值也会变。影响范围是 REST API 响应、webhook 载荷和 CSV/文件导出；使用严格/固定格式解析器的可能需要调整（Day.js 和多数 ISO 8601 解析器没问题）。精确相等的日期时间筛选仍按秒精度比较，可能漏掉非零毫秒的记录。MySQL、SQL Server、Oracle、公式渲染的日期时间以及应用内显示不受影响；不需要数据迁移或回填。请把这条当作提前通知，下次升级前审计一下集成方——本版本没有任何变化。
  • 自托管、数据完整性修复与可跳过人群 — 自托管的组织管理员获得管理后台/Members 访问权限（License 标签仍仅超级管理员可见）；Meta Sync 能处理上千列的 PostgreSQL schema；数据库错误做了分类以减少日志噪音。值得注意的修复：复制/沙箱 base 之间的权限隔离、公式在短暂连接抖动后恢复、实时重连后分组表格刷新、负数货币粘贴、长主键的撤销/重做、已安装 PWA 中的 SSO 登录。用到界面/工作流或碰到上述问题的建议升级；纯 MySQL/SQL Server/Oracle 的最小化部署、不用界面和工作流、日期时间解析也足够宽松的话可以放心跳过——2026.08.2 本身没有破坏性变更，也没有强制迁移。

修复了什么

  • 为导入的记录运行工作流程 - 创建记录、更新记录和记录匹配条件触发器现在针对通过 CSV 和文件导入添加的记录触发。在大量导入之前检查触发器，因为每个导入的记录都算作一次运行。
  • 工作流程画布 - 在工作流程之间切换或创建新工作流程会立即以 100% 缩放显示正确的图表，并且会打开一个新工作流程，并显示其“添加触发器”占位符。
  • 工作流程测试运行 - 在“当记录匹配条件时”测试此触发器现在遵循配置的过滤器，“当记录进入视图时从所选视图中采样记录”，并且节点变量仅反映当前测试运行。
  • 工作流中的列表记录限制 - 列表记录节点返回在其限制中配置的完整记录数，包括高于服务器页面大小的限制。
  • 智能文本与记录一起保存 - 当您 click 保存记录时，将保存对扩展记录中智能文本字段的编辑以及其他字段更改，并且关闭记录会提示您保存或放弃它们。
  • 公式字段和连接 blips - 公式字段在短暂的数据库连接故障中保持健康，并且任何标记有错误的字段都可以在下次读取时恢复。
  • 公式中的跨库查找 - 公式可以引用指向公式字段的跨库查找。
  • 重新连接后分组网格 - 当实时连接在空闲期后恢复时，分组网格视图会刷新其组、计数和页脚聚合。
  • 禁用的排序保持禁用状态 - 列表视图数据和分组网格现在支持排序启用切换，仅应用已打开的排序。
  • 查看文件夹 - 拖动“默认”部分仅移动该部分，复制视图会将其保留在其文件夹中，并且在创建第一个文件夹时，“默认”部分将展开展开。
  • Airtable 导入显示值 - 导入现在为每个表格选择一个可用的显示值，包括 Airtable 主字段为长文本的表格，回退到第一个符合条件的字段或新的标题字段。
  • 负货币粘贴 - 将 -100.50 或 -$1,234.56 粘贴到货币字段中会保留减号。
  • 权限在重复的基础之间保持隔离 - 字段和表权限、记录级安全策略和命令选项板结果现在严格限制在其自己的基础上，包括重复和沙箱副本。
  • 工作区记录使用情况 - 行计数使用情况现在对每个记录进行一次计数，因此可以根据工作区记录限制准确反映重复和快照的基数。
  • 使用长主键撤消和重做 - 主键值超过 20 个字符的表上的操作现在可以正确撤消和重做。
  • 安装的应用程序中的 SSO 登录 - 当 NocoDB 作为应用程序 (PWA) 安装时，Google、SAML 和 OIDC 登录正常完成，并且 OIDC 提供程序对话框现在验证其 URL 字段。
  • 集成选项列表 - 当无法加载 Slack 频道列表时，节点会解释原因并提供重试。- 界面修复 - 仅界面协作者可以从记录详细信息表或记录查看页面展开链接记录，分组依据可以在时间轴、甘特图和列表可视化上自由更改，界面构建器中的属性编辑无需重新加载页面即可应用，并且在切换页面之前所做的编辑将保存到其所在页面。
  • 缓存列表 - AI 聊天会话在使用后保留在侧边栏中列出，API 令牌范围更新保留所有权限，恢复的团队重新出现，并且列表视图级别保持不变。
  • PostgreSQL 数据源 - 从基本范围的连接创建数据源现在会显示架构字段，因此您可以选择 public 以外的架构。
  • 基本连接列表 - 基本设置 > 集成列出每个连接一次；同步集成位于“管理同步”下。

自托管注意事项

  • 组织管理员可以访问管理面板 - 在自托管部署中，具有组织管理员角色的用户现在可以访问管理面板和成员页面。 “许可证”选项卡仅对超级管理员可用。
  • 针对大型架构的 Meta Sync 的改进 - Meta Sync 现在可以在具有数千列的外部 PostgreSQL 架构上完成。在没有表所有权的情况下尝试进行架构更改也会返回一个更清晰的错误，标识受影响的表。
  • 改进的错误日志记录 - 数据库错误现在进行分类，以减少不必要的日志噪音。排除了约束违规等预期错误，而连接失败、池耗尽和繁忙的 SQLite 数据库等基础设施问题则包含诊断详细信息。

计划对 API 日期时间格式进行重大更改

此更改计划在下一个版本中进行，不是 2026.08.2 的一部分。我们现在宣布这一消息，以便为集成做好准备。 在 PostgreSQL 和 SQLite 部署中，NocoDB 返回的日期时间值将从秒精度变为毫秒精度：

今天 下一个版本
2026-07-25 12:34:56+00:00 2026-07-25 12:34:56.000+00:00
  • 范围： REST API 响应、Webhook 负载和 CSV/文件导出。值在读取时格式化，因此现有记录也以新格式返回。无需数据迁移或回填。
  • 要检查的内容： 使用严格或固定格式解析日期时间的消费者可能需要接受毫秒部分。 Day.js 等宽容解析器和大多数 ISO 8601 解析器不受影响。
  • **过滤器：**范围过滤器和排序不受影响。精确日期时间相等过滤器以秒精度进行比较，因此它们可能与携带非零毫秒的值不匹配。毫秒感知过滤计划作为后续措施。
  • 不受影响： MySQL、SQL Server 和 Oracle 连接保持第二精度，公式呈现的日期时间保持第二精度，并且应用程序中的日期时间显示不变。
