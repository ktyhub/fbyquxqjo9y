compose v5.7.1

这个项目是干啥的：Docker 官方的多容器编排工具，用一个配置文件就能一键启动一整套服务。给需要同时跑数据库、后端等多个容器的开发者用。

变更架构图

亮点

  • 远程资源缓存加固（OCI + git） — PR #14490 现在按 digest 校验拉取的 manifest，并且只接受完整的缓存条目；PR #14462 在中断和并发访问下保持提取项目缓存的一致性；PR #14475 把 git commit 检出到独立位置，并按资源种类使用单独缓存目录。这些一起修复了真实的缓存损坏和陈旧/部分内容 bug；如果你用 extends/includes 配合 OCI artifact 或 git 仓库，这是升级的主要理由。无需迁移。

  • docker compose down 不再移除无关镜像 — PR #14458（首次贡献者 @Aghayenoor）保留所选服务之外的镜像。这是有意的行为改变：定点 down 调用不会删除仍被其他服务使用的镜像。如果你依赖限定范围的 down，值得升级；但请核查任何依赖旧清理副作用的脚本。

  • 更清爽的进度、警告和流处理 — PR #14467 让网络和卷的进度各自只在一行报告一次，PR #14299 把”忽略 uid/gid/mode”的警告从配置加载移到创建时（因此只在真正适用时出现），PR #14444 把 io.EOF 当作有界事件流的正常结束。这些是小的 UX/健壮性改进，不是破坏性变更。

  • 仅工具链和内部重构 — Go 升到 1.27 再到 go1.27.4（#14486/#14489），加上 go.yaml.in/yaml/v4 v4.0.0（#14468）、gRPC 1.85.0（#14445）、docker/cli 29.9.3+incompatible（#14451）和 golangci-lint v2.15.0（#14487）；日志/attach、镜像和依赖图代码移入 internal/ 包。这是一次真正的补丁发布，不是重打标签或纯元数据变更——但没有破坏性变更或迁移步骤，没撞上上述缓存/down 问题的用户可以放心跳过。

发生了什么变化

修复🐛

  • 修复（oci）：在https://github.com/docker/compose/pull/14462中@ndeloof的中断和并发访问时保持提取项目的缓存一致
  • 修复（git）：检查提交，并通过https://github.com/docker/compose/pull/14475中的@ndeloof将远程资源的缓存保存在每种目录中
  • 修复（撰写）：在 https://github.com/docker/compose/pull/14467 中的@glours 的独立行中报告一次网络和交易量进度 *修复（配置）：在创建时警告忽略的uid / gid /模式，而不是在https://github.com/docker/compose/pull/14299中@ndeloof加载时警告 *修复（向下）：在https://github.com/docker/compose/pull/14458中保留@Aghayenoor选择的服务之外的图像
  • 修复（事件）：将 io.EOF 视为 https://github.com/docker/compose/pull/14444 中 @Bruce848647703 有界流的正常结束

内部🔧

  • 修复 https://github.com/docker/compose/pull/14455 中 @glours 的显示器测试夹具类型
  • ci：通过 docker/setup-docker-action 在 https://github.com/docker/compose/pull/14456 中安装 @glours 的 e2e 引擎
