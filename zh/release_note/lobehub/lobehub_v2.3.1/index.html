Linux 打包修复 (#22190)

第一个 Linux 桌面构建失败，因为电子构建器 26.16.1 的模板 Snap 目标在 AppImage 读取 chrome-sandbox 时从共享 linux-unpacked 目录中删除了 chrome-sandbox。窗户过去了； macOS 作业被矩阵快速失败取消。

  • 将电子构建器升级到 26.18.0 并更新了独立的桌面锁定文件，包括上游修复电子用户区/电子构建器#10333。
  • 添加了针对已安装的打包程序和实际临时文件的集成回归：在 26.16.1 上因 ENOENT 失败，在 26.18.0 上通过。下载/压缩器执行被存根；执行真正的暂存、过滤和文件系统突变。该助手对于其他目标保持不变，但被排除在 Snap 输入之外。
  • 更改文件 lint、回归和内置核心打包测试（2 通过）、冻结锁定文件安装和 git diff --check 通过。
  • 修复通过#22190合并，因为release/*分支需要PR；没有分支保护被绕过。
  • 此仅构建工具修复不需要新的 UI 接受。新的 PR CI 运行正在重新检查完整的多平台打包；本地测试并不要求真正的安装程序构建或启动。
