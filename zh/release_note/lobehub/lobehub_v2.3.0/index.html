lobehub v2.3.0

变更流程图

亮点

  • 主动式 Bot 默认开启（行为破坏性变更） — v2.2.21 中预告的灰度标志已移除：现在每个 Bot 都会判断其监听频道中的每条消息，自行决定发言、保持沉默还是等待，在没有额外模型调用的情况下介入未回答的问题（#22024、#22038）。要恢复旧的”仅 @提及才响应”行为，所有者必须在 Wake 策略标签页顶部禁用新的 主动参与 区块（立即保存；关闭后会隐藏 Duties/Channels/Pace，只保留监听关键词）。新的 Wake 记录标签页会用 30 天摘要、模型评分、原因和 Discord 链接审计每条被判断的消息（#21934）。任何依赖 Bot 在被提及前保持沉默的用户，都必须在升级前重新检查此设置。
  • 自托管升级需要迁移计划 — 六项自动启动迁移 0193–0198 新增目标/文件共享和结构化记忆表、文档历史归因、记忆列、索引、用于频道任务的 (message_id, member_id) 唯一索引，以及目标可见性（#21844、#21611、#21888、#21672、#21935、#21901、#22027）。关键：0196 会在事务中于 user_memories_* 表上建索引，运行期间阻塞写入；在大表上请用 CREATE INDEX CONCURRENTLY IF NOT EXISTS 预先创建，让该迁移变为空操作。另请注意 OIDC provider 现在把请求主机固定到 APP_URL（#21985）——上线前请验证该值正确。
  • 协作与频道 UX 是主要的功能工作 — 实时多人页面编辑，带有沙箱化的 Agent 编辑和同步时显示的已存储内容（#20322、#21924、#21919），Discord 风格的回复 Thread 和引用，为新 Agent/项目自动创建频道，以及把记忆整合为可在停止后恢复的”故事”（#21968、#22006、#22007）。仪表盘新增声明式卡片布局、createDashboard 工具和分阶段的小组件审批（#22016、#22049、#21954、#21936）。这是本版主要的功能收益。
  • 平台、API 与集成新增 — 持久化沙箱现已提供，预览和付费用户默认使用自己的网盘（#22032）；白标签构建可以设置自己的桌面身份，品牌信息从提示词、邮件和 passkey 流程中去硬编码（#21890、#21930）；积分额度可通过 API/SDK 和 lh 读取（#21933）；新增 CLI 命令 lh topic send、lh message reply 和 lh workspace member update（#21938、#21965、#21959）；浏览器工具新增 setViewport（#22011），以及通用 TTS 类型和 MiniMax t2a_v2（#21942）。OIDC 主机固定到 APP_URL 是显著的安全加固（#21985）。
  • 值得升级吗？ — 如果你想要主动式 Bot、实时协作、新的仪表盘/记忆模型，或持久化沙箱与白标签改动，就升级——这是一个包含 145 个 PR 的实质版本（v2.2.21 → v2.3.0，#22056）。如果你依赖 Bot 只响应 @提及且尚未审查新的 Wake 策略，或者你是自托管且记忆表很大、无法安排 0196 阻塞写入的迁移窗口，可以跳过。它不是空操作、重新打标签或纯元数据版本。

发布 v2.3.0

来自 PR #22056：https://github.com/lobehub/lobehub/pull/22056

🚀 LobeHub 发布 (v2.3.0)

发布日期： 2026 年 11 月 1 日
自 v2.2.21 起： 145 个合并 PR · 7 个贡献者

机器人不再等待被@提及。默认情况下，主动机器人处于启用状态，每个机器人都会读取其频道，在可以提供帮助时介入，并向其所有者显示其发出的每个呼叫。频道、页面、内存、仪表板、任务和目标使该版本更加完善。

🤖 主动机器人

到目前为止，只有当有人@提到它时，机器人才会回答。在 v2.2.21 中的推出标志后面预览了机器人唤醒。在 v2.3.0 中，每个机器人都会启用此功能：机器人会判断其观看的频道中的每条消息，并自行决定是否大声说话、保持安静或等待。

  • 默认情况下打开，带有关闭开关 - 推出标志消失了，每个机器人都会自行发言，除非其所有者将其关闭。该开关是通道设置“唤醒策略”选项卡顶部的新“主动参与”块，并在更改后立即保存。关闭后，“职责”、“频道”和“节奏”选项将被隐藏，只有观看关键字仍然会唤醒机器人。 (#22024)
  • 当它可以提供帮助时介入 - 对于所有者编写职责的机器人来说，机器人不再等待落在其中的消息。当有人留下无人回答的悬而未决的问题或问题时，它也会介入，并且机器人可以解决它。在一个人进入模型后立即出现一行而不是被跳过，并且机器人仍然不会回复给其他人的回复。这不会添加额外的模型调用。 (#22038)
  • 唤醒记录 — 机器人设置中的新唤醒记录选项卡列出了机器人判断的每条消息。它显示 30 天的摘要（唤醒、跳过、延迟、主动唤醒），以及每条消息的结果、模型分数和可读的原因，以及返回 Discord 上消息的链接。按结果过滤，仅主动唤醒或仅未标记，并将每个决策标记为 ✓ 正确或 ✗ 错误。 (#21934)
  • IM 中的故障更清晰 — 回复解释了快速失败沙箱调度错误和飞书错误 41050，而不是纯粹的故障，通用回复失败消息更清晰，内部元数据不包含在公共回复中。 （#21973、#21525、#21955、#21899）

✨ 亮点

  • 实时页面协作 — 多人可以同时编辑页面，页面代理编辑在沙箱中运行，页面在房间同步时显示其存储的内容，而不是空编辑器。 （＃20322，＃21924，＃21919）
  • 频道对话 — 在回复中引用消息，在嵌套在 Discord 风格连接线下的自己的线程中跟踪代理回复，并使用紧凑的 IM 风格编辑器进行编写。提及分别列出成员和代理。 （#22025、#22042、#21994、#22026、#21885）
  • 自行开放的频道 — 每个新代理都会获得一个直接频道，每个新项目都会获得一个通用频道。在只有一个代理的组中，每条消息都会直接发送给该代理。 (#22018、#21996、#21927)
  • 内存作为故事 — 旧上下文被合并到上下文和达析报告中，并在上下文选项卡上显示为故事，并且停止的合并运行会恢复而不是重新开始。 （#21968、#22006、#22007）
  • 仪表板 - 小部件使用带有预设和用户参数的声明性卡布局，仪表板获取描述和 createDashboard 工具，小部件批准显示其阶段。 （#22016、#22049、#21954、#21936）
  • 任务 — 从任务工具或 CLI 中选择任务模型，在公共任务上保留私有代理（使任务私有或接管），并为设备和工作目录使用一个“跟随代理”开关。 （#21852、#21937、#21932、#21848）
  • 目标 — 目标可以在工作区级别共享，您可以自己重命名或使用智能重命名。新目标不再使用整个指令作为标题。 （＃22027，＃21970）
  • 持久沙箱 — 持久沙箱已不再预览，付费用户默认使用其驱动器。 (#22032)
  • 文档、文件和收藏夹 — 将主题添加到收藏夹，通过 ID 直接链接到库文件夹、页面和文件，打开聊天旁边的文档文件链接，并通过链接共享文件。 （#21950、#21923、#21913）
  • 凭据 — 工作区和私有凭据选项卡，可在多个工作区之间共享。 (#21670)

🏗️ 核心代理和架构

  • 一个成员的运行永远不会中断另一个成员的实时运行，并且一旦写入其消息，就不再重新发送排队的后续运行。 （＃22037，＃21777）
  • 代理管理在安装市场插件之前搜索 MCP 市场，并且可以从身份表单创建代理。 （＃21703，＃21987）
  • 具有 MiniMax t2a_v2 语音和 TTS 支出标签的通用 TTS 模型类型。 (#21942)
  • 图像生成拒绝不支持的参数，并显示明显的错误而不是服务器错误。 (#21945)
  • 模型库中的中国供应商以国际美元定价。 (#21808)
  • 验证以帐户的语言写入生成的标准和报告。 (#22035)
  • 模型发现和运行时配置正确到达代理。 (#21895)

外部代理

  • Claude Code 项目内存显示在工作区面板中，代理配额会选择每个设备的 Claude Code 帐户。 （＃21234，＃21984）
  • 每个后台任务唤醒都会保留在运行的回复中，子代理线程在副本之间保持线性，并在最终确定后可恢复。 （＃21939，＃21917）
  • CLI 状态卡显示代理实际运行的设备。 （＃21931，＃21999）

📱 平台/集成

  • 桌面： 文件菜单中的新窗口打开当前工作区。在 macOS 27 上，侧边栏使用原生 AppKit 玻璃，窗口背景遵循系统主题切换。 （#21928、#21854、#21921、#21894、#21920）
  • **白标：**发行版可以设置自己的桌面应用程序标识，并且品牌不再硬编码在LLM系统提示、工具描述、身份验证电子邮件、密钥提示或默认助手名称中。 （#21890、#21930、#21902、#21882、#21946）
  • CLI: lh topic send / lh message reply 唤醒另一对话，lh topic send --new / lh message send 开始新对话，lh workspace member update 设置成员的头衔和职责。 （#21938、#21965、#21959）
  • CLI: 跟随代理在多路复用网关套接字上运行，并通过更清晰的升级重启来检测系统服务。 （＃22048，＃21869）
  • **API / SDK：**通过API、SDK和lh读取呼叫者的信用额度。 (#21933)
  • **浏览器工具：**组合键有效，并且 setViewport 可用。 (#22011)

🖥️ 用户体验

  • 聊天在您发送后保持其滚动位置，并在 500 行页面中再次加载历史记录。 (#22030)
  • 设备选择器在悬停时显示正在运行的主题，设备卡在 CPU 和内存旁边显示磁盘使用情况。 （＃21915，＃21940）
  • 搜索技能面板，将主题过滤为每个特工仅您自己的主题，并从批量栏中取消存档。 （#21961、#21870、#21876）
  • 项目“+”按钮会打开一个空白草稿，创建频道时项目代理会先出现。 （＃21989，＃22004）
  • 从 Works Canvas 选项卡管理画布存储，并从页面编辑器的斜杠菜单插入视频。 （＃21831，＃21925）
  • 验收悬停卡在浏览器中打开验收，本地报告可以接受或拒绝交付。 （＃21966，＃21947）
  • 八个特工封面纹理，徽章卡上有个人资料封面。 (#21868)
  • 启动加载提示仅在缓慢启动时出现。 (#21941)

🔒 安全性和可靠性

  • 安全性： OIDC 提供商将其请求主机固定到 APP_URL。 (#21985)
  • **可靠性：**页面在无服务器构建上保持播种和投影，文件代理 URL 从页面源解析，并且后期链接 PR 查找不再使设备视图崩溃。 （#21919、#21914、#21960）
  • 可靠性： 配额限制计划不再丢弃报告。 (#22000)

数据库迁移（自托管）

此版本添加了六个迁移 (0193–0198)：目标/文件共享和结构化用户内存表、文档历史记录属性、具有订阅登录名和设备帐户绑定的内存列、内存表上的索引、通道作业的 (message_id, member_id) 唯一索引以及目标可见性。它们在启动时自动运行。 （#21844、#21611、#21888、#21672、#21935、#21901、#22027）

[!注意] 0196 在事务内的 user_memories_* 表上构建索引，这会在运行时阻止对这些表的写入。如果它们很大，请在升级之前使用 CREATE INDEX CONCURRENTLY IF NOT EXISTS 创建相同的索引，以便迁移不会执行任何操作。
