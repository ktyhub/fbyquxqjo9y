ponytail

收录 30 个版本 · 最新 v5.3.3（2026年10月29日）

DietrichGebert/ponytail ↗

202630

10/29
v5.3.3 修订

这个人清理了乐队。在团队、企业和托管计算机上，第一个提示上的警告消失了，并且区域再次显示您的模型和会话名称。在 VS Code 中，它保留在一行上，其他插件的命令不再打印在马尾辫的名称下，并且嘈杂的“重复？”提示消失了。

 10/16
v5.3.2 修订

马尾辫 5.3.2 将您的旧会话带到董事会。 /ponytail band import 会读取您过去的 Claude Code 会话一次，并将其添加到成本、代理时间和代币中，以便您可以将它们与今天的会话进行比较。该板还显示每个会话使用的模型。

 10/16
v5.3.1 修订

马尾辫 5.3.1 修复了 5.3 的带子。克劳德代码提示上方的其他模组现在显示在带子下方而不是消失，并且在 Windows 上，带子找到没有 HOME 的文件，并在没有 mkdir 的情况下写入任务分类帐和板。感谢@AllDmeat 和@mohofo7 的修复，感谢@tomkor 和@1410822048 的报告。

 10/16
v5.3.0 小版本

马尾辫 5.3 在克劳德代码提示上方放置了一条带：当前任务的成本、其令牌和代理时间、重用了多少现有代码以及测试是否仍然通过。一台 click 可打开看板、一个本地页面，其中包含项目中的每项任务以及一张可供共享的卡片。默认情况下，所有内容都保留在您的计算机上，/ponytail band 隐藏它，并且需要 Claude 代码 2.1.290 或更高版本。

 10/13
v5.2.0 小版本

主要针对您选择的级别进行修复。现在，它可以承受上下文压缩，而不是回退到默认值，并且在 macOS 上，挂钩不会再丢失其输出，因此规则集始终会到达。 同样在这里：Cursor 安装程序留下了它无法单独理解的 hooks.json 文件，并且不再删除您自己的具有相似名称的钩子，OpenCode 不再陷入审查并支持 /ponytail default，pi 完成 /ponytail 参数，OMP 在默认级别启动新会话。感谢所有发送修复的人！

 10/12
v5.1.1 修订

修复版本。最重要的是来自 5.0 的代码库映射：存储库可以将其自己的文本放入隐藏的会话上下文中，并且存储库中的符号链接可以挂起会话启动，直到规则集永远不会到达。两者都已修复，并且地图现在有一秒的限制，因此规则始终会加载。 同样在这里：当项目固定旧节点时，挂钩再次工作，OpenCode 2 的三个修复（压缩缓存、命令参数、提及突出显示），并且 /ponytail-debt 现在跳过 .gitignore 中的所有内容。感谢本周发送报告和修复的所有人。

 10/08
v5.1.0 小版本

马尾辫不再将其名称写入您的代码中。故意的快捷方式现在标有中性注释 shortcut: , ，并且 /ponytail-debt 仍然可以找到旧的 ponytail:，因此您的分类帐中的任何内容都不会丢失。想要多说一句话，还是根本不说？在项目的 CLAUDE.md 或 AGENTS.md 中这样说并运行 /ponytail-debt 。 发货前对照 5.0.0 进行测量：相同数量的标记、相同的通过率、相同的成本。

 10/08
v5.0.0 大版本

Ponytail 5 是从头开始重建的：新规则、新审查、新审计。

 10/05
v4.13.0 小版本

此版本主要是关于马尾辫保持在您设定的水平。 Codex 上的切换级别现在提供了新级别的规则，每个项目都保留自己的模式，关闭实际上意味着关闭，并且状态线徽章在插件更新后仍然存在。 Kimi Code 作为新主机加入，自述文件现在还提供西班牙语、韩语、简体中文和日语版本，并且取消了 ZCode 支持。

 10/05
v4.12.0 小版本

审查和审计结果现在已编号，因此您可以回答“修复 2 和 4”，而不用引用后面的行。 CodeBuddy 通过现有的 Claude 插件运行马尾辫，/ponytail-gain 显示诚实的代理基准平均值（代码减少 54%，令牌减少 22%，成本降低 20%，速度提高 27%，安全性得到保证），而不是旧的单次数字（聊天基线膨胀）。自述文件也变得更精简：每个代理安装步骤现在都位于 INSTALL.md 中。

 10/04
v4.11.0 小版本

如果您在 Codex 中使用马尾辫，请更新。由于 v4.10.2 根 plugin.json 中的一行更改使 Codex、VS Code 和 Qwen 将马尾辫加载为仅技能代理插件，因此挂钩从未注册，规则也从未到达模型。这个版本去掉了这条线，他们又得到了完整的马尾辫。最重要的是，Hermes 发送一次规则集而不是每次都发送，审查和审核学习 reuse 标签，另外七个代理获得记录的设置。

 10/03
v4.10.3 修订

几次会议，一台机器，不再有战斗。马尾辫模式现在保留在每个项目中，因此一个存储库中的会话不再切换或清除另一个存储库中的会话模式。裸露的 /ponytail 在任何地方的行为都是相同的（关闭打开，打开仅报告级别），ZCode 最终获得规则集，并且 Codex 在每次启动时停止显示黄色警告。

 10/03
v4.10.2 修订

安全可靠的版本。生命周期挂钩不再将插件路径拼接到 shell 文本中，缓慢的子代理匹配器不再挂起会话，npm 发布现在等待绿色测试。最重要的是，Windows 和 WSL 挂钩停止挂起并再次找到它们的脚本，Pi 保留其提示缓存，OMP 保留其提示部分，Hermes 再次安装工作。感谢 11 位首次贡献者。

 10/02
v4.10.1 修订

OpenCode 2 支持。 OpenCode 插件无法在 OpenCode 2 上加载，并显示“插件必须导出默认定义”，现在它会加载所有命令和技能。相同的入口点仍然在 OpenCode 1 上运行（从 1.15 到 1.18.34 进行测试），并且在 OpenCode 2 上，/ponytail 开关已应用于当前消息。感谢@ragokan 提供的端口。

 09/14
v4.10.0 小版本

马尾辫的两个新家。标题：通过 hooks.json 提供本机游标支持，其中 scripts/cursor-hooks.js install 会合并到现有的游标挂钩文件中，并保留其中的其他所有内容。另外还有一个新功能：Grok Build 技能适配器、VS Code Copilot 终于被正确检测到（不再有 Claude Code 状态栏轻推），并且 Claude.ai 市场验证器再次接受该插件。

 08/07
v4.9.0 小版本

五周的工作一次性合并。标题：/ponytail default 使您选择的模式在重新启动后仍然有效，并且裸露的 /ponytail 现在报告活动级别而不是重置它。还有新功能：Qoder 支持、通过 PONYTAILSUBAGENTMATCHER 确定子代理作用域、pi 状态栏控件以及跨 Windows、Codex、OpenCode 和卸载程序的约 30 个修复。

 06/24

 06/23
v4.8.1 修订

补丁发布。仅元数据，不更改规则集或行为。 v4.8.0 附带的版本清单仍然读取 4.7.0（以及 0.1.0 上的 package.json 文件），因此插件即使在更新后也将 4.7.0 报告为最新版本。此版本将每个版本承载文件与 4.8.1 对齐，以便版本在 Claude、Codex、Copilot 和 Gemini 之间正确报告。
