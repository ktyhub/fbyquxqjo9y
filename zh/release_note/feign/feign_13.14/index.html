feign 13.14

小版本 发布时间2026年8月19日 来源OpenFeign/feign 英文原文

feign 13.14

变更流程图

亮点

  • Multipart 与请求头注入加固 — 一组修复让用户可控的请求头和 multipart 部件变得安全：Content-Disposition 中的 CRLF 和引号被转义（#3417），multipart/Content-Type 中的 CRLF 被剥离（#3432），解析后的请求头模板值中的 CRLF 也被剥离（#3444），边界值现在来自 SecureRandom（#3429），multipart 参数保留了委托方的内容类型（#3382）。如果你构造 multipart 请求或把外部值传入请求头，这一点很关键——它堵住了请求头注入的攻击面并修复了畸形请求体；单凭这一条就值得升级。

  • 字符集处理变得显式且一致 — 请求体现在按 UTF-8 编码，而不是平台默认字符集（#3442）；SOAP 请求体使用配置的字符集（#3433）；StringDecoder（#3453）、gson/Jackson 迭代器解码器（#3447）和 OkHttp 请求体读取器（#3441）现在都会遵循响应字符集；无效的 content-type 字符集回退到 UTF-8（#3427）；urlencoded 表单体中的集合值也会被编码（#3436）。好处是跨平台得到可复现的字节序列。注意：如果你此前依赖平台默认非 UTF-8 编码，或服务端声明了（错误的）字符集，输出和解码后的字符串可能改变——建议用针对性测试验证。

  • HTTP 客户端与 Content-Length 正确性 — 在 Http2Client 中，Content-Length 在收窄为 int 前先被限制上限（#3431）；GoogleHttpClient 和 DefaultClient 中对负长度做了封顶（#3492）；DefaultClient 修复了重复 Content-Length 的处理（#3448、#3451）；gzip/deflate 解码后清除了失效的长度值（#3445）。此外：jdk.httpclient.allowRestrictedHeaders 现在会被遵循（#3419）；空的 GET 请求体不再被转成 POST（#3463）；带空请求体的 POST/PUT/PATCH 不再被赋予默认的 Content-Type（#3507）；HC5 新增 deflate 请求编码（#3464）。这对与严格服务端及代理的互操作很重要；其中空请求体行为的改动最可能影响现有调用方。

  • 新协议与扩展能力 — 新增 HTTP QUERY 方法支持（RFC 10008，#3454）、基于 graphql-transport-ws 的 GraphQL 订阅（#3512），以及解码 GraphQL 操作的每个根字段（#3526）；Expressions 最大长度可配置（#3422，修复 #2916）；无效的表达式修饰符按字面量处理（#3437）；Capability 实例可以提供响应拦截器（#3446）；修复了克隆构建器上的流式方法（#3449）；创建 unmarshaller 时会应用 JAXB 工厂属性（#3519）；errorReading 抛出的 FeignException 保留响应体（#3415，修复 #2618）。这些大多是增量式增强；如果其中某项正好适用于你，就值得升级，否则不构成升级理由。

  • 构建/依赖迁移说明 — feign-bom 被扁平化，导入它不再覆盖你自己的依赖管理（#3508）：如果你此前依赖旧 BOM 来锁定传递依赖版本，需要重新显式声明。依赖升级包括 Spring Boot 4.0.6 → 4.1.0（#3408）和 hibernate-validator 6.2.5.Final → 9.1.0.Final（#3416/#3425/#3428），后者跨越了 javax→jakarta 命名空间边界——如果校验是你的技术栈的一部分，请连同众多传递依赖升级（httpclient5、netty、jackson-bom、google-http-client、guava）一起确认兼容性。主 changelog 中没有明确的 API 破坏性变更。结论：使用 multipart、在意字符集正确性，或想要新协议特性的团队应升级；仍锁定在 javax 校验或依赖 feign-bom 旧依赖管理行为的团队应先验证；完全不受上述影响的团队可以跳过。
