Release Note

版本 1.39.0 - 2026-09-01

变更流程图

亮点

  • 添加对 Kubernetes、v1.36 和 v1.37 的支持（默认：v1.37.0）
  • 默认容器运行时现在是containerd
  • 添加基于 Traefik Helm 的入口插件
  • VirtualBox 驱动程序现在支持 Apple Silicon (VirtualBox 7.1+)

特点

  • 添加对 Kubernetes、v1.36 和 v1.37 的支持（默认：v1.37.0）（#23567、#23596）
  • 添加基于 Traefik Helm 的插件 (#23225)
  • 将 Helm 添加到 minikube ISO (#23420)
  • 将默认访客 Helm client 升级到 Helm 4 (#23383)
  • 为 VM 驱动程序添加可配置的 DNS 服务器 (#23069)
  • 添加 --mdns 标志以在每次 VM 启动时启用 mDNS (#22964、#23208)
  • 驱动程序：使用确定性 MAC 地址 (#23172)
  • vfkit：在可用时自动选择 vmnet 共享网络 (#23040)
  • virtualbox：使用 VirtualBox 7.1+ 支持 darwin/arm64 (#22861)
  • ISO：为崩溃堆栈跟踪添加 systemd-coredump (#23064)
  • ISO：为 knftables 消费者启用内核 nftables (CONFIG_NF_TABLES) (#23518)
  • ISO：为 Calico 3.32.2 启用安全性 (#23592)
  • ISO：包含 aarch64 的 openvswitch 内核模块 (#23151)
  • ISO：启用 CONFIG_TASK_IO_ACCOUNTING 和相关内核选项 (#23271)
  • 下文：从 GitHub 下载预加载作为默认设置，从 GCS 下载预加载作为故障转移（#23087）

性能

  • 驱动程序：并行启动 VM 驱动程序 (#23112)
  • 为 krunkit 驱动程序添加 --vmnet-offloading 启动标志 (#22962)
  • ssh：外部 SSH client 首选 AES-GCM 密码（#23125）
  • ssh：在等待 SSH 服务器时避免不必要的睡眠（#23001）

错误修复

  • 插件：修复来宾虚拟机内的 Helm 验证失败（#23253、#23329）
  • 通过禁用 ExtendWebSocketsToKubelet 修复 Kubernetes v1.36+ 上的 cri-dockerd 的 kubectl exec (#22921)
  • 修复 --extra-config=etcd.* 产生无效的 kubeadm 配置（#23051）
  • 修复多节点CNI警告逻辑。 (#22779)
  • 修复 SSHRunner ExitCode 对于 SSH 命令总是返回 0 (#23364)
  • 修复 minikube 节点命令的使用字符串。 (#22775)
  • kvm：在运行 virsh 之前检查 libvirt 组成员身份（#23369）
  • 修复带有端口的注册表引用的保留标记 (#23228)
  • 使用缓冲通道来防止 goroutine 在状态超时时泄漏 (#23215)
  • 仅当标志明确时修复针对 virtualbox 的警告 (#22960)
  • 图像加载：修复加载容器使用的图像时出现静默失败的问题 (#23034)
  • 节点添加：使用 suggestMemoryAllocation 而不是硬编码 2200MB (#23305)
  • 代理：遍历 RoundTripper 包装器以剥离内部 *http.Transport 上的代理（#22910）
  • vmnet：修复 Intel Mac 上的brew 安装路径并支持brew bin 路径（#23039）
  • mount：澄清对双向防火墙规则的需求（#20442）
  • 驱动程序：在 macOS 上删除重复的 DHCP 租约处理（#23084）
  • 破解/更新：跟踪主要标签上的注册表插件（#23586）
  • 破解/更新：将 kong 图像标签更新为 3 (#23585)
  • ISO：用 nerdctl-bin Buildroot 包文件中的制表符替换空格 (#23438)
  • ISO：尝试修复 ISO 构建失败 (#22879)
  • ISO：修复 ISO 构建脚本可靠性和错误处理 (#23218)
  • ISO：支持在arm64主机上构建arm64 ISO（#22862）
  • ISO：使用 docker buildx 的二进制文件而不是从源代码构建（#22942）

重大变更

  • 将默认容器运行时更改为containerd (#23562)
  • ISO/KIC：将对 cri-dockerd 的支持限制为 x86 和 arm64，并将 cri-dockerd 迁移到预编译的 GitHub 二进制文件 ([#22922](https://github.com/kubernetes/minikub
