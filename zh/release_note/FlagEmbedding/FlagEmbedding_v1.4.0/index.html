FlagEmbedding v1.4.0

FlagEmbedding v1.4.0

这个项目是干啥的：是一个专门做文本检索模型的工具库，提供BGE系列模型，让做搜索和知识库问答的开发者能把资料里的相关内容更准地找出来。

变更架构图

亮点

  • BGE-Reasoner 作为全新 SOTA 检索家族登场 — PR #1510–#1531 引入了一个带推理增强的 embedder/reranker，宣称在 BRIGHT 上刷新了 state of the art，同时带来更新的 “v0923” embedder checkpoint（#1528）和一个用于对比的 Qwen3-Embedding-8B 基线（#1517）。对采用者来说，这是一个真正面向推理密集型查询的新模型层级，而不只是版本号提升。注意：它被明确标为 “preview”，而且一连串 README 链接/表格/数值修复（#1511、#1512、#1516、#1531）说明文档和报告结果在发布时仍在稳定过程中——在给自己的选择做基准测试前，请以最终 README 核对公布的数字。
  • BRIGHT 成为一等评估目标 — #1534/#1535 增加了端到端的 BRIGHT 支持和示例，#1553 增加 evaluate_recall_cap 指标，#1527 修复 runner 里的 evaluate_metrics，#1538 修复 pytrec_eval 安装失败。这点很重要，因为 BGE-Reasoner 的亮眼结论现在可以通过库自带的 harness 在本地复现——但安装修复也意味着之前的版本甚至没法干净地跑这个评估器，所以如果你要在 CI 里脚本化 BRIGHT 评估，请锁定这个版本。
  • 兼容 Transformers V5，解除依赖升级阻碍 — #1563（来自 @therealmichaelberna 的首次贡献）增加了对 Transformers V5 的前向兼容。实际收益是采用新版本不再强迫你压住 transformers 的版本锁；要留意的是在 V5 上做真实世界的回归测试，因为这类兼容性补丁通常先于对所有 model wrapper 的完整验证落地。
  • bf16 支持在推理、训练和评估中全面收紧 — #1566 把 embedder 切到 bf16 并修复 decode_only 中的 attn_implementation 接口；#1567 让 bf16 加载安全并统一 NumPy 转换；#1568 把 use_bf16 贯通到 AbsEvalRunner.get_model 和 COIR 模型初始化（#1532 还加固了分布式运行中的 dist.get_rank()）。对开发者来说，这意味着更低的显存和更快的推理/训练，同时评估中不会出现隐式的 dtype 不匹配。注意 decode_only 里 attn_implementation 接口的变化——覆盖注意力后端的调用方应重新检查参数，尽管官方并未宣布破坏性变更。
  • Matryoshka（MRL）支持从训练延伸到推理服务 — #1570 增加 use_mrl 微调接口，以及 embedder 推理时的 truncate_dim，这样你可以训练一个 Representation Learning 模型，并以多种输出维度提供服务（成本/精度的权衡），无需重新训练。对于正在给向量索引规模”量体裁衣”的团队，这是最直接有用的新能力。
  • 更多微调旋钮与新推理路径 — train_group_size 变为可定制（#1491），其误报的 “None” 警告也被消除（#1492），微调开放了 use_fast_tokenizer（#1526），#1572 新增带域路由的 decoder-only pseudo_moe 推理。这些都是面向高级用户的针对性补充（用于调优对比批次或试验 MoE 风格的域路由），而不是宽泛的 API 变更。

官方未记录本版本的破坏性变更。
