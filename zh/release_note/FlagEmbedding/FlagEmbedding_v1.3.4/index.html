FlagEmbedding v1.3.4

修订 发布时间2025年2月7日 来源FlagOpen/FlagEmbedding 英文原文

FlagEmbedding v1.3.4

变更流程图

亮点

  • 模型库新增模型 — bce-embedding-base_v1 现在可以通过标准 embedding 接口加载（#1198），bge-multilingual-gemma2 背后的训练数据已发布（#1245），model_mapping.py 也做了相应扩展（#1311）。对采用者来说这是最主要的能力增益：你可以把这些 checkpoint 直接换进现有的 FlagEmbedder/FlagReranker 流水线，无需自定义模型胶水代码；而公开的 Gemma2 训练数据让多语言微调变得可复现，不再是黑盒。
  • Embedder 构造函数签名变化 — #1189 移除了 embedder 类中”无用”的参数。这是唯一需要当作潜在破坏性变更看待的一项：任何把这些已删除 kwargs 传给 embedder 构造函数的代码都会开始抛 TypeError，所以升级前请审查所有实例化点。与此相关，#1248 给微调路径补上了缺失的 trust_remote_code 标志——没有它，decoder-only/自定义架构的 checkpoint 会在训练时加载失败。
  • 更广的硬件与依赖支持 — #1216 修复了 AbsReranker 中的 MPS 设备处理，Apple Silicon 用户终于能在 GPU 上跑 rerank，而不是回退到 CPU。#1350 为摩尔线程加速器增加了 MUSA 后端，对国产硬件部署是实打实的选择。#1343 修补了与 transformers 4.48.0 的兼容性，#1300 修复了一个 Python 3.8 类型提示错误——两者一起解除了依赖升级阻碍，并让较旧的解释器环境继续可用。
  • 值得重跑训练的修正 — #1183 修复了 BGE-M3 训练中的一个 bug，#1232 纠正了 DecoderOnlyEmbedderICLSameDatasetTrainDataset 里的类别索引错误，#1330 以及 #1328/#1342 修复了 ICL 和 embedder 微调路径。如果你在微调 M3 或使用 decoder-only ICL 数据集，之前产出的 checkpoint 可能有细微错误；这些修复分散在多个后续 PR 中，请重新训练，而不要假设早期权重没问题。
  • 评估数值可能变化 — #1256/#1257 修复了 air-bench harness 中的 AIRBenchEvalArgs，#1341 纠正 BEIR 数据加载器使用 validation 而非 dev 划分，#1227/#1230/#1235 刷新了 MTEB 评估代码。尤其是 BEIR 划分的修正会改变报告的检索分数，所以在与已公布表格对比前请重新建立基线。#1296 也更新了 C_MTEB 参考。
  • 内存与分布式训练清理 — #1349 解决了一次 OOM 失败，#1229 增加自动批大小调整，应能降低大批量 embedding 的入门门槛。注意 #1360 移除了数据并行（dp）训练代码：如果你的训练脚本依赖那条路径，就需要迁移到受支持的替代方案，尽管该版本的其余部分都是增量改动。
