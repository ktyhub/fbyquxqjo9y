FlagEmbedding v1.3.5

修订 发布时间2025年5月28日 来源FlagOpen/FlagEmbedding 英文原文

FlagEmbedding v1.3.5

变更流程图

亮点

  • 推理与评估的正确性修复 — 一组针对评估/推理路径的修复：stop_self_pool 的推理问题被修好（#1407），m3 modeling.py 中的一个 bug（#1410）在 #1424 中修复，evaluation/mteb/runner.py 得到纠正（#1426），evaluator.py 的评估流程被优化（#1366）。trange 进度循环现在用 batch_size 而不是硬编码的 256（#1401），字面量 "\n" 被替换为真正的换行（#1374），并在 #1423 和 #1425 中落地了常规 bug 修复与重构。如果你跑 MTEB 评估、self-pooling 推理或 m3 模型，这些会直接影响结果。
  • 模型加载修复 — 加载 "openbmb/MiniCPM-Reranker-Light" 现在会带上 trust_remote_code=True（#1378），消除了该 reranker 上的 remote-code 报错。只有使用这个特定模型时才有影响；否则是无操作。
  • 新模型与评估资产 — 新增 Matroyshka Re-Ranker（#1453）和 reinforced_ir（#1457、#1458、#1459），外加一个 coder 评估脚本（#1464）和环境更新（#1465）。这些是新的研究成果/能力，而不是修复——与 reranker 和 reinforced-IR 工作相关，普通 embedding 用户可以忽略。
  • 无破坏性变更 / 升级指引 — 未指出任何 API 破坏或迁移步骤；这是一个以 bug 修复和新增内容为主的版本，附带一处文档笔误修正（#1379），没有重新打标或仅改元数据的内容。任何依赖评估/推理正确性或新 reranker 的人都值得升级；只有当你锁定的是一条完全不碰评估器、m3/self-pooling 推理或 MiniCPM 加载的窄路径时，才可以放心跳过。
