  • RTX 5090、RTX PRO 6000 和 DGX Spark 上的 Qwen3.8-27B，重新测量：#35825 集束搜索。 SGLang 现在可以进行集束搜索。在您的请求中传递 beam_width，您将得到 n 最佳序列而不是单个样本。它在常规请求旁边开箱即用，尽管它尚未与推测解码、分解、DP 注意力或 HiCache 混合（#31626）。 DeepEP v2. DeepEP 的新 ElasticBuffer 引擎在 FP8 中以 --moe-a2a-backend deepep_v2 形式提供给 DeepSeek-V3/V4 和 Qwen3-MoE。它的缓冲区具有固定大小，因此解码可以在 CUDA 图下甚至跨节点运行。性能与经典后端（#35634、#34923）相当。 LayerNorm 序列并行性。 使用 --enable-layernorm-sp，每个张量并行等级仅标准化其自己的预填充令牌份额，而不是全部。这使得 H100 上的 Qwen3-8B 预填充节省了 3.5%，B200 上的 Qwen3-8B 预填充节省了 5.6%，并且节省的费用随着 TP 程度的增加而增加。目前仅使用 Dense Qwen3 模型 (#30915)。 Hopper 上的 W4A8 MoE。 如果您在 Hopper 上为 MXFP4 专家提供服务，您现在可以使用 --flashinfer-mxfp4-moe-precision fp8 将激活量化为 FP8。 DeepSeek-V4-Flash 获得约 12% 的输出吞吐量，而 GSM8K 精度没有变化。需要 FlashInfer 0.6.18 (#34967)。 默认 Blackwell MLA 后端上的 DCP。 解码上下文并行性现在在 trtllm_mla 上运行，而不仅仅是 CuTe DSL 和 Tokenspeed。它在长上下文中得到了回报：在 128K 输入下，普通 TP 在 8 个 B200 上停止每秒扩展约 680 个令牌，而 DCP 随着并发量的增长而继续扩展（#33926）。 更快的推测内核。 DSA 预填充 top-k 移动到 v2 内核，在 B200 上 1.3 到 1.8 的速度快了几倍（#35175）。 KDA 模型获得一个选择加入的融合接受路径 SGLANG_OPT_KDA_FUSED_ACCEPT_STATE=1，可将具有相同位输出的 Kimi-Linear 形状上的 MTP 验证和提交时间缩短 45% 至 63% (#33722)。 **默认情况下统一基数树。**统一树现在是每个模型的缓存，而不仅仅是混合模型（#35081，请参阅重大更改）。它还在本周期中实现了三件事：PD 解码工作人员可以重用 SWA 混合模型（如 gpt-oss）的缓存前缀（#27770），您可以在正在运行的服务器上附加或分离 L3 存储（#35269），并且 HiCache L3 的管道并行性在各个级别之间保持一致（#27010）。 重点关注 AMD。 长时间或不均匀的解码批次曾导致 MI300X 和 MI355X 上的许多计算单元处于闲置状态。新的持久精益内核将工作分散到所有这些内核上，在 MI355X 上吞吐量提高了 1.52 倍，令牌间延迟降低了 3.62 倍。它会在有帮助的地方自行打开，而 SGLANG_DISABLE_LEAN_ATTENTION=1 将其关闭（#33576）。 ROCm 上的 DSA 模型。 分解的 GLM-5.2 服务现在使用融合的 top-k 种子重新映射，这将八个 MI355X 上的解码 TPOT 从 23 毫秒缩短到 8 毫秒 (#36714)。 DeepSeek-V4 获得 v2 top-k 内核，速度提高了三倍 (#36684)，并且共享专家门修复使 GLM-5.2 的 TPOT 提高了 16% (#36124)。 依赖项。 FlashInfer 移动到 0.6.18 (#36954)，sql-deep-ep 移动到 0.1.2 (#35450)，sql-deep-gemm 移动到 0.1.7 (#37279)，以及月饼到 0.3.13 (#36493)。 Rubin 新增了 CUDA 13.4 预览映像 (#36233)，gfx942、gfx950 和 gfx1250 新增了 ROCm 10 映像 (#36434、#36871)。 按以下类别列出的完整 release note；重大变更和已知问题位于最后。

重大变更和升级说明

  • 统一的基数树现在是每个配置的默认缓存，包括仅完全注意模型； SGLANG_ENABLE_UNIFIED_RADIX_TREE 已弃用，可以取消设置：#35081
  • Spark3 在配置（Spark2_5Config、model_type spark2_5）、模型类和函数调用解析器上更名为 Spark2.5；工具调用解析器名称从 spark 更改为 spark25：#36416
  • 当 --moe-runner-backend 留在 auto 时，SM90、SM100 和 SM120 上的 DeepSeek-V4 FP4 专家检查点默认为 FlashInfer MXFP4 MoE 运行程序；保留显式后端：#35919
  • W4A4 MegaMoE 移至 --enable-w4a4-megamoe； SGLANG_OPT_DEEPGEMM_MEGA_MOE_USE_FP4_ACTS and SGLANG_OPT_DEEPGEMM_MEGA_MOE_USE_MXF4_KIND now only warn: #35918
  • 需要 FlashInfer 0.6.18； --dsa-topk-backend flashinfer 和 CuTe DSL NVFP4 W4A16 模式对于早期 FlashInfer API 没有后备方案：#36954、#33237、#35120
  • Constructing a ServerArgs no longer resolves it. Programs that build their own record must call resolve_once() before reading resolved values; the launcher does this for the engine: #35907
  • Kimi 混合模型再次在 CUDA 图表下尊重 --enable-symm-mem，因为 Torch 2.13.0 修复了强制其关闭的分配器错误：#34842
  • 精益（以工作为中心）解码注意力在 ROCm Triton 后端自动启用，其门预测获胜，包括在 CUDA 图表下； force it off with --enable-lean-attention=False or SGLANG_DISABLE_LEAN_ATTENTION=1: #33576
  • ROCm 7.2.4 图像移至 Python 3.12、火炬 2.11 和 triton 3.7； new ROCm 10 images ship for gfx942, gfx950, and gfx1250: #30984, #36434, #36871
  • SGLANG_USE_SGL_XPU 标志已删除； XPU now uses the sgl-kernel MoE kernels by default, and --moe-runner-backend triton restores the Triton path: #34492
  • 扩散缓存-DiT、CFG 门控和 DiT 注意力后端成为每个请求的采样参数； SGLANG_CACHE_DIT_* 环境变量保留为服务器默认值，并计划弃用：#35339
  • 混源视频VAE默认为平铺解码：#36012
  • 请求限制为 32 个停止字符串和 32 个停止正则表达式模式，每个模式最多 256 个字节，超出范围返回 HTTP 400：#37029
  • /rerun-stage is removed and /rerun-test is gated on commenter trust (zero cooldown or repo write): #35750
  • kill_process_tree waits for the reap by default in CLI, benchmark, and test teardowns: #36589
