新消息

  • GB300 上的 DeepSeek-V4.1 在负载下的预填充吞吐量提高了 1.5 倍，并且在 32K 到 64K 提示上的第一个令牌延迟降低了约 28%（#44403、#45059、#45107）。
  • SGLang 低延迟模式：选择加入 NVIDIA megakernel 和 AMD monokernel 插件将 DeepSeek-V4.1-Flash 解码作为融合持久内核运行，在 GB300 上单用户解码速度提高高达 44%，在 MI350X 上提高 75%（#44945， #45450、#44353、#44621)。
  • DeepSeek-V4.1-Flash、GLM-5.3-Flash 和 gpt-oss 等 MoE 模型在 H200 上的 8K 提示下达到第一个令牌的时间缩短了 30% 到 58% (#43363)。
  • 分页专家（选择加入）在单个消费者 GPU 上运行大于 GPU 内存的 MoE 模型，比 CPU 卸载快 30 倍（#42557、#45787）。
  • SGLang 现在通过 SGLang-TorchTPU（TPU 的 PyTorch 原生插件）在 Google TPU7x 上运行。
  • 现在，您可以使用新的可选 LoRA 引擎 (#45892) 在量化 MoE 模型（FP8 和 NVFP4）上提供 LoRA 适配器。
  • 运行解码上下文并行性的 DeepSeek 式 MLA 模型现在可以将其前缀缓存保留在基于 HiCache 文件的 L3 存储中 (#41187)。

重大变更和升级说明

  • DeepSeek-V4 和 V4.1 聊天现在遵循 deepseek-recipe。 提示、输出和本机 /separate_reasoning 和 /parse_function_call 端点通过 DeepSeek 的官方编码器，而 SGLang 自己的 encoding_dsv4.py / encoding_dsv41.py 消失了。 ZZPH100​​4ZZents 可能会注意到：流式工具调用参数以碎片形式到达（第一个块携带 arguments: ""），因此像 OpenAI ZZPH100​​5ZZ 那样将它们连接起来；工具调用 ID 使用官方 call_00_... 格式； V4 推理工作遵循 DeepSeek 的官方配置文件，并删除了 dsv4_reasoning_effort_profile 覆盖； V4 上的数字 reasoning_effort 返回 400； developer 消息呈现为系统消息； /parse_function_call 还使用 tool_index -1 返回对 tools 外部工具的调用；将 tools 与 continue_final_message 组合的请求返回 400。当设置 DeepSeek 推理或工具调用解析器时，输出解析将通过 deepseek-recipe 进行； sql-router 和 sglang-server 目前保留其 Rust 解析器：#45315、#45907、#46219
  • 对于受支持的 CUDA 配置（包括两个 PD 角色），DeepSeek-V4.1 解码器 SWA 有界重播默认处于启用状态。它在数字上与完全预填充不同。通过 --no-enable-decoder-swa-bounded-replay 以保持完全预填充，例如对于 RL 部署，其日志概率必须与训练器匹配：#44403、#45035
  • DeepSeek-V4.1 默认为 PD 下的 MegaAttention。 在 SM100 / SM103 上，两个 PD 角色现在都解析 flashmla_mega 并且 PD 握手检查 KV 布局，因此预填充和解码必须运行相同的注意力后端 (#45075)。一起升级预填充和解码，因为旧的解码无法读取新的握手字段；在两个角色上传递 --dsv4-attn-backend flashmla 以保留 FlashMLA。当注意力跨等级张量并行时，聚合服务器保留 FlashMLA：#46263
  • tokenspeed_mla 关注后端已删除。 tokenspeed_mla 仍然作为 cutedsl_mla 的已弃用别名启动，并带有警告。要进行切换，请传递 --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3，加上带有推测解码的 --speculative-attention-mode decode：#44803
  • --speculative-skip-dp-mlp-sync 已删除。 通过它的启动命令现在会失败，并出现无法识别的参数错误；放下标志：#45043
  • kitchen_int8 扩散量化名称已删除。 使用 convrot_int8，自 v0.5.22 起已弃用，取而代之：#45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE 现在被忽略而不发出警告。 它已经没有任何效果，因为统一基数树是默认的；将其从启动脚本中删除：#45090
  • 旧版 tar 格式的 .pt 检查点不再加载。 不安全的 weights_only=False pickle 回退已被删除；离线将此类检查点转换为安全张量或 zip 格式 .pt：#42760
  • 扩散 HTTP 端点验证更严格。 upscaling_model_path 和 frame_interpolation_model_path 的 URL 值返回 400，不支持的 response_format 在生成前被拒绝，失败的云上传返回 502 而不是 400：#43585
  • FlashInfer CUTLASS MoE 服务器的首次启动需要更长的时间。 启动自动调谐现在还涵盖预填充大小，因此未保存调谐结果的服务器需要更长的时间才能准备就绪（在 8x H200 上的 DeepSeek-V4.1-Flash 上，自动调谐从大约 41 秒变为 177 秒）。后来的初创公司重用保存的结果，--disable-flashinfer-autotune 跳过调整：#43363
  • 扩散 PNG 响应更大。 PNG 输出现在默认为 zlib 级别 0：相同的像素，大约 3 倍字节，编码速度快了几倍。将 output_compression 设置为 75 以外的值来选择级别：#45987
