sglang v0.5.14

亮点

新型号支持：GLM-5.2、LiquidAI LFM2.5、Kimi-K2.7-Code、Poolside Laguna-M.1、DiffusionGemma、Zyphra ZAYA1、 MiMo-V2-ASR 自第 0 天起在 GB300 上运行 DeepSeek-V4：在相同的交互性下，吞吐量提高了 5 倍，通过 SGLang 在 NVIDIA GB300 上提供 DeepSeek-V4（博客）。 Waterfill 和 LPLB MoE 负载平衡：用于 DeepEP 专家并行性的两种调度时负载平衡方法：用于共享专家调度的 Waterfill 和用于冗余专家副本的 LPLB，从而提高 DeepSeek-V3/R1 和 DeepSeek-V4 的吞吐量（博客）。 Blackwell (SM100) 上的 KDA CuteDSL 预填充内核：Kimi-Linear (KDA) 的新 CuteDSL 预填充内核，通过可重用的暂存工作区，1.08-1.52x 比 Triton 路径更快，加上 cuda-graph 填充修复（#27488）；请参阅Kimi-Linear 食谱。 线性注意前缀缓存内存节省：int8 检查点池将循环状态紧凑地存储在 Mamba 基数缓存中，大大增加了 KDA / GDN 模型的前缀缓存容量（#28185）；推测性卷积窗口中间缓存通过滑动窗口布局进行重复数据删除，将其占用空间减半，而没有数值变化（#28302）。 LPLB：用于 MoE 专家并行性的线性编程负载均衡器：通过求解每层 LP 来平衡冗余专家副本之间的令牌路由；通过 --ep-dispatch-algorithm=lp 选择加入，默认行为不变 (#24515)。 MSCCL++ 集成和 MNNVL allreduce 融合：MSCCL++ 迁移到上游 mscclpp Python 包（执行器 + DSL 编译器），并带有针对 TP=8 单节点和 TP=16 两节点的自动调整集合（#22734）； FlashInfer 融合 allreduce +残差+RMSNorm 重新启用 --flashinfer-allreduce-fusion-backend (auto / trtllm / mnnvl) 后面的 MNNVL 后端，修复分段 CUDA 图交互 (#23402)。 Nemotron DP 注意力 + MTP：混合 Nemotron-H 的数据并行注意力（Mamba2 + 完全注意力 + MoE），加上 MTP 支持（#24955）；请参阅Nemotron 3 Ultra 食谱。 AMD：ROCm/HIP 上的可破坏 CUDA 图形：可破坏的 CUDA 图形执行路径现在在 AMD GPU 上运行 (#28173)。 用于 DeepSeek-V4 的 NVFP4 MoE：在 Blackwell 上为 DeepSeek-V4 添加 NVFP4 MoE 量化路径，以实现更高的 MoE 吞吐量；使用 --moe-runner-backend flashinfer_trtllm_routed 启用（#25820）；请参阅DeepSeek-V4 食谱。 DeepSeek-V4 解码和量化优化：FP8 组量化现在直接从每个令牌组量化内核发出二次幂 (UE8M0) 缩放，删除单独的舍入通道 (#26766)； MLA 解码 q-heads 在注意力 TP 下填充为 64，因此 FlashMLA 调度约 2 倍便宜的 head64 内核而不是 head128 (#27954)； MHC prenorm 内核在启动时进行预热，以消除新服务器上首次运行的 JIT 减速问题 (#27986)； C4 / C128 路径支持 BF16 混合 dtype 压缩状态 (#27277)；请参阅DeepSeek-V4 食谱。 以下按类别列出完整的 release note。
