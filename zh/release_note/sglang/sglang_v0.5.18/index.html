sglang v0.5.18

亮点

来自 212 位贡献者的 710 个 PR。 此版本中的新型号（有关所有支持的型号，请参阅 说明书）：

型号 类型 公关 食谱
缪斯微光 自回归（多模式） #34262 链接
实习生-S2-莫比乌斯 自回归 #33691 链接
SANA-视频 扩散 #32921 链接
LingBot-视频-教育部 扩散 #32341 链接
LTX-2.5 扩散 #34471 链接
Cosmos3 边缘和蒸馏 扩散 #31590 链接
长猫-图片 扩散 #23274
加上 Qwen3.8 系列、Ling-3.0、Nemotron 3.5 Lightning、Dots3-Note 和 DeepSeek-V4-Pro-0813 的食谱食谱（[#34809]（https://github.com/sgl-project/sglang/pull/34809））。
启动时重叠的检查点暂存：检查点页面现在在 CUDA 图形捕获时从存储中暂存。 H100 上的 Qwen3-32B 启动速度比带预取的串口快 8.6-11.7%，并且比普通默认值快 2.38 倍（35.6 秒 vs 84.8 秒）。使用 --startup-weight-load-mode overlap (#32017) 选择加入。
带有 All-to-All 的 TP LMHead：TP LMHead 的 allgather + scatter 成为纯 DP dp-attention 的单个 all-to-all。在 DeepSeek-V4-Pro B200 解码上，LMHead 时间下降 320us 至 169us，TPOT 提高 36.97ms 至 35.67ms (#32313)。
用于纯 allreduce 的 FlashInfer MNNVL：非融合 allreduce 站点现在重用 FlashInfer MNNVL 工作区，而不是回退到 NCCL。 Blackwell 上的 DeepSeek-V4-Flash TP4 解码增益小批量时最高可达 +6.9%。自动启用 DeepSeek-V3/V3.2/V4；其他地方 --enable-flashinfer-pure-allreduce (#30700)。
NVFP4 检查点在 AMD 上运行：--quantization quark_mxfp4 对 ModelOpt 和 Quark NVFP4 权重进行反量化，并在加载时重新量化为 MXFP4，从不保存全精度副本。 97.5-100.2% GSM8K 恢复与 MiniMax-M2.7、GLM-5.1、Kimi-K2.6、Qwen3.5-397B 和 DeepSeek-R1 的 NVFP4 参考相比 (#29328)。
Kimi K3 针对 MI355X 进行了调整：分组头 MLA 验证内核取代了 MHA 形状的 split-KV 路径，该路径每个头重新读取共享潜在数据一次，以实现并发 2-32 时的 1.37-1.77x 吞吐量和 1.45-2.42x ITL； AITER MLA 预填充内核现在接受 K3 的 12 头形状（TTFT 高达 -14.9%）；经过 gfx950 调整的解码阶段 1 几何结构在 68k 输入时增加了 46-73% ITL，通过 SGLANG_MLA_DECODE_TUNE=1 选择加入。 GSM8K 保持在 0.951-0.957（#33981、#34261、#34837、#34580）。
一个编译内核缓存目录：Triton、FlashInfer、Inductor、DeepGEMM 和 CUDA 驱动程序缓存均移至 SGLANG_CACHE_DIR 下。升级后首次启动重新编译一次；请参阅重大更改 (#32434)。
依赖项：torch 2.13.0 与 triton 3.7.1 (#28836)、flashinfer 0.6.17 (#33997)、CuTeDSL 4.6.2、修复 Blackwell 上的 FA4 启动回归(#34372)，DeepEP 现在从发布的 sgl-deep-ep 轮子 (#33932) 和 sql-kernel 0.4.6.post1 (#33842) 安装。

重大变更和升级说明

  • CUDA PyTorch 堆栈移至 torch 2.13.0，带有 triton 3.7.1、torchvision 0.28.0 和 torchcodec 0.15.0（torchaudio 保持在 2.11.0）；针对 Torch 2.13 重建了 AOT 内核，XPU 后端如下：#28836、#33841、#31751
  • 每个编译的内核缓存都会移动到 SGLANG_CACHE_DIR 下，因此升级后的首次启动会重新编译一次。如果您预热或卷安装旧目录，请复制或符号链接它们（deep_gemm 和 flashinfer 是昂贵的）：~/.triton 到 {SGLANG_CACHE_DIR}/triton、~/.cache/flashinfer 到 {SGLANG_CACHE_DIR}/.cache/flashinfer、~/.cache/deep_gemm 到 {SGLANG_CACHE_DIR}/deep_gemm、/tmp/torchinductor_$USER 到 {SGLANG_CACHE_DIR}/inductor、~/.nv/ComputeCache 到{SGLANG_CACHE_DIR}/nv。设置 TRITON_CACHE_DIR、FLASHINFER_WORKSPACE_BASE、SGLANG_DG_CACHE_DIR、TORCHINDUCTOR_CACHE_DIR 或 CUDA_CACHE_PATH 中的任何一个都会将其保留在原来的位置：#32434
  • 删除了 torchao 集成（自从 torchao 引脚移至 0.17.0 以来，--torchao-config 已为每个接受的值引发了 ImportError）：[#34304]（https://github.com/sgl-project/sglang/pull/34304）
  • DeepEP 现在从发布的 sgl-deep-ep 轮子安装，而不是从源构建：#33932
  • 默认情况下，MoE 延迟最终确定在 NVFP4 + flashinfer_trtllm 路径上处于启用状态，具有未融合的非 TP1 共享专家（DeepSeek-V3 系列）；设置 SGLANG_ENABLE_MOE_DEFERRED_FINALIZE=False 回退：#33618
  • 对于统一基数缓存，统一缓存窗口外 SWA 插槽释放默认处于启用状态；设置 SGLANG_OPT_UNIFIED_CACHE_FREE_OUT_OF_WINDOW_SLOTS=False 以恢复旧行为：#34653
  • 远程媒体下载默认限制为 64 MiB，具有重定向验证和选择图像、视频和音频 URL 的精确主机名白名单：#34892
  • DSV4 融合 MHC post+pre 路径默认处于打开状态，包括 SM12x：#35214、#34019
  • torch.compile 成为扩散速度模式的选择：#34173
