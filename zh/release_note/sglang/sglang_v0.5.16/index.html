sglang v0.5.16

亮点

来自 169 位贡献者的 574 个 PR。 DSpark：置信度驱动的推测性解码：一种新的推测算法。它以半自回归方式分块起草，然后根据草稿自身的置信度而不是固定的草稿长度来调整每个验证窗口的大小。在 DeepSeek-V4-Pro 上达到 383.7 tok/s，接受长度约为 5，在 B300 上达到 TP8 (bs=1)。通过 --speculative-algorithm DSPARK 和 SGLANG_RAGGED_VERIFY_MODE=compact 启用；使用 --speculative-dspark-block-size 调整块（#30261、#31434、博客）。 Inkling 支持：具有 1M 代币上下文的 975B 参数多模式 MoE。它混合了滑动窗口、完整和 Mamba2 线性注意力，并添加了 NVFP4 MoE、可选的视觉/音频塔和本机 MTP。在 Blackwell 上，它达到 71.7k tok/s 输入 和 171.0 tok/s 每用户解码。在 Blackwell TP4/TP8、H200 和 AMD MI350X / MI355X 上进行了验证（#31681、博客、食谱）。 添加的其他新型号：LongCat 2.0 FP8、JetBrains Mellum v2、Pi0.5，以及对 LongLive 2.0 的扩散支持。 UnifiedRadixTree 现在是 SWA、Mamba 和 DSA 模型的默认设置。重播 SSM 和 Mamba int8 检查点已同步到其上，并且缓存命中现在仅重置其使用的状态（#30468、#30636、#30626、#31643）。 GLM-5.2 DSA 缓存层在预填充 CP 下分割：KV 和索引器缓存层跨 CP 列进行分片。每个等级拥有一个不相交的图层范围，而不是所有图层。这将 GLM-5.2-FP8 上的 8192 个令牌、78 层、cp_size=4 上的每等级 KV 内存减少了 ~74%（0.77 到 0.20 GB/等级）。使用 --enable-dsa-cache-layer-split 启用，这需要 --enable-prefill-cp --cp-strategy interleave (#29421)。 ReplaySSM 环规范验证 (GDN)：删除每个草稿的 SSM 快照。在 TP1 的 Qwen3.5-35B-A3B 上，推测从每 GPU 11.5 GB 到 1.8 GB（小 6.4 倍），精度和吞吐量相同。选择使用 --enable-gdn-replayssm-spec（默认关闭；仅具有线性草稿链的 GDN，{无，1} 中的 --speculative-eagle-topk），并通过 --linear-replayssm-cache-len 调整环 (#28695)。 Blackwell (SM100) 上的线性注意力：第一个正确的 KDA MTP 路径。对于 Triton（ncu，B=64），其 recurrent_kda 解码内核的运行速度为 29.6 us 与 36.8 us。完整解码路径在 B=128 处达到奇偶校验，在 B=256 时达到 **1.35x，并且低于此值时速度较慢 (#30113)。另外，GDN/KDA CuteDSL 预填充将状态 I/O 融合到 chunk-h 内核中（#30169）。 QServe 和 FBGEMM FP8 量化被删除：实验性 QServe (QoQ) W4A8 和 FBGEMM FP8 路径消失了。 --fp4-gemm-backend cutlass 以及树内 NVFP4 JIT 内核也随之出现，因此 NVFP4 GEMM 现在需要 FlashInfer（#31109、#30448）。 依赖项： flashinfer 0.6.14 (#29910)、CuTe DSL 4.6.0 (#31714)、sql-kernel 0.4.5 (#31496)、llguidance 1.7.6 （[#31484]（https://github.com/sgl-project/sglang/pull/31484））。

重大变更和升级说明

  • 实验性 QServe (QoQ) W4A8 和 FBGEMM FP8 量化路径已删除（根据 #28543）：#31109
  • SM90 / SM100 的 CUTLASS FP8 逐块删除，SM120 移至 JIT：#30438
  • --fp4-gemm-backend cutlass 与树内 NVFP4 JIT 内核一起被删除，因此 NVFP4 GEMM 现在需要 FlashInfer。使用 auto，它在 SM100 上选择 flashinfer_cutedsl，在 SM120 上选择 flashinfer_cutlass：#30448
  • UnifiedRadixTree 现在是 SWA、Mamba 和 DSA 型号的默认设置。这些架构上的行为更改：#30468
  • 现在默认启用分块输入对数概率处理以限制峰值内存：#31498
  • FA3 稀疏掩码内核默认关闭：#30356
  • 旧版 Sphinx docs/ 已删除； Mintlify 切换已完成：#28964
  • sglang.kernels 命名空间：内核逐字重新定位，仅导入路径发生变化；公共包装器保持默认为 AOT sgl_kernel 后端，因此通过它们到达内部路径的代码必须更新 (RFC #29630)：#30044、#31582
  • num_tokens_per_bs 在规范解码运行器中重命名为 num_tokens_per_req：#30977
  • --enable-deepep-waterfill 已重命名为 --enable-waterfill 且没有已弃用的别名，因此现有启动命令会失败并显示 unrecognized arguments：#27350
  • --optimistic-prefill-retries 重命名为 --optimistic-prefill-attempts，没有已弃用的别名：#30951
  • SGLang-Diffusion 训练后推出端点现在返回 application/msgpack 而不是 JSON，张量作为原始 msgpack 字节而不是 base64（tensor_to_base64 / base64_to_tensor 变为 tensor_to_bytes / bytes_to_tensor），因此 RL 推出消费者必须与服务器同步升级： #31565

已知问题

  • 具有可破坏的预填充 CUDA 图的 DP 注意力下的温度 0 不确定性。 在 DSV4-Flash FP4 配方中，#30898 引入的空闲等级虚拟扩展会扰乱真实请求的 logits，因此相同的温度 0 请求可能会出现分歧。保护确定性测试被禁用作为权宜之计而不是固定的（#31125）；不启用易碎预填充 CUDA 图可以避免该路径。
  • 撞到 flashinfer 0.6.15 已落地并在本周期恢复；此释放销 0.6.14 (#31502、#31625)。
  • **重叠调度程序下的 Mamba 轨道边界 seqlen 已修复，然后恢复（#31369、#31622）。根本问题仍然悬而未决。
  • CPU AMX 扩散优化 已恢复（#28527、#30716）。
  • GB300 CI 作业被暂时禁用，以保证此周期内运行程序的可用性（#31764），因此 GB300 覆盖范围取决于说明书的手动端到端验证。 按以下类别列出的完整 release note。
