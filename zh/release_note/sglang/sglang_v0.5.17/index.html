sglang v0.5.17

俚语 v0.5.17

亮点

来自 194 位贡献者的 582 个 PR。 Kimi K3 day-0 支持：2.8T 参数多模式 LatentMoE（896 个专家，前 16 位，在 3584 暗淡的潜在空间中路由），具有 1M 代币上下文、69 个 KDA 线性注意力层与 24 个 MLA 层交错，以及一个 MoonViT3d 视觉塔，作为原生 MXFP4 检查点发货。 SGLang 从第 0 天开始使用 DCP、DSpark 推测性解码、带 TP 解码的分块预填充 PP、KDA 感知前缀缓存、DCP 上的 HiCache L2、量化权重上的 LoRA 以及推理、工具调用和 OpenAI 兼容服务，并在 NVIDIA GB300 和 AMD MI35x 上进行验证（#32541， #32828、#32890、#33025、#33112、博客、食谱、路线图)。 MiniMax-H3 day-0 支持：MiniMax 的视频生成模型可在一个请求中生成视频和同步立体声音轨，在 SGLang-Diffusion 上本地服务于所有三个公共任务配置文件：文本到视频和音频 (t2va)、第一/最后一帧调节 (fl2va) 和图像/视频/音频参考调节（ref2va，也涵盖视频到视频）。已在 B200 (TP2 + Ulysses4)、H100 (TP2 + Ulysses2)、AMD MI300X 和 MI355X (Ulysses1/2/4/8) 以及具有分层卸载功能的 2x RTX 5090 上进行验证（#33275、cookbook）。 添加的其他新模型：EmbeddingGemma 和 LFM2.5 嵌入模型、nvidia/MiniMax-M3-NVFP4，以及 Poolside 的 Laguna-S-2.1 系列和 Inkling-Small 的食谱食谱。 对 Rust 前端的初始支持：迁移服务器的前半部分，从网络入口到将标记化请求传递给 GPU 调度程序的所有内容，从 Python 到多线程 Rust 实现（#29799）。 DCP 通信后端和 q-replicate (Helix)：DeepSeek-MLA 解码上下文并行路径获得可插入的通信后端。 a2a 在每层的单个 NCCL 集合中交换打包注意力输出和 fp32 LSE，其中 fp8 KV 作为 uint8 字节传输； fi_a2a 将跨等级交换委托给 GB200 上的 FlashInfer MNNVL 内核。 --dcp-replicate-q-proj 在本地投影全头 Q，并跳过每层 Q 头暗淡全聚集。使用 --dcp-comm-backend {ag_rs, a2a, fi_a2a} (#21637) 选择。 用于 MoE 预填充的 DWDP：一种新的预填充并行策略，可通过 NVLink P2P 预取对等专家权重并在本地计算所有专家，从而消除 EP 全面令牌调度。在使用 gpt-oss-120b、仅预填充的 4x B200 上，DWDP4 在 MNT 32K / ISL 32K 下达到 DEP4** 的 1.92 倍，并且在饱和时达到 506K 与 329K tok/s (1.54x) (CONC=128，ISL=8K)。使用 --dwdp-size 启用；作者将其标记为早期开发（#29778）。 会话引用感知统一基数缓存：对于代理和 RL 部署工作负载，请求可以携带稳定的 session_id，因此逐出知道活动会话仍然引用哪些前缀，而不是纯粹通过缓存策略逐出。使用 /close_session 发布参考。选择使用 --enable-session-radix-cache (#29173)。 SM90 FP8 MegaMoE for DeepSeek-V4：在 SM90 上为 DeepSeek-V4-Flash/Pro FP8 添加 DeepGEMM MegaMoE A2A 路径，包括预调度 JIT 内核和 FP8 专家权重准备。守卫在 SGLANG_OPT_USE_DEEPGEMM_MEGA_MOE=1 (#29016) 后面。 更快的大型 MoE 模型加载：过大或不连续的 CPU 权重视图正在推动病态的 H2D 传输，DeepSeek-V4-Pro TP8 在某些级别的 H2D 中花费了 27 到 32 分钟。在 H2D 之前将这些视图复制到连续存储中，可将完整模型加载时间从大约 35 分钟缩短至 6 米 20 秒 (5.6 倍)，将 GPT-OSS-20B BF16 从 545 秒缩短至 70 秒 (7.8 倍)，而 Qwen3.5-397B 的测量速度为 1.93 倍至 2.3 倍。选择使用 SGLANG_MOE_COPY_WEIGHT_VIEWS_BEFORE_H2D，默认关闭 (#32315)。 降低 AMD 上的 DeepSeek-V4 内存：删除不必要的专家填充会将 MI355X FP4 MoE 模型权重从 159.07 GB 降低到 112.36 GB，并将 HIP 压缩状态池引入内存保护程序 KV_CACHE 区域，让共置 RL 回收它，将测量的训练阶段占用空间从每个 GPU 约 143 GiB 减少到 87 GiB （[#31450]（https://github.com/sgl-project/sglang/pull/31450），[#31747]（https://github.com/sgl-project/sglang/pull/31747））。 更快的引擎恢复：今天，大型模型重新启动需要 3 到 6 分钟以上的时间，对于 4 个 GPU 上的 Qwen3-235B FP8 来说大约需要 6.5 分钟，因为权重从存储中重新加载，并且 CUDA 图形重新捕获。权重缓存守护进程保存每个 GPU 的权重，因此重新启动的引擎可以从缓存中恢复 (#27139)。 混合线性 MTP 解码中的主机开销较低：在规范 v2 重叠调度下，每个解码步骤都运行草稿、验证和扩展 CUDA 图，并且它们之间的急切接缝在低并发时成为 GPU 空闲时间。这会修剪主机的工作，使主机远离关键路径 (#32219)。 依赖项： flashinfer 0.6.15.post1 (#31927)、sql-deep-gemm 0.1.5.post1 (#32345、#33143)、helion 1.4 （#32562）、月饼 0.3.12.post1（#32302）、发电机代币器 1.7.0（#32981）。 PyTorch 保留在 2.11.0，CUDA 基础映像保留在 13.0.1。 按以下类别列出的完整 release note；重大变更和已知问题位于最后。
