sglang v0.5.12

修订 发布时间2026年5月16日 来源sgl-project/sglang 英文原文

sglang v0.5.12

亮点

  • DeepSeek V4 支持：DeepSeek-V4 的完整推理路径 (#23882)，包括： Day-0 功能：#23882
    • 并行性：张量并行性/专家并行性/上下文并行性/数据并行注意力
    • 硬件：Nvidia B300/B200/H200/H100/GB200/GB300、AMD MI35X
    • 预填充解码分解
    • HiSparse 用于将不活动的 KV 缓存卸载到 CPU 内存
    • 推理解析器和工具调用解析器
    • DeepSeek V4 的 DeepGemm 和 FlashMLA 内核，包括 MegaMoE Day-0 后添加：
    • 统一基数树 [UnifiedTree] 下的 DeepSeek V4 的 HiCache：#24691
    • W4A4 MegaMoE 内核 — 速度更快，精度下降可忽略不计：#25052
    • Hopper 上的 Marlin/FlashInfer W4A8 MoE 内核：#24816 #24986
    • 更快的 V2 融合压缩内核：#24890
    • H100/H20 上的 TP16 支持：#24949
    • 融合 SiLU+clamp+FP8 定量内核：#24897
    • 优化的 MHC + DeepGemm 管道（融合范数，融合 hc_head）：#24775
    • DSv4 的非标准聊天模板支持：#23915
    • 多去标记器支持：#24944
    • DeepSeek-V4 的管道并行性 + PD 支持：#24700
    • 适用于所有 Nvidia GPU 的统一 docker 标签 lmsysorg/sglang:v0.5.12 有关更多详细信息，请参阅 LMSYS 博客 和 DeepSeek-V4 食谱。
  • TokenSpeed MLA 注意力后端（Blackwell、FP8 KV 缓存）：新的 MLA 预填充/解码内核集成为 SM100 上的注意力后端，并为低延迟 MLA 服务提供 FP8 KV 缓存支持：#24925
  • DSv3.2 / GLM-5 FP4 低延迟性能：跨 DSv3.2 / GLM-5 内核启用 PDL、DeepSeek V3.2 索引器 GEMM 的 torch.mm 以及 Cute-DSL FP4 密集 GEMM 的重新设计 — 大幅削减 FP4 路径上的低延迟开销：#23965、#23856、#23590、 #25311
  • 新模型支持：DeepSeek V4 #23882、Intern-S2-Preview #24875、MiniCPM-V 4.6 #24855、Laguna-XS.2 #24204、Ring-2.6-1T #25360 和 Gemma 4 MTP #24436 — 以及用于调整部署命令的食谱。请参阅docs.sglang.io/cookbook
  • HiCache + UnifiedRadixTree：HiCache 框架支持 UnifiedRadixTree（带 SWA）、HiCache for DeepSeek V4、通过 Mooncake 存储卸载 SSD，以及跨级联驱逐、逻辑删除重放和部分匹配路径的稳定性修复：#23316、#23391、#24691、#24277、#24943、#24972、#25068、 #25277
  • 推测解码 V2 成熟：自适应规范 V2、EAGLE-3 SWA + 较新的绘图器、Kimi K2.5 EAGLE-3 MLA、Gemma 3/4 + EAGLE-3，以及跨草稿扩展路径的广泛命名/形状处理重构：#23336、#24663、#24664、#24826、#23976、 #24859
  • CUDA 13 DeepEP 迁移：Gateway DeepEP 源从社区分支交换到 deepseek-ai/DeepEP@hybrid-ep，因此 DeepEP 在 CUDA 13 默认值上干净地构建和运行； FlashInfer 与 gpt-oss triton-kernel 修复一起固定在 0.6.11.post1：#25113
