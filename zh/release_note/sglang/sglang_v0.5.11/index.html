sglang v0.5.11

修订 发布时间2026年5月5日 来源sgl-project/sglang 英文原文

sglang v0.5.11

亮点

  • CUDA 13 + Torch 2.11：默认 CUDA 版本在 SGLang、sql-kernel 和 Docker 映像中迁移到 13.0，PyTorch 从 2.9 升级到 2.11 — 现代化构建矩阵并解锁更新的内核：#21247、#24162、 ＃24183，＃23593（[跟踪问题＃21498]（https://github.com/sgl-project/sglang/issues/21498））
  • 默认情况下推测解码 V2：Spec V2（通过重叠调度来隐藏 CPU 开销）现在是默认设置，大大降低了 EAGLE/MTP/DFLASH 路径的每步 CPU 成本：#21062
  • 解码基数缓存以进行 PD 分解：解码端前缀缓存现在可以在预填充/解码分解下工作，恢复分解部署中长共享前缀的基数缓存命中率和 TTFT 节省：#19746
  • Day-0/新型号支持：Gemma 4、GLM-5.1、Qwen3.6、MiMo-V2.5 / V2.5-Pro、Ling-2.6-Flash、Mistral Medium 3.5 和 Kimi-K2.6 — 以及用于调整部署命令的食谱食谱。请参阅 docs.sglang.io/cookbook：#21952、#23808、#23811、#23851、#23947、#23486、#23394
  • DFLASH 推测解码：来自内核社区的新高吞吐量规范解码内核，跨模型后端和 AMD ROCm 扩展：#22077、#22358、#22342、#23553
  • 来自内核社区的 FA3 内核：由社区贡献的嵌入式 FA3 内核，与 FA4 集成，为用户提供易于维护的高性能选项：#20796
  • LoRA 支持 DeepSeek-V3 和 Kimi-K2：LoRA 现在适用于最大的基于 MLA 的 MoE 模型，包括 DeepSeek-V3 MLA LoRA 和 Kimi K2 — 支持对前沿规模模型进行基于适配器的微调：#22323、#22381
  • 上下文并行 (CP) 增强：CP 下的 All-reduce + RMSNorm 融合可实现端到端加速，并支持 moe_dp_size = 1 与任意 attention_cp_size 配对，因此 MoE 和注意力并行性可以独立调整：#21249、#22003
  • FlashInfer CuteDSL MoE Runner 后端：用于标准 FP4 MoE 路径的新专用 FlashInferCuteDslMoE 层，提供额外的高性能融合 MoE 选项：#21339
