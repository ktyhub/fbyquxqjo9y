herdr v0.9.1

这个项目是干啥的：一个专为 AI 编程助手设计的终端多路复用器，能把 Claude Code、Codex 等多个助手同屏管理并标出谁在干活、谁卡住了，给同时跑多个助手的开发者用。

变更架构图

亮点

  • 远程与多机工作流 — herdr --machine <label-or-id> 可以在没有打开 Herdr 窗口的情况下，控制已保存 SSH 机器上的代理、窗格、工作区和 worktree。两端机器都必须包含本更新；失败的远程命令不会回退到本地。增量屏幕更新、空闲连接退避和可恢复的卡住切换，显著改善了繁忙或不可靠的 SSH 会话。现在支持 Windows SSH 主机，但包的安装/更新仅限于确认过的交互式设置。
  • 终端输入与选择的保真度 — 修复涵盖大段粘贴、分片的鼠标报告、Kitty/WezTerm 按键协议，以及 Windows 的 Alt/Ctrl+S/增强键盘输入和鼠标坐标。在持续输出时，选中和滚动现在也能保持正确。对遇到丢键、幽灵字符或损坏的复制/滚动行为的 Windows SSH 和现代终端用户尤其重要。
  • 会话安全与迁移 — 无法加载的会话会保存在 session-backups/ 下，而不是被覆盖。**行为变更：**删除会话现在需要其精确名称（含大小写），即使在不区分大小写的文件系统上也是如此；以 - 开头的名称必须跟在 -- 之后。依赖不区分大小写删除的脚本需要使用精确名称。新启动的 macOS 服务端在登出后保留用户查找和 DNS；已有的受影响服务端需要完整的会话重启，实时交接无法修复。
  • 代理集成 — Letta Code 新增检测和原生对话恢复，但仍属实验性，通过 herdr integration install letta 安装，而非 Settings 或 JSON 集成 API。OpenCode V2 按窗格上报生命周期状态，同时保留 V1 支持；安装更新后的集成后请重启 OpenCode。Grok 的 /new 恢复引用现在会被保留；请重新安装 Claude 集成以采用其更严格的 hook 匹配。
  • 升级建议 — SSH/多机用户、Windows 主机或客户端、大量使用终端输入/复制的人，以及任何受代理状态 bug 影响的人，都值得升级。实时交接只有在发送端服务端包含本更新时才能传输超过 64 个窗格；旧服务端保留其旧上限，该功能仍属实验性。本地单机、工作流不受影响的用户可以推迟，不过会话安全和 macOS 上下文修复有更广的价值。

添加

  • 使用 herdr --machine <label-or-id> 控制保存的 SSH 计算机上的代理、窗格、工作区和工作树。命令使用保存的计算机会话，无需打开 Herdr 窗口。更新两台机器上的 Herdr 以使用 CLI 转发；失败的远程命令永远不会回退到本地。 (#3918)
  • 从 Linux、macOS 或 Windows 连接到 Windows SSH 主机。交互式安装确认后可以安装或更新完整的Windows软件包；后台重新连接从不安装更新。 （＃3651，＃3701，＃3661，＃3687，谢谢@JJLiebig）
  • 在光标处（而不是仅在末尾）编辑名称、过滤器和搜索文本。 Herdr 输入现在支持字符和单词移动、Home/End、删除和熟悉的 Ctrl+A/E/K/U/W/Y 快捷键，包括 Unicode 文本。 （＃1803，＃3698，谢谢@markjaquith）
  • 添加了 Letta 代码检测和本机对话恢复，包括默认对话。其实验性集成是通过 herdr integration install letta 安装的，而不是“设置集成列表”或 JSON 集成 API。 （＃3106，＃3107，谢谢@just-cameron）
  • 在打开链接之前按住 Ctrl 键可将其突出显示。包装的 URL 和 OSC 8 链接即使其开头或结尾位于视口之外，仍保持 clickable。 (#1282)
  • 侧边栏令牌规则现在可以使用 hide = true 隐藏匹配的令牌及其分隔符；当没有剩余标记时，行就会消失。 (#3925)

已更改

  • 工作区键盘导航现在按侧边栏顺序跨越连接的机器，在 Enter 切换机器之前有一个可见的突出显示。折叠的机器和工作树组仍然可以导航，而不会意外地将操作发送到错误的机器。 (#3754)
  • 当发送服务器包含此更新时，实验性实时切换现在可以传输超过 64 个窗格。较旧的运行服务器在首次升级时仍具有旧的限制；这不会更改更新安装顺序或使实时切换成为非实验性的。 （＃3393，＃3411，谢谢@kataokatsuki）
  • 在 Linux 和 macOS 上，停止接受输出的终端观察器将在 30 秒后断开连接，且没有写入进度。他们的窗格和其他 clients 继续运行；中断的流可能会在没有最终关闭记录的情况下结束。 (#3612)
  • Windows 终端清理现在显式重置鼠标报告模式。 #3748 中剩余的独立 Git Bash 分离报告仍在调查中；请勿将此版本视为该报告的已确认修复。 （#4055，感谢@JJLiebig）

已修复

  • 远程键入、切换和弹出交互不再因微小更改而重新发送整个窗格屏幕。繁忙的 SSH 会话使用较少的带宽，空闲连接的 clients 避免了不必要的重画工作。 （＃3769，＃3745，＃3822）
  • 停滞的 SSH 机器不再将 client 困在远离本地的地方。 Clicking 本地工作区或代理会取消未完成的远程切换，并且恢复的远程工作区会刷新，而无需进行离开和返回选择。重新连接之前的陈旧屏幕不会被重复使用。 （＃3903，＃3842）
  • 空闲 SSH 连接使用更少的 CPU，而不会丢失最终输出。重复的连接失败会后退，而不是重新连接 rapidly，并且支持在不停止远程窗格的情况下清理空闲桥。 （＃3728，＃4083）
  • 大粘贴不再因输出队列错误而断开 client 的连接。 (#3833)
  • SSH 设置现在显示身份验证说明和有用的错误，包括 Tailscale 登录 URL 和主机密钥故障，而不是显示为挂起或仅报告连接丢失。 machine add 还接受 SSH 目标之前的选项。 （＃3606，＃3731，＃3883）
  • 机器和工作树组正确折叠，无需更改选定的工作空间。侧边栏尊重工作区行间隙，在调整大小期间保持稳定，并显示新聚焦的工作区。 （＃3778，＃3738，＃3817）
  • 切换机器时，座席列表保持其滚动位置。当前工作空间和当前选项卡过滤器区分不同计算机上的相同 ID。 （#3937、#4101、#3732，感谢@minatoaquaMK2）
  • 后台计算机激活不再调整另一个 client 的聚焦窗格的大小。窗口标题遵循每个 client 自己的视图，而不是另一个 client 的选择。 （#3744、#4091、#4130，感谢@JJLiebig）
  • agent focus 和 pane move --focus 现在将附加的 clients 移动到请求的窗格。在没有焦点的情况下移动时，client 不再会跟随已删除的选项卡或稍后不相关的焦点更改。 （#3760、#4153、#4171，感谢@minatoaquaMK2）
  • 创建工作树再次聚焦其新工作区。部分失败的工作树删除可以重试，并且具有子模块的工作树提供明确的强制删除选择，而不是在没有恢复操作的情况下失败。 （＃3766，＃3314，＃1797）
  • 临时工作树操作错误横幅会过期，而不是无限期地保留在屏幕上。 （＃1827，＃4063，感谢@JJLiebig）
  • 当选项卡条溢出时，最后一个选项卡仍然完全可见，并且会话导航器再次绘制连接的树枝。 （＃4151，＃3843）
  • 静音侧边栏和选项卡标签在深色主题（包括 Windows 终端）上仍然可读。 （＃2692，＃4062，感谢@JJLiebig）
  • 鼠标拖动和复制模式选择在输出继续时保持活动状态，即使部分选择位于视口之外也是如此。复制使用所选范围内的当前文本。选择重绘还可以避免积压鼠标移动。 （＃3841，＃3895）
  • 双 click 选择在自动复制禁用的情况下仍然可见。按住第二个 click 并拖动扩展整个单词，标记选择在 CJK 标点符号处停止。主机选择颜色在透明背景上保持可见。 （#3847、#1836、#3706、#3798）
  • 滚动不再组合不匹配的终端快照或在全屏应用程序（例如 Neovim）中留下陈旧的包装行。备用屏幕历史记录读取可在更改标题和滚动条时保留内容。 （＃3900，＃3329，＃3979）
  • 本地 Kitty 图形在第一张图像之后保持直接传输。弹出窗口和通知仅隐藏重叠的图像位置；未覆盖的图像仍然可见。 （＃3785，＃4081）
  • 像素鼠标坐标独立于图像渲染工作，并使用终端的整数单元格大小，防止 clicks 在屏幕上漂移。 （＃3295，＃4140，感谢@JJLiebig）
  • 功能键 F1–F12 在 Kitty 键盘报告中被识别，F1–F4 还可以与来自脚等终端的参数化报告配合使用。 （#1809、#2378、#4067，感谢@ashokDevs 和@JJLiebig）
  • WezTerm 控制键报告现在保留 Enter、Backspace、Tab 和 Escape。 Cmd/超级修改的输入到达窗格应用程序时其修饰符完好无损。修改后的 Enter 与未请求增强键编码的窗格保持兼容。 （#3589、#3710、#4103、#4110，感谢@minatoaquaMK2）
  • 跨延迟读取的鼠标报告不再将其尾随字节泄漏到窗格输入中。 Clients 在终端重新连接后重新断言鼠标报告。 （＃3911，＃4079，感谢@JJLiebig）
  • 无法加载的已保存会话将在替换之前保留，而不是默默地覆盖。恢复副本保存在 session-backups/ 中；保存失败，原件未受影响。 (#4125)
  • 在不区分大小写的文件系统上，删除会话现在需要其确切名称，包括大小写。以连字符开头的名称可以在 -- 之后传递。 （#3819、#4233、#3220，感谢@minatoaquaMK2）
  • 新启动的 macOS 服务器在注销后仍保留对用户查找和 DNS 的访问权限。现有受影响的服务器需要重新启动完整会话；实时切换无法修复其继承的服务上下文。 （#4100）
  • Linux 进程发现在卡住的 WSL 代理周围保持响应，并避免重复扫描不断增长的进程树。 （#2179、#3621、#3674，感谢@dark2momo 和@caner-akca）
  • Linux 桌面通知将 Herdr 识别为其来源。 (#3638)
  • 没有目标的 pane split 现在在 Herdr 内部调用时会拆分调用窗格，而不是另一个 client 的聚焦窗格。显式目标保持其现有行为。 (#4123)
  • 实时代理名称可以承受临时过程检测的不确定性，而不是通过名称无法访问活动代理。 （＃3225，＃3574，感谢@caner-akca）
  • Windows Codex 提示在粘贴文本后可靠地提交，而不是丢失 Enter，包括长提示。 （＃3187，＃3961，感谢@JJLiebig）
  • OpenCode V2 从显示对话的窗格报告生命周期状态，因此共享服务器不会混淆窗格。已完成和中断的轮次返回空闲状态，而待处理的权限、表单和失败的执行仍处于阻塞状态。 V1 仍受支持；安装更新的集成后重新启动 OpenCode。 （#3757，感谢@markjaquith）
  • Codex 继续处理静态标题、禁用动画和排队后续内容。 Composer 闪烁和旧的确认文本不再使空闲窗格看起来被阻塞。 （#4092、#4099、#3988，感谢@minatoaquaMK2）
  • Claude Code 的 Unicode 活动旋转器和 Pi 的工作边框被正确识别。 Cline 启动器检测和空闲状态报告更加可靠。 （＃3949，＃3629，＃2396）
  • Pi 记录 Windows 上的本机会话路径。嵌套 OMP 进程不再替换父窗格的可恢复会话，并且可以识别 Windows Kimi npm 垫片。 （#3726、#2593、#3994、#3317、#4053，感谢@JJLiebig）
  • Grok 在 /new 之后更新其恢复引用，并且其导入的 Claude 兼容挂钩不再覆盖该引用。重新安装克劳德集成，采用较窄的钩匹配。 （＃2681，＃4018）
  • 写入失败时集成配置更新会保留现有文件。当启用的插件使用内联列表时，Hermes 安装还会保留有效的 YAML。 （#3970、#3839、#4056，感谢@JJLiebig）
  • 插件注册表写入保留符号链接。在仅 client 更新后，插件继续使用正在运行的服务器的兼容二进制文件，并且手动窗格导航再次发出焦点事件。 （＃3922，＃3824，＃4077）
  • 包含 UTF-8 BOM 的配置文件正确加载和保存。默认配置将 ui.accent 放在右表中。 （#3678、#3962、#2697，感谢@JJLiebig）
  • Windows 本地和 SSH 输入保留 Alt 组合、Ctrl+S 和增强的键盘文本，而不是删除按键或插入垃圾。远程死键输入不再添加额外的基本字符。 （＃3702，＃3910，＃3932，＃3948，＃4133，＃4148，谢谢@JJLiebig）
  • Windows 鼠标捕获保留 SGR 坐标，包括过去的第 95 列，重新连接可恢复鼠标报告。旧版 SSH 鼠标报告不再产生幻象字符或阻止后续输入。 （#4155、#3735、#4080，感谢@JJLiebig）
  • Git Bash SSH 连接遵循用户 SSH 配置中的主机别名。 （＃3947，＃4054，感谢@JJLiebig）
  • Windows 登录模式窗格遵循配置的 shell 并保持 PowerShell 工作目录报告最新。窗格启动路径使用一致的目录大小写。 （#1445、#4060、#4065、#4199，感谢@JJLiebig）
