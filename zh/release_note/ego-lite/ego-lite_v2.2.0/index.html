ego-lite v2.2.0

ego-lite v2.2.0

变更流程图

亮点

  • 浏览器自动化明显提速 — PR #534 把点击的可用性检查合并为一次注入调用；PR #510 去掉动作里固定的等待延迟，并在空闲页面上快速失败，因此每个动作的往返更少、空闲页面不再烧预算；PR #473 还阻止了 networkidle 超时在 e2e 预算中级联放大。跑大型 ego-browser 套件的话，这是升级的首要理由。
  • 共享进程下的状态与文件冲突修复 — Page 账本按浏览器实例隔离（#466），改为写入带版本号的文件而不是重命名覆盖（#602），保留加锁的版本而非替换（#607），并重试瞬时重命名错误（#531）；默认截图路径（#492）和唯一 guid 命名的下载目录（#587）在运行/进程间隔离，截图带六位后缀（#511）。在同一共享 Node 进程里跑多个 Page 或多个运行的人，现在拿到的是确定性的产物，不会跨运行互相覆盖。
  • 破坏性变更——插件 npm 包迁移到 @ego-lite scope — PR #589 把它们以 @ego-lite 重新发布；PR #605 让 npm 包独立于插件版本；PR #576/#588 使包符合最新宿主规范，并保持已发布包无需重发即有效。插件使用者必须把依赖名和 import 改成新的 scope——这是本版唯一的迁移步骤。其余均向后兼容。
  • 导航/快照健壮性与新的 agent 侧信号 — #603 用 goto 超时终止从未提交的导航；#606 在等待无响应 Page 超时后停止待处理导航；#532 给会话建立等待加边界并命名无响应的 Page；#585 重试跨越文档提交的快照；#497 在滚轮输入无法把目标带入视口时回退。特性方面：#494 在默认快照里标记视口外内容；#480 在每个 Page 会话上启用 Ego 自动化钩子；#479 恢复/分离每个自动附着的非 frame 目标；#575 让 finish() 关闭最后一个 Page 关闭后留下的空白锚点标签页；#449/#481 把 Skill 重构为入口 Skill 加按操作系统分版本的用法指南。注意 #474 的”提醒 agent 释放仍持有的任务空间”修复已在 #489 回退，所以本版该行为无变化。
  • 谁该升级 / 谁可跳过 — 这是一次有分量的版本（通过 #661 里的 v2.2.0-beta.5 合入经过实战检验），不是重新打标或仅改元数据。ego-browser 用户和插件使用者为了速度、可靠性和 scope 修复应升级——插件使用者需做 @ego-lite 的 import 迁移。只看 README/文档或 CI 工作流的团队可以跳过：#486、#596、#597、#604、#477、#526、#615、#572 都是面向维护者的，不改变运行时行为。
