graphiti v0.30.0

graphiti v0.30.0

这个项目是干啥的：一个给 AI 智能体用的时序知识图谱库，能记住并检索随时间变化的事实关系，给需要长期记忆的 Agent 开发者用。

变更架构图

亮点

  • 修复 Neo4j 数据库路由 — Neo4jDriver.execute_query() 此前忽略驱动的 database 设置，把所有查询（包括搜索）打到服务器的 home database，而基于 session 的写入则使用配置的数据库（#1481、#851、#798，PR #1814）。现在查询会路由到配置的数据库，默认 neo4j，并支持通过 execute_query(..., database_="name") 按次覆盖。这一点很重要，因为读写现在落到同一个数据库，消除了多数据库部署中悄悄发生的数据割裂。

  • ⚠️ Neo4j Enterprise 多库用户的破坏性变更/迁移 — 只有自托管 Neo4j Enterprise 且设置了自定义 database 或重命名了 home database 的部署会受影响；使用默认 neo4j 的标准配置无需操作。如果你的 home database 不叫 neo4j 且没有传 database，查询现在会打到 neo4j 而不是你的 home database——请显式传入数据库名以保持旧行为。此前通过 execute_query 写入的数据可能位于 home database，升级前可能需要迁移。

  • 面向边消费者的更丰富 FactResult — FactResult 模型和边处理新增 source_node_uuid、target_node_uuid 和 episodes（PR #1750）。对基于 fact/边结果开发的用户来说，这是有用的低风险改进：边现在自带端点和支撑片段，无需额外查询。

  • 两项针对性的正确性修复 — 边的 cross-encoder 候选短名单通过平衡合并得到修复（#1642，PR #1754），提升检索/重排质量；节点属性处理现在在没有适用实体类型时保留原有属性（PR #1764），避免无类型实体数据丢失。依赖搜索结果质量或实体属性的用户值得升级，不过两者都不改动公共 API。

  • 杂项维护加版本升级；升级判断 — 其余改动不涉及功能：文档将 Discord 提及改为 GitHub discussions（PR #1708），README 重新定位为时序知识图谱框架（PR #1801），移除 Claude PR 三分类工作流（PR #1788），graphiti-core 升到 0.30.0（PR #1818）。自托管 Neo4j Enterprise 多库用户应升级，但要规划上述数据库/迁移步骤；使用默认 neo4j 数据库、想要短名单和属性修复的用户应升级；对当前搜索质量满意且没有多库配置的用户可以合理跳过。

已修复：Neo4j 查询现在尊重配置的数据库 Neo4jDriver.execute_query() 之前忽略了驱动程序的数据库设置，并对服务器的主数据库运行所有查询（包括搜索），而基于会话的写入则使用配置的数据库（#1481、#851、#798）。查询现在正确路由到配置的数据库，默认为 neo4j。通过execute_query(…,database_=“name”) 还支持每次调用覆盖。

⚠️ 现有部署的行为更改：

受影响的对象：这仅影响自托管 Neo4j Enterprise 部署（多数据库支持是一项企业功能），其中数据库参数被手动设置为 Graphiti client 中 Neo4j 以外的其他内容，或者服务器的默认数据库被重命名。如果您使用默认 neo4j 数据库运行标准 Neo4j 设置，则无需执行任何操作。

如果您的服务器的主数据库未命名为 neo4j 并且您没有将数据库传递给驱动程序，则查询现在将针对 Neo4j 而不是您的主数据库 - 显式传递您的数据库名称以保持旧行为。 如果您配置了自定义数据库，现在可以正确读取目标数据库。之前通过execute_query写入的数据可能驻留在您的主数据库中，并且可能需要迁移。
