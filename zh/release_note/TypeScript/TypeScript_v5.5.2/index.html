TypeScript v5.5.2

修订 发布时间2024年6月20日 来源microsoft/TypeScript 英文原文

TypeScript v5.5.2

变更流程图

亮点

  • 更敏锐的类型推断 — TypeScript 5.5 会为符合条件的单返回函数推断类型谓词，于是常见的 .filter(x => x !== undefined) 和 .filter(x => x !== null) 模式无需显式注解就能保留收窄后的数组类型。常量 obj[key] 访问在检查之后也会收窄，前提是两边绑定都未改变（#57465、#57847）。留意那些故意把被排除的值重新塞回原本更宽数组的下游代码。
  • 面向并行的声明生成 — 可选的 --isolatedDeclarations 要求导出类型足够明确，并与 --declaration 或 --composite 配合，让打包器、构建系统等工具无需跨文件类型推断也能生成声明。新的 transpileDeclaration API 提供单文件声明产出，但准确性取决于输入是否满足 isolated-declarations 规则；仅开启这个 flag 并不会加快 TypeScript 自身的产出（#58201、#58261）。
  • JavaScript 与运行时库支持 — JSDoc @import 为受检 JavaScript 带来仅类型导入，且不产出运行时导入（#57207）；更新后的 Set、ReadonlySet 和 ReadonlySetLike 声明覆盖了该提案的非变更方法，如 union、intersection、difference、isSubsetOf（#57230）。正则表达式现在会检查语法和反向引用，但只针对字面量——传给 new RegExp 的字符串不检查——且新特性按配置的 ECMAScript target 校验（#55600）。
  • 更可移植的配置与 TypeScript API 用法 — ${configDir} 让共享的 tsconfig.json/jsconfig.json 基础配置按继承它的项目解析受支持的路径，而不是按基础文件的位置（#58042）。Node.js ECMAScript 模块现在可以直接从 typescript 包按名导入，简化了构建工具集成（#57133）。原计划自动探测 package.json 模块格式的改动在稳定版前被回退，别指望它出现在这里。
  • 构建与编辑器性能 — transpileModule 和 transpileDeclaration 跳过不必要的检查，利好 ts-loader、ts-jest 这类仅转译的工作流；TypeScript 报告其 transpileModule 基准测试中构建时间约快 2 倍（#58364）。语言服务的内存分配优化带来报告称 10–20% 的操作提速，包体积也从磁盘上的 30.2 MB 降到 20.4 MB（#58045、#55326）。
  • 对升级敏感的行为变化 — TypeScript 5.0 起废弃的选项现已失效，包括 target: "ES3"、importsNotUsedAsValues、preserveValueImports；请删掉它们，别再依赖 ignoreDeprecations: "5.0"。装饰器解析更严格，可能需要加括号，如 @(super.decorate)（#57749）；type undefined 声明现在被拒绝；声明/引用指令的产出以及 DOM 类型定义可能改变生成结果或引入新的类型错误。
