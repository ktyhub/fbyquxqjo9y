TypeScript v5.4.5

修订 发布时间2024年4月10日 来源microsoft/TypeScript 英文原文

TypeScript v5.4.5

变更流程图

亮点

  • 最后一次赋值后的闭包收窄 — PR #56908 终于让 TypeScript 把收窄结果带进回调：只赋值一次且此后在外层不再重新赋值的 let 或参数，在非提升函数内部会被视为已收窄（例如 url = new URL(url) 之后 names.map(...) 就能直接用）。需要注意的坑：嵌套函数内任何重新赋值（哪怕是 value = value）都会让这一细化失效，所以它救不了那些之后还会修改捕获变量的代码。

  • NoInfer<T> 工具类型 — PR #56794（基于 Andarist 的 #52968）提供了一种干净的方式，阻止类型参数参与推断。它消灭了经典的「默认参数把联合类型撑宽」问题——createStreetLight(["red","yellow","green"], "blue") 现在会报错，而不是静默地把 C 推断成四成员联合——也无需再用别扭的多余类型参数 workaround。纯增量特性，但它改变了现有泛型签名的写法。

  • --module preserve + bundler 解析 — PR #56785 新增一种 module 模式：ESM 的 import 原样输出，import = require() 输出为真正的 require()，同时隐式启用 moduleResolution: bundler、esModuleInterop 和 resolveJsonModule。对面向打包器或 Bun 的用户很重要：你选择的语法现在会驱动条件导出解析（import → .mjs，require → .cjs），因此选 preserve 可能改变构建实际加载的文件。

  • 可能让构建失败的行为变化 — 5.4 收紧了几项此前静默的检查：枚举兼容性现在要求已知值相同，并限制 Infinity/NaN 等成员名（#55924、#56161）；在 isolatedModules 下，仅类型导入若与局部值同名会报错，除非加上 type（#56354）；条件类型约束、交叉类型归约和模板字符串插值检查都更准确（#56004、#56515、#56598），映射过 any 剩余元素的元组现在会保留元素类型（#57031）。DOM lib.d.ts 也有变化（#57027）。编辑建议：合并前请在 5.4 上跑一遍完整类型检查——这些大多是正确性改进，但会表现为原本干净的代码里冒出新错误。

  • 5.5 的弃用悬崖 — 5.4 是 TypeScript 5.0 弃用选项（importsNotUsedAsValues、preserveValueImports、target: ES3、noImplicitUseStrict、out、prepend、隐式操作系统 newLine 等）仍能通过 ignoreDeprecations: "5.0" 工作的最后一个版本。根据 #51909，它们在 5.5 中会变成硬错误。如果你一直在拖这项迁移，现在就是窗口期。

  • 标准库与编辑器体验打磨 — 新增 Object.groupBy / Map.groupBy 声明（#56805，需要 target: esnext 或调整 lib），导入属性现在会按 ImportAttributes 检查（#56034），自动导入能理解 # 前缀的子路径导入（#55015），并新增补齐缺失参数的快速修复（#56411）。一个坑：Object.groupBy 返回的是可选属性，因此在 strictNullChecks 下 myObj.even 仍会报错。
