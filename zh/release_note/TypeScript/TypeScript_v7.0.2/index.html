TypeScript v7.0.2

修订 发布时间2026年8月20日 来源Microsoft/TypeScript 英文原文

TypeScript v7.0.2

这个项目是干啥的：一个给JavaScript加类型检查的编程语言，能提前发现代码错误、编译还快了很多，给写大型网页应用的程序员用。

变更架构图

亮点

  • 原生 Go 移植，构建快 8–12 倍 — TypeScript 7 是从零开始用 Go 重写的编译器；完整构建通常快 8–12 倍，总内存更低（例如 vscode 125.7s → 10.6s，内存 −18%；sentry 139.8s → 15.7s）。大型编辑器项目中首个错误出现时间从约 17.5s 降到 1.3s 以内。这是采用它的首要理由：tsc/--watch 循环大幅收紧，CI 不再是瓶颈（Slack 报告 CI 类型检查从约 7.5 分钟降到约 1.25 分钟）。

  • 新的并行化开关 — 实验性的 --checkers（默认 4）和 --builders（在 --build 下并行构建项目引用），以及强制单线程的 --singleThreaded。把 --checkers 提到 8 让 vscode 达到 7.51s（16.7 倍），代价是内存；注意 --checkers 4 --builders 4 最多可同时拉起 16 个 checker。请在各环境间固定相同取值——在少数情况下，不同 checker 数量会产生顺序相关的诊断结果。

  • 重建的 --watch 模式 — 文件监听现在使用 Parcel 的 @parcel/watcher 的 Go 移植版（附带极小的汇编垫片以避免 C++ 工具链依赖），取代过去在大型 node_modules 树上开销高昂的轮询方案。预期 CPU/内存开销更低，跨平台监听更稳定。

  • 7.0 没有编译器 API —— 规划并行安装 — 7.0 不提供编程式 API（承诺在 7.1 提供），因此 typescript-eslint 等工具仍需 TS 6.0。使用新的 @typescript/typescript6 兼容包，它提供 tsc6 二进制并重新导出 6.0 API，通过 npm alias 配置："typescript": "npm:@typescript/typescript6@^6.0.2" 搭配 "@typescript/native": "npm:typescript@^7.0.2"。每日构建现在在 typescript@next，而不是 @typescript/native-preview。由于尚无稳定 API，Vue/MDX/Astro/Svelte（Volar）和 Angular 模板工具无法使用 7.0——请在这些项目中禁用 TS 7 语言服务。

  • 继承自 6.0 的破坏性配置默认值 — 7.0 采用 6.0 的默认值，并把其弃用项升级为硬错误：strict: true、module: esnext、target 为 esnext 之前的最新稳定 ES、noUncheckedSideEffectImports: true、libReplacement: false、stableTypeOrdering: true（不可关闭）、rootDir: ./ 和 types: []。最值得注意的是两点：如果 tsconfig.json 不在 src 内，请加上 "rootDir": "./src"；对过去隐式获得的全局变量，请显式列出 "types": ["node", "jest"]。

  • 移除的 flag 与语义变化 — 现在不支持/无效：target: es5、downlevelIteration、moduleResolution: node/node10/classic、module: amd/umd/systemjs/none、baseUrl（请让 paths 相对项目根目录）、esModuleInterop/allowSyntheticDefaultImports: false、alwaysStrict: false、asserts 导入（改用 with），以及存在 tsconfig.json 时用 CLI 传文件路径构建（需传 --ignoreConfig）。模板字面量推断现在保留 Unicode 码点——HeadTail<"😀abc"> 得到 ["😀", "abc"]，而不是拆分代理对——这会破坏类型层面的 UTF-16 工具。JavaScript 检查也更严格：值不能再代替类型（typeof x），@enum、@class、独立的 ?、后缀 ! 和 Closure 风格函数语法都不再被识别；详见 typescript-go/CHANGES.md。
