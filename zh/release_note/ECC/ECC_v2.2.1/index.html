ECC v2.2.1

ECC v2.2.1

ECC 2.2.1

ECC 2.2.1 是 ECC 2.2 的错误和安全补丁。它保留已发布的 v2.2.0 历史一成不变。这些注释描述了准备好的补丁；出版 和签名证据在发布清单中单独跟踪。

安全和数据保护

  • GateGuard 和治理捕获可识别破坏性的 PowerShell 命令， 包括本机 PowerShell 工具路径。动态命令处理可防止 后来的变量赋值隐藏了早期未解决的调用 （[#2961]（https://github.com/affaan-m/ECC/pull/2961））。
  • 相对 GateGuard 豁免 glob 保留在项目根目录中。显式的 仍然支持绝对豁免 （[#2921]（https://github.com/affaan-m/ECC/issues/2921））。
  • 安装程序写入拒绝与未跟踪的用户拥有的文件发生冲突。失败 仅为他们实际编写的文件安装刷新所有权哈希，保留以前的 未触及的托管文件的所有权哈希 （[#2964]（https://github.com/affaan-m/ECC/issues/2964））。
  • 引导式设置在所有权过滤之前重新验证其预览，因此文件 出现在预览和应用之间会导致明确的重试而不是错误 成功。现有的相同用户文件不属于 ECC 所有权。
  • 卸载遵循 ECC_DRY_RUN=1，包括旧版 Codex 路径，并拒绝 无效的试运行值而不是默默地允许删除 （[#2952]（https://github.com/affaan-m/ECC/issues/2952））。
  • 观察者分析保留对不成功或未经证实的观察 处理。仅退出代码零不再允许存档 （[#2971]（https://github.com/affaan-m/ECC/pull/2971））。
  • Yarn 锁定文件将 toml 更新为 4.3.0，与 npm 锁定文件和 删除受影响的旧分辨率。

挂钩和安装

  • 手动 Claude 在 Claude 设置中安装注册 ECC 拥有的挂钩条目。 修复、同意更改和卸载在同时协调这些条目 保留不相关的设置。原子设置更新检查目录 识别并重试检测到的并发编辑 （[#2992]（https://github.com/affaan-m/ECC/pull/2992））。
  • 直接钩子入口点处理更大的 JSON 有效负载，具有有界、UTF-8 安全 读取而不是默默地截断有效输入。现有产量 包装限制保持不变 （[#2924]（https://github.com/affaan-m/ECC/issues/2924））。
  • Pi 适配器选择实际的 Node 运行时而不是递归地选择 作为 Node 执行已编译的 OMP 主机 （[#2909]（https://github.com/affaan-m/ECC/issues/2909））。
  • 安装程序列表和控制面板有助于避免急切的第三方依赖 正在加载。需要缺少运行时包的功能报告缺少 显式依赖 （[#2994]（https://github.com/affaan-m/ECC/pull/2994））。
  • 自主线束设置文档替换了不存在的包名称 和不支持的 CLI 标志以及记录的接口，并区分 来自持久外部调度程序的会话调度 （[#2957]（https://github.com/affaan-m/ECC/issues/2957））。

安装和释放表面硬化

  • 公共和打包安装文档现在一致指向已发布的 ecc-universal 命令而不是过时的或不相关的包名称。
  • AdaL 适配器文档使用正确的 npx ecc-universal doctor --target adal 命令。
  • 克劳德在特定于提供商的工作开始之前设置预检 git，因此缺失 如果采取正确的行动，先决条件很快就会失败。
  • 指导设置试运行使用独立的 HOME、配置、XDG、临时和 Windows 应用程序 数据根以避免环境主机状态影响审查或测试。
  • 确切的打包工件现在对克劳德和 Kimi 设置、更新、修复、重复安装、卸载和试运行流程。
  • 标识符回归覆盖阻止过时的 ecc、ecc-install 和其他 不匹配的发布路径命令会重新进入面向用户的文档。

此补丁中包含的当前主要文档

  • 规范的 Itô 工作流程现在记录了 ecc ito accept <ticket-id> 和 ito_accept MCP 工具。
  • 接受明确受限于买方权威路由。它路由 活跃的桌面报价需要人工审核，并且不声称进行交易。

出处边界

  • v2.2.1 旨在成为纯绿色 main 上的签名注释标签。
  • v2.2.0 仍然是不可变的历史无符号异常。不要动， 重新创建或重复使用该标签。

范围和限制

  • 插件依赖性处理不会捆绑或自动安装缺失 模块。数据库和模式验证功能需要其声明 运行时依赖。
  • 所有权保护涵盖未跟踪的碰撞和安装失败 检查站。成功升级保留现有更换合同 以前管理的文件。在升级之前备份有意的编辑。
  • 此补丁没有引入新的线束平台或声称每个 开放社区问题已解决。

升级

发布工作流程发布 2.2.1 并验证注册表完整性后， 安装或更新软件包，然后运行您已使用的相同 ECC 命令路径 使用。在发布完成之前，下面的精确版本命令将返回 E404。

npm install -g ecc-universal@2.2.1
ecc doctor

对于首次或指导终端设置：

npx ecc-universal setup

本地 Claude 市场路径仍然受支持：

/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc
