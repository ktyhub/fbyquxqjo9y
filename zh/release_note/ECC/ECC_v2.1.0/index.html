ECC v2.1.0

ECC 2.1.0：规划画布、Kimi Harness 和自托管计算

ECC 2.1 将计划审查转变为视觉循环，并打开自托管模型的线束。计划画布允许您在浏览器中查看代理计划。指向您要表达的部分，而不是在聊天中重新输入。新的 Kimi Code 安装目标和经过验证的 Itô GPU 路径使 ECC + 开源模型成为一流的设置，并得到我们公共赞助商的支持：Moonshot AI (Kimi)、Itô 和 Atlas Cloud。

计划画布：通过指向而不是重新输入来查看计划

下载MP4演示 /plan 以确认门结束，到目前为止，审查只是终端中的一堵降价墙。现在，代理在仅环回浏览器画布中打开计划：

  • Click 元素或选择文本来附加编号注释
  • 当工作人员在航站楼工作时，从侧轨与工作人员聊天
  • 批准计划 / 请求更改 按钮直接映射到 /plan 的确认门
  • 美人鱼图、表格和任务列表本地渲染；文件编辑实时重新加载页面
  • 与模型和线束无关：普通的 CLI + JSON 协议 (ecc-plan-canvas)，没有仅 Claude 的依赖性

Kimi 安全带：Moonshot AI 合作伙伴关系

ECC 现在直接安装到 Kimi Code (--target kimi) 中。 Kimi Code 本地发现已安装的 .kimi/AGENTS.md 指令和 .kimi/skills/ 工作流程：

bash ./install.sh --target kimi --profile minimal
npx ecc doctor --target kimi
kimi

Itô GPU 上的自托管

针对任何自托管开源模型运行 ECC。如果您需要 GPU 容量，Itô 是 ECC 的首选计算赞助商。集成提供了端到端的保护：

  • ecc ito find：选择加入规范 Itô CLI 的桥梁，提交实时、经过验证的 RFQ（不保留容量）
  • 受保护的实时节点资格和只读计算切换
  • 带有凭证的 CLI 垫片被彻底拒绝 赞助链接本身是被动的：它不调用询价、保留容量、提供计算或配置服务。通过 Itô 进行的托管推理尚未上线。任何 GPU 提供商都可以工作，而 ECC 与提供商无关。

合作伙伴

Moonshot AI (Kimi)、Itô 和 Atlas Cloud 现已成为 ECC 的公共赞助商。自述文件记录了推荐的自托管路径：Itô 用于 GPU 容量，在兼容端点后面提供 Kimi 检查点，然后在顶部使用 Kimi Code + ECC。每个选择都保持独立且可交换。

也在2.1

  • Hermes 和 OpenClaw 安装目标：另外两个安全带加入了 Claude Code、Codex、OpenCode、Cursor、Gemini、Zed、Copilot 和 Kimi
  • Codex ECC 导航指南：从 Codex 内部找到正确的技能/命令界面
  • GateGuard 路径豁免 (GATEGUARD_EXEMPT_GLOBS) 和可配置本能注入（计数 + 置信阈值）
  • PostToolUse 挂钩合并到同步/异步调度程序中，每个工具调用的进程更少
  • 供应链强化：安装程序运行时通过严格审查，预提交秘密扫描现在捕获 Anthropic API 密钥 (sk-ant-...)
  • 跨 OpenCode、Windows、bun 锁定文件、仪表板和项目检测的长尾社区修复 该目录现在有67 个代理、281 个技能和 94 个命令垫片（2.0.0 发货了 64/261/84），加上挂钩、规则、内存、持续学习和 AgentShield。
