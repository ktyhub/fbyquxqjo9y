ansible v2.19.13

变更流程图

亮点

  • 集中式 URL 凭据掩码（mask_url） — 2.19.13 在 module_utils 中引入 mask_url 工具，用于遮蔽 URL 内嵌的认证数据。它专门修复了此前会泄露的只有密码的形式 redis://:password@host（无用户名），密码曾以明文返回。对模块/collection 作者而言，这是今后在输出或结果中暴露带凭据 URL 时应使用的新标准工具——采用它就能让自定义代码与 core 的秘密处理模型保持一致。

  • 脱敏覆盖整个 URI 处理面 — get_url、uri、apt_key、rpm_key 和 url lookup 现在在所有显示和返回的 uri 数据中遮蔽认证信息。实际收益：内嵌凭据不再进入 stdout、回调输出、CI 日志或 fact 缓存。需要注意的行为变化：任何对完整返回 uri 字符串做断言、或从中解析出凭据的 playbook/测试现在会看到脱敏值，需要更新。

  • 掩码延伸到 URL 库的错误路径 — module_utils.urls 现在在所有抛出的错误中遮蔽 URL 内联认证信息。失败消息常被原样记录，这封堵了一条常见泄露通道——畸形的 user:pass@host URL 曾会在失败任务消息或 traceback 中回显秘密。

  • tempfile 路径遍历加固 — tempfile 现在拒绝包含路径成分的 prefix 和 suffix 值（如 ../x 或 /abs/x）以防止路径遍历。迁移提示：曾向这些参数传入目录分隔符或 .. 的自定义模块或插件现在会直接失败；调用前应清理为纯 basename。这是安全修复，不是装饰性改动。

  • 升级优先级 — 除新增的掩码工具外，该补丁完全出于安全考虑（凭据泄露加路径遍历）。playbook 中会抓取带内嵌凭据 URL 的团队应尽快升级，并审计任何从结果数据中回读秘密的代码。

  • 破坏性变更 — 无；这是一个向后兼容的安全加固补丁。
