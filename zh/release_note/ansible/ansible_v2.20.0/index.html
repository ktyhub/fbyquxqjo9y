ansible v2.20.0

ansible v2.20.0

变更流程图

亮点

  • Python 版本支持发生变化 — 控制节点正式放弃 Python 3.11 并新增 3.14；被管节点放弃 Python 3.8。ansible-test 的 base/default 容器现在默认使用 Python 3.14.0。升级前请审计控制节点镜像和任何 3.8 目标——这是最可能让原本顺利的 rollout 出问题的一点。

  • 移除 PowerShell 引号剥离（唯一的破坏性变更） — 在 Windows 复制/抓取操作中剥离路径多余引号的代码被删除。常规 playbook 不受影响，但任何传入过度加引号路径的任务现在会原样看到它。这是 Breaking Changes 下唯一的条目，因此 Windows 使用较多的团队应显式测试路径处理。

  • 长期弃用的特性现已移除 — 托管 collection 的 Galaxy 服务器必须支持 v3 API（v2 已移除）；ansible-galaxy 移除对 resolvelib <0.8.0 的支持；DEFAULT_TRANSPORT=smart 被移除（需显式选择 ssh 或 paramiko）；vault/unvault 的 vaultid 参数、dnf5 的 install_repoquery、yum_repository keepcache，以及 PARAMIKO_HOST_KEY_AUTO_ADD/PARAMIKO_LOOK_FOR_KEYS 配置项均被移除；未继承 BaseVarsPlugin 并定义 get_vars 的 vars 插件失去 get_host_vars/get_group_vars 回退。采用前请对照此清单检查配置和自定义插件。

  • 预示 Ansible 2.24 的弃用 — INJECT_FACTS_AS_VARS 仍默认为 True，但将在 2.24 翻转为 False，内部 vars 缓存也计划在那时移除（改用 vars 和 varnames lookup）。shell 插件的 wrap_for_exec API，以及把 ignore_files 作为字符串传给 include_vars 的做法也已弃用。现在就开始迁移到 ansible_facts['...'] 访问方式，避免日后出现警告。

  • 可选启用的 play 参数规格校验（技术预览） — 新的 validate_argspec play 关键字支持对 play 变量做类型化校验：设为 True（要求 play 有 name）或某个规格名，Ansible 会加载包含 argument_specs 的 <playbook_name>.meta.yml。这是早期、需主动启用的能力——值得在新 playbook 上试点以捕获错误变量，但还不能替代扎实的任务级校验。

  • 模板与模块中安静但真实的行为变化 — 标记处理被重构：多节点结果会把内嵌 None 强制转为空字符串，ternary 过滤器现在惰性求值（PR #85743），template lookup 跳过 finalize 使标记能留给 default 等过滤器（#85674），被 failed_when 抑制的错误改名为 failed_when_suppressed_exception，使回调不再重复显示（#85505）。模块方面，blockinfile/lineinfile 新增 encoding 选项（#85291、#84999），replace 切换到 unicode 文本模式 I/O（#85785），stat 可返回 SELinux 上下文（#85217），setup 新增按 VG 划分的 lvs 子键（#85632）。

#Changelog 有关此版本中包含的更改，请参阅完整的 changelog。
