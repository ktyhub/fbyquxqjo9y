Open-Generative-AI v1.0.6

修订 发布时间2026年4月25日 来源Anil-matcha/Open-Generative-AI 英文原文

Open-Generative-AI v1.0.6

这个项目是干啥的：一个在自己电脑上跑生成式AI的桌面工具，支持多款引擎和苹果芯片加速，给不想花钱上云、想在本地生成图片视频的人用。

变更架构图

亮点

  • 本地推理二进制恢复可用（#108） — 上游一次范围很窄的 stable-diffusion.cpp 发布（只有 Mac arm64、一个 Windows CUDA 运行时占位包和 Linux ROCm）让几乎所有其他平台的本地引擎下载都失败了，报错是 Error invoking remote method 'local-ai:download-binary': No binary found for this platform。现在下载器会回溯最近 15 个 leejet release，直到找到匹配当前 OS/架构的构建，Linux 的优先顺序是纯 x86_64 → vulkan → rocm。如果你之前为了让本地生成可用而一直卡在旧版本，现在可以升级了——但要预期拿到的是回退构建，而不是最新的上游版本。
  • 平台注意：macOS Intel 仍然只能用作 UI — 虽然提供了 1.0.6.dmg（x64），但 leejet 从未发布过 x86_64 的 macOS 二进制，所以本地引擎在那里依然装不上；#108 只是把晦涩的 IPC 报错换成了明确提示。Intel 用户应计划自带推理后端，或改用远程生成。
  • 源码安装对子模块更友好（#110） — 继承自 v1.0.5：安装流程不再假设 git 子模块已经初始化，所以全新 clone 和 CI checkout 不会中途失败。这主要影响从源码构建、而不是直接消费 .dmg/AppImage 的用户。
  • 设置入口更显眼（#111） — 同样来自 v1.0.5，新增醒目的 Settings 按钮，缩短了配置本地引擎的路径。改动不大，但考虑到 #108 现在可能静默回退到较旧的二进制，能快速确认当前用的是哪个引擎是很有用的。
  • 打包上的坑依然存在 — macOS 首次启动仍需先执行 xattr -cr "/Applications/Open Generative AI.app"，再右键 → 打开以绕过 Gatekeeper。在 Ubuntu 24.04+ 上，AppImage 可能因非特权用户命名空间限制而静默失败；要么设置 kernel.apparmor_restrict_unprivileged_userns=0，要么改装 .deb（自带 AppArmor 配置）。把这些写进安装文档，而不是每个用户都排查一遍。
  • 破坏性变更 — 本版本没有。

修复

  • Linux/Windows 上的本地推理引擎可再次下载 (#108) — leejet 最新的 stable-diffusion.cpp 版本暂时仅提供 Mac arm64 + Windows CUDA 运行时存根 + Linux ROCm，因此该狭窄集合之外的任何人都可以点击 Error invoking remote method 'local-ai:download-binary': No binary found for this platform。下载器现在会遍历最后 15 个 leejet 版本，直到找到一个实际上具有当前操作系统/架构的版本，并且 Linux 匹配器更喜欢普通的 x86_64 → vulkan → rocm。 macOS Intel 用户会得到更清晰的错误，因为 leejet 从未发布过 x86_64 macOS 二进制文件。
  • 加上 v1.0.5 的 #110（子模块安全设置）和 #111（突出的设置按钮）。

下载

  • macOS Apple Silicon (M1/M2/M3/M4)： Open Generative AI-1.0.6-arm64.dmg
  • macOS 英特尔 (x64)： Open Generative AI-1.0.6.dmg
  • Linux x86_64 — AppImage: Open Generative AI-1.0.6.AppImage （chmod +x 然后运行）
  • Linux x86_64 — Debian/Ubuntu: open-generative-ai_1.0.6_amd64.deb (sudo apt install ./open-generative-ai_1.0.6_amd64.deb)

首先在 macOS 上启动：xattr -cr "/Applications/Open Generative AI.app"，然后右键 click → 打开。 Ubuntu 24.04+ 上的 AppImage：如果无提示地失败，则安装 sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0 或安装 .deb（它附带 AppArmor 配置文件）。
