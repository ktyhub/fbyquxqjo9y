Codewhale v0.8.62

CodeWhale 是规范的项目、命令、npm 包和 发布资产名称。旧版 npm 包 deepseek-tui 是 已弃用并且不再收到进一步的版本。用户来自 v0.8.x 旧版 deepseek / deepseek-tui 名称应迁移 与 docs/REBRAND.md。

安装

推荐 — npm（一个命令，两个二进制文件）

npm install -g codewhale

包装器从此版本下载两个二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.62

该映像附带了 codewhale 调度程序和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个二进制文件将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

Unix（Linux / macOS）： 
tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装两个二进制文件，并将该目录添加到当前用户的 PATH 中。
  • 提取codewhale-windows-x64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 每个平台还附有裸露的、未存档的二进制文件（codewhale-<platform> 和 codewhale-tui-<platform>） - 这些是 npm 包装器和应用内 codewhale update 下载的内容，而上面的 .tar.gz / .zip 存档是建议的手动下载，并另外捆绑安装脚本。旧版 npm 包 deepseek-tui 已弃用并且不会重新发布。有关从 v0.8.x 旧二进制名称的迁移，请参阅 docs/REBRAND.md。

v0.8.62 里有什么

已更改

  • GLM-5.2 现在是默认的直接 Z.AI 型号。 DEFAULT_ZAI_MODEL 已解决 codewhale-tui 和 codewhale-config 中的 GLM-5.2； glm-5.1 别名仍然解析为 GLM-5.1 （默认值与别名分离 臂，因此它不再跟踪默认值）。文件和 config.example.toml 否 不再将 GLM-5.2 描述为选择加入预览。
  • GLM-5-Turbo 注册为真实模型并接线为更快/探索 GLM 系列的子代理兄弟：GLM-5.2 父路由 更快/探索儿童到 GLM-5-Turbo（直接 Z.ai）和 z-ai/glm-5-turbo (OpenRouter)，而不是降至 GLM-5.1。 GLM-5.1 和 GLM-5-Turbo 本身 没有更便宜的等级，并将孩子留在父母身上。
  • type: "explore" 子代理默认为 model_strength: "faster"。 有界 只读查找/搜索/状态工作现在使用更便宜的同系兄弟姐妹 自动，除非显式 model 或 model_strength: "same" 提供。非探索角色保留保守的 same 默认值。
  • GPT-5.5 / OpenAI Codex 更快的路线保留在 GPT-5.5 并进行推理 解析为 low（Codex 响应 API 没有真正的 off，因此解析的 现在的努力是诚实的low而不是off默默地重写）。否 当没有更便宜的同一提供商兄弟时，DeepSeek/GLM 后备是虚构的 存在。 DeepSeek Pro→Flash 路由及其无需思考的更快通道 不变。
  • 基本提示/委托技能指导更新以鼓励并行 广泛回购的只读探索（2-4 type: "explore" 子代理）， 版本、分支、基准和 API 表面调查，同时保持 父级中的架构、集成和最终验证。的 委托技能示例现在使用提供者中立的 model_strength 而不是 硬编码的 DeepSeek 模型 ID。
  • 代理合成护栏。 基础构成现在围绕工具构建 充分的证据而不是开放式的坚持：额外的阅读、搜索、 授权必须针对缺失的事实，代理人应回答 限制而不是无限期地扩大搜索范围。运行时循环保护 现在会提前阻止重复的只读/委托调用并限制重复 使用综合强制工具在单轮中进行广泛的查找/委托循环 错误。保护元数据区分精确的重复项 (identical_tool_call) 来自无进度循环 (no_progress_tool_loop)。
  • **子代理移交和可见性。**直接子代理完成已耗尽 在下一个父模型请求之前，因此完成的子模型可以唤醒主模型 立即建模，而不是等待空工具使用分支或空闲引擎 路径。嵌套子代理现在向其直接父代理报告完成情况 收件箱；主模型仍然只接收直接子完成，避免 孙子洪水，同时保留嵌套证据流。子代理输出 当子代理依赖于子代理时，指导现在需要子代理出处 儿童报告：引用儿童 agent_id 和儿童的证据行，以及 不要将儿童的发现作为直接证实的事实来呈现。侧边栏订单 子代理作为父/子树，并用父和注释嵌套行 悬停文本中的深度信息。
  • 子代理摘要出处 (#2652)。 子代理的自由文本结果现在是 明确视为未经证实的自我报告而不是证实 证据。完井定点搭载summary_kind: complete | truncated 因此父模型可以根据是否看到完整报告或 clipped 进行分支 摘录。简短摘要（≤ 12,000 个字符）获得软“重新验证材料” 索赔”后缀；较长的头部+尾部用诚实的标记截断 说明删除的中间内容无法通过 retrieve_tool_result 检索。 因此，每个摘要都只带有一个边界标记，而不是同时带有两个边界标记。
  • 提供者元数据集中化。 提供者环境变量、配置键、别名、 和身份验证提示现在通过共享 ProviderMetadata 注册表解决 codewhale-config、codewhale-tui 和 codewhale-cli，减少漂移 提供商选择器、codewhale auth、doctor --json 和设置之间 提示。

添加

  • 特工澄清问题 (#3102)。 特工现在拥有一流的 request_user_input 向用户提出结构化澄清问题的工具 通过模态 UI 界面，而不是仅发出聊天消息并希望 用户注意到。反映线束的批准/秘密请求流程 已经用于权限。该工具接受 1-3 个问题，每个问题都有一个 header、id、2-4 个可选选项（标签 + 描述）以及 allow_free_text / multi_select 标志（均默认为 false 向后兼容）。输入预先经过可操作错误的验证。有线 跨越所有层：request_user_input 工具、发动机处理 (turn_loop → approval)，交互式 TUI 模式 (UserInputView) 全键盘导航和运行时协议 (EventFrame::UserInputRequest + AppRequest::SubmitUserInput) 所以无头 /app-server clients 可以通过编程方式应答。奇偶校验测试涵盖 线路往返和省略标志默认值。
  • 转录超链接 — 带外 OSC 8 (#3029). Clickable 文件 / file:line / URL 链接现在通过列漂移安全到达终端 路径。链接有效负载由 Markdown 渲染器嵌入带内，然后 从ratatui缓冲单元中提取并重新发射到带外 ColorCompatBackend — 因此 ESC 字节永远不会占用显示列或 腐败的选择。支持终端获取直播超链接；其他人看到 标签文本不变。 Clipboard/选择提取条残留代码为 纵深防御。
  • 仅限 CodeWhale 的技能发现门 (#3296)。 新 [skills].scan_codewhale_only = true 将会话时技能发现限制为 CodeWhale拥有的根（<workspace>/.codewhale/skills、~/.codewhale/skills、 和任何显式的 skills_dir），同时忽略跨工具目录，例如 .claude/skills、.opencode/skills、.cursor/skills 和 ~/.agents/skills。 默认设置仍然是广泛兼容性扫描。
  • 权限/询问运行时规则 (#3295). 同级 permissions.toml 仅询问 规则现在由 TUI 引擎加载并应用于之前的 exec_shell 自动/会话批准快捷方式。匹配询问规则强制批准提示 在其他自动批准的流程中并被拒绝 approval_mode = "never"。
  • 运行时 API 无身份验证文档。 docs/RUNTIME_API.md 现在提供文档 codewhale app-server --insecure-no-auth 用于仅环回测试和警告 反对将其与 0.0.0.0 上的 --mobile 组合。

已修复

  • TUI 优化。 空启动欢迎块以实际启动块为中心 渲染文本宽度，修复旧版本遗留的偏心布局 面向侧边栏的欢迎组合。现在流式传输 HTTP 正文读取错误 解释 CodeWhale 是否可以在输出之前重试，或者是否出现警告 部分输出后以避免重播和复制流文本。
  • **配置注释保留。**重写config.toml、settings.toml或 tui.toml 现在将用户注释和格式合并回序列化中 文件；如果注释合并失败，写入将回退到纯序列化 输出而不是失败。
  • 快照门尊重每个工具快照 (#3292)。 每个工具快照 现在在写入之前检查[snapshots].enabled，匹配现有的 会话级门。
  • Poppler pdftotext 检测 (#1667)。 依赖解析器现在进行探测 pdftotext -v 而不是 --version，因为 Poppler 将 --version 视为 输入文件名。修复了仅安装 Poppler 的系统上的检测。
  • 计划确认清单可见性。 计划模式确认模式 现在在计划详细信息下显示活动清单，以便用户可以查看 在接受或修改计划之前具体的checklist_write工作分解。
