Codewhale v0.9.4

修订 发布时间2026年8月8日 来源codewhale-hq/Codewhale 英文原文

Codewhale 是 Shannon Labs 的公共产品。 codewhale 命令、npm 包和发布资产名称保留小写技术名称 标识符。旧版 npm 包 deepseek-tui 已弃用，并且 不再收到进一步的发布。来自 v0.8.x 旧版 deepseek 的用户 / deepseek-tui 名称应随 docs/REBRAND.md 一起迁移。

安装

推荐 — npm（一个命令，所有三个入口点）

npm install -g codewhale

包装器下载匹配的 codewhale、codew 和 codewhale-tui 此版本中的二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.4

该映像附带了 codewhale 调度程序、codew shim 和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序和 codew shim，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个 crate 将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

v0.9.4 中有什么

Codewhale v0.9.4 运送释放列车线束工作：熟悉的舰队 名册/设置界面具有明确的操作员领导者和用户/文件夹范围， 保留可操作代理而不是永久存档的工作条， 禁止投票而不冻结独立工作的等待政策， 更平静的工具输出和会话恢复，帐户/工作流程搜索/ 自动化/切换界面，更短的翻译就绪网站，以及 跨权限、DeepSeek 响应、SQLite 的发布阻止程序修复 文件编辑、终端宽度和 Windows 安装。

添加

  • 内存维护：remember 获得 revise 和 retire 旁边 默认append。两者都准确说出了他们所针对的音符并且都需要 改变的证据。仅追加内存衰减——修正 位于与之相矛盾的注释后面，并且两者都不断达到模型 - 因此该模型现在可以保持其自己的持久注释真实，而不仅仅是 添加到他们。
  • 模型记录的关于您的持久状态的审计跟踪。每个 就地内存编辑被记录到 memory/JOURNAL.md，并且每个 连续线束 refine / remove 到 JOURNAL.md 的状态旁边， 每个都有之前、之后和证据。线束拆除之前没有留下任何痕迹 即使该条目完全离开状态，也不会记录，因此日志 现在是其内容唯一幸存的地方。
  • 首次运行提示如下：Codewhale 第一次保存某些内容 耐用它指向/memory，翻译成全部十五个完整 语言环境包。这种状态影响了后来的会议，但从未提及任何内容 它存在。
  • 子代理检查点恢复：agents/followup 恢复 interrupted_continuable 子项从其检查点进入新的代理循环 — 新的代理 ID、原始提示加上之前的对话尾部 — 当 运行时已附加，否则保留仅队列语义 continuation_handle 返回；对同一个中断 ID 进行第二次后续操作 返回现有的恢复目标，而不是生成重复目标（PR #5242）。
  • MCP 注册表发现与注册表优先工具选择：registry_sync 将符合条件的本地 stdio 目录显示为完整的模型端候选者 设置、连接失败消息对提前退出和使用帮助输出进行分类 下一个注册表候选人的积分恢复，以及捆绑的 mcp-discovery 技能记录了流程（PR #5238）。
  • 渐进式新上下文披露：新会话的发送量最少 宪法核心——基本事实、用户意图和范围、真实 完成、机制保障和优先级——程序性的 按需披露的剧本，一个选择加入的项目上下文包 (project_context_pack_enabled) 计入上下文报告中，而 load_skill 通过 name="list" 进行目录发现；测量的新环境预算 下降约 40% (PR #5077)。
  • 命名舰队商店 v2：每个配置一个独立的 TOML 舰队 （schema = "fleet"），具有范围显式选择（用户全局默认值与 文件夹覆盖）、来自旧角色配置文件的迁移收据和原子 拒绝用同一个子弹击垮不同舰队的保存。

已更改

  • /fleet 再次成为熟悉的名单/设置面孔。操作符行是 舰队领导者（会话模型）；标题为选定的已保存舰队命名，并且 无论是用户全局的还是文件夹范围的。命名舰队切换生活在 /fleet fleets（按 Enter 键在行自己的范围内选择）。会话路由更改 暂时停留，直到 /fleet save、/fleet save-as 或 /model save-default。
  • 等待子代理指示禁止查看/状态轮询和休眠等待， 但允许不依赖于孩子成绩的独立工作—— 家长不再因有用的、不冲突的工作而中途冻结。
  • workflow run不再需要--fleet；保存的舰队是一个可选的引脚 角色+会话路由之上的层。
  • 主页和入门副本更短并且可以跨区域设置扫描， 保留字典密钥和 {brand} 令牌奇偶校验。
  • 工具结果现在呈现为具有实际扩展的普通有界预览； 存储、保留分类账和内部证据语言不再泄漏到 正常的成绩单。
  • 散文包装、目标状态、模态问题、作曲家尾部行为，以及 环境运动现在遵循一个跨狭窄界面的确定性界面契约 终端和快速流。
  • 侦察员和审阅者舰队角色获得网络访问权限和边界 验证面进行真实侦察，同时保留不可写， 无生壳安全地板。
  • 工作流程运行可以描述多达 1,000 个任务，同时最多允许 16 个实时任务 任务立即通过主机并发门。比赛现在订购 支持明确的分数优先选择，同时保留其成本优先 默认。
  • 运行时权限兼容性输入解析为一个实时 permission_posture。自动审核无需批准或结构化即可进行 问题模式、未解决的保留无法关闭以及计划过时的通话 姿势改变后重试权限（PR #5025）。
  • 重复和漂移的每回合元数据已被删除，以支持 运行时拥有的权限，以及大型内联帐户和技能测试现在都存在 拥有测试缝。
  • 将 Ratatui 固定到 0.30.0，并将 Ratatui-core 固定到 0.1.0。共享核心 0.1.1+ 使 Terminal::clear() 发出阻塞光标位置报告 与 TUI 输入循环竞争，可能会终止首次启动；两个引脚都是 承重，因为 0.30.0 声明了 ratatui-core ^0.1 并且会 否则自行解析转发（@bistack 的 PR #5192；上游 拉塔图伊/拉塔图伊#2640）。
  • 将 globset 更新为 0.4.19，将 clap-complete 更新为 4.6.8， futures-util 到 0.3.33，libc 到 0.2.189，actions/stale 到 11.0.0，以及 docker/4.5.2 的登录操作。锁定图还包括 RUSTSEC-2026-0221 的事件侦听器 5.4.2 修复。
  • 进度界面现在随处可见：最后一个用户可见 “工作更新待定”通知显示“待办事项列表”、工具构造函数和 文档将 todo_write 命名为单一规范进度工具，并且 work_update、TodoWrite 和 todo 保持注册为隐藏状态 兼容性别名，以便保存的脚本不断重播。
  • 默认情况下，子代理和 agents/wait 等待时间较短且上限： 阻塞等待默认为 30 秒，并拒绝阻塞超过 120 秒，因为 阻塞等待使会话对键入的输入和已解决的子项耳聋 已经作为 <codewhale:subagent.done> 哨兵报告。
  • Bash action=wait 荣誉timeout_secs（秒）和裸机timeout （毫秒）与规范 timeout_ms 一起，并将 block 作为别名 对于 wait，因此在其他等待工具上形成的习惯会得到它的持续时间 要求而不是默默地退回到 30 秒默认值；结果 元数据报告实际应用的 wait_timeout_ms。

已修复

  • 内存日志不再作为内存索引。它是 Markdown 中的 记忆树，所以源步行收集了它和每一个退休的笔记 重新进入其 before: 行下的可搜索集 — 将 修订版刚刚将确切的事实删除回提示中。
  • memory_path 指向已经本地的商店不再派生 第二家商店嵌套在它里面，默默地写在除了 用户命名的文件。
  • muse 和 muse-spark 在代理中解析为 muse-spark-1.1 注册表，而配置默认为 muse-spark-1.2，因此 CLI 和 应用程序服务器将这些别名路由到配置的默认值永远不会的地方 指出。注册表现在包含 1.2 和贡献者变体。
  • 显式的 type=builder （或其 implementer 别名）加上 write_authority=read_only 现在在生成时无法关闭，而不是启动 标记为写入角色，默默地只有侦察工具，然后自我封锁 燃烧一回合后（#5123）。支票故意缩小，因为有两个 相邻的组合是合法的并且保持合法：
    • type=worker + read_only — 工人是未命名的默认值（它呈现为 general），其能力来自权威，而不是来自其名称，因此 只读工作者是一个普通的通用子对象。工人、侦察员、 审核者和验证者仍然是四个规范的只读舰队角色。
    • 任何 role + read_only — role 是名册解析的标识，而不是 能力声明，因此验收工作流程仍然可以解决 implementer 到其保存的配置文件，同时确定该子项的范围以进行验证。 拼写为 type: "implementer" 的只读缩小的调用者应该 将其移至 role: "implementer"。
  • 用户全局凭证在显式工作空间中保留下来 CODEWHALE_CONFIG_PATH 选择没有本地密钥的路由 - 准备情况探测用户全局 在得出结论之前提供程序表缺少一个键。
  • 工作栏上的子代理令牌数字累积输入+输出（相同 工人预算使用的总和）而不是单独的完成令牌；过去了 当孩子安定下来时，时间仍然冻结。
  • 子代理的实时工作栏行显示他们还有多少待办事项 当孩子自己的账本有未解决的项目时，离开（N left）——从来没有 当不存在列表时制造零。
  • Surface 不再在无法强制执行操作系统沙箱的平台上声明操作系统沙箱。 策略解析器不接受平台输入，因此在默认的 Linux 上（bubblewrap 是选择加入）并且在所有 Windows 上，标头芯片读取 files: workspace 和 /status 读取 sandbox workspace-write，而没有任何限制。两者都 现在解析真正的后端并说 (unenforced)。
  • tool_category 挂钩条件仅匹配已退役的工具名称，因此 category = "shell" 拒绝钩子 — 安全控制 docs/HOOKS.md 文件——默默地从未被解雇。类别现在使用注册名称， 和多操作工具按操作分类。
  • -5、nan 或 1e300 的 Retry-After 标头导致请求任务崩溃 （Duration::from_secs_f64 因负值而恐慌）。解析现在受到保护并且 限制为一小时。
  • 不记名令牌不再泄漏到操作员可见的收据中。 授权： Bearer <jwt> 分为两个令牌，并且 JWT 不匹配任何密文规则； 前缀匹配也区分大小写，因此 SK-live-… 幸存下来。
  • prune_older_than 销毁了最新的回滚快照并保留了旧的 那些 - 每次启动时，对于具有跨越保留的快照的任何工作区 窗口。两条修剪路径现在共享一个孤儿链重建并保留每个路径 幸存者的真实时间戳。
  • 绝对或相对命令路径不再击败每个 execpolicy 拒绝 规则（/bin/rm -rf / 与 rm -rf / 规则不匹配）和类型化的 Allow 规则不再自动批准链接后缀，例如 git log ; curl … | sh。
  • File 读取范围参数和 Bash stdin/cwd/task_id 上的错误类型现在是 错误而不是静默默认值 - start_line:"1200" 字符串用于 返回文件头，并且非字符串 stdin 运行命令时没有 stdin 并报告成功。
  • 多字节工具 ID 不再使上下文检查器恐慌，宽 (CJK) 文本不再出现 更长的时间会溢出决策卡，并且主机名如 127.evil.example.com 不再被视为环回。
  • 拒绝模型实际上可以进行的辱骂（rlm action='open' 而不是 比退役的rlm_open； Bash 而不是 exec_shell）。
  • 子代理调度不再中止进程。 Tokio 运行时已构建 通过 #[tokio::main]，将每个工作线程保留为 2 MiB 默认值，同时 只有所有者线程收到显式的 16 MiB 堆栈 — 并且引擎运行 在一个工人身上。调试构建 agent 调度超出了该堆栈并引发了 SIGABRT，这不是恐慌，因此无法捕获；进程死亡 生成中期，从未发出子请求。发布版本不受影响。
  • 固定提供商的车队配置文件不再将裸模型 ID 泄漏到 会话路线。 model_overrides 导出每个角色的模型，同时删除其角色 提供商，因此派出固定到另一个提供商模型的侦察员 活动的 client 并在线路上被拒绝 — 可见为即时身份验证失败 在扇出的第一个子代理上。
  • 导轨的固定面板不再花费四行显示“无活动工作”。 现在，空面板会像“任务”面板一样折叠，并且设置 迁移不再将默认的 sidebar_focus = "auto" 折叠到固定的 永远在线的条带，它默默地将该面板交给了每个拥有该面板的用户 设置文件。 （一个空面板崩溃；一个面板持有结算 待办事项或已完成的工作人员不为空 - 请参阅常规登记条目 如下。）
  • 工作栏保留已确定的待办事项和诚实的子代理标题，同时 已完成/取消的工作人员从顶部条带中倒塌，因此扇出不会 永久吃掉转录本。失败或中断的工作人员保持可见 （他们仍然需要关注）。已定居的代理商仍然可以通过以下方式联系到 代理面板和目录。待办事项行用文字表达其状态（待办事项/ 正在进行/已完成/已取消），并且子代理行携带类型， 目标、已过去和输入+输出标记。每个工作排都是一扇门 每个导轨面板和位置：click 和 Enter 打开行的世界 （工作检查员/代理详细信息 - 包括成品代理）而不是 什么也不做。详细寻呼机关闭后，click 会重新打开 细节而不是被陈旧的切换所吞噬。
  • 当终端不能时，导轨将其行交给转录本 两个座位都可以坐，所以闲置的海洋可以在 24 排中保留下来，而不是被驱逐。
  • code_execution和js_execution不再向模型描述自己 作为沙盒。两者都是普通的本地子进程，没有 seccomp、jail 或 容器（PR #5221，作者：@h3c-hexin 和 @asto18089）。
  • Model Studio 推理控件现在无法在主机上而不是在主机上关闭 提供商枚举，因此自定义 base_url 不再接收阿里巴巴特定的 enable_thinking字段，而qwen3.8-max则不再发思 切换它不接受（@Inference1 的 PR #5233，结束 #5203）。
  • config.example.toml 不再声称 Shift+Tab 循环推理层。 Shift+Tab循环权限姿势； Ctrl+T 循环推理 （由 @vFONGv 发现，PR #5229）。
  • 阿里巴巴 Model Studio 推理控件现在是路由范围和模型范围的 而不是提供商范围内的（#5203，从 #5233 中收获 @Inference1)。码鲸发送 enable_thinking / preserve_thinking / reasoning_effort 仅当 配置的 base_url 是经过验证的阿里巴巴聊天完成主机，因此 将 modelstudio-* 提供商 ID 指向自定义网关不再注入 DashScope 的方言就进去了。 qwen3.8-max 和 qwen3.8-max-preview 是 仅思考，不再收到 enable_thinking: false 他们不能 荣誉； preserve_thinking 已发送给已记录的模型以接受它，因此 他们的推理痕迹会延续到下一个回合；和 deepseek-v4* / glm-5.x 将推理层映射到记录的 high / max 阶梯上。
  • xAI 设备登录现在可以从指向丢失的配置中恢复 Codewhale 拥有的凭证生成，而不是每次尝试都失败 带有一般激活错误，并完成失败报告完整的 错误链（#5032）。
