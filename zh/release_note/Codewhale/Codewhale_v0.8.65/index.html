Codewhale v0.8.65

CodeWhale 是规范的项目、命令、npm 包和 发布资产名称。旧版 npm 包 deepseek-tui 是 已弃用并且不再收到进一步的版本。用户来自 v0.8.x 旧版 deepseek / deepseek-tui 名称应迁移 与 docs/REBRAND.md。

安装

推荐 — npm（一个命令，两个二进制文件）

npm install -g codewhale

包装器从此版本下载匹配的运行时二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.65

该映像附带了 codewhale 调度程序、codew shim 和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序和 codew shim，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个 crate 将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

手动下载——平台档案（推荐）

下面的每个存档都包含 codewhale 调度程序、codew 填充程序和 codewhale-tui 运行时以及安装脚本：

平台 档案 安装脚本

Linux RISC-V codewhale-linux-riscv64.tar.gz install.sh
macOS x64 codewhale-macos-x64.tar.gz install.sh
macOS ARM codewhale-macos-arm64.tar.gz install.sh

Unix（Linux / macOS）： 
tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装 codewhale.exe、codew.exe 和 codewhale-tui.exe 并将该目录添加到当前用户的 PATH 中。
  • 提取物codewhale-windows-x64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 每个平台还附有裸露的、未存档的二进制文件（codewhale-<platform>、codew-<platform> 和 codewhale-tui-<platform>） - npm 包装器和应用内 codewhale update 下载匹配的运行时二进制文件，而上面的 .tar.gz / .zip 存档是建议的手动下载，并另外捆绑安装脚本。旧版 npm 包 deepseek-tui 已弃用且不会重新发布。有关从 v0.8.x 旧二进制名称的迁移，请参阅 docs/REBRAND.md。

v0.8.65 里有什么

添加

  • 提供商/模型/路由解析（EPIC #2608）。 规范提供商、模型、 提供和路线类型与单个 RouteResolver 产生 已解析 ReadyRouteCandidate（端点、线路协议、模型 ID、上下文 每个开关的限制、价格）（#3458、#3084、#3384）。正在执行的 client 是 现在从已解析的候选者构建，而不是从配置重新派生 （＃3384）。一个致力于、无网络的 Models.dev 型目录为模型提供了真实的模型 上下文窗口和定价，具有无秘密的实时缓存（#3497，#3498， 第3385章）提供带有出处的定价将投射到候选者身上（#3501， ＃3085），路线限制提供路线感知上下文预算服务（＃3508， ＃3523，＃3086）。
  • 舰队执行基础（EPIC #3154）。 舰队配置文件类型和配置 (#3469)，持久的经理简历，工作区代理配置文件加载解析为 工作运行时 (#3367)、任务规范中携带的加载意图 (#3512) 以及 保留已解决的检查路线的收据（#3154，#3166）。工人 状态被折叠到统一的/fleet表面并通过 运行时 API。
  • 提供者表面。 带推理功能的 /provider 就绪仪表板 准备情况、实验/支持的成熟度标记以及“开放模型” 该提供商”操作（#3083、#2984、#3485）；跨提供商 /model 搜索 具有滚动和提供程序提前输入（#3484，#3075）；直插式<think> 具有每个提供商覆盖的推理流路由（#3222）；使用遥测 规范化为规范标记类，包括响应缓存未命中和 推理标记（#2961，#3509）；以及带有承载/标头的远程 MCP OAuth 登录 身份验证优先级（#3527）。
  • 更多提供商和路线。 用户定义的兼容 OpenAI 的自定义提供商 通过 [providers.<name>] (#1519); DeepSeek Anthropic 兼容路线（#2963， #3449);千帆路线 (#3425);智浦并入Z.ai，待遇平等 模型标准化（#3539）； DashScope/Together 夹具。
  • 本地化模式选择器和作曲家指示器。 /mode 选择器提示， 模式名称和提示，加上作曲家的 Vim 模式指示器，现在呈现在 所有七个已发布的语言环境（面向模型的模式标签保持英文）。收获 来自@gordonlu 的#2239。
  • 网站和自动化。 运行时/集成页面、出处和 mirror-trust 副本、事实漂移 CI 门、已发布的安装脚本和 codewhale.net 上的每周社区摘要存档（#3419、#3421、#3415、#3482、 第3420章）；每个自动化模式/shell/trust/批准设置 (#3467)。
  • 模型参考浏览器。 只读 /modeldb 命令（别名 model-reference、modelref）在捆绑目录上打开一个寻呼机 — 每个 模型的事实上下文窗口、最大输出、模式和价格，按以下方式分组 提供者/种类。仅标签：它从不选择、路由或分层模型 （＃3205，＃2300）。
  • 转录预设。 /config preset <name> [--save] 机制，带有 第一个 calm 预设 — 平静模式、平静工具折叠、舒适间距以及 低速运动 - 仅演示和证据保存（#3478）。
  • 模型能力配置文件。 类型 model_profile 模块分离 来自解析的提供商路由功能的内在模型事实，非常紧凑 路线推迟了较重的非必要工具，而标准/完整路线则保留了 急切的工具表面（#3451，#3365）。
  • 实时提供商目录刷新。 无秘密的 /models 实时获取层 （401/403/404/429 映射到键入的结果）提供目录缓存； API key 授权请求，但永远不会保留到增量或缓存中 （＃3385）。

已更改

  • 配置模块化（#3311）。 ProviderKind（#3505），线束姿势 (#3507) 和提供商默认种子 (#3503) 移入专用模块，并且 config.rs 整体拆分为干净的叶模块（路径、搜索、 模型/基本 URL 常量、子代理限制）位于 pub use 外观后面。 AppMode 助手是集中式的 (#3510)，并且模式与权限策略是 现在通过单个 base_policy_for_mode 解析器导出，而不是 分散突变（#3386，保留咨询审查意图行为）。
  • 更精简的工具表面。 从活动集中删除 task_shell_* 并折叠 tool_search_*（#3463）；依次消除了loop_guard和编码推理 处置（#3462）；将 Orchestration 配置添加到章程中。
  • 路由。 提供者/模型切换和能力感知后备链 通过RouteResolver解决；推理努力被标准化为 已解决提供商；后备链现在会跳过缺乏身份验证的提供商 （＃2574）；上下文窗口和内存压力来自已解析的路线 （＃3086）。
  • UX. 批准模式获得了组分隔符和选定行插入符（#3515）； 选择器滚动/提前输入和选择对比度强化（#3500）；自述文件 被重写为架构结束（#3087）；回购代理的指导是 去硬编码以活出真相。
  • 车队身份和默认值。 车队工作人员现在以明确的方式输入 “召唤舰队成员”操作合同、设置/个人资料提示保留 默认模型行为为同路由继承，并生成工作线程 指令避免泄漏递归拓扑，只有协调器 需要。
  • **旧版群清理。**删除了过时的 /swarm 核心命令/菜单 注册，因此 /fleet 是产品表面，而 /subagents 仍然是产品表面 工作人员状态的兼容性快捷方式。
  • 运行状态动画。 工具卡和后台任务行现在共享一个 更快的盲文旋转节奏，因此 Bash/后台工作读取一致 文字记录和侧边栏都充满活力。
  • 恢复贡献者信用。 线程式机器可读信用 (docs/CONTRIBUTORS.md + .github/AUTHOR_MAP) 用于早期合并的工作 出厂时没有它，包括 /jobs cancel-all 操作和 npm @jieshu666 的重试超时提示 (#1538) 和社区 ACP 适配器 参考@rockeverm3m。

已修复

  • 释放卫生。 严格的cargo clippy --workspace --all-targets --locked -- -D warnings gate passes; npm run build不再弄脏生成的 网络事实；现场设置metadataBase；社区摘要页面解析每个 独立录制并本地化其镶边； cargo audit 是干净的 记录了 Starlark 传递性未维护的建议。
  • **路由和模式正确性。**普通的提示文字不再 解释为模式开关（#3387，#3491）；模型候选人的范围是 主动提供者；接受共同拥有的 DeepSeek 路由 (#3426)；不安全感 http:// 自定义端点发出咨询警告 (#1519)；和舰队 设置规划者的角色/模型选择现在驱动生成的配置文件。
  • 运行时稳定性。 MCP 连接丢失是显式的 (#3524)，HTTP API 调用重用共享 MCP 池 (#3532) 和每个代理子代理邮箱 遥测被限制以减少 UI 延迟 (#3454)。
  • YOLO 后台 shell 批准。 后台 shell 命令不再弹出 YOLO模式下的审批模式。 classify_risk 标记所有 shell 命令 具有破坏性，因此自动审查安全地板保留了所有“背景”外壳 审查，ForcePrompt 网站从未检查过 auto_approve — 仅 后台命令浮出水面，因为前台 shell 采取 Interactive 原点并跳过该分支。
  • Bash 批准模式适合。 shell 批准模式现在标记为 Bash 直接命令，避免在影响摘要中重复命令/workdir， 包装长命令，并切换到短终端上的紧凑控件，以便 决策键保持可见。
  • 自定义提供商选择器行。 现在具体 [providers.<name>] 条目 出现在提供者选择器中（id、端点、身份验证准备情况、线路协议、 当前模型）而不仅仅是通用占位符；授权准备荣誉 每个条目密钥/env/metadata/no-auth/loopback。
  • 被动 MCP 工具发现。 运行时 API 拥有的 stdio MCP 进程不存在 被动 /v1/apps/mcp/tools 请求产生的时间更长；现场发现 仍然可以通过 ?connect=true 获得。 doctor 现在对相对路径发出警告 没有 cwd 的 stdio MCP 命令。
