Codewhale v0.8.67

修订 发布时间2026年7月7日 来源codewhale-hq/Codewhale 英文原文

CodeWhale 是规范的项目、命令、npm 包和 发布资产名称。旧版 npm 包 deepseek-tui 是 已弃用并且不再收到进一步的版本。用户来自 v0.8.x 旧版 deepseek / deepseek-tui 名称应迁移 与 docs/REBRAND.md。

安装

推荐 — npm（一个命令，两个二进制文件）

npm install -g codewhale

包装器从此版本下载匹配的运行时二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.67

该映像附带了 codewhale 调度程序、codew shim 和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序和 codew shim，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个 crate 将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

手动下载——平台档案（推荐）

下面的每个存档都包含 codewhale 调度程序、codew 填充程序和 codewhale-tui 运行时以及安装脚本：

平台 档案 安装脚本
Linux x64 codewhale-linux-x64.tar.gz install.sh
Linux ARM64 codewhale-linux-arm64.tar.gz install.sh
macOS x64 codewhale-macos-x64.tar.gz install.sh
macOS ARM codewhale-macos-arm64.tar.gz install.sh
Windows x64（安装程序） CodeWhaleSetup.exe NSIS 设置
Windows x64 codewhale-windows-x64.zip install.bat
Windows x64（便携式） codewhale-windows-x64-portable.zip —
Unix（Linux / macOS）： 
tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装 codewhale.exe、codew.exe 和 codewhale-tui.exe 并将该目录添加到当前用户的 PATH 中。
  • 提取codewhale-windows-x64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 每个平台还附有裸露的、未存档的二进制文件（codewhale-<platform>、codew-<platform> 和 codewhale-tui-<platform>） - npm 包装器和应用内 codewhale update 下载匹配的运行时二进制文件，而上面的 .tar.gz / .zip 存档是建议的手动下载，并另外捆绑安装脚本。旧版 npm 包 deepseek-tui 已弃用且不会重新发布。有关从 v0.8.x 旧二进制名称的迁移，请参阅 docs/REBRAND.md。

v0.8.67 里有什么

添加

  • 您在/model中选择的模型现在是操作员：车队工人，其 任务规范和名册配置文件引脚没有模型继承活动会话路由 而不是硬编码的 auto 哨兵，匹配固定的操作符行 /fleet roster。任务级别和配置文件模型覆盖仍然获胜，并且 路由收据记录了应用的来源（task.model， agent_profile.model 或 run.model）。
  • 添加了 /workflow 命令（别名 /workflows、/wf）作为用户 选择加入工作流程编排。裸 /workflow 编排当前 工作——模型从对话上下文中综合目标； /workflow <objective> 缩小了行程； /workflow status [run_id] 和 /workflow cancel <run_id> 继电器式运行收据无需启动新的 运行。
  • 没有主动目标的裸 /goal 现在从对话中声明目标 通过 create_goal 上下文而不是打印用法；有一个积极的目标 保持状态读数，显式 /goal <objective> 不变。
  • 添加了宪法优先设置向导：统一的 /setup shell 恢复、后退导航和跳过重试状态；提供商/模型准备情况 具有自定义提供者表单和提供者选择器详细布局的卡片；一个 带有预设应用程序和项目覆盖警告的运行时姿势卡； 设置验证报告；和事务设置持久性 秘密编辑和回滚（#3402、#3403、#3404、#3405、#3406、#3410、 第3411章）
  • 添加了具有确定性渲染器的结构化用户全局构造， 提示块注入，带有预览和预设的指导原则创作 保存，并以/constitution管理器命令作为主要构成 管理界面，文件状态显示在设置中，操作显示在 诊断（#3793、#3806、#3811）。
  • 添加了模型辅助宪法和舰队概况起草 明确的批准门，记录了 untrusted 草案出处 模型创作的文本永远不会默默应用。更新用户保留他们的 现有宪法不变，并设立地方性宪法检查点 更新后需要（#3794）。
  • 添加了 Hotbar 路由编辑器 v1 以及路由切换槽操作和支持 对于自定义模型路由，加上配置的提供者路由管理器 /provider 和 /model 缺少身份验证切换到提供商密钥 条目（#2066、#3830、#3831）。
  • 添加了 .codewhale/rules/ 和 .claude/rules/ 的自动发现 目录作为项目上下文，总字节预算上限 组装的规则块。由枫 (@yekern) 贡献。
  • 将 context_input_budget_for_route 从发动机暴露在外 集成可以重用路线预算数学。贺信 供稿 （@h3c-hexin）。
  • 向运行时 API 添加了 GUI 配置持久性。由@gaord 贡献。
  • 添加了带有区域设置注册表和漂移的网站本地化矩阵 检查。由 @idling11 (#3090) 从 #3763 中收获。
  • 添加了 doctor 半应用设置状态检测和启动里程碑 跟踪启动性能诊断。
  • 添加了覆盖光标终端的 v0.8.67 计算机使用的dogfood提示 QA 流程、无头门、设置、子代理完成、车队、工作流程、模型 定价，并发布证据收集。
  • 舰队：现在报告本地工作内存使用情况，包括保留内存 当任务处于运行状态时。由@cyq1017 (#3901) 贡献。
  • 网站：社区中心、宪法论文页面和以宪法为中心 主页、从提供商注册表生成的模型页面、文档暗模式 以及完整的 SEO 元数据/站点地图覆盖，真正的终端播放器 宪法痕迹，以及现场明星徽章和版本。
  • 新增美团龙猫为一级OpenAI兼容提供商 （longcat，具有 long-cat、meituan-longcat 和 meituan 别名）， LONGCAT_API_KEY发现，LongCat-2.0默认型号，提供商 选择器连接、模型完成、提供商文档和 Web 提供商事实。
  • 舰队：添加了每个提供商的设置卡（持久性、宪法、热栏、 工具/MCP、远程运行时），具有统一的安装目录和特定于提供商的功能 凭证链接。提供程序设置进度以事务方式保存 回滚防护，Codex OAuth 不被提供者密钥存储，并且 无头 QA 合同可验证供应商之间的设置准备情况。
  • 舰队：添加了具有角色感知负载的舰队入门配置文件（侦察→快速， 经理→继承等）、/fleet setup 配置文件创作向导、舰队 有效权限记录、路由意图源跟踪。
  • 舰队：添加“操作员”作为内置舰队名册成员 - 首选 用于工作流程协调的 helm Fleet 插槽。运营商计划、路线、评论 输出，并根据需要调用其他舰队插槽。这是一个名册角色，而不是一个角色 单独的应用程序模式。完整的操作/操作模式架构被推迟 至 0.9.0。
  • 工作流程：声明式工作流程现在通过生产驱动程序运行 工作流工具连接到子代理调度，公共工作流表面是 重命名，并发出类型化的工作流程运行和状态收据 调试和验证。
  • 添加了与提供商无关的舰队名册和装载：特定于提供商 子代理限制、启动并发数和准入上限源自 配置，无需对任何单个提供程序进行硬编码。
  • 添加了工作流运行时基础：内部 JS 创作/运行时 crate 编译并重播示例工作流程。 0.8.67 附带 /workflow 选择加入， 生产驱动程序调度路径、子代理任务切换和类型化运行/状态 收据；更丰富的创作用户体验和完整的 TUI 运行视图仍在跟踪 v0.8.68（#2974，#4038）。

已更改

  • 明确舰队协调层级，角色真实化 原则：操作员（会话的 /model 选择）运行 操作并将管理人员分配给工作流程； 经理是中间的 一个工作流程的管理者。内置的审阅者现在是明确的 对抗性（假设更改被破坏，尝试反驳它），以及审查 子代理介绍采用相同的框架。内置manager/operator/ reviewer 名册成员现在运送角色 instructions 流入工人 舰队任务规范和代理/工作流程 profile: 生成时都会出现提示 路径；自定义配置文件通过相同的 instructions 字段覆盖它们。
  • 删除了从未有过不同路线的装饰性舰队词汇： tool-heavy 插槽和 strong/balanced/deep-reasoning/code/ review/tool-heavy 装载层。 inherit（运营商路线）和 fast（提供商的更快级别）保留；现有的退休名字 配置继续使用相同的自动路由进行解析（作为自定义标签），并且 /fleet setup 模型级台阶现在只提供真正的选择。
  • 提高了高吞吐量扇出的默认子代理并发性： max_subagents默认20→64（配置上限128）和排队+运行 入场上限 200 → 1024。使用计量计划但想要旧行为的用户 可以在config.toml中设置max_subagents = 20。
  • 将内部 whaleflow 子系统重命名为 workflow 工作区：codewhale-whaleflow/codewhale-whaleflow-js 板条箱变成 codewhale-workflow/codewhale-workflow-js、Rust 标识符和 JS 桥 符号被重命名，CODEWHALE_WHALEFLOW_JS_*环境变量 成为 CODEWHALE_WORKFLOW_JS_*，创作/RFC 文档移至 WORKFLOW_AUTHORING.md 和 WORKFLOW_EXTERNAL_MEMORY.md。历史 changelog 和追溯分类账条目保留旧名称作为记录。
  • 记录了 Homebrew 推出策略并添加了分销渠道 检查发布清单。由 @idling11 (#3489) 从 #3760 中收获。
  • 暂停了 Linux RISC-V 预构建版本和夜间工件，因为 rquickjs-sys 0.12.0 不运送 riscv64gc-unknown-linux-gnu 绑定器； 安装程序、文档和更新路径现在将 RISC-V 视为不受支持，直到 上游绑定或启用了bindgen的构建区域。
  • 审批提示冷静、紧凑、诚实，集中 宪法的首次后续行动；首轮入职现在无需干涉 进入设置向导，语言选择器提供每个附带的区域设置 （＃3929）。
  • 启动性能：启动看门人和存储扫描不再阻塞 第一帧，@mention 完成不再重新遍历每个工作区 击键、空闲离线队列克隆和重复工具输出哈希 被淘汰了。
  • 澄清了误导性的“Ctrl+B 将此命令设为背景”shell 措辞 (#3859) 和热栏帮助快捷方式。 Chanhyo Jung 贡献的文档 （@roian6）。
  • 记录了强制回购法不变量、宪法流程和 /fleet setup 配置文件创作向导；对齐permissions.toml动作 文档。文档由 @greyfreedom 贡献。
