Codewhale v0.8.61

CodeWhale 是规范的项目、命令、npm 包和 发布资产名称。旧版 npm 包 deepseek-tui 是 已弃用并且不再收到进一步的版本。用户来自 v0.8.x 旧版 deepseek / deepseek-tui 名称应迁移 与 docs/REBRAND.md。

安装

推荐 — npm（一个命令，两个二进制文件）

npm install -g codewhale

包装器从此版本下载两个二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.61

该映像附带了 codewhale 调度程序和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个二进制文件将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

手动下载——平台档案（推荐）

下面的每个存档都包含 **codewhale 调度程序和 codewhale-tui 运行时，以及一个安装脚本：

Unix（Linux / macOS）： 
tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装两个二进制文件，并将该目录添加到当前用户的 PATH 中。
  • 提取codewhale-windows-x64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 每个平台还附有裸露的、未存档的二进制文件（codewhale-<platform> 和 codewhale-tui-<platform>） - 这些是 npm 包装器和应用内 codewhale update 下载的内容，而上面的 .tar.gz / .zip 存档是建议的手动下载，并另外捆绑安装脚本。旧版 npm 包 deepseek-tui 已弃用并且不会重新发布。有关从 v0.8.x 旧二进制名称的迁移，请参阅 docs/REBRAND.md。

v0.8.61 里有什么

此版本为多代理工作提供了运行时控制平面：TUI 保留 当子代理运行时响应迅速，子代理会向车队式耐用工人汇聚 使用每个角色模型路由，并且提供者/模型路由在每个会话中都是隔离的。它还 折叠了一些社区贡献。

添加

  • WhaleFlow 运行时基础 — 工作线程运行时配置文件（角色/权限/shell/ 工具/模型路由，具有非升级子派生），跨提供商模型注册表 具有离线目录水合作用，以及提供者准备/上下文预算/提供者适配器/ 资源遥测服务。 （#3217、#3071、#3072、#3073）
  • 每角色、异构模型子代理路由 — 可以为子代理分配一个模型并 每个角色的提供者（例如侦察与综合；验证者路由到快速模型）。 （＃2027，＃1768）
  • 持久目标模式 — 具有令牌/时间核算和 在目标完成之前验证者作为法官的门。 （＃3215，＃891，＃1976，＃2058，＃2029）
  • 家长可见的工人互动合同——每个工人的建议行动。 (#3226)
  • 维护员GitHub工作流程技能； ACP 注册提交已准备就绪。 (#3192)
  • 传统应用程序服务器 HTTP 传输上与 OpenAI 兼容的 /v1/chat/completions 端点， 提供者中立，具有模型注册表解析和配置的凭据转发。

已更改

  • 子代理向车队式耐用工人汇聚 - 真正的工人生命周期状态是 投影到侧边栏而不是硬编码的“运行”，并且子代理返回结构化的 需要输入检查站而不是停车场。 （＃3226，＃3096，＃3154）
  • 每回合运行时标签公开能力状态，而不是面向人的模式标签。 (#3213)
  • 独立的 shell 和验证器工作默认为后台作业，具有非阻塞等待和 完成通知；现在阻塞需要显式等待。 (#3212)
  • 子代理启动现在向模型公开显式 model_strength 和 thinking 控件 而不是隐藏的子模型自动路由； explore 工作被记录为非常适合 更快的型号和 thinking: "off"。
  • 计划模式是严格只读的（无 shell 工具），与其运行时状态一致。
  • /swarm 在耐用的工作基板后面有门控。 (#3218)
  • 旧版 deepseek 安装/更新路径解析为 codewhale。 （＃2960，＃2924，＃2917）

已修复

  • 当多个子代理产生时 TUI 冻结（启动阻止程序） — 终端输入泵运行 离开渲染线程，AgentProgress 事件被合并，并且子代理不再驻留在 输入没有协调器来回答；六人压力测试保护输入/渲染/取消 活力。 （＃3216，＃3096）
  • 空闲子代理完成通知现在恢复父轮，而不是等待 稍后用户留言；感谢 @giovanni-paolilla 的死锁报告 (#3266)。
  • 提供者/模型路由隔离 - 提供者和模型状态是会话本地的，并且 不匹配的提供者+模型元组在路由边界处被拒绝。 (#3227)
  • 路由有效的上下文窗口元数据、超限预检和有限恢复 context_length_exceeded 而不是重新循环。 (#3204)
  • 同步工具（file_search、grep_files、list_dir）可取消且不再保留 一轮开放反对取消。 （#1791）
  • MCP stdio 代理启动提示不再束缚 YOLO/非交互式运行。 (#2475)
  • 后台 shell 恢复停止/失败；可配置的子代理 API 超时。 （＃1737，＃1786，＃1806）
  • Composer：可靠的排队转向 + Ctrl+S 发送（#3203、#3224）；页脚忙/闲指示器 （＃2982）； CJK 自动换行 (#963)； clickable 侧边栏停止目标 (#3028)；实时令牌吞吐量 （＃3190）；自动过期的终端子代理卡 (#3078)。
  • 安装程序/更新路径中的 Linux glibc 预检有明显错误。 （＃3207，＃1067）
  • 自更新重试暂时的 GitHub 元数据/资产故障并从 GitHub 回退 在构建发布资产 URL 之前，将 REST API 重定向到公共 releases/latest。 (#3232)
  • 提供商选择器按中性字母顺序列出提供商，而不是首先硬编码 DeepSeek；活动的提供商保持预先选择状态。 (#3076)
  • 一旦核对表，工作侧边栏不再显示过时的 phase now: / phase next: 策略行 已 100% 完成。
  • 计划模式不再快捷方式调查命名存储库、URL、版本的请求， 发布、构建状态、基准测试、错误、PR、问题、API 表面或本地代码路径。
  • 超大的粘贴文本在编辑器中保持可编辑状态，并在提交时附加文件备份 模型访问时间；感谢@idling11（#3267，关闭#3263）。
  • 裸数字键 1-8 现在插入文本，而不是触发热键栏插槽；使用 Alt+digit 用于 热键操作。感谢 @wjq2026 的报告和 @DieMoe233 的粘贴路径注释 (#3243)。
  • Kimi/Moonshot 工具模式将空函数参数标准化为根对象模式；谢谢 @jghwwnq 用于提供者重现 (#3265)。
  • Novita 默认使用其 OpenAI 兼容的 /openai/v1 端点，因此不再完成聊天 404开箱即用；感谢 @buko 的报告和端点验证 (#3255)。
  • 依赖安全：ws 在 npm 包中固定到 8.21.0 以关闭远程内存耗尽 DoS（依赖机器人）。
