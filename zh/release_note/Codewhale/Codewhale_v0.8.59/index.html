Codewhale v0.8.59

CodeWhale 是规范的项目、命令、npm 包和 发布资产名称。旧版 npm 包 deepseek-tui 是 已弃用并且不再收到进一步的版本。用户来自 v0.8.x 旧版 deepseek / deepseek-tui 名称应迁移 与 docs/REBRAND.md。

安装

推荐 — npm（一个命令，两个二进制文件）

npm install -g codewhale

包装器从此版本下载两个二进制文件并将它们放在同一目录中。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.59

该映像附带了 codewhale 调度程序和 codewhale-tui 运行时。 latest 标签也在发布时进行了更新。

货物（Linux / macOS）

cargo install codewhale-cli codewhale-tui --locked

这两个包都是必需的 - codewhale-cli 生成 codewhale 调度程序，而 codewhale-tui 生成调度程序委托给的交互式运行时。仅安装一个二进制文件将在运行时失败并出现 MISSING_COMPANION_BINARY 错误。

手动下载——平台档案（推荐）

下面的每个存档都包含 **codewhale 调度程序和 codewhale-tui 运行时，以及一个安装脚本：

平台 档案 安装脚本
Linux x64 codewhale-linux-x64.tar.gz install.sh
Linux ARM64 codewhale-linux-arm64.tar.gz install.sh
Linux RISC-V codewhale-linux-riscv64.tar.gz install.sh
macOS x64 codewhale-macos-x64.tar.gz install.sh
macOS ARM codewhale-macos-arm64.tar.gz install.sh
Windows x64（安装程序） CodeWhaleSetup.exe NSIS 设置
Windows x64 codewhale-windows-x64.zip install.bat
Windows x64（便携式） codewhale-windows-x64-portable.zip —
Unix（Linux / macOS）： 
tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows：

  • 对于安装程序路径，运行 CodeWhaleSetup.exe；它会在 %LOCALAPPDATA%\Programs\CodeWhale\bin 下安装两个二进制文件，并将该目录添加到当前用户的 PATH 中。
  • 提取codewhale-windows-x64.zip
  • 运行install.bat（复制到%USERPROFILE%\bin）
  • 将 %USERPROFILE%\bin 添加到您的路径 便携式 Windows 存档会跳过安装脚本 - 从任何目录提取并运行。 NSIS 安装程序当前未签名，可能会触发 Windows SmartScreen，直到签名证书连接到发布管道。 下面还附加了用于脚本编写和 npm 包装器的单独二进制文件。旧版 npm 包 deepseek-tui 已弃用且不会重新发布。有关从 v0.8.x 旧二进制名称进行迁移的信息，请参阅 docs/REBRAND.md。

验证（推荐）

从该版本下载校验和清单并验证：

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt
shasum -a 256 -c codewhale-artifacts-sha256.txt

v0.8.59 里有什么

添加

  • Moonshot Kimi K2.7 代码模型。 Moonshot/Kimi 提供商现在默认为 kimi-k2.7-code，识别该型号的 kimi/kimi-k2 别名，保留 显式 kimi-k2.6 可选，并添加 OpenRouter moonshotai/kimi-k2.7-code 注册表行。
  • 简洁详细模式 (#3052)。 CLI 非交互式启动现在默认 简洁的提示/输出规则，除非被 config、env 或覆盖 --verbosity，而交互式 TUI 启动默认情况下保持正常。 感谢@cyq1017 的公关。
  • 临时生成的项目上下文 (#3058)。 在中打开 CodeWhale 没有指令文件的目录现在保留有界的生成项目 内存中的概述而不是创建 .codewhale/instructions.md。
  • ACP 注册表身份验证元数据 (#1447)。 ACP stdio 适配器现在进行广告 initialize.authMethods中的终端认证设置，匹配 注册表的验证要求。
  • 侧边栏上下文菜单（#3065）。 Right-clicking 侧边栏不再显示 Paste； clickable 侧边栏行现在将其行命令作为第一个 上下文动作。
  • 侧边栏悬停弹出窗口 (#3088)。 流式传输现在保持侧边栏悬停 弹出窗口响应，同时继续限制转录本/主体鼠标 运动。
  • 深色主题选择对比（#3074，感谢@drpars）。 会话、配置、 帮助、上下文菜单和批准选择现在使用静音选择 背景而不是明亮的强调色。
  • 光标式活动元数据行 (#3146)。 密集成功的工具运行 摘要现在呈现为单个静音 Explored ... / Updated metadata 行，包括成功的通用验证程序的短命令系列标签 组，并保持键盘/鼠标扩展和细节检查完好无损。
  • 提供者等待可观察性（#3095）。 页脚停顿原因现在命名 活动提供商/模型路线、空闲秒数与流预算，以及是否 扇出计划仍处于 0 running 或正在等待调度。结构化 提供者等待事件从主滴答循环中每回合记录一次（不在 每个页脚都重画）。
  • 交互式扇出发射门（#3095）。 直接子代理子队列 在可配置信号量后面（[subagents] interactive_max_launch， 默认4）带有可见的queued: waiting for an interactive fanout slot 在他们的第一个模型步骤之前进行推理。
  • 目标生命周期控制。 /goal 现在是主要命令界面 会话目标，包括 pause、resume、complete、blocked 和 clear 控制，而 /hunt 仍然是兼容性别名。
  • 持久线程目标 API。 应用程序服务器 clients 现在可以设置、获取和清除 通过 thread/goal/set、thread/goal/get 和 thread/goal/get 实现耐用螺纹目标 thread/goal/clear，由具有 Codex 风格状态的国家存储支持， 令牌/时间核算字段。
  • **命令边界所有权层（#2888/#3055）。**内置斜杠命令 元数据现在位于 commands/registry.rs 中，斜杠解析位于 commands/parse.rs，以及集团所属指挥区的处理人员，保留 现有的调度面，同时减少未来的 commands/mod.rs 流失。
  • 批准规则源元数据 (#1186/#2971). 运行时 API approval.required 事件现在包括可选的 matched_rule 元数据 执行策略规则导致了该提示。感谢@greyfreedom 的公关 和 @Ram9199 用于审计语义讨论。
  • 本地化工具系列标签 (#2901)。 用于读取的工具活动标签， 修补、运行、查找、委托、扇出、RLM、验证、思考和通用工具 现在工作通过已发布的区域设置表进行路由。感谢@gordonlu 的 公关。
  • 本地化的配置部分标签 (#2918)。 现在的交互式配置视图 本地化部分和会话/保存的范围标签，同时保留英语 搜索词。感谢@gordonlu 的公关。
  • 本地化配置编辑器标签 (#2919)。 现在配置编辑器模式 本地化编辑标签、默认/不可用的占位符和有效的 货币提示。感谢@gordonlu 的公关。
  • 热栏数字键调度 (#3056)。 裸 1-8 现在触发绑定 热栏插槽仅在作曲家为空时触发，而Alt+1-Alt+8触发 无论作曲家文本和覆盖如何，插槽都会保留密钥所有权。谢谢 @reidliu41 的公关。
  • 语音听写命令 (#3051)。 /voice、/voice-send 和 /voice-control 现在通过 sox/rec/arecord 进行录制，通过 活动提供者的聊天完成 API，并在 作曲家光标。 voice.toggle热键动作发出真实声音 命令，以及所有七个已发行版本中本地化的帮助和状态文本 语言环境。感谢@huqantao 的公关。
  • 线程倒带和快照恢复 API (#2808). GUI clients 现在可以调用 POST /v1/threads/{id}/undo、/patch-undo 和 /retry 用于分叉、回滚、 或重新运行最近的线程，加上 POST /v1/snapshots/{id}/restore 按 ID 恢复工作区快照。感谢@bengao168 的公关。
  • 主动提供商后备链 (#2773)。 配置 fallback_providers 现在构建 TUI 可以报告的有序主要加后备路线， 使用 /provider fallback reset 前进并重置，包括页脚 后备状态的可见性。感谢@idling11 的公关。
  • 提供者元数据注册表 (#3005)。 内置提供者 ID、显示名称、 默认值、环境变量、配置键、别名和线路格式现在位于 共享元数据注册表，提供者漂移检查覆盖注册表 合同。感谢@sximelon 的公关。
  • 拥抱人脸提供者路线 (#2879)。 现在拥抱人脸推理提供者 拥有一流的配置、环境、文档和注册表覆盖范围 OpenAI兼容路由器，包括huggingface/hugging-face/ hugging_face/hf 别名和 HUGGINGFACE_*/HF_* env 后备。谢谢 @mvanhorn 的公关。

已修复

  • SSE 数据行不带空格 (#3152)。 聊天完成、响应和 Anthropic 流阅读器现在接受 data: {...} 和 data:{...} SSE 框架，匹配规范并防止提供者省略可选的 流空输出的空间。感谢@wgeeker 的公关。
  • 运行时线程详细信息 N+1 读取 (#3141)。 get_thread_detail 现在扫描 坚持转动项目一次并依次对它们进行分组，而不是阅读 项目目录每回合一次，保留项目顺序，同时保持大 线程细节负载响应。
  • 项目本地挂钩 trust 边界 (#3140). 现在是 .codewhale/hooks.toml 仅在用户拥有的配置中的工作区被 trusted 后加载，匹配 项目本地 MCP trust 模型，同时保留记录的 shell 命令 挂钩合同。
  • 技能注册表同步延迟 (#3139)。 /skills sync 现在同步注册表 具有有限有序并发的条目，因此网络延迟不再叠加 一次只使用一项技能，同时输出顺序保持确定性。
  • SiliconFlow 中国提供商配置 (#2893/#2895). siliconflow-CN 现在读取自己的 [providers.siliconflow_cn] / [providers.siliconflow-CN] 表并仅在未设置时回退到 [providers.siliconflow] api_key/base_url/model 字段。感谢@Artenx 的报告和 @idling11 的公关。
  • 自我更新下载超时 (#3006)。 codewhale update 现在应用 五分钟 HTTP client 超时因此被阻止或 GitHub 释放非常慢 下载失败而不是无限期挂起。感谢@New2Niu 的公关。
  • 旧版 deepseek 更新迁移 (#2960/#3013/#3053)。 正在运行 立即进行品牌重塑前安装的 deepseek update 或 deepseek-tui update 返回可复制粘贴的 npm、Cargo、Homebrew 和手动二进制迁移 步骤而不是尝试生成丢失的 codewhale 二进制文件。自述文件和 品牌重塑文档现在涵盖相同的升级路径。谢谢@jazzi 和 @tiangangQiu 用于报告，@cyq1017 用于更新路径 PR，以及 @angus-guo 用于自述文件 PR。
  • 短 codew shim 委托。 现在 codew 方便二进制文件 更喜欢之前安装在其旁边的同级 codewhale 调度程序 回退到 PATH，防止新的本地构建或安装 意外调用旧的全局调度程序。
  • 宪法 trust 措辞 (#2950/#3008)。 基本提示现在解释 “以 A 开头”表示 trust 的基线，而不是文字输出 格式规则。感谢@cyq1017 的公关。
  • TUI 提供商源恢复 (#3007/#3011)。 不支持的交互式 提供商现在报告该值是否来自 --provider、环境、 或配置。来自配置的不受支持的提供程序会回退到 DeepSeek，而无需 转发过时的密钥环秘密。感谢@cyq1017 的公关。
  • 执行自动模型切换 (#3148). 现在 codewhale exec --model auto 通过尊重 CodeWhale 模型环境别名来克服 CLI/TUI 边界 旧的 DeepSeek 模型在回退到提供商默认值之前进行切换。 感谢@hongchen1993 的公关。
  • macOS 快捷键修饰符 (#2938/#2943)。 类似 Ctrl 的快捷键 macOS 终端报告为 SUPER 现在可用于后台任务和 侧边栏焦点和弦，无需重写 clipboard 快捷键。谢谢@idling11 为了公关。
  • TUI 鼠标报告泄漏 (#3063/#3067)。 剥离原始 SGR 鼠标坐标 即使 use_mouse_capture 为假，也能从作曲家那里得到尾巴，覆盖 崩溃或焦点竞赛后孤立终端报告状态。
  • 子代理生命周期中断 (#3080)。 API-现在超时中断 发出 MailboxMessage::Interrupted，渲染终端中断卡，以及 协调管理器快照中过时的运行扇出计数。
  • OpenAI Codex 流诊断和主动工具崩溃 (#3146)。 响应桥现在报告嵌套 response.failed / response.incomplete错误代替unknown，并且密集成功 飞行中的工具突然崩溃到与以下相同的平静活动元数据行中： 承诺的历史。
  • OpenAI Codex 推理层。 从 DeepSeek 切换到 openai-codex 现在将过时的推理状态标准化为响应兼容 low/medium/high/xhigh 层。启动，/config，以及型号 选择器现在显示 Codex 标签而不是泄漏 DeepSeek off/max 名称，而 Codex 仍报告为响应负载 提供者。响应请求构建器还限制传统的 minimal 输入 至 low 并具有 Codex 要求使用的回归覆盖率 reasoning.effort，不是 DeepSeek thinking 字段。
  • OpenAI Codex 上下文元数据 (#3070)。 gpt-5.5 默认值和 CodeWhale 别名现在使用 OpenAI 记录的 1,050,000 个令牌上下文窗口 以及 128,000 个用于上下文压力、提示和医生的最大输出元数据 能力输出。
  • OpenRouter Nemotron 3 Ultra 预设。 OpenRouter 预设和模型 注册表现在发出 nvidia/nemotron-3-ultra-550b-a55b，同时保留旧的 超级别名兼容。
  • MiMo 切换后的 OpenRouter 身份验证 (#3064)。 从小米 MiMo 切换 OpenRouter 现在具有针对预检密钥故障的回归覆盖，并且 在发送任何请求之前进行承载身份验证标头隔离。
  • 响应严格工具架构兼容性 (#3062/#3017/#1883)。 响应 功能工具现在保留每个工具的严格模式兼容性，保持可选 严格模式字段可为空，并在以下情况下附加确定性约束注释 根组合组必须展平以用于响应。
  • **运行时提示自主环路防护（#3061）。**运行时策略参考 现在明确禁止当 <runtime_prompt> 为 只有新的回合内容，没有工具/子代理切换待处理。
  • 目标运行时状态同步。 目标代币预算和活动/暂停/完成 状态现在与目标一起同步到引擎中，并且模型可见 update_goal 只能标记目标已完成或已阻止。
