DocsGPT 0.17.2

这个项目是干啥的：是一个给企业文档做智能问答的工具，让员工用自然语言直接问出文档里的答案，还能接外部工具和跑代码来处理复杂问题。

变更架构图

亮点

  • 幂等任务与工具执行 — 基于 Postgres 的去重和租约防止 Celery 重投导致摄取、webhook 和工具副作用重复；部分摄取从分块检查点恢复，tool_call_attempts 记录提议、执行、确认和失败调用（#2450、#2479、#2484）。在上线 API 或 worker 进程前，请应用 Alembic 迁移 0004–0011。无 Key 的摄取任务现在从 source_id 合成保护 Key，重复失败会以事件终止，而非无限重试。
  • 实时事件与轮询 API 破坏性变更 — /api/events 通过 Redis Streams/pub-sub 投递用户级通知，/api/messages/<id>/events 在断线后重放已记录的 SSE 帧（#2472）。旧端点 /api/mcp_server/oauth_status/<task_id> 被移除；自定义 MCP 集成必须消费 mcp.oauth.* 事件，并向 get_oauth_status() 提供用户 ID。请保持 Redis 可达、允许长连接 SSE 穿过代理，或设置 ENABLE_SSE_PUSH=false 使用轮询回退。
  • 默认工具与定时代理 — 无代理聊天现在默认启用 memory、read_webpage 和 scheduler，可通过 DEFAULT_CHAT_TOOLS 配置；代理可选择 scheduler 进行一次或 cron 运行，支持 IANA 时区、工具白名单、token 预算和运行日志（#2485）。定时需要 Celery beat，且 scheduler 被排除在无头运行之外，防止自链式调用。代理绑定的聊天现在优先使用代理有效的 default_model_id，而非请求体中冲突的 model_id。
  • 摄取与 worker 韧性 — 存储的远程源配置在同步前被规范化，不支持的连接器同步被跳过，来源暴露 ingestStatus 和 /api/sources/reingest 用于恢复（#2480、#2482）。停滞的摄取只被标记为终态一次，而非反复告警。Docling 队列/批次上限和默认 4 GiB 的 Celery 子进程回收限制降低原生内存增长（#2478、#2484），代价是解析器并发降低。
  • 出站请求加固 — 代理工具和解析器现在只解析并校验 DNS 一次，直接连接已校验的 IP，默认禁用重定向，并对 LLM 提供的路径参数做 URL 编码（#2486）。这堵住了 DNS rebinding/重定向 SSRF 和路径/查询注入路径；依赖重定向的自定义工具必须显式处理。
  • 前端响应性与工具链 — 共享 API 客户端全局并发上限为 8、每路由 3，对进行中的 GET 去重但不合并变更操作；新的防抖 hook 减少请求抖动（#2458）。会话搜索现在匹配标题与问答内容（#2471），空消息或未变更的消息/会话名编辑被阻止（#2439）。前端 fork 应基于 TypeScript 6.0.3、Vite 8.0.10 和 react-dropzone 15 重新构建，并重新验证自定义上传集成（#2408、#2436、#2417）。
