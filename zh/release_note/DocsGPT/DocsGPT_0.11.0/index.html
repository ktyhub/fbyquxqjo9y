DocsGPT 0.11.0

变更流程图

亮点

  • 数据库模型迁移 — PR #1062 和 #1118（“Migrating database to new model”）是唯一需要运维介入的变更：请备份数据并在启动新后端前执行迁移，否则现有会话/来源可能无法读取。这对既有部署实质上是破坏性升级；全新安装没问题，但请预留维护窗口，不要原样复用旧数据库卷。
  • Milvus 成为一等向量后端 — #1045 将 Milvus 支持合入主干，与既有存储并存，因此已在运行 Milvus 的团队可以复用该基础设施，而不必另行配置。注意本版本客户端库也有变动——qdrant-client 1.9→1.11（#1081）和 Elasticsearch 8.12→8.15.1（#1067、#1144）——请针对新客户端版本验证检索器/索引行为。
  • React Widget 大改 — 可嵌入组件是变动最多的面：新增包括 large 预设的尺寸选项（#1084、#1107）、Next.js 兼容性修复（#1088）、升级的选项（#1089）、带错误处理的流式端点同步（#1092）、反馈收集（#1117）、流式滚动修复（#1113），并替换了弃用依赖（#1111）。如果你嵌入它，请固定版本并重新测试——多项 props 和行为发生变化，文档也在 #1093 中重做。
  • 流式与来源投递 — #1087 修复新建会话 ID 特有的流式 bug，#1140 新增流式来源，使引用与回答一同到达，而非之后零星涌入。会话来源 UI 被重做（#1075），共享会话现在会补齐来源（#1120），远程来源可同步（#1152）。感知延迟更好，但任何解析响应流的都应重新检查对新来源 payload 的处理。
  • 符合 OpenAPI 的端点与更易代理 — #1154 新增符合 OpenAPI 规范的端点，#1040 引入可复用的前端 API 客户端，#1112 简化代理，#1044 修正 delete-all 的 HTTP 方法类型。这让生成的客户端和程序化集成更实用——是重新生成手写客户端、确认旧端点形态是否已弃用的好时机。
  • 新的可观测性与摄取路径 — 日志（#1110）加上 Analytics/Logs 仪表盘（#1116）终于为运维人员提供了此前缺失的可见性，CSV 上传（#1109）与升级的 unstructured（#1064）拓宽了支持格式。注意依赖变动：remark-gfm 因 react-markdown 不兼容先升到 4.0.0 后回退（#1071、#1085、#1086），Redux Toolkit 跳到 2.2.7（#1069），LangChain 到 0.2.10（#1133）——请验证自定义主题和构建仍能通过。
