DocsGPT 0.15.0

这个项目是干啥的：是一个给企业文档做智能问答的工具，让员工用自然语言直接问出文档里的答案，还能接外部工具和跑代码来处理复杂问题。

变更架构图

亮点

  • 远程 MCP server，现支持 OAuth — #1947 新增远程 MCP 支持，#1964 围绕 OAuth 和使用 SSE 等传输的 fastmcp 客户端重建。这是代理构建者的核心能力：工具不再局限于进程内函数，代理可以接入外部 MCP 生态。如果你尝试过早期 MCP 实现，请重新测试——其认证和传输层已被替换。
  • 模型注册表与多提供方能力元数据 — #2158 引入带声明式能力的中央模型注册表，配合 #2174 修复通过 API 在代理中选择模型的问题。重要性：提供方/模型选择转向声明式、基于能力的路由。升级前请确认自定义模型已注册正确的能力，否则可能无法被选择。
  • PostgreSQL 成为一等向量后端 — #1906 新增 PGVectorStore，让你把 embedding 留在 PostgreSQL 中，而无需单独运维 Qdrant 实例（其也在 #1905 中得到修复）。对已在运行 Postgres 的团队，这是具体的迁移收益。配合 #2173 的上下文压缩，可降低长对话的 token 开销。
  • 带 schema 校验的结构化输出 — #1924 新增带 JSON schema 校验的结构化输出，可把代理响应约束到契约而非自由文本。结合提示词变量与模板渲染工作（#2128、#2091），这让代理输出可以安全地被程序化消费——如果你基于 API 开发，值得采用。
  • API 与配置面变动——检查你的集成 — Answer 路由被重构（#1896），用户路由重组为领域驱动布局（#2005），并修复 webhook（#2175）。更重要的是，#2050 重命名 LLM_PROVIDER 设置（及运行时命名），同时新增 Windows PowerShell 部署路径：上线前请更新环境变量/配置键。这些是自托管者和 API 消费者最可能的故障点。
  • 代理工具成熟；前端工具链大跃进 — 预置代理模板与种子数据（#1910）、token/请求限流（#2041）、带 OAuth 修复的 Google Drive 摄取（#1937、#1976）、多选来源（#1930），以及基于 MongoDB 的 NotesTool/MemoryTool 与 tool_id 管理（#1982、#2026），让代理更具生产可用性。前端方面，依赖跃升到 Tailwind 4、Vite 7、ESLint 9 和 i18next 25，自定义 fork 需要配置/样式迁移——请为此预留工作，而不是当成常规升级。
