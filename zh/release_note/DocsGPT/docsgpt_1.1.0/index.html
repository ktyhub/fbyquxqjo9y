DocsGPT 1.1.0

小版本 发布时间2026年10月25日 来源arc53/DocsGPT 英文原文

DocsGPT 1.1.0

变更流程图

亮点

  • 更低成本的多轮推理 — Responses prompt 缓存现在可以跨对话轮次持久化，重放的推理过程也计入计量；/v1 的用量还会报告缓存的 prompt token，让 API 集成方能审计缓存带来的节省（#3033、#3064）。
  • Artifact 贯穿完整工作流 — Word artifact 更丰富，API 客户端可以下载生成的 artifact，附件也可以是纯引用（#3060）。暂停的轮次在恢复时会保留附件和执行状态（#3063），聊天中的 artifact 卡片和预览让输出更易检查（#3095）。
  • 增量采集与上下文控制 — 重新采集现在只对变更过的材料重新做 embedding，manage_source_files 同步是就地替换某个源的文件，而不是全部重建（#3170）。新增的 context-limit 功能可以对检索上下文做显式控制（#3175）；整源采集被路由到专门的 Celery 队列，以隔离长时间任务（#3124）。
  • 可选的模型驱动检索与安全层 — 模型打分的 reranking 和决策预筛现在可用，但默认关闭，开启会增加模型调用、延迟和成本，上线前应先做基准测试（#3097）。决策 harness、API 模式、注入检查、基于模型的 prompt 注入扫描和对话分析同样都是可选能力（#3092、#3117、#3121）。
  • 更多连接器，收紧的 Drive 权限 — 新增 MCP 预设覆盖 CoinGecko、Alpha Vantage、Neon、Context7 和 Airtable；定时和 webhook 触发的 Agent 运行也可以使用代码执行器（#3079、#3039、#3056、#3059、#2950、#3081）。Google Drive 现在申请 drive.file 权限，通过服务账号读取文件夹，并把 Drive、SharePoint、Confluence 的引用链接回原始文件 —— 已有的文件夹集成应核验服务账号配置和 OAuth scope（#3169、#3155）。
  • 客户端与流水线升级需留意 — 已发布的 widget 库升到了 0.13.0，新增翻译后的 UI、JavaScript API、对话历史、侧边栏布局和推荐问题；请更新嵌入脚本，并针对新版本测试自定义样式/配置（#3139、#3153）。检索分块现在支持 token 重叠，重新采集的源可能产生不同的分块边界（#2919）。直接使用 PyPDF2 的 Python 集成应迁移到 pypdf，因为 PyPDF2 已被移除（#3150）。

本版本没有明确指出破坏性变更。
