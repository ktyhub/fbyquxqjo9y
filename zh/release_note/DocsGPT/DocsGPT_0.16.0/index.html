DocsGPT 0.16.0

这个项目是干啥的：是一个给企业文档做智能问答的工具，让员工用自然语言直接问出文档里的答案，还能接外部工具和跑代码来处理复杂问题。

变更架构图

亮点

  • 可视化 Agent 工作流与 CEL 分支 — 头号能力是可视化 Agent 工作流构建器（#2264），配合可以求值 CEL 表达式的条件节点（#2280），让你根据上下文/变量做分支，而不用硬编码线性流程。Agent 可以归入文件夹（#2245），Agent 的 “Self” 工具（Notes/Todo）现在通过 artifact 持久化，并支持流式 artifact_id（#2267）。为什么重要：这把 DocsGPT 从单轮提示+检索推向编排平台；如果你建的是扁平 Agent，得重新考虑它们的结构。
  • 采集大改造：Docling、OCR、S3 与 SharePoint — 解析切换到 Docling（#2202），附件支持 OCR（#2246），并为无法原生读取文件的模型提供合成 PDF 路径（#2263）。新增连接器包括带同步的 Amazon S3（#2244）和 SharePoint（#2283），同时改进了爬虫并改变了分块过滤（#2250）。为什么重要：扫描件和不原生支持文件的模型现在无需预处理即可工作 —— 但分块过滤的变化可能影响检索质量，上线前要重新索引并重新评估。
  • 流式与 token 计量重塑响应 — 思考 token 和 artifact_id 现在会流式输出（#2275、#2276、#2267）；历史 token 从分块计数，旧的 UI token 上限设置被移除（#2196），并有进一步的 token 修复（#2285）以及 Agent 侧的上下文校验/消息截断（#2249）。消息格式被改造（#2349），流式回退也做了加固（#2332）。为什么重要：直接使用流式 API 的消费者要预期事件/字段形态的变化，以及不再有客户端 token 上限 —— 请更新解析器，改为依赖服务端截断。
  • React widget：迁移到 styled-components v6 — widget 使用者必须处理 styled-components v6 下 shouldForwardProp 不再默认提供的问题（#2312）；依赖升到 6.3.12（#2323），npm 包升到 v0.6.3（#2333），发布也改为通过 Actions 自动化（#2328）。升级后要留意自定义 prop 泄漏到 DOM 元素上 —— 这是最可能出现的”以前能用”回归。
  • 构建需要 Node.js 22 — CI 和本地构建都必须升级到 Node.js 22 以兼容 Vite（#2169）。拉取 0.16.0 之前，把它当作工具链的最低版本要求；旧的 Node 镜像会导致前端构建失败。
  • 安全修复与更广的工具/provider 面 — 修复了 PromptsModal 中的存储型 XSS 向量（dangerouslySetInnerHTML）（#2279），如果提示词内容会被共享，这就是一个实打实的升级理由。扩展性方面的收获包括带 content-type 处理的 API 工具请求体序列化（#2192）、MCP 工具的动态配置渲染（#2286）、改进的工具日志/错误处理（含 DuckDuckGo）（#2282），以及新集成：Novita AI（#2320）、语音转文字（#2306）和 Research Agent（#2327）。
