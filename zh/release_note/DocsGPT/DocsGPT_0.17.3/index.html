DocsGPT 0.17.3

修订 发布时间2026年6月13日 来源arc53/DocsGPT 英文原文

DocsGPT 0.17.3

这个项目是干啥的：是一个给企业文档做智能问答的工具，让员工用自然语言直接问出文档里的答案，还能接外部工具和跑代码来处理复杂问题。

变更架构图

亮点

  • 新模型提供方与按模型 API 风格 — 0.17.3 新增 DeepSeek（#2497、#2499）并迁移 Google 提供方（#2496），但影响更大的是按模型的 api_flavor 开关（#2521），可让单个模型选用 OpenAI Responses API 而非经典 Chat Completions。配合 #2520 的推理内容透传（思考 token 现在到达客户端）和 #2522 对非 OpenAI 端点本地工具调用的修复。请留意那些现在需要显式配置 flavor 而非自动探测的提供方。
  • v1 API 上的结构化输出 — #2523 将 response_format / response_schema 带到 /v1/chat/completions，你可以直接请求 JSON Schema 约束的响应，而不用在提示词里 hack。结合 #2507 在 token 用量数据中加入模型 ID（按模型成本归属），这是重新审视客户端如何解析和计费模型输出的版本。
  • 工具调用与基于 Redis 的远程设备代理 — 远程设备连接现在作为工具暴露（#2506），#2511 通过将协调转移到基于 Redis 的代理，修复定时任务超时。运维上很重要：定时/代理运行现在依赖 Redis 可达，请将其纳入部署容量规划。#2517（更好的重试）、#2518（备用响应解析）和 #2529（兼容模式下更好的追问）等可靠性修复，让工具循环在抖动或非 OpenAI 端点上更有韧性。
  • 认证与会话可见性 — OIDC 登录在 #2530 落地，同时新增会话可见性（#2528）和可见性设置（#2531），为会话引入访问控制。自托管者应在升级前审查认证配置及既有会话的默认可见性——如果你此前依赖单一共享工作区，谁能看到什么可能会变化。
  • 提示词与代理系统改造 — #2533 重做默认提示词预设、提示词模板系统和工具命名，#2536 改进提示词下拉框。这是最可能坑到老用户的改动：任何按名称寻址工具或依赖旧模板变量/默认预设的代码都需要审查。#2534 的分析改造（按代理归属、统一日志时间线）和 #2527 的线程改进提供了更好的可观测性来验证新行为。
  • UI 与持久状态清理 — 前端组件清理（#2495）、Lucide 图标统一并对齐侧边栏（#2513）、移动端抽屉（#2502），以及 #2526：当持久状态进入终态后撤销陈旧的 UI 面——最后一项对基于持久执行流程开发的人很重要，它防止运行结束后僵尸 UI 残留。
