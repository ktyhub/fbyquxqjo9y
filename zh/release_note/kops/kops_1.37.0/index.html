kops v1.37.0

小版本 发布时间2026年11月10日 来源kubernetes/kops 英文原文

kops v1.37.0

这个项目是干啥的：Kubernetes 官方出的集群管理工具，用一条命令就能在云上建好、升级、扩容 K8s 集群，给需要自己搭和管 Kubernetes 集群的运维和工程师用。

请参阅完整的 kOps 1.37 release notes 了解详细信息，包括重大更改和弃用。

变更架构图

亮点

  • Kubernetes 1.37 支持，etcd 3.7.3 作为 Kubernetes 1.37 集群的默认设置
  • 云对象存储中的私有资产存储库：KOPS_BASE_URL 和 spec.assets.fileRepository 的 s3://、gs:// 和 azureblob:// URL，节点通过其实例身份进行身份验证
  • 更小、更具弹性的节点引导程序：通过更小的二进制文件和 xz 压缩，nodeup 下载从大约 120 MB 下降到 10 MB 以下，并且引导程序会重试失败的任务
  • 容器运行时：默认为containerd 2.3.6和runc 1.5.1，containerd配置版本为4；不再支持早于 2.1.0 的 containerd 版本
  • Karpenter 扩展：Karpenter v1.15.1、kOps 管理的中断处理（SQS 队列和 EventBridge 规则）、EC2NodeClass 中的根卷设置、instanceRequirements 支持以及混合 GPU 和非 GPU 实例组
  • **实例角色（Route 53、KMS、EC2、SQS）的 AWS IAM 权限更窄，并且不需要权限的角色没有内联策略
  • etcd-manager 更改：捆绑的 etcd 映像作为映像卷安装，并支持新集群上用户提供的映像的自定义 etcd 版本
  • 网络：Calico v3.32.3 迁移到 ClusterNetworkPolicy、AWS VPC CNI 的网络策略支持、具有实验性 nftables 网络策略后端的 kube-router v2.12.0 以及 kindnet v1.0.3
  • Azure：使用签名实例元数据进行身份验证的引导请求、过时虚拟机的 kops rolling-update cluster 检测以及高可用性控制平面上的两个云控制器管理器副本
  • Akamai (Linode)：实验性提供商现在管理 SSH 密钥、网络、子网、实例和块存储卷
  • 组件更新：etcd-manager v3.0.20261022 与 etcd 3.5.35/3.6.16/3.7.3、Cilium v1.18.16、AWS VPC CNI v1.23.2、CoreDNS v1.15.0、AWS 负载均衡器控制器 v3.6.2、证书管理器 v1.21.3、集群自动缩放器 v1.37.0
  • 删除：支持 Kubernetes 1.31、gossip DNS（和 protokube）、适用于 API 的 AWS Classic 负载均衡器和 Kopeio 网络。升级前使用 kOps 1.36 进行迁移
