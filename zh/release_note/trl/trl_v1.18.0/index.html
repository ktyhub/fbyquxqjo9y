旧路径仍然有效并发出 `FutureWarning`（在 v2.0.0 中删除）。转出循环扩展点位于训练器 `from trl.trainer.async_grpo_trainer import AsyncRolloutLoop, Rollout` 旁边，并且不从 `trl` 导出。 OpenEnv / Harbor 线束仍处于实验阶段，如 `trl.experimental.async_grpo.openenv_harness` 中的 `HarnessAsyncGRPOTrainer`。记录的指标名称在不同版本之间仍然可能发生变化。
快速入门，从 [文档](https://huggingface.co/docs/trl/async_grpo_trainer)。使用 `pip install trl[vllm,kernels,math_verify]` 安装，然后在 GPU 0 上启动 vLLM 服务器：
```bash
CUDA_VISIBLE_DEVICES=0 VLLM_SERVER_DEV_MODE=1 vllm serve Qwen/Qwen3.5-2B \
    --weight-transfer-config '{"backend": "nccl"}' \
    --logprobs-mode processed_logprobs \
    --api-server-count 8 \
    --max-model-len 4096

然后使用 CUDA_VISIBLE_DEVICES=1 python train_async_grpo.py 在 GPU 1 上进行训练：

# train_async_grpo.py
from datasets import load_dataset
from trl import AsyncGRPOTrainer
from trl.rewards import accuracy_reward

if __name__ == "__main__":  # the rollout worker is a spawned process that re-imports this script
    dataset = load_dataset("trl-lib/DeepMath-103K", split="train")

    trainer = AsyncGRPOTrainer(
        model="Qwen/Qwen3.5-2B",
        reward_funcs=accuracy_reward,
        train_dataset=dataset,
    )
    trainer.train()

这个例子是端到端运行的。这是健全性检查，而不是加速比较：
模型/数据/奖励 Qwen/Qwen3.5-2B、trl-lib/DeepMath-103K、accuracy_reward
硬件 2x B200：一个 GPU 上的 vLLM，另一个 GPU 上的训练器

培训师涵盖的内容均记录在培训师页面 上：
  • 树包装：每个微批次行都是一个前缀特里树，因此组的卷展共享的提示或多轮卷展的每一轮重复的历史记录都会转发一次。支持门控 DeltaNet 混合网络（Qwen3.5、Qwen3.6、Qwen3-Next）。
  • 代理培训：tools、environment_factory 和多轮部署。
  • 以屏蔽重要性采样为中心的得分作为默认目标 (score_centering=True)。 score_centering=False 为 GRPO 的 clipped 物镜提供了相同的遮蔽比。
  • 零优势群体过滤：奖励全部相等的群体在向前和向后花费之前被丢弃，并且他们的份额被记录为frac_zero_std_groups。
  • Top-k / top-p 重新归一化：使用 top_p 或 min_p，设置 top_k > 0，并且训练器在从中采样的候选集 vLLM 上归一化其对数概率。
  • LoRA 适配器同步：使用 --enable-lora 启动 vLLM，每个权重同步仅发送适配器（r=32 时约为 160 MB）而不是合并的权重。
  • 自定义推出循环：子类 AsyncRolloutLoop，覆盖 filter_prompt、generate_one、generate_one_turn、compute_advantages、setup 或 close，并将其设置为训练器子类上的 loop_cls。训练器的构造函数不会改变。
  • 带有阅读指南的指标：每个记录的指标都有一行定义，以及关于运行是受生成限制还是受训练者限制以及是否是饱和或采样重复的指南。
  • VLM 检查点的纯文本训练（Qwen3.5、Qwen3.6、Qwen3-VL），视觉塔冻结。 ：繁荣：这对您来说有什么变化。 如果您在 v1.17 中使用实验性 AsyncGRPOTrainer，则重大更改都在促销之前发生，因此不必在促销之后发生。 AsyncDistillationTrainer（仍处于实验阶段）在相同的 PR 中获得了相同的构造函数删除、配置重命名、超时合并、批处理和陈旧性更改以及度量约定。 构造函数参数：

修复

其中一些改变了跑步训练的内容。第一个需要对您已保存的模型执行操作。 由 SFTTrainer v1.7.0 保存到 v1.17.1 的 MoE 模型在每次转发时计算路由器 logits，包括推理。 SFT 将 output_router_logits=True 和 router_aux_loss_coef 写入模型配置中并保存它们，因此微调后的 MoE 模型不断返回其路由器 logits，并且覆盖的 coef 会转移到下一次微调。与 GRPO、RLOO、DPO 和 KTO 一样，SFT 现在不考虑配置。不过，它保留了模型加载的配置，因此即使在另一次微调之后，这些版本之一保存的模型也会保留该标志。要重置它，请将其设置回 False 并再次保存：

model = AutoModelForCausalLM.from_pretrained("path/to/model")
model.config.output_router_logits = False  # model.config.text_config.output_router_logits for a VLM
model.save_pretrained("path/to/model")
