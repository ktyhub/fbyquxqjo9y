trl v1.9.0

小版本 发布时间2026年7月21日 来源huggingface/trl 英文原文

trl v1.9.0

特点

GRPO 和 RLOO 中的可迭代/流数据集

长久以来的诉求终于落地。 GRPO 和 RLOO 依赖 RepeatSampler 重复每个提示 num_generations 次，并将它们跨进程分组 - 但采样器无法附加到可迭代数据集（没有长度，没有索引），并且旧的行为默默地绕过了采样器，悄悄地破坏了优势计算。 新的 repeat_iterable_dataset 生成器通过转换流本身而不是重新排序索引来重现 RepeatSampler 的精确排序。训练器通过 IterableDataset.from_generator 包装可迭代数据集，强制 dispatch_batches=False，并对每个进程的流进行分片，以在跨进程收集后保留提示组。

from datasets import load_dataset
from trl import GRPOConfig, GRPOTrainer

dataset = load_dataset("trl-lib/DeepMath-103K", split="train", streaming=True)

trainer = GRPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GRPOConfig(max_steps=1000),  # required for iterable datasets
    train_dataset=dataset,
    reward_funcs=accuracy_reward,
)

可迭代数据集需要 max_steps（无长度）。如果 dispatch_batches=True 与可迭代数据集组合，也会引发明显的错误。 作者：@albertvillanova，https://github.com/huggingface/trl/pull/6351

环境拥有的数据集

当提供 environment_factory 时，环境现在可以拥有数据。 train_dataset 变为可选：reset() 返回提示。不再仅仅为了驱动循环而制作虚拟数据集。

class WordleEnv:
    def reset(self, **kwargs) -> str:      # returns the prompt
        self._target = sample(words)
        return f"Guess a {len(self._target)}-letter word."
    def get_reward(self) -> float:
        return 1.0 if self._solved else 0.0
    def guess(self, word: str) -> str:     # exposed tool
        self._solved = word == self._target
        return _feedback(word, self._target)

trainer = GRPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GRPOConfig(max_steps=1000),
    environment_factory=WordleEnv,          # no train_dataset needed
)

适用于 GRPOTrainer 和 AsyncGRPOTrainer。提供的 train_dataset 仍然可以像以前一样工作；多环境路由数据集现在可以是仅 environment（不需要 prompt 列）。 作者：@qgallouedec，https://github.com/huggingface/trl/pull/6349

AsyncGRPO 中的消息级部署

一种从多轮对话中构建训练行的选择方式。消息模式将对话保持为消息，并每轮重新标记整个事物，然后检查新的标记是否仍以迄今为止持有的标记开始。如果是→追加新部分（与令牌模式相同）。如果没有 → 发生重写 → 关闭该行并打开与模型实际读取的内容相匹配的新行。

AsyncGRPOConfig(
    rollout_protocol="message",   # "token" (default) | "message"
    fork_threshold_tokens=1024,   # message-mode only
)

每转漂移被分类为CLEAN（追加）、REALIGN（最后答案尾部摆动→覆盖同一行）或FORK（真正重写→新行）。每次对话都有一个优点，并印在它产生的每一行上；在代币平均损失下，分叉是不可见的。为未来的树轨迹支持设置管道——评分已经与分支无关（按 rollout_id 分组）。 作者：@AmineDiro，https://github.com/huggingface/trl/pull/6250

AsyncGRPO：VLLMClient 和解耦重量同步

v1.8 推出工人分裂的后续行动。小型 VLLMClient 成为与 vLLM 服务器进行 HTTP 通信的单一位置（wait_for_server_ready、get_max_model_len、pause/resume 的命名方法、权重更新端点 — 无状态，因此可挑选）。 Generation 故意在 rollout 子项中保留其自己的异步 aiohttp 会话。 权重同步现在是根据独立于 rollout_worker 的配置构建的（之前是自定义部署工作人员将其强制设置为 None），并且可以通过新的 WeightTransferProtocol 注入。 token_budget 现在会在默认为 get_max_model_len() 之前等待 /health，因此启动缓慢的 vLLM 会等待而不是使运行失败。 作者：@AmineDiro，https://github.com/huggingface/trl/pull/6269

DistillationTrainer 重构

~13-PR 扫描重塑了实验性 DistillationTrainer 以实现未来的稳定性：

  • 提取 ServerDistillationTrainer 作为教师服务器路径 (#6454)
  • 将 IW-OPD 移至专用实验训练器 (#6453)
  • 从基础训练器中删除局部稀疏 top-1 损失路径 (#6455)
  • 从基础广义 JSD 损失中删除 top-k 支持 (#6456)
  • 通过词汇大小验证教师而不是标记器身份（#6457）
  • 弃用并删除 lmbda on/off-policy 混合和off-policy 训练分支（#6458、#6460）； GKD 纸质复制现在指向 GKDTrainer (#6459)
  • 接受 prompt 列和 messages (#6461)； 弃用消息格式数据集 (#6474)
  • ⚠️ 修复 num_items_in_batch 以计算生成的完成标记 - 损失分母对于策略训练是错误的（计算数据集完成，而不是生成的）并且 仅提示数据集为 NaN。这会改变旧路径上任何人的损失值 (#6478)
  • 端到端目标和开/关政策行为的准备引脚（#6450、#6451、#6452） 全部由@qgallouedec 提供。

新 IW-OPD 蒸馏物镜

重要性加权的策略蒸馏作为实验性 DistillationTrainer 上的一个可选目标 — 从采样令牌教师和 rollout logprobs 构建的分离的 IW-OPD 优势（在 use_vllm=True 时使用缓存的 vLLM rollout logprobs）。

DistillationConfig(
    distillation_objective="iw_opd",
    iw_opd_gamma=1.0,
    iw_opd_epsilon=0.2,
    lmbda=1.0, reverse_kl_top_1_mode="sampled",  # required
)

现在，作为上述重构的一部分，分成了自己的实验训练器。 通过 @kashif 在 https://github.com/huggingface/trl/pull/6191

log_multimodal 适用于 GRPO / RLOO

新的配置切换可控制多模式完成的图像是否记录到跟踪器。也适用于实验性 DPPO 和 GRPO-with-replay-buffer。 作者：https://github.com/huggingface/trl/pull/5408 中的 @apardyl 和 https://github.com/huggingface/trl/pull/6352 中的@albertvillanova
