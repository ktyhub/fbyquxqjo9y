trl v1.8.0

trl v1.8.0

特点

🎓 KTO 现已成为一名稳定的训练师

经过多次 KTOTrainer ↔ DPOTrainer 对准工作循环后，KTO 从 trl.experimental.kto 升级到顶级 trl 封装。与 DPO/GRPO/SFT 相同的 API — 导入从实验性转移，测试移至主测试树，文档不再将其标记为实验性。实验路径仍然有效并发出 FutureWarning（在 v2.0.0 中删除）。

# Before
from trl.experimental.kto import KTOConfig, KTOTrainer

# Now
from trl import KTOConfig, KTOTrainer

根据我们的遥测，KTO 是 TRL 中第四大最常用的培训师——这次毕业已经过期了。 作者：@albertvillanova 在 https://github.com/huggingface/trl/pull/6175, https://github.com/huggingface/trl/pull/6287 和 https://github.com/huggingface/trl/pull/6345

环境拥有的奖励和多环境支持

三个相互关联的变化使环境中的代理强化学习训练更加符合人体工程学。 环境拥有的奖励。 如果您的 environment_factory 环境定义了保留的 get_reward() 方法（无参数 → float），则每次完成的部署都会调用一次并被视为奖励源。 reward_funcs 成为可选的 - 不再将环境状态泄漏回训练者拥有的奖励函数。

class WordleEnv:
    def reset(self, **kwargs):
        self._target = sample(words); self._solved = False

    def get_reward(self) -> float:       # optional, reserved (not a tool)
        return 1.0 if self._solved else 0.0

    def guess(self, word: str) -> str:   # exposed as a tool
        self._solved = word == self._target; ...

trainer = GRPOTrainer(
    model=model,
    train_dataset=dataset,
    environment_factory=WordleEnv,       # no reward_funcs needed
)

多环境支持。 除了单个可调用之外，environment_factory 现在还接受 dict[str, factory]。每个数据集行通过 environment 列选择其环境，并且只有该环境的工具会在该行的提示中公开 - 因此编码任务和游戏可以在一次运行中一起训练，而不会泄漏彼此的工具模式。单一可调用用法不变。 GRPO、AsyncGRPO、DPPO 和 GRPO-with-replay-buffer 中的接线相同。 @qgallouedec 在 https://github.com/huggingface/trl/pull/6238; 多环境中 https://github.com/huggingface/trl/pull/6001 和 https://github.com/huggingface/trl/pull/6002 中的环境拥有的奖励

GRPO 的熵正则化

GRPOConfig 现在支持静态和自适应熵正则化 (Skywork-OR1)。奖金鼓励探索并有助于防止政策过早崩溃。

GRPOConfig(
    entropy_coef=0.01,          # static
    # or:
    use_adaptive_entropy=True,  # adjust to target entropy
    entropy_target=1.5,
    entropy_coef_delta=0.01,
    entropy_coef_min=0.0,
    entropy_coef_max=0.1,
)

自适应模式根据窗口聚合熵（梯度累积感知）在每个优化器步骤中调整系数一次，并将 entropy_coef 保留在检查点中以进行恢复。与 Liger 内核不兼容。 作者：@albertvillanova，https://github.com/huggingface/trl/pull/6140

quantization_config 训练器参数（简化的 QLoRA）

QLoRA 不再需要手动访问 model_init_kwargs 或预加载模型。

SFTTrainer(
    model="meta-llama/Llama-2-7b-hf",
    quantization_config=BitsAndBytesConfig(load_in_4bit=True),
    peft_config=LoraConfig(),
    train_dataset=dataset,
)

添加到 SFTTrainer、DPOTrainer、GRPOTrainer、RLOOTrainer、RewardTrainer 和 KTOTrainer。位于 peft_config（另一个不可序列化的 QLoRA 成分）旁边，流入 from_pretrained，如果也在 args.model_init_kwargs 中设置，则引发。还删除了冗余的 get_kbit_device_map() 线路 — QLoRA 在所有测试配置中都可以在没有它的情况下进行相同的训练。 作者：@qgallouedec，https://github.com/huggingface/trl/pull/6157 和 https://github.com/huggingface/trl/pull/6276

教育部辅助损失扩大至 DPO 和 KTO

v1.7在GRPOTrainer/RLOOTrainer/AsyncGRPOTrainer基础上增加了路由器负载均衡辅助损耗。它现在也适用于 DPOTrainer 和 KTOTrainer，因此带有偏好数据的训练后 MoE 模型可以让专家保持平衡。 作者：@qgallouedec，https://github.com/huggingface/trl/pull/6208 和 https://github.com/huggingface/trl/pull/6275

通过静态形状令牌包装实现神经元友好的 chunked_nll

分块 NLL 路径具有数据相关索引，破坏了 XLA/Neuron 编译。此 PR 对其进行了改造，通过有效性掩码上的稳定 argsort 将有效令牌打包到前面，迭代 ceil(n_valid / chunk_size) * chunk_size 整个块（张量，无 Python-int 同步），并在每个块内使用 ignore_index=-100。 GPU 行为不变； Neuron 现在也可以工作了——同样微小的内存占用（~1.33 GiB 与简单的 5.94 GiB 替代方案），无需每个掩码重新编译。 作者：@michaelbenayoun，https://github.com/huggingface/trl/pull/6314

AsyncGRPO 中的打包感知动态批处理

AsyncGRPO 微批处理在 v1.7 的无填充路径之上变得具有打包意识和令牌限制：

  • Σ Lᵢ² 行平衡 — 贪婪的最长优先分配为每个 DP 行提供相同的 Σ Lᵢ² 而不是相同的令牌计数（注意力为 O(L²)，FFN 为 O(L)，因此相等的令牌计数不会使挂钟相等）。 跨等级掉队者消失；基准测试中 4B 时 +19% MFU。
  • 令牌预算打包（选择加入）——使用可变样本计数将 token_budget 令牌的每一行限制在 per_device_train_batch_size 中，从而将峰值内存与 per_device_train_batch_size 解耦。在内存限制的情况下很有用（无梯度检查点、长上下文、非常大的模型）。 两者都利用 HF Trainer 现有的梯度积累——无需训练循环手术，FSDP/EP 集体保持同步。 作者：@AmineDiro，https://github.com/huggingface/trl/pull/6092

GOLDTrainer 中的 VLM 支持

GOLDTrainer 现在支持端到端的视觉语言模型。 作者：@Strongich，https://github.com/huggingface/trl/pull/5969
