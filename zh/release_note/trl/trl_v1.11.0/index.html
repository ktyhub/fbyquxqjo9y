trl v1.11.0

小版本 发布时间2026年8月26日 来源huggingface/trl 英文原文

trl v1.11.0

特点

使用 vLLM 自己的服务器而不是 TRL 的服务器

trl vllm-serve 用于围绕 vLLM 的 LLM 运行自定义 FastAPI 应用程序，具有自己的数据并行扇出和用于权重同步的工作扩展。 vLLM 自己的服务器涵盖了所有这些。自定义服务器消失了：trl/scripts/vllm_serve.py 从 1218 行下降到 ~130 行，现在将其标志转换为 vllm serve，打印等效命令，转发任何额外参数，并设置 TRL 需要的三个设置（--weight-transfer-config、--logprobs-mode processed_logprobs、--max-logprobs -1）。 fastapi、uvicorn 和 pydantic 额外保留了 vllm。 权重同步现在使用 vLLM 的 NCCL 权重传输引擎 - 张量被宣布一次并在单个打包广播中进行流式传输，而不是每个张量一个 HTTP 请求 + 广播。蒸馏老师logprobs来自prompt_logprobs。 基准（H100 上的 GRPO 服务器模式、Qwen2.5-1.5B / Qwen2.5-VL-3B、相同种子、相同数据）：

设置 之前 之后 加速
文本，TP=1 1.08、0.91/步 0.63、0.62 每步 1.59×
文本，TP=2 0.96、0.96/步 0.62、0.60 每步 1.57×
VLM，TP=1 2.14、2.13/步 1.48、1.48 每步 1.44×
与旧服务器相比，完成位相同（16/16 超过 4 个提示 × n=4，logprobs 与 0.0 超过 499 个令牌相同）。 trl vllm-serve 仍然接受相同的标志 - 它现在只是转发到 vllm serve。
作者：@qgallouedec，https://github.com/huggingface/trl/pull/6765
###新实验AsyncDistillationTrainer（+多师MOPD）
异步策略蒸馏，其架构类似于 AsyncGRPOTrainer：后台部署工作人员生成学生自己的完成结果，并根据通过 HTTP 提供服务的教师对其进行评分，因此生成和训练是重叠的，而不是交替的。教师永远不会在本地加载 - 只是一个 vLLM 服务器 URL。
还支持 MOPD（多教师策略蒸馏）：在 teacher_server_urls 中传递多个条目，并通过 teacher_id 列将每个样本路由给教师（例如，数学老师和代码老师，每个老师独立服务）。 
from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

示例重新组织到每个示例文件夹中

examples/ 按格式拆分（scripts/ 与 notebooks/），这些格式分散了相关文件（例如，sft_nemotron_3 既作为脚本*又作为笔记本存在，位于不同的文件夹中；OpenEnv 笔记本与 OpenEnv 脚本分开）。现在，所有内容都是每个故事一个文件夹 - 名称表示方法和任务（grpo_wordle、sft_gpt_oss、ppo_tldr），并且该文件夹包含示例所需的每个文件（脚本、笔记本、提示、聊天模板、评估代码）。删除了精简的单训练器演示脚本（它们位于 trl/scripts/ 中，每个训练器文档页面都有一个可运行的片段）。旧的 examples/scripts/… 和 examples/notebooks/… GitHub / Colab 链接将为 404 — 值得在下游帖子中标记。 作者：@qgallouedec，https://github.com/huggingface/trl/pull/6820
