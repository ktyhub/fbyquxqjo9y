trl v1.17.0

## 特点 ### 🔥 Mistral Large 4：在一个节点上微调 1T 参数模型 TRL 现在支持 [`mistralai/Mistral-Large-4-1T-A52B`](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B)：1T 参数，52B 有效。新的 [LoRA 示例](https://github.com/huggingface/trl/tree/main/examples/sft_mistral_large_4) 在单个 8×B300 节点上，在其 FP8 权重之上，使用 `SFTTrainer` 对其进行微调：专家通过令牌调度分为 8 种方式，其他所有内容在加载时通​​过 Transformer 的 `DistributedConfig` 在 8 个 GPU 上进行分片，LoRA 训练注意力以及密集且共享的专家 MLP。 测量结果：**约 8 秒内每步 32.7k 个令牌，每个 GPU 142 GiB**，推理对话中仅存在打包和助手损失。 <表对齐=“中心”> https://github.com/user-attachments/assets/5aa86ec7-6444-4bed-bfdc-0445e99bea0d ```python training_args = SFTConfig( model_init_kwargs={ "dtype": "auto", # keep the FP8 weights "distributed_config": DistributedConfig(fsdp_size=8, ep_size=8), }, packing=True, assistant_only_loss=True, ... ) trainer = SFTTrainer(model="mistralai/Mistral-Large-4-1T-A52B", args=training_args, peft_config=LoraConfig(...), ...) ``` `assistant_only_loss=True` 开箱即用：TRL 提供了一个与已发布的检查点相匹配的训练聊天模板，包括其 `reasoning_effort` 级别（`low`、`medium`、`high`）。需要 `transformers>=5.22.0`、`peft>=0.21.0` 和 `accelerate>=1.15.0`。 * 在 https://github.com/huggingface/trl/pull/8017 中添加 @qgallouedec 的 Mistral Large 4 * 将 Mistral Large 4 聊天模板与 @albertvillanova 在 https://github.com/huggingface/trl/pull/8018 中发布的检查点同步 ### 🎯 top-k、top-p 和 min-p 下的无偏重要性采样 vLLM 对 `top_k`、`top_p` 和 `min_p` 过滤后留下的标记标准化其对数概率，而训练器对整个词汇表进行标准化。每个采样令牌的对数比与过滤器保留的概率质量的对数有关，因此 vLLM 重要性采样比偏向 0（大约 1e-4，而不是 `top_p=0.9` 的 1）。训练器现在按照 [DeepSeek-V3.2](https://huggingface.co/papers/2512.02556) 中的保持采样掩码对每个标记采样的候选集进行标准化。 * AsyncGRPO：重新规范化https://github.com/huggingface/trl/pull/7627中@AmineDiro设置的top-k/top-p候选集上的log-probs * GRPO：重新规范化 top-k/top-p 候选集上的日志概率（vLLM 共置模式，vLLM >= 0.28；服务器模式将遵循），@albertvillanova 在 https://github.com/huggingface/trl/pull/7866 中 * 在 AsyncGRPO 中需要 `top_k` 和 `min_p`，以便 @albertvillanova 在 https://github.com/huggingface/trl/pull/7937 中保持重要性采样率无偏差 * 跟踪分块 log-prob 内核中的支持最大值，因此远低于最大值的候选集不再给出 0 的对数概率和非有限梯度，作者：https://github.com/huggingface/trl/pull/7983 中的 @kashif **💥 这会给您带来什么变化。** vLLM 将其返回的候选集限制为 `top_k`，因此，在 vLLM 和重要性采样校正（默认）打开的情况下，当 `top_p < 1.0` 或 `min_p > 0.0` 设置为没有 `top_k > 0` 时，`GRPOConfig` 现在会引发。设置 `top_k`（例如 `top_k=512`）或 `vllm_importance_sampling_correction=False`。 ### ⚖️ 分数居中是默认的 AsyncGRPO 目标 AsyncGRPO 的旧日志概率是 vLLM 采样器的，因此其比率将过时性与服务器和训练器之间的数值不匹配混合在一起。使用 FP8 采样器和 bf16 训练器，clipped 目标崩溃：奖励从 0.60 变为 0.34（FP8 权重）或 0.10（FP8 权重 + KV 缓存），步骤 300，而使用 bf16 采样器的 0.71 则相反。 [分数居中](https://huggingface.co/papers/2609.20807) 现在默认采用屏蔽重要性采样（`score_centering=True`、`importance_sampling_min=0.5`、`importance_sampling_max=5.0`）。有了它，FP8 采样器的训练与 bf16 采样器 (0.72) 完全相同。它的成本占发电量的 15-20%。 **💥 这会给您带来什么变化。** AsyncGRPO 现在默认以不同的目标运行训练，并且与采样器的比率超出 `[0.5, 5.0]` 的令牌将被丢弃。设置 `score_centering=False` 以保持 clipped 物镜。 作者：@AmineDiro，https://github.com/huggingface/trl/pull/7760 ### 🚀 更快的 AsyncGRPO 推出和打包 * **来自 vLLM 负载的自适应飞行上限**：部署工作线程遵循服务器的 KV 缓存使用情况，而不是接受固定的 `max_inflight_tasks`，因此请求停止在服务器上排队并被抢占。没有新的配置：所有内容都是从服务器读取的。作者：@AmineDiro，https://github.com/huggingface/trl/pull/7610 * **过滤零优势群体**（DAPO 的动态采样）：所有推出都获得相同奖励的群体，或者没有一个可以得分的群体，不再花费向前和向后的成本。作者：@AmineDiro，https://github.com/huggingface/trl/pull/7609 * **将采样掩码打包并垫在设备上**：`TreeRow.pack` 在 15 步运行中，在 0 级上从 250 秒到 31 秒，在 28k 令牌多轮行上从 1040 毫秒到 66 毫秒。作者：@AmineDiro，https://github.com/huggingface/trl/pull/7798 * 当 https://github.com/huggingface/trl/pull/7793 中的 @clementtisseau 的另一行有空闲空间时，继续填充微批次 * 在 https://github.com/huggingface/trl/pull/7792 中的@lewtun 在异步 GRPO 和异步蒸馏中使用 Blackwell GPU 上的 FlashAttention-4 ### 🌳 线性注意力混合体的树注意力 树打包 (v1.16) 现在支持门控 DeltaNet 混合：Qwen3.5、Qwen3.6、Qwen3-Next 和 OLMo-Hybrid。由于v1.16，培训师在初始化时拒绝了它们；在此之前，序列打包接受了它们，但默默地错误地对待它们。现在，通过 FLA 的分块内核，因果卷积和 delta 规则递归遵循树而不是行。 作者：@AmineDiro，https://github.com/huggingface/trl/pull/7686 ### 🎚️ 精确的分块对数概率 分块对数概率和 KL/JSD 头从 [Softmax 和交叉熵的修复](https://huggingface.co/papers/2610.31642) 中获得了两个精度修复：置信目标保持较小的梯度，匹配教师产生零梯度。 [熵保持强化学习](https://huggingface.co/papers/2603.11682)（附录B.4）报告了相同的高置信度策略梯度问题。 * 通过 @kashif 在 https://github.com/huggingface/trl/pull/7882 中修复分块损失精度 * 在https://github.com/huggingface/trl/pull/7890中通过@winglian修复跨步输入上的融合对数概率/熵（从SFT/DPO转移视图） ### 🔀 GOLD 中的 X-Token 交叉分词器蒸馏 `GOLDTrainer` 基于 [X-Token](https://huggingface.co/papers/2605.21699) 进行脱策略交叉分词器蒸馏：使用预先计算的投影矩阵设置 `lmbda=0.0` 和 `xtoken_loss_type="p_kl"` 或 `"h_kl"`。 * 通过 @kashif 在 https://github.com/huggingface/trl/pull/6126 中将 X-Token 交叉分词器 KD 添加到 GOLD 训练器 * 支持 https://github.com/huggingface/trl/pull/8010 中 @kashif 的 GOLD 字节偏移对齐中的字节回退分词器 (Gemma) ### 🟥 AMD GPU 上的训练 TRL 的训练器现在通过 PyTorch 的 ROCm 构建在 AMD Instinct GPU
