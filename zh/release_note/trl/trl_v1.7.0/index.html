trl v1.7.0

小版本 发布时间2026年6月25日 来源huggingface/trl 英文原文

trl v1.7.0

特点

SFT 默认 loss_type 现在是 "chunked_nll"

v1.6中宣布的翻盖已经落地。设置 loss_type 是可选的，默认值现在解析为 "chunked_nll" — 使每个 SFTTrainer 的运行峰值 VRAM 平均减少约 30%（在大词汇量型号上高达约 50%）**，挂钟时间为中性或稍快。无需采取任何行动。 当 use_liger_kernel=True 时，自动解析会回退到 "nll"（两条路径不兼容）。如果你想要旧的行为 - 例如对于自定义头 - 明确固定它：

SFTConfig(loss_type="nll")

作者：@qgallouedec，https://github.com/huggingface/trl/pull/5846

MoE GRPO / RLOO / AsyncGRPO 中的辅助损失

训练后 MoE 模型现在正确包含路由器负载平衡辅助损耗，与模型自身的参考转发和 SFTTrainer 相匹配。通过 model_init_kwargs 启用：

GRPOConfig(
    ...,
    model_init_kwargs={"output_router_logits": True, "router_aux_loss_coef": 0.001},
)

通过 _get_per_token_logps_and_entropies 进行检测（现在返回一个 3 元组，包括 aux_loss），将每个训练器匹配的梯度累积缩放折叠到保单损失中，并记录为 aux_loss。 AsyncGRPO 通过分块 LM 头路径中的 load_balancing_loss_func 重新计算它（与 SFT 的分块路径相同）。 由 @AmineDiro 在 https://github.com/huggingface/trl/pull/6083, 加上 router_aux_loss_coef 配置接线 由 @qgallouedec 在 https://github.com/huggingface/trl/pull/6085

新实验性 GMPO 培训师

几何平均策略优化 登陆实验训练器。将 GRPO 的每个标记的重要性比率算术平均值替换为 序列级几何平均值（clipped 对数比率的平均值，然后是 exp）； clipping是一种单边优势标志，应用于对数空间。每张纸默认 epsilon=0.4。

from trl.experimental.gmpo import GMPOConfig, GMPOTrainer

trainer = GMPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GMPOConfig(epsilon=0.4),
    reward_funcs=accuracy_reward,
    train_dataset=dataset,
)

作者：@raghulchandramouli，https://github.com/huggingface/trl/pull/6078

GRPO / RLOO 中的变形金刚连续配料

use_transformers_paged 在 v1.4 中已弃用；它现在被适当的变压器连续配料取代。旧分支默默地绕过重要性采样校正（logprobs = None）；新路径从 output.logprobs 捕获 logprobs 并公开 ContinuousBatchingConfig 用于 KV 缓存调整。

GRPOConfig(
    ...,
    use_transformers_continuous_batching=True,
    transformers_continuous_batching_config={
        "use_cuda_graph": False,
        "max_memory_percent": 0.4,  # leave headroom for training
    },
)

基准测试（Llama-3.2-1B-Instruct、A100 80GB、GSM8K）：1.25× 在 N=64 代速度更快，-16 GB 峰值 VRAM 与默认 generate() 相比。当 N ≥ 32 且完成长度可变时使用。 use_transformers_paged=True 仍然可以工作并使用 FutureWarning 转发到新标志。需要 transformers>=5.8.0。 作者：@sergiopaniego，https://github.com/huggingface/trl/pull/5765

AsyncGRPO：与 vLLM ≥ 0.22.0 的本机权重同步

WeightTransferClient 现在驱动 vLLM 的本机 4 相 RL 权重转移 API，而不是旧的 2 调用流程：pause(mode="keep") → start_weight_update → 线程 update_weights + NCCL 广播 → finish_weight_update → resume。在 H100 上跨单节点、FSDP2×4 + TP=4 和 2 节点 FSDP2×4 + DP=2×TP=4 进行端到端验证（权重同步时间 ≈ 0.18-0.8 s）。 作者：@AmineDiro，https://github.com/huggingface/trl/pull/5892

AsyncGRPO 中的无填充训练

AsyncGRPO 现在支持 SFT 已有的相同无填充路径。展平批次并使用基于 position_ids 的文档边界，而不是右填充最长序列 - 对异构长度工作负载有意义的加速和内存节省。 作者：@qgallouedec，https://github.com/huggingface/trl/pull/5854

实验性港口整合

新的 trl.experimental.harbor 适配器可通过 environment_factory 将 Harbor 代理任务套件插入 GRPOTrainer。与 OpenReward 集成相同的模式 — 一种规格连接所有三个训练器插槽：

from trl import GRPOConfig, GRPOTrainer
from trl.experimental.harbor import HarborSpec

spec = HarborSpec("AdithyaSK/data_agent_rl_environment_train", agent="bash", num_tasks=64)

trainer = GRPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GRPOConfig(num_generations=8, max_steps=50, max_tool_calling_iterations=25),
    train_dataset=spec.train_dataset,
    environment_factory=spec.environment_factory,
    reward_funcs=spec.reward_funcs,
)

内置 bash 线束，以及 jupyter 和 terminal_notes 示例线束。由新的 trl[harbor] extra 控制。 作者：@adithya-s-k 在 https://github.com/huggingface/trl/pull/6018

训练器配置中的 trust_remote_code

训练器配置上的单个 trust_remote_code: bool = False 字段现在涵盖了 整个负载表面 - 模型、处理器/分词器、参考模型、奖励模型、奖励分词器、教师 - 而不是强迫用户通过几个独立的 kwarg 字典来将其线程化。

SFTConfig(trust_remote_code=True)

删除 ModelConfig.trust_remote_code 以避免组合数据类时出现重复的 --trust_remote_code； CLI 行为不变。 作者：@qgallouedec，https://github.com/huggingface/trl/pull/5802

KTO ↔ DPO 对齐：测试、评估、sync_ref_model

毕业前的最后一个对齐周期：KTO 现在在 pad_to_multiple_of、sync_ref_model、evaluate()、方法顺序/签名、度量放置（全部移至 _compute_loss）以及真实文本 + VLM（包括多图像）测试套件上与 DPO 具有同等性。 全部由 @albertvillanova 发布的 PR：#6029、#6030、#6033、#6034、#6035、#6080、#6093、#6148、#6149、#6150、#6152、#6160、#6163。

GRPO / RLOO 中的 LFM2-VL 多模式输入

GRPO 和 RLOO 现在支持 LFM2-VL 端到端多模式输入。 作者：@zwischenraum，https://github.com/huggingface/trl/pull/6114

SFT 重构：在数据集准备期间构建标签

标签构建从整理器移出并进入数据集准备，因此“可训练的内容”恰好在一个地方定义。单个批处理的 map 会生成一个 labels 列，其中每个令牌在每个适用掩码为 1 时保留其 ID，否则为 -100。 Plain LM 保持存储中立；带有掩码列的预标记化数据集现在会经历相同的路径。修复#3927 的第 1 步。 通过 @0xadvait 在 https://github.com/huggingface/trl/pull/6037
