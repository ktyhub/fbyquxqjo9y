trl v1.10.0

特点

🎓 DistillationTrainer 现在是一名稳定的训练师

经过约 30-PR 的重构，重塑了其数据契约、丢失路径、生成堆栈、配置表面和测试，DistillationTrainer 和 DistillationConfig 从 trl.experimental.distillation 升级到顶级 trl 包。与SFT / DPO / GRPO / KTO相同的进口表面。旧的实验路径仍然有效并发出 FutureWarning（在 v2.0.0 中删除）。

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

还着陆了 trl distillation CLI 并将测试移至 tests/。完整的重构弧：将签名列切换为prompt（已弃用的messages格式），将生成堆栈固定到GRPO，连接分块JSD损失并删除完整logit路径，清理Liger路径以与分块路径共享提取，采用GRPO的log() / training_step计时/ _save_checkpoint，将测试套件重建为GRPO形状，以及更多。 由 @qgallouedec 提供约 30 个 PR（#6479、#6480、#6481、#6482、#6484、#6487、#6497、#6508、#6509、#6510、#6511、#6512、#6513、#6521、#6522、#6523、#6524、 #6525、#6526、#6530、#6537、#6604、#6605、#6606、#6607、#6609、#6610、#6611、#6612、#6613、#6614、#6629、#6630、#6632、#6633、#6634、 ＃6639，＃6640，＃6641，＃6642，＃6643，＃6644，＃6645，＃6647，＃6653）。

DistillationTrainer 支持视觉语言模型

在毕业的同时，VLM 在 DistillationTrainer 中进行端到端工作。 作者：@qgallouedec 在 https://github.com/huggingface/trl/pull/6650

AsyncGRPO：循环拥有代理训练（OpenEnv 工具）

AsyncGRPOTrainer 的新实验性 循环拥有（黑盒） 路径 — 用于训练运行自己的工具循环的外部代理，例如 opencode，而不是像 environment_factory 白盒路径中那样由 TRL 驱动每个回合。 代理以 transparent_proxy 模式在 OpenEnv 会话中运行；沙箱内代理捕获每个回合的令牌 ID 和日志概率。完成后，TRL 读取跟踪，重建每轮训练行，并使用会话的 verify() 对工作空间进行评分。附带三个调用者提供的策略挂钩（rollout_reward_fn、train_turn_fn、agent_turn_fn），因此您可以删除框架辅助调用（标题生成器、上下文摘要器）并仅强化您想要的回合。 包括一个独立的 examples/scripts/openenv/opencode.py（本地子进程沙箱 + DeepCoder 保留的标准输入/标准输出验证器），在 Qwen3-4B 上进行端到端验证。 由 @AmineDiro 在 https://github.com/huggingface/trl/pull/6420, 加上 HF 沙箱变体 由 @sergiopaniego 在 https://github.com/huggingface/trl/pull/6565

DiffusionGemma 块扩散 SFT 示例

google/diffusiongemma-26B-A4B-it 的新 SFT 示例实现了参考配方：每步一个响应块、t ~ U(eps, 1) 的统一随机令牌损坏、两遍自调节、整个画布上的平坦交叉熵以及编码器上的自回归共损失。 LoRA 的目标是注意力 + 密集 MLP 线性。需要 transformers >= 5.12.0。 附带 diffusion_gemma.jinja / diffusion_gemma_training.jinja 聊天模板（带有 {% generation %} 标记），因此 assistant_only_loss=True 开箱即用。 通过 @kashif 在 https://github.com/huggingface/trl/pull/6003
