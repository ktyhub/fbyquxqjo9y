cli v0.13.1

修订 发布时间2026年3月12日 来源googleworkspace/cli 英文原文

cli v0.13.1

变更流程图

亮点

  • 升级时凭据自动恢复 — 510024f 将失效的加密凭据从硬错误改为可恢复路径：无法解密的 credentials.enc 会被删除，gws 转而回退到其他来源（明文凭据、ADC），而不是直接失败。同时，当 keyring 中存有密钥但文件缺失时，会重新同步加密密钥文件备份。这对升级或更换 keyring 后遇到认证失败的用户最为重要——现在升级应当“开箱即用”，不再把你卡住。

  • 默认明文路径支持 ServiceAccount 凭据 — 同一提交新增对默认明文路径下 ServiceAccount 凭据的支持，并将令牌缓存文件名统一为常量。若你使用 ServiceAccount 认证且未指定自定义路径，现在行为更一致；常量重构属于内部改动，用户无需操作。

  • zsh ! 表格区域修复 — e104106 在 gws-shared skill 中新增 shell 提示章节，警告 zsh 的 ! 历史展开问题，并将配方和 skill 示例中含 ! 的表格区域由单引号改为双引号。仅当你在 zsh 下运行含 ! 区域的 gws 配方时相关（此前历史展开会破坏命令）；否则无影响。

  • 升级结论 — 无破坏性变更、无迁移步骤。若遇到失效 credentials.enc 错误、依赖默认路径的 ServiceAccount 认证，或在 zsh 中使用 ! 表格区域，值得升级。其余用户可跳过此补丁——它属于低风险加固，而非新功能，也不是空操作或仅改元数据的重新打标签。

Release Note

补丁变更

  • 510024f：将令牌缓存文件名集中为常量，并支持默认明文路径中的 ServiceAccount 凭据
  • 510024f：升级后自动从过时的加密凭据中恢复：删除不可解密的 credentials.enc 并转到其他凭据源（明文、ADC），而不是硬错误。当密钥环有密钥但文件丢失时，还会同步加密密钥文件备份。
  • e104106：将 shell 提示部分添加到有关 zsh ! 历史扩展的 gws 共享技能警告中，并将配方和技能示例中包含 ! 的工作表范围周围的单引号替换为双引号

安装 gws 0.13.1

通过 shell 脚本安装预构建的二进制文件

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/googleworkspace/cli/releases/download/v0.13.1/gws-installer.sh | sh

通过 powershell 脚本安装预构建的二进制文件

powershell -ExecutionPolicy Bypass -c "irm https://github.com/googleworkspace/cli/releases/download/v0.13.1/gws-installer.ps1 | iex"

将预构建的二进制文件安装到您的 npm 项目中

npm install @googleworkspace/cli@0.13.1
