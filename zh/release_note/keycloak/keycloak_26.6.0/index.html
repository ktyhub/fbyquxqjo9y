keycloak 26.6.0

小版本 发布时间2026年4月8日 来源keycloak/keycloak 英文原文

亮点

此版本为 Keycloak 的用户和管理员提供了新功能。此版本的亮点是：

  • JWT 授权授予，使用外部签名的 JWT 断言启用外部到内部的令牌交换。

  • 联合 client 身份验证，无需在 Keycloak 中管理单独的 client 机密。

  • 工作流程，使管理员能够自动执行领域管理任务，例如用户和 client 生命周期管理。

  • 零停机补丁发布，允许在次要版本流中滚动更新，而无需服务停机。

  • Keycloak 测试框架，取代了之前基于 Arquillian 的解决方案。

所有这些功能现已得到完全支持，并且不再提供预览版。 请继续阅读以了解有关每个新功能的更多信息。 如果您要从以前的版本升级，另请查看升级指南中列出的更改。

安全和标准

JWT 授权授予（支持）

JWT 授权授予 (RFC 7523) 旨在实现外部到内部的令牌交换用例。此授权允许使用外部签名的 JWT 断言来请求 OAuth 2.0 访问令牌。

在此版本中，JWT 授权授予从预览版升级为支持版。有关更多详细信息，请参阅 JWT 授权授予指南。

联合 client 身份验证（支持）

一旦与另一个颁发者存在 trust 关系，联合 client 身份验证允许 clients 利用现有凭据。它消除了为 Keycloak 中的每个 client 分配和管理单独机密的需要。

联合 client 身份验证现已升级为支持，包括支持由外部 OpenID Connect 身份提供商和 Kubernetes 服务帐户发出的 client 断言。

由于 OAuth SPIFFE Client 身份验证规范仍处于草案状态，因此此功能仍然是 Keycloak 中的预览功能。

有关展示所有权证明 (DPoP) 的新指南

保护应用程序指南中的 OAuth 2.0 演示所有权证明 (DPoP) 的新指南提供了有关如何通过限制令牌发送者来降低令牌被盗风险的信息。

有关更多详细信息，请参阅使用 DPoP 保护应用程序。

身份经纪 APIs V2（预览版）

此版本中引入了身份代理 APIs 的新预览版本 2。当在身份验证过程中使用代理时，Keycloak 允许您存储外部身份提供商发出的令牌和响应。应用程序可以调用特定端点来检索这些令牌，而这些令牌又可用于获取额外的用户信息或调用外部 trust 域中的端点。新版本改进了令牌检索端点，以替代内部到外部令牌交换（旧令牌交换 V1 的用例）。

有关详细信息，请参阅《服务器开发人员指南》中的身份代理 APIs 章节。

SAML 的逐步身份验证（预览版）

功能step-up-authentication-saml扩展了逐步身份验证以包括SAML协议和clients。此功能处于预览模式。更多信息请参阅服务器管理指南。

OAuth Client ID 元数据文档（实验）

OAuth Client ID 元数据文档 (CIMD) 是一项新兴标准，它定义了用于描述 OAuth 2.0 client 元数据的 JSON 文档格式。自版本 2025-11-25 起，模型上下文协议 (MCP) 需要授权服务器才能符合 CIMD。 Keycloak 现在包括对 CIMD 的实验性支持，使其能够充当 MCP 版本 2025-11-25 或更高版本的授权服务器。

请参阅与模型上下文协议 (MCP) 集成，了解包括 CIMD 在内的更新指南。

非常感谢Takashi Norimatsu的贡献。

管理

工作流程（支持）

工作流程允许管理员自动化和编排领域管理任务，将身份治理和管理 (IGA) 的关键功能引入 Keycloak。通过以 YAML 格式定义工作流，您可以根据事件、条件和计划自动执行领域资源（例如用户和 clients）的生命周期。

在此版本中，工作流程从预览版升级为受支持版。此版本还包括新的内置步骤、故障排除指南以及对工作流引擎的各种改进。

有关更多详细信息，请参阅服务器管理指南中的管理工作流一章。

组织群组

组织现在支持独立的组层次结构，允许每个组织管理自己的团队和部门，而不会在整个领域出现命名冲突。此更新包括身份提供程序映射器，可根据外部声明自动将联合用户分配到组织组。当请求组织上下文时，组成员身份会自动包含在 OIDC 令牌和 SAML 断言中。

有关更多详细信息，请参阅管理组织群组指南。

用户成员身份更改的新群组范围

细粒度管理权限 (FGAP) 现在包含一个新的组范围：manage-membership-of-members。

此作用域现在用作组端桥，用于根据用户当前的组成员身份评估用户端manage-group-membership 权限。 现有的 manage-membership 范围保留其目标组成员资格管理操作的当前行为。

通过 Vault SPI 查找 client 机密

现在可以通过 Vault SPI 管理和查找 clients 的秘密。

感谢 Tero Saarni 贡献此更改。

强制 LDAP 用户更改密码

现在初步支持 LDAP 密码策略控制。 支持仅限于当 LDAP 服务器指示必须更改密码时提示用户更新密码。 此前，Keycloak 让用户进入并忽略强制密码重置。 LDAP 高级设置中有一个新的可选设置“启用 LDAP 密码策略”来启用此功能。

感谢 Tero Saarni 贡献此更改。

配置和运行

Java 25 支持

Keycloak 现在支持与 OpenJDK 25 一起运行。 服务器容器镜像目前继续使用 OpenJDK 21 以支持 FIPS 模式。有关详细信息，请参阅 FIPS 指南中的注释。

零停机补丁版本（支持）

零停机补丁版本允许您在同一major.minor版本流中升级到较新的补丁版本时执行滚动更新，而无需服务停机。

在此版本中，零停机补丁版本已提升为支持并默认启用。 使用 Keycloak Operator 时，请将更新策略设置为自动以受益于此功能。

有关 Operator 配置的更多详细信息，请参阅通过滚动更新避免停机指南。

CloudNativePG 安装说明

对于在 Kubernetes 上运行 Keycloak 的用户，现在提供了有关如何利用 CloudNativePG Operator 在 Kubernetes 上部署 PostgreSQL 数据库以及如何将 Keycloak 连接到数据库的指南。

有关详细信息，请参阅《高可用性指南》中的在多个可用区中部署 CloudNativePG。

简化的数据库操作

几个新的命令行选项简化了 Keycloak 的数据库操作，并且无需使用原始 JDBC 连接选项：

  • 为数据库连接配置 TLS。

  • 数据库连接超时。

  • 生产就绪默认值的事务超时。

它还在启动时验证数据库的 UTF-8 字符编码是否正确，如果情况不正确，则打印警告。

在 Kubernetes 等编排器上运行时，启动和活动探针会在数据库迁移期间返回 UP，从而无需在升级期间调整探针，从而简化了升级。

有关各个方面的更多详细信息，请参阅迁移指南。

正常关闭 HTTP 堆栈

为了允许滚动更新配置更改或版本更新，Keycloak 节点的正常关闭可防止用户在登录时看到错误响应或在节点关闭时刷新其令牌。

从此版本开始，Keycloak 支持 HTTP 堆栈的正常关闭。 这包括在收到终止信号后延迟关闭、在此期间耗尽 HTTP/1.1 和 HTTP/2 连接的连接，以及完成正在进行的请求的关闭超时。

默认关闭延迟和关闭超时各一秒。 这应该非常适合反向代理使用 TLS 边缘终止或重新加密的设置，并且反向代理会收到有关 Keycloak 节点与 Keycloak 节点同时关闭的通知。 这是常见的设置，例如在 Kubernetes 环境中。

用户应根据其代理设置调整这些值。 有关详细信息，请参阅反向代理指南中的正常 HTTP 关闭部分。

环境变量的新 KCRAW_ 前缀用于保留文字值

Keycloak 现在支持环境变量的 KCRAW_ 前缀，以完全按照写入方式保留包含 $ 字符的值，而无需表达式求值。

使用标准 KC_ 前缀时，Keycloak（通过 SmallRye Config）计算值中的表达式（例如，解析 ${some_key} 并将 $$ 折叠为 $）。 这可以静默修改由秘密管理器或编排工具注入的密码或秘密，而手动 escaping 不可行。

设置 KCRAW_ 而不是 KC_ 会完全保留所提供的值。

有关详细信息，请参阅服务器配置指南中的保留带有 KCRAW_ 前缀的文字值部分。

自动重新加载包含不允许的密码的列表

当不允许的密码列表（也称为黑名单）发生更改时，会自动重新加载。这避免了列表更改时重新启动服务器的需要。

感谢 Tero Saarni 贡献此更改。

Kubernetes 和 OpenShift 上自动 truststore 初始化

Keycloak 现在在 Kubernetes 或 OpenShift 上运行时自动发现并 trust 集群证书颁发机构，无需操作员预先配置 truststore。

如果容器文件系统中存在以下证书，则会在启动时将以下证书添加到系统 truststore 中：

  • /var/run/secrets/kubernetes.io/serviceaccount/ca.crt（Kubernetes 服务帐户 CA）

  • /var/run/secrets/kubernetes.io/serviceaccount/service-ca.crt（OpenShift 服务 CA）

此行为默认启用，可以通过服务器选项 --truststore-kubernetes-enabled=true|false 进行控制（默认值：true）。

大多数部署不需要任何操作。如果您之前依赖 Operator 来管理这些 truststore 条目，那么服务器现在可以直接执行相同的功能。

适用于 Traefik 和 Envoy 的 Client 证书查找提供商

您现在可以为 Traefik 和 Envoy 代理使用新的 client 证书查找提供程序。 有关详细信息，请参阅文档的启用 Client 证书查找部分。

Keycloak Operator 中可配置的 Kubernetes 服务名称和端口

Keycloak Operator 现在支持覆盖它为 Keycloak 部署创建的 Kubernetes 服务的名称和端口。

以前，服务名称始终派生为 -service，并且服务端口始终与容器端口匹配。 您现在可以使用 spec.http.serviceName、spec.http.serviceHttpsPort 和 spec.http.serviceHttpPort 字段来 独立配置这些。

有关更多详细信息，请参阅高级配置指南。

敏感信息不显示在 HTTP 访问日志中

如果您使用 HTTP 访问日志记录功能，则会忽略敏感信息。 这意味着“授权”HTTP 标头中的令牌和特定的敏感 cookie 不会显示。

有关详细信息，请参阅配置 HTTP 访问日志记录。

可配置的日志文件轮换

现在可以在使用 Keycloak 的内置文件日志记录处理程序时配置日志文件轮换。 这包括一个完全禁用日志轮换的简单选项，这在使用 logrotate 等外部日志轮换解决方案时非常有用。

要禁用日志文件轮转：

bin/kc.sh start --log="console,file" --log-file-rotation-enabled=false

有关详细信息，请参阅文件日志记录指南。

HTTP 访问日志位于专用文件中

HTTP 访问日志现在可以写入专用文件，与服务器日志分开。 这使得独立处理和归档访问日志以进行安全审核和合规性监控变得更加容易。

有关详细信息，请参阅配置 HTTP 访问日志记录。

JSON 日志输出中的可自定义服务字段

Keycloak 现在提供本机选项来自定义所有日志处理程序（控制台、文件和系统日志）中 JSON 日志输出中的 service.name 和 service.environment 字段。

以前，使用 ECS 格式时，无法通过 Keycloak 配置覆盖 service.name 和 service.environment。 这使得将 JSON 日志字段与 OpenTelemetry 资源属性对齐变得困难。

您现在可以使用 log-service-name 和 log-service-environment 设置这些字段。

有关详细信息，请参阅配置日志记录指南。

新翻译和更新翻译

添加了印度尼西亚语和亚美尼亚语的新翻译。热烈欢迎这些语言的新语言维护者！ 瑞典语翻译还有新的语言维护者，他们翻译了所有剩余的消息密钥。非常感谢！

在翻译状态页面上关注翻译进度，帮助翻译，并阅读有关如何添加其他语言的翻译指南。

帐户界面中从右到左的语言支持

几个版本之前的登录 UI、管理 UI 和电子邮件模板中添加了对从右到左 (RTL) 语言的支持。此版本向帐户 UI 添加了初始 RTL 支持，从而完成了这项工作。

可观测性

通过 Keycloak CR 进行遥测配置

Keycloak 现在支持在使用 Operator 时通过 Keycloak CR 配置 OpenTelemetry 属性。 这些属性在可用的 OpenTelemetry 组件之间共享 - 日志、指标和跟踪。

有关更多详细信息，请参阅使用 OpenTelemetry 集中您的可观测性堆栈指南。

OpenTelemetry 的自定义请求标头

现在可以设置请求标头以通过 OpenTelemetry 协议 (OTLP) 导出遥测数据。 这主要用于在请求中提供令牌。

您可以通过 telemetry-header-

通配符选项指定这些标头，该选项接受任何自定义标头名称。 或者，对 OpenTelemetry 日志使用 telemetry-logs-header-
或对 OpenTelemetry 指标使用 telemetry-metrics-header-
。

有关更多详细信息，请参阅使用 OpenTelemetry 集中您的可观测性堆栈指南。

通过 Keycloak CR 的服务监视器注释和标签

现在可以在使用 Operator 时通过 Keycloak CR 配置服务监视器标签和注释。

有关更多详细信息，请参阅高级配置操作符指南。

扩展开发

Keycloak 测试框架（支持）

现在完全支持基于 JUnit 6 的 Keycloak 测试框架。

它取代了之前基于 Arquillian 和 JUnit 4 构建的解决方案。 该框架在幕后处理 Keycloak、数据库以及任何注入的资源（例如领域和 clients）的生命周期。

测试只需声明他们想要什么，包括特定配置，框架会处理其余的事情。

有关详细信息，请参阅Keycloak 测试框架。
