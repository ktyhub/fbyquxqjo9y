6.10.1 (2026-11-20)

这是发布到 npm 的第一个 6.10 版本。它包括以下 6.10.0 的更改、迁移说明和贡献者积分，以及补丁修复。

错误修复

  • kuna: 使用一个常量作为串行作业计数 (#12735) (3e3faf2)

6.10.0 (2026-11-20)

变更流程图

亮点

  • 使用三个离线 CLI 和 MCP 工具检查并提取 UEFI 固件卷、文件和 AMI NVRAM。 [#12342]（https://github.com/morluto/rea/pull/12342）。谢谢@bartman081523。
  • 检查 Android 启动映像和 OTA 有效负载、NES 2.0 容器以及 Maven、Gradle 和 NuGet 包元数据。 a88c0a5 #9487 #11378 #10674 05be423 #10353 43b9fa8#10351#8144。谢谢@Davmunrey、@gensokyo-dev、@jayykernel、@mvanhorn。
  • 证据修订版 2 给出了文件、进程、调试器和浏览器观察的明确主题身份。请参阅下面的迁移详细信息。
  • 经过验证的 Ghidra 12.2 通道可打开可识别的 DOS COM 文件，并支持更多 RISC-V、MIPS32 和 PowerPC64 ELF 目标。 #4811 #4487 #2362 #2338 #12517 #12085。谢谢@abhay-2108、@AurelioB、@Davmunrey、@kaoru0822-kitauji、@Rinkia。

变化

  • JavaScript 语义索引对嵌套评估上下文使用固定对象形状，以减少分配开销。 #9007。谢谢@mshzy。
  • 检查 ELF 动态依赖关系和所需的符号版本，解析单独的调试文件链接，离线检查 DWARF 编译单元，并解码 FDO 打包和 dlopen 注释。 e9c72db #7868 54e3918 #9560 637e4cb #8523 [#7237]（https://github.com/morluto/rea/pull/7237）[#7235]（https://github.com/morluto/rea/issues/7235）。感谢@AniketR10、@gensokyo-dev、@mvanhorn。
  • 从 WebAssembly 读取可审计的货物依赖项，并将 Go 和 Rust 依赖项证据导出为 CycloneDX。 #5069 237b1ea #8445。感谢@gensokyo-dev、@kaoru0822-kitauji、@mvanhorn、@yu0809。
  • 解码 CPython 3.14 和 3.15 字节码并使用 Kuna 1.1000。 1d08253#10518#12107。感谢@abhisheksharma001、@gensokyo-dev、@N0zoM1z0。
  • 托管成员检查保留 unresolved_definitions 并总结未解析的定义坐标。本机检查会显示原型指令冲突，解决 RISC-V 初始化程序指针，并识别签名覆盖的 Mach-O 切片。 #12462 #8161 #1244 #12109 #11620。感谢@akshad-exe、@N0zoM1z0、@ShuaixinHuang。
  • GDB 和 Rizin 解释了为什么停止的会话拒绝命令以及为什么调试器停止或关闭无法完成。 #11652 #11517 #11185。
  • 安装程序管理 fx、Junie、Goose 和 Kilo 注册，支持显式 MCP 目录配置文件选择，并将共享 enable: false 标记为手动冲突。紧凑 MCP 输入模式使用可移植的广告方言。 #10709 #9354 #11019 #10632。谢谢@kaoru0822-kitauji。
  • 读取器错误名称失败的完整性检查和强制限制。网桥拒绝识别是否发送了请求，并且恢复为超大 MCP 结果命名相关控制或下一个操作。 #11052 #11056 #11021 #11119 #11125 #11129 #11505 #11634 #11623 #11133 #11172 #11015 [#11777]（https://github.com/morluto/rea/pull/11777）。

⚠ 重大变更

  • 证据记录和手工制作的捆绑包需要 evidence_format: 2。使用 6.10 重新创建旧的观测值、捆绑包和快照。重新导出旧的观察结果不会更新它们的身份。读取 subject.identity 来代替 subject.digest、subject.format 和 subject.architecture（文件标识使用 sha256）。每条记录都有一个主题，在适当的时候使用明确的未知身份。身份（包括工件的选择）参与证据 ID。在使用 compare_artifacts 之前重新创建 6.7-era 工件摘要。 #11416#10861。
  • 快照使用 target: {kind, identity} 和非空 execution.subject: {identity, name, local_path}。绑定错误使用相同的目标形状。通用 Mach-O 证据 ID 包括所选切片。实时页面工具及其视图使用删除了凭据的 {kind: "url", url, origin} 身份、不透明 URL 的空源以及空主题名称和本地路径。保留或不可读的 URL 保留未知的身份。重新创建受影响的证据和快照。 #11551PR 11559。
  • 进程捕获需要 manifest.root_process。当观察到它们时，它们的主体身份是 {kind: "process", pid, start_time, executable_sha256}；当无法读取起始身份时，它们的主体身份是 {kind: "unknown", reason: "not-observed"}；当启用 PID 标准化时，它们的主体身份是 {kind: "unknown", reason: "withheld-by-caller"}。接受静默和解中的 cleanup_outcome: "cleaned"。重新创建保存的过程证据。现有的省略语义仍然适用：当 raw_data 等于 data 时，raw_data 被省略；当 residual_unknowns 不存在时，residual_unknowns 被省略。 #11568 #10481 #8032 #10956。感谢@gensokyo-dev、@N0zoM1z0、@Rinkia、@wunianze666-netizen。
  • Rizin 命令 Evidence 和 GDB 启动以及控制台 Evidence 使用 {kind: "session", session_kind, id, target}。当 REA 可以观察到会话目标时，会话目标会识别初始启动文件。 GDB 接受可选的可执行文件。如果没有之一，或者无法观察文件标识，则目标未知，原因是 not-observed。绑定仅描述启动文件。当前下位者的身份需要单独观察。重新创建调试器证据，因为它的 ID 发生了变化。 PR 11570 PR 11572 230db70 #11710 #11581。感谢@gensokyo-dev、@N0zoM1z0。
  • Ghidra 和 Hopper 配置文件用包含 rea_version 和 sources_sha256 的 analysis_profile.parameters.producer 取代了手动碰撞标记。 Ghidra 在选择值上删除了 bridge_sources_sha256 和版本后缀。漏斗掉落 function_dossier_coverage。个人资料和证据 ID 发生变化。打开目标并保存新快照。 [#11320]（https://github.com/morluto/rea/pull/11320）。
  • Ghidra 需要从 12.2 开始的受支持的 12.x 版本以及该版本声明范围内的 JDK（对于经过验证的 12.2 版本为 25 或更高版本）。对于 ComLoader 接受的 DOS COM 文件，请阅读报告的 load_address（现在是线性 0x100）。 BinaryLoader 后备仍然使用 1000:0100。 #12081#12086。
  • IDA 附加注册必须显式设置 "protocol": "native" 并使用本机插件端点来打开 GUI 数据库。将旧版 1.4 代理注册迁移到该模式或无头模式下的 ida-pro-mcp 2.x 管理程序。 procedure_callers 已从 IDA 配置文件中删除，并且 IDA 汇编/指令工具会删除 may_show_ui 注释。 #10846 #11546 #10516。
  • 使用 rea mcp 或 rea --mcp 代替 rea <command> --mcp。使用 rea completions <shell> 重新生成 shell 挂钩并更新 Markdown 参数诊断快照以进行新渲染。旗形未知 MCP 子命令遵循所选的输出格式。 7d502dd #11724 62014b5 #11742 #10583 #11654。感谢@gensokyo-dev、@N0zoM1z0。
  • MCP 拒绝 full 输入和输出架构配置文件。删除这些设置或选择 compact。未设置的 REA_MCP_OUTPUT_SCHEMA_PROFILE 现在表示 off；将其设置为 compact 以接收 tools/list[].outputSchema。 MCP极限误差省略details.limit.cli_flag； CLI 在适用时仍然提供自己的标志。 #10693#11413。
  • 在对 inspect_pcap_capture、start_rizin_debug_session、start_gdb_session（包括 inferior_tty）、load_frida_script 和 instrument_with_frida 的 MCP 调用中使用绝对本地路径。 CLI --script-file 仍然接受相对路径并记录解析后的绝对 source_path。 #11508 #11079 #11580 #11506。
  • 本机 rea analyze 拒绝仅包含 JavaScript 的选项，例如使用 invalid_request 命名标志的 --integrity-policy。仅对 JavaScript 目标传递这些选项。对于 inspect-managed-members --detail summary，将 --evidence-bundle <path> 重命名为 --evidence_output <path> 并在标准输出中读取 .summary 和 .evidence_bundle。发布失败使用共享错误形状。复合 CLI 故障（例如来自 compare-managed-members 的故障）可以将完整的输入作为 details.argument_observations[] 条目与 {argument, observation} 一起携带。 PR 10808 PR 10845 PR 10961。
