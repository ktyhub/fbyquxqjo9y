rea rea-agents-6.5.0

6.5.0 (2026-10-13)

测试指南 中列出了提供商先决条件和记录的验证范围。

变更流程图

亮点

  • 分析选定的 JavaScript 文件并恢复跨捆绑关系，而无需扩展选定的源范围。
  • 阅读跨二进制、托管、Android、Dart、WASM 和网络工作流程的紧凑摘要和页面保留证据。
  • 离线检查 SQLite 快照、数据包和信号记录、WebAssembly、Rust 依赖元数据和 Electron 熔断器。
  • 当分析或清理失败时，保留完整的证据和部分观察结果。

变化

  • JavaScript 源选择： 分析精确的应用程序路径，而无需将导入扩展到所选范围。未选择的文件保留身份和明确的未知覆盖范围；摘要传送与源选择保持分离。 （#1944，问题 morluto/rea#1848）。谢谢@kaoru0822-kitauji，@N0zoM1z0。
  • **代码分割恢复：**从多个选定的输入中恢复相关包，保留每个文件的来源和下游跨块导入。记录的 CLI/MCP 覆盖范围是 Linux x64，带有 Wakaru 1.14.0 和源代码拥有的 esbuild/webpack 固定装置；其他主机、版本和任意应用程序的等效性仍未得到验证。 （#1686，问题 morluto/rea#1605）。谢谢@JingHao-Leon，@pionxzh。
  • 包导入： 使用选定的加载器和包祖先解析精确的包导入别名，而不是猜测同级文件。 （#1862，问题 morluto/rea#1838）。谢谢@AWUQAQ，@mvanhorn。
  • 保留分析视图： 选择紧凑清单/WASM、托管元数据、Android 清单、Dart AOT、Mach-O 和 EVM 摘要，然后页面保留证据而无需重新运行分析。摘要交付保留了完整的记录结果及其原始覆盖范围。 (#2122、#2193、#2413、#2438、#2455、#2634、 #2308、9a18251)。谢谢@kaoru0822-kitauji，@N0zoM1z0。
  • 托管程序集： 检查成员时选择声明类型，使用独立覆盖率解码检查的 ldstr 文字，以及页面保留的成员摘要。调用和字段目标公开 target_declaring_type 和 field_declaring_type，包括支持的通用方法目标；未解决的元数据仍然未知。 (#1706、#2125、问题 morluto/rea#2121、#2162、问题 morluto/rea#2158、#3061、 问题 morluto/rea#3010、#2163、问题 morluto/rea#2160)。感谢@kaoru0822-kitauji、@N0zoM1z0、@Nelglor、@skoodster。
  • 数据包捕获： 使用有界 TShark 输出、紧凑捕获摘要和保留页面检查保存的数据包；发现已安装的协议/字段定义。实机覆盖记录使用Linux和Wireshark 4.6.6；本机 Windows/macOS 和 Bun 行为仍未得到验证。 （[#2318]（https://github.com/morluto/rea/pull/2318）、[#2340]（https://github.com/morluto/rea/pull/2340）、[#2496]（https://github.com/morluto/rea/pull/2496））。谢谢@3QL、@N0zoM1z0、@Olorinm。
  • **录制信号：**解码现有录音并通过呼叫者提供的 sigrok-cli 0.7.2 发现已安装的解码器/选项。这仅适用于 Linux，并且需要 util-linux prlimit；它不获取任何硬件样本。 （[#2339]（https://github.com/morluto/rea/pull/2339），[#2487]（https://github.com/morluto/rea/pull/2487））。谢谢@N0zoM1z0，@Olorinm。
  • Web 捕获： 从保留的 HAR 数据（包括观察到的查询参数名称）导出推断的方法/来源/路径模板 API 表面，同时保留未知数；查询值、标头和正文仍被排除。 (#1891、#2982、问题 morluto/rea#2913)。感谢@mvanhorn、@wunianze666-netizen、@zhangguiping-xydt。
  • QUIC 捕获： 检查保留的 aioquic 1.5.0 JSON qlog 0.3 对象和页面跟踪/流/观察。其他 qlog 布局仍然不受支持；重叠和丢失声明不能证明重传或网络丢失。 （[#2277]（https://github.com/morluto/rea/pull/2277））。谢谢@LuisTaffelli，@N0zoM1z0。
  • Fiddler 捕获： 使用保留的 HTTP 来源和有限解码检查本机 SAZ 档案。记录的制作人报道是固定的公共编码语料库；当前的 Fiddler Everywhere 变体和 Bun 原生执行尚未得到验证。 （[#2409]（https://github.com/morluto/rea/pull/2409））。谢谢@N0zoM1z0，@zahhak。
  • SQLite 快照： 使用表/列选择和有界证据检查显式选择的离线数据库。此操作需要 Node 24.x >=24.15 或 26+ 且 DatabaseSync.limits；支持的 Node 22 和更早的 24 运行时无法使用它。实时数据库/WAL 副本不会建立原子快照。 （[#2271]（https://github.com/morluto/rea/pull/2271））。谢谢@N0zoM1z0，@Y0UW1SH。
  • WASM 工件： 使用自带的 WABT 1.0.42 检查本地模块而不执行它们。比较两个完整核心模块检查证据记录的进口/出口，无需主动安装 WABT；不支持的签名和重复的身份仍然未知，并且比较不能建立运行时兼容性。记录的真实工具检查覆盖范围是macOS arm64。 （[#1533]（https://github.com/morluto/rea/pull/1533），[问题 morluto/rea#884]（https://github.com/morluto/rea/issues/884），[#2464]（https://github.com/morluto/rea/pull/2464），[问题 morluto/rea#2356]（https://github.com/morluto/rea/issues/2356））。谢谢@matbrgz、@N0zoM1z0、@thangldw。
  • Go 二进制文件： 检查嵌入的构建元数据，包括文件支持的未映射的 Mach-O 调试段。 （[#1363]（https://github.com/morluto/rea/pull/1363），[7fb097d]（https://github.com/morluto/rea/commit/7fb097d72c9931dd5dfae481ad2b9d3bb6029f15））。谢谢@Y0UW1SH。
  • Flutter APK： 识别快照/引擎构建并检查 AOT 结构，无需外部引擎。记录的真实 APK 覆盖范围使用记录的 Flutter Gallery 固定装置； macOS/Windows 和完整的池语义仍未得到验证，并且池覆盖仍然是部分的。 （[#1582]（https://github.com/morluto/rea/pull/1582））。谢谢@3QL。
  • HarmonyOS 软件包： 库存 HAP/HSP/App Pack 结构，无需执行代码。记录的真实工作流程涵盖通过存储库构建的 CLI/MCP 固定的 HAP；安装包和真正的 HSP/App Pack 覆盖范围仍未得到验证。 （[#1447]（https://github.com/morluto/rea/pull/1447））。谢谢@BaaRai。
  • Ghidra 原始输入和引用： 兼容的 Linux/macOS Ghidra 配置文件接受调用者选择的原始架构/条目信息，并在确切的地址公开键入的传入引用。 Windows Ghidra P0 承认下面描述的原始 NMOS 6502 配置文件；其他原始目标和传入引用方面保留在 Windows P0 之外。 （[#1868]（https://github.com/morluto/rea/pull/1868），[问题 morluto/rea#1836]（https://github.com/morluto/rea/issues/1836），[#1715]（https://github.com/morluto/rea/pull/1715），[问题 morluto/rea#1245]（https://github.com/morluto/rea/issues/1245））。谢谢@bugstan、@casesolved-co-uk、@mvanhorn、@N0zoM1z0。
  • Ghidra MIPS： 添加有界 MIPS32r2/o32 可重定位对象、软浮点整数寄存器存储、承认的 MIPS16 共享 ELF 以及狭义承认的无记录传统 MIPS32 可执行配置文件。后者固定字节序匹配的 32 位语言，并记录推断的 o32 作为分析假设。准入遵循每个记录的 ABI/标志/搬迁边界。 (#1949、问题 morluto/rea#1937、#1950、问题 morluto/rea#1938、#1991、问题morluto/rea#1851、#1898、问题 morluto/rea#1620)。谢谢@AurelioB、@BaaRai、@bqw371、@kaoru0822-kitauji、@N0zoM1z0。
  • Ghidra RISC-V： 承认小端 RV32/RV64 ET_EXEC ELF 声明支持的双浮点 ABI。可重定位/共享、大端和其他 ABI 配置文件仍然被拒绝；请参阅配置文件和记录的通道。 （[#2151]（https://github.com/morluto/rea/pull/2151））。谢谢@NIU-123370。
  • PSP 静态 ELF 配置文件： Ghidra 配置文件是 Linux x64、有界小端 ELF32 ET_EXEC，具有记录的 PSP/ABI 声明和兼容的调用者安装的 Allegrex 扩展。 PRX、共享/可重定位映像、PBP/ISO/CSO 和运行时仿真不在范围内。历史扩展实验与公共提供商的验证是分开的；真正的公共 Ghidra PSP 覆盖范围尚未得到证实。 （[#1599]（https://github.com/morluto/rea/pull/1599））。谢谢@jaelliot。
  • Ghidra 分析设置： 在分析之前应用经过验证的分析器覆盖，同时保留选定的分析配置文件。 （[#1913]（https://github.com/morluto/rea/pull/1913））。谢谢@akushonkamen、@kaoru0822-kitauji、@N0zoM1z0。
  • 附加本机 IDA MCP： 在现有旧版/无头配置文件旁边添加可选本机桥。录制的本机运行使用带有导航修正的 Linux IDA Free 9.4 和带有环回侦听器更改的 Windows IDA Pro 9.3；原生原生切换、原生 macOS 和 Windows IDA Free 仍未得到验证。附加数据库保持只读状态，并且永远不会保存或关闭。 （[#1544]（https://github.com/morluto/rea/pull/1544））。感谢@imissapixel、@N0zoM1z0。
  • Frida 检测： 添加显式本地/远程目标选择、调用者提供的脚本和保留的消息，以及脚本读取/输入诊断和有界消息驱逐。记录的真实覆盖范围是Linux本地Node标记工作流程； macOS、Windows 和远程设备/服务器仍未得到验证。 Instrumentation 执行外部代码并且具有破坏性，而不是只读的。 (#1359、#2211、问题 morluto/rea#2209、#2217、问题 morluto/rea#2213、 [#2628]（https://github.com/morluto/rea/pull/2628））。谢谢@dandgabr、@kaoru0822-kitauji、@N0zoM1z0。
  • Client 设置： 通过现有范围设置流程注册 Qoder、Trae、ZCode、DeepSeek Harness、Kimi Code、Factory Droid 和 WorkBuddy。 DeepSeek 包含在 6.5.0 中；历史 npm 6.4 检查没有涵盖它。 Live Trae 和 DeepSeek API 集成尚未得到验证。 (#1564、#1572、#1573、#1929、问题 morluto/rea#1839、#2744、 #2309、#3041、问题 morluto/rea#3040)。感谢@0xRafie、@BaaRai、@cainiao1992、@IvenKooLab、@whoishaha、@ysntony。
  • 网站： 添加维护的语言版本、持久/系统感知主题、键盘样式和嵌套证据缩进，以及逆向工程模型文章。更简单的主页和初学者旅程连接平台先决条件、client/提供商设置和提供的初步调查。 (#1779、问题 morluto/rea#1022、#1699、#1714、#1894、#2250、 #2432、#2732、#3274)。谢谢@CassieFox23、@kaoru0822-kitauji、@N0zoM1z0。
  • Rust 依赖元数据： 检查 ELF、PE 和瘦 Mach-O 中嵌入的可审计包/依赖记录，而不执行文件。丢失的元数据和推断的编译器哈希值保留了明确的限制；通用 Mach-O 需要选定的薄片。 （[#2456]（https://github.com/morluto/rea/pull/2456））。谢谢@mvanhorn。
  • 电子熔丝： 读取打包的熔丝字节和每片运行时影响，而无需启动或修改应用程序。丢失、截断和未知的电线仍然清晰可见；保险丝观察结果不能证明其他 Inspector 启用路径。 （[#2399]（https://github.com/morluto/rea/pull/2399））。感谢@kaoru0822-kitauji、@mvanhorn、@N0zoM1z0。
  • Ghidra PowerPC： 在受支持的 Linux/macOS 主机上承认有界 ELF32 大端 ET_EXEC PowerPC 具有显式语言配置文件。 PPC64、DOL 和其他变体仍处于此通道之外；请参阅配置文件和验证先决条件。 （[#1747]（https://github.com/morluto/rea/pull/1747））。谢谢@arielfikru。
  • 参考源摘要： 使用 CLI import-reference-source --detail summary 进行紧凑的清单、计数、状态和路径轮廓输出。完整的图表仍然可用并且仍然是默认的；隐藏的大纲条目保留单独的覆盖范围计数。 （#2768，问题 morluto/rea#2442）。谢谢@matbrgz，@To3akaRin。
  • 记录的 AArch64 崩溃： 使用记录的调用者提供的 Python 依赖项，从受支持的 Linux ELF64 小端核心注释中解码每个线程的 34 个 ABI 寄存器值。这些是记录的事实，而不是当前流程或图书馆身份的证明。 （#2505，问题 morluto/rea#2353）。谢谢@matbrgz，@NIU-123370。
  • Ghidra 字节搜索： 使用通配符、位掩码、地址边界和分页结果搜索已初始化的分析内存。卸载、覆盖和未初始化的块保留跳过的覆盖范围；这不是原始文件搜索。 （[#2341]（https://github.com/morluto/rea/pull/2341））。谢谢@mvanhorn。
  • 原始 NMOS 6502 图像： 使用 Ghidra 显式选择的无头图像（包括 Windows P0），使用调用者选择的条目和 16 位地址空间内的源映射。 Cartridge 解析、重置向量推理和 65C02/65816 不属于此配置文件。 （[#2079]（https://github.com/morluto/rea/pull/2079））。谢谢@Zhong-fan。
  • Swift String 观察： Ghidra 函数档案从公认使用站点的常量寄存器对派生受支持的 AArch64 Swift String 文字，保留指令/寄存器出处和显式省略。这是有界推导，而不是完整的字符串清单。 （#2049，问题 morluto/rea#2030）。谢谢@thefolahan。
  • 无头 IDA 过程查找： 解析规范包含过程条目的地址，并在现代无头配置文件中识别会话已认可的程序文档。不完整的调查仍然存在错误；附加配置文件不会宣传此遏制功能。 （#2374，问题 morluto/rea#2335）。谢谢@nikolay-dementiev。
  • 被动浏览器附件： 当 HTTP 目标发现不可用时，六种现有的被动浏览器工具接受显式端口环回浏览器 WebSocket 端点。仍然需要现有的同意和目标/来源检查；这不会启动浏览器或启用运行时检测。 （[#2346]（https://github.com/morluto/rea/pull/2346））。谢谢@all-black-493。
  • Android DEX 参考： 保留精确的方法描述符和带有源方法、DEX 条目、操作码和代码单元偏移量的单独直接调用观察。这些是静态引用；不可用的指令事实与方法级使用总数保持分离。 （[#2439]（https://github.com/morluto/rea/pull/2439））。谢谢@LcokHcak。
  • 离线 EVM 元数据： 保留来自合理终端 Solidity CBOR 根映射候选的有界、无损事实。候选人不证明 Solidity 起源或源/编译器身份，并且不会获取链接的元数据。 （[#2790]（https://github.com/morluto/rea/pull/2790））。谢谢@matbrgz。

修复

  • JavaScript 加载程序和导出标识： 尊重导入/要求条件和不可用的包元数据，将导出链接与写入分开，并将默认标识符导出解析为在导出语句中捕获的值。 (7e5cffa、322506d、81f7638、dae1e55)。谢谢@paoValle、@VarunGore36、@xu91102。
  • JavaScript 跟踪： 保留嵌套桥调用和幸存的提前返回谓词。遵循节点 ID 匹配选项，将路由种子与源值进行匹配，并保持不明确的运行时候选者未知。 (0351328、5031099、44c9d29、5e79d46)。谢谢@jpdefo。
  • 浏览器比较覆盖范围： 仅比较已知的重定向响应字段，并保留网络选择恢复指导以及独立事件更改。缺少响应事实并不能证明平等或变化。 （[2b60e09]（https://github.com/morluto/rea/commit/2b60e097f281f7708c69f1f7ba9263694547bcc0））。
  • 证据比较和分类账输入： 将仅显示的捆绑包差异报告为未更改，同时保留摘要，并将非规范捆绑包记录分类为无效的调用者输入。 （[030c477]（https://github.com/morluto/rea/commit/030c47732833c9cedcc31db1309eb3a1ca2c62e8），[3a34ad3]（https://github.com/morluto/rea/commit/3a34ad37bdb7b8debba0f6515ba85b80141f2716））。
  • 捕获和准入清理： 当父级成为文件时保留已删除文件的观察结果和原始字节，在取消期间保留不相关的 I/O 故障，并在释放未知的 LLDB 目标所有者之前需要明确的预启动证明。 LLDB 故障控制使用模拟边界。 （[e67c364]（https://github.com/morluto/rea/commit/e67c3642c8920a2a9c0e231ee2f16f50b245df31），[2daeff4]（https://github.com/morluto/rea/commit/2daeff4b243e1cd137c591ca394e18a1c05c8bbc），[45b6a7f]（https://github.com/morluto/rea/commit/45b6a7fe8f51a89951aaa823ffa627f6f5453a33））。感谢@SII-YDD、@xu91102。
  • Client 配置： 在安装程序写入之前验证 MCP 输出模式配置文件，在解析之前忽略 untrusted Gemini 工作区设置，并独立于仅标记的 client 根来识别已安装的技能。 （[0930e94]（https://github.com/morluto/rea/commit/0930e94e077ab7fb4d695f62785919a8a25c2e21），[aade9bb]（https://github.com/morluto/rea/commit/aade9bbcb79aa8504ab6921b25f8ab082aba78e7），[ba33c70]（https://github.com/morluto/rea/commit/ba33c706d26b63e43308be50c0249c72cff62cc6））。谢谢@CmsChase、@paoValle、@sx4im。

  • **ADB安装：**可选的replace输入不变。结果现在需要replace_requested来记录请求的adb install -r模式； replaced 可为 null，因为未观察到先前的设备封装状态。更新结果读取器以接受 null，而不是将重新安装意图视为替换证明。 （[864314a]（https://github.com/morluto/rea/commit/864314ac857924a7e6e65bfb37e8dc720fcc21e7））。
  • 托管/本机验证： 当模块身份未知时，未解析的 P/Invoke 结果可能会保留 matched_native 和候选事实。解释status、basis和limitations； module-identity-unknown 不验证对应关系，未解决不再意味着空洞的观察。 （[3f6b575]（https://github.com/morluto/rea/commit/3f6b5755b3e699bd9373641acffe0f2c5d2ab094））。 完整贡献记录：893 次提交和 529 次合并 PR。
