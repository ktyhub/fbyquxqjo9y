rea rea-agents-6.8.0

6.8.0 (2026-10-25)

变更流程图

亮点

  • 根据网络捕获、浏览器场景或提示构建本地代理环境，然后提供派生读取和证据门控写入，并将它们与新的应用程序捕获进行比较。
  • 检查更多已发布的格式，包括 GPU 代码对象、BEAM、Python 字节码、Unity IL2CPP 元数据、Godot PCK、PyInstaller、Node.js SEA、devicetree 和其他 PE/ELF 表。
  • 通过保留的摘要、选定的事实查询、可配置的恢复限制和面向行的 CLI 导出来保持大型调查的重点。 Complete Evidence remains available.

⚠ 重大变更

  • 功能分析： analyze_function 现在默认为保留摘要。 Set detail: "complete" for the previous inline dossier; the CLI retains its complete default and requires --evidence_output when selecting a summary. [#5660]（https://github.com/morluto/rea/pull/5660）。感谢@CryptoJones、@gensokyo-dev、@RishTheFish21。
  • 可访问性： 在节点 value 中接受 JSON 数字和布尔值，以及字符串和 null。更新之前假定纯文本值的消费者。 cc90771, #6759, #6467. Thanks @coygeek, @gensokyo-dev, @mvanhorn.
  • JSON 行： --format jsonl 现在发出对象集合行，后跟 $rea: "jsonl/v1"、type: "metadata" 记录； scalar selections and unsupported reports are refused. Parse control records separately, select a single supported collection when necessary, and use --format json for the previous whole-document output. See JSON Lines framing. #5629, #5487.感谢@gensokyo-dev、@jayykernel、@vijaykiran06。
  • 接口生成器： 键控存档图形标识使用十进制表 UID，而不是编写的 objectID/object-id。将创作的 ID 视为属性并更新持久的图形查找； ibtool and native NIBArchive identities keep their source semantics. 6fbe67d。
  • Frida: instrument-with-frida JSON 直接返回规范证据。 Read normalized_result.cleanup_error instead of the former top-level wrapper field. 48f700e。
  • Reconstruction proof: ID-array proof records no longer establish verified or ready ledgers. Supply implementation/revision bindings and individual claim outcomes; handle inapplicable, unavailable, and failed proof diagnostics. f8b65e7。
  • Mach-O imports: Handle a null import name when identity is ambiguous; use raw_name and name_status to distinguish observed expressions from exact symbols. 5d0d243, 169512a.
  • Node.js: Use a runtime satisfying ^22.23.4 || ^24.22.1 || >=26.12.1; Node 23 and 25 are unsupported.在安装或更新 REA 之前升级节点； the installer does not upgrade it. #6315, #6283. Thanks @GamerDubz, @gensokyo-dev, @ShikamaruNaaraa.
  • 浏览器存储： 历史哈希存储仍然可读，但比较保持未知，直到在新的表示中重新捕获两个捕获。 #6341, #6289.谢谢@coygeek，@gongfpp。
  • Environment serving: environment-serve serves derived state by default, including write tools whose effects are confirmed by recorded evidence. Use --replay-only for stateless replay of manifest tools. Read stop-summary state instead of state_evidence_id. [#5351]（https://github.com/morluto/rea/pull/5351），[#6158]（https://github.com/morluto/rea/pull/6158）。 Thanks @earakely-scale, @gensokyo-dev, @kaoru0822-kitauji.
  • MCP 模式： 输入广告默认为紧凑。设置 REA_MCP_INPUT_SCHEMA_PROFILE=full 以获得完整的广告指导和嵌套约束。 [#5975]（https://github.com/morluto/rea/pull/5975）。谢谢@gensokyo-dev。
  • 浏览器控制台参数： 当协议参数清单被省略或格式错误时，接受 null argument_types 和 text_capture.status: "unavailable"；保留这种不确定性。 [#6016]（https://github.com/morluto/rea/pull/6016），[#5934]（https://github.com/morluto/rea/issues/5934）。谢谢@coygeek，@kaoru0822-kitauji。
  • 重建摘要： summary.by_evidence_authority 由证据权威机构加密；从所需的 summary.by_source_state 读取以前的源状态计数。重新生成其闭包摘要取决于旧投影的分类帐。 [#5875]（https://github.com/morluto/rea/pull/5875），[#5838]（https://github.com/morluto/rea/issues/5838）。谢谢@coygeek，@kaoru0822-kitauji。
  • Swift 绑定： 一致性 type_name 和 protocol_name 可能为空；使用 type_binding/protocol_binding 类型的证据。用 MachoImportBinding 替换以前的 Objective-C 特定的导入绑定类型/模式。 d0067ba.
  • WebSocket 帧： 接受空操作码并保留未知的帧事实；数字操作码仅限于四位协议范围。 0bc2b42。
  • 仅资源检查： 证据主题和可执行摘要可能为空。使用 resource_root 和每个资源报告的来源，而不需要可执行目标。 6a6adf7。
  • 浏览器时间戳： 当协议不提供有限/可比较的时间时，控制台和会话时间线时间戳可能为空。在排序和比较中保持未知时间的明确。 690fc51、2a0410f。
  • 参考来源： 从 rootFailure 读取失败的根枚举，而不是在 "." 读取合成的失败子项；保留顶级源图限制。 6296fdf。
  • 文件系统捕获： 除了前面的原因文字之外，还接受 entry_unavailable 和 identity_changed 枚举省略原因。 c85b44e。谢谢@rudrakshagarwal4200-ai。
  • APK 区域设置： 将数字传统选择器（例如 es-r419）替换为 es-419 或 b+es+419。仍然支持两个字母区域。 29910d1。谢谢@mertkayacs。
  • XML plist 标量： 识别 $plist_type: "unknown" 并读取 element、literal 和 reason；未解析的 XML 标量使用此包装器而不是以前的实/空未知标记或格式错误的标量前缀。支持的扩展 UTC 年保留其时间戳。 3537e58。

  • 二进制布局： 使用调用方提供的 pwntools 环境检查 Linux x64 上的 ELF32 i386、小端 ARM 以及小端或大端 MIPS EXEC/DYN/REL 布局。 [#7052]（https://github.com/morluto/rea/pull/7052），[#6934]（https://github.com/morluto/rea/issues/6934）。谢谢@roblennon，@salmanalmutairi1。

  • 捕获到环境： 根据浏览器场景或提示构建环境，提取初始观察到的状态，并将环境与应用程序探测捕获进行比较。 #5182、#6946、#5319、#5699。感谢@earakely-scale、@gensokyo-dev、@kaoru0822-kitauji。
  • 状态支持的工具： 从状态渲染读取过滤器、搜索、排序和分页；将已确认的写入效果与更广泛的状态目标和基于记录的写入许可一起应用。 #5352、293832b、#5800、#5787、#5600、5375ff0、 #6169、#6385、#6897。感谢@earakely-scale、@gensokyo-dev、@kaoru0822-kitauji。
  • 状态学习： 对应用程序分配的值进行建模，保留特定于视图的时钟拼写，从场景计时学习写入时钟，派生字段，并学习跨排序数组和引用实体的创建。 7ec9b6e、#6136、957bcfa、#6138、#6967、#7025、 [#7034]（https://github.com/morluto/rea/pull/7034）。谢谢@earakely-scale。

  • 引擎工作流程： 绑定单个 Ghidra 反编译而不关闭其会话，分析 GameCube/Wii DOL 可执行文件，并检查静态 CUDA/HIP 代码对象。 #5662、#6240、#5813、#5340、#5345。感谢@arielfikru、@coygeek、@gensokyo-dev、@RishTheFish21。
