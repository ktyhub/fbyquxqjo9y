rea rea-agents-6.9.0

6.9.0 (2026-11-11)

变更流程图

亮点

  • 根据记录的应用程序状态构建和测试桌面任务，包括下载的 Linux 应用程序、可重复使用的构建计算机以及每次捕获的多个任务。
  • 离线检查更多已交付的工件：独立应用程序包、嵌入式固件、NTFS 收购、API 合同和 V8 代码缓存容器。
  • 使本机和运行时调查以保留的证据为基础，并提供分页结果、明确的覆盖范围和可恢复的资源限制。

⚠ 重大变更

  • 设置 clients 必须将 effect、rea_restart_required、restart_required 和 restartRequired 替换为 update_mode（runtime、restart、parameter）和 pending_restart。运行时设置器无法更改参数提供的限制； restart-mode 值保留其启动值直到重新启动。 #9885、be20bdfb26f7、aee1178839dd。感谢@gensokyo-dev、@N0zoM1z0。
  • 流程和桌面调用者必须检查 details.secondary_failures/secondaryFailures：混合批次将物理/提供商故障保持为主要状态，并保留键入的取消及其原始原因。保留的描述符可以产生cleanup_incomplete；遵循返回的恢复，而不是将其视为普通取消。自定义适配器必须使用所有者发布的检查/采样事实并保留其清理范围，直到发布成功。 #10141、#10113、#10109。
  • rea mcp add --command 现在仅接受本地 stdio 启动器：HTTP(S) 可执行 URL 在设置写入之前被拒绝，并且包获取被删除。在每个 client 的本机设置中配置远程传输，并在注册前安装/选择本地启动器。 #10102。
  • 除了捕获摘要和运行时密钥之外，运行时实例图标识现在还需要 identity.capture_evidence_id。节点 ID 会消化该身份，因此即使摘要和运行时密钥未更改，也会重新生成协调证据并重建节点键控查找。 #10063。
  • 保留的进程符号链接需要其存储的目标字节；重新捕获仅描述链接而不保留其目标的遗留观察结果。 #10082。
  • 函数档案必须一起记录 Swift 文字清单及其遗漏。通过规范提供者重新生成片面的观察结果；两者缺席且不受支持的观察仍然有效。 [#10068]（https://github.com/morluto/rea/pull/10068）。
  • 一致性清单架构 v2 将精确的字符串标记与片段分开，并拒绝旧的模糊 strings 字段。使用 npm run build:fixtures 重新生成未版本化的装置。 [#9977]（https://github.com/morluto/rea/pull/9977）。
