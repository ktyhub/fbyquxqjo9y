DeepSpeed v0.19.6

DeepSpeed v0.19.6

这个项目是干啥的：是一个帮大模型训练提速省显存的工具库，让研究和工程团队用普通显卡集群也能训练超大模型，并兼容新版PyTorch。

变更架构图

亮点

  • Apple Silicon（MPS）支持进入第一阶段 — ZeRO 1–3 阶段现在可在 MPS 后端运行（#8293），配套新增 Metal FusedAdam 算子和 CPU Adam 构建（#8300），通过非阻塞后端方法对 isend/irecv 做异步暂存（#8303），并减少 MPS P2P 暂存中的冗余拷贝（#8314）。对采用者而言这是头条能力：它开启了在 Mac 本地以熟悉的 ZeRO 语义训练的可能；但这明确只是第一阶段——算子/操作与 CUDA 尚未对齐，在把真实负载迁移上去之前请验证收敛性和不支持的操作。
  • AutoTP 走向生产可用 — 自动张量并行的编译 pass 作为系列之首落地（#8204），不均匀切分和通用检查点支持已完成（#8185），正确性修复覆盖未切分模块元数据（#8299）、lm_head 训练路由（#8302）、映射到 SKIP 规则的 HF embedding_rowwise 计划（#8294），以及通用检查点元数据中的 ZeRO-3 崩溃（#8270）。对采用者来说，这显著降低了静默的检查点/布局不匹配风险，但特性仍分散在多个进行中的 PR 里——请锁定版本，并在升级时重新验证检查点可移植性。
  • DeepCompile 与显存 offload 更快更安全 — 修复覆盖 ZeRO-3 下的冻结参数（#8214）、未消费 wait 的最后使用处理（#8254）、Python 3.9 静态方法（#8240），以及 pass 契约与实际调度 pass 的对齐（#8251）。在此基础上新增激活 offload（#8255）、非可重入的 CPU 检查点 offload（#8282）、新的 compile.offload_activation_pin_memory 开关（#8258），以及向 CUDA 注册以用于 GPU DMA 的原生 DeepNVMe 主机内存 pinning（#8211、#8283），pin 站点统一走 accelerator.pin_memory（#8256、#8257）。实际结论：offload 路径现在依赖 pinning 行为，请重新调整 offload 设置，并留意加速器上的主机内存注册情况。
  • 需要留意的行为变化 — NCCL 及其他进程组后端默认超时从 30 分钟改为 10 分钟（#8253）；检查点保存慢、弹性伸缩或有拖后腿 rank 的长作业，现在可能因 watchdog 超时更快失败，若依赖旧窗口请显式设置更长超时。另外：DeepSpeedConfig 不再把 max_grad_norm 写回调用方的字典（#8289），OneCycle 现在遵循文档所述的逐参数组列表（#8201），文档中移除了不存在的 ZeRO 选项 grad_hooks（#8242），OnebitLamb.get_lamb_coeffs 返回副本（#8227）。请审查任何从配置字典读回值、或依赖共享可变系数数组的代码。
  • RL rollout 与 MoE 算子吞吐 — HybridEngine 生成新增 CUDA 图支持（#8271）、rollout 性能分析（#8295）和跨 rollout 样本共享 prompt prefill（#8296）；融合 Triton SwigLU 算子（#8244）、分组 GEMM 专家偏移的 int32 溢出修复（#8261），以及 ZeRO-3 权重量化中参数 dtype 的保持（#8215）则面向 MoE 训练。如果你跑 RLHF 风格训练或 MoE 模型，这些是值得关注的收益；但算子和量化修复会改变数值，请对照基线验证。
  • 破坏性变更 — 无；这是一次向后兼容的补丁发布，上述改动均为增量能力、正确性修复和所述行为调整。
