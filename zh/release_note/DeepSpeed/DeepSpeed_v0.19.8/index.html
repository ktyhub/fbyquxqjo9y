DeepSpeed v0.19.8

修订 发布时间2026年10月20日 来源deepspeedai/DeepSpeed 英文原文

DeepSpeed v0.19.8

变更流程图

亮点

  • 旧特性移除，需清理配置 — Progressive Layer Dropping（#8562）和弹性训练（#8563）被移除；APEX AMP（#8564）、旧版课程学习（#8566）、LoCo Zero++（#8534）、sparse_gradients（#8504）、压缩库残留（#8535）和图收获（graph harvesting，#8579）被弃用或移除。升级前请审查配置、导入和训练脚本——被移除的路径可能直接导致启动失败，而不是静默回退。
  • AutoTP 现在会切分词表矩阵与权重共享模型 — 词表并行嵌入（#8582）和 LM 头（#8309）、eager 行并行输出头（#8538）、共享嵌入支持（#8680），以及 ZeRO-3 下 AutoEP + AutoTP 的折叠（#8670），共同降低了大词表模型的单卡显存压力。Liger 词表并行交叉熵仍是可选启用（#8540），启用前请核对其依赖和运行要求。
  • Muon 在 ZeRO、梯度累积和 offload 场景下更稳健 — ZeRO-3 现在每个优化器步只运行一次 Muon，而不是每个微批次都跑（#8600）；修复还覆盖带边界 gather 的 CPU offload（#8464）、混合参数形状（#8628），以及不截断更新幅度的 FP16 损失缩放（#8655）。BF16_Optimizer 也支持 Muon 与 FP32 梯度累积（#8526），逐头 Newton-Schulz 路径现在能识别注意力和线性注意力的结构（#8384、#8436）。
  • AutoEP 降低每层 MoE 开销 — 单个 DeepEP 缓冲区在多个 MoE 层间共享（#8557），默认 combine 去掉了一次冗余的 FP32 拷贝（#8621），split 规划与 token 打包重叠（#8359），从而抑制深层 MoE 堆叠中的显存增长和数据搬运。可选的 GC 策略、区域编译、激活注册表、融合行加权和 MiniMax-M3 预设提供了更多调优手段（#8451、#8380、#8650、#8644、#8651）；检查点回放也修复了缓存生命周期与布局处理问题（#8581、#8636）。
  • ZeRO 正确性修复，避免静默训练与检查点失败 — 本版修复了 ZeRO-1/2 中 CPU 梯度桶丢失（#8382）、ZeRO-3 异步 gather 不完整（#8539）、FP32 与非浮点缓冲区未保留（#8699、#8515），以及检查点转换时分片目标重复（#8624）的问题。另有两个行为变化需要留意：DeepSpeedCPUAdam 现在会拒绝不支持的 amsgrad，而非忽略它（#8694）；rollout 会拒绝与连续批处理共享 prefill（#8583）。
  • NPU 与 Triton 后端覆盖面扩大 — NPU 新增图操作（#8605）、融合的 Lion/Lamb/量化器算子（#8627）和原生 pinned 主机内存注册（#8532）。Triton 方面修复了 FlashAttention/MatMul 自动调优兼容性，并在 SwiGLU/AutoEP 恢复算子中使用 64 位 program ID（#8679、#8591）；可选的融合 RMSNorm 和 RoPE 面向 Llama 风格的 Hugging Face 模型（#8645、#8663）。
