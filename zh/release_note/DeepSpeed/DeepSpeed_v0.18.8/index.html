DeepSpeed v0.18.8

修订 发布时间2026年3月13日 来源deepspeedai/DeepSpeed 英文原文

DeepSpeed v0.18.8

这个项目是干啥的：是一个帮大模型训练提速省显存的工具库，让研究和工程团队用普通显卡集群也能训练超大模型，并兼容新版PyTorch。

变更架构图

亮点

  • ZeRO-3 梯度流处理 — PR #7898 把梯度处理从 default_stream() 改为 current_stream()，因此 ZeRO-3 现在遵循当前的 CUDA 流，而不是回退到默认流。如果你在自定义流上重叠通信与计算（梯度钩子、流水线阶段），这消除了一个微妙的错流/竞态隐患——在这个补丁上值得重新验证任何自定义流编排。这是 @michaelroyzen 的首次贡献。
  • fp16 配置快速失败校验 — PR #7889 现在会拒绝非有限或负数的 fp16.loss_scale 值，而不是任其传播到训练中。配置错误的 FP16 任务现在会在启动时报错，而不是静默漂移到 NaN；请审查任何依赖非常规或哨兵值的配置。
  • 双重归约诊断 — PR #7895 用可操作的错误信息取代了双重归约配置错误时的晦涩失败。由于 ZeRO 中双重归约是用计算换显存，这里出现清晰提示通常意味着你的拓扑或配置不支持它——而不是优化器的 bug。
  • 解锁昇腾 NPU 构建 — PR #7894 修复了华为昇腾 NPU 上异步 I/O 算子的编译。此前无法在启用异步 I/O 时构建的昇腾用户现在可以编译；这是 @huangyifan0610 的首次贡献。
  • Evoformer 多架构分发 — PR #7881 修复了 Evoformer（AlphaFold 风格）内核跨架构分发的根因，确保在非 x86 和多架构环境中选中正确的内核，而不是静默错误分发。
  • 更安静的日志与贡献者护栏 — PR #7891 抑制了嘈杂的 see_memory_usage 输出，PR #7890 解决了 CI 中 Bloom 测试挂起的问题，PR #7902 为 AI 编码代理新增 AGENTS.md/CLAUDE.md 规则。属于运维清理，而非运行时行为变化。

本版本无破坏性变更。
