DeepSpeed v0.18.5

这个项目是干啥的：是一个帮大模型训练提速省显存的工具库，让研究和工程团队用普通显卡集群也能训练超大模型，并兼容新版PyTorch。

变更架构图

亮点

  • ZeRO-3 检查点与反向传播正确性 — PR #7780 修复了 use_reentrant=True 与 PyTorch 风格反向及 ZeRO-3 搭配时的梯度检查点问题——这种组合此前可能静默产生错误的梯度；#7787 修复了 pipeline engine 的反向传播，#7789 在梯度归约时跳过空参数。如果你在 ZeRO-3 + 检查点 + 流水线并行下训练，请在信任续跑结果前升级。
  • BF16 优化器路径变更 — PR #7788、#7790 和 #7803 修正了 DeepSpeed 选择 BF16 优化器的方式：ZeRO 关闭时不再应用 BF16_Optimizer，并且现在会在正确的 ZeRO 阶段选择它。PR #7786 还修复了 ZeRO-0 + BF16 的检查点保存/加载。这会改变 BF16 配置下实际运行的优化器，因此升级后请核查损失曲线。
  • ZeRO-3 通信优化 — PR #7661 新增顺序 allgather 优化，#7805 修复 ping-pong buffer 索引重置并去掉一次冗余的流同步，#7769 跳过空张量上的压缩 allreduce。净效果是通信开销和同步次数减少，在启用压缩时最明显——无需改配置即可获得吞吐提升。
  • Apple Silicon（MPS）支持 — PR #7767 带来一批 MPS 修复，使本版本在 macOS/M 系列 GPU 上明显更可用。如果你此前在 Apple 硬件上跑不了 DeepSpeed，值得重试本地运行。
  • 序列并行与 Evoformer — PR #7809 修复了 Ulysses 中 sp_size < world_size 时反向传播的 rank 索引越界，#7784 修复了 Ulysses PEFT 测试，#7760 修复了 Evoformer 编译。对上下文并行/长上下文和蛋白质折叠工作负载很重要；其中 Ulysses 的 bug 专门影响序列并行规模与世界规模不相等的情况。
  • 修改已聚合参数现在会明确报错 — PR #7817 让 DeepSpeed 对没有 modifier_rank 就原地修改 GatheredParameters 的行为抛出清晰错误。此前这类修改可能静默地无法传播回分片参数；迁移方式是在修改聚合张量时传入 modifier_rank（并使用上下文管理器）。（另注意 #7802 修复了直接导入 Muon 优化器时的模块路径。）

本版本无破坏性变更。
