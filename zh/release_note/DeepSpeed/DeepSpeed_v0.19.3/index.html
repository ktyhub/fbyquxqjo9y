DeepSpeed v0.19.3

修订 发布时间2026年7月23日 来源deepspeedai/DeepSpeed 英文原文

DeepSpeed v0.19.3

这个项目是干啥的：是一个帮大模型训练提速省显存的工具库，让研究和工程团队用普通显卡集群也能训练超大模型，并兼容新版PyTorch。

变更架构图

亮点

  • ZeRO-3 混合精度正确性 — 多项修复纠正了 ZeRO-3 在混合 dtype 下收集参数的方式：_allgather_params_coalesced 现在为输出缓冲区使用每个参数各自的 dtype（PR #8073），量化缩放缓冲区同样处理（PR #8128），混合 dtype 参数在 autocast 下的 gather 得到修复（PR #8113），ZeRO-3 的 hook 现在也能配合属性委托模块工作（PR #8144）。如果你在 bf16/fp16 或量化条件下用 ZeRO-3 训练，这些是实打实的正确性修复，不是表面功夫。

  • 默认值变化会影响训练行为 — 默认值在无声中改变：gradient_clipping 现在默认为 1.0（PR #8068），bf16 的 check_grad_overflow 默认开启以与 fp16 对齐（PR #8035），activation_checkpointing 的 num_layers 默认为 None 从而触发 configure() 的断言（PR #8041），fp16 动态损失缩放参数会被校验为正数（PR #8050）。升级前请复查配置——依赖旧隐式默认值的运行可能表现不同。

  • 弃用与配置迁移 — ZeRO-3 弹性检查点被弃用（PR #8099），依赖它的用户需要迁移路径。Muon + reduce_scatter 在 ZeRO-1/2 下先是被拒绝（PR #8090），随后在同一版本中获得正式支持（PR #8141），并有数值正确性测试背书（PR #8091）。save_checkpoint 和 warmup LR 调度器新增校验（PR #8126），还加了 total_num_steps == warmup_num_steps 时的 ZeroDivisionError 防护（PR #8142）。

  • 新能力 — On-Policy Distillation（OPSD）Trainer 的 Hybrid Engine rollout（PR #8027）、AutoEP + AutoTP 并行折叠（PR #8064）及 AutoEP 对 ZeRO-3 zero.Init 源模块的支持（PR #8060）、apply_rotary_pos_emb 的可选 torchembed 后端（PR #8052）、Inference V2 支持 EXAONE 4.5（PR #8121）、可配置的引擎日志级别（PR #8067），以及公共 API 的类型标注（PR #8079、PR #8118）。

  • DeepCompile/稳定性修复与升级结论 — DeepCompile 获得多项修复（profile 元数据回填 PR #8094、profiling 显存清理 PR #8106、dynamo 跳过帧中的 ZeRO-3 gather PR #8059、标量输出回退 PR #8149），另有 shm.cpp 中与安全相关的缓冲区长度检查（PR #8082）、deepspeed_io_handle_t::wait() 中的 fd 泄漏修复（PR #8075），以及 Python 3.9 的 AutoEP 导入修复（PR #8119）。如果你在用 ZeRO-3、DeepCompile、AutoEP/AutoTP 或 Python 3.9，建议升级；其余都是 CI/DCO/文档改动（含版本提升 PR #8070），对运行无影响，稳定的非 ZeRO-3 环境可以跳过。
