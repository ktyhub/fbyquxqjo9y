DeepSpeed v0.20.0

这个项目是干啥的：是一个帮大模型训练提速省显存的工具库，让研究和工程团队用普通显卡集群也能训练超大模型，并兼容新版PyTorch。

变更架构图

亮点

  • HybridEngine 图 rollout 覆盖面扩大，后端改为可选启用 — 非贪心的 temperature/top-k/top-p 采样现在也支持图解码与连续批处理（#8939）；Transformers 5.20 的 query offset 和预构建的 4 维 SDPA 掩码消除了捕获阻碍（#8852、#9004）。捕获改为按能力判断而非按 CUDA 名称判断（#8933、#8980）：CUDA/NPU 自动选择加入，自定义加速器需实现 is_graph_capture_supported() 和流捕获检测，否则回退到 eager 执行。使用 hybrid_engine.enable_graph_capture；enable_cuda_graph 仍是已弃用的别名。

  • ZeRO-1/2 修复多请求梯度累积 — 累积边界不再被视为优化器步：梯度跨请求边界保留，直到 step() 才更新，同时不会把过期梯度带入下一次更新（#8949、#9018）。ZeRO-2 CPU offload 现在在紧凑的分区存储中累积（#9044），低精度梯度恢复前会清理陈旧的 offload 暂存区（#8728）。这对延迟更新、条件性使用参数以及 CPU offload 训练很重要。

  • ZeRO-3 强化精度保持与 offload 效率 — 模型显式保持在 FP32 的参数在 ZeRO-3 下不再被降精度（#8843），ZeRO-3 和 ZeRO-1 BF16 优化器的 FP32 主权重会得到恢复（#8892），从 state_dict 加载的 CPU 优化器状态保留 FP32（#8974）。pinned 主权重回拷避免缓慢的可分页 CPU 类型转换（#8840），dtype 已匹配时复用分区避免重复的主权重存储（#8842），NVMe 预取不再与既有交换缓冲区分配冲突（#9014）。

  • AutoEP/AutoTP 与 VocabTP 支持更多组合负载 — ZeRO-3 现在可以把 AutoEP + AutoTP 折叠与 CPU 优化器 offload 组合使用（#8829），并修正了该配置下路由专家梯度裁剪（#8823）。VocabTP 新增融合的 Hugging Face 前向路径，用于词表并行的 LM 头投影加损失（#8945），以及 Triton 广义 JSD 算子（#8958），为大词表训练和蒸馏负载提供更高效的执行选项。

  • 确定性执行成为显式策略 — 启用 deterministic_mode: true 可获得严格的 PyTorch 确定性算法、禁用 TF32/cuDNN 自动调优、确定性的 FPDT FlashAttention 反向传播，以及固定的 Triton 分组 GEMM 配置（#8917）。该模式拒绝 ROCm、CUDA 兼容的非 NVIDIA 加速器以及旧的 stochastic_mode: true；在 CUDA 初始化前请校验 cuBLAS workspace 环境。把它当作复现/调试模式，生产使用前先做基准测试。

  • 破坏性变更 — 未列出。
