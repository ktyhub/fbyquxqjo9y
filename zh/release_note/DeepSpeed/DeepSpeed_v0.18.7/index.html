DeepSpeed v0.18.7

DeepSpeed v0.18.7

这个项目是干啥的：是一个帮大模型训练提速省显存的工具库，让研究和工程团队用普通显卡集群也能训练超大模型，并兼容新版PyTorch。

变更架构图

亮点

  • ZeRO-1/2 初始化更快 — 当设备有足够空闲显存容纳对齐后的扁平缓冲区时，参数组现在直接在加速器上展平，避免 CPU 侧拷贝和传输（#7828）。上游 8×H100 上 32 层 Qwen3-30B 的 ZeRO-2 配置基准从约 382 秒降到约 130 秒；显存紧张的运行仍走 CPU 路径，快速路径需要临时设备显存。
  • ZeRO 反向性能与 PyTorch 2.3 兼容性 — 期望的 hook 数量在反向阶段边界缓存，不再为每个梯度 hook 重新扫描，消除了 v0.18.5 在 ZeRO-2/3 中的二次开销（#7886）。梯度累积查找现在在反向 hook 期间启用 grad 模式，修复了 PyTorch 2.3 下的 AttributeError 失败（#7841）。
  • GatheredParameters 修改规则更严格 — 启用 ZeRO-3 完整性检查后，在 GatheredParameters(..., modifier_rank=None) 内做原地修改会抛出 rank 同步的 RuntimeError，而不再允许不协调的更新（#7832）。若由单个 rank 修改参数且结果需要广播，请使用 modifier_rank=<rank>；请审查 rank 本地的修改代码。
  • XPU 与 autocast 的破坏性迁移 — Intel XPU 现在使用上游 PyTorch 的 torch.xpu 和 SYCL 扩展机制，而不再使用 IPEX；xpu.external 和基于 IPEX 的 XPU 推理构建器被移除（#7877）。自定义加速器代码必须把 get_accelerator().amp() 替换为 torch.amp.* 并显式指定 device_type；2.4 之前的兼容回退已移除（#7879）。XPU 部署应使用官方 XPU wheel，并保证 icpx 版本与其 SYCL 运行时匹配。
  • 更广的推理与硬件支持 — Inference V2 新增 EXAONE 4.0（#7853），把仅限 CUDA 的 BF16 转换 intrinsics 替换为兼容 ROCm 的路径，同时保持 CUDA 行为不变（#7846），并修复了 Evoformer 编译（#7862）。Arm 新增 shm_comm 支持（#7800），扩展了 Arm 主机上的共享内存通信选项。
  • 部分训练与失败处理修复 — Muon 参数组现在排除 requires_grad=False 的参数，避免冻结层后只剩一种优化器类型时出现的空组失败（#7869）。把 35 处裸 except 改为 except Exception，让 KeyboardInterrupt 和 SystemExit 能正常向上传播，而不再被吞掉（#7873）。
