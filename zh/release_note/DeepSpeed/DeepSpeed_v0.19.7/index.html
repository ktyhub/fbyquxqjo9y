DeepSpeed v0.19.7

这个项目是干啥的：是一个帮大模型训练提速省显存的工具库，让研究和工程团队用普通显卡集群也能训练超大模型，并兼容新版PyTorch。

变更架构图

亮点

  • 破坏性移除 — 稀疏注意力、Nebula 检查点、deepspeed.compression、1-bit Adam/Lamb、0/1 Adam 和 MiCS ZeRO-3 均被移除。sparse_attention、Nebula、compression 和 MiCS 配置项现在会直接报错，请在升级前迁移这些负载（#8490、#8493）。还要更新 LR-range-test 脚本：--lr_range_test_staircase 现在只看是否出现，直接给裸 flag 即可启用，不要再传 True/False（#8337）。
  • Muon 终于尊重优化器设置 — 调用方参数组在拆分为 Muon 和 Adam 分支时会保留各自的 LR 和权重衰减（#8440）；Newton–Schulz 现在在默认 ZeRO stage 0 下运行，而不再静默把 Muon 降级成 SGD（#8442）；zero.Init 配合 ZeRO-3 时能正确识别矩阵参数，而不再把所有权重留在 AdamW（#8438）。现有 Muon 任务的更新轨迹会变化，stage 0 也会多出计算量。
  • AutoEP 新增可选快速路径 — DEEPSPEED_AUTOEP_COMM_BACKEND=deepep 可选择 DeepEP v2，NCCL 仍是默认；上游基准报告在 16 张 H100 上端到端提速 1.22 倍（#8213）。要求 DeepEP v2 和 NCCL ≥2.30.4，折叠张量并行会回退到 NCCL。另一条独立路径 combine_impl="fused_weighted_sum" 可降低中间显存，但仍属实验性，且没有统计上确凿的端到端收益（#8326）。
  • ZeRO 检查点可移植性提升 — zero_to_torch.py --dtype 和 convert_zero_checkpoint_to_state_dict(...) 支持导出 FP32/FP16/BF16，同时保留共享别名；原有的 FP32 转换保持兼容（#8318）。较低精度可减小产物体积和分片规划需求，但会引入舍入误差。不同 AutoTP 规模之间的通用检查点续训也得到修复（#8474）。
  • 编译与分布式执行的正确性修复 — 在 DeepCompile 下启用激活检查点时，AutoTP 集合通信不再静默消失（#8355），_DimZeroAllToAll 现在会在 torch.compile 下传播反向梯度（#8491）。Ulysses 还修复了 seq-first 的 all-to-all 输出布局（#8317），并按 DistributedAttention 实例跟踪 KV 头数量（#8316）。升级后启用这些路径时，请重新核对损失和梯度一致性。
  • 连续批处理以实验特性登场 — 设置 SamplingConfig.continuous_batch_size=N 可让 rollout 独立回收请求并回填 KV-cache 行，同时保持输出顺序（#8368）；还新增了 prefill/decode 和连续批处理的性能分析（#8350、#8494）。默认生成行为不变，但新路径目前要求 Transformers 缓存类支持、等宽 prompt、贪心单样本解码和单设备验证。
