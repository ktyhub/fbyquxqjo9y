DeepSpeed v0.19.4

修订 发布时间2026年8月6日 来源deepspeedai/DeepSpeed 英文原文

DeepSpeed v0.19.4

变更流程图

亮点

  • ZeRO-3 + AutoTP 推理 — 张量并行现在可与 ZeRO-3 推理配合，包括替换 HuggingFace lm_head、保留 tp_plan 元数据，以及跨 TP 和 DP rank 的检查点合并。这消除了一项重要的组合限制；请重新检查此前合并过的检查点，并验证在你目标并行拓扑下的往返转换（#8167、#8146、#8187、#8168）。
  • 更广的梯度累积支持 — 托管累积新增对 ZeRO 阶段 0/1 的支持，非托管累积新增阶段 2/3。阶段 0/1 用户获得显式托管模式，ZeRO-2/3 工作负载可以保留手动累积控制而无需自定义绕行方案（#8184、#8203、#8217）。
  • 修正的训练调度 — WarmupLR 保留每组的基础学习率，张量专属 LR 在调度器更新（包括 OneCycle）后依然存在，且 OneCycle 的阶梯计数现在会影响曲线。无效的 warmup 类型和零步调度也会被拦截。这些修复会改变实际 LR 轨迹，因此请重新验证基线和恢复的任务（#8171、#8202、#8205、#8179、#8151、#8166）。
  • MoE 正确性与性能 — dispatch 修复了 Tutel + TP 的静默数据损坏，使 Tutel 共享 MoE 支持 k != 1，为 Ampere/Ada 增加 Triton grouped-GEMM，并改进 AutoEP 的 rank 切分与路由。MoE 用户应对新的 expert-GEMM 路径做基准测试，并在更换后端、top-k、专家数或丢 token 行为时重跑正确性检查（#8195、#8174、#8180、#8190、#8155）。
  • 更安全的编译与运行时诊断 — DeepCompile 状态现在限定在图与引擎生命周期内，并修复了 ZeRO-3 聚合参数的归属问题；zero.Init 现在会对静默单 rank 回退发出警告；阻塞式 AIO 绑定会释放 GIL。请演练引擎重建和检查点路径，排查 rank 回退警告，并预期线程化 I/O 工作负载有更好的重叠（#8159、#8157、#8089、#8196）。
  • 兼容性 — 本版本未指出破坏性变更。
