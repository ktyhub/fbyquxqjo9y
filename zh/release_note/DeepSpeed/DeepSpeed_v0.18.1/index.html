DeepSpeed v0.18.1

修订 发布时间2025年10月23日 来源deepspeedai/DeepSpeed 英文原文

DeepSpeed v0.18.1

这个项目是干啥的：是一个帮大模型训练提速省显存的工具库，让研究和工程团队用普通显卡集群也能训练超大模型，并兼容新版PyTorch。

变更架构图

亮点

  • ZenFlow 登陆 ZeRO-3（#7516） — Stage 3 现在提供 ZenFlow 代码路径，为显存受限的 LLM 训练者提供一个不必在设备内存中持有完整优化器状态的优化器。这是本版本的旗舰能力：值得拿它与你现有的 offload/CPU-adam 方案做基准对比，而不是假定配置一一对应——它改变的是显存—吞吐的权衡，而不只是多了一个 flag。

  • Ulysses 序列并行接入 HF Accelerate（#7638） — Ulysses SP 实现现已与 Hugging Face Accelerate 集成，因此已经以 Accelerate 为标准的团队可以不离开自己的启动器抽象就采用长上下文序列并行。迁移成本主要在配置层，但要验证注意力内核和头数的假设，因为 SP 会改变张量并行组的语义。

  • 通过 DataStates-LLM 实现异步检查点（#7166） — 新增异步检查点引擎，把快照写入从训练步中解耦，直击检查点密集型任务中占主导的停顿时间。对大模型任务这在运维上意义重大：它用后台 I/O 流水线换取更短的步骤时间尖峰，因此要注意新的 CPU/内存压力，并在生产环境信任它之前验证恢复正确性。

  • 张量级学习率（#7633） — 优化器现在接受按张量（而非仅标量）设置的学习率，从而无需自定义参数组 hack 就能实现逐层或按模块的学习率调度。行为上是增量的，但任何假定单一标量 LR 的工具都应审查其读取和上报学习率的方式。

  • 自定义优化器与 Muon 行为（#7634、#7641） — DeepSpeedZeroOptimizer 子类现在可以在 __init__ 中吸收任意 **kwargs，便于集成自定义优化器；同时 Muon 被明确排除在 embedding 和 lm_head 层之外。如果你维护 ZeRO 优化器子类，或曾依赖 Muon 更新每个参数，请调整配置与预期——这是真实的行为变化，不只是修复。

  • 大模型稳定性与诊断（#7639、#7636、#7637） — 修复了 multi_tensor_apply 中尺寸超过 INT_MAX 时的非法内存访问（对超大张量/模型至关重要），以及 ZeRO-2 的内存占用上报和断言问题——现在断言会点名参数而不是给出零 id。这些主要在大规模或调试输出中显现，因此按旧断言/内存字符串做日志解析和告警的地方可能需要更新。

本版本未报告破坏性变更。
