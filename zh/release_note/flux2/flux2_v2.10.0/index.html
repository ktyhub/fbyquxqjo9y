flux2 v2.10.0

变更流程图

亮点

Flux v2.10.0 是一个功能版本。我们鼓励用户升级以获得最佳体验。 新功能概述：

  • 对象标识普遍可用； ObjectLevelWorkloadIdentity 功能门已停用
  • 用于控制器间通信的 SPIFFE mTLS
  • 通知Event、Alert和Provider API升级为v1
  • OCIRepository 作为 HelmRelease 的图表源
  • 使用注释正则表达式和 --override-manager-before-dry-run (Kustomization) 加密的文件的 SOPS 解密
  • 使用 .spec.policyChangeDelay 进行图像更新批处理、重试拒绝的推送和 .Changed.Summary (ImageUpdateAutomation)
  • 默认情况下为 ImageRepository 标签启用 Flux 工件存储后端
  • 跨命名空间工件、租户命名空间配置和路径模式发现 (ArtifactGenerator)
  • 新的 Zoom、incident.io 和 Mastodon 通知提供商
  • 使用 Kubernetes 1.37 和 Go 1.27 构建 ❤️ 非常感谢所有帮助我们发布此版本的 Flux 贡献者！

Kubernetes 兼容性

此版本与以下 Kubernetes 版本兼容：

Kubernetes版 最低要求
v1.35 >= 1.35.2
v1.36 >= 1.36.1
v1.37 >= 1.37.0

[!注意] 请注意，Flux 项目仅提供对 Kubernetes 最新三个次要版本的支持。 供应商提供了与旧版本 Kubernetes 和 OpenShift 的向后兼容性，例如 ControlPlane 为 Flux 提供企业支持。

OpenShift 兼容性

Flux 可以使用 Flux Operator 直接从 OperatorHub 安装在 Red Hat OpenShift 集群上。该操作员允许配置 Flux 多租户锁定、网络策略、持久存储、分片、垂直扩展以及来自 Git 存储库、OCI 工件和 S3 兼容存储的集群状态同步。

升级流程

⚠️ 此版本中的重大更改：

  • 对象标识始终启用，并且默认 Flux RBAC 不再在 serviceaccounts/token 资源上授予 create 动词。如果您的安装依赖于默认的RBAC，请在升级之前将具有此权限的ClusterRole绑定到控制器ServiceAccount。请参阅 fluxcd/flux2#6139 了解所需的 ClusterRole 和 ClusterRoleBinding。
  • 通知Alert和Provider API升级为v1。将 v1beta3、Alert 或 Provider 转换为 v1 会删除已弃用的 Alert.spec.summary 和 Provider.spec.interval 字段、Azure 事件中心的静态 JWT 令牌以及 Provider.spec.secretRef 中的 TLS 或代理配置。请改用 eventMetadata.summary、proxySecretRef 和 certSecretRef。
  • Flux 工件存储后端现在是 ImageRepository 标签数据库的默认设置。切换门会擦除本地标签数据库，因此升级后的第一次协调会重新扫描每个 ImageRepository。设置 --feature-gates=FluxStorage=false 以继续使用 BadgerDB。
  • .spec.kubeConfig.configMapRef 的远程集群身份验证使用对象身份；将旧版 audiences 密钥替换为 credential.auth.fluxcd.io/audiences。 请按照【Flux v2.7+升级流程】(https://github.com/fluxcd/flux2/discussions/5572)从老版本Flux平滑升级到v2.10。
