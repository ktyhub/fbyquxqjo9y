flux2 v2.8.0

变更流程图

亮点

Flux v2.8.0 是一个功能版本。我们鼓励用户升级以获得最佳体验。 有关此版本中包含的新功能和 API 更改的简要概述，请参阅宣布 Flux 2.8 GA 博客文章。 新功能概述：

  • Helm v4 支持，包括服务器端应用和基于 kstatus 的健康检查 (HelmRelease)
  • 使用 CEL 表达式 (HelmRelease) 对 Helm 管理的对象进行就绪性评估
  • 通过 .status.inventory (HelmRelease) 中的库存跟踪改进了 Helm 版本的可观察性
  • 通过 CancelHealthCheckOnNewRevision 功能门（Kustomization、HelmRelease）缩短了 Flux 管理的应用程序恢复的平均时间
  • 支持直接从 Flux 通知评论 Pull 请求 (Provider)
  • kustomize-controller (Kustomization) 中订购资源应用程序的自定义 SSA 应用阶段
  • 从存储库所有者处自动查找 GitHub 应用程序安装 ID（GitRepository、ImageUpdateAutomation、Provider）
  • 支持 Cosign v3 以验证 OCI 工件和容器映像 (OCIRepository)
  • ArtifactGenerator 支持提取和修改 Helm 图表 (ArtifactGenerator)
  • 通过 DirectSourceFetch 功能门（Kustomization、HelmRelease、ArtifactGenerator）获取源对象时绕过缓存 ❤️ 非常感谢所有帮助我们发布此版本的 Flux 贡献者！

Kubernetes 兼容性

此版本与以下 Kubernetes 版本兼容：

Kubernetes版 最低要求
v1.33 >= 1.32.0
v1.34 >= 1.34.1
v1.35 >= 1.35.0

[!注意] 请注意，Flux 项目仅提供对 Kubernetes 最新三个次要版本的支持。 供应商提供了与旧版本 Kubernetes 和 OpenShift 的向后兼容性，例如 ControlPlane 为 Flux 提供企业支持。

OpenShift 兼容性

Flux 可以使用 Flux Operator 直接从 OperatorHub 安装在 Red Hat OpenShift 集群上。该操作员允许配置 Flux 多租户锁定、网络策略、持久存储、分片、垂直扩展以及来自 Git 存储库、OCI 工件和 S3 兼容存储的集群状态同步。

升级流程

：警告：Flux API、v1beta2 和 v2beta2（于 2024 年弃用）已达到使用寿命并已从 CRD 中删除。 请按照【Flux v2.7+升级流程】(https://github.com/fluxcd/flux2/discussions/5572)从老版本Flux平滑升级到v2.8。
