flux2 v2.9.0

变更流程图

亮点

Flux v2.9.0 是一个功能版本。我们鼓励用户升级以获得最佳体验。 有关此版本中包含的新功能和 API 更改的简要概述，请参阅宣布 Flux 2.9 GA 博客文章。 新功能概述：

  • Flux CLI 插件系统，带有镜像和架构插件 (flux plugin)
  • 服务器端应用字段忽略规则进行细粒度漂移控制（Kustomization）
  • 使用 Age 后量子密码 (Kustomization) 进行 SOPS 解密
  • Kubernetes OpenBao和Vault的工作负载身份验证（Kustomization）
  • Helm 渲染后策略，包括图表挂钩支持 (HelmRelease)
  • Helm 值参考镜像 helm --set-literal (HelmRelease) 的文字模式
  • 在 CEL 健康检查表达式中允许空类型（Kustomization、HelmRelease）
  • 使用 SSH 密钥进行 Git 提交签名和验证（GitRepository、ImageUpdateAutomation）
  • 使用 Workload Identity (GitRepository) 进行 AWS CodeCommit 身份验证
  • 自定义 Sigstore trusted 根，用于气隙环境中的无密钥验证 (OCIRepository)
  • monorepos 的路径模式目录发现 (ArtifactGenerator)
  • 无秘密、OIDC 保护的 webhook 接收器 (Receiver) ❤️ 非常感谢所有帮助我们发布此版本的 Flux 贡献者！

Kubernetes 兼容性

此版本与以下 Kubernetes 版本兼容：

Kubernetes版 最低要求
v1.34 >= 1.34.1
v1.35 >= 1.35.0
v1.36 >= 1.36.0

[!注意] 请注意，Flux 项目仅提供对 Kubernetes 最新三个次要版本的支持。 供应商提供了与旧版本 Kubernetes 和 OpenShift 的向后兼容性，例如 ControlPlane 为 Flux 提供企业支持。

OpenShift 兼容性

Flux 可以使用 Flux Operator 直接从 OperatorHub 安装在 Red Hat OpenShift 集群上。该操作员允许配置 Flux 多租户锁定、网络策略、持久存储、分片、垂直扩展以及来自 Git 存储库、OCI 工件和 S3 兼容存储的集群状态同步。

升级流程

：警告：Flux API、image.toolkit.fluxcd.io/v1beta2 和 notification.toolkit.fluxcd.io/v1beta2 已达到使用寿命并已从 CRD 中删除。 请按照【Flux v2.7+升级流程】(https://github.com/fluxcd/flux2/discussions/5572)从老版本Flux平滑升级到v2.9。
