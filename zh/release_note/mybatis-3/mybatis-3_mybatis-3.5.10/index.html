变更流程图

亮点

  • Java 16+ 的 OGNL 访问修复——现代 JVM 应升级 — #2392 消除了在 Java 16+ 上于 OGNL 表达式中调用方法时出现的非法反射访问警告和 `InaccessibleObjectException`。如果你在 Java 16+ 上运行 MyBatis，并在映射中使用 OGNL 方法调用，单凭这一点就值得升级；在更旧的 JDK 上这不是问题。
  • Records 与构造器自动映射——主要的功能收益 — #2195 修复了破坏 Records（JEP-359）自动映射的 `IllegalAccessException`，新的 `argNameBasedConstructorAutoMapping` 选项（#2192）让构造器参数名驱动列查找，而不再需要显式映射。使用 Records 或基于构造器的不可变 DTO 的团队应升级；使用普通 JavaBean 映射的团队收益不大。
  • 连接池中断语义 — #2503 让 `PooledConnection#getConnection()` 在被中断时设置线程的中断状态，因此检查 `Thread.interrupted()` 的关闭/取消逻辑现在能正确工作，而不是悄悄吞掉中断信号。如果你依赖中断驱动的连接池超时，这一点相关；否则无感。
  • 可选的事务性能优化，无强制迁移 — `JdbcTransactionFactory` 新增 `skipSetAutoCommitOnClose`（#2426），对于关闭时 `setAutoCommit()` 往返开销大的驱动，可避免该调用；`` 中 `` 现在也可以跟在 `` 之后（#2541）。两者都是向后兼容的放宽，发布说明确认自 3.5.9 以来没有已知破坏性变更——因此对大多数用户是低风险的可直接替换版本，但只有当上面某项修复确实与你相关时才值得动手。
  • 结论：针对性升级，并非人人需要 — 如果你在 Java 16+ 上、使用 Records/构造器自动映射，或想要 `skipSetAutoCommitOnClose` 这个调优开关，就值得升级。如果你用的是较旧 JDK、常规 JavaBean 映射，且没有连接池中断或驱动性能方面的顾虑，可以放心跳过——这里没有需要紧急处理的事项，无论升不升都无需迁移工作。 以下是翻译及梳理后的内容，已移除@符号和贡献者信息，并转为Markdown语法：

Bug 修复：

  • 在调用 OGNL 表达式中的方法时，出现了意外的非法反射访问警告（或在 Java 16+ 中出现 InaccessibleObjectException）。详情查看 #2392
  • 在自动映射 Records (JEP-359) 时抛出了 IllegalAccessException 异常。详情查看 #2195
  • 当 PooledConnection#getConnection() 被中断时，未设置 ‘interrupted’ 状态。详情查看 #2503

增强功能：

  • 新增了一个选项 argNameBasedConstructorAutoMapping。如果启用，构造函数参数名称将用于在自动映射时查找列。详情查看 #2192
  • 为 JdbcTransactionFactory 新增了一个属性 skipSetAutoCommitOnClose。跳过调用 setAutoCommit() 可以在某些驱动程序上提高性能。详情查看 #2426
  • <constructor /> 中的 <idArg /> 现在可以列在 <arg /> 之后。详情查看 #2541

自 3.5.9 以来没有已知的不兼容更改。

请参阅 3.5.10 里程碑页面 了解完整的更改列表。
