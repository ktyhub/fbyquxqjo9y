graphify v0.9.113

修订 发布时间2026年11月19日 来源Graphify-Labs/graphify 英文原文

graphify v0.9.113

  • 更改：包装最小 Python 现在是 3.11.5（以前是 3.11），并且每个解释器的 soupsieve 都固定到 4.1.1。 soupsieve 的修补版本需要 3.11.5，因此提高地板会清除开放的 soupsieve 建议（CSS 选择器解析器中的 ReDoS 和递归/多项式 DoS，通过可选的 svg/all/pdf 附加功能中的 beautifulsoup4 传递到达）。在 Python 3.11.0-3.11.4 上安装，保持解析为 0.9.112； 3.11.5 及更高版本上的每个人都不受影响（#5301，感谢@TPAteeq）。
  • 修复：一个类或模块的 ruby 方法，其名称仅通过前导/尾随 _ 或大小写（_read_attribute/read_attribute、_where!/where!）（包括 class << self 中的那些）不同，获得不同的节点 id，而不是一个吞掉另一个（#5292，感谢 @rohit-jsfreaky）。
  • 修复： lua 表字段函数的名称仅因前导/尾随 _（M._load/M.load、Runner:_start/Runner:start）不同而获得不同的节点 ID； M.f/M:f 仍然命名一个字段（#5294，感谢 @rohit-jsfreaky）。
  • 修复：scala 成员的名称仅因前导 _、_= setter 后缀或大小写不同（_enter/enter、size/size_=、forEach/foreach），包括跨类及其伴随对象，获得不同的节点 ID（#5296，谢谢@rohit-jsfreaky）。
  • 修复：elixir def 的名称仅因前导/尾随 _、!/? 后缀或大小写（_name/name、get/get!、__schema__/schema）不同而获得不同的节点 ID，因此 get! 调用 no get 上的着陆时间更长（#5298，感谢 @rohit-jsfreaky）。
  • 修复： rust 前奏特征的类型参数（impl From<Celsius> 中的 Celsius 或 T: Into<Celsius> 绑定）被读取为通用参数引用，而不是被误认为特征本身，因此它不再发出错误的 implements/inherits 边缘（#5332，感谢 @azeemshaik025）。
  • 修复：当语料库中的另一个包命名同级文件类型时，go 保留成员调用：冲突的无源存根被移动到自己的 id，而不是对真实声明加盐并孤立其方法边缘，从而删除了调用（#5304，感谢 @Yi-111-a）。
  • 修复：ruby 在访问修饰符（private def validate、private_class_method def self.audit）之后内联编写的方法保留其封闭类的成员身份，而不是作为文件级函数发出，因此对其的调用解析为该方法（#5310，感谢@Synvoya）。
  • 修复：swift 作为运算符表达式（base + bonus()、!isEmpty()）的最后一个操作数的调用（语法将其解析为被调用者）将被提取而不是删除（#5311，感谢 @Synvoya）。
  • 修复：kotlin 前缀运算符（!isReady()、-compute()）下的调用被提取而不是被删除，包括堆叠前缀和 !obj.ready() （#5312，感谢 @Synvoya）。
  • 修复：vbnet 具有默认值的参数被视为可选，无论修饰符顺序如何（ByVal Optional x As Integer = 0、ByRef Optional ...），因此方法数量和重载解析是正确的（#5320，感谢@Deepjyoti-Sarmah）。
  • 修复：当 AST 缓存位于源以外的另一个驱动器上时（Windows 跨驱动器情况，其中 os.path.relpath 引发并且每个文件都有一个空键），cpp 包含标识将被保留，因此声明/定义折叠仍然有效；正常的同一驱动器路径保持不变（#5145，感谢@Ayushraj06位）。
  • 修复：llm 标签生成重试保留 512 个令牌的输出下限，因此单社区恢复通行证不再在其恢复的批次下方匮乏；显式的 GRAPHIFY_MAX_OUTPUT_TOKENS 仍然会覆盖（#2086，感谢@Synvoya）。
  • 修复：ruby 在 class << self 块内编写的模块的 include/prepend/extend 发出其 mixes_in 边缘，而不是因为只扫描直接类主体语句而被错过（#5317，感谢 @Synvoya）。
  • 修复：python 具有参数化基类（class C(Base[T])、class D(Mapping[str, int])）的类将 inherits 边发出到基类型，并针对继承方法调用进行遍历，而不是被删除并标记为不透明；嵌套泛型参数、调用基数和 mod.Base[T] 仍然不被视为父级（#5318，感谢 @Synvoya）。
  • 修复：tsconfig tsconfig.json extends 和精确的 compilerOptions.paths 映射解析为它们命名的真实扫描配置/文件，而不是悬挂的存根；非语料库包扩展、通配符路径和循环扩展失败关闭（#5223，感谢@Deepjyoti-Sarmah）。
  • 修复：cpp 无法访问的类前向声明​​（一个不包含路径到达的声明）不再阻止将成员声明折叠到其外线定义中；真正不明确的情况（模板或第二个定义）仍然保持独立（#5337，感谢@winesoft-namjin-yun）。
  • 修复：提取针对涉及 id 冲突的标头的导入不再无条件地重新指向标头变体：重新指向由导入文件的语言系列控制，因此冲突的 foo.h/foo.py 旁边的 Python import foo 保持其边缘到 foo.py，而不是作为跨语言而被删除（#5328，谢谢@sdivyanshu90）。
  • 修复：提供精确节点 ID 的查询直接解析到该节点，而不是被共享其标记化源路径的其他节点超越（#5343，感谢 @Ayushraj06 位）。 AST 缓存模式增加到 49；热缓存重新运行受影响的 Ruby、Lua、Scala、Elixir、Rust、Swift、Kotlin、VB.NET、Python 和 TypeScript-config 提取。
