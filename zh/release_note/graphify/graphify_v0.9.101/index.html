graphify v0.9.101

图形化 0.9.101

跨 C++、Rust、Python、Go、构建写防护和增量重建的分辨率准确性和缓存正确性发布。

C++

  • 成员调用 x.m() 按接收者的类型绑定，现在从函数参数和类字段键入，而不仅仅是本地变量（void render(Base* b){ b->draw(); } 解析为 Base::draw）；无类型或不明确的接收者保留其文件内绑定（#3215，#4946）。
  • 外联或分割头定义附加到其类文件位于其包含集中的唯一所有者，而不是交叉绑定到不相关的同名函数；不明确的所有者无法关闭（#4916，#4920）。
  • 本地可调用值（lambda 或 std::function）通过字节范围绑定生命周期保留在全局调用解析之外，因此它不再对同名全局进行虚假的 INFERRED 调用；后来的合法全局调用仍然存在（#4917，#4921）。
  • 类型别名引用（using Foo = Bar; 然后 Foo x;）通过精确的拼写进行绑定，并且加盐别名保留其自己的 contains 边缘 (#4951)。

Rust

  • 模块限定的调用（crate::b::helper()、super::m::f()）通过限定符验证的跨文件解析进行解析，保留在调用者的包内（#2135、#4944）。
  • 在表达式宏的参数（println!("{}", f())、vec![g()]）内编写的调用被链接、门控到允许列表，因此 macro_rules! 主体和自定义 DSL 不会受到影响（#4945）。

Python / 去

  • 方法内的裸调用不再自绑定到同名方法；它解析为其命名的导入或模块级函数（#4933）。
  • 跨 PEP 420 命名空间包的导入解析分为多个 src/ 根 (#4929)。
  • 通过接收者字段到达的 Go 方法值被链接为 indirect_call (#1566, #4931)。
  • Go 包级 var 初始化器引用它命名的类型（#2360、#4932）。

构建/缓存/重建/监视

  • 当实体去重将已保存的节点折叠到幸存的孪生节点中时，写防护不再拒绝健康的图；真正的损失仍然被拒绝（#4940，#4952）。
  • 独立来源的语义文件证据在折叠到 AST 文件自身节点后仍然存在；普通的 INFERRED 提及鬼魂仍然会折叠，因此图表不会累积重复项（#4896，#4927）。
  • 仅当边缘的文件和别名目标共享语言系列时，文件干别名索引才会重新绑定边缘 (#4949)。
  • 缓存键保留其书面大小写，因此 README.md 和 readme.md 不再冲突，并且通过 os_long_path 打开散列/字数文件（#4925，#4937）。
  • --code-only 图表在钩子、update 和监视重建中保持仅代码状态（#4923、#4939）。
  • 当不支持 msvcrt.locking 时，重建不再永远等待（#4924、#4926）。
  • 完全协调会逐出排除的链接 git 工作树的源记录 (#4919)。
  • 仅 AST 更新保留节点 ID 与代码定义冲突的跨文件语义证据 (#4950)。
  • 切片文件仅在每个切片成功并按块顺序组装后才会被缓存（#4943，#4947）。 AST 缓存模式增加到 36 个；热缓存重新运行受影响的提取。 感谢@nothariharan、@Deepjyoti-Sarmah、@azizur100389、@andrebrait、@ayushcodes10、@madhusudanpatnaik、@Ethan-Ethan-Ethan 和@AndresDiagoM。
