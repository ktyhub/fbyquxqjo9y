graphify v0.9.112

修订 发布时间2026年11月17日 来源Graphify-Labs/graphify 英文原文

graphify v0.9.112

  • 文档：python 自述文件、其翻译、贡献、发布、错误报告模板和 ruff/pyright 目标现在将 Python 3.11 指定为最小值，与 0.9.111 中提供的地板相匹配（#5238，感谢 @Deepanshu-Mehta；@Max17190 在 #5237 中发送了相同的修复程序）。
  • 文档：链接自述文件中的始终在线设置链接，所有翻译都直接指向 docs.graphify.com/open-source/vibe-coding，而不是从旧指南/始终在线路径进行重定向（#5261，感谢@SyedFahad7）。
  • 修复：java 每个重载方法都有自己的由元数和擦除签名键控的节点，而不是所有重载都崩溃到一个删除成员和错误路由调用的节点； affected 覆盖匹配现在可以感知数量，因此拆分 run(int) 不会通过标签与超类型 run() 绑定，并且也可以处理跨存储库和通用方法重载（#5251，感谢 @deba2k5）。相同数量、仅类型不同的重载仍然绑定到第一个声明的重载（镜像 C# 先例 #4584）；文字参数类型调度是后续操作。重载的构造函数仍然共享一个节点。
  • 修复：go 裸接收器类型 (func (s Service) m()) 解析为其自己的包类型，而不是与语料库中的每个同名类型进行匹配，因此每个声明 Service 的两个包保留自己的成员调用边缘，而不是都因模糊性保释而丢失它们（#5242，感谢 @ayushcodes10）。
  • 修复：rust use crate::... 导入在其自己的板条箱内解析，而不是跨板条箱边界泄漏到多板条箱工作区中另一个板条箱的同名项目；单箱 crate:: 导入仍然像以前一样解析（#5240，感谢@Max17190）。
  • 修复：当 this.x = function (params) {...} 成员的参数之一遮盖参数位置中使用的同名语料库函数时，js this.x = function (params) {...} 成员不再制造错误的 indirect_call；它自己的参数和从封闭范围捕获的名称被视为本地绑定，而真正未绑定的名称仍然可以解析（#5241，感谢@Max17190）。
  • 修复：c 目录限定角度包含 (#include <dir/header.h>) 解析为匹配的本地文件，并且标准库标头（<stdio.h>、<functional>）远离别名索引，因此不会将同名项目文件修复到它们上；共享目录限定名称的本地标头仍然可以解析（#5218，感谢@Yi-111-a）。
  • 修复： sql 以非 ASCII 字母命名的表，其语法折叠为裸 _ 不再创建具有空 id 的节点或空 id 的边；假边缘被丢弃（#5250，感谢@grbr2010）。
  • 修复： dedup 前缀派生单词与其基本单词分开，因此反义词和前缀对（synchronous/asynchronous、cyclic/acyclic、reload/load）不再通过模糊标签合并折叠在一起，而像 handler/handlers 这样的真正词形变化仍然合并（＃5239，感谢@Deepanshu-Mehta）。
  • 修复：构建跨语言边缘防护的系列表不再偏离提取器的：37 个没有系列条目的扩展（因此永远不会删除巧合的跨语言名称冲突）得到协调，并且如果两个表再次出现分歧，则测试将失败 CI（#5247，感谢 @Yi-111-a）。
  • 修复：安装 graphify claude install 将其部分写入克劳德代码实际读取的文件中。仅当项目或其上方的任何目录中不存在 CLAUDE.md（CLAUDE.md、.claude/CLAUDE.md、CLAUDE.local.md）时，Claude Code 才会读取项目的 AGENTS.md，因此在 AGENTS.md 旁边创建 CLAUDE.md 会默默地向 Claude Code 隐藏 AGENTS.md。现在安装的目标是现有的 CLAUDE.md/.claude/CLAUDE.md（如果存在），否则是现有的 AGENTS.md/.claude/AGENTS.md，否则是像以前一样的新 CLAUDE.md；卸载是对称的（#5277，感谢@andrebrait）。
  • 修复：安装 graphify install 拒绝覆盖它无法解析的现有 Kilo 配置，而不是默默地用仅 graphify 文件替换它并丢失用户的设置；有效或丢失的配置仍然像以前一样合并（#5265，感谢@divya0795）。
  • 修复：分析两个文件导入周期在枚举上限填充之前列出，因此在具有许多较长周期的图表上，不再删除最紧密的（相互两个文件）周期；该列表现在在运行中也是确定性的（#5267，感谢@divya0795）。
  • 修复： 提取 网络收缩防护未针对没有任何保护的源（从未生成任何已保存节点的源，例如未安装可选语法额外的文件）进行武装，因此此类源不再阻止稍后合法收缩图形的提取；确实保存了记录的消息来源仍然武装警卫（#5245，感谢@ayushcodes10）。
  • 修复：构建折叠 Markdown 文档孪生保留了幸存者的结构：真正的标题节点不再被误认为是页面的语义孪生，并且页面节点（及其 frontmatter 和 contains 边缘）被保留，而真正的语义孪生仍然折叠（#5272，感谢 @sdivyanshu90）。
  • 修复：构建符号链接语料库别名被独立修剪：排除或删除一个符号链接别名不再会删除其目标或解析为同一文件的同级别名，因为修剪匹配现在键在语料库路径上，而不是解析的物理目标（#5273，感谢@sdivyanshu90）。
  • 修复：pascal 树保姆语法无法端到端解析的单元（例如带有转义 SQL 字符串文字的单元）通过保留字节长度的屏蔽重试来恢复，而不是产生任何节点；重试仅在正常解析出错时运行，并且仅在严格更健康的情况下才被接受，因此已解析的单元不会改变（#5264，感谢@patrykseksymfonia）。
  • 修复：pascal 基类解析为其声明单元中的真实声明，而不是与文件名约定匹配的存根，因此 inherits 边缘和通过它继承的调用可以跨文件解析（#5280，感谢 @patrykseksymfonia）。
  • 修复：pascal 通过全局对象变量（DM.Open，Delphi 数据模块习惯用法）的调用解析为变量的类型成员：提取器记录单元级全局变量、每个类字段和每个例程影子，并且解析通过使用子句绑定合格的调用失败关闭，当字段、本地或数组类型的全局影子名称时，它无法解析（#3101，谢谢@patrykseksymfonia）。
  • 功能：delphi 表单 (.dfm/.lfm) 链接到实现它的单元：表单类和每个 OnClick = Handler 存根获得到同级 .pas 中真实类和方法的推断 references 边缘，通过基本名称和唯一的类/方法查找配对（#5281，感谢 @patrykseksymfonia）。 AST 缓存模式增加到 48；热缓存重新运行受影响的 Go、Java、JS/TS、C/C++、SQL 和 Pascal 提取。
