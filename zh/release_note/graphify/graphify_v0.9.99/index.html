graphify v0.9.99

0.9.99 (2026-10-30)

  • 功能：路径 当多条路由长度相等时，graphify path 和 MCP shortest_path 工具报告最保守的一条：在所有最短路径中，选择最弱跳数最弱的路由，摘要指出它是 N 条等长路由中最弱的路由。以前返回的是任意等长路由，因此置信度可能会夸大连接的确定性。这是 #4881 的后半部分（前半部分，在 also_seen 中保留折叠边的较弱证据，通过 #4891 在 0.9.98 中发送，感谢@SyedFahad7）。
  • 修复：go 包级 var 初始化程序中的调用（包括在 func-literal 闭包内部，常见的可交换挂钩模式）被记入文件节点而不是被删除（#2360，#4867，感谢 @nothariharan）。
  • 修复：go 作为函数参数 (Wrap(s.Health)) 传递的方法值被链接为 indirect_call，使 Go 与 Python/JS 的按方法值回调具有同等地位；保守地防范现场访问误报（#1566，#4868，感谢@nothariharan）。
  • 修复：go 接收者的字段（其结构在同一包的同级文件中声明）被键入，因此其成员调用在通常的 struct-here-methods-there Go 布局中解析，并且字段类型在增量重建中保持不变（#3368，#4866，感谢 @nothariharan）。
  • 修复：调度表中列出的 python module.func 值（{"a": mod.func_a}，包括嵌套集合）解析为引用的函数为 indirect_call，而不是被删除；不可调用、类和本地接收器值保持不变（#1566、#4773，感谢@nothariharan）。
  • 修复：安装 Gemini 在 Windows 上获得自己的全局技能目录（~/.gemini/skills/graphify），而不是与 agents 平台的目录冲突；预先存在的 agents 技能被记录下来，而不是被删除（#2800，#4770，感谢@nothariharan）。
  • 修复：安装全局 OpenCode 插件写入 ~/.config/opencode（与全局技能位于同一位置）而不是当前目录，安装/卸载/刷新保持对称，遗留位置仍然清理（#3398，#4771，感谢 @nothariharan）。
  • 文档：技能“按顺序执行这些步骤。不要跳过步骤。”指令被改写为“除非上面的快速路径适用”，解决了与所有生成的主机上现有图快速路径的矛盾（#4061，#4721，感谢@nothariharan）。
  • 功能：服务 path、explain 和 neighbors/get_neighbors 将边缘存储的 confidence_score 与其标签 ([INFERRED 0.75]) 一起打印； EXTRACTED 保持裸露（定义为 1.0），缺失或非有限分数保留裸露标签。由最弱跳路径摘要和 also_seen 证据标签组成（#4882，#4888，感谢@SyedFahad7）。
