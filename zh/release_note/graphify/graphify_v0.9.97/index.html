graphify v0.9.97

0.9.97 (2026-10-27)

  • 安全性：基本原理修订基本原理标签的凭证修订移动到单个预缓存阻塞点（_safe_extract 内的 _redact_rationale_labels），因此没有提取器可以跳过它，并且它现在涵盖更多泄漏形状：带有空用户或密码中带有 //@ 的 URL userinfo、PEM 私钥主体、通过 _ 粘合到周围文本的令牌（例如ghp_...)、Slack xoxe- 刷新令牌、短 JWT 和 Common Lisp 文档字符串（以前无需编辑即可构建标签）。良性字符串（哈希、sk- 散文、没有用户信息的 URL）将被单独保留（#4647，感谢 @0xkaushik-ai）。
  • 安全性：depsanyio 在 CVE-2026-63374（IDNA 2003 与 2008 主机名验证旁路，允许非 ASCII 域上的 MITM 为不同 ASCII 主机 CVSS 9.3 提供证书）之上的 mcp extra 中降至 >=4.14.2。 anyio 只是一个传递依赖项，并且锁定文件已经解析了 4.15.1，因此这是阻止未来重新解析回归的底线。
  • 修复：markdown ATX 标题按照 CommonMark 解析：# 的尾随运行不是标题文本的一部分（## Setup ## 是“Setup”），最多允许三个缩进空间（四个是缩进的代码块），并且像 ## ## 这样的仅散列行不会生成任何节点（#4790、#4791，感谢 @jaimemartinez）。
  • 修复：markdown 围栏代码块由 CommonMark 规则（反引号和波形围栏、信息字符串、匹配闭合长度）跟踪，因此看起来像围栏内标题的行不再作为结构泄漏，并且包含 ``` 行的 ~~~ 块之后的标题不再丢失（#4787、#4788，感谢 @jaimemartinez）。
  • 修复： yaml 结构提取读取组成的节点树，因此键携带其书面拼写和自己的源代码行，而不是全部落在第 1 行，并且 YAML 1.1 裸键（如 on/off/yes/no）不再折叠为布尔值（工作流 on: 块被提取，而不是变成True 节点）（#4784，#4785，感谢@jaimemartinez）。
  • 修复：razor 组件的 @implements 接口被提取为 implements 边缘，而不是默默地丢弃（#4820，感谢 @ayushcodes10）。
  • 修复：terraform 别名提供程序块获得自己的别名限定节点（因此两个 provider "aws" 块不再合并为一个并丢失属性），并且 provider = aws.west 引用解析为它而不是悬空；字面上名为 provider 的 local 不再被误读（#4819，感谢 @ayushcodes10）。
  • 修复：嵌套 END PROGRAM 后面的 cobol 段落通过程序堆栈重新附加到封闭程序，而不是坚持嵌套程序（#4824，感谢 @ayushcodes10）。
  • 修复：blade wire:click 指令绑定裸方法名称：匹配点修饰符（wire:click.prevent="submit"），从名称中修剪调用参数（deleteItem(5) 绑定 deleteItem），并且 $ 前缀的魔术动作不会产生任何伪造的边缘（#4823，感谢 @ayushcodes10）。
  • 修复：pascal record 在正则表达式回退中被识别为具有自己的方法的类型（默认路径，没有可选的 pascal 额外），与树保姆路径匹配； operator 成员也被提取（#4825，感谢@ayushcodes10）。
  • 修复：vbnet Operator 声明被提取为其类的 operator 类型成员，并且其主体会被遍历以进行调用，因此运算符内部的辅助调用不再消失（#4821，感谢 @ayushcodes10）。
  • 修复：fortran call 使用提取器自己的跨文件存根习惯用法解析为它实际命名的子例程，而不是使用调用文件名称（从未解析）加盐的目标（#4795，感谢 @ayushcodes10）。
  • 修复：cli graphify query --help/-h（现在为 graphify explain --help/-h）不打印用法，而不是对文本“—help”运行文字查询；仅包含“—help”作为子字符串的较长问题仍然作为查询运行（#4830，感谢@curl-man）。
  • 修复：js 嵌套（内部）函数不再泄漏到文件范围名称映射中，因此文件中其他位置的调用绑定到该名称的顶级函数，而不是它看不到的内部函数；递归、阴影和同级作用域正确解析（将 Python 作用域方案移植到 JS/TS）（#4767，感谢 @smngvlkz）。
  • 修复：ocaml and 链式 module ... and ... 或 class ... and ... 中的每个绑定都会被提取，而不仅仅是第一个，因此后面的绑定不再被默默删除；每个都有自己的源代码行（#4822，感谢@ayushcodes10）。
  • 修复：verilog SystemVerilog 类 task 方法的建模类似于 function 方法（其自己的节点、method 边缘和参数类型引用），并且任务局部变量不再作为类上的错误字段引用而泄漏（#4774，感谢 @ayushcodes10）。
  • 修复：在构建和原始 --no-cluster 写入路径上，构建 没有 relation 的边缘被删除而不是保留，并且别名折叠（relationship 到 relation）在检查之前运行（#4810，感谢 @legendteddy；重现器也由 @sunhouy 归档为 #4826）。
  • 修复：构建收缩保护对保存的文档提及节点进行计数，该节点在重新加载时折叠到其 AST 文件孪生中，而不是丢失，因此当实际上没有丢失任何内容时，不再拒绝仅集群写入（#4778，#4779，感谢@AndresDiagoM）。
  • 修复：检测一个链接的 git 工作树，其主要签出解析在扫描根内部被修剪，因此同级工作树不再被索引为存储库的第二个完整副本（#4683，#4833，感谢@barlowa124；@AndresDiagoM 在#4685 中的重复工作）。
  • 修复：解决 pnpm-workspace glob 中的内联注释会根据 YAML 规则被删除，并且 Path.glob 拒绝的 glob（** 组件或绝对模式）会被跳过并发出警告，而不是导致整个 extract 运行崩溃（#4681、#4687，感谢 @Deepjyoti-Sarmah）。
  • 修复：报告社区中心 [[wikilink]] 通过导出使用的同一个 export._obsidian_safe_stem 进行重击，因此链接与导出实际写入的文件匹配，而不是悬空（#4696，感谢 @ayushcodes10）。
  • 修复：wiki 仅按字母大小写重新标记的社区保留其文章，而不是让扫描删除运行刚刚写入的文件；在区分大小写的文件系统上，陈旧的小写双胞胎被取消链接，而不是在新文件上重命名（这将默默地恢复旧的文件体）（＃4508，＃4798，感谢@dupeisen）。
  • 修复：查询填充动词 get/gets/got/getting 从查询术语中删除（如现有的 work/works），因此标记为“Get”的框架中心不会通过精确匹配奖励作为 BFS 种子拉入；对文字 Get 的节点查找仍然可以解析（#4686，感谢 @AndresDiagoM）。
