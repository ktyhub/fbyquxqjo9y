graphify v0.9.104

图形化 0.9.104

  • 安全性：技能 /graphify Runbook 不再将扫描路径替换为 Python 代码。现在，每个生成的代码块（检测、AST 和语义提取、构建、诊断、标签、清单和 --update）都从步骤 1 通过引用的heredoc 写入的 trusted graphify-out/.graphify_root sidecar 读取已解析的扫描根，而不是将代理提供的路径粘贴到字符串文字中。名称带有引号或 $(...) 的目录以前可以突破 Path('INPUT_PATH') 并作为代码运行；现在它被读取为惰性数据。涵盖组装好的主机和 Aider/Devin 巨石（#4762，感谢 @danikdanik）。
  • 修复：可靠性对合约或接口类型（IERC20 token; token.transfer()、IERC20(a).transfer()、token().balanceOf()）接收者的调用通过该类型的线性化按名称和数量绑定到类型自己的声明，而不是产生任何边缘；门控到单个可见的合约/接口，并在未知或不明确的类型上失败关闭（#5060，感谢@rohit-jsfreaky）。
  • 修复：solidity 由 using A for T 指令 (using SafeCast for uint256; x.toUint48()) 附加的调用绑定到它附加的库或自由函数，与接收者的类型和比调用大 1 的元数相匹配；当接收器类型未知、库不明确或两个函数适合时失败关闭（#5062，感谢@rohit-jsfreaky）。
  • 修复：一个范围内的solidity成员、自由函数和类型，其名称仅因前导 _ 或大小写（_grantRole / grantRole）不同而获得单独的节点 ID，因此 _ 符号不再消失在其孪生中，并且其调用落在正确的节点上（#5027，感谢 @rohit-jsfreaky）。
  • 修复：csharp 构造函数（实例、静态或主）是其类型拥有的自己的节点，其主体和 : base(...)/: this(...) 调用记入它； new X(...)、: base(...) 和 : this(...) 附加地链接了元数正确的重载，并且两个拟合重载或未解析的基数不会给出构造函数边缘（#5054，感谢@rohit-jsfreaky）。
  • 修复：属性或索引器访问器、表达式主体或运算符/转换主体内的 csharp 调用将记入该成员而不是丢失；索引器成为 this[] 节点，操作员成为 .operator +() 节点（#5056，感谢 @rohit-jsfreaky）。
  • 修复：查询作为查询术语唯一匹配的相同标签节点保留为种子，而不是被每个标签上限删除，因此每个不同的术语至少保留一个种子，而通用标签泛洪保持上限（＃5027，感谢@Vaibhav2824）。
  • 修复：watch 只读事件通过仅更改的 event_filter 保留在 inotify 掩码之外，因此大树不再将看门狗驱动到自我维持的队列溢出循环中；在没有 event_filter 支持的看门狗版本上回退并发出警告（#5033，感谢@Deepjyoti-Sarmah）。
  • 修复：缓存 \\?\ 长路径拼写不包含在缓存标识中，因此通过 \\?\C:\... 和 C:\... 到达的同一文件共享一个条目；还修复了 UNC 共享下的空统计索引写入、Windows 上的虚假“统计索引切换”警告以及错误共享其目标摘要的联结/符号链接别名（#5035，感谢 @Bortlesboat）。
  • 修复：缓存 stat-index 键在 Windows 长路径根下保持根相对，因此移动或克隆的语料库保留便携式密钥快速路径（#5035，感谢 @Vaibhav2824）。
  • 修复：测试 TypeScript unicode 固定装置在每个平台上都以 UTF-8 形式编写，因此字节偏移量与 Windows (cp1252) 主机上的提取器匹配（#5064，感谢 @ayushcodes10）。
  • 修复：测试 hook-freshness 源模拟通过 os_long_path 进行规范化，因此 read-error/stale 分支实际上在 Windows 上执行（#5065，感谢 @ayushcodes10）。
  • 修复：测试手表挂起队列测试比较 Path 对象，因此 / 和 \ 分隔符在 Windows 上比较相等（#5039，感谢 @Yi-111-a）。
  • 修复：提取不明确的 Python 导入的占位符节点 id 是从与签出无关的数据（模块名称、扫描根相对源文件、位置）而不是绝对路径进行哈希处理，因此不同路径或移动的缓存中的同一项目会获得相同的 id（#5045，感谢 @Fardin7798）。
  • 修复：yaml 使用 CloudFormation 内在标记（!Ref、!GetAtt、!Sub）的模板不再无法解析：作用域许可加载程序会重建每个 ! 标记节点的形状而不对其进行评估，而 !!python/... 标记仍然会引发并且从不执​​行（#5077，感谢 @ayushcodes10）。
  • 修复：观看 --watch 增量更新会在 graph.json 丢失时重建完整语料库，而不是单独从清单中编写部分图表（#5020，感谢 @azizur100389）。
  • 修复：观看 JS/TS 分辨率输入（tsconfig.json、jsconfig.json、锁定文件）的更改会触发完全重建，因此导入器会选择新的分辨率，而不是留下陈旧的 imports_from 边缘（#5020，感谢 @azizur100389）。
  • 修复：摄取同一 URL 的两个并发 graphify add 捕获不再相互干扰：捕获文件是专门创建的 (O_EXCL)，并且冲突会重试新名称，并获取一次有效负载（#5020，感谢 @azizur100389）。
  • 修复：反映学习覆盖中格式错误的条目被跳过，而不是使整个负载崩溃，并且遗留的空源条目被保留为无源注释（＃5020，感谢@azizur100389）。
  • 修复：全局 全局清单中格式错误的存储库条目会自行删除，保留其他跟踪的存储库，并且仅备份和重置非对象根或存储库映射（#5020，感谢 @azizur100389）。
  • 修复：查询在子文件夹上新构建的图表不再被标记为 #1504 之前的版本（这会引发无操作 extract --force）：legacy-id 探针在派生文件茎之前剥离 .graphify_root 偏移量，并且仍然捕获真正的遗留图表（#5019，感谢 @neumannpeter1231-lang）。
  • 修复：tree graphify export tree 可以识别 src 节点别名（以及 file/path/filepath），因此带有这些键的图形会呈现一棵已填充的树而不是空树；仅概念图仍然报告为空（#5030，感谢@Adityakk9031）。
  • 修复：cli graphify provider add 接受 --pricing-input=VALUE/--pricing-output=VALUE 等于语法，并以干净的错误拒绝非数字、非有限或负价格，而不是回溯或有毒的成本估算（#5031，感谢 @Adityakk9031）。 AST 缓存模式增加到 40；热缓存重新运行受影响的 Solidity 和 C# 提取。上述 Python 和 YAML 修复不需要碰撞（占位符 id 在每个文件缓存后解析，并且之前失败的 YAML 从未被缓存）。
