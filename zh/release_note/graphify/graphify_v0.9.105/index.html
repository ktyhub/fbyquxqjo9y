graphify v0.9.105

图形化 0.9.105

  • 修复：从Linux监视树中删除watch忽略的目录（node_modules、.git、构建输出），因此大型项目不再注册数以万计的浪费的inotify监视并冒ENOSPC的风险；非 Linux 递归观察器没有改变，并且仍然会在每次真正的更改时触发（#5074，#5091，感谢 @Deepjyoti-Sarmah）。
  • 修复：cpp 通过在其他标头中声明的类字段（client.actions->Execute()，值为 .、原始指针 -> 和单参数 unique_ptr/shared_ptr 接收器）路由的成员调用链解析为跨包含集的字段类型成员，门控为唯一类型和成员，否则会失败；类位于另一个存储库中的类型化本地被停放以进行跨存储库合并（#5098，感谢@xRedLeader）。
  • 修复：markdown 命名大写 \ 命名空间类（\Foo\Bar、App\API）或类型限定方法调用（Type::member()）的代码范围保留为符号提及而不是被删除，而非调用 Type::CONST/Type::class 保持删除（#5093，感谢 @Adityakk9031）。
  • 修复：ts/js 通过解构的 CommonJS 桶要求（const { Thing } = require('./barrel')，其中桶重新导出 Thing）的调用通过遵循桶的导出来解析为真实声明，而不是删除边缘（#5034，#5104，感谢 @qq2514568380）。
  • 修复：wiki 孤儿扫描折叠为 casefold（不是 lower），因此仅在完整 Unicode 大小写折叠（Straße/STRASSE、Σ/ς）下发生冲突的两个文章名称各自保留自己的文件，而不是作为孤儿删除一个文件；这次运行写入的文件永远不会被清除（#5087，#5102，感谢@nothariharan）。
  • 修复：构建超边在增量 graphify update 中保持完整：它们是从仅 JSON 编写器使用的嵌套图槽中读取的，并且在删除源修剪后，超边仅删除其已删除的成员（仅当没有剩余成员时才删除其自身），而不是默默地丢失或留下悬挂的超边（#5081、#5103，感谢 @nothariharan）。
  • 修复：缓存降级（生产不足）的语义缓存条目不再固定语料库：在收缩防护看到重新提取返回的数据小于存储的图之后，该条目被标记为 partial，因此下一次运行会重新分派它，而不是永远重播降级的结果（#5083，#5101，感谢 @nothariharan）。
  • 修复：受影响的 graphify affected <file> 传递地播种文件的嵌套成员节点（类内的方法），而不仅仅是一跳，因此影响分析不再低估绑定到嵌套成员的调用者（#5094，感谢 @Adityakk9031）。
  • 修复：tree build_tree 从文件父级派生公共目录根，因此单文件或单目录树不再自我嵌套在文件本身下（#5092，感谢@Adityakk9031）。
  • 修复：查询名称位于模式或命名空间限定符（public.sweep_widget_state()、fmt.Println）后面的标签在其尾部与整个查询匹配，并排名在每个令牌层之上，因此它不再被单令牌冲突节点竞争并从种子中删除（#5080，#5095，感谢@sunhouy）。
  • 修复：检测增量过时检查会散列一个文件，该文件的时间戳落在其 mtime 两侧的时钟偏差窗口内，因此不移动 mtime 的相同滴答重写仍然会被捕获，而不是被提供为过时的（#5090，感谢 @sunhouy）。
  • 修复：路径 graphify path A B 拒绝其单词出现在图中任何地方的端点（未找到退出），而不是返回由松散重叠的令牌构建的误导性路线（#5085，感谢@sunhouy）。
  • 修复：csharp 经典的扩展​​方法调用（x.Foo()，其中 Foo 声明为 static ... Foo(this X x, ...)）通过在名义分派后运行的附加传递绑定到扩展方法的声明，门控到可见名称空间、匹配的 this 类型和唯一的适用方法；同名的实例方法获胜，非扩展静态或未导入的扩展没有优势，并且歧义无法关闭（#4828，#4849，感谢@Deepjyoti-Sarmah）。
  • 修复： markdown 散文中的裸露的、不合格的自由函数提及（token、无 () 且无命名空间）仅当在标题的节链中引用其定义文件（或其中的另一个符号）时才绑定到同名函数，而不是匹配语料库中的任何同名可调用函数；参考样式链接（[text][label]）在使用站点解析（#4804，#4806，感谢@madanlalit）。
  • 修复：导出 to_json 收缩保护不再将重新提取时替换或修剪为删除的语义源视为“丢失”，因此不会拒绝合法的 graphify update；真正的不明原因的心理咨询仍然被拒绝（#5107，感谢@khkar）。
  • 修复：构建一个节点，其 file_type 或 confidence 作为来自漂移 LLM 传递的结构化值（列表/字典）到达，不再使验证/构建成员资格检查崩溃：验证将其显示为模式错误，并且构建将其折叠到 concept/INFERRED 而不制造分数（#5088，感谢 @sdivyanshu90）。
  • 修复： llm 字符上限下方的可分割文档，其模型输出截断被提升为全范围切片并二等分（并重试），而不是保留为截断的部分结果；不可分割或代码/二进制单元仍然无法关闭（#5072，#5078，感谢@aadilrizwan）。
  • 功能： llm 自定义 OpenAI 兼容提供程序的 extra_headers 作为 default_headers 转发到 client，范围仅限于该提供程序，并删除任何 Authorization 标头，因此它无法覆盖配置的凭据（#3680、#4783，感谢 @jaimemartinez）。
  • 性能：提取全图中间体（一次性 CLI 上的解析备忘录、构建/集群/导出工作列表）在消耗后立即释放，从而减少大型语料库上的峰值内存；图形输出是字节相同的（#5063，感谢@TPAteeq）。
  • 修复：skillgenclaw/kiro/pi 子代理提示现在告诉工作人员将其块写入 CHUNK_PATH，因此磁盘调度块不再内联返回并在合并步骤中丢失（#5040，感谢 @connhodendatabase）。
  • 修复：取决于，pdf 和 all 附加功能中的 pypdf 下限提升至 6.21.4，以获取其安全修复程序（#5015，感谢 @yotamleo）。 AST 缓存模式增加到 42；热缓存重新运行受影响的 C++、Markdown 和 C# 提取。
