accelerate v1.2.0

这个项目是干啥的：一个帮PyTorch模型轻松在多张显卡或多台机器上训练的工具，配置简单还能组合并行，给搞AI训练的工程师用。

变更架构图

亮点

  • 完整的 TorchDynamo 配置 — Accelerator 现在接受 dynamo_plugin=TorchDynamoPlugin(...)，暴露插件除 backend 和 mode 快捷方式之外的完整配置。传 dynamo_plugin 或 dynamo_backend 之一；两者同时提供会抛 ValueError（#3251）。
  • 可选启用的 device-map 回收 — infer_auto_device_map(..., fallback_allocation=True) 在默认策略会因内存紧张而让某个加速器闲置时，可以放置一个更小的模块。现有行为仍是默认值，同时诊断信息现在会指出被跳过的设备及其最低内存要求（#3066）。
  • 更安全的 offload 与嵌套 dispatch — get_state_dict_offloaded_model 现在会在 CPU 上物化缓冲区，align_module_device 只移动直接参数，get_state_dict_from_offload 不再迁移非 offload 的模块（#3217、#3253）。preload_module_classes 现在能触及嵌套子模块，修复检查点 dispatch 期间的 meta-device 失败（#3248）。
  • 训练循环兼容性 — DataLoaderShard.set_epoch() 现在会把 epoch 转发给实现了 set_epoch() 的自定义 batch sampler，让其按 epoch 变换洗牌（#3246）。DeepSpeed CPU offload 会为 AdamW、Adagrad 和 32 位 Lion 选择对应的 CPU 优化器，而不总是用 CPU Adam；其他优化器类仍回退到 CPU Adam。被包装的 schedule-free 优化器现在也能正确收到 train()/eval()（#3255、#3266）。
  • 更广的后端支持 — find_executable_batch_size 能识别 XPU 的显存不足错误（#3236）；安全反序列化在 NumPy 2 上使用 numpy._core，同时保留 NumPy 1 路径（#3247）；bitsandbytes ≥0.43.2 时 4-bit 模型不再需要强制 dispatch hook，降低开销（#3223）。
  • 破坏性变更 — 未宣布。

核心

  • 通过https://github.com/huggingface/accelerate/pull/3236中的@faaany在XPU上启用`find_executable_batch_size`
  • 在 https://github.com/huggingface/accelerate/pull/3247 中使用 @qgallouedec 的 numpy._core 代替 numpy.core
  • 在https://github.com/huggingface/accelerate/pull/3066中@Nech-C为infer_auto_device_map中未分配的设备添加警告和回退
  • 允许 https://github.com/huggingface/accelerate/pull/3251 中的@muellerzr 将完整的发电机配置传递给加速器
  • [WIP] FEAT Decorator 用于清除加速环境变量，由 @BenjaminBossan 在 https://github.com/huggingface/accelerate/pull/3252 中实现
  • [data_loader] 还可以选择将 set_epoch 传播到 https://github.com/huggingface/accelerate/pull/3246 中的 @tomaarsen 的批量采样器
  • 在 https://github.com/huggingface/accelerate/pull/3268 中 @faaany 的 accelerate config 提示文本中使用 XPU 而不是 GPU

大建模
