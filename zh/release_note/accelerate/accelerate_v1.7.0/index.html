accelerate v1.7.0

accelerate v1.7.0

变更流程图

亮点

  • 区域化 torch.compile 编译 — 像 decoder 层这样的重复块现在可以独立编译和缓存，降低大模型的冷启动编译时间。在调用 accelerator.prepare() 前用 TorchDynamoPlugin(use_regional_compilation=True) 即可启用；CLI 和环境变量支持在 #3572 中加入。
  • 逐层类型转换以降低推理显存 — 新增 attach_layerwise_casting_hooks() API（#3427），把参数存储精度与计算精度分离——例如 FP8 存储、BF16 计算——以降低内存占用。在依赖 FP8 存储前，请先针对你的模型和工作负载验证输出质量。
  • FSDP2 检查点与内存改进 — FULL_STATE_DICT 支持（#3527）让 Transformers 的 .save_pretrained() 能用于 FSDP2 包装的模型。CPU-offload 后端选择（#3574）和 cpu_ram_efficient_loading=True 的内存尖峰（#3482）也得到修复；QLoRA 支持（#3546）已可用，但仍需更广泛验证。
  • 隐式 torch.compile 动态行为的破坏性变更 — 当 USE_DYNAMIC 未设置时，插件现在保留 dynamic=None，而不再默认取 False（#3567），让 torch.compile 自行选择动态形状行为。如果你依赖此前隐式的静态默认值，请显式设置 dynamic=False。
  • 分布式训练正确性修复 — set_epoch() 现在真正生效（#3556），这对采样器顺序和跨 epoch 的可复现性很重要。同时防止分布式处理中 GPU 被重复使用（#3526），减少多 GPU 作业的资源争用。

区域编译

区域编译首先针对重复的块（例如解码器层），而不是立即编译整个模型。这允许编译器缓存并重用后续块的优化代码，从而显着减少第一次推理期间通常出现的冷启动编译时间。感谢@IlyasMoutawwakil 提供的功能！您可以此处查看完整的基准测试，并查看我们更新的编译指南以了解更多详细信息！ 要启用此功能，请在 TorchDynamoPlugin 配置中设置 use_regional_compilation=True。

# Configure the compilation backend
dynamo_plugin = TorchDynamoPlugin(
    use_regional_compilation=True,
    ... # other parameters
)
# Initialize accelerator with the plugin
accelerator = Accelerator(dynamo_plugin=dynamo_plugin)
# This will apply compile_regions to your model
model = accelerator.prepare(model)

分层铸造钩子

我们引入了一个新的钩子，可以在推理过程中启用每层向上和向下转换（例如，对于线性层）。这允许用户使用单独的存储和计算数据类型运行模型，从而节省内存。该概念首先在 diffusers 中实现，其中将模型向下转换为 FP8 被证明是有效的，且质量不会出现重大下降。由 @sayakpaul 在 https://github.com/huggingface/accelerate/pull/3427 中贡献

model = ....
storage_dtype = torch.float8_e4m3fn
compute_dtype = torch.bfloat16
attach_layerwise_casting_hooks(
            model,
            storage_dtype=storage_dtype,
            compute_dtype=compute_dtype,
        )

更好的 FSDP2 支持

此版本包含许多新功能和错误修复。值得注意的是，我们增加了对 FULL_STATE_DICT（FSDP 中广泛使用的选项）的支持，现在使 Transformer 中的 .save_pretrained() 能够与 FSDP2 封装模型一起使用。现在也支持 QLoRA 培训，但需要更多测试。我们还解决了与参数卸载到 CPU 相关的后端问题。此外，启用 cpu_ram_efficient_loading=True 时发生的显着内存峰值已得到修复。还包括其他一些小的改进和修复 - 请参阅更改内容部分了解完整详细信息。

  • FULL_STATE_DICT 已由 https://github.com/huggingface/accelerate/pull/3527 中的 @S1ro1 启用
  • @winglian 在 https://github.com/huggingface/accelerate/pull/3546 中的 QLoRA 支持
  • 在 https://github.com/huggingface/accelerate/pull/3574 中正确设置 CUDA+FSDP2+cpu-offload 的后端
  • 在 https://github.com/huggingface/accelerate/pull/3482 中通过 @S1ro1 使用 cpu_ram_efficient_loading=True 时修复了内存峰值

更好的 HPU 支持：

我们为 Intel Gaudi 硬件添加了 文档！ 自 v1.5.0 起，已通过此 PR 提供支持。

  • 通过@yuanwu2017在https://github.com/huggingface/accelerate/pull/3495中将HPU添加到加速配置中
  • 在 https://github.com/huggingface/accelerate/pull/3537 中添加 @regisss 的 Gaudi 文档

Torch.compile 对 dynamic 参数的重大更改

我们更新了设置 self.dynamic 的逻辑，以显式保留 None，而不是在未设置 USE_DYNAMIC 环境变量时默认为 False。此更改使行为与 torch.compile 的 PyTorch 文档保持一致。感谢@yafshar 在 #3567 中贡献了这一改进。
