accelerate v1.11.0

accelerate v1.11.0

变更流程图

亮点

  • Python 最低版本 3.10 — Python 3.9 在 EOL 后不再支持（#3809），因此升级前请更新 CI 镜像、部署运行时和依赖约束。已弃用的 FindTiedParametersResult 类型也被移除（#3786）；请移除相关 import，或把注解迁移到受支持的 tied-parameter API。

  • Apple MPS 上的混合精度 — MPS 训练现在接受 mixed_precision="fp16" 或 "bf16"（#3373）。FP16 需要 PyTorch 2.8+，BF16 需要 2.6+；启用前请确认你的 Torch 构建版本。这让 Apple Silicon 的训练配置更接近 CUDA 的混合精度工作流。

  • Transformer Engine MXFP8 — 在 fp8_config 中设置 use_mxfp8_block_scaling 即可使用 MXFP8 分块缩放方案（#3688）。这会改变 FP8 量化和缩放行为，而不是一个即插即用的提速开关，因此请按 NVIDIA 硬件和 Transformer Engine 的要求验证精度与吞吐。

  • FSDPv2 特性对齐 — FSDPv2 新增 ignored_params 支持（#3731），能在 no_sync() 内通过 set_requires_gradient_sync(False) 正确抑制梯度同步（#3762），并支持通过 CLI 或 fsdp_config 传入混合精度 dtype 字符串（#3751）。这避免了梯度累积时不必要的 all-reduce 并简化配置，但要确认字符串选择的 dtype 与硬件和 autocast 策略匹配。

  • 分布式可靠性与内存 — CPU-RAM 高效加载现在覆盖 ND 和 HSDP 并行（#3740）；另有修复处理多节点 CUDA 无效设备序号错误（#3779）和 XPU INT64 all_gather 失败（#3756）。大规模分片工作负载将面临更小的主机内存压力和更少的启动/集合通信失败。

TE MXFP8 支持

我们在 TransformerEngine 集成中添加了对 MXFP8 的支持。要使用它，您需要在 fp8_config 中设置 use_mxfp8_block_scaling。请参阅 nvidia 文档 [此处]。 (https://docs.nvidia.com/deeplearning/transformer-engine/user-guide/examples/fp8_primer.html#MXFP8-and-block-scaling)

  • 在 https://github.com/huggingface/accelerate/pull/3688 中通过 @pstjohn 加速添加对 TE MXFP8 配方的支持

MPS 设备的 FP16/BF16 培训

MPS 设备的 BF16 和 FP16 支持终于来了。现在，您在 Mac 上训练时可以通过 mixed_precision = "fp16" or "bf16"（fp16 需要火炬 2.8，bf16 需要火炬 2.6）

  • 通过 @SunMarc 在 https://github.com/huggingface/accelerate/pull/3373 中为带有 mps 设备的放大器添加 bf16/fp16 支持

FSDP 更新

以下 PR 分别添加了对 FSDPv2 的 ignored_params 和 no_sync() 的支持：

  • 修复：https://github.com/huggingface/accelerate/pull/3762 中的 @EquationWalker 应该调用 model.set_requires_gradient_sync(False) 来关闭 FSDP2 中的梯度同步 混合精度现在可以作为 dtype 字符串从加速配置文件中的加速 cli 标志或 fsdp_config 传递：
  • 壮举：允许 https://github.com/huggingface/accelerate/pull/3751 中@kmehant 将混合精度策略作为 dtype
