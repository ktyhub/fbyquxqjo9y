accelerate v1.15.0

v1.15.0：FSDP2 激活内存、dtensor 改进

FSDP2

此版本中有大量 FSDP2 工作：两个修复，以长序列长度削减激活内存，对 torch >= 2.13 的捆绑嵌入支持，以及一轮检查点正确性和规模修复。 激活检查点包装了匹配层（self_attn、mlp、规范）的每个“子项”，而不是层本身，因此每个子项间激活都会保存下来以供向后使用。现在它包裹了该层。 还有一个新的仅 FSDP2 activation_checkpointing_offload，它将剩余的每层检查点输入移动到固定的 CPU 内存。梯度与普通激活检查点的梯度完全相同：

# fsdp2.yaml
fsdp_config:
  fsdp_version: 2
  fsdp_auto_wrap_policy: TRANSFORMER_BASED_WRAP
  fsdp_activation_checkpointing: true
  fsdp_activation_checkpointing_offload: true
accelerate launch --config_file fsdp2.yaml train.py
  • FSDP2 激活检查点：包装匹配的变压器层本身，而不是它的每个子层，由 @qgallouedec 在 #4172 中编写
  • 添加 FSDP2 activation_checkpointing_offload：通过 @qgallouedec 在 #4175 中将检查点层输入卸载到固定 CPU 内存
  • 修复 torch >= 2.13 上的 FSDP2 捆绑嵌入模型：将输出嵌入放在 @qgallouedec 的同一个 full_shard 组中 #4171
  • 修复 FSDP2/PEFT/FULL_STATE_DICT 删除除 0 级之外的每个等级的适配器碎片，由 @AmineDiro 在 #4206 中完成
  • FSDP2：每个等级的 torch.save/load 用于 SHARDED_STATE_DICT，以修复 #4105 中 @gygdh-001 的 2800+ NPU 检查点超时
  • 修复了@HaomingSong 在#4119 中的 FSDP 分片检查点路径解析
  • 当 @qgallouedec 在 #4180 中在没有分片尺寸的网格上启用 FSDP 时，会出现明显的错误

D 张量

针对 DTensor 分片模型的两个修复，您可以使用 FSDP2、张量并行性或任何 N 维并行性设置来实现：当普通张量和 DTensor 混合时，梯度 clipping 在 foreach 操作上不再失败，并且 prepare_model 会保留已分片的模型：

  • @michaelbenayoun 在 #4219 中对 dtensor 的 Clip 梯度范数支持 -prepare_model：不要将 DTensor 分片模型移动到设备（@qgallouedec 在 #4181 中）

卸载和量化

现在可以将整个模型发送到磁盘，包括绑定权重 - 对于 llm-compressor 这样的工具非常有用，这些工具可以在无法容纳大型模型的机器上压缩大型模型：

  • [卸载] 支持@kylesayrs 在 #4083 中的全盘卸载
  • 修复@shoemoney 在 #4151 中 FP8 张量上的磁盘卸载崩溃问题

追踪器

自定义跟踪器可以按名称注册，然后像任何内置跟踪器一样从 log_with= 中进行选择：

from accelerate import Accelerator
from accelerate.tracking import register_tracker_class

register_tracker_class(MyTracker)  # MyTracker.name == "my_tracker"
accelerator = Accelerator(log_with="my_tracker")
  • 添加 register_tracker_class 以通过 @javierdejesusda 在 #4060 中的名称注册自定义跟踪器
  • 修复 MLFLOW_NESTED_RUN 永远无法关闭嵌套的问题（@yupengtang 在 #4223 中）
