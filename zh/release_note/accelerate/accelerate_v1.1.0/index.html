accelerate v1.1.0

这个项目是干啥的：一个帮PyTorch模型轻松在多张显卡或多台机器上训练的工具，配置简单还能组合并行，给搞AI训练的工程师用。

变更架构图

亮点

  • 移除 Python 3.8 支持 — PR #3194（“Goodbye Python 3.8!”）是头号破坏性变更：v1.1.0 要求 Python 3.9+。如果训练环境锁定在 3.8，请留在 v1.0.1，或先升级解释器再升级——否则安装/依赖解析会硬性失败。
  • 检查点默认以 weights_only=True 保存/加载 — PR #3036 把所有兼容对象的 torch.save 切换到更安全的序列化模式。这是一项值得测试的安全与行为变更：加载时能防御任意 pickle 代码执行，但包含自定义类或非张量对象的检查点可能无法加载，除非把它们注册为 safe global（或显式退出该模式）。
  • Megatron-LM 插件升级到 0.8.0+ — PR #3174 更新插件代码，要求 Megatron-LM 0.8.0 或更高。这是第二处兼容性破坏：Megatron 用户必须同步升级 Megatron-LM，否则插件会失配。
  • 专属 data_seed 提升可复现性 — PR #3150 增加 data_seed 参数，让你独立于模型初始化/分片种子来控制数据采样随机性。当你希望在其他种子变化的多次运行间保持固定数据顺序时很有用——对做严格对照实验的人来说是一次有意义的升级。
  • DeepSpeed 迎来 Torch Dynamo — PR #3069 让 torch.compile/dynamo 能在 DeepSpeed >= 0.14.4 上使用，因此必须升级 DeepSpeed 才能受益。注意：一个损坏的 dynamo 测试在 #3155 中被直接删除，所以请把它视为早期阶段，验证编译后的运行，而不是假定行为等价。
  • 大模型推理工具与 FSDP 陷阱 — PR #3188 新增 has_offloaded_params，PR #3204 新增 align_module_device，更精细地控制 offload 参数状态和设备放置；PR #3159 解锁 CPU bitsandbytes 分布式 LoRA 微调。留意 PR #3154：tied 权重在 FSDP 参数初始化后必须重新绑定，否则 tied embedding 可能静默发散——这是一个不会报错的隐蔽正确性 bug。
