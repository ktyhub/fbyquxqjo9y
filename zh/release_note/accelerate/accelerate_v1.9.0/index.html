accelerate v1.9.0

accelerate v1.9.0

变更流程图

亮点

  • Trackio tracker 支持（PR #3669） — Accelerate 现在接受 log_with="trackio"，这是一个基于 🤗 Datasets/Spaces 构建的免费、本地优先的实验追踪器。日志保存在本地或私有 HF Dataset 中，并可通过 Gradio 面板查看，你可以用 init_kwargs={"trackio": {"space_id": ...}} 把它托管在 Space 上。它沿用现有 tracker 初始化流程，因此采用它基本只是改个配置——对不想付 SaaS 账单的团队来说，这是零成本替代 WandB 的方案。

  • 更快的模型加载（PR #3674） — set_module_tensor_to_device 新增 clear_device 标志以跳过缓存清理，拷贝改用 non_blocking=True，并在控制权返回调用方前只做一次同步。据报 Diffusers 加载提速 4–5 倍；对反复加载大检查点几乎是白捡的收益，但 clear_device 用内存整洁度换速度，长时间运行的进程要盯住显存。

  • 破坏性变更：find_executable_batch_size() 回退策略改变（PR #3684） — OOM 时 batch size 现在按 0.9 缩放，而不是减半。这避免过度缩小 batch、留下 GPU 容量浪费，但意味着收敛前需要更多次重试，且最终 batch size 与 v1.8.x 不同——请重新校准硬编码的 batch size 预期和基准。

  • 分布式训练细节打磨（PR #3640、#3677、#3671、#3629、#3656） — FSDP 获得 e5e2 支持，并在启动器下默认使用混合分片（#3640）；FP8 无需显式配置 Accelerator() 即可使用（#3677）；DDP + DTensor 现在报清晰错误而非莫名崩溃（#3629）；no_sync() 为 DeepSpeed ZeRO-2/3 提供保护（#3656）。这些主要是正确性/健壮性工作——如果你遇到过静默的错误分片或难懂的 DeepSpeed 失败，值得升级。

  • 值得注意的修复 — WandB 配置现在能在离线模式正确保存（#3648），空的基础 dataloader 不再产生幽灵 batch（#3659），示例取消固定 datasets 版本（#3681），无效配置键会发出警告（#3613）。空 dataloader 的改动可能改变边界管线中的循环终止条件，请验证任何依赖旧行为的代码。

Trackio 追踪器支持

我们添加了对 trackio、轻量级、💯 免费实验跟踪 Python 库的支持，该库构建于 🤗 数据集和空间之上。 主要特点是：

  • 本地优先设计：仪表板默认在本地运行。您还可以通过指定 space_id 将其托管在空间上。
  • 在本地保留日志（或在私人拥抱面部数据集中）
  • 使用 Gradio 仪表板在本地（或在 Hugging Face Spaces 上）可视化实验
  • 这里的一切，包括在 Hugging Faces 上托管，都是免费！ 要与加速一起使用，您需要设置 log_with 并初始化跟踪器
accelerator = Accelerator(log_with="trackio")
config={"learning_rate": 0.001, "batch_size": 32}
# init_kwargs in order to host the dashboard on spaces
init_kwargs = {"trackio": {"space_id": "hf_username/space_name"}
accelerator.init_trackers("example_project", config=config, init_kwargs=init_kwargs})

依赖 set_module_tensor_to_device 时的模型加载加速

在清除缓存的同时设置张量非常慢，因此我们添加了 clear_device 选项来禁用它。 另一个小的优化是在各处使用 non_blocking 并在将控制权返回给用户之前进行同步。这使得加载速度稍微快一些。

  • 在 Diffusers 中加速模型加载 4-5 倍 ⚡ by @a-r-r-o-w in https://github.com/huggingface/accelerate/pull/3674

FDSP、Deepspeed、FP8 细微改进

  • 添加对 e5e2 的支持，并在 @IlyasMoutawwakil 在 https://github.com/huggingface/accelerate/pull/3640 中使用启动器时默认为混合模式
  • 修复 FP8 测试，使 FP8 无需直接在 https://github.com/huggingface/accelerate/pull/3677 中通过 @pstjohn 配置 Accelerator() 即可使用
  • @S1ro1 在 https://github.com/huggingface/accelerate/pull/3671 中对 FSDP 进行了一系列改进
  • 修复：https://github.com/huggingface/accelerate/pull/3629 中 @S1ro1 的 DDP + Dtensor 模型正确错误
  • 修复 https://github.com/huggingface/accelerate/pull/3657 中@shimizust 的 fsdp2 示例拼写错误
  • 在 no_sync() 中添加了检查，以避免在 https://github.com/huggingface/accelerate/pull/3656 中 @xliu0105 使用 deepspeed Zero2/3 时出现错误

🚨🚨🚨 重大更改 🚨🚨🚨

find_executable_batch_size() 将不再在每次 OOM 后将批次减半。相反，我们将批量大小乘以 0.9。这应该可以帮助用户不浪费 GPU 容量。 *“停止将我的批次减半！” · 默认退避 0.5 → 0.9 by @SunMarc in https://github.com/huggingface/accelerate/pull/3684
