accelerate v1.13.0

小版本 发布时间2026年3月4日 来源huggingface/accelerate 英文原文

accelerate v1.13.0

AWS Neuron 支持

我们现在支持 AWS Neuron (Trainium/Inferentia) 设备。感谢@michaelbenayoun 添加此内容。

  • @michaelbenayoun 在 https://github.com/huggingface/accelerate/pull/3935 中的神经元整合

XPU 改进

我们删除了 IPEX 依赖项并改进了 XPU 的设备无关代码。

  • 在https://github.com/huggingface/accelerate/pull/3884中@kaixuanliu对XPU设备使用spawn而不是fork
  • 在https://github.com/huggingface/accelerate/pull/3883中通过@yao-matrix删除ipex
  • 通过https://github.com/huggingface/accelerate/pull/3890中的@yao-matrix增强XPU的新代码，并使它们与设备无关
  • 修复了 @hexfaker 为非 CPU 训练错误设置的 KMP_AFFINITY https://github.com/huggingface/accelerate/pull/3912

FSDP2 改进

我们为 FSDP2 用户添加了一系列重要修复：仅向上转换需要 grad 的参数、更好地绑定嵌入错误、DCP 优化器加载、bf16 优化器步骤崩溃修复以及 torch < 2.7.0 兼容性。

  • 仅当 https://github.com/huggingface/accelerate/pull/3848 中的 @ojh31 需要_grad 时才向上转换 FSDP2 参数
  • 通过 @amanzoni1 在 https://github.com/huggingface/accelerate/pull/3878 中的目标 ValueError 指导修复 FSDP2 绑定嵌入错误
  • bug：fsdp 无法在 https://github.com/huggingface/accelerate/pull/3904 中使用 @flymin 的 dcp 加载优化器状态
  • 修复当启用 fsdp2 且模型为 bfloat16 时，optimizer.step 中的崩溃，作者为 https://github.com/huggingface/accelerate/pull/3905 中的 @sywangyi
  • 通过 @Mr-Neutr0n 在 https://github.com/huggingface/accelerate/pull/3924 中修复火炬 < 2.7.0 上的忽略参数 FSDP2 崩溃

DeepSpeed 序列并行性

我们对 v1.12.0 中引入的 DeepSpeed + 序列并行集成添加了多项修复，包括 SP 训练期间的评估支持和正确的流程组处理。

  • [SP] 修复 https://github.com/huggingface/accelerate/pull/3858 中 @kashif 的损失计算示例
  • 如果 @kashif 在 https://github.com/huggingface/accelerate/pull/3862 中启用了 CP 和 SP，则 [SP 和 CP] 会出错
  • DeepSpeed 在 https://github.com/huggingface/accelerate/pull/3916 中拥有自己的进程组（@kashif）
  • [Deepspeed] 当 deepspeed 和 sp_size > 1 时，@kashif 在 https://github.com/huggingface/accelerate/pull/3914 中跳过设备网格创建
  • 在https://github.com/huggingface/accelerate/pull/3917中@jp1924启用deepspeed Sequence Parallel期间的评估

FP8

我们增强了 FP8 训练。感谢@shimizust 修复 torchao 支持。

  • 通过 https://github.com/huggingface/accelerate/pull/3831 中的 @shimizust 修复 FP8 torchao 默认配置的填充和 FSDP2 全收集支持
  • 通过 @ksivaman 在 https://github.com/huggingface/accelerate/pull/3852 中修复 Transformer Engine 的执行
  • 在 https://github.com/huggingface/accelerate/pull/3857 中添加 @neha222222 的 MS-AMP 弃用警告

性能

Accelerate 现在通过推迟严重的依赖关系来更快地导入，并且 torch.compile 钩子被延迟禁用。

  • @SunMarc 在 https://github.com/huggingface/accelerate/pull/3953 中更快地导入
  • @SunMarc 在 https://github.com/huggingface/accelerate/pull/3947 中禁用延迟编译
  • 在 https://github.com/huggingface/accelerate/pull/3888 中禁用 @SunMarc 的钩子编译
