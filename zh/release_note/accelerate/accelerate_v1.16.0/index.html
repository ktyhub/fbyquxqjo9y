accelerate v1.16.0

这个项目是干啥的：一个帮PyTorch模型轻松在多张显卡或多台机器上训练的工具，配置简单还能组合并行，给搞AI训练的工程师用。

变更架构图

亮点

  • 硬版本下限与移除的集成（破坏性） — 本版本放弃 Python <3.11 和 PyTorch <2.6（#4459、#4461），升级前请锁定环境。两个集成被完全移除：PiPPy（#4462）和 MS-AMP（#4463），任何依赖它们的流水线必须改造或留在 v1.15。已弃用的 FP8RecipeKwargs 也被移除（#4464）；请迁移到 AORecipeKwargs（TorchAO）、TERecipeKwargs（Transformer Engine），否则配置会导入失败。
  • 统一的加速器发现与首个单芯片 TPU 支持 — 通过 torch.accelerator 路由后端检测（#4335、#4547），自定义/已注册的 PyTorch 后端不再需要库内各处的设备专用分支——如果你维护非 CUDA 集成，这是有意义的简化。首批 torch-tpu 支持落地，并修复了 tied 权重、safetensors 加载、内存报告和 FP16 校验（#4570）；TPU 仍属早期阶段（更广泛支持在进行中），但原生 API 兼容路径意味着现有集成可以继续工作。
  • FSDP meta 设备加载与免优化器准备 — RAM 高效加载得到大幅修复：现在能处理非零 rank 上的 meta 参数以支持 Transformers 风格的 meta-device 加载，FSDP1 重新连接优化器引用，FSDP2 区分 meta 参数与其分片替身（#4576），另修复了忽略的参数/缓冲区（#4568）和激活检查点（#4575）。FSDP2 现在可以在没有优化器的情况下准备模型（#4519），终于让训练前调用 Trainer.evaluate() 这类模式成为可能；结合恢复的 FP16 GradScaler 状态（#4291）和保留的输出/loss dtype（#4403），这对显存受限的微调是一个很棒的版本。
  • 更干净的启动器退出与错误报告 — accelerate launch 现在在 Ctrl+C/SIGTERM 时干净退出并回收子进程，而不是留下孤儿进程，torchrun 关闭时也不再输出虚假的启动器 traceback（#4573）；simple_launcher 还会上报子进程错误，同时保留实时输出（#4305）。实际收益是更可靠的分布式作业控制，以及在 CI 和抢占式集群上可调试的失败。
  • 值得复核的行为与正确性修复 — accelerate launch 不再强制 torch.compile(dynamic=False)（#4254），此前被抑制的动态形状重编译可能重新出现——注意编译时间。修复了 CPU/磁盘 offload 时缓存 INT8 权重导致的显存泄漏（#4325），以及 balanced_low_0 按位置而非设备 ID 解析内存限制（#4298）和亚字节/打包 dtype 的内存估算（#4237）。梯度裁剪现在与 Transformers 对齐（#4266），张量并行可以与复制式数据并行共存（#4193），skip_first_batches 保留 drop_last 和 device mesh 等数据加载器选项（#4296）——这些都可能细微改变训练数值或性能，升级后请与已知正常的运行做对比验证。

加速器支持

Accelerate 现在更广泛地使用 torch.accelerator 来支持注册的 PyTorch 后端，而无需在整个库中建立单独的特定于设备的分支。现有集成在需要兼容性时保留其本机 API。 这还包括通过 torch-tpu** 对 **单芯片 TPU 使用的初步改进。更广泛的 TPU 支持仍在进行中。

  • 简化后端发现并扩展自定义加速器支持 — @SunMarc（#4335、#4547）。
  • 修复单芯片 torch-tpu 使用的绑定权重、安全张量加载、内存报告和 FP16 验证 — @tengomucho (#4570)。

启动器改进

现在，当使用 Ctrl+C 或 SIGTERM 中断时，accelerate launch 会干净地退出，从而清理子进程。分布式启动还可以处理 torchrun 关闭信号，而无需额外的启动器回溯。

  • 清理中断时的子进程并改进 --quiet 和 --debug 行为 — @SunMarc (#4573)。
  • 在 simple_launcher 中显示子进程错误，同时保留实时输出 — @albertvillanova (#4305)。

FSDP

一些修复解决了 RAM 高效加载的问题，包括与 Transformer 的兼容性，将模型加载到非零等级的元设备上。现在，当初始化替换元参数时，FSDP1 会重新连接优化器引用，并且 FSDP2 在将这些参数映射到其分片替换时可以正确区分这些参数。 FSDP2 还支持在没有优化器的情况下准备模型，从而允许在训练之前进行 Trainer.evaluate() 等工作流程。

  • 修复 FSDP 元参数初始化和优化器映射 — @SunMarc (#4576)。
  • 修复 FSDP2 RAM 高效加载被忽略的参数和缓冲区 — @SunMarc (#4568)。
  • 修复启用激活检查点时的 FSDP2 分片 — @SunMarc @Titus-von-Koeller (#4575)。
  • 允许在 FSDP2 下准备没有优化器的模型 — @qgallouedec (#4519)。 🚨🚨🚨 ## 要求和删除 加速现在需要 Python 3.11+ 和 PyTorch 2.6+。 此版本还删除了几个已弃用的集成和 API。
  • 将最低 Python 版本提高到 3.11，将 PyTorch 版本提高到 2.6 — @SunMarc (#4459、#4461)。
  • 删除 PiPPy 和 MS-AMP 集成 — @SunMarc (#4462、#4463)。
  • 删除已弃用的 FP8RecipeKwargs。使用 AORecipeKwargs 用于 TorchAO 或 TERecipeKwargs 用于 Transformer 引擎 — @SunMarc (#4464)。
