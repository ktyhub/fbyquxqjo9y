accelerate v1.14.0

accelerate v1.14.0

变更流程图

亮点

  • FSDP2 训练正确性 — FSDP2 现在在分片前把模型转换为统一 dtype，对 embedding 和归一化层做完全分片，并把冻结的非浮点 Params4bit 排除在包装之外（#3985、#4015、#3987）。混合精度训练和 QLoRA 应能避开这些已知的分片断言和崩溃，无需手工绕行。
  • FSDP2 加载与转换 — 全状态加载现在使用基于 key 的匹配，并修正了 dtype 和 Params4bit 处理（#3982、#4021、#3981）。自动包装遵循 _no_split_modules，prepare_model() 防止重复包装（#3999、#3977）。to-fsdp2 转换会丢弃不支持的 FSDP1 专用 key，而不是把它们泄漏到 FSDP2（#4065），因此这些选项不再被转发。
  • 扩展的硬件支持 — Accelerate 现在支持端到端的 AMD ROCm 工作流（#4025）；Neuron 会对 all-gather 和 broadcast 操作做 padding 以减少重编译（#4000）。XPU 方面，pytorch-triton-xpu 更名为 triton-xpu（#4007）；请更新任何显式的依赖引用。
  • 量化 offload — 现在支持 TorchAO offload（#3973），int8 offload hook 的统计能正确恢复（#4044），keep_in_fp32_modules 在 load_and_quantize_model 中能与 tied 权重协同工作（#4043）。这减少了 offload 带共享参数的量化模型时的精度意外。
  • 分布式数据边界情况 — BatchSamplerShard 支持配合 even_batches 使用动态 batch size（#3969）。另有修复移除进程数多于样本数时意外的 padding（#4052），并修正 shard 数与进程数相等时的可迭代数据集分片（#3958）。使用了绕行方案的管线应重新核对样本数和 padding 假设。
  • 破坏性变更 — 上游未声明。

FSDP2 改进

此版本带来了大量 FSDP2 修复和生活质量改进：加载时正确的数据类型处理、嵌入/规范的分片、QLoRA 崩溃预防以及更强大的自动换行策略。

  • @SunMarc 在 #4015 中的 Fsdp2 full_shard 嵌入和规范
  • 修复了 @SunMarc 在 #4021 中的 fsdp2 加载完整状态字典 dtype 不匹配的问题
  • 修复@SunMarc 在 #4022 中的区域编译 fsdpv2
  • [FSDP2] 在 full_shard 之前将模型转换为统一数据类型，以修复 @roycho96 在 #3985 中的混合数据类型断言错误
  • [FSDP2] 从 full_shard 中自动排除非浮动冻结 Params4bit 以防止 QLoRA 崩溃，@roycho96 在 #3987 中
