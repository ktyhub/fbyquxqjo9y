accelerate v1.10.0

小版本 发布时间2025年8月7日 来源huggingface/accelerate 英文原文

accelerate v1.10.0

这个项目是干啥的：一个帮PyTorch模型轻松在多张显卡或多台机器上训练的工具，配置简单还能组合并行，给搞AI训练的工程师用。

变更架构图

亮点

  • 可组合的 N 维并行 — ParallelismConfig 把 DP 分片/复制、TP 和 CP 组合进同一个拓扑。把它传给 Accelerator，通过 device_mesh= 把 accelerator.torch_device_mesh 提供给 Transformers，然后调用 accelerator.prepare()；也支持自定义 device mesh（#3682），减少手工搭建 mesh 和进程组的工作。
  • 集成式上下文并行 — CP v2 纳入同一套配置和准备流程（#3700），为长上下文训练提供序列维度切分。请验证注意力处理：Accelerate 的自动 CP 路径假定因果注意力并会移除 attention mask，因此自定义或非因果掩码需要显式集成。
  • 面向 MoE PEFT 的 FSDP 正则忽略 — ignored_modules 现在接受正则表达式（#3698、#3719），让 FSDP 能与 PEFT 一起用于包含 q_proj 和 v_proj 的 MoE 层，尤其针对 gpt-oss。避免过于宽泛的模式，否则可能把更多参数排除在分片之外、增加显存占用。
  • 更健壮的并行生命周期 — parallelism_config 在 Accelerator 上暴露（#3703），在 Trainer 状态重置后得以保留（#3713），并从 PartialState 中移除（#3720）；集成代码应从 accelerator 读取它。仅 TP 的 prepare() 和 TP 环境变量解析也得到修复（#3707、#3716）。
  • 更低的 offload 开销与可预期的配置 — CPU offload 现在在张量已位于目标设备时跳过传输（#3695）；环境变量值改为大小写不敏感（#3712），减少配置上的意外。
  • 移除 IPEX 启动 flag — 已弃用的 accelerate launch --ipex 选项被移除（#3721）。请从脚本和包装器中删除它；PyTorch 2.7+ 已提供此前依赖该选项的 Intel CPU/XPU 优化。

N 维并行性

跨多个 GPU 训练大型模型可能很复杂，尤其是在结合不同的并行策略（例如 TP、CP、DP）时。为了简化此过程，我们与 Axolotl 合作推出了一种易于使用的集成，使您可以直接在训练脚本中应用并行策略的任意组合。只需传递一个 ParallelismConfig 来指定每个并行类型的大小 - 就是这么简单。 请参阅我们最新的博文 了解有关其工作原理的更多信息。

parallelism_config = ParallelismConfig(
    dp_shard_size=2,
    dp_replicate_size=2,
    cp_size=2,
    tp_size=2,
)
accelerator = Accelerator(
    parallelism_config=parallelism_config,
   ...
)
model = AutoModelForCausalLM.from_pretrained("your-model-name", device_mesh=accelerator.torch_device_mesh)
model = accelerator.prepare(model)
