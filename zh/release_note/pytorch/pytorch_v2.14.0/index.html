x = torch.tensor(0.0, requires_grad=True) torch.clamp_min(x, 0.0).backward() print(x.grad) # tensor(1.)

value = torch.tensor(0.0, requires_grad=True) bound = torch.tensor(0.0, requires_grad=True) torch.clamp_min(value, bound).backward() print(value.grad, bound.grad) # tensor(1.) tensor(0.)

版本2.14：

x = torch.tensor(0.0, requires_grad=True)
torch.clamp_min(x, 0.0).backward()

分布式

  • 实现 new_group() 的自定义 Python 进程组现在必须接受 backend 关键字参数 (#188489) 当默认进程组提供自己的 new_group() 方法并且 torch.distributed.new_group() 将子组创建委托给它时，这适用。 PyTorch 现在转发已解析的后端，以便自定义实现可以正确构造请求的子组。没有此参数的现有实现将引发 TypeError: ... got an unexpected keyword argument 'backend'。接受并使用该参数，或者当实现只有一个后端时接受并忽略它。 之前： 
    class MyProcessGroup(...):
    def new_group(
        self, ranks, *, timeout=None, pg_options=None,
        group_name=None, group_desc=None
    ):
        ...
    之后： 
    class MyProcessGroup(...):
    def new_group(
        self, ranks, *, timeout=None, backend=None, pg_options=None,
        group_name=None, group_desc=None
    ):
        ...
  • NCCL 对称内存池不再自动将 register_mem_pool(..., symm=True) 之后分配的段升级到对称窗口 (#192112) 从 CUDA 分配器回调注册这些后期段可能会在持有分配器锁的同时仅在某些列上调用集体 NCCL 操作，从而导致不可恢复的挂起。后期段现在仍然是普通的注册 NCCL 缓冲区。需要新分配的段才能使用对称窗口算法的应用程序必须在创建这些分配后集体取消注册并再次注册该池。 之前： 
    backend.register_mem_pool(pool, symm=True)
with torch.cuda.use_mem_pool(pool):
    tensor = torch.empty(size, device="cuda")
# Newly allocated segments were automatically upgraded, but this could hang.
    之后： 
    backend.register_mem_pool(pool, symm=True)
with torch.cuda.use_mem_pool(pool):
    tensor = torch.empty(size, device="cuda")

# Collectively refresh registration after the pool grows.
backend.deregister_mem_pool(pool)
backend.register_mem_pool(pool, symm=True)
  • 非会员等级现在从实验性 torch.distributed.split_group() 接收 GroupMember.NON_GROUP_MEMBER 而不是 None (#190725) 当每个请求的拆分中不存在调用等级时，split_group() 现在返回与 new_group() 相同的非成员哨兵。使用 is None 标识非成员的代码必须与 torch.distributed.GroupMember.NON_GROUP_MEMBER 进行比较。 之前： 
    group = torch.distributed.split_group(
    split_ranks=[[0, 1], [2, 3]]
)
if group is None:
    return
    之后： 
    group = torch.distributed.split_group(
    split_ranks=[[0, 1], [2, 3]]
)
if group == torch.distributed.GroupMember.NON_GROUP_MEMBER:
    return

线性代数前端

  • 删除已弃用的 torch.cholesky() 和 Tensor.cholesky() API (#186817) 现在拨打 RuntimeError，将用户引导至 torch.linalg.cholesky()。替换返回一个下三角因子；之前请求 upper=True 的调用者应采用 .mH 的共轭转置。 版本2.13： 
    lower = torch.cholesky(a)
upper = torch.cholesky(a, upper=True)
    版本2.14： 
    lower = torch.linalg.cholesky(a)
upper = torch.linalg.cholesky(a).mH
  • 删除已弃用的 torch.qr() 和 Tensor.qr() API (#186815) 现在，呼叫会发出 RuntimeError，将用户引导至 torch.linalg.qr()。将布尔值 some 参数替换为 mode="reduced" 或 mode="complete"。 版本2.13： 
    q, r = torch.qr(a)
q_full, r_full = torch.qr(a, some=False)
    版本2.14： 
    q, r = torch.linalg.qr(a, mode="reduced")
q_full, r_full = torch.linalg.qr(a, mode="complete")

# or through the relay-only entry points
from torch._dynamo.backends.tvm import tvm_meta_schedule, tvm_auto_scheduler

pipeline = tvm.relax.get_pipeline("static_shape_tuning", target="llvm", total_trials=2000)

C++ 前端

  • 删除已弃用的零参数 C++ 重载 c10::Scalar::isIntegral() 和 c10::isIntegralType(ScalarType) (#187115) 调用任一重载而不指定布尔值是否算作整数的代码将不再编译。显式传递includeBool；使用 false 保留已删除的重载的行为。 版本2.13：

MPS

  • C++ MPS macOS 版本帮助程序及其枚举成员已重命名 (#188645) 包含 <ATen/mps/MPSDevice.h> 的下游 C++ 代码必须用 at::mps::is_macos_at_least() 替换导出的 at::mps::is_macos_13_or_newer() 函数。相关的 MacOSVersion 成员也删除了其名字中的 VER 和 PLUS 部分。不提供兼容性别名，因此使用旧名称的代码将不再编译。 版本2.13：

复杂前端

  • bfloat16 的复杂类型提升现在使用新的 torch.bcomplex32 shell dtype 而不是 torch.complex64 (#186928) torch.bcomplex32 将实部和虚部存储为 bfloat16。因此，将 bfloat16 张量与复数标量组合或以其他方式请求其相应的复数类型的操作可以生成 bcomplex32 而不是 complex64。由于 bcomplex32 是一种具有有限运算符支持的 shell 数据类型，因此之前在 complex64 中运行的操作现在可能会引发未实现的错误。当需要先前的精度或运算符覆盖范围时，显式转换为 complex64。 版本2.13： 
    x = torch.ones(4, dtype=torch.bfloat16)
assert torch.result_type(x, 1j) == torch.complex64
    版本2.14： 
    x = torch.ones(4, dtype=torch.bfloat16)
assert torch.result_type(x, 1j) == torch.bcomplex32

# Preserve the previous complex64 behavior explicitly.
y = x.to(torch.complex64) + 1j

    with torch.autograd.graph.saved_tensors_hooks(pack, unpack):
    output = torch.utils.checkpoint.checkpoint(

        input,
        use_reentrant=False,
        context_fn=sac_context_fn,

    with torch.autograd.graph.saved_tensors_hooks(pack, unpack):
    output = torch.utils.checkpoint.checkpoint(
        function,
        input,
        use_reentrant=False,
        context_fn=sac_context_fn,
        respect_saved_tensors_hooks=True,

    # generators were eagerly exhausted on first execution

  • 弃用 CUDAGraph.register_generator_state()； CUDA 图现在在捕获期间首次使用 RNG 时延迟注册生成器状态 (#176753) 该方法现在是空操作并发出弃用警告。删除显式注册调用；当捕获期间使用生成器时，图形会自动保留所需的状态。 之前： 
    graph = torch.cuda.CUDAGraph()
state = generator.graphsafe_get_state()

with torch.cuda.graph(graph):
    generator.graphsafe_set_state(state)
    output = torch.rand(16, device="cuda", generator=generator)
    之后： 
    graph = torch.cuda.CUDAGraph()
state = generator.graphsafe_get_state()

with torch.cuda.graph(graph):
    generator.graphsafe_set_state(state)
    output = torch.rand(16, device="cuda", generator=generator)
  • 弃用 GreenContext.set_context() 和 GreenContext.pop_context()；使用自定义流来激活绿色上下文 (#188419) 这些方法现在发出 FutureWarning。从绿色上下文创建一个流，并将其与 torch.cuda.stream() 一起使用。与绿色上下文之外的流同步仍然是调用者的责任，并且应在需要时使用 CUDA 事件。 之前： 
    ctx = torch.cuda.green_contexts.GreenContext(num_sms=1)
ctx.set_context()
try:
    output = model(input)
finally:
    ctx.pop_context()
    之后： 
    ctx = torch.cuda.green_contexts.GreenContext(num_sms=1)
stream = ctx.Stream()
with torch.cuda.stream(stream):
    output = model(input)

即时生产

  • TorchScript API 现在发出可见的 FutureWarning，而不是通常隐藏的 DeprecationWarning (#189914) torch.jit.script、torch.jit.trace、torch.jit.save 和 torch.jit.load 等呼叫现在明显将用户引导至 torch.compile 或 torch.export。 torch.utils.mkldnn、torch.fx.experimental.optimization 和 torch.distributed.optim 的导入还可以避免在仅导入这些模块时急切地编译 TorchScript。 之前： 
    scripted = torch.jit.script(model)

    exported = torch.export.export(model, example_inputs)
torch.export.save(exported, "model.pt2")

新功能

Python 前端

  • 添加 torch.accelerator.initial_seed()、torch.accelerator.get_rng_state() 和 torch.accelerator.get_rng_state_all() 用于与后端无关的加速器 RNG 检查（#186597）
  • 通过 Tensor.__dlpack__(read_only=True) 和 torch.utils.dlpack.ReadOnlyTensorWrapper 添加只读 DLPack 导出，包括与兼容消费者的写时复制保留交换 (#188554)
  • 添加 torch.Generator.philox_state()，以便 Python 编写的内核可以保留 Philox 计数器范围，这些范围在 CUDA 图形捕获和重放中保持正确（#191019）

自动毕业

  • 现在可以在没有函数的情况下调用 torch.utils.checkpoint.checkpoint() 来创建急切模式装饰器，其检查点配置与包装函数的参数分开 (#189411) 
    checkpointed_function = torch.utils.checkpoint.checkpoint(
    use_reentrant=False
)(function)
output = checkpointed_function(*args, **kwargs)
    柯里化形式最初是在 eager 模式下支持的；现有的直接呼叫仍保持 torch.compile 下的兼容形式。
  • 添加 torch.autograd.graph.node_creation_hook，一个线程本地上下文管理器，其回调接收在其范围内创建的每个完全填充的自动分级图节点。回调可以检查节点、存储元数据或注册向后前挂钩和后挂钩，包括在高阶微分和检查点重新计算期间创建的节点 (#189284)
  • 添加 ctx.set_output_grad_dtype(*dtypes) 以实现自定义 torch.autograd.Function。从 forward 或 setup_context 调用一次，它声明每个输出所需的梯度数据类型，独立于输出的存储数据类型；具体的数据类型转换传入的渐变，而 None 保持其数据类型不变 (#189634)
  • 添加对 torch.cdist 和 torch.nn.functional.pdist 的二阶梯度支持，因此梯度-梯度计算不再因为 _cdist_backward 或 _pdist_backward 缺少导数而失败 (#188901)

  • 新增公共torch.distributed.set_timeout() API；私有 _set_pg_timeout() 别名仍然可用，但带有弃用警告 (#187387)
  • 添加 torch.distributed.tensor.logspace 用于构造分布式对数间隔张量 (#186398)
