FlexAttention 登陆 Apple Silicon (MPS)，在稀疏模式上比 SDPA 加速高达约 12 倍，并在 CUDA 上获得确定性后向路径以进行可重现的梯度计算。 CuTeDSL“原生 DSL”后端为 Inductor 提供了第二条高性能代码路径（与 Triton 一起）用于关键 GPU 操作，并具有更快的编译速度。 [原型] nn.LinearCrossEntropyLoss 将最终预测和损失计算相结合，将峰值 GPU 内存削减多达 4 倍，以进行大词汇量语言模型训练。 torchcomms，PyTorch 分布式的新通信后端，提高了大型集群训练的容错性、可扩展性和可调试性。 FSDP2 现在通过专用进程组（选择加入）重叠减少分散和全收集通信，从而提高分布式训练吞吐量。 Python 3.15 滚轮支持，通过 pytorch 存储库索引在 Linux 上支持 PyTorch，包括与自由线程 3.15t 兼容的版本。 更广泛的平台支持：ROCm 通过原生 HIP CMake 获得 AOTriton 0.12b，Arm 添加了 Armv9-A torch.compile 目标，Intel XPU 公开了新的设备遥测 APIs。 有关这些突出显示功能的更多详细信息，您可以查看发布博客文章。以下是此版本的完整 release note。 # 跟踪回归 ### ROCm 轮子在没有 GPU 的环境中在 CPU 上破坏 `torch.compile` 在没有可用 GPU 的环境中运行 `torch==2.13.0+rocm7.2` 轮（`torch.cuda.is_available()` 是 `False`）会破坏 CPU 路径上的 `torch.compile`：第一次编译会引发 `RuntimeError: Can't detect vectorized ISA for CPU`（[#189194](https://github.com/pytorch/pytorch/issues/189194)）。这是 `torch==2.12.1+rocm7.2` 的回归，`torch==2.12.1+rocm7.2` 在相同的设置中可以很好地编译 CPU 代码（检测例如 `VecAVX2`）。 2.13 ROCm 轮似乎依赖于 ROCm 构建器映像中存在的某些内容来检测 CPU 矢量化 ISA，因此它在 ROCm 映像上运行时可以工作，但在纯 CPU 映像上运行时会失败。 解决方法：在 ROCm 映像上运行 `+rocm` 轮，或为无 GPU 环境安装标准 CPU/CUDA 版本。 # 向后不兼容的更改 - 停止构建 CPython 3.13t（自由线程）二进制文件 (#182951) 上游`pypa/manylinux`于2026年5月7日删除了CPython 3.13t（自由线程），因为3.13t 是实验性的，已被现在非实验性的 CPython 3.14t 取代。结果， PyTorch 2.13 不再提供 `cp313t` 轮子（Linux、Triton 和相关工件）。用户在 自由线程解释器应移至 Python 3.14t。 PyTorch 2.12： ```bash # cp313t (free-threaded 3.13) wheels were available python3.13t -m pip install torch ``` PyTorch 2.13： ```bash # Use free-threaded Python 3.14t instead python3.14t -m pip install torch ``` - 运算符模式中不再允许裸露的 `PyObject` (#184209) 裸露的 `PyObject` 被意外地接受在操作符模式字符串中 PyTorch 2.12。这是没有记录的，现在被拒绝，因为 `torch.compile` 不支持自定义操作的任意 `PyObject` 输入。如果 您使用裸 `PyObject` 参数或返回类型解析或注册模式， 您现在将收到架构解析错误。 PyTorch 2.12： ```python >>> from torch._C import parse_schema >>> parse_schema("foo(PyObject x) -> ()") # accepted ``` PyTorch 2.13： ```python >>> from torch._C import parse_schema >>> parse_schema("foo(PyObject x) -> ()") # raises a schema parse error ``` - 删除 Bazel 构建支持 (#180883) Bazel 构建从未被广泛采用，并且仍然依赖于过时的 Bazel 6， 而更广泛的生态系统已经转移到 Bazel 9。所有 Bazel 构建文件和 CI 作业都已迁移 已被删除。使用 Bazel 构建 PyTorch 的用户应迁移到受支持的 CMake/`pip install` 构建流程。 PyTorch 2.12： ```bash # Build PyTorch with Bazel bazel build //:torch ``` PyTorch 2.13： ```bash # Bazel build files have been removed; build from source with pip instead pip install --no-build-isolation -e . ``` - `StorageImpl` 的内置写时复制 (COW) 物化被可插入物化器挂钩取代 (#179063) `StorageImpl` 不再直接了解 COW。其内部 COW 入口点 `StorageImpl::is_cow()`、`StorageImpl::maybe_materialize_cow()` 和朋友 `cow::materialize_cow_storage()` 已被删除，取而代之的是单个可插拔 后端注册运行一次的`MaterializeFn`钩子（`void(*)(StorageImpl*)`）， 在第一个可变数据指针访问上。 COW 现在只是这个钩子的一个消费者 (`c10::impl::cow::materialize_cow`)，以及所有 COW 行为（惰性克隆、重新计数 共享数据，写时复制）不变。这也为加速器后端提供了 急切模式图编译器是提交延迟分配的零快速路径成本的地方 或在第一次突变时实现符号缓冲区。 这是仅限 C++ 的更改。它影响调用的树外后端/扩展 直接去掉了`StorageImpl` COW符号；他们将无法针对 2.13 进行编译 出现诸如 `no member named 'is_cow' in 'c10::StorageImpl'` 之类的错误。迁移到 新挂钩 API (`set_materializer()` / `has_materializer()` / `clear_materializer()`)。 PyTorch 2.12： ```cpp // Detect a COW storage and force it to materialize. if (storage.is_cow()) { storage.maybe_materialize_cow(); } ``` PyTorch 2.13： ```cpp // Register a one-shot materializer; it runs on the next mutable-data access // and then clears itself. COW registers c10::impl::cow::materialize_cow this way. storage.set_materializer(&my_backend_materialize); // void(StorageImpl*)

// has_materializer() replaces is_cow() for “is a deferred materialization pending?” if (storage.has_materializer()) { /* … */ }

- 将 `shared_ptr<Node>` 转换为 `intrusive_ptr<Node>` (#181139)。这改变了 `Tensor::grad_fn` 的签名。对 `Tensor.grad_fn()` 的访问应从 `std::shared_ptr<Node>` 更改为 `c10::intrusive_ptr<Node>`。同样，C++ autograd 函数的构造也应该改变：
PyTorch 2.12：
```cpp
std::shared_ptr<CustomCppNode> node(new CustomCppNode(), torch::autograd::deleteNode);

PyTorch 2.13：

auto node = c10::make_intrusive<CustomCppNode>();
  • 从源代码构建时支持的最低 NCCL 版本现在是 2.23 (#186292) PyTorch 现在在编译时要求 NCCL >= 2.23，并且保护 2.23 或更早版本中引入的 NCCL 功能的预处理器/运行时门已被删除。如果用户针对早于 2.23 的系统 NCCL 从源代码构建 PyTorch，则会遇到针对已删除门的编译错误。将 NCCL 安装升级到 >= 2.23 进行构建。预构建的 PyTorch 轮子已经捆绑了兼容的 NCCL，因此 pip/conda 用户不受影响。
  • 删除命名张量 (#173895) 命名的张量功能（长期不推荐使用的原型）已被完全删除，以减少开销和代码膨胀。所有关联的 Python 和 C++ API 都消失了，包括 Tensor.names、Tensor.rename()、Tensor.refine_names()、Tensor.align_to()、Tensor.align_as()、torch.align_tensors()、工厂函数上的 names= 关键字（例如 torch.zeros、torch.empty、torch.ones），以及C++ Dimname / DimnameList API。以前依赖命名维度的代码必须按位置跟踪维度顺序，并避免使用任何现已删除的 API 或操作重载。
  • onednn::qconv2d_pointwise.binary 和 .binary_tensor 运算符不再为其输入别名，而是返回新的张量。以前，这些操作改变了 qaccum 输入缓冲区并直接返回它，违反了自定义操作符输出不得别名输入的 PyTorch 不变量。这通过旧的 -> Tensor(a!) 模式悄悄地绕过了别名检查，并将成为未来 PyTorch 版本中的硬错误（如 #182063 中提到的），因此模式和实现被更正以返回新的输出。大多数用户不受影响，只有直接调用这些操作并依赖于 qaccum 就地突变的代码现在必须读取返回的张量。 (#177171)

弃用

  • 不推荐使用返回其输入之一别名的输出的自定义运算符 (#182063) 当自定义运算符返回的输出与其在 torch.compile 下的输入之一相同（或以其他方式别名）的张量时，PyTorch 现在会发出 UserWarning ，表明它已被弃用，并将在 PyTorch 的未来版本中成为错误。此前警告称该更改将登陆 PyTorch 2.12；该时间表已被推迟。要更新代码，请返回有问题的输出而不是输入的克隆，或重构运算符，使其不返回别名张量。 已弃用： 
    @torch.library.custom_op("mylib::foo", mutates_args=())
def foo(x: torch.Tensor) -> torch.Tensor:
    return x  # output aliases the input -- deprecated
    更新： 
    @torch.library.custom_op("mylib::foo", mutates_args=())
def foo(x: torch.Tensor) -> torch.Tensor:
    return x.clone()  # return a clone instead
  • 使用量化数据类型 quint8、qint8 和 qint32 创建张量现已弃用并发出警告。这涵盖了 Python 和 C++ 调用站点；请参阅 #184982 了解迁移指南 (#184984) PyTorch 2.12： 
    >>> x = torch.quantize_per_tensor(torch.randn(3), 0.1, 0, torch.quint8)
    PyTorch 2.13： 
    >>> x = torch.quantize_per_tensor(torch.randn(3), 0.1, 0, torch.quint8)
UserWarning: Creating tensors with quantized dtypes (quint8, qint8, qint32) is deprecated
  • 将分布式集体操作重命名为 _single 命名方案并弃用旧名称（#186123、#186124、#186125、#186134、#186135、#186144） 为了使公共 torch.distributed 集体 API 与 torchcomms 的 TorchCommBackend 使用的命名保持一致，all_gather_into_tensor 重命名为 all_gather_single，reduce_scatter_tensor 重命名为 reduce_scatter_single。以前的名称继续作为委托给新函数的薄包装器工作，但现在发出 FutureWarning。 PyTorch 2.12： 
    dist.all_gather_into_tensor(output, input)
dist.reduce_scatter_tensor(output, input)
    PyTorch 2.13： 
    dist.all_gather_single(output, input)
dist.reduce_scatter_single(output, input)

新功能

Python 前端

  • 添加两个新的运算符标签，torch.Tag.inplace 和 torch.Tag.out，让运算符声明如何写入结果：inplace 意味着它就地改变张量，out 意味着它写入调用者提供的输出张量。本机 PyTorch 运算符会自动标记，使用 torch.library 定义的自定义运算符可以通过添加标签来选择加入。要标记为 inplace，运算符必须将其变异的张量作为其第一个位置参数（声明为 Tensor(a!)，并且是唯一的可变参数）并返回相同的张量。以这种方式标记自定义运算符可以改善其在 torch.compile 下的行为：inplace 操作现在会经过 auto_functionalize，因此重新放置过程可以分析克隆并跳过不必要的副本，并且 inplace 和 out 操作都会免费生成其假/元内核。请参阅 Python 自定义运算符教程 了解如何创作和标记自定义运算符。 （#181100、#181099、#184199、#184200、#184201、#184202、#184203、#180851、#180852）
  • 添加 const_data_ptr() Python 绑定到 torch.Tensor 以进行只读数据指针访问 (#180382)
  • 将 abbr 属性添加到 torch.dtype，该属性返回 dtype 的短字符串缩写（例如，torch.float32.abbr 返回 "f32"）(#177296)
  • 允许位置参数作为关键字参数传递给 autograd 自定义 Function (#182206)
  • 在 torch.func 命名空间中公开 rearrange，以获得 einops 风格的张量 reshaping (#173183)

火炬.nn

  • 添加 nn.LinearCrossEntropyLoss，一个融合线性投影加交叉熵损失模块，避免实现完整的 logits 张量（#181573、#185852、#172286、#186113）

自动毕业

  • 添加 torch.autograd.graph.region_activation_memory_budget (#185979)
  • 支持将梯度输入作为 dict 传递到 torch.autograd.grad 和 torch.autograd.backward (#178140)

分布式

  • 为对称内存参数 (lib.register_symm_mem_args()) 添加注册 API，让运算符（包括树外操作）声明哪些参数需要对称内存分配 (#173513)
  • 删除 NCCLSymmetricMemory 对 ProcessGroupNCCL 的显式依赖，使对称内存能够与 torchcomms 等树外后端一起使用 (#184260)
  • 在 Python 中实现进程组后端时支持从 Python 访问 ReduceOp.PREMUL_SUM 因子 (#185863)
  • 公开 NCCL 2.30 maxP2pPeers 配置绑定 (#181686)
  • 在 ROCm 上添加用于对称内存的 rocSHMEM Triton 集成 (#178658)
  • 支持通过 step() 的新 loss_kwargs 参数将额外的关键字参数传递给管道调度中的损失函数，从而启用需要超出 (output, target) 参数的损失函数（例如需要令牌计数进行缩放的分块交叉熵）(#181057)

分布式 FSDP2

  • 添加 FSDPModule.set_separate_reduce_scatter_group 为 reduce-scatter 提供自己的 NCCL 通信器，支持选择加入 all-gather 和 reduce-scatter 的重叠 (#186335)
  • 添加 set_reduce_scatter_max_input_buffers 以保持多个减少分散输入缓冲区处于运行状态，因此向后计算不再因等待回收单个减少分散缓冲区而停滞 (#186000)

分析器

  • Profiler/Kineto 现在在 CUDA 后端发出通道元数据 (#185968)

发电机

  • 添加 torch.compiler.set_default_backend 以覆盖全局默认的 torch.compile 后端，因此树外后端作者不需要在每个调用站点传递 backend= （遵循 torch.set_default_dtype/torch.set_default_device 的模式）。显式 backend= 参数仍然优先 (#178944)
  • 添加 torch.compile(f, isolate_recompiles=True) 为每个 torch.compile 调用提供自己独立的缓存桶，防止多个 torch.compile 调用针对同一函数时缓存查找和重新编译限制检查中的交叉编译干扰 (#178351)
  • 向 @leaf_function 添加 register_multi_grad_hook 支持，当所有 requires_grad 输入都计算出梯度时，允许向后钩子在每次向后传递时触发一次 (#179609)

电感器

提前电感 (AOTI)

  • 为 AOTI 稳定 ABI 生成的 C 垫片现在由 TORCH_TARGET_VERSION 进行版本控制和门控，因此新版本中引入的垫片仅在目标版本支持它们时才会公开 (#181916)

  • 添加了稳定的 AOTI 流垫片 aoti_torch_stream_native_handle 和 torch::stable::accelerator::Stream::nativeHandle()，位于 TORCH_FEATURE_VERSION >= 2.13 后面，用于从稳定的 ABI 检索本机流句柄 (#183930)
