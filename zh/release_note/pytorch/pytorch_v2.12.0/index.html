亮点

<表>

由于更新了 cuSolver 后端选择，CUDA 上的批处理 linalg.eigh 速度提高了 100 倍。 新的torch.accelerator.Graph API 统一了 CUDA、XPU 和树外后端的图形捕获和重放。 torch.export.save 现在支持微缩放 (MX) 量化格式，从而能够完全导出大幅压缩的模型。 Adagrad 现在支持 fused=True，将 Adam、AdamW 和 SGD 与单内核优化器实现结合起来。 torch.cond控制流现在可以在 CUDA 图形内捕获和重放。 ROCm用户获得可扩展的内存段、rocSHMEM对称内存集合和FlexAttention管道。 有关这些突出显示功能的更多详细信息，您可以查看发布博客文章。以下是此版本的完整 release note。 # 向后不兼容的更改 ## 构建前端 - 加强了 `FindARM.cmake` 中的 SVE 编译检查，这可能会拒绝先前接受但不正确的 SVE 配置（[#176646](https://github.com/pytorch/pytorch/pull/176646)） 启用 SVE 的源代码构建现在可以更严格地验证编译器配置。如果之前通过的构建具有不完整或不匹配的 SVE 设置，那么它现在可能会在 CMake 配置期间失败，而不是稍后在编译期间失败。更新编译器/工具链标志，以便它们准确地描述目标 SVE 支持，或为该构建禁用 SVE。 - 将构建 PyTorch 所需的最低 CUDA 版本从源代码更新为 CUDA 12.6 ([#178925](https://github.com/pytorch/pytorch/pull/178925)) 不再支持使用早于 12.6 的 CUDA 版本从源代码构建 PyTorch。构建自定义二进制文件的用户应安装 CUDA 12.6 或更高版本，并确保 `CUDA_HOME` 指向该安装。 版本 2.11： ```bash CUDA_HOME=/usr/local/cuda-12.4 python setup.py develop ``` 版本2.12： ```bash CUDA_HOME=/usr/local/cuda-12.6 python setup.py develop ``` - 在 CMake 构建文件中强制执行 C++20 最低要求 ([#178662](https://github.com/pytorch/pytorch/pull/178662)) 源构建现在需要支持 C++20 的编译器和构建配置。如果您维护从源代码构建 PyTorch 的自定义构建脚本或下游扩展，请更新编译器并删除 PyTorch 可以构建为 C++17 的假设。 ## 分布式 - `torch.distributed.nn.functional` 操作现在在 `torch.compile` 下提升 `RuntimeError` ([#177342](https://github.com/pytorch/pytorch/pull/177342)) `torch.distributed.nn.functional` 中的所有操作（例如，`broadcast`、`all_reduce`、`all_gather`、`reduce_scatter`、`all_to_all_single`）现在在 `torch.compile` 内部调用时都会引发 `RuntimeError`。用户应迁移到 `torch.distributed._functional_collectives` 中的功能集合 API。 版本2.11： ```python @torch.compile def my_func(x): return torch.distributed.nn.functional.all_reduce(x, op=ReduceOp.SUM) ``` 版本2.12： ```python @torch.compile def my_func(x): return torch.distributed._functional_collectives.all_reduce(x, reduceOp="sum", group=group) ``` ## 火炬弹性 - `torchrun` 现在默认为操作系统分配的空闲端口用于单节点训练，而不是端口 29500 ([#175699](https://github.com/pytorch/pytorch/pull/175699)) 当运行 `torchrun --nproc-per-node=N script.py` 而不指定 `--master-port` 或 `--standalone` 时，默认行为现在通过 `c10d` 会合后端自动使用操作系统分配的空闲端口。这消除了同时运行多个训练作业时的“地址已在使用中”错误。多节点训练，显式 `--master-port`、`PET_MASTER_PORT` env var 和 `--standalone` 不变。 版本 2.11： ```bash # Used static rendezvous on port 29500 by default torchrun --nproc-per-node=4 train.py ``` 版本 2.12： ```bash # Uses OS-assigned free port by default torchrun --nproc-per-node=4 train.py

To explicitly use a fixed port:

torchrun —nproc-per-node=4 —master-port=29500 train.py

## MPS
- 所有 MPS 张量现在都分配在统一内存中（[#175818](https://github.com/pytorch/pytorch/pull/175818)）
以前，MPS 张量可以分配在纯设备内存或统一内存中。现在所有 MPS 张量无条件使用统一内存。这简化了内存管理，并使 CPU 无需显式副本即可访问 MPS 张量数据。依赖于仅设备内存布局的代码可能会观察到不同的性能特征。
## 电感器
- 2.11 中引入的 `max_autotune` 布局约束延迟现已选择加入（[#175330](https://github.com/pytorch/pytorch/pull/175330)）
在 2.11 中，Inductor 延迟了 `max_autotune` 模板的布局冻结，以暴露更多融合机会。这导致了区域电感器故障模式，因此 2.12 中的默认设置恢复为立即布局冻结。依赖延迟行为获得融合机会的用户应通过 `torch._inductor.config.max_autotune_defer_layout_freezing` 或 `TORCHINDUCTOR_MAX_AUTOTUNE_DEFER_LAYOUT_FREEZING=1` 明确选择加入。
版本2.11：
```python
# Deferred layout freezing was the default
torch.compile(model, mode="max-autotune")

版本2.12：

import torch._inductor.config as cfg
cfg.max_autotune_defer_layout_freezing = True
# or set TORCHINDUCTOR_MAX_AUTOTUNE_DEFER_LAYOUT_FREEZING=1
torch.compile(model, mode="max-autotune")

发布工程

  • 弃用 CUDA 12.8 构建，转而支持 CUDA 13.0 (#179072) CUDA 12.8 二进制文件已从 PyTorch 二进制构建矩阵中删除。 CUDA 13.0 现在是稳定的默认值，CUDA 12.6 仍然可供使用旧驱动程序的用户使用。明确固定 cu128 索引 URL 的用户将需要切换到 cu130（推荐）或 cu126。 版本2.11： 
    pip install torch --index-url https://download.pytorch.org/whl/cu128
    版本2.12： 
    # Use CUDA 13.0 (default on PyPI):
pip install torch
# Or explicitly:
pip install torch --index-url https://download.pytorch.org/whl/cu130
# Older driver fallback:
pip install torch --index-url https://download.pytorch.org/whl/cu126
  • 与 CMake < 3.10 的兼容性将在未来版本中删除 (#166259) 针对早于 3.10 的 CMake 版本构建的源代码现在会发出弃用警告。未来版本将需要 CMake 3.10 或更高版本；请在此之前升级 CMake。

线性代数

  • 多个 CUDA 线性代数运算符不再使用 MAGMA 后端，现在无条件分派到 cuSolver 或 cuBLAS：
    • torch.linalg.eigh 现在发送到 cuSolver (#174619)
    • torch.linalg.lu_solve 现在发送到 cuSolver/cuBLAS (#174248)
    • torch.linalg.cholesky_inverse 现在发送到 cuSolver (#174681)
    • torch.linalg.cholesky_solve 现在发送到 cuSolver (#174769) 调用这些 API 的用户代码无需更改。实际影响是针对依赖 MAGMA 特定数值行为、性能特征或调试的用户。这些调用现在使用 CUDA 上的 cuSolver/cuBLAS 实现。

FullShardedDataParallel2 (FSDP2)

  • 不再支持通过不带图形中断的 FSDP2 挂钩进行编译（#174863、#174906）。如果您将编译的 autograd 与 FSDP2 一起使用，请更新代码以允许 FSDP2 挂钩周围的图形中断，或禁用 FSDP2 训练步骤的编译的 autograd。 版本2.11： 
    with torch._dynamo.config.patch(compiled_autograd=True):
    compiled_model = torch.compile(fsdp_model, fullgraph=True)
    loss = compiled_model(input).sum()
    loss.backward()
    版本2.12： 
    # Either run FSDP2 backward without fullgraph.
compiled_model = torch.compile(fsdp_model, fullgraph=False)
loss = compiled_model(input).sum()
loss.backward()

# Or apply compile before applying FSDP.
compiled_model_pre_fsdp = torch.compile(model, fullgraph=True)
compiled_model = fully_shard(compiled_model_pre_fsdp, ...)
loss = compiled_model(input).sum()
loss.backward()

发电机

  • torch.compile(fullgraph=True) 现在在调用运行未编译的代码时发出警告； 2.13 中会出现错误（#181940） 此前，fullgraph=True 仅在 Dynamo 实际编译并运行该函数后才进行验证。如果 Dynamo 在调用时被绕过（例如，在用户定义的 TorchDispatchMode 下），则注释不会产生任何影响。 2.12发出警告； 2.13 将引发。 对于没有 fullgraph 更强保证的图形破坏错误，请使用 torch._dynamo.error_on_graph_break。 版本2.12： 
    from torch.utils._python_dispatch import TorchDispatchMode

class LoggingMode(TorchDispatchMode):
    def __torch_dispatch__(self, func, types, args=(), kwargs=None):
        return func(*args, **(kwargs or {}))

@torch.compile(fullgraph=True)
def model(x):
    return x.sin() + 1

# A user-defined TorchDispatchMode is active, so Dynamo skips the frame
# and no compiled code runs — emits a warning in 2.12, will raise in 2.13.
with LoggingMode(): # Remove this to fix warning
    model(torch.randn(3, 4))

    版本 2.12：

  • 在 torch.compile 配置模块中添加了弃用框架，以便可以将单个选项标记为弃用（#169837）

电感器

  • 为 torch.compile 添加了用户定义流支持。 Inductor 现在在包装器中使用 codegens 流上下文管理器（进入/退出）和 record_stream 调用，使用户流能够通过正确同步、调度程序集成和跨流依赖性跟踪流过已编译区域（#165390、#165391、#165504、 #165505、#174223、#176700、#177694)
  • 添加了用于异步激活卸载的 ao::offload、ao::reload 和 ao::wait 操作。这些操作封装了异步 CPU 卸载流管理，遵循与 c10d 功能集合相同的异步 2 操作模式，将 IR 大小从 7 个节点（卸载）和 5 个节点（重新加载）减少到每个 2 个节点（#177621）
  • 添加了用户定义的 Triton 内核一元尾声融合。 Inductor 现在可以将用户 Triton 内核与下游逐点尾声（例如 relu()）融合，通过 AST 解析用户内核源并将尾声内联到 tl.store 表达式中（#173662）
  • 为自定义操作添加了外变体发现和降低。当自定义操作同时注册功能和 .out 重载时，Inductor 会自动将单输出和多输出功能操作降低为其 .out 变体为 ExternKernelOut，从而实现内存规划器缓冲区重用（#175116、#176117）
  • max_autotune 现在扩展到组合内核。自动调整管道生成每个子内核块大小的阶段配置并对其进行基准测试，并具有链式顺序自动调整和每个子内核缩减提示（#177715、#178936、#179317）
  • 为 mm 和 addmm 添加了非 TMA 持久 Triton 模板以实现最大自动调谐，从而在没有 TMA 的硬件上启用持久内核（#177781、#179095）
  • 添加了对 torch.float8_e5m2 dtype 的 CUTLASS 后端支持，包括注册 FP8 GEMM 自动调整（#171176）
  • 向 max-autotune-gemm 添加了 XPU CUTLASS GEMM 内核代码生成和代码缓存，允许 CUTLASS 风格的 GEMM 模板针对 Intel GPU（#161938、#161939）
  • 为 sort、median 和 mode 操作添加了 MTIA Triton 代码生成器 (#178525)
  • 添加了深度 conv1d 的 Triton 模板（#175280）
  • 在 at::vec::convert 中为 Inductor C++ x86 后端添加了 AVX10.2 fp32↔fp8 内在函数 (#172309)
  • Pallas 后端：添加了标量预取和间接访问支持（#177212）
  • 添加了 disable_welford_reduction 配置标志以选择退出代码生成中的 Welford 缩减（#175778）
