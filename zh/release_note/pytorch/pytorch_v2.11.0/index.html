火炬.nn

通过 window_size 添加滑动窗口支持到 varlen_attn，使可选参数仅包含关键字 (#172238)

torch.nn.attention.varlen_attn 的签名已更改：在可选参数之前插入了 *（仅关键字分隔符）。以前，诸如 is_causal、return_aux 和 scale 之类的可选参数可以按位置传递；它们现在必须作为关键字参数传递。还添加了新的 window_size 关键字参数。

# Before (2.10)
output = varlen_attn(query, key, value, cu_seq_q, cu_seq_k, max_q, max_k, True, None, 1.0)

# After (2.11) — pass as keyword argument
output = varlen_attn(query, key, value, cu_seq_q, cu_seq_k, max_q, max_k, window_size=(-1, 0), return_aux=None, scale=1.0)

从 varlen_attn 中删除 is_causal 标志 (#172245)

is_causal 参数已从 torch.nn.attention.varlen_attn 中删除。因果注意力现在通过 window_size 参数表示：使用 window_size=(-1, 0) 进行因果屏蔽，或使用 window_size=(W, 0) 进行因果注意力，滑动窗口大小为 W。默认的 window_size=(-1, -1) 对应于完全（非因果）注意力。

# Before (2.10)
output = varlen_attn(query, key, value, cu_seq_q, cu_seq_k, max_q, max_k, is_causal=True)

# After (2.11) — use window_size instead
output = varlen_attn(query, key, value, cu_seq_q, cu_seq_k, max_q, max_k, window_size=(-1, 0))

分布式（DTensor）

当未提供 grad_placements 时，默认情况下，### DTensor.to_local() 向后转换 Partial 展示位置为 Replicate。 (#173454)

以前，在 Partial DTensor 上调用 to_local() 会保留向后梯度中的 Partial 位置，与 from_local() 组合时可能会产生不正确的梯度。现在，向后传递会自动将 Partial 前向放置映射到 Replicate 梯度放置，与 from_local() 的行为相匹配。 依赖先前行为（其中 to_local() 向后保留 Partial 梯度）的用户可能会看到不同的梯度值。为了确保正确性，请显式地将 grad_placements 传递给 to_local()。 版本2.10：

# Partial placement preserved in backward — could produce incorrect gradients
local_tensor = partial_dtensor.to_local()

版本 2.11：

# Partial → Replicate in backward by default (correct behavior)
local_tensor = partial_dtensor.to_local()
# Or explicitly specify grad_placements for full control:
local_tensor = partial_dtensor.to_local(grad_placements=[Replicate()])

_PhiloxState.seed 和 _PhiloxState.offset 现在返回 torch.Tensor 而不是 int (#173876)

DTensor RNG 内部 _PhiloxState 类更改了其 seed 和 offset 属性以返回张量而不是 Python 整数，并且设置器现在需要张量。这使得 RNG 状态与 PT2 跟踪兼容（之前的 ZZPH100​​ZZ 调用对假张量不友好）。 直接读取 _PhiloxState.seed 或 _PhiloxState.offset 并将它们视为整数的代码将会中断。调用.item()获取int值。设置时，将值包装在张量中。 版本 2.10：

from torch.distributed.tensor._random import _PhiloxState

philox = _PhiloxState(state)
seed: int = philox.seed          # returned int
philox.offset = 42               # accepted int

版本2.11：

from torch.distributed.tensor._random import _PhiloxState

philox = _PhiloxState(state)
seed: int = philox.seed.item()   # now returns Tensor; call .item() for int
philox.offset = torch.tensor([42], dtype=torch.int64)  # must pass Tensor

ROCm

caffe2 支持已从 ROCm PyTorch 的 hipify 预处理中完全删除。这称为“hipify v2”行为。 （＃174087，＃174300，＃174388，＃174499，＃175098）

hipify v1 背景

当 caffe2 和 PyTorch 是独立的项目时，ROCm 支持策略是不同的。 对于 caffe2，所有文件和类都将按照 CUDA 到 HIP、Cuda 到 Hip、cuda 到 hip 等模式重命名。 PyTorch 不会重命名类，但会按照相同的重命名模式创建新文件（例如，aten/src/ATen/cuda/CUDABlas.h 到 aten/src/ATen/hip/HIPBlas.h）。 因此，caffe2 有一个名为“HIP”（从“CUDA”重命名）的独特设备后端，而 ROCm PyTorch 则伪装成“cuda”设备 (torch.empty(1, device="cuda"))。 一旦 caffe2 和 PyTorch 项目合并，就会导致 caffe2 期望使用“HIP”设备而 PyTorch 期望使用“cuda”设备之间不匹配。 为了缓解这种不匹配，在 aten/src/ATen/hip/impl 下创建了“Masquerading”类。

  • HIPAllocatorMasqueradingAsCUDA.h
  • HIPCachingAllocatorMasqueradingAsCUDA.h
  • HIPGuardImplMasqueradingAsCUDA.h
  • HIPStreamMasqueradingAsCUDA.h 这些类通常在 ROCm PyTorch 对源文件进行 hipify 预处理期间透明地使用。 c10/ 和 caffe2/ 下的所有文件都使用 caffe2 重命名行为进行 hipified，而所有其他“PyTorch”文件则使用其他策略。 Masquerading 类将在 hipify 预处理期间替换其 CUDA 对应类。 例如，c10/cuda/CUDAStream.h 的 CUDAStream 将替换为 aten/src/ATen/hip/impl/HIPStreamMasqueradingAsCUDA.h 的 HIPStreamMasqueradingAsCUDA。 这些伪装类调用底层 caffe2 代码并创建“HIP”设备，并且该设备将被伪装类重置为“cuda”。

hipify v2 新行为

Hipify v2（#174087、#174300、#174388、#174499、#175098）进行了以下更改：

  • “伪装”类已被弃用。重新设计为现有类的薄壳，以实现向后兼容性。
  • 不要将“CUDA”类重命名为“HIP”。仅重命名 CUDA 运行时 API。文件仍然被重新命名。
  • 删除了 HIP 设备与 CUDA 设备的 caffe2 解决方法。 我们非常小心地使这一更改向后兼容。 尽管 PyTorch 目前可以使用 hipify v2 行为干净地构建，但明确包含 Masquerading 标头或称为 Masquerading API 的下游 PyTorch 扩展项目可能会受到影响，从而导致构建失败。 例如，在实现向后兼容性之前，xformers 项目未能使用 hipify v2 更改进行构建。 PR 展示了解决构建失败问题最初所需的更改，，但在 hipify v2 BC 破坏行为得到改进后，此类更改不再需要。

export_for_training 之前作为单独的 API 提供，用于导出模型，同时保留训练语义。该功能已被删除。用户应改用 torch.export.export，它返回与之前的 export_for_training 相同的图表。

ONNX

从 torch.onnx.export 中删除 fallback 选项 (#173189)

fallback 参数已从 torch.onnx.export() 中删除。以前，当 fallback=True 时，如果 dynamo 导出器失败，导出器将自动回退到基于 TorchScript 的旧导出器。此后备方案已被删除，因为它过于复杂，需要不同的输入，生成不同的模型，并且向新导出器隐藏了错误。 迁移： 从 torch.onnx.export() 呼叫中删除 fallback=True（或 fallback=False）。如果您需要回退行为，请通过捕获异常并单独调用旧导出器在您自己的代码中显式实现它。

# Before
torch.onnx.export(model, args, "model.onnx", dynamo=True, fallback=True)

# After
torch.onnx.export(model, args, "model.onnx", dynamo=True)

从 ONNX 调度程序中删除过载匹配逻辑 (#165083)

torch.onnx.export() 中的 custom_translation_table 参数不再接受每个割炬操作的功能列表。以前，用户可以传递一系列重载的 ONNX 函数（例如，一个用于浮点张量，另一个用于布尔张量），调度程序将根据输入类型自动选择正确的重载。这种复杂的类型匹配逻辑已被删除，因为 torchlib 不再对相同的 opset 版本使用重载。 custom_translation_table的型号由dict[Callable, Callable | Sequence[Callable]]变更为dict[Callable, Callable]。现在将 Sequence 作为值传递会引发 TypeError。 **迁移：**为每个运算符提供单个函数，而不是重载列表。如果您需要依赖于类型的行为，请在单个函数内处理它。

# Before
custom_translation_table = {
    torch.ops.aten.logical_and.default: [custom_impl_float, custom_impl_bool],
}

# After
custom_translation_table = {
    torch.ops.aten.logical_and.default: custom_impl,
}

    版本2.11：
