### 使用 `requires_grad=True` 张量调用时，现在可以正确抛出 `tensordot` 的 out 变体的错误 (#150270)
请避免使用 `requires_grad=True` 传递输出张量，因为梯度不能
计算该张量。
在2.7.0中

a = torch.empty((4, 2), requires_grad=True) b = torch.empty((2, 4), requires_grad=True) c = torch.empty((2, 2), requires_grad=True)

does not error, but gradients for c cannot be computed

torch.tensordot(a, b, dims=([1], [0]), out=c)

在2.8.0中

a = torch.empty((4, 2), requires_grad=True) b = torch.empty((2, 4), requires_grad=True) c = torch.empty((2, 2), requires_grad=True) torch.tensordot(a, b, dims=([1], [0]), out=c)

RuntimeError: tensordot(): the ‘out’ tensor was specified and requires gradients, and

its shape does not match the expected result. Either remove the ‘out’ argument, ensure

it does not require gradients, or make sure its shape matches the expected output.

## 火炬.编译
### 使用 `mark_dynamic` 进行张量形状的专业化现在可以正确应用错误 (#152661)
在 2.8 之前，符号形状上的守卫可能会被错误地
如果之前用防护装置测试了符号形状评估，则省略
被抑制（这通常发生在编译器本身内）。这已修复
在2.8中，通常会默默地“做正确的事”并添加正确的
守卫。然而，如果新的守卫导致标记为 `mark_dynamic` 的张量变成
专门化，这可能会导致错误。一种解决方法是使用
`maybe_mark_dynamic` 代替 `mark_dynamic`。
有关更多信息，请参阅问题 #157921 中的讨论
上下文。
版本 2.7.0
```python
import torch

embed = torch.randn(2, 8192)
x = torch.zeros(8192)

torch._dynamo.mark_dynamic(x, 0)

@torch.compile
def f(embedding_indices, x):
    added_tokens_mask = torch.where(x > 10000, 1, 0)
    ei = torch.narrow(embedding_indices, 1, 0, x.size(0))
    return ei.clone()

f(embed, x)

版本 2.8.0

import torch

embed = torch.randn(2, 8192)
x = torch.zeros(8192)

torch._dynamo.maybe_mark_dynamic(x, 0)

@torch.compile
def f(embedding_indices, x):
    added_tokens_mask = torch.where(x > 10000, 1, 0)
    ei = torch.narrow(embedding_indices, 1, 0, x.size(0))
    return ei.clone()

f(embed, x)

与 torch.compile 相关的几个配置变量已被重命名或删除

  • Dynamo 配置变量 enable_cpp_framelocals_guard_eval 已更改为不再有任何效果 (#151008)。
  • 电感器配置变量 rocm.n_max_profiling_configs 已弃用 (#152341)。 相反，使用基于 ck-tile 的配置 rocm.ck_max_profiling_configs 和 rocm.ck_tile_max_profiling_configs。
  • 电感器配置变量 autotune_fallback_to_aten 已弃用 (#154331)。 电感器将不再默默地回落至 ATen。请添加 "ATEN" 至 max_autotune_gemm_backends 为旧行为。
  • 电感器配置变量 use_mixed_mm 和 mixed_mm_choice 已弃用 (#152071)。 Inductor 现在支持序言融合，因此不需要 现在特殊情况。
  • 电感器配置设置 descriptive_names = False 已弃用 (#151481)。请使用其他可用的之一 选项："torch"、"original_aten" 或 "inductor_node"。
  • custom_op_default_layout_constraint 已从电感器配置转移到 functorch 配置（#148104）。请通过参考 torch._functorch.config.custom_op_default_layout_constraint代替 torch._inductor.config.custom_op_default_layout_constraint。
  • AOTI 配置变量 emit_current_arch_binary 已弃用 (#155768)。
  • AOTI 配置变量 aot_inductor.embed_cubin 已重命名为 aot_inductor.embed_kernel_binary (#154412)。
  • AOTI 配置变量 aot_inductor.compile_wrapper_with_O0 已重命名为 compile_wrapper_opt_level (#148714)。

为 HigherOrderOperator（例如 cond）添加了更严格的别名/突变检查，如果不支持输入和输出之间的别名/突变，则会显式出错（#148953、#146658）。

对于受影响的 HigherOrderOperator，将 .clone() 添加到别名输出以解决此问题。 版本 2.7.0

import torch

@torch.compile(backend="eager")
def fn(x):
    return torch.cond(x.sum() > 0, lambda x: x, lambda x: x + 1, [x])

fn(torch.ones(3))

版本 2.8.0

import torch

@torch.compile(backend="eager")
def fn(x):
    return torch.cond(x.sum() > 0, lambda x: x.clone(), lambda x: x + 1, [x])

fn(torch.ones(3))

guard_or_x 和 definitely_x 已合并 (#152463)

我们删除了 definitely_true / definitely_false 和关联的 API，将其替换为 guard_or_true / guard_or_false，提供类似的功能，可用于 达到同样的效果。请迁移到后者。 版本 2.7.0

from torch.fx.experimental.symbolic_shapes import definitely_false, definitely_true

...
if definitely_true(x):
  ...

if definitely_false(y):
  ...

版本 2.8.0

from torch.fx.experimental.symbolic_shapes import guard_or_false, guard_or_true

...
if guard_or_false(x):
  ...

# alternatively: if guard_or_false(torch.sym_not(y))
if not guard_or_true(y):
  ...

在 torch.export.export 和 export_for_training 中将默认值切换为 strict=False (#148790、#150941)

这与 strict=True 之前版本的默认值不同。恢复到旧的默认值 行为，请明确传递 strict=True。 版本 2.7.0

import torch

# default behavior is strict=True
torch.export.export(...)
torch.export.export_for_training(...)

# strict=True must be explicitly passed to get the old behavior

torch.export.export_for_training(..., strict=True)

ONNX

torch.onnx.export 中的默认 opset 现在为 18 (#156023)

dynamo=False 时，默认 ONNX opset 版本已从 17 更新为 18。用户可以设置 opset_version 来显式选择 opset 版本。 版本 2.7

# opset_version=17

版本 2.8

JitTraceConvertStrategy 已被删除 (#152556)

删除 dynamo=True 后，支持 ONNX 导出器中的 JIT 跟踪和脚本化模块。建议您直接导出 nn.Module，或在导出到 ONNX 之前使用 torch.export 创建 ExportedProgram。

onnxscript>=0.3.1 是 dynamo=True 选项所必需的 (#157017)

您必须将 onnxscript 升级到 0.3.1 或更高版本才能与 PyTorch 2.8 兼容。

构建前端

从 Dispatcher.h 中删除了 torch/types.h 包含内容 (#149557)

这可能会导致隐式依赖此包含的 C++ 代码中出现构建错误（例如非常旧版本的 torchvision）。 请注意，Dispatcher.h 不属于 torch/types.h 的包含项，仅作为 短期黑客安抚torchvision。如果您遇到 torchvision 构建错误，请 更新到更新版本的 torchvision 可以解决此问题。

将 DLPack 升级为 1.0 (#145000)

作为升级的一部分，一些 DLDeviceType 枚举值已被重命名。请切换 到新名字。 版本 2.7.0

from torch.utils.dlpack import DLDeviceType

d1 = DLDeviceType.kDLGPU
d2 = DLDeviceType.kDLCPUPinned
...

版本 2.8.0

from torch.utils.dlpack import DLDeviceType

d1 = DLDeviceType.kDLCUDA  # formerly kDLGPU
d2 = DLDeviceType.kDLCUDAHost  # formerly kDLCPUPinned
...

NVTX3 代码已从 cmake/public/cuda.cmake 移至 cmake/Dependencies.cmake (#151583)

这是构建系统界面的一次重大改变。之前通过cmake/public/cuda.cmake获得NVTX3的下游项目 （即调用 find_package(TORCH REQUIRED)）现在需要在库本身中显式配置 NVTX3 支持（即使用 USE_SYSTEM_NVTX=1）。 此更改是为了修复下游项目由于 PROJECT_SOURCE_DIR 不匹配而无法找到 NVTX3 的损坏行为。 版本2.7.0：

  • 使用 -DUSE_SYSTEM_NVTX 的下游项目将能够通过 PyTorch 的 cmake/public/cuda.cmake 逻辑找到 NVTX3 和 torch::nvtx3。
  • 不使用 -DUSE_SYSTEM_NVTX 的下游项目会遇到 CUDA 12.8 或更高版本的构建错误。 版本2.8.0：
  • 使用 -DUSE_SYSTEM_NVTX 的下游项目将无法通过 PyTorch 的 cmake/public/cuda.cmake 找到 NVTX3 或 torch::nvtx3。下游项目现在需要通过在 PyTorch 的 cmake/Dependences.cmake 中实现相同的逻辑来显式查找 NVTX3 和 torch::nvtx3。
  • 不使用 -DUSE_SYSTEM_NVTX 的下游项目将在没有 NVTX 的情况下继续构建，除非构建过程的另一部分重新启用 NVTX。

弃用

2.9 中将删除对 MacOS Ventura 的 MPS 支持

PyTorch 2.8 是支持 MacOS Ventura 上 GPU 加速的最后一个版本。在接下来的 版本 (2.9)、MacOS Sonoma（2023 年 9 月发布）或更高版本需要使用 MPS 后端。

torch.ao.quantization 已弃用，并将在 2.10 中删除 (#153892)

迁移：

  • Eager 模式量化（torch.ao.quantization.quantize、torch.ao.quantization.quantize_dynamic）
    • 仅权重和动态量化：使用 torchao eager 模式 quantize_。
    • 静态量化：使用torchao PT2E量化。
  • FX 图形模式量化（torch.ao.quantization.quantize_fx.prepare_fx、torch.ao.quantization.quantize_fx.convert_fx）：使用 torchao PT2E 量化（torchao.quantization.quantize_pt2e.prepare_pt2e、torchao.quantization.quantize_pt2e.convert_pt2e）。 请注意，PT2E 量化已迁移到 torchao (https://github.com/pytorch/ao/tree/main/torchao/quantization/pt2e)。有关详细信息，请参阅 https://github.com/pytorch/ao/issues/2259 和 https://docs.pytorch.org/ao/main/quick_start.html#pytorch-2-export-quantization。

torch.onnx.export 的 dynamo=False（当前默认）选项已弃用（#152478、#155580）

从 PyTorch 2.9 开始，默认值为 dynamo=True。我们鼓励您迁移到使用 torch.onnx.export 中的 dynamo=True 选项。此标志使 torch.export.export 成为默认导出路径，替换 TorchScript。 要保持旧行为，请显式设置 dynamo=False。我们鼓励您还尝试使用 fallback=True 选项，如果出现错误，该选项将使导出器回退到 dynamo=False 路径。
