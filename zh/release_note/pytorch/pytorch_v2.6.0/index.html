亮点

我们很高兴地宣布 PyTorch® 2.6 (release notes) 发布！此版本对 PT2 进行了多项改进：torch.compile 现在可以与 Python 3.13 一起使用；新的性能相关旋钮torch.compiler.set_stance；多项 AOTInductor 增强功能。除了 PT2 的改进之外，另一个亮点是 X86 CPU 上的 FP16 支持。 注意：从本版本开始，我们将不再在 Conda 上发布，详情请参阅[公告]弃用 PyTorch 官方 Anaconda 频道。 对于此版本，随 CUDA 12.6.3 附带的实验性 Linux 二进制文件（以及 Linux Aarch64、Linux ROCm 6.2.4 和 Linux XPU 二进制文件）是使用 CXX11_ABI=1 构建的，并且使用 Manylinux 2.28 构建平台。如果您使用自定义 C++ 或 CUDA 扩展构建 PyTorch 扩展，请更新这些构建以也使用 CXX_ABI=1 并报告您遇到的任何问题。对于下一个 PyTorch 2.7 版本，我们计划将所有 Linux 版本切换为 Manylinux 2.28 和 CXX11_ABI=1，请参阅 [RFC] PyTorch 下一个轮子构建平台：manylinux-2.28 了解详细信息和讨论。 此外，在此版本中，作为一项重要的安全改进措施，我们更改了 torch.load 的 weights_only 参数的默认值。这是一个破坏向后兼容性的更改，请参阅此论坛帖子 了解更多详细信息。 自 PyTorch 2.5 以来，此版本由 520 名贡献者的 3892 次提交组成。我们衷心感谢我们热心社区的贡献。一如既往，我们鼓励您尝试这些并在我们改进 PyTorch 时报告任何问题。有关如何开始使用 PyTorch 2 系列的更多信息，请访问我们的入门 页面。 <表>

在编译函数的不同调用之间可以采取的不同行为（“立场”）。例如，其中一种立场是 “eager_on_recompile”，指示 PyTorch 在需要重新编译时立即编码，并尽可能重用缓存的编译代码。 有关更多信息，请参阅 [set_stance 当用户将用户定义的 Triton 内核转换为自定义运算符时，`torch.library.triton_op` 允许 `torch.compile` 窥视实现，从而使 `torch.compile` 能够优化其中的 Triton 内核。 有关更多信息，请参阅 [triton_op 中使用 `torch.compile` 优化模型。 **[测试版] AOTInductor 的新包装 APIs** 引入了新的包格式“[PT2 archive](https://docs.google.com/document/d/1RQ4cmywilnFUT1VE-4oTGxwXdc8vowCSZsrRgo3wFA8/edit?usp=sharing)”。这本质上包含 AOTInductor Minifier 文档](https://pytorch.org/docs/2.6/torch.compiler_aot_inductor_minifier.html)。 **[Beta] AOTInductor：ABI 兼容模式代码生成** AOTInductor 生成的模型代码依赖于 Pytorch cpp 库。随着 Pytorch 的快速发展，确保之前 AOTInductor AOTInductor 编译的模型提供向后兼容性保证。 **[Beta] FP16 支持 X86 CPU（Eager 模式和 Inductor 模式）** Float16 数据类型通常用于减少 AI 推理和训练中的内存使用并加快计算速度。最近推出的 [Intel® Xeon® 6 with
