我们很高兴地宣布 PyTorch® 2.5 发布！此版本为 SDPA 提供了新的 CuDNN 后端，默认情况下可为 H100 或更新的 GPU 上的 SDPA 用户提供加速。此外，torch.compile 的区域编译提供了一种减少 torch.compile 冷启动时间的方法，允许用户编译重复的 nn.Module（例如 LLM 中的变压器层）而无需重新编译。最后，TorchInductor CPP 后端通过众多增强功能（如 FP16 支持、CPP 包装器、AOT-Inductor 模式和最大自动调谐模式）提供可靠的性能加速。 自 PyTorch 2.4 以来，此版本由 504 名贡献者的 4095 次提交组成。我们衷心感谢我们热心社区的贡献。与往常一样，我们鼓励您尝试这些并在我们改进 2.5 时报告任何问题。有关如何开始使用 PyTorch 2 系列的更多信息，请访问我们的入门 页面。 另外，请查看我们发布的新生态系统项目 TorchRec 和 TorchFix。

测试版功能

[测试版] SDPA 的 CuDNN 后端

cuDNN“Fused Flash Attention”后端已针对 torch.nn.functional.scaled_dot_product_attention 落地。在 NVIDIA H100 GPU 上，这可以比 FlashAttentionV2 提供高达 75% 的加速。默认情况下，H100 或更新 GPU 上的所有 SDPA 用户都会启用此加速。

[Beta] torch.compile 无需重新编译的区域编译

通过 torch._dynamo.config.inline_inbuilt_nn_modules 进行区域编译，无需重新编译，在 2.5+ 中默认为 True。此选项允许用户编译重复的 nn.Module（例如 LLM 中的转换器层）而无需重新编译。与编译完整模型相比，此选项可以导致更小的编译延迟，与完整模型编译相比，性能下降 1%-5%。 有关详细信息，请参阅教程。

[Beta] TorchInductor CPU后端优化

此功能推进了 Inductor 的 CPU 后端优化，包括 CPP 后端代码生成以及与定制 CPU 内核的 FX 融合。 Inductor CPU 后端支持常见数据类型和所有 Inductor IR 操作的矢量化，以及静态和符号形状。它兼容 Linux 和 Windows 操作系统，并支持默认的 Python 包装器、CPP 包装器和 AOT 电感模式。 此外，它还扩展了 GEMM 模板（2.5 中的原型）的最大自动调谐模式，从而进一步提高性能。后端支持各种 FX 融合，降低到定制内核，例如用于线性/Conv 操作的 oneDNN 和 SDPA。 Inductor CPU 后端在三个基准测试套件（TorchBench、Hugging Face 和 timms）中始终实现性能加速，在测试的 193 个型号中，97.5% 的性能优于 eager 模式。

原型特征

[原型] FlexAttention

我们引入了灵活的 API，只需几行惯用的 PyTorch 代码即可实现各种注意力机制，例如滑动窗口、因果掩模和 PrefixLM。该 API 利用 torch.compile 生成融合的 FlashAttention 内核，从而消除了额外的内存分配并实现了与手写实现相当的性能。此外，我们使用 PyTorch 的 autograd 机制自动生成向后传递。此外，我们的 API 可以利用注意力掩模中的稀疏性，从而比标准注意力实现取得显着改进。 更多信息和示例请参考【官方博文】(https://pytorch.org/blog/flexattention/)和【注意力健身房】(https://github.com/pytorch-labs/attention-gym)。

[原型] 编译的 Autograd

Compiled Autograd 是 PT2 堆栈的扩展，允许捕获整个反向传递。与 AOT 调度程序跟踪的向后图不同，Compiled Autograd 跟踪被推迟到向后执行时间，这使得它不受前向传递图中断的影响，并允许它将向后挂钩记录到图中。 更多信息请参考【教程】(https://pytorch.org/tutorials/intermediate/compiled_autograd_tutorial.html)。

[原型] 飞行记录仪

飞行记录器是一种新的调试工具，可帮助调试卡住的作业。该工具的工作原理是在集合体运行时不断捕获有关集合体的信息。在检测到卡住的作业时，该信息可用于快速识别行为不当的级别/机器以及代码堆栈跟踪。 更多信息请参考下面的【教程】(https://pytorch.org/tutorials/prototype/flight_recorder_tutorial.html)。

[原型] 使用 GEMM 模板对 CPU 进行最大自动调谐支持

torch.compile 中电感器 CPU 后端的最大自动调谐模式会在编译时分析多种操作实现，并选择性能最佳的一种。这对于 GEMM 相关操作特别有利，使用基于 C++ 模板的 GEMM 实现作为使用 oneDNN 和 MKL 库的基于 ATen 的方法的替代方案。我们支持 FP32、BF16、FP16 和 INT8，并支持 x86 CPU 的尾声融合。我们发现 dynamo 基准套件的几何平均加速提高了 7%，LLM 推理的下一个令牌延迟提高了 20%。 更多信息请参考【教程】(https://pytorch.org/tutorials/prototype/max_autotune_on_CPU_tutorial.html)。

[原型] Windows 上的 TorchInductor CPU

torch.compile 中的电感器 CPU 后端现在可以在 Windows 上运行。目前我们支持 Windows 感应器的 MSVC (cl)、clang (clang-cl) 和 Intel 编译器 (icx-cl)。 更多详情请参阅教程。

[原型] CPU 路径上的 FP16 支持急切模式和 TorchInductor CPP 后端

Float16 是一种常用的简化浮点类型，用于提高神经网络推理/训练的性能。自此版本以来，CPU 路径上支持 eager 和 TorchInductor 的 float16。

[原型] 自动加载设备扩展

PyTorch 现在支持树外设备扩展的自动加载，通过消除手动导入的需要来简化集成。该功能通过 torch.backends 入口点启用，通过确保无缝扩展加载来简化使用，同时允许用户在需要时通过环境变量禁用它。 有关详细信息，请参阅教程。

[原型] 增强的 Intel GPU 支持

英特尔® GPU 支持增强功能现已适用于英特尔® 数据中心 GPU Max 系列和英特尔® Client GPU（内置英特尔® Arc™ 显卡的英特尔® 酷睿™ Ultra 处理器和用于 dGPU 部件的英特尔® Arc™ 显卡），这可以让您在 PyTorch 2.5 版本中更轻松地加速英特尔 GPU 上的机器学习工作流程。在此版本中，我们还在 Windows 上启用了对英特尔® Client GPU 的 PyTorch 的初始支持。

  • 扩展了 PyTorch 硬件后端支持矩阵，以包括英特尔数据中心和 Client GPU。  
  • 实施 SYCL* 内核，以增强 Aten 运算符在英特尔 GPU 上的覆盖范围和执行，从而提高 PyTorch eager 模式下的性能。
  • 增强了 torch.compile 的英特尔 GPU 后端，以提高各种深度学习工作负载的推理和训练性能。
    这些功能可通过 PyTorch 预览和夜间二进制 PIP 轮提供。有关 Intel GPU 支持的更多信息，请参阅文档。

  • [c10d] 删除 ProcessGroup 选项并公开后端选项以反映正确的代码结构 (#132931)
    • 我们在 2.0 中发布了可调度集合，我们将使用后端选项进行后端初始化，并且不再需要 PG 选项。
    • 在2.4及之前版本中，用户可以执行以下操作：
    # Users can pass in a basic option when creating an instance of ProcessGroup
base_pg_options = ProcessGroup.Options(backend=str(backend))
base_pg_options._timeout = timeout

pg: ProcessGroup = ProcessGroup(
  store, rank, group_size, base_pg_options
)

# Users then need to create a backend option to create the comm backend (e.g., ProcessGroupNCCL)
pg_options = ProcessGroupNCCL.Options()
backend = ProcessGroupNCCL(
  store, rank, group_size, pg_options
)
    • 但从 2.5 开始，用户不需要传递选项来创建 ProcessGroup 实例，并且用户仍然可以为 pg 设置默认后端，因为用户仍然尝试在代码中获取默认后端：
    # No basic option is passed in when creating a instance of ProcessGroup
pg: ProcessGroup = ProcessGroup(store, rank, group_size)
pg._set_default_backend(Backend.backend_type_map[backend])
# Users then need to create a backend option to create the comm backend (e.g., ProcessGroupNCCL)
pg_options = ProcessGroupNCCL.Options()
backend = ProcessGroupNCCL(
  store, rank, group_size, pg_options
)

ONNX

torch.onnx.export 的选项（前三个参数除外）现在仅包含关键字 (#131501)

选项只能通过关键字提供，以允许 torch.onnx.export API 的未来添加和演变。 示例：
版本2.4

torch.onnx.export(model, input, f, True, False)

版本2.5：

torch.onnx.export(model, input, f, export_params=True, verbose=False)

已弃用的内部 API torch.onnx._export 已被删除 (133824)

torch.onnx._export 是内部 API，不适合公共消费。请使用公共 torch.onnx.export 代替。 示例：
版本 2.4

torch.onnx._export(...)

版本2.5：

torch.onnx.export(...)

torch.onnx.ExportOptions 中的 op_level_debug 选项已被删除 (#134961)

该选项旨在识别操作员差异，但事实证明不可靠，已被删除。相反，使用 torch.onnx.export(..., report=True, verify=True) 选项来验证导出的模型。

ONNXProgramSerializer 类已被删除 (#135261)

torch.onnx.ONNXProgram 中的 ONNX 模型现在由 ONNX IR 维护和序列化。
当使用相应的文件扩展名调用 ONNXProgram.save() 时，默认支持 textproto、onnxtext 和 json 格式。

SymbolicContext 类已被删除 (#132184)

已弃用的 torch.onnx.SymbolicContext 类已被删除。 （非发电机）自定义符号函数不能再将 ctx: torch.onnx.SymbolicContext 作为第一个参数。

对 caffe2 的支持已被删除 (#129021)

  • 从 onnx_unpack_quantized_weights 中删除 Caffe2 处理 (#129021)
  • 删除torch.onnx.symbolic_helper中的is_caffe2_aten_fallback

一些错误类被删除

CheckerError 和 InvalidExportOptionsError 已被移除。用户始终可以捕获 RuntimeError 来处理 torch.onnx 导出错误。

model = model.eval()  
torch.onnx.export(model, inputs, path)

dynamo=True 选项和新的导出逻辑（#132530、#133743、#134304、#134782、#135378、#135399、#135786、#136162、#135134、#134976、#135367、#135418、 ＃135591，＃135520）

我们在 torch.onnx.export() 中引入了 dynamo=True 选项。建议从 PyTorch 2.5 开始替代 torch.onnx.dynamo_export。 版本2.5：

onnx_program = torch.onnx.export(model, inputs, kwargs=kwargs, dynamo=True)  
# Use the external_data option to save weights as external data  
onnx_program.save(“model.onnx”, external_data=True)  
# To save without initializers  
onnx_program.save(“model.onnx”, include_initializers=False, keep_initializers_as_inputs=True)

torch.onnx.export(model, args, dynamo=True, report=True, verify=True) 利用 torch.export 和 ONNX IR 将捕获的 ExportedProgram 高效、稳健地转换为 ONNX。与 2.4 中的 dynamo_export 相比，这一新流程将内存消耗减少了一半，同时在 ONNX 图中保留了丰富的张量形状和堆栈跟踪信息。您可以利用 report=True 选项获取 Markdown 格式的转换报告，以诊断任何转换问题。设置 verify=True 以使用 ONNX 运行时以数字方式验证 ONNX 模型。 当使用 external_data=True 将模型权重作为外部数据保存到 .onnx 文件时，大于 1 MB 的权重现在在 64 KB 地址对齐。这允许运行时内存映射权重，以在推理过程中提高内存效率。

[注意]
dynamo=True 选项当前仅支持 ONNX opset 18。未来版本将扩展对较新 opset 的支持。 [注意]
dynamo=True 选项需要最新版本的 onnxscript 和 onnx 软件包。
