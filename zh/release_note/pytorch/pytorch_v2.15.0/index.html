torch.load(..., weights_only=True) 不再允许嵌套张量 (#194380)

嵌套锯齿状和跨步嵌套张量不再位于默认的 weights_only 允许列表中。现在，加载包含 weights_only=True（默认）的检查点会因 Unsupported global: GLOBAL torch.nested._internal.nested_tensor._rebuild_njt was not an allowed global by default（或对于跨步嵌套张量为 GLOBAL torch._utils._rebuild_nested_tensor）而失败。要加载包含嵌套张量的检查点，请使用 torch.serialization.safe_globals 明确允许它们（见下文），或对 trusted 文件使用 weights_only=False。 版本2.14：

loaded = torch.load("njt.pt", weights_only=True)  # works

版本2.15：

from torch.nested._internal.nested_tensor import _rebuild_njt, NestedTensor
with torch.serialization.safe_globals([_rebuild_njt, NestedTensor]):
    loaded = torch.load("njt.pt", weights_only=True)

通过 torch.ops.* 和 torch._C._dispatch_call_boxed 调用的运算符现在使用 PyTorch 自己的警告和异常翻译，而不是 pybind11 的 (#193451)

我们使 torch.ops.* 调用经历与库的其余部分相同的异常和警告转换。这意味着过去由 pybind 处理的一些异常转换现在由本机处理。用户定义的 pybind 异常转换因此丢失。恢复它可能会在未来的版本中完成，作为更广泛的异常处理程序改进的一部分。 此外，来自这些操作员的 TORCH_WARN 警告现在到达 Python 的 warnings 模块，因此当警告转变为错误 (-W error) 时，它们会发出警报。 std::out_of_range 仍变为 IndexError (#195713)。 版本2.14：

# C++ op: throw std::invalid_argument("bad size");
try:
    torch.ops.my_lib.my_op(x)
except ValueError:  # pybind11 translation
    ...

版本2.15：

# C++ op: TORCH_CHECK_VALUE(false, "bad size");
try:
    torch.ops.my_lib.my_op(x)
except ValueError:
    ...

# TORCH_WARN from the op is now a Python warning
with warnings.catch_warnings():
    warnings.simplefilter("ignore")
    torch.ops.my_lib.my_op(x)

选择性激活检查点现在会保存而不是重新计算具有有序效果的运算符的输出，除非策略返回 CheckpointPolicy.MUST_RECOMPUTE (#196956)

在急切模式下，如果 create_selective_checkpoint_contexts 策略为具有有序效果的非别名运算符（例如通过 register_effect(torch.library.EffectType.ORDERED)）返回 CheckpointPolicy.PREFER_RECOMPUTE，则该选择现在将被覆盖并保存其输出，因此在向后过程中不再重播副作用。这可以增加激活记忆。要保持 2.14 行为，请为该运算符返回 CheckpointPolicy.MUST_RECOMPUTE。 c10d 命名空间中的运算符被排除。在 torch.compile 下，有效运算符上的 CheckpointPolicy.MUST_RECOMPUTE 现在会在编译时引发： RuntimeError: AOTAutograd does not support MUST_RECOMPUTE for effectful operations because forward effects cannot join the backward effect-token chain. 请改用保存策略。

policy = lambda ctx, op, *args, **kwargs: CheckpointPolicy.PREFER_RECOMPUTE
checkpoint(fn, x, use_reentrant=False, context_fn=lambda: create_selective_checkpoint_contexts(policy))
# 2.14: an effectful op in fn runs twice; 2.15: once (use CheckpointPolicy.MUST_RECOMPUTE to replay)

分布式 (c10d)

nccl 后端现在默认使用重写、清理的 NCCL 实现（#192281、#192895、#193237、#193241）

backend="nccl"（也是 init_process_group() 的默认 CUDA 后端）现在创建新的实现。旧版实现仅在本版本中以 backend="nccl-legacy" 形式提供：nccl-legacy 和 TORCH_DIST_USE_NCCL2=0 将在下一版本中删除，因此请迁移到 nccl 或 nccl-lazy。 默认使用 nccl（热切初始化）。当您需要独立的点对点通信器时，请使用 nccl-lazy：集合体在一个急切创建的通信器上运行，并且每个发送/接收对等点对都有其自己的延迟创建的通信器和流，因此到不同对等点的并发 P2P 可以重叠（如在遗留后端中）。 与传统后端的区别：

  • 在 init_process_group()/new_group() 中急切地创建通信器，甚至为未使用的组分配 GPU 内存。
  • 每个组绑定到一个 CUDA 设备：device_id，否则为 LOCAL_RANK % torch.cuda.device_count()（或以设备数量为模的全局排名）；未使用ZZPH100​​ZZ。另一个 GPU 上的张量失败并显示 Expected tensor on cuda:X but found tensor on cuda:Y 或 ProcessGroupNCCL is bound to device cuda:X but an operation was issued on cuda:Y。如果需要通过device_id；每个进程需要多个 GPU 需要 nccl-legacy。
  • dist.get_backend_impl(...) 返回新的后端类，因此 isinstance(..., ProcessGroupNCCL) 是 False，并且缺少 comm_split_count() 等仅遗留方法。
  • 异步 all_gather 的 work.get_future() 值是每秩输出的列表，而不是保存堆叠张量的单元素列表；改为读取传递给 all_gather 的输出列表（适用于两个后端）。 要暂时恢复 2.15 中的旧行为，请在创建进程组之前在每个等级上设置 TORCH_DIST_USE_NCCL2=0，或使用 nccl-legacy： 版本2.14：
dist.init_process_group("nccl")  # ProcessGroupNCCL

版本2.15：

dist.init_process_group("nccl", device_id=torch.device("cuda", local_rank))  # new implementation
dist.init_process_group("nccl-lazy", device_id=torch.device("cuda", local_rank))  # independent P2P communicators
dist.init_process_group("nccl-legacy")  # legacy implementation, removed in the next release

TensorProperties 在腌制的 .metadata 文件中获得可选的 strides 字段。在旧版本中，dcp.load 会引发 CheckpointException 报告 too many values to unpack (expected 5)。没有标志可以写入旧格式。 版本2.14（加载2.15检查点）：

dcp.load(state_dict, checkpoint_id="/ckpt/step_100")

版本2.15：

分布式 FSDP2

使用 MixedPrecisionPolicy(reduce_dtype=None)，fully_shard 现在在参数的 grad_dtype（默认情况下其原始数据类型）而不是 param_dtype 中累积和减少梯度 (#194434)

这是 BC 破坏：mp_policy.reduce_dtype=None 不再默认为 mp_policy.param_dtype。

  • [流行案例] fp32 参数，MixedPrecisionPolicy(param_dtype=bf16)
    • 之前：BF16中发生了梯度积累和减少 *之后：梯度累积和减少发生在fp32中（2x减少分散字节）
  • [罕见情况] bf16 参数，MixedPrecisionPolicy(param_dtype=fp32) *之前：梯度累积和减少发生在fp32中 *之后：BF16中发生梯度积累和减少 如何处理BC：显式设置mp_policy.reduce_dtype。 在梯度累积（无reduce-scatter）中，未分片参数的.grad始终保存累积值，在未分片时通过model.parameters()可见。在此更改之前，当设置 reduce_dtype 时，.grad 是 None，并且与 param_dtype 不同（FSDP 将总和保存在隐藏的 reduce_dtype 缓冲区中）。 版本2.14：
# fp32 parameters
mp_policy = MixedPrecisionPolicy(param_dtype=torch.bfloat16)
fully_shard(model, mp_policy=mp_policy)
# gradients accumulate and reduce-scatter in bf16

版本2.15：

# fp32 parameters
mp_policy = MixedPrecisionPolicy(param_dtype=torch.bfloat16)
fully_shard(model, mp_policy=mp_policy)
# gradients accumulate and reduce-scatter in fp32

# to keep the 2.14 behavior, set reduce_dtype explicitly
mp_policy = MixedPrecisionPolicy(param_dtype=torch.bfloat16, reduce_dtype=torch.bfloat16)
fully_shard(model, mp_policy=mp_policy)

torch.distributed.config.pipeline_per_direction_p2p 已重命名为 pipeline_per_edge_p2p，现在每个定向排列边缘使用一个通信器 (#196666)

旧名称被删除，没有别名：设置属性会引发 AttributeError: torch.distributed.config.pipeline_per_direction_p2p does not exist，而 TORCH_DISTRIBUTED_PIPELINE_PER_DIRECTION_P2P 会被默默忽略。 版本2.14：

dist_config.pipeline_per_direction_p2p = True

版本2.15：

dist_config.pipeline_per_edge_p2p = True  # or TORCH_DISTRIBUTED_PIPELINE_PER_EDGE_P2P=1

分析器

C++ 堆栈跟踪现在默认使用 dladdr 而不是 addr2line 进行符号化 (#195462)

TORCH_DISABLE_ADDR2LINE 现在默认为打开状态，因为 addr2line 速度慢并且可能挂起。 TORCH_SHOW_CPP_STACKTRACES=1 错误和 CUDA 内存快照中的 C++ 帧现在显示库路径和偏移量，以及仅导出时的符号名称（否则为 ??）。要恢复 addr2line，请设置 TORCH_DISABLE_ADDR2LINE=0 或 TORCH_SYMBOLIZE_MODE=addr2line。

TORCH_SHOW_CPP_STACKTRACES=1 TORCH_DISABLE_ADDR2LINE=0 python train.py

CUDA 内存快照将分配器的 mallocWithAddress 标记记录在新的 internal_metadata 字段中，而不是将其附加到 user_metadata (#193432)

torch.cuda.memory._snapshot() 跟踪条目中的 user_metadata 现在正是使用 torch.cuda.memory._set_memory_metadata 设置的（现在也接受字典）。在 user_metadata 中搜索 mallocWithAddress 的工具必须改为读取 internal_metadata。

# 2.14
tagged = [e for e in trace if "mallocWithAddress" in e["user_metadata"]]
# 2.15
tagged = [e for e in trace if e.get("internal_metadata") == "mallocWithAddress"]

删除已弃用的 FunctionEvent.metadata_json 属性 (#198265)

现在访问它会引发 AttributeError: 'FunctionEvent' object has no attribute 'metadata_json'，并且 metadata_json 构造函数参数被删除。使用 FunctionEvent.metadata，这是设置 _ExperimentalConfig(expose_kineto_event_metadata=True) 时填充的字典（不是已弃用的 event_metadata）。

metadata = event.metadata_json  # 2.14: JSON string
metadata = event.metadata  # 2.15: dict[str, Any] or None

将实验性 CUPTI 监视器分析器后端重命名为 Cuspy，不使用旧名称的别名 (#195881)

在_ExperimentalConfig(custom_profiler_config=...)中，"cupti_monitor"现在是"cuspy"，"cupti_monitor_async_export"现在是"cuspy_async_export"；旧名称会默默地回退到默认的 Kineto 后端。 prof.take_pending_cupti_export() 现在为 take_pending_cuspy_export()（旧名称为 AttributeError）。更喜欢新款 torch.profiler.CuspyConfig。

# 2.14
cfg = _ExperimentalConfig(custom_profiler_config='{"backend":"cupti_monitor"}')
# 2.15
cfg = _ExperimentalConfig(custom_profiler_config='{"backend":"cuspy"}')

发电机

高阶操作现在拒绝其体内的输入突变和别名，除非操作选择加入 (#185738)

之前，Dynamo 默认允许任何高阶操作体对其输入进行变异或别名。不实现这些语义的操作可能会默默地生成无效的图。突变和别名现在默认处于关闭状态。支持它们的内置包装器（wrap、检查点、autograd.Function、autocast/set-grad 包装器）选择加入。flex_attention mask_mod 可以读取捕获的视图，但不得改变输入或返回别名。在 fullgraph=True 下，不支持的突变或别名会引发 Encountered input mutation during higher order op tracing 或 Encountered aliasing during higher order op tracing；否则，Dynamo 图会中断并回退到急切执行。重写高阶操作体以避免突变或混叠。 例如，将就地 flex_attention 分数修改器重写为异地操作： 版本2.14：

def score_mod(score, b, h, q, k):
    score.add_(1)
    return score.clone()

版本2.15：

def score_mod(score, b, h, q, k):
    return score + 1

电感器

torch.compiler.nested_compile_region(options=...) 现在仅接受电感器配置补丁的白名单（#195864、#195865）

通过 get_invoke_subgraph_compile_options(fw_inductor_config_patches=..., bw_inductor_config_patches=...) 的补丁过去可以接受任何 torch._inductor.config 密钥，尽管许多补丁都被默默地忽略了。现在仅接受fallback_by_default和max_autotune；其他键升高 ValueError: Inductor config key '<key>' is not supported in forward nested compile-region options（或 backward）。将其他选项应用于整个编译函数。现在，补丁字典会在创建选项时进行快照，因此以后的突变不起作用，并且默认值不再隐式设置 triton.autotune_at_compile_time=True。 版本2.14：

opts = get_invoke_subgraph_compile_options(fw_inductor_config_patches={"triton.multi_kernel": 1})

版本2.15：

opts = get_invoke_subgraph_compile_options(fw_inductor_config_patches={"max_autotune": True})
compiled = torch.compile(fn, options={"triton.multi_kernel": 1})

torch.compiler.precompile 现在是一个模块而不是可调用的；使用 torch.compiler.precompile.capture(...) 捕获并使用 torch.compiler.precompile.load(...) 重新加载（#197993、#198135、#198213）

现在跟注 torch.compiler.precompile(fn, *example_inputs) 会引发 TypeError: 'module' object is not callable。 capture(fn, *, artifact_path, cache_path) 返回一个上下文管理器，您可以在 with 块内调用一次该管理器；当块干净退出时（或在 cap.save() 上），它会写入这两个文件，并且 load 现在采用这些路径。 decompositions= 移至 tracer=MakeFxTracer(decompositions=...)。 版本2.14：

python_code, cache = torch.compiler.precompile(lambda m, x: m(x), model, x)
f = torch.compiler.precompile.load(python_code, cache)

版本2.15：

with torch.compiler.precompile.capture(lambda m, x: m(x), artifact_path="m.py", cache_path="m.cache") as cap:
    cap(model, x)
f = torch.compiler.precompile.load("m.py", "m.cache")

可组合性

在功能化下，split、split_with_sizes 或 unbind 的再生输出现在被重建为其基础的单个 slice 或 select，因此其 grad_fn 是 SliceBackward0/SelectBackward0 而不是SplitBackward0/SplitWithSizesBackward0/UnbindBackward0 (#194037)

这极大地减少了改变许多 split() 视图的代码的编译时间（例如，128 个视图从 32 秒缩短到 15 秒）。梯度不变，但就地错误现在用输出索引 0 命名新操作：RuntimeError: Output 0 of Select is a view and is being modified inplace. 检查 grad_fn 名称、匹配旧错误文本或功能化图中的模式匹配 split/unbind 节点的代码需要更新。没有选项可以恢复以前的行为。 版本2.14：

>>> out = torch.func.functionalize(f)(x)  # f returns base.unbind(0)[1] after base.add_(1)
>>> out.grad_fn
<UnbindBackward0 object at 0x...>

版本2.15：

>>> out = torch.func.functionalize(f)(x)
>>> out.grad_fn
<SelectBackward0 object at 0x...>

发布工程

PyPI 轮子现在附带 CUDA 13.2，并且 CUDA 12.6 和 CUDA 13.0 轮子不再发布（#196249、#198913）

默认的 PyPI 轮从 CUDA 13.0 移动到 CUDA 13.2。 2.15轮毂为cu132和cu134； cu126 和 cu130 不再生产。 CUDA 13 轮子需要 NVIDIA 驱动程序 580 或更高版本以及 Turing (sm_75) 或更高版本的 GPU，因此 Maxwell、Pascal 和 Volta GPU 以及具有 CUDA 12.x 驱动程序的主机应保留在 2.14。 版本2.15：

# PyPI wheel now uses CUDA 13.2
pip install torch

# CUDA 13.4 wheels
pip install torch --index-url https://download.pytorch.org/whl/cu134

# To stay on CUDA 12.6 or CUDA 13.0, pin PyTorch 2.14:
pip install torch==2.14.0 --index-url https://download.pytorch.org/whl/cu126  # or cu130

Python 3.10 车轮不再发布（#198233、#199398）

PyTorch 2.15 将二进制文件支持的最低 Python 版本提高到 3.11：没有为 torch 或 Triton 轮构建 cp310 轮，CI 不再在 Python 3.10 上进行测试。在 Python 3.10、pip 上找不到 2.15 车轮。升级到 Python 3.11 或更高版本，或继续使用 PyTorch 2.14。 版本2.14：

python3.10 -m pip install torch  # cp310 wheel available

版本2.15：

python3.11 -m pip install torch==2.15.0  # Python 3.11 through 3.15 (including 3.14t and 3.15t)

ROCm 车轮移至 ROCm 7.14 和 10.0； ROCm 7.2 轮子和 gfx900/gfx906 内核已删除 (#194919)

gfx900 (MI25) 和 gfx906 (MI50/MI60、Radeon VII) 用户可以继续使用 2.14 (rocm7.2) 或使用 PYTORCH_ROCM_ARCH 中的这些目标从源代码构建。

pip install torch --index-url https://download.pytorch.org/whl/rocm7.14  # or rocm10.0

Linux CUDA 轮子不再依赖 cuRAND 库 (#194850)

PyTorch 仅使用 cuRAND 设备 API，因此 torch 不再链接 libcurand，不再将其预加载到 import torch 上，并且轮子的 CUDA 要求不再包括 cuRAND。调用 cuRAND 主机 API（例如 curandCreateGenerator）并依赖 pip install torch 引入 cuRAND 库的扩展或库可能无法加载 libcurand.so，现在必须自行安装。 版本2.15：

pip install torch
pip install "cuda-toolkit[curand]==13.2.2"  # match the toolkit version of your wheel

CUDA

当 out 没有与输入相同的数据类型时，CUDA 上的 torch.histc(..., out=...) 现在会引发错误 (#196100)

CUDA 过去常常默默地转换为任何 out dtype。它现在匹配 CPU 和 MPS，并拒绝不匹配，甚至扩大不匹配。不使用 out 进行计算并进行投射。 版本2.14：

>>> torch.histc(x, bins=4, min=-2.0, max=2.0, out=int64_out)  # silently truncated

版本2.15：
