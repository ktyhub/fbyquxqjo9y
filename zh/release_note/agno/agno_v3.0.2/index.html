agno v3.0.2

修订 发布时间2026年8月30日 来源agno-agi/agno 英文原文

#Changelog

行为改变

  • 运行元数据优先：metadata 现在解析为组件，然后解析为会话，然后解析为 Agent、Team 和 Workflow 上的调用站点，因此传递给 run() 的 metadata= 胜过组件值之前胜出的 agent.metadata。运行不再将会话元数据分配回共享组件，因此在运行后读取 agent.metadata 以观察会话值的代码现在可以看到构造函数值。会话层仅适用于调度预读取会话的位置，因此 Team.arun 和异步数据库代理和工作流路径仍然仅从组件和调用站点进行解析。 (#9104)
  • MCPConfig 拒绝未知字段：MCPConfig/MCPServerConfig 现在在构造时引发无法识别的关键字参数，而不是忽略它们，因此诸如 tool= 之类的拼写错误在启动时失败，而不是默默地提供不同的工具表面。 (#9819)
  • BaseRemote.acancel_run 签名：抽象方法获得取消表面通过关键字传递的 auth_token 参数，因此第三方 BaseRemote 子类必须接受它。 (#9819)
  • 推理检测询问提供者：本机推理检测现在会在回退到模型 ID 匹配之前查询提供者，因此当提供者报告思维不受支持时，为思维配置的 Gemini 或 Claude 模型将被归类为非推理。查找是缓存在推理管理器上的阻塞 HTTP 调用，Ollama、OpenRouter 和 Moonshot 路径上有 10 秒超时。基于 ID 的回退也发生了变化：gpt-5 变体在 OpenAI 和 Azure OpenAI 上匹配，Groq 和 Ollama 匹配 gpt-oss 和 qwen3，Ollama 的 qwen2.5-coder 不再被视为推理模型。 (#8616)
  • MCP 配置重命名：AgentOS(mcp=...)、MCPConfig 和 default_tools 是 mcp_server=、MCPServerConfig 和 enable_builtin_tools 的新拼写。旧名称继续作为别名使用，针对 3.1 进行删除；通过具有不同值的两种拼写都会引发。 (#9819)

新集成

  • Synthorai 模型提供商：Synthorai (agno.models.synthorai) 通过其 OpenAI 兼容端点与 Synthorai 网关进行通信，读取 SYNTHORAI_API_KEY 并默认为 https://synthorai.io/v1。它已在提供程序查找表中注册，因此 model="synthorai:<model-id>" 字符串也会解析。 (#9788)
  • WaveSpeed 图像和视频生成：WaveSpeedTools（pip install agno[wavespeed]，来自 WAVESPEED_API_KEY 的密钥）通过 WaveSpeed API 生成媒体。 generate_image 和 generate_video 采用文本提示并返回携带 Image/Video 工件的 ToolResult，在 poll_interval 和 timeout 内同步轮询。 （#9620，修复#9621）
  • Serply 搜索工具包：SerplyTools 通过 Serply API 搜索 Google 网络、新闻和学术，阅读 SERPLY_API_KEY。默认情况下，网络搜索处于开启状态； search_news、search_scholar 或 all=True 启用其他。丢失密钥或失败的请求将返回 error 字段而不是引发。 （#9780，修复#9779）
  • AtomicMail 工具包：AtomicMailTools 为代理提供了自己的收件箱。 register_inbox 通过 AtomicMail 的工作证明注册提供一项，无需域设置或人工验证，而 send_email 和 list_inbox 通过 JMAP 工作。凭据缓存到 ~/.atomicmail/credentials.json，以便以后运行重用相同的收件箱，并且 pow_timeout（默认 300 秒）限制解决方案。 (#9130)

改进

  • 代理、团队和工作流作为 MCP 工具：MCPConfig.tools 现在接受 Agent、Team 和 Workflow 实例、远程代理和组件工厂，将每个实例发布为其自己命名的 MCP 工具 — chief，而不是 run_agent(agent_id="chief")。 component.as_tool(name=..., description=...) 以您选择的名称和描述发布一份。即使使用 default_tools=False，continue_run 和 cancel_run 也会与暴露的组件一起注册，因此在确认时暂停的运行仍然可以通过 MCP 恢复。 (#9819)
  • 工具包作为 MCP 工具：MCPConfig.tools 现在接受 Toolkit 并为每个注册方法发布一个 MCP 工具，由工具包自己的 enable_*/include_tools/exclude_tools 缩小范围，之前它在此处提出了 TypeError。框架参数（RunContext、Agent、Team 和 _agno_* 通道）不包含在面向 client 的架构中并填充在服务器端。返回 ToolResult 的工具被渲染为 MCP 内容块 - 文本、图像和音频、视频和文件字节的嵌入式资源以及仅 url 工件的 resource_link。之前关闭了 get_app() 的 **kwargs 入口点现在发布其声明的模式或其命名参数。 (#9846)
  • MCP 工具标题和行为注释：as_tool() 和 @tool/Function 现在接受 title 和 annotations，AgentOS 通过 MCP 发布这些暴露组件、自定义工具及其八个内置工具。即使您未设置任何内容并默认断言 readOnlyHint: False、destructiveHint: True、openWorldHint: True，公开的组件也会发布标题，并且每个键都会合并您的覆盖。未知的注释键会引发而不是传输到 client。 (#9844)
  • 上下文提供程序 query_timeout 和 write_tools：每个上下文提供程序都接受 query_timeout，这是应用于每个 query_<id> 工具调用的挂钟截止日期，它会生成错误块而不是挂起运行。它需要 Python 3.11 或更高版本，并在低于该值的施工时筹集。五个具有写入功能的提供程序还接受 write_tools 来替换默认的写入子代理工具集。 (#9104)
  • Wiki GitBackend 使 PAT 远离磁盘：令牌通过临时凭证助手在每次 git 调用时注入，而不是被烘焙到 origin URL 中，并且现有克隆在设置时被重写为裸 URL。这需要 git 2.31 或更高版本。 (#9104)
  • Slack 交付选项和更安全的批准卡：Slack 界面获得了 markdown、unfurl_links 和 unfurl_media，现在在每条消息上都明确发送。批准卡使模型生成的工具参数中的反引号、换行符和尖括号变得惰性，因此它们无法突破内联代码范围。 (#9104)
  • 无头 Google OAuth：Google 工具包接受 AuthConfig(interactive=False) 或 GOOGLE_OAUTH_NONINTERACTIVE=1，以引发而不是阻止浏览器 OAuth 流，该流永远不会在无头主机上完成。 (#9104)
  • 计划列表：新的 ScheduleManager.list_all() 和 alist_all() 分页整个计划目录和表面数据库错误，而不是返回空目录，由 get_schedules 上的新 raise_on_error 参数支持。列表现在将 created_at 关系打破为 id，因此共享时间戳的行不再跨页面跳过或重复。 (#9104)
  • Moonshot 和 OpenRouter 推理：MoonShot (Kimi) 获得读取 reasoning_content 的同步、异步和流式推理处理程序，并且 OpenRouter 通过 OpenAI 推理路径进行路由。以前，只有当它们的 ID 碰巧包含 deepseek-r1 或 minimax-m2/m3 时，才会拾取两者。 (#8616)
  • MCP 配置范围缩小到零工具现在发出警告：当默认工具打开但 include_tags/exclude_tags 范围超出每个标签并且没有传递自定义 tools 时，MCPConfig 在构建时记录警告 - 启动 /mcp 端点的配置不列出任何内容。配置仍然被接受，并且解析的工具表面没有改变。 (#9748)

错误修复

  • IPython 9.17 上的 CodeMode(allow_shell=False)：IPython 9.17 延迟注册脚本魔法并在查找时重新创建它们，因此从单元魔法表中删除 bash 不再禁用它 - %%bash 仍然在配置为禁止 shell 访问的内核中运行。现在，内核首先具体化脚本魔法提供程序，并从惰性表和实时注册表中删除 bash，因此加载诸如 %%sh 之类的同级魔法无法重新注册它。
  • 来自独立进程的注册表 MCP 工具包：StudioTools 现在在解析工具时按需连接未连接的注册表 MCP 工具包，因此从脚本、笔记本或 eval 运行创建或编辑组件不再失败并显示“工具包没有功能且无法持久化”。 eval.suite.cli/acli 采用新的 mcp_tools=[...] 参数，在案例运行之前连接这些工具包，并且 MCPToolbox 清除 close() 和失败过滤器上的 client 状态，以便重新连接重新应用 toolsets/tool_name。 (#9845)
  • 流式工作流程步骤中的执行器错误：当 Step 的 Agent 或 Team 执行器在中途失败时，流式路径将错误事件视为已完成的步骤，并发出带有 success=True 的空 StepOutput。 Step.execute_stream 和 Step.aexecute_stream 现在引发一个 RuntimeError 命名该步骤及其执行器，因此失败会通过正常的步骤错误处理，并且生成的 StepOutput 携带 success=False 和错误文本。现在，像任何其他步骤失败一样，会重试失败的流步骤。 （#9138，修复#7185）
  • 暂停运行面板中的截断工具参数：人机交互面板使用 rstrip(", ") 构建其参数列表，它会删除一组字符而不是后缀，因此也会删除属于最后一个参数自身值的尾随逗号和空格。所有三个块现在都按照 format_tool_calls 已经做的方式加入参数。这仅用于显示；传递给该工具的参数从未受到影响。 （#9246，修复#9248）

食谱

  • 固定 gpt-4o、gpt-4o-mini 或 gpt-5.4-mini 的食谱示例现在使用 gpt-5.6-luna，跨 355 个文件。网关示例也被重写，因此 LiteLLM、OpenRouter、AzureOpenAI、AzureAIFoundry、CometAPI、Requesty、LangDB 和 AIMLAPI 示例依赖于解析 gpt-5.6-luna 的网关或 Azure 部署。专用 ID 和日期快照未更改。 (#8939)
