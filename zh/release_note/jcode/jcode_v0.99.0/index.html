jcode v0.99.0

帐户故障转移、休眠和更快的重新加载

变更流程图

亮点

  • 当达到使用限制时，自动重试打开下一个池帐户，包括桌面版和 SDK clients
  • 休眠空闲会话以释放内存，测量 RAM 状态并在下一次交互时透明唤醒
  • 通过立即显示本地记录并仅发送新历史记录，可以更快地重新加载和恢复大型会话

改进

  • 支持 GPT-6.1 Sol 的 OpenAI 超快速度层，具有快速应用的快速命令和热键
  • 显示已保存的帐户、缓存的配额以及启动帐户路由器和使用卡中的可用重置
  • 带有响应式仪表和紧凑的 Mil 和 Bil 代币总数的波兰使用卡
  • 在登录选择器中提供其他 OAuth 帐户，并从中重新验证已保存的帐户
  • 通过更准确的缓存重用诊断显示内联缓存未命中
  • 显示Jcode推理支出余额
  • 压缩 OpenAI 和 Anthropic 请求主体以减少上传时间
  • 为大型远程目录构建 UI 线程的 /model 选择器
  • 仅重新连接更改的 MCP 服务器，而不是重新启动所有服务器
  • 通过删除任务图并将集群根工作量默认为低来简化集群模式

修复

  • 将启动标题和帐户行保持在窄宽度的单行上
  • 清楚地显示使用限制拒绝，而不是陈旧的配额栏
  • 修复分叉会话在重播 Anthropic Web 搜索块上失败的问题
  • 在使用中正确计算双子座思维和工具使用令牌
  • 当完成有效负载到达空时保留流式 OpenAI 输出
  • 当请求被取消或失败时保留令牌使用
  • 修复 Windows 命名管道连接在启动探测时挂起或失败
  • 修复 Firefox 冷启动被陈旧的僵尸进程阻止的问题
  • 折叠展开的固定待办事项并恢复整体进度显示 完整 changelog：https://github.com/1jehuang/jcode/compare/v0.98.1…v0.99.0

平台可用性

  • Linux x86_64：可用
  • Linux aarch64：可用
  • macOS Apple Silicon：可用
  • macOS 英特尔：可用
  • Windows x86_64：可用
  • Windows ARM64：可用
  • FreeBSD x86_64：可用 Windows 可执行文件未签名。未配置 Azure Artifact 签名，并且存储库的现有 WINDOWS_SIGNING_REQUIRED=false 覆盖允许未签名的发布。 Windows 可能会显示发布者或 SmartScreen 警告。
