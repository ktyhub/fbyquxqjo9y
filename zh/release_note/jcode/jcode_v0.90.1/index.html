jcode v0.90.1

提供商可靠性和修复

亮点

  • 回答 529 或另一个 5xx“大量使用”错误的 OpenAI 兼容提供商现在会自动重试，而不是失败，并且错误不再归咎于您的网络
  • /usage 显示 Kimi 代码、Cursor 和 Z.ai 编码计划的真实配额窗口（感谢 @ghoker143）
  • 当后续提示未决时按 Esc 会停止当前回合并运行后续（感谢 @SiavZ）

改进

  • Copilot 接受目录中宣传的每个模型的推理工作，并将其发送到响应和聊天完成 API 上
  • 保存的 API 密钥保留在其环境文件中而不是正在运行的进程中，因此编辑密钥文件无需重新启动即可生效
  • client 显示服务器解析的上下文窗口而不是占位符
  • jcode 日志记录实际启动的二进制文件，以诊断 PATH 上的过时副本
  • Gmail可以更新、列出和删除草稿
  • 编辑器中的撤消操作可立即恢复整个打字爆发，包括韩语和其他 IME 输入（感谢 @mg-mg-mg）
  • OpenAI 兼容配置文件的成本估算回落到其他提供商价格目录中的匹配模型（感谢 @ogodevonline）
  • 编辑工具行显示其意图，并且扩展徽章出现在每个差异模式中

修复

  • 通过 —provider auto 启用 DeepSeek 使用自己的默认模型和 1M 上下文，而不是 200K 的 anthropic/claude-sonnet-4
  • Termux 上的应用内更新会像安装程序一样修补 glibc ELF 解释器，并拒绝切换到无法运行的二进制文件
  • 配置的 /colors 角色现在适用于 256 色终端
  • 不再存储或发送提供商拒绝的格式的图像，并且会话会从由此产生的 400 错误中自我修复
  • 会话保存在 SIGTERM 时耗尽，中断的检查点无法再复制历史记录
  • 人为历史修复：孤立或迟到的工具结果以及孤立的本机网络搜索不再导致请求错误
  • 格式错误的工具调用会在有限的重试次数内得到纠正，而不是循环
  • 当完成门跳闸后出现新的开放工作时，自动戳重新启动
  • /accounting 不再解析为 /account
  • 崩溃检测器不再将空闲时关闭的会话报告为中断（感谢@SK-DEV-AI） 完整 changelog：https://github.com/1jehuang/jcode/compare/v0.90.0…v0.90.1

平台可用性

  • Linux x86_64：可用
  • Linux aarch64：可用
  • macOS Apple Silicon：可用
  • macOS 英特尔：可用
  • Windows x86_64：可用
  • Windows ARM64：可用
  • FreeBSD x86_64：可用
