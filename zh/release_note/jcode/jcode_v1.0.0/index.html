jcode v1.0.0

这个项目是干啥的：一个用 Rust 写的极轻量终端编程助手外壳，多个会话共用后台、内存占用极低，还能自动记住历史、让多个助手并行干活，给追求速度和多开会话的开发者用。

群、云和更轻的终端

变更架构图

亮点

  • 重新设计的集群分阶段和平行通道计划作业，在依赖关系完成时自动启动工作人员，并在一个固定视图中显示整个团队的进度
  • jcode Cloud 正式启动：使用 /cloud 将会话或协调群移动到虚拟机，断开连接后继续工作，并使用 /local 将对话和存储库恢复
  • 更轻的终端，具有更低的 CPU 使用率、更少的后台唤醒、更快的脚本渲染和更少的渲染文本内存

改进

  • 在我们自己的 jcode 开发会议中，11 月 2 日至 8 日和 11 月 9 日至 15 日期间，worker 启动数量从 88 次增加到 174 次，平均每个活动会话的worker 调度数量大约是原来的三倍
  • 分析版本 client 使用的 CPU 减少了 25%，空闲 client 唤醒每秒从 2.68 下降到 1.51，大型会话中的渲染跨度内存从 20.4 MB 下降到 14.6 MB
  • Spinner 帧处理速度加快了 3.5 倍，4,000 条消息转录本上的附加帧处理速度加快了 8.3 倍
  • 云会话首先加载最近的历史记录并按需获取较旧的消息； 7,000 条消息会话的初始历史负载从 14.3 MB 缩小到 261 KB
  • 在 /resume 中搜索完整对话，并在同一个选择器中搜索拼写错误、实时预览以及本地和云会话
  • 设置帐户优先级，使用 Ctrl+Alt+J/K 热插拔帐户，检查刷新/使用卡，并配置每个会话的上下文限制
  • 通过有界的 JavaScript 预览跟踪实时和已完成的代码模式调用，这些预览可以承受状态更改和转录压缩
  • 在完成消息中查看工作通道进度和最终报告，并提供更清晰的等待和恢复结果
  • 减少后台窗口中的轮询和重绘，在重新加载时保留焦点状态，并重用不可变的记录和提供程序请求数据，而不是重复复制它
  • 实时语音输入包括波形和流式草稿记录；模型发现和响应观察的使用归因得到改进

修复

  • 从短暂的网络中断和 HTTP/2 流错误中恢复，而不会过早地失败或建议不相关的模型切换
  • 改进帐户故障转移确认、重试取消以及防止过时回退重新发送
  • 恢复绘制恐慌后，将终端保持在 TUI 模式，包括微小的 tmux 窗格
  • 改进云切换恢复、存储库替换安全性、重新连接和就地运行时重新加载
  • 避免重复重绘未更改的待办事项快照以及重复读取已完成的后台任务文件 完整 changelog：https://github.com/1jehuang/jcode/compare/v0.99.1…v1.0.0

平台可用性

  • Linux x86_64：可用
  • Linux aarch64：可用
  • macOS Apple Silicon：可用
  • macOS 英特尔：可用
  • Windows x86_64：可用
  • Windows ARM64：可用
  • FreeBSD x86_64：可用 Windows 可执行文件未签名。未配置 Azure Artifact 签名，并且存储库的现有 WINDOWS_SIGNING_REQUIRED=false 覆盖允许未签名的发布。 Windows 可能会显示发布者或 SmartScreen 警告。
