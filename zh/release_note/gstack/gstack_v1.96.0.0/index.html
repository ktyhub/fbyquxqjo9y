gstack v1.96.0.0

这个项目是干啥的：把 Claude Code 变成一支虚拟开发团队的配置集，内置 CEO、设计、审查、测试、发版等角色，给想单枪匹马做大项目的开发者和小团队用。

变更架构图

亮点

  • 安全——立即升级 — Chromium 156 修复了 macOS 沙箱逃逸漏洞 CVE-2026-106378，qs 和 @hono/node-server 被固定到越过两条中危公告的版本，/setup-browser-cookies 现在会警告回退浏览器仍信任遭入侵的 eMudhra 证书颁发机构。多处泄漏也被堵上：精简版 /autoplan 评审人不再收到 .envrc、.env-production、凭据文件或粘贴的密钥；/ship 和 gstack-autoplan export --public 不再把所有者的审批原话、run id、计划哈希或答复贴进公开 PR/导出；review_exclude_paths 不能再隐藏原生二进制、含 NUL 字节的代码或带凭据的文件。macOS 用户或发布公开仓库的人，单凭这些就该升级。

  • /ship 更快更严——经常发布就值得 — 在完全相同的代码上跑出的绿色 CI 现在被信任，不再重跑整套测试，因此 /ship 更早推送；pre-push 会对改动文件运行仓库自身的家务检查（生成文件、大小守卫），并拒绝残留的合并冲突标记。评审深度扩展到支出/计费代码、eval 评分器、出站网络调用、归档、进程启动、可执行文件、数据封存/文件隐藏代码，以及会打印密钥的文档；新增 review ship-policy 键用于自定义风险路径，review_exclude_paths 可排除数据/日志/凭据但保留读取凭据的代码行。注意行为变化：在 Anthropic 模型上，第二模型评审现在默认用 GPT-6.1 Sol 并拒绝同族评审人，评审机器人的分流可在 Greptile 之外配置。

  • 浏览器 QA 走向多 agent 与触控优先 — 多个 agent 可同时驱动 gstack 浏览器而互不抢标签页（按 agent 分标签，或用 --session 命名），QA 可用 $B device "iPhone 15" 模拟手机，并通过 $B tap、swipe、pinch、touch 发送真实触控输入。browse handoff 现在使用 GSTACK_CHROMIUM_PATH，这对钉住自定义 Chromium 的人很重要。做移动端 QA 或并行 agent 工作流的值得升级。

  • 行为变化与新 skill——升级前须知 — 新增 /runaway-stopper，可找出烧 token 的 agent 线程/子 agent、干净地停止它们并设置默认值防止复现。但 Claude Code 和 Cursor 不再自动启动 /land-and-deploy 或 /modernize（必须手动输入命令），/investigate 在 eval 显示其固定五阶段流程从未被遵循后也去掉了该流程。新增可选项：./setup --loadout lite、./setup --skill-routing、./setup --skill-contracts。gstack-clean 回收 .gstack/ 临时文件和过大的 browse 日志，但在你传 --apply 前只报告不动手。

  • 结论——实质性发布，非空转或重新打标签 — 安全、/ship 和浏览器都有真实代码改动；为 CVE/依赖修复以及 /ship 速度和评审深度而升级。任何依赖已移除的 /land-and-deploy//modernize 自动启动的人必须调整。从不使用 /ship、浏览器或多 agent 工作流的团队可以合理跳过。

gstack v1.96.0.0

涵盖 1.92.56.0 到 1.96.0.0 版本的大型版本：/ship now trusts 绿色 CI 运行而不是重新运行测试，并将有风险的代码发送到更深入的审查，浏览器获得触摸屏测试和每个代理选项卡，新的 /runaway-stopper 技能到来，并且有几个安全修复程序。

新消息

  • 新技能：/runaway-stopper 查找正在燃烧令牌的代理线程和子代理，将它们停止在干净的点，并设置默认值以防止它们返回#3975。
  • 当 CI 运行已经通过完全相同的代码时，/ship 不再重新运行整个测试套件；它使用该结果并提前推送，以便其检查在 CI #3901 旁边运行。
  • 在每次推送之前，/ship 现在都会对您接触的文件运行存储库的快速内务检查（生成的文件、大小防护等），并拒绝剩余的合并冲突标记 #3923、#3965。
  • /ship 发送更多有风险的代码进行全面审查：支出和计费代码、评估记分器、出站网络调用、档案、进程生成、可执行文件、密封数据或隐藏文件以防止审查的代码以及可以打印机密的文档。存储库可以通过其发货策略中的新 review 键添加自己的风险路径 #3920、#3829、#3972、#3959、#3864、 [#3866]（https://github.com/garrytan/gstack/pull/3866）。
  • /ship 的审阅者不再自己克隆其他存储库，并且存储库可以列出他们永远不能读取的路径 #4007、#4011。
  • 新的 review_exclude_paths 船舶政策密钥将数据、日志和收据排除在 /ship 的审查之外，同时仍然保留代码和任何读取凭证的行 #3852。
  • /review 的清单现在从拉取请求类型（文档、CI、脚本或应用程序代码）开始，并添加一项检查，确保新文件遵循存储库自己的语言、工具和平台 #3852。
  • /ship 可以对您列出的任何评论机器人的评论进行分类，而不仅仅是 Greptile #3852。
  • 在 Anthropic 模型上，/ship 的第二个模型审核现在默认为 GPT-6.1 Sol（测试它的设置），并拒绝来自同一模型系列的审核者 #3698。
  • Codex 第二模型评论现在报告他们使用了多少代币，感谢 @omicron-soft #3729。
  • 多个代理可以同时驱动gstack的浏览器，而无需接管彼此的选项卡；每个都有自己的会话，或者您可以使用 --session #3858 命名会话。
  • QA 可以使用真实触摸输入测试手机页面：$B device "iPhone 15" 模拟手机，$B tap、swipe、pinch 和 touch 发送触摸 #3858。
  • gstack-clean 回收项目 .gstack/ 文件夹中旧的暂存文件和超大浏览日志；它只会报告，直到您通过 --apply #3858。
  • Capy 上的 Claude Opus 5.5 课程获得 gstack 技能的简化版本，指导文本较少，Claude Code 用户可以使用 ./setup --loadout lite #3858 选择它。
  • /investigate 不再让模型经历固定的五阶段程序，评估表明它从未遵循过#3858。
  • 两个选择加入的克劳德代码钩子：./setup --skill-routing 建议适合您提示的 gstack 技能，而 ./setup --skill-contracts 在其“完成意味着”步骤运行之前阻止技能结束 #3912。
  • /investigate、/review、/qa 和 /verify 现在会说明何时在描述中使用它们，并匹配更多人们实际输入的短语 #3909。
  • Claude Code 和 Cursor 不再自行启动 /land-and-deploy 或 /modernize；输入命令来运行它们#3808。
  • /autoplan 跳过错误修复的计划审核，并使用一名精益审核员来审核功能，并且父代理只能使用 gstack-autoplan next --ceo-only #3897、#3767 运行其 CEO 审核。
  • 当技能标记问题与 #3868 相关的偏好时，/plan-tune 会从未注册问题的答案中学习。
  • 必须有意保留旧值的测试现在可以保留一行放弃注释，命名旧值和原因，而不是使 /ship 的预推送文字检查失败 #3891。
  • Eval 计划现在为 Claude Haiku 5.5、GPT-6 Luna 和 Gemini 4 Argon 定价，并且 /codex 命名了当前的 GPT-6 等级，感谢 @exGeni 和 @DanCanadian #3732。
  • 如果启动 /ubicloud 的机器死机，由 /ubicloud 启动的 Ubicloud 运行可以从另一台机器上恢复和拆除 #3961。
