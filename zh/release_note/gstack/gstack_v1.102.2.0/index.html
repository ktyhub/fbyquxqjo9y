gstack v1.102.2.0

修订 发布时间2026年11月21日 来源garrytan/gstack 英文原文

gstack v1.102.2.0

这个项目是干啥的：把 Claude Code 变成一支虚拟开发团队的配置集，内置 CEO、设计、审查、测试、发版等角色，给想单枪匹马做大项目的开发者和小团队用。

变更架构图

亮点

  • Codex 兼容性修复 — 在 Codex 0.170 上，skill 不再因临时文件清理而失败，因为它们避开了被拒绝的 rm -f 形式（#4612）；/review 在 OpenAI 模型下不再把已完成的安全评审报成失败（#4622）。Codex 用户应升级。
  • /plan-tune 的隐私修复 — 答案摘要器现在在把键入的答案发给模型之前，先写入承诺的离机发送记录；如果记录无法写入，就什么都不发。新增回归测试强制此行为（#4621）。任何使用 /plan-tune 的人都应升级，以修正这一数据处理问题。
  • /ship 可用于大型仓库 — GSTACK_REVIEW_PLAN_TIMEOUT_MS 现在一致生效，仅含排除项的无效评审策略回退为评审全部内容并大声警告，并修复了若干合并、评审轮次、CI 重跑和大会话处理 bug（#4580、#4595、#4606–#4608、#4632、#4637）。破坏性行为： /ship 仍不能更改自己的评审策略。大型仓库或堆叠分支用户收益最大。
  • Skill 路由与 /office-hours 变化 — Skill 建议现在来自 hook，而非提议在 CLAUDE.md 里加 ## Skill routing 段；现有文件保持原样，因此无需手动迁移（#4629）。/office-hours 现在从基本事实出发，并在每次启动会话以带日期的测试收尾（#4468）。使用任一工作流就升级；否则这些变化基本无关。
  • Eval 模型护栏与历史重置 — /eval-plan 拒绝 gpt-4o 及被取代的模型，并给出替代名称；自 2026-11-22 起冻结的计划需要 100 条人工标注输出，而非 40 条，模型裁判结果才计入（#4630）。gstack 的 eval 辅助程序也从 Claude Haiku 4.5 迁到 Haiku 5.5，重启了付费用例的通过率历史（#4630、#4639）。Eval 维护者应升级并预期重新标注数据；不跑 eval 的用户可跳过这些变化。

gstack 1.102.2.0 修复了两处让 Codex 上 skill 失效的问题，阻止 /plan-tune 在无记录的情况下把你键入的答案发给模型，让大型仓库能用 /ship，使 /office-hours 从基本事实出发，并把 skill 路由从你的 CLAUDE.md 移到现在承担该职责的 hook 里。

Codex

  • 在 Codex 0.170 上清理临时文件时，skill 不再中断：gstack 的 Codex skill 不再使用 Codex 拒绝的 rm -f 形式（此前 67 次拒绝，之后 0 次）。（#4612）
  • Codex 上用 OpenAI 模型时，/review 不再把真正跑过安全评审的评审判为失败。Codex 会加密发给该评审人的消息，因此 gstack 现在从它启动的评审人识别该环节，而非从消息文本。（#4622）

隐私与遥测

  • /plan-tune 的答案摘要器现在在把你键入的答案发给模型之前，先写入 README 承诺的离机发送记录；若记录无法写入，就什么都不发。新测试会让任何未写记录就调用模型的情况失败。感谢 @robbiesierra 报告。（#4621）
  • 在 Capy 安装上，只有所有者的选择加入会发送用量数据，只读代码的评审人不发送，错误报告带错误类别。（#4597）

Skills

  • /office-hours 重写：先要求提供基本事实，每次启动会话以带日期的测试收尾。（#4468）
  • gstack 不再提议向项目的 CLAUDE.md 添加 ## Skill routing 段。skill 建议 hook 现在承担该职责：有了它，Claude Code 在 60 次测试会话中的 45 次和 48 次加载了正确的 bug-fix skill，而没有 gstack 时是 0/60。现有 CLAUDE.md 文件不受影响。（#4629）
  • 计划评审不再把 /design-review 审计摘要当作分支的设计文档。感谢 @robbiesierra 报告。（#4623）
  • /cso 在读取源文件前会检查其上每一层文件夹，因此绝不会穿过符号链接文件夹读取。（#4592）

大型仓库上的 /ship 与评审

  • GSTACK_REVIEW_PLAN_TIMEOUT_MS 现在在 /ship 使用它的所有地方提高评审计划时限，因此有数十万文件的仓库也能完成评审规划。超时消息会点名该设置。（#4632、#4637）
  • 当基础分支的评审策略仅在排除列表上无效时（例如超过 64 个模式），/ship 现在会带着大声警告评审每个文件，而不是拒绝，这样修复该策略的 PR 本身也能被评审。PR 仍不能更改自己的评审策略。（#4637）
  • 在使用 vitest 或 jest 的仓库中，Node 内置测试文件现在用 node --test 运行。感谢 @eoin-obrien 报告。（#4626）
  • /ship 不再卡在评审人已清除的评审意见上，按评审策略的读法统计评审轮次，并把安全发现排除在 PR 正文之外。（#4595）
  • 当 Capy 的 drive 同步数据库超过 100 MB 时，/ship 的评审不再停止。（#4606）
  • /ship 的评审读取器被告知绝不要停止并非自己启动的进程。（#4607）
  • /ship 不再因为 main 上已有的堆叠父级而要求新评审（#4580），在只带入基础分支的合并中保持已评审的 head 为最新（#4577），遵循仓库对 CI 跳过测试的重跑时限，并在新 worktree 需要安装包时给出提示（#4608）。
  • 落地一个就绪的 PR 不再依赖手工抄录的闸门裁定，且 ready note、发布 PR 和 squash 信息表述正确。（#4596）
  • 含大量捕获 agent 会话的结果 PR 现在可以被评审。（#4574）

Evals

  • /eval-plan 拒绝 gpt-4o 及任何被取代的模型作为 arm、裁判、读取器或模拟器，并给出替代名称；当计划明确说明时，用供应商默认模型测试的竞品可豁免。自 2026-11-22 起冻结的计划需要 100 条人工标注输出，而非 40 条，模型裁判的数字才计入。（#4630）
  • gstack 自身的 eval 辅助程序从 Claude Haiku 4.5 迁到 Haiku 5.5，重启了每个付费用例的通过率历史。一个脚本化测试 actor 留在 Haiku 4.5，因为 Haiku 5.5 会在该测试等待的事件之前行动。（#4630、#4639）
  • /eval-plan 写出的计划更省钱。（#4591）

文档

  • README 和文档不再声称 gstack 能让你的 agent 修更多 bug；它们说明它做什么、不做什么。（#4598）
  • 新页面：跨 agent 系统工作。（#4583）

面向 gstack 贡献者

  • Free Tests 在 16 核 runner 上运行分片（前 5 次运行中位耗时从 222 秒降到 154 秒），分片完成时间更接近。（#4600、#4578）
  • 被 runner 跳过的隔离测试现在会让运行失败，而不是通过。感谢 @Huyvux12，其 #4551 发现并首次修复。（#4590）
  • 抖动修复：spawnSync 溢出检查（#4613）；每周测试时间记录重新能落地（#4581）且记录的时间是最新的（#4633）；任务日志的 sleep 对真实 runner 足够长（#4589）。
  • 最慢的免费测试文件被拆成六份（#4588），Windows setup 测试在安装改动后更快完成（#4575），PR 不再等待抖动测试上传（#4579）。
  • 九个运行 eval 的团队的习惯被写入 gstack 自身的工作规则（#4585、#4602）；gstack 在 Capy 上的自身使用与真实使用分开统计（#4576）；Capy 上 agent 线程的 token 签到行减半，以匹配 Capy 的新计数（#4582）。
  • 一项关于 /ship 是否需要其辅助 agent 的实验更新了计划：每个 arm 一次不计数的试点、一次对一半案例的预定检查、在最终远程闸门拒绝处停止，以及为其裁判多做一次带标注的尝试。（#4587、#4605、#4609、#4611）
