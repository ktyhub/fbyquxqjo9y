gstack v1.99.4.0

变更流程图

亮点

  • /ship 评审韧性 — 在 Capy 上，如果 OpenAI 以网络安全风险为由拒绝第二模型评审，/ship 会用 GPT-6 Astra 配一份只读正确性简报重试一次，再用 Gemini 4 Carbon，并在 PR 中明确标注第二评审仍不可用（#4350）。这减少了无声的单模型评审，同时不把拒绝当作批准。
  • GBRAIN_HOME 正确性与迁移检查 — setup、restore、/health 及其他 gbrain 检查现在遵循并修剪 GBRAIN_HOME，而非假定 ~/.gbrain；当配置只存在于 GBRAIN_HOME 下时，同步提示也能工作（#4343、#4344）。升级后步骤： 若两处位置都存在，运行一次 gstack-gbrain-source-wireup --check-target；TARGET: MISMATCH 表示早先的同步指向了另一个 brain。
  • /ship 测试与大 diff 可靠性 — .github/scripts/ 这类隐藏文件夹中的测试不再被报成”未找到测试”；基于文件名的 review_exclude_paths 条目现在会排除结果 manifest.json 这类类配置数据文件；超过 2 MB 的 PR diff，第二模型评审会独立渲染（#4348、#4356、#4361）。这避免了本可避免的失败和 REVIEW_DIFF_TOO_LARGE 卡住，尤其对数据密集型 PR。
  • 更严格的评审闸门核算 — 评审人现在以一行阻塞项计数结尾，gstack 会将其与解析出的发现核对，防止措辞异常的阻塞项蒙混过关（#4353）。这主要面向维护者，但强化了 /ship 的通过/失败判定。
  • 升级建议 — 如果你用 /ship——尤其是 Capy、隐藏测试文件夹或大 diff——或依赖带 GBRAIN_HOME 的 gbrain，就升级；其他用户可以跳过此版本。没有列出接口破坏性变更，gbrain 目标检查是唯一明确的迁移步骤。

gstack v1.99.4.0

主要是 /ship，gstack 的命令可以为您审查、测试和打开拉取请求：它的第二个模型审查现在在提供商的拒绝中幸存下来，并且具有自定义大脑文件夹的 gbrain 用户再次获得了正确的大脑。

新消息

  • 当 OpenAI 以网络安全风险为由拒绝 /ship 的第二个模型审查时，Capy 上的 /ship 现在会在 GPT-6 Astra 上重试一次，并提供只读正确性摘要，然后在 Gemini 4 Carbon 上重试一次，并在 PR 中明确表示第二次读取仍然缺失 #4350。

修复

  • 当 GBRAIN_HOME 指向一个大脑而 ~/.gbrain 持有另一个大脑时，gbrain 设置和恢复不再写入错误的大脑，并且当您唯一的配置位于 GBRAIN_HOME 下时，现在会出现技能开始同步提示 #4343。
  • /health 和其他 gbrain 检查现在从 GBRAIN_HOME 读取 gbrain 的配置，按照 gbrain 修剪它的方式进行修剪，而不是仅从 ~/.gbrain #4344 读取。
  • /ship 现在在隐藏文件夹（例如 .github/scripts/）中运行测试文件，而不是因为“未找到测试”而失败 #4348。
  • 当您的基础分支的 review_exclude_paths 按文件名命名时，具有配置样式名称的数据文件（例如结果 manifest.json）现在会离开 /ship 的审查，因此大型结果 PR 不再以 REVIEW_DIFF_TOO_LARGE 停止 #4356。
  • 对于差异超过 2 MB 的拉取请求，/ship 的第二模型审查可以再次单独呈现 #4361。

维护者的变化

  • /ship 的审阅者现在以一行结束，说明有多少结果被阻止，并且 gstack 会根据它读取的结果进行检查，因此以不寻常形式编写的阻止程序将不再能够通过 #4353。 **升级：**如果您设置了GBRAIN_HOME并且还有~/.gbrain文件夹，则运行gstack-gbrain-source-wireup --check-target一次。它会打印 TARGET: MATCH 或 TARGET: MISMATCH 并告诉您较早的同步是否已发送到另一个大脑。 比较v1.99.3.0…v1.99.4.0 · 完整changelog
