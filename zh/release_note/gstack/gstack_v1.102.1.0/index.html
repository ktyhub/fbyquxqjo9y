gstack v1.102.1.0

这个项目是干啥的：把 Claude Code 变成一支虚拟开发团队的配置集，内置 CEO、设计、审查、测试、发版等角色，给想单枪匹马做大项目的开发者和小团队用。

变更架构图

亮点

  • 遥测加固 — 使用数据现在只通过 gstack 受检的端点流动；公钥无法访问数据表，已登录的 Supabase 用户也被拒绝访问。选择加入的运行会额外收集九个固定选项字段，涵盖 agent/模型、调用与终止上下文、路由/hooks 状态、随机的每会话 ID 以及升级结果——不含代码、路径、提示词或仓库名。迁移/破坏性行为： 早于 v0.11.16.0 的版本会停止发送使用数据，因为它们直接写入数据表；如果你依赖用量上报，请升级。
  • 安全修复 — /careful 现在拦截更多 wipefs 变体、带引号或经符号链接写入 /dev 的操作，以及 git push -fn --no-dry-run。/cso 审计含符号链接的仓库时不再跟随链接，而是逐条报告目标。密钥隐藏现在能捕获斜杠之后的 name=value 凭据，堵住了 /cso 历史报告中暴露的缺口，同时保护评审材料、用量数据和 /ship 日志。
  • Skill 加载与建议 — Claude Code 在加载每个 skill 时会执行其 start 步骤，解决了测试中模型只有 45%–62% 的时间会遵循该步骤的问题；加载失败时保留此前的手动回退。建议现在忽略反引号和代码块内的内容，bug 报告提示只推荐已安装的 bug-fix skill，而不再优先给 /verify。后台任务和浏览器扩展安装也会说明将添加什么、如何移除。Codex 及其他 agent 保留原有 start 步骤行为。
  • /ship 与评审可靠性 — 当仓库存储已满、GitHub 无法保存运行产物时，/ship 可以改用 CI 任务的日志；当更早的 CI 测试运行无法复用时，它会停下来给出指引，而不是启动完整的本地测试套件。被接受的 open-note 裁定现在可以放行发布，包括外部保存的发现。仅做 eval 的预注册走更轻的单评审人路径，数据行不再虚增评审规模，run ID 以及以 GStack 开头的团队在审批记录中也能正常工作。
  • 升级建议 — 这是一次实质性的安全与可靠性发布，不是重新打标签。Claude Code 用户、重度使用 /ship/评审的团队、接触密钥的人以及依赖遥测的用户都应升级。其他不受这些路径影响的 agent 或工作流可以合理跳过；除了旧客户端的遥测截断外，没有通用的 API 或配置迁移。

gstack 1.102.1.0 修复了”斜杠后写入的密钥可能未被隐藏就打印出来”的缺口，收紧了 gstack 的用量上报并让选择加入的用户更能用上它，修复了 gstack 为提示词挑选正确 skill 的一系列 bug，并让 gstack skill 的 start 步骤在 Claude Code 加载该 skill 时执行，从而不再被跳过。

用量上报（遥测，选择加入）

  • 用量上报后端现在只接受通过自身受检端点传入的数据：仓库里的公钥不再能读写数据表，已登录的 Supabase 用户被全面拒绝。gstack 自身的测试运行从不发送用量数据，测试流量不计入 gstack-community-dashboard，其周活数现在统计真实安装数而非更新检查数。早于 v0.11.16.0（2026 年 3 月）的 gstack 版本停止发送用量数据，因为它们直接写表。（#4537）
  • 如果你选择加入，每次 skill 运行现在还会发送九个新字段，每个都从固定列表中选取：是哪个编码 agent 运行的、模型家族、是你/模型/另一个 skill 发起的、为何结束、其自身检查是否通过、gstack 的路由段落与 hooks 是否配置好、随机会话 id，以及对于升级，来自哪个版本、升级为何失败。来自 CI 和 gstack 自身 eval 的运行会自我标记，gstack 无法测量的时长发送空值而不是 0。选择加入的问题会列出新字段，匿名模式现在说明发送的是”无设备 ID；每个 agent 会话一个永不复用的随机 id”。没有任何字段携带代码、文件路径、提示词或仓库名；每个字段都列在 docs/privacy.md 中。（#4542）

Skills 与 skill 建议

  • 在 Claude Code 中，每个 gstack skill 的 start 步骤现在在 skill 加载期间运行，因此模型无法再跳过它（测试运行里，模型只有在 45% 到 62% 的会话中遵循了已加载 skill 的 start 步骤）。如果加载失败，skill 会用一行说明，模型仍像以前一样自己执行 start 步骤。Codex 和其他 agent 保留旧指令。（#4509）gstack 检查该 start 步骤的付费测试现在会把加载期间跑过的那次计入。（#4543）
  • 当提示词读起来像 bug 报告时，skill 建议 hook 现在只给出你已安装的 bug-fix skill，绝不在其前面推荐 /verify。在 60 个真实 bug 修复提示词上，它现在对全部 46 个 bug 报告都点名了 bug-fix skill。（#4539）
  • skill 建议 hook 现在忽略反引号和代码块里的词，因此像 “Run gh pr review 123” 这样的引用命令不再触发 /review，粘贴日志里的 --fix flag 也不会让提示词看起来像 bug 报告。感谢 @vilano93 发现并首次修复。（#4566）
  • 在安装后台任务（gbrain autopilot）或 gstack 浏览器扩展之前，gstack 现在会用一行说明即将添加什么，包括如何移除。新增的测试会在未来安装步骤漏掉这行时失败。（#4538）

安全与防护

  • 破坏性命令检查（/careful）堵上了更多绕过磁盘擦除和强制推送拦截的方式：wipefs -a 在所有目标及更多拼写形式下都被拦截，写入磁盘时若路径带引号或经由指向 /dev 的链接也被拦截，git push -fn --no-dry-run 算作真正的强制推送。此前被拦截或被询问的操作，现在没有一项被放行。（#4534）
  • /cso 现在可以审计含符号链接的仓库。它会在报告中列出每个链接及其目标，且从不跟随，此前只要有一个链接（哪怕是 CLAUDE.md -> AGENTS.md）就会中断审计。感谢 @nathanshox 报告并首次修复。（#4567）
  • gstack 的密钥隐藏现在也能隐藏斜杠之后以 name=value 形式写的密码、API key 或 token（例如 cfg/api_key=… 或 https://host/cb/token=…），此前只在行首捕获。/cso 的历史报告曾打印出这类值；现在它以及 gstack 隐藏密钥的所有其他位置（评审材料、用量数据、/ship 日志）都会隐藏它们。（#4571）

/ship 与代码评审

  • 当 GitHub 因仓库存储已满而拒绝保存运行文件时，绿色 CI 运行仍计入 /ship 和合并：gstack 现在可以在相同的检查下从任务日志读取同一条记录。（#4536）
  • 当 CI 更早的测试运行无法复用时，/ship 现在会停下来告诉你该怎么做，而不是在你机器上启动整套测试套件。（#4565）
  • 当仓库所有者裁定一次中断评审的发现可作为 open notes 接受时，这些裁定现在能让 /ship 完成（#4552），评审记录会标明哪些发现仍在等待裁定（#4553），且发现保存在单独文件中时裁定同样有效（#4568）。
  • 只添加 eval 计划及其纯数据文件的 PR（预注册）现在走为文档类设计的更轻的单评审人评审，且 gstack 计算评审规模时数据行不再算作代码行。（#4544）
  • /ship 审批记录中的 run id（如 507-7192673）不再被误认成电话号码而拦截，名称以 “GStack” 开头的团队也能记录裁定。（#4549）

浏览器与测试

  • 浏览器辅助程序不再选择 Chrome 拒绝打开的 10080 端口，因此大约每 39,000 次启动中就有 1 次不再无法加载自身页面；还修复了一个不稳定测试。（#4554）
  • 当 /ship 以允许的方式修复评审人的结果行时，gstack 的文档同步 eval 不再失败。（#4555）
  • 对 gstack 开发者：在 gstack 免费测试运行中失败后重试通过的每个测试现在都会被记录，包括手工在分支上启动的运行，这样不稳定测试就能被统计并修复。（#4572）
  • 对 gstack 开发者：PR 上的测试运行提前一步启动，因为拆分测试的任务现在与更早的检查并行运行，而不是等它们之后。（#4570）

  • 在 Claude Code 中，每个 gstack 技能的开始步骤现在在技能加载时运行，因此模型无法再跳过它（在测试运行中，模型仅在 45% 到 62% 的会话中遵循加载技能的开始步骤）。如果加载失败，该技能会在一行中说明这一点，并且模型会像以前一样自行运行开始步骤。 Codex 和其他代理商保留旧的说明。 (#4509) 检查此启动步骤的 gstack 付费测试现在会计算加载期间运行的步骤。 (#4543)

  • 技能建议挂钩现在会忽略反引号和代码块内的单词，因此“运行 gh pr review 123”等带引号的命令不再触发 /review，并且粘贴日志中的 --fix 标志不再使提示看起来像错误报告。感谢@vilano93，他发现并首先修复了它。 (#4566)
  • gstack 现在会在一行中告诉您在安装后台作业 (gbrain autopilot) 或 gstack 浏览器扩展之前要添加的内容，包括如何删除它。如果将来的安装步骤忽略该行，则新测试将失败。 (#4538) 安全与保障

  • 当所有者裁定停止审查的结果可以作为开放注释接受时，这些裁决现在让 /ship 完成 (#4552)，审查记录显示哪些结果仍在等待裁决 (#4553)，并且当审查结果保存在单独的文件中时，裁决也有效 (#4568)。
