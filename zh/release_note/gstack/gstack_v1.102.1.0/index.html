gstack v1.102.1.0

gstack 1.102.1.0 弥补了斜杠后写入的秘密可以不隐藏地打印的差距，锁定 gstack 的使用报告并使其对选择加入的人更有用，修复了 gstack 如何为提示选择正确技能的一系列错误，并使 gstack 技能的开始步骤在 Claude Code 加载技能时运行，因此无法跳过。 使用情况报告（遥测、选择加入）

  • 使用情况报告后端现在仅通过其自己的检查端点接受数据：存储库中的公钥无法再读取或写入表，并且登录的 Supabase 用户将被拒绝一切。 gstack 自己的测试运行从不发送使用数据，测试流量被排除在 gstack-community-dashboard 之外，并且其每周活动计数现在计算实际安装而不是更新检查。早于 v0.11.16.0（2026 年 3 月）的 gstack 版本停止发送使用数据，因为它们直接写入表。 (#4537)
  • 如果您选择加入，现在每个技能运行还会发送 9 个新字段，每个字段都从固定列表中选择：哪个编码代理运行它、模型系列、您、模型还是其他技能是否启动了它、结束的原因、它自己的检查是否通过、gstack 的路由部分和挂钩是否设置、随机会话 ID、以及升级的版本以及升级失败的原因。从 CI 和 gstack 自己的 evals 标签运行，gstack 无法测量的持续时间被发送为空而不是 0。选择加入问题列出了新字段，匿名模式现在表示它发送“没有设备 ID；每个代理会话的随机 ID 永远不会重复使用”。没有字段包含代码、文件路径、提示或存储库名称；每个字段都在 docs/privacy.md 中列出。 (#4542) 技能和技能建议
  • 在 Claude Code 中，每个 gstack 技能的开始步骤现在在技能加载时运行，因此模型无法再跳过它（在测试运行中，模型仅在 45% 到 62% 的会话中遵循加载技能的开始步骤）。如果加载失败，该技能会在一行中说明这一点，并且模型会像以前一样自行运行开始步骤。 Codex 和其他代理商保留旧的说明。 (#4509) 检查此启动步骤的 gstack 付费测试现在会计算加载期间运行的步骤。 (#4543)
  • 当提示读起来像错误报告时，技能建议挂钩现在会单独命名您已安装的错误修复技能，并且不会在其前面建议 /verify。现在，在 60 个真实的错误修复提示中，它会在所有 46 个错误报告中命名错误修复技能。 (#4539)
  • 技能建议挂钩现在会忽略反引号和代码块内的单词，因此“运行 gh pr review 123”等带引号的命令不再触发 /review，并且粘贴日志中的 --fix 标志不再使提示看起来像错误报告。感谢@vilano93，他发现并首先修复了它。 (#4566)
  • gstack 现在会在一行中告诉您在安装后台作业 (gbrain autopilot) 或 gstack 浏览器扩展之前要添加的内容，包括如何删除它。如果将来的安装步骤忽略该行，则新测试将失败。 (#4538) 安全与保障
  • 破坏性命令检查 (/careful) 关闭了围绕其磁盘擦除和强制推送阻止的更多方式：wipefs -a 在每个目标上都被阻止，并且在更多拼写中，当其路径被引用或通过到 /dev 的链接时，对磁盘的写入将被阻止，而 git push -fn --no-dry-run 算作真正的强制推送。以前被阻止或询问的任何事情现在都不允许。 (#4534)
  • /cso 现在可以审核包含符号链接的存储库。它在报告中列出了每个链接及其目标，并且从不跟踪它，而在此之前，单个链接（甚至 CLAUDE.md -> AGENTS.md）停止了审核。感谢@nathanshox 的报告和第一次修复。 (#4567)
  • gstack 的秘密隐藏器现在还隐藏密码、API 密钥或斜杠后写为 name=value 的令牌（例如 cfg/api_key=… 或 https://host/cb/token=…），而之前它仅在行首捕获它们。 /cso的历史报告已经打印了这样的值；它和 gstack 隐藏秘密的所有其他地方（查看材料、使用数据、/船舶日志）现在都隐藏它们。 (#4571) /发货和代码审查
  • 当 GitHub 由于存储库的存储已满而拒绝存储运行的文件时，绿色 CI 运行仍然计入 /ship 和合并：gstack 现在可以在相同的检查下从作业日志中读取相同的记录。 (#4536)
  • /ship 现在停止并告诉您当 CI 的早期测试运行无法重用时该怎么做，而不是在您的计算机上启动整个测试套件。 (#4565)
  • 当所有者裁定停止审查的结果可以作为开放注释接受时，这些裁决现在让 /ship 完成 (#4552)，审查记录显示哪些结果仍在等待裁决 (#4553)，并且当审查结果保存在单独的文件中时，裁决也有效 (#4568)。
  • 仅添加评估计划及其纯数据文件（预注册）的拉取请求现在获得用于撰写的较轻的单审阅者审阅，并且当 gstack 调整审阅大小时，数据行不再算作代码行。 (#4544)
  • /ship 审批记录中的运行 ID，例如 507-7192673，不再被误认为电话号码而被屏蔽，并且名称以“GStack”开头的团队可以记录裁决。 (#4549) 浏览器和测试
  • 浏览器助手不再选择 Chrome 拒绝打开的端口 10080，因此大约 39,000 个启动中的一个不再无法加载自己的页面；一项不稳定的测试也得到了修复。 (#4554)
  • 当 /ship 以允许的方式修复审阅者的结果行时，gstack 的文档同步 eval 不再失败。 (#4555)
  • 对于 gstack 工作人员：现在会记录在 gstack 的免费测试运行中失败然后通过重试的每个测试，包括在分支上手动启动的运行，因此会计算并修复不稳定的测试。 (#4572)
  • 对于使用 gstack 的人员：拉取请求上的测试运行会更快地开始一步，因为拆分测试的作业现在与早期检查一起运行，而不是在它们之后运行。 (#4570)
