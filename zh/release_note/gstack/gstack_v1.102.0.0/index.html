gstack v1.102.0.0

gstack 1.102.0.0 使 Codex 成为一流的主机：它现在获得 gstack 的技能建议、破坏性命令检查和 /review 的清单保留。破坏性命令检查被重建，询问的频率大大降低，同时发现更多的真实伤害。 破坏性命令检查（/小心）

  • 它不再询问删除临时文件（/tmp、mktemp 文件夹、缓存、构建输出），并且现在在项目外部删除、丢弃未提交的工作、历史重写、远程分支删除、数据库重置和云删除之前询问。无论写入方式如何，/ 或主文件夹的递归删除、强制推送到默认分支以及擦除整个磁盘都会被阻止。在重播 254,322 个真实代理命令时，无害请求从命令的 1.40% 下降到 0.33%，捕获的破坏性命令从 948 个命令中的 443 个增加到 930 个。(#4513)
  • 它更仔细地读取命令：git push --repo=origin +main、cd 后的强制推送或 --all/--mirror、安静的 git clean -q、find -L … -delete 和 wipefs -a 在每个拼写中都会被捕获； git push -nf SQL 文本的空运行和 grep 不再询问。在相同的重播中，它捕获的破坏性命令不少于，并且增加了 141 个无害的请求（总共占命令的 0.39%）；后续行动正在处理这些问题。 (#4525)
  • 代理 SDK 程序收到警告而不是询问，因为 SDK 拒绝询问无人回答。设置 GSTACK_SESSION_KIND=interactive 以保留询问。 (#4513) 法典
  • ./setup --host codex (Codex 0.170+) 添加了钩子，建议正确的 gstack 技能提示，并在每个 shell 命令之前运行破坏性命令检查。 Codex 无法询问单个命令，因此有风险的命令会在交互式会话中被阻止，并在 codex exec 下发出警告。 Trust 当 Codex 在启动时询问时挂钩。 (#4512)
  • 如果 Codex 试图在没有对抗性通过或报告的情况下完成，则 /review 会举行一次，就像 Claude Code 一样。 (#4522) 它将以 task_name 开头的 Sol 子代理计为该通道。 (#4526)
  • 当您的 Codex 文件夹的路径包含 shell 字符时，Codex 挂钩可以工作，卸载会保留您自己的挂钩 trusted，安装程序更紧密地匹配 Codex 的挂钩模式，并且 /review 的检查列表读取引用的 ; 并正确读取失败。 (#4528)
  • 技能建议、选择器提示和文档按照 Codex 列出的方式命名技能（$review，而不是 $gstack-review）。 （＃4523，＃4524）
  • 办公时间、计划设计审查和 gstack 升级再次加载到 Codex 上，codex exec 下的一项技能知道它是无人值守的，Codex 审阅者从干净的上下文开始。 (#4510) 挂钩和路由
  • 默认情况下，辅助挂钩处于打开状态，破坏性命令检查作为挂钩运行，并且在长错误报告上触发提示路由。凭借 gstack 自己的技能，路由钩子路由了 60 个真实错误报告中的 14 个（原为 17 个）；文档现在匹配。 （#4503，#4505）
  • 路由挂钩现在还建议您自己安装的技能，并停止向 /qa 发送错误报告。通过安装的技能，它可以发送 60 个真实错误报告中的 40 个。 (#4506) /发货、审核和 CI
  • 在 Capy 上，/ship 不再对您的 GitHub 帐户下的拉取请求进行编辑或评论；它将文本交给 Capy 自己的 PR 工具。 (#4518)
  • 输出被切断的命令现在会失败，而不是根据其输出的一部分进行判断。这弥补了差异超过 64 MiB 的推送可以携带凭证通过预推送挂钩的差距。 （＃4492，＃4502）
  • 失败的第二模型审查列出了停止它的原因，将 402 记录为预算停止，并且从不删除自己的提示。 （＃4515，＃4519）
  • 当修复涉及合并检查时，第二轮审核现在会对其进行审核，而不是报告已完成。 (#4520)
  • Ship 策略可以将发布的数据标记为内容，以便 /ship 可以审查大数据 PR，并且此类文件夹无法隐藏源代码或代理文件以防止审查。 （＃4511，＃4516）
  • 当正在发货的结帐不是项目的默认结帐时，/ship 的审核有效。 (#4507)
  • /ship 的状态机检查接受其读取器写入的标题行。 (#4504)
  • 更改号码检查会停止标记仅共享 limit 等单词的测试。谢谢@dtoelke。 (#4496)
  • 当版本仅重新生成声明的文件时，合并版本的 PR 会重用其先前的测试运行。 (#4483)
  • 当 Claude Code 在提交之前运行 /verify 时，它会进行快速检查，而不是完整的修复循环 (#4508)，并且该检查在超时时会彻底失败。 (#4527)
  • 评论收集器不再删除作为摘要项目符号编写的真实 P0，并停止将评论者的范围列表视为调查结果。 (#4527)
  • gstack-ship-queue ready 现在填写了与其他开放 PR 的试验合并，第二个模型检查了决策记录，加上六个小/船舶工具修复，包括记录从另一个代理转发的裁决。 (#4529)
  • 工作人员在自己的会话中启动的测试运行不再因停滞而被终止。谢谢@dtoelke。 (#4533)
  • 免费套件 CI 在缓慢的 Ubuntu 镜像中幸存下来，并且修复了四个不稳定的测试和评估检查。 (#4530) GBrain
  • /sync-gbrain 的读取检查在第一页超过 64 KB 时起作用。 (#4497)
  • 同步第二个存储库不再使第一个存储库要求您再次同步。谢谢@SatriaSuriaAriffin。 (#4532)
