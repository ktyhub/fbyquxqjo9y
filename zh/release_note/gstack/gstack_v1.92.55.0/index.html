gstack v1.92.55.0

这个项目是干啥的：把 Claude Code 变成一支虚拟开发团队的配置集，内置 CEO、设计、审查、测试、发版等角色，给想单枪匹马做大项目的开发者和小团队用。

变更架构图

亮点

  • /ship 评审与测试大改 — 评审深度现在按风险而非 diff 大小决定（#3820）：触及安全、用户数据、金钱、密钥、登录或合并检查的代码走完整评审团，其余走轻量评审，文档/测试只需单个评审人。评审最多两轮，未解决的阻塞项升级给仓库所有者，而不是进入第三轮循环。评审人对照远程基础分支（#3780），测试选择不再把同名兄弟文件误认为改动的模块（#3814），也不让”warn”放过失败的测试（#3792），且若已有未完成的 merge/cherry-pick/revert，/ship 会干净地停下（#3785）。如果你依赖 /ship，这是升级的核心理由——更少的幽灵阻塞、更少的冗余循环、更安全的合并。

  • 排队/批量合并加固并泛化 — gstack-ship-queue 不能再同时向 main 发布两个合并，也不能合并缺少版本提升的 PR（#3737）；wave plan 只按真实代码冲突分组 PR，并排除 CI 红灯或仍在运行的 PR（#3791）；wave 可把同一领域的 3–6 个 PR 折成一个 PR、一次 /ship 运行和一个版本（#3772）；批量合并现在适用于任意仓库，而非只有 gstack（#3692）。对一天合并很多 PR 的团队值得；一次只发一个 PR 则无关。

  • 新命令与更广的工具/平台支持 — gstack-flaky 把失败的测试重跑一次，防止抖动把 CI 变红，并记录以便每日集中修复（#3612）。/autoplan --ceo-only 运行一次安静、无提问的 CEO 评审（#3788）；/retro 新增 “Friction by skill” 行，/retro global 现在能看到 Kimi Code、OMP 和 Antigravity 会话。gstack 可安装进 Gemini CLI，并剔除 v1.91.231.0 之前安装中的陈旧 test/eval 包（#3778）；未设置 OpenAI key 时，设计 skill 通过 Google Gemini 生成图片样机——设置 GEMINI_API_KEY 即可启用（#3768）。OpenClaw/Hermes 用户可选择启用 gstack-harness register openclaw|hermes --start-hook（默认关闭，#3786）。

  • 升级前需检查的迁移/配置变化 — 团队模式安装现在跟随 stable 分支，该分支指向此版本；想跟踪每次合并可用 gstack-config set update_channel main。install.sh --project 现在把子文件夹解析到其 git 仓库根目录，并拒绝仓库名这类非文件夹值（#3783）——审查任何传旧格式的自动化。嵌套仓库现在可用空的 .gstack-project 文件声明自己是独立项目（#3777）。注意 docs/support-tiers.md 中的支持策略：macOS/Linux 完全支持，Windows 和 Gemini 模型仅最低限度支持（#3812）。

  • 可靠性修复与升级结论 — gstack-brain-sync 不再发布无法解析的 JSON，并能从 push_failed 恢复（#3796、#3728）；gstack-redact 和密钥检查减少 diff 行及 Python/Dart 标识符的误报；项目提交了 gstack 自身文件时，更新不再无声卡住（#3750）；Windows 修复恢复了 gstack-review-scope summary，并让 JSONL 合并驱动处理非英文文本/CRLF（#3714）。这是一次实质性常规发布（117 个版本），不是重新打标签或仅改元数据——用 /ship、合并队列或需要新命令的就升级。仅 Windows/Gemini 环境且从不涉及发布的可以跳过，因为这些平台仍只是最低限度支持，主要拿到的是小修复。
