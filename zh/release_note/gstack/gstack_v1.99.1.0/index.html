gstack v1.99.1.0

gstack v1.99.1.0

主要是安全修复：gstack-uninstall 不再删除未保存的工作，大脑同步和预推送挂钩捕获更多隐藏的秘密，以及 /review 和 /ship 在非 Claude 主机下的 Windows 上重新启动。

修复

  • /review 和 /ship 在 Codex、Cursor 和其他非 Claude 主机下的 Windows 上再次启动，其中安装程序遗漏了它们需要的文件，并且 /retro 和 /write-skill 具有相同的差距（感谢 @SatriaSuriaAriffin）#4286。
  • gstack-uninstall 不再删除嵌套在另一个签出中的工作树、锁定的工作树、作为其自己的 git 存储库的 .gstack/ 文件夹或您在要求继续时编辑的工作树 #4267。
  • gstack-uninstall 现在会检查要删除的每个文件夹中是否有未提交或未推送的 git 工作，而不仅仅是运行它的存储库，如果发现任何 #4282，则会以文件夹名称停止。
  • Brain sync 现在扫描 git 将其视为二进制的文件，并捕获在现有密钥下添加的 auth 值，因此不再推送此类文件中的密钥 #4276。
  • 大脑同步现在可以捕获 JSON 转义背后隐藏的秘密，而 ~/.gstack 中的预提交挂钩会检查同步所执行的相同类型的秘密 #4264。
  • 秘密检查和预推送挂钩现在捕获跨两行 UTF-16 文本的秘密分割，并且删除大型二进制文件不再阻止推送 #4261。
  • gstack 的 QM 版本不再包含 gstack-review，因为基准测试发现它标记了太多问题而没有改进工作； gstack 自己的 /review 未更改 #4279。

维护者的变化

  • /ship 审查簿记：在仅文档提交之后开始的授权后续审查现在很重要，并且所有者的裁决可以清除授权后续审查发现的新阻止者，以便 /ship 可以以列出的方式完成 #4278 #4260。
  • 预合并和合并队列修复：部分预合并检查运行不再作为完整的检查运行通过，队列在检查 PR 之前获取最新的主文件，当其就绪注释从未到达 GitHub 时它会拒绝，并且当仅分支运行隐藏红色检查时它会发出警告 #4258 #4256 [#4254]（https://github.com/garrytan/gstack/pull/4254）[#4270]（https://github.com/garrytan/gstack/pull/4270）。
  • 现在，当仅重新运行运行中的不相关作业时，会接受重用的 CI 结果 #4274。
  • 测试修复：合并队列测试、每个新版本都失败的医生策略测试，以及六项测试和评估检查，这些检查误读了正确的工作或与自己的固定装置进行了竞争#4271#4293#4284。 升级： 重新运行 gstack-artifacts-init（或在您恢复的计算机上运行 gstack-brain-restore）以刷新 Brain-sync 预提交挂钩。如果您运行 QM 版本，请删除其 sandbox/skills/gstack-review/ 文件夹并运行 qm up。 比较v1.99.0.0…v1.99.1.0 · 完整changelog
