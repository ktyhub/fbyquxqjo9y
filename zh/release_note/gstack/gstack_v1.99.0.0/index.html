gstack v1.99.0.0

gstack v1.99.0.0

一个大型版本：UI 工作的构建时设计循环、许多 /ship 和 /autoplan 修复，以及在推送任何内容之前进行更强大的秘密检查。

新消息

  • /design-review --build <preview url> 是您仍在构建的 UI 的新选择循环：它列出了您的更改可以显示的状态，使用屏幕截图检查桌面和手机宽度上的每个状态，并修复最多三轮的间距和点击目标问题，而无需提交任何内容 #4142。
  • gstack 的设计 lint 现在可以检查正在运行的应用程序屏幕的某一部分是否有拥挤的行、狭窄的帮助文本、像名字一样响亮的注释以及小点击目标 #4138。
  • /ship 现在用日常用语编写拉取请求标题、提交消息、分支名称和 changelog 条目，说明使用该项目的人发生了什么变化 #4146。
  • 存储库可以在 .gstack/ship-policy.json (docs_only) 中列出自己的仅文档文件夹，因此那里的散文更改也跳过 /ship 中的完整测试运行 #4185。
  • /eval-plan 现在要求 lesson: 行，gstack 的指导说结果记录会以两个或三个简单的要点打开，首先起作用的是 #4173。
  • /autoplan 文档和帮助文本现在说明了快速运行和完整的交互式运行实际上给审阅者带来了什么#4186。

修复

  • /autoplan 的最终批准步骤再次呈现，并且接受对其计划批准项目的回复（感谢 @exGeni 的报告，感谢 @ElNeMeR70 和 @szsunyuan 提出的修复建议）#4219。
  • /autoplan 的 rec 和 all 回复现在应用每个建议的计划更改，并且 rec 是单字默认值 #4225。
  • 在克劳德代码 ZZPH100​​ZZ 压缩长会话后，/autoplan 不再卡在阶段之间（由 @vilano93 报告和修复）#4226。
  • 当 Claude Code 将其阶段报告保存为以另一句话开头的摘要时，/autoplan 不再在一个阶段后停止（感谢 @mstormo 找到原因）#4171。
  • 选择加入 /autoplan 门现在使每个阶段在其自己的报告之后立即发布其结果，按顺序 #4135。
  • 当 Linux 主机阻止 Chromium 的沙箱（原生 Ubuntu 23.10+ 或非 root Docker）时，gstack 的浏览器现在会打印清晰的修复，而不是 Playwright 日志墙 #4162。
  • 浏览器缺失错误不再告诉 Linux 和 Windows 用户打开 macOS 专用的 Aside 应用程序 #4131。
  • browse scroll <selector> 再次滚动到该元素，而不是滚动到页面底部 #4192。
  • gstack 的渲染器不再将 Debian 和 Ubuntu 的 /usr/bin/browse（指向 xdg-open 的链接）误认为是自己的浏览器 #4192。
  • 在 Codex、repo-local 和其他没有 ~/.claude 的安装上，浏览器保存的站点技能现在保留在它们保存的项目中，而不是显示在每个项目中 #4192。
  • 当问题的标记是用 capitals 编写或带有格式错误的提示时，“从不问”问题首选项现在仍然适用 #4192。
  • 在浏览守护进程中启动两个快速隧道，或者在守护进程自己启动期间启动一个，不再使第二个公共 ngrok 隧道保持打开状态，而您无法关闭 #4210 #4212。
  • 当 Bun 在检查健康钩子时崩溃时，./setup 不再拒绝健康钩子 #4167。
  • gstack-uninstall 不再删除存储库提交的 .gstack/ 文件或 .gstack-worktrees/ 中未保存的工作 #4241。
  • macOS 上的 QA 捕获不再将已完成的命令记录为不完整（感谢 @vilano93 的报告和测量）#4170。
  • 当两台机器各自记录大脑同步推送之间的决策时，同步现在会重建合并的决策列表，而不是在以后的每次推送中失败 #4220。
  • 秘密检查和预推送挂钩现在读取 git 视为二进制的文件（NUL 字节、UTF-16 文本或 -diff 属性），因此隐藏在文件中的令牌不再被推送 #4243。
  • 学习、时间线事件和大脑​​同步不再存储或推送带有密码的 Stripe live 密钥、Slack 令牌、npm 令牌或数据库 URL #4247。
  • 预合并机密检查不再使读取环境变量的代码失败，例如 opts.env.API_TOKEN 或 import.meta.env.X #4157。
  • 预合并机密检查不再在 Django 的 session = self.client.session 上停止/发布（由 @dgrant 报告）#4228。
  • 预推送检查不再标记名称仅以 tmp 或 scratch 开头的真实文件 #4177。
  • 当 /ship 发布 PR 描述时，虚假隐私更少：CI 运行号码和类似的机器编写号码不再被读取为电话号码 #4198。
  • 当 /ship 的文档检查回复出现小格式错误时，它不再停止，并且仅修复形状错误的回复一次，而不是用完重试 #4147 #4205。
  • /ship 的第二模型审查在提到问题时不再被认为是干净的，并且以有关其检查的句子结束的干净审查不再被报告为缺失 #4130 #4136 #4140。
  • /ship 不再停留在干净的审阅者回复上，仅顺便提及一个严重性词，或者停留在带有嵌套列表的编号项目的低调查结果上 #4218 #4237。
  • /ship 不再打开 GitHub 问题以获取 PR 未更改的代码中的审查结果；它们保留在 PR 描述 #4208 中。
  • /ship 不再停滞在合并了数千个数据文件的分支上，大结果 PR 现在符合其审查大小限制 #4149 #4184。
  • /ship 不再要求对您的审核政策遗漏的文件进行资金审核，也不再保留结果文件进行审核，因为模型回复包含“fit (” #4159 #4195。
  • 当 CI 结果在同一提交中重用时，/ship 不再运行相同的剩余本地测试两次 #4127。

维护者的变化

  • gstack 自己的拉取请求仅更改面向人类的文档，现在会跳过测试套件并运行文档检查 #4178。
  • 合并工具修复：合并队列在检查失败时不再调用 head green，不再放置堆叠 PR 的未经审查的父提交，在一个 git 进程中读取其注释，并接受重新运行 CI 再次运行 #4235 #4229 #4242 [#4246]（https://github.com/garrytan/gstack/pull/4246）。
  • 审阅工具修复：在较早的审阅发现阻止程序之后进行后续的干净审阅计数，仅围绕已审阅的更改移动行的基本合并不再强制进行另一次全面审阅，并且带有引用名称的数据文件保留其秘密行审阅 #4188 #4259 #4203。
  • 规划记录修复：计划检查适用于公共存储库，每个 /autoplan 批准哈希命名其自己的运行，代理无法再解决仅限所有者的 /autoplan 问题，并且批准表将本地路径保留在 PR 描述之外 #4133 #4137 #4201 [#4199]（https://github.com/garrytan/gstack/pull/4199）。
  • 代理线程工作流程文档和工具：线程将其 PR 保留到最后，在更新之间保持安静，在持有开放 PR 时无法存档，并且外部 PR 被视为错误报告；仅限 Capy 的工具移至其自己的文件夹中，并仅安装在 Capy 计算机上 #4240 #4176 #4244 #4251 #4250 #4204 #4213 #4224 #4145 #4143。
  • 设计说明衡量对仅代理线程拉取请求进行较轻的检查可以节省什么#4144。
  • 现在在拉取请求合并之前需要进行“简单标题”检查，并处理很长的描述 #4152。
  • CI：Trunk 现在监视更多拉取请求作业并接收仅用于片状测试检测的免费套件结果，当其计时数据过时时，免费套件将保持在其作业时间上限内，并且依赖项和 CI 操作会出现补丁冲突 #4148 #4187 #4245 [#4202]（https://github.com/garrytan/gstack/pull/4202）。
