gstack v1.91.242.0

这个项目是干啥的：把 Claude Code 变成一支虚拟开发团队的配置集，内置 CEO、设计、审查、测试、发版等角色，给想单枪匹马做大项目的开发者和小团队用。

变更架构图

亮点

  • 每周发布与新的 stable 频道 — v1.91.242.0 是 gstack 首个每周标签，汇总了自 v1.91.146.0 以来的 96 个版本；这是真正的聚合，不是仅改元数据的重新打标签或空转。团队模式自动更新现在跟随指向此处的新 stable 分支；如果你此前跟踪每次合并，那不再是默认，必须运行 gstack-config set update_channel main 重新选择。团队模式和钉住标签的用户应升级（stable 上会自动发生）；已经跟随 main 的个人用户可以跳过频道变更。
  • 安全加固，但有一处提醒 — #3463 将 dompurify、MCP SDK、zod、body-parser、fast-uri 和 ip-address 移到修复版本，#3312 阻止目标仓库通过其 .env 或 bunfig.toml 重新配置 gstack 自身的程序。有一处残余是披露而非修复：BROWSER.md（#3403）记录 gstack 自带的浏览器仍信任遭入侵的 eMudhra 中间证书，以及如何检查。如果你运行不受信任的仓库或在意依赖 CVE，就升级；证书问题仍需手动检查。
  • 更小的安装与 Windows 稳定性 — 全新安装减少约 520 MB，因为 ./setup 现在只安装生产依赖（#3426），安装器瞄准 Bun 1.4.4（#3368、#3345）。Windows 获得三个具体修复：无符号链接的工作流锁让 skill 重新能启动（#3424），关闭 Git Bash 路径转换时不再丢失评审/提问/学习/时间线记录（#3431），以及当 Bun 来自 npm 时，浏览器终端 agent 不再每 60 秒重启或闪出控制台（#3388）。Windows 用户和磁盘/CI 受限的环境应升级；其他人可视作家务更新。
  • 评审与发布闸门变化 — 严重程度统一为单一标度，CRITICAL 或 INFORMATIONAL，覆盖 /ship 各专家、/plan-eng-review 和 /review（#3402）；/ship 和 /review 只能重审自己的修复，但收窄后的通过永远不能成为放行的评审（#3414、#3404）；合并队列现在拒绝从未运行过 /ship 的 PR（#3438），第二意见的”未就绪”不再被报告为干净（#3376）。测试选择现在覆盖 Rust、嵌套 pnpm/vitest、Django/Dart/Flutter 和无扩展名的 .jsx/.mts/.cts 导入。依赖 /ship 或合并队列闸门的团队应升级，因为这些改变了什么能合并；纯 /review 用户也受益。
  • 设计与无人值守流程行为 — /design-shotgun 上选中的布局现在会带入 /design-html，而非重新挑选（#3422），已接受的 craft 发现会持久化并通过 gstack-design-craft --accepted <finalized.json> 消费（#3422），落地页围绕单一访客动作构建（#3420）。主动建议现在默认四个核心 skill，带 core/all/off（#3432），gstack-config set plan_mode_preamble off 可去掉前言（#3308），无人值守运行把最终摘要写到 .gstack/tmp/ 下，并仅在支持处写 GSTACK_RESULT 行（#3409、#3392）。设计和 Capy/无人值守用户应升级；若从不用这些流程或 plan mode，可安全跳过。
