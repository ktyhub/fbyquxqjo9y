gstack v1.91.318.0

变更流程图

亮点

  • /ship 明显更可靠 — 评审深度现在随 diff 风险伸缩，--review-fanout auto|serial|parallel 适配可用子 agent 数量，增量评审减少重复工作，同时能扛住 rebase、基础分支合并和堆叠 PR 的重定向。修复还覆盖没有 VERSION 的仓库、被删除/重命名的测试、gstack-pr-shots 修改 .gitignore，以及嵌套自动升级。频繁使用 /ship 的人应升级。
  • CI 等待与合并队列改进 — 新的 gstack-pr-wait 报告真实 PR 事件，不再让 /land-and-deploy 轮询，支持 --exclude <check>，并用 gstack-config 键区分必需的评审机器人与仅供参考的。运行合并队列的团队升级理由最明确。
  • Agent 集成与 skill 工具扩展 — 新 skill 包括 /write-skill、/modernize、/ubicloud 和 /design-motion；harness 原生安装和 OpenClaw 任务-skill 发现提升了可发现性。共享前导缓存和缩小 15–40% 的 skill 加载也降低了开销。Skill 作者和 harness 用户应升级；其他人可跳过这些新增项。
  • 破坏性变更与要求有限 — 破坏性： 移除 Dia 浏览器支持，gstack 不再从它导入 cookie；请换用其他受支持的浏览器。跨新提交复用 /ship 评审现在要求 git 2.39 或更高。所提供的条目中没有发现大范围迁移。
  • 发布行为与证据限制 — stable 现在每周更新两次，通常至少间隔 72 小时；安全修复和稳定频道回归修复可绕过该间隔。所提供的 changelog 在 1.91.253.0 处截断，因此无法评估 1.91.242.0 与 1.91.252.0 之间的改动。
