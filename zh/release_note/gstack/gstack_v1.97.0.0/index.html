gstack v1.97.0.0

小版本 发布时间2026年11月7日 来源garrytan/gstack 英文原文

gstack v1.97.0.0

这个项目是干啥的：把 Claude Code 变成一支虚拟开发团队的配置集，内置 CEO、设计、审查、测试、发版等角色，给想单枪匹马做大项目的开发者和小团队用。

变更架构图

亮点

  • 浏览器安全——建议升级 — 内置浏览器升级到 Playwright 1.65.0 / Chromium 158，不再信任遭入侵的 eMudhra 证书颁发机构（#4087）。审计与网络日志也不再留存输入值、对话框答案、cookie、请求头、URL 查询值和凭据（#4073、#4081、#4082）。凡是用到 gstack 浏览器工具的人都应升级。
  • 减少 /ship 评审循环与卡住 — /ship 不再在自身改文档、机械性的版本/规则提升，或不匹配的 review_exclude_paths 变更后要求重复评审。评审人收到的仍是裁剪后的同一份 diff，大仓库的规划约 35 秒完成，还修复了若干误报或评审卡住的情况。文档、测试覆盖率和计划审计现在遵从你偏好的模型，而不再固定用 Sonnet 5.5（#4038、#4042）。
  • 新增可选的工作流闸门 — 启用 ./setup --investigate-gate 后，修复前必须写下根本原因，包括通过 shell 做的改动；启用 ./setup --ceo-review-gate 后，/plan-ceo-review 在记录排序后的发现前不能结束（#4045、#4047）。较慢的闸门扫描不再让会话在未经检查的情况下结束。这些都是可选开关，不启用则行为不变。
  • 发布策略兼容性 — 官方未宣布破坏性变更。但新的 ship-policy 键 mechanical_retake 和 test_code 要求 gstack 1.97.0.0（#4079）。稳定频道用户现在也能在一天内收到关键修复，稳定版与已测试的 main 改动最多相差一周（#4083）。
  • 针对性的可靠性修复 — gstack-brain-sync 即便遇到误导性的远程 URL 也能正确重试推送，browse 守护进程避免端口选择竞态，/runaway-stopper 能容忍常规的 CI 签到，Ubicloud runner 不再把 API 错误当作成功、也不会销毁其他调用方的 VM。用到这些工作流的就升级；否则除了浏览器安全改进外，这个版本基本可以跳过。

gstack v1.97.0.0

主要是 /ship，gstack 的命令为您审查、测试和打开拉取请求：减少不必要的额外审查轮次、遵循您的模型偏好的审核、将 /investigate 和 /plan-ceo-review 保留到其关键步骤的两个选择加入门，以及浏览器安全修复。

新消息

  • /plan-ceo-review 的选择加入门会阻止会议结束，直到审核写出排名结果；使用 ./setup --ceo-review-gate #4047 将其打开。
  • /investigate 的选择加入门会阻止修复，直到写下根本原因，包括通过 shell 命令进行的修复；使用 ./setup --investigate-gate #4045 将其打开。
  • 如果您遵循稳定的更新渠道，重要的修复（安全、回归、数据丢失、阻止程序）现在可以在一天内达到稳定，并且稳定不会比主 #4083 上测试的更改晚超过一周。

修复

  • 安全性：gstack 的捆绑浏览器现在使用 Playwright 1.65.0 和 Chromium 158，它不再是受损的 eMudhra 证书颁发机构 #4087。
  • 浏览审核日志不再保存您在页面中输入的内容，例如使用 fill 或 type 发送的密码、对话答案以及 cookie 或标头值。由 @derHaken #4073、#4081 报告。
  • 浏览审核日志和网络日志不再保留 URL 查询值或凭据，因此提交的登录表单的字段不会出现在磁盘上 #4082。
  • gstack-brain-sync 不再仅仅因为远程 URL 包含 auth 或 403 之类的单词而将被拒绝的推送称为身份验证错误，因此它会按应有的方式重试推送 #4035。
  • 浏览守护进程不再因“端口……正在使用中吗？”而失败。在繁忙的机器上；现在，它在开始侦听之前选择其端口 #4035。
  • gstack 的秘密扫描不再将 config.prod 或 server.local(...) 等普通代码标记为泄露的内部主机名，感谢 @nazarli-shabnam #4043。
  • /ship 的文档、测试覆盖率和计划审核现在在您在首选项中设置的模型上运行，而不是始终在 Sonnet 5.5 #4038、#4042 上运行。
  • 当 /ship 自己的文档审核在审核后编辑文件时，即使审核运行两次 #4034、#4071，也不再要求进行另一轮审核。
  • 当没有文件匹配 #4030、#4036、#4041 时，在主分支上添加 review_exclude_paths 模式不再强制再次通过审核打开拉取请求。
  • 每个 /ship 审阅者现在都会看到相同的修剪后的差异，包括在启动失败后自行重建指令的审阅者 #4048。
  • /ship 的审查计划在非常大的结果存储库上大约 35 秒完成，而不是超时 #4040。
  • 充满捕获模型提示的结果拉取请求不再仅仅因为这些提示提到 API 关键变量而达到 /ship 的审核大小限制 #4044。
  • /ship 和 /review 不再计算审阅者的结束语，例如“这些都没有达到关键”。作为一项重要发现 #4075。
  • 父级被挤压合并的堆叠拉取请求不再将 /ship 标志 main 自己的更改作为未经审查的编辑 #4021。
  • 在审核完成后添加包含金钱、担保或数字声明的文档行时，/ship 不再卡住 #4062。
  • /ship 在基本合并后不再卡住，既更改了已审阅的行，又移动了旁边的代码；它现在要求进行一次小的重新检查 #4054。
  • 当基础合并仅碰撞您的船舶政策声明为机械的版本或规则编号时，/ship不再要求新的审查#4053。
  • /ship 不再停止在审核后添加的 Godot .uid 文件上，并且您的船舶策略现在可以命名您自己的测试文件 #4063。
  • 最低 gstack 版本比最新稳定版本更新的发布策略现在会按名称拒绝，而不是将会话发送到无法满足它的升级 #4080。
  • /investigate 的“上次编辑后再次测试”检查现在会注意到通过 shell 命令（例如 sed -i 或 Heredoc #4078）编写的修复。
  • 当扫描运行缓慢时，/investigate 和 /plan-ceo-review 门不再让会话不受检查地结束 #4072。
  • /runaway-stopper 不再将等待 CI 时每四分钟检查一次的代理标记为失控 #4069。
  • /ubicloud 后面的 Ubicloud 运行程序永远不会将 API 错误视为成功，也永远不会破坏另一个调用者以相同名称创建的虚拟机 #4039、#4046。

维护者的变化

  • /ship 的完成和接受步骤更好地处理所有者授予的修复轮次：链式修复检查所有计数，授予的轮次刷新自行重新读取的资金和安全，所有者规则的注释关闭其发现，结果命名其使用的赠款 #4050、#4064、#4070， [#4077]（https://github.com/garrytan/gstack/pull/4077）。
  • 金钱和安全重新读取记录在以后的主合并中保留下来，并接受从基础船舶策略中获取 CI 等待限制 (ci_record_timeout_s) #4058、#4065。
  • 当分支仅添加测试运行时，接受会根据其自己的测试策略检查该分支，并且所有者可以为一次测试运行授予例外 #4061。
  • 新的船舶策略密钥 mechanical_retake 和 test_code 需要 gstack 1.97.0.0 #4079。
  • 在 Capy 上，/ship 帮助程序命令现在记录它们自己的调用，因此运行的调用计数是已知的 #4059。
  • gstack 自己的存储库现在每 8 小时对 main 运行一次付费发布检查，在 main 移动后合并之前重新测试合并到 main 提示的拉取请求，并且在合并之前重新运行 CI 跳过的测试文件 #4031、#4029、#4028。
  • 合并步骤在 Linux 上运行的检查中隐藏了自己的环境，包括 GitHub 令牌 #4032。
  • 发布文件检查接受存储库的发布工具重新生成的发布输出#4033。
  • 编辑 setup 的拉取请求不再在窄屏幕上运行每个付费评估案例 #4056。
  • 免费 CI 慢分片警告现在考虑了跨并行作业分割的分片，感谢 @indraoverflow #4085。
  • 测试修复：两个测试文件现在在一个进程中通过，四个片状测试报告它们失败的原因 #4068、#4074。
  • 证据清单记录最新的路由和/调查评估判决#4076。
  • gstack 现在为另一个代理主机生成三种技能（调查、审查和计划审查）的按需加载版本 #4049。
  • 代理文档：Capy 上的代理仅通过 Capy 的 PR 工具发表评论和请求评论，代理运行/发布睡眠直到完成并保持上下文较小，AGENTS.md 仅按名称列出技能 #4027、#4055、#4060。 比较v1.96.0.0…v1.97.0.0 · 完整changelog
