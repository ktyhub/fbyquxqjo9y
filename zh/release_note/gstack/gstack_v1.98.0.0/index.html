gstack v1.98.0.0

变更流程图

亮点

  • 新安装走 stable 频道 — 全新 git clone 加 ./setup 现在跟随经过测试的 stable 版本，而非 main，因此新用户拿到的是经过审查的构建；现有安装和贡献者 checkout 仍跟随 main，setup 会打印切换命令。在 Capy 上，gstack 现在至少每天自更新到最新 main，除非带有理由地钉住 [#4091]。这很重要，因为新用户得到的是可预测、经过测试的基线，而非 main 上的每个改动。

  • 破坏性——两个 skill 退役 — /plan-eng-review [#4108] 和 /investigate [#4110] 不再安装，因为 eval 发现它们相比普通 Opus 5.5 没有收益，在 18 个真实 bug 修复上也无增益；/autoplan 仍会运行其工程评审阶段。迁移：下次 ./setup 会移除旧条目，但保留你以这些名字编写的 skill。任何直接调用这些斜杠命令的人必须调整。

  • 本地服务与远程配对全面锁死 — 通过 /pair-agent 隧道，远程 agent 现在只能打开网页：不能读取本地文件、挑选磁盘路径或保存截图 [#4116]。design board 和 iOS QA 后台服务只响应直接的本地请求，且 design board 链接带私有密钥 [#4117]。/setup-gbrain 不再把 gbrain 数据库 URL（含密码）放到命令行，凭据脱敏范围更广 [#4114]；Capy 安装器在检测 Bun/Node 版本时停止加载 bunfig.toml/.env [#4115]；/make-pdf 只从文档自身文件夹读取真实图片文件，否则显示”图片已阻止”占位符 [#4113]。这是升级的最强理由。

  • 会话闸门与 UI 检测修复 — /plan-ceo-review [#4102] 和 skill 必需步骤 [#4104] 的完成闸门现在等待 Claude Code 写完 transcript，因此已完成的运行不再被错误拦住；/autoplan 新增可选闸门，通过 ./setup --autoplan-gate 或 gstack-config set autoplan_gate on 启用 [#4100]。/ship 和 /autoplan 现在能识别 .ts/.js 内的 Lit/htm 模板为前端——触发设计检查和 Design 阶段——且快速运行不再声称合并了跳过的 Design 阶段 [#4112] [#4121]。PR 等待被限流为每分钟最多一次 GitHub 检查，并带速率限制退避，以停止消耗共享 API 配额 [#4109]。

  • 值得升级吗？ — 是的：任何暴露 /pair-agent、design board、iOS QA 或 gbrain 凭据的人（这里的加固是实质性的），想要 stable 频道的新安装用户，以及获得评审记账、共享预算和合并前检查修复的 /ship 维护者 [#4089]–[#4124]。如果你依赖已退役的 /plan-eng-review 或 /investigate skill 且尚未迁移，或你特意想让全新 clone 跟随 main 而非 stable，可以跳过——不过现有安装本就保持 main。这是实质性发布，不是重新打标签或仅元数据空转。

gstack v1.98.0.0

新安装现在遵循经过测试的稳定版本，两项很少使用的技能已退役，并且多个本地服务和浏览器的远程配对已被锁定。

新消息

  • 新的 git clone 和 ./setup 现在遵循稳定通道，因此新用户可以获得经过测试的版本，而不是主版本上的每个更改；现有的安装和贡献者签出继续遵循 main，并且安装程序会打印要切换的命令。在 Capy 上，gstack 现在每天至少更新一次到最新的 main，除非你有原因固定它 #4091。
  • /autoplan 有一个选择加入门（./setup --autoplan-gate 或 gstack-config set autoplan_gate on），可以防止会话结束，直到每个计划阶段都发布其报告并且最终批准步骤被写入 #4100。
  • /plan-eng-review 不再安装，因为两次评估发现它比普通 Opus 5.5 没有添加任何内容； /autoplan 仍然运行其工程审查阶段，下一个 ./setup 会删除旧条目，但会留下您单独以该名称编写的技能 #4108。
  • /investigate 不再安装，在对 18 个真实错误修复进行评估后发现没有从中获得任何好处；下一个 ./setup 以相同的方式删除旧条目 #4110。

修复

  • 在 Capy 上，在 open /ship 或 review 中间运行的 gstack 安装检查不再升级其下的 gstack，并且升级路径现在无需 flock 二进制文件 #4095 即可工作。
  • /plan-ceo-review 门不再在 Claude Code 写完其成绩单之前判断会话，因此完成的审核不再被错误地持有 #4102。
  • 在完成所需步骤之前保留技能会话的检查现在也会等待 Claude Code 完成写入脚本，因此完成的运行不再被错误阻止 #4104。
  • gstack 等待拉取请求现在最多每分钟检查一次 GitHub 并等待速率限制，因此它们停止使用共享的 GitHub API 配额 #4109。
  • /ship 现在将 .ts 或 .js 文件中以 Lit 或 htm 模板编写的 UI 视为前端，因此这些更改会得到设计检查，而不是默默地跳过它 #4112。
  • /autoplan 现在可以识别相同的 Lit 和 htm 模板 UI 以及行、选择器和菜单等单词，因此这些计划会进入设计阶段，并且快速运行不再显示它合并了它跳过的设计阶段 #4121。
  • /make-pdf 仅从文档自己的文件夹中读取本地图像，并且仅读取真实图像文件；其他任何内容都会呈现为可见的“图像被阻止”占位符 #4113。
  • 通过 /pair-agent 隧道，远程代理现在只能打开网页：它无法读取本地文件、选择磁盘上的路径或让浏览器在那里保存屏幕截图 #4116。
  • 设计板和 iOS QA 后台服务现在仅回答直接向它们发出的本地请求，并且设计板链接现在在 URL #4117 中包含私人秘密。
  • /setup-gbrain 不再在其他本地用户可以看到的命令行上传递包含密码的 gbrain 数据库 URL，并且 gstack 的修订检查现在可以捕获更多类型的凭据 #4114。
  • Capy 安装程序在读取项目的 Bun 和 Node 版本时不再加载项目的 bunfig.toml 或 .env #4115。

维护者的变化

  • /ship 的审核记账得到了多项修复：后续审核和所有者授予的额外轮次现在可以正确计数，审核后的版本和文档编辑不再强制进行另一轮，被拒绝的审核记录现在会说明它来自哪个提交，以“Finding 1”开头的审核者发现保持其自己的严重性 #4089 #4093 #4096 #4099 #4101 #4106。
  • 交给新线程的 /ship 运行保留一个支出预算，并且远程检查清除的 CI 结果现在满足 /ship 针对该树的本地测试步骤 #4088 #4098。
  • 测试装置不再使 /ship 认为审阅者从网络获取，并且更新通道测试不再能够编写开发人员的真实 gstack 配置 #4105 #4094。
  • 代理线程拉取请求现在显示他们是否有计划步骤，并且存储库可以在合并之前要求它#4118。
  • 修复了三个 /ship 工具错误：第二个模型审查调度与审查计划相匹配，并且预合并检查结果在仅测试重新运行和移动的基础分支中仍然存在#4124。
