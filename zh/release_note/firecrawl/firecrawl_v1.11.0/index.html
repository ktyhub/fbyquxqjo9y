firecrawl v1.11.0

这个项目是干啥的：一个把整个网站爬下来并整理成 AI 可用数据的工具，支持搜索和并发抓取，给需要喂数据给大模型的开发者用。

变更架构图

亮点

  • Firecrawl Index — 新增的选择性启用索引目标是让抓取最多快 5 倍，现在还为搜索、提取和 map 操作提供数据，支持按域名切分、RPC 和扩展的 SDK 参数。索引/搜索用户值得升级；其他人可以把这个加速当作可选项，而非默认保证。
  • 爬取可观测性与控制 — GET /crawl/ongoing 提供了查询进行中爬取任务的 API，改进的活动日志则增加了 webhook 事件的可见性。Webhook 投递的日志也更清晰，让进行中的爬取和集成失败更容易监控。
  • 计费、任务元数据与变更跟踪 — credits_billed 现在贯穿整个流水线传播，任务携带新的 integration 字段，变更跟踪也支持标签。这对计费对账和多集成工作流很有用；解析这些记录的消费方可能需要适配新增字段。
  • 值得据此行动的 Bug 修复 — 移除查询参数清理逻辑，修复了上一版本中被破坏的 extract；爬取预完成逻辑也得到修正。移除 GCS 存在性检查还降低了任务查找开销。未列出明确的破坏性变更或必需的迁移步骤。
  • 升级建议 — 推荐 extract 用户、跑长时间爬取任务的团队，以及依赖新索引或活动遥测的团队升级。对 v1.10.0 满意的用户可以推迟升级；Java SDK、Fire Enrich 示例以及测试/文档改进都不会实质改变核心运行时。

Firecrawl v1.11.0 来了！

主要特点

  • 推出了 Firecrawl 指数
    • 如果选择加入，抓取速度可提高 5 倍
  • 改进的活动日志
    • 查看网络钩子事件
    • 主动抓取管理
  • Fire Enrich 示例（开源 Clay）
  • 社区 Java SDK
  • 还有更多

特点

  • 改进了 Playwright 测试和 webhook 测试覆盖率
  • 添加了 GET /crawl/ongoing 端点
  • 在变更跟踪中引入了标签支持
  • 将 integration 字段添加到作业中并通过队列工作器传播
  • runpod v2 和更新的 mu 的并行测试
  • 将 queryIndexAtSplitLevel 移植到 RPC
  • 增强了 SDK 的索引和缺失参数
  • 删除了冗余的 GCS 检查以提高性能
  • 添加了跨管道的 credits_billed 字段
  • 启用域级索引拆分以实现更好的地图查询
  • 在搜索和提取操作中使用索引
  • 删除了未使用的索引列

修复和改进

  • 修复了抓取预完成逻辑
  • 重构了 callWebhook 并添加了日志记录
  • 改进的索引测试（FIR-2214）
  • 修复了 JS SDK 测试
  • 澄清了自述文件中的抓取选项用法
  • 修复了环境示例中缺失的 PLAYWRIGHT_MICROSERVICE_URL
  • 改进并发限制通知电子邮件
  • 删除了破坏提取的查询参数清理
