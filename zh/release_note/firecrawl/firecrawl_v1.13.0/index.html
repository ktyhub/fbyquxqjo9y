firecrawl v1.13.0

这个项目是干啥的：一个把整个网站爬下来并整理成 AI 可用数据的工具，支持搜索和并发抓取，给需要喂数据给大模型的开发者用。

变更架构图

亮点

  • 新的抓取能力 — 新增 Google Slides 抓取、通过新的 PDF action 生成当前页面 PDF，以及通过 quality 参数生成更高分辨率的截图。parsePDF 和 PDF action 现在在 Python 和 JS SDK 中都可用，因此如果你需要这些输出格式就升级；否则它们不影响现有工作流。
  • 更广的爬取与区域支持 — allowSubdomains 现已接入爬虫的 filterURL 并在 SDK 中开放，让子域名爬取真正可用，而不只是声明了参数。Stealth Mode 还新增了 AU、FR 和 DE 地区。这对区域性或多子域名爬取是有用的升级，但需要你主动启用——不要以为之前的爬取覆盖面会自动扩大。
  • 值得检查的可靠性与 Bug 修复 — Worker 存活检查不再向濒死的 worker 排队任务，任务数查询和无 Redis 的爬取状态处理得到改进，TLS/DNS 错误也更清晰。修复还涉及 pdf、credits 的作用域，以及 ignoreInvalidURLs/maxConcurrency 的行为。命中这些具体故障场景的用户应升级；其他人可以把它当作增量加固。
  • 部署变更，而非 API 断裂 — 旧的缓存机制（包括 Redis 缓存、PDF 缓存和爬取 map）已被移除（#1667），Storage 现在只实例化一次。自托管运维人员应检查自定义的 Redis/缓存依赖，并在升级前验证部署；本 changelog 未记录明确的 API 迁移步骤。
  • 小幅且针对性的改动 — 国际化 URL 校验，以及通过 safeFetch 在 scrapeURL 中支持 cookie，拓宽了可接受的输入；控制台新增了按周查看用量的视图。针对 Faire 的任务过期绕过属于内部/针对性改动，不构成大多数用户的升级理由。总体来看，为了新格式或已修复的爬取问题而升级；否则此版本可选。

特点

  • 通过 safeFetch 支持 scrapeURL 中的 cookie
  • 添加谷歌幻灯片 scraping
  • 将 PDF 操作添加到 API、Python 和 JS SDK
  • 截图质量配置
  • Python 和 JS SDK 中的 parsePDF 支持
  • 允许国际 URL
  • 在SDKs中启用子域爬行
  • 作业排队前检查工人的活跃度

改进和修复

  • 删除了旧的缓存系统（Redis、PDF缓存等）
  • 增强的错误消息（TLS、DNS）
  • 改进了作业计数查询和错误处理
  • 修复了 pdf、credits 范围、ignoreInvalidURLs 错误
  • 减少并发限制中的过度登录
  • 为 Faire 团队添加了特殊的工作到期绕过
  • JS SDK 中统一后备逻辑
