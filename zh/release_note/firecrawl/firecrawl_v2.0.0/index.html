firecrawl v2.0.0

变更流程图

亮点

  • 破坏性变更：全新客户端 + API 面 — 这是真正的主版本断裂，不是换标签。v1 客户端必须整体替换：JS 改为 new Firecrawl({ apiKey: 'fc-YOUR-API-KEY' })，Python 改为 Firecrawl(api_key='fc-YOUR-API-KEY')，REST 调用迁到 https://api.firecrawl.dev/v2/。几乎每个方法都改名了（scrapeUrl→scrape、crawlUrl→crawl/startCrawl、checkCrawlStatus→getCrawlStatus、batchScrapeUrls→batchScrape、checkBatchScrapeStatus→getBatchScrapeStatus、extract→startExtract），类型也改名（FirecrawlDocument→Document、ScrapeParams→ScrapeOptions、CrawlStatusResponse→CrawlJob、FirecrawlError→SdkError），而 generateLLMsText/checkGenerateLLMsTextStatus（Python 的 generate_llms_text）被彻底移除，v2 中没有对应物。请预留真正的迁移和测试时间——这里没有向后兼容垫片。
  • 破坏性变更：格式、爬取选项与默认值变化 — "extract" 格式改名为 "json"，且现在必须使用对象形式 { type: "json", prompt, schema }；截图同样改用 { type: "screenshot", fullPage, quality, viewport }，而非旧的 fullPage 字符串形式；parsePDF 变为 parsers: [{ "type": "pdf" } | "pdf"]；新增字符串格式 "summary"。爬取选项也有变化：allowBackwardCrawling 和 maxDepth 被移除（改用 crawlEntireDomain 和 maxDiscoveryDepth），ignoreSitemap（布尔值）变为 sitemap（"only"/"skip"/"include"）。行为上，请求现在会被缓存，maxAge 默认 2 天，且 blockAds、skipTlsVerification、removeBase64Images 默认开启——因此即使在代码仍能运行的地方，结果和下游处理也可能悄然不同。
  • 足以支撑升级的新能力 — 搜索新增 sources，除 Web 结果外还支持 "news" 和 "images"；爬取接受自然语言 prompt，自动推导路径/限制，并可通过新端点 https://api.firecrawl.dev/v2/crawl-params-preview 在提交任务前查看推导出的选项。SDK 也统一为显式异步模式：startCrawl + getCrawlStatus（或 crawl 等待器），以及对应的 startBatchScrape/getBatchScrapeStatus 和 startExtract/getExtractStatus 组合——这让长时间运行的任务更可预测。
  • 可靠性与安全加固 — 这里落地了大量 infra 工作：sitemap XML 解析从 JavaScript 重写为 Rust（PR #1840），恢复 Rust 链接过滤逻辑（#1822），修复多处 robots.txt 解析器问题，清理停滞任务以避免爬取挂起（#1838、#1839、#1859），修复 ignoreQueryParameters 的 URL 去重、isSubdomain 和 maxConcurrency（#1871），外加一批依赖漏洞升级（form-data 4.0.0→4.0.4、axios 1.6.8→1.11.0、esbuild/tsx、koffi），以及可在任意 UID 下运行的 Docker 镜像（#1819）。从运维角度看，这意味着卡死的爬取更少、依赖攻击面更小。
  • 谁该升级 / 谁可跳过 — 新接入者，以及想要 summary、新 json/截图格式、sources 搜索、prompt 驱动爬取或安全补丁的人，应直接上 v2。现有 v1 用户应把它当作计划性迁移（客户端、方法、类型、格式和爬取选项全变了），而不是直接替换式升级；如果你不需要新功能且 v1 用得稳定，可以推迟到能腾出迁移时间再动。这绝不是一个空操作或纯元数据发布——破坏面很广，因此在切换前请用”Quick migration checklist”和 crawl-params-preview 端点做验证。

介绍 v2.0.0

关键改进

  • 默认情况下更快：请求缓存，maxAge 默认为 2 天，并且启用 blockAds、skipTlsVerification 和 removeBase64Images 等合理的默认值。

  • 新摘要格式：您现在可以指定 "summary" 作为直接接收页面内容的简洁摘要的格式。

  • 更新了 JSON 提取：JSON 提取和更改跟踪现在使用对象格式：{ type: "json", prompt, schema }。旧的 "extract" 格式已重命名为 "json"。

  • 增强的屏幕截图选项：使用对象形式：{ type: "screenshot", fullPage, quality, viewport }。

  • 新搜索源：通过设置 sources 参数，除了 Web 结果之外，还可以在 "news" 和 "images" 中进行搜索。

  • 带提示的智能爬行：传递自然语言prompt进行爬行，系统自动导出路径/限制。使用新的crawl-params-preview端点在开始作业之前检查派生选项。

快速迁移清单

  • 将 v1 client 用法替换为 v2 clients：
    • JS：const firecrawl = new Firecrawl({ apiKey: 'fc-YOUR-API-KEY' })
    • Python: firecrawl = Firecrawl(api_key='fc-YOUR-API-KEY')
    • API：使用新的 https://api.firecrawl.dev/v2/ 端点。
  • 更新格式：
    • 需要时使用 "summary"
    • JSON模式：使用{ type: "json", prompt, schema }进行JSON提取
    • Screenshot 和 Screenshot@fullPage: 指定选项时使用屏幕截图对象格式
  • 在 SDK 中采用标准化异步流程： *爬行：startCrawl + getCrawlStatus（或crawl服务员）
    • 批次：startBatchScrape + getBatchScrapeStatus（或batchScrape服务员） *摘录：startExtract + getExtractStatus（或extract服务员）
  • 抓取选项映射（见下文）
  • 检查爬行 prompt 与 crawl-params-preview

格式和抓取选项

  • 使用字符串格式作为基础知识："markdown"、"html"、"rawHtml"、"links"、"summary"。
  • 使用 parsers: [ { "type": "pdf" } | "pdf" ] 代替 parsePDF。
  • 使用 JSON 的对象格式、更改跟踪和屏幕截图：

JSON 格式

 curl -X POST https://api.firecrawl.dev/v2/scrape \
     -H 'Content-Type: application/json' \
     -H 'Authorization: Bearer YOUR_API_KEY' \
     -d '{
       "url": "https://docs.firecrawl.dev/",
       "formats": [{
         "type": "json",
         "prompt": "Extract the company mission from the page."
       }]
     }'

  curl -X POST https://api.firecrawl.dev/v2/scrape \
