firecrawl v1.10.0

firecrawl v1.10.0

变更流程图

亮点

  • 新 Search API（头号特性） — 新端点把 Web 搜索与抓取合为一次调用：返回结果全文、可选输出格式（markdown、HTML、links、screenshots）、语言/国家/时间范围/结果数参数，并提供 Python + Node.js SDK 的一等支持。还附带 ignoreBlockedURLs（#1580）、搜索可忽略并发限制（#1617）以及搜索预览不计费（#1622）。如果你此前把搜索服务串接到 Firecrawl，这是实打实的升级理由；纯抓取用户从中得不到好处。
  • 计费与积分核算——升级前请核对 — PDF 抓取现在按每页 n 积分计费（#1553），/scrape 调用新增 credits_billed 列，改为 worker 侧计费并更严格地执行超时（#1607）；搜索预览明确不计费（#1622）。这是本版本中最接近迁移关注点的内容——如果你的负载包含 PDF 或高并发 /scrape，请重新核对成本预期。
  • 代理与 worker/队列可靠性 — 自动模式代理同时落地到 scrapeURL（#1551）和 JS SDK（#1602）。一批修复针对僵尸 worker 清理（#1575）、extract 状态在 TTL 过期后仍可保留（#1599）、并发队列插入逻辑和 rateLimiterMode 覆盖 bug（#1595、#1593），以及更有选择性的 robustFetch 日志（#1588）。这些是运维可用性改进——在大规模场景下意义明显，对轻度用户影响很小。
  • 自托管 — 新增可部署的 Playwright 镜像（#1625）、使用独立的不淘汰 Redis 的支持（#1600）、记录 MAX_RAM/MAX_CPU 环境变量（#1581），并修复了 LLM’s.txt 子域缓存及绕过选项（#1557）、查询参数中特殊字符的 URL 校验（#1547）。自托管用户应升级，若采用不淘汰 Redis 实例，请检查自己的 Redis 配置。
  • 较小的 API/元数据改动——无破坏性变更 — 新增 /cclog 并发日志端点（#1589）、v1 extract 的 ignoreInvalidURLs（#1585）、用于 URL 匹配开发体验的 unnormalizedSourceURL（#1601）、元数据提取中的 itemprop 属性（#1624），以及 Rust SDK 中爬取的 webhook 参数（#1609）。未声明明确的破坏性变更、弃用或迁移步骤，因此正常升级即可；只有当这些都与你的工作流无关时才跳过。

我们很高兴地宣布推出新的 Search API 端点，它将网络搜索与 Firecrawl 强大的 scraping 功能相结合。

搜索功能：

  • 搜索网络并通过一次 API 呼叫从结果中获取完整内容
  • 选择特定的输出格式（markdown、HTML、链接、屏幕截图）
  • 自定义搜索参数（语言、国家、时间范围、结果数量）
  • 完全支持 Python 和 Node.js

更多功能

  • scraping（scrapeURL、js-sdk）的自动模式代理#1551、#1602
  • scrapeURL/pdf 的超时处理和内容类型改进 #1570、#1604、#1592
  • Redis 改进：单独的非驱逐 Redis 支持 #1600
  • 搜索改进：ignoreBlockedURLs，忽略并发限制 #1580、#1617
  • 用于并发日志记录的新 /cclog 端点 #1589
  • 元数据提取现在包括 itemprop 属性 #1624
  • 自托管：可部署的 Playwright 图像 #1625

修复和改进

  • 更好地处理 LLMs.txt + 绕过选项 #1557
  • 改进了 URL 验证和特殊字符处理 #1547
  • 僵尸工作者清理 + 提取状态的 TTL 处理 #1575、#1599
  • 修复并发队列逻辑和速率限制器覆盖 #1595、#1593
  • 更好地记录搜索分页和强大的获取 #1572、#1588
  • 小修复：og:locale:alternate、adblock 切换、剧作家专用逻辑、格式错误的元数据数组 #1597、#1616、#1574

测试和文档

  • 添加 MAX_RAM 和 MAX_CPU 环境变量文档 #1581
  • 测试基础设施改进 #1623
