firecrawl v2.5.0

变更流程图

亮点

  • 爬取引擎与并发（重头戏） — 这实质上是一次核心重写：新的语义索引 + 自研浏览器栈（发布说明中宣称”最高质量的 Web 数据 API”）、新的爬取架构（#2320），以及 NUQ 并发跟踪系统，支持按所有者/按组限流、动态并发计算、group_id + 任务积压/加组操作（#2302、#2305、#2309），并始终填充 NUQ 指标以便观测。如果你跑高并发或租户场景的爬取，为了控制力和可见性应该升级——但请把它当作会改变行为的内部大改造，而不是常规补丁。
  • 新的数据面支持 — 现在可以抓取 .xlsx（Excel）文件（#2284），并从文档的 <head> 提取元数据以丰富输出（#2342）。另需注意：启用 allowSubdomains 时，includePaths 现在会正确作用于子域名（#2278）。流水线依赖电子表格或元数据提取的团队，应专门为这些改动升级。
  • 自托管大幅简化 — JS SDK（#2237）和 Python SDK（#2290）在自托管部署时都不再要求 API key，自托管搜索从 Google 切换到 DuckDuckGo（#2225），并修复了 Python SDK 跨 API 调用的超时处理（#2288）。自托管用户应升级以摆脱 API key 的麻烦；注意换成 DDG 可能改变搜索结果的质量/格式，因此要验证依赖搜索的工作流。
  • 计费变化——/search 更贵了 — /search 的定价更新为每 10 条搜索结果 2 积分（#2299），同时修复了一处计费 bug（#2301），并修复了设置 location 时 country 参数默认变为 undefined 的问题（#2283）。这对 API 消费者是直接的成本/行为变化：大量使用 /search 的人应在升级前测算新的积分消耗；轻度用户可以忽略。
  • 可靠性修复与一处明确提醒 — 并发队列中的死锁和重复任务处理（#2295、#2343）、robots.txt 警告的可靠呈现（#2287）、递归 schema 中的循环引用（#2298），以及 Rust 客户端从 print 迁移到 tracing（#2324），都是扎实的稳定性改进。注意：Playwright 视口/截图尺寸的修复（#2329）已在 #2332 中回滚，因此截图/视口问题可能仍然存在。changelog 未声明破坏性变更或迁移步骤；如果你依赖截图，请在正式采用前测试该路径。

v2.5.0 - 世界上最好的网络数据 API

我们现在拥有最高质量和最全面的网络数据 API，由我们的新语义索引和自定义浏览器堆栈提供支持。

请参阅下面的基准：

新功能

  • 为 .xlsx (Excel) 文件实现了 scraping。
  • 引入了新的爬行架构和NUQ并发跟踪系统。
  • 每个所有者/组的并发限制+动态并发计算。
  • 添加了小组积压处理并改进了小组操作。
  • 添加了 /search 定价更新
  • 添加了团队旗帜以跳过国家/地区检查。
  • 始终填充 NUQ 指标以提高可观察性。
  • 用于改进 CI 测试的新测试站点应用程序。
  • 从文档头提取元数据以获得更丰富的输出。

增强和改进

  • 改进了阻止列表加载和不受支持的站点错误消息。
  • 更新了 x402-express 版本。
  • 改进了子域的 includePaths 处理。
  • 更新了自托管搜索以使用 DuckDuckGo。
  • JS 和 Python SDK 不再需要 API 密钥进行自托管部署。
  • Python SDK 超时处理改进。
  • Rust client 现在使用 tracing 而不是 print。
  • 减少自动充电 Slack 通知中的噪音。

修复

  • 确保抓取 robots.txt 警告可靠地出现。
  • 解决了并发死锁和重复作业处理。
  • 修复了搜索国家默认值和定价逻辑错误。
  • 修复了线束环境中的端口冲突。
  • 修复了 Playwright 中的视口尺寸支持和屏幕截图行为。
  • 解决了 CI 测试不稳定问题（剧作家缓存、产品测试）。
