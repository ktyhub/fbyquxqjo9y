ChuanhuChatGPT 20250815

变更流程图

亮点

  • 支持 GPT-5 模型 — 头条能力：现在可以从模型列表中选择 OpenAI 的 GPT-5。采用者应把它当作不止是下拉菜单新增一项——GPT-5 是推理模型，你的集成可能传入的参数（如 temperature、top_p、固定 token 预算）会被忽略或表现不同，响应结构/消息角色也可能包含旧提示模板不预期的推理内容。上线前请确认所用 API key 具备 GPT-5 访问权限，并复查任何假定 GPT-4 时代语义的代码。
  • DeepSeek 模型 — 本版本引入第二个新供应商，把模型选择扩展到 OpenAI/Google 之外，通常提供成本低得多的推理选项。预计要配置一个新的供应商条目（base URL/API key），并在 UI 或下游解析器中处理 DeepSeek 独立的推理字段——只渲染最终答案的原始响应会悄悄丢掉思维链。值得作为预算替代方案评估，但请先用你自己的提示验证输出格式。
  • Gemini 自定义 API 主机 — 对重视基础设施的用户来说，这是运维意义最大的改动：Gemini 请求不再写死到 Google 默认端点，你可以让它走企业代理、反向代理或 AI 网关（例如用于出口管控、区域路由或日志）。现有配置不受影响；新主机字段只有确实需要代理时才有意义。若把它指向期望不同鉴权方式的 OpenAI 兼容网关，请留意主机/凭据不匹配。
  • 第三方 JS CDN 切换到 cdnjs — 一个安静但真实的行为变化：如果你运行在严格 CSP、防火墙白名单或气隙/离线环境，且此前把旧的 JS 主机加了白名单，这些脚本现在会被拦截，直到你更新 script-src/网络规则。陈旧的缓存 HTML 或 service-worker 资源可能仍引用旧 URL，升级后请强制刷新。另外，更新检查失败现在会给出更清晰的错误信息，有助于诊断受限网络中的连通性问题。
  • LaTeX 渲染禁用（已知问题） — 上游标记为一个由 Gradio bug 导致的已知回归，模型输出中的数学符号将不再在应用内渲染。若你的工作流涉及公式、科学或学术内容，这是最可能坑到你的改动：请在自己的管线中验证数学密集的响应，并规划下游渲染绕过方案，因为没有文档说明的应用内开关。解决取决于上游 Gradio 修复，而非 Chuanhu 侧补丁。
  • 破坏性变更 — 无：未引入 API、配置或迁移方面的破坏性变更；现有配置可延续，唯一值得注意的行为例外是 LaTeX 回归。
