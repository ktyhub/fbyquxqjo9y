变更流程图

亮点

  • 应用内新增更新提醒 — 新的更新检查功能让运行中的实例可以发现新版本，无需手动盯着仓库。注意这只是检测，不是自动升级：版本大致每周发布一次（本 tag 紧随 20230619），你仍需自行按 wiki 的手动更新步骤操作。
  • 引用改为聊天气泡呈现 — 引用的来源站点从行内文本/链接改为气泡式 UI。若你定制过前端 CSS 或抓取引用输出的 DOM，请预期视觉/标记会变化，并检查自定义主题是否正确设置了新气泡的样式。
  • 版本显示改为识别 tag — 从带 tag 的检出运行时，UI 现在显示 tag 名（如 20230628）而非原始 commit hash，便于支持和 bug 报告归类。留意无 tag 或浅克隆：没有 tag 时会静默回退到 commit hash，因此若依赖可读版本字符串，请拉取 tag。
  • 前端 JS 外置到 custom.js — Gradio 执行的 JavaScript 已重构为引用 custom.js 文件，而非内联脚本。这是迁移成本最高的一项：任何注入或打补丁到内联脚本的人都必须把改动搬进 custom.js，否则下次更新会被覆盖——不过迁移完成后，你就有了一个干净的单一覆盖点。
  • 本地化与链接渲染修复 — 删除对话的确认现在已本地化（对非英文部署有用），并修复 URL 相邻字符被转义、导致链接显示损坏的 bug。低风险维护，但请移除你为畸形链接加过的本地绕过。
  • 本次版本无破坏性变更。
