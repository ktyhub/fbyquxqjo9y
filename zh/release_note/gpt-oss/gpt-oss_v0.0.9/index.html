gpt-oss v0.0.9

修订 发布时间2026年1月13日 来源openai/gpt-oss 英文原文

gpt-oss v0.0.9

这个项目是干啥的：OpenAI 开源的权重模型仓库，可在本地跑大模型并针对苹果芯片做了优化，给想在自己设备上部署模型的开发者用。

变更架构图

亮点

  • Metal API 迁移（破坏性） — max_batch_tokens 从 Model 挪到了 Context。在 Model 上配置它的 Python 包装代码必须更新；Metal 用户升级前应检查这些调用。
  • Prefill 性能 — 去掉 MoE MLP prefill 期间的 GPU-CPU 同步，并避免 RoPE 后把 KV 值复制进 KV cache。这减少了停顿和内存流量，可能改善服务延迟和吞吐；changelog 没有给出基准数据。
  • Metal 构建可靠性 — 移除一个导致 Metal 构建失败的重复变量，并简化 Python 包装里的 Model 类型检查。遇到那个构建错误就升级；否则主要算维护更新。
  • 微调与 notebook 工作流 — 新增 GPT-OSS Reinforcement Finetuning Example、有状态的 Jupyter notebook 选项，以及浏览器可靠性修复。对微调和交互式实验最有用；纯推理用户可以跳过这些新增内容。
  • 文档与追踪 — 新增 AWS 官方上线博客文章、重组 AWS 文档，并加上用于追踪的 User-Agent 头。AWS 用户从文档受益；其他人要注意这个遥测相关的 header 变化，但除此之外不需要这个版本。

发生了什么变化

  • 添加官方 AWS 发布博客文章，并将 AWS 部分重新格式化为 @neoremind 在 https://github.com/openai/gpt-oss/pull/197 中的 Awesome-gpt-oss.md
  • 金属：简化 Python 包装器中 @Maratyszcza 在 https://github.com/openai/gpt-oss/pull/202 中的模型类型检查
  • 金属：通过 https://github.com/openai/gpt-oss/pull/201 中的 @Maratyszcza 将 max_batch_tokens 从模型移至上下文
  • @danielhanchen 在 https://github.com/openai/gpt-oss/pull/208 中的 GPT-OSS 强化微调示例
  • 通过https://github.com/openai/gpt-oss/pull/199中的@dkundel-openai添加有状态的jupyter笔记本选项并使浏览器更加可靠
  • 在 https://github.com/openai/gpt-oss/pull/218 中 @ibahmed-oai 的 Prefill 中的 MoE MLP 期间删除 GPU-CPU 同步
  • 在 https://github.com/openai/gpt-oss/pull/221 中 @ibahmed-oai 的预填充过程中，无需将 RoPE 之后的 KV 复制到 KV 缓存 *修复：删除https://github.com/openai/gpt-oss/pull/220中@hukurou0导致Metal构建失败的重复变量
  • 将用户代理添加到标头中，以便 https://github.com/openai/gpt-oss/pull/235 中的 @smboy 进行跟踪
