parlant v4.0.6

[4.0.6] - 2026-11-16

添加

  • parlant lint 通过您的编码代理来检查 Parlant 代理项目。它 打印编码代理的指令：要运行哪些 lint 章节，每个章节都在 它自己的子代理（parlant lint --section SECTION --chapter CHAPTER 打印 章节的规则），以及如何按严重程度处理发现的问题。高发现是 立即修复，每轮最多提出 3 个中等问题类型，并且 低的只有你同意。第一部分是行为（观察 结合了多种情况，无论是替代方案还是必须全部 保持）以及措辞和语气（罐装 回应而不是政策或指示中的措辞）。每条规则都有一个 ID，例如 BHV001，在各个版本中保持不变。
  • parlant init 现在安装了 git 预推送钩子（.githooks/pre-push，设置 通过 core.hooksPath）停止推送直到提交被检查， 脚手架 AGENTS.md 告诉编码代理运行 parlant lint 每次推动之前。进行 linting 并提交修复后，parlant lint --done records the commit so the push goes through; git 推送 --no-verify 跳过钩子。该项目的克隆打开了钩子 git config core.hooksPath .githooks。 --no-git不安装挂钩。
  • parlant dashboard agent cards AGENT_ID DESTINATION 写入您的每个文件 网站提供服务，以便个人人工智能代理找到您的代理，进入 DESTINATION/.well-known： A2A 为 agent-card.json，Poppy 为 poppy.json 和 poppy-0.4.json， Meta Muse 和 Shopify 使用的个人代理协议。 --no-a2a 和 --no-poppy 遗漏了一个家庭。 Poppy 文档需要代理的站点集 在仪表板中，因为 Poppy 通过其域来识别企业；没有它 命令写入卡并如此说。 parlant dashboard agent view 显示 代理的 POPPY ADDRESS，parlant widget init 指向新命令。 parlant dashboard agent card老款仍单独打印A2A卡 说明。
  • 聊天小部件的 onPathChanged(path, notifyAgent) 告诉客服人员哪个页面 访客已开启。当小部件加载和路径更改时调用它 无需重新加载； notifyAgent(path, data?)添加自定义事件 （{ type: "page_view", page: path, ...data }，来源 customer_ui）无法启动 一个答复。新的对话先于其他任何事情获取它，以便代理可以知道 您的定价页面上提出的问题来自您主页上提出的问题。

已更改

  • 在高代理努力下，修剪以前发现的规则现在默认为 低模型推理，匹配规则排序。显式模型路径推理 设置仍然优先。
  • 当一项政策涉及另一项政策时，现在用以下标准来判断所涉及的政策： 考虑到这一点的政策。当其措辞依赖于 他们的，例如另一个策略定义的“附加组件”。它仍然匹配 它本身的优点，并且蕴涵像以前一样起作用：当一项蕴涵政策 匹配，相应的也被激活。
  • 来宾和登录客户可以将自定义事件添加到自己的会话中， 使用源 customer_ui，最多 4 KB 数据，每分钟 30 个。到目前为止仅 后端可以，因此站点必须通过自己的服务器中继页面视图 使用管理密钥。其他来源仍然需要管理密钥；自定义权限 不授予 CREATE_CUSTOM_EVENT 的门一直拒绝它们。 PARLANT_CUSTOMER_UI_EVENT_MAX_BYTES 更改大小限制（默认为 4096）。
  • 带有视频头像的聊天小部件现在将视频移动到旁边的圆圈中 对话滚动后代理的姓名及其留下的空间 关闭。向上滚动超过顶部会将其返回。标头保留其 高度并在圆圈下方的消息上淡出。名字和 字幕在视频移动时淡出，然后回到圆圈旁边， 名字下的副标题。照片头像现在与停靠的头像大小相同 圆圈，其标题也会在其下方的消息上方淡出。向上滚动 小部件中的内容不再在简短的对话中被拉回，并且 发送消息会带来视图。 在手机上，小部件仅显示圆圈，该圆圈被裁剪到脸上 通过头像的 launcher 设置。您的项目保留副本 parlant widget init制造。要选择这个，请运行 parlant widget init --force，它将替换该副本以及您所做的任何更改 做到了。
  • 以 Gemini 作为您的提供者，以中等、高度和最大努力程度进行回复 审查检查现在在 Gemini 4 Hydrogen 上运行，而不是在 Gemini 3.8 Flash 上运行。中等 努力保持低推理。在网站代理上，这将回复数量从 15 减少到 30 秒到 6-8，并且 Hydrogen 在 3.8 Flash 的回复中保留了其推理 出于低级推理，把它写成了一篇。只需最少的努力即可坚持下去 闪存精简版。您自行设置的react或review.*路线不变。至 保留旧模型，明确路由，例如 "react": p.ModelConfig("gemini:gemini-3.8-flash", reasoning="low")。
  • LiteLLM 对于两项审核检查的默认值现在是 gemini/gemini-4-hydrogen 而不是 gemini/gemini-3.8-flash。

已修复

  • 带有标题但没有注释的观察结果不再出现在特工的观察结果中 说明作为空条目（其标题后跟“详细信息：[无]”， 没有它的条件）。现在，仅当规则达到代理的提示时 说了些什么：它的内容（观察笔记、政策行动），或者 它相关的工具，在这种情况下，即使在 它有一个标题。没有内容的规则也被排除在注释之外 告诉代理哪些指令本轮失去了优先级。观察结果 没有注释，继续努力建立关系、预设响应范围和 匹配；它们根本不需要任何提示代币。
  • 日志记录范围现在在异常和取消后展开，因此稍后记录 在同一任务中不要保留过时的组件标签。
  • 聊天小部件将其免责声明和“由 Parlant 提供支持”置于手机输入下方。
  • 聊天小部件不再在空聊天或简短聊天中显示“↓ 新消息” 访客向上滚动。现在，只有当下面有东西可以跳到时，药丸才会出现。
  • 聊天小部件不再以杂散的 * 结束已完成的回复。回复与 奇数个 * 子弹用于在最后一个单词后得到一个。半型 当回复流淌时，粗体和斜体仍然关闭。拿起这个和 其他小部件修复，运行 parlant widget init --force，它将替换您的 项目的小部件副本以及您对其所做的任何更改。
  • 在 Gemini 4 模型上设置的推理级别，如示意性路线 "review.*": p.ModelConfig("gemini:gemini-4-hydrogen", reasoning="high")，现在 发送给双子座。它曾经被丢弃，所以模型认为是它自己的默认值。
  • 预设响应相关性现在考虑之前每个查询块的匹配 选择最接近的响应，保留每个响应的最佳匹配分数。
