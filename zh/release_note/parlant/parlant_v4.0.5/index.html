parlant v4.0.5

[4.0.5] - 2026-11-12

添加

  • Gemini 4 Hydrogen 通过 Gemini 提供商工作，包括流式回复、 工具调用、保存的对话重播和令牌记账。选择它作为 gemini:gemini-4-hydrogen;现有默认模型不变。
  • 聊天小部件将客服回复中的 Markdown 表格显示为表格。他们 用于显示为管道线。列对齐、单元格内嵌 Markdown 并逃脱了管道工作。一旦出现标题和分隔符，就会出现流式表格 行到达并逐个单元格填充。一张宽桌子在里面横向滚动 该消息和您网站自己的表格样式不会改变它。你的项目 保留制作的副本 parlant widget init。要选择这个，请运行 parlant widget init --force，它将替换该副本以及您所做的任何更改 做到了。
  • 事件流 (sse=true) 现在在每一帧上携带 id 并从 它。与 Last-Event-ID 重新连接的 client 在帧后拾取 上次看到的内容，而不是从头开始重播会话。流询问 重新连接浏览器等待三秒（retry: 3000），并且空闲 流每 15 秒发送一条保持活动注释，因此代理不再 在 wait_for_data 过期之前关闭安静连接。当一个请求 同时携带 min_offset 和 Last-Event-ID，两者中较晚者获胜：a 重新连接 client 通常在其 URL 中仍包含原始 min_offset， 并尊重它将重播会议。延迟和保活 间隔可以用 PARLANT_SSE_RETRY_MS 和 PARLANT_SSE_HEARTBEAT_SECONDS； 0 禁用保持活动，0 禁用保持活动 延迟省略了 retry: 线。
  • Gemini 服务于 Google 的 Gemini Decision 1 (gemini-decision-1)，该决策给出了答案 关于一次对话的许多是/否、选择和量表问题 请求。 {"*": "gemini"} 路线现在使用它进行规则排名 在一批中对规则进行排名的努力，因为 OpenAI 和 OpenRouter 路线已经 与他们的决策模型有关。在路线上将其命名为 "matching.rank[capability=decision]": "gemini:gemini-decision-1"。它使用 您现有的 GEMINI_API_KEY。 Gemini 报告没有任何费用，因此添加一个 gemini-decision-1 进入 server.set_pricing(...)（Google 列出每人 $0.10 百万个输入代币，没有任何输出）来定价。

已更改

  • Gemini 模型在您的服务器上计算令牌，而不是询问 Gemini API， 每次计数大约需要 300 毫秒。工具调用后的一步做了两个这样的 在选择预设响应时连续调用，因此在工具调用后进行回复 现在提前大约 0.4–0.6 秒开始。计数使用开放的 Gemma 3 tokenizer 和 都在 Google 的一两个令牌之内。 gemini 额外现已安装 sentencepiece。分词器从 raw.githubusercontent.com 下载一次， 在后台，在第一个计数上。直到它准备好，或者如果你的服务器 无法到达 GitHub，Parlant 像以前一样使用 API 进行计数并记录一个警告 这么说。
  • 客服人员不再重复客户之前对他们说过的话 回复（“物流初创公司的潜在客户开发，所以……”）。现在有反应 回应消息的含义，以及当客户回答时 代理自己的问题，代理直接进入下一步。提示没有 更长的时间禁止股票致谢，例如通过名字“有意义”。
  • parlant init 创建的代理不再学习重复访客的话 回来。热情的主人和乐观的人物现在对这条信息做出了反应 意思是，当访客来访时，热情的主人会直接进行下一步 回答它的问题。现有项目保留自己的文本；复制新的 如果您的代理人也同意的话，请使用新的 parlant init 的措辞。

已修复

  • 在托管（仪表板托管）服务器上，session.metadata.get()、.set() .delete()、session.update() 和 server.get_session() 失败 实时对话“找不到会话”，因为他们在商店中查找 保存启动声明而不是保存会话的声明。他们 现在使用与引擎和 API 相同的会话存储，如 session.labels 已经这样做了，因此读取或写入的检索器或工具 会话元数据的工作原理与本地托管的相同。
  • 定价检查不再警告未使用的提供商默认模型 更具体的模型路线会覆盖它们，例如 Gemini 嵌入 人为服务器。仍然可以通过其他路线到达的模型以及模型 实际观察到的使用情况，仍包含在定价范围内。
  • 返回结构化结果的 MCP 工具（例如 pydantic 模型）现在给出 代理结果为普通 JSON。之前，电话已接通，但客服人员仍在 告诉“工具调用错误”，因此它可以重试已经进行的调用 效果或告诉客户失败了。
  • 并发负载下的 Gemini 代理不再在彼此后面排队 正在创建提示缓存。对其他缓存的请求，以及其请求 缓存已存在，立即继续；仍然请求相同的缓存 共享一个创作，因此它被创建一次并且其存储费用被收取一次。
  • 随着会话和事件历史记录的增长，具有 MongoDB 存储的服务器启动速度更快。 当商店的录制版本已经与正在运行的版本匹配时，启动否 不再通过其加载器读回每个文档。当迁移是 需要时，文档会像以前一样加载和迁移。
