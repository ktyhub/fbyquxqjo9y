parlant v4.0.2

[4.0.2] - 2026-11-05

添加

  • 聊天小部件可让访客浏览器中的 AI 代理与您的代理对话 通过 WebMCP（document.modelContext；今天在 Chrome 中的一个标志后面）。开 在它所在的每个页面上，小部件都会注册一个 ask_agent 工具，描述为 代理人的姓名。如果没有对话，则调用将启动小部件的对话 然而，正如代理人为客户持有的那样（customer_represented_by_an_agent）， 通过聊天发送问题，因此它会显示回复，打开 聊天，并在回合结束后回答浏览器代理。跟进 呼叫继续相同的对话。消息中携带 metadata.parlant_widget.asked_by = "customer_agent"，所以聊天和你的 工具可以区分访问者的代理和访问者。在 a 中什么也没有发生 没有 WebMCP 的浏览器； webmcp={false} 将其关闭。 ParlantTransport 的 sendMessage 采用可选的元数据参数，而 ensureSession 采用 标志的选项。
  • Server(session_store=..., customer_store=...) 接受 s3://bucket 用于在 Amazon S3 中保留会话和客户的 URL。给帕兰特一桶 它自己的。凭证来自AWS凭证链；添加 ?region= 或， 对于 S3 兼容存储，?endpoint=。存储必须支持 条件写入，防止并发服务器覆盖每个 别人的更新。空集合在重新启动和失败的迁移中仍然存在 write 将原始数据保留在原处。除了按 ID 查找之外的任何查询， 例如列出会话，读取集合中的每个对象，因此使用 MongoDB 如果您需要大规模索引查询。
  • 聊天小部件 (parlant widget init) 将代理的照片合二为一 avatar 支柱：{ type: "logo", src }、{ type: "photo", src, live? } 或 { type: "video", src?, poster?, live?, launcher? }。视频头像播放 标题下的短静音循环，滚动一次对话 它启动，并在聊天展开时保持其打开的大小。关于封闭的 发射器，launcher 将其裁剪到脸上。省略 src 以使用 小部件自己的代理视频。 live 在视频的 角落也是红色的，而无法访问服务器。使用保存的 H.264 MP4 与-movflags +faststart； iPhone Safari 在 WebM 上停滞。

已更改

  • 聊天小部件的持续建议从其打开的建议中脱颖而出： 在聊天背景上以主题的主色勾勒出轮廓和字母， 而不是灰色填充。
  • 在手机和平板电脑上，聊天小部件会关闭屏幕键盘一次 消息已发送，无论是键入还是从建议中选择，因此回复 并没有隐藏在它的背后。
  • 通过 LiteLLM 提供商，审核路线现在默认为 gemini/gemini-3.8-flash代替gemini/gemini-3.6-flash，一样 Gemini 提供商已经为他们使用的模型。
  • 当访客询问时，lead-gen 脚手架的代理不再猜测 该企业、其产品或项目及其产品知识没有 回答。它说这是一个很好的问题，但很难正确回答 聊天，主动提出让他们与团队联系，要求提供电子邮件或电话 号，并通过 request_team_follow_up 传递问题。无关的 问题、现有客户的订单问题和价格按如下方式处理 之前。为了实现这一点，record_lead 现在只需一个 目标和联系人：buying_for 和 role 是可选的，未知的 没有得分。
  • parlant dashboard project confirm 完成本地或自托管项目 即使其服务器已经持有会话，例如尝试代理。 它首先将它们导入仪表板，就像仪表板的同步一样，并且 然后完成设置，因此项目不再停留在“完成设置”。 耗时超过 90 秒的导入会停止 SYNC_IN_PROGRESS；再次运行 confirm 以继续等待相同的导入。 失败的导入以 SYNC_FAILED 及其原因停止。
  • parlant init --dashboard --json 和 parlant dashboard project create --json 对于本地或自托管项目，现在列出 nextSteps，以结尾 project confirm。搭建的 AGENTS.md 告诉编码代理确认 连接服务器后即可启动该项目。
  • 创建一个托管项目后，其设置检查发现如何运行它， parlant dashboard project create 现在指向 parlant dashboard --project ID deploy：首次现场部署完成 设置。仪表板的设置页面是可选的，用于查看设置。

已弃用

  • 聊天小部件的 avatarUrl、avatarStyle 和 liveIndicator 道具，位于 avatar的青睐。当 avatar 未设置时它们仍然有效。

已修复

  • Gemini Argon 可以使用其原始签名思想重放已保存的工具调用 阻止而不是不必要地退回到仅结果的历史。
  • 按标签过滤会话现在返回完整的页面和工作 连续游标，在任一排序顺序中具有一致的总计数。
  • MongoDB 游标分页现在在后面的页面上保留 $or 过滤器，因此 过滤列表不再包含请求集之外的记录。
  • 预设回复现在为其文本和内容保留单独的搜索向量 每个信号，因此信号不再在相关性索引中发生冲突。 在创建或更新回复时适用；现有索引不是 自动重建。
  • 在 iPhone 上，聚焦聊天小部件的消息框不再缩放页面 ，这将打开的聊天推离了屏幕的右边缘。盒子 在触摸屏上使用 16px 字体，低于 iOS 缩放的尺寸。
  • 本地和 MCP 工具现在接受逗号分隔的列表参数，无需 括号，同时保留引号逗号和空列表。
  • 聊天小部件的最新消息不再出现在建议下方 当某些内容占用了转录本的空间时出现的消息框，例如 发送后立即出现“连接中断”横幅。成绩单 仅当消息增长时才固定在底部，而不是当其视图缩小时。
  • 无效的上下文变量新鲜度计划在保存之前被拒绝， 因此，计划更新失败会使变量的现有数据保持不变。
  • 当客服人员仍在处理问题时收到的客户消息 即使发动机处于工作状态，前一个转弯现在也按预期取代了该转弯 拒绝步骤的中间：被拒绝的工具调用或消息 审阅钩子，由审阅者或通过审核。之前，拒绝重新开始 该步骤并删除了待处理的取消，因此客服人员完成了回复 回复第一条消息，然后单独回复第二条消息。 快速连续发送两条消息的客户现在会收到一条回复， 两者都考虑在内。

安全

  • 将 uv 的最低 python-multipart 版本提高到 0.0.30 和 pip 安装，防止安装受以下影响的版本 CVE-2026-53539。

[4.0.1] - 2026-11-02

已更改

  • parlant init --scaffold lead-gen 现在创建其代理 preamble_config=p.PreambleConfiguration.encourage()。在第一个工具出现之前 打电话给客服人员说一句简短的话，例如“让我检查一下”，所以 访客不会默默等待。没有它，序言就无法管理： 无论模型在工具调用之前编写什么，都会直接执行。
  • lead-gen 和 retail-store 脚手架中的每个工具现在都有一个 narration，例如“检查哪些天是空闲的”或“跟踪您的 发货”。聊天会在工具运行时显示它，而不是通用的 “运行工具”。

已修复

  • 使用 Anthropic 提供程序，Claude Opus 4.7 上的索引不再失败 更高版本或任何 Claude 5 模型，包括默认路由（Sonnet 5.5 和 俳句 5.5)。 Parlant 发送了 temperature，这些型号拒绝了 “此型号已弃用 temperature。”；现在它只发送一个到 Claude 3 型号和 Claude 4 型号直至 4.6，仍然接受它。
  • 克劳德寓言模型的推理工作现在改用适应性思维 一个有思想的预算，《寓言》拒绝了这一点。
  • Claude Opus 4.5 的推理工作不再失败。帕兰特发送了 它拒绝适应性思维（“适应性思维不受 这个模型”）；它现在有了一个思考预算，就像十四行诗和俳句 4.5 一样。
