anything-llm v1.16.1

修订 发布时间2026年8月27日 来源Mintplex-Labs/anything-llm 英文原文

变更架构图

亮点

  • 思维链汇总（Chain-of-thought rollup） — PR #6182 把多步代理思考与工具调用折叠成单一可折叠栏：收起时只占一行，展开后每个思考一步并带连线轨迹，流式输出时活动思考显示在标题栏。Assistant Panel 中也有同样的呈现，Beacon 现在把思考块作为可折叠 markdown 流式输出。对运行长周期代理的开发者来说，这为答案腾出了屏幕空间，同时不丢失调用栈；还有一处相关修复，防止模型永不闭合 think 标签时推理永久卡住。
  • 导航前会先警告再中止推理 — 值得注意的行为变化：此前”true”中止信号会在你离开聊天时静默终止生成以节省算力。本版本在丢弃响应前插入确认，#6190 还阻止推理进行中卸载模型。草稿现在也能在导航后保留（#6191）。注意流式过程中会弹出新的确认对话框；后台完成已列入路线图，将作为面向高并发配置的可配置选项。
  • Foundry Local 内嵌（桌面/Windows） — 原生 SDK 让该提供商自包含，无需单独安装 Foundry Local；支持 x64 和 ARM64，要求 Windows 11 24H2 build 26100+。WinML 面向 CPU/GPU/NPU，目录提供 GPU/NPU 优化变体，模型通过能力检测自动加载。实际注意点：微软推广期间模型可用性仍有限，且视觉模型不可用——可把它当作 AnythingLLM 未明确支持硬件配置时的后备方案。
  • GenieX 取代 Snapdragon NPU 引擎（破坏性） — 托管的”AnythingLLM GenieX”提供商面向 X/X2 Elite ARM64 设备，但旧引擎的模型会在更新时删除，必须重新下载。NPU 模型和常规 GGUF 预计会有显著提升；团队强烈建议只用 GGUF，因为高通纯 NPU 模型只有 4K 上下文窗口，会拉低代理质量。升级时请为重新下载预留预算，并重新评估模型选择。
  • Bedrock 与 LocalAI 提供商扩展 — AWS Bedrock 跨区域推理配置现在通过 bedrock-runtime 路由（#6181）：带地理前缀的 ID（us.、eu.、global.）会出现在下拉框中并被正确解析，GovCloud 及其他分区支持手动输入区域。LocalAI 新增图像生成（#6176）和按模型上下文窗口自动检测（#6177），手动上下文设置降为可选覆盖——如果你此前在自托管服务器上硬编码了上下文长度，这点与你相关。
  • 成本追踪与流稳定性修复 — 成本追踪在 #6150 落地，便于计量代理支出。可靠性方面：修复了未锁定 undici 上内容头长度不匹配导致的 Gemini 崩溃（现已兼容 v6 和 v7）、聊天模式下 Anthropic/Bedrock 流式中止崩溃（#6186），以及可能一次暂停就清空整个聊天的 abort 监听器泄漏。Windows 管理员还获得静默/无头安装与卸载 flag，便于无人值守部署。

活动与思维链大改

我们彻底改造了 UI，面向展示多次思考与工具调用的长周期代理任务，把它们汇总成一个干净、可折叠的 UI 元素。

这样你能把更多屏幕空间留给真正的回答，同时仍然以易读的格式保留模型产生的重要调用栈与思考。

导航警告

最近，我们在所有支持的 LLM 上加入了真正的中止信号，这样当你取消推理或离开页面时，我们会停止推理以节省算力成本。

但这带来一个意料之外的副作用：离开聊天时会取消推理，阻止后台完成。现在我们会先警告你再中止响应。

路线图项目： 我们打算把它做成用户可配置，让你可以自定义该行为，并为能够同时运行多个并行推理会话的高性能或高并发配置允许后台推理。

Foundry Local 内嵌（仅桌面）

FoundryLocal 是微软构建的推理引擎，在 Windows 11（24H2 版本，build 26100 或更高）上预装可用。

它使用 WinML 在任何 Windows 硬件配置上为 CPU、GPU 或 NPU 加载模型。对于我们没有明确支持的硬件配置，这是个不错的选择。请记住，由于 FoundryLocal 仍在推广中，模型可用性可能有限。视觉模型目前不可用。

我们与微软合作，如果你遇到 bug 或问题，我们可以帮忙转交给 FoundryLocal 团队

面向 Snapdragon 的 GenieX（仅桌面）

[!NOTE] 这取代了我们之前的 Snapdragon NPU 引擎。旧引擎的任何模型都会在更新时被删除，你需要重新下载这些优化模型。NPU 模型和常规 GGUF 应该会看到显著的性能提升。

我们强烈建议此引擎只使用 GGUF 模型。高通纯 NPU 模型的上下文窗口只有 4K，会导致糟糕的代理体验。

GenieX 是高通构建的开源推理引擎（前身为 NexaAI），可在 X 和 X2 Elite 设备的 NPU 上高效运行 GGUF 和高通 AI Hub 模型。

在下拉框中选择”AnythingLLM GenieX”提供商，即可获得完全托管的内置支持。GGUF 和纯 NPU 模型都能利用 NPU，让你同时获得能效与智能。

我们与高通合作，如果你遇到 bug 或问题，我们可以帮忙转交给 GenieX 团队，或你可以在他们的 GitHub 上提 issue。感谢 @zhiyuan8、@alexchen4ai 和 @alanzhuly
