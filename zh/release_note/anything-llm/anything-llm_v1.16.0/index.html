anything-llm v1.16.0

小版本 发布时间2026年8月13日 来源Mintplex-Labs/anything-llm 英文原文

变更架构图

亮点

  • 通过 /img 实现图像生成 — PR #5904 在配置了支持的提供商时新增图像生成，若该提供商支持图像编辑，还可用图片附件进行编辑/后续/组合提示。这是头条功能，但在你配置此类提供商之前实际上是空操作，而且代理工具驱动的图像生成被明确推迟到下次更新。
  • 代理会话可在运行中控制 — PR #5856 让你在实时代理聊天中开关工具而无需重新加载或新建会话（只显示已配置的工具），PR #6063/#5970 让”停止生成”端到端中止推理，从而停止后不再有”幽灵推理”。新的 create-scheduled-job 代理工具（PR #5916）和 You.com 网页搜索提供商（PR #6058）扩展了代理能力——如果你运行代理聊天，这是强升级理由。
  • 大型工作区的文件/数据处理改进 — PR #6027 在把文件夹拖入文档管理器时保留文件夹层级，但只导入顶层文件（递归导入推迟）；你可以把文件直接放入现有文件夹，URL 抓取器现在在省略时默认 https，懒加载有助于处理数千份文档。新增 Gitea 数据连接器（PR #6087）和 GitHub 连接器中的 GitHub Enterprise URL 支持（PR #6117）增加了摄取来源。
  • 升级前需检查的破坏性/行为变更 — 移除了工作区头像支持（PR #6010），工作区系统提示词覆盖现在在 Workspace.new() 中受门禁（PR #5971），OpenAI/Anthropic 的默认回退模型发生变化（PR #5949），并且工作区更新载荷现在会被校验，畸形请求不再返回误导性的 200（PR #6070）；AWS Bedrock（PR #6081）和 FoundryLocal（PR #6119）被”大修”。未记录明确的迁移步骤，因此如果你依赖这些领域，请重新验证提供商/模型配置。
  • 升级建议 — 这是一个内容充实的次版本，不是重新打标签或仅元数据变更：大多数 v1.15.0 用户应升级以获得代理控制、真正的停止生成、图像生成以及提供商/连接器修复。如果你依赖工作区头像、之前的 OpenAI/Anthropic 回退模型，或者完全不需要代理/图像/连接器功能，可以合理跳过——唯一真正的迁移成本是在 Bedrock、FoundryLocal 和回退模型变更后重新检查配置。

显着变化

图像生成

现在，当设置支持的提供程序时，您可以通过 /img 生成图像。 如果您的提供商支持图像编辑，此流程还允许使用图像附件进行编辑、后续操作或组合提示。

代理工具生成图像的能力将在下次更新中提供。

更好的文件选择器用户体验

现在，在文件选择器中，您可以拖动整个文件夹，它们的层次结构将保留在上传面板中。这只会导入文件夹中的 顶级 文件 - 在以后的更新中它将变得更深且递归。 您现在还可以直接将文件拖放到现有文件夹中，而无需移动它。 最后，您不再需要在 URL 获取器中键入 https - 如果省略，它只会假设 https。 我们还针对文件夹中包含数千个文档的情况进行了一些重大性能改进，例如文件夹的延迟加载。

会话中工具切换

现在，在代理聊天期间，您可以随意打开/关闭工具，无需重新加载或启动新会话。仅已配置的工具（如果需要配置）可用。

停止生成

现在的一个很大的改进是，aborting 响应实际上也完全杀死了推理，这样当中流不再需要时，幽灵推理就不会继续。
