anything-llm v1.8.5

修订 发布时间2025年8月15日 来源Mintplex-Labs/anything-llm 英文原文

anything-llm v1.8.5

变更流程图

亮点

  • 文档聊天大改 — 从 RAG 优先改为在模型上下文窗口允许时尝试完整文档文本（#4261）；文档现在按工作区线程和用户划分范围，并提供可见的上下文窗口管理器，可丢弃陈旧文件同时保留历史，当你溢出到长期记忆时还会出现嵌入提示。这很重要，因为”总结这个文档”这类查询现在能好好工作，而不是回答”你在说什么”——对任何做文档分析的人来说，这是最强的升级理由。
  • 移动端支持（实验性） — 你可以在实验性功能开关后，将 AnythingLLM Mobile App - Android Beta 连接到你的实例，并在统一界面中使用它的 Agent Skills 和流程（#4173）。只有当你想要设备端/跨设备连续性时才值得启用；它被明确标记为实验性，如果你需要稳定、受支持的界面就跳过。
  • 新提供商与模型选择 — 新增 Moonshot AI 作为 LLM/代理提供商（#4178）、Chroma Cloud 作为向量数据库（#4273）、Exa 作为搜索提供商（#4258）、原生 embedder 模型选择（含多语言支持，#3835），以及通用 OpenAI TTS 的 model 字段（#4171）。如果其中任何一项匹配你的技术栈就升级——否则这些都是增量且低风险的。
  • 面向开发者的签名/配置变更（与迁移相关） — 没有正式宣布”破坏性变更”，但 writeToServerDocuments 现在接收配置对象（#4213），sendCommand 使用非位置参数的调用签名（#4218），validFuncCall 只检查必填参数和未定义的选项（#4214），并且自定义 JWT TTL 可配置（#4234）。如果你针对这些内部接口写脚本或依赖默认 JWT 过期时间，升级前请审计集成；典型 UI 用户不受影响。
  • 针对性修复与可跳过人群 — 修复了通过 OpenAI 兼容 API 的多模态聊天（#4135）、export-chats API 端点的导入错误（#4220）、应用版本指标端点（#4209），以及针对非 public schema 的 PostgreSQL 查询（#4202），并新增翻译（罗马尼亚语 #4247、西班牙语 #4263、希伯来语 #4241）。如果你遇到其中任何问题或想要文档/移动端功能，建议升级；如果你在 v1.8.4 上稳定运行且不使用受影响的路径，可以放心等待——这是一个内容充实的功能版本，不是空操作或仅元数据改标签。

移动支持

现在，在 实验功能 下，您可以将 AnythingLLM 移动应用程序 - Android Beta 连接到您的实例，以无缝融合设备内和设备外体验。在一个统一的界面中利用您的实例代理技能和流程！

文档聊天已被彻底修改

https://github.com/user-attachments/assets/0e4ab18d-fb58-480a-94f5-907664dd8f3f 当我们第一次构建 AnythingLLM 时，平均上下文窗口为 4K - 几乎无法容纳完整文档。所以我们决定永远把 RAG 放在第一位。这有其缺点，因为 RAG 在语义上依赖于询问有关文档内容的问题。这会导致“总结此文档”的结果很差，只能由文档告诉“你在说什么”。 好吧，现在我们两全其美。文档的范围仅限于工作区线程和用户，我们将尝试在可能的情况下使用完整的文档文本，并且您的模型可以支持它。如果您超出了此数量，我们可以要求您嵌入该文档，以便您可以解锁该长期记忆。 您还可以轻松管理和查看上下文窗口，以删除不再相关的文件，但保留对话历史记录。 您还可以直接将文件嵌入到工作区文件管理器中:)
