anything-llm v1.11.1

修订 发布时间2026年3月2日 来源Mintplex-Labs/anything-llm 英文原文

anything-llm v1.11.1

这个项目是干啥的：一个能把你的文档喂给大模型、再像聊天一样提问的私有知识库工具，还能连接各种 AI 插件，适合想搭个人或团队知识库的人。

变更架构图

亮点

  • @agent 的原生工具调用 — 工具调用现在使用提供商原生支持，支持多步本地工作流并持续执行直至完成，设有 10 次调用的安全上限。AnythingLLM Default、Ollama 和 LM Studio 在支持时会自动启用；其他列出的提供商需要 PROVIDER_SUPPORTS_NATIVE_TOOL_CALLING。云提供商不受影响。
  • AMD Lemonade 支持 — Lemonade 现已成为一等本地运行时，让你可以连接托管其上的模型，尤其是在 AMD 硬件上。如果你使用或计划使用 Lemonade，值得升级；否则单凭此点可选。
  • 首页与主题改进 — 重新设计的首页在完成引导后能更快进入聊天，另有浅色模式侧边栏更新和专属深色主题（支持跟随系统偏好）。这是 UX 升级，而非迁移既有配置的理由。
  • 可靠性与输入修复 — 修复了 GitLab 连接器无限循环和大型仓库上的限流崩溃、Gemini 代理 400 错误、useIsDisabled 事件监听器泄漏、引导流程密码校验，以及文本域光标导航问题。大型 GitLab 用户和 Gemini 代理用户有具体的升级理由。
  • 升级指引 — 变更日志未说明破坏性变更或必需迁移步骤。依赖新支持的非自动启用提供商的用户必须按文档用环境变量选择加入；无此需求且不受修复影响的用户可安全推迟。

主页重新设计

AnythingLLM 主主页已完全重新设计，更加现代且用户友好，因此您在入职后打开应用程序后即可立即开始聊天。

原生工具调用

<标注类型=“信息”> 原生工具调用是与您的 LLM 提供商和模型进行工具调用的最佳性能和体验。如果你可以启用它，你应该启用它。 这仅适用于本地 LLM 提供商。它对 OpenAI、Anthropic 或 Azure 等云 LLM 没有影响。 </标注> 我们彻底修改了 @agent 工具调用的工作方式。现在，我们将利用您的 LLM 提供商和模型的新本机工具调用功能。 这对您意味着什么：

  • 您现在可以使用您的 LLM 提供商和模型运行复杂的多步骤工具调用。
  • 您的模型现在将继续工作，直到生成或确定完成您的最终响应。
  • 即使是小型工具调用模型，您也会获得 100 倍更好的响应 我们还实施了保护措施来防止无限循环，每个响应最多调用 10 次工具，以防止任务失控。

限制

大多数提供商不允许我们探测模型是否支持本机工具调用。 如果您的模型支持，以下本地 LLM 提供商将自动支持本机工具调用：

  • 默认内置LLM提供商（AnythingLLM默认）
  • 奥拉马
  • LM工作室 对于其他人，您需要设置一个 ENV 变量以启用支持的提供程序的本机工具调用。
  • 通用 OpenAI
  • 格罗克
  • AWS 基岩
  • 柠檬水
  • 莱特法学硕士
  • 本地人工智能
  • 开放路由器 这可以通过 PROVIDER_SUPPORTS_NATIVE_TOOL_CALLING 环境变量进行设置。
PROVIDER_SUPPORTS_NATIVE_TOOL_CALLING="bedrock,generic-openai,groq,lemonade,litellm,local-ai,openrouter"

AMD 集成的 Lemonade
