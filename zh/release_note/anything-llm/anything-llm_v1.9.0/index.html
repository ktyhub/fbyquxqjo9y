anything-llm v1.9.0

小版本 发布时间2025年10月9日 来源Mintplex-Labs/anything-llm 英文原文

anything-llm v1.9.0

变更流程图

亮点

  • 代理流式大改造 — #4279 为所有提供商和模型带来实时工具调用与响应流式输出，终结了加载转圈的时代。对嵌入代理的开发者来说，这是头条改动：UI 可以渲染增量的工具调用和 token，而不再阻塞等待最终答案，因此任何围绕同步代理响应构建的东西都应按流式路径重新测试。后续改动把 OpenAI 代理迁移到 Responses API（#4467），并让 Gemini 代理脱离 Untooled（#4505）。
  • Web 原生文档摄取 — #4398 新增对静态托管文件的抓取/解析/文档创建，让代理可以按需从 URL 拉取 PDF、电子表格和 CSV，无需预先上传。配合 #4504（改进的 collector URL 处理）和 #4516（大写 URL 修复）：摄取边界情况显然仍在加固中，因此在生产流程中依赖非平凡 URL 前请先验证。
  • OpenAI 提供商迁移到 Responses API — #4404（LLM）和 #4467（代理）把 OpenAI 集成切换到 Responses API，随后 #4458 修补了 OpenAI 指标。这是最可能出现微妙回归的地方：如果你依赖精确的 token 统计、流式语义或提供商特有行为，请在切换前针对 v1.9.0 运行指标和计费断言。
  • 摄取 API 与提示词模板新增 — #4342 为 document/upload、document/upload/{folderName} 和 document/upload-link 新增 metadata 参数；#4414 引入新的默认系统提示词变量（用户 ID、工作区 ID、工作区名称）；#4396 在最终流式块中报告来源。API 客户端可以在上传时附带元数据，并从最终块读取引用而无需第二次请求——请检查那些假定最终块不含来源数据的代码。
  • 新提供商与本地模型易用性 — Microsoft Foundry Local（#4435）、CometAPI（#4379）和重建的 Cohere 聊天实现（#4489）扩展了提供商选择，#4468 为 LM Studio 和 Ollama 增加上下文限制自动检测，#4448 为 Ollama 暴露可配置的 HTTP 超时。本地模型用户可以去掉手工上下文窗口设置，但请在自定义或量化模型上验证自动检测出的限制。
  • 部署与配置加固 — 新的 Helm chart（#4484）让 Kubernetes 部署成为一等公民；#4397 允许传入 Chromium 参数，使文档 collector 不再需要 SYS_ADMIN——对容器化安装是实实在在的安全收益；#4394 新增 SIMPLE_SSO_NO_LOGIN_REDIRECT。采用时请复核容器安全上下文和 SSO 重定向流程。

本版本未明确列出破坏性变更。

@agent 大修和直播 ⚡️️

<视频src =“https://github.com/user-attachments/assets/fbbfab37-e1b0-442b-b7d4-277aacfcf9bb”></视频> 当 Anyllm 首次推出时，LLM 世界的词汇中还没有“代理”这个词。代理正在迅速成为构建人工智能应用程序的标准，也是与法学硕士互动的核心体验。 长期以来，由于构建代理的复杂性、参差不齐的工具调用支持、甚至无法使用工具的模型以及更多书呆子的东西，我们经常不得不解决一种使用起来并不有趣的体验，因为 99% 的时间你只是在等待响应的加载旋转器。

新的特工体验现已到来

实时流式传输工具调用和响应（所有提供商、所有模型） 代理现在可以从网络实时下载和提取文件（例如：链接到 PDF、Excel、csv）。您将使用文档的任何内容都可以由代理从网络上实时读取。

即将推出：

  • 座席实时API呼叫，无需座席流程
  • 代理图像理解
  • 座席系统提示透传+用户上下文感知
  • 实时文件搜索跨平台默认技能

显着改进：🚀

  • 所有型号和提供商现在都支持代理流
  • Microsoft Foundry 本地集成
  • 通过代理或上传器临时抓取/下载任何网络资源
