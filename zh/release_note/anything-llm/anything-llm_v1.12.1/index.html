anything-llm v1.12.1

修订 发布时间2026年4月22日 来源Mintplex-Labs/anything-llm 英文原文

变更架构图

亮点

  • 可续传的文档 embedding — PR #5254 用状态事件、任务队列和 fork 进程取代了逐文档 embedding。你可以看到每个文档的进度、增删排队中的文档，并且离开页面也不会丢失进度。对于文档密集型工作区，这是最强的升级理由。

  • 邮件与日历代理技能 — 内置的 Gmail、Outlook（通过 Entra Application）和 Google Calendar 集成只需极少配置，应用结果的引用也得到改进。代理会话现在会报告 chatId，无需刷新页面即可重新生成聊天、TTS 及相关操作。如果你希望代理处理邮件或日程工具，建议升级。

  • 提供商与文档输出兼容性 — Ollama 升级到 0.20.7 以支持 Qwen3.5 和 Gemma 4，Generic OpenAI 新增能力检测，Lemonade 得到更新，PDF 生成现在支持韩文、中文和日文。Lemonade embedding 失败现在会抛错而非返回空结果，让索引失败可见，而不是产生误导性输出。

  • 升级建议 — 未列出破坏性变更或必需迁移步骤。如果你依赖大文档上传、新集成或更新后的提供商/PDF 支持，建议升级；否则稳定的纯聊天工作流可以合理跳过这个补丁。新的基于 ENV 的代理技能自动批准是可选功能，应有意识地启用，因为它会减少人工审批控制。

显着改进

流式文档嵌入

现在，当您将文档上传到工作区时，会在嵌入过程中报告每个文档的进程。这是性能和用户体验方面的巨大改进。在此过程中，您可以向队列添加和删除文档，甚至可以关闭并离开页面，而不会丢失进度。

应用程序集成

现在有以下应用程序的内置集成，代理技能所需的设置最少甚至为零：

  • Gmail
  • 展望
  • 谷歌日历

其他改进

  • 主 UI 中的图像灯箱
  • 通过自定义 mdpdf fork 为 PDF 生成启用韩文、中文和日文字符支持
  • 更好地引用应用程序集成
  • DDG 在代理技能中默认的网络搜索
  • 当文档生成代理生成时，在计算机上的本机应用程序中打开文档
  • 通过 ENV 设置自动批准代理技能
  • Ollama 升至 0.20.7（Qwen3.5 支持、Gemma 4 等）
  • Unload model when closed 的新自定义 > 聊天设置，用于在用户关闭聊天窗口时卸载模型。
  • 通用 OpenAI 能力检测/ENV 设置
  • 更新 Lemonade 以支持 1.10.0 更改
  • 加泰罗尼亚语翻译
  • 名称字段添加到 API 键
  • 在代理会话中报告聊天 ID，因此现在您可以重新生成聊天、TTS 和更多操作，而无需重新加载页面。
