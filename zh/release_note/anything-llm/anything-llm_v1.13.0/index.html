anything-llm v1.13.0

小版本 发布时间2026年5月26日 来源Mintplex-Labs/anything-llm 英文原文

变更架构图

亮点

  • Model Router（PR #5324） — 一个用户自定义的混合路由层，可在单次对话中混合本地后端（Ollama、LM Studio）与云提供商（OpenAI、Anthropic、Google），无需手动切换。规则分两类：计算型（关键词、token 数、时段、图片附件——即时求值）和 LLM 分类型（自然语言意图）。Sticky routing 把线程固定到某个模型，避免逐条消息来回抖动；路由决策现在使用准确的 token/消息计数（PR #5680）。注意：路由对终端用户不可见，但必须由管理员配置，而且没有安全的默认值——一条宽松的规则可能悄悄把敏感提示词送到云模型。请把规则集当作数据治理配置的一部分，而不是设好就忘的功能。
  • 定时任务（Scheduled Jobs，PR #5322） — AnythingLLM 变成常驻代理运行时：定义提示词、挑选工具、通过可视化 Cron Builder 设定计划（无需手写 cron 语法），然后就可以走开。任务拥有专属技能以约束工具范围，与交互式聊天使用相同的工具（网络搜索、文档分析、自定义技能、MCP），具备完整运行历史（含推理/工具调用/生成文件），并支持带深链回到结果的推送通知。要留意成本和影响范围：一个带着云工具和开放式提示词的无人值守代理，可能按紧凑计划烧掉 API 预算，因此请有意识地界定技能和计划。生成的文档现在也可通过 API 取回（PR #5658）。
  • 自动记忆与个性化（PR #5269） — 后台抽取任务构建记忆库并注入系统提示词，分为工作区级（项目上下文）和全局（姓名、偏好）记忆。你可以关闭抽取、编辑条目或手动添加记忆，避免把模型周期花在回顾聊天历史上。对开发者的影响：实际系统提示词现在是动态的，token 预算和提示词缓存假设会在轮次之间变化，而且抽取会增加后台 LLM 成本。请审计存储了什么——聊天里说过的任何话都可能变成持久的提示词内容。
  • 代理调研（Agent Surveys，PR #5577） — 一种特殊工具，让代理在继续之前先提出澄清问题，答案会随聊天消息持久化，供后续轮次使用。它默认关闭，必须在代理设置中启用。适合含义模糊的多步骤任务，但全局启用（尤其是在无人值守的定时任务上）会给原本自主的流程引入交互式暂停。
  • “Auto mode” → “agent mode” 及相关行为变化（PR #5551、#5550、#5516、#5595、#5691） — 术语变更：auto mode 现称 agent mode；agent 模式下线程会自动重命名（#5550），双重 /reset bug 已修复（#5516），auto-speak 现在在 agent 模式下可用（#5595），Prompt 重构不再阻塞主聊天内容（#5691）。引用 “auto mode” 的脚本、文档和支持答复都需要更新。另请注意 MUM 迁移把 DeviceTokens（#5655）和斜杠命令（#5684）转移到某个现有管理员用户——升级后请确认你的管理员账号拥有它们，如果你曾以编程方式删除工作区，还要检查工作区删除保护（#5662）。
  • 提供商、平台与 API 加固 — 新增用于代理网页浏览的 Baidu Search 提供商（#5388）和 MiniMax LLM 支持（#5450）；OpenShift 任意 UID/GID-0 Docker 镜像（#5136）和面向受限部署的可配置 collector 端口（#5607）；修复了 Gemini 上并行工具调用导致的 400 错误（#5630）；推理内容现在流经 v2 流处理器（#5654），并正确处理 DeepSeek v4 推理（#5527）；TTS 在合成前会剥离 Markdown（#5560）。如果你流式输出响应或在 Gemini 上运行多工具代理，这些是最可能改变集成行为的修复。

本版本没有破坏性 API 变更。

本版本专注于改善代理体验、为代理系统添加新功能，并迈向更被动、更个性化、混合式的 AI 体验。

此版本的重点是改善代理体验并为代理系统添加新功能，以及转向更加被动、个性化和混合的人工智能体验。

Model Router：首个消费者混合人工智能体验

模型路由器功能是首个用户定义的智能路由系统，它将本地和云人工智能无缝融合成完全由您控制的单一、统一的体验。到目前为止，您必须选择：在本地运行所有内容，或将所有内容发送到云端。这种权衡已经结束。 使用模型路由器，您可以定义规则。您发送的每条消息都会自动分析并路由到适合该特定任务的完美模型，无论是用于快速问题的轻量级本地模型、用于复杂数学的推理模型，还是用于细致入微的法律分析的最强大的云模型。全部来自同一个聊天记录。对用户来说都是不可见的。一切由你定义。 是什么让这如此令人兴奋：

  • 混合人工智能。 在一次对话中将本地模型（Ollama、LM Studio 等）与云提供商（OpenAI、Anthropic、Google）混合并匹配。无需手动切换！
  • 您拥有完全的控制权。 创建计算规则，这些规则可即时触发关键字、令牌计数、一天中的时间或图像附件。或者使用LLM分类规则以简单的英语理解意图。
  • 节省资金而不牺牲质量。 将简单查询路由到廉价或本地模型。为真正需要的消息保留昂贵的 API 呼叫。
  • 智能缓存。 我们先进的粘性路由系统使您在对话线程期间保持在同一模型上，因此您不会在每条消息上在模型之间跳转。 我们相信，这是人工智能助手工作方式的根本性转变。您第一次获得本地模型的隐私、云模型的强大功能以及了解何时使用每个模型的智能。而且它是 100% 开源的。 了解如何设置您的第一个路由器 →

预定工作：当你不工作时，你的人工智能会工作

如果您的人工智能助手可以按照您定义的时间表在后台自动为您工作，而无需您动手，会怎样？ 预定工作 将 AnythingLLM 转变为始终在线的人工智能员工队伍。创建自动运行的重复任务：早间简报、每周报告、数据监控、研究摘要。您通常要求代理做的任何事情，但都是自动化且免提的。您可以设置特定于工作的技能，这样模型就不会被工具淹没，并且结果是可重复的。 为什么这会改变一切：

  • **设置好后就不用管它了。**定义提示，选择工具，选择时间表，然后走开。您的代理会在您需要时准确运行：每天早上 8 点、每周一中午、每小时整点。
  • 不需要技术知识。 我们的可视化 Cron Builder 可让您通过简单的下拉菜单来安排作业。没有神秘的 cron 语法，没有命令行，没有代码。只需点和click。
  • 完全代理能力，完全自动化。 预定作业可以访问与常规聊天相同的工具：网络搜索、文档分析、自定义技能、MCP 集成等。如果代理可以在对话中完成这件事，那么它就可以按计划完成。
  • 完整的运行历史记录。 每次执行都会记录代理的完整推理、工具调用、生成的文件和最终响应。随时查看过去的运行，或在新线程中从代理中断的地方继续。
  • 推送通知。 即使 AnythingLLM 在后台，也会在作业完成时收到提醒。 Click 直接跳到结果。 企业工具为这种自动化收取数千美元的费用。仅云平台要求您将数据传输给第三方。 AnythingLLM 为您提供预定的 AI 代理，这些代理完全在您的计算机上运行，​​并且数据在您的控制之下。 醒来后会看到隔夜电子邮件的摘要。自动编写每周进度报告。监控网站的变化。可能性是无限的，只要您专注于重要的事情，这一切就会发生。 了解如何创建您的第一个预定作业 →

自动记忆和个性化

AnythingLLM 现在支持自动记忆提取和个性化，因此您的 AI 助手可以记住您谈论的内容，并利用这些知识来个性化其响应。 AnythingLLM 运行后台作业，从聊天中提取记忆并将其存储在内存库中。然后，该记忆库用于个性化您的人工智能助手的响应 - 您可以完全控制记住的内容以及如何使用它 如果您不想让模型花费周期来查看聊天历史记录，您甚至可以手动将记忆添加到内存库中。 记忆有两种类型：

  • 工作空间记忆：这些是特定于当前工作空间的记忆（例如您正在处理的内容、特定于项目的信息等）
  • 全局记忆：这些是特定于整个 AnythingLLM 实例的记忆（例如您的姓名、偏好等） 记忆被注入人工智能助手的系统提示中，以便它可以使用它们来个性化其响应，并且是对人工智能助手知识库的欢迎补充。 了解如何启用和管理内存→

代理调查（特殊工具）

代理调查是一种特殊工具，可让您的人工智能助手在继续操作之前提出澄清问题。当您正在处理复杂的任务并且代理需要更多信息才能继续时，这非常有用。 默认情况下此功能处于关闭状态，必须在代理设置中启用。问题的答案与聊天消息一起保存，以便客服人员可以在以后的回合中使用它们。 了解如何启用和管理代理调查 →
