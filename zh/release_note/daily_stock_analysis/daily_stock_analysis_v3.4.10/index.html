daily_stock_analysis v3.4.10

daily_stock_analysis v3.4.10

变更流程图

亮点

  • ETF OHLCV 从全零变为真实数据 — EfinanceFetcher._fetch_etf_data 从 ef.fund.get_quote_history（只有净值、忽略 beg/end）切到 ef.stock.get_quote_history，并从 _normalize_data 移除过时的净值列映射（#541、#527）。此前用 ETF 画图或算指标的人其实一直在吃零值开盘/最高/最低/收盘/成交量/金额——这是值得升级的正确性修复，但旧版本已落库的 ETF OHLCV 要重新校验。
  • 补齐北交所覆盖 — 8/4/92 开头的 6 位代码现正确归类为北交所，Tushare/Akshare/Yfinance 认 .BJ 或 bj 前缀，Baostock/Pytdx 对这些代码显式切换数据源，900xxx 沪市 B 股不再被误判（#491、#533）。跟踪北交所标的的用户直接受益，其余无感。
  • tiktoken 护栏——当作「不要浮到 0.12」的硬规则 — requirements.txt 固定 tiktoken>=0.8.0,<0.12.0，规避 0.12.0 引入的 Unknown encoding cl100k_base 插件注册回归（#537）。不算破坏性变更，但自行维护环境且已经拉到 0.12.0 的话必须钉住版本，否则分词会直接失败。
  • 报告输出：模型透明化与图片推送 — 报告 meta、页脚和推送内容现在都会露出 model_used（完整 LLM 名），Agent 多轮调用还会逐轮展示实际使用的模型（含 fallback 切换）（#528、#534）；个股汇总支持转图推送 Telegram/WeChat/Custom/Email（#455、#535）。新增开关：MD2IMG_ENGINE=markdown-to-file 改善 emoji 支持（需 npm i -g markdown-to-file）、PREFETCH_REALTIME_QUOTES=false 跳过 efinance/akshare_em 全市场预取；转图失败会点名缺失依赖（wkhtmltopdf / m2f），仅配企业微信图片的场景不再做冗余的全报告转图。
  • 诊断与小的解析修复，无需迁移 — Web UI 现在把 HTTP 400 拆成多种原因（Agent 未启用 / 参数缺失 / 模型工具不兼容 / 上游 LLM 错误 / 本地连接失败），不再笼统报「服务器/网络」故障（#540）；狙击点位提取在没有「元」字时也不会再把括号里的技术指标数字当成买入价（#488、#532）。没有显式破坏性变更或迁移步骤。依赖 ETF OHLCV、北交所代码、多渠道图片推送或 tiktoken 0.12+ 的用户建议升级；只跑主板、文本报告且依赖集正常的用户可以跳过这个补丁。

已修复

  • 🐛 EfinanceFetcher ETF OHLCV 数据 (#541, #527) — 将 _fetch_etf_data 从 ef.fund.get_quote_history（仅 NAV，无 OHLCV，无 beg/end 参数）切换为 ef.stock.get_quote_history； ETF 现在返回正确的开盘价/最高价/最低价/收盘价/成交量/金额，而不是零；从 _normalize_data 中删除过时的 NAV 列映射
  • 🐛 tiktoken 0.12.0 Unknown encoding cl100k_base (#537) — 在requirements.txt中固定tiktoken>=0.8.0,<0.12.0以避免0.12.0中引入的插件注册回归
  • 🐛 Web UI API 错误分类 (#540) — 前端不再将每个 HTTP 400 视为相同的“服务器/网络”故障；现在区分代理已禁用/缺少参数/模型工具不兼容/上游 LLM 错误/本地连接失败
  • 🐛 北交所代码识别失败 (#491, #533) — 8/4/92 开头的 6 位代码现正确识别为北交所；Tushare/Akshare/Yfinance 等数据源支持 .BJ 或 bj 前缀；Baostock/Pytdx 对北交所代码显式切换数据源；避免误判上海 B 股 900xxx
  • 🐛 狙击点位解析错误 (#488, #532) — 理想买入/二次买入等字段在无「元」字时误提取括号内技术指标数字；现先截去第一个括号后内容再提取

添加

  • Markdown-to-image for dashboard report (#455, #535) — 个股日报汇总支持 markdown 转图片推送（Telegram、WeChat、Custom、Email），与大盘复盘行为一致
  • markdown-to-file engine (#455) — MD2IMG_ENGINE=markdown-to-file 可选，对 emoji 支持更好，需 npm i -g markdown-to-file
  • PREFETCH_REALTIME_QUOTES (#455) — 设为 false 可禁用实时行情预取，避免 efinance/akshare_em 全市场拉取
  • Stock name prefetch (#455) — 分析前预取股票名称，减少报告中「股票xxxxx」占位符

Changed

  • Enhanced markdown-to-image failure warning (#455) — 转图失败时提示具体依赖（wkhtmltopdf 或 m2f）
  • WeChat-only image routing optimization (#455) — 仅配置企业微信图片时，不再对完整报告做冗余转图，避免误导性失败日志
  • Stock name prefetch lightweight mode (#455) — 名称预取阶段跳过 realtime quote 查询，减少额外网络开销
  • 📊 分析报告模型标记 (#528, #534) — 在分析报告 meta、报告末尾、推送内容中展示 model_used（完整 LLM 模型名）；Agent 多轮调用时记录并展示每轮实际使用的模型（支持 fallback 切换）
