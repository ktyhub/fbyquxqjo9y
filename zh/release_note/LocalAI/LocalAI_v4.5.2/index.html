LocalAI v4.5.2

修订 发布时间2026年6月26日 来源mudler/LocalAI 英文原文

LocalAI v4.5.2

这个项目是干啥的：是一个能在自己电脑上跑的OpenAI兼容接口工具，让没有显卡或不想上云的人也能在本地调用大模型，不花API费用。

变更架构图

亮点

  • macOS/Darwin 的 Opus 后端现在能构建和打包 — PR #10523 修复了 Opus 音频编解码后端在 Darwin 上的构建和打包。此前你在 macOS 上根本无法产出该后端，因此 Mac 用户实际上被排除在所有依赖它的功能之外。这是构建/打包修复，而非推理变更——模型行为、API 和配置格式均未改动。
  • Realtime API 中的 WebRTC 语音是真正的受益者 — Opus 是 Realtime API 多模态语音流水线（VAD → STT → LLM → TTS）所用 WebRTC 传输的必需编解码器。随着该后端现在可在 macOS 上安装，基于浏览器的低延迟语音会话终于能在 Mac 上通过 local-ai backends install opus、Backends 页面、/backends/apply 端点或 EXTERNAL_GRPC_BACKENDS=opus:<path> 工作。在此之前，WebRTC 会话在 macOS 上失败仅仅因为编解码后端不可用。
  • Apple Silicon 获得 Metal 变体 — 需关注的画廊目标是 metal-opus（latest-metal-darwin-arm64-opus），这样 Apple Silicon Mac 会拿到 Metal 加速构建，而 Intel/CPU 的 Darwin 使用标准的 opus / latest-cpu-opus 镜像。如果你按 digest 固定后端镜像而非使用画廊，升级后请重新拉取以真正获取该修复。
  • 源码构建与 CI 的影响 — 如果你在 macOS 上自行构建后端，Go 后端构建路径（build-darwin-go-backend、backend/go/opus 的 Makefile/package.sh）和 make test-opus 现在都能在 Darwin 上运行，macOS 后端/镜像构建应不再在 opus 步骤失败。Linux 和 Windows 流水线无变化。
  • 范围与升级路径 — 这是一个单修复的补丁版本（v4.5.1 → v4.5.2）：可直接替换的二进制/后端升级，无需更改配置或模型 YAML。如果你不在 macOS 上使用 WebRTC/Opus，对你没有实际变化。
  • 无破坏性变更 — 本次发布没有；无需迁移步骤。

其他变化

  • 修复（后端）：通过 https://github.com/mudler/LocalAI/pull/10523 中的 @localai-bot 在 macOS/Darwin 上构建 opus 后端并打包
