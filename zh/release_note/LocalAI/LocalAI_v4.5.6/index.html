LocalAI v4.5.6

修订 发布时间2026年6月30日 来源mudler/LocalAI 英文原文

LocalAI v4.5.6

这个项目是干啥的：是一个能在自己电脑上跑的OpenAI兼容接口工具，让没有显卡或不想上云的人也能在本地调用大模型，不花API费用。

变更架构图

亮点

  • 跨副本分布式状态 — 微调、量化和 agent 任务现在通过 SyncedMap 同步（#10542），agent 节点返回空的后端列表，而不是让 backend.list 失败（#10565）。分布式部署应应用修正后的 agent NATS 权限（#10549、#10571），并在共享模型卷上设置 LOCALAI_DISTRIBUTED_SHARED_MODELS，以避免重复暂存（#10566）。
  • 原生检测后端 — 新的 ggml voice-detect 和 face-detect 后端取代了 Python 的 insightface/speaker-recognition 路径（#10441），减少了运行时依赖和部署复杂度。切换后，现有的 Python 后端配置应重新验证输出是否一致。
  • 语义化的实时轮次边界 — 实时处理新增了语义 VAD 的语句结束 token（#10444），让应用在声学静音检测之外，还能获得一个由模型推导的轮次边界。关闭轮次或触发响应的客户端，应针对这个额外信号测试其时序假设。
  • 流式与工具调用正确性 — OpenResponses 现在限制恢复流的缓冲并强制响应所有权，抑制内存增长和跨响应访问（#10569）。推理模型流在 max_tokens 后停止重试而非循环（#10448），因此客户端应把该限制视为终态；SGLang 也在应用聊天模板前解析工具调用参数（#10558）。
  • 模型选择与上下文行为 — 无法解析的 GGUF 回退到 DefaultContextSize（#10563），画廊匹配不再混淆 F16 与 BF16（#10564），滑动窗口注意力模型默认 swa_full:true（#10611）。最后一项会改变上下文处理、内存用量和吞吐量；如需旧有配置，请显式设置。
  • 破坏性平台变更 — Fish Speech 放弃其 Darwin/Metal 构建目标（#10561），因此依赖 Metal 加速的 macOS 用户必须切换后端或停留在更早的版本。另外，macOS 公证票据现在直接装订到 .app，而非仅 DMG（#10606），改善了 Gatekeeper 校验。
