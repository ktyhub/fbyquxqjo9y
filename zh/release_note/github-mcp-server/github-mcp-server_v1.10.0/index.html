github-mcp-server v1.10.0

亮点

v1.10.0 是 GitHub MCP 服务器的重要安全性、可靠性和兼容性版本。

默认情况下更安全

  • 添加了带有表单引发和受保护的多往返状态的确认存储库删除（#3076）。
  • 将承载凭证限制为配置的 GitHub 权限 (#3056)。
  • 对 GitHub Enterprise 主机强制执行 HTTPS (#3069)。
  • 使无效的静态 --tools 配置无法关闭（#3050​​）。
  • 强化锁定、请求限制、缓存隔离、URL 遍历和响应清理（#3109、#3112、#3113、#3111、#3108、 #3114、#3110)。

更好的 GitHub 企业服务器兼容性

  • 当问题自定义字段 GraphQL 类型不可用时，list_issues 和 search_issues 现在可以安全降级（#3086、#2897）。
  • list_issues 现在返回受让人登录名和未分配问题的稳定空数组 (#3064)。
  • 当 GitHub API (#3081) 提供时，验证失败会暴露安全规则集详细信息。

更安全的存储库文件操作

  • get_file_contents 现在可以识别符号链接并清楚地标记取消引用的内容。
  • 符号链接写入需要明确的 allow_symlink_write: true 选择加入（#3071）。
  • 修复了二进制 MCP 资源被 Base64 编码两次的问题 (#3098)。

更可靠的工具合约

  • 修正了 add_issue_comment 输入模式 (#3085)。
  • issue_write.issue_fields[].delete: false 现在是严格模式 ZZPH100​​ZZents 的有效无操作（#3077）。
  • 零参数工具接受省略的 arguments 属性，同时拒绝显式的 null 和格式错误的 JSON (#3099)。
  • 通知订阅工具明确宣传破坏性行为 (#2936)。
  • 副驾驶审核请求拒绝现在返回可操作的指导，而不是简单的 404 (#3119)。

项目、行动和效率

  • 添加了项目视图生命周期操作和可见字段配置（#2961、#2988）。
  • 减少操作和其他成功响应负载（#3047、#3055）。
  • 改进了清理性能并刷新了 UI/构建依赖项（#3120、#3100）。

需要注意的行为变化

  • 未知的静态 --tools 名称现在会阻止启动。
  • 符号链接更新需要明确的选择加入。
  • 请求不能放松服务器强制锁定。
  • 过大的 HTTP 请求正文会被提前拒绝。
  • add_issue_comment 执行更严格的互斥模式验证。
  • 存储库删除需要合格的现代 MCP client、表单获取支持和适当的范围。
