lowcode-engine v1.3.2

修订 发布时间2024年2月23日 来源alibaba/lowcode-engine 英文原文

lowcode-engine v1.3.2

这个项目是干啥的：阿里开源的低代码搭建引擎，靠拖拽就能拼出页面还带全新命令系统，给想快速做后台管理页的前端开发者用。

变更架构图

亮点

  • 全新命令系统与 plugin-command 包 — 头条变化是一等公民的命令层：新的命令 API 落地（#2882），默认命令得到更新（#2901），相关功能被拆到独立的 plugin-command 包（#2906、#2907、#2908），并在 #2909 补充文档。这是增量特性，不会破坏现有功能，但要使用它必须接入新包/API——如果你一直在等命令抽象，值得升级。

  • checkPropTypes 移入 utils — 请核对你的导入 — PR #2879 将 checkPropTypes 迁移到 utils 模块，#2877 则扩展它，使 IPublicTypePropType 可以直接作为规则使用（并在 #2881 增加更多测试）。changelog 没有明确的迁移说明，因此如果你从旧位置导入 checkPropTypes，升级前请确认该路径仍可解析。这是唯一存在真实迁移风险的地方。

  • 属性与工作区 bug 修复 — 属性变更现在会一致地触发事件：取消设置属性（#2894）和删除属性（#2902）都会发事件，这对依赖观察者响应模型变更的用户很重要。另有两项工作区修复：失效的 workspace.plugins.xxx API（#2904）和 undefined 的 workspace.editorView（#2921）。如果你遇到其中任何一个，应升级。

  • 模拟器、setter 与右键菜单修复 — react-simulator-renderer 不再错误处理脱离节点上的 children（#2888，@Zeral-Zhang 的首次贡献）；右键菜单在 menus 为空时停止事件冒泡（#2899）；setter 修复 params 不是 shell SettingField 的问题（#2913）并补充字段类型（#2891）；TypeScript 定义得到更新（#2905）。属于增量式的正确性与类型改进，而非新能力。

  • 值得升级吗？ — 未声明破坏性变更，也不是重新打标签或仅元数据变更；本次是增量特性加上针对性的 bug 修复。如果你需要命令 API、checkPropTypes/IPublicTypePropType 规则，或属性/工作区修复，就采用它。如果这些都与你无关，其余只是文档/测试方面的改动（如 #2862、#2874、#2880），可以安全跳过。

lowcode-engine是什么

Lowcode-engine是一个低代码开发平台，旨在简化应用程序的构建过程。它通过可视化的界面和预构建的组件，使开发者能够快速创建和部署应用，而无需深入的编程知识。这种方式不仅提高了开发效率，还降低了技术门槛，使得更多的人能够参与到软件开发中来。

为什么要使用lowcode-engine?

使用lowcode-engine的原因有很多。首先，它显著缩短了开发周期，开发者可以通过拖拽组件和配置参数来快速构建应用。其次，低代码平台通常具有良好的可扩展性，允许用户根据需要添加自定义功能。此外，lowcode-engine还支持团队协作，多个开发者可以同时在同一个项目上工作，提升了团队的工作效率。最后，低代码开发平台的学习曲线相对较低，非技术人员也能快速上手，推动了业务与IT的紧密结合。

lowcode-engine v1.3.2版本更新了什么

在v1.3.2版本中，lowcode-engine进行了多项重要更新和修复，具体包括：

  • 文档更新：移除了示例部分的标题级别。
  • 功能增强：checkPropTypes支持IPublicTypePropType作为检查规则。
  • 测试增强：增加了parse-metadata的测试。
  • 功能改进：将checkPropTypes移动到utils模块。
  • 新增命令API。
  • 修复了多个bug，包括在删除属性时发出事件等。

这些更新不仅提升了平台的稳定性和功能性，也为开发者提供了更好的使用体验。
