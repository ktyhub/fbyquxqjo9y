LightRAG v1.4.9.9

修订 发布时间2025年12月22日 来源HKUDS/LightRAG 英文原文

变更流程图

亮点

  • 工作区与模型隔离 — 流水线状态和内存状态现在按工作区隔离，PostgreSQL/Qdrant 向量存储则按嵌入模型和维度隔离数据，防止跨工作区污染和维度不匹配崩溃（#2369、#2391、#2513）。已有存储会自动迁移；通过 wrap_embedding_func_with_attrs 设置 model_name 即可使用带模型后缀的表，未设置的函数仍留在旧的无后缀表中。
  • 核心集成需要迁移 — 直接集成 LightRAG 的代码面临破坏性变更：chunking_by_token_size 的参数被重命名（#2379），按名称传参的调用方需要更新。自定义嵌入函数要用 embedding_dim、max_token_size、model_name 元数据恰好包装一次；嵌套包装的问题也已修复（#2522）。自定义分块函数现在可以是异步的，避免昂贵分块时的阻塞（#2336）。
  • 嵌入维度与 token 上限 — EMBEDDING_SEND_DIM 为 OpenAI 和 Gemini 增加了可配置维度，维度校验和 OpenAI 输入自动截断则避免了无效向量和 token 超限的 API 失败（#2328、#2329、#2368、#2523）。更换模型或维度会切换到隔离的向量命名空间，因此请把它当作一次迁移/重新嵌入的决策，而不是普通配置改动。
  • 缓存可迁移性与提示缓存 — 新增 KV 迁移工具和 LLM 查询缓存清理工具，可在存储后端之间转移缓存的抽取/摘要数据，并清除陈旧的查询命中（#2330、#2335）。切换后端前请先执行迁移；重构后的实体抽取提示词也提升了 OpenAI 提示缓存的复用率，降低重复抽取成本（#2426）。
  • 结构化文档抽取 — DOCX 摄入现在包含表格内容，XLSX 处理会保留制表符/换行并转义特殊字符（#2383、#2386），让结构化数据也能被检索。要享受这些改进需重新摄入已有文档；分块文本会变，嵌入自然也会变。
  • 安全与启动加固 — React 19.2.1 修复了 React Server Components 漏洞（#2494）。API 服务现在可以在没有构建好的 WebUI 资源时启动，并且配置改为惰性初始化（#2418、#2351）；上传不再被依赖安装阻塞（#2350），改善了无头与容器部署。

版本说明 V1.4.9.9

重要提示

  • 为管道状态和内存存储添加工作空间隔离：可以同时创建具有不同工作空间的多个 LightRAG 实例，这标志着在单个 LightRAG 服务器内实现无缝工作空间切换的重大进步。
  • 为 PostgreSQL 和 Qdrant 添加按模型名称和维度进行工作空间矢量数据隔离：之前，LightRAG 使用单个集合/表进行差异嵌入模型和维度，导致多工作空间中维度不匹配崩溃或数据污染。
  • OpenAI 和 Gemini 支持维度选择 引入了新环境变量的嵌入模型：EMBEDDING_SEND_DIM
  • 在不同的KV存储之间添加LLM缓存迁移和LLM查询缓存清理工具：使用户能够切换存储后端而不会丢失缓存的提取和摘要数据。
  • 增强型 DOCX 提取与表内容支持。
  • 通过正确处理单元格内的 tab 和 newline 字符来增强 XLSX 提取。 *修复React服务器组件中的关键安全漏洞：#2494
  • 为嵌入函数添加自动文本截断支持：OpenAI 嵌入函数现在尊重 EmbeddingFunc 中的 max_token_size 值，并自动截断输入文本以防止因文本超出模型令牌限制而导致 API 错误。

有何突破（仅适用于 LightRAG 核心集成）

  • 重命名分块函数的参数：如果将分块函数合并到LightRAG中并按名称传递参数，则需要更新相应的代码。
def chunking_by_token_size(
    tokenizer: Tokenizer,
    content: str,
    split_by_character: str | None = None,
    split_by_character_only: bool = False,
    chunk_overlap_token_size: int = 100,
    chunk_token_size: int = 1200,
) -> list[dict[str, Any]]:
  • 使用wrap_embedding_func_with_attrs将带有model_name的embedding_func注入LightRAG：
@wrap_embedding_func_with_attrs(
    embedding_dim=1536, max_token_size=8192, model_name="text-embedding-3-small"
)
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=4, max=60),
    retry=(
        retry_if_exception_type(RateLimitError)
        | retry_if_exception_type(APIConnectionError)
        | retry_if_exception_type(APITimeoutError)
    ),
)
async def embedding_func(texts: list[str]) -> np.ndarray:
    client = AzureOpenAI(
        api_key=AZURE_OPENAI_API_KEY,
        api_version=AZURE_EMBEDDING_API_VERSION,
        azure_endpoint=AZURE_OPENAI_ENDPOINT,
    )
    embedding = client.embeddings.create(model=AZURE_EMBEDDING_DEPLOYMENT, input=texts)

    embeddings = [item.embedding for item in embedding.data]
    return np.array(embeddings)

rag = LightRAG(
      working_dir=WORKING_DIR,
      llm_model_func=llm_model_func,
      embedding_func=embedding_func,
)

为了确保无缝过渡，注入没有 model_name 的 embedding_func 的遗留代码将继续与原始的无后缀向量表连接。
