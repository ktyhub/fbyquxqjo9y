LightRAG v1.5.5

变更流程图

亮点

  • DOCX 可选启用智能标题（Smart Heading） — 原生 DOCX 解析器新增 smart_heading 引擎参数（#3364），可在排版看着清晰但格式很差的文档中重建标题结构：恢复没有样式的章节标题、降级误判的标题（图注、日期、版本说明）、修复倒置/跳级/同级的层级、拆分合并的子文档，并压缩臃肿的目录。这直接改善 RAG 索引的 P 分块边界和标题↔正文关联——但它默认关闭，因此在你按 FileProcessingPipeline 文档启用之前，已有语料不受影响。
  • 大规模安全加固 — 多项安全公告落地：常量时间密码比较（GHSA-c759-cx9p-mrwq、#3423）、/login 限流（GHSA-frch-4w6v-q5xx、#3424）、聊天 Markdown 清洗以防存储型 XSS（GHSA-xpjq-3w4w-w5wr、#3437）、/health 的配置披露改为需认证（#3329）、对未认证且暴露在网络的服务发出警告（GHSA-mmg5-8x8q-v934、#3328）、移除 API 错误中的原始异常文本（CWE-209、#3422）、IPv6 过渡导致的 SSRF 绕过补丁（#3426）、Postgres _dollar_quote 加固（#3427）、任务 ID 路径注入防护（#3324），以及 Docker CVE 固定版本 + 非 root 镜像（#3330）。如果你暴露了 API 服务，这是优先升级项；未认证端点返回的信息会变少。
  • 流水线可靠性与资源治理 — 一组重构让长时间摄入更稳健：多进程键锁的死进程恢复（#3408、#3409、#3413、#3415、#3431）和取消安全的锁释放（#3407）、按工作区隔离的流水线入口（#3458–#3467）、共享存储状态的原子更新（#3417），以及流水线处理的常驻内存大小上限（#3481–#3489、#3497）。文档变更现在可通过预写锚点、日志化自定义分块和扫描回滚来恢复（#3416）。内存受限或多 worker 部署的运维人员受益最大。
  • 认证契约变化 — #3358 明确并强制要求 X-API-Key 与 Authorization 在每个请求中互斥（修复 #2632）。同时发送这两个请求头的客户端需要审查——其中一个会被忽略或拒绝。结合上面的 /health 门控，任何依赖未认证配置读取的集成都应视为必须迁移。
  • 会改变索引结果的正确性修复 — ainsert_custom_chunks 不再静默跳过知识图谱构建（#3394），并遵守流水线忙碌契约（#3401）；重新处理不再累积陈旧描述或边权重（#3395、#3399、#3398）。compute_args_hash 的缓存键冲突通过带长度前缀的编码被封堵（#3435），这意味着此前复用的部分缓存条目可能是错的。Token 窗口化现在会拒绝 chunk_overlap >= chunk_size（#3396），处在这个边界的配置会开始报错。被截断的 LLM 响应不再被缓存（#3446、#3448）。
  • 性能、遥测与清理 — 实体/关系 map-reduce 中描述只做一次分词（#3359），共享存储管理器在更新标记/命名空间/状态路径上的 RPC 被削减（#3434、#3436、#3439），JSON KV 快照使用 DictProxy.copy()（#3433）。Milvus/Qdrant（#3360）、Redis（#3370）和 AsyncOpenAI（#3371）客户端现在会在 finalize() 中正确关闭。WebUI 展示服务端查询延迟和首 token 延迟（#3387），以及实时的 m_lock/a_lock 计数（#3440）——有助于诊断锁重构所针对的争用问题。另提供面向本地部署的 Apple 容器编排方案（#3347）。 未正式声明破坏性变更；但请注意上面的认证请求头与 chunk_overlap 行为变化。

🎉 添加Word文档Smart Heading识别功能

从 v1.5.5 开始，LightRAG 的内置 DOCX 解析器引入了 智能标题 功能 - 即使对于格式不良的 DOCX 文档，也能实现更好的基于部分的分块。

许多 DOCX 文档具有视觉上清晰的章节结构，但缺乏正确配置的 Word 大纲级别，或者在编辑、复制和串联过程中保留不正确的标题样式。过去，这些问题可能会导致章节标题被视为正文，或常规文本被错误识别为标题，从而导致分块边界偏离文档的真实语义章节。对于依赖标题结构的 P 分块策略，这会产生碎片化的上下文或来自不同部分的混合内容，从而影响后续的索引和检索。

智能标题针对此类格式不佳但语义清晰的文档，尽可能恢复其真实的标题结构：

  1. 恢复丢失的章节标题：识别视觉上显示为标题但缺乏正确配置的大纲级别的内容，从而减少章节结构的丢失。
  2. 减少正文作为标题的误报：恢复常规正文、完整的子句、标题、日期和版本说明，这些错误地将标题样式带回正文，避免无意义的分块边界。
  3. 改善标题层次不一致：减少同级标题层次不一致、父子层次倒置、跳级等问题，使章节结构更加连贯。
  4. 区分合并文档中的多个内容：识别每条内容的主要标题和文档边界，防止不同文档之间的章节级干扰。
  5. 减少长目录带来的噪音：压缩过长的目录，最大限度地减少重复信息对索引和检索的干扰。

通过为后续分块提供更可靠的部分结构，智能标题有助于维护标题与其相应正文文本之间的语义关联，使分块结果更好地与文档的原始内容组织保持一致。

智能标题是 Native DOCX 解析器的一项可选功能，需要激活才能生效。有关启用和配置说明，请参阅：docs/FileProcessingPipeline / 中文版。
