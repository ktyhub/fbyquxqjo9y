LightRAG v1.1.2

修订 发布时间2025年1月16日 来源HKUDS/LightRAG 英文原文

LightRAG v1.1.2

变更流程图

亮点

  • MongoDB 16 MB 上限与 Neo4j 连接池调优（#581） — 超过 MongoDB 16 MB BSON 文档上限的文档不再会导致插入失败，这对索引大文件的用户很关键。同一个 PR 还新增了 NEO4J_MAX_CONNECTION_POOL_SIZE 环境变量，你终于可以按负载调整 Neo4j 并发度，而不必沿用那个会悄悄限制并行写入的默认值。
  • 多格式摄入与惰性依赖（#587，基于 #565） — 文档加载支持的格式更多了，依赖也改为按需解析而非一次性全部安装。这缩减了安装体积，避免拉入你用不到的重型解析器——但请确认你实际依赖的特定格式的可选依赖在运行时确实存在。
  • 旧版 Python 上的 Postgres 不再受阻（#589） — README 现在正确记录了 Postgres 用法，并修复了旧 Python 解释器上 Postgres 部署的一个错误（更新日志写作 “python version<12”，很可能是 <3.12，请核对你的锁定版本）。如果你曾为 Postgres 部署而压住解释器版本不变，这个版本解除了该限制。
  • 查询期关键词抽取可定制（#585） — 现在可以插入自定义函数，为用户查询单独做关键词抽取并使用独立提示词。这是检索调优上真正有价值的改进：查询侧的术语不再与文档侧提示词耦合，你可以按用户实际提问方式而非文档写法来定制抽取。
  • 流水线 + 缓存让插入更稳健（#590） — insert 方法新增流水线处理和缓存，让批量摄入更有韧性，也避免对重复内容做无用功。升级后值得重跑一次大型索引任务，确认吞吐和去重行为符合预期。 未报告破坏性变更。

发生了什么变化

  • 修复 mongoDB 文档 16MB 限制并为 Neo4j 添加操作系统环境 NEO4J_MAX_CONNECTION_POOL_SIZE by @jiabin2wang20230918 在 https://github.com/HKUDS/LightRAG/pull/581
  • 增强：多格式文档支持和动态依赖管理 #565 by @ParisNeo in https://github.com/HKUDS/LightRAG/pull/587
  • 丰富postgres使用的README.md，修复https://github.com/HKUDS/LightRAG/pull/589中@ShanGor在python版本<12上运行postgres的问题
  • 添加自定义功能，为用户查询单独提取关键字，并在 https://github.com/HKUDS/LightRAG/pull/585 中由 @gurjot-05 单独提示
  • 通过https://github.com/HKUDS/LightRAG/pull/590中的@jin38324通过管道处理和缓存机制增强插入方法的鲁棒性
