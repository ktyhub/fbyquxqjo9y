LightRAG v1.1.7

修订 发布时间2025年2月18日 来源HKUDS/LightRAG 英文原文

变更架构图

亮点

  • 向量存储选项更丰富 — Chroma 现在通过 local_path 支持磁盘上的 PersistentClient，本地部署不再需要单独跑一个 Chroma 服务（#772）。MongoDB 新增由 Atlas Vector Search 支撑的 MongoVectorDBStorage，同时提供基于 Motor 的异步 KV、图和文档状态实现（#781）；Atlas 用户应确认向量搜索可用，并配置 cosine_better_than_threshold。
  • 异步摄入改变了 API 语义 — 文本和文件上传会被送入后台流水线，批量文件并发处理（#791）。返回成功只表示”已接收”，不等于”已索引”，所以查询前请轮询文档状态。迁移要点：把 /documents/batch 换成 /documents/file_batch，不要期望 InsertResponse 里还有 document_count，文本数组改用新的 /documents/texts 端点（#798）。
  • 自定义系统提示词与 token 预算 — 所有检索模式下，query()/aquery() 都用 system_prompt= 取代了 prompt=；已有的自定义提示词调用必须更新（#806）。本地检索现在会把实体上下文按 token 预算截断，并可用 MAX_TOKEN_TEXT_CHUNK、MAX_TOKEN_ENTITY_DESC、MAX_TOKEN_RELATION_DESC 配置分块/实体/关系的上限（#797），这减少了超大提示词，但也可能改变检索到的上下文。
  • WebUI 大改版 — 新界面新增 API 标签页，修复组件路径和无效的 num_turns 处理，支持 Markdown 渲染，并展示流式错误（#792、#800、#816）。同时改进了 CORS 与流式响应头，方便浏览器和代理客户端（#785）；围绕旧 UI 构建的集成或自动化应重新验证。
  • Neo4j 可靠性修复 — 标签校验和更宽泛的错误处理，配合修正后的 get_edge() 属性结构、可配置超时、浮点超时解析以及 max_pool_size 修复（#780、#812、#805、#820）。Neo4j 部署应复查连接池/超时配置，并测试依赖边属性格式的下游代码。
  • 存储扩展契约更严格 — 存储基类现在强制要求实现抽象方法，并通过 get_docs_by_status() 统一文档状态查询；PostgreSQL、Oracle、TiDB 的数据库连接模块改为按需动态加载（#795、#833）。自定义后端必须实现规定的接口，混合存储部署应跑一遍启动冒烟测试。
