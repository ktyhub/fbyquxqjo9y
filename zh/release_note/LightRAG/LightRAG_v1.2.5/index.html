LightRAG v1.2.5

修订 发布时间2025年3月10日 来源HKUDS/LightRAG 英文原文

变更架构图

亮点

  • 图变更终于能跨后端持久化 — PR #990 补齐了缺失的存储方法，让实体/关系编辑在所有支持的数据库上都能生效；#1006（重命名实体时会在向量数据库中同步更新其关系，而不是留下孤立数据）、#1009（实体合并）和 #1018（更多编辑修复）进一步加固。这意味着从”以读为主的索引”转变为”可策展的索引”：你可以在线修正或合并实体而无需重建索引。需要注意的是向量存储的一致性——这正是陈旧关系 bug 的根源，批量编辑后请验证嵌入。
  • API 服务新增认证与缓存控制 — #1000 为 API 服务加入用户认证，#1025 新增 LLM 缓存控制的环境变量。如果你把 API 暴露到 localhost 之外，这个版本就该采用，但要规划凭据配置，别假设可直接替换；缓存开关也为你针对缓存 LLM 响应做确定性测试提供了一个抓手。
  • .env 解析方式变了——审查你的部署配置 — #995 改为从当前工作目录加载 .env，而不再从脚本所在目录加载。这是本版本最隐蔽的行为变化：服务管理器、定时任务以及 CWD 与安装路径不同的容器，可能静默丢失配置。请显式设置工作目录，或直接注入环境变量。
  • 查询调优与摄入选项 — #1003 为图查询新增最小度数过滤，让你能抑制弱连接节点、降低大图上的检索噪声。摄入方面，#989 新增摘要语言环境变量，#1011 加入 Docling 加载器，#1030 改进迭代抽取。注意 #994 的 EVO 语言配置已在 #1005 中被回退——不要基于它开发，改用 #989。
  • 值得为此升级的存储层修复 — #1036 重构了 Neo4j 实现并修复 Gunicorn 下的存储初始化（如果你跑多 worker，这条很关键），另有 PostgreSQL 标签/图读取（#1024）、Qdrant payload ID（#1027）、entities_section_list 逗号问题（#1021）的配套修复，以及任务/错误处理改进（#1002）。多 worker 的 Neo4j 部署是主要受益者。 未声明破坏性变更；#995 的 .env 路径变化是升级前需要验证的唯一行为变化。
