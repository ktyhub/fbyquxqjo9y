LightRAG v1.4.6

修订 发布时间2025年8月3日 来源HKUDS/LightRAG 英文原文

LightRAG v1.4.6

变更流程图

亮点

  • 更快的文档删除（#1904） — 删除现在使用实体/关系索引，而非遍历整张图，因此删除成本取决于被删文档的规模，而非整个语料库的大小。如果你做批量清理或频繁重新摄取不断变化的语料，这是头条改进——在大型知识图谱上延迟应显著降低。未记录迁移，但升级后值得针对一张已有的大图验证删除行为。

  • 宽容的抽取解析（#1897） — LLM 输出现在经过 json-repair，畸形的响应（尾随逗号、截断的对象、游离的散文）会被修复而非丢弃。好处是更少的静默抽取失败和重试循环；微妙之处是抽取结果可能变化——此前因解析错误而丢失的实体现在可能出现，这会在重新摄取时改变图内容。

  • JSON KV 的工作区隔离（#1899） — 基于 JSON 的 KV 键现在按工作区划分命名空间。共享同一存储后端的多租户/多工作区部署不再面临键冲突和跨工作区数据串漏的风险——如果你按工作区隔离客户，这是一项应优先处理的正确性修复。升级后请确认现有键解析到预期的命名空间。

  • OllamaServerInfos 移至 base（#1893） — 该类搬迁到 base 模块，整合了共享类型。从旧路径直接导入的代码需要更新导入路径；普通服务端用户不受影响，但这是最可能破坏下游代码的一行。

  • 优雅的服务器关闭（#1895） — 现在会妥善处理终止信号，排空进行中的工作并释放资源，而非在请求中途直接退出。这对容器/Kubernetes 滚动发布和自动扩缩容很重要——此前突然的 SIGTERM 意味着请求被丢弃或状态写到一半。

  • 破坏性变更 — 未声明；无需 schema 或配置迁移（上述导入路径调整是唯一需要注意之处）。

新消息

  • 壮举（性能）：通过 https://github.com/HKUDS/LightRAG/pull/1904 中 @danielaskdd 的实体/关系索引优化文档删除性能
  • 重构：通过 https://github.com/HKUDS/LightRAG/pull/1897 中的@danielaskdd 使用 json 修复库提高 JSON 解析可靠性

修复了什么

  • 修复：通过 https://github.com/HKUDS/LightRAG/pull/1899 中的 @danielaskdd 解决了 json KV 存储的工作区隔离问题
  • 修复：通过 https://github.com/HKUDS/LightRAG/pull/1893 中的 @danielaskdd 将 OllamaServerInfos 类移动到基础模块
  • 通过 @danielaskdd 在 https://github.com/HKUDS/LightRAG/pull/1895 中为 LightRAG 服务器添加优雅的关闭处理 完整 Changelog：https://github.com/HKUDS/LightRAG/compare/v1.4.5…v1.4.6
