LightRAG v1.4.16

修订 发布时间2026年5月7日 来源HKUDS/LightRAG 英文原文

变更流程图

亮点

  • OpenSearch PIT 搜索排序改动（破坏性） — PR #2991 把 PIT（point-in-time）搜索改为按版本感知的排序决胜规则；对于 OpenSearch < 3.3.0 的现有部署，这是硬性中断。部署 v1.4.16 之前请先把集群升到 3.3.0+——旧集群上分页检索查询会失败，而且本版本没有回退路径。请把它当作一次协同升级，而不是可直接替换的补丁。
  • 任务感知嵌入 — PR #2560 新增任务感知嵌入支持，让嵌入层按任务（例如查询 vs. 文档）采用不同处理方式，而不是把所有文本一视同仁地编码。这是检索质量特性，但有个迁移前提：只有在现有向量按任务感知方案重新嵌入/重建索引之后，收益才会体现——所以在生产语料上启用时请规划一次索引重建。
  • Voyage AI 嵌入成为一等支持 — PR #2484 显式加入 Voyage AI 嵌入支持，Voyage 的领域专用模型不再需要通过 OpenAI 兼容层转接。此前用该绕行方案的读者现在有了正式路径——请检查配置中的新提供方设置，并核对模型名是否与适配器期望一致。
  • 结构化输出抽取修复 — PR #2965 在存在 response_format 时，从 .parse() 调用中移除 stream 参数。实际效果是：实体/抽取调用现在可以兼容那些拒绝”流式 + JSON schema 响应格式”组合的 LLM 后端。注意反向情况——如果你此前刻意依赖流式结构化输出，这些调用现在会改为缓冲，因此尽管正确性提升，延迟行为会变化。
  • Podman 部署选项 — PR #2983 新增兼容 Podman 的 compose 文件，让你可以在无守护进程或隔离网络的主机上以 rootless 方式运行整套服务，无需改写上游 compose 文件。Docker 路径没有变化，只是扩大了支持的部署范围。
  • WebUI 更新 — 状态提示条被详情弹窗取代（#3025），eslint-plugin 升级带来的 react-hooks lint 错误已清理（#3036），前端依赖树做了大面积更新，其中 lucide-react（1.x）和 i18next（26.x）发生了大版本跳跃。这些都不影响检索行为，但如果你维护自定义 WebUI 翻译或覆盖，i18next 的大版本升级是必须回归测试的一项。
