LightRAG v1.5.8rc2

变更流程图

亮点

  • 查询失败不再返回空答案 — 失败的查询现在返回错误，而非误导性的”无上下文”结果（#4478），当关键词提取没有任何产出时 aquery_data 返回其失败形态（#4419）。纯推理的补全结果既不返回也不缓存（#4483），防止不可用响应进入缓存。请更新回退逻辑与监控，以区分检索失败和合法的空结果。

  • 提供商超时与重试更可预测 — LLM_TIMEOUT 现在触达每一个提供商客户端，包括按角色的配置，embedding/rerank 客户端也收到各自的超时设置（#4474、#4479）。非正数的超时值表示”无超时”（#4098），因此需要有限截止时间时请用正值。永久性的 Jina 与通用 rerank 4xx 错误停止重试（#4028、#4420），而畸形的 OpenAI 补全以及 Bedrock、LMDeploy、AGE 的瞬时失败会重试（#4279、#4447、#4458、#4212）。

  • 客户端所有权与异步行为更安全 — 调用方提供的 OpenAI HTTP 客户端不再被关闭，并保留其配置的默认 header（#4237、#4152），让自行管理客户端的应用可以安全地复用连接。内部创建的 Zhipu 客户端在调用后关闭（#4427），Qdrant 的向量 upsert 刷新移出事件循环（#4446），降低并发摄取时的延迟与阻塞。

  • 存储删除现在会显式报错 — Nano、MongoDB、PostgreSQL 和 OpenSearch 现在会传播队列、KV 和文档状态的删除失败，而非静默完成部分清理（#4424、#4167、#4432、#4169）。自定义删除与恢复工作流应捕获并重试这些异常。工作区清空现在会移除每个 embedding 模型的向量（#4263），取消的上传也会被清理（#4223），降低陈旧数据风险。

  • 文档摄取更好地保留 Unicode 与 OOXML 结构 — 修复了 UTF-8 BOM 污染，接受 UTF-16/UTF-32 BOM 文件，HTML/分块偏移保持 Unicode 安全（#4132、#4434、#4438、#4116）。DOCX 处理现在遵循 on/off 值与页眉重复，同时保留特殊文本节点、OMML 函数名和字面 Markdown 示例（#4430、#4433、#4239、#4259、#4204）；点开头的 bundle 文件与资源也可正常工作（#4219、#4440、#4291）。这些改动改善了抽取与引用溯源，DOCX 正文解析据报还快了 7.7%（#4298）。

  • 兼容性 — 未宣布破坏性变更；尽管如此，升级前请审查受 bcrypt 长度限制和密码（#4489）、无效的 rerank/分块设置（#4487、#4488）、超时语义以及异常处理。
