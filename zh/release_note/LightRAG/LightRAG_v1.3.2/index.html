LightRAG v1.3.2

修订 发布时间2025年4月17日 来源HKUDS/LightRAG 英文原文

变更流程图

亮点

  • 图存储查询性能 — 这个补丁的头条是延迟：Neo4j 操作改为用 UNWIND 批量执行（#1341），PostgreSQL AGE 查询也做了大修（#1383）。对于运行大型知识图谱的用户，这是影响最大的改动——重度图查询会明显变快；但两个后端的优化方式不同，请重新跑自己的基准，不要假设两者表现一致。
  • WebUI 中可编辑图实体 — 节点/边的名称和描述现在可以直接在 WebUI 中编辑（#1364），背后新增了 graph_db_lock 来保证多进程间编辑的一致性（#1367）。如果你用多个 worker 连同一个图数据库，正是这把锁避免编辑竞态——启用编辑前请确认你的部署确实用上了它。
  • 新的查询控制与流式能力 — 新增 bypass 查询模式（#1338）和用于 Ollama 模拟 LightRAG 服务的 /context 前缀（#1305），同时 WebUI 查询测试支持流式响应（#1331），#1332 修复了这些测试中的历史轮次问题。这些让你有更多方式探查原始检索行为，而不必改动生产环境的提示词配置。
  • LLM 缓存语义发生变化 — 新增环境变量 ENABLE_LLM_CACHE（#1318）、FORCE_LLM_SUMMARY_ON_MERGE（#1334）和 OPENAI_API_BASE（#1330），并修正了缓存行为：缓存现在覆盖节点/边合并（#1328），在 enable_llm_cache 关闭时能正确停止写入（#1377）。如果你此前见过陈旧的合并摘要或意外的缓存写入，本补丁改变了这一点——请重新检查依赖缓存的工作流。
  • 索引正确性与解析 — Gleaning 现在只合并新实体/边（#1337），分块处理失败会取消待处理任务，标签搜索支持字符串中间匹配（#1322），.docx 解析改用 python-docx（#1345）。这会改变重新索引时的抽取结果——去重行为变了，如果你依赖多次摄入后实体集合保持稳定，请验证输出。
  • 图后端与稳定性修复 — PostgreSQL AGE 现在能处理含反斜杠的内容（#1360），并修复了子查询缺少 FROM 别名的问题（#1375）；空值处理（#1315）和 global_args.timeout=None（#1333）也已修复。如果 AGE 摄入以前会被转义文本卡住，或因未设置超时而崩溃，这些文档值得重新跑一遍。 本版本无破坏性变更。
