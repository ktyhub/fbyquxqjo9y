LightRAG v1.4.13

修订 发布时间2026年4月2日 来源HKUDS/LightRAG 英文原文

LightRAG v1.4.13

变更流程图

亮点

  • 认证加固，但有个部署坑 — PR #2869 让服务在配置了 AUTH_ACCOUNTS 时拒绝使用默认 JWT 密钥启动。这是实实在在的行为变化：此前依赖回退密钥同时定义了账号的部署，现在会直接报错失败，所以请在升级之前生成并设置一个专用的 JWT 密钥——尽管没有声明破坏性变更，这实际上是一个必需的迁移步骤。
  • Memgraph 后端的 Cypher 注入已堵住 — PR #2849（@sebastiondev 的首次贡献）对 upsert_node 中的 entity_type 做了净化，消除了一个 CWE-89 注入点。如果你的摄入流水线接受的实体元数据并非完全可信，这一条值得优先处理。
  • 存储不再饿死事件循环 — PR #2847 在存储路径中加入协作式让出，避免长时间写入阻塞异步处理；PR #2855 则引入了 PostgreSQL 性能计时埋点。两者合起来，既提升了持续负载下的吞吐量，也让 PG 后端能看到每次操作的延迟——适合在调优前建立基线。
  • 所有后端统一状态 API — PR #2853 为所有存储后端加上 get_docs_by_statuses，并修复了 PostgreSQL 连接池和分页错误。此前手写状态过滤的代码可以收敛到一次调用；如果你遇到过连接耗尽或分页结果被截断，这个连接池修复尤其重要。
  • 上手更顺、配置升级更安全 — PR #2870 新增 make dev bootstrap 目标，让贡献者一条命令即可完成初始化；PR #2854 修复了 .env 重新生成的问题，确保你保留的变量在重跑初始化后不会丢失。这降低了新开发者的上手成本，也消除了定制化部署在升级时静默丢配置的一个隐蔽途径。
  • 不易察觉的知识图谱正确性修复 — PR #2857 补回了实体合并 upsert 时缺失的 file_path（保护来源溯源/引用），#2868 在 Memgraph 图查询中保留起始节点，#2872 处理了 Postgres 边查询中带引号的 AGE 实体 ID。这些都是静默的数据质量修复——如果你依赖图遍历或来源归因，尤其相关。 本版本未声明破坏性变更。
