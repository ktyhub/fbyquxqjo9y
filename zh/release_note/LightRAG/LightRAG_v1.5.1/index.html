LightRAG v1.5.1

修订 发布时间2026年6月9日 来源HKUDS/LightRAG 英文原文

LightRAG v1.5.1

变更流程图

亮点

  • 实体抽取提示词重写（#3231） — 默认抽取提示词现在只保留格式约束：少样本示例被移除，避免较弱的模型把示例里的实体/关系照抄进实际抽取结果。上游在 Qwen3-30B 上验证没有质量损失，但这只是单一模型的信号——升级前后最好自己 diff 一下抽取质量。ENTITY_TYPE_PROMPT_FILE 现在是提供自定义实体类型和示例文本的官方入口，过去依赖旧内置示例的团队应迁移到它，而不是去 fork 提示词。
  • 按章节感知的入库与检索（#3211、#3225、#3218、#3223、#3226、#3214、#3215） — 标题上下文现已贯穿整条流水线：切块时可把标题路径随查询送给 LLM，抽取提示词会带上章节面包屑，表格切分时会注入并冻结表头，表格/绘图/公式的 sidecar 会携带 parent_headings。这有助于消歧跨章节重复出现的实体，但新字段是在切分阶段生成的——想享受到好处，就得对现有语料重新建索引。父标题长度上限（#3226）刻意与抽取面包屑对齐，避免查询和抽取提示词的 token 预算不一致；P 策略切块器的修复（#3214、#3215）也属于同一轮一致性工作。
  • 可取消查询（#3227、#3230） — WebUI 新增 Stop 按钮，可中止进行中的查询；同时修复了双击 Send 反而取消而非提交查询的问题。对在按量计费的 LLM 端点上跑昂贵多跳检索的团队，这是直接的成本抓手：查询跑飞了可以直接掐掉，不必为后续每个流水线阶段继续付费。用自动化驱动 UI 的团队应重新测试快速连续提交，因为该行为是有意改过的。
  • 配置与依赖调整（#3209、#3194、#3208、#3229） — MAX_ASYNC 更名为 MAX_ASYNC_LLM 并保留别名回退，所以现有环境变量文件仍能工作——但把别名当兼容垫片看待，要有计划地迁移。Redis 约束放宽为 >=5.0.0,<9.0.0，Redis 8.x 进入支持范围；之前被钉在低版本的值得测一测。MinerU 的 MINERU_LOCAL_IMAGE_ANALYSIS 现在默认为 false（#3208），如果你依赖隐式启用本地图片分析，请显式设置。另外 RetrievalTesting 改名为 RetrievalView（#3229）：功能无变化，但按旧名称写的选择器、文档和运维手册会失效。
  • 存储与解析器正确性（#3206、#3210、#3219、#3221、#3222、#3224） — Postgres 表检查现在遵循配置的 search path；如果你按 schema 做租户隔离，这点很关键——以前的检测可能查错了 schema。非 ZIP 格式的 .docx 会给出准确报错；MinerU 现在保留 HTML 表格内容（含跨行跨列的表头），不再丢弃；多模态提示词会声明表格以 HTML 还是 JSON 形式传入，模型不用再猜。抽取侧则去掉了多模态关系描述里多余的 “in section unknown” 文本，降低生成图谱的噪声。
  • 破坏性变更 — 严格来说没有：API 和存储格式都没有破坏性改动，只有上面的配置和 UI 重命名需要逐一核查。

重要提示

为了防止较弱的法学硕士无意中将提示中的少样本示例合并到提取结果中，官方实体关系提取提示已在当前版本中更新，删除了少样本示例。对 Qwen3-30B 模型的实证评估表明提取质量没有下降。但是，建议用户仔细监控其特定法学硕士的表现，以确保结果一致。

要修改系统的默认行为，请通过 env var ENTITY_TYPE_PROMPT_FILE 提供实体类型和示例提示文本。
