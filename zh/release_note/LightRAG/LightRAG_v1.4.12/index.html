LightRAG v1.4.12

LightRAG v1.4.12

这个项目是干啥的：是一个轻量级的检索增强框架，让开发者用更低成本把文档变成能问答的知识库，并借助图结构提升回答质量。

变更架构图

亮点

  • 认证：支持 bcrypt 前缀哈希并修复登录流程 — PR #2813 新增对 bcrypt 前缀密码哈希的支持（如 $2a$/$2b$/$2y$），从基于 bcrypt 的系统导入的凭据现在可以直接校验通过，不必强制重置。PR #2821 修复了 loginToServer 请求的 content type 及缺失的 grant_type，这两个问题在严格遵循标准的认证端点上会导致令牌签发失败；如果此前在代理或新服务器配置下登录失败，请重新测试。
  • pgvector 更快、容量更大 — Upsert 现在每次批量写入 200 条，减少批量摄入时的往返次数；PR #2663 让 Postgres 后端可以用 HALFVEC（float16）为向量建索引，索引内存大约减半，同时抬高了高维模型的维度上限。如果过去大向量受限于内存或 HNSW 维度上限，这就是对应的修复——但需要重建索引才能生效。
  • 仅权限加密的 PDF 终于能摄入了 — PR #2827（外加一个热修复）可以处理只设置了所有者限制、没有用户密码的加密 PDF，受保护文档在摄入时不再打不开。此前因”已加密”被跳过的文档现在可以进入流水线。
  • 删除与取消操作可安全重试 — PR #2826 让文档删除在重试下具备幂等性，避免瞬时故障后留下孤立或部分状态。配套热修复还阻止了被取消的流水线把文件重新标记为 unknown_source，中断的任务不再污染来源元数据。现在重跑失败的摄入和删除是安全的。
  • 几项小改进：清洗速度与 Mongo 可观测性 — PR #2814 加快了 utils.py 中的文本清洗，降低摄入开销；PR #2834 在 AsyncMongoClient 实例化时附带驱动信息，改善 APM/监控中的连接归因。都是低风险、可直接替换的改动。 无破坏性变更——完全向后兼容，无需迁移步骤。

热修复

  • 通过将批处理大小增加到每个操作 200 条记录来优化 Postgres Vector DB 更新插入性能。
  • 解决了打开受仅限权限限制保护的 PDF 文件的问题
  • 修复了管道取消导致文件名错误更改为“unknown_source”的问题

发生了什么变化

  • feat(auth)：在 https://github.com/HKUDS/LightRAG/pull/2813 中添加 @danielaskdd 的 bcrypt 前缀密码哈希支持
  • ⚡ Bolt：通过 https://github.com/HKUDS/LightRAG/pull/2814 中的 @danielaskdd 优化 utils.py 中的文本清理
  • 修复 https://github.com/HKUDS/LightRAG/pull/2821 中 @danielaskdd 的 loginToServer 内容类型和缺少 grant_type
  • Postgress/pgvector 后端现在允许在 https://github.com/HKUDS/LightRAG/pull/2663 中使用 @Daggle24 的 HALFVEC 索引大型嵌入
  • 修复：通过 @danielaskdd 在 https://github.com/HKUDS/LightRAG/pull/2826 中使文档删除重试安全
  • 修复（pdf）：通过 @danielaskdd 在 https://github.com/HKUDS/LightRAG/pull/2827 中处理无密码的仅许可加密 PDF
  • 将驱动程序信息添加到 @alexbevi 在 https://github.com/HKUDS/LightRAG/pull/2834 中的 AsyncMongoClient 实例化中
