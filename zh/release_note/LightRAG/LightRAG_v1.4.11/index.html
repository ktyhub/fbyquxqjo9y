LightRAG v1.4.11

修订 发布时间2026年3月20日 来源HKUDS/LightRAG 英文原文

变更流程图

亮点

  • 统一的 OpenSearch 后端 — OpenSearch 现在支持全部四种 LightRAG 存储类型：KV、向量、图和文档状态（#2739），另外还有 LLM 缓存 KV 存储（#2790）和向导配置（#2797）。部署方可以把多套存储系统收敛为单一运维栈。
  • 引导式部署与配置 — 交互式初始化向导和 Docker Compose 支持可以拉起本地嵌入、重排和存储服务，模块化的 Makefile 目标也简化了部署（#2548、#2763）。打算告别手改 .env 的团队应通过向导重新生成配置，而不是盲目照搬已有值。
  • 摄入更可靠、更快 — Qdrant 现在限制批量大小以避免大型 upsert 的载荷失败（#2740），PostgreSQL KV upsert 改用 executemany（#2742），OpenSearch 去掉了 refresh="wait_for"（#2786）。大型导入会更稳健、延迟更低；但 OpenSearch 的写入可能要等索引刷新间隔之后才可搜索，而不是立即生效。
  • 查询延迟降低 — 查询嵌入改为批量预计算，不再串行调用 API 获取（#2729），知识子图 BFS 也用上了 deque（#2725）。多查询负载的嵌入往返更少，大型图遍历则避免了队列头部移除的线性耗时。
  • 文档清理与元数据处理改进 — 失败文档的分块元数据会被保留以便可靠删除（#2749），缺失的文件路径不再以 unknown_source 传播（#2793、#2796），Faiss 的 meta.json 也不再重复存储向量（#2733）。直接从 meta.json 读取向量的自定义工具应改为查询向量存储。
  • 兼容性 — 未列出破坏性变更。

重要提示

  • 集成 OpenSearch 作为统一存储后端，为所有四种 LightRAG 存储类型：KV、Vector、Graph 和 DocStatus 提供全面支持。
  • 引入了交互式设置向导来简化配置，取代手动 .env 文件编辑。现在可以支持通过 Docker Compose 本地部署嵌入、重新排名和存储后端。欲了解更多详情，请参阅交互式设置指南。
