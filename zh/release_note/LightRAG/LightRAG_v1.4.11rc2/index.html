LightRAG v1.4.11rc2

修订 发布时间2026年3月13日 来源HKUDS/LightRAG 英文原文

变更流程图

亮点

  • 模块化部署流程 — 新的 Makefile 把初始化拆成 env-base、storage、server 三个目标，比原先一整块向导更易于复用和自动化。用法见 docs/InteractiveSetup.md（#2548、#2763）。
  • Qdrant 批量摄入更可靠 — 有界批处理把大型 upsert 拆成更小的请求，减少批量索引时因载荷过大导致的失败及相应重试（#2740）。
  • 图检索延迟降低 — get_knowledge_subgraph() 现在用 deque 做 BFS，查询嵌入改为批量预计算，消除了多查询负载下串行的嵌入 API 往返（#2725、#2729）。
  • 存储更轻、更可配置 — FAISS 的 meta.json 不再序列化向量，减小了元数据文件和相关 I/O；Milvus 存储现在支持参数化配置，便于按部署场景调优（#2733、#2672）。
  • 摄入失败后的恢复更干净 — 保留失败文档的分块元数据，使删除清理能可靠移除关联分块，减少处理失败后的孤立数据（#2749）。
  • 破坏性变更 — 本版本未列出。

新消息

  • 添加 Makefile 以通过 @mlimarenko 在 https://github.com/HKUDS/LightRAG/pull/2548 中快速部署
  • 重构（Makefile）：通过 https://github.com/HKUDS/LightRAG/pull/2763 中的 @danielaskdd 将整体向导拆分为模块化环境库/存储/服务器目标

设置向导的详细信息请参考：InteractiveSetup.md

发生了什么变化

  • 通过 @danielaskdd 在 https://github.com/HKUDS/LightRAG/pull/2740 中进行有限批处理修复 Qdrant 大型更新插入有效负载失败
  • perf: 在 https://github.com/HKUDS/LightRAG/pull/2725 中 @giulio-leone 的 get_knowledge_subgraph() 中使用 deque 作为 BFS 队列
  • perf：批处理预计算查询嵌入，以消除 @errajibadr 在 https://github.com/HKUDS/LightRAG/pull/2729 中的顺序 API 往返
  • 修复：通过排除 https://github.com/HKUDS/LightRAG/pull/2733 中 @Br1an67 的向量来减少 FaissVectorDBStorage meta.json 文件大小
  • 通过 @hanlianlu 在 https://github.com/HKUDS/LightRAG/pull/2672 中的参数化配置增强当前 MilvusVectorDBStorage
  • 修复：保留失败的文档块元数据，以便 https://github.com/HKUDS/LightRAG/pull/2749 中的 @danielaskdd 进行可靠的删除清理
  • 构建（deps-dev）：通过 https://github.com/HKUDS/LightRAG/pull/2750 中的 @dependabot[bot] 进行 2 次更新，在 /lightrag_webui 中碰撞 ui 组件组
  • build(deps)：通过 https://github.com/HKUDS/LightRAG/pull/2751 中的 @dependabot[bot] 进行 3 次更新，在 /lightrag_webui 中碰撞前端次要补丁组
  • build(deps)：通过 @dependabot[bot] 在 https://github.com/HKUDS/LightRAG/pull/2759 中进行 4 次更新来提升 github-actions 组
