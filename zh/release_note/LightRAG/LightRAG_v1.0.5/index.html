LightRAG v1.0.5

修订 发布时间2024年12月9日 来源HKUDS/LightRAG 英文原文

变更架构图

亮点

  • 查询期嵌入缓存与缓存机制大改 — 这是 v1.0.5 的标志性改动：嵌入现在会在查询时缓存（PR #406），而不再仅限于摄入阶段，减少每次检索重复的嵌入调用及其 API 成本。PR #412 整体重构了缓存逻辑，PR #421 又加入了嵌入相似度缓存和基于 LLM 的相似度检查——实际上形成了一层语义复用机制，可以用缓存响应改写过的查询，而不再只匹配完全相同的请求。开发者应把缓存结果视为”新计算出来的”：升级后计划让已有缓存失效或重建，因为键的语义和命中行为都变了。
  • 缓存嵌入的 args_hash 正确性恢复 — PR #408 修复了启用嵌入缓存时 args_hash 从不计算的问题，原因是它只在常规缓存路径上计算。这是新查询缓存的正确性前提：没有由配置派生的哈希，不同的嵌入设置可能在缓存条目上冲突或漏命中。在生产环境启用查询缓存前请先升级，否则可能返回用不同参数算出来的结果。
  • 流式输出成为一等能力 — PR #407 新增 Ollama 流式输出及 Open-WebUI 聊天演示；PR #417 加入兼容 OpenAI 的流式输出并删除不可达代码；PR #430 提供独立的 Ollama API 服务演示。对采用者来说，这意味着两套 LLM 后端都能开箱即用地逐 token 返回，并附可运行的参考示例，方便把 LightRAG 接入聊天 UI，而不必自己搭流式管道。
  • 新嵌入后端：Jina — PR #423 新增 Jina 嵌入支持，在现有 OpenAI/Ollama 路径之外扩展了可插拔选项。如果你的技术栈里已有 Jina，可以直接把 LightRAG 指向它而无需自定义包装；结合缓存方面的工作，现在也是重新评估嵌入成本与延迟的好时机。
  • 会在 API 行为上体现的正确性修复 — 有几项修复影响的是使用者，不只是内部：PR #435 修复响应中的 Unicode 转义（如 "/utils"，如果你解析输出文本就很相关），PR #429 解决意外的 keyword_extraction kwargs 错误，PR #432 把 _closed 换成 is_closed() 以正确判断异步客户端生命周期，PR #415 在 _handle_entity_relation_summary 中把 entity_or_relation_name 强制转为字符串以避免类型错误。PR #434 调整了关键词抽取提示词，#428 关闭了 issue #306。图谱 UI 还新增了节点和边的悬浮提示（#424）——虽小，但对调试时查看知识图谱很有用。
  • 无破坏性变更。
