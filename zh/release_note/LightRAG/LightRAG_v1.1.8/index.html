LightRAG v1.1.8

LightRAG v1.1.8

这个项目是干啥的：是一个轻量级的检索增强框架，让开发者用更低成本把文档变成能问答的知识库，并借助图结构提升回答质量。

变更架构图

亮点

  • 存储与连接生命周期大改 — PR #846 重构了 LightRAG 打开、池化和关闭数据库连接的方式。这是对采用者影响最大的改动：初始化/关闭顺序可能与 v1.1.7 不同，凡是有自定义存储后端或长驻服务的，在生产环境依赖之前，请重新验证 finalize()/清理路径和连接复用。
  • 修复全新安装与服务端启动 — PR #842 和 #848 修复了服务端启动路径以及一处遗漏的安装依赖。如果 v1.1.7 起不来自带服务、或在干净环境里直接崩，这个版本应该能解决——建议重建钉死的容器/CI 镜像，别假定旧镜像还能用。
  • ainset_custom_kg() 恢复可用 — PR #811 修复了此前坏掉的异步自定义知识图谱插入 API（实际名字是 ainsert_custom_kg()）。以前通过程序化方式而非文档入库来写入实体和关系的团队，终于可以用异步路径了；把当初为绕过这个坏调用而写的 workaround 清一遍。
  • Office 文档索引修复 — PR #844 修复了 Office 格式文件的入库，这是”为什么我的文档没进图谱”这类反馈的常见源头。如果你索引 .docx/.pptx 这类源文件，请重新跑一遍——v1.1.7 建出来的索引可能是不完整的，而且悄无声息。
  • PostgreSQL / AGE 后端加固 — PR #867 改进了 PostgreSQL 执行路径，#869 和 #870 调整了图扩展（AGE）的回退行为，随后还有一个跟进提交。如果你跑 Postgres + AGE 图后端，留意回退的处理方式——连续改动说明这块还在稳定过程中。
  • 更干净的类型标注与文档 — PR #847 整理了类型标注，对库使用者的 IDE 和静态分析体验是改善，文档也在 #856/#857 中同步更新。运行时风险低，但如果你之前钉了 type: ignore 注释，可能会冒出类型检查错误。

v1.1.8 未宣布破坏性变更。
