lettuce 6.9.0.RELEASE

这个项目是干啥的：Java 生态里常用的 Redis 客户端，基于 Netty 做成线程安全，同步、异步、响应式调用都支持，给需要在 Java 程序里操作 Redis 的后端开发用。

变更架构图

亮点

  • 断连时快速失败拒绝（破坏性） — 使用 DisconnectedBehavior.REJECT_COMMANDS，或 DisconnectedBehavior.DEFAULT 且关闭自动重连时，Redis Cluster 命令在目标节点连接仍在建立时（启动后的首批命令、新的 slot 映射、MOVED/ASK 重定向）现在立即失败，而不是等到连接超时；所有连接类型下，channel 写入失败的命令现在被拒绝，而不是静默重新入队。此前依赖 Lettuce 缓冲这些命令的应用会看到异常大幅提前暴露。
  • 迁移：预先连接集群节点 — 要避免新的启动期拒绝，应显式预连接集群节点，而不是依赖惰性建连；这正是 #3747（@Vaibhav026 对 #3782 的回溯）交付的修复。如果代码在启动后立即发命令，或在新 slot 映射上发命令，必须调整初始化或处理失败。
  • 版本范围很重要 — 此行为也进入 7.7.0 及之后，但 7.0.x–7.6.x 线不包含。从这些线迁到 7.7.0+ 同样引入该变化，那边也要当作行为迁移处理。
  • 值得升级吗？ — 在 6.8.x 上且想要修正后的快速失败语义，或计划迁到 7.7.0+ 并希望各版本行为一致的话就升。如果用 DisconnectedBehavior.DEFAULT 的自动重连、很少遇到断连/集群重连，或停留在 7.0.x–7.6.x，可以跳过。这是真实的行为变更版本（Redis 2.6+–8.2、Java 8–21），不是只改元数据的重发 tag。

Lettuce 团队很高兴地宣布 Lettuce 6.9.0 发布！ 此版本更改了连接不可用时拒绝命令的方式。阅读行为改变 在升级之前，请先阅读以下内容。

Lettuce 6 支持 Redis 2.6+ 至 Redis 8.2。在Java运行时方面，Lettuce需要 至少支持 Java 8 并适用于 Java 21。

感谢所有使 Lettuce 6.9.0 成为可能的贡献者。

行为改变

这适用于命令在断开连接时被拒绝的情况：使用 DisconnectedBehavior.REJECT_COMMANDS 或使用 DisconnectedBehavior.DEFAULT 和自动重新连接已禁用。

  • Redis 集群：当与目标节点的连接仍在进行时，命令现在会立即失败 已建立，例如启动后或出现新插槽映射后向节点发出的第一个命令。这个 也适用于使用 MOVED/ASK 重定向的命令。之前，这些命令等待连接 尝试，直到连接超时。
  • 所有连接类型：当向通道写入命令失败时，该命令现在被拒绝而不是 正在重新排队。

为了避免启动后立即被拒绝，请预先连接到集群节点。

7.7.0 及更高版本中也有此更改。 7.0.x – 7.6.x 系列不包括它。

修复

  • DisconnectedBehavior.REJECT_COMMANDS 对于等待 https://github.com/redis/lettuce/issues/3747 中惰性节点连接建立的 Redis 集群命令不会快速失败（@Vaibhav026 向后移植 https://github.com/redis/lettuce/pull/3782）
