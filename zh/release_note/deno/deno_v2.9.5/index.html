deno v2.9.5

deno v2.9.5

变更流程图

亮点

  • 实验性 QuickJS 后端 — 新增可选启用的 JS 引擎（#36194），与 V8 并存。它仍是实验特性，属于”尝鲜”而非默认切换，但表明 Deno 正在探索引擎选择；暂勿用于生产负载。

  • 新的 CLI 与 Web API — deno add --unscoped 可用无作用域名称为 JSR 包设置别名（#36319），deno task --members 只在选定的工作区成员中运行任务（#35748，对 monorepo 很有用），Blob/Body 新增 textStream()（#35616）用于流式消费文本。这些都是低风险新增，可以放心立即开始使用。

  • 需要迁移的权限变更 — node:dns.getServers() 现在需要 --allow-sys（#35941）。这是唯一行为破坏性变更：在更严格权限集下调用它的代码会失败，直到你授予 --allow-sys。依赖此前隐式访问的调用方应在升级前审查并更新权限。未列出其他明确破坏性变更。

  • Node.js 兼容性与稳定性 — 大批修复缩小了 Node 差距：node:test 标签（#36292）、util.diff（#36289）、v8.promiseHooks（#36281）、fs 写入的 flush 选项（#36290）、fs.readdir 排序（#36341），外加 Web Streams 背压/重入以及多个 http2 和 TLS panic 修复（#36321、#35867、#36230）。如果你在 Deno 上运行面向 Node 的代码或框架，这是升级的最强理由。

  • 性能与升级对象 — 多项启动优化（有序的发布启动函数、减少预急切模块求值、Rust 中处理常见路径的 tick drain、去掉 Linux unwind 表），加上阻塞池上的异步 readFile/writeFile 和 SIMD base64url（#36219、#36331、#36157、#36265、#36160、#36398）。Node 兼容用户、monorepo/工作区用户以及对冷启动或 I/O 敏感的人值得升级；如果负载稳定且未触及 getServers 权限变更，可以跳过。这是一次实质性补丁，不是重新打标签或纯元数据发布。
