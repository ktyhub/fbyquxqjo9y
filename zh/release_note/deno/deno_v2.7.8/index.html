deno v2.7.8

deno v2.7.8

变更流程图

亮点

  • Node.js 兼容性 — 本版新增 process.threadCpuUsage()、node_api_create_object_with_named_properties 和 N-API 9 支持，并修复了 Buffer.concat() 对大于 4GB 缓冲区的损坏、fs.cp() 跨权限边界、child_process 中数字 FD/IPC 处理、node:domain 跨异步边界行为，以及 TTY 之外的 readline.createInterface()。依赖这些 API 的应用应升级，尤其是在处理大缓冲区或多 GB 数据时。

  • 调试与密码学 — 新的 NodeRuntime CDP 域修复了 --inspect-brk 阻塞，让独立 node 调试更可靠。ext/crypto 新增 P-521 签名/验证/ECDH 派生，对密码学密集型负载是实质性升级；其他修复改善了 executionContextDestroyed 投递和拆卸行为。

  • 包管理 — 全局安装现在使用 JSR 包的锁文件，deno update 与 deno outdated 能正确解析 --frozen，npm 全局安装会为每个 bin 条目创建 shim，审计检查会遵循 package.json 覆盖。approve-scripts 在禁用锁文件时也能工作，解析修复改进了 BYONM 版本匹配和 file:/link: 依赖处理。使用全局工具、JSR 安装或严格锁文件流程的团队应升级。

  • 运行时与工具链修复 — 值得注意的改动包括 AbortSignal.any() 内存泄漏、HTTP/TLS 连接生命周期与升级泄漏、accept 饥饿、Windows 交互式选择器方向键、Temporal 类型输出和组件表达式格式化的修复。这些主要影响受相应 bug 困扰的用户；否则这是一次扎实的维护发布，但并非人人必升。

  • 破坏性变更 / 迁移 — 未列出明确破坏性变更或必需迁移步骤。本版不是纯元数据或重新打标签，但未被上述 bug 或新增 API 影响的用户可以合理跳过。
