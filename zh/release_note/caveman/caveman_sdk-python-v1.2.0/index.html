caveman sdk-python-v1.2.0

发布 发布时间2026年9月30日 来源JuliusBrussee/caveman 英文原文

caveman sdk-python-v1.2.0

  • **突破（许可证）：**从 MIT 重新授权给 Apache-2.0 以及其余的 Caveman 3.0.0 中的存储库。在此之前的版本保留 MIT 许可证。
  • 只等待另一个呼叫的共享功能获取的呼叫者不再获取 在断路器中记录其故障：冷启动时拒绝连接为一 失败，每个服务员都没有一次。中断的半开探头没有记录任何内容 并释放探针槽。新CircuitBreaker.release()。
  • observe()/observe_background()规范收货范围，如TypeScript 这样做，并删除范围无效的收据。异步observe()有自己的 收据工作人员（一名工作人员，十六人排队），因此收据永远不会占用优化的 插槽。
  • 运行时令牌被去除周围的空白（已安装的秘密文件的 尾随换行符）；带有可打印 ASCII 之外的任何其他字符的标记 每次通话时都是 invalid_configuration 而不是 runtime_unavailable。
  • https:// 或 socks 代理 URL 为 invalid_configuration； ready() 和 preflight() 命名不受支持的方案。 MiddlewareError可选配 细节。
  • endpoint 是运行时原点 (scheme://host[:port])，如 TypeScript， 当端点被拒绝时，""；它从不回显用户信息。
  • delete_session() 验证响应，如 TypeScript：schema_version 必须为 1，originals_deleted 仅对于文字 true 为 true，并且 deleted 仅出现四个安全非负整数计数。
  • 恢复绑定仅传递 handle/offset/limit/query retrieve()；非对象参数或缺少句柄引发 MiddlewareError("invalid_request")，适配器变成工具错误。
  • 协程接收器（on_report、on_decision、on_diagnostic）在 调用者的事件循环而不是泄漏“从未等待”的警告；他们的 失败永远不会接到电话。
  • version_unverified 警告一次行显示“Caveman 中间件正在运行” 未经验证的框架版本`，因为该调用仍在继续。
  • 传输限制整个交换（连接、代理隧道、TLS、标头 和正文）在截止日期之前，并且从不重用服务器关闭的连接 空闲时。
  • aclose() 永远不会阻塞被卡住的工人。
  • 第一个功能获取是单次飞行。不可用的功能视图 刷新一次。服务器公布的截止日期是有上限的。
  • JSON 被严格解析（无 NaN；整数值浮点数变为整数），并且 端点解析更加严格。
  • 警告一次规则，决策事件的runtime_build和adapter_error 对于不可序列化的清单，现在匹配 TypeScript。
  • 新的 unsupported_provider 和 unsupported_request 原因代码。
  • 出口商：成本也以 caveman.usage.cost_usd 形式发出。
  • 警告一次行现在显示“穴居人中间件通过内容传递” 不变：adapter=…reason=…，与TypeScript相同。日志过滤器 匹配旧的 Caveman middleware decision:` 前缀需要更新。
  • 严格的 ready()/preflight() 现在报告第一个 decline()。
  • decline() 接受任何目录原因和可选适配器 ID， 警告一次行名称。它永远不会在严格模式下引发。
  • Python地板从3.13降低至3.11。
  • caveman_cloud.middleware实现中间件协议1.1并且稳定： 它遵循 semver，因为 caveman-middleware 1.0 依赖于它。请求携带Caveman-Middleware-Features， Caveman-Middleware-Client，并且当配置 tracer 时，SDK 自己的跨度为 traceparent/tracestate （绝不是应用程序的环境上下文，如 TypeScript 中）。
  • 容错解析能力，单次飞行缓存300秒 刷新。新的政策修订或转换版本不再拒绝计划。
  • 仅带有恢复标记和手柄的 exact_ccr 替换件 应用较短的 UTF-8 字节。 recovery: "none" 从未应用，这 关闭文本注入路径。
  • 新断路器：连续 5 次故障或 20 次故障中的 10 次后断开，保持不变 打开 30 秒，然后允许一个探头。截止日期很重要；本地错误和 4xx 错误则不然。 格式错误的 Unicode 报告为 unsupported_shape。 Retry-After荣获殊荣。
  • 默认期限来自功能（第一次获取之前 500 毫秒）。 Retrieve 有自己的 5 秒截止日期和自己的池。
  • 异步调用即使在排队时也会遵守其截止日期。泳池重建后 fork()。 aclose() 将飞行中呼叫解析为 closed，而不是引发 CancelledError。
  • 运输：保活重复使用； DNS、连接和 TLS 在截止日期内； HTTPS_PROXY/HTTP_PROXY/NO_PROXY； ssl_context；可插拔 transport； 端点路径前缀； allow_insecure_transport; max_concurrency。
  • 每个候选人的预算取代了 256 名候选人或 4096 名候选人的整个呼叫旁路 清单项目。
  • 构建时不再出现端点问题。 recovery() 返回 None 对于无效范围。范围被标准化，因此电子邮件和空格被散列。 delete_session() 返回结果。
  • 新功能：对 caveman.middleware、on_decision 事件进行一次警告记录 （包括 no_candidate），选择加入 OTel tracer/meter 和 as_sync()， ensure_sync()、ensure_async()。
  • 凭证不受 vars()、repr() 和酸洗的影响。
  • OTelExporter.record_span(cache_creation_tokens=) 发射 gen_ai.usage.cache_creation.input_tokens。 gen_ai.usage.cost_usd 是 已弃用；它一直保留到 1.x。
  • 发布流程：每个版本都会获得一个 GitHub 版本，其中包含这些说明和 CycloneDX 其依赖图的 SBOM。
