caveman v4.1.0

Caveman 4.1.0 是一个维护版本：修复了压缩、OpenCode、Hermes、Pi、代理和挂钩的错误，不再填满并停止压缩的恢复存储，以及人们要求的一些小开关。 Caveman-compress 现在拒绝包含密钥或令牌的文件，并再次从技能中心安装。

需要采取行动

  • providers.<name> 块下的 forward_headers 现在会阻止代理启动。 之前，它被默默地忽略：没有标头被转发，唯一的症状是上游 401。将上游配置为兼容安装：compat.<name> 与 base_url 和 forward_headers，加上 wire_dialect: anthropic（如果它使用 Anthropic 协议）（请参阅 docs/technical/configuration.md）（＃1458）。
  • caveman-compress 拒绝文本包含凭证的文件，例如私钥块或云、Git 主机或模型 API 令牌。压缩将文件发送到您的模型提供程序，因此首先将机密移至环境变量或机密管理器中。错误命名了该行，而不是秘密。像 sk-... 或 $OPENAI_API_KEY 这样的占位符仍然会压缩（#1471）。

已更改

  • 旧的恢复句柄现在可能会过期。 恢复存储用于永久保留每个压缩的原始文件，因此它已满并停止压缩（＃1370）。当写入超出存储上限时，它现在会释放空间：空闲 14 天（存档）或 30 天（任何）的会话的类型化对象将过期，最旧的在前，直到存储达到 80%。检索过期的句柄会回答 cave_expired_recovery，并且每次过期都会记录在 proxy.log 中。 Blob 恢复永不过期 (#1481)。

新

  • caveman-proxy recovery-store status|check|repair 适用于损坏的 ccr.db。损坏的存储现在拒绝写入，而不是在升级过程中保持损坏；阅读继续工作。修复仅复制字节仍与其哈希匹配的行，并将损坏的文件移到一边而不受影响。 caveman status 和 caveman doctor 指向它（#1369，#1481）。
  • 使用 CAVEMAN_REINFORCE=0 或 ~/.config/caveman/config.json 中的 "reinforce": false 或存储库的 .caveman.json 关闭每次提示提醒。完整的规则集仍然在会话开始时发送（#1468）。
  • --hook-node node 使安装的钩子在运行时通过 PATH 找到 Node，而不是固定安装时路径，对于切换 Node 版本的人来说 (#1452)。默认值保持不变，因为在终端外部启动的应用程序看不到 shell 的 PATH。
  • 当 Node 不存在时，安装程​​序会回退到 Bun。 Node 保持在第一位（#570，#1344 by @cyrus-za）。
  • caveman learn 扫描 Pi 会话，并尊重 PI_CODING_AGENT_DIR / PI_CODING_AGENT_SESSION_DIR （#1317 by @tranducquy0）。
  • caveman mem 可以将内存恢复到较早的值，而 supersede --stdin 的替换对于命令行来说太大（#1386 by @PARTHDESHMUKH2005）。 ZZPH100​​ZZent 首先检查安装的二进制文件是否支持 --stdin，因此较旧的二进制文件无法再将文字文本 --stdin 存储为事实。

已修复

穴居人压缩

  • Hermes 的技能中心以 --force 无法覆盖的危险判决阻止了安装。每个发现都是错误匹配，并且匹配的文本会以相同的行为重新拼写 (#1464)。
  • 备份以文件的完整路径为关键，因此两个项目的 CLAUDE.md 不再共享一个备份插槽。在写入之前终止的运行会删除其备份和暂存文件，因此下一次运行不会中止。
  • 验证现在拒绝在正文后附加评论（#1433）。提示保留带有指令的动词（#1434）。 Frontmatter 在两个通道上都保持本地化（#1359 by @leninworld）。 URL 和路径上的尾随标点符号不再导致验证失败（#1356 by @Pharex38）。凭证点文件和裸点文件（例如 .env）会按名称被拒绝（#1357 by @Pharex38，#1363）。 开放代码
  • OpenCode 2：为安装的专业实际加载的 API 生成收缩插件（#1445）。 OPENCODE_CONFIG_DIR 到处都受到尊重 (#1441)。已删除的会话将被执行（#1444），并且主机的项目目录将被传递（#1443）。
  • 安装程序已安装的探针可以正确读取 JSONC settings.json，并且该插件支持存储库 defaultMode: "off"（#1430、#1431 by @Quinnod345）。 爱马仕
  • caveman enable hermes 写入仍然解析的 YAML (#1405)。它按值读取所有权，因此重新格式化的配置仍保留所有权（#1410）。它向 plugins.enabled / plugins.disabled 会员资格致敬（@Ha1baraA11 的#1442、#1446）。 Pi (@caveman-ai/pi 0.3.2)
  • 每个提示上下文作为消息发送，因此提供程序的提示缓存在每个提示中都存在（#1364，#1376 by @worldofgeese）。
  • 4 KB 以下的工具输出不再被检索句柄替换（@danieldutu 的#1365、#1378）。现在带有查询的 caveman_retrieve 表示它返回摘录（@danieldutu 的#1368、#1377）。
  • Pi 的虚拟 router/auto 模型不再警告它无法路由 (#1449)。兼容路由针对没有 /v1 的 OpenAI 基本 URL 进行验证（#1325 by @szsunyuan）。 代理、统计数据和成本
  • 克劳德代码请求声明顾问工具再次定价，而不是每个请求都显示“未知”成本（#1465）。流式人择响应从正确的位置读取其结果限定符 (#1453)。
  • 由 client 关闭的已完成的 Codex 流保留其令牌计数（@Ha1baraA11 的 #1397、#1398）。
  • caveman start 读取代理的顶级 mode，而不是嵌套的 middleware.mode (#1457)。
  • SSRF 防护阻止的兼容上游现在响应 cave_upstream_blocked 并记录主机以及 CAVE_SSRF_ALLOWLIST 修复，而不是通用 502 (#1440)。
  • caveman stats 在大型存储上不再超时：每个请求的缓存摘要移动到自己的表，在后台迁移（#1371、#1481）。超时时，它会命名数据库大小并建议 --days 7。
  • 本机运行时：CCR 写入不再重新扫描整个存储，这在大型家庭中使本机请求耗尽了 250 毫秒的预算并关闭为空（#1279）。报告了过长的 native.sock 路径（@Ha1baraA11 的#1399、#1402）。
  • 与句柄不匹配的恢复字节将被拒绝（#1373 by @zsltg）。恢复存储的页面上限适用于每个连接，并且其写入是序列化的（@zsltg 的#1374、#1375）。统计窗口被索引（#1372 by @zsltg）。 Bedrock ARN 模型 ID 保留其编码斜线（#1345 by @AlSh007）。中间件响应未标记为超过四分之一的限制（#1367 by @AlSh007）。 Kimi K3 的努力已被映射（#1306 by @ysntony）。包装插件的 caveman_retrieve 结果不再重新压缩（#1432）。
  • Claude OAuth 令牌刷新通过代理中继。路由 Gemini 固定 API-key auth，而不是退出 41。
  • 根据供应商页面重新验证定价目录（价格未更改）。 Vertex gemini-2.5-pro 和 gemini-2.5-flash 已删除：Google 均于 2026 年 10 月 20 日退役，这些请求现在显示为未定价而不是定价错误 (#1473)。 挂钩和安装器
  • Statusline 设置将 $ 保留在 CLAUDE_CONFIG_DIR 路径中（@Ha1baraA11 的#1400、#1401）。比较托管挂钩条目时会忽略关键顺序，因此 doctor --fix 停止与重新排序的条目进行斗争（@jamestrandung 的#1437、#1420）。卸载不再删除不是它创建的 settings.json.bak (#1330 by @AlSh007)。
  • Codex PostCompact 挂钩输出有效（#1467 by @mauhpr）。光标总是停止从 AGENTS.md 注入技能文件（#1411 by @minhhung2556）。挂钩下载被限制并固定到 HTTPS（#1269 by @tejgokani）。
  • ENABLE_TOOL_SEARCH 默认为 "true" 以匹配 Claude 代码（#1362 by @AliReza99）。 引擎、缩小和学习
  • 转义管道保留在 Markdown 表格单元格内（#1456 by @kevin9327）。大于 2^53 的整数远离数字范围轨道（#1332 by @AlSh007）。省略音符放置稳定（#1343 by @CHLIN0）。 CR 分隔的终端输出不再被截断。
  • caveman-shrink 跳过空列表条目而不是退出（#1435、#1436 by @shaikn6），并读取 Anthropic input_schema 工具（#1331 by @AlSh007）。
  • caveman learn 停止将穴居人自己的注入上下文报告为您粘贴的文本（#1459），并将冷简历与缓存搅动分开（#1419 by @jamestrandung）。 代理版本
  • 测试的代理版本上升：Codex 0.166.0、Claude Code 2.1.318、Gemini CLI 0.67.0、OpenCode 1.19.5、Qwen Code 0.26.8、Kilo 7.8.27、OpenClaw 2026.11.1 和 Hermes 0.23.0，每个版本都通过了存储库的一致性运行（#1474，与@szsunyuan的#1416和@anirudhqwerty的#1451）。 Pi暂时留在1.0.4； Pi 1.5.0 需要兼容性工作 (#1225)。

维护

  • 安全性：klauspost/compress v1.20.3 (GO-2026-6865)、golang.org/x/net v0.62.0 (GO-2026-6860、GO-2026-6866) 以及修补的 Go 工具链。 @caveman-ai/middleware 的 MCP 适配器现在需要 @modelcontextprotocol/sdk 1.32.0 或更新版本 (GHSA-6prh-2h8m-c8cw)，并在找到旧适配器时如此说明 (#1466 by @sudip28122812-creator)。 filelock 已修补，损坏的 litellm 版本被排除在外（#1379 by @szsunyuan）。
  • 依赖项碰撞：npm 开发组 (#1479)、golang 图像、pip 组。
  • 二进制文件：bin-v4.1.0。 CLI：@caveman-ai/cli 4.1.0。树莓派：@caveman-ai/pi 0.3.2。
