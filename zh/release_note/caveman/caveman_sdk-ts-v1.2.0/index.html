caveman sdk-ts-v1.2.0

发布 发布时间2026年9月30日 来源JuliusBrussee/caveman 英文原文

caveman sdk-ts-v1.2.0

  • **突破（许可证）：**从 MIT 重新授权给 Apache-2.0 以及其余的 Caveman 3.0.0 中的存储库。在此之前的版本保留 MIT 许可证。
  • onDecision 和 onDiagnostic 接受异步接收器：被拒绝的承诺是 像投掷一样被吞咽，就像 onReport 那样，而不是未经处理的 拒绝终止 Node。
  • 只等待另一个呼叫的共享功能获取的呼叫者不再获取 在断路器中记录其故障：冷启动时拒绝连接为一 失败，每个服务员都没有一次。其主机中止的调用不记录任何内容（它曾经 记录成功，因此取消的半开探针关闭了断路器）并释放 探针槽。新CircuitBreaker.release()。
  • 运行时标记被修剪掉周围的空白；任何其他字符 外部可打印 ASCII 为 invalid_configuration，如 Python。
  • https:// 或 socks HTTPS_PROXY/HTTP_PROXY 是 invalid_configuration 使用由 ready() 和 preflight() 命名的不受支持的方案，而不是 每次通话都是 runtime_unavailable。 MiddlewareError 采用可选细节。
  • retrieve()（以及恢复绑定）抛出 MiddlewareError('invalid_request') 对于不是对象的参数 字符串 handle，而不是 TypeError。
  • version_unverified 警告一次行显示“Caveman 中间件正在运行” 未经验证的框架版本`，因为该调用仍在继续。
  • CommonJS node16 消费者可以使用 import sdk = require(...) 和 带值的 import * as：.d.cts 垫片重新导出值，而不仅仅是类型。
  • @caveman-ai/sdk/middleware 稳定：@experimental 标记消失， 它遵循 semver，因为 @caveman-ai/middleware 1.0 依赖于它。
  • sourceId 不是范围标记的候选者将被跳过 unsupported，如 Python。
  • 出口商：成本始终导出为 doubleValue，即整美元金额 也是如此，如 Python。
  • 中间件传输荣誉HTTPS_PROXY/HTTP_PROXY/NO_PROXY，无 NODE_USE_ENV_PROXY，从不代理环回，并添加 ca 选项。
  • 计划验证是全面的：任何格式错误的计划都是 invalid_plan，绝不会 adapter_error。
  • 断路器、Retry-After 和 TTL 功能使用单调时钟。 检索和删除有自己的并发预算。服务器通告 截止日期有上限（5 秒优化，30 秒检索）。
  • 更严格的端点解析；以 BOM 为前缀的响应被拒绝； 429 带有 坏的UTF-8主体仍然是capacity。
  • 当没有可用的转换时，preflight() 报告 unknown_capability。 counts.skipped 表示发送减去替换。陈旧版本刷新运行 通过断路器串联。
  • 新的 unsupported_provider 和 unsupported_request 原因代码。
  • 导出器：用户提供的缓存创建属性再次传递并 不再被夹紧。成本也以 caveman.usage.cost_usd 形式发出 （gen_ai.usage.cost_usd 已弃用）。
  • 新的只读 MiddlewareRuntime.strict。
  • decline() 接受任何目录 ReasonCode 和可选适配器 ID， 警告一次日志行随后命名该名称。
  • typesVersions 和 .d.cts 垫片：使用 node10 或的 TypeScript 项目 node16 CommonJS 解析可以导入两个入口点，无需 skipLibCheck。
  • @caveman-ai/sdk/middleware实现中间件协议1.1：
    • 能力被宽容地解析，缓存300秒并刷新 单程
    • 计划在政策修订变化中仍然存在
    • 错误按照协议指定进行处理，包括 Retry-After
    • 新断路器在连续 5 次故障或 20 次故障中的 10 次后断开，并且 计算最后期限
    • 每个候选人的预算取代了整个呼叫旁路
  • 安全：替换件必须是exact_ccr，携带恢复标记并 句柄，并且严格以 UTF-8 字节表示。 recovery: "none"输出为 从未申请过。
  • 修复了每个请求的内存泄漏 (AbortSignal.any)。运行时令牌否 更长的时间出现在 JSON.stringify 或 util.inspect 中。
  • 本地数据错误不再算作运行时中断，并且 4xx 响应不再算作运行时中断 更长的清除缓存功能。
  • 新选项：maxConcurrency、allowInsecureTransport、onDecision、 tracer、meter。端点路径前缀有效，deadlineMs 默认为 运行时的广告价值。
  • 构造函数永远不会抛出：端点和选项错误警告一次并显示 ready()/preflight()。 decline() 不再在严格模式下抛出异常。
  • 中断（实验子路径）：
    • recovery() 对于无效范围返回 null。
    • deleteSession() 返回 SessionDeleteResult。
    • validateCapabilities 被删除。
    • 范围被标准化：不是有效标记的值被散列到 h-…。
  • 请求发送 Caveman-Middleware-Features、Caveman-Middleware-Client 和 W3C 跟踪上下文。
  • 节点楼层降低至 >=22.12。 CommonJS require() 的工作原理是 要求（esm）。
  • OTel 出口商：cacheCreationTokens 发出为 gen_ai.usage.cache_creation.input_tokens。
  • 发布流程：每个版本都会获得一个 GitHub 版本，其中包含这些说明和 CycloneDX 其依赖图的 SBOM。
