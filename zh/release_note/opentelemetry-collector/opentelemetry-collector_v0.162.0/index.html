opentelemetry-collector v0.162.0

opentelemetry-collector v0.162.0

最终用户 changelog

🛑 重大变化 🛑

  • cmd/mdatagen：生成的处理器生命周期测试现在断言处理器默认情况下将传入上下文传播到下一个使用者。 (#15994) 使用 skip_context_propagation: true 禁用
  • processor/queue_batch：将 queuebatch 处理器重命名为 queue_batch 处理器。 (#14396)

💡增强功能💡

  • extension/memory_limiter：添加 otelcol_memorylimiter_refused_requests 指标以记录扩展模式下的网络请求拒绝。 (#15561)
  • pkg/confighttp：默认启用保活配置。 (#16026) 推出功能门 pkg.confighttp.PrioritizeNewKeepalive。禁用时，该标志 恢复删除 keepalive 配置的旧行为 已弃用的字段 IdleConnTimeout、MaxIdleConns、MaxIdleConnsPerHost、 当该标志被禁用时为 DisableKeepAlives。
  • pkg/exporterhelper：通过 batch::partition::idle_timeout 配置分区空闲超时并将默认值提高到 90 秒。 (#15894)
  • pkg/exporterhelper：使多批处理程序分区 LRU 缓存大小可配置并导出缓存大小指标。 (#14526) 添加 sending_queue::batch::partition::cache_size（默认 10000）以限制 活动分区批处理程序的数量。价值 必须是积极的。当前大小和配置容量导出为 otelcol_exporter_queue_batch_partition_cache_size 和otelcol_exporter_queue_batch_partition_cache_capacity。
  • pkg/pprofile：通过用索引查找替换 switchDictionary 中的线性扫描重复数据删除，加速导出器队列批处理期间的配置文件字典合并，将每次合并成本从 O(N*L^2) 降低到 O(N+L)。 (#15544) 没有行为改变：合并的字典内容和重新映射的索引与之前相同。
  • pkg/receiverhelper：停止分配跨度链接，当长期上下文接收器在没有父跨度上下文的情况下启动操作时，该跨度链接始终会被丢弃。 (#15998) 使用 LongLivedCtx: true 创建的接收器不再构建 trace.Link 长期存在的上下文不携带有效的跨度上下文。 SDK已经放弃了这样的链接， 所以行为没有改变。这会删除每个接收操作 7 个分配中的 3 个。
  • pkg/xpdata：减少 xhash.MapHash 在具有许多条目的地图上花费的时间。 (#15990)

🧰错误修复🧰

  • exporter/debug：支持 AIX 上的已知同步错误处理 (#15924) 启用调试导出器来处理 AIX 上的已知同步错误。
  • pkg/exporterhelper：拆分批次时仅删除超大项目，而不是丢弃后面排队的每个项目 (#15936) 目前仅适用于日志
  • pkg/exporterhelper：将导出器和 data_type 属性添加到导出器/排队范围。 (#16022)
  • receiver/otlp：当请求内容类型不是可以编码状态的类型时，错误处理程序保留 HTTP 状态代码 (#15995) 扩展了 #13414 中的修复，该修复处理了缺失的 Content-Type。内容类型是 存在但不受支持或畸形，仍然落入 500 {"code": 13, "message": "failed to marshal error message"}，报client错误 例如来自服务器身份验证扩展的 401 或来自不受支持的内容编码的 400 服务器故障。

v1.67.0/v0.161.0

🛑 重大变化 🛑

  • pkg/pprofile：删除已弃用的 AggregationTemporality、Duration、SetDuration (#15855)
  • pkg/scraperhelper/controller：删除已弃用的 AddScraper 函数 (#15934)
  • pkg/service：删除已弃用的 ZapOptions (#15935)
  • pkg/xconfmap：删除已弃用的 WithForceUnmarshaler 函数 (#15932)

💡增强功能💡

  • pkg/pdata：避免在 WriteInt64 和 WriteUint64 中分配（#15629）

🧰错误修复🧰

  • cmd/schemagen：接受在生成的收集器配置架构中没有配置主体编写的组件 (#15728)
  • pkg/confmap：修复了有效 URI 之前出现的转义 URI 阻止后续 URI 扩展的错误。 (#15867) 现在，URI 扫描在转义 URI 之后继续，同时将转义表达式保留为文字文本。
  • pkg/featuregate：拒绝带有空点分隔段（前导、尾随或连续点）的功能门 ID，例如.foo、foo.、foo..bar。 (#15676)
  • pkg/pprofile：当 key_strindex 未设置时，停止擦除内联属性键，并在解析后清除 key_strindex。 (#15793)
  • pkg/pprofile：在编组和解组 OTLP 配置文件导出请求时，通过 ProfilesDictionary 字符串表引用资源和范围属性字符串。 (#15792)
  • pkg/scraperhelper：修复当刮擦运行时间长于收集间隔时关闭因额外刮擦而延迟的问题 (#15736) 如果在下一个蜱虫触发时刮擦仍在运行，则待处理的蜱虫和关闭 信号在完成时可能都已准备好，并且控制器在它们之间随机选择。

API changelog

💡增强功能💡

  • cmd/mdatagen：允许配置元数据作者为生成的可选字段选择 configoptional.Some 或 configoptional.Default (#15977) 设置 go_struct.optional_mode: default 生成可选对象配置 具有后备默认值的部分，同时在配置之前保持其不存在。省略 optional_mode 保留现有的 configoptional.Some 行为。
  • pkg/config/configgrpc：将 gRPC client 的常用设置的核心类型迁移到 mdatagen 生成的基于架构的配置。 (#15967)
  • pkg/exporterhelper：添加NewDefaultBatchConfig以构建具有默认值的BatchConfig，包括分区cache_size和idle_timeout默认值。 （＃14526，＃15894）
  • pkg/exporterhelper：通过 batch::partition::idle_timeout 配置分区空闲超时并将默认值提高到 90 秒。 (#15894)
  • pkg/exporterhelper：使多批处理程序分区 LRU 缓存大小可配置并导出缓存大小指标。 (#14526) 添加 sending_queue::batch::partition::cache_size（默认 10000）以限制 活动分区批处理程序的数量。价值 必须是积极的。当前大小和配置容量导出为 otelcol_exporter_queue_batch_partition_cache_size 和otelcol_exporter_queue_batch_partition_cache_capacity。
  • pkg/xpdata：从 contrib 存储库中移动 pdata 哈希 API (#15914)

🧰错误修复🧰

  • cmd/schemagen：修复了 RefResolver 使用每次出现的注释改变共享、缓存的类型定义，这会导致每当多个字段引用相同类型时，生成的模式具有不正确的（并且运行到运行不确定的）description/x-optional/x-pointer 值。 (#15984)
  • pkg/pdata：修复 pcommon.Value.CopyTo 以深度复制 ValueTypeBytes 值而不是共享后备数组 (#15621) CopyAnyValue 中的 bytes oneof 字段是直接赋值的，因此副本和源共享相同的 []byte。 这也影响了 Map.CopyTo 和 Slice.CopyTo，它们委托给 CopyAnyValue。
