opentelemetry-collector v0.165.0

小版本 发布时间2026年11月6日 来源open-telemetry/opentelemetry-collector 英文原文

opentelemetry-collector v0.165.0

图像和二进制文件：https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.165.0

最终用户 Changelog

🛑 重大变化 🛑

  • pkg/confighttp：删除已弃用的字段 IdleConnTimeout、MaxIdleConns、MaxIdleConnsPerHost、DisableKeepAlives。 (#15973)

🚀 新组件🚀

  • pkg/xreceiverhelper：添加带有 ObsReport 的 xreceiverhelper，该 ObsReport 报告每个样本类型的配置文件样本指标。 (#16251) ObsReport.EndProfilesOpBySampleType 记录 otelcol_receiver_{accepted,refused,failed}_profile_samples 指标带有额外的 sample_type 属性，格式为“type:unit”，因为单个有效负载可以容纳多个配置文件 具有不同的样本类型。使用 ProfileSampleCountsByType 计算之前的样本计数 配置文件将传递给下一个消费者，因为数据可能会在下游发生变化。 OTLP 接收器现在使用 EndProfilesOpBySampleType。

💡增强功能💡

  • pkg/configmiddleware：允许覆盖 confighttp.ToClient 和 configgrpc.ToClient 使用的拨号器 (#16019)
  • pkg/featuregate：允许在功能门 ID 中使用下划线。 (#16243)
  • pkg/pdata：提高 pcommon.Map Get、Range 和 All 函数的性能。 （＃16282，＃16321）
  • pkg/pdata：更新 oneof 原语时减少分配数量 (#16226)
  • pkg/service：服务现在支持根据 otelconf v0.26.0 的更新配置其他资源检测器以进行内部遥测。 (#15869)
  • pkg/service：当管道将批处理器与 Exporterhelper 批处理结合在一起时，启动时发出警告。 (#15965) 检测不会交叉连接器或检查隐藏 Exporterhelper 批处理功能的导出器包装器。
  • pkg/xprocessorhelper：仪器xprocessorhelper.NewProfiles与otelcol_processor_incoming_items、otelcol_processor_outgoing_items和otelcol_processor_internal_duration，与其他信号构造器一致。 (#15523)
  • processor/memory_limiter：添加 garbage_collector 配置部分以允许通过 enabled 字段禁用强制垃圾收集。 (#15081)
  • processor/queue_batch：将queue_batch 处理器升级为针对跟踪、指标和日志的beta 版，针对配置文件升级为alpha 版。 (#12022)
  • processor/queue_batch：将队列和批次指标报告为处理器指标（#14038）

🧰错误修复🧰

  • cmd/mdatagen：修复处理单元素或空枚举属性时 Attribute.TestValue() 和 Attribute.TestValueTwo() 中的恐慌。 (#15644)
  • cmd/mdatagen：修复当指标迁移的 through_gates 功能门升级到 alpha 版本后生成的指标测试失败的问题。 (#16249) 生成的测试现在显式地为每个测试用例设置迁移功能门并恢复 他们之前的清理状态，而不是假设默认情况下禁用门。 当门的阶段禁止案例所需的状态时，例如禁用稳定门，指标生成器 测试仅跳过其与门相关的计数和警告断言，以及每个组合的版本度量 跳过该组合的子测试。
  • cmd/mdatagen：为 exported_configs 定义生成自述文件配置文档。 (#16164) exported_configs 下的对象定义和标量类型别名现在呈现在 config: 表之后的 README 中。 仅声明 exported_configs 的包现在可以在自述文件包含配置标记后获取生成的文档。 仅声明 exported_configs 的组件不再获得空配置表。
  • cmd/schemagen：加载架构时处理文件未找到错误（#15925）
  • pkg/configgrpc：通过配置的最大接收消息大小而不是库默认值来限制 zstd 解码器窗口。 (#16280) zstd 帧在标头中声明其窗口，并且解码器分配它 在产生任何输出之前，因此一个精心设计的小消息可能会驱动一个大的消息 分配与 max_recv_msg_size_mib 无关。解码器也是 gRPC 处理完消息后立即返回到其池中。
  • pkg/confighttp：通过 max_request_body_size 绑定 zstd 解码器窗口，而不是库默认值。 (#16280) zstd 帧在标头中声明其窗口，并且解码器分配它 在产生任何输出之前，因此一个精巧的小机身可以驱动一个大的 无论配置的请求主体大小如何分配。
  • pkg/confighttp：接受内容编码：等同于无编码的标识。 (#15122)
  • pkg/exporterhelper：修复当持久发送队列将请求转发到另一个管道时出现的 Cannot unref freed data 恐慌 (#15256)
  • pkg/exporterhelper：使用 wait_for_result，取消发送队列已接受的请求不再提前返回 (#16255) 以前，取消的上下文使其在请求仍然存在时返回 context.Canceled 已发送，因此呼叫者可以报告已发送的数据失败。取消仍然需要 未对请求执行任何操作时生效。
  • pkg/pdata：向 AnyValue、ArrayValue、KeyValueList 和 KeyValue 的原始解组添加递归深度限制 (100)，以防止恶意制作的深度嵌套有效负载造成堆栈溢出。 (#15301)
  • pkg/service：跳过关闭期间尚未构建的图形节点，以防止部分接收器重新加载无法构建接收器时出现恐慌。 (#16261)
