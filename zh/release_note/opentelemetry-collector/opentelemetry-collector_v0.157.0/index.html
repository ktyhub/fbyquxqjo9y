opentelemetry-collector v0.157.0

小版本 发布时间2026年7月21日 来源open-telemetry/opentelemetry-collector 英文原文

opentelemetry-collector v0.157.0

图像和二进制文件：https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.157.0

最终用户 Changelog

🛑 重大变化 🛑

  • pkg/exporterhelper：将 otelcol_exporter_queue_batch_send_size_bytes 和 otelcol_processor_batch_batch_send_size_bytes 的直方图存储桶边界替换为跨度为 128 B 到 16 MiB 的 2 次方字节规模集。 (#15535) 之前的边界包括许多小的亚千字节存储桶，这些存储桶对于字节规模没有用处 有效负载，otelcol_exporter_queue_batch_send_size_bytes 最大为 6000 字节，所以几乎所有 观测值落入 +Inf 溢流桶中。新边界是 128 B 的 2 的幂 到 16777216 (16 MiB)，为实际批量有效负载大小（包括小 超时刷新批次）并保留两个 在相同的仪表板上直接比较的指标。硬编码特定 le 的仪表板或警报 这些直方图的值需要更新。
  • processor/batch：将 otelcol_processor_batch_batch_send_size_bytes 的直方图存储桶边界替换为跨度为 128 B 到 16 MiB 的 2 次方字节规模集。 (#15535) 之前的边界包括许多小的亚千字节存储桶，这些存储桶对于字节规模没有用处 有效负载。新边界是从 128 B 到 16777216 (16 MiB) 的 2 的幂，给出了有意义的 实际批次有效负载大小的分布（包括小的超时刷新批次）并保持 指标直接与 otelcol_exporter_queue_batch_send_size_bytes 在同一仪表板上。仪表板或警报 需要更新此直方图的硬编码特定 le 值。

💡增强功能💡

  • all：用于核心组件的引导 config.schema.yaml（调试/otlp/otlphttp 导出器、otlp 接收器、批处理/内存限制器处理器、内存限制器/zpages 扩展）。实现组件配置架构路线图 RFC 的第一阶段。 (#14543) 模式是使用 opentelemetry-collector-contrib 中的 schemagen 工具生成的，并手动调整以捕获 验证规则和对共享库模式的引用（confighttp、configgrpc、configretry、exporterhelper、 等）。添加了 .schemagen.yaml 设置文件和 generate-schemas Makefile 目标，以便模式可以 可重复地再生。
  • pkg/service：将实验性 service::telemetry::resource::detection/development 资源检测应用于收集器的内部遥测资源。 (#14311) 这遵循 OpenTelemetry 配置模式，通过处理 探测器选用service::telemetry::resource::detection/development::detectors。 当前支持的检测器条目有 container、host、process 和 service。 请参阅 OpenTelemetry 配置 Go 支持表并搜索 ExperimentalResourceDetector 用于电流检测器支持： https://github.com/open-telemetry/opentelemetry-configuration/blob/main/language-support-status.md#go 示例： 
    service:
  telemetry:
    resource:
      attributes:
        - name: foo
          value: bar
      detection/development:
        detectors:
          - host: {}
  • pkg/service：添加 service.partialReload 功能门（Alpha）和 service.partialReloadReceivers 功能门（Beta），当非接收器配置部分未更改时，它们在配置重新加载时仅重新启动接收器，避免对处理器、导出器和扩展造成不必要的中断。通过 --feature-gates=service.partialReload 启用。 (#5966)

🧰错误修复🧰

  • exporter/debug：修复了 normal 详细封送拆收器打印的范围索引；每个范围都标有其父资源的索引而不是其自己的位置 (#15541) 影响所有四个信号（日志、跟踪、指标、配置文件）——例如资源下的第二个范围打印为 #0 而不是 #1。
  • pkg/config/configgrpc：修复了 WaitForReady 选项不适用于 gRPC client 连接的问题。 (#15615)
  • pkg/featuregate：修复当 --feature-gates 值包含空逗号分隔元素（例如 --feature-gates=alpha,）时出现的恐慌 (#15536) 现在，空标识符会在标志解析期间产生返回的错误，而不是索引超出范围的恐慌。
  • pkg/service：修复当资源检测器发出切片值属性时收集器启动恐慌（例如 process 检测器的 process.command_args）（＃15571） createResource 将 OTel SDK 属性值直接传递给 pcommon.Value.FromRaw，这 切片仅接受 []any，因此生成的任何 string、int、float 或 bool 切片资源属性 <Invalid value type> 错误并中止 service.New。切片类型的属性现在已转换 元素方面。
  • pkg/service：记录扩展报告的状态事件（#15557）

API Changelog

🛑 重大变化 🛑

  • pkg/config/configgrpc：删除 BalancerName 功能（#9477） 请改用 DefaultBalancerName 常量。

🚩 弃用 🚩

  • pkg/xconfmap：弃用 WithForceUnmarshaler 选项。 (#15614) 请改用 confmap.WithForceUnmarshaler。

🚀 新组件🚀

  • pkg/config/configstorage：添加新的configstorage模块以支持存储配置字段。 (#5832)

💡增强功能💡

  • pkg/confmap：添加WithForceUnmarshaler选项。 (#15614) 此选项允许强制顶级 Unmarshal 方法，即使 Conf 是 已经是来自 Unmarshal 方法的参数。有关更多详细信息，请参阅 Godoc。
