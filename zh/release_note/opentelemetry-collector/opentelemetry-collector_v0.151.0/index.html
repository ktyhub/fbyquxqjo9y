opentelemetry-collector v0.151.0

小版本 发布时间2026年4月28日 来源open-telemetry/opentelemetry-collector 英文原文

opentelemetry-collector v0.151.0

图像和二进制文件：https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.151.0

最终用户 Changelog

🛑 重大变化 🛑

  • cmd/builder：在生成的 Collector 源中，Go 模块中的 replace 语句现在默认使用相对路径。 (#15097) 我们希望这不会破坏现有的用例，其中生成的收集器仅以临时方式用于构建。它可以将生成的 Collector 代码作为寿命更长的工件进行跟踪，从而允许其在任何计算机上运行（而绝对路径将根据生成 Collector 源的计算机而有所不同。）我们添加了 dist::use_absolute_replace_paths，以便在存在需要绝对路径的不可预见的用例的情况下返回到绝对路径行为。
  • pkg/confighttp：稳定框架Snappy功能门。 (#15096)

💡增强功能💡

  • all：添加对服务遥测资源配置的声明性架构支持。 (#14411) service::telemetry::resource 配置现在接受具有显式名称/值对的声明性模式： 
    service:
  telemetry:
    resource:
      schema_url: https://opentelemetry.io/schemas/1.38.0
      attributes:
        - name: service.name
          value: my-collector
        - name: host.name
          value: collector-host
    为了向后兼容，仍然支持旧的内联属性映射格式： 
    service:
  telemetry:
    resource:
      service.name: my-collector
      host.name: collector-host
    注意：resource.detectors 已被接受以实现向前兼容性，但尚未被收集器应用。
  • exporter/otlp_grpc：将 server.address 和 url.path 属性添加到 otlp 导出器生成的指标中。 (#14998)
  • exporter/otlp_http：将 server.address 和 url.path 属性添加到 otlp_http 导出器生成的指标中。 (#14998)
  • pkg/config/configgrpc：将 UserAgent 字段添加到 ClientConfig 以允许覆盖默认的 gRPC 用户代理字符串。 (#14686) otlp gRPC 导出器无条件地通过以下方式设置用户代理 拨号时的 grpc.WithUserAgent() 优先于每次呼叫 元数据，导致任何用户配置的用户代理被默默丢弃。 ClientConfig 中添加了专用的 UserAgent 字段，当 set，直接在拨号选项中使用，而不是默认的 BuildInfo 派生字符串。
  • pkg/config/configgrpc：在 client 端点中接受 gRPC 解析器方案 URI（例如 passthrough:///host:port）以允许控制名称解析（#14990） 迁移到 grpc.NewClient 后，一些 gRPC client 组件（例如 OTLP） 导出器在双堆栈 DNS 环境中遇到连接问题。现在可以这样 通过在端点字段中使用 passthrough:/// gRPC 解析器方案进行修复。
  • pkg/config/confignet：添加对 Windows 命名管道 (npipe) 传输的支持 (#15085)
  • pkg/service：使用旧的 v0.2.0 声明性配置格式时发出警告 (#15088)

🧰错误修复🧰

  • pkg/otelcol：在 otelcol components 命令中精确打印一次组件 (#14682) 这解决了跳过别名组件的问题。
  • pkg/otelcol：同步收集器运行和关闭生命周期，以便关闭阻塞，直到运行完成所有清理。 (#4947) 关闭现在会阻塞，直到运行完成清理，匹配 http.Server 语义。 如果在 Run 之前调用 Shutdown，则清理后下一次 Run 调用将返回 nil 配置提供者。
  • pkg/pdata：在 Value.AsString() 中使用符合规范的字符串表示形式表示 NaN、Infinity 和 -Infinity。 (#14487)
  • pkg/pprofile：修复编组-解组-合并往返后资源和范围属性的数据损坏。 (#15084)
  • pkg/service：遥测配置中的非字符串资源属性现在返回错误而不是恐慌 (#15171)
  • pkg/xscraperhelper：修复分析刮刀助手中的配置文件合并（#14790）
  • receiver/otlp：修复配置文件接收器将其样本报告为跨度（#15089）

API Changelog

🛑 重大变化 🛑

  • receiver/otlp：Config.Protocols 现在是命名字段而不是匿名嵌入字段。 (#15178) 对 cfg.GRPC 和 cfg.HTTP 的访问权限必须更新为 cfg.Protocols.GRPC 和 cfg.Protocols.HTTP。

🚩 弃用 🚩

  • cmd/mdatagen：DefaultMetricsBuilderConfig 函数已弃用。请改用 NewDefaultMetricsBuilderConfig。 (#15165) 生成的 DefaultMetricsBuilderConfig 函数已重命名为 NewDefaultMetricsBuilderConfig 遵循 Go 命名约定。旧函数作为已弃用的包装器保留，并将被删除 在未来的版本中。

💡增强功能💡

  • cmd/mdatagen：处理 mdatagen 中生成代码中配置字段的默认值。 (#14560)
  • cmd/mdatagen：通过 override_value_enabled 标志添加对资源属性配置的选择性覆盖值支持 (#15109) 组件可以通过在其元数据中设置 override_value_enabled: true 来选择加入。yaml。 启用后，将使用类型化的 override_value 字段生成每个属性的配置类型 允许用户覆盖收集器配置中的资源属性值。 没有该标志的组件继续使用共享的 ResourceAttributeConfig 类型。
  • cmd/mdatagen：扩展 mdatagen 配置代码生成以正确处理 allOf 嵌入引用的默认值 (#14560)
  • cmd/mdatagen：处理生成的配置结构中的字符串验证器（#14807） 支持的验证器包括 minLength、maxLength 和 pattern。
  • pkg/config/configgrpc：为默认负载均衡器的名称添加 DefaultBalancerName 常量 (#15139) 这取代了 BalancerName 功能。
  • pkg/config/configgrpc：在 client 端点中接受 gRPC 解析器方案 URI（例如 passthrough:///host:port）以允许控制名称解析（#14990） 迁移到 grpc.NewClient 后，一些 gRPC client 组件（例如 OTLP） 导出器在双堆栈 DNS 环境中遇到连接问题。现在可以这样 通过在端点字段中使用 passthrough:/// gRPC 解析器方案进行修复。
  • pkg/exporterhelper：添加了 WithAttrs 选项以允许导出器指标上的自定义属性 (#14998)

🧰错误修复🧰

  • cmd/mdatagen：修复了 mdatagen 中 allOf 字段未正确处理的错误，导致数据模型生成不正确。 (#15153)
  • pkg/otelcol：同步收集器运行和关闭生命周期，以便关闭阻塞，直到运行完成所有清理。 (#4947) 关闭现在会阻塞，直到运行完成清理，匹配 http.Server 语义。 如果在 Run 之前调用 Shutdown，则清理后下一次 Run 调用将返回 nil 配置提供者。
  • pkg/pdata：在 gRPC 服务处理程序中使用池感知构造函数，以便顶级请求结构参与sync.Pool 生命周期。 (#14763) 所有信号类型的 gRPC 服务处理程序都分配了顶层 ExportXxxServiceRequest 带有裸露的 new()，绕过sync.Pool pdata.useProtoPooling 已启用。这导致对象返回到池中 通过删除永远不会被检索。处理程序现在使用池感知 New*() 构造函数。
