opentelemetry-collector v0.159.0

小版本 发布时间2026年8月17日 来源open-telemetry/opentelemetry-collector 英文原文

opentelemetry-collector v0.159.0

图像和二进制文件：https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.159.0

最终用户 Changelog

💡增强功能💡

  • pkg/exporterhelper：添加 pkg.exporterhelper.queueBatchEnabled 功能门（#14038、#13582、#12022） 启用后，NewDefaultQueueConfig() 返回的批量设置具有 batch::enabled 正确。请参阅迁移 RFC。

🧰错误修复🧰

  • pkg/exporterhelper：批处理后记录otelcol_exporter_queue_batch_send_size和otelcol_exporter_queue_batch_send_size_bytes，并添加otelcol_exporter_enqueue_size和otelcol_exporter_enqueue_size_bytes作为入队时间大小。 (#14674) 以前，批量发送大小直方图是在入队时 (Offer) 记录的，因此它们 测量传入请求的大小，而不是传递给的批处理后请求 下游发送者。这些直方图现在记录在 obs 报告发送器中。 以前的排队时间测量在新的下保留 otelcol_exporter_enqueue_size 和 otelcol_exporter_enqueue_size_bytes 指标 队列大小。启用导出器批量处理程序的用户将观察到不同的值 otelcol_exporter_queue_batch_send_size*。 otelcol_exporter_queue_batch_send_size 和 otelcol_exporter_queue_batch_send_size_bytes 现在仅在配置 sending_queue::batch 时才记录；他们根本不会出现 对于不启用批处理的出口商。
  • pkg/scraperhelper：使用 {record} 而不是 {datapoint} 作为日志记录和配置文件记录抓取指标的单位 (#15730) 影响 otelcol_scraper_scraped_log_records、otelcol_scraper_errored_log_records、 otelcol_scraper_scraped_profile_records 和 otelcol_scraper_errored_profile_records。

API Changelog

🛑 重大变化 🛑

  • extension/zpages：使 confighttp.ServerConfig 成为 Config 的命名字段，而不是嵌入字段。 (#15308)
  • pkg/confighttp：使 configauth.Config 成为 AuthConfig 的命名字段，而不是嵌入字段。 (#15308)

💡增强功能💡

  • pkg/config/configretry：将 BackOffConfig 迁移到 mdatagen 生成的基于架构的配置。 (#15502)
  • pkg/config/configtls：将 TLS 核心类型迁移到 mdatagen 生成的基于架构的配置。 (#15693)
