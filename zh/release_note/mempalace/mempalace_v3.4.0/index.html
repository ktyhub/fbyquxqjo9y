mempalace v3.4.0

小版本 发布时间2026年6月6日 来源MemPalace/mempalace 英文原文

变更流程图

亮点

  • 可插拔向量后端 — 现在可以通过 MEMPALACE_BACKEND 或 --backend 选择 Qdrant、pgvector 或 sqlite_exact，取代默认的 ChromaDB。如果你已经在跑 Postgres/Qdrant，这消除了对 ChromaDB 的锁定，且默认行为不变；坚持默认值的话，对你没有任何变化。
  • mempalace migrate-wings（迁移步骤） — 一次性、可选启用的迁移，通过去除首尾分隔符来规范化旧版 wing 名称。如果你在升级 v3.4.0 之前的宫殿，某些 wing 在被迁移前可能无法被发现——参见 docs/recovery/wing-name-migration.md。全新安装可以忽略。
  • 全新安装上的语义搜索此前是静默坏的 — 默认的 embeddinggemma 模型现在可与 ChromaDB 1.5.x 一起工作；此前在新安装上语义搜索会静默返回空结果。这是升级的最强理由：任何针对 ChromaDB 1.5.x 安装并看到搜索为空/异常的用户，都应升级到 v3.4.0。
  • 静默失败与隐私修复 — 防止 drawer_id 哈希冲突导致的静默数据丢失，阻止 import mcp_server 重新创建 ~/.mempalace（遵循隐私关闭开关），为 diary_write 增加 content 别名及其缺失参数诊断，并修复显式向量后端上的单文档输入。无需任何操作，但这些修复消除了真实的正确性/数据完整性风险。
  • 打包与基础设施（谁可以跳过） — 为 MCP 服务器和 CLI 新增 CPU + GPU Docker 镜像，并为原子化多词实体名称增加已知系统词库。GitHub Actions 的可信发布（OIDC，需手动批准门控）变更仅面向维护者——对终端用户是空操作。如果你没有旧宫殿，也没有遇到搜索/数据丢失问题，就没有强制迁移，不过上述修复仍使升级低风险且值得。

v3.4.0 — 可插入后端、Docker 和可靠性修复

特点

  • 可插入向量后端 - Qdrant、pgvector 和 sqlite_exact 以及默认 ChromaDB，可通过 MEMPALACE_BACKEND / --backend 进行选择。
  • MCP 服务器和 CLI 的 Docker 图像（CPU + GPU）。
  • mempalace migrate-wings — 一次性迁移，可规范遗留翼名称（条带前导/尾随分隔符），以便升级前的宫殿保持可发现性。参见 docs/recovery/wing-name-migration.md。
  • 已知系统词典在实体检测中保持多词产品名称的原子性。

修复

  • embeddinggemma（默认模型）现在可与 ChromaDB 1.5.x 配合使用 - 语义搜索在全新安装时默默失败。
  • 防止 drawer_id 哈希冲突导致静默数据丢失。
  • 导入 mcp_server 不再重新创建 ~/.mempalace（尊重隐私终止开关）。
  • diary_write 接受 content 别名并恢复丢失参数的诊断。
  • 显式向量后端正确处理单文档输入。

基础设施

  • 通过 GitHub Actions Trusted Publishing (OIDC) 进行 PyPI 发布，通过手动批准进行控制。
