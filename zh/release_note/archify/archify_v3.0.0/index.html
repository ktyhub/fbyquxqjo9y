archify v3.0.0

Archify 3.0 — 更清晰的图表，经过验证的交付

Archify 3.0 带来了重新设计的图表阅读器、更清晰的布局和路由，以及在交还生成的工件之前验证生成的工件的交付工作流程。它遵循dev上的集成更改和实际项目试验。

发生了什么变化

  • 重新设计的阅读器。 默认情况下，注释位于图表下方。阅读器将图表和控件安装到其可读性楼层允许的第一个屏幕上，并在必要时缩放细节并滚动。窄图还保留可用的页面布局。
  • 更清晰的图表。 架构和工作流程布局和布线更仔细地处理扇出、返回路径、标签和共享走廊。 Lifecycle v2 引入了通道/列布局、状态标记和更好的源标记间距，同时保留 schema-v1 几何支持。
  • **使用画布的序列图。**图例位于所有时间线内容下方，可以换行为多行，并且不再与生命线相交。消息标签遵循其线条颜色。测量宽度建议可指导对新的未固定图表（包括带有品牌徽标的参与者）进行有界扩展修复。
  • 跨所有五种类型的验证交付。 存储库支持的源、工件出处、组成检查和浏览器检查参与交付工作流程。 Windows 路径处理、可复制包和跨平台烟雾检查已得到强化。
  • 查看器翻译作为数据提供。 英语和简体中文仍然内置； meta.translations 提供其他查看器语言，而无需添加特定于渲染器的区域设置分支。

从 2.x 升级

  • 引导/故事视图和普通共享卡导出已被删除。使用概述、路线、镜头和规范导出。现有的 meta.views 数据被接受但被忽略；已经生成的独立 HTML 保留其嵌入式查看器。
  • 仍然支持现有的 schema-v1 输入。当网格布局适合任务时，使用 Lifecycle v2 创建新图表；不需要转换现有的 v1 文件。
  • 查看器翻译和创作的图表文本是分开的：翻译查看器不会翻译节点名称或消息标签。
  • 该技能仍可在 Node.js 18 或更高版本上运行。规范的 ZIP 是使用固定的 Node 22 工具链构建的；用户不需要该打包工具链来运行它。

验证和剩余限制

集成批次通过了完整的 Node 版本、浏览器/WebM、Windows 路径、跨平台包和 DSH 检查。实际项目试验还修复了图例、首屏和序列宽度。自动检查并不能保证完美的构图：复杂的分支工作流程可能仍然需要创作修复，某些布局保留交叉，面向软件的图例可能需要针对非软件主题进行调整。 使用随附的 archify.zip 作为规范技能包。有关详细更改和贡献者归属，请参阅 3.0.0 changelog。

中文摘要

Archify 3.0 更新了图形查看器、布局与路由、Lifecycle v2，以及生成后的交付检查。时序图的图例会避开消息和生命线，宽画布留白也会给出有次数限制的修复建议。 升级时请注意：引导视图和普通分享卡导出已移除；旧的 meta.views 数据仍可读取，但不再展示。已有 v1 图形输入继续支持，已经生成的独立 HTML 不会被升级自动改写。复杂流程仍可能需要调整，自动检查通过不等于每张图都无需视觉审查。
