JeecgBoot v3.8.1

修订 发布时间2025年7月2日 来源jeecgboot/JeecgBoot 英文原文

JeecgBoot v3.8.1

变更流程图

亮点

  • 安全与授权 — 修复 v3.8.0 遗留的 zip 炸弹漏洞（Issue #8199）、SQL 黑名单绕过（Issue #8335）、在线报表权限缺口，以及 Spring Boot 3 下 JimuReport 1.9.4 的高危组件漏洞。外网暴露部署、开放文件上传、知识库和报表场景受益最大。

  • AI 平台加固 — 官方宣布 AI 应用达到上线标准，新增移动端聊天、OCR 示例、权限注解，并修复工作流脚本/分类/子流程、本地 DeepSeek 与 Ollama、停止响应、图片解析、知识库向量化等问题。兼容性提醒： JDK 21 可以启动应用，但 AI 工作流编排在该环境下仍不可用。

  • 新的集成与交付方式 — 新增基于 AK/SK 鉴权的 OpenAPI、用 Vite + Vue3 + Electron 打包的桌面客户端（支持 Windows/Linux/macOS），用户导入可带入部门与角色，钉钉登录和部门同步也得到改进。主要利好需要对外提供 API、发布桌面客户端或批量导入组织数据的团队。

  • 低代码与依赖变更 — 代码生成新增关联记录控件、JavaScript 增强、自定义按钮空方法和 uniapp-vue3 模板；JVxeTable 升到 4.13.31、jsqlparser 升到 4.9，SQL 解析代码统一收敛到 MiniDao，同时修复大量表格、表单、字典和分页问题。自定义表格扩展与 SQL 定制升级后应做回归测试；官方未给出正式迁移步骤。

  • 升级建议与 API 注意点 — v3.8.0 用户强烈建议升级，尤其是外网暴露或重度使用 AI 的部署。行为变更： AI 工作流调用接口现在允许免登录调用，若这些端点可被访问，请复查网关与网络访问控制。未使用 AI 或桌面功能、且已规避上述漏洞的团队可暂缓跟进新功能。

升级日志

推出系列新功能；AI应用平台功能稳定；支持Electron桌面应用；基于AK和SK认证鉴权OpenAPI功能；用户导入支持导入部门和角色；代码生成支持关联记录控件、js增强和自定义按钮等
