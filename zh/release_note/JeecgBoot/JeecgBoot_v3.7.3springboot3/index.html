JeecgBoot v3.7.3springboot3

JeecgBoot v3.7.3springboot3

这个项目是干啥的：是一个基于Spring Boot的低代码后台开发平台，让企业开发者用生成器和现成模块快速搭出管理系统，少写重复的增删改查。

变更架构图

亮点

  • Spring Boot 3 + JDK 17 是迁移，不是补丁 — PR #5563 把整个技术栈搬到 Boot 3 和 Java 17，意味着 javax → jakarta 命名空间切换和更高的最低运行时要求。Docker 基础镜像也改为 JDK 17（#7317），构建镜像和 CI runner 必须同步更新；依赖改用 jeecg-boot-starter3（#5566、#5567）而非旧 starter。请按分阶段升级加完整回归来规划，不要原地替换。
  • Tomcat 换成 Undertow（#5716）— 这是有感知的行为变化：server.* 调优参数、连接器/线程池设置和错误处理都不一样，所有 Tomcat 专属配置都要重写并做压测。同一 PR 还把 fastjson 固定到 2.0.43；加上 Druid 1.2.22 的兼容性改动（#6081、#6091），数据源侧也会有配置层面的差异。
  • 采用前有必要知道的 Boot 3 兼容性修复 — Shiro 无法使用 Spring Boot 3 自带的 Jedis（#5741、#5767），该分支最终统一到 Jedis 3.8.0（#5782）；JAXB 不再随 JDK 提供，因此显式固定了 jaxb-runtime（#5723、#5765）。JimuReport 和 Minidao 在此版本才获得 Boot 3 构建（#5698），jeewx-api 换成 weixin4j（#8004）——微信集成需要真正改代码，不只是升版本号。
  • 安全与认证面 — 修复 CVE-2023-6378（#8008），Shiro 升级到 2.0.4（#8256）。文档/认证侧：生成的 API 文档范围变了（#5730），部分端点被排除，免登录端点去掉了 token 校验头（#8053），Swagger 生成也重构了（#8116）。如果网关或生成的客户端依赖这些头或规范，请重新验证公开端点并重新生成客户端。
  • 改变生产行为的运行时与部署修复 — Redis KEYS 改为 SCAN（#7564、#6918、#6876），去掉了可能拖垮生产 Redis 的阻塞调用。WAR 部署启动失败（#7949）已修复——以 WAR 方式部署的用户尤其要关注；此外还有分布式事务示例（#7379）、Boot 3 默认值修正（#5935）和代码生成 schema 注解参数（#5742/#5766），因此新生成的代码会不一样；vue-router 也被固定（#7797）以保证前端构建可复现。
