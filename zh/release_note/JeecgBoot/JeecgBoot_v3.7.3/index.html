JeecgBoot v3.7.3

修订 发布时间2025年2月10日 来源jeecgboot/JeecgBoot 英文原文

JeecgBoot v3.7.3

变更流程图

亮点

  • 三套 AI 后端，一个低代码平台 — 核心变化：低代码 AI 助手现在可在 DeepSeek v3 与 ChatGPT 之间切换，并新增通过 Ollama 本地部署 DeepSeek-R1 的路径（help.jeecg.com/java/ai/DeepSeekR1.html）。对采用者而言，这意味着数据敏感场景可以把推理留在本地；项目推荐 DeepSeek v3 以获得速度与质量。留意 #7754：此前每轮新对话都会重发完整历史，升级后 prompt token 消耗和重复上下文应恢复正常。

  • 前端工具链跃升 Vite 6 — 构建栈升级到 Vite 6，antd 套餐也刷新到 3.4.19 和 4.2.6 两条线。这是升级时最容易踩坑的改动：Vite 6 是大版本跳跃，自定义构建配置、插件和 Node 版本都需重新验证。另 #7644（3.7.2 执行 install 后开发服务器报错）已修复——在信任就地升级前，先做一次干净安装和 dev-server 冒烟测试。

  • 升级路径加固（Flyway + 表结构） — 从 3.7.2 升级时，两个迁移阻塞点已解决：Flyway 自动升级失败（#7650）和 sys_announcement_send 缺少 id 主键（#7725）。这两项很关键：Flyway 跑失败或无主键表可能让就地升级静默卡住或损坏数据——发布前请确认迁移完整跑通。

  • 值得单独为它升级的 Redis 稳定性修复 — 两个影响生产的缺陷：无法释放的锁导致死锁、重复 exists 命令引发 QPS 飙升（#6876），以及针对 sys:cache:online:list* 的 ERR unknown command "keys"（#6918），后者常见于禁用 KEYS 的托管/集群 Redis。如果使用托管 Redis，这是本版本运维意义上最重要的修复。

  • JimuReport/JimuBI 1.9.3 与 JVxeTable 清理 — JimuReport 和 JimuBI 均升级到 1.9.3，并集中修复了一批低代码表单缺陷：字典处理（#7497）、单选删除不触发（#7624）、getValue 与文档不一致（#7631）、JvxeUserSelectCell 中 maxTagCount 被硬编码为 1（#7661）、textarea 重复 blur 事件（#7664）、图片上传只认第一张图（#7750），以及模糊查询 JRangeNumber 代码生成在父子表单上不渲染（#7549）。做 Online 表单的团队会看到多个长期痛点被清掉。

  • 破坏性变更 — 没有明确标注；Vite 6 大版本升级是唯一有实际升级风险的变化，因此前端构建是唯一需要冒烟测试的领域。

升级日志

春节被DeepSeek刷屏了，这款火出圈的产品JeecgBoot速速跟上，最新版已经装备三个AI大模型：DeepSeek v3版、ChatGPT 和 [DeepSeek-R1本地大模型](https://help.jeecg.com/java/ai/DeepSeekR1.html “DeepSeek-R1大模型本地化”），推荐使用DeepSeek速度更快、质量更高。
