WeKnora v0.4.0

小版本 发布时间2026年4月15日 来源Tencent/WeKnora 英文原文

变更架构图

亮点

  • VectorStore 成为一等、API 可管理的资源 — 本版本把向量存储从隐式管道变成可管理实体：schema/迁移与仓库层（#922）、带连接测试的服务层（#933），以及 CRUD API 端点和文档（#934）。对采用者而言，现在可以通过 API 配置和验证向量后端，而不必改配置再重启；升级时会有新迁移，并在摄取前用连接测试快速暴露错误凭据。
  • 模型提供方大幅扩展，并支持超时控制 — Azure OpenAI 远程模型（#925）、Ollama（#930）和百度（#944）网页搜索提供方，以及覆盖 chat/embedding/rerank 的 WeKnoraCloud 提供方（带签名 docreader #927）和凭据管理/状态检查（#961），后续还扩展 VLM 支持（#974）。结合可自定义的代理 LLM 调用超时（#916），如果你此前受制于提供方锁定或慢模型挂起，这就是值得采用的版本——不过同时运行两家云提供方集成时，切换前应确认哪条路径负责 embedding/rerank。
  • 存储与加密内部改动带来破坏性变更 — OSS 服务从 AWS S3 SDK 迁移到阿里云 OSS SDK v2（#956），并新增阿里云存储配置（#949）；S3 兼容部署需要重新检查端点、凭据和 bucket 设置，而不能假设无缝替换。同时 CryptoService 被普通 AES 工具函数取代（#954），任何直接调用该服务的下游代码都必须重写——这是真正的 API 破坏，不只是重构。好消息是 MINIO_ENDPOINT 终于可通过环境变量配置（#911），消除了部署上的一个痛点。
  • 视频多模态上线后又立即移除 — 视频支持在 #926 中加入，并跟随一个迁移版本冲突修复（000032 → 000033，#937），但随后视频解析器被彻底移除（#966）。净效果：不要在 v0.4.0 上基于视频摄取做开发；实际发布的功能集不包含它。需要注意迁移重新编号——任何在预发布构建上应用过原始 000032 迁移的人，升级前应验证 schema 状态，因为两个版本占用了同一个编号。
  • IM 与连接器渠道获得面向生产的加固 — 微信集成支持二维码登录和长轮询（#946），并加入 Notion 连接器（#923）和附件支持（#935）；私有化 WeCom 部署现在可指向自定义端点（#955）。值得注意的是，<kb> 和 <web> 引用标签在发送到 IM 前会被剥离（#947）——这项变更净化了消息，但意味着依赖这些标签判断来源的下游消费者会失去该信号。
  • 桌面/Lite 版与 Windows 构建健壮性提升，并有一个编译器 workaround 需了解 — 基于 Wails 的桌面应用加上 Lite 自动配置和 UI 工作（#938、#941）新增了自动配置失败处理（#976），服务启动现使用重试机制及平台特定的关闭信号（#939）。对 Windows 上的 Go 1.24，neo4j 驱动先从 v6 降级到 v5（#942），随后回退到 v6 并采用 -p=1 构建 workaround（#943）——Windows 构建者应采用该 flag，而不是固定旧版驱动。
