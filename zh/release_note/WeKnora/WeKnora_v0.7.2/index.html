WeKnora v0.7.2

修订 发布时间2026年8月7日 来源Tencent/WeKnora 英文原文

WeKnora v0.7.2

这个项目是干啥的：一个能基于你自己的文档资料回答问题的知识库系统，支持多个知识库和翻译，给想搭智能客服的公司用。

变更架构图

亮点

  • MCP server 基于 2.x 高层 API 重建 — #2420 将 server 迁移到 MCP 高层 MCPServer API（v1.1.0），而 #2395 单独把 Python SDK 固定到 1.x——两条不同的版本线，升级前请确认是哪一条在管控你的客户端。真正阻碍采用的是协议级修复：#2375 修正导致初始化失败的 SSE 消息路由，#2371 将诊断信息移到 stderr 使 stdio 传输不再崩溃，#2422 接受非 UUID 的 Agent ID。新增工具：list_shared_knowledge_bases（#2497）和 create_knowledge_from_text（#2532）。如果你依赖旧的低层 server 接线，请留意启动回归。
  • Wiki 变得可编辑、可版本化 — #2336 新增页面修订历史，支持差异对比、回滚和手动编辑，#2338/#2547 完善了修订抽屉与阅读器布局。归档页面现从 lint 游标和统计中排除（#2503、#2549），创建页面时文件夹路径得以保留（#2429）。重要性：wiki 从只追加的笔记变为可治理的内容——但回滚会重写内容，因此请把修订历史当作新的审计面。
  • 分块与检索正确性全面梳理 — 一批改动改变了检索器实际看到的内容：确定性合并顺序（#2319）、尊重流水线改写后位置的重叠裁剪（#2555、#2556、#2558）、带检索元数据的可编辑分块（#2370），以及预览/切分器对齐（含规范化行尾）（#2539、#2541、#2546）。存储卫生同样重要：批量删除现清理绑定的向量库（#2329），缺失的向量引擎按需重建（#2357），SQLite 在 top-k 前先过滤向量候选（#2440）——如果 SQLite 结果发生变化，原因就在这里。另修复：异步段落索引导致评估指标恒为零的问题（#2359）。
  • 多副本部署的 IM 稳定性 — #2349 和 #2365 加固连接生命周期，并在 leader lock 丢失后恢复渠道；#2551 和 #2557 修复 WeCom 长连接死锁，并将连接关闭限定在所属代次。如果你运行多个副本，这些就是止住渠道抖动的关键修复。集成扩展包括：通过 blocks API 同步飞书 docx 及按类型下钻（#2334）、飞书云盘数据源（#2466），以及 QQBot markdown 回复（#2483）。
  • 认证与权限行为变化 — #2568 不再在哈希前净化注册密码，因此含特殊字符的新账号会严格按输入内容哈希（现有哈希不受影响）；如果你的注册流程会剥离或转换输入，这点值得注意。内部重组为按领域拆分的路由与统一的认证会话上下文（#2331），共享代理的源权限得到加固（#2417），#2421 让 embedding 运行时读取自己的会话——修复了 500 错误和刷新后丢失会话的问题。
  • 存储、API 与升级提示 — S3 用户可以依赖 AWS “NoAk” 默认凭据，如 IRSA/实例角色（#2008），resource_urls=public 返回可直接加载的文件 URL（#2531）——对嵌入场景很方便，但要检查暴露风险。迁移 000076 被重新编号（#2340），部署文档在早期文档补充被回退（#2571、#2572）后统一到 docker compose pull 指引（#2574、#2576）：升级时请拉取新镜像，而不是复用缓存标签，否则可能运行旧 schema。
