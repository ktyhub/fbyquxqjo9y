WeKnora v0.6.1

修订 发布时间2026年6月5日 来源Tencent/WeKnora 英文原文

WeKnora v0.6.1

变更流程图

亮点

  • CLI 线路契约破坏性变更——重写你的自动化 — PR #1475 带来 feat(cli)! 的 v0.7 agent 优先线路契约与命令面清理；这个 ! 是认真的：使用旧命令语法的 shell 脚本和 CI 任务在升级后会失败，需要按新契约重写。后续 PR #1510 新增 --dry-run、MCP 注解和会话 continue-stream，因此切换前请先用 dry-run 模式验证流水线。这是 v0.6.1 中唯一需要迁移规划而非直接覆盖升级的项。
  • OpenSearch 成为一等向量后端 — 这是有意为之的四 PR 上线：准备（#1445）、带开关的骨架（#1481）、读/写路径（#1482），最终启用 k-NN 驱动（#1542）。如果你一直在等一个可自托管的 Milvus/Qdrant/ES/Doris 替代方案，就是它了。配合 #1608（Milvus 数据库选择），并注意 #1611 现在会拒绝跨存储的 reuse_vectors 知识迁移——切换存储时应计划重新 embedding，而非搬迁向量。
  • 内置模型转向声明式配置即代码 — #1453 引入基于 YAML 的模型定义，支持 ${ENV} 插值（不要把 API Key 提交进 YAML），#1483 新增生命周期语义：删除、复活及默认不变量保护。新增 display_name 列（#1547）和原生 Gemini embeddings（#1571）一并落地，还有 MiniMax-M3（#1569）及按模型配置思考模式（#1613）。部署前请执行迁移，并把默认不变量当作防止误删兜底模型的护栏。
  • 平台运维与多租户安全显著加强 — #1493 提供统一的系统管理控制台和平台审计日志，#1504 为 invite_only 模式新增多次可用的分享链接邀请（封闭部署不再需要逐用户开通账号）。如果你向租户暴露端点配置，安全相关改动包括：#1596 依据 SSRF 策略校验向量库连接地址，#1581 为异步 goroutine 增加 panic 恢复，避免单个坏事件拖垮 worker。
  • 检索与摄取加固，避免静默失败 — #1484 在重排序 API 失败时回退到原始检索结果（不再因重排序器抖动而返回空答案），#1555 按文本重叠拼接分块而非按位置，修复了重排/乱序分块的质量回退。摄取侧：可取消的解析与终结态（#1522）、trace 时间线中的停止解析控件（#1549）、可靠的终结计数（#1552），以及 embedding 前清理内联图片载荷（#1536、#1546）。预期“卡在 99%”的文档更少，解析状态更可观测。
  • 值得客户端审查的 API 与 MCP 面变化 — /knowledge/search 现接受 ?query= 别名但拒绝空关键词（#1612），依赖空关键词“列出全部”行为的客户端会失效。MCP 通过 Python server 新增只读 wiki 工具（#1502），并支持多传输及恢复会话配置（#1490）；Doris 现在内联 LIMIT/OFFSET 字面量并做参数插值（#1488），Elasticsearch 搜索排除 embedding 字段以减小响应体（#1433）。请特别针对 #1612 检查所有直接 API 消费者。
