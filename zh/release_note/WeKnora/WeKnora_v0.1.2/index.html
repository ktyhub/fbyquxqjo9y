WeKnora v0.1.2

修订 发布时间2025年9月10日 来源Tencent/WeKnora 英文原文

WeKnora v0.1.2

变更流程图

亮点

  • 构建工具迁移（破坏性） — make docker-build 被移除；请更新 CI 改用 make docker-build-app、make docker-build-docreader、make docker-build-frontend 或 make docker-build-all。make docker-restart 不再重建镜像。虽然目标会检测宿主机平台，但 DocReader Dockerfile 仍下载 x86_64 的 protoc 和 amd64 的健康探针，因此 ARM64 源码构建并非开箱即用。
  • OCR 镜像与运行时变更 — DocReader 从 PP-OCRv5 切换到 PP-OCRv4，启用方向分类，强制 PaddleOCR 使用 CPU，并将模型文件烘焙进镜像。请重建或重新拉取 wechatopenai/weknora-docreader；预期首次使用时的下载更少、OCR 精度与延迟可能不同，且没有 PaddleOCR GPU 加速。
  • 图片摄取现改为串行 — 单图和单分块并发上限都封顶为 1，修复了竞态和资源争用错误，但会覆盖更高的 max_concurrent_tasks 值。请为更慢的多模态摄取做好规划；应在 gRPC 负载均衡器后扩展 DocReader 副本，而不是提高旧设置。
  • 启动就绪与 COS 部署 — 新增 gRPC 健康服务和 grpc_health_probe 检查，防止 DocReader 就绪前启动应用。非 Compose 部署需要等效的 gRPC 探针和足够的 OCR 初始化启动时间。Compose 现在也把 COS_* 设置转发给 app，修复 COS 启动失败（issue #223）；请确保 .env 中填充了这些变量。
  • 可配置主机端口 — APP_PORT、FRONTEND_PORT 和 DOCREADER_PORT 仅改变发布的主机端口，默认分别为 8080、80 和 50051。容器端口和 DOCREADER_ADDR=docreader:50051 保持不变，因此重新映射时请更新反向代理、防火墙规则和外部探针。
  • 检索健壮性与 DashScope 重排序 — 空 LLM 改写响应现在保留原查询，而不是替换成空检索字符串。后端还会在配置的 URL 包含其精确端点时自动选择阿里云 DashScope 重排序；请提供完整端点，并避免调试日志，因为适配器会记录 bearer API Key。

主要更新

🐛 错误修复

  • 健康检查: 修复了文档读取器服务的健康检查实现
  • 查询处理: 改进了空查询的处理逻辑
  • OCR模型: 修复了Docker容器中OCR模型预加载的问题
  • 并发处理: 解决了图像解析器的并发错误
  • Makefile: 修复了Docker构建相关的问题

✨ 功能增强

  • 知识库管理: 增强了知识库列值更新方法
  • 端口配置: 新增支持修改监听端口配置

📚 文档更新

  • 添加了Markdown文件处理解析的文档说明
  • 完善了文档处理流程的说明 完整 Changelog：https://github.com/Tencent/WeKnora/compare/v0.1.0…v0.1.2
