WeKnora v0.3.2

修订 发布时间2026年3月4日 来源Tencent/WeKnora 英文原文

WeKnora v0.3.2

这个项目是干啥的：一个能基于你自己的文档资料回答问题的知识库系统，支持多个知识库和翻译，给想搭智能客服的公司用。

变更架构图

亮点

  • 异步重新解析与远程 URL 摄取 — #679 新增异步知识重新解析 API（含示例），#696 支持直接从远程文件 URL 创建知识。两者结合让摄取流水线可以重新索引已有文档，并从 HTTP/对象存储来源拉取数据，无需绕道本地上传。需要围绕异步形态来设计：重新解析不再是调用即返回，你需要轮询状态或接入完成回调。
  • 存储与 Doc Processor 重构 — #704 是架构上的核心，绝不只是内部清理：存储与文档处理被大幅改造，任何自定义存储层或 doc-processor 接线都应视为集成点发生了迁移。它伴随 #705 落地，后者为向量 embedding 新增 TagID 和 IsRecommended 字段——这是存储 schema 变更。请计划重新 embedding/重建索引，而不是假设现有向量会自动带上新字段。
  • 需要配置迁移：MinerU 端点已移除 — #706 从 ParserEngineConfig 及相关组件中移除了 mineru_api_base_url。如果你通过该字段把 MinerU 指向自托管或自定义端点，升级后该设置会被忽略（或导致配置校验失败）。这是本版本唯一真正的破坏性变更——上线前请审查解析器配置。
  • 新后端：Milvus 与火山引擎 TOS — #699 新增 Milvus 作为检索向量数据库，#691 新增火山引擎 TOS 作为对象存储后端，扩展了此前受限于既有选项的部署目标。它们是增量新增而非替换，但各自都是全新的集成面——值得在预发环境验证，尤其是叠加在 #704 存储重构之上时。
  • 部署与 API 面变化 — Helm 前端 APP_HOST 默认值改为 app（#694）。如果依赖旧默认值，请在 chart 升级后验证 ingress/前端仍能访问应用。#698 修复 Swagger 生成并重新生成文档，因此请针对新 spec 重新生成 API 客户端。#695 让表单校验容忍非布尔响应——如果你的认证提供方返回真值字符串而非 JSON 布尔值，这点很相关。
  • 聊天体验与推理模型优化 — #689 修复 Ollama 聊天响应中“thinking”内容的处理，推理模型输出不再泄漏到流式回复或破坏其解析。UI 方面：批量会话管理（#692，以及 #703 支持批量模式加载所有会话）、Mermaid 图渲染（#702），以及用户级记忆图谱预览（#687）——如果你向终端用户提供多会话聊天或知识图谱，这些很实用。
