WeKnora v0.2.1

修订 发布时间2025年12月8日 来源Tencent/WeKnora 英文原文

WeKnora v0.2.1

变更流程图

亮点

  • Qdrant 成为一等检索器 — v0.2.1 新增 Qdrant 作为完整检索引擎，同时支持向量相似度和全文关键词检索，并为关键词查询提供基于 jieba 的中文分词。对开发者而言，这解锁了混合中英文语料的混合检索，无需单独的分词服务。请注意集合命名：集合由 embedding 维度派生（weknora_embeddings_768），因此切换到不同向量大小的模型会静默指向一个全新的空集合，而不是复用现有数据。
  • 检索器配置迁移到 RETRIEVE_DRIVER — 引擎选择现在由 RETRIEVE_DRIVER 环境变量驱动，GetEffectiveEngines() 负责动态解析，引擎映射集中在 types/tenant.go。关键是，用户注册时不再写入检索器配置。这简化了租户开通并去掉了一次按用户配置写入，但这是主要的迁移点：依赖注册时配置的部署或集成测试现在必须设置该环境变量，否则会回退到默认引擎。
  • Docker Compose profiles 可运行精简技术栈 — 新增 profile（minio、qdrant、neo4j、jaeger、full）及对应的 dev.sh 参数（--minio、--qdrant 等）取代了全有或全无的启动方式，因此你可以只拉起某个检索器所需的基础服务。Qdrant 固定到 v1.16.2，稳定了升级，但意味着你需要显式选择更新的 Qdrant 版本，而不是继承它们。
  • 迁移现在能容忍部分启动 — 失败迁移的自动脏状态恢复，以及 Neo4j 连接重试配合指数退避，让容器化部署中 Neo4j 在迁移时可能尚未就绪的场景安全得多。配合改进的迁移错误日志，这消除了“迁移一半、无法重启”这一此前需要人工干预的常见根源。
  • 两个值得升级的修复 — 修复了 Qdrant 关键词搜索对中文查询返回空结果的问题，因此新引擎上的中文用户应升级，而不是继续评估 v0.2.1 的前一版本。图片 URL 校验也简化以提高兼容性，这是一次有意放宽，接受的输入比之前更多——如果你此前在绕过更严格的拒绝，这点很相关。

[0.2.1] - 2025-12-08

🚀 新功能

  • 新：Qdrant 矢量数据库支持
    • 与 Qdrant 完全集成作为检索引擎
    • 同时支持向量相似度搜索和全文关键词搜索
    • 基于嵌入维度的动态集合创建（例如，weknora_embeddings_768）
    • 使用jieba专业中文分词进行关键词查询

⚡ 基础设施改善

  • 改进：Docker 撰写配置文件管理
    • 添加了可选服务的配置文件：minio、qdrant、neo4j、jaeger、full
    • 增强了 dev.sh 脚本，带有 --minio、--qdrant、--neo4j、--jaeger、--full 标志
    • 将 Qdrant Docker 映像版本固定到 v1.16.2 以确保稳定性
  • 改进：数据库迁移系统
    • 为失败的迁移添加了自动脏状态恢复
    • 添加了具有指数退避功能的 Neo4j 连接重试机制
    • 改进了迁移错误处理和日志记录
  • 改进：猎犬引擎配置
    • 检索器引擎现在从 RETRIEVE_DRIVER 环境变量自动配置
    • 用户注册期间不再需要编写检索器配置
    • 添加了动态引擎分辨率的 GetEffectiveEngines() 方法
    • types/tenant.go 中的集中式发动机映射

🐛 错误修复

  • 已修复：Qdrant 关键字搜索对于中文查询返回空结果
  • 修复：简化图像 URL 验证逻辑以获得更好的兼容性
