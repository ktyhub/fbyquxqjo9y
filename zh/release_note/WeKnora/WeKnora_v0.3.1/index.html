WeKnora v0.3.1

修订 发布时间2026年2月10日 来源Tencent/WeKnora 英文原文

WeKnora v0.3.1

这个项目是干啥的：一个能基于你自己的文档资料回答问题的知识库系统，支持多个知识库和翻译，给想搭智能客服的公司用。

变更架构图

亮点

  • 远程后端与 HTTPS 代理 — Nginx 现在可通过 APP_HOST、APP_BACKEND_PORT 和 APP_SCHEME=https 指向单独部署的后端（#672）。APP_PORT 现在只控制主机端口映射；远程部署应移除前端的 depends_on: app，本地默认值不变。
  • 兼容 MinIO 的数据分析 — CSV、XLS 和 XLSX 知识文件现在通过 GetFileURL 预签名 URL 加载，而非容器内本地路径，修复了 MinIO 下代理分析和表格摘要失败的问题（#676）。请确保生成的对象存储 URL 能从 DuckDB 进程访问。
  • DuckDB spatial 初始化 — 启动现在先执行 INSTALL spatial 再 LOAD spatial，修复全新环境中扩展缺失的失败（#677）。离线或隔离网络部署应预先缓存该扩展并验证空间工作负载，因为安装失败仅记录为警告。
  • HTTP 下的剪贴板兼容性 — 复制操作现在优先使用 navigator.clipboard，并回退到 document.execCommand('copy')，覆盖邀请码与链接、API 详情和检索分块（#678）。这恢复了非安全 LAN 部署上的功能，但生产环境仍推荐 HTTPS。
  • 共享知识库发现 — 共享知识库现在出现在空间侧边栏和知识库列表中，代理编辑器将“我的”与“协作的”知识库分开并用中英文标签标注（#680），让团队资源更容易发现和选择。
  • 破坏性变更 — 无。

发生了什么变化

  • 壮举：通过https://github.com/Tencent/WeKnora/pull/672中的@lyingbug支持远程后端和HTTPS代理
  • 修复（数据分析）：通过 @Dounx 在 https://github.com/Tencent/WeKnora/pull/676 中预先签名的 URL 加载知识文件 *修复：@Dounx在https://github.com/Tencent/WeKnora/pull/677中找不到duckdb空间扩展错误
  • 修复：通过 @tsukiga-kirei 在 https://github.com/Tencent/WeKnora/pull/678 中添加 clipboard API 非安全上下文的后备
  • feat(ui)：通过https://github.com/Tencent/WeKnora/pull/680中的@lyingbug增强ListSpaceSidebar和KnowledgeBaseList中的资源管理
