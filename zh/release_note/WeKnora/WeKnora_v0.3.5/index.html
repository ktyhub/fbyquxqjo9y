WeKnora v0.3.5

修订 发布时间2026年3月27日 来源Tencent/WeKnora 英文原文

变更流程图

亮点

  • 破坏性：MCP 工具命名与 Milvus 度量类型 — MCP 工具现在以服务名而非 UUID 命名（PR #783，修复 #715），任何引用基于 UUID 工具名的客户端或自动化都必须更新。另外，Milvus 向量检索从 IP 切换到 COSINE（PR #802）；由于度量类型在索引创建时固定，现有基于 IP 的集合/索引很可能需要删除重建才能生效。这两项是最可能需要迁移工作的改动。
  • 安全与数据完整性加固 — RemoteAPIChat 的 SSRF 防护得到加强（PR #811），对暴露该端点的用户很重要。租户设置更新不再有丢失 api_key 加密的风险（PR #800），知识库创建现在遵循全局默认存储引擎而非覆盖它（PR #784）。如果你管理租户或暴露远程聊天，这些修复让升级强烈建议。
  • 新提供方与 IM 渠道 — 新增 OpenRouter 作为 embedding 提供方（PR #780）、Novita AI 作为 LLM 提供方（PR #794），将 MiniMax 模型从 M2.1 升级到 M2.7（PR #812），并通过 IM 优化、新平台（PR #774、PR #796）和 Mattermost 渠道（PR #820）扩展即时通讯支持。这是后端与渠道选择的实质扩展，不过大多是增量新增而非行为改变。
  • 代理能力 — 新增 GetSuggestedQuestions API，提供针对代理的问题建议（PR #809）；通过 VLM 自动描述 MCP 工具结果图片（PR #808）；改进提示词模板中的上下文/意图分类（PR #814）；修复未配置知识库时的空响应（PR #819）。对在 WeKnora 之上构建代理的团队值得升级。
  • 聊天/前端正确性与开发体验 — 净化时保留图片 markdown（PR #789）；通过绕过 go-openai 限制支持 vLLM 原生推理（PR #791）；修复 markdown 代码块渲染（PR #797）和摘要回退中的 UTF-8 截断（PR #813）；重置知识文件页计数器（PR #790）；过滤空段落以避免阿里云重排序错误（PR #806）；以及首次运行开发配置修复（PR #779）和缺失的 i18n 键（PR #804、PR #801）。净效果：推荐大多数用户升级；只有当你依赖 UUID MCP 工具名或 IP 度量的 Milvus 索引、且尚未准备重建索引时才暂缓。
