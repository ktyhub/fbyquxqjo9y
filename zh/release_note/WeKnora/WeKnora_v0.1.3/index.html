WeKnora v0.1.3

修订 发布时间2025年9月16日 来源Tencent/WeKnora 英文原文

WeKnora v0.1.3

变更流程图

亮点

  • 认证与会话 — 新增登录/注册、租户感知的访问控制、受保护路由、JWT access/refresh token，以及 401 时自动刷新（#301）。请更新浏览器自动化和深链以处理 /login；token 持久化在 localStorage 中，因此请强制 HTTPS 和严格的 CSP。
  • 前端集成变更 — 内置客户端用 Authorization: Bearer <token> 取代了 X-API-Key 和 WeKnora_settings 运行时覆盖（#301）。依赖运行时端点、API Key 或知识库选择的自定义前端需要改造。
  • 密钥泄露与 XSS 加固 — 初始化状态响应现在不再返回模型 API Key（#294），Markdown、聊天和文档 HTML 用 DOMPurify 净化，并校验图片 URL（#299）。请轮换可能已泄露的 Key，更新期望取回 Key 的客户端，并审查新的 CSP——它仍允许 unsafe-inline 和 unsafe-eval。
  • 需要 COS 迁移 — COS 初始化现在使用 COS_BUCKET_NAME 而非 COS_APP_ID，并修正了上传/下载的 bucket URL 构造（#300）。请在 .env/Compose 中重命名该变量，否则启动会因“缺少 COS 配置”失败；之后请做文件往返冒烟测试。
  • OCR 与多架构支持 — OCR 启动新增 AVX 检测和 PaddleOCR 兼容处理（#275）；docreader 构建根据 TARGETARCH 选择 protoc 和 grpc_health_probe，而非硬编码 amd64（#291）。请重建镜像，并在较老的 x86 和 ARM64 主机上验证 OCR 与 gRPC 健康检查。
  • 容器运维 — app 和 docreader 现在直接运行，app 容器以非 root 运行，日志输出到 stdout/stderr 而非 supervisor 管理的文件（#283）。前端也会等待后端健康后再启动（#277）。请更新日志采集、bind mount 权限、重启假设和启动超时。

  • 壮举：通过 https://github.com/Tencent/WeKnora/pull/283 中的 @lyingbug 调整应用程序和 Docreader 日志输出

  • 修复（ui）：为了安全起见，@lyingbug 在 https://github.com/Tencent/WeKnora/pull/294 中忽略显示 APIKEY
  • 杂务（文档）：通过 @lyingbug 在 https://github.com/Tencent/WeKnora/pull/295 中修复文档拼写 *修复（ui）：修复https://github.com/Tencent/WeKnora/pull/299中@lyingbug的xss攻击
