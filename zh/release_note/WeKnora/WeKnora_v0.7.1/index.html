WeKnora v0.7.1

这个项目是干啥的：一个能基于你自己的文档资料回答问题的知识库系统，支持多个知识库和翻译，给想搭智能客服的公司用。

变更架构图

亮点

  • 链路追踪迁移到 OTLP/OTel — Langfuse 现在使用 OTLP/OTel 线路协议（#2099），并合并结束元数据、自动导出根 span（#2111）。请更新可观测性配置并验证 collector 接收，尤其是已修正的图谱与多模态 trace（#2190）。
  • 移除 Neo4j 对话记忆 — 这是主要的破坏性变更（#2130）。依赖 Neo4j 支撑记忆的部署必须在升级前修改受影响的工作流；更新日志未记录可直接替换的方案。
  • API Key 获得更安全的控制面作用域 — 平台级 Key（#2165）、限定范围的文件服务与摄取路由（#2154），以及禁止通过 API Key 分配 owner 角色（#2225），都要求重新审查并收窄自动化凭据的范围。源文件下载也限制为 Editor 及以上（#2250）。
  • 重排序与检索行为变化 — 火山引擎重排序现在会对超出 API 文档上限的请求分批（#2147、#2155）。vLLM 调用默认不再发送 truncate_prompt_tokens（#2160），请验证后端侧的截断与上下文限制。稳定的 top-k 排序（#2091）也可能改变回归测试中结果的精确顺序。
  • 知识库生命周期修复减少陈旧数据 — 摄取超时不再留下挂起任务（#2106），删除知识库时无需依赖请求上下文即可清除排队工作（#2202、#2215），异步删除也不再留下可见的僵尸行（#2195）。克隆/导出修复还保留了分块及父文本中的图片 URL（#2183、#2188、#2191）。
  • 自托管部署需要做配置检查 — Compose 环境变量现与代码一致，并修复了 Helm GraphRAG 的 bug（#2164），请让部署清单与当前示例对齐。PDF 渲染并行度现在遵循基于 CPU 的默认值（#2168），而 embedding/模型客户端与 Doris Stream Load 共享 SSRF 安全的 HTTP 传输（#2201、#2213、#2276）；请相应重新验证自定义内部端点。
