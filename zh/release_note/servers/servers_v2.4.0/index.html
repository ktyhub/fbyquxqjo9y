servers v2.4.0

安全修复

v2.4.0修复了三台服务器中的六个漏洞。升级@modelcontextprotocol/server-filesystem至2.3.0， 以及 mcp-server-git 和 mcp-server-fetch 至 2026.11.11。

套餐 受影响 固定在
@modelcontextprotocol/server-filesystem 2.3.0 之前的所有版本以及 2025.1.14 到 2026.8.31 的最新版本 2.3.0
mcp-server-git 通过2026.11.4 2026.11.11
mcp-server-fetch 通过2026.11.4 2026.11.11

@modelcontextprotocol/server-filesystem 2.3.0

  • 读取保留在已检查的文件中（Linux 和 macOS）。读取工具和文件资源现在打开一个相对于所检查的目录的文件，就像写入已经做的那样，因此在访问检查和读取之间交换符号链接的目录不能再从允许的目录之外返回文件。 FIFO、套接字或设备被拒绝而不是读取。 在 Windows 上，这会缩小竞争范围但不会结束，至于写入 (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file 仅移动它检查的源。 一个设备内的移动首先以新名称将源从其自己的检查目录中取出，因此交换为符号链接的源目录不能再将外部文件带入允许的目录中，在该目录中该文件将变得可读（GHSA-7m4x-rv66-mxhh）

mcp-server-git 2026.11.11

  • 存储库自己的 Git 配置不再能让服务器运行程序。 untrusted 存储库上的只读调用（例如 git_status）用于使用服务器的权限运行其 .git/config 中命名的命令（core.fsmonitor、diff.external、挂钩、过滤和合并驱动程序、签名）。现在每个 Git 命令都会覆盖这些设置，并且早于 2.31 的 Git 将忽略覆盖，被拒绝 (GHSA-6hqx-gqrx-c5r2)
  • --repository 限制涵盖了替代对象存储、链接工作树和 Git 目录中的链接。 允许的存储库内的存储库可以通过 objects/info/alternates 读取另一个存储库的对象，或者将链接工作树的 Git 目录作为允许的存储库传递。两者都被拒绝，Git 目录中的符号链接通向允许的存储库之外也是如此。 在 Windows 上，尚未覆盖目录连接 (#5520) (GHSA-q74p-4wrc-q7w6)

mcp-server-fetch 2026.11.11

  • IPv6 站点本地地址是私有的。 私有地址防护将 fec0::/10 读取为公共地址。现在已被拒绝，全球单播 (2000::/3) 之外的任何不携带 IPv4 地址 (GHSA-3rxj-6jhw-qfv7) 的 IPv6 地址也被拒绝
  • **robots.txt 与站点将解析的路径以及写入的路径相匹配，因此 //private 或 /x/../private 无法再通过 Disallow: /private (GHSA-f9hh-cmx9-2f23)

从日期版本的 npm 版本升级

TypeScript 服务器从日期版本（2025.x、2026.x）迁移到 1.0.0 中的语义版本。软件包管理器将 2.3.0 的排名低于每个 2025.x 和 2026.x 版本，因此他们不会将其作为升级提供。如果您使用的是 @modelcontextprotocol/server-filesystem 的日期版本，请显式安装 2.3.0：npm install @modelcontextprotocol/server-filesystem@2.3.0。
