servers v2.5.0

安全修复

v2.5.0修复了三台服务器中的八个漏洞。升级mcp-server-git至2026.11.18， @modelcontextprotocol/server-filesystem 至 2.4.0 和 @modelcontextprotocol/server-everything 至 2.3.1。

mcp-server-git 2026.11.18

  • 合并不再启动 Git 的自动维护。 成功的 git_merge（包括快进）以 git maintenance run --auto 结束，其垃圾收集以存储库自己的 gc.recentObjectsHook 名称运行命令，并具有服务器的权限。对于服务器运行的每个 Git 命令，maintenance.auto 现在是 false，gc.auto 是 0 (GHSA-h2g3-rwxm-xfm3)
  • Git 永远不会自己获取丢失的对象。 存储库的配置可以声明一个承诺者远程并命名 Git 运行以从中获取的程序（remote.<name>.uploadpack、core.sshCommand），然后当它需要不在磁盘上的对象时启动只读工具。延迟获取已关闭 (GIT_NO_LAZY_FETCH=1)，Git 太旧而无法兑现，拒绝声明承诺者远程的存储库 (GHSA-87qg-cmw8-jc5m)
  • 工具写入工作树后会再次读取驱动程序。 存储库的配置可以包含合并或签出创建的文件，因此过滤器或合并驱动程序可能会在服务器清空其找到的驱动程序后出现，并在冲突后的 git merge --abort 期间运行。 git_checkout、git_merge 和中止现在在任何其他 Git 命令运行之前再次读取驱动程序。 这样的写入后，--repository 限制检查尚未重复 (#5599) (GHSA-9vjp-x34c-xg6v)
  • 名称为空的过滤器或合并驱动程序也会被清空。 Git 接受 [filter ""]，由 .gitattributes 中的 filter= 选择，而服务器的存储库驱动程序列表错过了它，因此它的命令运行了 (GHSA-pm7p-vphh-2cg7)
  • 指向工作树之外的索引条目将被拒绝。 对于 --repository，精心设计的 .git/index 命名路径（例如 ../outside/secret）使 git_diff_unstaged 和 git_diff 返回该文件的内容，而 git_status 则报告该文件是否存在。现在，在任何工具读取索引之前，都会从顶部检查索引，并且可以关闭可以命名工作树外部目录的未跟踪缓存（[GHSA-r2q8-f657-4r56]（https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-r2q8-f657-4r56））
  • 子模块自己的配置不再运行程序。 使用存储库配置中的 diff.submodule=diff，git_diff 在子模块自己的 diff.external 和 textconv 驱动程序下的每个更改的子模块内运行嵌套差异，并且 git_checkout 和 git_add 也在其自己的配置下的子模块内运行 Git。 diff.submodule 现在是 short，签出子模块定义的驱动程序被覆盖，并且对于已签出的存储库，拒绝早于 2.33 的 Git（不会将覆盖传递到子模块）（GHSA-8wv7-r664-7594）

@modelcontextprotocol/server-filesystem 2.4.0

  • 目录列表保留在已检查的目录中（Linux 和 macOS）。 list_directory、list_directory_with_sizes、directory_tree 和 search_files 现在会在检查后列出目录，因此在检查和列表之间交换符号链接的目录不能再返回允许目录之外的条目名称。 在 Windows 上，列表尚未锚定 (#5600) (GHSA-rq2p-q7c4-6g27)

@modelcontextprotocol/server-everything 2.3.1

  • gzip-file-as-resource 将 NAT64 地址视为其携带的 IPv4 地址。 该工具的私有地址防护将 64:ff9b::/96 中的地址读取为公共地址，因此在具有 NAT64 网关的网络上，URL 可以通过该地址到达私有 IPv4 地址。现在检查嵌入的 IPv4 地址 (GHSA-38j4-j742-j7r3)

从日期版本的 npm 版本升级

TypeScript 服务器从日期版本（2025.x、2026.x）迁移到 1.0.0 中的语义版本。软件包管理器将 2.4.0 的排名低于每个 2025.x 和 2026.x 版本，因此他们不会将其作为升级提供。如果您使用的是 @modelcontextprotocol/server-filesystem 的日期版本，请显式安装 2.4.0：npm install @modelcontextprotocol/server-filesystem@2.4.0。
