servers v2.1.0

安全修复

v2.1.0修复了三台服务器中的八个漏洞。升级 @modelcontextprotocol/server-filesystem 和 @modelcontextprotocol/server-everything 至 2.0.1，以及 mcp-server-fetch 至 2026.10.24。

套餐 受影响 固定在
@modelcontextprotocol/server-filesystem 1.0.0 至 2.0.0，以及日期版本至 2026.8.31 2.0.1
@modelcontextprotocol/server-everything 1.0.0 至 2.0.0，以及日期版本 2025.9.24 至 2026.8.31 2.0.1
mcp-server-fetch 通过 2026.10.19 2026.10.24

@modelcontextprotocol/server-filesystem 2.0.1

  • 写入保留在已检查的目录中（Linux 和 macOS）。访问检查和写入之间交换为符号链接的父目录无法再将 write_file、edit_file、create_directory 或 move_file 目标重定向到允许的目录之外。 在 Windows 上，这只是部分修复；该通报说明了仍然暴露的内容以及如何围绕它进行配置（[GHSA-53mr-w429-c597]（https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-53mr-w429-c597））
  • 路径按照使用时的情况进行检查。 访问检查不再删除文件操作保留的尾随引号或空格，因此无法再访问以允许的具有该后缀的目录命名的同级目录 (GHSA-7rgq-gccq-qphx)
  • 以不同字母大小写拼写的符号链接不再通过不区分大小写卷上新路径的符号链接检查，例如 macOS 的默认值。这是 2026.8.31 中的回归 (GHSA-4gxg-m5jx-9j57)
  • list_directory_with_sizes 在读取其大小之前检查每个条目，因此允许目录内的符号链接不再显示其外部文件的大小和修改时间 (GHSA-hhwq-wxfx-cj7g)

@modelcontextprotocol/server-everything 2.0.1

  • HTTP 和 SSE 传输拒绝来自其他 Web 来源的请求。 它们现在检查 Origin 标头，不再发送 Access-Control-Allow-Origin: *，因此用户访问的网页无法再调用服务器的工具（例如 get-env）或读取其结果（GHSA-mvf5-2qqv-rg3c）

mcp-server-fetch 2026.10.24

  • 地址检查和连接使用相同的主机名。 对于国际化 (IDNA) 主机名，服务器用于检查名称的一种形式并连接到另一种形式，该形式可以到达内部地址 (GHSA-v38p-wf49-hx2j)
  • NAT64 地址是根据它们携带的 IPv4 地址来判断的。 64:ff9b::/96 中包装私有、环回或链路本地 IPv4 地址的地址现在会被拒绝，因为 IPv4 映射的地址已经被拒绝 (GHSA-66qx-2266-pmj6)
  • 每次重定向后都会再次检查 robots.txt，不仅针对首次请求的 URL (GHSA-3jqg-r5pp-rmp2)

从日期版本的 npm 版本升级

TypeScript 服务器从日期版本（2025.x、2026.x）迁移到 1.0.0 中的语义版本。软件包管理器将 2.0.1 的排名低于每个 2025.x 和 2026.x 版本，因此他们不会将其作为升级提供。如果您使用的是日期版本，请显式安装 2.0.1，例如 npm install @modelcontextprotocol/server-filesystem@2.0.1。
