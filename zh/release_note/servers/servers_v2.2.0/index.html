servers v2.2.0

安全性：Node.js 运行时和 CA 证书更新（2026 年 10 月）

2026 年 10 月 20 日，eMudhra 披露其八个中间 CA 证书的私钥可以从公共证书中恢复。 10 月 21 日，Node.js 发布了安全版本，更新了其捆绑的 CA 证书以应对攻击，并修复了多个不相关的高严重性运行时 CVE。 10月23日，Python的certifi 2026.10.23移除了eMudhra根emSign Root CA - C1和emSign ECC Root CA - C3。 这些服务器的状况

  • TypeScript 服务器依赖 Node.js 运行时进行证书检查。 它们不提供自己的 CA 证书。只有 server-everything 发出出站 HTTPS 请求 (gzip-file-as-resource)，并且其运行的 Node.js 会验证这些请求。 server-filesystem、server-memory 和 server-sequential-thinking 不进行网络连接。
  • mcp-server-fetch 通过 httpx 针对 certifi 捆绑包验证 HTTPS。从 PyPI（uvx mcp-server-fetch、pip install mcp-server-fetch）安装可解决当前的 certifi、ZZPH100​​ZZ 或更高版本。存储库的 fetch Docker 文件从其锁定文件安装，此版本将其移至 certifi 2026.10.23 (#5341)。
  • mcp-server-git 和 mcp-server-time 不进行网络连接。 如果您从 npm 运行 TypeScript 服务器（npx 或全局安装） 它在您的 Node.js 上运行，我们无法为您更新。请运行 Node.js 24.22.1 或 26.12.1 或更高版本，并与 node --version 进行检查。包的 engines 字段接受任何 Node.js 24，因此 npm 不会警告您有关较旧的、未修补的运行时。 如果您从现有环境运行 mcp-server-fetch 10 月 23 日之前创建的环境保留其较旧的 certifi。使用 uvx --refresh mcp-server-fetch 或 pip install -U certifi 刷新它。
