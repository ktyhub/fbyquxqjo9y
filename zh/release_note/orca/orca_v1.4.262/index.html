orca v1.4.262

修订 发布时间2026年11月17日 来源stablyai/orca 英文原文

先前版本：1.4.261：重大性能改进、光标聊天和可自定义的 + 菜单。

更快的聊天切换、更低的内存使用和 git Blame ✨

在 macOS 和 Linux 上以更少的内存保持更多对话的打开，并在隐藏视图中进行更少的工作的情况下在聊天之间移动。此更新还可以帮助终端会话从您上次停下的地方继续，并将行历史记录直接放入编辑器中。

  • ⚡ 跨多个聊天进行工作： 聊天 UI 在 macOS 和 Linux 上使用更轻的助手。隐藏的聊天视图暂停更新，同时保留您的草稿、阅读位置和编辑器状态以供您返回；代理继续工作。
  • 🧹 回收磁盘空间： 设置→工作区清理可以从已删除的工作区中删除 Orca、Claude Code 和 Codex 聊天记录。默认关闭；启用它要求确认并包括以前删除的工作区。已删除的聊天记录无法恢复。
  • ⌨️ 返回相同的终端文件夹： 窗格会记住您上次在重新启动时更改目录的位置，包括文件夹工作区中。 Windows 还会修复返回繁忙窗格后的杂散字符。
  • 🔍 查看谁更改了一行： Git Blame 状态项显示光标行的作者和日期。在仓库工作区中，click 打开提交；在“设置”→“编辑器”中启用 内联 git Britain 以在代码旁边添加注释。
  • 👤 让帐户切换更清晰： 命名已保存的 Claude 和 Codex 帐户并查看他们最后观察到的计划。当您接受“重新启动”或使用“始终重新启动”时，繁忙的 Claude 终端会话将在所选帐户上恢复，而无需等待其当前工作完成。

变更架构图

亮点

  • 在一张卡中设置代理： 一起选择代理、型号和支持的工作量或快速选项，然后使用 作为聊天打开 或 作为终端打开。如果提供，默认工作量可让代理选择自己的级别。
  • 控制中断： 右键 click 工作区可将其通知静音，同时保留其未读点。睡眠工作区在重新启动后仍保持睡眠状态，工作区卡预览可让您尝试不同的样式。
  • 使用您的语言和插件： 在“设置”或“入门”中发现社区翻译。插件更新审核命名添加的访问权限并可以对批准进行分组；合格的更新可以从他们的通知中获得批准。
  • 保存远程文件供以后使用： 在远程文件链接上选择 下载… 以保存它，而无需打开其他应用程序。 Windows 还可以识别映射到 WSL 发行版的驱动器盘符上的项目文件夹。
  • 解决被阻止的 Codex 操作： 聊天解释自动审核拒绝并为该操作提供 批准一次。

兼容性和升级说明

  • Codex 历史记录共享： 启用共享后，帐户会在下次启动之前移动到一个对话存储；这可能会延迟首次启动，并且繁忙的帐户会稍后迁移。关闭共享会保留共享历史记录；长时间的对话在共享需要启用时开始。 Windows 降级后，其他帐户将回退到您的默认 Codex 登录，直到您再次更新。
  • Windows 终端： 关闭并重新打开现有终端以修复杂散字符。
  • 回购设置步骤： 对于该回购设置命令的未来版本，早期的 orca.yaml 批准现在计为 trust。 VM 创建和存储库在主机之间共享 ID 保持每个版本的批准。
