orca v1.4.241

聊天和浏览器的行为符合您的预期 🧭

此版本使聊天遵循您的代理设置，将 Chrome 风格的工具引入内置浏览器，并帮助 SSH 连接和托管服务器恢复。您还可以找到聊天字体设置、实时代理浏览以及更稳定的 Hermes、Kimi、Kiro 和 Windows 终端。

简短版本

  • 遵循您的设置的聊天： 新聊天使用设置 → 代理中每个代理的权限，重命名的聊天将其名称保留在会话历史记录中，并且聊天不会写入终端仍在运行的对话。
  • 更接近 Chrome 的浏览器： 将 DevTools 停靠在窗格内，使播放声音的选项卡静音，悬停时查看链接的 URL，并在页面内使用 Orca 快捷键和鼠标后退/前进。
  • 观看座席浏览： 光标和徽章显示座席正在 clicking 或打字的位置，聊天会将您跳转到页面，来自终端和聊天的链接会在其来源旁边打开。
  • SSH 死角更少： 保存的端口转发在重新启动后返回并解释故障，仅证书主机通过您的系统 ssh 连接，托管服务器更新而无需关闭终端。
  • 可靠地启动和恢复代理： Hermes 和 Kimi 窗格在重新启动后恢复，Kiro 报告其 V3 引擎的状态，并且代理启动时键入的密钥将保留为草稿。
  • 完善重要的地方： 选择聊天字体，在非美国键盘上使用 Cmd/Ctrl + + 进行缩放，从 macOS 终端打开仅云文件，并获得更稳定的 Windows 终端和粘贴。 电话和网络更新： 电话不再丢弃终端输出片段，聊天重命名和每个聊天的权限模式现在显示在那里。对于从未设置标题的 Windows 代理，会话选项卡还保持“正在工作”和“需要您”。

兼容性和升级说明

  • 新终端主机： 新终端在新终端主机上启动，因此适用此版本的终端修复。更新之前已打开的终端将在前一个主机上继续运行并保持连接，直到您将其关闭。
  • **聊天权限：**设置→聊天不再有自己的权限下拉菜单；在“设置”→“代理”中为每个代理进行设置。现有的聊天保留其保存的权限，并且聊天自己的权限菜单仅更改该聊天。
  • 在终端中打开对话： 如果终端可能仍在编写对话，则其聊天将不会发送，并要求您退出那里的代理或关闭该终端。关闭该终端可以让下一个发送通过。
  • 托管 SSH 服务器： 无论如何更新 使运行的终端持续进行更新。重新启动后恢复聊天的提议需要已经运行此版本的服务器。
  • OpenCode 模型选择： OpenCode 2.0.14、2.0.15、2.0.17 和 2.0.18 在选择模型时保留第一条消息未发送，因此 Orca 拒绝在这些版本上选择模型。
