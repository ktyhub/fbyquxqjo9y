orca v1.4.242

内存更轻，Claude 代理 click，远程服务器记得 🪄

此版本对内存的占用较小，终端主机和 WSL 连接中的内存使用量较低，终端中的空闲 CPU 使用量也较少。它还可以让您直接从侧边栏打开 Claude 子代理，使 Codex 聊天在询问模式下在编辑前进行询问，并帮助配对服务器、SSH 和 WSL 主机保留您的选项卡并解释故障。此版本还修复了 Windows、Linux 和 macOS 上的问题。

简短版本

  • 从侧边栏打开 Claude 子代理： Click 侧边栏或仪表板中的 Claude 子代理行，以在同一终端中打开其记录，然后 click 父代理返回。一只眼睛会标记您正在观看的人。
  • 首先询问的聊天： 询问模式下的 Codex 聊天现在会在编辑工作区之前询问，配对服务器上的远程 Claude 终端可以继续聊天，而无法开始的聊天会告诉您原因。
  • 代理在您离开时恢复： 恢复的 Claude 会话保留其工作级别和启动标志，Codex 保留您上次授予的权限，会话历史记录可在更多文件夹和服务器上查找聊天。
  • 远程服务器会记住： 配对服务器在重新启动时保持选项卡状态，关闭的选项卡保持关闭状态，WSL 主机在每次重新启动后停止重新配对，并且 SSH 失败会说明实际出了什么问题。
  • 内存更轻： 终端使用的空闲 CPU 少得多，终端主机下次重新启动时使用的内存更少，WSL 连接需要的内存少得多，资源面板现在与 macOS 上的活动监视器相匹配。
  • 来自社区的修复： 间隔 Windows 启动器路径、韩语输入、自动化中的 DST、焦点跟随鼠标、选项卡拖动和 Linux 软件包都工作得更好。 电话和网络更新： 电话现在可以解释无法访问的计算机，而不是永远旋转，并且流式回复和长时间的网络聊天重绘更少。当手机以桌面尺寸观看时，向终端询问问题的终端程序也可以继续运行。

兼容性和升级说明

  • 在“询问”模式下进行 Codex 聊天： “询问”现在以只读方式运行，并在工作区编辑之前询问；批准我和完全访问权限保持不变，已经运行的工作仍保留其授权。配对服务器上的聊天将保留旧行为，直到该服务器更新为止。
  • Claude 子代理导航： 默认情况下，带有 Claude 状态挂钩。 Orca 仅将其插件加载到 Orca 窗格中，并在其使用的每个 Claude 文件夹中的 keybindings.json 中添加一个快捷方式（第一个不使用 Ctrl+Alt+G、H 或 V 的快捷方式）。在设置 → 代理 → Claude 子代理导航中将其关闭以删除该快捷方式。已经运行的克劳德会议需要重新启动。
  • 配对服务器： 将窗格移动到新选项卡并继续聊天中的远程 Claude 终端需要服务器运行此版本。在较旧的服务器上，移动仅保留在此窗口中，与以前一样，并且“聊天 UI 中的继续”显示为禁用并带有更新提示。
  • Claude 帐户切换： 当系统默认 Claude 文件夹登录到旧帐户时，切换帐户现在还可以重新启动在该文件夹中运行的会话。该对话框将会话分为旧帐户上的会话、其他会话和无法移动的会话。
  • WSL 主机： 与 WSL 主机服务器的连接现在通过 bash，并在 bash 丢失或太旧时回退到 Node。这不需要服务器更新并且适用于任何服务器版本。
