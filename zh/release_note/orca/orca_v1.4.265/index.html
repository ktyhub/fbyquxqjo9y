orca v1.4.265

先前版本：1.4.264 — 聊天命令找到其工作区，使浏览器能够正常工作。

Orca 机器人简介（测试版）

Orca 机器人像一流的队友一样工作：每个托管代理会话都会获得其工具和身份，机器人可以代表所有者进行共享，它们更可靠地遵循 Slack 线程和 Gmail 触发器，并且连接它们更清晰、更安全。

  • 每个机器人会话都会获得其工具和身份： 托管代理会话不再仅限于 Claude 和 Codex；每个人都从其所需的工具和身份开始。
  • 🔗 机器人可以共享，就像所有者一样： 代理 CLI 呼叫者可以像所有者一样使用共享。
  • 💬 松弛线程显示机器人正在做什么： 线程现在反映了轮到它正在做什么，长答案会完整到达而不是被分割。
  • 📬 Gmail 触发器与真实发件人匹配： 触发器与发件人的实际地址匹配，而不是可能不同的显示名称。
  • 🛡️ 更清晰的访问警告： 访问确认对话框现在会在连接机器人之前阐明您允许的内容。

亮点

机器人、连接器和访问。 通过带有类别图标的更快连接器选择器、经过修剪的 Slack 连接对话框（显示安装后如何提及机器人）以及更清晰的访问控制警告来连接机器人。列出的其他对话仅供代理上下文中参考，因此机器人会专注于被询问的对话。完成警报和工作人员停止报告带有抄本读取添加的回复，并且代理被告知要设置哪种邮件类型，包括通过 --on。 **适合繁忙聊天和终端的更轻的桌面。**长选项卡条仅呈现可见区域，会话保存写入更改的条目，新消息在其他聊天流中通过，并且可能冻结窗口的终端滚动循环已修复。 在其他聊天流传输时发送。 新聊天的发送工作优先于后台流写入。隐藏的作曲家也会停止监听每次击键，并且关闭的聊天会释放他们不再需要的状态行。当多个对话处于活动状态时，这些更改会减少竞争性工作。 **读取状态而不丢失线程。**展开活动行以了解详细信息或打开子代理自己的视图。问题之前的文本在转弯折叠后仍然可见，保留的图表在工作区切换后仍然存在，并且早期消息的失败加载提供了重试功能。 在正确的主机上使用代理。 Claude 和 Codex 安装遵循聊天运行的主机。现有的个人安装优先； Orca 的托管副本也可用于其终端。远程帐户控制和使用情况显示也得到修复。 选择自动桌面更新。 在 设置 → 常规 → 关于 中启用 自动更新，让 Orca 使用您的更新节奏、渠道和延迟来下载、安装和重新启动。它默认为关闭。如果自动安装将终止实时或启动进程内终端、WSL 移动处于活动状态或无法保存窗口状态，则自动安装会等待。 电话兼容性。 下面列出的电话更改是此版本边界中包含的源更改。安装此桌面更新不会安装移动应用程序更新；这些功能需要相应的移动版本。

Orca 机器人简介（测试版） 亮点机器人、连接器和访问。 通过带有类别图标的更快连接器选择器、经过修剪的 Slack 连接对话框（显示安装后如何提及机器人）以及更清晰的访问控制警告来连接机器人。列出的其他对话仅供代理上下文中参考，因此机器人会专注于被询问的对话。完成警报和工作人员停止报告带有抄本读取添加的回复，并且代理被告知要设置哪种邮件类型，包括通过 --on。 **适合繁忙聊天和终端的更轻的桌面。**长选项卡条仅呈现可见区域，会话保存写入更改的条目，新消息在其他聊天流中通过，并且可能冻结窗口的终端滚动循环已修复。 在其他聊天流传输时发送。 新聊天的发送工作优先于后台流写入。隐藏的作曲家也会停止监听每次击键，并且关闭的聊天会释放他们不再需要的状态行。当多个对话处于活动状态时，这些更改会减少竞争性工作。 **读取状态而不丢失线程。**展开活动行以了解详细信息或打开子代理自己的视图。问题之前的文本在转弯折叠后仍然可见，保留的图表在工作区切换后仍然存在，并且早期消息的失败加载提供了重试功能。 在正确的主机上使用代理。 Claude 和 Codex 安装遵循聊天运行的主机。现有的个人安装优先； Orca 的托管副本也可用于其终端。远程帐户控制和使用情况显示也得到修复。 选择自动桌面更新。 在 设置 → 常规 → 关于 中启用 自动更新，让 Orca 使用您的更新节奏、渠道和延迟来下载、安装和重新启动。它默认为关闭。如果自动安装将终止实时或启动进程内终端、WSL 移动处于活动状态或无法保存窗口状态，则自动安装会等待。 电话兼容性。 下面列出的电话更改是此版本边界中包含的源更改。安装此桌面更新不会安装移动应用程序更新；这些功能需要相应的移动版本。发生了什么变化 机器人、连接器和访问📱 电话和手机💬 聊天和状态行🤝 工人和协调 代理、模特和帐户🖥️ SSH、WSL 和远程主机🌐 浏览器🗂️ 工作区、侧边栏和选项卡⌨️ 终端🔀 源代码控制和集成📝 编辑器和文件🎨 设置、插件和语言⚡ 性能和可靠性↩️ 已恢复🛠️ 测试、CI 和维护新贡献者
