LlamaFactory v0.8.3

修订 发布时间2024年7月18日 来源hiyouga/LlamaFactory 英文原文

LlamaFactory v0.8.3

变更流程图

亮点

  • 无污染打包（neat_packing） — #4224 移植了 Functionary 的打包策略，序列拼接后不同样本的 token 不会互相 attend。如果你之前靠朴素打包提吞吐，这个版本就该切换：GPU 利用率不变，但不再有悄悄抬高训练损失、拉低评测效果的标签泄漏。它是可选 flag，现有配置在显式加上之前保持旧行为。
  • 更广的模型与量化覆盖 — 新增 Gemma2 (9B/27B)、InternLM2.5-7B、CodeGeeX4-9B-Chat、TeleChat-1B-Chat 的 base/chat 模板；quantization_method 参数在现有后端之外加入 HQQ 和 EETQ。对受限硬件上跑 27B 级推理，这是实用抓手——但量化会改变数值表现，长微调前先短跑验证。
  • BAdam + ZeRO-3 与 DeepSpeed/PiSSA 修复 — #4352 让 BAdam 兼容 ZeRO-3 分片，消除了以前”分块优化器省显存”和”分片并行”二选一的局面；#4580 另行修复 DeepSpeed + PiSSA。在有限 GPU 上扩展全参数风格微调的团队，配置空间明显变宽。注意如果你钉了旧版 DeepSpeed——这个组合以前是坏的，别假定旧版本能复现 CI。
  • 真正的划分评测与按批次指标 — eval_dataset（#4691，划分修正在 #4821）让你留出真正的评测集，而不是在训练切片上打分；batch_eval_metrics 改变了指标聚合方式。如果你公开的数字来自训练划分，和 v0.8.2 日志对比前请重新基线——差异可能来自测量方式而非模型质量。
  • 多轮与工具调用训练控制 — mask_history（#4878）把损失限制在最后一个 assistant 轮次，历史/user token 不再贡献梯度；tool_format（#4417）显式控制工具使用数据的提示模板。这些改变的是模型被优化的目标，不只是格式——如果你在多轮轨迹上微调 agent，这点很重要；如果你预期旧的 mask 行为，也很可能是回归来源。
  • 奖励建模与 DPO 行为变化 — RM 损失函数被修订，DPO 截断长度被纠正，value-head 保存回调被修复（#4746）。如果你训练 RM 或跑 DPO/PPO，v0.8.2 的 checkpoint 和奖励曲线不能直接比较；恢复任务前先短跑一次基线，并复核保存的 value-head 产物。

无破坏性变更；reserved_label_len 在 DPO 中已弃用，应从配置里移除。
