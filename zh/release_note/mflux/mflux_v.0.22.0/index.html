mflux v.0.22.0

mflux v.0.22.0

这个项目是干啥的：一个在Mac本地跑的AI绘画和修图工具，支持Qwen-Image和FIBO图像编辑，给想在电脑上手动画图的创作者用。

变更架构图

亮点

  • 相同 seed 的输出会变——请规划可复现性 — 多项修复会让同一 seed 下的图像发生变化：Z-Image 现在以 bfloat16 运行其 transformer，在 M5 上快约 30%，但像素略有差异，可用 --float32 来匹配旧版本（#803）；新增可选启用的 --compute-precision float16（compute_precision=mx.float16），用于 FLUX.2 klein、Z-Image 和 Qwen-Image 2.1，也会改变像素（默认关闭）（#820）；FLUX.1、FIBO 和 Qwen-Image 找回了 0.16.0–0.21.0 期间丢失的最后一个归一化层 bias——Qwen-Image 在视觉上有差异（#839）。用 0.16.0–0.21.0 保存的模型仍按旧方式生成；如需带上该 bias，请从原始权重重新保存。任何跨版本比对图像的人都需要用这些 flag/重新保存。
  • Python API 扩展，附带两处行为破坏 — mflux-generate-krea2、-lens、-boogu、-ideogram4（#821）以及 mflux-generate-qwen/-edit（#836）现在开放 validate/load/generate。破坏性变化：Qwen 系列命令在 --model 指向其他模型时现在会报错，而不再静默忽略（#836）；mflux-generate-qwen-edit --model qwen-image-edit-2511/qwen-edit-2511 终于会加载 2511 权重并在 timestep 0 读取参考图——这些名称过去加载的是 2509，而不带 --model 时仍运行 2509（#844）。QwenImage21Edit 新增 rewrite_prompt() 和 scheduler 参数，image_paths 也接受 PIL 图像（#835）。依赖旧有”忽略或加载 2509”行为的调用方必须调整。
  • Qwen-Image-2.1 与 Z-Image 的显著改进 — Qwen-2.1 和 -2.1-edit 不再把所有权重都加载进内存：8 位模型在 512x512 下的内存峰值从约 24 GB 降到约 13 GB，配合 --low-ram 进一步回到约 8 GB（#833）。新增的 mflux-generate-qwen-2.1-controlnet 引入阿里的 Fun ControlNet Union——一个检查点覆盖 Canny、depth、pose 以及另外五种控制类型，并通过 --image-path/--mask-image 支持局部重绘（#842）。调度器修复让 --scheduler 真正生效（z-image/ernie-image 的 --scheduler=NAME 不再被覆盖 #849；qwen-2.1-edit 现在会应用到编辑过程，并记录到 --config-from-conf #835）。如果你受内存限制或使用这些模型，值得升级。
  • LoRA 正确性提升 — 烘焙进 -q 量化模型的 LoRA 现在与实时适配器效果一致（此前在 q8 上强度 0.5 的弱 LoRA 会损失约 20%）；低于 8 位的层保留自身位宽，不再被重新量化（#824）。新适配器的 lora_B 以零初始化，使第 0 步等同于基础模型，消除了第 0 步的网格状伪影（#811）。Qwen-Image-2.1 编辑的步缓存不再在少于 10 步的运行（如 6 步的 viggle_turbo）中跳步；烘焙时若权重承载的更新不足 90%，会给出警告并建议使用 --no-bake-lora（#843）。
  • 安全依赖升级让此版本值得升级 — urllib3 提升到 ≥2.8.0，修复 HTTPS 代理 TLS 和流式响应 DoS 问题（#822）；fsspec 提升到 ≥2026.6.0，修复 ReferenceFileSystem 代码执行漏洞 GHSA-27vj-qcqg-25rc（mflux 并不直接使用 fsspec）（#838）。如果你不用 Qwen-2.1/Z-Image/FLUX.2 路径、不依赖旧版相同 seed 的输出，也不依赖 Qwen 的 --model/LoRA 烘焙特性，其余都是增量改动可以跳过——但安全修复本身足以支持升级。

0.22.0

改进

  • mflux-generate-krea2、mflux-generate-lens、mflux-generate-boogu 和 mflux-generate-ideogram4 现在向 Python 呼叫者公开 validate、load 和 generate。 （#821）
  • mflux-generate-qwen 和 mflux-generate-qwen-edit 现在为 Python 调用者公开 validate、load 和 generate，并在 --model 命名另一个模型而不是忽略它时停止并显示错误。 （#836）

已修复

  • mflux-generate-z-image 和 mflux-generate-ernie-image 现在保留一个名为 --scheduler=NAME 的调度程序。之前，该拼写已被命令的默认调度程序所取代。 （#849）

已更改

  • Z-Image 在 bfloat16 而不是 float32 中运行其转换器。 M5 上的去噪速度大约快 30%，并且相同种子的图像略有变化。添加 --float32 以从旧版本重现图像。 （#803）
  • 当提示达到 512 个令牌限制时，Z-Image 现在会写入警告。之前，模型忽略了没有消息的额外文本。 （#810）
  • LoRA 训练：新的适配器现在从 lora_B 为零开始，因此步骤 0 是基本模型。之前，每个新适配器都会向每个修补层添加随机更改，这会导致步骤 0 预览中出现网格图案。 （#811）
  • FLUX.2 klein、Z-Image 和 Qwen-Image 2.1 采用新的选择加入 --compute-precision float16（Python 中的 compute_precision=mx.float16），仅运行 float16 中的注意力层和前馈层。在相同的峰值内存下，M1 Max 上的每一步速度加快了 8-35%，整代速度加快了 7-29%；给定种子的图像略有变化。默认情况下它是关闭的。 （#820）
  • 将 urllib3 更新为 2.8.0 或更高版本，以修复 HTTPS 代理 TLS 和流响应拒绝服务漏洞。 （#822）
  • 在 FLUX、FLUX.2、Qwen-Image、Krea 2 和 Z-Image 上烘焙到负载量化模型 (-q) 的 LoRA 现在具有与实时适配器相同的效果。它曾经丢失了一部分，对于 q8 上 0.5 规模的弱 LoRA 来说大约丢失了 20%。低于 8 位的层保留其位，而不是在 q8 处重新量化。 （#824）
  • 加载使用 mflux-save 保存的 SeedVR2 模型不再警告文件夹“不包含与原始文件名匹配的文件”。 （#828）
  • 添加调度程序文档 (#829)
  • mflux-generate-qwen-2.1 和 mflux-generate-qwen-2.1-edit 不再在加载时将每个重量读入内存。对于 512x512 的 8 位模型，峰值从约 24 GB 降至约 13 GB，而 --low-ram 在大多数运行中再次将其降至约 8 GB。 （#833）
  • mflux-generate-qwen-2.1-edit --scheduler 现在到达编辑（已检查，然后被忽略），并且 --enhance-prompt 使用每个参考图像重写，而不仅仅是第一个。 QwenImage21Edit 获得 rewrite_prompt() 和 scheduler 参数，并在 image_paths 中获取 PIL 图像。两个 Qwen-Image-2.1 命令都会记录除 linear 之外的调度程序，因此 --config-from-conf 会重播它。 （#835）
  • 需要 fsspec 2026.6.0 或更高版本，修复了其 ReferenceFileSystem (GHSA-27vj-qcqg-25rc) 中的代码执行漏洞。 mflux 不直接使用 fsspec。 （#838）
  • FLUX.1、FIBO 和 Qwen-Image 再次加载其最后一个归一化层的偏差。 mflux 0.16.0 到 0.21.0 放弃了它，因此它们的图像发生了变化：FLUX.1 略有变化，Qwen-Image 明显变化。使用这些版本保存的模型会像以前一样生成；再次保存原始权重以包含偏差。 （#839）
  • 新命令mflux-generate-qwen-2.1-controlnet：Qwen-Image-2.1与阿里巴巴的Fun ControlNet联盟。一个检查点采用 Canny、深度、姿势和另外五种控制图像，并通过与 --image-path 和 --mask-image 相同的分支进行修复。 （#842）
  • Qwen-Image-2.1 编辑的步骤缓存不再跳过 10 个步骤以下的运行中的步骤，例如 6 步 viggle_turbo 计划，其中跳过会明显改变图像。现在，当烘焙权重低于其更新的 90% 时，烘焙 LoRA 会发出警告，并建议 —no-bake-lora。 （#843）
  • Qwen-Image-Edit-2511 自行运行：mflux-generate-qwen-edit --model qwen-image-edit-2511（或 qwen-edit-2511）加载 2511 权重并在时间步 0 读取参考图像，如检查点所期望的那样。到目前为止，这些名称已加载 2509。如果没有 --model，该命令仍会运行 2509。(#844)
