mflux v.0.24.0

mflux v.0.24.0

0.24.0

安全

  • 现在需要枕头 13.0.0 或更新版本。它修复了 FlashPix JPEG 解码 (GHSA-5x8w-8jj5-q52h) 中的严重堆溢出和其他建议。 (#935)
  • MFlux 现在需要 Pillow 13 和 Python 3.11 或更新版本。不再支持 Python 3.10。升级到 Python 3.11 或更高版本以安装此版本。 (#933)
  • 使用 Pillow 13 (ImportError: cannot import name '_IntegralLike' from 'numbers') 启动时，mflux 命令不再崩溃。 （#890）

新型号

  • 新型号：Bria 的 FIBO 2（Fibo 2.0 Dev 和 Fibo 2.0 Edit Turbo）以及 mflux-generate-fibo2 和 mflux-generate-fibo2-edit。从 JSON 标题或简短描述进行文本到图像的编辑，使用可选蒙版、渲染文本、LoRA 和量化编辑一到五张图像。 (#924)
  • 新模型：来自 Circlestone-labs 的 Anima（Turbo、Aesthetic 和 Base）以及 mflux-generate-anima。它加载circlestone-labs/Anima的ComfyUI文件并支持kohya LoRA、-q 4 to 8、—compute- precision float16和mflux-save。 (#931)
  • 新模型：来自 OpenMOSS 的 MOSS-Image-SFT，带有 mflux-generate-moss-image。它完全在 MLX 中运行，包括 Qwen3.5-9B 文本编码器，并支持量化和 mflux-save。 (#914)
  • mflux-generate-iris 运行 Iris-3B，这是一种直接生成像素的 3B 文本到图像模型（无 VAE）：分 4 步进行 Turbo（--model iris-3b，默认）和基本模型（--model iris-3b-base）。 （#899）

改进

  • FIBO 2：mflux-generate-fibo2 也运行 Edit Turbo，并且两个 FIBO 2 命令均采用 —expand-prompt（使用 FIBO-vlm 写入 JSON 标题）、—cfg-end 和 —step-cache-ratio，在模型加载之前检查 JSON 标题并解码低内存条中的 VAE。 (#934)
  • mflux-generate-moss-image 现在采用 --lora 并保留 LoRA 作为运行时层，因此逐步蒸馏的 LoRA 保留其所有更新。 --model moss-image-base 运行 MOSS-Image-Base。 (#929)
  • mflux-generate-qwen-2.1 和 mflux-generate-qwen-2.1-edit 有一个新的 --small-text-encoder 标志。它使用 Qwen3.5-0.8B 和 zen-image-edit 适配器而不是 Qwen3-VL-8B，并下载 2.1 GB 而不是 17.5 GB。 (#906)
  • FLUX 3、FLUX.2 Klein、ERNIE-Image、Z-Image、Lens 和 Ideogram 4 现在可以解码 bf16 行条中的 VAE。解码在 1024×1024 时大约需要 1.6 GB，而不是 7–14 GB。 --vae-tiling 不再改变颜色。 --vae-full-precision使用较早的全图像解码。 (#910)
  • mflux-generate-flux2 和 mflux-generate-flux2-edit 为 FLUX.2-klein-4B 提供了新的 --small-text-encoder 标志。它使用 Qwen3-0.6B 和适配器而不是 4B 文本编码器，因此模型需要更少的内存。 （#896）
  • mflux-generate-flux2 和 mflux-generate-flux2-edit 有一个新的 --small-decoder 标志。它使用 Black Forest Labs 的小型 VAE 解码器解码 FLUX.2 klein 图像，该解码器速度更快且需要更少的内存。 （#897）
  • mflux-save --hf-symlink [USERNAME] 添加了一个 Hugging Face 缓存条目，链接到已保存的文件，因此 --model USERNAME/<folder> 通过 repo id 加载已保存的模型。超级简单的 mflux-save --model Qwen/Qwen-Image-2.1 -q 5 现在可以使用自动命名 - 需要环境变量 MFLUX_MODELS_DIR (#903)
  • 已发布的 mflux-community FLUX 3 存储库现在仅按名称解析：添加了连字符别名（flux-3-image-klein、flux-3-image-klein-base），因此存储库名称推断出正确的基本模型，而不是引发“无法推断基本模型”。 （#909）

已修复

  • 在 Hugging Face 上保存了 Krea 2 检查点，如 mflux-community/krea-2-* 存储库，现在通过存储库 ID 加载；他们在没有变压器的情况下下载并失败了。作为 —model 传递的文件现在会收到一个错误，在 Krea 2、FLUX、FLUX.2 和 Z-Image 上如此。 （#873）
  • FLUX.2 klein：当 sidecar 将 "small_text_encoder" 记录为字符串（例如 "false"）时，--config-from-metadata 不再打开小文本编码器；相反，它会报告错误。 （#905）
  • 修复 Z-Image ControlNet mlsd 预处理器在 OpenCV 5 上崩溃的问题，并允许 opencv-python 5。 (#901)

已更改

  • mflux-check 无需下载即可验证本地 MFlux 和 Safetensors 模型包。使用 —fix 从兼容的本地缓存快照恢复丢失的 MFlux 分片。 （#877）

文档

  • docs/plugins.md 中的 pip 示例现在安装 mflux-teacache。之前，pip install mflux-<name> 在 shell 中失败，因为 shell 将 < 和 > 读取为重定向。 （#886）
  • 将 mfluxible 添加到自述文件中的社区应用程序列表中，这是一个带有浏览器工具、MCP 工具和 OpenAI 兼容端点的 HTTP API 服务器。 （#885）

内部

  • CI 现在在 GitHub 的 macos-15 运行器上运行测试和模型注册表作业，然后在 2026 年 11 月 2 日 macos-14 映像停用之前。(#887)
  • FLUX 3 快速测试现在将蒸馏变压器和基础变压器与固定 FP32 和 BF16 参考张量进行比较，包括图像调节和时间步长规则。 （#883）
  • FLUX 3 贡献者可以记录相位计时、重置和 RSS 上的 MLX 峰值，以及可重复的 32 GB q4 基线。 （#894）
