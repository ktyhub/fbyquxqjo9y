mflux v.0.21.0

发布 发布时间2026年10月3日 来源mflux-community/mflux 英文原文

mflux v.0.21.0

变更流程图

亮点

  • Qwen-Image-2.1 变成编辑平台——最值得升级的理由 — 新增的 mflux-generate-qwen-2.1-edit 支持基于指令的编辑，最多可用十张参考图，输出 RGBA 并带前缀 KV 缓存；底层是新的 QwenImage21Edit Python API，可量化并导出带完整视觉能力的检查点。它新增 --mask-image、--auto-mask、--strength、--enhance-prompt、--verify 和 --use-step-cache（#749），通过 --lora 支持 PEFT .default 适配器（#756），兼容常见的 transformer./diffusion_model. 权重导出（含融合的 gate_up 权重）（#768、#777），还加入 --scheduler viggle_turbo，配合 --steps 6 把 40 步压缩到 6 步（#764）。如果你的工作流就是 Qwen 编辑，那这次升级毫无疑问该做。
  • 显著的性能与内存优化 — Qwen-Image-2.1 最高快约 1.8 倍：文本前缀缓存限制为最近两个 embedding、融合了 Q/K norm+rope 的 Metal 内核（可用 MFLUX_QWEN21_DISABLE_FUSED_PROLOGUE=1 关闭），以及 generate_image(..., teacache_ratio=0.25) 在变化最小的步上复用噪声，再提速约 1.4 倍（0.4 时为 1.77 倍）（#778）。步复用参数现为 --step-cache-ratio（--teacache-ratio 仍可用），会记录到元数据中，并通过共享的 mflux.models.common.step_cache.StepCache 由 --config-from-conf 复现（#779）。LoRA/LoKr 现在以模型的加载精度运行，而非 float32（#801）；OpenCV/PyTorch 改为懒加载（#787）；--low-ram 会在 VAE 解码前释放 transformer，覆盖 Z-Image、Krea-2、FLUX.2 Klein、Ming-Image、ERNIE-Image 和 Ideogram-4（#802）。显存紧张或批量处理的用户很值得升级。
  • 迁移提示：一次软重命名、三处更严格的报错 — 三个 flag 改名但旧名仍作为别名保留，脚本不会立刻失效：--make-conf（原 --metadata）、--no-exif（原 --no-metadata）、--config-from-conf（原 --config-from-metadata）（#797）。更严格的地方：权重名与模型不匹配的检查点现在会报错，而不是悄悄加载成随机权重（#758）；PEFT lora_A/lora_B 布局的 DoRA 适配器现在会直接报错停止，而不是静默丢掉幅度（#774，LoKr 的 dora_scale 仍可加载）；带直接 delta 的 Z-Image ComfyUI LoRA 需要使用默认的 baked 推理模式（#772）。使用第三方转换检查点或 PEFT DoRA 适配器的用户，升级前请重新验证自己的流程。
  • 新模型与可嵌入的 Python API 扩展覆盖面 — 通过 mflux-generate-ming 新增 inclusionAI Ming-Image-0.1-Design，这是一个面向设计、支持 RGBA 输出的文生图模型，其 16B MoE 文本编码器可用 --text-encoder-quantize 单独量化（#765）。Z-Image、Z-Image-ControlNet 和 Z-Image-Turbo 现在开放 load/generate（三者还都新增 validate，可在不加载权重的情况下校验请求）（#780、#785），ERNIE-image 系列命令也获得 validate/load/generate（#815）；mflux-save 可保存 SeedVR2 3B/7B 放大器，mflux-upscale-seedvr2 --model <dir> 会从权重中读取具体变体（#800）。如果你把 mflux 嵌入 Python 使用，或想要新模型/放大器，这次升级很有用。
  • 减少静默错误输出的正确性与安全修复 — 升级 anyio 以修复 CVE-2026-63374 和 CVE-2026-64847（经 httpx/huggingface-hub 传递引入）（#744）；transformer/ 目录下的旧版 Krea 2 检查点重新可以加载，而不会被当成未训练模型（#792）；图像元数据现在以全精度保存 LoRA 缩放、ControlNet 强度和 Redux 强度，让 --config-from-conf 能真正复现一次运行（#805）；透明参考图改为合成到白底，而蒙版仍以 “preserve” 保留透明（#793）；Qwen 编辑的多 seed 运行只计算一次自动蒙版和提示词改写，而不是每个 seed 都算（#796）。依赖 --config-from-conf 可复现重跑或使用旧 Krea 2 权重的用户都会受益；不在 Qwen/Z-Image/Krea 范围内、也没有这些检查点的用户可以合理推迟，不过单看安全升级本身风险很低。

0.21.0

添加

  • Qwen-Image-2.1 现在通过 mflux-generate-qwen-2.1-edit 支持基于指令的编辑，最多可包含十个参考图像、RGBA 输出和前缀 KV 缓存。新的QwenImage21Edit Python API可以量化并导出完整的视觉检查点；现有的生成命令和纯文本导出仍然可用。 （#741）
  • 日志记录现在在 CLI 启动时配置；使用 --verbose 使其更详细。 (#747)
  • Qwen-Image-2.1 编辑：mflux-generate-qwen-2.1-edit 的新 --mask-image、--auto-mask、--strength、--enhance-prompt、--verify 和 --use-step-cache 选项。它们提供屏蔽编辑、自动对象屏蔽、更精细的编辑、提示重写、重试自检以及更快的运行。 (#749)
  • 通过 --lora 添加了对 PEFT .default 适配器的 Qwen Image 2.1 LoRA 支持。 (#756)
  • Qwen-Image-2.1：mflux-generate-qwen-2.1 和 mflux-generate-qwen-2.1-edit 的新 --scheduler viggle_turbo。借助 Viggle 的精炼涡轮 LoRA 和 --steps 6，它只需 6 个步骤即可生成和编辑，而不是 40 个步骤。(#764)
  • 新模型：inclusionAI Ming-Image-0.1-Design (mflux-generate-ming)，一个以设计为中心的文本到图像模型，具有 RGBA 输出；其16B MoE文本编码器可以使用--text-encoder-quantize单独量化。 (#765)
  • Qwen Image 2.1 现在接受普通变压器。和扩散模型。 LoRA 导出，包括融合的 gateway_up 权重和调制/时间步嵌入适配器。 (#768)
  • Z-Image 现在加载带有融合 QKV 投影和归一化/偏差增量的 ComfyUI LoRA。包含直接增量的适配器需要默认的烘焙推理模式。 （#772）
  • 支持独立安装的 mflux 命名空间扩展，使社区 mflux.web UI 包能够在可编辑的签出和单独的导入目录中共存。 (#776)
  • Qwen-Image-2.1 参考编辑现在通过与文本到图像相同的映射支持 LoRA 适配器，包括烘焙控件和元数据重播。这两个命令共享 Transformer 核心和组件加载机制，同时保留与现有模型导出的兼容性。 (#777)
  • mflux-generate-z-image-turbo 现在公开 ZImageTurboCommand.load 和 ZImageTurboCommand.generate，因此 Python 代码可以加载模型一次并使用命令自己的标志处理生成许多图像。 （#780）
  • mflux-generate-z-image 和 mflux-generate-z-image-controlnet 现在为 Python 调用者公开 load 和 generate，并且所有三个 Z-Image 命令都添加了 validate，它在不加载权重的情况下检查请求。 （#785）
  • mflux-save 现在可以保存 SeedVR2 3B 和 7B 升频器。 mflux-upscale-seedvr2 --model <dir> 从保存的权重中读取变量。 （#800）
  • mflux-generate-ernie-image-turbo 和 mflux-generate-ernie-image 现在向 Python 呼叫者公开 validate、load 和 generate。 （#815）

改进

  • Qwen-Image-2.1 生成速度提高约 1.8 倍：去噪步骤运行速度提高约 12%（缓存文本前缀，仅限于两个最近的嵌入；融合 Q/K 规范 + 绳金属内核，使用 MFLUX_QWEN21_DISABLE_FUSED_PROLOGUE=1 禁用），并且 generate_image(..., teacache_ratio=0.25) 在变化最小的步骤上重用之前的噪声，进一步提高 1.4 倍（0.4 时为 1.77 倍）。 （#778）
  • Qwen 图像 2.1 的步骤重用现在为 --step-cache-ratio（--teacache-ratio 仍然有效），并且该比率记录在图像元数据中并由 --config-from-conf 重播。逻辑是共享的（mflux.models.common.step_cache.StepCache），因此其他型号可以采用它。 (#779)
  • MFlux 现在仅在使用 OpenCV 和 PyTorch 的代码路径中导入它们。不使用这些库的命令在启动时没有它们。 （#787）
  • LoRA 和 LoKr 适配器现在以模型加载的精度运行，而不是 float32。 bfloat16 模型上的训练和 LoRA 推理使用更少的内存并且运行速度更快。 （#801）

已修复

  • 由于 CVE-2026-63374 和 CVE-2026-64847，导致 Anyio 受到影响。 MFlux 不直接导入它 - 它由 httpx 通过 Huggingface-hub 传递使用 (#744)
  • mflux 现在拒绝权重名称与模型不匹配的检查点，并出现命名零件和缺失权重的错误。之前，这样的检查点加载了随机权重并产生噪音。这主要影响为其他程序转换的检查点。 （#758）
  • 使用 lora_A / lora_B 矩阵（PEFT 布局）保存的 DoRA 适配器现在在每个模型上都会因错误而停止，而不是在没有其大小的情况下加载。带有 dora_scale 的 LoKr 适配器仍然加载。 (#774)
  • 早期版本保存的 Krea 2 检查点（transformer/ 下的 mflux 分片）会再次加载，而不是未经训练。 （#792）
  • 具有透明度的参考图像在模型看到它们之前合成为白色；蒙版将其透明背景保留为“保留”。 （#793）
  • Qwen-Image-2.1 编辑：多种子运行现在找到自动掩码并重写提示一次，而不是为每个种子重写一次。编辑验证现在可以读取任意间距的纯文本回复。 (#796)
  • --low-ram 现在在 Z-Image、Krea-2、FLUX.2 Klein、Ming-Image、ERNIE-Image 和 Ideogram-4 中进行 VAE 解码之前释放变压器。之前，变压器权重在解码期间保留在内存中，这增加了峰值内存。 （#802）
  • 图像元数据现在可以完全精确地保持 LoRA 尺度、ControlNet 强度和 Redux 强度。之前，这些值四舍五入到小数点后两位，因此 --config-from-conf 不会重播相同的运行。 （#805）

已更改

  • 三个 CLI 标志具有新名称：--make-conf（原为 --metadata）、--no-exif（原为 --no-metadata）和 --config-from-conf（原为 --config-from-metadata）。旧名称继续用作别名。 （#797）

内部

  • 将 Qwen-Image-2.1 添加到 CI 清单脚本 (scripts/ci_extract_models.py) .. 并改进代理方向和技能以提醒 AI 代理执行此任务。 （#742）
