mflux v.0.19.1

这个项目是干啥的：一个在Mac本地跑的AI绘画和修图工具，支持Qwen-Image和FIBO图像编辑，给想在电脑上手动画图的创作者用。

变更架构图

亮点

  • 安全依赖下限提高 — Pillow、Requests、PyTorch、Transformers 和 urllib3 的最低版本均已提高，传递依赖刷新，并从 lock 中移除了未使用的 cryptography 依赖（#655），清掉了 35 项 Dependabot 告警（19 高、12 中、4 低）。这是升级的主要理由：对大多数用户没有代码改动，但拉取该补丁前请检查你固定的依赖是否仍满足新的最低版本。
  • 修复 LoRA 烘焙进低于 8 位量化模型——此前会静默出错 — 此前 -q 4 --lora X 在开启烘焙（默认）时，会以基础层的精度对合并后的权重重新量化；在 Krea 2 的 q4 下，group step 约为 delta rms 的 12 倍，适配器实际上被丢弃，你拿到的是基础图，而日志却报成功（#665、#668）。现在低于 8 位的层在折入 delta 时会以 q8 重新量化，并在控制台输出一行提示有多少层做了调整；这适用于运行时烘焙，也适用于带 --lora 对量化模型执行 mflux-save。如果你在 q4/q5/q6 下烘焙 LoRA，必须升级——你此前的输出可能一直是错的却不自知。
  • 破坏性变更：外来 --model 取值和有歧义的 flag 现在会被拒绝 — boogu、z-image、flux2 和 ideogram4 的 CLI 此前会静默忽略属于其他家族的内置名称，转而运行自己的模型（例如 mflux-generate-boogu --model dev 跑的是 Boogu）；现在会在 CLI 启动、权重尚未加载时就报错，只接受该命令自身模型的别名（flux2：注册表中任意 flux2- 条目；z-image：其蒸馏版兄弟模型），路径/repo id 仍可通过 model_path 加载（#578、#650）。--instruction 加入 --prompt/--prompt-file 组，因此 --prompt-file --instruction 现在会失败；flux2-edit 也会强制蒸馏检查点的 --guidance 1.0 规则。迁移：升级前请从脚本中清除外来的 --model 名称，以及 --prompt-file --instruction 的组合用法。
  • 元数据 sidecar 变得可复现 — get_right_half() 现在会携带 negative_prompt、image_paths 和 redux 相关字段，--save-full-image 合成图会在 --metadata 下生成 sidecar，redux_image_paths 写成 JSON 列表而非 Python repr 字符串，因此 mflux-generate-redux --config-from-metadata（-C）终于能恢复路径和强度，且 --redux-image-paths 改为在恢复后必需，而非解析时必需（#578、#649、#663）。迁移提示：旧的 repr 字符串 sidecar 有意不被当作路径列表解析，如果你依赖 -C，请重新生成它们。
  • 开发体验与发布流程——不用就跳过 — mflux-capabilities 现在报告的是线上类型（int、float、path、int-or-scale），而非 vae_tile_size、PosixPath 这类 Python 转换器名称，并正确列出 --instruction（#578、#652）；shell 补全改为从已安装的控制台脚本和真实的 build_parser() 中发现，补上了包括 mflux-capabilities 在内的六个缺失命令（#651）。此外新增通过 scripts/ci_extract_models.py 为 Hugging Face CI 提供机器可读的模型注册表（#658），把 Lens DiT 迁移到共享的 WeightDefinition 接口（#654），并将 PyPI 发布置于受保护的 pypi 环境之后、仅允许 main 分支并快速失败（#646）。没有面向用户的模型或图像质量变化；只有内部工具和基础设施用户会受影响。

🔒 安全

  • 更新的锁定依赖项超出了所有报告的易受攻击范围：提高 Pillow、Requests、PyTorch、Transformers 和 urllib3 的最低支持版本，刷新受影响的传递依赖项，并从锁中删除当前未使用的加密依赖项。这解决了 Dependabot 的 35 项调查结果：19 项高、12 项中、4 项低。 （#655）

🐛 错误修复

  • --instruction 独占性已声明，并且对 mflux-capabilities 可见：在解析后手动检查了上下文编辑的提示/指令互斥，因此功能转储将 --instruction 发布为独立标志，而 --prompt-file --instruction 完全被忽略。 --instruction 现在加入 --prompt/--prompt-file argparse 组； “至少一个”要求保留在解析后。还修复了 --width 插入高度默认值的帮助，并记录了 fibo-edit 的 matte 不写入 sidecar 的原因。 （＃578，＃669）
  • 将 LoRA 烘焙为低于 8 位的量化模型会默默地丢弃适配器：折叠以基础层自身的精度重新量化合并权重，并且低于 8 位，量化步长比典型的 LoRA 增量更粗糙（在 Krea 2 的 q4 上，组步长测量约为 12 倍增量均方根），因此默认情况下启用烘焙的 -q 4 --lora X 会生成基础图像，而日志报告成功。当 delta 折叠时，亚 8 位层现在在 q8 重新量化，与 fp8 路径采用的转义相同，并有一条控制台线报告移动了多少层；每层加载器已经从存储的形状中重建了这种混合保存。适用于运行时烘焙以及具有 --lora 的量化模型的 mflux-save。 （#665，#668）
  • 外部 --model 值在 boogu、z-image、flux2 和 ideogram4 CLIs 上被拒绝：它们都默默地忽略了另一个系列的内置名称并运行自己的模型（mflux-generate-boogu --model dev 运行 Boogu；mflux-generate-ideogram4 --model qwen-image 运行 Ideogram）。它们现在通过与 krea2/lens/ernie/z-image-turbo CLIs 相同的限制进行解析：接受命令自身模型的别名（或者，对于 Flux2，任何注册表 flux2- 条目，对于 z-image，它的蒸馏兄弟）被接受，在 CLI 启动期间在任何权重移动之前出现任何其他错误，并且路径或存储库 id 像以前一样通过 model_path 继续加载。 Flux2-edit 还强制执行与 Flux2-generate 相同的蒸馏检查点 --guidance 1.0 规则。 （＃578，＃650）
  • Shell 完成涵盖每个已安装的命令：生成器的手动维护列表已将 6 个命令漂移到 pyproject 后面（mflux-generate-boogu、mflux-generate-lens、两个 mflux-generate-ernie-image 命令、mflux-generate-ideogram4、mflux-capabilities 从未完成）。现在可以从已安装的控制台脚本中发现命令，并且在 CLI 公开 build_parser() 的情况下，补全是从 CLI 的真实解析器生成的，而不是手动复制的配方。 （＃578，＃651）
  • mflux-capabilities 发布线路类型，而不是 Python 转换器名称：由命名转换器验证的选项泄露了函数名称作为其类型（--vae-tile-size 声明类型 vae_tile_size、--mlx-cache-limit-gb 声明 positive_float、每个路径选项声明 PosixPath）。命名转换器现在映射到它们生成的值：int、float、path 和 int-or-scale，用于接受像素计数、2x 因子或 auto 的值。转储的类型字段通过测试固定到该封闭词汇表。 （＃578，＃652）
  • 上下文中结果的元数据 sidecar 可以重现运行：当将元数据克隆到裁剪的一半时，get_right_half() 删除了 negative_prompt、image_paths 和 redux 字段，并且即使在 --metadata 下，--save-full-image 复合材料也可以在没有 sidecar 的情况下保存。 redux_image_paths 也被序列化为 Python repr ("['a.png', 'b.png']") 而不是列表，因此 --config-from-metadata 永远无法读回它。 controlnet_save_canny 和 image_outpaint_padding 的无法访问的恢复分支（没有发布的编写器发出过的密钥）将与 outpaint 解析块中的杂散调试 print() 一起被删除。 （＃578，＃649）
  • mflux-generate-redux --config-from-metadata 可以重播 sidecar：#649 使 redux_image_paths 成为 JSON 列表，但 redux CLI 仍然声明了 argparse-required 标志和 supports_metadata_config=False，因此仅 sidecar 重新运行在恢复运行之前退出了 2。 -C 现在恢复路径和强度，恢复后而不是解析期间需要 --redux-image-paths，并且在解析命名 sidecar 时出现丢失 sidecar 路径错误。旧的 repr-string sidecar 不被视为路径列表。 （＃578，＃663）

📝 文档

  • Lens 和 Boogu Image 已记录：两个型号都加入了 README 的支持型号表，每个型号都有一个涵盖用法和选项的每个型号的 README。 （#659）

🧰 DX 和维护

  • 机器可读的模型注册表提取：新的 scripts/ci_extract_models.py（具有 ci-extract 工作流程和 just 配方）将支持的模型注册表转储为 JSON，CI 需要它来自动构建 Hugging Face 的 MFlux 模型。 （#658）
  • PyPI 发布门控在受保护的 pypi 环境后面：发布工作流程现在在 pypi 部署环境下运行，因此其审阅者批准和分支保护规则在任何内容到达 PyPI 之前适用，并且 trusted 发布者固定到该环境名称。快速失败步骤还会拒绝来自除 main 之外的任何参考的调度。 （#646）
  • 镜头 DiT 通过共享的 WeightDefinition 接缝加载：用其他型号使用的机制替换其定制的重量加载路径。 （#654）
  • Flaky Gemma 2 因果关系测试已修复：测试可能会选择词汇外的标记并虚假失败。 （#653）
