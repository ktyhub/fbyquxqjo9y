codebase-memory-mcp v0.4.10

codebase-memory-mcp v0.4.10

这个项目是干啥的：给 AI 编程助手装的代码库记忆，一次调用就摸清整个项目的架构和调用关系并用图谱记牢。给想让 AI 快速看懂大项目的人用。

变更架构图

亮点

  • 观察列表取代全盘扫描轮询（#49） — watcher 不再调用 ListProjects() 枚举磁盘上每个 .db，只轮询显式观察列表中的项目。项目在 index_repository 成功、autoindex 完成或工具调用引用非会话项目时（例如 search_graph(project="other-repo")）进入列表，delete_project 会立即移除它们。死代码（cachedProjects、projectsCacheTime、projectsCacheTTL、InvalidateProjectsCache()）已删除。这直指一个 OOM 回退：旧代码每 60 秒打开每个已索引项目的数据库并快照其全部文件，因此内存随已索引项目总数 × 文件数增长。

  • 需要注意的行为变化 — 上一个会话已索引的项目不再在启动时自动观察，只有你与它们交互（索引、查询、追踪、跨项目调用）后才会重新进入观察。这是有意的资源节省，但如果你依赖空闲项目的后台新鲜度，这是刻意的语义改变，而非 bug。

  • 升级/迁移 — 无需配置或 schema 迁移，只需运行 codebase-memory-mcp update。未指出破坏性的 API 变更，可原地安全更新——唯一的行为差异就是上述观察列表语义。

  • 谁该升级 — 已索引很多项目的人，或遭遇过 watcher 内存无限增长/OOM 的人应升级；这正是此版本的全部目的。单项目、无内存压力的用户可以跳过而无实际损失，因为这是性能/资源修复而非新功能。

观察者的显式观察列表 (#49)

修复了 OOM 问题，即观察者将在启动时打开每个索引项目的数据库，甚至是用户未积极处理的项目。

发生了什么变化

  • 用显式监视列表替换了扫描所有轮询 - 监视程序不再调用 ListProjects() 来发现磁盘上的数据库。只有监视列表中的项目才会轮询文件更改。
  • 监视索引 — 当 index_repository 成功或自动索引完成时，项目将添加到监视列表中。
  • 删除时取消监视 — delete_project 立即从监视列表中删除项目。
  • 跨项目接触 - 当工具调用引用非会话项目（例如 search_graph(project="other-repo")）时，该项目将被添加到监视列表中，以便在会话期间保持最新状态。
  • 删除了死代码 - cachedProjects、projectsCacheTime、projectsCacheTTL 和 InvalidateProjectsCache() 都消失了。

为什么

在具有许多索引项目的计算机上，旧观察者将打开每个 .db 文件并每 60 秒捕获所有这些文件的文件快照。这导致内存无限增长，与索引项目总数×文件计数成正比。新方法仅监视用户正在积极交互的项目。

行为改变

在上一个会话中索引的项目在当前会话中不会自动观看。当用户与它们交互（索引、查询、跟踪等）时，它们会再次受到监视。这是理想的行为——不要将资源花费在用户不使用的项目上。
