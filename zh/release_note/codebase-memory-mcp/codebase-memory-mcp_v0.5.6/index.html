codebase-memory-mcp v0.5.6

codebase-memory-mcp v0.5.6

这个项目是干啥的：给 AI 编程助手装的代码库记忆，一次调用就摸清整个项目的架构和调用关系并用图谱记牢。给想让 AI 快速看懂大项目的人用。

变更架构图

亮点

  • 安全修复（建议升级） — 修复 store 搜索/BFS 中的 SQL 注入和 HTTP 参数注入（#124）、handle_manage_adr 中的释放后使用（#126）、幽灵 .db 文件创建，以及 SQLite 连接泄漏。仍在旧版本的用户应升级；未说明配置迁移要求。

  • search_code v2 — 重写为四阶段流水线，带来图排序、函数边界扩展、path_filter、可配置的 context 和目录摘要。默认输出改为 compact；full 返回完整函数，files 返回文件计数，因此依赖旧输出格式的集成应检查解析逻辑。未索引的项目保留原始 grep 回退。

  • Kubernetes 与自定义语言支持 — 新增 20 多种 Kubernetes 资源类型的索引、Kustomize base/overlay 关系以及 Resource 图节点。可通过 .codebase-memory.json 或全局配置中的 extra_extensions 配置自定义扩展，项目设置优先；对基础设施类和模板较多的仓库尤其有用。

  • 稳定性与兼容性 — 修复 tools/list stdio 挂起（#99）、WAL 设置顺序导致的 SQLITE_BUSY（#117）、平方级导入解析（#107）、会话项目名不匹配，以及若干 Windows/Linux 构建问题。遇到 MCP 挂起、数据库争用、索引缓慢或平台构建失败时应尽快升级。

  • 升级结论 — 这是实质性版本，不是换标签：安全与可靠性修复值得普遍升级，Kubernetes 索引和扩展映射是主要功能诱因。变更日志未列出正式破坏性变更或必需迁移步骤；未受这些问题影响且不用新功能的用户可以合理延后。

v0.5.6 的新增功能

search_code v2 — 图增强代码搜索

search_code 工具已使用 4 阶段管道完全重写，该管道将 grep 速度与知识图智能相结合：

  • 3 种输出模式：compact（默认 — 函数名称 + 匹配行）、full（带有突出显示匹配的完整函数体）、files（带有匹配计数的文件列表）
  • 图表排名：按结构重要性排名的结果（首先是定义，其次是流行函数，最后是测试）
  • 块扩展：grep 匹配自动扩展为包含函数边界 - 不再有零散的行片段
  • path_filter：范围搜索到特定目录（例如，仅限 src/）
  • context 行：完整模式下匹配周围的可配置上下文
  • 目录分布摘要：显示哪些目录包含匹配项 当项目未建立索引时，优雅地退回到原始 grep。

Kubernetes 和自定义索引

对 Kubernetes 清单的完整基础设施即代码支持：

  • 解析部署、服务、ConfigMap、Secret、Ingress、CronJobs 和 20 多种资源类型
  • 自定义叠加分辨率（基础→叠加关系）
  • 资源节点出现在知识图中，带有标签、命名空间和容器规格
  • 图形模式中新的 Resource 节点标签

用户定义的扩展映射

自定义文件扩展名 → 通过 .codebase-memory.json（项目级）或 $XDG_CONFIG_HOME/codebase-memory-mcp/config.json（全局）进行语言映射：

{"extra_extensions": {".blade.php": "php", ".mjs": "javascript"}}

项目配置优先于全局配置。

安全修复

  • SQL 注入 存储搜索/BFS 和 HTTP 服务器中的参数注入 (#124 — @map588)
  • handle_manage_adr 获取路径中的 Use-after-free (#126 — @halindrome)
  • Ghost .db 文件预防：查询处理程序现在在打开 SQLite 之前验证项目是否存在 — 防止空数据库文件累积 (#120)
  • 二进制替换：具有写入前取消链接模式的新 cbm_replace_binary，处理只读目标和 Windows 重命名旁路回退 (#114)

稳定性和兼容性修复

  • MCP stdio 缓冲：修复了导致 tools/list 挂在某些 clients 上的 poll()/getline() FILE* 不匹配问题（#99 — @halindrome）
  • SQLite WAL busy_timeout：在 journal_mode=WAL 之前设置以防止 SQLITE_BUSY 出现锁争用（#117 — @halindrome）
  • 导入解析器 O(N²) → O(N)：用 TSTreeCursor walk 替换索引 ts_node_child() 循环 - 修复具有许多导入的文件的二次减慢（#107 - @halindrome）
  • 会话项目名称不匹配：detect_session 现在使用相同的 cbm_project_name_from_path() 作为管道
  • Windows：UI zip 文件名修复、setenv/unsetenv 兼容包装器、HOME 未设置时的 USERPROFILE 回退
  • Linux：添加 -D_GNU_SOURCE 以获得 strcasestr 可见性（#111 — @trollkotze）
  • libgit2：修复 -Wmissing-field-initializers 构建错误（#91 — @jsyrjala）
  • 内存泄漏：在 delete_project 之后查询未链接的 .db 时，resolve_store 泄漏了 SQLite 连接

综合烟雾测试

从 4 个阶段扩展到 7 个阶段，涵盖完整的二进制生命周期：

  • 阶段 5：MCP stdio 传输 — 初始化握手、工具/列表、工具调用往返、内容长度成帧（OpenCode 兼容性）
  • 阶段 6：CLI 子命令 — 安装/卸载/更新 --dry-run、配置设置/获取/重置、具有只读边缘情况的模拟二进制替换
  • 阶段 7：MCP 高级工具调用 — 通过 JSON-RPC 调用 search_code v2、get_code_snippet 冒烟测试现在在 Docker 测试基础设施 (test-infrastructure/run.sh smoke) 和 CI 中在所有 10 个平台×变体组合上运行。

更新命令改进

  • --dry-run 标志：显示在不下载或修改文件的情况下会发生什么
  • --standard / --ui 标志：跳过交互式变体提示（CI 友好）
  • 更新成功后重启提醒

CI 和基础设施

  • 固定 GitHub 操作以提交 SHA（依赖机器人：VirusTotal 5.0.0、安装节点 6.3.0、联合签名安装程序、证明构建来源）
  • Docker 测试基础设施：用于本地跨平台烟雾测试的 smoke 和 smoke-amd64 服务
  • 清理了 Go 时代的工件，更新了纯 C 项目的 THIRD_PARTY.md
