codebase-memory-mcp v0.3.2

修订 发布时间2026年3月2日 来源DeusData/codebase-memory-mcp 英文原文

变更架构图

亮点

  • 一次调用掌握架构全貌 — 新增 get_architecture 工具，提供 12 个可选方面（languages、packages、entry_points、routes、hotspots、boundaries、services、layers、clusters、file_tree、adr，外加筛选选项），用于快速上手代码库。用 get_architecture(aspects=["all"]) 获取完整视图，或只选需要的方面以控制输出量。这是实打实的新能力，不是只改元数据或空转的版本。

  • 持久化架构决策 — 新增 manage_adr，用 6 个固定章节（PURPOSE、STACK、ARCHITECTURE、PATTERNS、TRADEOFFS、PHILOSOPHY）跨 AI 会话保存已校验的 ADR；支持用 include 筛选章节、用 sections 做局部补丁、拒绝缺失或非规范章节，并对已有文档（ARCHITECTURE.md、docs/adr/*）给出发现提示；长度上限从 4000 提高到 8000 字符。

  • 破坏性变更——受影响者须迁移 — 工具 read_file 和 list_directory 被移除（编码代理已原生支持），任何调用它们的自定义客户端都必须适配。聚类算法从 “Leiden” 改名为简化 Louvain，internal/store/leiden.go 被 louvain.go 取代。search_graph 和 search_code 现在默认不区分大小写；如需精确匹配请传 case_sensitive=true。

  • 正确性修复 — qnToPackage 现在会给出有意义的子包（“store”、“pipeline”），而不是把所有东西压成 “internal”；入口点、热点和路线现在通过 is_test 属性加文件路径匹配来排除测试函数；边界限定为 Function/Method/Class 节点，而非所有节点类型。

  • 结论——谁该升级 — 想要一次调用完成架构发现、跨会话 ADR 持久化或图精度修复的用户应升级。如果完全不用新工具，且依赖默认区分大小写的搜索又没有设置 case_sensitive=true，可以安全跳过。这是一个带明确移除项的特性 + 修复次要版本，发布前请先看破坏性变更那条。

v0.3.2 的新功能

架构概述 (get_architecture)

新工具可在一次调用中提供即时代码库定位。返回 12 个可选方面：

  • 语言：按文件数分类的语言
  • 程序包：具有节点数的顶级程序包
  • entry_points：主/初始化函数（过滤掉测试函数）
  • 路由：带有处理程序的 HTTP 端点
  • 热点：扇入最常调用的函数（过滤掉测试函数）
  • 边界：跨包调用量
  • 服务：跨服务 HTTP/异步链接
  • layers：包级层分类（入口/核心/内部）
  • 集群：跨 CALLS、HTTP_CALLS 和 ASYNC_CALLS 边缘的 Louvain 社区检测
  • file_tree：压缩目录结构
  • adr：存储的架构决策记录 使用 get_architecture(aspects=["all"]) 进行全面定位或选择特定方面以减少输出。

架构决策记录 (manage_adr)

通过结构化、经过验证的记录在整个 AI 会话中保留架构决策：

  • 6 个固定部分：目的、堆栈、架构、模式、权衡、哲学
  • 部分过滤：manage_adr(mode="get", include=["STACK", "PATTERNS"]) 仅返回所需的部分
  • 部分更新：manage_adr(mode="update", sections={"PATTERNS": "..."}) 修补一部分，保留其余部分
  • 验证：商店拒绝缺少任何部分的内容；更新拒绝非规范密钥
  • ADR 发现：当不存在 ADR 时，在存储库中找到有关现有架构文档的提示（ARCHITECTURE.md、docs/adr/* 等）
  • 最多 8000 个字符（原为 4000 个）

鲁汶社区检测

从“Leiden”重命名以准确反映算法（简化的 Louvain，而不是需要基于 CPM 的细化的实际 Leiden）。 get_architecture 中的 clusters 方面使用 Louvain 来发现跨包的隐藏功能模块。

不区分大小写的搜索

search_graph 和 search_code 现在默认不区分大小写。设置 case_sensitive=true 进行精确匹配。

错误修复

  • qnToPackage：修复了从限定名称中提取子包的问题 - 包现在显示有意义的名称（例如“store”、“pipeline”），而不是折叠到顶级目录（“internal”）
  • 测试过滤：入口点、热点和路由现在通过 is_test 属性 + 文件路径模式匹配排除测试功能
  • 边界过滤：仅限于函数/方法/类节点（之前包括所有节点类型）
  • 删除了未使用的工具：删除了 read_file 和 list_directory — 由编码代理本地处理

文件已更改

  • 新：internal/store/architecture.go、internal/store/architecture_test.go、internal/store/louvain.go、internal/tools/architecture.go
  • 修改：internal/tools/tools.go、internal/pipeline/communities.go、README.md等9个文件
  • 删除：internal/store/leiden.go（重命名为 louvain.go）
