OpenSandbox release-1.2.0-rc.1

OpenSandbox release-1.2.0-rc.1

这个项目是干啥的：一个用来隔离运行代码和程序的沙箱工具，把程序关在安全小房间里跑，给需要安全执行不可信代码的开发者用。

1.2.0 系列上的第一个候选版本，包含自 release-1.1.1 以来合并的所有内容 - 标题是 OSEP-0024：快速沙箱的自动暂停和访问唤醒，端到端着陆。图片现已发布； SDK/CLI 封装以 1.2.0 稳定凸点发货。请测试并报告问题。

变更架构图

亮点

  • 快速沙箱的自动暂停和访问唤醒 (OSEP-0024) 实现端到端：入口活动跟踪和唤醒路径、服务器端空闲清理器、选择加入 lifecycle.idlePolicy 创建字段以及所有五个 SDK 中的唤醒重试合约 — 默认关闭，仅附加（#2156 #2180 #2192 #2198 #2218)
  • Egress sidecar（实验性、选择加入）：实时凭证绑定 Vault 准入、具有有限耗尽的 HTTP/2 支持、原子策略文件持久性和运行时故障遏制 (#2176 #2201 #2182 #2162 #2172)
  • SDK 可靠性：五个 SDK 中的任何一个中，文件上传和下载不再在 30 秒请求超时时中止； execd 现在报告沙箱范围的 CPU/内存和 OOM 终止 (#2165 #2186 #2196 #2206 #2191 #2200)

服务器

  • 实现 OSEP-0024 自动暂停的服务器端以实现快速沙箱：生命周期创建字段 lifecycle.idlePolicy（idleTimeoutSeconds 30–86400、onIdle: pause、wakeOnAccess、可选 activeProbe）使用 pydantic 边界进行验证，并保留为保留的 sandbox.opensandbox.io/idle-policy Sandbox CR 注释（注释写入失败保持故障安全 - 沙箱已创建）不受监管）；空闲清理器从通知者缓存中枚举选择加入的 fsb 沙箱，检查 Redis 中的活动（单调最大写入，丢失密钥墓碑只能延迟暂停），采用每个沙箱暂停锁定并在锁定下重新验证​​，并发出幂等 FastPath PauseSandbox；声明的 activeProbe 通过入口网关执行，繁忙的应答记录普通活动； OpenSandbox-Skip-Activity: skip 哨兵抑制对一个请求的观察，并在网关和服务器代理跃点上被剥离 (#2192 #2181)
  • 在新的生命周期自动化保护伞下配置空闲-暂停：[idle_pause] 变为 [automation.idle_pause]，并且删除了冗余的 redis.enabled 门 - 当 enabled = true 时需要 redis.dsn（在负载时验证），大声失败而不是默默地不启动清扫器；为了简洁起见，configuration.md 被重写，现在记录了 ingress.secure_access 和缺少的 env-var 覆盖（#2215）
  • 默认 BatchSandbox Pod 为 restartPolicy: Never：kubelet 就地容器重新启动从其映像中重新创建了主容器 - 擦除可写层和内存中状态 - 而沙箱不断报告 Succeed；对于沙箱来说，重新启动从来都不是有意义的恢复，因此诚实的默认设置是不重新启动，这也使得控制器的终端故障路径可以访问。模板中的显式 restartPolicy 仍然获胜，Windows 配置文件继续强制 Always（多阶段安装依赖于它），并且池模式保持不变（#2128）
  • 将 pasta/slirp4netns/none 视为容器运行时网络模式并直接传递它们，使 podman 的内核级网络可选择 - 在 netavark 打破桥接模式的 Windows 11 + WSL2 上，pasta 是唯一的工作网络，之前创建失败，并出现 400 请求用户定义的 Docker 网络； networkPolicy 现在在这些模式下被拒绝，因为没有可供出口 sidecar 连接的桥（之前对于 none 默默接受）（#2203）
  • 解析小数秒不是 3 或 6 位数字的 Docker 时间戳：Docker 写入 RFC3339Nano（删除尾随零），Python 3.10 的 fromisoformat 拒绝 5 位小数，并且帮助程序回退到 datetime.now() - 所以 createdAt 和status.lastTransitionAt默默报出当前时间；现在，分数被零填充为 6 位数字 (#2220)

SDK

以下代码更改适用于 1.2.0 稳定版本 - rc 不附带 SDK 软件包。

  • 将 OSEP-0024 SDK 合约添加到所有五种语言：类型化的 lifecycle.idlePolicy 创建字段（具有镜像服务器的 client 端快速失败验证的 IdlePolicy/ActivityProbe 模型：超时 30–86400 秒、onIdle: "pause" 配对、探测路径/超时界限；通过标准和模板创建连接）以及唤醒重试合约 - 在携带网关拥有的 OpenSandbox-Wake: expired 标记的 503 上（它的存在证明请求已被停放且从未转发，使任何方法重试都是安全的），SDK 在 Retry-After 之后在有限预算下重新发送（默认 5 次尝试/60 秒，每个 client 旋钮），耗尽会引发类型化的唤醒超时异常尝试和等待时间，服务器端恢复永远不会取消，裸 503 处理不变，SSE/流传输绕过唤醒重试（[#2198]（https://github.com/opensandbox-group/OpenSandbox/pull/2198）[#2218]（https://github.com/opensandbox-group/OpenSandbox/pull/2218））
  • 在所有剩余的四个 SDK 中，停止在请求超时（默认为 30 秒）时限制文件上传和下载 — 整个调用超时（http.Client.Timeout、OkHttp callTimeout、AbortController、HttpClient.Timeout）涵盖发送请求正文和读取响应，因此任何大型或缓慢的传输即使在健康的情况下也会在飞行中失败；传输现在在专用 client 上运行，没有整个调用截止时间，仍然限制响应标头的等待，因此停滞的传输仍然会失败而不是挂起（[#2165]（https://github.com/opensandbox-group/OpenSandbox/pull/2165）[#2186]（https://github.com/opensandbox-group/OpenSandbox/pull/2186）[#2196]（https://github.com/opensandbox-group/OpenSandbox/pull/2196）[#2206]（https://github.com/opensandbox-group/OpenSandbox/pull/2206））
  • 抑制 Go、Python 和 JavaScript 中 client 池预热创建的 sandbox.create client 指标，与 Kotlin 保持一致：预热流量（硬编码 skipHealthCheck，数百毫秒）先前混合到面向用户的创建延迟指标中，并拖累了 p50/p99；从池获取直接创建和面向用户的创建保持报告（#2199）

Python

  • 清理取消的异步池启动：在等待中取消 SandboxPoolAsync.start() 会使实例陷入 STARTING，其中后续的 start() 会静默返回，并且启动拥有的资源会跳过清理；取消现在重用协调清理路径，移动到 STOPPED，并重新引发，以便调用者可以重试 (#2209)
  • 停止将失败的文件替换报告为成功：普通文件系统适配器捕获并丢弃生成的 client 的 JSONDecodeError，因此来自 replace_contents() 的空或非 JSON HTTP 400/500 返回成功，并且代理可以继续在未应用的编辑上进行构建；捕获被删除，并恢复记录的 SandboxException 失败契约（隔离会话适配器保留其空体兼容性捕获）（[#2222]（https://github.com/opensandbox-group/OpenSandbox/pull/2222））

去

  • 在跨源重定向上剥离所有 OPEN-SANDBOX-*/OPENSANDBOX-* 标头和每个配置的身份验证标头（包括 X-EXECD-ACCESS-TOKEN、X-API-Key 和自定义 WithAuthHeader 名称），将每个目标与初始请求的方案、主机和有效端口进行比较，以便凭据无法在以后的外部源跃点上重新出现；跨生命周期、execd、出口、文件传输、SSE 和创建指标应用，同时保留自定义 CheckRedirect 策略 (#2178)

控制器

  • 保留 BatchSandbox 直至清理完成：已删除的沙箱可能会从生命周期 API (GET 404) 中消失，而其拥有的 pod 仍在运行，从而让替换沙箱在旧写入器退出之前写入相同的持久目录；删除现在使用前台级联删除以及现有的任务清理和池释放终结器，一旦接受删除，TTL 协调就会停止 - DELETE 在接受时仍返回 204，在托管清理期间查询报告 Stopping，并且仅在运行时消失后才到达 404；所有五个 SDK 的 kill 文档和日志都描述了接受的删除语义 (#2154)

执行

  • 通过 cgroupfs 轮询报告 OOM 杀死：沙箱内部无法访问内核端证据（没有 CAP_SYSLOG，没有 /dev/kmsg），因此 OOM 事件无法观察到； execd 现在每 5 秒轮询一次沙箱 cgroup，并比较内核 OOM Kill 计数器（v2 上的 memory.events，v1 上的尽力而为） - 分层计数器覆盖嵌套的 cgroup，如 bwrap 隔离会话 - 使用 local/descendant 级别属性导出 execd.system.oom.kills 以及具有尽力而为受害者属性的结构化警告日志；观察程序独立于 OTLP 导出运行，不需要任何功能 (#2191)
  • 报告沙箱范围内的 CPU/内存指标：GET /metrics 和 execd.system.cpu.usage/execd.system.memory.usage_bytes 仪表通过 gopsutil 读取 /proc，它在容器内描述主机 - 仪表板显示主机范围的内存和 CPU；当沙箱 cgroup 带有配置的限制时，现在使用来自沙箱自己的 cgroup（cpu.stat/cpu.max、memory.current/memory.max、v1 后备、混合主机更喜欢 v1），并为无限制的来宾（例如快速沙箱 microVM）保留先前的主机视图；线路格式不变 (#2200)
  • Content-Disposition 中的百分比编码引号和反斜杠：包含 " 或 \ 的文件名生成了标准解析器不接受的带引号字符串（mime.ParseMediaType 拒绝了它，而 clients 根本没有文件名）；这些名称现在通过与非 ASCII 名称相同的 filename*=UTF-8'' 编码进行路由 (#2161)
  • 在设置下载标头之前解析 Range 标头：格式错误的范围回答 416，但仍附加文件的 Content-Disposition 和 Content-Length，截断 JSON 正文或完全丢弃它 — 在 Python SDK 中作为连接错误出现，而不是 416 SandboxApiException；错误响应现在是干净的 JSON 416，并且 200/206 响应保持不变 (#2216)

网络

出口

以下所有项目均涉及默认关闭的 OSEP-0023 实验修订版运行时间；旧版部署和仅 DNS 部署保持不变。

  • 添加实验性实时凭证绑定 Vault 准入：Vault 突变流经修订交易，并在发布公共结果之前安装经过私有身份验证的快照；仅在请求与 SNI/HTTP/1 权威协议精确匹配后（ECH 扩展 ClientHellos 保持不透明），绑定的 HTTPS 连接才会被允许并注入标头凭据，并且每个请求的凭据轮换、现有连接上已删除绑定的防护以及在耗尽截止日期时传输报废；范围是 443 上的精确主机 HTTPS，具有 HTTP/1.1 和内联标头凭据（#2176）
  • 在发布前确认实时策略修订：策略 API 和自动 deny.always/allow.always 重新加载现在按顺序提交 - 可选文件持久性、nft 应用程序、准确的接收者确认或协调的读回、然后代理发布和 API 成功 - 当 nft 生效后接收器失败时，具有故障关闭恢复功能，并且纯策略更新的 30 秒耗尽期限从不延长跨越后续版本（#2182）
  • 添加实验性 HTTP/2 准入和有界排出：快照以原子方式绑定到请求标头处的实际 client 流 ID，后栅栏请求在到达原点之前获取 REFUSED_STREAM，GOAWAY 等待未完成的输出义务，而到期时使用异常关闭，并且一次性 mitmdump 退出回退涵盖了无法验证的清理所有权；适配器固定到 CPython 3.10/3.11 并拒绝配置的链式上游代理 (#2201)
  • 包含 sidecar 网络命名空间中的运行时恢复故障：意外的 MITM 退出现在会触发一个独立的、回读验证的 IPv4/IPv6 栅栏，该栅栏在进程生命周期内固定到原始命名空间 - 阻止所有输入/输出/转发流量，包括现有连接和环回 - 仅在真正的规则回读后报告 QuarantineConfirmed；正常的成功突变永远不会引入栅栏（#2172）
  • 以原子方式保留实验修订策略文件：使用 fsync + 重命名 + 目录 fsync 通过同一目录临时 inode 进行写入，恢复放回确切的先前字节（或同步缺失），以及不支持的存储（文件绑定挂载、只读或符号链接路径、硬链接、不安全的所有权、不支持的 SELinux/IMA 元数据）在触及原始文件之前被拒绝；操作员必须提供现有的出口拥有的、独占写入的目录挂载（#2162）
  • 在策略恢复之前对 nft 应用效果进行分类：本地构造、启动前取消和启动失败均未更改（状态保留，恢复后允许重试），成功执行已提交，并且每个启动后或未分类错误均未知 — 在尽力恢复之前关闭写入器准入和锁定恢复；缺失表后备保留两个错误并且永远不会降级未知结果（#2167）

入口

  • 实施 OSEP-0024 活动跟踪和访问唤醒：使用 --activity-enabled，每个路由请求都会将单调活动时间戳记录到 Redis — 即发即忘，永远不会在热路径上 — 通过每个副本写入合并、Lua 单调最大更新，使无序写入永远不会回归最新的观察结果，以及管道批处理；使用 --wake-enabled，路由到暂停的快速沙箱的请求将被停放，而不是回答 503：在检查点围栏的单次飞行下，每个沙箱的每个副本一个 ResumeSandbox，有界停车场和预算（溢出/超时回答 503 + Retry-After，而恢复继续，永远不会取消），并且仅当安全可重播时，陈旧路由重新进入才会在新路由上重播；如果两个标志均未设置，则行为与今天的字节相同（#2156）
  • 完整的 OSEP-0024 唤醒强化：转发后的过时路由重放仅限于具有可复制主体的幂等方法（转发的 POST 永远不会默默地重新执行）；预转发唤醒超时答案带有 OSEP 定义的标记（503 + Retry-After: 1 + ZZPH100​​ZZ + 命名沙箱的 sandbox_wake_timeout 主体），从每个上游响应中剥离，因此沙箱无法伪造出处；单独的恢复许可证（--wake-restore-max，持有至航班航站楼）限制并行恢复独立于停车场；现在唤醒需要严格从 Sandbox CR 注释中读取每个沙箱 lifecycle.idlePolicy 选择加入 - 缺失或格式错误意味着没有策略，而今天的永久 503 永远不会是隐式选择加入； gateway.wake.* 图表值连接标志并仅在启用时添加只读 RBAC (#2180)

快速沙箱

  • 使沙箱删除可靠：删除现在在任何运行时缺失检查之前发送受隔离的 Fastlet 删除，因此丢失的注册表项、传输失败或空检查响应不再被视为沙箱已消失的证据（这可能会在 CR 消失时孤立 microVM）； Fastlet 记录每个身份的墓碑，因此延迟创建无法恢复已删除的沙箱，并且清理终结器在 CR 创建时保留（#2214）
  • 使创建布局恢复更快：在经过验证的拒绝后，FastPath 在有限的预算内刷新其候选列表（不包括已经尝试过的 Fastlet），并在切换之前等待最多 2 秒让分配状态赶上，并且进程本地创建跟踪器会阻止已删除或替换的 Fastlet pod 阻止新分配的投影或赛车 pod 丢失恢复 - 首次创建的快乐路径保持不变（#2214）
  • 批量来宾 NAT 更新：新的来宾 VM 插槽准备专用 DNAT/SNAT 链，并且恢复仅替换一批 iptables-restore --noflush 中的那些链，因此重新应用相同的来宾地址不再累积规则，并使用新的 fast_sandbox_network_guest_apply_stage_latency_seconds 指标来分隔应用阶段（#2214）

其他

  • 控制台：登陆新的可选 Web 控制台的第一部分 - 具有 httpOnly 会话和租户/管理员登录的 FastAPI BFF，代理生命周期 /sandboxes API（在列表/获取上包含 runtimeSummary），以及涵盖租户概述、沙箱列表/创建/详细信息、更新/删除和端点的 React SPA；五个计划的控制台 PR 中的第一个，随后是管理 UI (#2129)
  • CLI：将配置文件值强制为其声明的类型，以便数字 api_key 不再默默地解析为 null（用 ValidationError 破坏每个命令）并且数字 defaults.timeout 不再使 sandbox create 崩溃（[#2169]（https://github.com/opensandbox-group/OpenSandbox/pull/2169））；保持输出在非 UTF-8 流上可写 - GBK/cp1252/C-locale 用户无法运行任何 osb 命令，因为表情符号渲染通常在工作完成后引发 UnicodeEncodeError；流现在转义不可编码的字符，并且 YAML 输出被重新转储转义以保持有效（#2187）；在每个工具实际读取它们的地方编写已安装的技能 - claude 目标现在写入 .claude/skills/<name>/SKILL.md （之前的平面文件从未默默加载），全局 cline/copilot 目标写入 ~/.cline/rules/opensandbox-<name>.md 和 ~/.copilot/copilot-instructions.md；以前安装的惰性文件不会迁移 (#2194 #2208)
  • 快速沙箱集成环境：通过发布的 osb CLI 而不是原始 curl 驱动验证阶段（模板构建、沙箱创建/终止、端点获取、暂停/恢复、快照创建/获取/列表/删除/恢复、更新），server_api 仅保留用于 CLI 不公开的调用（网络策略替换 PUT、RFC） 7396 合并补丁、快照重入代码围栏、网关探测器）（#2171）；添加一个选择加入的 IDLE_PAUSE=1 配置文件，用于部署临时 Redis、启用 [automation.idle_pause] 扫描器和网关活动/唤醒值，并验证 up 上的完整自动暂停 → 访问唤醒循环，以及 SDK e2e 套件和夜间 KVM 工作流程作业 (#2202)
  • 文档：接受并记录 OSEP-0024 — 提案本身 (#2152) 以及涵盖支持、idlePolicy 字段参考、活动探测合约、SDK 唤醒重试行为和交互式图表 (#2217) 的架构页面和用户指南；将七个分散位置的组件遥测指标统一为 docs/guides/telemetry.md 的一个参考（#2205）；使用重新设计的 SVG 图、压缩的出口页面和网络隔离指南重新定位来刷新网络架构页面（#2210）；与代码对齐（Go 1.25，Gin — 不是 Beego）（#2175），删除 AGENTS.md 规则的重复数据并声明架构与指南放置规则一次（#2211），并将“共享 Fastlet 出口配置文件”误用词修复为“每个 Fastlet 共享出口进程” pod”，并注明 gRPC 以 FastPath 结束（#2225）
