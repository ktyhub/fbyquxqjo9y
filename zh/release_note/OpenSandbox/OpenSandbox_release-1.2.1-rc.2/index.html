OpenSandbox release-1.2.1-rc.2

这个项目是干啥的：一个用来隔离运行代码和程序的沙箱工具，把程序关在安全小房间里跑，给需要安全执行不可信代码的开发者用。

1.2.1 补丁线上的第二个候选版本，包含自 release-1.2.1-rc.1 (2026-11-04) 以来合并的所有内容。标题是 OSEP-0026 资源感知超额订阅着陆端到端：服务器记录每个模板的有效机器形状，将其作为 ResourceAware 池上的每个沙箱限制转发，并在快照恢复中重播记录的限制，并由专用 KVM 验证通道进行验证。快速沙箱网络在端口范围的出口规则上达到了同等水平，实验性 OSEP-0023 主题修订运行时从会话基础进步到强制准备就绪门，并且固定的快速沙箱获得了选择加入仅 rootfs 的 OCI 快照。安全批处理消除了真正的数据丢失和可用性错误：已关闭请求对象中的未知字段现在被拒绝，控制器重新启动无法再逐出实时沙箱的 Pod，并且服务器代理的数据路径进入维护模式。图片现已发布； SDK/CLI 封装以 1.2.1 稳定凸点发货。

变更架构图

亮点

  • 资源感知超额订阅 (OSEP-0026) 端到端实现：模板机器形状在构建时记录，当所选池报告 ResourceAware 时根据沙箱限制转发，快照恢复重播源记录的限制而不是失败，verify-resourceaware CI 阶段将链断言为 cgroup 值 (#2602 #2623 #2628 #2633 #2637)
  • 快速沙箱出口奇偶校验和强化：现在对每个主题强制执行端口范围的 NetworkRule.ports 规则（取消 400 拒绝）（#2662）； DNS 租约在内核中更新并在邻居删除后继续存在（#2652 #2653）；实验性 OSEP-0023 主题修订运行时间在已确认快照上达到就绪门 (#2666)
  • 安全和生命周期：关闭的请求对象用 422 拒绝未知字段，而不是默默地忽略它们（#2576）；控制器重新启动不再驱逐分配给实时沙箱的 Pod (#2398)；服务器-代理数据路径已弃用为维护模式 - 通过入口网关路由沙箱流量（#2548）

服务器

  • 资源感知超额订阅 (OSEP-0026)：每个模板的有效机器形状（默认后的 CPU/内存）在构建时记录在 spec_json.machine 中，并以相同的方式投影到 CRD 中（#2623）；当且仅当所选池报告 ResourceAware 时，模板模式将其创建为每个沙箱 resources.limits，而 LegacySlot/旧版 FastPath 池无法安全地进行字段省略，并且池模式读取 TTL 缓存（#2628）；快照创建记录源的每个沙箱限制并恢复重播它们 - 之前在 ResourceAware 池上恢复的成型模板沙箱会回退到池默认值，并且 FastPath 完全拒绝恢复（#2633）； FastPath 存根以资源感知原型字段为基础重新生成（#2619）；该合约在 OSEP-0026 (#2602) 中定义
  • 服务器代理的数据路径已弃用进入维护模式：/sandboxes/{id}/proxy/{port}、use_server_proxy 参数、匹配的 SDK 选项和 CLI/MCP 标志现在带有显式弃用标记（Deprecation: true 响应标头、每种语言的运行时警告），仅具有安全性和错误修复 — 部署应通过入口网关公开沙箱流量(#2548)
  • 已关闭请求对象中的未知字段将被清理后的 422 信封拒绝，而不是被静默丢弃 - 卷上的 readonly: true 不再静默地保持可写状态，并且 createIfNotExist: false 不再启用自动卷创建；十个模型（image/auth/platform/volume/OSSFS/credential-proxy/snapshot-renew requests）现在使用 extra = "forbid"，并且 TypeScript auth token 属性已弃用（#2576）
  • Kubernetes informer 跟踪每个对象的写入，而不是使整个缓存失效：每次创建/修补/删除之前都会将整个工作负载缓存标记为不同步，直到完全重新列表（最多 60 秒），因此具有稳定写入（更新就足够）的副本几乎可以为来自 API 服务器的每次读取提供服务，并以 429 秒结束；读取现在仅对写入的对象生效，直到 WATCH 事件确认为止 (#2599)
  • 空闲-暂停活动探测器遵守其判决契约：它永远不会引发，并且每次失败只会丢弃当前候选者 - 一个深度嵌套的 200 个答案，用于逃避和跳过其余的扫描；答案现在必须是未压缩的，适合 4 KiB，并作为整个交换范围在 timeoutSeconds 内到达 (#2596)

SDKs

以下代码更改适用于 1.2.1 稳定版本 - rc 不附带 SDK 软件包。

Python

  • 格式错误或超出范围的 Content-Range 整数被视为未知元数据（64 位有界），并且当标准和隔离会话下载中响应元数据映射失败时，异步流响应将关闭 - 以前底层流可以保持打开状态（#2570）
  • Python MCP 服务器公开后台命令状态和增量日志：command_get_status（运行状态、退出代码）和 command_get_logs（内容 + 不透明光标），并在工具描述中提供轮询指导（#2648）

JavaScript

  • 正亚毫秒命令超时至少舍入 1 毫秒 — Math.round 将 0.0004 s 序列化为 timeout: 0，这会禁用普通命令的运行时绑定并在 Bash 会话中选择服务器默认值 (#2440)

去

  • 唤醒预算限制飞行中的重试：在标记唤醒 503 后，进一步的尝试将获得剩余 WakeOverallDeadline 的截止日期（仅限标头 - 已建立的 SSE 流和下载主体永远不会被切断）（#2572），并且跳过无法满足剩余预算的通用退避或 Retry-After 等待，因此混合失败重试不再休眠超过截止日期或隐藏旧唤醒标记背后的普通错误（#2611）
  • 池强化：取消的获取不再消耗健康的空闲条目或触发创建（#2616）；优雅关闭在等待独立获取耗尽时尊重调用者取消（#2617）；空闲维护（收缩、接近到期 reaping）在创建回退期间继续，而不是在整个周期内被跳过（#2565）
  • 以 UTF-8 BOM 开头的 SSE 响应不再丢弃第一个数据帧或其事件/ID 字段 - 命令初始化帧可能会丢失执行 ID (#2618)；现在，无论时间如何，状态请求内到期的运行超时期限都会返回 SandboxRunningTimeoutError，因此 errors.As 分类是稳定的（#2668） SDK 自述文件赶上已发布的表面：生命周期 idlePolicy + 唤醒重试、renewalPolicy 以及以所有五种语言记录的端口范围规则 (#2590)；交换凭证和 fsb 模板创建/轮询流程记录为 JavaScript、Python、Go (#2597) 和 Kotlin (#2620)；网络隔离示例使用真实的导入和规则类 (#2711)

控制器

  • 控制器重新启动后的池驱逐不再删除实时沙箱的 Pod：内存中的分配存储仅在 Schedule 内恢复，但在每个池协调时首先执行驱逐 - 在重新启动后的第一次协调中，标记为驱逐的每个 Pod 看起来空闲并被删除，包括已分配的 Pod；恢复现在在任何存储读取之前运行（#2398）
  • 降低 poolMax 现在可以扩展空闲池 Pod：之前它仅限制增长，因此高于新界限的空闲 Pod 会无限期运行；仅删除空闲 Pod，并且已计划的删除会计入界限 (#2470)
  • 删除的 BatchSandbox 的状态 RV 期望被删除，修复了无限制的领导堆增长 - 每个 BatchSandbox 的最后一个状态补丁的条目在进程的生命周期中一直保留（#2646）
  • 领导者选举时间是可配置的：--leader-elect-lease-duration、--leader-elect-renew-deadline 和 --leader-elect-retry-period（加上图表值），因此较慢控制平面上的操作员可以阻止 10 秒 API 服务器停顿，从而强制进行完全重新选举；默认值不变 (#2651)
  • 图表：控制器功能标志 ConfigMap 被渲染到控制器的命名空间中 - 它进入 Helm 发布命名空间，控制器从不读取它，因此 controller.podRecovery.* 被默默地忽略（#2694）

执行

  • 隔离会话文件 API 隐藏覆盖删除的条目：内核白化（0/0 设备）、user.overlay.opaque 目录和 API 自己的 .wh. 标记现在隐藏 stat/read/list/search 中较低的条目 — 在 rm f && mkdir d 之后，删除的 f 和 d/x 仍然可以读取其旧内容，并且RemoveAll("d") 至今仍可列出 d/x (#2469)
  • 重命名和 chmod 上的复制忠实于下层：保留模式（包括 setuid/setgid/sticky）和会话所有权，符号链接保持符号链接，可以重命名仅较低层的目录，并且 rm f.txt && mv f.txt g.txt 不再复活已删除的文件； chmod 拒绝符号链接，而不是跟随它们到主机路径（#2638）
  • MITM CA trust 与出口重新启动的竞争已关闭：引导程序仅 trust 是在观察到的缺失后出现或在稳定窗口中幸存下来的 CA，并且只要导出的 CA 内容发生更改，生命周期观察者就会重新安装系统/合并/NSS/JDK trust - 以前，边车重新启动会在沙箱中留下到处都是旋转出的 CA，直到重建(#2582)
  • 前台隔离运行不再将脚本写入 shell 的标准输入：读取标准输入（read、cat）的代码消耗了脚本的其余部分，包括结束标记，破坏了退出代码并劫持了会话；代码现在通过 eval 和 </dev/null 运行，语法错误以状态 2 结束运行，并且会话继续存在 (#2517)
  • 较小的修复：PTY 持有者的最终输出块在 exit 帧之前刷新，而不是与之竞争（持有管道的后台子进程最多延迟 exit 2 秒）（#2644）； cgroup v1 指标和 OOM 监视遵循容器的挂载根，因此 Docker-on-cgroup-v1 报告主机 CPU/内存而不是沙箱的限制 (#2641)；目录下载返回 400 而不是依赖于文件系统的 500/empty-200，并且格式错误的 Range 标头的 416 携带一条消息（#2451）；无效的 /files/search glob 返回 400 而不是 500（或空目录上的 200）（#2687）； created_at 通过 statx 报告 inode 诞生时间，因此 chmod/rename 不再更改它（#2604）； Jupyter 完成源自内核的实际结果（回复 + 空闲，保留 IOPub 错误），而不是对其进行竞赛 (#2606)

网络

出口

  • 在快速沙箱中对每个主题强制实施端口范围的出口规则：每个主题的 nft 路径获得 TCP 端口允许/丢弃链（MITM 匹配连接的原始端口，而不是代理侦听器），fsb 服务器通过 ports 并由 (target, ports) 合并，并且取消创建时 400 拒绝 - 允许前拒绝和仅 TCP 语义与经典配置文件匹配，并且域+端口在两者中都保持拒绝状态(#2662)
  • 经典 sidecar 上的 PATCH /policy 不再丢弃未触及的规则：共享合并密钥允许不相关的补丁删除现有的 deny 并打开阻塞的流量（失败打开）；现在保留了补丁中缺少的范围的基本规则，与记录的合同相匹配（[#2664]（https://github.com/opensandbox-group/OpenSandbox/pull/2664））
  • 快速沙箱 DNS 租约在内核中更新：普通的定时元素添加成功，但内核到期时间保持不变，因此一旦第一个超时结束，到缓存 IP 的新连接就会被丢弃；更新现在使用添加/删除/重新添加序列（#2652），并且在删除一个主题时重建共享 nft 表会重新添加其余主题的未过期租约，而不是让空闲的缓存 IP 被阻止（#2653）
  • 实验性 OSEP-0023 主题修订运行时进步**[实验]**（在 OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME 后面，准入仍然禁用）：仅安装主题会话，具有经过身份验证的每个子 IPC 和新的控制生成（#2589），一个 FIFO 生命周期耗尽工作人员记录 SET/REMOVE/重新绑定/接管意图(#2609)，在绑定后和每次 Vault/policy 突变后安装每个主题的决策快照 (#2634 #2649)，并且数据平面就绪挂钩现在控制当前栅栏/生成/摘要的已确认快照 - 在授权或 ACK 丢失时返回 503 (#2666);所有权和修订集成合同固定在 OSEP-0022/0023 (#2586) 中
  • 实验性 sidecar 实时修订运行时在启动时拒绝额外的拦截端口，并且在非规范（非 443）TLS 目标端口上无法关闭，而不是让它们到达稍后的 HTTP 权限门（#2587）

入口

  • 唤醒策略读取重用单个 Kubernetes 配置：使用启用唤醒的解析 REST 配置两次提供常规和快速沙盒路由，第二个全局标志注册在使用 flag redefined: cluster 启动时出现恐慌（#2600）

快速沙箱

  • OCI 部署上的本机 ublk 温池：OverlayBD 现在从 2 GiB 设备的 4/8 池开始（图表可调 runtime.oci.poolLow/poolHigh/poolSizeGB，poolLow=0 禁用），因此模板创建命中预分配设备，而不是按需分配； CI 断言热命中，没有遗漏或守护进程重新启动 (#2594 fast-sandbox#163)
  • 在 OverlayBD 路径上选择仅包含 rootfs 的 OCI 快照 (FSEP-0001)：捕获仅保留可写 rootfs 层，无需内存转储，并恢复启动而不是原地恢复 — 较小的工件，没有内存大小的暂存窗口，也没有 CPU 模型固定，工件清单驱动恢复；失败的 RootfsOnly 恢复会暂停路由，直到恢复成功；运行时级别的功能，OpenSandbox 快照 API 接线稍后出现 (#2706 fast-sandbox#173 fast-sandbox#167)
  • 生命周期强化：Fastlet 与 VM 池 OOM 隔离，并在准备阶段保留耗尽错误、资源诊断和失败的运行时身份（#2626 fast-sandbox#162）；创建后立即暂停不再与控制器的状态投影竞争 - 中断的暂停保留其意图，并发恢复保留检查点沿袭，因此不需要 client 端稳定延迟 (#2626 fast-sandbox#166)
  • 快照和协调器恢复：协调隔离捕获并撤回不安全路由、退出隔离运行时、隔离 vsock 路径、恢复暂停路由以及仅在活动池中替换终端 Fastlet Pod；重置修订时间戳保留分数 (#2706 fast-sandbox#172 fast-sandbox#170)
  • 图表：快速沙箱控制器和 firecracker 运行时工作负载接受 podLabels/podAnnotations/nodeSelector/affinity，可以禁用运行时的 DART P2P 网格（runtime.p2p.enabled=false 不呈现无头服务/对等端口，代理直接从原始存储中提取），并且控制器图表为未建模的二进制标志获得 controller.extraArgs (#2566)
  • ResourceAware 集成：具有 POOL_MODE=resource-aware 选择的 ResourceAware SandboxPool 固定装置 (#2622)、在 CR/cgroup/饱和级别断言成形模板转发的 verify-resourceaware 阶段 (#2637)，PR 集成通道现在默认运行 ResourceAware 堆栈，同时每晚保持 LegacySlot 覆盖范围(#2647)
  • 较小的修复：设置 routeKeys.existingSecret 时，快速沙盒图表会跳过开发路由密钥 Secret - 生产安装不再呈现已发布的仅用于开发的 Ed25519 私钥（#2695）

其他

  • 控制台：浏览器沙箱 shell 通过 BFF WebSocket 将 xterm 桥接到 execd 的 PTY — 租户和管理列表上的条目、租户密钥和 execd 令牌保留在 BFF 上，打开一个页面就是一个 PTY (#2233)；连接后丢弃的 execd 连接报告为丢失的 shell，而不是声称 shell 无法打开的错误回溯（#2639）； UI 标签已翻译为英文 (#2657)
  • 节点代理：选择加入的 vm-console 源收集快速沙箱来宾控制台输出 - 从驱动程序编写的 fast-sandbox.json 进行节点本地 VM 发现，无需 CR 监视，每个沙箱 UID 跨放置更改的原始字节保真度，以及重新启动安全确认的偏移量（#2234）；集成环境部署它并断言端到端收集（#2676）；运营指南涵盖路径对齐、节点覆盖和发现规则 (#2677)
  • CLI：非表配置部分被拒绝并出现明显错误，而不是使每个命令崩溃（[#2551]（https://github.com/opensandbox-group/OpenSandbox/pull/2551））； None 表格单元格呈现为 - 而不是文字文本 (#2691)；空的出口规则目标是带有 ACTION=TARGET 提示的使用错误 (#2692)
  • OSEP-0025 后续：指定解析器调用者身份验证 - 每个 TCP 解析拨号上缓存的 Ed25519 JWT，根据服务器发布的 JWKS 进行离线验证，缩小应用程序层的延迟 R4 差距（#2631）
  • 治理：维护者提名和移除规则收紧 - 组件维护者的多数批准、路径所有者支持、发起者 LGTM 以及退休/移除流程（#2678）； @jianpingpei 被提名为节点代理维护者 (#2679)
  • OSEP 和文档：OSEP-0024/0026 和六个早期的 OSEP 被标记为已实现，OSEP-0006（开发者控制台）被撤销（#2624 #2670 #2671 #2672 #2673); OSEP 索引页已从文档站点中删除 — GitHub 上的 oseps/ 是规范索引 (#2674)

升级与兼容性

  • 中断：已关闭请求对象中的未知字段现在返回 422 — 先前忽略的密钥（例如卷上的 readonly）被拒绝；每个字段发送一次，alias 或 Snake_case，但不能同时发送；在 TypeScript SDK 中，ImageAuth.token 与 username/password 组合现在失败 — 仅发送 username 和 password (#2576)
  • 弃用：服务器代理数据路径（/sandboxes/{id}/proxy/{port}、use_server_proxy、SDK/CLI/MCP 选项）处于维护模式 - 没有新功能，仅进行安全性和错误修复；通过入口网关公开沙箱流量（#2548）
  • 行为更改：前台隔离运行中的代码无法再读取会话的标准输入（它只能以这种方式获取运行自己的脚本），并且语法错误现在会在会话存活时以状态 2 结束运行 - 之前它会杀死 shell (#2517)
  • 行为更改：目录下载返回 400 INVALID_REQUEST_BODY，而不是依赖于文件系统的 500 或空/不完整的 200/206；使用/directories/list路线；格式错误的范围 416 获得 message 字段（#2451）
  • 行为更改：空闲暂停活动探测答案必须是未压缩的，最多 4 KiB，并且在 timeoutSeconds 内作为整个交换范围完成 — 其他任何内容都是对该候选者的错误判决（#2596）
  • 行为更改：空闲 Pod 数量超过降低的 poolMax 的池现在会扩展超出部分（仅删除空闲 Pod）（#2470）
  • 快速沙箱：支持 OCI 的部署默认保留空闲的 ublk 设备池 - 设置 runtime.oci.poolLow=0 以保留之前的按需行为，并将 poolSizeGB 与自定义磁盘大小的内置模板容量相匹配（#2594）
  • 快速沙盒：端口范围的出口规则 (NetworkRule.ports) 现在在快速沙盒路由上被接受并强制执行 - 它们之前返回 400；现有规则不受影响 (#2662)
  • 仅实验性出口实时修订运行时：额外的拦截端口在启动时被拒绝 - 启用该运行时时删除 OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS (#2587)
  • 仅实验性快速沙箱修订运行时（OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME=true）：数据平面就绪挂钩可能会返回 503，直到主题快照得到确认；创建然后等待 fastpath_wait_ready_seconds（默认 30 秒）并返回 Pending/Unavailable (#2666)
