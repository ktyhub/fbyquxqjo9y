OpenSandbox release-1.1.1

这个项目是干啥的：一个用来隔离运行代码和程序的沙箱工具，把程序关在安全小房间里跑，给需要安全执行不可信代码的开发者用。

1.1.1 补丁线的稳定剪切：修复了损坏的 1.1.0 服务器轮 - 孵化的 VCS 排除过滤默默地从 PyPI 包中删除了提交的 FastPath gRPC 存根，因此 opensandbox-server 的每个 1.1.0 安装在导入时都会失败； PyPI 是不可变的，因此修复程序在此行上发布（#1959）。 SDK/CLI/服务器包在 1.1.1 上发布（1.1.1-rc.1 仅发布图像）。 1.1.0 上的每个人都应该升级。以下每个部分的基线：release-1.1.0。

变更架构图

亮点

  • 修复了 1.1.0 服务器轮：FastPath 存根现在包含在包中并干净地安装导入； SDK/CLI/服务器包在 1.1.1 发布（#1959）
  • 身份绑定文件系统操作：execd 将文件 API 作为显式 Linux UID/GID 执行，所有五个 SDK 中均包含 FilesWithIdentity/files_with_identity；隔离会话获得多个独立的覆盖安装 (#2070 #2093 #2094 #2095 #2096 #2097 #2032)
  • 服务器强化：快照创建在持久化之前提交运行时对象，因此早期读取无法映射到 Failed，代理后端故障映射到 502/504 而不是通用 500，以及池沙箱的诊断工作 (#2098 #2077 #2084 #2104)

服务器

  • 通过桥接到 agents.x-k8s.io/v1beta1 上的 spec.operatingMode (Running/Suspended) 来实现代理沙箱提供程序的暂停/恢复，并进行状态派生 (Paused/Pausing/Resuming/Terminated) 以及无效转换时的 409；两个端点之前都返回“不支持”（#1975）
  • 隔离共享一个 Kubernetes 命名空间的租户：创建标记 opensandbox.io/tenant，并列出/获取/删除/暂停/恢复/代理将其他租户的标记沙箱隐藏为 404，而未标记的旧沙箱在到期之前保持可见；还为 ServiceAccount CA 不匹配添加了 kubernetes.insecure_skip_tls_verify (#1973)
  • 修复服务器在多租户模式下重新启动后静默更新意图下降的问题：解析器现在回退到集群范围的标签查找，并使用 403 断路器和结构化警告，trust 在可验证时从意图负载中观察入口命名空间，并且单租户部署永远不会解析超出配置的命名空间（[#1819]（https://github.com/opensandbox-group/OpenSandbox/pull/1819））
  • 添加 [docker] publish_host 以在一个主机地址上发布桥接模式沙箱端口（默认 0.0.0.0 不变） - 使用 127.0.0.1 或 Docker 桥接网关，无令牌 execd 端口不再登陆公共接口（#1954）
  • 添加一个类型化的、仅限管理的 [egress.upstream_proxy] 配置部分（URL + 可选授权，在加载时验证），该部分在 Docker 和 Kubernetes 上注入 sidecar 的链接上游 CONNECT 代理，当请求的 networkPolicy 不兼容时，会出现故障关闭 400 秒；秘密值不再在配置验证错误中回显（#1999），加上 ca_cert_path (Docker) 和 ca_secret_name (Kubernetes)，因此由私有 CA 签名的 https:// 代理是 trusted，无需替换系统 trust 存储 — PEM 在 sidecar 中增强了 /etc/ssl/certs (#2030)
  • 使 k8s/fsb 上的早期读者能够无竞争地创建快照：POST /sandboxes/{id}/snapshots 现在会在持久化 Creating 行之前创建运行时对象（SandboxSnapshot CR / fsb 提交），并在不排队工作线程的情况下返回，因此读取时同步无法再将尚未创建的对象映射到 Failed — 包括在其他 HA 副本上；恢复重新提交内联卡住的行（#2098），修复创建后立即进行 client 轮询将行翻转为永久 Failed 的窗口（#2077）
  • 将代理后端故障映射到有意义的状态：读/写超时返回 504 BACKEND_TIMEOUT，响应中重置和协议错误返回 502 BACKEND_RESPONSE_FAILED，为连接故障保留 502 BACKEND_CONNECTION_FAILED — 在请求中终止的沙箱不再看起来像服务器错误（#2084）
  • 查找池分配的 pod 以进行 k8s 诊断：池化的 BatchSandbox 不带有 opensandbox.io/id pod 标签，因此每个日志/事件/检查调用都会返回 404；查找现在回退到工作负载的 alloc-status 注释中列出的 Pod (#2104)
  • 在配置块运行之前创建失败时删除自动创建的 Docker 卷（映像拉取、凭据/上游代理检查、Windows 先决条件、OSSFS 准备） - 输入错误的映像名称不再泄漏它触发的 PVC (#2103)
  • 将删除池/任务模式 BatchSandbox 报告为 Stopping/DELETING：metadata.deletionTimestamp 现在胜过运行时状态发布，因此在最终确定期间 pod 未就绪的沙箱不再翻转回 Pending/CREATING (#2122)
  • 阻止 Docker 元数据 PATCH 恢复已删除的密钥：patch() 现在从覆盖文件开始（如 get() 那样），而不是重新合并容器标签，因此 {"env": null} 保持删除状态，清空的覆盖文件不会恢复原始标签（#2065）
  • 在模板创建时接受 env 并将其烘焙到快速沙箱黄金映像中（/etc/sandbox-init.env，继承源映像的 OCI Config.Env），缩小 SandboxTemplate.spec.envs 存在但生命周期 API 拒绝它的差距；所有 SDK 均受支持 (#1984)
  • 唤醒 Kubernetes 创建等待通知者监视事件，而不是固定的 1 秒轮询，将预热池创建延迟从约 1 秒缩短到数十毫秒，同时保持轮询回退（#1996）
  • 强制将提交的 FastPath gRPC 存根发送到服务器轮中 - 将它们包含在孵化的 VCS 排除项中，并在发布之前在发布工作流程中烟熏导入构建的轮 - 这是 1.1.0 安装时损坏修复（#1959）
  • 修复了 Helm RBAC 和 fsb 快照运行时中的快速沙箱快照 CR 复数 (sandboxsnapshots)，其中 sandboxesnapshots 可能因缺少 RBAC 而导致列表/监视失败 (#1972)
  • 通过 429 容量映射传播底层 FastPath 错误消息（保留状态和 Retry-After，添加 cause 字段），以便准入/运行时故障（例如 KVM 设备损坏）不再被掩盖为池耗尽，并在映射之前警告记录原始错误（#2001）
  • 澄清续订合同：renew-expiration 可以缩短、保留或延长到期时间（任何未来目标均有效），而 max_sandbox_timeout_seconds 仅限制创建，而不限制续订或总生命周期 — 文档和 SDK 参考一致，并涵盖 Docker、Kubernetes 和 FastSandbox (#2087)
  • 修复 Docker 边缘：拒绝使用记录的 409 重复暂停已暂停的沙箱，而不是将 Docker 的“已暂停”显示为 500（#2023），并仅针对选择隔离扩展的沙箱清除 Docker 屏蔽/只读系统路径，以便可以安装嵌套的 Bubblewrap私有 procfs (#1982)

SDK

  • 端到端添加身份绑定文件系统操作：execd 获得由每个请求工作进程支持的附加 /v1/filesystem/{uid}/{gid} 路由，该进程使用显式凭据和帐户派生的补充组运行（故障关闭，现有路由不变），并且每个沙箱 SDK 都会公开它 - Python files_with_identity、JavaScript filesWithIdentity、Kotlin filesWithIdentity、 C# FilesWithIdentity、Go FilesWithIdentity — 因此 Linux 在实际访问时检查所选用户的权限；身份选择属于 trusted 后端，这会强制执行文件系统权限，并且不是租户边界 (#2070 #2093 #2094 #2095 #2096 #2097)
  • 在 API 和所有五个 SDK 上的每个隔离会话中公开多个独立的覆盖安装：CreateIsolatedSessionRequest.overlays ({path, mode, persist}) 具有单独的主机跟踪或临时 tmpfs 上部，workspace 保留为糖，而 SessionState 与规范列表相呼应 — 完成了内部基础#2021 (#2032)
  • 在所有五个沙箱 SDK（Python 异步/同步、JavaScript、Kotlin/Java、Go、C#）中添加 commands.setEnv，以实现持久运行时环境注入：将 KEY=VALUE 附加到沙箱环境文件，并具有运行时精确序列化、本地密钥/NUL 验证以及未设置 EXECD_ENVS 时的大声失败(#2013)
  • 跨沙箱、代码解释器和 MCP SDK 进行系统性跨语言审计清理：重试回退崩溃至零延迟并丢弃会话 cwd、Python 隔离会话忽略 encoding 和准备预算报告陈旧错误、JS 恢复共享并终止源沙箱的传输、Kotlin 代码运行丢弃每个 SSE 框架事件和永远不会设置 exitCode，C# create 在新鲜沙箱 404 上失败，并且在空主体上创建 NRE，MCP 每次调用都会关闭，从而破坏服务器范围的共享传输 — 每个都通过回归测试进行修复 (#2020)
  • 支持在所有五个 SDK 上创建模板上的 env，匹配服务器端黄金图像烘焙 (#1984)
  • 跨语言对齐后台命令流完成：删除 execd 的固定完成延迟后，Go、Kotlin 和 C# 中的后台结果收集现在在启动确认时返回，如 Python 和 JavaScript，而不是等待 EOF 并推断退出代码 0 — 查询最终结果的命令状态；对于较旧的服务器，前台调用仍会读取 EOF (#1825)

Python

  • 引发来自 create_session 和 delete_session 的错误响应：两者都将解析的模型传递给错误处理程序（需要原始状态），因此 400/404/500 返回 None 作为成功，并通过伪造的 status_code=200 引发未知状态 - CLI 可以为从未存在的会话打印“已删除会话” (#2066)
  • 在 ConnectionConfig/ConnectionConfigSync 上公开 follow_redirects，传播到所有手写异步/同步 httpx client，包括 SSE clients 和生成的 client 包装器 (#1123)
  • 当准备期限在请求中到期时，保留最后一个真实端点错误：预算不再将其自己的 SandboxReadyTimeoutException 记录为 last_error，因此像 KUBERNETES::POD_IP_NOT_AVAILABLE 这样的原因不会被掩盖为普通超时（#2121）
  • 在服务器代理模式下验证代码解释器请求：上下文创建和流式执行现在像沙箱文件请求一样附加 API 密钥，修复来自同一代理的 401 (#2125)
  • 序列化 SandboxPoolSync.shutdown() 拆解：并发关闭（或关闭赛车 start()）可能会两次关闭预热事件循环；拆卸现在在专用锁下是幂等的（#2041）
  • 孤立共享预热事件循环，而不是在运行中预热时关闭它：当有界耗尽等待结束且预热仍在运行时，关闭会使循环保持活动状态，以便运行中预热完成并清理其沙箱，而不是销毁挂起的任务并跳过清理（#2142）
  • MCP：将预期的 OpenSandbox 验证映射到 MCP 2.x ToolError，以便 clients 获得可操作的消息，而不是通用的“执行工具时出错”（#2108）

JavaScript

  • 将空体非 2xx 响应视为错误：openapi-fetch 不会为 Content-Length: 0/204/HEAD 响应设置 error，因此来自网关的空 404/502/503 使 deleteSandbox、pauseSandbox 和文件删除在沙箱和代码解释器包中看起来都成功(#2101)

科特林

  • 通过 sandbox.filesWithIdentity(uid, gid) 进行身份绑定文件系统操作 — 请参阅上面的跨 SDK 条目 (#2095)

C#

  • 通过 sandbox.FilesWithIdentity(uid, gid) 进行身份绑定文件系统操作 — 请参阅上面的跨 SDK 条目 (#2096)

去

  • 通过 sandbox.FilesWithIdentity(uid, gid) 进行身份绑定文件系统操作 — 请参阅上面的跨 SDK 条目 (#2097)
  • 记录以前未覆盖的表面：文件操作、卷安装 (host/pvc/ossfs)、完整模板工作流程、带有自定义运行状况检查的 WaitUntilReady 和 SandboxManager (#2024)

控制器

  • 在 opensandbox/controller 仪表上添加 OpenTelemetry 分配器路径指标：池分配计划、分配状态持久性和分配结果同步持续时间直方图（具有命名空间/池/成功属性），通过 OTLP 导出（#2014）
  • 为自定义扩展准备池分配表面：poolassign 下的 Predicate 接口和谓词方法现在已导出 - 包保留在 kubernetes/internal/ 下，因此外部 Go 模块尚无法导入它（#2037）
  • 自动替换在初始启动期间陷入配置失败的 BatchSandbox Pod：在达到阈值后将删除在 ImagePullBackOff/ErrImagePull 中等待的从未就绪的 Pod，以便调度程序可以逃脱损坏的节点（一个完整的磁盘导致一个生产队列有 114 个卡住的沙箱），并提供每个沙箱、每代替换预算和 PodRecoveryLimitReached 警告；永久损坏的图像将被跳过（#1961）
  • 支持自定义快照映像 URI 模板：--snapshot-image-uri-template / controller.snapshot.imageURITemplate 名称 rootfs 和带有快照/沙箱/容器/命名空间元数据和 date/dateInZone 帮助程序的 QEMU VM 状态目标，在创建作业之前进行验证（无效引用、重复目标）；空保留现有命名（#2004）
  • 修复了仅在非空 IP 上接纳 pod 的 free-pod 谓词：任务调度程序将任务绑定到标记为 NotReady（仍在启动或重新启动）的 pod Kubernetes，分配 POST 失败且没有重试，并且跳过了健康的同级；现在像其他所有谓词一样需要准备就绪（#2138）
  • 当状态查询在发布期间失败时，保留最后已知的任务状态：单个超时的 /getTasks 不再将 releasing 任务标记为已消失，从而跳过 Set(nil)、跳过 postStop 挂钩，并让控制器在任务仍在运行时删除清理终结器或将 pod 返回到池中 (#2067)
  • 跳过已 Paused BatchSandbox 的暂停调度：更新暂停的沙箱会影响其生成并重新触发 handlePause，它需要正在运行的源 Pod 并将沙箱驱动到 Failed/PauseFailed (#2082)
  • 修复图像提交者死锁，其中通过 cgroup v2 freeze 暂停 QEMU 容器永远不会完成（KVM 工作内核线程永远不会到达 frozen），方法是跳过已经通过 QMP 暂停的 QEMU 容器的冗余冻结并使用 --pause=false 提交（#1986）

执行

  • 在显式 Linux 身份下执行普通文件系统操作：附加 /v1/filesystem/{uid}/{gid} 路由使用选定的 uid/gid 和帐户派生的补充组生成每个请求的工作进程，在不支持的平台上失败关闭；现有航线保持其当前身份 - 同一版本中面向 SDK 的后续船舶 (#2070)
  • 公开公共隔离会话覆盖 API（验证、与旧版 workspace 的规范合并、每个覆盖分配器分配）— SDK 下的详细信息和 SDK 支持（#2032）
  • 为覆盖会话在其可移动子树 (<upper_root>/.execd-cleanup/<session-id>) 之外提供持久的清理标识：启动恢复仅删除完全匹配的目录，并且在进程内或重新启动时重试部分删除或丢失的记录，而不是孤立上层目录 (#2107)
  • 让已完成的后台命令的子级继续运行：Wait 后上下文取消不再对整个进程组发出 SIGKILL，因此后台 nohup ./server & 会在其脚本中幸存下来 - 取消和超时仍然会杀死该组（#2074）
  • 当 bash 会话运行超时时杀死整个进程组：只有 bash 本身被杀死，因此 (sleep 2; …) 子进程使运行在截止日期之后继续挂起（#2079）
  • 在前台 /command stdout/stderr 事件文本中保留 \n/\r 字节，因此串联事件会重建命令的行结尾，包括空白行和尾随未终止片段；当 CRLF 跨事件到达时，Python SDK 的面向显示的 Execution.text 和 stderr 摘要不再插入额外的空行，而原始 logs.stdout/logs.stderr 保留其原始文本（#2033）
  • 删除每次运行的 bash 会话脚本文件 (execd_bash_*.sh)，该文件保留每个会话环境变量的副本 - 包括机密 - 可由同一用户的任何后续命令读取 (#2076)
  • 在计算长度之前限制 HTTP Range 端：在常规下载和隔离会话下载中，bytes=0-9223372036854775807 溢出到负长度并以损坏的 Content-Range/Content-Length 和无正文回答 206 (#2089)
  • 删除命令完成后固定的一秒延迟，将终端事件返回延迟中值从约 1000 毫秒缩短到亚毫秒，同时保留输出刷新和心跳清理（#1825）
  • 停止在信息级别记录每个 stdout/stderr 块，这在输出繁重的工作负载上占 execd 日志量的 99.8% (#1906)

网络

出口

  • 继续全线的凭据绑定 TLS 拦截基础 (OSEP-0023) [实验]：在 mitmproxy 生命周期锁 (#2036) 下保存的生成固定实时修订会话回调，ECH/SNI/静态传递的无凭据 ClientHello 分类与 needs_registry 准入请求(#2046)，一种有界连接准入注册表，它拒绝耗尽而不是降级为不透明直通(#2062)，并标记选择器切换未发现的准入(#2072)，请求准入固定到一个不可变的快照，没有旧凭证回退和永久已删除主机的围栏 (#2088)、具有全局预算和分页检查的有界请求处理生命周期 (#2091)、未覆盖连接的单调报废截止日期 (#2100)、具有准备/提交/中止重试语义的联合 Receiver/TLS-Registry 发布(#2106) 通过内部 InstallationReceiver (#2120) 连接到经过身份验证的修订 IPC，修订支持的 Vault 突变事务具有精确尝试协调和就绪防护 (#2124)，冻结有效策略修订候选重新验证每个绑定，包括仅 HTTP 的绑定(#2139)、具有精确引导身份和隔离不确定结果的受保护的修订恢复和就绪发布(#2151)，以及针对生产端点的跨语言 IPC 恢复覆盖范围(#2136) — 仅基础工作； public Vault 在门下仍然写入 503，并且选择性 TLS 保持禁用状态
  • 扩展链接的上游 CONNECT 代理：trust https:// 代理由私有 CA 通过附加样式的 OPENSANDBOX_EGRESS_MITMPROXY_UPSTREAM_EXTRA_CA 捆绑包进行签名，该捆绑包增强了系统 trust 存储以进行所有上游 TLS 验证，从服务器的 ca_cert_path/ca_secret_name 配置（#2030）；支持快速沙箱配置文件下的链式代理，具有配置文件范围的端点丢弃，因此沙箱工作负载无法直接到达上游代理，通过 dnsproxy 上游和 Pod 解析器同时解析基础设施 DNS 播种，以及在守护进程停机期间永久删除元素的原子 nft 表播种（#2003）

安装

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.1.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
# Before first install, configure the server API key and enable the ingress
# gateway (required on Kubernetes; the bare render disables it, and the server
# refuses to start with an empty api_key) — see the deployment guide:
# https://open-sandbox.ai/deployment/
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.1.1            # Python
npm install @alibaba-group/opensandbox@1.1.1   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.1.1")
dotnet add package Alibaba.OpenSandbox --version 1.1.1
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.1.1

# Run the server locally
uvx opensandbox-server==1.1.1
