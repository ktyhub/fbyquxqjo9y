OpenSandbox python/sandbox/v0.1.16

这个项目是干啥的：一个用来隔离运行代码和程序的沙箱工具，把程序关在安全小房间里跑，给需要安全执行不可信代码的开发者用。

变更架构图

亮点

  • 默认重试改变了失败行为 — 最重磅的改动是给异步和同步客户端共用了一套重试传输层：幂等请求现在会在 HTTP 429/502/503 时自动重试，带退避、抖动、Retry-After、单次超时和整体截止时间（#1372）。这是唯一需要提前规划的行为变化：依赖快速失败的调用方必须通过 RetryPolicy.disabled() 显式关闭；用户自己提供的传输层不受影响，流式 SSE 也不会重放。另注意 HTTP 429 现在抛的是带解析后 retry_after 的 SandboxRateLimitException，而不是笼统的错误（#1496），所以捕获旧异常类型的代码要更新。
  • 新的生命周期与后台运行能力是纯增量 — Sandbox.create / SandboxSync.create 新增可选的 preStart 和 periodic 生命周期钩子，超时范围以服务端为准（#1588、#1605）；隔离会话可以启动脱离式后台工作，并轮询状态和增量输出（#1456）；sandbox 响应新增 Pool 分配、execd init 模式和加固层等增量字段（#1481、#1474）。这些都是可选启用/尽力而为——字段缺失只是表示服务端无法确认状态——所以采用它们不需要迁移。
  • 对重度用户有实打实的性能与可靠性收益 — 异步 create/connect/resume 现在并行解析 execd 和 egress 端点，把两次管理查询压成一次等待（#1531）；空闲 Pool 清理改成有界并发（PR 实测 100 个 sandbox 的清理从约 8.3 秒降到约 0.8 秒，#1475）。池耗尽也会干净地表现为 HTTP 429 加 KUBERNETES::POOL_CAPACITY_EXHAUSTED 和 Retry-After，而不是笼统的就绪超时（#1581）；创建 sandbox 本身仍是非幂等的，并且刻意不在该状态码上重放。
  • 协议与诊断修复去掉了几处坑 — #1444 让 SSE 分帧符合标准（在 JSON 字符串里保留 Unicode 分隔符，同时接受旧式裸 JSON 帧），#1532 让后台流在 execution_complete 时停止，避免误报 RemoteProtocolError，#1567 修复了端点缓存竞态（一次过期抓取会淘汰较新的结果），错误消息也会把非结构化响应体保留为原始 response_body，并给出更清晰的就绪诊断（#1496、#1493）。对日志/测试断言值得留意的是：异常消息现在包含了以前省略的响应体。
  • 结论：多数用户应升级；不是空操作或重新打标 — 这是一个有实质内容的版本，包含新功能、性能提升和修复，还顺带把 fallback 版本升到 0.1.16 并重新生成了生命周期模型/User-Agent（#1622、#1623）。如果你想要对瞬时 429/502/503 的韧性、更快的启动/清理、后台运行或钩子，或者正踩到 SSE/缓存的 bug，就该升级。如果你要求严格的快速失败语义、捕获旧的无差别 429 异常类型，而且暂时还用不上 RetryPolicy.disabled() / 新的 SandboxRateLimitException，则可以合理跳过。

新消息

✨ 特点

  • 弹性 HTTP 传输 — 异步和同步 clients 现在共享可配置的重试传输，包括回退、抖动、Retry-After 处理、每次尝试超时、总体截止时间和重试回调。默认情况下，对 HTTP 429、502 和 503 上的幂等请求启用重试；需要先前快速失败行为的调用者可以使用 RetryPolicy.disabled()。用户提供的传输保持不变，流式 SSE 请求绕过重放。 #1372
  • 沙盒生命周期挂钩 - Sandbox.create 和 SandboxSync.create 现在接受可选的 preStart 和定期生命周期挂钩，具有稳定的 Python 模型和服务器对齐验证。挂钩超时范围仍然是服务器权威的。 #1588 #1605
  • 后台在隔离会话中运行 — 隔离会话可以启动独立工作并轮询其状态和增量组合输出。活动后台运行暂停空闲收集；只读工作区拒绝后台执行，因为它们无法保留运行日志。 #1456
  • 运行时分配和强化可见性 - 沙盒响应可以公开已确认的池分配摘要，而隔离功能包括 execd init 模式和强化层状态。这些字段是附加的，当服务器无法确认相应的状态时，这些字段将保持不存在。 #1481 #1474
  • 池容量背压 — 兼容的生命周期服务器现在可以将耗尽的 Kubernetes 池容量显示为带有 KUBERNETES::POOL_CAPACITY_EXHAUSTED 和 Retry-After 的 HTTP 429，而不是最终报告通用就绪超时。沙箱创建仍然是非幂等的，并且在此状态下不会自动重播。 #1581

⚡ 性能

  • 更快的沙箱启动 — 异步沙箱创建、连接和恢复同时解析 execd 和 egress 端点，将两个管理 API 查找减少为一个并行等待。失败传播和创建清理语义保持不变。 #1531
  • 有界并行池清理 — 空闲沙箱发布使用有界并发，同时保留尽力清理和遗留公共行为。 PR 中测量的 100 个沙箱清理时间从大约 8.3 秒减少到 0.8 秒。 #1475

🐛 错误修复

  • 符合标准的 SSE 解析 - 命令和隔离执行流现在使用 SSE 特定的框架，在 JSON 字符串内保留 Unicode 分隔符，同时保持与传统裸 JSON 框架的兼容性。 #1444
  • 可靠的后台命令完成 — 后台命令流在 execution_complete 之后停止，从而防止当对等方在最终 HTTP 终止符之前关闭时出现错误的 RemoteProtocolError 故障。前台流行为不变。 #1532
  • 端点缓存竞争修复 — 完成较旧的端点提取不再删除异步或同步 clients 中较新的替换正在进行的提取。 #1567
  • 更有用的 API 错误 — 非结构化 4xx 和 5xx 响应主体包含在异常消息中，并作为原始 response_body 字节保持可用。 HTTP 429 响应使用 SandboxRateLimitException 并公开解析的 retry_after（如果存在）。 #1496 #1372
  • 更清晰的就绪诊断 — 就绪超时消息保留计时、连接上下文和最后的运行状况检查错误，而不建议可能不适用的特定于部署的网络修复。 #1493

📦 其他

  • 重新生成了生命周期模型，将包回退版本提升到 0.1.16，并将异步和同步默认用户代理字符串与版本对齐。 #1622 #1623
