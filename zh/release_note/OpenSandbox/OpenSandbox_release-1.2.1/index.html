OpenSandbox release-1.2.1

这个项目是干啥的：一个用来隔离运行代码和程序的沙箱工具，把程序关在安全小房间里跑，给需要安全执行不可信代码的开发者用。

为从 1.2.0 升级的用户提供稳定的补丁版本，包括 1.2.1 候选版本和后续修复。服务器、CLI、SDK、图表和平台映像一起通过 1.2.1 发货。

变更架构图

亮点

  • 动态凭证： Credential Vault Exchange 跨服务器、出口和所有五个 SDK 解析每个请求的凭证，而无需存储已解析机密的持久性 (#2457 #2535 #2534 #2560）。
  • 多版本快速沙盒 VMM： 托管 Firecracker 1.16.1/1.17.0 捆绑包允许新模板构建选择最高安装版本，而现有工件使用其准确记录的 VMM 版本进行恢复，如果不可用则显式失败 (#2795 #2812 快速沙箱#189)。
  • 更安全的数据和容量管理： 在原子替换可用的情况下，分阶段上传可减少覆盖数据丢失，控制器重新启动可保留实时沙盒 Pod，并且 Docker 强制执行请求的可写层磁盘配额 (#2433 #2478 #2398 [#2716]（https://github.com/opensandbox-group/OpenSandbox/pull/2716））。

服务器

  • 通过 ResourceAware 池上的创建和快照恢复来承载模板 CPU/内存形状；旧池保留其现有行为 (#2602 #2619 #2623 #2628 #2633）。
  • 在可写容器层上强制执行 Docker resourceLimits.disk，对于不支持的驱动程序或无效限制返回 400，而不是默默地忽略它们（#2716）。
  • 允许直接从暂停的沙箱中生成 Docker 快照 (#1941)。
  • 将服务器代理的数据路径移至维护模式；现有流量仍受支持，但部署应迁移到入口网关 (#2548)。
  • 拒绝已关闭请求对象中的未知字段，而不是默默接受拼写错误的选项（#2576）。
  • 通过每个对象通知者失效和服务器端元数据选择器减少 Kubernetes API 流量并列出成本（#2599 #2559）。
  • 要求 OCI 模板工件在预期存储库中通过 SHA-256 固定（#2491）。
  • 当无法恢复 Docker 过期强制时启动失败，同时删除的容器除外 (#2533)。
  • 其他修复改进了创建超时诊断和空闲暂停探测范围（#2434 #2596）； Docker 挂载、主机路径和资源验证（#2421 #2505 #2474 #2701 #2751)；代理 GET 正文和耗尽错误 (#2518 #2519)；以及空元数据过滤器、名称验证和 API 错误代码 (#2461 #2499 #2702 #2703）。

SDK

  • 所有五个 SDK 支持交换凭证源和仅凭证绑定身份验证； Kotlin/C# 使用者必须重新编译并审查扩展的凭证类型 (#2534 #2560）。
  • 可选的详细下载 API 公开状态、标头、范围和部分响应检测，无需更改现有适配器；当编码长度无法描述解码输出时，Python/JavaScript/C# 报告未知总数（#1597 #2592）。
  • 文档扩展了生命周期/网络选项、交换凭证、模板工作流程和 S3 示例 (#2590 #2597 #2620 #2506)。

Python

  • MCP 添加了 command_get_status 和 command_get_logs 用于后台命令轮询和增量输出（#2648）。
  • 静默命令 SSE 流现在超时；放弃下载释放连接，并且流式传输失败始终使用 SDK 异常 (#2527 #2487 #2531 #2570 #2515 [#2525]（https://github.com/opensandbox-group/OpenSandbox/pull/2525））。
  • 优雅的池关闭会排出清理杀戮，而不是放弃沙箱；较小的修复包括端点失效、适配器重定向/挂钩和可操作的 MCP 错误（#2507 #2409 #2553 #2524）。

JavaScript

  • 防止正亚毫秒命令超时变得无限制；修复无限重定向截止日期、结构化隔离会话错误以及迭代期间关闭下载（#2440 #2488 #2466 #2514）。

科特林

  • 将小数命令/会话超时毫秒向上舍入，防止亚毫秒值变得无界（#2537）。

C#

  • 使用常见的 CredentialSource 型号进行直插式和交换式变体；重新编译时更新仅内联假设（#2560）。

去

  • 在 Execution.Text() 中保留代码解释器输出片段，而不插入换行符（#2447）。
  • 强制执行唤醒、运行状态和解释器就绪预算，而不截断已建立的流或接受未完成的就绪探测（#2572 #2611 #2528 #2668 #2480#2504)。
  • 在取消的池操作期间保留清理所有权，并栅栏不完全销毁以进行重试；取消的获取不再消耗健康的空闲容量（[#2542]（https://github.com/opensandbox-group/OpenSandbox/pull/2542）[#2617]（https://github.com/opensandbox-group/OpenSandbox/pull/2617）[#2580]（https://github.com/opensandbox-group/OpenSandbox/pull/2580）[#2616]（https://github.com/opensandbox-group/OpenSandbox/pull/2616））。
  • 生命周期更改后，在不取消其他调用者仍需要的提取的情况下，隔离陈旧端点查找（#2503 #2564 #2579）。
  • 其他修复了绑定重试溢出和服务器提供的延迟（#2452 #2508 #2509)；改进 SSE 解析、多部分边界和标头合并 (#2439 #2618 #2468 #2529)；以及正确的池维护、遥测截止日期和超时测试（#2453 #2565 #2540 #2479）。

控制器

  • 添加命名空间范围的缓存、可配置的领导者选举计时和用于部署调整的 controller.extraArgs (#2571 #2651 #2566)。
  • 在驱逐之前恢复池分配，在控制器重新启动后保护实时沙盒 Pod (#2398)。
  • 拒绝缺少所需摘要的 rootfs 快照并保留其 Pod，而不是删除唯一的可恢复运行时 (#2482)。
  • 其他修复可防止与生命周期相关的内存增长，在 poolMax 减少后删除多余的空闲 Pod，并将恢复 ConfigMap 放置在正确的命名空间中 (#2646 #2470 #2694）。

执行

  • 当 JUPYTER_TOKEN 未设置时发现 Jupyter 运行时令牌 (#2448)。
  • 在重命名之前暂存上传和独立文件替换，以保护现有内容；原子性需要一个可写的包含目录，并具有如下所述的就地权限回退（[#2433]（https://github.com/opensandbox-group/OpenSandbox/pull/2433）[#2478]（https://github.com/opensandbox-group/OpenSandbox/pull/2478））。
  • 在复制/重命名期间保留隔离工作区内容和模式，执行覆盖删除，并拒绝符号链接 chmod 而不是遵循主机目标 (#2638 #2469）。
  • Kubernetes egress-sidecar CA 轮换后刷新 MITM trust，避免持续的 TLS 故障（#2582）。
  • 隔离运行不再消耗 shell 控制输入；删除 Bash 会话会终止所有活动运行，PTY 关闭会挂起普通后台作业，同时保留忽略 HUP 的作业的类似终端的行为 (#2517 #2731 #2733）。
  • 恢复 Jupyter 启动重试和会话清理，立即使不支持的语言失败，并在报告完成之前传递输出/错误（#2486 #2689 #2606）。
  • 在临时设置失败后恢复 SQL 执行，而不自动重播查询 (#2757)。
  • 安全强化： 对下载标头中的控制字节进行百分比编码并纠正 RFC 8187 文件名编码 (#2741 #2516）。
  • 其他修复涵盖命令日志关联和验证（#2598 #2686）； PTY 输出和导出转义符 (#2644 #2772)；下载/搜索验证和文件时间戳（#2451 #2687 #2604)； cgroup-v1 指标和 SQL 字节渲染 (#2641 #2685)；以及针对旧版 Kotlin/JVM 部署的选择加入旧版 SSE 解决方法 (#2472)。

网络

出口

  • Credential Vault Exchange： 使用出口派生的沙箱身份和请求目标通过 UDS/HTTPS 解析新标头；解析失败关闭，保管库既不保留也不缓存解析的机密 (#2457 #2495 #2500 #2501 #2535 #2538 #2539 #2547 #2549 #2563)。
  • 强制执行快速沙箱每个主体 TCP 端口和 IP/CIDR 加端口策略，包括通过 MITM 进行原始目的地检查 (#2662)。
  • 热重载快速沙箱操作员拒绝/允许规则和可达端口上限，无需重新启动出口；更改以原子方式应用于活动主题，保留先前的失败策略并在撤销后拒绝过时的 DNS 答案。网络安全指南记录了部署、优先级和实施边界，同时保留旧指南 URL (#2727 #2814）。
  • 允许 dns+nft sidecar 策略 PATCH/DELETE 选择阻止与 dropEstablished=true 建立的流量；不支持快速沙盒（#2346）。
  • [实验] 通过持久围栏、经过身份验证的子会话和确认的策略/Vault 快照强化严格的 Actions v2 所有权/持久性和主题准备情况；默认值保持不变 (#2441 #2460 #2493 #2586 #2589 #2609 #2634#2649#2666#2708)。
  • [实验] — 不适用于生产： OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound 选择预算内的 TLS 握手实验，无法进行凭证注入或请求转发：所有解密的 HTTP/1.1 和 HTTP/2 源流量仍被拒绝。 all 保持默认； OSEP-0023 推出描述了未完成的工作（#2737 #2797 #2777）。
  • **安全修复：**策略 PATCH 保留未触及的拒绝规则，并且拒绝无效的 defaultAction 值，而不是产生不一致的、潜在的失败开放强制执行（#2664 #2662 #2693）。
  • 更新内核中的快速沙盒 DNS 租约，并在删除期间保留其他主体的租约 (#2652 #2653）。
  • 其他强化包括实验性拦截端口验证、幂等就绪挂钩和 nft 烟雾/回读检查（#2587 #2510 #2543 #2735）。

入口

  • 使用一个队列加等待唤醒预算并根据航班生命周期对其进行验证；混合常规/快速沙箱唤醒路由在启动时不再出现恐慌（[#2511]（https://github.com/opensandbox-group/OpenSandbox/pull/2511）[#2513]（https://github.com/opensandbox-group/OpenSandbox/pull/2513）[#2600]（https://github.com/opensandbox-group/OpenSandbox/pull/2600））。
  • 其他修复验证旧主机名端口，更正最终状态/client-IP 遥测，并删除唤醒测试竞争（#2578 #2484 #2688 #2512）。

快速沙箱

  • 捆绑管理的 Firecracker 1.16.1/1.17.0 二进制文件用于运行时和模板构建，选择准确的工件记录版本进行恢复，而不是默默地使用最新安装的 VMM (#2795 #2812 fast-sandbox#189)。
  • 在有界 cgroup 子树中隔离 ResourceAware direct-Firecracker VMM，保护 Fastlet 免受池本地 OOM 的影响，同时保留失败的运行时身份以进行清理（#2626 fast-sandbox#162）。
  • 在新的对象存储模板中启用空闲页面报告，将客户释放的内存返回给主机，而不更改静态资源承诺；尚不支持 OCI 模板 (#2546 fast-sandbox#114）。
  • 通过可重用的热 ublk 设备和尽力而为的检查点/rootfs 层压缩来改进 OCI 存储（#2594 fast-sandbox#163 #2546 fast-sandbox#158）。
  • 重用本地发布的 OCI 检查点 blob，以实现更快的同节点恢复、有限存储、实时设备引用保护以及注册表回退 (#2812 fast-sandbox#178）。
  • [实验] RootfsOnly OCI 快照现在从运行时捕获扩展到 Fast Sandbox 的 FastPath 和 SandboxSnapshot CRD，具有功能检查、生产模式验证和日志恢复。恢复冷启动而不保留内存； OpenSandbox REST/SDK 模式选择和 RootfsOnly 暂停/恢复仍然不受支持（#2706 fast-sandbox#173 #2812 fast-sandbox#177）。
  • OverlayBD 模板构建现在默认注入访客控制并验证冻结/解冻；现有模板需要重建以获得 RootfsOnly 捕获功能（#2812 fast-sandbox#183）。
  • 为第一方 Kubernetes 组件添加共享 YAML 配置的文件日志记录和轮换，以及可选的 stderr 镜像；日志收集器和自定义启动标志需要迁移（#2812 fast-sandbox#197）。
  • 公开带时间戳的模板构建阶段、经过的时间以及跨映像拉取、rootfs 准备、来宾准备情况、快照和发布的失败 (#2815 fast-sandbox#201）。
  • [实验] Fence 延迟了具有持久所有者身份和确认退役的严格 Actions v2 操作； v1 保留默认值（#2546 fast-sandbox#152）。
  • 添加命名空间/API-client 调整、图表调度挂钩、可选的直接源传递和模板烘焙的 execd init 模式 (#2581 fast-sandbox#161 #2566 #2494#2497)。
  • 立即创建/暂停/恢复转换现在会收敛，不会产生延迟，并且活动池会替换终端 Fastlet Pod，而不是将其计为容量（#2626 fast-sandbox#166 #2706 fast-sandbox#172）。
  • 在 ublkd 设备丢失后恢复空闲的共享快照文件附件，无需手动擦除缓存；与其他沙盒租约的附件仍然受到保护，而不是在实时消费者下重建（#2812 fast-sandbox#193）。
  • 其他修复包括基于 BusyBox 的模板准备情况、时间戳精度和现有秘密渲染 (#2626 fast-sandbox#164 #2706 fast-sandbox#170 #2695);恢复 Firecracker 图像/模板引用的缓存关联匹配（#2812 fast-sandbox#119）。
  • 在不改变饱和容量的情况下扩大 ResourceAware 部署覆盖范围并修正固定装置 CPU 预算 (#2622 #2637 #2647 #2669 #2812)；改进 ublk 恢复、交换/控制台集成测试、KVM 选择和快照分段文档 (#2454 #2561 #2676 #2665 #2714)；门 PR KVM 在维护者添加的 ok-to-test 上运行，没有不相关的标签取消活动运行 (#2813)。

其他

  • 控制台： 添加具有 BFF 持有凭证和自动会话清理功能的浏览器 PTY shell，改进断开连接反馈，并将界面翻译成英语 (#2233 #2639 #2657）。
  • **Node-agent：**通过选择加入的 vm-console 源收集来宾内核/init 控制台输出，使用节点本地 VM 元数据和重新启动安全偏移，而不是集群范围的沙盒监视（#2234 #2677 #2546 快速沙箱#154)。
  • CLI 修复了保留文字输出和字符串配置 (#2520 #2522)；改进配置、参数、超时和覆盖拒绝错误 (#2521 #2551 #2692 #2742 #2748 #2743);并修复 PTY 清理、指标监视和表输出，包括 osb template get 丢失的 manifest_ref (#2523 #2691 #2747 #2745)。
  • 示例添加 ACK PeerPods/TDX 演练并采用 Google ADK 2.13.0 的本机环境/工具集，同时更正 Python 网络隔离示例 (#2545 #2734 #2711）。
  • 治理/文档发布 AAIF 章程和 DCO/CC-BY-4.0 贡献规则，澄清投票和所有权，协调提案状态以及文档签名/出处差距 (#2490 #2678 #2679 #2680 #2624 #2670 #2671 #2672 #2673 #2674#2467)。
  • 维护涵盖孤立节点代理流、死代码/测试清理、单平台种类导入和 Linux/eBPF 测试设置（#2471 #2496 #2640 #2736 #2573#2473)。
  • 发布准备包括候选版本升级、注释和生成的 BOM (#2583 #2584 #2585 #2588 #2720 #2723 #2724 #2725 #2726)。

升级与兼容性

  • 托管 Firecracker： 部署匹配的图表、运行时和构建器映像； runtimeEnvironments → firecracker.firecracker.vmmDir 现在受支持，并且必须引用绝对托管二进制目录。新的托管版本选择最高安装版本（当前为1.17.0）； Full/RootfsOnly 恢复需要清单记录的版本，如果不可用则失败，而不是回退到最新版本。保留现有工件的 1.16.1 二进制文件，无需重新标记它们；保留旧的二进制文件并不能保证持久快速沙盒状态的降级兼容性（#2795#2812fast-sandbox#189)。
  • **请求验证：**从关闭的请求对象中删除未知的键并仅使用一种别名拼写；这些现在返回 422。用支持的 username/password 替换 ImageAuth.token/Docker-config extras，从名称/地址中删除尾随换行符，并仅对策略 defaultAction 使用 allow/deny (#2576 #2499#2693)。
  • SDK 凭证模型： Kotlin/C# 与 1.2.0 不兼容 ABI；重新编译和审查扩大的来源和可为空/无类型的身份验证假设。 Exchange auth仅包含credential； Python 内联源拒绝额外的键，生成模型用户应该更喜欢手写模型。使用带键的 Go 文字来更改源/元数据模型和 Execution； JSON 往返会丢失 Execution.Text() 的私有格式化模式（#2560 #2534 #2447）。
  • 代理/入口： 将仅维护的服务器代理选项迁移到入口；旧主机名端口必须是 1–65535 格式的规范十进制，并且 --wake-park-budget 必须低于 --wake-max-flight-lifetime (#2548 #2578 #2511)。
  • Docker 配额： 提供的 disk/storage/ephemeral-storage 限制必须为正值且受存储驱动程序支持，否则创建返回 400。仅覆盖可写层，不覆盖挂载、卷或映像层； Windows 保留其现有的磁盘大小行为 (#2716)。
  • Docker 预检/启动： 正确的重复、根、包含冒号或保留的安装目的地和数量高于已签名的 int64；显式 / 主机路径允许列表授权所有 POSIX 后代。过期恢复失败现在会阻止启动，除非容器同时被删除；调查持续存在的守护程序错误（#2421 #2505 #2751 #2474 #2533）。
  • **下载：**详细的 API 对于定制适配器仍然是可选的；在附加之前检查 206/isPartial 和范围，并关闭响应正文。未知总数使用-1；编码的 HTTP 长度/范围不是解码的进度或恢复偏移量。 Python 调用者应该捕获 SDK 异常，而不是原始 httpx 错误（#1597 #2592 #2515 #2525）。
  • 超时和轮询： Python 命令流在没有字节的 max(request_timeout, 30s) 之后超时；提高 request_timeout 以获得合法的沉默。 MCP轮询器必须在完成后再次读取日志并保留不透明游标；空输出并不完成。自定义 Go 池存储必须尊重取消，并且不完全销毁将被保留以进行重试（#2527 #2648 #2580）。
  • **上传原子性：**使用可写包含目录进行分阶段上传/隔离替换；现有的可写文件在暂存权限错误时会回退到非原子截断。普通/files/replace保持原位。分阶段替换保留模式，而不是 xattrs/ACL/功能/SELinux 标签；对于普通写入，所有权是尽力而为；对于隔离写入，所有权是会话 UID/GID (#2433 #2478)。
  • 上传存储： 硬链接/开放读取器保留旧的索引节点，分段覆盖可能需要大约三倍的文件大小，并且中断的写入器可以留下暂存文件。避免保留 .osb-upload-/.osb-staging- 名称，尤其是前缀加 16 个十六进制数字；直接重命名现有的碰撞。特殊文件目标会被拒绝，而绑定安装/打开的文件可以阻止重命名；目录同步是尽力而为（#2433 #2478）。
  • 会话生命周期： 独立的前台标准输入现在是 /dev/null；使用文件或此处文档。 Bash 会话删除会终止所有重叠运行； PTY close 在组终止前添加 SIGHUP 和最多 500 毫秒，而忽略 nohup/HUP 的作业可以生存（#2517 #2731 #2733）。
  • Jupyter/JVM: 自定义映像需要显式令牌或可发现的运行时令牌文件以及请求的内核。优先选择阴影 sandbox-api 1.0.18+ 而不是 EXECD_SSE_LEGACY_COMPAT，默认情况下关闭并删除结构化 exit_code 值 (#2448 #2689 #2472）。
  • **控制器配置：**缓存范围必须包括所有托管命名空间，加上快速沙箱模板/运行时环境命名空间；它不会更改 RBAC 或提供租户隔离。查看现已生效的 controller.podRecovery.*，并删除普通清单升级留下的过时的 ConfigMap。自定义选举时间需要租用 > 续订 > 1.2×重试 (#2571 #2581 fast-sandbox#161 #2694 #2651)。
  • **Exchange部署：**对齐服务器/SDK/egress版本； sidecar实时修订运行时不支持交换。未实现解析器调用者身份验证 - Ed25519/JWKS 仍仅用于设计。将受保护的 UDS 或仅 trusted 出口 HTTPS 与 trusted CA 结合使用；沙箱允许规则不得公开解析器，单独的 MITM UID 排除并不是隔离（#2501 #2549 #2631 #2547）。
  • [实验性] 严格操作 v2： 仅在具有持久状态、隔离管理端口和管理员授权的干净基础直接 Firecracker 部署上启用匹配 sandbox.fast.io/actions/v2 的 OPENSANDBOX_EGRESS_ACTIONS_API_VERSION/Fastlet actionsApiVersion 值。暂停/恢复、快照/恢复、实时绑定删除、所有者迁移和相同 UID 重用仍然不受支持；使用终端删除/新 UID、保留栅栏，并且切勿将栅栏视为身份验证或将现有状态降级为 v1 (#2441 #2460 #2493 #2546 快速沙箱#152)。
  • [实验]凭据绑定拦截： OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound 仍然拒绝解密的应用程序转发，并且不得在生产中启用。未设置开关后，启用的两个旧门仍然是已弃用的别名；修订运行时仅适用于安装。显式模式/门冲突、空/未知值以及在 sidecar 上设置此开关会导致启动失败 (#2737 #2797）。
  • 实验启动要求： 凭证绑定模式需要透明MITM、dns+nft，并且仅默认拦截端口80,443；删除不安全的 TLS 验证、链式代理和有效的 ignore_hosts/allow_hosts。检查运行时用户 config.yaml，然后检查 config.yml；读取/解析错误失败关闭。要返回 all，请取消设置两个旧门； sidecar live 版本还拒绝额外的拦截端口（#2587 #2797）。
  • 端口策略： Fast Sandbox 仅支持 TCP，每个规则最多 256 个端口，并且不支持域加端口组合；正常更新保留已建立的流。 dropEstablished 仅在 dns+nft sidecar PATCH/DELETE 上受支持，被 POST 忽略，并且在 Fast Sandbox、仅 dns、live-revision 或 chained-proxy-plus-transparent-MITM 模式中不受支持；它安装数据包丢失，而不是 TCP 重置。单独删除仅允许端口不会触发已建立的流阻塞 (#2662 #2346)。
  • 操作员规则重新加载： Fast Sandbox在一分钟内重新加载运行时可变规则文件；将 ConfigMaps 安装为目录，而不是 subPath，并允许 kubelet 投影延迟。形象化的规则仍然需要新的形象和重新创造。成功重新加载清晰的 DNS 学习租约，因此允许的域需要再次查找；失败的重新加载会保留之前的覆盖，并且不会强制终止已建立的连接（#2727 #2814）。
  • **网络安全边界：**域拒绝过滤 DNS，不直接连接到已知 IP；对这些路径使用显式 IP/CIDR 拒绝或默认拒绝策略。操作员拒绝覆盖操作员允许，因此允许的内部服务需要拒绝范围划分。经典 Docker/Kubernetes 产品仅在提供 networkPolicy 时才注入出口；不支持 poolRef 和 networkPolicy，因此在模板中配置池控件 (#2814)。
  • **ResourceAware 推出：**直接 Firecracker resource-admission.json 从 v2 移动到 v3；旧/新 Fastlet 拒绝其他配置版本，因此协调每个池的控制器/Fastlet 升级。心跳仍然是 v2。主机需要可写 cgroup v2、clone3(CLONE_INTO_CGROUP) 和零有效池交换；共享内存上限不是针对每个虚拟机的保护，也不是容器替换后生存的保证（#2626 fast-sandbox#162）。
  • 恢复大小调整： ResourceAware 池使用模板 CPU/内存形状；新的快照重播源限制，恢复时间调用者限制必须匹配。没有记录限制的旧池和快照保留其先前的行为 (#2623 #2628 #2633）。
  • [实验] RootfsOnly： Full 仍然是默认值；显式 RootfsOnly 模式可通过 Fast Sandbox FastPath/CRD 用于可重用的 OCI 快照，而不是暂停/恢复或 OpenSandbox REST/SDK 模式选择。新的捕获需要合格的修补 Firecracker 1.17.0 模板、实时访客助手、合格的内核/OverlayBD 后端、专有的 ext4 所有权以及具有匹配摘要/存储证明的绝对 FAST_SANDBOX_ROOTFS_QUALIFICATION 配置文件；自定义二进制摘要不会绕过版本门。一起升级运行时、Fastlet/Proxy、构建器和工具，重建合格的模板，并保留日志/栅栏。恢复冷启动并重新运行入口点；不承诺应用程序内存保留或经过验证的跨CPU/架构可移植性（#2706 fast-sandbox#173 #2812 fast-sandbox#177 快速沙箱#189)。
  • OverlayBD 模板构建： 来宾控制注入和冻结/解冻验证现在对于 OCI 构建器是强制性的； FSB_GUEST_CONTROL_ENABLED 不再是选择退出的选项。丢失/不兼容的帮助程序或失败的探针会停止构建。原生模板不变；现有 OCI 模板需要重建而不是元数据编辑才能获得捕获功能（#2812 fast-sandbox#183）。
  • 快速沙箱日志： 覆盖的 Kubernetes 组件现在默认在 /var/log/fast-sandbox 下写入旋转文件（每个文件 100 MiB、10 个备份、7 天备份保留、gzip）；除非配置了 alsoStderr: true，否则应用程序日志不再出现在 kubectl logs 中。将旧版 klog 输出标志替换为共享日志记录 YAML，为图表管理的静态工作负载连接 ConfigMap/日志卷挂载，并单独配置每个租户命名空间。配置仅在启动时使用：对 Fastlet 使用受控池耗尽/替换，而不是删除活动 Pod，并在临时日志丢失之前安排收集。显式丢失/无效的配置或不可写的输出会阻止启动；轮换限制不是硬盘配额，也不涵盖来宾/VM 日志 (#2812 fast-sandbox#197）。
  • OCI 检查点缓存： 为附加 blob 缓存保留空间（默认值：16 GiB、4096 个文件、1 GiB 可用空间保留），与 OverlayBD 的块缓存分开。将暂存/缓存/设备状态保留在一个文件系统上，以便硬链接重用；跨文件系统放置或争用将回退到注册表。设置 FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES=0 以禁用 blob 缓存插入/查找；有源设备引脚仍然受到保护，包括预算缩减时（#2812 fast-sandbox#178）。
  • ublkd 恢复： 仅当没有其他沙盒租约需要附件时，自动共享快照文件重建才适用；它不是正在运行的虚拟机的透明恢复。在正常生命周期中删除受影响的沙箱，然后在其他租约剩余时重试，而不是手动擦除共享缓存（#2812 fast-sandbox#193）。
  • 模板重建： 选择加入 runtime.execd_run_as_init 需要重建模板； execd 仍然是 guest PID 1 下的子收割机。空闲页面报告还需要重建对象存储模板和兼容的 VMM/内核支持，无法切换恢复的设备状态，并且不启用 OCI 报告或证明更高的过度使用是合理的；回滚使用旧模板（#2494 #2497 #2546 fast-sandbox#114）。
  • **OCI图表默认值：**现在保留空闲的ublk设备；设置 runtime.oci.poolLow=0 进行按需分配，并将 poolSizeGB 与四舍五入的 rootfs 容量相匹配。 P2P 默认保持启用状态；自定义 runtime.config 需要单独调整直接源传递（#2594 fast-sandbox#163 #2566）。
  • 快照完整性： 缺少提交摘要现在在保留 Pod 时无法暂停；旧快照未修复。 OCI 模板引用必须在预期存储库中携带完整的 SHA-256 摘要；重建无效引用（#2482 #2491）。
  • CLI 脚本： 非肯定请求超时和空规则目标是使用错误； osb config init 覆盖拒绝现在退出 1，而不更改文件 (#2742 #2692 #2743）。
  • VM 控制台集合： 选择加入 vm-console，将 hostPaths.vmConsole 与运行时状态根对齐，覆盖每个运行时节点，并管理文件接收器保留（#2234 #2677）。
  • 工件验证： 伞式工作流程不提供一揽子签名/出处覆盖； BOM 摘要匹配不是来源证明，并且不得绕过签名要求 (#2467)。
