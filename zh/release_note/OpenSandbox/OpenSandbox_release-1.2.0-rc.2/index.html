OpenSandbox release-1.2.0-rc.2

预发布 发布时间2026年10月21日 来源opensandbox-group/OpenSandbox 英文原文

OpenSandbox release-1.2.0-rc.2

1.2.0 系列上的第二个候选版本，包含自 release-1.2.0-rc.1 以来合并的所有内容 — 标题是 Credential Vault (OSEP-0022)，用于快速沙箱的端到端登陆：具有持久的每个主题持久性和暂停/恢复传输的出口持有的保险库、用户可访问的服务器路由保险库 API 和池固定的 MITM CA。网络策略遵循相同的出口保持模式，并且 NetworkRule 在经典配置文件中获得端口范围的规则 - 快速沙箱拒绝它们失败关闭，直到 fastlet nft 路径强制执行它们。图片现已发布； SDK/CLI 封装以 1.2.0 稳定凸点发货。请测试并报告问题。

变更流程图

亮点

  • Credential Vault (OSEP-0022) 端到端地实现快速沙箱：出口 sidecar 保存带有持久每个主题文件的库、用于暂停/恢复的密封快照传输以及插槽重用时的陈旧主题接管 (#2249 #2252 #2255 #2250);服务器通过 FastPath 处理程序中继公开用户可访问的 POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API，其凭证值从未出现在任何公共读取中 (#2263)，并且 MITM CA 固定在每个池中，因此出口重新启动不再在实时沙箱下旋转 trust 锚点 (#2251)
  • 网络策略镜像保管库：记录的快速沙箱策略通过中继 CRUD、持久持久性和暂停/恢复快照传输 (#2309) 成为出口保持状态，并且 NetworkRule 在经典配置文件中获得端到端的端口范围规则 - 规范、sidecar nftables、服务器验证和所有五个 SDK，而快速沙箱拒绝 ports目前失败关闭 - 加上没有用户策略可以打开的运营商端 TCP 端口底线 (#2212)
  • 生命周期和诊断改进：lifecycle.renewalPolicy 替换了不透明的续订扩展密钥 (OSEP-0009) (#2296)；诊断上下文 API 到达服务器、所有五个 SDK 和 CLI (#2292)； execd 修复使启动失败可区分，逐字节保留会话输出，并停止无提示磁盘增长 (#2303 #2318 #2295)

服务器

  • 实现凭证保险库的服务器端（OSEP-0022，快速沙箱配置文件）：用户可访问的 POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API 通过 FastPath InvokeHandlerAction 处理程序中继推送完整的保险库修订，并将中继响应视为同步出口验证的确认 - CRD 永远不会携带保险库材料，并且每次公共读取都会在服务器端进行清理； PATCH 在内存中组成（delete → replace → add，每个名称最多解析一次），以 expectedRevision 作为跨副本后备，非 fsb 后端代理 sidecar 的 /credential-vault 表面，并且 fsb credentialProxy 创建时拒绝被解除（#2263）
  • 将固定的 MITM CA 烘焙到服务器创建的 SandboxTemplates (OSEP-0022) 中：新的 [kubernetes] template_mitm_ca_secret / template_mitm_ca_secret_key 配置（默认关闭）在每个服务器创建的模板上发出 spec.egressMitmCertificate — 仅证书条目，从不私钥； Secret 必须存在于每个模板命名空间（ops-runbook 发行版）中，并且丢失的副本会导致构建明显失败 (#2288)
  • 添加 lifecycle.renewalPolicy (OSEP-0009)：访问更新选择加入从不透明的 extensions["access.renew.extend.seconds"] 创建密钥移动到结构化的 renewalPolicy.extendSeconds (300–86400)，镜像 idlePolicy 模式；旧密钥已被弃用（在 1.x 中受支持，在 2.0 中被删除），只有当解析值匹配时才接受两者的设置，该值标准化为现有的 Docker 标签/Kubernetes 注释，因此升级前沙箱会不断更新，快速沙箱会以 400 拒绝它，而不是默默地接受无操作(#2296)
  • 实现诊断上下文端点（来自 rc.1 的 OSEP 合约）：GET /v1/sandboxes/{sandboxId}/diagnostics/context 返回 Docker、Kubernetes 和 Fast Sandbox 的沙箱 ID、生命周期状态、后端类型和后端定义的标识符，无需连接到 execd — Kubernetes 上下文在分配 Pod 之前保持可用，未实现它的扩展后端返回 501 (#2292)
  • 通过沙盒代理转发仍然编码的路径：Starlette 从百分比解码路径绑定 {full_path:path} 路由，代理将该值粘贴回上游 URL，因此解码的 ? 启动查询，# 片段，%2F 成为分隔符，%25 和非 UTF-8 转义被重写，并且 %2E%2E 段被解析 - 代理现在从原始路径中获取 client 的仍编码尾部（验证它解码为路由路径，并进行重新编码后备）并从原始查询字符串中读取查询；后端逐字节接收请求目标，与入口网关匹配，并且 Docker 主机映射端点上的 %2E%2E 前缀转义已关闭（#2228）
  • 在 Pod 仍在运行时报告 BatchSandbox 过期：过去的 spec.expireTime 仍被报告为 Running（带 IP 的就绪 Pod），因此挂钟计费在配置的超时后持续增长；到期现在在就绪状态之前检查并返回 Terminated / SANDBOX_EXPIRED，其中 last_transition_at 设置为 expireTime 本身（#2238）
  • 拒绝会默默删除写入的 gVisor 快照：gVisor 默认 --overlay2=root:self 下的 docker commit 可以报告 READY，同时恢复沙箱的任何写入（只有不透明的 /.gvisor.filestore.* 条目可见）；快照预检现在会解析容器的运行时并拒绝 gVisor，除非有效参数包含 --overlay2=none，并且当文件系统差异仅用于文件存储时，创建会失败（#2241）
  • 将 [docker] 安全配置文件和 secure_runtime 应用于 execd 缓存容器：它忽略了 apparmor_profile / seccomp_profile / docker_runtime，因此在默认 seccomp 配置文件阻止 execd 映像的主机上，每个 POST /sandboxes 都会失败 503，并且没有配置转义 (#2254)
  • 确保并发 Docker 元数据补丁安全：存储的读取-修改-写入已解锁，每次写入都共享一个临时名称，因此对沙箱的两个并发 PATCH /metadata 请求会争先恐后地达到 500（重命名时为 FileNotFoundError），或者默默地丢弃对方的密钥；存储范围的锁加上每次写入的临时名称序列化补丁（每个密钥的最后写入获胜），失败的写入不再留下其临时文件，并且端点合同现在按运行时记录 - Kubernetes 补丁写回它读取的整个标签集，fsb 补丁仅发送由 UID 和生成隔离的自己的密钥（[#2267]（https://github.com/opensandbox-group/OpenSandbox/pull/2267）[#2281]（https://github.com/opensandbox-group/OpenSandbox/pull/2281））
  • 解决事件循环之外的代理端点：HTTP/WebSocket 代理处理程序直接调用同步 get_endpoint — Docker 上的每个代理请求调用一个 Docker 套接字，apiserver 读取 Kubernetes 缓存未命中 — 阻塞每个其他请求和流的循环；缓慢的 Docker 守护进程（例如在镜像拉取期间）足以冻结服务器；现在，查找通过 asyncio.to_thread 运行，并保留租户上下文（#2268）
  • 启用 Redis 消费者时应用更新冷却时间：代理更新完全跳过 min_interval_seconds（每个代理请求运行 get_sandbox + 过期更新）并且队列意图仅针对每个入口副本进行限制，因此每个时间间隔最多更新 N 次副本；冷却时间现在适用于每个续订源，并且仅在成功续订后才开始（#2276 #2279）

SDKs

以下代码更改适用于 1.2.0 稳定版本 - rc 不附带 SDK 软件包。

  • 将 Credential Vault client 合约添加到所有五个 SDK (OSEP-0022)：模板支持的沙箱在与网络策略相同的模板源信号（OPEN-SANDBOX-ORIGIN: template 或本地 createFromTemplate 标志）上通过服务器路由 Vault 调用，而 sidecar-direct 适配器保持不变； Python 的 Sandbox.credential_vault 现在返回两个配置文件的保管库服务，并且 Go 获得在同一信号上分支的 Sandbox 级保管库方法（#2263）
  • 将 lifecycle.renewalPolicy 添加到所有五个 SDK (OSEP-0009)：通过创建转换器连接具有 client 端快速失败验证 (extendSeconds 300–86400) 的类型化创建字段，替换不透明扩展密钥 (#2296)
  • 在 SDK 表面上实施诊断（使用 #2292）：context 通过所有五种语言的管理器和沙箱外观公开，并且 JavaScript、Go 和 C# 获得与现有 Python/JVM 表面匹配的公共日志/事件 API（自定义工厂继续工作 -新的诊断服务是可选的）
  • 支持所有五个 SDK 中的端口范围的出口规则 (#2212)：NetworkRule.ports（TCP 1–65535，每条规则最多 256 个，target 现在可选），client 端验证镜像服务器（范围、重复项、上限、域+端口被拒绝、网络掩码-CIDR+端口）被拒绝）； JavaScript 将目标或端口不变式编码为联合类型，Python 在读回时标准化空白线目标

Python

  • 停止将取消的端点获取传播给等待者：共享获取端点缓存将获取调用者的 CancelledError 设置为共享未来，因此并发等待者 - 例如TaskGroup 兄弟姐妹 — 抚养了 CancelledError，尽管没有什么能取消他们；服务员现在重新解析（缓存端点、较新的飞行中获取或他们自己的端点），而取消的调用者仍然像以前一样引发（#2277）
  • 通过沙箱池转发 credential_proxy：PoolCreationSpec.credential_proxy 被同步和异步创建路径删除，因此预热和直接创建沙箱会默默地丢失请求的凭据代理配置；自定义工厂保持兼容（未设置时省略关键字）（#2283）
  • 重新生成生命周期 client 以删除 #2212 中规范更改留下的陈旧硬编码默认值（timeout_seconds: 2、wake_on_access: true → UNSET）；连线行为未更改 - 服务器应用相同的默认值 (#2280)

去

  • 使用 API 密钥对代理数据平面请求进行身份验证：代理模式将租户 API 密钥（可以创建、暂停和删除租户的每个沙箱的凭证）作为 X-EXECD-ACCESS-TOKEN（以及出口身份验证）发送到 untrusted 沙箱，同时忽略服务器中间件读取的 OPEN-SANDBOX-API-KEY 标头，因此多租户代理请求失败401 并表现为就绪超时；租户密钥现在位于服务器标头中，并且永远不会走私到沙箱或出口边车中，无论大小写如何，端点提供的和调用者提供的代理密钥都会获胜，并且直接模式保持无密钥（[#2274]（https://github.com/opensandbox-group/OpenSandbox/pull/2274））

控制器

  • 修复任务执行器将空退出文件视为退出代码 0：填充程序在写入退出文件之前创建退出文件，并且 Inspect 忽略解析错误 - 中间杀死的填充程序（或写入失败，例如完整磁盘）将失败或中断的任务报告为 Succeeded；无效或空文件现在会进入 pid 检查（Running 活着时，ProcessCrashed 一旦消失）（#2270）

执行

  • 保留 bash 会话输出行结尾：run_in_session 标准输出事件删除了 \n/\r 字节，因此空行是不可恢复的，并且连接运行的事件不会重建其输出；事件文本现在带有其原始行结尾（空白行表面为仅包含结尾的事件），将会话流与前台 /command 合约对齐 - 消费者应在每次运行时连接事件文本，而不是将每个事件视为无换行符的行（#2318）
  • 报告 exit_code 命令错误：运行并退出非零的命令和进程从未启动的命令（例如 fork/exec: argument list too long）报告相同的错误事件，因此从 evalue 读取退出状态的 client 可以将启动失败报告为成功；新的可选 error.exit_code 仅当进程运行并完成非零时才出现（信号终止时的 -1）（#2303）
  • 通过隔离会话文件 API 提供 binds 挂载点：合并视图路由器仅注册覆盖挂载，因此 session.files 失败，ErrPathOutsideOverlays 位于 session.run 可以读取的相同绑定目标上；现在每个绑定都会注册一个路由视图（dest → source，只读绑定拒绝写入，绑定视图阴影覆盖在前缀关系上）（[#2299]（https://github.com/opensandbox-group/OpenSandbox/pull/2299））
  • 在取消链接之前截断命令输出文件：分叉的子进程（守护进程）在保存输出 fd 的同时合法地超出命令的生存期，因此未链接的文件会以不可见的 (deleted) 增长的方式持续消耗磁盘，直到最后一个持有者退出；现在，每个现有的删除点都会首先截断为零，并且仅在看门人删除时才会触及后台输出，因此保留窗口保持可读（#2295）
  • 忽略扫描错误的无效上限使用指标：失败的文件系统扫描发出误导性的 execd.isolation.upper.usage_bytes 0，而会话和数据仍然存在；现在省略无效读数（有效的空上部仍报告 0），并且当 upper_max_bytes > 0 和扫描失败时配额准入失败关闭，而不是默默地绕过记帐（[#2257]（https://github.com/opensandbox-group/OpenSandbox/pull/2257））
  • 避免冗余的 JDK MITM CA 导入：安装了多个 JDK 的沙箱通常共享一个 trust 存储，但每个 JDK 都重新运行 keytool 导入（四个 JDK 的 ~6.2 ）；现在，通过解析 trust 存储路径和证书内容比较来消除重复初始化，将阶段切换到 ~0.6 ，同时仍然替换旋转证书（#2310）
  • 当解析的用户环境没有可用的 TERM 时，默认 PTY 会话为 TERM=xterm-256color，因此交互式程序会获得颜色；显式的 TERM 总是获胜 (#2313)

网络

出口

OSEP-0022 保险库项目涉及 fast-sandbox 配置文件的凭证保险库表面； OSEP-0023 后续版本的范围仍然是默认关闭的实验修订运行时。

  • 添加用于快速沙箱的出口保管库（OSEP-0022），分阶段登陆：内部/vault/{sandboxUid}中继表面，具有仅创建的POST（重复的409，跨服务器副本的原子），使用expectedRevision和expectedIncarnation前提条件的完整修订版PUT，这样过时的编写器永远无法登陆重置的后继者，包括值的GET和保留策略的DELETE (#2249);每个主题的持久持久性 - Pod 范围的卷下每个主题一个文件（可选 tmpfs），与策略文件相同的提交协议，因此 acked 意味着持久且已应用，incarnation-fenced 重新加载，并在解除绑定时清除（#2252）；并删除了被取代的 fastlet-proxyVault 路由及其挂起的推送缓存（#2247）
  • 在暂停/恢复期间携带保管库（OSEP-0022“保管库生命周期”）：VAULT_EXPORT 在运行时拆卸之前严格将保管库文件复制到快照捆绑包中，并密封主题（所有保管库操作在暂停时回答 409；强制执行继续），并且 VAULT_IMPORT 是唯一授权的化身转移 - 该捆绑包在 data-plane-ready 之前使用恢复的栅栏重新标记，在任何持久效果之前根据当前策略进行验证；真正的导出失败会使主题解封并无法通过暂停检查点，因此拆卸永远不会在没有捆绑包的情况下运行，并且出口本地保管库可以在重试时幸存下来（[#2255]（https://github.com/opensandbox-group/OpenSandbox/pull/2255））； vaultTransfer 功能信号允许没有保管库持久性的出口完全跳过传输 - 检查点在没有保管库（传输前语义）的情况下继续进行，而不是失败（[#2290]（https://github.com/opensandbox-group/OpenSandbox/pull/2290））
  • 定义槽重用上的过时主题接管：快速沙箱调度密钥是槽 IP 并且槽被重用，因此 SET_BINDING 可以声明仍由已死亡但已注册主题持有的密钥 - 出口现在将其视为权威，在注册后继拒绝优先之前，在注册表锁下拆除过时主题的 nft 规则、DNS 引用计数、MITM 重定向和保管库切片；流量永远不会分派到过时的规则，延迟卸载保持围栏保护的无操作，并且每个失败路径都会使每个主题要么完全注册，要么完全被驱逐（#2250）
  • 固定快速沙箱 MITM CA（OSEP-0022“MITM Trust 锚点”）：池固定的版本化 CA 从只读秘密挂载播种到 mitmdump confdir（幂等，可卸载对上的故障关闭），替换启动时生成 - 出口重新启动不再轮换 CA 并静默地使每个活动沙箱的 TLS 失效trust；丢失或不匹配的 CA 仅拒绝 /healthz 上出现的 mitmCaFingerprint / mitmCaDown 和操作状态的 MITM 插件（策略执行不受影响），因此模板↔池秘密错配一目了然（#2251）
  • 将快速沙盒网络策略与保管库模式保持一致：记录的策略变为出口保持状态 - 具有修订先决条件（未知主题 404、化身不匹配 412、密封 409）的 /policy/{sandboxUid} 中继表面、使用相同提交协议的持久每个主题文件、镜像保管库的 POLICY_EXPORT/POLICY_IMPORT 快照传输，以及在出口重新启动后提交的文件取代重播的创建时绑定输入（#2309）
  • 端到端支持端口范围的出口规则（经典配置文件）：NetworkRule.ports（TCP 1–65535，每条规则 ≤256）使 target 成为可选 — 仅端口规则，或与 IP/CIDR 组合的端口；域+ports 被拒绝，因为域规则在 DNS 代理层评估； Deny-before-allow 优先级在整个范围内保持不变，并且修复了使第二个仅端口规则驱逐第一个规则的 PATCH 合并键错误；运营商提供的 reachable.ports.cap 白名单在每个用户规则之前强制执行为始终拒绝，因此即使 defaultAction: allow 也无法打开非白名单端口； fast-sandbox 路由以 400 拒绝 ports，直到 fastlet nft 路径可以强制执行它们（失败关闭，已记录）（#2212）
  • 将静态 TLS 直通选择器添加到实验性实时修订运行时：OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS 是应用于 ClientHello 的有界精确/通配符主机数组，具有 443 重叠拒绝；现有的非空本机 ignore_hosts/allow_hosts 现在 拒绝在实时模式下启动 — 将静态 TLS 旁路条目迁移到数组（传统模式不变，未添加公共拦截模式）（#2229）
  • 发出 TLS 准入计数器：每个最终 ClientHello 准入源 egress.mitm.tls.connections_total 都有一个尽力而为的事件，带有封闭的 mode/decision/reason 标签 — 它测量准入决策，而不是握手或请求，并且明确不是安全证据（#2265）
  • 添加仅安装主题修订 IPC 基础（OSEP-0023 第 4 阶段）：经过身份验证的 v2 Unix 套接字通道将目标绑定修订事务路由到独立的、禁用准入的安装接收器，并具有冻结请求字节和丢失回复协调功能；还没有生产调用者 (#2284)
  • 发送 egress-trace，出口映像内的只读准入查看器：实时策略状态、nft 集和带有 TTL 的 DNS 租约、用其准入判决注释的真实出站连接，以及将策略拒绝与解析器故障分开的 probe <domain> 子命令； Sidecar 行为没有改变，并且故意不显示解密的 L7 内容 (#2230)
