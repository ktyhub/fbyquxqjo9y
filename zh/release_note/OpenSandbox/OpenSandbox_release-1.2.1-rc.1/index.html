OpenSandbox release-1.2.1-rc.1

预发布 发布时间2026年11月4日 来源opensandbox-group/OpenSandbox 英文原文

OpenSandbox release-1.2.1-rc.1

1.2.1 补丁线上的第一个候选版本，摘自 release-1.2.0 (2026-10-27)。标题：OSEP-0025 Credential Vault Exchange — 一个 exchange 凭证源，通过可插拔解析器、跨出口、服务器、所有五个 SDK、快速沙箱 e2e 和 Credential Vault 指南进行端到端有线连接，提供每个请求标头解析。另外值得注意的是：execd 原子上传、rootfs 快照的摘要验证、Kubernetes 创建超时启动诊断以及大型集群的 informer 缓存范围。每个部分的基线是 release-1.2.0。 rc 版本发布图像但保留包 - SDK/CLI 工件在 1.2.1 稳定凹凸处发货。

变更流程图

亮点

  • Credential Vault Exchange (OSEP-0025)：按请求动态标头解析、故障关闭且从不持久，跨服务器和所有五个 SDK (#2457 #2535 #2534 #2560)
  • 数据安全：execd 上传自动替换，因此失败的写入会保留旧文件 (#2433)；控制器拒绝提交结果缺少摘要的 rootfs 快照 (#2482)
  • 可操作性：创建超时报告pod启动失败原因（#2434）；控制器和 fsb 控制器获得 --namespaces 缓存范围 (#2571 #2581)

服务器

  • 沙盒列表将元数据相等过滤器推送到 Kubernetes 标签选择器中，因此大型命名空间不再在过滤之前实现每个工作负载 (#2559)
  • 模板 OCI 强化：发布存储库语法在创建时进行验证，沙箱创建需要摘要固定的发布引用 - 成功的模板无法再解析为可变或不相关的清单（#2491）
  • Kubernetes 创建超时，在回滚之前附加 Pod 启动失败原因（不可调度、ImagePullBackOff、警告事件） - 可以再次通过 API 诊断映像拉取和调度失败 (#2434)
  • Docker：并发容器删除不再中止启动过期恢复，并且剩余的 Docker 错误会导致启动失败，而不是默默地删除计时器（#2533）；在配置之前，重复的、根的和服务器挂载冲突的目标将被拒绝并返回 400 (#2421 #2505)
  • storage.allowed_host_paths 中的显式 POSIX 根现在覆盖其后代；后代检查产生 // 并且从未匹配（#2474）
  • 代理：声明主体的 GET 会随之转发，因此 Elasticsearch 样式的请求将停止失败并返回 500 (#2518)；池耗尽返回 503 PROXY_POOL_EXHAUSTED 而不是以 500 结尾的 180 秒等待（#2519）
  • 较小的修复：metadata=env= 过滤空值而不是匹配所有内容（#2461）； gateway、bucket-name 和 env-name 验证器拒绝尾随换行符 (#2499)

SDK

所有五个 SDK 均接受 Exchange 凭证保管库有效负载（exchange 源 + 无类型绑定身份验证），与服务器和出口线路合同保持一致 (#2534 #2560）；请参阅升级和兼容性中的 Kotlin/C# ABI 说明。详细的下载方法公开了所有五种语言的响应元数据（状态、Content-Range、isPartial）；现有签名不变，自定义文件系统实现必须添加它们（#1597）

Python

  • SSE 命令流出现读取超时：commands.run() 在 max(request_timeout, 30s) 静默后引发 SandboxTimeoutException，而不是在停止的 execd 上永远阻塞（#2527）
  • 异步池正常关闭会耗尽待处理的杀戮，而不是取消它们并留下未跟踪的沙箱直到 TTL (#2507)
  • 下载流在删除、提前关闭或迭代中期放弃时释放 HTTP 响应 - 不再出现连接池耗尽（#2487 #2531）
  • 流请求和正文读取期间的传输错误会引发 SDK 异常，而不是泄漏原始 httpx 错误（#2515 #2525）
  • 较小的修复：端点缓存失效范围仅限于飞行密钥（#2409）； NetworkPolicyAdapter 传播重定向选项和事件挂钩 (#2553)； MCP 服务器报告 SDK 错误而不是一般消息 (#2524)

JavaScript

  • 隔离会话请求抛出带有状态/请求 ID/错误代码的 SandboxApiException，而不是平面 Error (#2466)
  • 无限或负的重定向截止时间被视为无 - requestTimeoutSeconds: Infinity 不再失败每个经过身份验证的请求（[#2488]（https://github.com/opensandbox-group/OpenSandbox/pull/2488））
  • 在其自己的循环内关闭下载流干净地结束迭代，而不是抛出 TypeError (#2514)

科特林

  • 亚毫秒级命令超时四舍五入为 1 毫秒； 500 µs 之前序列化为 0，execd 将其视为无界 (#2537)

C#

涵盖跨 SDK 交换模型 (#2560)。

去

  • 重试/超时强化：Retry-After 饱和度和 60 秒上限现在适用于通用重试路径 (#2452 #2508)；退避饱和而不是包裹负数（#2509）； ReadyTimeout 在较长的调用者截止日期下强制执行（#2528）；解释器准备就绪探测是有截止时间限制的，并且需要确认零退出（#2504 #2480）；遥测 POST 有自己的五秒限制 (#2540)
  • 端点缓存：在失效期间进行中的获取（#2503）；生命周期突变使缓存的端点无效（#2564）；最后一个离开的服务员取消了共享获取（#2579）；配置/端点标头不区分大小写地合并（#2529）
  • 池：空闲 FIFO 在移除/重新插入后仍然存在（#2453）；关闭服务员尊重来电取消（#2542）； Destroy 限制状态存储耗尽 (#2580)
  • Execution.Text() 连接代码片段而不使用分隔符，因此 "Loading" + "...done\n" 不再获得换行符；命令格式不变（#2447）
  • 较小的修复：SSE 解析器接受 CR 分隔的事件（#2439）；分段上传保留其生成的边界（#2468）；片状诊断断言检查 net.Error.Timeout() (#2479)

控制器

  • 结果缺少摘要的 Rootfs 快照提交现在失败 (CommitResultUnavailable/CommitResultIncomplete) 并报告 PauseFailed 并保留 pod - 之前暂停报告成功，删除 pod，并且以后的每次恢复都永久失败 (#2482)
  • --namespaces 限制通知者缓存的范围，修复大型共享集群上的启动 OOM；空默认值保留完整集群语义；图表值 controller.namespaces (#2571)

执行

  • 上传是原子的：暂存临时文件+重命名，保留模式/所有者和以下符号链接 - 失败的上传（ENOSPC、I/O 错误、终止）不再破坏替换的文件（#2433）
  • 当 JUPYTER_TOKEN 未设置时，Jupyter 令牌是从代码解释器映像的 jpserver-*.json 中发现的；显式配置获胜 (#2448)
  • Jupyter 启动等待恢复到约 5 分钟 - 针对冷图像的退避 Cap 交互在约 11 秒后中止 (#2486)
  • EXECD_SSE_LEGACY_COMPAT（默认关闭）从 1.0.18 之前的 SDK 的 SSE 事件中省略 exit_code，其 kotlinx 运行时在未知密钥上崩溃（#2472）
  • filename* 使用 RFC 8187 attr-chars 进行编码，因此使用 =、:、' 的名称以严格的 clients 进行解析 (#2516)

网络

出口

  • Credential Vault Exchange (OSEP-0025)：exchange 源（UDS/HTTPS 解析器端点）、无类型绑定身份验证、仅标记快照绑定、POST /credential-vault/_resolve 端点以及使用故障关闭 407/stream-kill 注入解析标头的插件集成 — 解析的材料永远不会持久、缓存或读回；仅内联保管库不变（#2457 #2495 #2501 #2500 #2535 #2538)； sidecar 配置文件与快速沙箱 e2e 端到端集成（#2549 #2547 #2561)；添加了指南章节（#2563）
  • 解析器调用者身份验证被推迟 (D5)：https:// 解析器端点必须仅可出口访问（UDS 权限或网络范围的 nft 规则）作为当前 trust 边界 (#2549)
  • OSEP-0023 基础工作仍在继续 [实验]：Vault v2 安全读取器 (#2441)、具有所有者防护的严格遗留管理 (#2460)、具有服务器调用者的严格模式 Vault v2 编写器 (#2493) — 默认值仍为 v1；严格模式需要配对的快速沙箱生产者
  • 重播的 data-plane-ready 钩子是幂等的 (200)，而不是虚假的 409 (#2510)

入口

  • 启动验证：--wake-park-budget必须低于--wake-max-flight-lifetime；错误配置之前用 400 或空 200 而不是 503 + Retry-After 回答停放请求（#2511）
  • 排队的唤醒请求受一个公园预算的限制，而不是近两个 (#2513)
  • 较小的修复：最终状态在 1xx 响应后记录，因此 103 Early Hints 不再伪装成请求状态（#2484）；旧主机路由端口已验证（sb-70000 不再为 502，sb-08080 不再到达端口 8080）（#2578）；修复了仅测试数据竞争（#2512）

快速沙箱

  • 检查点链保持有界：暂停/恢复检查点层链在提交期间通过overlaybd-merge被压缩，因此重复的循环不再无限制地增长恢复链（[#2546]（https://github.com/opensandbox-group/OpenSandbox/pull/2546）[fast-sandbox#158]（https://github.com/opensandbox-group/fast-sandbox/pull/158））
  • 节点本地 VM 发现：firecracker 运行时在进程日志旁边为每个 VM 写入一次写入的 fast-sandbox.json 记录（完整的沙箱 UID、命名空间、名称、位置），因此节点本地代理通过目录扫描发现本地 VM，而不是在集群范围内监视 Sandbox CR；发布永远不会阻止配置，并且拆卸会删除记录（#2546 fast-sandbox#154）
  • 内存：选择加入基于压力的准入来宾内存回收，并在内置模板中默认启用空闲页面报告（#2546 fast-sandbox#114）
  • Fastlet 强化：严格管理的 Actions v2 传输（此版本的出口严格管理接收器的生产者一半）、所有者退休竞赛修复、跨缺席库存的终端围栏保留以及并行准入探测（#2546 fast-sandbox#152）
  • fsb 控制器：--namespaces 确定通知者缓存的范围（当集合错过运行时环境命名空间时拒绝启动），--kube-client-qps/--kube-client-burst 调整共享 API-服务器 client 速率限制器 — 选择加入图表值 controller.namespaces/controller.kubeClientQPS/controller.kubeClientBurst，默认值不呈现新标志(#2581快速沙箱#161)
  • 初始化拓扑：runtime.execd_run_as_init 现在将 EXECD_INIT=1 烘焙到 fsb 黄金映像模板环境中 — 之前在 fsb 上被忽略，因此 execd 从未担任 OSEP-0018 init 角色；注入的值胜过 client 提供的密钥 (#2494)；集成环境固定完整的来宾拓扑，并且整个 e2e 表面默认将其打开（#2497）
  • 集成环境：overlaybd 模板构建会预先探测 ublk 添加/删除路径并自我修复楔形内核设备，而不是在注定的构建中失败约 16 分钟，并且拆卸会释放孤立设备（#2454）；烟雾断言会显示真正的 nft 错误，而不是将其视为缺失规则（#2543）；全链交换解析器验证阶段（服务器中继 → 出口 _resolve → 来宾观察到的注入标头）乘坐 verify-native/verify-overlaybd (#2561)

其他

  • CLI：文本被转义而不是解析为丰富的标记 - 像 /tmp/notes[draft].txt 这样的路径正确打印并且不再失败成功的命令（[＃2520]（https://github.com/opensandbox-group/OpenSandbox/pull/2520））；损坏的配置文件会清晰地报告，而不是使每个命令崩溃（[#2521](https://github.com/opensandbox-group/OpenSandbox/pull/2521)）； config set 逐字存储字符串键值（007123 保持 007123）（#2522）；当 WebSocket 从未打开时，PTY 会话将被删除 (#2523)
  • 节点代理：目录从未出现过的日志流在保留窗口后会被遗忘，而不是永远保留（#2471）
  • 文档：图像签名声明与实际工作流程覆盖范围一致（#2467）； AAIF 章程和治理整合 - 代码贡献现在需要 DCO 签署（#2490）； S3 模板示例集 format: native (#2506); OSEP-0025 状态和合同引脚 (#2539)
  • 内务管理：跨模块删除死代码（#2496）； execd CI 安装 eBPF 烟雾的 Tracef (#2473)

升级与兼容性

  • Kotlin/C# SDK 与 1.2.0 源兼容，但不与 ABI 兼容 — 重新编译；没有电线变化（#2560）
  • Python：静默 SSE 流现在在 max(request_timeout, 30s) 之后引发 SandboxTimeoutException (#2527)；下载正文错误引发 SDK 异常，而不是原始 httpx 错误（#2525）
  • Go：Execution.Text() 不再在代码片段之间插入分隔符（#2447）；非空位置 Execution{...} 文字不再编译 - 使用键控文字
  • Execd 原子上传：不可写目录中的可写文件被拒绝，设备/FIFO 目标被拒绝，xattrs/ACL/setgid 位未携带，绑定安装目标失败 (EBUSY)，SIGKILL 中上传可以留下 .osb-upload-* 暂存文件，峰值磁盘 ~3× 文件大小 (#2433)
  • 服务器启动：过期恢复期间的 Docker 错误（并发删除除外）现在会阻止启动 - 在重新启动的主管下运行（#2533）
  • 入口：现在在启动时强制执行低于 --wake-max-flight-lifetime 的 --wake-park-budget；默认不受影响 (#2511)
  • 模板列表：metadata=env= 现在过滤空值（#2461）
  • OSEP-0025：交换是附加的和选择加入的，但解析器调用者身份验证被推迟 - https:// 解析器端点必须只能出口可达（[#2549]（https://github.com/opensandbox-group/OpenSandbox/pull/2549）[#2563]（https://github.com/opensandbox-group/OpenSandbox/pull/2563））
  • 快速沙箱：默认情况下免费页面报告；每个 VM fast-sandbox.json 记录； controller.namespaces 必须覆盖池/沙箱和运行时环境命名空间，否则控制器拒绝启动（#2546 #2581）
  • 图像：opensandbox/<component>:release-1.2.1-rc.1（所有三个注册表；用于快速沙箱的 fsb 图像）
  • 软件包：未更改 - SDK/CLI 工件在 1.2.1 稳定版本中发布
  • 图表：从此标签渲染（helm template ./manifests/charts/opensandbox）
  • Kubernetes：支持范围 v1.21 – v1.34
  • 倾斜：支持服务器↔ CLI/SDK 同一条线； ±1次轻微警告
