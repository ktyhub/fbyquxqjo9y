OpenSandbox release-1.2.0

这个项目是干啥的：一个用来隔离运行代码和程序的沙箱工具，把程序关在安全小房间里跑，给需要安全执行不可信代码的开发者用。

1.2.0 系列的稳定版本，通过两个候选版本加上一个 RC 后硬化增量，将自 release-1.1.1 以来的所有内容合并。图像随 rcs 一起提供； SDK/CLI/服务器包在 1.2.0 发布。 1.1.x 上的每个人都应该升级。以下每个部分的基线：release-1.1.1。

变更架构图

亮点

  • 快速沙箱的自动暂停和访问唤醒 (OSEP-0024) 实现端到端：入口记录活动并暂停对暂停沙箱的请求，直到恢复完成，服务器在选择加入的 lifecycle.idlePolicy 创建字段后面运行空闲清扫器，并且所有五个 SDK 都获得唤醒重试合同 - 默认情况下关闭，仅附加（#2156 #2180 #2192 #2198 #2218)
  • Credential Vault (OSEP-0022) 端到端地实现快速沙箱：出口 sidecar 拥有具有持久的每个主题持久性和密封暂停/恢复传输的库，服务器公开用户可访问的库 API，其凭证值从未出现在任何公共读取中，并且 MITM CA 按池固定，因此出口重新启动不再在实时沙箱下旋转 trust 锚点 —加上经典配置文件中端到端的端口范围出口规则 (#2249 #2252 #2255 #2263 #2251 #2212)
  • 快速沙箱快照和模板构建可以发布到 OCI 注册表并从 OCI 注册表启动（OverlayBD OCI 生命周期），可靠性活动消除了所有五种语言的 SDK 文件传输中的整个调用超时，使 execd 报告沙箱范围内的 CPU/内存和 OOM 终止，并修复了一长串 Docker 后端正确性和 PTY/会话输出问题(#2338 #2165 #2200 #2191)

服务器

  • 实现 OSEP-0024 自动暂停的服务器端以实现快速沙箱：lifecycle.idlePolicy 创建字段（idleTimeoutSeconds 30–86400、onIdle: pause、wakeOnAccess、可选 activeProbe）保留为保留的沙箱 CR 注释；空闲清理器枚举选择加入的 fsb 沙箱，检查 Redis 中的活动，获取每个沙箱暂停锁定，并发出幂等 FastPath PauseSandbox；声明的 activeProbe 穿过入口网关，而 OpenSandbox-Skip-Activity 哨兵会抑制一个观察，并在网关和代理跃点上被剥离。配置在 [automation.idle_pause] 下移动，并且在启用清扫器时在负载时验证 redis.dsn (#2192 #2181 #2215)
  • 实施 Credential Vault API（OSEP-0022，快速沙箱配置文件）：POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault 通过 FastPath 处理程序中继推送完整的保险库修订，并将中继响应视为同步出口验证的确认 - CRD 永远不会携带保险库材料，并且每次公共读取都会在服务器端进行清理； PATCH 在内存中与 expectedRevision 作为跨副本后端，非 fsb 后端代理 sidecar 的 /credential-vault 表面，并且 fsb credentialProxy 创建时拒绝被解除（#2263）
  • 将固定的 MITM CA 烘焙到服务器创建的 SandboxTemplates (OSEP-0022) 中：新的 [kubernetes] template_mitm_ca_secret 配置（默认关闭）在每个模板上发出 spec.egressMitmCertificate — 仅证书条目，从不私钥； Secret 必须存在于每个模板命名空间（ops-runbook 发行版）中，并且丢失的副本会明显导致构建失败 (#2288)
  • 添加 lifecycle.renewalPolicy (OSEP-0009)：访问续订选择加入从不透明的 extensions["access.renew.extend.seconds"] 密钥转移到结构化的 renewalPolicy.extendSeconds (300–86400)；旧密钥已被弃用（在 1.x 中受支持，在 2.0 中被删除），并且快速沙箱以 400 拒绝它，而不是默默地接受无操作（#2296）
  • 实现诊断上下文端点（#2236 中的规范）：GET /v1/sandboxes/{sandboxId}/diagnostics/context 返回 Docker、Kubernetes 和 Fast Sandbox 的沙箱 ID、生命周期状态、后端类型和后端定义的标识符，无需连接到 execd — Kubernetes 上下文在分配 Pod 之前保持可用；未实现它的扩展后端返回 501 (#2292)
  • 通过沙箱代理转发仍然编码的路径：Starlette 从百分比解码的路径绑定了 {full_path:path} 路由，因此解码的 ? 启动查询，%2F 成为分隔符，并且 %2E%2E 段被解析 - 关闭 Docker 主机映射端点上的前缀转义；代理现在从原始路径获取 client 的仍编码尾部（验证它解码为路由路径）并从原始查询字符串中读取查询，因此后端逐字节接收请求目标，与入口网关匹配（#2228）
  • 继续阻止事件循环中的 Docker 调用：代理端点查找、网络存在验证和每 PVC 卷检查/创建在异步处理程序内同步运行，因此缓慢的 Docker 守护进程（例如在大型拉取期间）冻结了包括代理流量在内的所有其他请求；它们现在在保留租户上下文的工作线程上运行，并且卷验证失败仍然会清理自动创建的卷（[#2268]（https://github.com/opensandbox-group/OpenSandbox/pull/2268）[#2366]（https://github.com/opensandbox-group/OpenSandbox/pull/2366））
  • 停止将映像继承标签报告为 Docker 上的沙箱状态：元数据读取回退到每个非保留容器标签（包括从映像合并的标签），并且恢复的容器继承了保留标签，例如 expires-at、主机端口和出口令牌；在最坏的情况下，恢复的 TTL 沙箱在服务器重新启动后会因已过期而被删除。现在创建将请求的元数据键记录在保留标签中，并仅读回这些键，并且图像上存在但未由沙箱设置的保留标签在容器启动之前被清空（#2363 #2269）
  • 拒绝会静默删除写入的 gVisor 快照：gVisor 默认 --overlay2=root:self 下的 docker commit 可以报告 READY，同时不恢复沙箱的任何写入；快照预检现在拒绝 gVisor，除非有效参数包含 --overlay2=none，并且当文件系统差异仅用于文件存储时，创建将失败关闭 (#2241)
  • 保留创建回复丢失的 fsb 快照：持久接受请求后，来自 FastPath 的 UNAVAILABLE/DEADLINE_EXCEEDED 返回 500 而不写入一行，使 SandboxSnapshot 及其已发布的工件搁浅，没有记录；现在，创建会在失败之前探测快照，并在 FastPath 持久保存快照时将其报告为已提交 (#2361)
  • 修复剩余的 Docker 后端毛病：BatchSandbox 过期报告 Terminated/SANDBOX_EXPIRED，而不是 Running 过去的 spec.expireTime (#2238)；并发生命周期冲突映射到 404/409 而不是 500 (#2387)；并发元数据补丁不再争先恐后地进入 500 秒或丢弃密钥 (#2267 #2281)； createdAt 在读取过程中保持稳定，并记录暂停/恢复转换（#2405）；网络策略操作已验证，未知字段返回 422 (#2383 #2385)；沙盒图像是从容器配置中读取的，因此 docker rmi -f 的图像不再是 500s GET /sandboxes (#2353)；模板读取 trust 数据库投影，而不是在每次创建门检查时同步 CR (#2326)；当启用 Redis 消费者时，更新冷却时间适用于每个更新源（#2276 #2279）； BatchSandbox pod 默认为 restartPolicy: Never，因此 kubelet 重新启动时无法再擦除可写层，同时报告 Succeed (#2128)； podman 的 pasta/slirp4netns/none 网络模式通过（networkPolicy 被拒绝，因为没有可连接的网桥）（#2203）；具有异常小数秒的 Docker 时间戳不再默默地报告当前时间（#2220）；并且 execd 缓存容器遵循 [docker] 安全配置文件和 secure_runtime (#2254)

SDK

以下代码更改适用于 1.2.0 套件。

  • 将 OSEP-0024 SDK 合约添加到所有五种语言：带有 client 端快速失败验证的类型化 lifecycle.idlePolicy 创建字段，加上唤醒重试合约 - 在携带网关拥有的 OpenSandbox-Wake: expired 标记的 503 上（它的存在证明请求已停放且从未转发，使任何方法重试安全），SDK在 Retry-After 之后在有限预算下重新发送（默认 5 次尝试/60 秒，每个 client 旋钮），并且耗尽会引发类型化唤醒超时异常；裸 503 处理不变（#2198 #2218）。该合约最初绕过了流传输；启动流的请求现在在 JavaScript、Python 和 Go 中唤醒重试 — 已建立的流永远不会重播 — 而 C#/Kotlin 流启动当前会快速失败 (#2357 #2426)
  • 将 Credential Vault client 合约添加到所有五个 SDK (OSEP-0022)：模板支持的沙箱在与网络策略相同的模板源信号上通过服务器路由 Vault 调用，而 sidecar-direct 适配器保持不变 (#2263)
  • 在所有五个 SDK 中停止在请求超时（默认 30 秒）时限制文件上传和下载 — 整个调用超时涵盖发送正文和读取响应，因此任何大型或缓慢的传输即使在健康的情况下也会在飞行中失败；传输现在在专用 client 上运行，没有整个调用截止时间，仍然限制响应标头的等待，因此停滞的传输仍然会失败而不是挂起（[#2165]（https://github.com/opensandbox-group/OpenSandbox/pull/2165）[#2186]（https://github.com/opensandbox-group/OpenSandbox/pull/2186）[#2196]（https://github.com/opensandbox-group/OpenSandbox/pull/2196）[#2206]（https://github.com/opensandbox-group/OpenSandbox/pull/2206））
  • 在 SDK 表面上实施诊断（使用 #2292）：context 通过管理器和沙箱外观以所有五种语言公开，并且 JavaScript、Go 和 C# 获得与现有 Python/JVM 表面匹配的公共日志/事件 API (#2292)
  • 将 lifecycle.renewalPolicy 添加到所有五个 SDK (OSEP-0009)：具有 client 端快速失败验证的类型化创建字段 (extendSeconds 300–86400)，替换不透明扩展密钥 (#2296)
  • 在所有五个 SDK 中支持端口范围的出口规则：NetworkRule.ports（TCP 1–65535，每个规则最多 256 个，target 现在可选），client 端验证镜像服务器（范围、重复、上限、域+端口被拒绝）； JavaScript 将目标或端口不变量编码为联合类型 (#2212)
  • 在 Go 和 Kotlin 中展示权威的 execution_complete.exit_code，优于之前的 evalue/inferred-0 后备版本，同时保持与旧服务器的兼容性 (#2330)；无论 JavaScript、C# 和 Kotlin 中的标头名称大小写如何，都会在配置的键上遵循显式提供的 OPEN-SANDBOX-API-KEY 标头 (#2348 #2372 #2375)；抑制 Go、Python 和 JavaScript 中创建的 client 池预热的 sandbox.create 指标 (#2199)
  • 在 JavaScript、C# 和 Go 中剥离跨源重定向上受保护的凭据：只要重定向更改方案/主机/端口，就会删除沙箱前缀标头、端点令牌（X-EXECD-ACCESS-TOKEN、X-API-Key）和配置的身份验证标头，同时保留同源跃点和不相关标头；文件上传永远不会遵循 JavaScript 中的重定向，并且在浏览器中，不透明重定向会失败关闭，而不是冒险重放凭据（[#2178]（https://github.com/opensandbox-group/OpenSandbox/pull/2178）[#2173]（https://github.com/opensandbox-group/OpenSandbox/pull/2173）[#2183]（https://github.com/opensandbox-group/OpenSandbox/pull/2183））
  • 通过共享策略路由 JavaScript 和 C# 代码解释器数据平面标头：直接模式 /code 请求不再携带租户 OPEN-SANDBOX-API-KEY 进行执行，显式配置的连接密钥优先于配置的 apiKey，没有重复的大小写变体条目，并且端点范围的凭据仍然获胜 (#2149)

Python

  • 启动流时重试网关的唤醒超时：SSE clients 完全剥离重试包装器，因此每当恢复超出网关的公园预算时，针对自动暂停沙箱的 commands.run、会话运行和 codes.run 就会失败，并显示 503；流传输现在带有仅唤醒重试（没有一般重试，没有添加截止日期），并且文档不再声称流绕过重试（[#2357]（https://github.com/opensandbox-group/OpenSandbox/pull/2357））
  • 标准化连接域：domain / OPEN_SANDBOX_DOMAIN 中的尾部斜杠或 /v1 生成服务器 404 的 //v1/... URL — 相同的变量在所有其他 SDK 中工作； Python 现在剥离两者 (#2347)
  • 跨自有传输重用 SSL 上下文：每次调用时都会重新加载 CA 证书，从而阻塞异步并发下的事件循环 — 测量的创建 P50 在并发下提高约 18–28% (#2360)
  • 保留 UTF-8 BOM 之后的第一个 SSE 事件（包括跨网络块的分割）（#2226）；取消时关闭唤醒超时响应主体（#2371）；关闭中断的异步文件下载响应，以便取消或失败的读取不再占用连接（#2369）；当错误响应携带非 JSON 主体时保留状态代码 - 代理的 HTML/空 404/500 之前显示为没有状态的 InvalidArgumentException (#2402)；从代码解释器 codes.run 失败中引发共享结构化错误，而不是丢失 retry_after 的手工构建异常（#2364）；将代码解释器输出片段保留在 Execution.text 中，而不是插入额外的换行符 (#2408)；将亚毫秒命令超时舍入到 1 毫秒，而不是发送 0（禁用超时）（#2419）；停止将已取消的端点获取传播给并发等待者（#2277）；通过沙箱池转发 credential_proxy，沙箱池之前默默地将其丢弃（#2283）；停止将失败的文件替换报告为成功（#2222）；清理取消的异步池启动，而不是陷入 STARTING (#2209)；重新生成生命周期 client 以删除过时的硬编码默认值（线路行为不变）(#2280)； MCP：取消一个工具调用不再取消同一沙箱的合并共享连接，该连接使所有其他等待调用失败（#2355）

JavaScript

  • 保留带有 CR 行结尾的执行事件：SSE 解析器仅在 LF 上拆分，因此有效的 CR 分隔流会默默地删除执行 ID、输出和完成事件 (#2374)
  • 将运行中端点缓存失效范围扩展到每个沙箱，因此使沙箱 B 失效不再丢弃沙箱 A 的待处理获取结果（#2349）
  • 在文件上传中保留重用的字节块：重用 Uint8Array/Buffer 视图的异步生产者将变异内容上传两次，而不是两次快照（#2428）；响应标头到达后保持呼叫者取消处于活动状态 - 中止 SSE 流中或下载中之前使主体保持运行（[#2350]（https://github.com/opensandbox-group/OpenSandbox/pull/2350））
  • 去除跨源重定向上受保护的标头（请参阅上面的跨 SDK 条目）（#2173）

科特林

  • 在任何大小写中，在配置的密钥之前保留显式的 API 密钥头，并在未配置时停止附加空密钥头（#2375）
  • 在反序列化失败时保留原始响应主体，并从序列化器/运行时不匹配中捕获 LinkageError - 以前，AbstractMethodError 转义了每个处理程序，以静默方式终止 SSE 流，服务器的实际响应无法恢复（#2416）

C#

  • 无论大小写如何，都遵循显式的 API 密钥标头：区分大小写的检查添加了第二个冲突的默认条目，并且指标报告器替换了调用者的凭据（#2372）
  • 剥离跨源重定向上受保护的凭据，并通过共享数据平面标头策略路由代码解释器请求（请参阅上面的跨 SDK 条目）（#2183 #2149）

去

  • 默认情况下停止重试非幂等写入：启用重试后，27 个 POST/PATCH 调用站点（沙箱/会话/命令/文件/快照/vault 突变）可以执行两次并仍然返回成功 - POST/PATCH 默认情况下不再重试状态代码，仅重试被证明是预发送的传输失败（请求字节之前的拨号/CONNECT/TLS），并且 SSE 引导程序绕过通用重试循环；接受重复执行风险的调用者可以通过 RetryConfig.RetryableStatusCodesNonIdempotent 选择加入 (#2342)
  • 启动 SSE 流时重试网关的唤醒超时：六个流调用站点（命令/代码/会话运行、指标监视）之前立即失败并标记为 503；引导程序现在停在相同的 Retry-After 预算内，并在耗尽时返回类型化的唤醒超时错误 - 已建立的流永远不会重播，即使选择写入状态，仍然不会重试裸露的 503，并且通过重定向链到达的 503 会失去唤醒来源，因此永远不会重新发送已执行的请求；依赖快速失败的调用者可以通过 WakeRetryDisabled() (#2426)
  • 将行终止符保留在 Execution.Text() 中：execd 已在事件文本中包含 \n/\r，并且需要串联才能重建标准输出，但帮助程序在终止事件之间插入了额外的换行符（"a\n" + "b\n" 变为 "a\n\nb\n"）；现在，仅当前面的事件尚未以终止符结束时才添加分隔符（#2381）
  • 从直接模式数据平面请求中剥离租户 API 密钥：通过 ConnectionConfig.Headers 提供的租户密钥被传递给 untrusted 沙箱内的 execd 和 egress sidecar — 完成所有五个 SDK 的凭证暴露修复 (#2337)
  • 使用 API 密钥标头对代理数据平面请求进行身份验证，而不是将租户密钥走私到沙箱中，修复多租户代理模式下的 401 错误（#2274）；表面 execution_complete.exit_code (#2330)

控制器

  • 保留 BatchSandbox 直到清理完成：已删除的沙箱可能会从生命周期 API (GET 404) 中消失，而其拥有的 pod 仍在运行，从而让替换沙箱在旧写入器退出之前写入相同的持久目录；删除现在与现有终结器一起使用前台级联删除 - 在托管清理期间查询报告 Stopping，并且仅在运行时消失后才到达 404 (#2154)
  • 修复任务执行器将空退出文件视为退出代码 0，当填充程序在写入过程中被终止时，该任务执行器将失败或中断的任务报告为 Succeeded (#2270)

执行

  • 报告沙箱范围内的 CPU/内存指标和 OOM 终止：GET /metrics 读取容器内主机的 /proc，因此仪表板显示主机范围内的数字；现在，在配置限制时，使用来自沙箱自己的 cgroup（为无限来宾保留主机视图），并且 cgroupfs 轮询器每 5 秒比较一次内核 OOM Kill 计数器，以导出带有结构化警告日志的 execd.system.oom.kills — 不需要任何功能（#2200 #2191）
  • 通过文件 API 为会话私有 /tmp 提供服务：严格隔离配置文件的 /tmp 是一个没有主机端路径的匿名 tmpfs，因此 /tmp 下的文件 API 路径失败，调用者必须通过 base64 shell 命令来传输工件； /tmp 现在是一个主机支持的每会话目录，绑定安装到命名空间中 — 相同的私有语义，但可通过现有文件端点读取和写入 (#2424)
  • 支持浏览器 PTY WebSocket 身份验证：浏览器无法在本机 WebSocket 握手上设置 X-EXECD-ACCESS-TOKEN，因此终端连接需要 BFF 中继； PTY 升级现在通过 opensandbox-pty 子协议的凭据条目（Kubernetes 样式）接受现有的 execd 令牌，没有新的令牌颁发者，并且为 SDK/CLI clients 保留标头优先级（#2334）
  • 当前台运行被取消或断开连接时，保持隔离会话处于活动状态：运行的上下文源自 HTTP 请求，因此断开连接或 timeout_seconds 到期 SIGINT 会影响整个进程组，包括持久会话 shell — 会话终止，以后的每次运行都会出现 404 错误；现在，当会话存活时，运行仅中断正在运行的命令（具有有限的 SIGKILL 升级），静默前台运行会发出定期的 SSE ping，因此网关空闲超时不再关闭流（#2351）
  • 保留 bash 会话输出行结尾：run_in_session 标准输出事件删除了 \n/\r 字节，因此空行无法恢复，并且连接事件不会重建输出；事件文本现在带有其原始行结尾 - 消费者应在每次运行时连接事件文本 (#2318)
  • 当 Jupyter 内核终止或连接断开时结束 Jupyter 执行：这两种情况之前都使代码解释器请求无限期地打开，而 SSE ping 使其保持活动状态；他们现在执行失败（KernelDied / KernelConnectionLost）一次（[#2401]（https://github.com/opensandbox-group/OpenSandbox/pull/2401））
  • 继续读取超过 16 MiB 的行的会话输出：读取循环在上限处停止 — bash 会话挂起，直到 24 小时默认超时，并且隔离的会话将输出泄漏到下一次运行中；过长的行现在分段传递（从不分割 UTF-8）（#2275）
  • 在隔离会话中运行大型后台代码：包装器将代码作为单个 bash -c 参数传递，并且 Linux 将一个 exec 参数限制在 128 KiB — 上面的后台代码仅因 Argument list too long 而失败；现在它像前台路径一样通过标准输入传递（#2400）；探测专用网络功能，因此受限制的运行时会出现 share_net=false 会话的结构化错误，而不是不透明的 EOF (#2333)
  • 较小的修复：在命令完成和错误时显式报告 exit_code (#2303 #2316)；在流作为框架 SSE error 事件而不是裸露的 JSON 主体启动后发送运行错误，Python SDK 丢弃（[#2354]（https://github.com/opensandbox-group/OpenSandbox/pull/2354））；保持 PTY 输出缓冲，直到 shell 退出时耗尽，因此输出的最后一个屏幕不再丢失 (#2362)；始终在 PTY 接管时发送 WSCloseTakenOver (4001) 关闭帧，即使是写入中间 (#2376 #2378)；在读取其输出时编写独立运行的脚本，以便繁琐的运行不再在 stdin/stdout 管道上死锁 (#2399)；拒绝会话文件视图中超出范围的绝对路径，而不是默默地触摸错误的文件（[#2322]（https://github.com/opensandbox-group/OpenSandbox/pull/2322））；通过隔离会话文件 API 提供 binds 挂载点（#2299）；在取消链接之前截断命令输出文件，以便持有 fd 的守护进程不会导致不可见的磁盘增长 (#2295)；忽略无效的上限使用指标，并在扫描错误时关闭配额准入失败（#2257）；跨共享 trust 存储删除重复的 JDK MITM CA 导入（~6.2 s → ~0.6 对于四个 JDK）（#2310）；未设置时默认 PTY 会话为 TERM=xterm-256color (#2313)；对 Content-Disposition 文件名中的引号和反斜杠进行百分比编码 (#2161)；并在设置下载标头之前解析 Range 标头，以便格式错误的范围返回干净的 JSON 416 (#2216)

出口

OSEP-0022 保险库项目涉及 fast-sandbox 配置文件的凭证保险库表面； OSEP-0023 项目的范围仍然是默认关闭的实验修订运行时。

  • 添加用于快速沙箱的出口保管库 (OSEP-0022)，分阶段登陆：内部 /vault/{sandboxUid} 中继表面，具有仅创建 POST（重复、跨服务器副本为 409）、使用 expectedRevision 的完整修订 PUT 和 expectedIncarnation 前提条件，以便过时的写入者永远无法登陆重置的后继者、包括值的 GET 和 DELETE 来保留策略(#2249);每个主题的持久持久性 - Pod 范围的卷下每个主题一个文件（可选 tmpfs），与策略文件相同的提交协议，因此 acked 意味着持久且已应用，incarnation-fenced 重新加载，并在解除绑定时清除（#2252）；并删除了被取代的 fastlet-proxyVault 路由（#2247）
  • 在暂停/恢复期间携带保管库（OSEP-0022“保管库生命周期”）：VAULT_EXPORT 在运行时拆卸之前严格将保管库文件复制到快照捆绑包中并密封主题（所有保管库操作在暂停时回答 409；强制执行继续），并且 VAULT_IMPORT 是唯一授权的化身传输 - 真正的导出失败会导致暂停检查点失败，因此拆卸永远不会在没有捆绑包的情况下运行，并且 vaultTransfer 功能信号让没有保管库持久性的出口会跳过传输而不是失败 (#2255 #2290)
  • 固定快速沙箱 MITM CA (OSEP-0022)：池固定的版本化 CA 从只读秘密挂载播种到 mitmdump confdir，取代了启动时生成 — 出口重新启动不再轮换 CA 并默默地使每个活动沙箱的 TLS trust 失效；丢失或不匹配的 CA 仅拒绝 /healthz 上出现的带有 mitmCaFingerprint / mitmCaDown 的 MITM 插件（#2251）
  • 在槽重用上定义陈旧主体接管：快速沙箱调度密钥是槽 IP 并且槽被重用，因此 SET_BINDING 可以声明仍由已死亡但已注册主体持有的密钥 - 出口现在将其视为权威，在注册后继拒绝优先之前拆除陈旧主体的 nft 规则、DNS 引用计数、MITM 重定向和保管库切片(#2250)
  • 将快速沙箱网络策略与保管库模式保持一致：记录的策略变为出口保留状态 - 具有修订前提条件的 /policy/{sandboxUid} 中继表面、持久的每个主题文件、POLICY_EXPORT/POLICY_IMPORT 快照传输，以及出口重新启动后，提交的文件取代重播的创建时绑定输入（#2309）
  • 端到端支持端口范围的出口规则（经典配置文件）：NetworkRule.ports（TCP 1–65535，每条规则 ≤256）使 target 成为可选 — 仅端口规则，或与 IP/CIDR 组合的端口；域+ports 被拒绝，因为域规则在 DNS 代理层评估；运营商提供的 reachable.ports.cap 白名单在每个用户规则之前强制执行为始终拒绝，因此即使 defaultAction: allow 也无法打开非白名单端口，并且快速沙箱路由会以 400 拒绝 ports，直到 fastlet nft 路径可以强制执行它们（失败关闭，已记录）（#2212）
  • 将 MITM 重定向目标从端口范围规则中免除：在运营商端口底线和透明 MITM 都处于活动状态的情况下，每个拦截的流都会被默默地黑洞化 - iptables REDIRECT 在过滤器链运行之前将 dport 80/443 重写到本地侦听器，因此底线补码丢弃判断重写的端口；现在，侦听器元组在每个端口范围规则之前被接受，不会添加新的可达性，并且非白名单拦截端口现在在代理处明显失败，而不是静默传递（#2435）
  • 继续 OSEP-0023 实验基础**[实验]**：实时凭证绑定 Vault 准入，按请求轮换 (#2176)，发布前确认的策略修订 (#2182)，HTTP/2 准入，有界排出 (#2201)，意外 MITM 退出时的运行时故障遏制（#2172）、原子修订策略文件持久性（#2162）、nft 应用效果分类（#2167）、静态 TLS 直通选择器（针对冲突的本机列表启动拒绝） (#2229)、TLS 准入计数器 (#2265)、仅安装主题修订版 IPC 基础 (#2284) 以及在 v2 生命周期消费者之前进行聚合快速沙箱主题转换 (#2294)
  • 较小的项目：运送 egress-trace，出口映像内的只读准入查看器（实时策略状态、nft 集、DNS 租约、每个连接判决和 probe 子命令；解密的内容永远不会显示）（#2230）；当 client 使用 TCP 时，通过 TCP 转发 DNS 查询，因此大的截断答案（SPF/DKIM TXT，多记录响应）最终到达（#2358）；当一个快速沙盒网关上的最后一个主体发布时，保留共享网关 DNS 规则，该规则之前删除了整个共享 nft 表（#2427）；从创建时策略引导程序中修剪 fsync 并添加每阶段创建延迟检测 - 真正的热交付在执行策略的情况下端到端测量不到 100 毫秒 (#2327)

入口

  • 实施 OSEP-0024 活动跟踪和访问唤醒：使用 --activity-enabled，每个路由请求都会将单调活动时间戳记录到 Redis — 即发即忘，永远不会在热路径上；对于 --wake-enabled，路由到暂停的快速沙箱的请求将被暂停，而不是回答 503：在检查点围栏的单次飞行、有界停车场和仅限于具有可再现主体的幂等方法的过时路由重播下，每个沙箱的每个副本一个 ResumeSandbox；唤醒超时答案带有 OSEP 定义的标记 (503 + Retry-After: 1 + OpenSandbox-Wake: expired)，从每个上游响应中剥离，因此沙箱无法伪造出处；如果两个标志均未设置，则行为与之前的字节相同 (#2156 #2180)

升级与兼容性

  • 破坏（Go SDK）：默认情况下不再重试 POST/PATCH 请求 - 写入的状态代码重试需要通过 RetryConfig.RetryableStatusCodesNonIdempotent 显式选择加入，并且不再重试写入的不明确的传输失败（读/写超时、意外的 EOF）；依赖写入重试的调用者必须处理返回的错误或选择加入（#2342）
  • 行为更改（Python 和 Go SDKs）：启动流的请求（commands.run、codes.run、会话/隔离运行、指标监视）现在会在唤醒预算内重试网关的标记唤醒超时 503，而不是快速失败 — 已建立的流永远不会重播；使用 WakeRetryDisabled() (Go) 保持旧的快速失败或禁用唤醒重试 (Python) (#2357 #2426)
  • 行为更改：SDK 显示帮助程序不再在已终止的标准输出事件之间插入额外的换行符（Go Execution.Text()、Python 代码解释器 Execution.text），并且 Go 帮助程序将尾随 CR 视为旧版 1.2 之前的 bash 会话事件的终止符（#2381 #2408)
  • 行为更改：bash-session stdout 事件文本现在包含其原始行结尾，并且空行显示为事件 - 消费者必须在每次运行时连接事件文本以恢复准确的输出，而不是将每个事件视为无换行符的行 (#2318)
  • 行为更改：超过 spec.expireTime 的 BatchSandbox 现在报告 Terminated / SANDBOX_EXPIRED 而不是 Running，即使 pod 仍处于就绪状态 - 将 Running 视为活动的调用者应检查过期时间（#2238）
  • 行为更改：BatchSandbox Pod 现在默认为 restartPolicy: Never — 依赖隐式 Always 并希望重新启动的部署必须在其 batchsandbox_template_file 中显式设置它 (#2128)
  • 行为更改：已删除的沙箱在 Stopping 中保持可查询状态，直到运行时清理完成，然后才返回 404 - 共享持久目录的 client 应该在开始替换之前等待 404 (#2154)
  • 行为更改：不带 --overlay2=none 的 gVisor 容器的由 Docker 支持的快照会被 SNAPSHOT::UNSUPPORTED_RUNTIME (409) 拒绝，而不是静默发布不完整的映像 (#2241)
  • 行为更改：当沙箱 cgroup 配置了限制（以前是主机范围）时，execd CPU/内存指标会报告沙箱范围内的值；指标名称和线路格式保持不变，但仪表板将发生变化 (#2200)
  • 行为更改：在 Docker 上，从图像继承的标签不再显示为沙箱元数据，恢复的沙箱不再继承源的保留标签，并且 image.uri 报告创建沙箱时使用的引用 (#2363 #2269 #2353)
  • 行为更改：未知的 NetworkPolicy/NetworkRule 字段现在返回 422，无法识别的创建时操作返回 400（之前默默地忽略）；标签和资源名称中的尾随换行符被拒绝；合同有效输入不变（#2383 #2385）
  • 行为更改：networkPolicy 对于 Docker 网络模式 none/pasta/slirp4netns 被拒绝 — 之前对于 none 静默接受（#2203）
  • 行为更改（转到 SDK，直接模式）：通过 ConnectionConfig.Headers 提供的租户 API 密钥不再发送到沙箱内的 execd/egress (#2337)
  • 行为更改：模板读取（GET /templates，创建门）报告数据库投影，其新鲜度受监视交付（通常为毫秒）限制 - 刚刚完成的构建竞赛的创建可以看到短暂的可重试 404（#2326）
  • 行为更改：隔离会话文件 - 会话安装之外的 API 路径会被拒绝并出现错误，而不是静默解析到工作区中（#2322）
  • 行为更改（仅限实验出口实时模式）：非空本机 ignore_hosts/allow_hosts 现在拒绝启动 - 将静态 TLS 旁路条目迁移到 OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS (#2229)
  • 行为更改：当 upper_max_bytes > 0 和使用扫描失败时，execd 上层目录配额准入失败关闭（以前配额检查被悄悄绕过）（#2257）
  • 弃用：extensions["access.renew.extend.seconds"] 创建密钥已弃用，取而代之的是 lifecycle.renewalPolicy.extendSeconds — 在 1.x 版本中受支持，在 2.0 中删除；仅当值匹配时才接受两者设置（#2296）
  • 快速沙箱：OverlayBD 模板现在需要 OCI 存储，并且快照 spec.templateName 是可选的，status.manifestRef 承认 oci:// — 更新采用名称索引或所需 templateName 的使用者 (#2338)

安装

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.0
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
# Before first install, configure the server API key and enable the ingress
# gateway (required on Kubernetes; the bare render disables it, and the server
# refuses to start with an empty api_key) — see the deployment guide:
# https://open-sandbox.ai/deployment/
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.2.0            # Python
npm install @alibaba-group/opensandbox@1.2.0   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.2.0")
dotnet add package Alibaba.OpenSandbox --version 1.2.0
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.2.0

# Run the server locally
uvx opensandbox-server==1.2.0
