OpenSandbox release-1.1.1-rc.1

OpenSandbox release-1.1.1-rc.1

1.1.1 补丁线上的第一个候选版本，剪切以修复损坏的 1.1.0 服务器轮：hatchling 的 VCS 排除过滤默默地从 PyPI 包中删除了提交的 FastPath gRPC 存根，因此 opensandbox-server 的每个 1.1.0 安装在导入时都会失败 - PyPI 是不可变的，因此修补行是 1.1.1 （[#1959]（https://github.com/opensandbox-group/OpenSandbox/pull/1959））。除了该修复之外，此 rc 还包含自 release-1.1.0 以来合并的所有内容：代理沙箱暂停/恢复、共享命名空间租户隔离、监视驱动的创建延迟、commands.setEnv 以及跨所有五个 SDK 的系统审计清理、出口的上游代理链接以及两个快速沙箱引脚碰撞。每个部分的基线是 release-1.1.0。 rc 版本发布图像但保留包 - SDK/CLI 工件在 1.1.1 稳定凹凸处发货。请测试并报告问题。

变更流程图

亮点

  • 修复了 1.1.0 服务器轮：FastPath 存根现在包含在包中并干净地安装导入（#1959）
  • 服务器：在代理沙箱提供程序上暂停/恢复，共享 Kubernetes 命名空间的沙箱的租户隔离，池创建由监视事件唤醒，而不是 1 秒轮询 (#1975 #1973 #1996)
  • SDKs：所有五种语言的 commands.setEnv 运行时环境注入，加上系统的跨语言审核清理，修复了数十个正确性错误（#2013 #2020）

服务器

  • 通过桥接到 agents.x-k8s.io/v1beta1 上的 spec.operatingMode (Running/Suspended)、状态派生 (Paused/Pausing/Resuming/Terminated)、resourceVersion 前提条件以及无效转换时的 409 来实现代理沙箱提供程序的暂停/恢复；两个端点之前都返回“不支持”（#1975）
  • 隔离共享一个 Kubernetes 命名空间的租户：创建标记 opensandbox.io/tenant，并列出/获取/删除/暂停/恢复/代理将其他租户的标记沙箱隐藏为 404，而未标记的旧沙箱在到期之前保持可见；还为 ServiceAccount CA 不匹配添加了 kubernetes.insecure_skip_tls_verify (#1973)
  • 修复服务器在多租户模式下重新启动后静默更新意图下降的问题：解析器现在回退到使用 403 断路器和结构化警告的集群范围标签查找，trust 在可验证时从意图负载中观察入口命名空间，并且单租户部署永远不会解析超出配置的命名空间（#1819）
  • 添加 [docker] publish_host 以在一个主机地址上发布桥接模式沙箱端口（默认 0.0.0.0 不变） - 使用 127.0.0.1 或 Docker 桥接网关，无令牌 execd 端口不再登陆公共接口（#1954）
  • 添加一个类型化的、仅限管理的 [egress.upstream_proxy] 配置部分（URL + 可选授权，在加载时验证），该部分在 Docker 和 Kubernetes 上注入 sidecar 的链接上游 CONNECT 代理，当请求的 networkPolicy 不兼容时，会出现故障关闭 400 秒；秘密值不再在配置验证错误中回显（#1999）
  • 在模板创建时接受 env 并将其烘焙到快速沙箱黄金映像中（/etc/sandbox-init.env，继承源映像的 OCI Config.Env），缩小 SandboxTemplate.spec.envs 存在但生命周期 API 拒绝它的差距；所有 SDK 均受支持 (#1984)
  • 唤醒 Kubernetes 创建等待通知者监视事件，而不是固定的 1 秒轮询，将预热池创建延迟从约 1 秒缩短到数十毫秒，同时保持轮询回退（#1996）
  • 强制将提交的 FastPath gRPC 存根发送到服务器轮中 - 将它们包含在孵化的 VCS 排除项中，并在发布之前在发布工作流程中烟熏导入构建的轮 - 这是 1.1.0 安装时损坏修复（#1959）
  • 修复了 Helm RBAC 和 fsb 快照运行时中的快速沙箱快照 CR 复数 (sandboxsnapshots)，其中 sandboxesnapshots 可能因缺少 RBAC 而导致列表/监视失败 (#1972)
  • 通过 429 容量映射传播底层 FastPath 错误消息（保留状态和 Retry-After，添加 cause 字段），以便准入/运行时故障（例如 KVM 设备损坏）不再被掩盖为池耗尽，并在映射之前警告记录原始错误（#2001）
  • 修复 Docker 边缘：拒绝使用记录的 409 重复暂停已暂停的沙箱，而不是将 Docker 的“已暂停”显示为 500 (#2023)，并仅针对选择隔离扩展的沙箱清除 Docker 屏蔽/只读系统路径，以便嵌套 Bubblewrap 可以安装私有 procfs (#1982)

SDK

以下代码更改适用于 1.1.1 稳定版本 - rc 不附带 SDK 软件包。

  • 在所有五个沙箱 SDK（Python 异步/同步、JavaScript、Kotlin/Java、Go、C#）中添加 commands.setEnv，用于持久运行时环境注入：将 KEY=VALUE 附加到沙箱环境文件，并具有运行时精确序列化、本地密钥/NUL 验证以及未设置 EXECD_ENVS 时的大声失败(#2013)
  • 跨沙箱、代码解释器和 MCP SDK 进行系统性跨语言审计清理：重试回退崩溃至零延迟并丢弃会话 cwd、Python 隔离会话忽略 encoding 和准备预算报告陈旧错误、JS 恢复共享并终止源沙箱的传输、Kotlin 代码运行丢弃每个 SSE 框架事件和永远不会设置 exitCode，C# 创建在新鲜沙箱 404 上失败，并且在空主体上创建 NRE，MCP 每次调用都会关闭，从而破坏服务器范围的共享传输 — 每个都通过回归测试进行修复 (#2020)
  • 支持在所有五个 SDK 上创建模板上的 env，匹配服务器端黄金图像烘焙 (#1984)
  • 跨语言对齐后台命令流完成：删除 execd 的固定完成延迟后，Go、Kotlin 和 C# 中的后台结果收集现在在启动确认时返回，如 Python 和 JavaScript，而不是等待 EOF 并推断退出代码 0 — 查询最终结果的命令状态；对于较旧的服务器，前台调用仍会读取 EOF (#1825)

控制器

  • 修复图像提交者死锁，其中通过 cgroup v2 freeze 暂停 QEMU 容器永远不会完成（KVM 工作内核线程永远不会到达 frozen），方法是跳过已经通过 QMP 暂停的 QEMU 容器的冗余冻结并使用 --pause=false 提交（#1986）

执行

  • 删除命令完成后固定的一秒延迟，将终端事件返回延迟中值从约 1000 毫秒缩短到亚毫秒，同时保留输出刷新和心跳清理（#1825）
  • 支持 bwrap 隔离层中每个会话的多个独立覆盖安装（工作空间与系统路径的单独上部、嵌套阴影、临时 tmpfs 上部）；没有公共 API 更改的内部基础 - 请求级 overlays 字段如下 (#2021)
  • 停止在信息级别记录每个 stdout/stderr 块，这在输出繁重的工作负载上占 execd 日志量的 99.8% (#1906)

网络

出口

  • 将选择加入的上游 CONNECT 代理添加到透明 mitmproxy 路径 (OPENSANDBOX_EGRESS_UPSTREAM_PROXY/_AUTH)，通过具有 SNI/主机一致 CONNECT 权限的企业转发代理路由沙箱出口，失败关闭启动验证，并且取消设置时不会发生行为变化 (#1816)
  • 继续凭证绑定的 TLS 拦截基础 (OSEP-0023) [实验]：在 sidecar 启动时引导经过身份验证的修订会话并在内门后面重新启动 (#1948)，使用发布前确认提交语义暂存未发布的 Credential Vault 突变候选者 (#1980)，序列化/policy 和 Vault 在共享突变屏障后面写入（#1991），在发布前阶段始终规则重新加载（#1997），在不确定的协调器结果中保留精确的尝试身份（#2007），并通过精确尝试协调添加引导后修订更新(#2017) — 仅基础工作； public Vault 在门下仍然写入 503，并且选择性 TLS 保持禁用状态

入口

  • 通过 OpenSandbox-Access-Renew: skip 标头支持按请求选择退出访问更新意图，在网关和服务器代理路径上触及和剥离节流状态之前被抑制 - 用于运行状况探测和其他心跳式流量（#1966）

快速沙箱

  • 图表：添加控制器容忍度、将 sandboxtemplateBuilderPodSpec PodSpec 片段 ConfigMap 合并到黄金映像构建 Pod 中、fastletProxyImage 覆盖，以便注入的 sidecar 不再需要来自 docker.io，以及受污染或注册表限制的集群的代理/看门人运行时资源（#1968）
  • 两次碰撞固定的快速沙箱源：f45bc60 删除了旧版 API 服务器的 CRD CEL 验证，使 P2P 在对等网关接缝后面成为可选，并允许模板来宾继承源映像的 OCI 环境 (#1989)； 2b5e840 删除节点端来宾内核资产（kernelPath 成为可选），添加快照 CPU 模板兼容性准入，并在恢复之前将被监禁的 /dev/kvm 重新绑定到主机设备编号（#2028）；中间的 fb87a53 引脚将构建器的默认来宾内核更改为 6.18.36 (#1992)

其他

  • CLI：添加模板和快照管理（osb template create|get|list|delete、osb snapshot ...，以及 sandbox create 上的 --template/--snapshot-id）（#2002），sandbox create 和 template create 的 kubectl 样式 -f/--file 请求文件覆盖严格的完整线路格式未知字段拒绝（#2019），并修复 sandbox metrics --watch 在 execd 的原始 SSE 字段名称上失败（#1970）
  • 图表：正确的图表元数据，统一 release-<appVersion> 后备上的图像标签默认值，使 imagePullPolicy 可配置，将数据平面命名空间保留在 helm.sh/resource-policy: keep 上，并使用明确的安装顺序重写围绕伞式发布流程的部署指南（#2006）
  • 快速沙箱工具：添加自托管 KVM 集成测试工作流程 (#1978 #1985)，这是一个为 Firecracker (#1995) 提供预分配的 reflink-XFS 状态磁盘的帮助程序，这是一个真实的黄金映像测试工作负载(#1983)，并在集成环境中将 MinIO 替换为 RustFS (#2009)
  • 文档：发布快速沙箱性能页面，其中包含测量的创建/快照/恢复数据（#1951 #1992），锐化自述文件介绍和功能（#1960），修复因文档重组而损坏的链接(#1957)，将 OSEP-0016 标记为已实现 (#1955)，添加 DeerFlow 集成示例 (#2011)，并删除未维护的 NullClaw 示例 (#2016)
  • 发布：跨图表和图像参考将平台版本提升至 1.1.1-rc.1

升级与兼容性

  • PyPI 上的 1.1.0 服务器包在导入时损坏并且无法替换（PyPI 是不可变的）——升级到此行；参见#1959
  • 行为更改：Go、Kotlin 和 C# 中的后台命令结果集合在启动确认时返回，不再推断退出代码 0 — 查询最终结果的命令状态 (#1825)
  • 行为更改：在多租户模式下，共享命名空间中另一个租户的标记沙箱现在解析为 404；未标记的遗留沙箱在过期之前保持可见（#1973）
  • 快速沙箱操作符：2b5e840 引脚删除捆绑的节点端来宾内核 - 恢复从不启动内核，直接启动需要显式操作符 kernelPath 引脚（#2028）；集成环境读取 RUSTFS_*/RC_IMAGE 而不是 MINIO_*/MC_IMAGE，没有旧别名（#2009）
  • 图片：opensandbox/<component>:release-1.1.1-rc.1（所有三个注册表）
  • 软件包：未更改 - SDK/CLI 工件在 1.1.1 稳定版本中发布
  • 图表：从此标签渲染（helm template ./manifests/charts/opensandbox）
  • Kubernetes：支持范围 v1.21 – v1.34（图表声明 kubeVersion: ">=1.21.1-0"）
  • 倾斜：支持服务器↔ CLI/SDK 同一条线； ±1次轻微警告
