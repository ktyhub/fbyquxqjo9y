OpenSandbox v1.0.5

修订 发布时间2026年7月24日 来源opensandbox-group/OpenSandbox 英文原文

OpenSandbox sdks/sandbox/go/v1.0.5

变更流程图

亮点

  • 可重试的连接池获取策略（#1347） — Acquire 现在可以通过 AcquirePolicyRetryNextIdle 和 AcquirePolicyRetryNextIdleThenCreate 跳过陈旧的空闲连接候选，MaxAcquireRetries 默认为 3。因为现有策略保持原行为，这是可选启用的：如果你的池里会出现陈旧/已关闭的空闲连接，可以采用它；但要清楚 “then create” 变体可能通过静默回退到直接创建，掩盖 idle 连接池整体坏掉的问题——建议配合自己的创建失败告警。
  • 流式与陈旧连接加固（#1316） — 长生命周期的 SSE 命令流不再受全局 RequestTimeout 限制，慢任务的输出不会在中途被截断。幂等的 GET/HEAD 调用在超时/重置/EOF 后会在新连接上恰好重试一次。实际好处是链路不稳时误报更少；要注意重试被刻意限定在幂等方法上，非幂等调用仍会快速失败，以免产生重复的副作用。
  • 隔离会话生命周期与 UID 模式（#1295、#1320、#1264、#1269） — 现在可以按 ID 附着到隔离会话，让无状态 worker 在 execd 内存中的会话还活着时恢复出可用句柄——这对 worker 重启意义很大，但注意只在内存会话存续期间有效。会话还新增了显式 bind mount 和用于检查的列表 API，模式响应会暴露每种模式的 setpriv/userns 可用性：请求不可用的模式现在会以 503 NOT_SUPPORTED 失败，所以调用方应探测可用性并处理这个状态，而不是假设某个 UID 模式一定存在。
  • 可观测性与客户端身份（#1307、#1326） — Sandbox.Create 会向生命周期服务发出 fire-and-forget 的 sandbox.create 延迟事件，并能容忍旧服务端版本差异；如果担心遥测外发，可用 OPENSANDBOX_DISABLE_METRICS=1 关闭。另外，SDK 会尽力探测主机内网 IPv4 并在出站请求里加上 OPEN-SANDBOX-CLIENT-IP——用户提供的值从不被覆盖，所以依赖该 header 的代理或网关应显式设置它，避免歧义。
  • 请求匹配与快照过滤（#1251、#1301） — Credential Vault 的请求匹配新增可选占位符，覆盖路径、查询、header 和 body，包括透传认证绑定，让动态凭据注入灵活得多，但需要谨慎划定范围，避免占位符模式过度匹配。快照列表也支持精确的 name 过滤，取代脆弱的客户端过滤，便于精确查找。

本版本没有破坏性变更。

新消息

✨ 特点

  • 重试池获取策略 — Go 沙箱池现在支持 AcquirePolicyRetryNextIdle 和 AcquirePolicyRetryNextIdleThenCreate，允许 Acquire 在失败或回退到直接创建之前跳过过时的空闲候选者。现有政策保持当前行为； MaxAcquireRetries 默认为 3。#1347
  • 沙箱创建指标 — Sandbox.Create 现在向生命周期服务器报告即发即忘的 sandbox.create 延迟事件。报告会忽略旧服务器版本偏差，并且可以使用 OPENSANDBOX_DISABLE_METRICS=1 禁用。第1307章
  • Client IP 标头 — SDK 现在尽力检测主机 Intranet IPv4 并在出站请求中将其作为 OPEN-SANDBOX-CLIENT-IP 发送。用户提供的标头永远不会被覆盖。第1326章
  • 附加到隔离会话 — SDK 现在可以通过会话 ID 附加到现有的隔离会话，从而允许无状态工作人员在 execd 内存会话保持活动状态时恢复功能句柄。第1295章
  • UID 模式可用性 — 隔离会话响应现在公开每个模式 setpriv / userns 可用性，并且不可用的请求模式会失败并显示 503 NOT_SUPPORTED。第1320章
  • 精确的快照名称过滤 — 快照列表现在支持精确的 name 过滤器。第1301章
  • 隔离会话绑定安装和列表 — 隔离会话现在可以接收显式绑定安装，并且 SDK 公开隔离会话列表，以便调用者可以检查活动会话。第1264章 第1269章
  • Credential Vault 占位符替换 — 请求匹配现在支持路径、查询、标头和主体表面的选择加入占位符，包括直通身份验证绑定。第1251章

🐛 错误修复

  • 流和陈旧连接强化 - 长期 SSE 命令流不再使用正常的总请求超时，因此命令输出不会被 RequestTimeout 切断。幂等 GET / HEAD 请求在超时、重置或 EOF 错误后在新连接上重试一次。第1316章

📦 其他

  • 增加了此版本的 Go SDK 版本常量和默认用户代理字符串。第1384章
