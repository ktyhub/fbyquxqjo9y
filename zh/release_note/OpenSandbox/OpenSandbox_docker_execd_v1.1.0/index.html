OpenSandbox v1.1.0

小版本 发布时间2026年8月26日 来源opensandbox-group/OpenSandbox 英文原文

OpenSandbox docker/execd/v1.1.0

新消息

✨ Features

  • execd 作为沙箱初始化 (OSEP-0018)。 execd 现在可以作为 PID 1 运行：在每个启动路径上具有 managedProcess 抽象的单个收割机、信号转发 (TERM/HUP/USR1/USR2/WINCH)、入口点拥有的退出代码传播以及池路径的子收割机回退。通过 EXECD_INIT=1 选择加入（由 Docker/K8s Batch/Agent/Pool 的服务器的 runtime.execd_run_as_init 注入）；经典拓扑不变，默认关闭。 (#1474)
  • 预执行强化层。 新的 opensandbox-launcher 本机帮助程序应用 env strip → KEEPCAPS → 边界集修剪 → no_new_privs → 身份删除 → seccomp → execve； [landlock] 添加了文件系统白名单（在 ABI/内核 5.13 下失败打开，报告为 unsupported）。 GET /v1/isolated/capabilities 获得一个具有每层状态的 hardening 对象；每一层都会降低失效开放性。 (#1474)
  • eBPF 观察变体。 execd-ebpf (CGO + cilium/ebpf) 将 exec/connect/privilege 与 CO-RE 挂钩，范围仅限于沙箱 cgroup，发出旋转 JSONL 审计；需要带有 BTF 的内核 ≥5.10。默认图像未更改。 (#1474 #1562)
  • preStart 和 periodic 生命周期挂钩 (OSEP-0020)。 CreateSandboxRequest.lifecycle 通过内部 OPEN_SANDBOX_LIFECYCLE env 传输到沙箱（Kubernetes；Docker 提供程序拒绝生命周期请求）。 execd 在 preStart 之前启动 HTTP，通过收割者感知托管进程路径运行非重叠的 periodic 挂钩，并且仅在 preStart 成功后释放用户进程。 Config persists at $HOME/.execd/lifecycle.toml, with EXECD_LIFECYCLE_CONFIG as exact override;引导同步和预启动关闭通过 TERM/KILL 看门狗进行故障关闭，并且内部传输变量从用户代码中剥离。 API 模型在 Go/Python/JS/Kotlin/C# SDK 中对齐。 (#1587 #1588 #1589)

🐛 错误修复

  • In-namespace signals no longer leak into /command in init mode. kill -HUP 1 previously killed whatever /command was running (signal: hangup);信号现在仅由 init 转发器拥有。 (#1546)
  • PTY 创建失败发出第二个成功正文。 POST /pty 现在在错误响应后立即停止，而不是附加成功正文和不存在的会话 ID。 (#1603)
  • cwd 验证现在支持请求范围的环境。 前台/后台 /command 请求可以使用自己的 envs 映射中的 cwd 变量，而不是被拒绝 400。(#1611)
  • 非 root 工作负载无法启动：/bootstrap.sh 标准化为 0755。 已部署的映像将 bootstrap.sh 作为 0751 root:root，在挂钩运行之前将具有非 root 默认用户（例如 admin）的映像发送到 CrashLoopBackOff。现在，无论签出权限如何，映像构建都会强制执行 execd/execd-ebpf/opensandbox-supervisor/bootstrap.sh 上的执行位。 (#1619 #1606)
  • preStart 超时从 300 秒提高到 10800 秒（3 小时）。 periodic.timeoutSeconds 保持在 300 秒；产品策略界限现在仅在服务器端强制执行，execd 仅保留技术溢出防护。 (#1637)

📦 Misc

  • OSEP-0018 覆盖范围结束：服务器路径和 Kubernetes 强化 e2e（ConfigMap 携带的隔离 TOML，无服务器逻辑更改）、PTY 强化、bwrap + init-reaper 集成、自定义 [seccomp]/keep_capabilities 策略、EXECD_INIT↔TOML 漂移引脚、K8s 针对 init 模式 Pod 重新启动回收，运行时启动的停止，以及 execd-ebpf 裸容器烟雾（兼作内核 5.10 验证）。测试冗余和死代码修剪（-359 行）。 （＃1554＃1555＃1562＃1574）
  • OTLP 端点自动允许在共享组件中提供（出口遵循 OTEL_EXPORTER_OTLP_METRICS_ENDPOINT/OTEL_EXPORTER_OTLP_ENDPOINT；PTY 查看器读取循环一路重构）。 (#1504)
  • 生命周期挂钩指南，包含时序图和每个 SDK 创建示例； SDK client 端超时验证与服务器一致。 (#1605)
