OpenSandbox v1.0.22

修订 发布时间2026年8月13日 来源opensandbox-group/OpenSandbox 英文原文

OpenSandbox docker/execd/v1.0.22

这个项目是干啥的：一个用来隔离运行代码和程序的沙箱工具，把程序关在安全小房间里跑，给需要安全执行不可信代码的开发者用。

变更架构图

亮点

  • 破坏性变更：私网隔离现在 fail closed — 显式设置 share_net: false 的会话现在要求 NetNS/UserNS bind-pinning 成功；安装失败时 execd 返回可重试的 503。升级前请检查编排层的重试处理与隔离能力；共享网络的会话不受影响。（#1397）
  • 后台执行与运行可观测性 — 设置 run.background: true 会拿到一个 JSON 运行句柄，然后可以轮询 runs/{runId} 及其 /logs 端点。进行中的运行不计入空闲垃圾回收，因此长时间运行的工作负载不会丢失状态或输出。（#1456）
  • 五个 SDK 全都支持重新附着会话 — attach(sessionId) 可以从一个 ID 重建出功能完整的句柄，worker 重启后也一样；SessionState 会回显创建参数，便于有状态恢复。（#1295）
  • 只读 PTY 查看与更可移植的 shell 执行 — 可以选用 ?mode=viewer，让多个客户端与独占持有者一起回放和跟随 PTY，且查看者之间的背压相互隔离。PTY、bash 会话和隔离 API 现在会从 Bash 回退到 sh，包括在没有 bash 的镜像上正确处理 dash/ash 的 export -p。（#1420 #1359 #1361 #1367）
  • 隔离失败范围收窄，安全边界加强 — 独立的 setpriv/userns 探测现在只对不可用的 uid_mode 选项返回 503 NOT_SUPPORTED。原生 workload-identity 门禁与生命周期检查会在计费信息丢失时终止隔离会话；即使 execd 的凭据/配置变量在白名单里，也会从 bwrap 会话中剥离。（#1320 #1388 #1392 #1314）
  • 面向高输出和重启负载的可靠性修复 — 慢速 Jupyter 消费者不再让突发执行死锁，SSE 输出避免被 ping 竞态和代理错误破坏，egress 启动时会清理陈旧的 mitmproxy CA，防止 pod 内容器共同重启后出现 HTTPS 失败。依赖更新解决了已知的 CVE 暴露。（#1464 #1216 #1371 #1385 #1250）

新消息

⚠️ 重大变更

  • 专用网络会话在启动时无法关闭。 显式 share_net: false 会话现在需要 execd 绑定固定工作负载 NetNS/UserNS 并在失败时返回可重试的 503；共享网络会话未更改。 (#1397)

✨ 特点

  • 后台在隔离会话中运行。 run 接受 background: true 并返回 JSON 句柄；新的 runs/{runId} 状态和 .../logs 端点支持轮询。运行中的运行会阻止空闲 GC。 (#1456)
  • 只读 PTY 查看器。 选择加入 ?mode=viewer 可以让多个 client 与专属持有者一起观看正在运行的 PTY 会话，并具有重放 + 实时输出和背压隔离功能。 (#1420)
  • 所有五个 SDK 中的 attach(sessionId)。 从裸 ID 重建功能齐全的会话句柄，例如工作人员重新启动后； SessionState 现在回显创建参数。 (#1295)
  • uid_mode 可用性探测。 execd 独立探测 setpriv/userns，并针对不可用模式返回 503 NOT_SUPPORTED，而不是使所有隔离失败。 (#1320)

🐛 错误修复

  • 隔离会话的故障关闭工作负载生命周期（安全性）。 本机门会阻止沙箱命令，直到 execd 验证工作负载身份；如果生命周期记帐丢失，会话将终止。 （#1388#1392）
  • execd config env 不再泄漏到 bwrap 会话中（安全）。 EXECD_ACCESS_TOKEN、JUPYTER_*、EXECD_ISOLATION_CONFIG 始终被剥离，即使已列入允许列表。 (#1314)
  • 修复了缓慢消费者下的 Jupyter 执行死锁 - 在突发输出期间不再出现永久挂起。 (#1464)
  • Bash → sh 后备，适用于 PTY、bash 会话和隔离的 API，包括在无 bash 图像上正确引用破折号/ash export -p。 （＃1359＃1361＃1367）
  • 出口启动时清除旧的 mitmproxy CA — 修复 pod 容器共同重启后的 HTTPS 故障。 (#1371)
  • 消除了 SSE 流损坏 - 修复了 ping goroutine 竞争和代理错误泄漏（约 64% 的夜间 e2e 故障率）。 (#1216)

📦 其他

  • CVE 依赖性碰撞：grpc v1.82.1、x/crypto v0.52.0、x/net v0.55.0、postcss 8.5.11。 （#1385#1250）
  • Apache 2.0 许可证标头添加到 21 个文件中。 (#1313)
