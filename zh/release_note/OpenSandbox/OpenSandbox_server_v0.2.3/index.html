OpenSandbox v0.2.3

修订 发布时间2026年8月26日 来源opensandbox-group/OpenSandbox 英文原文

OpenSandbox server/v0.2.3

新消息

⚠️ 重大变更

  • OPENSANDBOX_EGRESS_SANDBOX_ID 现在被服务器注入并在请求 env 中被拒绝 — 服务器在 Docker 和 Kubernetes 运行时中无条件设置出口 sidecar 的沙箱 ID 属性变量，并将其从 env 白名单中删除。在 env 中传递它的请求现在会得到 400，而不是用户可欺骗的值。第1381章

✨ 特点

  • 沙箱生命周期挂钩 (preStart / periodic)、OSEP-0020 — CreateSandboxRequest.lifecycle 被接受、验证（保留的传输、重复的周期名称、池分配组合），并通过保留的 OPEN_SANDBOX_LIFECYCLE env 传输到 Kubernetes 工作负载以供 execd 执行。 Docker 明确拒绝生命周期请求； PATCH 和其他钩子类型超出了范围。附带对齐的 Java/Kotlin、Python 和 TypeScript SDK 模型。第1588章 第1589章
  • preStart.timeoutSeconds 限制从 300 秒提高到 3 小时 — 服务器和 OpenAPI 限制现在允许预启动挂钩最多 10800 秒；周期限制保持在 300 秒。执行端产品策略绑定已被删除，仅保留服务器上的策略更改。第1637章
  • QEMU VMState 暂停/恢复基于 runc 的沙箱 — 通过 QMP 迁移选择捕获来宾内存/vCPU/设备状态； rootfs 和压缩的 VMState 存储为单独的 OCI 映像，由不可变的 SHA-256 摘要键入。支持池化 BatchSandbox 暂停、分离和独立恢复，同时保留来宾内存、可写磁盘、启动 ID 和计数器连续性。仅 Rootfs 快照保持向后兼容。第1584章
  • 池容量耗尽现在可以由机器识别 - 控制器发布 PoolAllocationPending/PoolCapacityExhausted 条件；服务器等待有界采集窗口（新 kubernetes.pool_acquisition_timeout_seconds，默认 30 秒），然后返回带有 KUBERNETES::POOL_CAPACITY_EXHAUSTED 和 Retry-After: 5 的 HTTP 429，而不是通用的 504 就绪超时。旧的控制器可以安全地恢复到现有的行为。第1581章
  • 生命周期响应中的池分配摘要 — getSandbox 现在显示一个可选的 Sandbox.allocation 块（mode: pool、poolRef、state: allocated），用于确认 Kubernetes 池分配，仅针对具有匹配分配证据的具体非通配符池引用发出。没有暴露 pod/命名空间/IP 数据。第1481章
  • 通过 OTLP 的通用 HTTP 请求指标 — 瘦 ASGI 中间件导出 server.http.request.duration (ms) 和 http_method、匹配的 http_route（或 unknown 对于未路由/身份验证失败的请求）和 http_status_code 属性，补充现有的创建持续时间直方图。原始路径、ID、键和主体从来都不是属性；而是属性。当 [otel] 禁用时无操作。第1561章
  • 具有范围的稳定诊断 API — 诊断现在遵循公共内联描述符约定：logs: container|all 和 events: runtime|lifecycle|all，其中 400 DIAGNOSTICS_SCOPE_UNSUPPORTED 用于未知范围，并针对不完整的尽力而为范围发出显式警告。已弃用的 no-scope 纯文本响应仍然适用于 Deprecation 标头。第1553章
  • 快速沙箱队列后端基础工作 (OSEP-0007) — FastPath v2 gRPC client 使用类型化错误映射（FastPathNotFound → 404 等）包装所有 FastPathService RPC，创建/状态映射层将公共合约转换为快速沙箱语义，拒绝不支持的字段（volumes、 platform、resourceRequests、credentialProxy、snapshotId等）有明显错误。尚未连接为活动运行时。第1558章 第1559章
  • 安全访问签名密钥可以来自 Kubernetes Secret - 服务器接受 OPENSANDBOX_SECURE_ACCESS_KEYS / OPENSANDBOX_SECURE_ACCESS_ACTIVE_KEY env 覆盖（镜像 API 密钥覆盖，需要网关模式），Helm 图表添加 server.gateway.secureAccess.existingSecret （与纯文本 keys 互斥，在渲染时强制），因此 GitOps 流永远不会提交密钥材料。第1445章
  • Docker 运行时 sandbox_env / sandbox_binds — 新的 [docker] 字段应用队列范围的环境变量并将主机绑定挂载到每个沙箱容器（请求 env 胜过 sandbox_env；配置绑定优先于请求派生的绑定），为 Docker 运行时提供 K8s Pod 模板具有的操作员端挂钩。第1303章
  • 出口 sidecar 准备超时可配置 — 新的 [egress] timeout_seconds（默认 30 秒，拒绝非正值）允许 Docker 部署调整服务器等待 sidecar 运行状况端点的时间。第1522章
  • 启动时验证租户命名空间 (OSEP-0014) — 服务器快速故障验证每个租户命名空间是否存在并且在提供流量之前是否可访问，将所有丢失/无法访问的命名空间聚合到单个致命错误中，而不是仅在请求时失败。 OSEP-0004/0005/0014 标记已实施。第1389章

🔒 安全

  • CVE 修复依赖项颠簸 — google.golang.org/grpc → v1.82.1 跨 kubernetes/ingress/execd/egress/internal（xDS RBAC 和 HTTP/2 修复），postcss → 8.5.11（通过 sourceMappingURL 读取的任意文件）。第1385章

🐛 错误修复

  • Docker 端点查找速度提高约 108 倍 — 容器查找现在通过 opensandbox.io/id 标签验证确定性 sandbox-<id> 名称，仅在需要时回退到标签扫描。本地基准：execd+egress 端点分辨率为 6.07s → 56ms。第1400章
  • 当监视停止时，通知者缓存会过期 — has_synced 现在表示“缓存当前处于活动状态”，而不是“初始列表完成一次”；停滞或半开的手表（例如在控制平面升级之后）降级为直接 API 读取，而不是永远服务于冻结状态，这导致以前使用 POD_READY_TIMEOUT 时每次创建都为 504。源自现有旋钮（resync_period + watch_timeout）的绑定；没有新的配置。第1534章
  • 中止响应时的代理连接泄漏 - 当下游 client 在响应正文流开始之前断开连接时，后端 httpx 响应从未释放，逐渐耗尽共享池，直到 httpcore.PoolTimeout。代理现在拥有整个 ASGI 生命周期的后端响应，防止 aclose() 被取消，并在设置失败时释放。压力测试：清理 1000/1000 次断开连接。第1488章
  • 独特、稳定的代理操作 ID — 20 个代理 HTTP 操作之前发出 4 个依赖于进程的重复操作 ID（16 个 OpenAPI 警告）；现在，每个方法都有自己的确定性 ID，具有相同的运行时调度、身份验证和 405 行为。生成的 clients 应该重新生成。第1634章
  • PVC 自动创建不再因格式错误的 500 而崩溃 - PVC 所有者引用补丁经过了不受支持的 _content_type 路径，该路径引发了 ApiTypeError（使 PVC 没有所有者引用）并且 SandboxErrorCodes.INTERNAL_ERROR 未定义，掩盖了真正的错误。两者均已修复：补丁使用支持的战略合并 call_api 路径；已定义错误代码。第1538章 第1447章
  • 模板容器 securityContext 现在到达 Pod - 深度合并之前批量替换了模板的容器，默默地删除了容器级 securityContext。模板键现在补充（从不覆盖）运行时值，与现有的volumeMounts理念相匹配。第1564章
  • 根相对后端重定向保留在代理路由下 - 来自沙箱后端的 Location: /login 被重新设置为 /v1/sandboxes/{id}/proxy/{port}/login；绝对、网络路径和仅查询引用保持不变。第1516章
  • 服务器代理端点删除入口路由标头 — OpenSandbox-Ingress-To（不区分大小写）从 use_server_proxy=true 响应中删除，同时保留安全访问和其他端点标头。第1503章
  • 代理响应上没有重复的 Date/Server 标头 — 代理保留原始 Date，同时抑制 Uvicorn 的默认值（和后端 Server 标头），仅发出一个 Date。第1471章
  • 无效恢复错误不再泄漏控制器内部 - 正在运行（内部成功）沙箱的 409 消息现在显示“状态正在运行”而不是“阶段成功”； HTTP 状态和错误代码不变。第1586章
  • 拒绝非有限 CPU 限制 — 在 Docker NanoCPU 转换之前拒绝 nan、无限和溢出值，而不是默默接受。第1568章
  • 允许混合只读 PVC 子路径安装 — 当声明的每个安装都是只读时，PVC 源设置为只读；阻止合法混合策略 PVC 创建的服务级别拒绝已被删除。第1440章
  • 代理沙箱服务器代理端点解析 — 内部端点解析现在委托给工作负载提供程序，并从 status.podIPs（而不是仅 BatchSandbox 注释）读取代理沙箱 Pod 地址，并在附加端口之前将 IPv6 文字括起来。第1424章
  • 版本报告已在各处修复 — /openapi.json、已安装的包元数据和图表 appVersion 均报告过时的 0.1.0；服务器现在在运行时从包元数据中读取其版本，构建注入 SETUPTOOLS_SCM_PRETEND_VERSION，并且发布脚本会碰撞 Chart.yaml appVersion。第1439章

📦 其他

  • execd v1.0.22 附带 OSEP-0018 init 模式强化 — 作为沙箱 init (PID 1) 执行，具有预执行强化地板（env strip、bounding set、no_new_privs、identity drop、环境上限、seccomp）和 Kubernetes 强化 e2e + PTY/bwrap 覆盖范围。第1474章 第1555章
  • 隔离会话失败关闭工作负载生命周期门 — 服务器将本机 Bubblewrap 生命周期门分发到两个运行时的 /opt/opensandbox；工作负载将保持阻塞状态，直到 execd 将其标记为就绪。仅第一阶段 - 能力准入和会话网络仍处于禁用状态。第1388章
  • 出口透明 MITM 可以拦截额外的 TCP 端口 — 实验性 OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS 将端口附加到始终在线的 80/443，并进行故障关闭验证（多端口上限 15）；凭证绑定仍然仅适用于规范端口。第1379章
  • 自动碰撞 — egress v1.1.5 → v1.1.7 (#1391 #1498 #1600)； execd v1.0.22（#1501）。
