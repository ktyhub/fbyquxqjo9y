hermes-agent v2026.7.20

修订 发布时间2026年7月20日 来源NousResearch/hermes-agent 英文原文

#爱马仕代理v0.19.0(v2026.7.20) 发布日期： 2026 年 7 月 20 日 自 v0.18.0 起： ~2,245 次提交 · ~1,065 个合并 PR · ~2,465 个文件已更改 · ~300,000 个插入 · ~36,000 个删除 · ~3,300 个问题已解决 · 450+ 社区贡献者

水银释放。 赫耳墨斯是信使之神，这个窗口我们让他像这样移动。每个平台上首次生成令牌的时间都下降了 ~80%，默认情况下推理流实时进行，桌面应用程序获得了约 20-PR 的速度大修（流式 Markdown 速度加快 14 倍、虚拟化差异、快速会话切换），并且 TUI 增量呈现 Markdown。围绕这个速度脊柱：您现在可以管理您的 Nous 订阅，而无需离开终端，将 Bitwarden 和 1Password 直接插入 Hermes，让智能审批默认为您判断标记的命令，观看您的子代理实时工作，并且 trust 得益于耐用的交付分类帐，完成的响应**在网关崩溃中幸存下来。此版本还汇总了 v0.18.1 和 v0.18.2 基础设施补丁标签中的所有内容 - 这些窗口已在此处完整记录。

✨ 亮点

  • Hermes 的速度显着加快 - 在很短的时间内获得第一个令牌 - 冷启动“初始化代理…”过去常常在你的第一个回合到达模型之前就吃掉 ~4.3 秒；现在约为 0.9 秒，减少了约 80%，适用于 CLI、网关、TUI、桌面和 cron 等。第 2 轮攻击了您在等待时“看到”的内容：推理模型现在默认实时传输其思维（不再盯着旋转器 30 秒），响应框按标记而不是按行进行绘制。如果赫耳墨斯在回答之前感觉自己深吸了一口气，那呼吸就消失了。 (#59332、#59389 — @teknium1)
  • 桌面应用程序速度浪潮 - 20 多个目标性能 PR - 过去的长回复在 Markdown 分割器中花费的 CPU 比现在多 14 倍；巨大的差异冻结了审查窗格，直到我们将其虚拟化；切换会话不再影响布局。流式处理不再重新渲染侧边栏和每个令牌的每个工具行，配置文件后端在悬停意图时预热，引导隐藏窗格在空闲时安装，而不是在冷启动关键路径上安装。最终效果：桌面应用程序感觉就像是负载下的本机应用程序，即使有大量的成绩单和忙碌的代理。 （#67154、#67818、#65898、#66033、#66747、#67742 等 — @OutThisLife)
  • 从终端管理您的 Nous 计划 — /subscription 和 /topup — 更改您的订阅过去意味着访问计费网站。现在，/subscription 在 TUI 或经典 CLI 中打开完整流程：查看您的计划和剩余限额，准确预览升级费用（“立即支付 $46.30 并升级”）或降级何时生效，并应用它 - 带有计划更改横幅和撤消。桌面应用程序有一个匹配的计费设置选项卡。您的钱包永远不必离开键盘。 (#51639、#61054、#61067 — @alt-glitch)
  • 智能批准现在是默认设置 - 当 Hermes 想要运行标记的命令时，LLM 审阅者现在会独立评估它，而不是要求您批准每一个命令 - 并且每个判决仅涵盖该确切的命令，因此匹配相同模式的后续命令会得到自己的审阅。结合新的用户定义的拒绝规则（即使在 yolo 模式下也会阻止命令）和 /deny <reason>（它告诉代理“为什么”您拒绝，以便其进行纠正），日常审批疲劳在不放弃控制的情况下急剧下降。 (#62661、#59164、#54518 — @teknium1)
  • 将您的密码管理器插入 Hermes — Bitwarden 和 1Password 秘密来源 — API 密钥不再需要以明文 .env 形式存在。新的可插拔 SecretSource 接口让 Hermes 在加载时从 Bitwarden 和 1Password（op:// 引用）获取机密，同时启用多个保管库、确定性优先级、冲突警告和每个变量的来源。这将 11 个相互竞争的社区 PR 整合到一个精心设计的界面中——未来的保险库提供商将作为插件加入。 （#59498 — @teknium1，1Password 提供程序从 @hwrdprkns 抢救出来）
  • 观看您的子代理工作 - 实时记录 + 持久的后台委托 - delegate_task 调度现在返回实时记录文件，您可以在子代理启动时 tail -f：每个工具调用、结果和流式回复，每个子代理一份人类可读的日志。现在，后台委托完成是持久的 - 如果流程在运行中重新启动，结果将通过所有权检查的分类帐恢复并交付，而不是消失。分散出一个舰队，观察任何工人的实时情况，并且永远不会丢失结果。 (#67479、#63494 — @teknium1)
  • 完成的答案不会再丢失 - 交付义务分类账 - 如果网关在生成您的响应和确认平台实际交付它之间发生故障，那么该答案就会悄然消失（并且您已经为此回合付费）。最终响应现在记录在平台发送周围的 state.db 的持久分类账中，并在下次启动时重新传递 - 关闭 Telegram、Discord、Slack 和所有其他渠道的 P1 无声丢失窗口。 (#67181 — @teknium1)
  • 一个网关，多个配置文件 - 基于配置文件的消息路由 - 共享一个机器人令牌的单个多路复用网关现在可以将特定的公会、通道或线程路由到不同的配置文件 - 每个配置文件都具有完全隔离的配置、技能、内存和秘密。从一个机器人将您的工作 Discord 服务器指向 work 个人资料，将您的业余爱好服务器指向 personal。第二波多重强化意味着一个错误配置的配置文件无法再摧毁整个网关。 （#64835 抢救@Burgunthy、#65700、#60589 — @teknium1、@benbarclay + 六名被抢救的贡献者）
  • 新的提供商和最新的前沿模型 - Fireworks AI 和 DeepInfra 成为一流提供商（Fireworks 具有成本估算功能，在提供商选择器中排名第二），Upstage Solar 通过抢救加入，模型目录被拾取 GPT-5.6（Sol/Terra/Luna + Pro 变体，每条路线端到端有线连接），grok-4.5 (GA)， moonshotai/kimi-k3、claude-fable-5 / claude-sonnet-5 和 GA tencent/hy3 — 加上用于本地设置的 LM Studio JIT 模型加载。 (#62593、#63969、#61616 — @kshitijk4poor 完成@rob-maron 的#61578、#60887、 #65913、#64541、#65472)
  • 将思维发挥到最大 - 新的推理工作级别和每个模型控制 - 推理工作获得了 max 和 ultra 级别（GPT-5.6 和 Codex 的顶级），从 CLI 到桌面，可以在任何地方进行选择，并合理地限制较小规模的提供商。您现在还可以在配置中固定每个模型的推理工作覆盖，在 MoA 预设中设置每个插槽的工作量（您的顾问努力思考，您的合成器保持快速），以及辅助模型的每个任务工作量。思考深度现在是一个旋钮，而不是一个全局开关。 (#62650、#64458、#64631、#64597 — @teknium1)
  • 您的会话、您的数据 — 导出所有内容 — hermes sessions export 现在可以编写 Markdown、Quarto、HTML、仅提示，甚至 Hugging Face-ready 跟踪格式，并具有完整的过滤器表面（年龄、工作空间、平台）、选择加入的 --redact 秘密清理通道以及缝合到一个逻辑导出中的压缩会话沿袭。与新的修剪过滤器和批量存档配合使用，以保持会话存储整洁。您的对话历史记录现在是一个真实的数据集，而不是一个黑匣子。 （#60186 抢救@web3blind、#60492、#60507、#59327 — @teknium1)
  • 安全强化回合 - 此窗口关闭了一长串凭证表面差距：顶点凭证范围远离子进程环境并通过配置文件秘密范围，媒体/视觉/图像生成本地文件读取通过一个共享凭证读取防护路由，webhook body-size-cap扫描每个aiohttp服务器，Telegram传输错误中的机器人令牌编辑，添加到编辑器的Fireworks令牌前缀，六个P1 browser/MEDIA/.env 强化 PR 一次性挽救，CI 针对 untrusted-ref 插值进行强化。 (#57660、#58709、#59215、#56582、#57842 — @teknium1、@srojk34、 @kshitijk4poor，@jquesnelle）
