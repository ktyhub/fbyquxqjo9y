paperclip v2026.1117.0

小版本 发布时间2026年11月18日 来源paperclipai/paperclip 英文原文

发布时间：2026-11-17 Paperclip v2026.1117.0 进行了 1,586 次提交，从 2026.1110.0-beta.0 升级。标题是一个新的默认工作区：协调器布局和代理聊天现在是标准的，任务聊天显示了运行者代理实际做了什么——它的计划、内联差异、工具调用、子代理和您可以批准的计划。围绕这一点：可以在委派权限内建立连接的代理、用于代理配置的完整 YAML 编辑器、上下文窗口和使用限制读数（带有 one-click Compact）、主动聊天消息和 Codex 和 Pi 的自动中转转向、Codex 图像生成以及目录中的 1Password、Supabase、Vercel 和 boxd。在下面，Runner 在更多情况下通过重新启动、崩溃和容器重新部署继续运行，本地 Codex 和 OpenCode 代理保持温暖以实现更快的后续操作，沙箱工作区可以在 S3 支持的安装上更换服务器后继续运行，主板在断开连接的情况下继续工作，运行日志和技能包从 PostgreSQL 移至您配置的存储中。

重大变更

  • 默认情况下，内置 Google Workspace 连接器处于关闭状态。 虽然 Paperclip 的 Google 应用验证正在等待，但 v2026.1106.0 中引入的统一 Google Workspace 连接受到新实验设置的限制：关闭连接器后，连接器将从应用程序中隐藏，并且其设置、发现和工具执行都会被阻止（包括 v2026.1106.0 上保存的连接），而会出现 Composio 和 Arcade Google 应用程序。要保持 Google Workspace 连接正常运行，请开启设置 → 实验 → Google Workspace 连接器 (Paperclip) (enableGoogleWorkspaceConnector)。 (#19247)
  • 每个子任务都有自己的执行工作空间。 在每个创建路径（API、create_task、聊天建议、插件和新建子任务对话框）上，子任务不再共享父任务的签出、分支或未合并的更改； inheritExecutionWorkspaceFromIssueId 现在仅复制项目和工作区策略，并删除传递给创建的祖先的 executionWorkspaceId。绑定到其父级工作区的较旧版本的子级在下次运行时将移动到其自己的工作区。依赖于子级编辑父级结帐的工作必须通过 Git 合并或推送；不相关的任务仍然可以通过显式的 existing 选择共享工作空间。 (#19860)
  • 代理创建的任务树停在父级 → 子级。 当代理请求孙级时，服务器会在请求者父级下的请求者旁边创建任务，并返回 parentAdjusted: true 而不是嵌套得更深；板用户仍然可以嵌套到任何深度，并且现有的树仍然有效。期望 parentId 与请求匹配的脚本应读取 parentAdjusted。 (#19312)
  • 本机代理通过 paperclip_finish/paperclip_block 报告任务状态。 当本机运行保留其任务时，分配的代理自己的 PATCH /api/issues/{id} 状态更改返回 409 native_run_status_reported_by_finish，这同样适用于恢复操作解析路由；告诉跑步者代理修补自己状态的自定义指令或技能应该切换到完成工具。 (#18411、#18489)
  • 本地 Codex 和 OpenCode Runner 代理默认保持温暖状态。 当未设置 Runner 生命周期时，本地 Codex 和 OpenCode 代理会在运行后将其运行器保持 5 分钟空闲窗口；克劳德、远程目标和其他安全带每回合都会保持不变。迁移 0443 会清除现有本机 Codex、OpenCode 和 Claude 代理中存储的“轮流”值，除非其配置历史记录显示有人明确选择它，并记录每个代理的 agent.updated 活动条目。要防止跑步者停留在常驻位置，请将跑步者生命周期设置回 依次。 (#19888)
  • 技能包移出 PostgreSQL，此版本成为回滚平台。 迁移 0415 后，存储库和托管技能包内容在回读检查后在后台转换为您的配置文件或对象存储。一旦运行，较旧的二进制文件需要重新水化数据库内容；在混合版本滚动升级期间，在每个进程上设置 PAPERCLIP_SKILL_PACKAGE_STORAGE_ENABLED=false，并保持该存储的持久性和备份。技能版本列表响应现在返回文件名和类型，不带文件正文。 (#18082)
  • Enter 提交任务回复和新任务。 Shift+Enter 插入新行；要保持 Cmd/Ctrl+Enter 提交，请打开实验首选项 Command/Ctrl+Enter 提交 (enableLegacyComposerSubmit)。 (#19272)
  • pi_local 进程不再继承服务器的 PAPERCLIP_* 环境。 只有运行时 API URL 和侦听主机/端口、运行范围变量和适配器的配置环境传递；依赖于继承的服务器变量的 pi_local 命令必须在代理的适配器环境中设置它。 (#14503)

亮点

  • 协调员工作区和代理聊天是标准的 — 现在，每个人都会进入一个围绕每个代理一次对话构建的工作区：任务建议将聊天请求转换为链接回其对话的分配任务，任务和决策显示为紧凑的卡片，在上下文面板中打开文档，收件箱队列通过搜索、过滤器和历史记录收集您需要的内容，而任务访问、分配授权和审核门仍然适用（#17983， [#19360]（https://github.com/paperclipai/paperclip/pull/19360））。使用新任务按钮导航组聊天、任务和收件箱，任务打开所有任务并记住您的视图，旧收件箱链接重定向到任务（[#18703](https://github.com/paperclipai/paperclip/pull/18703)、[#18831](https://github.com/paperclipai/paperclip/pull/18831)、[#19363](https://github.com/paperclipai/paperclip/pull/19363)、[#19393](https://github.com/paperclipai/paperclip/pull/19393))；聊天目录列出了每个代理的头像、角色、搜索和未读计数，并且代理可以固定在页面旁边（[#19685](https://github.com/paperclipai/paperclip/pull/19685)、[#19627](https://github.com/paperclipai/paperclip/pull/19627)）。每个人都可以在实验设置中使用**经典工作区**返回到之前的布局。
  • 任务聊天显示代理实际做了什么 - 运行者轮流将代理自己的计划渲染为停靠的任务列表（#19252）；文件编辑带有内联 +N −M 差异，并且更改的文件以“本轮已更改”卡结尾（#19269）；工具行命名动词、主语、退出代码和持续时间，并说明策略拒绝工具的时间 (#19265)； Claude 子代理显示为可折叠卡片，带有提示、进度、嵌套工具和结果 (#19264)；钩子决策和 Codex 自动审查判决、网络搜索、模型切换、等待和验证检查都有自己的行（#19266、#19262）；法典推理摘要显示为标题项目符号 (#19271)；并利用诸如“Compacting…”之类的横幅显示为筹码，而不是泄漏到答案中（#19267）。计划运行将 Codex 和 Claude 置于其本机计划模式，并且提议的计划在确认门后成为任务的计划文档，因此“批准”恢复代理，“请求更改”发回您的原因（[#19291]（https://github.com/paperclipai/paperclip/pull/19291））。最终聊天回复现在是客服人员的完整答案（最多 32,000 个字符），而不是 4,000 个字符的预览 (#19971)。
  • 运行程序通过重新启动和重新部署继续运行 - 在正常重启、部署、崩溃或容器替换之后，本机运行在更多情况下会自行继续：在引导程序或沙箱和工作区准备期间捕获的运行会在同一运行中重新启动其引导程序，并且在 Claude 和 OpenCode 以及 Codex 上的同一对话中，在飞行中中断的转弯会继续一次（#19524， #19616、#19694、#20153、#19501、#19699、#20118)。服务器从加密的控制器检查点重新启动后，将重新采用 Remote Runner 代理，从而保持沙箱租用、会话和活动轮次 (#17439)。现在，每个服务器启动都持有一个受保护的数据库租约，因此被替换的 Docker、Kubernetes 或 Fly 容器搁浅的工作将被恢复，而不是停留在卡住状态，并且一旦证明其所有者已消失，而不是在期限超时后（[#20054]（https://github.com/paperclipai/paperclip/pull/20054），[#19953]（https://github.com/paperclipai/paperclip/pull/19953），所保存的记录就会被释放（[#20054]（https://github.com/paperclipai/paperclip/pull/20054），[#19953]（https://github.com/paperclipai/paperclip/pull/19953） #19950、#20004、#20006)；接受的结果在硬终止后重新启动后几秒钟内完成（#19713、#19591）；排队运行在服务器侦听后大约一秒内开始（#19431）；并重新启动不再耗尽运行的恢复预算（#19948、#19625）。对于没有服务器可以判断的记录，主板会执行确认先前的服务器已停止操作（#20067、#20084）。
  • 更快的跟进 - 默认情况下，本地 Codex 和 OpenCode 代理处于热状态，测量到的第一个令牌的后续时间在 p50 上从 Codex 的 12.0 秒下降到 4.7 秒，对于 OpenCode 从 21.7 秒下降到 4.2 秒（#19888）；后续行动在准备期间声称停放的跑步者 (#20195)，Claude 后续行动更快地约 1.5–2 秒到达提供程序 (#20145)，并开始重用经过验证的可执行文件、提供程序包和启动上下文 (#18390， #17749、#18405)。
  • 沙箱工作区在服务器更换后仍然存在 - 在使用外部 PostgreSQL、S3 存储和稳定的机密主密钥进行安装时，沙箱环境中的 Runner 代理的新任务工作区保留在沙箱中，并且每次运行的文件都作为加密、经过验证的快照保存在对象存储中；替换服务器重新连接到记录的沙箱或将最后保存的版本恢复到新版本，而无需旧主机或将文件复制回 Web 服务器的磁盘。 “文件”面板标签 实时工作区 或 保存的副本，可以使用 server/scripts/migrate-remote-workspaces.ts 显式导入现有工作区（先试运行，然后 --apply），其他设置保留其当前路径。自上次保存以来所做的编辑仍然取决于实时沙箱。 （[#18403]（https://github.com/paperclipai/paperclip/pull/18403），[#18826]（https://github.com/paperclipai/paperclip/pull/18826））
  • 代理可以建立连接 — 在自己的授权（tools:manage_connections、tools:manage_profiles 及相关）及其负责人的当前权限内，代理可以通过应用程序使用的相同 API 配置应用程序和工具连接、聊天和电子邮件通道、AI 帐户和池、访问配置文件以及 MCP 网关；需要人工操作的步骤（登录、同意、凭证输入）会在通常的设置屏幕中保存为交接，当您完成这些步骤时，代理会继续执行。代理仍然无法批准自己的受管请求或编辑自己的权限授予；用户明确要求的更改可能会放松代理代理自己的工具控制，而无需单独批准。现有代理的权限不会回填。 (#17737、#17739)
  • 将代理编辑为一个 YAML 文档 — 新的 高级 选项卡可编辑整个配置 — 配置文件、线束和运行时、指令文件、技能引脚、工具、通道、权限和 trust、机密和 API 密钥 — 作为版本化的 paperclip/v1 代理文档。保存会经过每个资源自己的 API 并通过更改预览进行验证，过时的写入会被拒绝，部分保存会保留草稿，并且凭据会保持编辑状态；省略的设置保持不变，显式的空值会清除它们。 （[#18036]（https://github.com/paperclipai/paperclip/pull/18036），[#18168]（https://github.com/paperclipai/paperclip/pull/18168））
  • 视图中的上下文和使用限制 — 任务属性显示受让人的上下文窗口（“258k 的 10%”），其中包含 Codex 和 Claude Runner 代理的令牌、缓存输入、成本和压缩的详细信息，并且聊天标记每个压缩（#19273）； 现在压缩在运行之间运行线束自己的压缩，仅板和运行中不可用（[#19378]（https://github.com/paperclipai/paperclip/pull/19378））； 使用限制行显示提供商的速率限制窗口（“5h 78% · 重置 15:40”）（#19270）；并且达到其提供程序限制的代理将等待“等待使用限制重置”，而不是刻录运行和重试，而手动运行和对话轮流仍然开始（[#19246]（https://github.com/paperclipai/paperclip/pull/19246））。
  • 联系到您的聊天以及您可以引导的客服人员 — 客服人员可以通过新的 send_chat_message 工具将结果发布到与其负责人的常设聊天中，其中包含任务访问和隐私检查、源任务的链接以及每个人的未读状态（#18374）。 Codex 或 Pi Runner 回合运行时排队的消息将在 5 秒的“Sending in Xs”窗口（包含“编辑”和“取消”）后转入实时回合；其他线束保持队列，并且转向和中断保持可用（#19970）。
  • 一块能够渡过中断的板 — 一个连接横幅取代了每页错误，加载的内容在中断期间保持可见并在恢复时刷新（#15754、#18822）；任务编辑、文档、决策、新任务和消息在断开连接时保留草稿，并经过验证或重新发送，而不是丢失或重复（#17960、#18412）；每个用户和公司的一小部分读取数据会缓存 24 小时，因此在中断期间重新加载仍然会显示它们，并在注销时清除（#18825）；当页面块失败时，部署后的陈旧选项卡会自行重新加载（#17349、#19361）。
  • Codex 图像生成和技能发现 — Codex Runner 代理将 Codex 的内置图像工具保留在其现有登录中，并且直接 OpenAI API-key 连接上的代理获得 Paperclip generate_image 工具，该工具调用 gpt-image-2 服务器端，将密钥保留在代理的 shell 之外，并根据代理的预算计算支出（[#19516]（https://github.com/paperclipai/paperclip/pull/19516），[#19654]（https://github.com/paperclipai/paperclip/pull/19654））。新的 search_skills 和 load_skill 工具可让代理在运行的现有公司和项目访问检查下查找和读取未分配的公司技能，而无需更改其分配 (#19676)。
  • 留下 PostgreSQL 的存储 — 在 S3 支持的实例上，新的运行日志和选择加入的提供程序跟踪将作为不可变段写入现有存储桶中，无需新设置，原始跟踪使用现有保管库密钥进行加密，并且现有本地历史记录将在后台复制并带有经过验证的摘要 (#18327)。技能包移动到配置的文件或对象存储（#18082）。 .paperclip-repositories/ 下的额外项目存储库成为每个项目和存储库一个共享克隆的工作树，而不是每个任务的完整克隆，并通过选择加入扫描将现有工作区移动（#17382、#17369、#17407）。
  • 目录中的更多内容 — 1Password 作为服务帐户连接，具有八个受管理的保管库和项目操作（#17249）； Supabase 获得管理 API 连接，其中包含 11 个已审核项目、身份验证、数据 API 和边缘功能操作，Vercel 成为团队范围的 REST 连接，替换其不可用的 MCP 条目 (#17217)；新的 boxd 沙箱提供程序插件将每个沙箱作为 KVM microVM 运行，该沙箱在同一任务的运行之间暂停，并保留磁盘、内存和进程（#17284）。当 Native runner 实验设置开启时，Kimi Code 将 Runner 作为实验性工具加入 (#18028)。

修复

  • 运行、停止和重试 — 在任务自己的工作树中继续用尽或受阻恢复后重试，未提交的文件、分支和 .git 完好无损（#19666、#19693）；普通任务重试在暂时设置失败时获得正常的有界自动重试（#19384）；在锁定争用情况下重试聊天连接的任务将被保存或返回可重试的 409 而不是 500 （#18895、#18896）；取消重试留下的保留、重复的无重播保留和全盘重新启动不再阻止以后的消息和重试（[#19276]（https://github.com/paperclipai/paperclip/pull/19276），[#17055]（https://github.com/paperclipai/paperclip/pull/17055），[#18838]（https://github.com/paperclipai/paperclip/pull/18838），[#19181]（https://github.com/paperclipai/paperclip/pull/19181））；在本机会话启动时停止运行将返回 409 native_stop_pending 而不是 500 (#19189)，停止重试 PostgreSQL 死锁而不是失败 (#17895)，并且运行程序连接静默 90 秒的运行将结束并恢复，而不是永远显示“正在工作” (#19407);中断像停止一样稳定下来，然后是您的消息，而不是尝试失败的横幅（[#19633]（https://github.com/paperclipai/paperclip/pull/19633），[#19149]（https://github.com/paperclipai/paperclip/pull/19149））；沙箱提供商的临时 5xx、429 或租赁时间超时自动重试（#19412）；释放子树暂停会重新启动它中断的工作，一次（[#19394]（https://github.com/paperclipai/paperclip/pull/19394），[#19421]（https://github.com/paperclipai/paperclip/pull/19421））；其依赖性在其受让人的活动轮次期间完成的阻塞任务在该轮次结束时继续（[#19457](https://github.com/paperclipai/paperclip/pull/19457)）；成功的例程运行不再触发结束 blocked 的切换唤醒（#9129）；运行程序停止运行结束时提供程序或工具启动的每个进程，包括 nohup/setsid 作业 (#19727)；等待未完成的阻塞子任务的重试显示为等待并链接该子任务（#20109）；父任务总是在其子任务完成时被唤醒，即使在其运行结束时错过了唤醒 (#20180)；恢复对话框不再承诺唤醒被阻止的任务或以前的受让人，并且释放暂停会重新检查任务的当前状态（#17521）；在任何提供程序工作之前，在 session.open 失败的本机运行会自动重试，而不是阻止任务 (#18854)；当维护消耗结束时，排队将恢复，并且任务视图显示等待（#17967，#18065)；重试恢复成功运行后仍在排队的已保存聊天输入（#18621）；从板上关闭任务会干净地停止其活动的本机运行（[#18616]（https://github.com/paperclipai/paperclip/pull/18616））； 立即检查适用于持续执行受阻止任务的监视器，并且 UI 表示自动检查已暂停 (#18061)。
  • 消息和注释 - 当在保存注释和写入其唤醒之间重新启动时，当其运行因过时而被取消时，或者当它被添加到排队运行时（[#19992]（https://github.com/paperclipai/paperclip/pull/19992），[#20066]（https://github.com/paperclipai/paperclip/pull/20066），[#18913]（https://github.com/paperclipai/paperclip/pull/18913）），注释不再丢失；代理或公司暂停期间发送的评论将在暂停解除时保存并传送一次 (#19956)；在模型读取之前，引导消息不再因重新启动而丢失（#19962）；在运行准备时发送的消息进入其第一轮而不是中断它，并且在其完成时发送的消息随后传递一次（[#20168]（https://github.com/paperclipai/paperclip/pull/20168），[#19183]（https://github.com/paperclipai/paperclip/pull/19183））；在先前的运行完成后发送保存的后续任务重新打开并交付一次（[#19600](https://github.com/paperclipai/paperclip/pull/19600)）；已应答卡的收据离开作曲家队列（[#19376](https://github.com/paperclipai/paperclip/pull/19376)）；任务被重新分配的运行无法再关闭新所有者的任务 (#19186)；撤回卡或取消问题不再使代理的下一次本机运行在开始之前失败（#19163）；已接受的最终回复已可靠发布，因此在没有可见答案的情况下任务无法显示已完成 (#19200)；当停止运行仍在稳定时发送的重定向消息将被保存而不是被删除（[#19122]（https://github.com/paperclipai/paperclip/pull/19122））；再次记录一个人在对话中对代理人的纯人类计划或提案的明确批准（[#19243]（https://github.com/paperclipai/paperclip/pull/19243））； Stop 后保留的排队后续消息获得发送控制并被传送 (#17959)。
  • 成本和预算 — 一张丢失的使用收据不再冻结“已完成的运行等待会计”背后有硬预算的公司：一旦恢复结束并且提供商被验证停止，已知的使用量就结算（根据价目表定价，或根据您的政策记录为未定价的使用量），没有关闭证据的运行最多可以保留新工作 10 分钟，并且仅在达到硬停止、明确暂停或不活跃的公司时拒绝入场(#19497、#19673、#19606、#19944);临时记帐保留期间所做的注释、重试和新分配在清除时仅运行一次（#19741、#19702、#19829）；停止本机运行的预算或代理暂停不再导致任务被阻止且无法控制 (#20143)； 提高预算，现在在硬停止时为每个运行预算停止的任务提交一次重试，而不收取尝试费用 (#20144)； Codex 运行第一轮之前报告的使用情况不再计入该运行费用 (#19783)；引用已删除代理或项目的政策时，预算概览不再失败 (#18389)； Grok/xAI OAuth 令牌刷新不再在每次运行时向成本页面添加重复的订阅卡 (#16512)。
  • 权限和访问 — 具有 status 字段的 PATCH /api/agents/{id} 不再绕过仅限主板的暂停和终止操作（#19955、#20164）；关闭 CEO 代理上的“可以创建代理”现在会停止 hire_agent 和 POST /agent-hires (#20041)；默认无范围 tools:use 授权不再打开连接工具配置文件中未执行的操作 (#20160)，并且保存安装列表不再将广泛配置文件重新附加到您已缩小范围的代理 (#17906)；插件日志、作业运行和仪表板数据仅返回调用者的公司，实例管理员保留实例范围的视图（#17435）； credentialValues 信封是从 HTTP 日志中编辑的（#13742）；秘密编辑以线性时间运行，因此大型 Base64 负载不再冻结服务器 (#16999)；除非获得新的 commentary:view 权限，否则特工只能读取自己的评论，该权限默认处于关闭状态（#19842）；目标不能再被赋予来自另一家公司的父目标，并且插件补丁不能再将目标移动到另一家公司（#19203）；当项目访问拒绝停止低 trust 代理的任务时，任务会这样说，授权操作员可以从代理设置添加项目并重试（#17509、#17552）； AWS Secrets Manager 访问拒绝和缺少凭证显示为有指导的访问问题，而不是一般提供商错误 (#10946)； OpenRouter 上的 OpenCode 获取临时本地凭证，而不是其环境中可重用的上游密钥 (#17949)。
