paperclip v2026.916.0

paperclip v2026.916.0

纸clip v2026.916.0

发布时间：2026-09-16

Paperclip v2026.916.0 包含 503 次提交，从当天发布的 2026.916.0-beta.0 升级。标题是 Connections 列车：AI 运行时凭证（Claude 和 Codex 订阅、API 密钥、共享帐户）现在位于 Connections 中，与其他帐户具有相同的授权和权限边界，通过招聘和任务执行跟踪负责人，并且可以从需要它们的任务中进行内联连接或修复。围绕它：代理通过 AgentMail 获取自己的电子邮件地址，实验性聊天连接器将 Slack、Discord、Telegram、Microsoft Teams 和（通过 Photon）iMessage 对话带入任务中，GitHub 访问成为持久的个人身份而不是共享令牌，公告作为本机应用内卡片到达，实验性 Paperclip Runner 从上一个版本的基础工作发展成为完整的执行引擎 - 现在在自托管上默认打开大门为显式配置的代理安装。

重大变更

  • **便宜的模型配置文件被删除。**允许恢复和覆盖在更便宜的模型上运行的第二种执行模式已从适配器元数据、代理运行时配置、任务覆盖、恢复规则、API 和主板 UI 中消失；迁移 0236 从代理配置中剥离存储的 modelProfiles 块。现在，正常工作和恢复工作有一种模型选择路径。 (#12683)
  • 代理 API 不再返回明文凭据。 序列化代理的每个端点（详细信息读取、公司代理列表和创建/更新/生命周期路由）用于回显存储的 adapterConfig.env，因此 plain 绑定（API 密钥、令牌）逐字返回给任何能够读取代理的调用者，包括通过 GET /api/agents/me 的代理本身。所有三个响应系列现在都通过一位编辑演示者进行路由。从这些响应中删除实时凭证的集成将停止工作——这就是泄漏。 （[#9860]（https://github.com/paperclipai/paperclip/pull/9860），@glovario）
  • 自动生产力审查已退役。 将运行计数、评论计数和经过时间转化为管理审查任务的检测器及其延续保留被删除 - 基础设施故障可以满足其规则和制造工作。有限的恢复、预算、明确的阻碍和正常的审查阶段都仍然存在；现有任务记录保持可读且不变。 (#13263)
  • X-Forwarded-Host 仅受到 trusted 代理的尊重。 同源防护用于接受来自任何直接 client 的转发主机，让调用者将其自己的标头提升到 trusted 源集中。现在，仅当直接对等方通过操作员的 TRUST_PROXY 设置时，转发的主机才会计数 - 反向代理后面的部署应确认 TRUST_PROXY 已配置，或者代理的转发主机将被忽略，转而使用原始 Host 标头。 (#12832)
  • Anthropic 的旧版 REST 连接选项已消失，并且 REST 工具连接被验证为 REST。 过时的 REST 设置路径已被删除，以支持支持的 AI 帐户流程，并且 stdio 验证不再允许不支持的 REST 连接通过（或因误导性的 templateId 错误而失败） - 现有的不支持的连接现在会收到准确的拒绝。 (#13346)

变更流程图

亮点

  • AI 凭证现在存在于 Connections 中 — 提供商登录不再是针对每个代理的配置，而是成为具有连接已强制执行的所有权、授权和访问权限的托管帐户：代理重复使用负责用户的帐户或允许的共享帐户，模型/线束选择保持独立于凭证选择，旧代理将保留其现有身份验证，直到他们明确采用托管连接 (#13247)。相同的登录组件在入职、代理配置和连接器页面中重复使用，而不是第二个登录向导 (#13248)。雇佣代理继承招聘代理的提供者凭证引用，以便委派的队友可以从其第一次运行进行身份验证 (#13268)，并且连接会跟随旧运行者和本地运行者的雇佣 — 丢失的帐户会暂停任务并提供内联连接表单，而不是失败 (#13438)。每个负责的用户都会获得每个提供商的默认值，因此同一代理可以在一个人的订阅和另一个人的 API 密钥上运行 (#13351)。火车在着陆时也变得更加坚固：订阅登录可以在经过身份验证的自托管实例上工作，而不会暴露服务器运营商的 CLI 帐户 (#13344)，凭证租约可以在事务池中生存，而不是报告幻象“连接繁忙”(#13347)，一个 Anthropic 订阅连接支持并发运行 - 仅支持文件凭证仍然序列化（#13445），并且连接探测、已保存帐户重用和任务切换获得了可靠性通过（#13404、#13161）。
  • 代理获得自己的电子邮件 - AgentMail 连接（实验性）为代理提供专用收件箱：传入电子邮件成为任务中分配的工作，发送是通过 Paperclip 验证的显式代理操作，并且内部任务评论永远不会意外地作为外发邮件泄漏。提供商密钥保留在服务器保管库中，董事会通过任务电子邮件卡跟踪每个对话。 (#13256)
  • 通过聊天工具联系您的客服人员 - 实验性本机聊天连接器将 Slack、Discord、Telegram、Microsoft Teams 或 GitHub 机器人身份绑定到一名客服人员，并将每个承认的外部对话绑定到一项任务，并具有持久的每个对话队列、问题、进度、文件和交付收据 - 董事会评论保留在内部，除非明确发送到渠道，并且根本不会发送原始推理、日志和凭据（[#13100]（https://github.com/paperclipai/paperclip/pull/13100），[#13038]（https://github.com/paperclipai/paperclip/pull/13038））。 iMessage 通过实验性 Photon 通道加入：共享 Pro DM 或专用号码，包括照片，Paperclip 保留任务所有权和批准权限 (#13299)。在应用程序本身中，实验性代理聊天为每个人提供了与每个代理的持久对话 - 由真实任务和正常治理支持，而不是并行聊天存储 - 并且每个公司代理都可以通过可搜索选择器从聊天侧边栏访问（[#13284]（https://github.com/paperclipai/paperclip/pull/13284），[#13420]（https://github.com/paperclipai/paperclip/pull/13420））。
  • GitHub 访问成为身份，而不是共享令牌 — GitHub 应用程序支持的身份具有持久刷新、存储库访问检查和 Webhook 交付，取代了临时令牌，建立在现有托管连接和加密授权的基础上 (#12843)。当多人控制一个代理时，托管的 Git、gh 和 GitHub 工具会根据接受的指令解析负责人的凭据 - 具有持久的延续规则，并且不会回退到队友的访问权限 (#13005)，并且该身份也会项目到沙箱运行程序中 (#12907)。围绕核心：浏览跨组织的存储库访问 (#12998)，为每个项目选择多个源存储库 (#13010)，干净地解析到同一 GitHub 帐户的重复连接 (#13022)，并且登录状态和连接存储库访问在 UI 中可见并简化（[#12993]（https://github.com/paperclipai/paperclip/pull/12993）、[#13047]（https://github.com/paperclipai/paperclip/pull/13047）、[#12893]（https://github.com/paperclipai/paperclip/pull/12893））。
  • 公告到达应用程序 — 原生公告卡使用原生组件呈现经过验证的 JSON 提要（主角可以是静态图像或独立的 HTML/CSS 动画），因此发布或撤回卡片不需要发布应用程序。该实例上的每个帐户都会存在解雇情况 - 关闭的卡在公司和浏览器之间保持关闭状态 - 命名的临时提要允许作者在制作之前测试内容。默认情况下针对托管源启用；升级指南可以选择退出。 (#13403)
  • 入职直接走向工作代理 - 连接步骤作为模型源问题打开，内置提供商登录 - 单张卡上的一个连续序列，包括 API 密钥输入，粘贴的登录代码保留在屏幕上并立即回答（#12440、#12863、 #12801、#12820、#12613、#13193)。现在，您的第一个任务以与参谋长的聊天形式打开，参谋长等待您的答复而不是自行逃跑，并且参谋长的招聘是可靠的（[#13068]（https://github.com/paperclipai/paperclip/pull/13068），[#13317]（https://github.com/paperclipai/paperclip/pull/13317））。创建以后的代理会在简化的向导中借用相同的连接控件和重新组织的配置页面 (#13011)，并且在设置过程中会重复使用保存的模型连接，而不是要求您再次登录 (#13161)。

改进

  • 应用程序和连接器目录不断增长 - 应用程序离开了其实验大门，连接设置更短，托管的 Google 访问可在具有安全默认来源的干净自托管安装上运行（#12728）。下面：连接授予和委派身份 (#12341)、托管外部 MCP 连接器 (#12346)、安全远程 MCP 和 PostHog 设置 (#12339)、Composio 和 Gmail 连接器 (#12342)、扩展的自助服务目录，具有基于意图的设置（#12344、#12347、#12345)、精细的 Postman 和 Shopify 流程 (#12357) 以及整合的连接器管理（[#12684]（https://github.com/paperclipai/paperclip/pull/12684））。 Google Workspace 设置后来进行了端到端修复：目录和创建使用相同的可用性规则，所有权选择在功能更改后仍然存在，Paperclip 是默认的 Google 身份验证方法，具有自定义 OAuth 一链接（#13289、#12619、#12623）。代理还可以从本机任务源请求新的服务连接，并从任务中查看连接操作（#13058、#13063）。
  • 模型和提供程序更新 — Claude Fable 5.1 可以在 Claude 适配器中选择，具有直接的人类和基岩推理配置文件 ID (#12730)； Codex 凭借其特定于模型的控件获得了 GPT-6 Astra (#12851)；未设置的 Claude 模型在任何地方都解析为 Opus 5，默认值在代理配置中可见 (#13055)。 Grok 将沙箱设备登录面板与一个私有的、公司范围的凭证主页一起加入，管理远程订阅运行并将刷新的凭证复制回主机（#12469、#12618、#12696）。每个 Codex 帐户都有自己的主目录和路径秘密，并且代理可以绑定到公司默认登录之外的 Codex 登录名（#12709、#13067）。
  • 原生 Paperclip Runner 现在可以完成全部工作 - 并且自托管安装默认情况下打开大门 - 上一个版本的基础工作成为 enableNativeRunner 标志背后的完整实验执行引擎，现在默认为自托管实例启用（云管理实例将其关闭）（[#13068]（https://github.com/paperclipai/paperclip/pull/13068））：本机 Codex 执行和 Claude ACPX 运行时加上合格的 OpenCode 运行时（#12616、#12590、#12588、#12691)、托管提供程序后端 (#12699)、具有安全传输的远程执行基础（#12638、#12639）、管理和可观察性（#12641）以及本机转投影到任务聊天（#12617）。该控件是一个统一标志，用于控制每个设置路径（#12656、#12666）。开放默认设置仅解锁大门：显式配置的本地 Codex、OpenCode 和合格的 ACPX 代理可以使用运行器，登录保留在旧适配器上，不会自动切换，并且在实验设置中关闭 enableNativeRunner 会再次关闭它。
  • 操作员控制 — 托管实验标志 enableIsolatedWorkspacesByDefault 使没有自己策略的每个项目都使用独立的每任务 git 工作树，因此舰队默认不再意味着手动编辑每个项目（#13444）。新的标准 trust 代理可以默认雇用其他代理 - 低 trust 代理保留禁用的默认设置（#12814）。哨兵监控分为 SENTRY_DSN_FRONTEND 和 SENTRY_DSN_BACKEND，旧的 SENTRY_DSN 仍然作为后备（#12678）。实验设置页面摆脱了死控件和组开发人员工具（#12681），并且 PAPERCLIP_HIDDEN_SETTINGS 也在生产切换器菜单中受到尊重（#12788）。
  • 任务界面焕然一新 - 简化的导航基础，具有精致的任务和工作区界面、一致的悬停/弹出/间距行为以及紧凑的仪表板和实时运行卡，您可以实际扫描（#12746、#12747、#12748、 #12854、#12793、#13269)。工作产品在任务工件选项卡上获得丰富的卡片和运行工件清单 (#12717)，viewer=full 文档深层链接直接从外部通知打开最大化的侧窗格 (#12812)，作曲家获得带有简化的任务控件、状态徽章和内联阻止程序删除的停止控件（#13104、#13097)、单项选择题在选择中提前 (#13234)、跑步者活动压缩为在实时和保存的视图中共享的滚动的每组摘要 (#13255、 #13274、#13421)、从任务创建的任务按项目显示 (#13241)、长任务聊天在流式传输期间保持响应 (#13229、#13228)，以及移动设备获得真正的实体选择器表、全角任务树和间距通道（#13343、#13250、#13304、#13122)。
  • 找到任务的任务搜索 - 完整和快速的搜索统一围绕 PostgreSQL 术语覆盖范围，具有明确的相关带和保守的拼写错误恢复，并根据评分语料库进行判断。 (#13335)
  • 在不接触数据的情况下尝试它 - 仅前台 test-drive CLI 命令使用自己的数据目录和提供商支持的 CEO 启动一个隔离实例，并具有重用保护措施和恢复的凭据输入（#12894、#12898）；除非明确要求，否则服务器启动不再打开浏览器（#12435）。
  • 沙箱运行变得更快、更坚固 - 温暖的 Daytona 工作区持续不断，主机工作区保持耐用性边界（#12904、#12901），HTTP/2 沙箱桥承载二进制体和附件路线（#12923），选定的技能阶段进入远程 Claude ACP 运行(#13196)，丢失的沙盒控制通道无法快速转弯而不是挂起(#13158)。

修复

  • 服务器安全性和正确性 - 特权服务器边界得到强化（#12776），项目目标 ID 被验证存在并属于公司（#12779），listComments 在非 UUID afterCommentId 上不再有 500 秒(#8695, @Maxxsong7)，Docker 快速入门通过 (#6846, @rsclafani) 传递 PAPERCLIP_ALLOWED_HOSTNAMES。
  • 数据库池修复而不是楔入 — 空闲连接被回收，池被命名并在关闭时结束 — 关闭堆积后端的重启循环，直到 PostgreSQL 拒绝每次启动（#12956，@stubbi） — 并且重播其套接字写入在回收的池连接上失败的查询，而不是使请求失败（[#13417]（https://github.com/paperclipai/paperclip/pull/13417））。
  • 入职连接步骤显示其工作 - 入职期间的提供商登录现在会显示验证进度并在继续之前确认订阅，而不是显示为挂起 (#13499)，并且在读取令牌时会跳过计算机上陈旧或过期的 Claude 凭据文件，而不是中断登录 (#13505)。
  • 更多连接可靠性 — 个人 MCP 身份验证发现已畅通无阻 (#13497)，并且一个 OpenAI 或 xAI 订阅连接支持并发代理运行，与此版本中的 Anthropic 修复相匹配 (#13452)。
  • 恢复和唤醒 - 隐藏问题被排除在搁浅恢复和继续唤醒中（#5648，@im0xMagnus），阻塞唤醒等待而不产生重复运行（#13236），过时的继续唤醒被拒绝（#13173），您发送的消息当运行停止时，在恢复后保存并传递而不是消失（#13327、#13270、#13405），用户消息可以继续停止的本机任务（#13239），重试耗尽事件不再耗尽注意反馈内存(#13451)，启动运行可以在重叠部署中幸存(#13285)，并且运行轮询和工作区检查放大会减少(#13174)。
  • 沙箱和工作区 - 卡住的沙箱插件会明显阻止运行，并在启动时重新启用错误的捆绑插件（#12957，@stubbi），停滞的沙箱启动会在不等待安装的情况下取消（#13352），工作区设置恢复并重试(#13353)，遗留的 Daytona 启动失败从任务和收件箱中恢复 (#13272)，项目的所有存储库都为本地和沙箱任务配置 (#13442)，临时工作区引导扫描恢复而不是运行失败(#13481)，沙盒文件在旧版和本机运行器上发布 (#13493)，并且运行事件有效负载保留 NUL 字符 (#13325)。
  • Web 应用程序 — Service Worker 带有每个构建 ID 标记，因此部署实际上到达停放的选项卡 (#12725)，工作区就绪通知呈现为紧凑的系统通知而不是代理气泡 (#12716)，提要卡完全可 clickable (#13294)、任务页面存档快捷方式已恢复 (#13253)、代理指令不再错误保存 (#12502)、公司导航仅限于可访问的成员资格 (#13039)、“近期任务”停止跨选项卡回显存储反馈(#13402)，并且计划到自动转换仅在计划确认时发生(#12695)。
  • 适配器 — 在配额分类中检测到无限定符的 Claude 使用限制消息 (#12475)，Codex 登录和环境测试就运行使用的凭据达成一致 (#13064)，Codex 启动 trust、历史读取和恢复使用情况得到纠正(#13110)，Grok 从主机目录进行环境测试，并在不存在的工作空间中继续存在 (#13416)，并且在保留可用的运行时默认值的同时防止意外的引擎回退 (#13105)。

升级指南

  • 无新平台要求：v2026.831.0 的 Node.js 24.11.0 地板保持不变。
  • 迁移：此版本添加了 49 个数据库迁移（0231 到 0279）。它们在启动时自动运行。通过火车：清理冗余的自动创建的应用程序连接工具配置文件行 (0231)、连接授予和委派身份 (0232)、托管外部 MCP 连接器 (0233)、本机运行程序提供程序跟踪、运行事件唯一性、后端、会话恢复和会话目标 (0234–0235、 0237–0238、0248)、删除存储的廉价模型配置文件 (0236)、持久 GitHub 身份和每人执行身份上下文 (0239–0245)、连接服务并检查任务中的连接操作 (0246–0247、0249)、持久任务恢复(0250–0254)、聊天提供程序和数据基础 (0255–0270)、每个代理 Codex 登录绑定 (0271)、AgentMail 收件箱 (0272)、部署安全启动运行 (0273)、代理聊天 (0274)、iMessage Photon (0275)、AI 连接和每用户提供商默认值 (0276–0277) 以及公告解除状态 (0278–0279)。只有 0231 和 0236 丢弃数据 - 冗余工具配置文件分别包括行和删除的廉价模型配置文件；其他一切都是附加的。
  • 新的可选环境变量：
    • SENTRY_DSN_FRONTEND / SENTRY_DSN_BACKEND — 独立的浏览器和服务器错误监控；传统的 SENTRY_DSN 仍然可以作为两者的后备。 (#12678)
    • PAPERCLIP_ANNOUNCEMENTS_ENABLED — 应用内公告默认开启；设置为 false 以选择退出。 PAPERCLIP_ANNOUNCEMENTS_FEED_URL 覆盖进给（默认 https://pages.paperclip.ing/announcements/v1/current.json）。 (#13403)
    • PAPERCLIP_TOKEN_BROKER_ALLOWED_HOSTS — 沙盒令牌代理可以到达的以逗号分隔的额外主机，用于远程 MCP 设置（默认值：无）。 (#12339)
    • PAPERCLIP_DISABLE_CWD_ENV_FILE — 设置为 true 以阻止服务器从其工作目录加载 .env 文件（默认值：加载）。 (#12894)
  • 删除了 API 表面：modelProfiles 已从适配器元数据、代理运行时配置和任务覆盖中消失（#12683）；代理响应中的明文 env 值已被编辑（#9860）； Anthropic 的旧版 REST 连接设置选项已删除 (#13346)。
  • 需要注意的行为更改：实验性 Paperclip 运行器门 enableNativeRunner 现在默认为自托管实例打开 - 仅显式配置代理，不会自动切换，云托管实例保持关闭状态 (#13068)；新的标准 trust 代理默认可以雇用其他代理 (#12814)，取消设置 Claude 模型解析为 Opus 5 (#13055)，Apps 不再位于实验门后面 (#12728)，并且 X-Forwarded-Host 需要代理trust（请参阅重大更改）。
