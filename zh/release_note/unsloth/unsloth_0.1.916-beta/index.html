unsloth v0.1.916-beta

预发布 发布时间2026年11月6日 来源unslothai/unsloth 英文原文

unsloth v0.1.916-beta

这个项目是干啥的：一个让大模型微调训练更快、更省显存的开源库，原本跑不动的模型普通显卡也能试，给预算有限的研究者和个人开发者用。

此版本为 Unsloth 带来了巨大的性能修复：在长时间聊天中更快的打字和搜索、更快的图像/视频加载、双 GPU 图像/视频生成。它还为每个聊天添加了单独的浏览器、浮动浏览器窗口。

变更架构图

亮点

  • 大量性能修复，下周将推出更多 Glass 主题优化
  • 玻璃主题修复不再模糊，更好的渲染，更多选项
  • 统一内存卸载现在可以正确地适用于大型模型
  • 每个聊天都有单独的浏览器 - 多个聊天现在可以单独运行自己的浏览器
  • 浮动浏览器您可以在聊天中移动和调整大小并让模型做它的事情
  • 动态 V3.1 Qwen3.8-Flash - 令牌使用量减少 50%，准确度提高 15%
  • 双 GPU 图像和视频 在匹配的 NVIDIA 卡上速度提高 2 倍
  • 更快的聊天搜索和删除 - 更快地搜索和删除聊天
  • 稳定的扩散图像/视频模型加载速度高达 40%
  • LTX-2.5 视频 在 16 至 24 GB GPU 上的新提示速度更快

聊天表现

  • 当 Glass 主题或聊天背景打开时，在长聊天中打字不再滞后。
  • 聊天搜索在很长的历史记录中保持快速，而不是加载失败。
  • 在大型历史记录中，清除和删除聊天记录要快得多。
  • 启动后首次使用语音或音频功能不再将流式回复冻结几秒钟。
  • 使用 Unsloth 模型 引擎大声朗读，在说话之前不再在模型查找上等待几秒钟。
  • 背景图像上的玻璃主题在没有 GPU 渲染的情况下响应速度提高了 2 倍，就像在某些 Linux 桌面上一样。

图片和视频

  • 借助两个匹配的空闲 NVIDIA GPU，SDXL、Qwen-Image 和 Wan2.2 5B 等型号在安装到一张卡上时，可以在第二张卡上运行每个步骤的一半，速度大约为 1.5 至 1.8 倍。
  • 在相同的设置中，FLUX 和 Lumina 2 在两张卡上分割均匀大小的一批图像。
  • SDXL 加载速度提高了 40%，因此第一张图像可以更快到达。
  • 在 16 至 24 GB GPU 上，LTX-2.5 在 GPU 而不是 CPU 上对新提示进行编码，因此具有新提示的 clip 渲染速度要快得多。
  • 在帧相同的情况下，LTX-2.5 GGUF Q8_0 视频在 NVIDIA GPU 上的渲染速度提高了约 10%。
  • 当模型未量化、GGUF 或卸载时，使用相同 LoRA 的重复渲染速度更快。
  • 某些图像模型（例如 FLUX 和 Z-Image）在使用 AMD RDNA3 和 RDNA4 GPU 的 Linux 上渲染速度更快。

不懒惰的新功能

  • 将内置浏览器作为一个小窗口浮动在聊天上方，您可以移动和调整大小；每个聊天都会记住它是否浮动。
  • 从单文件检查点加载 Anima、Chroma、MOSS-Image 和 Krea 2 图像模型，以及除 Chroma 之外的所有图像模型的 LoRA 和 LoKR 文件。
  • 玻璃主题使背景图像变暗而不是模糊，其他页面上的控件与聊天的玻璃相匹配。
  • 所有者可以重命名托管帐户，而不会丢失其聊天记录、文件或设置。
  • 所有者可以在 设置 > 常规 > 下载 中限制模型下载速度。
  • OpenAI 兼容连接可以发送自定义标头。

修复

  • 在已下载非 GGUF 模型的仅聊天安装中，第一个聊天会获取默认模型而不是失败。
  • 仅 CPU 机器上的 GGUF 模型不再会因自动上下文而耗尽内存。
  • 在 Windows 上，HTTPS 下载在暂停或中断后恢复，而不是重新开始。
  • 在 Windows 上更新 Unsloth 不再在最后静默半分钟。
  • 通过 MCP 连接 Blender 再次可用。
  • 比较模式不再将第一条消息的一个窗格留空。

培训和图书馆

  • 在 Python 中，Llama、Qwen2 和 Qwen3 型号的 model.generate() 在 Linux 下的 NVIDIA GPU 上默认速度更快，对于小型型号而言可达数倍。
  • 对分成数百个文件的 Hub 数据集的训练启动时间提前一分钟。
  • 通过仅辅助完成，以换行符开头的答案不再被排除在训练之外。
