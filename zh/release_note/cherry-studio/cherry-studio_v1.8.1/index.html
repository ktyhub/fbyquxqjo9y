cherry-studio v1.8.1

cherry-studio v1.8.1

这个项目是干啥的：一个桌面端 AI 助手客户端，把多家大模型装进同一个界面，支持聊天、翻译和知识库，适合想统一管理各种 AI 模型的用户。

变更架构图

亮点

  • Agent 与 MCP 可靠性 — 对运行 agent/MCP 的人来说是实打实的功能修复：hub 工具自动审批现在会解析到底层服务器（#13493），通过协议安装的服务器获得白名单自动信任路径（#13586），budgetTokens 会回退以兼容 Agent 思考模式（#13575），工具输出和内联代码渲染出可点击的文件路径（#13465）。语言检测不再误开启思考模式（#13565），gh-pr-review 技能新增多 agent 团队评审与自动修复（#13530）。如果你通过深链进入 Zed，Zed URL scheme 和 OpenExternalAppButton 重设计（#13501）也值得关注。以 agent/MCP 为核心工作流的用户应升级。
  • Azure OpenAI 与错误诊断 — 聊天传输现在保留带日期的 API 版本（#13506），对把 Azure OpenAI 部署锁定到特定 API 版本、却一直被悄悄提升的用户很关键。流失败现在会露出真实错误，而不是笼统的 NoTextGeneratedError（#13542），让排查模型/provider 问题明显更容易。Azure 用户和追查不透明流式错误的人值得升级。
  • Windows / macOS 启动与鉴权修复 — 平台特有的阻塞问题得到解决：code-tools 启动错误和 Windows 上的 Qwen Code 鉴权（#13400）、非英语系统上 Windows Terminal 无法启动（#13551），以及为卡在旧代码签名上的 macOS 用户提供手动下载选项（#13378）。如果你用 Windows（尤其是非英语区域）、使用 Qwen Code，或旧 macOS 装不上新签名版本，这是很强的升级理由。
  • 备份系统重构 — 备份子系统经过重写，加入旧版备份处理和路径安全（#13587）。因为涉及备份的写入/恢复方式并收紧了路径校验，依赖备份的人应在升级后验证一次恢复。这里还附带一些 UI/体验项：聊天消息容器不再横向滚动（#13508），每日自动 i18n 同步（#13521）只是翻译内容。
  • 升级结论与迁移 — 这是一个真正的补丁版本，包含实质修复和几个小特性——不是空操作、重新打标签或仅改元数据的发布。changelog 未记录破坏性变更或必需迁移，因此是低风险升级：agent/MCP 用户、Azure OpenAI 用户、Windows/非英语用户，以及遇到启动或流式 bug 的人都应升级。稳定的英文环境、没有 agent/MCP/Azure/备份依赖的用户可以合理跳过。仅涉及开发/CI 的条目（发布构建现在在 PR 合并时触发，而非每次 push——#13512）对最终用户不可见。
