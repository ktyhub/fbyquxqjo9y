cherry-studio v1.9.3

修订 发布时间2026年4月24日 来源CherryHQ/cherry-studio 英文原文

变更架构图

亮点

  • 提供商与模型兼容性 — 多个热修复恢复提供商特定行为：尊重 model.endpoint_type 后，自定义参数不再在 CherryIN/NewAPI 上丢失（#14409）；AiHubMix/NewAPI 的 Anthropic 模型禁用原生结构化输出以避免损坏（#14376）；通过对 @ai-sdk/openai 打补丁支持 gpt-image-2 并新增模型图标（#14488, #14539）；CherryIN 种子 apiHost 与迁移 183 对齐（.cc）（#14528）。Bedrock 配置拒绝空的 baseURL/region 字符串（#14425），API 服务器现轮换逗号分隔的提供商 API Key（#14346）。若使用上述任一提供商，仅此就值得升级。
  • 智能体与 Claude Code 可靠性 — Claude Code 现通过 cli-wrapper.cjs 启动而非原生二进制（#14430）——若有任何东西依赖旧二进制路径，这是值得注意的行为变化。Soul Mode 保留会话指令（#14424），原生工具循环保持存活（#14481），已安装技能列表在切换时保持稳定（#14472）。这些直接惠及依赖智能体/工具调用的用户。
  • 安全与依赖 — form-data 从 2.3.3 升到 4.0.5（#14441），把上游安全修复带入这个间接依赖；openExternal 现允许 vscode/cursor/zed 深链（#14437），修复编辑器链接失效且不开放任意 scheme。两者都无需用户操作。
  • MCP、IM 与 UX 修复 — 通过把连接超时交给 SDK，慢 SSE 的 MCP 服务器得以恢复（#14348）；处理来自 IM 渠道的飞书图片消息（#14421）；拖拽上传接受不区分大小写的扩展名（#14416）；备份正确处理符号链接（#14471）；限制内置网页搜索的使用（#14466）；快速面板状态在关闭时重置，避免模型被取消选择（#14378），横向多模型消息不再触发外层滚动（#13964）。
  • 升级建议 — 这是错误修复/热修复补丁版（v1.9.2 → v1.9.3）：无破坏性变更，用户也无需新迁移步骤（迁移 183 只是对齐目标）。智能体/Claude Code 用户、使用 CherryIN/NewAPI/AiHubMix/Bedrock 的用户、gpt-image-2 用户、慢 SSE MCP 配置，或想要 form-data 安全更新的用户值得升级。若均与你无关可安全跳过——无论如何风险都很低。
