cherry-studio v1.7.13

修订 发布时间2026年1月25日 来源CherryHQ/cherry-studio 英文原文

cherry-studio v1.7.13

变更流程图

亮点

  • Anthropic 提示词缓存 — PR #12333（@nekohy 的首次贡献）在请求路径加入 Anthropic 缓存支持，重复的大上下文可复用而非重发。对运行长时智能体会话的用户，请检查系统提示词与工具定义是否位于可缓存的消息边界——延迟与 token 成本的节省正是在那里实现。
  • 新增百川模型 — PR #12364 把百川加入提供商名单，多一个可选模型后端。采用门槛低，但切换前请确认 API Key 与端点配置符合该提供商期望的格式。
  • 构建与 CI 转向 pnpm 优先 — PR #12358 用 pnpm install 取代手动预构建包下载，PR #12374 在工作流中加入 pnpm 安装与缓存。贡献者与 CI 维护者获得 lockfile 驱动、可复现的依赖解析和更快的任务；代价是离线或气隙构建现在需要填充好的 pnpm store 或 registry 镜像，而非自带 tarball。
  • feishu-notify 改为子命令 CLI — PR #12371 把飞书/Lark 通知脚本迁移为带子命令的 TypeScript CLI 工具。这是需要注意的接口变更：任何直接调用旧入口的 CI 步骤或辅助脚本，都必须按新的子命令语法重写。
  • Linux 与 macOS 桌面集成修复 — PR #12348 把 X11 窗口 class 与名称设为 cherry-studio，平铺窗口管理器与自启动规则终于能通过 WM_CLASS 匹配该应用；PR #12355 为 SelectionService 的修饰键检测加入 macOS key-code 处理，修正苹果键盘上的选择/快捷键行为。
  • 资源与更新路径清理 — PR #12269 新增 dispose 方法移除 abort 监听器，防止长生命周期会话中监听器累积（持续使用下的慢泄漏）；PR #12351 在 differentialPackage 禁用后移除遗留的 blockmap 处理，让更新路径不再有死掉的差分更新逻辑。

发生了什么变化

  • 修复：在https://github.com/CherryHQ/cherry-studio/pull/12351中@defi-failure禁用differencePackage后删除块图处理
  • 在 https://github.com/CherryHQ/cherry-studio/pull/12333 中添加 @nekohy 的人类缓存
  • feat(scripts): 通过@EurFelux在https://github.com/CherryHQ/cherry-studio/pull/12371中的子命令将feishu-notify迁移到TypeScript CLI工具
  • 重构：在 https://github.com/CherryHQ/cherry-studio/pull/12358 中使用 pnpm install 而不是 @beyondkmp 手动下载预构建包
  • 修复(Tray): 在https://github.com/CherryHQ/cherry-studio/pull/12348中通过@TRSWNCA将X11窗口类和名称设置为cherry-studio
  • feat(baichuan):在https://github.com/CherryHQ/cherry-studio/pull/12364中添加@pippobj的baichuan模型
  • 修复(SelectionService)：添加 macOS 按键代码支持，以通过 https://github.com/CherryHQ/cherry-studio/pull/12355 中的 @0xfullex 进行修饰键检测
  • 修复（工作流程）：在 https://github.com/CherryHQ/cherry-studio/pull/12374 中添加 @EurFelux 的 pnpm 安装和缓存
  • 修复：在 https://github.com/CherryHQ/cherry-studio/pull/12269 中添加 dispose 方法以防止 @DeJeune 泄漏中止侦听器
