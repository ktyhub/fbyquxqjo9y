cherry-studio v1.8.3

修订 发布时间2026年3月25日 来源CherryHQ/cherry-studio 英文原文

变更流程图

亮点

  • 智能体模式能力与可靠性提升 — Agent SDK 升级带来 ToolSearch 与 UI 渲染器，智能体模式现支持 OpenRouter，推理模型新增推理强度控制。每次传输会话使用全新的 MCP 服务器、修正向量记忆的 agentId 过滤/搜索回退，并在中止时停止思考计时器，提升会话隔离与可靠性；使用智能体的用户应升级。
  • 提供商兼容性修复范围聚焦但重要 — Copilot 的 gpt-5.4 模型现路由到 responses，并新增专用的 @ai-sdk/groq 提供商以避免 reasoning_content 报错。当 reasoning_effort 为默认值时，temperature/topP 不再被错误禁用；Claude 4.6 自适应思考、Gemini 接地引用、聚合器 PDF 处理与 base64 图片处理也一并修复；用到这些路径的用户建议升级。
  • 启动与 Windows 安全修复值得关注 — @napi-rs/canvas 平台二进制文件解决了缺失依赖导致的启动崩溃，并通过 0.1.97 覆盖支持 Windows ARM64。CodeToolsService 还阻止了 Windows 上的命令注入；受启动崩溃、Windows ARM64 或 Windows 代码工具影响的用户应更新。
  • 本地集成与日常工作流改进 — Claude Code 新增 LMStudio 与 Ollama 支持并带 API Key 占位符，OpenClaw 同步改用各模型上下文窗口并保留用户配置。引导式上手、同名模型 ID 区分、主题批量删除、链接解析改进，以及对 venn 和 ishikawa 图表的 Mermaid 11.13.0 支持，带来实用的易用性提升。
  • 升级建议 — 这是一次内容实在的补丁更新，不是重新打标签或仅改元数据的发布。未列出破坏性变更或必需的迁移步骤；智能体、受影响提供商、Windows 以及本地工具/OpenClaw 用户应升级，工作流不涉及这些修复的用户可跳过。
