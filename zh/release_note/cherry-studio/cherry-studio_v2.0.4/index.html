cherry-studio v2.0.4

修订 发布时间2026年8月13日 来源CherryHQ/cherry-studio 英文原文

变更流程图

亮点

  • API 网关与 MCP 获得真正的能力增强 — HTTP 网关找回了 MCP 能力：/v1/mcps 端点恢复（PR #18080），新增可选开启的 MCP 会话，支持服务端到客户端的推送和进度回报（PR #18094），并加入统一的 token 估算和真实的工具结果图片（PR #17195）。内部 Agent Responses 请求现在会发送稳定的 prompt_cache_key（PR #18343），网关关闭也不再因活跃的流而挂起（PR #18489）。如果你通过 API 网关使用 Cherry Studio，这个版本等于把你早就发现缺失的功能补了回来。

  • 崩溃与可靠性修复是最强升级理由 — 多个长期稳定性问题得到解决：修复长而快的流式响应导致渲染器二次方内存增长并崩溃的问题（PR #18450），每条流的 destroyed 监听器不再在 WebContents 上泄漏（PR #18278），多模型重试/流收敛更加稳健（PR #18304）。AI trace 查看器现在以增量方式提供，并有界保留（PR #18203）以及虚拟化的 span 树（PR #18296）。如果你经常跑长生成或检查大型 trace，这些改动直接值得拥有。

  • 需要注意的行为变化（无需迁移） — 没有面向用户的破坏性变更或迁移步骤，但一些行为变严了：知识库现在拒绝逃出宿主 material 根目录的相对路径（PR #18401，安全加固），上下文设置会完整读取附件、对 fs_read 做门禁，并恢复”最后 N 条”上下文限制（PR #18192），模型定价支持按输入 token 数分层计价（PR #18248）。RelativeFilePath/PosixRelativeFilePath 的品牌重构（PR #18229、PR #18230）只是编译期类型变化，对最终用户没有运行时迁移要求。有外部路径知识引用或自定义定价配置的人，升级后应做一次健全性检查。

  • Windows 与本地模型用户获得实质修复 — 本地模型新增 DirectML 和 CoreML 加速（PR #18350）；Windows 上系统 OCR 现在发送图片字节，并把非 PNG 图片转码为 PNG，使 JPEG 能够解码（PR #18335、PR #18361），Unicode 命令路径得以保留（PR #18201），npx/uv 解析改用 findExecutableInEnv（PR #18436）。Agent/MCP 可靠性也通过把中止信号传播到进行中的工具调用（PR #18294）、回放前规范化旧版 v1 MCP 工具名（PR #18224），以及清理崩溃会话的恢复 token（PR #18289）得到提升。

  • 升级结论 — 这是实质性版本，不是空操作、重新打标签或仅改元数据的变更。使用 API 网关/MCP、跑长流、依赖 Windows OCR 或本地模型，或从事 agent/知识库相关工作的人应升级。如果只用基础聊天、且不涉及上述领域，可以合理跳过——其余大部分条目是 CI、测试、文档和面向贡献者的工具改动（i18n 同步、Claude 工作流整合、测试清理），不改变运行时行为。
