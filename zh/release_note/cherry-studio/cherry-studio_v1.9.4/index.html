cherry-studio v1.9.4

修订 发布时间2026年4月30日 来源CherryHQ/cherry-studio 英文原文

cherry-studio v1.9.4

这个项目是干啥的：一个桌面端 AI 助手客户端，把多家大模型装进同一个界面，支持聊天、翻译和知识库，适合想统一管理各种 AI 模型的用户。

变更架构图

亮点

  • 模型支持与路由 — 新增 DeepSeek V4+，并通过 Claude 兼容端点转发 reasoning_effort（PR #14551、#14572）；新增 MiMo V2.5（#14557）；为 mistral-small-2603 加入视觉能力和 reasoning_effort（#14541）。Kimi K2.6 现在会禁用不受支持的 temperature/top_p，网关拉取模型使用配置的 API key（#14580、#14605）。未列出迁移步骤。
  • DeepSeek 可靠性 — 网页搜索结果中的 DSML 标签会被抑制，DSML 工具调用标记会被解析为 AI SDK 的工具调用，提升工具使用兼容性（#14721、#14747）。伴随这些修复，@ai-sdk/deepseek 升级到 2.0.30（#14718）。
  • Agent 破坏性行为 — @cherry/browser MCP 不再自动注入（#14571）。**迁移：**如果你的 agent 工作流依赖这一默认行为，请显式配置并添加浏览器 MCP。
  • 图片生成与 provider 修复 — 解决 gpt-image-2/gpt-image-1.5 失败及 pending 占位符卡住的问题（#14578）；无扩展名的图片编辑现在默认使用 image/png（#14616）。OpenCode 新增 new-api provider 支持和端点类型路由（#14511），Windows 不再把代码块中的 Unix 风格路径当作可点击链接（#14709）。
  • 升级建议 — 使用受影响模型、agent 工具调用、图片生成、OpenCode provider 或 GitHub Copilot 模型拉取的人值得升级。其他人可以跳过此补丁；除显式配置 @cherry/browser 外，changelog 未列出大范围配置或数据迁移。
