RuView v3681

RuView v3681

变更流程图

亮点

  • Windows 特征值构建解锁 — wifi-densepose-signal 此前在 Windows 上无法用默认特性编译：openblas-src 在那里拒绝静态构建（“Non-vcpkg builds are not supported on Windows”）。#2530 去掉了这个硬阻断，Windows 采用者终于无需本地打补丁或 vendored 变通即可启用特征值特性。

  • 按目标平台选择 OpenBLAS 后端 — ndarray-linalg 现在在 Windows 上声明为 openblas-system，其他平台为 openblas-static。这是让修复生效的机制：Windows 消费者链接系统/vcpkg 提供的 OpenBLAS（请确保已安装且可被发现），而 Linux/macOS 保持自包含的静态构建。非 Windows 平台行为不变——只有链接策略不同。

  • BLAS 仍为可选 — 两种后端声明都保持可选，因此 --no-default-features 仍会彻底去掉 BLAS。这是对 @PretaxE63 在 #825 中原始修复的有意修正：原修复把依赖变成无条件，悄然把 BLAS 重新引入每一个 default-features = false 的消费者——膨胀构建体积并重新要求 BLAS 库。如果你特意禁用默认特性以保持无 BLAS，这个约定仍然成立。

  • 聚焦的回溯移植，无 schema 变动 — 对 #825（由 Uxsshann 共同署名）的移植有意丢弃了原始改动里夹带的一份无关重新生成的 Tauri schema。改动范围局限在 signal/BLAS 接线，因此待审噪音更少，对下游消费者造成的意外表面变化也更少。

  • 仅源码快照 — v3681 是 CI 验证的源码发布，不附带固件包。容器镜像通过单独的 sensing-server-docker 工作流发布，固件在专门的 vX.Y.Z-esp32 tag 上。想找可运行镜像或 ESP32 二进制的开发者应从那些流水线拉取，而不是本 tag。

无破坏性变更。

由 CI 管道验证的源快照。此条目不包含固件包。 变化： 修复（信号）：在 Windows 上使用系统 OpenBLAS 来获取特征值特征 (#2530) openblas-src 拒绝在 Windows 上进行静态构建（“非 vcpkg 构建是 Windows 上不支持”），因此默认功能版本为 wifi-densepose-signal 无法在那里编译。声明 ndarray-linalg 每个目标：Windows 上的 openblas-system，其他地方的 openblas-static。两者都 保持可选，因此 —no-default-features 仍然完全丢弃 BLAS。 由 @PretaxE63 从 #825 移植，保持依赖项可选（ 原始使其成为无条件的，这将 BLAS 重新添加到每个 default-features = false Consumer）并删除不相关的 重新生成 Tauri 模式。 共同作者：Uxsshann usattha@gmail.com 源代码提交： 48f8091e92d5fa93b06dc177ae064fc0def6267a 容器镜像通过传感服务器发布工作流程单独发布。 固件下载附在专用 vX.Y.Z-esp32 版本中。
