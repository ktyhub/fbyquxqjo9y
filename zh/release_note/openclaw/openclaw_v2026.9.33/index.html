openclaw v2026.9.33

这个项目是干啥的：一个AI助手工具，更新失败能自动恢复、私人检查保持私密，升级更稳更安全，给想要安心用AI的日常用户用。

这是仅网关的 extended-stable 版本，相当于我们当前的 LTS。此版本是 2026 年 9 月底发布的 OpenClaw，此外还有重要的安全更新、可靠性和性能修复以及新模型支持等功能。本次发布时 OpenClaw 的最新版本是 2026.10.3

2026.9.33

变更架构图

亮点

  • 更安全的 9 月升级： 2026.9 系列上的更新保持状态、插件数据、服务所有权和 Windows 状态路径完好无损，并拒绝通过未归属的 Doctor 写入进行自动恢复。 （＃160167，＃166755）感谢@RomneyDa，@vyctorbrzezowski，@jalehman，@Alix-007，@jayzhou2309，@nitinjwadhawan，@SunnyShu0925，@obviyus，@vincentkoc，@taihartman和@DonnieFi。
  • 在 pnpm、npm 和 Windows 上完成的更新： pnpm 12 网关服务和启动器在本机更新中继续存在，保留的更新程序运行时不再阻止 npm 恢复，并且在 Doctor 重新检查驱动程序祖先后，Windows 更新不再回滚。 （＃170003，＃170131，＃170170，＃169563）谢谢@xilopaint，@k-sekula，@Warhangel，@RomneyDa，@DonnieFi，@Takhoffman，@NianJiuZst，@masatohoshino，@obviyus，@ericcurtin，@jjjhenriksen，@sjf-oa，@ceckert， @jayzhou2309、@brokemac79、@Yolo521-bot、@mightyx 和 @ajmtrz。
  • 新模型支持： 运行 Meta Muse Wonder，使用 MiniMax M3.1 思维努力级别，并在令牌过期后保持登录到 MiniMax 门户 OAuth。 （＃170232，＃160089，＃160459）谢谢@RomneyDa，@NianJiuZst，@Takhoffman，@php737，@masatohoshino，@rongtianhua，@DonnieFi，@obviyus，@ericcurtin，@jjjhenriksen，@sjf-oa，@ceckert，@jayzhou2309，@brokemac79， @xilopaint、@k-sekula、@Warhangel、@Yolo521-bot、@mightyx 和 @ajmtrz。
  • 更可靠的模型转变： 代理运行尊重实时思维水平，本地提供商获得响应标头截止日期，ChatGPT WebSocket 正常关闭恢复，Codex 回复保留其最终令牌。 （＃168566，＃168282，＃167512，＃168400）谢谢@obviyus，@ericcurtin，@mightyx，@RomneyDa，@DonnieFi，@Takhoffman，@NianJiuZst，@masatohoshino，@jjjhenriksen，@sjf-oa，@ceckert，@jayzhou2309， @brokemac79、@xilopaint、@k-sekula、@Warhangel、@Yolo521-bot 和 @ajmtrz。
  • 工作在网关重新启动后仍然存在： 中断的自动化轮转、引导会话、云工作人员声明和部分工作人员回复现在可以在重新启动后恢复或保留。 （＃170162，＃170252，＃170161，＃170223）谢谢@DonnieFi，@Takhoffman，@NianJiuZst，@RomneyDa，@masatohoshino，@obviyus，@ericcurtin，@jjjhenriksen，@sjf-oa，@ceckert，@jayzhou2309，@brokemac79， @xilopaint、@k-sekula、@Warhangel、@Yolo521-bot、@mightyx 和 @ajmtrz。
  • **传输和设备稳定性：**实时发送在队列恢复后仍然存在，并且节点请求不再因不相关的配对活动或在写入另一个设备的配对时失败。 （＃169010，＃169486，＃169575）谢谢@RomneyDa，@DonnieFi，@Takhoffman，@NianJiuZst，@masatohoshino，@obviyus，@ericcurtin，@jjjhenriksen，@sjf-oa，@ceckert，@jayzhou2309，@brokemac79，@xilopaint， @k-sekula、@Warhangel、@Yolo521-bot、@mightyx 和 @ajmtrz。
  • 代理和更新稳定性： 携带大量兼容的 10 月修复程序，用于代理轮次、会话、通道和更新恢复。 （＃170476）谢谢@RomneyDa，@yetval，@Dimitri-lcht，@Program-123，@dhruv1220，@Shenrui-Ma，@igs-rogenlo，@changeroa，@hxy91819，@Takhoffman，@harjothkhara，@TYY-2005，@giodl73-repo，@masatohoshino， @obviyus、@jalehman、@wangmiao0668000666 和 @an2in。

修复

  • **更新和Doctor：**保持Doctor在不可读的主管和子绑定错误下运行，保持干净的服务安装拒绝不受本机权限恢复的影响，停止因停止cron和清理而写入更新历史记录，避免仅簿记修复拒绝，并且永远不要删除OAuth配置文件，因为旧的身份验证存储不可读。 （＃169665，＃169658，＃169283，＃170195，＃170256）谢谢@DonnieFi，@Yolo521-bot，@Takhoffman，@NianJiuZst，@RomneyDa，@masatohoshino，@obviyus，@ericcurtin，@jjjhenriksen，@sjf-oa，@ceckert， @jayzhou2309、@brokemac79、@xilopaint、@k-sekula、@Warhangel、@mightyx 和 @ajmtrz。
  • 从 2026.8.35 更新： 通过“允许始终”批准的 cron 作业在更新后保持无人值守运行，删除的存储一代上留下的 pnpm 12 网关服务被重写为持久安装链接，Doctor 推迟可选检查，以便更新在旧更新程序的时间限制下完成，已删除 SDK 导入的官方插件不再默默保留，Kubernetes pod 在启动之前运行 Doctor。 (#171816) 谢谢@RomneyDa。
  • 网关响应能力： 以回复标记（例如 [[reply_to_current]]）开头的长流回复不再重新解析每个增量的整个回复，这可能会使网关忙碌数十秒。 ＃166781（＃166782）​​感谢@boeingchoco和@obviyus。
  • Tailscale： 中断的 Tailscale Serve 启动会停止其服务进程，当 tailnet 拒绝服务时网关会保持本地访问，并且公共聊天在启动后不再立即返回 503。 ＃167436（＃167514，＃171509，＃167604）感谢@pandysp和@RomneyDa。
  • **上下文引擎：**持有旧阻塞轮的会话不再重复阻塞轮警告并在每次运行时重新读取它。 (#167595) 谢谢@jalehman。
  • **状态数据库：**状态读取不再保持关闭状态，直到状态清理失败后网关重新启动为止。修复#162085。 (#171709) 感谢@RomneyDa 和@residentb2b。
  • **更新摘要和Doctor：**成功的更新停止将已解决的插件数据和设置升级列为待处理，可选的dreaming-cron检查或快照清理失败不再阻止更新，并且macOS LaunchAgent修复接受正在进行的引导程序。 （#170413、#170754、#170740）感谢@RomneyDa 和@DonnieFi。
  • **提供程序：**恢复 DeepSeek calls 标记而不是泄漏工具有效负载，在线程准备失败后恢复 Codex 后续请求，并在无法保存凭据时设置失败时选择别名 llama.cpp 模型。 （＃169728，＃169431，＃168232）谢谢@TOMUIV，@jjjhenriksen，@DonnieFi，@Takhoffman，@NianJiuZst，@RomneyDa，@masatohoshino，@obviyus，@ericcurtin，@sjf-oa，@ceckert，@jayzhou2309，@brokemac79，@xilopaint， @k-sekula、@Warhangel、@Yolo521-bot、@mightyx 和 @ajmtrz。
  • 通道和工具： 通道工具在配置写入重新启动帐户后继续工作，ACP 代理在单独安装 acpx 时保留插件和 OpenClaw 工具，Talk 协商在连接后不再立即中止，并且路由轮流提供阻塞问题。 （＃164848，＃159396，＃164272，＃170083，＃170039）谢谢@sjf-oa，@ceckert，@jayzhou2309，@ajmtrz，@brokemac79，@DonnieFi，@Takhoffman，@NianJiuZst，@RomneyDa，@masatohoshino，@obviyus， @ericcurtin、@jjjhenriksen、@xilopaint、@k-sekula、@Warhangel、@Yolo521-bot 和 @mightyx。
  • **自动化：**失败的一次性自动化始终发出警报，并且 cron 在等待主机准入时不再持有状态写入器。 （＃169102，＃168291）谢谢@DonnieFi，@Takhoffman，@NianJiuZst，@RomneyDa，@masatohoshino，@obviyus，@ericcurtin，@jjjhenriksen，@sjf-oa，@ceckert，@jayzhou2309，@brokemac79，@xilopaint，@k-sekula，@Warhangel， @Yolo521-bot、@mightyx 和 @ajmtrz。
  • 版本检查： Windows 安装程序检查容忍缓慢的 gateway stop 帮助和表面清理错误，打包检查从繁忙的网关端口恢复，并且扩展稳定候选者现在有资格从以前的扩展稳定版本升级。 （＃169567，＃170178，＃171565）谢谢@RomneyDa，@DonnieFi，@Takhoffman，@NianJiuZst，@masatohoshino，@obviyus，@ericcurtin，@jjjhenriksen，@sjf-oa，@ceckert，@jayzhou2309，@brokemac79，@xilopaint， @k-sekula、@Warhangel、@Yolo521-bot、@mightyx 和 @ajmtrz。 ###完整贡献记录 此审核记录涵盖完整的 v2026.9.9..a902bd2d4bd1707cdc0c861bb9bf92727645f700 历史记录：65 个范围内 PR + 0 个保留的仅种子 PR = 65 个唯一 PR。生成清单还提供直接提交作为编辑输入；上面分组的注释优先考虑用户影响。
