llama_index v0.14.21

这个项目是干啥的：一个把大模型接上你自己数据的框架，文档一丢进去就能做问答和搜索，也会搭智能助手，给想搭私有知识库问答的应用开发者用。

变更架构图

亮点

  • 核心可靠性修复——遇到这些问题的用户请升级 — llama-index-core 0.14.21 加固了三条失败路径：DocumentSummaryIndex.delete_nodes 传入无效节点 ID 时不再抛 KeyError（#21067）；结构化输出失败现在会处理 ValueError/TypeError，不再以崩溃收场（#21090）；持久化层的 fs.open() 调用现在显式传入 UTF-8 编码（#21111），这在 Windows 或任何非 UTF-8 默认区域设置下尤为关键。都是小巧的防御性改动，不涉及 API 变化。

  • Message Block Buffer 回归已处理 — #21339 标题为「Fix Breaking Change in Message Block Buffer Resolution」，即修复此前引入的破坏性变更，而非制造新的破坏。如果你曾被那个回归卡住、绕过锁定或打过补丁，这个版本值得跟进。变更日志未记录迁移步骤，因此把它当作恢复原有行为，并重跑你自己的聊天/消息块流程来确认。

  • 两项可选启用的能力 — llama-index-embeddings-nvidia 0.5.1 新增 HTTP 客户端支持（#21046）；llama-index-llms-bedrock-converse 0.14.6 新增 Google Gemma 模型（#21380）。只有使用这些特定集成时才相关；两者都不影响其他包。

  • 这主要是一次依赖提升的维护版本 — 绝大多数版本提升（包括不少跨小版本的，例如升到 0.5.0/0.6.0/0.7.0）都仅来自协调性的「bump the pip group across 96/87/68 directories」PR（#21381、#21382、#21394），没有行为层面的代码改动。别把长长的包列表误读成功能大变动。

  • 结论——定向升级，非强制 — 受 KeyError/结构化输出/编码修复或消息块回归影响的核心用户，以及想要新功能的 NVIDIA-embeddings 或 Bedrock-Converse 用户，值得升级。其他所有人都可以放心跳过：除了消息块修复外，没有跨领域的 API 变化，也没有记录的迁移步骤。
